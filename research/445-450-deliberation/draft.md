# #445〜#450 降ろし方の案(軽の審議・起案と内部の調査)

対象: `state=undelivered` で `issue=445〜450` の実装マーク 188 件(全件 `check=manual plan=scheduled`)。#324 の付け替え時の 205 件との差 17 件は #325・#355・#444 へ寄せた分で、整合する。一覧は `inventory.tsv`。補助は `list-marks.cjs`(列挙)、`merge.cjs`(案の結合と集計)、`noadopter.mjs`(d にできない節の判定)。

## 1. 方針

- 降ろし方は4つから1つ。(a) 機械の検査、(b) 様式の欄、(c) 手引き(スキル・常駐の指示・reference・生成文を含む)、(d) 降ろさない(plan=adopter)
- (a) は決定可能な条件(値の一致・存在・構文・日付の前後・件数)に限る。自由な文の意味や改ざんの防止は閉じない。意味の判断は (c) に置き manual で開示する
- (b) は結果と証跡の欄まで。手順は書かない。標準の表を複製せず、参照の一文で足りるものは一文にする(0701)
- (d) は「採用者の環境の固有の値・組織の体制・外部の契約など、テンプレートが持てないもの」に限る。決めた理由は件ごとに `inventory.tsv` に書いた。次の4型のどれかに当たる
  - AI 実行基盤に属する(ADR-0104。接続経路・監視・切替・適合性評価): 0568 0712 0713 0715 0716 0718 0826 0827 0833 0711
  - 組織の会議運営・内部監査・稟議・提案書(案件をまたぐ、または導入前): 0665 0707 0832 0901 0964 0974 0950 0959 0960 0961
  - 案件をまたぐ入力(他案件の企画書、ポートフォリオ): 0878 0668
  - 課金・利用量の計測(ADR-0096 の IMPL-0370 と同じ判断): 0569 0570 0619
  - 規定が許す向きで、テンプレートの既定が安全側: 0766(第7章の例外承認で受ける。Q2)。規制要件の中身が法域固有: 0836
- 3つの問い(Q1 結果と証跡まで / Q2 例外承認で受けられるか / Q3 破られたとき誰が何を失うか)の適用
  - Q3 が重い群は細かく降ろす: 安全(F.7 の記録、故障挿入の環境、CL の上限)、取り消せない操作(秘匿情報の無効化、本番反映の承認)、適合の主張(G-7 基準7、表現の禁止)
  - Q3 が軽い群は手引きに留める: 判定の運用、体裁、分量
- 新しい様式は2枚まで: ① F.7 の安全適合性の検証記録(`templates/09` の節。448 の 12 件を1節で受ける) ② 移管記録(H-1・H-2・H-3 を1枚。447 の context-transfer-record 14 件)。他は既存の様式への欄の追加で足す。欄は件ごとに増やさず群で畳む(下の「畳み」)

## 3. (d) の実装の仕方

- 属性の変え方(マーク1件あたり): `plan=scheduled` → `plan=adopter`、`issue=` と `review=` を削除、`decision=ADR-NNNN` を追加。`state`・`check`・`target` は変えない。`check=manual` の注記には「確かめる者」(`MANUAL_WHO_RE`)が要るため、末尾の「確かめる者: 計画の Issue…の担当者」を「確かめる者: 採用者の〈役〉」へ書き換える。`target` は planned のままでよい(undelivered だけが使える)
- `markAttrProblems`: adopter は `decision` 必須、`issue`・`review` は禁止されていない。ただし `issue=` を残すと `marksWithIssue` が数え続けるため削除する(`impl-plan-issues` の対象から外れる)
- `check-impl-plan-issues.mjs --issue N` は、その番号を `issue=` に持つマークの有無だけを見る。(d) へ移したマークは数えない。全件が移るか他へ寄せ終えれば 0 件で閉じられる。機械は Issue を閉じない
- `decision=` の存在の検査は「属性があること」だけで、指す ADR の実在は検査しない(`scripts/check-impl.mjs` 183・357 行、`impl-inventory.mjs` 447 行で確認)。実在は `lint:refs` の範囲にあるかを実行で確かめる(未確認)
- 記録の所在: ADR-0084 の決定4 の表は採用済みで書き換えない。新 ADR を起こし、決定に (d) の件ごとの「採用者に委ねる理由」と「採用者に求めること」を表にする(IMPL-0237→ADR-0090 決定6 と同じ型)。理由を書けない件は scheduled に戻す(marking の規則)
- 台帳: `npm run impl:write` で再生成。冒頭の「見直しの年月を過ぎた scheduled」の件数が減る。`impl-inventory.yaml` の note に plan の記述があれば合わせる(未走査)
- 順序: 新 ADR の起票 → マークの属性更新 → `impl:write` → `npm run check` → Issue の閉じる前確認

## 4. 判断の割れそうな境界
