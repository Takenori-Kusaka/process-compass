### 直す

**R2-1 ADR-0175 決定3 の表が、L-1〜L-4・M-5(0826)の note の直しに追随していない**(0713 の行は高、他は編集の指摘)

- 根拠: マークは `decision=ADR-0175` を引く。ADR の表の「採用者に求めること(確かめる者)」が採用者の読む義務の一覧になる
  - **0713(高)**: マークは「正解を改めたとき(3.12.3 要求事項16)に測り直す」と、確かめる時「正解を改めるとき」を含む。ADR の行は「採点者の識別を変えた後の基準値の扱い」「採点者を変えるとき」だけ。ADR を読む採用者は測り直しの義務を落とす。表示(ADR)と実態(マークの範囲)が食い違う
  - 編集の指摘(意味は変わらない。マークが正): 0833(提供者の上限を数えない・IMPL-0370)、0964(D-O01)、0568(案件の側の固定を決めていない記録)、0665(3.7.4・3.7.2 と IMPL-0656)、0826(IMPL-0726・0729・0827)の行が、マークの note より狭い。0665 の行は末尾に「(IMPL-0701 と同じ理由。ADR-0175)」と自己参照が残る
- 直し方: ADR は未 push なので、表の各行の本文を、いまのマークの note から「(ADR-0175)」と確かめる者を除いた文へ揃える。0713 の確かめる者の欄に「正解を改めるとき」を足す

### 開示して閉じる(undelivered の表示で開示済み)

**R2-2 0827 は scheduled・issue=447 に戻ったが、降ろし先と note が採用者の基盤のまま**(中)
- 所在: `roles-responsibilities.md` の IMPL-0827、`impl-targets.yaml` の `model-quality-monitor`(名「モデルの品質の監視(採用者の AI 実行基盤)」、ADR-0104 でテンプレートは持たない)
- 根拠: 裁定 10 節5 は「通知を受けた案件が作業を止めることは、常駐の指示か手引きで届けられる」として (c) 候補へ戻した。マークは 33eef837 の前と同一に戻したので、note は「準拠テンプレートは持たない」理由だけを書き、(c) で届ける部分が表示に出ない。台帳では「採用者の AI 実行基盤(予定の置き場)」と「計画 #447」が並ぶ
- 高ではない理由: state=undelivered・plan=scheduled・issue=447 の表示は実態(未達で、#447 が追う)と合う。食い違うのは置き場の名だけで、区分は着手のときに確定すると裁定が決めている
- 閉じ方: #447 へのコメント(decision.md 6 節の文案)に「0827 の降ろし先は着手のとき案件の側(常駐の指示か gate の手引き)へ改める。いまの target は採用者の基盤のまま」と書く

**R2-3 committee-agenda の path が (c) の区分と合わない**(低)
- 所在: `impl-targets.yaml` の `committee-agenda`(path `scripts/committee/`、名「判定当日の議題の照合(予定)」)
- 根拠: 裁定 10 節2 は 0832 を (c)(`gate` のスキルの手引き)とした。path はスクリプトの置き場を示す。説明の末尾は「テンプレートの手引きで届ける予定」と書いており、説明と path が食い違う
- 閉じ方: 0832 は scheduled で区分は着手で確定する。#447 のコメントに「0832 は gate の手引きへ降ろし、そのとき committee-agenda の path を改める」と書く。0718(control-rollout)・0715(deprecation-inventory)の登録は「採用者の側に置くかは決めていない」と書いてあり、scheduled と矛盾しない
