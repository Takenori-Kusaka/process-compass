### 中

**M-1 IMPL-0878 は、テンプレートが決定可能な検査で届けられるのに (d) にしている**
- 所在: `deliverable-templates.md:1213`、ADR-0175 決定3 の表
- 根拠: 直前の表は「前案件の記述と同一である」を**機械が検査する**と定める。比較は値の一致で決定可能。テンプレートの外にあるのは入力(前の案件の企画書)だけ。`check-g1.mjs` に入力のパスを受ける引数を足せば、比較の機構はテンプレートが持てる。0962 の note は「表現の検査が降りれば採用者は提案書に掛けられる」とし、機構だけを届ける型を認めている。0878 だけその型を採らない。新しい note の確かめる者は「G-1 の判定者(人)」で、条文の「機械」と食い違う。さらに `target=g1-check` は実在する `check-g1.mjs`(template-file)を指したまま、テンプレートは実装しないと表示している
- 直し方の案: (a) にする(`check-g1.mjs` に前の企画書の所在を受ける引数を足し、与えられたときに同一の欄を出す。与えられないときは「未確認」と出す)。入力を置くことは採用者の値として note で開示する。d のまま残すなら、note に「規定は機械の検査。採用者が自らの比較の機構を置く」と書き、`target` を planned の採用者の置き場へ改める

**M-2 IMPL-0832 の理由は ADR-0175 決定2 の列挙に当たらず、手引きで届けられる**
- 所在: `roles-responsibilities.md:1373`(3.10.7)
- 根拠: 3.10 は工程ゲートの判定の事前レビュー期間(単一の案件)で、案件をまたぐ会議体ではない。決定2 の列挙(AI 実行基盤・案件をまたぐ会議体・内部監査の実施・他案件の入力・導入前の稟議文書・費用の計測)に「当日のふるまい」は無い。判定資料の未解決の論点(3.10.3 の記載事項2)はテンプレートの判定の流れ(IMPL-0210、#325)が持つ。議題を未解決の論点に限ることは、`gate` のスキルの手引き(c)で届けられる。旧 note は「判定資料の未解決論点の一覧に議題を照らす」としていた。新しい note の「記録に残らない」は、この分析と食い違う
- 直し方の案: (c) にする(降ろし先は `.claude/skills/gate/SKILL.md`。#447 に残す)。d のままにするなら、ADR-0175 決定2 の列挙に「会議の当日のふるまい」を足す。その場合、決定2 の変更として扱う

**M-3 IMPL-0832 の旧 note にあった「追わない」の記録が消えた**
- 所在: 同上。3.10.7 の箇条「黙読の時間を置く。資料の読み上げを議事に含めてはならない」「判定に異議を述べた者も判定の後は従う」
- 根拠: 旧 note は、これらを「制度設計の事項として追わない」と明記していた。新しい note はこれを落とした。同じ箇条を追う他のマークは無い(grep で確かめた)。いまは「書かれていない」と「課さないと決めた」(追わないと決めた)の区別がつかない(コアポリシー「却下は成果である」)
- 直し方の案: note に「黙読・読み上げの禁止・判定の後の実行は、当日のふるまいにしか違反が現れないので追わない」を戻す

**M-4 IMPL-0718 の理由の事実が誤っている**
- 所在: `roles-responsibilities.md:1949`、ADR-0175 決定3 の表
- 根拠: note は「全社の統制と CI 基盤は案件のリポジトリの外にある」とする。実際には準拠テンプレートは案件のリポジトリに CI(`template/.github/workflows/` の 10 本)を持つ。外にあるのは、全社の統制の更新を決めることと、昇格の予定日を決めることである。「警告として先行して入れ、猶予の後に必須へ上げる」受け手の側の仕組みは、テンプレートの CI が持ちうる。反対の委員は「細かい定義の増加」を理由に残したが、裁定はこの点を検討していない。旧 note にあった「3.12.8 要求事項4・5 も同じ」も note から落ちた(`impl-targets.yaml` の説明には残る)
- 直し方の案: 理由を「統制の更新と昇格の予定日を決めるのは全社の AI運用担当者で、案件の外にある」へ改め、範囲(3.12.8 の4・5)を note に戻す。受け手の側(警告の段・昇格の日の表示)をテンプレートが持つかは、#447 の範囲として記録する。決めないなら、決めないと記録する

**M-5 IMPL-0715・0826・0827 で、案件が受け取る側の部分も一緒に外れた**

  - 0826・0827: 切替を通知すること・止めることは基盤の側の行為である。一方で、通知を受けた案件が作業を止めることは、常駐の指示か手引きで届けられる。0827 は「基準を下回れば作業を停止する」で、品質の劣化したモデルで作業を続けない統制(取り消しにくい結果に響く)である。旧 note は、切替の期間の記録と開示を IMPL-0726・0729 が運ぶと書いていたが、新しい note はこれを落とした
