### R1-2 中 — 調整の記録の「判定の根拠の欄」がテンプレ4 に無い

- 所在: `lifecycle.md:665`(「調整の種別(表の行)と理由は、判定の根拠の欄に書きます」)
- 根拠: 標準のテンプレ4(`deliverable-templates.md:760` 付近の欄の表)にも、準拠テンプレートの `templates/04-gate-record.md` にも「判定の根拠」の欄は無い。欄は挙動要約・確認した項目・確認していない事項・差し戻し理由・決断の記録などで、結果は「通過 / 差し戻し」の2値に縛られる(`04-gate-record.md` の「判定結果」)。調整に2値の結果は当てはまらない。前例の「価値責任者の判断」は、`04-gate-record.md:53` の節「ゲートでない判断の記録」に置き場と結果の読み替え(通過=着手を認める)がある。「価値責任者の調整」には、それに当たる読み替えが無い
- 直し方の案: 書く欄を、テンプレ4 に実在する欄名(例: 「決断の記録」または節「ゲートでない判断の記録」)に改める。結果の欄の扱い(調整では「通過」を「調整を行った」と読むか、結果を書かないか)を、`deliverable-templates.md:767` の注記に書く。template の `04-gate-record.md` の項目として #443 の残り 5 に加える

### R1-3 中 — 「下位の担当には、担当自身の識別子が入った」は確かめた記録が無い

- 所在: `human-ai-boundary.md:1128`(EV-0319 の本文「下位の担当には、担当自身の識別子が入りました」)、`phase5-implementation/agent-trace-control.md:138`(「下位の担当(サブエージェント)の実行では、担当自身の識別子が入ります」)
- 根拠: intake.md §3.5 の W1〜W7 に下位の担当の試行は無い。根拠は「確かめられなかったもの」の欄の、調査の担当の環境で `CLAUDE_CODE_SESSION_ID` と `CLAUDE_CODE_CHILD_SESSION=1` を見た、という観測だけである。提供者の文書では、`CLAUDE_CODE_CHILD_SESSION=1` は Claude Code が Bash・PowerShell・Monitor の道具やフックで起こすすべての子プロセスに設定される。下位の担当であることの印ではない。さらに、調査の担当は Orca の作業役(別の `claude` の起動)だった可能性がある。そうなら、それは下位の担当ではなく別のセッションである。親の識別子と比べた記録も無い。手引きは断定の形で書いており、確かめていないことを事実として示している
- 直し方の案: 2か所とも「下位の担当(サブエージェント)の実行で、どの識別子が入るかは確かめていない」に改める。EV-0319 の差し替え条件(下位の担当の確認)はそのまま残す。IMPL-1019 の note(「下位の担当の起動でも記録されることは確かめていない」)とは、これで揃う
