## 所見

### R2-1 高 — 書き先を「決断の記録」にしたことで、調整の記録に胆識の水準の規律が及ぶ(新しい義務。ADR-0173 の表示と食い違う)【直す】

- 所在: `lifecycle.md` 2.10.5 の段落(「調整の種別(表の行)と理由は、人が書く欄のうち『決断の記録』に書きます」)、`deliverable-templates.md:767` の注記、ADR-0173 決定3(「種別と理由は『決断の記録』に書く」)、ADR-0173 結果(「採用者に新しい義務を課さない」)、decision.md §6、IMPL-0954 の note
- 根拠:
  1. 「決断の記録」は、欄の名でなく、構造を持つ節である(5.7.2。確認した事項・確認していない事項・判断が変わる条件・受容したリスク・確定の形態)。**種別や理由を書く欄は、その構造に無い**。R1-2 の指摘(実在しない欄を書き先にしている)は、名を変えても実質は残る
  2. 5.7.1 は、決断の記録を G-8・SG・例外承認の「胆識」の水準に置き、「決断の記録(5.7.2)の確定の形態は、人確定に限ります」と場面を限らずに書く。5.7.2 は「確認していない事項が空欄、または『なし』の記録は、確認の範囲を把握しないまま承認した記録として扱う」とし、`deliverable-templates.md:918` は同じ記録を「無効」とする。決断の記録へ書かせると、これらが調整の記録に及ぶ。2.10.5 の表の行1〜3 は「調整の記録のみ」(価値責任者の単独で軽く回す経路)であり、そこに胆識の水準の記録(確認していない事項の必須、人確定)を課すことになる。**これは採用者への新しい義務である**。ADR-0173 結果の「新しい義務を課さない」と食い違う
  3. 既存の欄の意味を変えている。標準のテンプレ4 の節見出しは「決断の記録(G-8・SG・例外承認で必須)」、準拠テンプレートの `04-gate-record.md:160-162` は「適用: G-8・ステージ移行ゲート・例外承認」「この3つの場面でのみ記入します」である。調整の記録で記入させると、「のみ」と矛盾する。IMPL-0954 の新しい note は、この限定を認めたうえで、書き先を「準拠テンプレートの項目として降ろす」と書く。これは準拠テンプレートの節の適用範囲を広げる予告であり、ADR-0125・#226 の適用範囲の書き方とも合わない
  4. 機械の検査には影響しない。`template/scripts/gate/` に、ゲート名「価値責任者の調整」の記録の決断の記録を確かめる処理は無い(`aggregate-evidence.mjs` の決断の記録の検査は G-8 だけ)。食い違いは規範の上のもので、採用者が本文どおりに運用すると義務が増える
- 直し方の案(議長が選ぶ):
  - (a) 書き先の欄を名指さない。「調整の種別(表の行)と理由を、人が書く欄に書く。5.7.2 の決断の記録の構造は課さない」とする。前例の「価値責任者の判断」も、標準のテンプレ4 では書き先の欄を名指していない(注記 :767)。準拠テンプレートでの置き場(節「ゲートでない判断の記録」に倣う節)は、IMPL-0954 の note で準拠テンプレートの項目として開示する
  - (b) 決断の記録を課すと決めるなら、新しい義務なので重へ上げる(R1-1 の (b) と同じ扱い)
  - どちらでも、`lifecycle.md` 2.10.5・`deliverable-templates.md:767`・ADR-0173 決定3・decision.md §6・IMPL-0954 の note の5か所を同じ文に揃える。直した後、lint:impl と impl:write を流す
- 2巡目の後の扱い: 表示(新しい義務を課さない)と実態(5.7.1・5.7.2 の規律が及ぶ)が食い違う高なので、巡の数に関わらず直す。直しの確認は、上の5か所の文の一致と、5.7.1・5.7.2・テンプレ4 の節見出しが変わっていないことだけを見ればよい
