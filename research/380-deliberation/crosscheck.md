## 高

### H-1 (A) の受け皿のレビューの本文を、書き込みの権限を持つ判定される側が書き換えられる可能性を、コードが確かめていない

- 所在: `template/scripts/gate/material-attribution.mjs:53-59`(`declarationOf` は本文の 1 行目だけを読む)、`:82-105`(`exceptionReviewBacking`)、`:112-132`(`stopReviewCandidates`)。`template/.github/workflows/gate-g5.yml:336`(jq が取り出す欄に編集の有無・編集者が無い)。`src/content/docs/phase4-process-design/gate-criteria.md:151-` EV-0220
- 根拠: GitHub の公式文書(「Managing disruptive comments」)は、書き込みの権限を持つ者が issue・PR・コミットの他人のコメントを編集できると書いている。PR のレビューの本文が含まれるかは実機で確かめていない。含まれる場合は、判定される側 X が、記名者 Y が先頭のコミットに出した既存のレビュー(G-6 の承認の本文など)の 1 行目を `例外承認: D-012` や `停止の解除: 解除` に書き換えられる。書き手は Y、対象のコミットは先頭のままなので、(A) の条件 1〜6 をすべて満たして通る。GraphQL の `lastEditedAt`・`editor` で編集を検出できるが、検査は読んでいない。EV-0220 はこの前提を E0 として開示しているが、本文(第4章・第5章)と IMPL-0413 は (A) を「記名者本人の操作」として delivered machine で表示している。開示されていても、受け皿の既定の経路の前提が崩れる可能性がある
- 見立て: 裁定 R-2 の (A) の条件に「本文が書き手以外に編集されていない」が無い。裁定の側の欠落を、実装がそのまま引き継いだ

### H-2 (B) の「作成者の経路」は、記名者の PR に他人が積んだコミットも記名者の操作に数える。品質監査 F-1 と同じ前提で、名前を借りる経路が残る

- 所在: `template/scripts/gate/material-attribution.mjs:175-177`(`info.author` は PR の作成者。行を入れたコミットの author・push した者は見ない)、`:222-226`(`ghHosting` が取るのは `pr.user.login` だけ)。`gate-criteria.md:120`

### M-5 「判定の材料」の語が第1章 1.4 の定義と衝突する。新しい語を2つ足している

- 根拠: 1.4 は判定の材料を「判定者が、判定基準の確認方法として読む記録」とし、例に G-3 の判断記録と G-7 の運用引き継ぎ文書を挙げ、「判定の材料を、判定の証跡に数えない」とする。第4章の閉じた列挙は、例外承認・停止の解除・層1・D-0・前倒しで要る SG を「判定の材料とする記録」とし、列挙に無い記録を判定記録とする。基底ブランチへ入る判断記録・引き継ぎ文書は列挙に無いため判定記録に分類され、1.4 の「判定の材料を判定の証跡に数えない」と逆になる。また列挙した記録の多く(停止の解除の様式、SG の判定記録)は様式としては判定記録そのもので、働き(機械の検査が読む)で区分している。さらに「転記の確認」「帰属の確認」を太字の新しい語として導入しており、裁定と ADR-0106 が理由に挙げた「語彙を増やさない」と合わない。どちらも 1.4 に無い

## 5. 回帰の試験の材料

- `scripts/regress/lib/bin/gh`: `gh api` の3つの形を `$MOCK_PRS` のファイルで返す。ファイルが無ければ後段の `[]` に落ちる(注記どおり)。`commits/<sha>` の代役が `[]` を返すと `verified: false`・`authorLogin: null` になり、数えない側へ倒れる。ファイルの mode は 100755 のまま。Linux で落ちる要素は読んだ範囲では見当たらない
- `t288.mjs`: PR の時点の検査に渡す `hosting()` が、既定ブランチの全コミットを「acct-1〜3 が承認した PR #70」に写す。既存の場面(権限者でない・AI の名義・申し立ての前の日付など)は元の理由で落ちるため、試験の意図は変わらない。代わりにこのファイルでは帰属の照合が常に満たされ、照合が数えない側へ倒れることは試験していない(テンプレート側の試験が受ける)
- `t288b.mjs`: `import` の間に `const` を置いているが、ESM の `import` は巻き上げられるため構文上は問題ない。`prsDir` は使う前に定義されている
- `verify-n.mjs`: 外部の承認者に `accounts: ['ext-acct']` を足した。N6 の意図(名簿の外部の人が承認した者)は保たれる。2 回目の台帳のコミットで D-001 の行は変わらないため、`-G` は D-001 を1回目のコミットに帰す(代役の PR #50)。D-002(承認した者が空欄)は帰属の照合より前の理由で落ち、意図どおり
- 3 本とも **実行で確かめていない**(Windows の制約。冒頭)。t288 の PR の時点の場面で、権限者のアカウントが acct-1〜3 の外にある場面があれば落ちる。CI(Linux)の結果で確かめる必要がある
