# 会議体の議題(#380 判定記録だけの PR に GitHub のルールセットが課す1件の承認)

入力: Issue #380、`survey-380-1-internal.md`(内部)、`survey-380-2-external.md`(外部)。

## 前提として確かめた事実(要旨)

- 第4章「判定記録を基底ブランチへ入れる操作」は、判定記録だけのコミットを基底ブランチへ入れる操作に、記名者以外の承認を課さない(ADR-0070、EV-0111)。IMPL-0124 は undelivered
- 記録の大半は条項を満たしている。様式と写しは記録用ブランチ `records` へ承認なしで入り、出荷の PR がまとめて基底ブランチへ運ぶ。承認 1 件が残るのは、出荷の PR、例外承認の台帳、停止の解除の記録の 3 つ(`template/.github/rulesets/README.md:85-93`)
- 台帳と停止の解除は records へ移せない。`check-pr.mjs` が既定ブランチの先端から読むため(`check-pr.mjs:7,981`)
- **残る承認 1 件は、判定される側が自分の例外や解除を書き足して PR を通す経路を事実上塞いでいる**。PR の時点の照合は名前だけで、台帳の行は IMPL-0128 の照合の対象外。条項を字義どおり降ろす案(パス単位の免除、bypass、records への移設)は、どれもこの統制を外す
- 新しい穴(H-1): 出荷の PR について「開くのは出荷判定者、承認するのも出荷判定者本人」と書いているが、GitHub では PR の作成者は自分の PR を承認できない(`rulesets/README.md:79,81`、`ship-evidence.yml:245,257`、`template/README.md:142`)
- 1 名と外部確認者の体制では、AI が本人のアカウントで動く限り、3 種の PR すべてに外部確認者の承認が要り、ADR-0070 が解消したはずの「中身を見ない承認」が残る
- ルールセット: `team.json` は承認 1 件・`require_code_owner_review: false`、bypass_actors 無し。CODEOWNERS の該当行は雛形のままで誘導層も既定では効いていない
- その他のずれ: 直接の push を止めるルールセットと ADR-0057:509「層1 の改版に PR を課さない」の食い違い(H-4)。集約の RECORD_PATHS が層1・D-0 まで含み条項より広い(H-5)。EV-0111 の差し替え条件が書き換えだけを数え追記を測らない(H-6)
- 外部: GitHub にパスごとに承認件数を変える公式の手段は無い。`required_reviewers`(2026-02 GA)はパスごとにチームの承認を足せるが、ユーザー所有のリポジトリでは使えない。「一律 0 + パス条件で 1 件を足し戻す」構成は理屈の上では組めるが公式の記述も検証も無い。bypass はアクター単位でパスを見ない(exempt は監査記録を残さない)。Actions・App の承認が件数に数えられるかは確かめられない。Azure DevOps・GitLab・Gitea にはパス単位の承認規則・免除がある
- 内部調査の有力案 a3: 例外承認と停止の解除の受け皿を、対象の PR 上の記名者本人のコメントレビューへ広げる。作成者本人でもコメントレビューは出せる。第4章の受け皿を様式に限る規定と ADR-0070 を改める必要がある

## R-1 条項の向き

- 問い: 「記名者以外の承認を課さない」(ADR-0070)を維持するか、見直すか。残る承認 1 件が自己の例外・解除を止める唯一の人の門になっている事実をどう評価するか。どちらが誤りか

## R-2 例外承認の台帳と停止の解除の受け皿

- 問い: 記録だけの PR を要しない受け皿(対象の PR 上の記名者本人のコメントレビュー、records への移設と既定ブランチの読み方の変更など)を採るか。それぞれで、判定される側の書き足しをどう塞ぐか

## R-3 出荷の PR の承認(H-1)

- 問い: 出荷の PR を誰が開き、誰が承認するか。GitHub の自己承認の禁止との関係。1〜2 名の体制

## R-4 テンプレートの手段と採用者への委任

- 問い: パス条件の required_reviewers・bypass・App による承認など、テンプレートで取れる手段の採否。plan=adopter とする範囲。GitHub 以外のプラットフォームでの扱い(本標準はプラットフォームを選ばない)

## R-5 付随のずれと記録

- 問い: H-4(層1 の改版と直接の push の禁止)、H-5(RECORD_PATHS の範囲)、H-6(EV-0111 の差し替え条件)を本件で直すか。新しい ADR、EV・IMPL、採らない案
