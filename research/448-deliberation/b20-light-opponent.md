## 1. #355 の単位ごと

### U1 台帳の行

**0787 賛成(条件つき)**。F2(返却目安の書き換え)は、範囲の始点と終点の台帳の比較で決定可能である。ただし次を条件にする。

- `exception-expiry.mjs` の `countRangeExceptions` は既に始点・終点の台帳を比べている(L110〜140)。**同じ関数群に足す形**にし、別の始点の取り方を作らない。始点の台帳が読めない(初回・shallow clone)ときは「確認できない」と表示し、欠落にしない
- 「範囲の外の履歴の書き換えは見ない」旨は note に残す。これは根拠水準マークで開示する対象である(表示と実態の食い違いを避ける)
- 期限を**短くする**変更は書き換えだが害は無い。延長だけを欠落にするか、方向を問わないかを裁定すること。方向を問わないと、誤記の直しが欠落になる。**推奨: 延長のみ**(破られて失うのは回収の期限の信頼)

**1008 賛成**。ただし受付の F3 は、`kind === '例外'` だけを見る現状の確認である(L69・78・89・116 で確認)。「類似検知」は別の区分語のため、同じ関数を `kind` の集合で広げるときに**既存の `例外` の件数(`countRangeExceptions`)の意味を変えない**ことを試験で固定する。件数の定義(1.10.2)が変わると、別の指標(0739 の隣)がずれる。

**1009 賛成**。置き場を固定しない判断に賛成。`impl-no-adopter.yaml` の「類似の検知の実施記録」に当たるため adopter にできず、manual で降ろすのは正しい。ただし**manual の delivered は、機械が何も見ないことを意味する**。note へ「機械は実施の有無を見ない」と明記すること。

### U2 開示の表示

**0739 賛成**。件数は決定可能。

**0687 修正**。受付は「出力の文から 7 見出しと成立判定を確かめる関数を足し、欠けを失敗にする」とする。`aggregate-evidence.mjs` の 7 項目の見出しは固定の文字列として出力される(L6448 付近など)。**自分が固定で出す見出しの有無を自分で確かめる検査は、構造上いつも成功する**(恒真)。落ちるのは、出力コードを壊す回帰のときだけで、それは試験の仕事である。標準の「記載の欠落」が指すのは「項目を導く記録が無い」ことで、受付も別の項で「項目を導けない」を扱うとある。

- 提案: (a) 機械の検査は、**項目を導く入力の記録(判定記録・D-0・構成の変更記録・例外承認の記録)の不在**に限る。これは決定可能(存在)であり、標準の文言とも合う。(b) 見出しの確認は試験(`test-aggregate-records.mjs`)に置き、出力の検査としては作らない。(c) note に「項目の中身の妥当性は見ない」を残す
- 失敗の仕方: 「失敗にする」は、記録が無い採用初期の案件で常に落ちる可能性がある。他の記録の欠落と同じく gaps に数え、止める基準は既存の基準9 の扱いに従うこと

**0631 賛成**。試験の追加のみ。実装は規定どおり(F7)。

**0755 修正**。空欄を欠落にしない(ADR-0127 決定7)点に賛成。しかし次を確かめること。

- 様式 08 の価値責任者の行(L125)は「発注側の氏名。受注側の人を書かない」と指示している。ここに「置かない」という**自由な語**を許すと、氏名の欄に語が入る。値の語彙を**閉じた 1 語**(例: 「置かない」)に決め、それ以外の語を氏名とみなす
- 「置かない」にした委託で G-2 を未達と表示することは、**採用者への新しい結果を生む**(委託の構成で G-2 が常に未達になる)。標準の文は「置かない委託は G-2 を受注側の判定で代えない」で、未達の表示を求めている。ここでは新しい義務ではなく既存の義務の実装と読めるので軽でよいが、**既存の案件の構成が「置かない」を書いたとき、G-2 を未達とする代わりに第7章の例外承認で受ける道があること**を手引きに 1 行書く(判断軸 2)

### U3 第7章の行使

**0628 修正**。分け方(要求事項 2・4・5 を機械、1・3 を manual)に賛成。しかし受付は「制限の範囲に触れて承認が足りない変更に対応づく行は、識別の語なしで 7.9.4 の行と決まる」とする。

- 提案: 対応づけは**既存の例外承認の対応づけ(変更の識別・対象)**を使い、7.9.4 に当たる条件は「制限の範囲(`restrictionHit`、`config.mjs` L1760)に触れ、独立した人の確認が 2 名に満たない」とする。これは決定可能で、識別の語は要らない。成立しないなら、**識別の語は 0612 とは別に**、既存の印(下記)に揃えて置く

**0669 修正**。「枠の消費の件数と残り」は 0628 の対応づけの精度に依存する。**誤検知で枠が減って見える表示は、現場に枠の過少申告か不信を生む**。表示は止めない点に賛成。件数の横に「対応づけは 0628 の条件による」と添えること。

**0612 反対(取り下げを求める)**。これが本件で最も重い指摘である。

- 受付は「区分『例外』の行の『受容した理由』の先頭に識別の語 `ファストトラック:` を置く」とする。しかし B18 の取り込みで、**`templates/03-debt-ledger.md` L94 は既に「内容の先頭の印 `ファストトラック(短縮: <ゲート>)`」を定めている**(ADR-0200 決定2)。`check-pr.mjs` L744〜782 は、その印を正規表現で読み、IMPL-0567(限定列挙)・IMPL-0610(未回収の間の再申請の拒否)を delivered / machine で実装している(実際にファイルを読んで確認)
- つまり**ファストトラックを見分ける手段は既にある**。受付の「見分ける手段が無い」は、B18 の取り込み前の状況である。新しい語を置くと、同じ概念に印が 2 つでき、片方だけを書いた行が 0612 の指標と 0610 の拒否のどちらかで見落とされる。受付は「#445 の IMPL-0610・0567 が使える」と書くが、その 2 つは**既に別の印を使っている**。受付は前提の状態を誤っている
- 提案: 0612 は**既存の印**を数える。発生率・回収完了率は台帳から決定可能。**適用後の欠陥発生率**は「欠陥の台帳の『原因の変更』で結ぶ」とあるが、原因の変更の記入は任意であり、記入が無いと欠陥 0 に見える。これは**測定の誤り方が楽観側に偏る**ので、率の表示には必ず「結び付けた欠陥の件数と、原因の変更の欄が空欄の欠陥の件数」を併記する。併記できないなら、欠陥発生率は manual にして機械では出さない
- 新しい語・新しい欄・新しい区分を足さないという受付の自己の方針(8 節)とも、新しい語の導入は矛盾する
- ADR-0217 の「識別の語」の項は不要になる。ただし「測定の定義を決める」という項は要る

### U4 判定記録

**0667 修正**。

- 受付は 7.7.5 の表に欄「不合格の必達基準の番号と通算の回数」を足すとする。しかし**様式にはすでに「7.7.5 の回数」の欄がある**(`04-gate-record.md` L239〜242。必達基準2 の回数)。標準 7.7.5 要求事項 4 は「必達基準の番号ごと」と言い、現在の欄は必達基準 2 だけを運ぶ。ここは**欄の拡張が要るかどうかの実質的な判断**で、編集では済まない。対象を必達基準 2 だけに限る(丙・乙の継続・保留。SC-M の縮小は数えない、等の標準の詳細が必達基準2 だけにあるため)のか、全必達基準に広げるのかを裁定すること。広げると**様式の必須欄が増える新しい義務**に近い
- 「3 を超える記録を欠落にする」は、**判定者が書いた数字を信じる検査**である。数字を 0 や 1 と書けば通る。機械で閉じるのは「書かれた値が 3 を超える」ことだけで、数え直さないこと(標準の本文)は閉じない。受付は note に書くとしているが、それでは**表示が「3 回を超える継続を拒む」ように読める**。表示と実態の食い違いを避けるため、**根拠水準マークで開示する**か、検査の文を「書かれた回数が 3 を超えたとき欠落」と正確に書く
- 追加の提案: 前回までの記録の回数と今回の回数の**差が 1 でない**(増え方の飛び・減少)ことは、同じ必達基準の連続した判定記録の比較で決定可能。数え直しの防止には、こちらが有効である。ただし過剰な検査にならないか検討すること(採らないなら、その旨を明記)

**0622 修正**。IMPL-1022 の先例に揃える点に賛成。記録の有無と経過を表示し止めない設計は、出荷の基準でない点で正しい。分けた manual 側(実施者の独立と合否の中身)の確かめる者を「内部監査」とするが、**小規模な構成には内部監査の席が無い**。その場合の確かめる者(第三者の席の無い構成)を note に書くこと。

**0638 修正**。任意の欄にする点、全席を暫定とみなさない点に賛成。

- 「期間内の判定で併記が無ければ未達と表示する」は、**D-0 の暫定任命の表(L334)の期間の欄の書き方**に依存する。期間の欄が日付として読めない行(自由文)の扱いを決めること。読めない行を暫定と数えない場合は、未達が表示されない方向に倒れる(安全側ではない)。**読めない行は「確認できない」と表示し、欠落にはしない**(0523 と同様に)のが整合する
- 「確認済みの者」は力量の記録で確かめた者を指す。その者が**実在の名簿の人か**は機械で見られるが、確認済みであることは見られない。自己申告になる点は開示すること

**0523 修正**。

- 受付は「状態の行を除いた本文を、判定した版と範囲の先端で比べる」とする。比較の対象となる「判定した版」は G-3 の判定記録の `版` 欄(L19)で、コミット SHA かどうかが様式で保証されているか(自由文のとき読めない)を確かめること。**読めないときは未確認と表示して欠落にしない**とする案に賛成
- 誤検知: (1) 保管領域への移動(`adr-write` L95 が両置き場で読むとする点は妥当)。(2) 状態の行の形が旧様式(`## ステータス` の節の最初の行。`check-decisions.mjs` L47 の注)のとき、除く範囲を誤ると差が出る。(3) 誤字の修正や整形も「書き換え」になる。標準の「書き換えない」を字義どおりに実装するなら、これは欠落でよいが、**運用では誤字の直しが G-3 の再判定を要する**ことになる。それが標準の意図かを確かめ、意図でなければ「意味を変える差」の定義が要る(これは機械では閉じない。その場合は manual)
- **提案**: 機械の検査は「状態の行を除いた本文の文字列が、判定した版と範囲の先端で完全一致しない」ことを**注意(欠落ではなく所見)**とし、止めない。ADR-0136 は同種の判断記録の再検査を「文字列の一致で見て、ずれの申告は人が行う」と決めた先例で、これに揃える。止める検査にするなら、誤検知率を実在の ADR 履歴で測ってから決めること

## 2. #448 の軽

**1015 修正**。設問の追加(Q1)は設問数を変える(8 問 → 9 問)ため、**既存の構成の扱い**が問題になる。受付は「回答の無い既存の構成を『いいえ』と見なさない」とする。それなら**未回答の構成はどう表示され、何を止めるか**を決めておくこと。未回答を「確認できない」と表示して止めないのか、`check-d0` を落とすのか。落とすなら、既存採用者の初回の push が一斉に落ちる。止めるなら移行の猶予(1 サイクル)を設計すること。また README・SKILL の「8問」の改訂漏れは `npm run check` で拾えるかを実行で確かめること。

## 5. 全体への指摘

1. **受付の「確認」の限界**: 受付の F1〜F10 のうち、F2・F3・F5 は探針の実行、他は読みである。私はこの審議で再実行していない。**実装の段で、各 `machine` 件に ng/ok の対の試験を置く**という受付の申し送りに賛成するが、ng の試験が**実際に落ちること**(試験が恒真でないこと)を、実装のコミットの前に 1 件ずつ確認すること
2. **B18 取り込みの影響**: 受付は B18 の取り込み前の template を読んだ箇所が多い(0612 が典型)。B18 の差分に入った他の変更(印・欄・関数)で、受付の「現状」の欄が古くなっていないか、**実装の前に全 29+21 件の現状を再読する**こと

## 6. 重へ上げるべき点

1. **0683 の置き場**(新しい設定のキー か 区分「例外」の行か)。上の分析のとおり、**新しい設定のキーは採用者に新しい義務(期限つきの許可を設定に書く)を生む**。ただし採否が割れるのは、ADR の原則の変更ではなく設計の選択である。軽の 2 委員で割れたら議長が裁定し、採らない案を記録する。重へ上げるのは、議長が「例外の台帳に載せる」を採り、**ライセンスの許可を第7章の例外承認で受ける**ことが標準の語彙(7.3 の例外承認の対象)を広げると判断した場合に限る
2. **0743/1019 の `unknown` の読み**。「版を特定できない実行の出力を監査の入力に用いない」の**範囲**(未コミットの変更を含むか)を決めることは、監査の母集団を変える。安全や取り消せない操作ではなく、適合の主張の信頼に響く。**母集団が空になる読みを採るなら、新しい義務の変更に当たる**ので重へ上げる。語を分けるだけで足りるなら軽のまま

それ以外は軽でよい。0667 の対象を必達基準 2 に限るか全必達基準に広げるかは、広げる場合だけ**様式の必須欄の増加=採用者への新しい義務**に当たるため、議長が広げると裁定したときは重へ上げる。
