## 議題 1 IMPL-0738 未達のまま出荷が止まらない穴

**結論**: 機械の検査を採る。出荷の証跡の集約が、案件の CL が 1 以上か規制業のとき、構成の `unmet`(未達のゲート)が 1 件でもあれば**記載の欠落**に数える。欠落の文に、未達のゲート名と、解く道(未達の解消。体制の回復か `/process-change` による構成の更新)を書く。CL0 かつ規制業でない案件は止めず、保証の開示への表示と G-8 の受容の記名のまま(現状どおり)。マークは delivered / machine / `test-aggregate-records.mjs`。試験は CL0・CL1・規制業 × 未達の有無の対を置く。

**理由**
- 条文(`tailoring-guide.md` L118)が「出荷しない」と明文で定める。実装が欠けているので、穴は条文でなく実装の側(Q3: 安全重要度が高い案件が未達の統制のまま出荷し、適合の主張の信頼が崩れる)
- 決定可能な条件(CL・規制業・`unmet` の有無)だけで閉じる。AI の判断が入らない
- 集約は既に `unmet` を適合の主張の妨げに数えている(`aggregate-evidence.mjs` 系の `blockers`、config.mjs L293)ので、主張は止まるのに出荷は止まらない、という食い違いを解消する
- 範囲は「`unmet` のすべて」とする。表の見出しは体制の縮小の文脈だが、`unmet` は構成が持つ唯一の未達の表現であり、種類で分ける根拠が条文に無い。この読みは**暫定**。根拠水準マークで開示する(`:::caution[暫定 EV-NNNN / 見直し YYYY-MM]`)

**採らない案**
- 欠落でなく表示だけにする: 条文の「出荷しない」を満たさない
- 「未達のうちリスクを評価していないもの」だけを止める(外部の先例の型): リスク評価の機構が本標準に無く、新設になる。新しい義務を課す設計であり、判断軸の「安さ」ではなく根拠の欠如で退ける
- 7.3 の例外承認で CL1 以上の未達を出せるようにする: 7.3 は R1 の変更の扱いで、表の 3 行目と役割が違う。逃げ道を足すと明文の「出荷しない」と矛盾する。珍しい構成で止まって困る場合は、`unmet` を解く(体制を満たす)のが正規の道
- 既存の案件への猶予期間: 猶予は新しい条項になる。F4 のとおり CL1・3〜9 名・スタック未確定の構成で G-3 が未達になるなら、その構成は条文のとおり止まる。**これが典型の初期状態でないかは未確認**。議長は裁定の前に、実際の `unmet` の導出条件(どの構成で未達が出るか)を 1 回確かめてほしい。典型の初期状態で止まるなら、実装でなく `unmet` の導出か軸E の選択肢側を直す別件になる

**機械で閉じない点の開示**: `unmet` が正しく導かれていること(構成の正しさ)は閉じない。構成の導出は別の統制(IMPL-0349 ほか)が持つ。マークの note に「構成が偽なら止まらない」と書く。粒度が欠陥ごとのリスク評価より荒いことも note に書く

**矛盾の検査**
- `tailoring-guide.md` L113-121 の表と整合(実装を足すだけ)。実在を確かめた
- 第8章の軸E「人員が足りない場合」: 条文は軸E の選択肢に従うとする。選択肢の内容(出荷しない側)を本文で確かめていない。**未確認**
- ADR-0092 決定7(未達の表示を続ける): 表示は続けるので両立するはずだが、本文は未読。**未確認**
- 回帰: `shipBlocked`・IMPL-0450 の既存の止める経路と重複しても、欠落は集合なので二重に数えない設計にする

## 議題 2 IMPL-0498 層の合わさりの承認の数え方

**結論**: 受付の案を、次の限定を付けて採る。
- 検出の式: 基底が既定でない写し X の `merge_commit_sha` が、既定へ入った PR Y の `head_sha` の祖先で、**かつ X に層ごとの有効な承認が無い**とき、Y を「層ごとの確認あり」に数えない
- 祖先を読めない(履歴が浅い・取得できない)ときは**未確認**と表示し、欠落にはしない(IMPL-0241 と同じ扱い)
- 数えないことの帰結は、G-6 の確認ありの件数が減ること。既存の G-6 の欠落規則がそのまま効く。新しい停止を足さない
- rebase の見逃し(中間の層の取り込みの後に Y を rebase する)は式で閉じない。**閉じたと書かず、根拠水準マークと note で開示する**。マークは delivered / machine / `test-aggregate-records.mjs` + 暫定 EV
- 手引き(`gates/G-6.md`)に 1 文を足す: 手動のスタックの層は、層ごとに必須のレビューを掛けた保護を勧める。条文の外の手引きとして置き、義務にしない

**理由**
- Q3: 承認が 1 件で複数の層の確認に化け、未レビューの差分が G-6 を通る。G-6 は人の確認の核で、適合の主張に響く
- 外部調査の確認: GitHub の標準のスタックは各層を基底の規則で評価する。よって式が当たるのは手動のスタック・squash・保護の無い中間のブランチで、標準のスタックに誤検出を出さない。受付の F5 と整合
- SLSA の「承認は文脈に結びつき、別の文脈へ移した内容は改めて要る」と同型。最終版への承認という共通項にも合う
- 承認の有無を式に入れるのは、層ごとに正当に承認された積み重ねを誤って数えなくならないため。決定可能(祖先関係と承認の有無)

**採らない案**
- GitHub の設定が正しければ足りるとして機械の検査を置かない: 外部調査の指摘どおり薄い可能性はある。だが `ship-evidence` の verify は必須でない(F6)ので、設定の誤りを集約が拾う第二の線が要る。信頼性を優先して置く
- patch-id 等の近似で rebase の見逃しを塞ぐ: 決定可能でなく、偽陽性が出る。コアポリシー(機械は決定可能な条件だけ)に反する。却下を明記する
- 祖先を読めないときに欠落にする: 取得の失敗で出荷が止まる。IMPL-0241 の先例に反する

**機械で閉じない点の開示**: (a) rebase の見逃し (b) 承認の有効性の実質(同一人物 3 名の承認は記録つきで受ける既存の決定を変えない。SLSA の「別の人」と緊張するが、本議題で扱わない) (c) 保護の設定が実環境で効いているか(adopter の env-check が持つ)

**矛盾の検査**
- IMPL-0250(手動のスタックの承認を層ごとに数えない。delivered / manual)の note が「集約が見ないことは IMPL-0498 が追う」と書く。本案はその空白を埋める。矛盾しない(`gate-criteria.md` L2403 で確認)
- `b3-decision.md` 1.3 の「base.ref だけでは区別できない」は、祖先関係と承認の有無の併用で解く。b3 の本文は未読で、受付の記述による。**未確認**
- IMPL-0248・0254(中間の層へのマージの拒否)は予防、本案は事後の検出。重複でなく補完

## 議題 3 IMPL-0990 G-3 の表と機械で閉じない検査

**結論**: 受付の案 C を採る。`gate-criteria.md` L634 の行を「前の判断記録と記述が一致している | しない | 判定する」に改める。人の判定の手順は G-3 の補助ファイル(`gates/G-3.md`)に 1 文: 判定者は、置き換える・一部置き換える判断記録を、置き換えられる側の記録と並べて読み、事業影響の記述が食い違えば理由を判定記録に書く。マークは delivered / manual、確かめる者は技術判断者(G-3 の判定者)。L642 の「降りていません」の文と IMPL-0132 の note の「前の記録との一致は IMPL-0990」を、「機械では見ない(課さないと決めた)」へ直す。

**理由**
- 同じ表の L627 が引く第5章 5.7.4 は「記述の質を機械判定して承認可否を決めてはならない」とする。一致を失敗にする案 A は、この規定と直接ぶつかる
- 定義と閾値に根拠が無い。全部を置き換える判断記録は正当に同じ影響を書くため、一致は欠陥でない。外部調査も、類似度・一致の閾値を合否に使う先例は無く、候補の絞り込みと人の確認の型が実務と見る
- 表と実態の食い違い(表は検査すると言うが検査は無い)が現状の欠陥。これを解消するのが最小の目的で、読み手が「書かれていない」と「課さない」を区別できる状態にする(コアポリシー)
- Q3: 破られても失うのは判断記録の整合の質で、安全や取り消せない操作でない。細かく書く場面でない

**採らない案**
- 案 A 一致を失敗にする: 5.7.4 と衝突し、閾値に根拠が無い
- 案 B 所見として出す: 読まれる保証が無い(IMPL-1022 の経緯、外部調査)。読まれない出力を足すことは、変わらない表示は読まれないという既存の知見に反する。機械が候補を出して人が読む型は魅力だが、出力の消費者が決まらないまま足さない。**将来、消費者(判定者の必須の項目)を決める別議題で再訪できる**ことは記録に残す
- 現状維持(undelivered のまま): 表が検査すると偽る状態が続く。disclosure として弱い

**機械で閉じない点の開示**: 人の判定が実際に行われたかは機械で閉じない。manual の確かめる者を記名する。手引きは義務の追加でなく、既存の 5.7.4 の人の判定の具体化にとどめる。根拠水準マークは不要(新しい値を置かない)。ただし「人が並べて読めば食い違いを拾える」ことの実証は無いので、記録の欄に 1 行、暫定の旨を note に添える

**矛盾の検査**
- `b1-decision.md` 1.2 の7 は所見の案を出したが実装していない(受付による)。本案はそれを採らないと記録する形で、決定の取り消しでなく未実施の案の却下。本文は未読。**未確認**

## 議題 8 IMPL-0925 故障挿入の環境

**結論**: 受付の案を採る。表の「挿入した環境」の列を、「試験台の実機」「模擬環境」「専門部門の設備」「実行前の挿入」のいずれかで**始まる**語に限り、それ以外(空欄・上記以外)は欠落にする。ただし、様式 L188 の列の見出しは「実行時・ハードウェアによる挿入のとき」の条件つきなので、**条件に当たらない行(実行前にコードを変える挿入)の空欄を欠落にしない**ため、語彙に「実行前の挿入」を入れて明示させる。つまり空欄の扱いは「どの語も無ければ欠落」とし、行が実行時かどうかを機械が判定しない。delivered / machine。

**理由**: 本番や稼働中への故障挿入は危険事象を起こしうる(Q3)。値の語彙の一致は決定可能。外部には本番への挿入を禁じる条文が無く、E0 のまま。本標準が足す規定なので重の対象

**採らない案**: 本番でないことを機械で確かめたと表示する(語の一致までしか閉じない)。語彙の先頭一致でなく自由文を読む(閉じない)。列を必須にして条件を外す(条件に当たらない行を不当に落とす)

**開示**: 「実際に本番でないこと」は閉じない。manual とし note と EV-0296 に明記する。検査の合格を「本番でない」と表示しない。確かめる者は G-7 の判定者

**矛盾の検査**: 様式の L201 の「挿入した環境は、試験台の実機・模擬環境・専門部門の設備の別と識別を書く」と語彙が揃う。語彙の「実行前の挿入」は様式の注記に追加が要る
