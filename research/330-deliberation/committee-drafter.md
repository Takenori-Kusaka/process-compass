# #330 起案委員の意見

日付: 2026-11-17。立場: 起案。読んだ実物: intake.md、gate-criteria.md L996-1022・L1631-1642、template-repository.md L856-870、exception-escalation.md 7.3(L50-75)。template/ は未取得で、テンプレートの挙動は実行していない(intake の「確かめていないこと」と同じ)。

## 0. 結論(先に)

- **新しい義務は課さない**。採る案は「保証の開示 項目4 に、未実施の検査名と継続期間を併記する」だけ。項目6 の既存の型(L1633・L1642)の適用範囲の拡張で、人に新しい記述を書かせない(L1640 の「既存の記録からの投影」)。軽で足りる
- 「実装の開始後に空コマンドを失敗にする」は採らない(新しい義務。重の条件に当たる)。反対委員がこれを推す場合は、割れた点が新しい義務なので、議長は重へ上げる
- 例外承認(7.3)は、この案では**要らない**。7.3 の対象は「満たさない判定基準」(L60)。未実施は現行で失敗ではなく通過なので、承認で受ける相手がいない。受けるのは「項目4 に出る」ことそのもの。ここは intake の見立て(例外承認で受ける)を修正する(論点2)

## 1. 論点 A: 実装の開始後に続く未実施

### 1.1 現状の欠けの特定

- 空の任意検査が通ること自体は設計どおり(ADR-0028・0033、L1684 の「未達・未測定は受け入れる」)
- 欠けは**可視化の強度**。項目6 は「未測定が続く期間」を併記するのに、項目4 は「未実施と通過を区別する」(L1631)で止まる。出荷判定者(G-8)が、未実施が何出荷続いているかを読めない
- 破られたとき(方針3): 失うのは出荷判定者と事業決裁者。基準2(Critical/High 0 件、L733)が、空の lint で「0 件」と読まれ、適合の主張が「検査したことになっている」状態になる。失う中身は適合の主張の信頼であって、安全ではない(安全に直結するテスト・秘匿情報は既に失敗)。よって、結果として足りるのは「未実施が 0 件の合格と区別でき、続いていることが見える」まで

### 1.2 変える文の案

**(a) gate-criteria.md L1631(項目4 の行)**

現行: `機械検査の結果。未実施と通過を区別する`

案: `機械検査の結果。未実施と通過を区別し、未実施の検査は検査名と、未実施が続いている期間(最初の出荷からの経過)を併記する`

**(b) gate-criteria.md L1642 の直後に1行足す**

案: `- 項目4 が「未実施」の検査は、未実施が続いている期間を併記する。未実施は正当な値(探索段階や、検査の道具が無い構成)だが、続いていることを見えるようにする。値の良否では差し戻さない`

- 「期間」の起点を「最初の出荷」に揃えるのは、項目6 と同じ決定可能な条件(証跡の日付の存在)にするため。「実装の開始」(SG-0)の判定を機械に任せない。SG-0 の通過の記録を使う案は、記録の形が検査の入力として定まっていないので採らない(論点4)
- 「基準2・5 の件数は、静的解析が未実施のとき、0 件ではなく未実施と読む」旨は、(a)の「未実施と通過を区別する」で既に足りる。重ねて書かない(重複)

**(c) template-repository.md L862・L866(編集。意味を変えない)**

- 表の行を分ける。「静的解析・依存監査・ライセンス検査・依存の導入」は現行どおり未実施で通過。「カバレッジ」は別の行にし、「製品のコードが無い間は対象なしで通過。言語のアダプタで記録が出ないときは失敗(G-5 基準3、ADR-0124 決定1)」と書く
- L866 の注意書き(:::caution)に1文を足す案: `未実施の検査は、保証の開示 項目4 に、続いている期間とともに出ます。`
- カバレッジの行の分割は、intake の A-3 のとおり編集に当たる見込み。ただし「製品のコードあり/なし」の境は coverage-check.mjs の挙動で確かめてから書く(未確認。確かめずに書かない)

### 1.3 既存の条項・ADR との矛盾

- ADR-0033 決定6(歯止め=対象なし)・ADR-0028・ADR-0124 決定1: 矛盾しない。いずれも「未実施を失敗にしない/測れないものを通さない」の線引きで、本案は線を動かさず表示だけ足す
- L1004「実装が存在する段階で、この扱いを用いてはならない」: 対象は**対象なし**の記録。本案は未実施(対象の有無を確かめていない、またはコマンドが空)を扱い、範囲が違う。ただし利用者が混同しうるので、(b)の文に「対象なしとは別」と書き足すかは会議体で決める(私は書かない側。L1010-1018 の表が既に区別している)
- 観点16(assurance-case.md:273): 文言に既に「未実施が通過として集計」が入っている。変えない。「未実施にも当てるか」への答えは「既に当たる文言。新設しない」
- 項目の追加は「差し戻すのは記載の欠落だけ」(L1641)と整合する。併記の欠落は差し戻す、値は差し戻さない

### 1.4 IMPL-0234・IMPL-0239 の state

- **IMPL-0239**(対象なしの通過): 内容を2つに分けて扱う
  - 「実装の開始後に対象なしを用いない」は、IMPL-0475 が目印のある場合を delivered にしている。残るのは「目印を持たないコード」。これは機械では決められない(コードか否かの判定)ため、**undelivered のまま残し**、note に「目印を持たないコードは機械で検出できない。人(出荷判定者)が項目4 の継続期間を読んで確かめる」と書く。state を delivered にしない(表示と実態の食い違いを作らない)
  - 「記録の3項目(基準・理由・時刻)を証跡へ残す」は、template の項目(論点 T-3)で実行して確かめる。確かめて合えば、その部分を別の IMPL に分けて delivered(check=machine)にする。確かめられなければ undelivered のまま
- **IMPL-0234**(任意の検査が空のとき通知して通す):
  - 「通知を出して通す」は、項目4 に未実施が出る(T-1)で届く。試験を足したら check=machine の delivered へ。note は「通知」から「証跡と項目4」へ改める
  - 「依存の取得失敗時に各検査器が失敗で終わるか」は別の事柄。IMPL を分け、確かめるまで undelivered を表示し続ける。この Issue の範囲で確かめきれないときは、既存の open Issue へコメントで足す(新規起票しない)
- `issue=330 review=2027-04` は、降ろす先が決まった分だけ更新し、`npm run impl:write` で台帳を再生成する。台帳は手で編集しない
- 降りていない規定を消さない。上の2つを delivered にするのは、実行での確認ができたときだけ

## 2. 例外承認(7.3)で受けられるか(方針2)

- 受けられない、が正確。7.3 は「満たさない判定基準」の逸脱を承認する(L60)。空の lint を通すことは現行の規定の範囲内(基準の未充足ではない)なので、例外承認の対象ではない。ここに7.3 を持ち込むと、全採用者に「未実施を続けるたびに承認」を課す新しい義務になる
- 7.3 が効くのは、**将来**「継続が N 出荷を超えたら G-5 を失敗にする」を採る場合の逃げ道。本案はそれを採らないので、7.3 は触らない
- 方針2の問い(新しい条項を足さずに受けられるか)への答え: 条項の新設はせず、既存の項目6 の型(L1642)と同じ形の1行を足す(1.2 b)。これを「新しい条項」と数えるかは議長の判断に委ねる。私は、既存の型の適用範囲の拡張で、採用者の義務(人が書くこと)は増えないと考える。増えるのは集約(機械)の出力のみ

| 案 | 採らない理由 |
| --- | --- |

## 6. 根拠水準マークが要る箇所

- 1.2(a)(b)の併記そのもの: 「続いている期間を見せれば出荷判定者が気づく」という前提は、実証が無い(項目6 の型でも同様)。既存の項目6 のマークがあれば、それに束ねる。無ければ `:::caution[暫定 EV-NNNN / 見直し 2027-05]` を項目4 の併記に付ける。E0(なし)、単一の設計判断で、運用で気づかれた事例は無い、と書く
- 採らない案のうち「N 出荷」は、閾値を採らないので EV は要らない。ただし条項に「閾値を課さないと決めた」と1文で明記する(「書かれていない」と「課さないと決めた」の区別)
- マークを足したら `npm run evidence:write`、IMPL を足したら `npm run impl:write` を実行する

## 7. 反対委員の争点への備え

- 「表示だけでは形骸化する」への答え: 未達・未測定を正当な値とする設計(L1641)の下では、可視化が唯一の統制で、項目6 も同じ。形骸化を理由に失敗へ上げるなら、項目6 も同じ扱いになり、ADR の原則の変更になる(重)
- 「SG-0 の後は失敗にすべき」への答え: SG-0 の判定を機械が閉じられない。閉じられない統制を機械の検査にしない(CLAUDE.md の統制の閉じ方)
- 議長の裁定でどちらを採っても、割れた点が新しい義務なら重へ上げる
