## 4. 論点ごとの答えの案(所有者の方針 2026-11-16 の 3 つの問い)

### 論点 A: 実装の開始後に続く未実施
(1) 条文は結果と証跡まで。条文に書く候補: 「SG-0 を過ぎた後、任意の検査が未実施のまま続く場合は、その検査名と未実施の継続期間を保証の開示 項目4 に併記する」。手順(どのコマンドを足すか、各言語の lint の選び方)は手引き(template-repository.md)へ
(2) 珍しい構成(lint の道具が無い言語、社内の閉じた道具)は、新しい条項を足さず、第7章 7.3 の例外承認で受ける。例外承認は期限と回収責任者を持ち、期限切れで効力を失う(exception-escalation.md:62-63)。これは未実施が期限なく続くことへの既存の歯止めそのもの。**「未実施を続けたい」は例外承認、「道具が実際に存在しない」は省略(テーラリングの宣言)**で受けられる見立て
(3) 破られたとき: 誰が失うか。出荷判定者と事業決裁者が、未実施を知らずに受容する。基準2(Critical/High 0 件)が空の lint で 0 件と読まれ、採用者の適合の主張が「検査したことになっている」状態になる。失うのは「適合の主張の信頼」。安全に直結する検査(秘匿情報・テスト)は既に空を許さない。よって細かく書くべきは「未実施を 0 件の合格と区別して見せる」ことだけで、空を失敗にする義務までは要らない見立て

条項を足さずに受けられるか:
- 受けられる部分: 珍しい構成(例外承認)、実装の開始の判定(IMPL-0475/0476 が既に失敗にしている範囲)、観点16(文言は既に未実施を含む)
- 足りない部分: 項目4 の「未実施が続く期間」の併記。ただし項目6 の既存の型の転用で、新しい条項というより既存の型の適用範囲の拡張。条項の追加か、項目4 の導出元の記述の追記かは会議体で決める

採らない候補(記録しておく):
- 実装の開始後に空コマンドを失敗にする: 新しい義務で、lint の道具が無い言語の採用者を門前払いにする。例外承認で受けられる範囲を条項が潰す。安全でも取り消せない操作でもない
- 未実施が N 日続いたら G-5 を落とす: N の根拠が無い(EV マークが要る)。値で落とすと形式的な記入が起きる(L1692 の既存の理由)
- 観点16 に「未実施」を新設の別観点として足す: 文言に既に入っている。重複
- 決定 6 を ADR-0033 に遡って未実施まで広げる: 採用済み ADR は書き換えない。新 ADR か本文で扱う

### 論点 B: go・none・undetermined の基準3
- 解消済み。(1) 結果は「未実施として失敗」と条文に既にある (2) 例外は 7.3 で受けられる (3) 破られたときの被害は ADR-0124 が扱い済み。再審議しない。残るのは A-3 の取り残しの編集と、K-8 の「測る範囲(全体か変更か)」の `coverage-check.mjs` の挙動(ADR-0124 決定1 で go・python は変更の範囲まで測る)が、delivered かの確認のみ

## 6. 外部の調査の要否
