## 1. 所見

### X-1 重大 版を発行した後の main が、発行した版の名で配られ、記録される

**根拠**

- `community/standard-editions.md:15` は、作業中の版を「最新の発行の後に変わった内容」と定義している
- 一方で `scripts/lib/edition.mjs:43` の `editionLabel` は、`edition.yaml` の最新の発行の版をそのまま返す。発行の後のコミットでも同じ値になる
- `scripts/build-template-kb.mjs:244` は、知識ベースの `source.edition` に、ビルドしたコミットに関係なく `edition.yaml` の値を書く
- `ci.yml:184-188` の `VERSION.md` も同じ。第1版を発行した翌日の main は、`VERSION.md` で「第1版(… 発行)」、知識ベースで `source.edition: 第1版` と名乗ってしまう
- テンプレートの `/process-change` 種別 `edition` は、複製した知識ベースの版と一致すれば受け付ける(`template/scripts/init/generate-profile.mjs:3670`)。このため、発行の後に変わった規則を複製した採用者が「第1版」に従うと記録でき、そのまま適合の主張の名を得る
- いまは発行が無いので顕在化していない。しかし最初の発行の時点で 1.10.3 の「作業中の版を名指さない」が機械の側から破られ、Q-1 の目的(版が要求の識別になる)を失う

**修正案**

- `edition.yaml` の `history[0].commit` を持つ版にする
- ビルドしたコミットがそれと一致しない場合は、次のように扱う
  - `editionLabel` は「作業中の版(第1版の発行の後)」を返す
  - 知識ベースは `source.edition: null` と `source.basedOn: 第1版` を書く
- または、発行した版を不変の配布物(タグ、または版ごとの配布ブランチ)として固定し、知識ベースの版はそこからだけ立てる
- テンプレートの種別 `edition` は、版と発行のコミットの両方が一致する知識ベースに限る
- `check-gate-criteria` に、上の不一致の検査を足す

### X-2 重大 採用済み ADR の「逸脱」の決定と矛盾しており、ADR-0083 が補う対象として挙げていない

**根拠**

- ADR-0035 の決定2(`adr/0035-separation-by-execution-context.md:86`)は「3 を満たせない体制では、権限の分離を代償措置つきの逸脱として記録します。ADR-0029 の出荷判定者の例外と同じ扱い」と決めている
  - 同じ ADR の 118 行も「権限の分離が逸脱として表示され続ける」と書く
  - 実装はこの離脱を (b) 列挙に無い離脱へ移した(`roles-responsibilities.md` 3.5.3 の表の 3 行目、`overview.md:433`)。これにより、3名以上を含む全規模で主張を妨げることになった
- ADR-0056 の決定5(`adr/0056-assurance-argument.md:96`)は「1〜2名の体制では、兼務を逸脱として記録する」(出荷判定者 × 事業決裁者)と決めている。168 行も同旨
- ADR-0040 の決定3(`adr/0040-...md:51`)は「欠けた必須欄を、逸脱として登録する」と決めている。テンプレートの様式の省略という、別の意味の「逸脱」である
- ADR-0083 のステータス(`adr/0082-...md:10`)が補うと書くのは ADR-0068 の決定1・4 と ADR-0029 だけである
- 採用済みの ADR の本文は書き換えないため、ADR-0035 と ADR-0056 は「逸脱」と書いたまま残る
- CLAUDE.md の突合の手順は、矛盾があればどちらが誤りかを決めることを求めている。とくに ADR-0035 は、ADR-0029 と「同じ扱い」と書いている。このため、代償措置を ADR-0029 から借りた (a) の候補とも読める。分類を議長が決めていない状態である

**修正案**

- ADR-0083 のステータスと決定7 に、次を明記する
  - ADR-0035 決定2 の「代償措置つきの逸脱」と ADR-0056 決定5 の「逸脱」は、本 ADR の列挙に無い離脱と読み替える
  - ADR-0040 決定3 の「逸脱」は、テンプレートの様式の登録の語であり、1.4 の定義の外とする
- ADR-0035 を (b) とする判断は、議長の確認を経る。ADR-0035 の「ADR-0029 と同じ扱い」を代償措置の定めと読まない理由を、ADR-0083 に書く
- 必要なら、ADR-0035 の扱いを新しい ADR で置き換える

  - 出荷を止めない
  - 保証の開示の項目5・7 への表示
- 実装は「扱いの手続であり、離脱を補う措置ではない」とした(`implementation.md:108`)。理由の付け方は妥当だが、条文からは一意に決まらない
- 認証情報の分離は X-2 のとおり、ADR-0035 が ADR-0029 と同じ扱いの逸脱と決めている
- 裁定は「新しい条件を発明しない」と定めた。どちらを (a) にしても、条件の発明には当たらない。既存の条項の読みの問題である

**修正案**

- 2件の分類を議長に上げる
- (b) を維持する場合は、上の読みを ADR-0083 決定7 の表に理由として書く
- (a) にする場合は、閉じた列挙に D-2・D-3 として加える。その場合は、作業中の版のいまのうちに行う(加えるのは N を上げる改訂のため)

### X-11 中 1.3 の外の部分の引用に、版の無いものが残る

**根拠**

- 版の無い部分の引用が3か所ある
  - `deliverable-templates.md:1454`(ISO/TR 14121-2 6.5.2)
  - 同 1455 行(ISO/TR 14121-2 6.4.3、NIST SP 800-30 2.1)
  - `tailoring-guide.md:747`(ISO 26262-2 表1)
- 裁定 Q-4 は「部分(箇条・表・図)を引くときは必ず版つき」と定めた
- 離れ7(`implementation.md:161`)の未了の一覧は、JIS Z 8301・ISO 9000・ISO 13849-1・ISO 26262 などを挙げる。しかし ISO/TR 14121-2 と NIST SP 800-30 は無い
- NIST SP 800-30 は、台帳(EV-0027 の根拠)に Rev.1 とある

**修正案**

- 版の分かる3件(ISO/TR 14121-2:2012、NIST SP 800-30 Rev.1)は、いま版を付ける
- ISO 26262-2 は、読んだ版を確かめて付ける。分からなければ、その旨を書く
- 離れ7 の一覧に、部分の引用を漏れなく載せる

### X-12 軽 `check-citations` の照合が、題名の部分一致に頼る

**根拠**

- `scripts/check-citations.mjs:24` の呼び名の照合は、カードの題名に版の文字列が含まれるかだけを見る
  - ISO 12100:2010 の行は、JIS B 9700:2013 のプレビューのカード(SRC-0645。題名に「ISO 12100:2010 IDT」)で通る
  - 追補の部分(`/AMD1:2015`)は照合しない。IEC 62304:2006 の本体のカードが無くても、追補のカード(SRC-0525)で通る
- 1.3 の「読んだ範囲」の列と、カードの `verification.status` の整合も見ない
- `qms-document-control.md` は「ISO 9001:2015 は 2026-09 に改訂版が発行されており」と書く。しかし 1.3 には、12207 と同じ形の置き換えの注記が無い

**修正案**

- 照合を「カードの `version` と、呼び名の版」に変える
- 1.3 の各行に、読んだ範囲と `status` の対応の検査を足す。少なくとも、`unreachable` のカードだけで支える行を注意に出す
- ISO 9001 の改訂(二次情報)を 1.3 の注記にも書く

### X-13 軽 初期化の記録の欠けを、契約検査が注記に留める(離れ4)

**根拠**

- 裁定 Q-5 は「同じコミットに init の記録を書くことを契約の検査で確かめる」とした
- 実装は、どの場合も注記にした(`template/scripts/gate/verify-gate-contract.mjs:569`)
- 集約は、境のコミットを範囲に含む場合だけ欠落として出す(`aggregate-evidence.mjs:1258`)
- 古い履歴を直せないという理由は妥当である。しかし、境のコミットを含む PR(初期化そのもの)でも失敗にしないため、欠けを作る時点で止める手段が無い

**修正案**

- 境のコミットが検査の対象の範囲(PR の差分の範囲)にあるときは、契約検査を失敗にする
- 範囲の外の過去の欠けだけを注記に留める
- 適用の表明の件数(開始から表明まで)には、この欠落を常に1件として含める旨を、1.10.1 か ci-gates に書く

### X-14 軽 試験が持たない場合がある

**根拠**

`test-edition-end.mjs` に、次の場合が無い。

- 終了の後に種別 `notice` を受け付けること
- 契約検査が、手で書いた不正な `end` の記録(理由の区分なし・記名なし)と `edition` の記録を不整合にすること
- X-7 の範囲の場合(版をまたぐ範囲、終了の後の過去の範囲)
- D-0 の「従う本標準の版」の欄と `standard.edition` の一致。IMPL-0310 は一致させる旨を書くだけで、検査しない

**修正案**

- 上の4つを試験に足す
- D-0 との一致は、`check-d0.mjs` で検査するか、IMPL-0310 の注記に「一致は検査しない」と書く

### X-15 軽 既存の採用者の宣言が、要求事項4 の追加で記録の欠落になる

**根拠**

- 第8章「調整は宣言を伴う」に要求事項4(従う版)を足した
- 1.10.1(`overview.md` 1.10.1 の「宣言の記載が欠けていても…記録の欠落」)によって、版の欄の無い既存の D-0 は記録の欠落を持つことになる
- これを示す機械の出力は無い

**修正案**

- #315(旧い構成の移行)へ、D-0 の版の欄の移行を明示して渡す
- それまでの扱い(欠落として数えるか)を 1.10.3 か第8章の注記に書く

### X-16 軽 その他の細部

- IMPL-0309(再開の経路)の降ろし先が `profile-generator` になっている。再開は構成の変更の記録の種別の問題なので、`config-change-log` の方が合う
- 親の submodule は、テンプレートの `main` ではないブランチのコミット(bc8fd4f。`origin/claude/process-compass-313` にはある)を指している。テンプレートの `main` へ入れる順序を、マージの前に確かめる
- EV-0162 の差し替え条件は、緩める向きと強める向きを書いている。しかし、観測されなかった場合に保つことを書いていない(EV-0159・0161 は書いている)

## 6. ADR-0083 の正確さ

- コンテキストと決定1〜6 は、裁定 Q-1〜Q-6 と一致する。外部の型の要約(認証の制度の移行、FAA AC 20-115C、ISO/IEC 17065:2012 の目次、MISRA、専門業務用指針 10.4・10.5)は、裁定と EV の本文と矛盾しない

  - 補う対象の ADR の列挙(ADR-0035 決定2、ADR-0056 決定5、ADR-0068 決定2、ADR-0040 決定3)
  - 影響の、作業中の版の間に表明もできないこと(X-4)

  - 実装で足した選択肢を、検討済みの形で書いていること(X-3)
- ADR-0068 は、ステータスの節の1段落だけが変わった
