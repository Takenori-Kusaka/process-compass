## Q-1 標準の版の付番と改訂時の扱い

### 結論
1. **版は「発行」という人の行為で付ける**。main への push ごとの公開物は版を持たない「作業中の本文」とし、主張に引けない
2. 版の識別子は **`N.M` の2段と発行日**(例「第1.0版(2026-11-15)」)。N は規範の変更で、M は規範を変えない変更で上げる
3. **移行期間を置かない**。案件は適用した版のまま続けてよい。新しい版への適合は、新しい版で調整を宣言し直した後でなければ主張しない(FAA AC 20-115C の型)
4. 案件が従う版は、準拠テンプレートの `process.config.json` に記録する。変える経路は `/process-change` の新しい種別に限る

### 理由
- `qms-document-control.md:90` は「ハッシュは監査の場で版の識別子として通用しない」と書き、本標準はこれを採用組織へ課している [内部・確認]。自分に課さない規定を他組織へ課す標準は、信頼されない
- H.8 は適用の表明に「適用した版」を書かせるが、版の形を定めた条項が無い [内部・確認]。書かせる欄に書ける値が無い状態である
- 本標準には認証機関が無い(1.10.2 :384)[確認]。IAF の 36 か月は、認証機関が移行審査をする前提の値である [外部]。審査する者がいない標準が期日で旧版を失効させても、失効を確かめる者がいない。**主張できる文言を制限する**型(DO-178C の「旧版で続けてよいが、新版への適合を宣言してはならない」)なら、表明の文面だけで検査できる [外部]
- 適用の単位は案件である(1.10 :347)[確認]。案件は終わる。案件の途中で版を強制的に切り替えると、ADR-0068 決定2 の「導いた要求事項のすべてを同時に」が、版の切替のたびに途中から掛かり直す。案件の選択で切り替えるほうが、切替の時点を記録に1つだけ残せる
- 2段で足りる理由: 主張への影響は「規範が変わったか、変わっていないか」の2値しか無い。SLSA も MAJOR.MINOR の2段で、MAJOR を「要求事項の追加」で上げる [外部]。3段目(semver の patch)は、主張の扱いを何も分けない

### 他の案を落とす理由
| 案 | 落とす理由 |
| --- | --- |
| 日付だけの版(YYYY-MM) | 規範が変わったかを識別子から読めない。同じ月に2回発行すると衝突する |
| 意味つきの3段(semver) | 3段目が主張の扱いを分けない。区分が増えるほど、発行の都度の判断がぶれる |
| コミットのハッシュを版とする(現状) | `qms-document-control.md:90` が自ら否定している。前後関係を人が読めない |
| push ごとに版を上げる | 版が日に何度も変わり、表明の版の欄が意味を失う。発行の判断(人)が介在しない |
| 36 か月の移行期間 | 失効を確かめる主体が本標準に無い。期日の値の根拠は認証の審査の周期で、本標準に当てはまる実証が無い |
| 改訂で旧版の表明・主張をすべて失効させる | 案件の途中で、本人の行為なしに適用の外へ落ちる。ADR-0068 決定1 の理由(開始から完了までの出荷が規定の外に落ちる)と同じ欠陥を生む |

### 文の案(第1章へ新設する 1.11「本標準の版」)
本標準は、版を付けて発行します。版を付けるのは発行の時点に限ります。発行していない本文は、作業中の本文です。
- 版の識別子は「第N.M版」とし、発行日を併記する。N と M は 0 以上の整数とする
- 規範の変更を含む発行では N を 1 上げ、M を 0 とする。規範の変更とは、要求事項・禁止事項の追加・削除・強さの変更、適用範囲の変更、ゲートの基準の変更、テーラリングの規則データの変更、様式の必須欄の変更をいう
- 規範の変更を含まない発行では M を 1 上げる
- 発行の記録には、版、発行日、規範の変更の一覧と各変更の根拠(ADR または Issue)、発行を決めた者の記名を残す
- 発行した版の全文を、後の版を発行した後も参照できる状態に保つ
- 作業中の本文を、適用の表明と適合の主張に引かない
- 案件は、適用の開始の時点で発行されている版のうち1つを選び、その版を案件の記録に残す
- 案件は、選んだ版のまま適用を続けてよい
- 後の版を発行しても、それより前の版で述べた適用の表明と適合の主張は失効しない
- 案件が従う版を変えるときは、変更先の版で第8章の調整の宣言をやり直し、版を変えた時点を案件の記録に残す。変えた時点の後は、変更先の版の要求事項のすべてを同時に適用する(1.10.1)
- 案件が従う版より後の版に適合していると主張しない

本標準は、旧い版の発行を取り消す期日と、版の移行期間を定めません。本標準に、移行を審査する制度が無いためです。

### 機械の検査(降ろし先。実装マークは `state=undelivered` で付ける)
- 標準側: 前回の発行の版の目印(タグ)と HEAD の間で、`src/data/tailoring/`・`src/data/template-fields.yaml` に差分があるのに M だけを上げた発行を、検査で失敗させる。**逆向き(N を上げたのに規範の差分が無い)は検査しない**(本文の規範の文の変更は機械で網羅できないため。規範の変更の一覧は人が書く)
- 公開サイト: 最新の発行の後に本文の変更がある場合、各ページに「第N.M版の後の未発行の変更を含む」と出す
- `dist/standard` の `VERSION.md` と知識ベースの `source` に `version`(発行した版、または `unreleased`)を足す。`check-template-drift.mjs` は `source.commit` を比較から外したまま、`source.version` を比較に含める
- テンプレート: `process.config.json` に `standard.version` を置く。`/process-init` が知識ベースの `source.version` から書き、`unreleased` の知識ベースからは初期化しない。変える経路は `/process-change` の新しい種別 `standard-version` だけとする。契約検査は、`standard.version` と知識ベースの `source.version` の一致を確かめる

### 矛盾の検査
- ADR-0068 決定2(同時に適用、経過措置なし)と整合する。版の切替も、切替の時点で全部を掛ける
- `improvement-cycle.md:151`(着手時の版のまま完走)は採用組織のプロセス定義の規定で、本案と同じ向き。読み替えを防ぐ注記を足す(Q-6)
- 決定事項: **最初の発行(第1.0版)は外部への発行で、取り消せない操作に当たる**。発行の判断は人(所有者)が行う。本会議体は付番の規則までを決め、発行そのものは決めない
- 根拠水準: 移行期間を置かない判断は、認証機関を持たない標準での実証が無い。**新しい EV を付ける**(差し替え条件: 発行後に、旧い版のまま続けた案件と切り替えた案件の件数、切替時に生じた未達・欠落の件数)

## Q-2 適用の終了

### 結論
定義する。**事象は2つ(案件の終結・適用の取り下げ)に限る**。期日による失効・一時停止・範囲の縮小は、終了の事象として採らない。終了の後は現在形の適用の表明をせず、終了前の範囲の適合の主張は、記録を保管している限り残る。

### 理由
- 外部の制度は終了を「期日の失効・取消し(一時停止)・範囲の縮小」の3事象で書く [外部]。ただし、それは組織を対象にした**認証**の事象である。本標準の適用の単位は案件(1.10 :347)で、認証が無い [確認]。事象は案件の側から立てる
- 案件の終わりに当たる語は、会議体の「中止」(`roles-responsibilities.md:699`)とステージ移行の「中止」しか無く、1.10 と結び付いていない [内部]。終了を定めないと、終わった案件の「適用している」がいつまでも現在形で残る
- 一時停止を採らない理由: ADR-0068 決定3 は「導入の途中を表す状態を設けない」とした [確認]。一時停止は同じ種類の中間状態で、「止めている間の変更」を規定の外へ出す経路になる
- **終了を、未達を隠す手段にさせない**。同じ案件で適用を再び始めることを許すなら、終了から再開までの変更を件数から外せてしまう。再開した場合は最初の開始から数え、空白の期間の変更を記録の欠落として数える。これで、終了を宣言する利得は「本当に終わった案件」に限られる

### 他の案を落とす理由
| 案 | 落とす理由 |
| --- | --- |
| 終了を定義しない | 終わった案件の現在形の表明が残る。テンプレートに終了を記録する場所が無いまま(内部 7節7) |
| 期日による失効(CMMI の3年など) | 失効を確かめる主体が無い。案件の適合の主張は、もともと期間またはリリースで区切る(1.10.2)ため、期日の失効が足すものが無い |
| 一時停止 | ADR-0068 決定3 の中間状態の禁止と矛盾する |
| 範囲の縮小を終了の事象にする | 案件の範囲の変更は、体制の変化点と同じく調整の宣言のやり直しで扱える(`tailoring-guide.md:87-89`)。終了と呼ぶと、縮小した部分の未達が終了扱いで消える |
| 再開を一律に禁止する | 安全ではあるが、事業の中断と再開(ステージの移行)のたびに案件の識別を作り直させる。空白を欠落として数えれば、禁止と同じく隠蔽を防げる |

### 文の案(1.10 へ新設する 1.10.3「適用の終了」。見出しを「適用の開始・終了と適合の主張」に改める)
適用の終了は、次のいずれかの決定を、案件の記録に残した時点とします。
- 案件の終結(完了、または会議体・ステージ移行ゲートの判定による中止)
- 適用の取り下げ(案件は続くが、本標準の適用をやめるという組織の決定)

終了の記録には、次の事項を書きます。
- 終了の時点と事由(終結・取り下げのいずれか)
- 決定した者の記名
- 適用の開始から終了の時点までの、未達のゲートの件数・記録の欠落の件数・逸脱の件数
- 判定が指す記録の保管期間(第4章「判定が指す記録の保管」)

- 適用の終了の後は、当該案件に本標準を適用していると現在形で表明しない
- 終了の後に述べてよいのは「[案件]に、[開始]から[終了]まで本標準を適用していた」という過去の事実の表明に限る。件数の併記は 1.10.2 による
- 終了より前の範囲について述べた適合の主張は、終了によって失効しない。判定が指す記録を保管期間の内に失った範囲について、適合を主張しない
- 適用の終了の後に、案件のリポジトリ・文書に残る現在形の適用の表明を取り除く
- 期日の到来・一時停止・範囲の縮小を、適用の終了として扱わない
- 同じ案件で適用を再び開始する場合、件数は最初の適用の開始から数え、終了から再開までの変更を記録の欠落として数える
- 適用の終了の決定は、取り消せない操作として扱う(第5章 5.5.1 の場合(c))

本標準は、適用の一時停止を設けません。一時停止は、導入の途中と同じ中間の状態であり、止めている間の変更を要求事項の外へ出すためです(1.10.1)。

### 機械の検査
- テンプレート: `/process-change` の種別に `end`(事由 `closed` / `withdrawn`)を足す。`changeLog` に記録し、`configured` は `true` のまま残す(未設定へ戻す変更は今も契約検査が落とす。`template-repository.md:705`)
- 出荷の証跡の集約: `end` の後の変更は件数に数えず、一覧に出す。`end` の後に再び開始の記録がある場合、空白の期間の変更を欠落として数える
- いずれも未実装。実装マークを `state=undelivered` で付ける

### 矛盾の検査
- ADR-0068 決定3 と整合する(中間状態を作らない)。ADR-0068 :111 が後継へ送った論点を閉じる
- `gate-criteria.md:76-82` の保管期間(組織が定める、`IMPL-0243 undelivered`)を参照する。保管期間の値は本案で決めない
- 取り下げの決定者の席は第3章に照らし、事業決裁者とするかを突合で確かめる必要がある(本意見書では席を指名していない)

## Q-3 逸脱がある場合の適合の主張

### 結論
1. **「逸脱」を1つの意味に定める**。逸脱 = 本標準が条項で条件と代償措置を定めて許した、要求事項の本来の形からの外れ。本標準が条件を定めていない外れは、逸脱ではなく未達または記録の欠落とする
2. 1.7.1 の「逸脱を認めない」を、「満たさない状態を適合の主張の範囲に含めない」に改める
3. 逸脱を持つ範囲の主張は、**語を分ける**。「適合の主張」と「逸脱を伴う適合の主張」の2つとし、後者は逸脱の件数と一覧を必ず併記する。逸脱を持つ範囲に、限定の無い「適合している」を使わない
4. **正本は 1.10.2**。適用の表明・適合の主張の必須の記載を 1.10.2 に集め、H.8 は 1.10.2 を引く投影にする

### 理由
- 「逸脱」は 1.7.1 :224 の「要求からの外れ(適合の否定)」と、3.5.2・ADR-0029 の「代償措置つきの逸脱(構成の区分)」の2義で使われている [内部・確認]。1.7.1 は ISO/IEC Directives Part 2 の 3.3.3(no deviation is permitted)から来ている [外部]。ADR-0029 の逸脱は、3.5.2 という**本標準自身の条項**が条件を定めた経路である [確認]。条項の条件を満たすことは、その条項への適合である。したがって、誤っているのは 1.7.1 の語の選び方で、ADR-0029 の構成ではない。ただし ADR-0029 の構成は独立性を欠いたままで(3.5.2 「代償措置は独立性の回復ではありません」)[確認]、限定の無い「適合」と同じ語で呼ぶと、読み手は独立性があると読む
- 12207 系の「完全適合 / 修整適合」と MISRA の「Compliant / Deviations」は、独立に「逸脱つきの適合を別の語で呼ぶ」に達している [外部]。12207 の箇条4 の本文は読めていない [外部]。よって語を借りず、構造だけを採る(「修整適合」の語は使わない。本標準では調整(テーラリング)は全案件が行うため、「修整」の語は全員に当たってしまう)
- 適合の主張を禁じる案(主張できない)を落とす理由: 2名の体制は G-6 を満たせても G-7 の逸脱が3名になるまで残る(1.10.2 :382、ADR-0029 影響)[確認]。禁じると、本標準が自ら許した構成が、どれだけ記録を揃えても適合を主張できない。区別して開示すれば、読み手は判断の材料を失わない
- 逸脱を許すのは本標準の条項が定めた所だけ、とする理由: MISRA は「逸脱できない層」を標準の側が先に決め、指名された技術権威の同意の無い逸脱を禁じる [外部]。本標準で同じ働きをするのは「条件を条項に書いた逸脱の閉じた一覧」である。テンプレートの `detectDeviations` は既に各逸脱に `source`(条項)と `resolveWhen` を持たせている [確認]。一覧に無い逸脱を機械が拒める
- 正本を 1.10.2 に置く理由: 1.9 末尾が「附属書H は既存の条項からの投影であり、要求事項の正本は各章です」と書き [確認]、1.7 が「同じ事項の規定は1か所に書く」と定める [確認]。H.8 にだけある要件(版・調整・逸脱・記名の自然人の署名)は、投影が正本を超えている状態である

### 他の案を落とす理由

| 逸脱があっても限定なしで「適合」と言える(現状の字面) | 独立性を欠く構成と欠かない構成が、同じ文で表明される。`implementation-B.md:243` が穴として自認している |
| 逸脱があれば適合を主張できない | 本標準が条件つきで許した構成を、条件を満たしても罰する。2名の体制の記録を揃える誘因を消す |

| 正本を H.8 に置く | 附属書H は投影と自ら定める。正本を附属書に置くと、本文の 1.10.2 が投影の側に回る逆転が起きる |

### 文の案
1.4 の用語に足す:

| 用語 | 定義 |
| --- | --- |
| 逸脱 | 本標準が条項で条件と代償措置を定めて許した、要求事項の本来の形からの外れ。構成に記録し、条件が解けるまで表示し続ける。本標準が条件を定めていない外れは逸脱ではなく、未達または記録の欠落とする |

1.7.1 の表の「要求」の「意味」の欄: 「適合を主張するには、これを満たす。満たさない状態を、適合の主張の範囲に含めない」

1.10.2 の表を次に改める:

| 述べること | 述べる条件 | 併記する事項 |
| --- | --- | --- |
| 適用の表明 | 適用の開始の後で、適用の終了より前である | 従う版(1.11)、調整の宣言の所在、未達のゲートの件数、記録の欠落の件数、逸脱の件数。無い場合は 0 件と書く |
| 適合の主張 | 範囲の内に、未達のゲート・記録の欠落・逸脱が無い | 従う版、主張の範囲(期間またはリリース) |
| 逸脱を伴う適合の主張 | 範囲の内に、未達のゲートと記録の欠落が無く、逸脱がある | 従う版、主張の範囲、範囲の内の逸脱の件数と一覧(逸脱ごとに根拠の条項と代償措置) |

- 表明と主張は、組織の自己宣言として書き、記名の自然人が署名する
- 併記する事項のいずれかを欠く表明・主張を、本標準に基づく表明・主張として扱わない
- 逸脱がある範囲について、「逸脱を伴う」の限定を付けずに適合を主張しない
- 本標準の条項が条件を定めていない外れを、逸脱として記録しない
- 対外の文書での文例は附属書H H.8 による。H.8 は本節に無い必須の事項を足さない

H.8 の表の表明の2行は、条件の欄を「第1章 1.10.2 による」だけにし、署名・版・逸脱の要件を本文側へ移した上で、文例に「逸脱を伴う」の行を加える。

### 機械の検査
- テンプレート: `deviations[]` の各要素の `source` が、標準側に置く閉じた一覧(新設 `src/data/deviation-rules.yaml`。条項・条件・代償措置・解ける条件)に実在することを契約検査で確かめる。一覧は知識ベースへ複製する
- 標準側: 本文で「逸脱として記録する」と書く条項(`roles-responsibilities.md:427`・`:518`・`:552`、`tailoring-guide.md:186`・`:213`、`adoption-guide.md:224`・`:317`・`:653` など [内部])が、一覧に1件ずつ対応することを検査する。**対応しない条項は、条件と代償措置を書き足すか、逸脱でなく未達に改める**(どちらにするかは突合で決める)
- 表明の様式の出力(`IMPL-0120`)は未達のまま。逸脱の件数を加えて `undelivered` で表示し続ける

### 矛盾の検査
- ADR-0029 の本文は書き換えない。語の定義は新 ADR で置く。ADR-0029 の構成(`required` のまま、未達と別区分、消す操作なし)は本案と整合する
- ADR-0029 :70「消す操作は設けない」と 3.5.2 条件1「3名以上で失効」の関係: 失効は将来の範囲で逸脱が無くなることを意味し、失効より前の範囲の逸脱は記録に残る。件数は主張の範囲の内で数える(Q-6)。両者は矛盾しない
- 未決の点: 第7章の例外承認(技術負債台帳の区分「例外」)は、変更ごとの基準からの外れである。逸脱の定義(条項が条件を定めた外れ)に当たるか、別の区分として表明に件数を併記させるかは、本意見書の調査の範囲で決めきれない。**突合の論点として残す**

## Q-4 引用規格の版の書き方

### 結論
ISO/IEC Directives Part 2 の 10.4・10.5 の規則を採る。1.3 の全行を**発行年付き**にし、各行に「本標準が読めた範囲」と出典台帳の識別子を持たせる。改訂時の見直しを、標準の版の発行の作業として定める。

### 理由
- 本標準は部分を引いている(H.10 は ISO 9001:2015 の箇条の対応表)[内部]。Directives 10.5 は部分の引用は必ず発行年付きとする(番号が振り直されるため)[外部]。版なしの引用は、全改訂を取り込む場合に限る(10.4)[外部]。本標準は ISO 9001:2026 の本文を読んでいない(`assurance-case.md:109`)[内部]ので、全改訂を取り込むとは言えない
- 1.3 は 12207:2017 を引くが、台帳には 2017 年版のカードが無く、2026 年版(SRC-0491)だけがある [内部]。本文から SRC への参照は 0 件 [内部]。引用の版と、読んだ版の対応を、機械も人も確かめられない
- 読了の状態を書かせる理由: 本標準は「読了していない条文が残る」ことを、規格への適合を主張しない理由にしている(H.8 の禁止の表)[確認]。読めた範囲を引用の行に書けば、その理由を読み手が確かめられる

### 他の案を落とす理由
| 案 | 落とす理由 |
| --- | --- |
| 現状維持(一部だけ版なし) | 版なしの行は、読んでいない新版を取り込む意味になる |
| すべて版なしにして「最新版による」 | 本標準は新版を読む前に引用を更新できない。Directives 10.4 の条件を満たさない |
| 引用規格を持たない(12207:2026 の型) | 本標準は 9001 の箇条へ対応表を持ち、42001 等の要求を前提に構成している(1.3 :62)。前提を書かないと読み手が確かめる手段が無い |

### 文の案(1.3 の表の前)
本標準が引く規格は、発行年を付けて引きます。引いた版だけを、本標準の前提とします。
- 1.3 の表の各行に、規格の番号と発行年、対応する JIS の番号と発行年(ある場合)、本標準が読めた範囲(全文・部分・未取得)、出典台帳の識別子を書く
- 発行年を付けない引用をしない
- 本文・附属書で規格の箇条・表・図を引くときは、1.3 の表の版によるか、その場で発行年を付ける
- 引いた規格の新しい版が発行されたことを出典台帳に記録したら、本標準の次の版の発行までに、その行を見直す。見直しの結果(新しい版へ改める、または旧い版のまま引く理由)を発行の記録に残す
- 新しい版へ引用を改めることは、規範の変更として扱う(1.11)

### 機械の検査
- `lint:sources` を拡張し、1.3 の表の各行に発行年と実在する SRC の識別子があることを確かめる
- SRC カードの `events` に後継の版が記録された規格を、1.3 が旧い版で引いており、見直しの記録が無い場合、**標準の版の発行の時点でだけ**失敗させる(日々の CI では警告の一覧に出す)
- 台帳に無い規格のカードの追加(内部 4.2 の 10 件)は作業であり、本 Issue の受け入れ条件に入れる。12207:2026 への更新の判断そのものは #341

### 矛盾の検査
- `qms-document-control.md:141-143`(箇条番号は H.10 の1か所に書く)と整合する
- 版の値: ISO 12100:2010 / JIS B 9700:2013、ISO/IEC/IEEE 90003:2018 と記憶しているが、**[未確認]**。カード登録の段で原典を確かめる

## Q-5 適用の開始の境(pre-init)

### 結論
境は「**`process.config.json` が `configured: true` で、かつ `changeLog[0].kind` が `init` である、最初のコミット**」とする。どちらの片方だけでも境にしない。境を決められない履歴は、境を推測せず欠落として出す。定義の正本は `template-repository.md` に置き、`ci-gates.md:313` はそれを引く。

### 理由(どちらが誤りか)
- 1.10.1 の適用の開始は「調整の宣言を記録に残した時点」[確認]。テンプレートで宣言の記録に当たるのは `/process-init` の生成物で、`generate-profile.mjs` は同じコミットで `configured: true` と `changeLog[0] = {kind:'init'}` を書く [確認]
- **実装の誤り**: `findInitCommit()` は `configured === true` だけを見る [確認]。手で `configured: true` を入れた(宣言を生成していない)コミットを、適用の開始にしてしまう。宣言の無い時点を開始にする点で、1.10.1 に反する
- **文書の不足**: `ci-gates.md:313` の「`changeLog[]` の1件目」はデータを指し、コミットを指していない。1件目を書き換えた履歴では境が動く [内部]
- 両方を条件にすると、内部 5.3 の4つの場合はすべて一意に決まる。旧い構成(`changeLog` 無し)は境を決められないので、欠落として出す。黙って `configured` だけで決めると、宣言の記録が無い履歴を「適用している」として扱う

### 他の案を落とす理由
| 案 | 落とす理由 |
| --- | --- |
| 実装に揃える(`configured` だけ) | 宣言の無い開始を許す |
| 文書に揃える(`changeLog[0]` だけ) | `changeLog[0]` の切り詰めで境が動く。`configured: false` の履歴でも開始になりうる |
| 境を人が手で記録する | 後から動かせる。ADR-0068 決定1 の「境は履歴の1コミットで決まり、後から動かせない」に反する |

### 文の案
`template-repository.md` の表の行:
- 構成の初期化のコミット: `process.config.json` が `configured: true` を持ち、かつ `changeLog` の1件目の種別が `init` である、最初のコミットとする。第1章 1.10.1 の適用の開始に当たる
- 初期化のコミットの後に、`changeLog` の1件目を変えない
- 境を決められない履歴(初期化のコミットが無い、または `changeLog` を持たない構成)は、境を推測しない。出荷の証跡の集約は、境を決められないことを記録の欠落として出す

第1章 1.10.1 に足す:
- 適用の開始の後に調整の宣言をやり直しても、適用の開始の時点を動かさない
- 調整の宣言が第8章の3つの要求事項のいずれかを欠く場合も、宣言を記録に残した時点を適用の開始とする。欠いた事項は記録の欠落として表示し、宣言の無い省略は、省略しなかったものとして要求事項を適用する

### 理由(後半の2文)
- 2回目以降の宣言が開始を動かさないことは、どこにも書かれていない [内部 7節2]。単数の「時点」から推せるが、推測に頼る文は規格の文ではない
- 不完全な宣言で開始が定まらないとすると、「宣言はしたが開始していない」という状態ができる。これは ADR-0068 決定3 が禁じた「準備中」と同じである。欠落として表示する案は `tailoring-guide.md:18`(欠く省略は調整として扱わない)とも整合する。省略が無効なら、要求事項はそのまま掛かる

### 機械の検査
- `findInitCommit` を、`configured === true && changeLog?.[0]?.kind === 'init'` に改める。見つからない場合の欠落の出力を足す
- 契約検査に、初期化の後の `changeLog[0]` の変更の拒否を足す(`template-repository.md:704` の切り詰めの拒否と同じ所)

### 矛盾の検査
- ADR-0068 決定1 と整合する。`implementation-B.md:246` が送った不一致を閉じる
- #315(旧い版の構成の移行)と接する。旧い構成を欠落として出すことは、#315 の移行手順の入口になる
