## 1. 既存の決定と規定

| 出所 | 該当の内容 |
| --- | --- |
| ADR-0079 決定7 | 氏名の確認(`nameConfirmed`)は本人以外の記名に限る。体制の内の人が1名の名簿では本人の記名を受け付け、自己申告として開示する。**記名者の名義が AI を示す語を含む確認を数えない旨は、ADR の本文に無い** |
| #296 implementation.md 6.5(追加の裁定) | 「本人の記名は、確認される氏名そのものが AI を示す語を含むため、語では落とさない。本人以外の記名は従来どおり語で落とす」。記録の無い確認(#296 より前の確認を含む)は、1名の名簿では効かせて未記録と出し、2名以上の名簿では契約検査が落とす |
| ADR-0111 決定2 | 確認の記名者の資格(本人以外か、名簿の人か、AI の名義でないか、前から名簿にいるか)は類B として、変化点の前の構成で照らす |
| ADR-0111 決定5 | 1名から2名以上へ移る変化点では、前の名簿で効いていた本人の自己申告(**本人の記名・記録の無い確認**の両方)を確認待ちとして受け付ける |
| ADR-0111 決定6 | 既存の記録の記名者は、その記録が作られた変化点の前の構成で照らす。氏名の確認の状態の移り変わりを理由に照らし直さない。準拠テンプレートは「本人の記名の記録だけがあり、2名以上の名簿で効かない確認」を既存の記録の照合に限って効かせる。確認待ちの本人が記名した他の人の確認は拒否する(AR-5) |
| 第4章 G-6(gate-criteria.md L1069〜1072) | 「本人の記名・AI の名義の記名・記録の無い確認では効かない」。移行の変化点の確認待ちは「本人の記名による確認と記録の無い確認」を対象にする。既存の記録の記名者は「その記録が作られた時点の構成で照らす」。確認待ちの本人が記名した確認は「後で数えられないため受け付けない」 |
| EV-0229(G-6) | 支えは試作と試験の場面だけで、「ほかの経路が無いことは示していません」と開示済み |
| #375 implementation.md「気づいたこと」 | 経路1・経路2 を裁定の範囲の外として残した。経路2 については「未記録の確認は #296 より前の旧い構成に限られる」と書いた |

突合で分かったこと:

- G-6 の「AI の名義の記名」が、**本人以外が確認済みの、AI を示す語を含む氏名の人**の記名を含むかは、標準の本文から読み切れない。含むとする解釈は、#296 の追加の裁定(実装の記録)に1行あるだけである。ADR-0079・ADR-0111 の本文には無い
- G-6 の既存の記録の箇条は「作られた時点の構成で照らす」と一般に書く。ADR-0111 決定6 の準拠テンプレートの実装の記述は、それを「本人の記名の記録」に絞った。経路2 は、標準の文と実装の絞り込みの差にある

- 記名者の「AI の名義」の判定が2つある。記名の受け付け(`aiNameBlocked`)は確認で上書きでき、確認の数え方(`confirmedNames` L468・`confirmedAccounts` L2534)は語だけで決まる。経路1 は、この2つの差から生じる

## 3. 実行での確認

### 3.1 経路1(3名の体制。山田が Claude Dupont の氏名を確認済み)

| 場面 | 結果 | 観測 |
| --- | --- | --- |
| 1a Dupont の記名で、Gemini Sato を足して確認する(任命なし) | **受け付け** | 記録 `decidedBy: Claude Dupont`、`nameConfirmations: [{id: gsato}]`、記録の `nameOverrides` は Dupont だけ。Gemini の状態は `invalid`、`confirmedNames` に入らない。差分の表示は「Gemini Sato の氏名を実在の人の氏名として確認した(名義の機械検査の上書き)」と出る。書き出した直後の構成で、契約検査が「本人以外が記名した変化点の記録がありません」と落とし、集約も欠落を1件出す |
| 1a の後、山田が記名し直す | 受け付け | Gemini は `other` になる。回復はできる |
| 1b 1a に加えて、同じ変化点で Gemini を技術判断者に任命する | 拒否 | 類A の名義の検査で Gemini を AI の名義として拒否する(任免の決定者の要件でも別に拒否)。**数えない確認を使う任命は通らない** |
| 1d Gemini が確認待ちのまま、Dupont が無関係の変化点(鈴木の所属)へ記名する | **受け付け** | 記録に `nameConfirmations: [{id: gsato}]` が自動で載る(`pendingNameConfirmations`)。記名者が意図しない数えない確認が、記録に積み上がる |
| 1f 参考: 外部の人(任命権者)の記名で Gemini を確認する | 受け付け | `other` として数える |
| 1g Dupont の記名で、新しく足す田中の AI を示す語のアカウント(`copilot-tanaka`)を確認する | **受け付け** | 記録 `accountConfirmations` は残るが `confirmedAccounts` に入らない。契約検査が落とす。**アカウント名の確認にも同じ経路がある** |
| 1h 対照: 1g を山田が記名する | 受け付け | 数える |

経路1 は、統制を緩める穴ではない。数えない確認は使えず(1b)、契約検査と集約が欠落として止める(1a)。問題は次の3つである。

1. 後で数えられない記録を、記録の時点で受け付ける。AR-5 が退けたのと同じ型である
2. 差分の表示が「確認した」と出し、契約検査の文が「本人以外が記名した記録がありません」と出る。本人以外(Dupont)の記録は実在するため、どちらの文も原因を言い当てない
3. 1d のとおり、確認待ちの氏名がある間、AI を示す語を含む氏名の人の記名する変化点ごとに、数えない確認の記録が足される

### 3.2 経路2(1名の体制の Claude Dupont。旧い構成は、記録から `nameConfirmations`・`nameOverrides` と要約値の連鎖を除いて模した)

| 場面 | 2人目を足す変化点 | 高橋が Dupont を確認する変化点 |
| --- | --- | --- |
| 2a 旧い確認・委任なし | 受け付け(確認待ち) | 受け付け。`other` になる |
| 2b 旧い確認・1名の間に本人が委任の規則と変更種別を記録 | 受け付け(確認待ち。委任の席は delegated のまま) | **拒否**: 「変更種別 "表示文言" を登録した者 "Claude Dupont" は … AI の名義の記名を受け付けない」。差分には、規則 DR-001 の決定者を受け付けられないための「委任 → 協働」も出る |
| 2c 対照: 本人の記名の記録あり・委任あり(AR-4) | 受け付け | 受け付け。規則・種別・委任の席を保つ |
| 2d 旧い確認・委任あり。2人目を足す前に、1名のまま本人が記名する変化点を1つ出す | 受け付け | 受け付け。その変化点が `nameConfirmations: [{id: dupont}]` を記録し、`self` に変わるため AR-4 に乗る |
| 2e 旧い確認の構成で、今の版のまま本人が委任を記録する | — | 委任の変化点が確認を自動で記録し、`self` になる |
| 2f 1名→2名を経ない旧い2名の構成(記録の無い確認の人が既存の委任の記録の記名者) | — | **拒否**(2b と同じ文)。契約検査は、確認の前から規則・種別・席の名義で落ちている |
| 2g 回避の試み: 確認と同じ変化点で、高橋が変更種別を登録し直す | — | 拒否(登録は事業決裁者の席の責任者 = Dupont に限る) |
| 2h 回避: 委任の規則と変更種別を外し、席を協働へ戻して確認する | — | 受け付け。`other` になる。規則と承認の記録は失う |
| 2i 2f の構成に高橋の確認の記録を手で足し(確認後の状態の模擬)、次の変化点を高橋が記名する | — | 受け付け。規則・種別・委任の席を保ち、契約検査の Dupont・DR-001・表示文言の error は0件 |

経路2 について分かったこと:

- 起きる条件は「記録の無い確認の人が、既存の記録(委任の規則の決定・承認、変更種別の登録)の記名者である」こと。今の版で本人が記名する変化点を1つでも出せば `self` に変わる(2d・2e)。したがって、#296 より前の版で作った記録を持ち、今の版で記名の変化点を出さないまま2名以上になった構成に限られる(#375 の見立てと合う)
- 1名から2名への移り変わりに限らない(2f)。旧い2名以上の構成で、記録の無い確認の人が既存の記録を持てば、本人以外の確認の変化点そのものが拒否される
- 拒否は統制を守っていない。確認が入った後の変化点では、`confirmedNames` が高橋の記録を数えるため、同じ既存の記録は通る(2i)。拒否が効くのは、確認する変化点が既存の記録を確認の前の構成で照らすためだけである(AR-4 と同じ型)
- 今の回避は、2人目を足す前の記名(2d。1名の注記「記録してください」が案内している)か、委任を外して後で作り直すこと(2h)である。2b・2f の構成では前者を使えない。後者は承認の記録を失う

### 3.3 範囲の外で見えたこと(実行していない。コードの読み)

- `confirmedNames` は、記名者が今の名簿にいることを数える条件にする。確認した人が名簿から外れると、その人の確認が数えられなくなる。ADR-0111 決定6 が「人の離脱による既存の記録の扱いは変えない」とした範囲であり、本件では扱わない。既存の Issue へ寄せる候補

| 2-D 既存の記録の照合に、この変化点の確認を数える | 本人以外の確認を含む変化点では、既存の記録の記名者を、その確認を足した後の構成で照らす | 無し | 実装との比較では受け付けが増える。統制は変えない | ADR-0111 決定6 の「作られた変化点の前の構成で照らす」と、採らなかった案(f)の趣旨に触れる。確認の変化点の外(確認待ちの間の、記名の無い変化点など)は救わない |

2-B を採る場合、確認待ちの間の委任の席の扱い(`clampSeats` の `ctxPrior`)も、記録の無い確認の人について AR-4 と同じになる。2c で確かめた AR-4 の場面と同じ扱いであり、契約検査が落ち続けることも同じである。2-B は `nameConfirmationProblems` と契約検査の文を変えない。

## 6. 審議の重さの判定の材料

- 経路1 の 1-A: 採用組織への新しい義務は無い。標準の本文に一文が要る(「AI の名義の記名」が、確認済みの AI を示す語を含む氏名の人の記名を含むこと)。これは #296 の追加の裁定を標準へ上げるもので、原則の変更ではない。軽で扱える
- 経路2 の 2-B: 新しい義務は無い。ツールの拒否を減らす向きであり、独立の突合で「統制を緩めていない」ことを確かめる必要がある。確かめる要点は、確認待ち・`invalid` の間の契約検査・集約・委任の席が今と同じに止まることである。突合で重大度「高」が出れば重へ上げる
- 1-E(確認済みの語を含む氏名の人の確認を数える)を議論に乗せるなら、#296 の裁定の変更になるため、重へ上げる
- ADR: 決定は新しい ADR で ADR-0111 決定6 を補う形になる(採用済みの本文は書き換えない)。EV-0229 の対象(「ほかの経路が無いことは示していません」)に、本件の経路を加えて見直すかを決める
- 回帰の試験: `suite/name-confirmation.mjs` に経路1・経路2 を固定した場面は無い。1-A・2-B のどちらも、既存の fixture の期待値とは衝突しない(AR-5 の拒否の文の照合を除く。1-A で文を一般化するなら期待値の文を合わせる)

## 7. 調査担当の見立て(議長の裁定ではない)

- 経路1: 1-A を推す。AR-5 と G-6 の「後で数えられない確認は受け付けない」を、列挙ではなく数え方の関数に拠る形へ一般化する。アカウント名の確認も同じ関数の構図なので、範囲に含めるのが一貫する。採らない案は 1-C(AR-5 と割れる)、1-D(記録と表示が食い違う)、1-E(緩める向きで、#296 の裁定の変更)
- 経路2: 2-B を推す。標準の文(作られた時点の構成で照らす)に実装を合わせるもので、確認後の構成が同じ記録を通す以上、確認の変化点での拒否は何も守っていない。2f まで救える。採らない案は 2-A'(不変条件が崩れる)、2-C(G-6・決定5 に反し、2f を救わない)、2-D(決定6 の文に触れる)
