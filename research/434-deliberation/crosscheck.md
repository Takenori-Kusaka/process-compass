## 2. 指摘

### F-1 G-6 の「記録の無い確認は、既存の記録の照合に使わない」が、1名の名簿と移行の変化点の規定と字面で衝突する(重大度: 中)

- 所在: `gate-criteria.md` G-6 の既存の記録の箇条(L1072 付近)、ADR-0120 決定2 の5つ目の箇条
- 根拠: 同じ G-6 は「記録の無い確認も、1名の名簿では効かせたまま」とし、ADR-0111 決定5 は移行の変化点で記録の無い確認を確認待ちとして効かせる。実際、2b の準備(2人目を足す変化点)は、記録の無い確認の Dupont が記名した既存の規則・変更種別を確認待ちで通している(X1 の前提)。無条件の文は、これらの場面でも照合に使わないと読める。裁定は 2-B を採らないとしただけで、この一般の文を求めていない
- 実行での裏づけ(`probe2.mjs`): Y1 1名の旧い構成(記録の無い確認の Dupont が既存の規則・変更種別の記名者)で、Dupont が記名する無関係の変化点を受け付け、委任の席は delegated のまま。Y2 1名から2名へ移る変化点でも、規則 DR-001 と委任の席が保たれる。どちらも、記録の無い確認で既存の記録の記名者を通している。実装は正しく、本文の文だけが実装と食い違う
- 直し方の向き: 「本人以外の確認の照合の根拠に、記録の無い確認を使わない」のように、決定2 の照合に範囲を限る。1名の名簿と確認待ちの扱いは変えない旨を同じ文に書く

### F-2 G-6 の「例外として」と、ADR-0120 の決定6 の読みの関係が食い違う(重大度: 低〜中)

- 所在: G-6 の既存の記録の箇条「照らし直さないことの例外として」。ADR-0120 ステータスの表の ADR-0111 決定6 の行
- 根拠: ADR-0120 は、決定6 の照らし直しの禁止を「効力を落とす向きの照らし直しを止める規定と読む」とし、決定2 の照合は禁止の範囲の外にあるという読みを書いた。G-6 は同じ照合を禁止の「例外」と書く。読みの関係を明記するという裁定の条件は ADR では満たしているが、本文と ADR で読み方が2つになる
- 直し方の向き: どちらかへ揃える。ADR の読み(禁止の範囲の外)を採るなら、G-6 の「例外として」を「この禁止は、本人以外の確認の変化点で確認を数えた後の構成で照らす照合を妨げない」の形にする

### F-3 2g の否定の場面が回帰へ固定されていない(重大度: 低)

- 所在: `test-name-confirmation-timing.mjs`、回帰の試験 `suite/name-confirmation.mjs`(場面の一覧)
- 根拠: 裁定は「確認の変化点の外(2g など)の拒否が残ることを実行で確かめ、否定の場面を回帰へ固定する」とした。固定されたのは記名なしの変化点と、同じ変化点で旧い確認の人が足した規則・変更種別である。高橋による登録し直し(2g)と、旧い確認の本人が記名する確認の外の変化点(X3)は固定されていない。挙動は X2・X3 で拒否を確かめた
- 直し方の向き: 2g と X3 の2場面を否定の場面として足す

### F-4 確認の外の拒否の案内が、変更種別の拒否の文にだけ付く(重大度: 低)

- 所在: `generate-profile.mjs` の `legacySigner` の案内(変更種別の拒否の文に足す)
- 根拠: 裁定は「拒否の文で、原因と本人以外が確認すれば通ることを案内する」とした。X3 では席の記名の検査が先に拒否し、その文は本人以外の記名の確認を要する旨を言うが、「本人以外が確認すれば既存の記録も照合して通る」ことは言わない。既存の規則(DR-001)の成立が落ちる場面(差分の「委任 → 協働」)にも案内が無い
- 直し方の向き: 既存の規則の成立が落ちる行にも同じ案内を付けるか、拒否の末尾に1回まとめて出す

### F-5 名簿に既にある確認の旨を、数えられない記名者が意図して確認する場合は、拒否されず注意で通る(重大度: 低)

- 所在: `nameConfirmationCandidates` の `explicit`(前の名簿に同じ氏名の確認の旨があれば明示でないと扱う)、ADR-0120 決定1 の4つ目の箇条
- 根拠: 既存の旗の確認は「名簿をそのまま渡す」手順で行う(拒否の文の案内もそう書く)。この手順では、明示した確認と自動で載る確認を区別できない。Dupont が Gemini の既存の旗を確認するつもりで記名すると、拒否ではなく注意で通り、確認は記録されない。注意は出るため黙っては通らない。ADR はこの境界を「この変化点で書いたものでない確認」と定義しており、ADR とは一致する
- 直し方の向き: 注意の文に「この変化点は確認として記録されていない」ことを強く出す。または、確認の変化点を明示する入力(例: 確認の対象の id の列挙)を設けるかを後続で検討する。この点は採否の判断を要するので、この突合では向きの候補だけを示す

### F-6 ADR-0120 に「見直しの契機」の節が無い(重大度: 低)

- 所在: `0120-uncountable-confirmations-and-later-signer-check.md`
- 根拠: 直近の ADR-0115〜0119 は、どれも「見直しの契機」の節を持つ。ADR-0120 は決定3 で EV-0236 を引くだけである。EV-0236 の差し替え条件(照合した既存の記録を別の者が記名していた事象が1件でもあれば見直す)は、ADR の見直しの契機に当たる
- 直し方の向き: EV-0236 の差し替え条件を、見直しの契機の節として ADR にも書く

### F-7 ADR-0111 への追記に日付の前置きが無い(重大度: 低)

- 所在: `0111-name-confirmation-in-same-change-point.md` のステータスの節に足した段落
- 根拠: 同じ日の先例(ADR-0114 の「補足(2026-11-11): … ADR-0119 が補いました」)は、日付つきの前置きを付けている。採用済み ADR の本文を書き換えない規約は守られている(ステータスの節への追記だけで、決定6 の本文は変えていない)
- 直し方の向き: 「補足(2026-11-11):」を前置きする

### F-8 強制層の変更が承認待ちであることが、ADR のステータスに無い(重大度: 低)

- 所在: ADR-0120 のステータス「採用(2026-11-11)」。テンプレートのコミット本文は「AI維持管理者の承認待ち(承認者は未記入)」とする
- 根拠: ADR-0115 は「所有者の承認待ちの事項」を節として持つ。ADR-0120 は承認待ちに触れない
- 直し方の向き: 承認待ちである旨と、承認の記録の置き場を ADR のステータスか影響の節に書く

## 3. 確かめて問題が無かったこと

- 経路1: 明示した氏名の確認・アカウント名の確認は、数え方の関数(`confirmedNames`・`confirmedAccounts`)へこの変化点の記録1件だけを渡して照らし、数えられなければ拒否する。AR-5 は `nameConfirmPending` を外して照らすため、同じ関数で null になり、特例として扱われる。原因を名指しする文は AR-5 の側に残る
- 経路1: 名簿に既にある確認の旨は、数えられない記名者の変化点の記録へ載らず、注意が出る(1d)。数えられる記名者では載る(対照)
- 経路1: 正当な確認(山田の記名)は通る。1名の名簿の本人の記名は `self` として数える
- 経路2: 照合は `laterConfirmation` があるとき(本人以外の記名として数える確認を記録する変化点)に限る。既存の規則は、この変化点で追加・変更・承認していないものに限る(`existingRuleIds`)。既存の変更種別は前の構成と JSON が一致するものに限る
- 経路2: 照合の日付は変化点の `date`(試験で `DAY`)、記名者は `decidedBy`。既存の changeLog は書き換えない(試験で前の記録と一致を確かめている)
- 経路2: 差分の行・変化点の記録(`laterSignerCheck`)・D-0 の変化点の履歴・集約の保証の開示(組織の外へは件数だけ)で、作られた時点の照合と区別して出る
- 統制: 確認の前は契約検査と集約が落ちる(X1)。確認の後は、照合で通した記録以外の error は出ない
- G-6 の1文は、裁定の文のとおり氏名とアカウント名の両方の箇条に入った
- IMPL-0472・0473 は書式どおりで、`impl-inventory.yaml` に登録され、台帳の検査を通る。EV-0236 は caution の書式どおりで、台帳の検査を通る
- 文体: 本文はですます調、箇条書きはである調。内部リンクは `/process-compass/` を含む
- 裁定に無い追加: F-1 の一般の文のほかは見当たらない。採らない案(1-E、2-A、2-A'、2-B、弱めた 2-B、2-C)は ADR の採らなかった案に記録されている
