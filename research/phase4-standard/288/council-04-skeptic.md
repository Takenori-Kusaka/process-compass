# 288 会議体 意見書04 — 懐疑役(現場の開発責任者)

- 日付: 2026-10-03
- 立場: 現場の開発責任者として、過大な主張と形骸化を警戒する。「組織として品質を保証する」へ改めること自体には反対しない(調査の2ファイルが支持している)。改訂が次の失敗を生まないかを突く
- 入力: `council-00-brief.md`、`research-01-japan.md`(以下「調査01」)、`research-02-international.md`(以下「調査02」)、`adoption-decision-sheet-draft.md`(以下「シート」)、ADR-0056、附属書H(`assurance-case.md`)、第4章 G-7・G-8(`gate-criteria.md` 446〜675行)、`research/282-survey-2026-09/themes/TH06・TH07` の結論

## 結論(10行)

1. 「保証する」は**既定の宣言ではなく、条件が揃ったときにだけ導ける結論**として書く。成立条件は保証の開示から機械で判定し、満たさない出荷では組織も「保証する」と書けない
2. 保証の三つの動詞(確実にする・確認する・実証する)は、**動詞ごとに対応する記録を名指しする**。記録を持たない動詞は主張に含めない
3. 層1(トップマネジメントの受容の基準)は、**許容量の宣言ではなく「受容しない条件」の否定リスト**と外枠の列挙にする。1ページ・導入時と変化点だけ。案件ごと・出荷ごとに書かせない
4. 「全員の合意」は要件にしない。代わりに、**異議を退けた受容を層1 の責任者へ自動で届ける**経路と、異議 0 件の継続を形骸化の兆候として見る規定を置く
5. AI の誤りへの答えは「プロセスを回したから」ではなく、**出荷ごとの製品側の証拠(人が先に定めた基準への機械検査、独立した人の確認、測った検出能力)**に置く。準拠の事実だけを根拠に保証を主張してはならない、と書く
6. 1名体制は、外部の確認者を置かない限り**組織として品質を保証すると主張できない**と明記する。価値ゼロにしないために、現行 H.8 の「言える表現」と、外部依頼で成立条件へ到達する道筋を併記する
7. シートは附属書へ規範として取り込まない。本標準の回答を Q1〜Q9 に限って附属書H から投影し、Q10〜Q18 の大半は「答えを持たない」と明記する。回答は作成者の自己評価であり E0 で開示する
8. ADR-0056 の決定2〜7・10 は残す。置き換えるのは帰結「品質を保証すると主張しない」、H.1「品質保証の意味」、H.8 の一律禁止。G-8 には受容の基準への照合と、異議を退けた受容の上申を足す

## 懐疑の出発点 — 改訂が生みうる5つの失敗

| # | 失敗 | 根拠 | 本意見書で防ぐ箇所 |
| --- | --- | --- | --- |
| F1 | 「保証します」の言葉だけが先に立ち、根拠と証拠が伴わない | 品質不正の上位要因はコンプライアンス意識の欠如と品質保証部門の牽制の不全(各72%、調査01 S9)。本標準の効果の測定は無い(附属書H H.9 問17、E0) | 決めること1・4 |
| F2 | 組織の合意が同調圧力や形式的な承認に崩れる | 「強い同調圧力のゆえに…できないことをできないと言うことが困難」(調査01 S9)。形式の機械強制が中身を伴わない充足を生んだ事例(TH07 FND-0097、E2)。確認ダイアログが形だけの同意になる経路(TH07 FND-0236、E1) | 決めること2 |
| F3 | AI が誤ることを前提にした根拠になっていない | 「開発プロセスの管理による品質保証が寄与する割合も小さい」(QA4AI、調査01 S22)。文脈を切り離した再レビューでも注入欠陥の約73%を見逃した(TH06 FND-0087) | 決めること3 |
| F4 | 1名体制・小さな組織で、保証できないのに保証すると書く | 1名体制では独立は成立しない(附属書H H.11)。附属書H の表示例は、検出能力が5回連続で未測定(H.6) | 決めること4 |
| F5 | 層1 が現場の負荷と形骸化を増やす | 文書が製品を上回る状態(ADR-0056 却下案「案件ごとに論証を書かせる」)。装置修理 PR が 55〜65%(TH07 FND-0230、E2) | 決めること2・6 |

現場から見て最も起きやすいのは F1 と F5 の組み合わせです。経営層が「保証すると書ける標準になった」と受け取り、営業資料から範囲と開示が落ち、現場には受容の基準の書類が増える。改訂の文言は、この経路を塞ぐことを最優先にするべきです。

## 決めること1 最上位の主張の文言

### 案

主張を**条件つきの結論**として書きます。

> 本標準を適用する組織は、次の成立条件をすべて満たす出荷について、(範囲)の品質を保証すると、顧客・社会へ主張できる。保証とは、組織が顧客・社会との約束(受入基準と受容の基準)を明文化し(実証する)、それを満たすプロセスを確立し(確実にする)、出荷ごとに独立した検証と是正を行い(確認する)、その結果と確かめていない範囲を証拠として示したうえで、組織が責任を引き受けることをいう。保証を主張し、その責任を負うのは、適用した組織のトップマネジメントである。本標準は保証しない。

- **主語**: 適用した組織。説明責任はトップマネジメント(調査02 結論1、ISO 9001 5.1.1 a)。本標準そのものは主語にしない(調査02 結論2、GSN 0:3.2)
- **相手**: 顧客・社会(調査01 S4 注記3、結論3)。組織内の人々ではない
- **動詞と記録の対応**: 3つの動詞は、それぞれ次の記録が実在するときだけ主張に含める。記録を名指しできない動詞は書かない

| 動詞 | 中身 | 対応する記録(既存) | 記録が無いとき |
| --- | --- | --- | --- |
| 確実にする | プロセスの確立 | 層1 の受容の基準、D-0 体制図、テーラリングの宣言、ゲートの構成 | 主張できない |
| 確認する | 出荷ごとの検証と是正 | G-5 の実行記録、G-6 の判定記録、検出能力の測定値(5.6.2)、ポストモーテム(C9) | 測定値が「未測定」なら成立条件(e)を欠く(決めること4) |
| 実証する | 約束の明文化と証拠の提示 | 受入基準(G-2・G-4)、保証の開示(H.6)、G-8 の受容の記名 | 主張できない |

- **主張の成立条件**は保証の開示の値から機械で判定し、開示の1行として出す(決めること4 の表)。人が「成立している」と書く欄を作らない
- **主張しないこと**(現行 H.2)は全て残す。加えて「本標準への準拠、および組織内の受容が、製造物責任・契約責任・規制上の責任を限定すること」を主張しないことへ足す(調査01 S16・S19、調査02 5節。製造物責任は無過失責任で、社内の合意は抗弁にならない)
- **根拠水準マーク**を最上位の主張そのものへ付ける。「この成立条件を満たした出荷で欠陥の流出が減る」ことは測っていない(H.9 問17、E0)

### 理由

- F1 への対策の核心は、**「保証する」の文言と、証拠の有無を切り離せないようにすること**です。宣言を既定にすると、条件を欠いた出荷でも同じ文言が残ります。結論として導く形なら、条件を欠いた出荷では文言そのものが出ません
- 調査01 の含意(c)と調査02 の含意7 は、いずれも主語の取り違えが誤りの本体だと言っています。主語を組織へ移すことには賛成です。ただし主語を移しただけでは、品質不正の構造(宣言と実態の乖離)は防げません。JSQC-Std 52-001 の「確実に保証することができる」も、RCA による改善が回り続けることを前提にしています(調査01 S8 の (b))
- 動詞ごとに記録を名指しするのは、JSQC 注記3 の「実証する」が「約束を明文化し、それが守られていることを証拠で示す」と定義されているからです。証拠を名指しできない保証は、この定義から外れます

### 採らない案

| 案 | 理由 |
| --- | --- |
| 「本標準に従えば、組織は品質を保証できる」と無条件に書く | F1 そのもの。準拠の事実が保証の根拠になり、QA4AI の指摘(プロセス管理の寄与は小さい)と正面から矛盾する |
| 「本標準は品質を保証する」 | 規格は保証しない(調査02 結論2、IEEE の告知、GSN 0:3.2)。主語の誤りを逆向きに犯す |
| 保証の水準を3段階以上の等級で示す | ADR-0056 決定6 の却下理由(等級が目標になる、境界に実証が無い)が今も当たる |
| 「リスクを最小化している」を主張の中身にする | 規格の基準は受容可能な残留リスク(調査02 結論6、AI RMF 1.2.3)。最小化は検証できず、言葉だけが残る |

## 決めること2 組織の合意と、許容できるリスクの決め方

### 案

**層1 は「受容しない条件」を中心にした1ページに限る**。トップマネジメントが導入時に記名し、体制の変化点(第3章 3.13)と重大な欠陥の流出の後に見直します。

| 層1 の欄 | 書くもの | 書かないもの |
| --- | --- | --- |
| 1 外枠 | 適用される法令・契約・業界規格の列挙。「該当なし」も値として書く | 社内で決めた許容量を、外枠より緩く書くこと |
| 2 受容しない条件 | 事業決裁者が G-8 で受容してはならない残存リスクの条件(例: 独立した人の確認を経ていない R1 の変更、検出能力の未測定が組織の定めた回数を超えて続く、CL1 以上で G-6 未達) | 数値の「リスク許容量」。ソフトウェアで測れない値を書かせない |
| 3 受容の権限 | G-8 で受容できる者と、層1 の責任者へ上げる条件 | 部門ごとの合意の手続 |
| 4 対外の伝達 | 受容した残存リスクを顧客へどう伝えるか(受託は納品ごとの保証の開示) | — |
| 5 見直しの契機 | 体制の変化点、重大な欠陥の流出、受容しない条件に一度も当たらないまま組織の定めた期間が過ぎたこと | 定期の全面改定の義務 |

- **置き場所**: 新しい様式を作らず、D-0 の表1 またはテーラリングの宣言へ欄として足す。第8章の宣言と同じ扱いにする
- **出荷ごとの照合**: G-8 の事業決裁者は、保証の開示が欄2 の条件に当たるかを確かめる。当たるかどうかは開示の値から機械で読める形に書かせる。当たる残存リスクは事業決裁者が受容できず、欄3 の者へ上げる
- **「全員の合意」は要件にしない**。代わりに次の2つを置く
  - 周知: 層1 を組織の構成員が読める場所に置く(ISO 31000 5.2「組織と利害関係者へ周知」、調査02 2.1)
  - 止める声の経路: 構成員の誰でも、欄2 に当たる疑いを出荷判定者へ届けられる。届いた疑いは G-8 の異議の欄へ転記される
- **独立した牽制**: 現行の G-8「出荷判定者の異議」に次を足す
  - 事業決裁者が**異議を退けて受容した**場合、その記録を層1 の責任者(トップマネジメント)へ自動で届ける。止める権限は増やさない。届けるだけ
  - 内部監査は、異議の件数が組織の定めた期間 0 件のまま続くことを、所見 0 件の継続と同じく抽出条件にする(プロセス内部監査「監査自体の形骸化を検知する」と同じ型)

### 理由

- 調査の補正(c)「規格が求めるのは全員の合意ではなく、権限を持つ者の説明責任・記名・責任の割り当て・周知」(調査02 結論5)に従います。全員の合意を要件にすると、F2 の温床を条文にすることになります。品質不正の第三者委員会報告18件のうち72%が牽制の不全を挙げ、同調圧力を明記しています(調査01 S9)。合意を求める規定は、反対しにくい空気を正当化します
- 全員参加を「全員が責任者」と読むと、誰も止めない状態になります(調査01 2節 (b))。責任を名指しの記名へ集める現行の設計(G-8 の記名)は正しく、維持します
- **層1 を否定リストにする理由**: 肯定形の「許容できるリスク量」は、ソフトウェアでは数値で書けません。書けない値を書かせると、「社会的に許容される水準とする」のような空文が並び、毎年同じ文面で記名される書類になります(F5)。否定リストなら、開示の値と機械で照合でき、**実際に出荷を止めたかどうかで働きを測れます**
- ISO 14971 4.2 は受容の基準の方針をトップマネジメントに求め、水準は定めません(調査02 2.3)。AI RMF も、既存の基準が無い場合に限って組織が許容度を定めるとします(1.2.2)。外枠を先に列挙させるのは、経済産業省の「社会的に許容できる範囲」が先、事業の採算が後、という順序(調査01 S16・S17、4節 (c))を書式で強制するためです
- 異議を退けた受容の上申は、JSQC-TR 12-001 の要因「品質保証部門と社長を含む経営層との関係が希薄であった」(調査01 S9)への直接の対策です。拒否権を足さないのは、ADR-0056 が G-7 を値の良否で止めない設計にした理由(形式を満たすための記入が起きる)を壊さないためです
- 見直しの契機に「一度も当たらないまま期間が過ぎた」を入れるのは、作動しない統制は機能している統制と区別できない(附属書H H.7)からです。層1 自体の形骸化を、層1 の欄で検出させます

### 採らない案

| 案 | 理由 |
| --- | --- |
| 「組織の全員が合意していること」を保証の要件にする | 補正(c)に反する。F2 を条文化する。合意の記録は署名の束になり、何を確かめたかを示さない(TH07 FND-0233) |
| 層1 を案件の開始時ごとに書かせる | F5。案件ごとの論証を却下した ADR-0056 の理由と同じ |
| 層1 に数値のリスク許容量を書かせる | 測れない値の記名は空文になる。外枠が定める場合はその値を欄1 に書けば足りる |
| 品質保証部門に出荷の拒否権を与える | G-7 の設計を壊す。止める権限を持つ者を増やすと、滞留と、止めないための形式的な通過の両方が起きる。上申で足りる |
| 品質保証部門の設置を要求する | 小さな組織で成立しない。牽制は機能(異議・上申・内部監査)で定め、部門を定めない(附属書H H.12 の現行方針) |

## 決めること3 AI の関与を前提にした保証の根拠

### 案

保証の根拠を、プロセスへの準拠ではなく、**出荷ごとの製品側の証拠**に置くと明記します。

> 組織が保証を主張する根拠は、本標準への準拠の事実ではない。出荷ごとに、(1) 人が生成より前に定めた受入基準への決定論的な検査の結果、(2) 作成を指示した者と別の人による確認の記録、(3) 測定した検出能力、(4) 確かめていない範囲の開示、(5) 出荷後に誤りを検出し戻す手段、の5つである。本標準は、この5つの証拠が出荷ごとに生じ、欠けたときに欠けたと表示される仕組みを定める。本標準への準拠の事実だけを根拠に、保証を主張してはならない。

- **QA4AI への答え**: 「プロセスの管理が AI の成果物の品質を保証する」とは言わない。プロセスの役割は、製品側の証拠を出荷ごとに生じさせ、欠けた証拠を隠せなくすることに限る、と書く。NEC の「プロセス品質は必要条件だが十分条件とはしない」(調査01 S12)と同じ立ち位置を、本標準の言葉で明記する
- **AI の確認の数え方**(ADR-0056 決定4、附属書H H.4)は変えずに、保証の根拠の側からも引く。AI の推定による判定は判定に数えず、検出の層に限る。複数の AI の合議・一致は数えない
- **検出能力が「未測定」の出荷は、根拠(3)を欠く**。附属書H H.11 が自ら書くとおり、C5(人の確認)は C6(検出能力の測定)なしには立たない。決めること4 の成立条件(e)へつなぐ
- **残るリスクは主張の隣に置く**: 誤りの相関、仕様の誤り、注入欠陥と実欠陥の差(H.11)は、保証を主張する文書の中で、主張と同じ見出しの下に書く。附属書の末尾へ追いやらない
- **担当者・モデル・ベンダーの交代**: 現行の 3.4.2(担い手の識別ごとの適合性確認と失効)、3.12、3.13 で答える。交代の後は検出能力の値が失効し、成立条件(e)を自動で欠く

### 理由

- F3 の核心は、QA4AI の「寄与する割合も小さい」(調査01 S22)を、言い換えでかわさないことです。シートの経営・QAへの説明文「AIを信用することを採用条件としない」は方向として正しいが、そのまま書くと、何が信用の代わりになるのかが空いたままになります。代わりになるのは、AI と独立な手段で得た製品側の証拠だけです(シート Q4・Q6)
- 現行の附属書H は、この5つの部品を既に持っています(C2〜C9)。改訂で足りないのは、**保証の主張とこの5つの証拠を結ぶ規定**と、**準拠の事実を根拠にすることの禁止**です。後者が無いと、「ピットイン方式に準拠しているので品質を保証します」という F1 の文が書けてしまいます
- AIQM の「自己適合宣言の拠り所」という位置づけ(調査01 S23)は使えますが、拠り所はあくまで拠り所です。宣言の中身は組織の製品の証拠でなければ、AIQM 自身の「エビデンスの定義や承認者の明確化が必要」とも合いません
- 外部信号なしの自己修正は改善しない(TH06 FND-0086、E3)、LLM 間の誤り相関(同 FND-0079、E3)。AI の確認を重ねることは、保証の根拠になりません

### 採らない案

| 案 | 理由 |
| --- | --- |
| 「本標準のプロセスに従うことが、AI 成果物の品質の根拠である」 | QA4AI と矛盾する。F1 の文を許す |
| 複数の AI による相互確認の一致を、保証の根拠に数える | 誤りの相関(FND-0079)。現行 H.4 の禁止事項と矛盾する |
| AI の層の検出率が高いことを、人の確認を減らす根拠にする | H.4 条件4 に反する。73%見逃しの測定(FND-0087)がある |
| 適合性確認(3.4.2)の結果を検出能力の値として保証の根拠にする | 事例への合否であり、工程での検出率ではない(H.7) |

## 決めること4 保証できない範囲と、その場合の扱い

### 案

出荷ごとに、**主張の成立条件**を保証の開示から機械で判定します。結果は2値(成立 / 不成立)で、不成立なら欠けた条件を列挙します。

| # | 成立条件 | 読み取る開示の項目 | 欠けやすい体制 |
| --- | --- | --- | --- |
| a | 層1 の受容の基準が記名され、見直しの期限内である | 項目2(テーラリングの宣言) | 導入直後 |
| b | 開示が層1 の「受容しない条件」に当たらない | 項目1・3・5・6 | — |
| c | R1 の変更がすべて、作成を指示した者と別の人の確認を経ている(例外承認で出荷した R1 の変更は、成立に数えない) | 項目1・3 | 1名体制 |
| d | 出荷判定者(G-7)と事業決裁者(G-8)が別の自然人である | 項目1 | 1〜2名体制 |
| e | 人の層の検出能力が、組織の定めた期間内に測定されている | 項目6 | 小規模全般 |
| f | 保証の開示に記載の欠落が無い | G-7 基準9 | — |

- **不成立の出荷では、組織は「品質を保証する」と書かない**。代わりに定型の文を出す。言い換えない

  > 本リリースについて、組織は品質の保証を主張しません。満たしていない条件は次のとおりです。実施した確認と、確かめていない範囲は、添付の保証の開示のとおりです。

- **1名体制は、外部の確認者を置かない限り c・d を欠き、保証を主張できない**と明記する。代償措置は条件の充足に数えない(現行 H.6「代償措置は未達の解消として扱わない」と同じ)
- **価値をゼロにしない書き方**: 不成立でも、次の3つは残ると書く
  - 現行 H.8 の「使ってよい表現」(実施した事実、記録から再構成できること)は、成立・不成立を問わず使える
  - 欠けた条件が列挙されるので、受け入れる側(顧客・発注者)が、自らの判断で受け入れるかを決められる(H.9 問8「可否は受け入れる側が決める」を維持)
  - 成立へ届く道筋を示す。1名体制でも、R1 の変更の確認を外部へ依頼し(c)、G-7 を外部の者が担えば(d)、成立へ届く。道筋の表を附属書H に置く
- **不成立の出荷で残存リスクを受容するのは、現行どおり G-8 の事業決裁者**。受け入れる側への伝達は層1 の欄4 による
- 成立条件の選定には実証が無い。根拠水準マーク(E0)を付け、差し替え条件を書く(例: 成立と判定した出荷と不成立の出荷で、出荷後の欠陥の比率に差が無ければ、条件を見直す)

### 理由

- F4 への対策は、**小さな組織にも保証を主張させる書き方を探すことではなく、主張できないことを正直に、機械的に表示させること**です。1名体制では独立は成立しません(H.11)。そこで「組織として保証する」と書かせれば、それは F1 の小型版です
- NEC は導入期を「組織による品質保証: 対象外」と、組織が明示的に決めています(調査01 S12)。保証しない段階を明示することは、日本の実務に先例があります
- AI Act 第17条2項は規模への比例を認めつつ、「いかなる場合も、要求される厳格さと保護の水準を尊重する」と続けます(調査02 4.4)。規模で変えてよいのは実施の程度であり、**保証の主張の条件を規模で緩めてはなりません**
- 2値は ADR-0056 決定6 の「等級で表さない」と緊張します。区別を書きます。決定6 が退けたのは品質の水準の等級です。成立条件の判定は、品質の水準ではなく、**主張の前提が揃っているかの判定**です。2値を超える段階(「部分的に保証」など)は作らない。段階を作ると、等級と同じく目標になります
- 成立条件 e を入れるのは、検出能力の未測定が常態化しうるからです。附属書H の表示例は5回連続の未測定を示しています(H.6)。未測定のまま保証を主張できるなら、確認は「やった」の記録だけになります(TH07 FND-0097 の型)
- 判定を機械にするのは、人が「成立」と書く欄を作れば、同調圧力の下でそこが埋まるからです(F2)

### 採らない案

| 案 | 理由 |
| --- | --- |
| 1名体制でも、代償措置を条件に保証を主張できるとする | 代償措置は未達の解消ではない(現行規定)。F4 そのもの |
| 1名体制での本標準の適用を禁じる | ADR-0028・ADR-0056 の方針(未達を隠さず表示する)に反する。小さな組織が本標準を使う理由を失う |
| 成立を人の判断(品質保証部門の判定)で決める | 判定の欄が同調圧力で埋まる(F2)。G-7 に十分性の判定を戻すことにもなる |
| 「条件付き保証」「限定保証」の段階を設ける | 等級と同じく目標化する。対外文書で限定句が落ち、「保証」だけが残る(F1) |
| 成立条件に「層1 の記名」だけを置き、出荷ごとの照合を求めない | 一度記名すれば以後すべての出荷で保証を主張できる。導入時の書類が免罪符になる |

## 決めること5 採用判断シートの扱い

### 案

- **シートを規範の附属書として取り込まない**。採否のロジック(採用可能〜不採用)は採用する組織が使う道具であり、本標準の要求事項ではない
- **本標準の回答**を、附属書H H.9 と同じく既存の条項からの投影として置く。対象は Q1〜Q9 に限る。各回答はシートの5要素(主張・範囲・根拠・証拠・限界と責任)で書く。現行 H.9 の列(答え・根拠の条項・根拠の水準・証跡)に「範囲」と「限界と責任」を足す
- **回答は作成者の自己評価である**と明記し、根拠水準マーク(E0)を付ける。差し替え条件は、実在の採用組織の品質保証部門がシートを記入した記録
- Q10〜Q18 は、本標準の範囲で答えられるものと答えられないものを分けて明記する

| Q | 本標準の現行の範囲で | 該当する箇所 |
| --- | --- | --- |
| Q10 投資の目的・停止基準 | **答えを持たない**。事業の判断である | — |
| Q11 総費用と便益 | **答えを持たない**。統制の費用を測る規定は無い | — |
| Q12 依存先の把握 | 一部。モデルの提供者は 3.12 で扱う。個人・プロンプトの依存の重要度と代替性は扱わない | 3.12、5.8.2 |
| Q13 AI 停止時の縮退 | 一部。AI が使えなかった期間の扱いを開示する(項目7)。縮退運転の計画は求めない | 3.12.5、H.6 項目7 |
| Q14 自社に残る資産 | 一部。仕様・受入基準・判定記録はリポジトリに残る。移管可能性は検査しない | 第6章 |
| Q15 生成に関与しない人の理解・変更 | 一部。G-6 の挙動要約。保守性の検証は求めない | G-6、附属書C |
| Q16 技術判断力の維持 | **答えを持たない**。任命基準(3.4)はあるが、後継者の育成計画は扱わない | — |
| Q17 誰が止められるか | 一部。権限の一時制限(7.9)、G-8 の差し戻し、異議。評価構造(リスクを隠さない人事評価)は扱わない | 7.9、G-8 |
| Q18 有事の決定 | 一部。インシデント対応。契約変更・規制変更時の顧客説明は扱わない | インシデント対応、H.9 問16 |

- 「答えを持たない」は、**本標準が課さないと決めた**ことを示す(コアポリシー)。採用する組織が自らの規程で答える
- シートの「即時保留・不採用条件」8項目は、本標準の規定と突合し、対応する規定がある項目(「AIが正しい根拠が同じAIの説明だけ」→ H.4、「受容する責任者がいない」→ G-8 の記名)と、無い項目(「業務知識を自社へ取り出せない」「人材を維持する計画がない」)を表で示す

### 理由

- 本標準の作成者が、本標準の採用判断の問いに自ら答えて「採用可能」の材料を出すのは、シート自身が退ける循環(Q4「AI自身の自己評価とは異なる根拠」)と同じ構造です。回答を出すことは有益ですが、自己評価であることを開示しなければ F1 になります
- シートの5要素は、IPA「品質説明」の4項目にシートが「限界と責任」を足したもので(調査01 3節 (b))、公的な先行枠組みと対応します。H.9 の列へ取り込む価値があります
- 組織継続命題(Q10〜Q18)を本標準の範囲へ広げると、本標準は事業継続計画と人材育成の規格になり、装置が肥大します(F5)。答えられないと書くほうが信頼性が高い。読み手が「書かれていない」と「課さないと決めた」を区別できるからです
- 採否のロジックを規範にすると、「採用可能」の判定が目標になり、回答欄が埋めるための記入になります(TH07 の Goodhart の型)

### 採らない案

| 案 | 理由 |
| --- | --- |
| シートを附属書として取り込み、採否のロジックを規範にする | 採用判断は採用する組織の権限。判定が目標化する |
| 導入時ゲート(G-0)を新設し、Q1〜Q18 の回答を合否条件にする | 新しいゲートを足さないという ADR-0056 決定10 に反する。F5 |
| Q10〜Q18 にも本標準の回答を用意する | 範囲外の約束になる。答えを持たない問いに答えを書くと、読み手は課されていると誤読する |
| 回答を本標準の作成者の判断で「回答あり」と判定して載せる | 自己評価の循環。E0 の開示なしには載せない |

## 決めること6 既存の決定との関係

### 案

| ADR-0056 の決定・帰結 | 扱い | 理由 |
| --- | --- | --- |
| 決定1 附属書H を投影として置く | 残す | 第2の正本を作らない設計は、層1 を足しても変える理由が無い |
| 決定2 最上位の主張(工程についての主張) | **残し、位置を変える**。新しい最上位の主張(決めること1)の根拠(層2 の論証の中身)とする | 工程の主張は、保証の根拠として今も正しい。上に組織の主張を載せる |
| 決定3 主張しないこと | 残す。「準拠と組織内の受容が外部責任を限定すること」を足す | 主張しないことを減らす理由が無い。外部責任の一文は調査01・02 が揃って求める |
| 決定4 AI による確認の数え方 | **そのまま残す** | QA4AI への答えの核。弱めると F3 |
| 決定5 署名の意味 | 残す。G-7 に十分性の判定を戻さない | G-7 の設計は保証の主張と独立に正しい |
| 決定5 異議の経路 | 残し、「異議を退けた受容の上申」を足す | 決めること2 |
| 決定6 保証の開示7項目 | 残す。項目を増やさず、成立条件の判定結果を開示の1行として機械で出す。層1 の版は項目2 に含める | 新しい記述を人に書かせない原則を守る |
| 決定7 形骸化の示し方 | 残す。層1 の「受容しない条件」に当たった件数と、異議の件数を作動の記録に加える | 層1 と異議も作動で測る |
| 決定8 対外表現 | **一部を置き換える**。「品質を保証する」の一律禁止を、「成立条件を満たした出荷について、範囲と保証の開示を伴う場合に限り、組織が使える」に改める。範囲と開示を伴わない「品質を保証する」、「欠陥が無いことを保証する」、「承認した人間が品質を保証する」は引き続き禁止 | F1。限定句が落ちた文を禁止として明記する |
| 決定10 論証を支えない検査の廃止候補 | 残す。層1 にも適用する | 層1 が一度も作動しなければ廃止または見直しの候補 |
| 帰結「本標準は品質を保証すると主張しない」 | **置き換える**。「本標準は保証しない。保証を主張し責任を負うのは適用した組織である。本標準はその主張の成立条件と証拠を定める」 | 調査02 結論2・含意7 |
| H.1「品質保証の意味」(ISO 9000 の定義だけ) | 置き換える。JSQC-Std 00-001 1.3 の三つの動詞を主とし、ISO 9000:2026(2015 年版は 2026-05-27 廃止)を版を明記して併記する。ISO 9000:2026 の本文は未読である旨を残す | 調査01 1節 (c)、調査02 結論8 |

第4章への変更は次のとおりです。

- **G-7**: 性質は変えない。基準9 の突合の対象に「成立条件の判定結果の行」が開示にあることを含める(値の良否は判定しない)
- **G-8**: 次の2点を足す
  - 基準2 の受容は、層1 の「受容しない条件」に照らして行う。当たる残存リスクは受容できず、層1 の受容の権限を持つ者へ上げる
  - 出荷判定者の異議を退けて受容した記録は、層1 の責任者へ届ける
- **新しいゲートを足さない**。層1 は導入時と変化点の宣言であり、ゲートではない

新しい ADR に、ADR-0056 のうち置き換える部分(帰結の一文、H.1、決定8 の一部)を明示して置きます。採用済み ADR の本文は書き換えません。

### 理由

- 現行の ADR-0056 は、F1〜F3 への歯止めとして既に厚い設計です(AI の確認を判定に数えない、署名は正しさの承認ではない、未達を値として開示する、異議の経路)。改訂で問題なのは主語と相手の取り違えであり、この歯止めではありません。歯止めを緩めて「保証できる」に近づける改訂は、信頼性を下げます
- 置き換えを最小限にする動機で言っているのではありません。残す各決定には、上表のとおり今も成り立つ理由があります。逆に G-8 には、層1 と外部責任の層が欠けているという調査02 の指摘(2.3 (c)、7節)が当たるので、変更を要します
- 対外表現の一律禁止を外すと、F1 の入口が開きます。外すなら、「範囲と開示を伴わない形」の禁止を同時に書かなければなりません

### 採らない案

| 案 | 理由 |
| --- | --- |
| ADR-0056 を全面的に置き換える | 決定4〜7 の歯止めまで再審になる。調査はそれらの誤りを示していない |
| 帰結の一文だけを改め、層1 と G-8 を変えない | 受容の基準なしの受容は、案件ごとのその場の判断になる(調査02 2.3 (c))。主語を変えても実態が変わらない |
| G-7 に保証の成立の判定を担わせる | G-7 に十分性の判定を戻すことになる。成立条件は機械で判定し、G-7 は記載の有無を見る |
| 層1 をゲート(G-0)として置く | 新しいゲートを足さない(決定10)。F5 |

## 会議体へ投げる未決の問い

1. 成立条件 e(検出能力の測定)の「期間」を本標準が定めるか、組織に委ねるか。本意見書は組織に委ねる案だが、委ねると「期間を無限に定める」抜け道が残る。最長の上限だけを本標準が持つ案も検討に値する(根拠は E0)
2. 成立条件 c で、例外承認で出荷した R1 の変更を成立に数えない案は、緊急修正の多い組織で常に不成立になる。それを正しい表示とみなすか
3. 受託で、成立・不成立の判定結果を納品ごとに顧客へ渡すことを必須にするか。渡すと契約の条件になり、判定が目標化する恐れがある(現行 H.6 が検出率の値を外へ出さない理由と同じ構造)
