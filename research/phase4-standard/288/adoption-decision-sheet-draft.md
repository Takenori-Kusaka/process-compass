# ピットイン開発プロセス 採用判断シート（たたき台）

> **目的**：本シートは、ピットイン開発プロセスの採用候補者が、開発チームの回答を根拠に「品質保証できるか」「組織として長期運用できるか」の採否ロジックを自ら組み立てるための一枚ものです。個別手法の実施有無ではなく、**何を保証でき、何が残余リスクとして残り、誰が引き受けるか**を問います。

生成AIの管理は、個別成果物の確認だけでなく、組織の方針、責任、リスク評価、測定、運用、継続改善を一体で扱う必要があります。これはNIST AI RMFの Govern・Map・Measure・Manage、およびISO/IEC 42001のAIマネジメントシステムの考え方とも整合します。[^1][^2][^3]

## 採用判断の上位命題

**ピットイン開発プロセスを採用するのは、開発側が次の二つを、適用範囲・根拠・証拠・限界・責任者を伴って説明できる場合である。**

1. **品質保証命題**：AIの成果物を全面的に信頼または全件精読しなくても、重要な誤りを予防・検出・封じ込めし、当該リリースを出してよい理由を説明できる。
2. **組織継続命題**：AIの利用を拡大しても、費用・依存・知識・人材・責任を組織の統制下に置き、AIやベンダーが変化・停止しても事業を継続できる。

## A. 品質保証の問い

| ID | 開発側に求める回答 | ピットイン側の回答記入欄 | 未回答時の判断 |
|---|---|---|---|
| Q1 | **何を、どの利用条件・範囲で「品質保証できる」と主張するのか。** 非対象範囲も明示できるか。 |  | 保証対象を定義できず、採用判断不能 |
| Q2 | **絶対に壊してはならない品質条件は何か。** 業務規則、権限、データ、安全、法令、性能等を具体化できるか。 |  | 検証対象が不明なため保証不能 |
| Q3 | **AIはどこに関与し、どこまで権限を持つのか。** 人間・AI・自動化の責任境界を説明できるか。 |  | AI固有の影響範囲を評価不能 |
| Q4 | **AIが誤っていても、何がその誤りを発見するのか。** AI自身の自己評価とは異なる根拠を示せるか。 |  | 循環的な自己確認となり保証不能 |
| Q5 | **重要な品質条件ごとに、満たしたと判断する証拠は何か。** 要求と証拠の対応を追跡できるか。 |  | 「テスト成功」の意味を評価不能 |
| Q6 | **人間が確認しない部分はどこか。なぜ未精読でも保証できるのか。** 代替証拠と適用限界を説明できるか。 |  | 未レビューではなく未検証となるため不採用 |
| Q7 | **現在の検証でも見つけられない失敗は何か。** 未検証領域と残余リスクを明示できるか。 |  | リスク受容判断ができない |
| Q8 | **出荷してよいという最終主張は何か。** 誰が技術的判断を行い、誰が残余リスクを受容するのか。 |  | QA・採用者への責任転嫁となる |
| Q9 | **出荷後に前提が崩れたことをどう知り、止め、戻し、説明するのか。** |  | 一回限りの検査となり、運用品質を保証不能 |

NIST AI RMFは、AIリスクを文脈化し、測定し、残余リスクを許容範囲内に管理し、運用中も評価することを求めています。 生成AIについては、第三者サービス、知財、プライバシー、情報セキュリティ等の追加リスクと、反復的なテスト・評価・妥当性確認・検証が重視されています。[^2][^4][^5][^6]

## B. 組織・事業継続の問い

| ID | 部門長・開発側に求める回答 | ピットイン側の回答記入欄 | 未回答時の判断 |
|---|---|---|---|
| Q10 | **何の事業成果を得るためにAIへ投資するのか。** 導入しない場合との比較と、停止・拡大基準を説明できるか。 |  | 利用量だけが目的となり採算を判断不能 |
| Q11 | **AIによる便益から、検証・修正・教育・管理を含む総費用を差し引いても価値があるか。** |  | 高価な活動を成果と誤認する恐れ |
| Q12 | **どのAI、ベンダー、個人、データ、プロンプト、エージェントに依存しているか。** 重要度と代替性を把握できるか。 |  | 隠れた単一障害点を管理不能 |
| Q13 | **AIまたはベンダーが停止・値上げ・品質変更した場合、何が止まり、どこまで縮退運転できるか。** |  | 事業継続性を説明不能 |
| Q14 | **AIを替えても自社に残る資産は何か。** 業務知識、仕様、評価基準、テスト、運用手順を移管可能か。 |  | 成果が外部ブラックボックスに閉じ込められる |
| Q15 | **AI生成物を、生成に関与しなかった人が理解・変更・復旧できるか。** 組織能力として再現できるか。 |  | 将来の保守不能・属人化を許容することになる |
| Q16 | **AIに依存しない技術判断力を、誰に、どの水準で残すのか。** 10年後の後継者・育成・交代を説明できるか。 |  | 技術能力の空洞化を管理不能 |
| Q17 | **速度目標と品質・安全・学習が衝突したとき、誰が止められるか。** 現場がリスクを隠さない責任・評価構造か。 |  | トップダウン施策が統制を形骸化させる |
| Q18 | **重大事故、情報漏えい、契約変更、規制変更時に、誰が停止・切替・顧客説明を決定するか。** |  | 有事の責任と意思決定が成立しない |

第三者AIの便益とリスクは継続的に監視し、統制を文書化することがNIST AI RMFで明示されています。 ISO/IEC 42001も、AIを開発・提供・利用する組織に対し、責任、リスク評価・処置、性能評価、監視、継続改善をマネジメントシステムとして扱う枠組みを示しています。[^7][^4][^5][^1]

## 回答の合格条件

各回答は、次の5要素を満たして初めて「回答あり」とみなします。

| 要素 | 判定質問 |
|---|---|
| **主張** | 何ができる／できないと断定しているか |
| **範囲** | どの製品・変更・組織・期間・利用条件に限るか |
| **根拠** | なぜその主張が成立するのか |
| **証拠** | 第三者が追跡・再確認できる記録は何か |
| **限界と責任** | 残る不確実性は何で、誰がいつまで引き受けるか |

「対応しています」「レビューします」「AIは補助です」「別製品へ切り替えられます」「教育します」だけでは回答とみなしません。

## 採否ロジック

| 判定 | 条件 | 採用判断 |
|---|---|---|
| **採用可能** | Q1〜Q18の重要項目に5要素を伴う回答があり、残余リスクが許容範囲内 | 対象範囲を明記して採用 |
| **条件付き採用** | 不足はあるが、影響範囲、代替策、責任者、解消期限が明確 | 対象・期間・利用権限を限定して採用 |
| **検証採用** | 品質または事業価値の証拠が不足するが、小さく可逆的な試行で取得可能 | 本番影響を限定した実証のみ許可 |
| **保留** | 重要回答または証拠が不足し、追加設計・検証で解消可能 | 不足条件を明示して再判定 |
| **不採用** | 保証対象、独立検証、未レビュー範囲、残余リスク受容、依存先、退出能力、責任者のいずれかが不明 | ピットイン開発プロセスを統制可能と判断しない |

### 即時保留・不採用条件

- AIの関与範囲または権限を特定できない。
- 「AIが正しい」とする根拠が、同じAIの説明・テスト・レビューだけである。
- 人間が確認していない範囲と代替証拠を説明できない。
- 重大な残余リスクを受容する責任者がいない。
- AI停止時に重要業務を継続・縮退・復旧する方法がない。
- 業務知識・評価基準・運用知識を自社へ取り出せない。
- 生成物を理解・変更できる人材を維持する計画がない。
- 利用停止を決める基準と権限者がいない。
