# 284・285 検証で見つかった問題の修正仕様(2026-09-30)

3つの検証(突合、場面の検証、品質保証部門の初見レビュー)の指摘を受けた修正。**本書の決定が、作業仕様(`284-285-revision-spec.md`)と食い違う場合は本書が正しい**。ADR-0054〜0056 は未コミットであり、本書の決定に合わせて本文を直してよい(採用済みの旧 ADR は書き換えない)。

## 決定(主担当が決めたこと。担当は言い換えてよいが、意味を変えない)

### K1 委任・標準変更・L3 は同じものを指す
- 委任の範囲(登録した変更種別)は、**標準変更カタログ(第3章 3.7.4)に登録した変更種別**と同じものである
- 登録した種別には、AI自律レベル L3(機械が常時監視し、人が事後に確認する)を適用する。**登録の判定が、当該種別についての 5.4.5 の引き上げの判定を兼ねる**
- 登録の根拠は、連続運用の期間ではなく、7条件の条件3・4(既存のテストで検出できること、取り消しを実行した実績)に置く
- 登録するのは、リリース判定会(B-4)。B-4 を置かない体制では、D-0 体制図の決定の権限を持つ者(人)
- 登録した種別の個別の変更は、G-5 の通過をもって先へ進む(3.7.4 の現行どおり)。**G-6 は事後の抜き取りで判定する。G-7 と G-8 は個別の変更ごとには行わず、登録時の事前承認と、期間ごとの保証の開示への計上で扱う**。期間の開示を突合して記名する出荷判定者の席と、リリース決裁の席は委任しない
- 第8章「極小規模での事後監査への切替」は、**5.5.4 の委任を 1〜2名体制へ適用したもの**として書き直す。分岐の条件を7条件へ揃える(3条件と7条件が併存すると、緩いほうだけが使われる)。「既存の規定(3条件での切替)を7条件へ改めた」ことを ADR-0054 に明記する
- 1〜2名体制で、作成を指示した者と別の人を抜き取りの実施者に置けないときは、責任者本人が抜き取った旨を保証の開示へ表示する。本人による抜き取りを独立した確認として数えない。第8章「事後監査の手続」の直後の文は「対象の抽出方法と所見の是正の追跡はフェーズ6 による。実施者は上表による」とする

### K2 協働の席でも、受入基準の内側の作業上の選択は担い手が決める
- **承認済みの受入基準とスコープの内側にある作業上の選択は、運用形態が協働の席でも、担い手が決めて記録する。選択のたびに人へ戻さない**。人は、変更ごとの確定の場で、記録された選択をまとめて確認する
- 人へ戻すのは、(a) 5.5.5 の人が確定する判断 (b) 受入基準・スコープ・公開インタフェース・データ形式を変える選択 (c) 取り消せない操作、に当たる場合
- ADR-0054 決定6、5.5.1、テンプレートの CLAUDE.md に書く

### K3 2名体制では相互の確認で G-6 が成立する
- 独立は人の単位で定義する(ADR-0054 決定7)。したがって **2名体制では、作成を指示していない側の人が確認すれば G-6 は成立する**。相手も作成の指示に関与した変更と、1名体制では、外部に置く。置けなければ未達
- ADR-0028 決定1 の「外部のレビュア」は「作成を指示した者以外の確認者」と読む。ADR-0054 のステータス欄に、この補足を明記する
- 第3章 3.5 の「3名未満の場合は独立レビューを外部へ依頼する」、第8章 軸A、`src/data/tailoring/questions.yaml` の `q-external-reviewer`(「レビューを頼める相手はチームの外にいる?」)を改める。質問は「作成を指示した本人以外に、確認できる人がいるか」とし、help に「2名体制の相手、他チーム・別部門・社外コミュニティなど」と書く。回答 ID(`reviewer-yes` / `reviewer-no`)は変えない
- G-7(出荷判定者の兼務)は 3名未満では逸脱のまま(ADR-0029)

### K4 席の作業を複数の人が担う場合
- 席の責任者は席ごとに1名。席の作業を複数の人が担う場合(開発者が5名、レビュアが2名など)、成果物ごとの結果責任者は担当表(D-0)で1名に定める(3.2 の現行どおり)
- 責任者でない担い手(人)の増減・交代は、兼務禁止と独立の再判定に影響する場合、または人数の境界を通過する場合に限り、体制の変化点に数える

### K5 体制の縮小と、その他の変化点の扱い
- **人の離脱で成立しなくなった統制は、「緩める向きの決定」ではなく「未達の発生」である**。記名を待たず、即時に未達として構成へ反映し表示する。旧い構成のまま止めない。未達のまま出荷するかどうかは、既存の規定(R1 は 7.3 の例外承認、CL1 以上と規制業は不可)による
- 安全重要度が上がり委任を適用できなくなったとき、抜き取り待ちの委任の変更は、協働の手続で全件を確認し直す
- 提供者の障害・利用上限で AI が使えない期間は、変化点に数えない。ただし期間と、その間の扱い(人へ戻した / 止めた)を D-0 の改訂履歴に記録し、保証の開示の項目7 に出す
- 3.12.5 の一時的な切り替えの間は、担い手の識別が変わるため、委任を協働へ下げる
- ステージを前へ戻す変更(軸B を PoC へ戻すなど)は、記名と理由だけでは足りず、ステージ移行ゲート(SG)の判定を要する
- 委任の範囲を狭める変更は、厳しくする向きである(即時)
- 緩める向きの決定をするのは、対象の席の責任者、または D-0 の決定の権限を持つ者。**AI の名義の記名を受け付けない**
- 納期だけの変更は変化点に数えない。起票された場合は「構成の変更なし」と記録する(第3章・テンプレート・template-repository.md の表現を、この文に揃える)
- 変化点3(運用形態と委任の範囲の変更)の起票は、対象の席の責任者が責任を持つ
- 即時に品質保証部門へ知らせるものへ、「検出の層に数えている AI の担い手の識別の変更」を足す(検出率の測定値が失効するため)。通知先は出荷判定者の席の責任者とする
- 暫定任命(3.4.1)で、確認済みの者による併記を置けない場合は、その判定を未達として表示する

### K6 署名の意味と、品質保証部門の異議
- 出荷判定者の署名が意味するのは、**(1) 事前に定めた出荷基準(欠陥トリアージ基準、安定性の閾値など G-7 の基準)を満たしていること (2) 定めた検証の記録と、保証の開示が揃っていること**。成果物の正しさと、数値の十分性は意味しない
- ADR-0056 決定5 の引用文を次へ改める: 「出荷判定者の署名は、成果物の正しさの承認ではない。事前に定めた出荷基準を満たしていることと、定めた検証の記録および成立しなかった統制の一覧が揃っていることの確認である。一覧に載った残存リスクの受容は、リリース決裁(G-8)の決断の記録に事業決裁者が記名する。」
- **出荷判定者は、開示された未達・未測定について異議を G-8 の決断の記録へ残せる**。事業決裁者は、異議を読んだうえで受容を記名する(G-8 へ規定し、内部監査の観点14「G-8 の決断の記録に、開示された未達・未測定への受容と、出荷判定者の異議の扱いが記載されているか」を足す)
- 附属書D §4 の「既存制度への変更点」へ、3点目「出荷判定者の署名の意味を定め、残存リスクの受容を事業決裁者の記名へ置く。出荷判定の規程の改定を要する」を足し、「手続は変わらない」の類の記述を改める(見出しの「2点のみ」も直す)

### K7 保証の開示の補足
- 項目6 が「未測定」のときは、**未測定が続いている期間(最初の出荷からの経過)を併記する**。未測定は正当な値だが、続いていることを見えるようにする
- 項目1・3・6 には、**前回の出荷の値を併記する**(悪化しているかを読めるようにする)
- 対外文書へ添える保証の開示では、項目6 は検出率の値ではなく、測定している事実・測定時点・推移の向きで示す(H.7 と H.8 の食い違いの解消)
- リスク区分を確定した者を、判定記録へ記名する(3.8.1)。開示の項目3 の区分が自己記載だけに依る場合は、その旨を表示する
- 受託では、納品ごとに保証の開示を受け渡す。委任を適用するかどうかは契約で合意する(第8章 軸D、テンプレ8)

### K8 附属書H の修正
- H.4 条件4 と ADR-0056 決定4 の「委任の範囲を除く」を削り、「通過を理由に人の確認を減らさない。合否条件に入れない。委任の変更で人の事前確認が無いのは、AI の確認の通過によるものではなく、5.5.4 の7条件による」とする
- テストの分離はリスク区分で段階が違う。H.1 の直後、H.4 の表、H.9 のテストの問いを、5.8.4 とフェーズ5「AI生成テストの検出力検証」の本文どおりに書き分ける(R1・R2・R3 それぞれで、実装を渡すか、変異試験が必須か)。H.1 の「切り離された検証」が何を指すか(人の独立 / 文脈の分離 / 入力の分離)を、リスク区分ごとに1つの表で示す
- H.9 へ問いを足す: 教育と力量(3.4.1、3.4.2)、モデル提供者の管理(3.12)、リスク区分を誰が確定するか(3.8.1)、未達が多いとき品質保証部門は出荷を止められるか(K6)、欠陥が流出したとき同じ条件で作った出荷済みの成果物をどう扱うか(5.8.2 の記録で特定できる。遡及点検の範囲は[インシデント対応]で決める。本標準は一律の遡及点検を課していない、と明記)。H.10 へ力量と供給者管理の行を足す
- H.9 の CL の記述と 1名体制の可否は、第8章 軸E と ADR-0028 の本文を読んで一致させる(食い違っていれば、ADR-0028 の「影響」に合わせて軸E の側を直す)
- 利用記録(5.8.2)が全案件で必須であることと、第8章 軸E の「AI生成箇所の追跡(CL0 は任意)」が別のものであることを、両方の本文を読んで書き分ける
- 冒頭の「本附属書が自ら定めるのは」に H.7 を加える
- 「検出の層」を第1章 1.4 の用語へ足し、H.4 の初出で定義を書く

### K9 語の整理
- 5.2 の3点目は「指示した者と別の自然人を責任者とする席が確認する」(1名体制で、同一人物の別の席で満たせる書き方にしない)
- 5.8.4 の段階名と、フェーズ5 `test-effectiveness.md` 冒頭の定義で「独立性」を人以外の単位に使っている箇所を、「分離の段階」へ改める(最強の段階=組織的な独立だけが「独立」)。見出しを変える場合は、その見出しへのリンク元も直す。ADR-0054 のステータス欄に「ADR-0012 決定5・ADR-0015 決定5 の『独立性』の語を、人の単位の独立と、文脈・入力の分離へ呼び分ける(補足)」と書く
- 「R1 は取り消しに相手方の同意を要する変更」という説明は、3.8.1 の R1 の定義(認証・認可・個人データ・事業継続を含む)より狭い。「R1 は事後の取り消しを前提にできない(3.8.1)」へ改める
- 第4章「記録なしで先へ進めば逸脱」の文へ「変更単位で識別された委任の変更を除く」を足す
- 5.5.6 の表の外に置いた限定(委任の列は7条件を満たす変更だけ、協働の列は R2 まで)を、列見出しへ入れる(ADR-0039)
- 第3章 3.5.1 に残る特定の製品名(Filetto)を、製品名に依存しない例へ直す(1.7 の原則)

### K10 根拠水準マーク
- 今回足した根拠水準マーク(ADR-0054〜0056 の EV-0040〜0045 と、本文の EV-0046 以降で実際に使ったもの)の差し替え条件に、**判定の向き**を足す(ADR-0045 決定1: 観測量と、どの値ならどう判断を変えるか)。例: 「…の件数。逸脱と判定された割合が抜き取りの2割を超える場合、R3 の委任を協働へ戻す」のように、向きを文で書く。閾値に根拠が無いなら「N件でも生じた場合」のように書く
- EV-0041 の注記と水準を一致させる(E2 = 単一事例)

### K11 データと周辺ページ
- `src/data/processes/integrated.yaml`: AI維持管理者 × AI運用担当者の分離を、1〜2名体制では逸脱として記録する形へ(現行の `exception: none` を、3.5 の本文に合わせる)。G-1 の「条件付き承認」を第4章の2値へ
- `src/content/docs/tool/knowledge-base-schema.md`(禁止事項の件数、「独立レビューの省略」)、`tool/proposal-logic.md`(同)、`phase5-implementation/ci-gates.md`(「G-7 の判定基準4項目」→ 現行の基準数。保証の開示の出力の制約: リスク区分が PR の自己記載に依ること、など)、`phase5-implementation/qms-document-control.md`(G-7 の成立条件「兼務がない」を 3.5.2 と合わせる)、`phase5-implementation/template-repository.md`(納期の記述)
- `zenn/`(別リポジトリの submodule)は今回触らない

### K12 委任の規則の追加・拡大は、統制の弱化として扱う(ADR-0038 との突合)

突合で「確かめられなかったこと」として残っていた点を決める。

- 委任の該当を判定する機械の規則(`delegation.rules`)は強制層である。規則の追加と範囲の拡大は、事前の承認という遮断を外す変更であり、ADR-0038 決定1 の「遮断の解除」に当たる。**統制の弱化として扱う**
- したがって、緩める向きの手続(5.5.7)は2つの記名を要する。**委任するという決定**は席の責任者(5.5.7 の現行どおり)。**規則そのものの変更の承認**は AI維持管理者(第3章 3.11.2 の指示資産・強制層の承認権限)。経路は既存の `state:needs-platform`(第5章フェーズ5 ラベル運用 4.3)。新しいラベル・ゲートは足さない
- 検知した者(出荷判定者、AI の担い手を含む)は、差分が変更の主張と一致するかの確認までに留め、許容可否を判断しない(ADR-0038 決定2)
- 1〜2名体制で席の責任者と AI維持管理者が同一人物でも、引き渡しと、どの席で判断したかを記録する(ADR-0038 決定5)
- 範囲の縮小と規則の削除は弱化に当たらない(厳しくする向き。即時)
- 採らなかった案: 委任の決定を AI維持管理者だけに寄せる(席の結果責任を負う者が決めない形になる)/事業決裁者の決裁を常に要する(ADR-0038 が退けた「判断の要らない事項まで決裁へ集まる」形)

反映先: F1 = 5.5.7 の表と ADR-0054(引き上げの決定の節とステータス欄の関係に ADR-0038 を足す)。F2 = 附属書H の H.9(「誰が統制を緩められるか」の問いがあればその回答)。F3 = `/process-change` で規則の追加・拡大を受けたときの残作業に「AI維持管理者の承認(`state:needs-platform`)」を出し、`changeLog` に規則の承認者を記録する欄を持つ(名簿と照合)。
