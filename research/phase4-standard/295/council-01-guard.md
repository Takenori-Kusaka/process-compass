- 提出日: 2026-10-11
- 読んだもの: council-00-brief、inventory-01-summary、research-01-external、`gate-criteria.md` 「タスクの分割基準」全節、ADR-0047、`phase6-operation/metrics.md`「実績を基準へ機械的に変換しない」、council2-03-defender、`check-pr.mjs:515-545`、`config.mjs:1105-1120`、`tailoring-guide.md:322-335`。council2-01/02、`generate-profile.mjs` の該当行、`tmp/audit295-template/` の実走結果は未読(inventory の記述を信頼した)
- 根拠水準の凡例は ADR-0026 に従う。外部の【二次】【未確認】は事実として扱わない

## 1. 立場の宣言

守ろうとする失敗は1つ。**AI が生成した巨大な変更が、誰にも確認されないまま本番へ届くこと**。規制業では「上限を外した結果、確認されない変更が出た」ことが組織の責任問題になる。

同時に、次の事実を認める。

- 固定の遮断が全案件の合否を 100% 落とすなら、それは統制ではなく**回避の動機の製造機**である。利用者は分割偽装(1 PR を 7 PR に: research-01 の eBay 指摘【二次】)か、承認の形骸化へ逃げる。Goodhart の帰結であり、遮断を守る側の失敗でもある
- 400 行の出自は SmartBear/Cisco(2006)の1回のレビューセッションの目安であり、PR の合否閾値ではない【確認】。「400 だから正しい」とは主張しない

したがって主張は「遮断を維持せよ」ではない。**「数値を外すなら、確認されないまま届かないことを別の機械的な仕掛けで保証せよ。その仕掛けを示せない案は採らない」**である。私の案は、遮断をやめず、**解除の費用を下げ、解除の証跡を較正の母集団にする**ものである。

要点: 問題は「遮断である」ことではなく、(a) 算定が過大、(b) 解除経路が使えない、(c) L1/L2 を宣言できない、の3点。遮断の有無と、この3点は別の問題である。

## 2. 論点ごとの具体案

### 論点1 PR サイズ上限の既定の扱い

**案: 「遮断の既定は維持し、解除を同一 PR 内の1承認に縮める(解除ゲート)。L1/L2 は宣言経路を新設する」。**

| 状態 | 超過時の扱い |
| --- | --- |
| L0(既定・宣言なし) | 超過は `gate-g5` を保留(失敗でなく `pending`)にする。解除は下記の「超過説明」と作成者以外1名の承認 |
| L1 宣言あり | 緩和後の上限(自組織の実測で定めた値)を適用。超えたら L0 と同じ解除ゲート |
| L2 宣言あり | 行数・ファイル数は警告のみ。審査深度は R(リスク区分)で決める。ただし下記の R 軸の例外を除く |

- 「観測のみ(上限なし)」は採らない。ADR-0047 が却下済み(「上限が無い状態は、AI が生成する巨大な変更をそのまま通す経路になる」)で、前提の変化の根拠(新しい観測・出典)が本調査に無い。「サイズ上限を合否にして欠陥が減った査読付き実証は未確認」は、**合否をやめて減る実証が無い**ことと対称であり、遮断をやめる根拠にならない
- 超過説明(同一 PR の本文に置く、様式は4行): ①分割できない理由 ②確認を担保する手段(テスト・影響範囲の提示・機械的変換の決定論性。標準の「緩和できる手段」の表のうち認められたものに限る) ③人が読むべき重点箇所 ④算定から除外できない大物(生成物・fixture)の内訳。AI が書いてよいが、**承認者(人)が署名する**
- 既定値(400/15)は動かさない。動かすなら較正手続による(論点5)。ただし**L0 の既定値の「定数」としての説明は書き換える**: 「合否ではなく、解除ゲートを起動する値」と明記する(標準の文言も `:940` の「遮断として運用してはならない」と実装の整合を取る必要がある。下記の矛盾の扱いを参照)

**標準との矛盾の扱い**: 標準の「遮断として運用してはならない」(ADR-0047)の趣旨は、**遮断により較正の母集団が打ち切られること**への対処であり、「マージを止めてはならない」ではない。母集団が打ち切られない(超過を解除ゲートで通し、判定完了時間と規模が記録される)ならば、保留は ADR-0047 の趣旨と両立する。ただし文言の読み違いを残さないよう、**新 ADR で「遮断」の定義(母集団から外す差し戻しを遮断と呼び、記録つきの解除経路を持つ保留は遮断としない)を明文化する**。これは却下された「目安のみ化」の蒸し返しではない。

**規制業・CL2 以上とそれ以外で分けるか**: **CL では分けない。変更ごとの R で分ける**(ADR-0039: 「案件の CL からリスク区分依存の条項の適用外を導かない」)。

- **R1(安全関連部を含む)・R2 の変更、および確約範囲・コア指定パスに触れる変更**は、L2 を名乗っていても行数上限を警告に落とさない。L2 は「取消可能性の担保」と「リスク採点の稼働」を要し、リスク採点の外れ値がそのまま本番へ出ることが一次事例の限界として標準自身が書いている(`gate-criteria.md:889`)。R1・R2 でその外れ値の責任を取れるのは、行数でなく人の判定である
- R3(委任の対象になりうる低リスク)の変更だけ、L2 で警告のみとできる
- CL は、L1/L2 の宣言の**証拠水準**(記録の保存期間、独立した確認の周期)の強度に使うかを問う。ただし ADR-0039 との整合は未確認であり、会議体で突合してほしい。CL を使うなら「適用外の導出」にしない形に限る
- 分け方の根拠水準: E0(規制業の実務慣行は私の知る範囲の推論であり、一次資料を読んでいない)

### 論点2 算定方式

**案: 算定を3つ直す。いずれも「何を数えるか」であり、上限値は動かさない。**

1. **追加+削除の合算をやめ、「変更行(unified diff の変更ブロック内で置換は max(追加, 削除) として数える)」へ改める**。書き換えが2倍になる偏りは、レビューの負荷(新しい内容を読む)と合わない。ただし**純粋な削除は数える**(削除は消えるものの確認が要る)。根拠水準: E0。レビュー負荷を測った一次資料は無い。判断は「過大算定は偽の不合格を作る」という推論に拠る
2. **テスト・fixture・snapshot は「算入するが重みを下げる」でなく「別枠で数える」**。実装・テストで別々の上限を持つ。固定の重み係数(例: 0.5)は根拠が無く採らない。別枠の上限は初期値を置かず、**初期は実装枠の合計に対する比で警告**し、較正の母集団に入れる(E0)
   - ただし snapshot・fixture の**自動更新**は、更新前後の差分を人が読めないため、除外ではなく「生成物の印」要件(下記)を満たしたものだけ除外する。**印の無い生成物を機械で識別して除外しない**(IMPL-0049 の既存方針を維持)
3. **生成物の印を基底へ先に入れる要件は維持する**。除外を作成者の自己申告にすると、大物を「生成物」と称して通せる。印が基底ブランチに先にあることが、作成者が同一 PR で除外を作れない統制である。**この要件を外す案は採らない**。ただし、初回(基底に印を作れない)の経路は、論点3の「初回足場の扱い」で別に解く

### 論点3 例外の経路

**案: 現行の「PR 2本・承認 2回」を日常の経路として残さない。ただし廃止でなく、2つの経路に分ける。**

| 経路 | 用途 | 経路の中身 |
| --- | --- | --- |
| 解除ゲート(日常) | 規模超過の通常の解除 | 同一 PR 内、超過説明+作成者以外1名の承認。台帳の行は**マージ後に自動で追記**(PR 番号は作成後にしか決まらない問題を解消) |
| 例外承認(第7章 7.3) | 解除ゲートで足りないもの(R1・R2、確約範囲・コアに触れる、記録を残せない事情) | 現行どおり。台帳へ先に入れる |

- 同一 PR で足した台帳の行を数えない原則(作成者が自分の例外を作る穴を塞ぐ)は、**解除ゲートでは「承認者が作成者と別の人であること」と「承認がコミット後のレビュー承認であること」に置き換える**。作成者=承認者を禁じる不変条件(P4)は維持する
- **1名体制**: 解除ゲートの承認者を確保できない。選択肢を3つ検討して1つを推す。
  - (a) 1名体制では解除ゲートを使えないので、L0 のまま超過は不可(現状。使えない)。**採らない**
  - (b) 作成者自身が承認する(自己承認)。ADR(suite の fixture 記録: 3名の同一人物の承認は記録つきで受け付けた、ただし拒否は採らず層1の錠で塞いだ)と整合させる形にはできるが、**統制としては無い**。規制業では監査で指摘される
  - (c) **AI は承認者になれない(T-31 AI 名義の拒否)ので、1名体制では「時間を空けた自己承認+事後の第三者サンプリング」を条件とする**。具体的には、作成から承認まで最低 24 時間(暫定 E0)の冷却、承認の記録に「第三者(外部監査・別組織・後日の自分以外)への事後開示の予定」を要する。これは**統制の水準が下がることを承認の記録に明記する**形であり、無いことを隠さない
  - 推奨: **(c)**。1名体制ではそもそも独立レビューが成立しない(S-15 の独立レビュー2名)ことを標準が既に認めているはずで、規模の例外だけを2名要求にする整合性が無い。ただし CL2 以上の案件で1名体制が現れうるかは未確認であり、**CL2 以上かつ1名体制の組み合わせでは (c) を許さず、規模超過を解除不可とする**ことを提案する(その組み合わせで巨大な変更を通す必要がある案件は、体制を変えるべき)。この線の置き方は E0 であり、会議体で潰してほしい
- **初回足場の扱い**: process-init 直後の製品の足場(950 行)が通らない問題は、「基底ブランチが空」であることが原因である。**基底に1つも製品コードが無い間(初回の足場)は、規模判定を保留とし、同一 PR 内で「足場であること」を宣言して承認する**。初回のみ・基底に製品コードが無いことで機械判定できる。巨大変更の抜け道にならない(基底が空なので、既存の動作を壊す変更が存在しない)。E0

### 論点4 能力依存の値の失効(P3)

**案: 「モデル世代交代」を再評価の**契機**にするが、値の自動変更・失効にはしない。**

- 契機を、暦(見直し期限)に**足して**置く。契機は観測できるものに限る: 自組織が採用するモデルの識別子の変更、または AI 生成 PR の規模の分布(p75)が、前四半期から一定以上動いたとき(閾値は置かない。E0)
- 契機が起きたときの**義務**: ①較正の手続を前倒しして実施する ②上限の見直しの要否を判定記録に残す(見直さないという判断も記録する)。**値を自動的に失効させない**。失効すると上限が空白になり、「何も確認されない」期間が生じる(対して S-10 の失効の仕組みは失効後の扱いが明確か要確認。S-10 は良い先例とされているが、本調査では未読)
- 「足場は撤去でなく移動する」の一次資料の扱い: **この資料は私の立場の強い根拠である**。能力が上がると「小さく保つ価値」が消えるのでなく、守り方が移る(Anthropic Engineering 2026-03-24【確認】)。研究側の整理(CMU/Stanford 等【二次】)も「守るのが難しくなった」と読める。ゆえに、再評価の結果は「撤去」「維持」「移す(例: 行数→リスク採点)」の3値で記録させ、**撤去は他の担保(L1/L2 の手段)が記録で示された場合に限る**
- 緩める向きの再較正を自動化しない。metrics.md の歯止め(更新は人の判断・引き上げには実績以外の根拠・更新周期は観測周期より長く・措置と更新を同じ場で決めない)を、モデル世代交代による前倒しにも適用する。**契機が起きたことが、自動で上限を上げる根拠になってはならない**(実績以外の根拠=手段の変化の記録が要る)
- 根拠水準: E1(契機の設計は標準の既存の較正の枠組みの延長。ratchet の先例【確認】は Notion のみ)

### 論点5 ほかの能力依存の定数

方針は「維持する/直す/観測へ移す」の3分類を、**実害の向き**で決める。

| 項目 | 扱い | 理由 |
| --- | --- | --- |
| 全体カバレッジ 80%(T-07) | **観測へ移す(合否にしない)**。ただし**変更されたコードのカバレッジ**(差分のカバレッジ)は合否に残す | 全体の数値は新規コードの未検証を平均で隠す。差分基準は AI の巨大変更に直接効く。値(80)は E0 でマークを付ける |
| 自己修復の反復 3回(T-08) | **維持**。ただし「3回で止まったら人へ」の**停止という構造**を維持の本体とし、回数は設定値にして較正対象とする | 無限ループの歯止め(コスト・破壊的な修正の連鎖)。回数だけを能力で動かす |
| 全 PR・全 push の承認失効(T-09) | **直す**。承認後の変更が**差分の実質に触れたとき**に失効(コメント・文言のみは失効させない)。機械判定できない場合は失効側に倒す | 毎 push で失効するなら承認が儀式化する。実質変更の判定ができない間は失効側。**承認後の変更を黙って通さない**ことが不変条件 |
| 「30 分・100 行」の AI への指示(T-22) | **指示から外し、規範(レビュー可能性)で書く**。数値は目安として別行に残す | AI への数値指示は分割偽装を誘発する。規範を伝える方が頑健(E0。推論) |
| 委任の規模条件(T-10・S-20) | **L0 の既定値に固定したまま維持**。委任は解除ゲートの対象外とする(解除できない) | 委任は事後確認の経路であり、規模を緩めると確認のない巨大変更の経路になる。tailoring-guide:329 の「切替は上限の緩和を伴わない」は維持。**ここは緩めない** |
| S-04(レビュー30分)・S-05(見積8時間)・S-07(帯域3〜4件/日)のマーク無し | **維持するが、根拠水準のマークを付ける**(ADR-0026)。値は暫定とし、見直し期限を置く | 実証が無いなら無いと書く。「マーク無し」は是正対象。撤去するかは較正の実測後 |
| SLA の目安(T-21・S-08) | 組織が自分で決める値へ移す(既に較正対象) | |
| T-18・T-19・T-24 の不整合 | 不整合の修理。判断を要しない(T-24 は標準が充足率へ改訂済みなので追随) | 検査が無いための乖離 |

- 観測へ移す項目には、**移した先で観測が実際に取れていること**を条件にする(取れていない観測へ移すのは撤去と同じ)。較正の母集団を保存・集計するコードが無いこと(inventory)は、本件の前提条件である。**母集団の保存・集計が先、定数の緩和が後**の順序にする

### 論点6 維持するもの(P4)

**案: 「能力と切り離して固定する不変条項」の一覧を、標準の1箇所へ置く。**

1. 独立性: 作成者=承認者の禁止(解除ゲート・例外承認とも)。AI 名義の承認の拒否
2. 追跡性: 変更と判定記録の対応。解除の記録は必ず残る(マージ後の自動追記も含む)
3. 閾値・除外設定と製品コードの同時変更の禁止(T-14)
4. 記録の存在: 超過の判定完了時間と規模の記録(較正の母集団)
5. 取消可能性: L2 の要件、委任の事後監査
6. 停止の申し立て(T-15)

これらは能力と無関係。**モデルが賢くなっても「同じ人が自分の変更を承認してよい」とはならない**。同時に「維持するもの」を決めた理由(守っている失敗)を一覧の各行へ書く(「書かれていない」と「課さないと決めた」を区別するため)。

## 3. 他の立場への反論

### (A)「リスク・結果指標へ移す先進現場」への反論

主張の予想: Meta の Diff Risk Score、DORA の変更失敗率、Google の「ハードなルールはない」を根拠に、行数上限を廃止し、結果指標で管理せよ。

- **結果指標は遅れて出る。** 変更失敗率は、確認されない巨大変更が**本番へ出てから**わかる。規制業では「一度出たらよい」ではない。結果指標は較正の入力であり、事前の歯止めではない
- **Meta は「人のレビューを別の保証へ置き換えた」のであって、数値を捨てたのではない。** 標準自身が書くとおり、対象はリスクの最も低い上位 5% かつ確信度が高いものに限られ、自動テスト・段階的ロールアウト・本番監視を置く(`gate-criteria.md:886`)。この前提を持たない組織が水準だけ模倣すると、外れ値がそのまま本番へ出る。**宣言(L2)の条件を満たす記録を示してから外す**のが、私の案と先進現場の案の差のなさである
- Google の「ハードなルールはない」は、**レビュアーが最終判断をする体制**(OWNERS・readability・経験者のレビュアー)の中の記述である。体制が無い組織へ移植できない。さらに、リポジトリは 2025-11-21 にアーカイブされている【確認】
- **DORA は「小さなバッチ」をむしろ重視**(AI 時代に重要)し、時間基準を推す。DORA が支持するのは行数の廃止でなく、**測り方を結果(時間)へ寄せること**であり、私の案(較正を充足率で行う)と矛盾しない。ここは譲れる点: 行数を「規範」に置かず代理指標として扱うこと(標準が既にそうしている)
- ただし譲る点も明記する: **解除ゲートの発火率が高すぎる(下記の失敗条件)なら、先進現場の主張が正しい**。観測で決める

### (B)「較正・失効の標準運営」への反論

主張の予想: 暦とモデル世代で値を自動的に失効させ、較正を仕組みで回せ。

- **自動失効は、失効後の空白に統制が無い。** 失効の瞬間に何も確認されない期間を作る。先例(Notion の ratchet)も、緩める方向を人の承認に限っている【確認】。「自動再較正を禁じる明示の一次資料」は未確認であり、先例の沈黙を根拠にしない一方、緩める自動化に先例が無い点は事実
- 較正の自動化は、標準自身が禁じている(`gate-criteria.md:977`、metrics.md の歯止め1)。モデル世代交代を契機にしても、**契機は前倒しの義務を生むだけで、値を決めるのは人**
- ただし同意する点: 母集団を保存・集計するコードの不在は致命的で、**較正が回る前提がまだ無い**。私の案も、較正の前提(母集団の保存)を先にする(論点5末尾)

### (C)「全案を落とす懐疑役」への反論

主張の予想: 解除ゲート・L1/L2 宣言・R 軸・冷却時間など、全て E0 の装置を増やすだけで、ADR-0046 が戒めた「装置を増やすほど回避と未記録の確率が上がる」に当たる。実証無しに何も足すな。

- 半分は正しい。**私の案の中で実証があるものは無い**(下記の根拠水準)。ゆえに、**装置を足す案ではなく、既存の装置(例外承認)を軽くする案**として示した。足すのは「解除ゲート」の1つで、例外承認の2本・2承認を1本・1承認へ縮めるだけである。新しい記録は、同一 PR の4行のみ(既存の記録の置き場所の変更)
- 「何もしない」は選択肢ではない。**実走で指摘は事実と確認されている**(inventory)。何もしなければ、利用者は(a)定数を書き換える(T-14 の同時変更禁止に触れる)、(b)分割偽装、(c)採用の放棄、のいずれかになる。(a) は閾値の直接緩和であり、私の守る失敗への最短経路になる
- 「全案を落とす」ことが成果である点には同意する。**採らない案を明記する**(本書では、観測のみ化、重み係数、CL による適用外の導出、1名体制の自己承認の無条件化、モデル世代交代による自動失効を、採らないとした)

## 4. 自案が失敗する条件(自分で落とす)

1. **解除ゲートの承認が形骸化する**。承認者が内容を読まずに承認するなら、遮断を維持しても統制は無い。**解除ゲートの発火が全 PR の相当な割合に達する**(目安: 発火が直近の PR の 2 割を超える。この値は E0 の仮置き)なら、定数が現場に合っておらず、承認が儀式になっている証拠である。その場合は上限の見直し(較正)の義務を発生させるべきで、本案はこれを較正の契機に含める。それでも発火率が下がらないなら、**私の案は失敗しており、先進現場の案(結果指標+リスク採点)へ移るべきである**
2. **承認者が確保できない体制が現場の大半だった場合**。1名体制が多数で、(c) の冷却時間+事後開示が「承認を遅らせるだけ」の儀式になる。CL2 以上かつ1名体制で解除不可とする線が、規制業の実在の案件を止めるなら、その線は誤っている
3. **変更行の算定(置換は max)が、レビュー負荷と相関しない場合**。実測が無い。置換を max にすると、全面書き換えを過小に見積もりうる。実装枠と別枠の上限の比の警告が機能しなければ、算定修正は偽の安心を作る
4. **R 軸が自己申告になる場合**。R の判定が自己申告なら、R1・R2 を避けたい者は R3 と申告できる(ADR-0044 決定4 が書いた機序)。R の判定を変更の触れるパス(確約範囲・コア指定・安全関連)から機械的に導く部分は守れるが、それ以外の R は自己申告に残る
5. **解除の記録が較正の母集団にならない場合**。マージ後の自動追記が保存・集計に届かなければ、ADR-0047 の打ち切りがそのまま残り、収縮が再発する。**母集団の保存・集計の実装が先**であり、これが後回しになるなら、本案は着手しない方がよい
6. **ADR-0047 の読み替え**(保留は遮断としない)が、「採らないと決めたこと」を蒸し返していると判断される場合。私は、母集団の打ち切りを防ぐ趣旨と両立すると考えるが、会議体が「遮断」の定義の変更を新 ADR の必要な変更と判断するなら、新 ADR の起草と、旧 ADR の置き換えの明記を要する

## 5. 根拠水準と、実証が無い部分

## 6. 会議体へ求めること

1. 「遮断」の定義の明文化(新 ADR)を、論点1の前提として決める。却下された目安のみ化と区別がつくか判定してほしい
2. 1名体制の経路を論点3の (c) で採るか。CL2 以上×1名体制を解除不可とする線の可否
3. 較正の母集団の保存・集計の実装を、定数の変更より先にする順序で合意してほしい。順序が守られない案は採らない
