# #295 決定の骨格(主担当が会議体の4意見書を突き合わせて決めた。2026-10-11)

意見書: `council-01-guard.md`(統制を守る側)、`council-02-frontier.md`(AI 先進の現場)、`council-03-steward.md`(標準の運営者)、`council-04-skeptic.md`(懐疑役)。事実関係と棚卸しは `inventory-01-summary.md`、外部調査は `research-01-external.md`。

## 0. 突き合わせの結果

4者が一致した点(採る):
- 規模の超過を、既定では**失敗にしない**。標準自身が「遮断として運用してはならない」(ADR-0047 決定の趣旨)と定めており、実行層がそれに反していた
- 日常の経路として、PR 2 本・承認 2 回の例外承認をやめる。人の確認は**同じ PR の中**で完結させる
- **超過の観測を保存・集計する**ことを、上限を動かす手続より先に実装する。母集団が採れないことが、較正が動かない根本原因(懐疑役は最優先とした)
- 構造の不変条件(独立性、追跡性、閾値と製品コードの同時変更禁止、AI 名義の拒否、人の確定)は固定する
- 能力依存の値は、値を自動で変えない。緩める向きは人の判断に限る(厳しくする向きは即時でよい)
- 算定は追加+削除の合算をやめ、ファイルごとの max(追加, 削除) とし、テスト・fixture・snapshot は別に数える

意見が割れ、決めた点:
- **超過時の既定**: 統制を守る側は「保留+同一 PR の超過説明+作成者以外 1 名の承認」、先進の現場は「合格のまま `size:over` を付け、区分の下限を R2 へ引き上げ。遮断は未保証行が非常に大きい段だけ」、標準の運営者は「記録(`size-attestation`)の欠落だけを遮断」。→ **採る形**: 超過は失敗にしない。PR 本文に「規模の確認」(実施者・読み切れたか・分割しなかった理由・保証の所在)を要し、**この欄が無い、または「読み切れなかった」なら失敗**(差し戻し)。超過した PR は区分の下限を **R2** に引き上げる(既存の `riskFloor` の仕組み)。これにより、独立した人の確認(G-6)と区分の確定者という既存の人の関門が、超過に自動で掛かる。新しい承認の仕組みは足さない。先進の現場の UCL(未保証行)・モジュール数の導出は、機械で検査できる条件が定まっておらず、自己申告・偽装の余地が大きいため、**今回は降ろさない**(採らない。懐疑役の指摘のとおり、L1/L2 の宣言を自己申告のまま降ろすと形骸化する)
- **L1/L2 の宣言**: 懐疑役は「今回降ろさない」。他の3者は降ろす。→ **採る形**: 構成に `task.assurance`(水準 L0/L1/L2、根拠の所在、宣言者、宣言日、見直し日)を足す。宣言は**記録であり、緩和を自動で与えない**。検査するのは根拠の所在の実在だけ(標準の「水準は自己申告でなく条件の充足を記録で示す」に沿う)。水準が L1 以上で根拠が実在するとき、超過した PR の「規模の確認」は、保証の所在の記入だけで足りる(読み切れたかの欄は不要)。L2 でも行数の上限を外す(`null`)ことは、R1・R2 の変更と確約範囲・コア指定のパスに触れる変更を除く。L2 の機械の検証(リスク採点の稼働)はテンプレートに降ろさず、`state=undelivered` で開示する
- **1 名体制**: 作成者が実施者になってよいが、「独立した人の確認が無い」と記録して表示し続ける(既存の G-6 未達の表示)。CL2 以上×1 名体制の解除不可(統制を守る側の案)は、独立した人の確認の欠落が既に出荷の集約で欠落になるため、**重ねて足さない**
- **能力変化の契機(P3)**: 懐疑役は「観測できない契機」として却下、他の3者は採る。→ **採る形(弱い形)**: 契機は「**`/process-change`(種別 performer)の記録にあるモデル・指示資産の版の変更**」と「暦」とする(観測できる記録だけ)。「世界のモデルが賢くなった」を契機にしない。契機で値を自動で変えない。再評価待ちの定数を `/process-change` の出力と `/pit` に**注記**として出し、人が「残す/外す/移す」を記録する。懐疑役が指摘した「世代交代で短くしてよいが導かれる」危険を避けるため、能力が上がったことを理由に**短縮しない**周期・窓(S-14 の観測窓、T-26 の力量確認周期、S-23 の監査周期)は登録簿で「能力に依らない」と明記する
- **例外承認(7.3)**: 規模の超過では日常の経路から外す。R2 以上の規範の逸脱に残す。**ADR-0047 の決定1(超過を通す唯一の経路が例外承認)を部分的に置き換える**(新 ADR-0058)。ADR-0047 が却下した「目安のみ化」とは別である(超過に人の確認・記録・区分の引き上げを課し、観測を保存する)

## 1. 決定

### D1 規模の超過の既定(第4章 G-5・「タスクの分割基準」)
- 規模(算定は D2)が基準値(既定 400 行・15 ファイル。L0 の既定値)を超えた PR は、`pr-rules` で**失敗にしない**。代わりに(a) `size:over` を結果に出し、(b) 区分の下限を R2 へ引き上げ(`riskFloor` と同じ経路。R1 のまま上げない)、(c) PR 本文の「規模の確認」の欄を要する
- 「規模の確認」の欄: 実施者(確認した人の氏名)/ 読み切れたか(はい・いいえ)/ 分割しなかった理由 / 保証の所在(テスト・契約・型など、確認の範囲を限定したもの)。**欄が無い、実施者が AI の名義、「読み切れたか」が「いいえ」のいずれかなら失敗**(差し戻し。実装計画へ戻す)
- ファイル数は**観測のみ**(通知)。合否にしない(標準自身が「数値自体の実証が無い」と書く)
- 実施者は作成を指示した者でもよい(1 名体制)。その場合は「独立した人の確認が無い」を記録に出す(新しい検査は足さない)
- 基準値は構成 `task.maxChangedLines`・`maxChangedFiles` のまま(意味は「超過で規模の確認を要する基準」)。**値の域に `null`(基準なし)を足す**。`null` は L2 の宣言と根拠が実在する場合だけ受け付け、R1・R2・確約範囲・コア指定のパスに触れる変更には掛けない
- 標準側: gate-criteria.md「タスクの分割基準」と ADR で、「超過は差し戻しが既定」を「超過は規模の確認を要し、人の確認(G-6)が R2 として掛かる。確認が取れない超過だけを差し戻す」へ改める

### D2 算定(check-pr.mjs)
- 製品コードのファイルごとに max(追加, 削除) を足す(置換を 2 倍に数えない。純削除は削除行数)
- テスト・fixture・snapshot は別に数え(通知に出す)、基準値の判定には入れない。ただし、既存テストの削除・書き換えの一覧(T-17)は現状のまま。テストの置き場の判定は、慣習的なパターン(`test/**`、`tests/**`、`__tests__/**`、`*.test.*`、`*.spec.*`、`fixtures/**`、`__snapshots__/**`)を既定とし、構成 `task.nonProductPaths` で足せる(閾値と製品コードの同時変更の禁止の対象に加える)
- ロックファイル・印のある生成物・空白だけの変更・内容の変わらない名前の変更・文書・記録・強制層・構成は従来どおり除く。生成物の印を基底に先に入れる要件は維持
- 初回の `chore/process-init` は、製品コードが無い間は規模の判定を行わない(`Spec: setup` の扱いは従来どおり)

### D3 例外の経路
- 規模の超過に 7.3 の例外承認は不要。`exceptionFor`(台帳の行を要する経路)は、規範の逸脱(R2 以上)に残し、規模の経路から外す。既存の台帳の行は有効のまま(過去の記録を壊さない)

### D4 観測の保存と較正
- **出荷の集約**(`aggregate-evidence.mjs`)が、出荷範囲の PR について、規模の分布(行数・ファイル数の区間ごとの件数)、`size:over` の件数、規模の確認の「読み切れたか」の内訳、超過 PR の判定完了時間(取れるとき)、差し戻された PR(記録のあるもの)を、保証の開示の観測として出す。値は自動で上限へ反映しない
- 標準側: 較正の手続(充足率 8 割)は人の判断のまま。母集団の入力に、集約の規模の分布を使えることを書く。較正の周期の歯止め(metrics.md の規定 3: 更新の周期は観測の周期より長く)に、「四半期で観測し、更新は半期以上」を明記する(標準の運営者の指摘。現行の文言が四半期ごとの更新と読める点を直す)

### D5 L1/L2 の宣言(構成 `task.assurance`)
- `{ level: 'L0'|'L1'|'L2', basis: <リポジトリ内のパス、無ければ空>, declaredBy, declaredAt, reviewAt }`。未宣言は L0。`/process-change` の種別 `settings` で変える。L0 から L1/L2 へは「緩める向き」(記名と理由を要する)
- 検査: `basis` が実在すること、`reviewAt` を過ぎていないこと。過ぎていれば L0 として扱い、通知する
- L1 以上で根拠が実在する場合、規模の確認は「保証の所在」の記入だけでよい

### D6 能力依存の値の再評価(P3。標準の登録簿と `/process-change` の注記)
- 標準(第6章 metrics または gate-criteria の較正の節の近く)に**能力依存の定数の登録簿**を置く。各行: 値、依拠する前提、担っている保証と、移った先、再評価の契機、能力に依るか(依らない周期・窓はそう明記)。最初の登録: 規模の基準値(400 行・15 ファイル)、レビューの所要 30 分、見積 8 時間、レビュア帯域 3〜4 件/日、自己修復 3 回、カバレッジの下限、コンテキストの目安(CLAUDE.md 200 行・6,000 トークン)、自律度の引き上げの 3 か月、層数 3
- 契機: (1) `/process-change`(種別 performer)でモデル・指示資産の版が変わったとき、(2) 暦(見直し日。EV の見直し日と同じ)。契機で**値を自動で変えない**。`/process-change` の出力と `/pit` が「再評価待ちの定数 N 件」を注記し、人が「残す/外す/移す」と、移す場合は移した先の保証を記録する(記録の置き場は `docs/` 配下の記録の置き場)
- 根拠水準マークの無い値(S-04 30 分、S-05 8 時間、S-07 3〜4 件/日、S-18 の 200 行)に、暫定のマーク(EV-NNNN、E0。差し替え条件に観測量と判定の向き)を付ける。S-05「見積 8 時間超は分割必須」は「目安。超えたら理由を記録する」に改める(要求に見える文言を外す)

### D7 AI への指示の更新(T-22・S-06)
- テンプレートの `CLAUDE.md`、`07-implementation-plan.md`、`task-breakdown/SKILL.md`、`implement/reference/task-size.md` から、「30 分で読み切れる」「目安 100 行超は人へ確認」という数値の指示を外し、「関心事が 1 つで、受入基準の束につき 1 Task。確認が要る大きさ・範囲なら『規模の確認』の欄に書く」へ改める。AI が自主的に細切れにして「分割しすぎない」(標準)と衝突する問題を避ける

### D9 今回は直さず、後継 Issue に引き継ぐもの(採らないと決めたものではない)

## 2. 採らないと決めたこと(「書かれていない」と区別するため、ADR に明記)

- 規模の基準値を引き上げるだけの案(能力が上がるたびに上げ続ける定数のままで、構造が変わらない。懐疑役)
- 上限を廃止する・観測のみを既定にする案(超過に人の確認も記録も課さなくなる。ADR-0047 が却下した目安のみ化と同じ。EV-0033 の再開条件は別)
- 超過を無記録で通す案
- 能力の世代交代を契機に値を**自動で**変える案、モデル名と定数の対応表を標準に置く案(足場は消えず移動する。一次資料)
- 未保証行(UCL)・モジュール数の導出を既定にする案(今回)。機械で検査できる条件が定まらず自己申告になる
- 日常の経路に例外承認(PR 2 本・承認 2 回)を残す案
- 外部ベンチマークの値を既定にする案
- 「人の帯域は AI の進化に比例して増える」という前提(懐疑役の指摘: 人の帯域は固定で、機械生成コードの認知負荷は人手より高い可能性。レビュー側の定数は能力と無関係に維持される場合がある。したがって規模の基準値は**廃止でなく、超過時の扱いを「遮断」から「人の確認と記録」へ移す**)

## 3. 根拠水準と開示

- 指摘の事実関係(実走で再現。400 行超が全滅、算定が実装の約 2 倍、1 名体制の例外経路)は E1(実走)
- 超過時の扱いの変更、`size-attestation`、R2 への引き上げ、`task.assurance`、再評価の登録簿は実証が無く E0。差し替え条件: 利用者の PR 分布の実測、超過 PR の「読み切れなかった」比率、超過 PR の手戻り・取り消しの観測(集約が出す)
- 懐疑役の疑問(利用者の「100% 落ちる」の原因が能力の向上かは証拠が無い)は残る。本件の根拠は「標準の規範(レビュー可能性)と実装(固定定数)の食い違い」と「実走」であり、能力の向上を理由にしない
- 機械は 2026-10-02(#286)に初めて規模を検査し始めた(懐疑役が `git log -S` で確認)。利用者の版は未確認
