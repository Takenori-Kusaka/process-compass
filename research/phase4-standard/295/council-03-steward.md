## 1. 立場と、守ろうとする失敗

守る失敗は3つ。**「固定しない」と「自動で動かす」の両方に危険がある**と考える。

| # | 失敗 | 出所 | 今回の論点との関係 |
| --- | --- | --- | --- |
| F1 | 較正の母集団が上限で打ち切られ、毎期収縮する | ADR-0047 | 現行テンプレートは 400 行超を 100% 遮断しており、F1 を再現している。母集団の保存コードも無い |
| F2 | 実績から基準が自動で決まると知られ、実績を出し切らなくなる | `metrics.md:87-100` | 「AI が賢くなったら上限を自動で上げる」案は F2 をそのまま招く |
| F3 | 能力が変わっても古い定数が残り続ける | 今回の指摘 | 暦だけの見直し(EV-0005 は 2027-08)では、2026-03 から 08 の変化の速さに追随できない |

したがって設計するのは、値でも自動調整でもなく、**人の判断を経る再評価の仕組み(契機・記録・失効時の表示)**である。

## 2. EV-0033 の失効条件の評価(先に結論)

EV-0033 の差し替え条件は「(a) 差し戻し件数 > 0 かつ (b) 例外承認経由の超過レビュー件数 = 0 が 2 四半期続けば、経路が回避されているとして、上限を合否から外し目安のみとする」である。

**形式上は未達。実質上は、条件が想定した事態が、条件の前提を壊す形で観測された。**

- 形式: 数えるコードが無く、件数は誰も持っていない(inventory:15)。ADR の採用は 2026-08-14 で、2 四半期連続は早くても 2027-Q1 以降。形式の充足を主張できない
- 実質: 実走で 401 行以上は常に失敗し、例外経路は PR 2 本・承認 2 回を要し、1 名体制では経路自体が不成立(inventory:13)。(b)=0 は構造的に確定している。これは「利用者が経路を使わなかった」ではなく「使えなかった」である
- 帰結: EV-0033 の主張は「経路を置けば、較正データが供給される」だった。**経路が使えない状態の (b)=0 は、この主張の反証ではなく、検定の不成立**である。したがって、再開条件が予約した「目安のみ」へ直行すると、主張を一度も検証せずに捨てることになる

**提案**: 「目安のみ」へは行かない。経路を「使える形」へ置換し(論点 1・3)、**計数の開始日を明記して条件を再設定する**(次節)。再設定した条件で (a)>0 かつ (b)=0 が 2 四半期続いたら、標準が予約したとおり目安のみへ移る。これは ADR-0047 §1 の部分置換であり、新 ADR で行う(本文書き換え禁止)。

ADR-0047 の却下案(目安のみ)を蒸し返してはいない。新しい観測は「例外経路が 1 名体制で成立しない」という実走結果で、ADR 採用時には未観測だった。ただしこれは当方の監査の実走 1 件と利用者 1 名の報告であり、根拠水準は E1(間接)に留まる。

## 3. 論点ごとの具体案

### 論点 1: 既定の扱い(遮断のまま / 警告+深度 / 観測のみ / 担保水準)

**案: 規模ではなく「記録の欠落」を遮断する。**

- 超過(400 行・15 ファイルまたは宣言値)そのものは **CI を失敗にしない**。状態は「要判断(neutral 相当)」とし、PR に次の `size-attestation` ブロックを要求する
  - 実施者(人名。AI 名義は T-31 の拒否を維持)、読み切れたか(はい/いいえ)、所要時間(機械取得できなければ自己申告で、その旨のフラグ)、分割しなかった理由(1 行)
- **ブロックが無い超過 PR は失敗**(遮断するのは記録の欠落)。ブロックがある超過 PR は通る
- 通った超過 PR には**審査深度の引き上げ**を課す: (i) 人間のレビュー判定が必須(AI レビュー単独は不可。T-29 を維持)、(ii) 判定完了時間の SLA を通常どおり適用、(iii) 「読み切れなかった」と答えた PR は差し戻す(ここが標準の「差し戻しの既定」の実装)
- 担保水準 L1/L2 は、宣言欄で上限の値と遮断の有無を変える(論点 3 の(c))

**ADR-0047 §1 との関係**: 標準は「例外承認を経た場合に限り超過のままレビューを実施してよい」と書く。本案は、サイズ超過の通過経路を第 7 章 7.3(規範からの逸脱の承認)から**同一 PR 内の記録**へ移す。7.3 は R2 以上の規範逸脱に残す。サイズ超過は規範逸脱ではなく、較正の観測対象として扱う。この線引きが妥当かは会議体で争点にしてよい。

**採らないと決めること**: (1) 超過を無記録で通す(母集団が打ち切られる)、(2) 「観測のみ(上限なし)」を既定にする(ADR-0047 が却下。AI 生成の巨大変更の通路になる。E0 だが、通路が開くことへの懸念を解消する実証も無い)、(3) 規模そのものの遮断を既定に戻す(F1 の再現)。

### 論点 2: 算定方式

運営者の観点は「何を数えるか」より**測定単位の連続性**である。算定を変えると過去の分布と比べられなくなり、較正が壊れる。

- 記録には**生値を分けて保存**する: 追加行、削除行、ファイル数、テスト・fixture・snapshot の行、生成物(印のあるもの)の行、散文の成果物の行
- 判定に使う量は「レビュー対象行」と名付け、**算定版(`measure_version`)を記録に必ず付ける**。版を変えたときは新旧の母集団を混ぜず、版ごとに充足率を出す
- 具体的な定義(追加+削除の合算をやめるか、テストを除くか)は他の担当に委ねる。当方が求めるのは「どの定義でも、生値から再計算できること」と「版の変更が人の判断と記録を経ること」だけ

### 論点 3: 例外の経路と 1 名体制

- 日常の超過経路から「PR 2 本・承認 2 回」を外す(論点 1)。7.3 の方式は規範逸脱用に温存する
- **1 名体制**: 作成者=実施者を許す。ただし記録に `independence: none` を付け、**母集団には入れるが層別して集計**する。理由: 除外すれば 1 名体制の観測が永久に採れず(F1 の変種)、混ぜれば SLA の意味(待ち時間)が違う分布が混ざる。較正に使うかは人が決める
- 「1 名で通したこと自体」は T-16(承認者数の警告)の手本どおり、合否にせず警告として表示し続ける

### 論点 4: 能力の変化を契機とする再評価(P3)

**既存の変化点に結ぶ**: テンプレートの `/process-change` には `performer` 種別(モデルの版・指示資産・権限・実行基盤の変更。標準 3.12.3 の回帰評価と接続)が既にある。新しい仕組みを足さず、この種別に再評価の義務を付ける。

1. **登録簿**: 標準側に `src/data/capability-constants.yaml`(仮称)を置く。各項目は `id`、`値`、`依拠する前提`(例: 「レビュアーが差分を逐行で読む」)、`担っている保証`、`失効契機`、`根拠水準(EV)` を持つ。既存の `template:kb` の複製経路でテンプレートへ配る(正本は標準側)
2. **契機**: (a) `performer` の変更のうち、人が `generationChange: true` と宣言したもの(提供者が世代として公表したモデルの更新)、(b) 退出の予行(3.12.3)で回帰評価の差分が出たとき、(c) **暦の下限として、四半期ごとに 1 回**(宣言が `false` に倒される回避への備え)
3. **処理**: `/process-change` は値を**自動で変更しない**。登録簿の該当項目すべてについて、台帳 `docs/calibration/reassessments.md`(仮称)へ「再評価待ち」の行を作る。期限は次の較正の会、遅くとも 30 日
4. **記録する項目**(人が埋める): 契機(旧版→新版)/ 対象の定数 / **判断の材料**(その期間の超過件数・SLA 充足率・差し戻し率・リバート率。**材料が空のまま「維持」とは書けない**)/ 判断(維持・変更・観測へ移す)/ **この定数が担っていた保証は、どの機構へ移ったか、移っていないか**(「足場は撤去でなく移動する」への応答。移っていなければ、値を緩める判断はできない)/ 判断者(人名)/ 次の契機
5. **失効時の表示**: 期限を過ぎて未記録の項目は、**値を消さず適用も継続**し、「再評価待ち(期限超過 N 日)」を `/pit` と D-0 に出し続ける(IMPL の `state=undelivered` と同じ扱い。未達のゲートと同じ)。失効で値が消えて「上限なし」になる設計は採らない
6. **非対称**: 厳しくする向き・維持は人が即時に記録できる。**緩める向きは `metrics.md` 規定 2 に従い、「手段の変化」(モデル世代)に加えて、その手段の下での自組織の観測(超過記録・回帰評価の結果)を要する**。世代交代という事実だけでは緩められない。観測が無い(超過ゼロ)組織は、緩める向きの変更ができない。そのかわり、遮断をやめて警告に移すこと(論点 1)は観測を要しない

**採らないと決めること**: (1) モデル名と定数の対応表(「このモデルなら 800 行」)を標準に置く(根拠が無く、陳腐化する)、(2) 世代交代による定数の自動変更、(3) 契機による自動失効で値を無効にする、(4) 外部ベンチマーク(DX の PR 中央値 44→72 行など)を目標値や緩和幅に使う(`gate-criteria.md:981` の既存方針。母集団により結果も割れている)。

### 論点 5: ほかの能力依存の定数

- **新しい分類を持ち込まず、上の登録簿に載せる**。載せる条件は「依拠する前提が人間の速度・能力のとき」(inventory の B)。登録しない定数は、A(構造の不変条件)であることを理由付きで示す
- **S-04(レビュー 30 分)・S-05(見積 8 時間超は分割必須)・S-07(帯域 3〜4 件/日)は根拠水準マークが無い**。ADR-0026 の要求を満たしていない。まずマークを付ける(根拠水準は暫定 E0。出所を示せないなら E0 と書くのが誠実)。`metrics.md` 105 行の適用先表に S-04・S-07 を追加し、較正の対象にする
- **S-05 は「必須」を外す**。「必須」は遮断であり、F1 の構造を持つ。目安+超過の記録へ改める(論点 1 と同形)
- **S-07 は同ページの「1 人あたり 3 件」(`gate-criteria.md:1081`)と値が食い違う**。どちらが誤りかを突合で決める(未読の箇所があるため、断定は避ける)
- **S-14(自律度引き上げに 3 か月)**: 暦の観測期間であり、能力ではなく信頼の蓄積に由来する。**能力の向上を理由に短縮しない**(緩める向きの変更であり、論点 4 の 6 の非対称に従う)
- **S-18(コンテキスト量・context rot)**: 能力依存が最も強い。観測へ移す候補(登録簿の失効契機を最短にする)。**S-09**: 充足率に連動する形のままでよい(測定が前提)
- **観測の周期と更新の周期**: 現行の較正は「四半期ごとに分布を出し、新しい上限とする」と読め、観測の周期と更新の周期が同じに見える。`metrics.md` 規定 3(更新の周期を観測より長く)に反している可能性がある。**四半期で観測し、半期(2 四半期分の窓)で更新する**形へ改めることを提案する(本文の精読による指摘で、実際の運用で乖離が出ているかは未確認)

### 論点 6: 維持するもの

P4 に賛成する。能力と切り離す不変条件は、登録簿の対象外であることを `capability-constants.yaml` の冒頭に明記し、**「能力が上がっても変えない」と書く**(独立性、追跡性、記録の存在、閾値の同時変更禁止、AI 名義の拒否、取消可能性)。読み手が「書かれていない」と「課さないと決めた」を区別できるようにするため(コアポリシー)。

### (b) 較正の母集団: 遮断でなく何を保存するか

遮断をやめるだけでは母集団は採れない。**保存する観測のレコード**を定める。

| 項目 | 内容 |
| --- | --- |
| 識別 | PR 番号、マージ/差し戻しの別、日付 |
| 規模の生値 | 論点 2 の各行数、ファイル数、`measure_version` |
| 経路 | 通常 / 超過記録 / 差し戻し(未レビュー) |
| 時間 | レビュー依頼から判定確定まで(PR のタイムラインから機械取得を優先。取れなければ自己申告フラグ付き) |
| 層別 | リスク区分(R)、`independence`(独立レビューの有無。1 名体制を含む)、実施者種別 |
| 宣言値 | その時点の上限値と `basis.level` |

- **差し戻しの規模も保存するが、充足率の母集団には入れない**。ADR-0047 が却下した「差し戻しを母集団に含める」とは別物で、「打ち切りの大きさ」(右側で何件切れたか)を併記するためだけに使う。これで F1(収縮)が起きていないことを、人が見て検出できる
- **保存先**: 基底ブランチのファイルへ追記すると、PR が要る(2 PR 問題の再発)。マージ後ワークフローが、**保護対象外の専用 ref(`calibration` ブランチ等)へ追記専用で書く**。この記録は観測であり承認ではないため、bot 名義でよい(T-31 は承認の名義を対象とする)。四半期の較正の会で、人が集計を台帳へ 1 PR で取り込む
- **自動集計の結果を上限へ自動反映しない**(`metrics.md` 規定 1)。判断者と記録は人

### (c) 宣言された値の記録と、未宣言のときの既定

- `process.config.json` の PR 上限を、値だけでなく**宣言の組**にする: `limits.pr = { lines, files, basis: { level: L0|L1|L2, evidence: <条件を示す記録へのパス>, declaredBy, declaredAt, reviewAt }, enforce: records }`
- **未宣言の既定 = 標準の L0 既定値(400/15)+「記録の欠落のみ遮断」**。`generate-profile.mjs` が全案件へ同じ遮断を降ろす現状をやめる。既定値は**提案**であり、案件ごとの宣言は生成物へ残す
- L1・L2 は「自己申告ではなく条件の充足を記録で示す」(標準)。検査は ADR-0040 の方式で、**`evidence` 欄の存在と、指すファイルの実在だけ**を確認する(内容の判定はしない)。示せなければ L0 に戻す
- 値の域: 正の整数、または `null`(上限なし)。`null` は L2 かつ `evidence` がある場合に限る
- 委任(R3 の自動マージ)の規模条件は、**宣言値ではなく L0 既定値のまま据え置く**。委任は緩める向きの変更であり、能力が上がっても、上限の宣言を緩めただけで委任の範囲が広がってはならない(標準 `tailoring-guide.md:329-331` の「切替は上限の緩和を伴わない」と同じ趣旨)

## 4. 他の立場の主張と反論

**統制を守る側**(「遮断を外すと AI の巨大 PR が通る」)
- 遮断が守っているのは規模ではなく、実走では**例外経路が使えない状態で 100% 失敗していること**であり、これは統制ではなく回避(PR の分割、`Spec: setup` の濫用)を誘発する。分割は標準が禁じた「レビューを分割して対処する」行為そのもの。ただし「回避が実際に起きたか」の観測は無い(E0)。
- 本案は遮断を捨てず、遮断の対象を記録の欠落へ移し、通過後の審査深度を上げる。人間のレビュー判定の必須化、AI 単独レビューの不可、SLA の適用は維持する。
- 認める点: 「読み切れた」の自己申告は弱い。ここを補うのは、記録の層別と、手戻りとの突き合わせ(下の失敗条件)である。

**AI 先進の現場**(「上限は廃止か観測のみ。モデルが賢くなれば自動で緩めるべき」)
- 自動で緩めることは F2 を招く。基準が実績や能力から自動で決まると知られると、実績の出し方が変わる。
- 世代交代が緩める根拠になる事実を示す一次資料は、本文書では確認できていない。足場は撤去でなく移動するという同じ資料の記述もあり、世代交代だけでは緩める根拠にならない。
- 認める点: 暦だけの見直しは確かに遅い。論点 4 の契機は、その遅れを埋める。観測が出れば、緩める判断は人の判断で可能になる。

**全案を落とす懐疑役**(「記録欄を増やすだけ。自己申告の儀式が増える。台帳が肥大する」)
- 現状(固定の遮断)も全案件に強制される案であり、実証が最も乏しい(E0)。落とすだけでは、その案が既定として残る。
- 認める点: 儀式化の危険は実在する。下の失敗条件で、儀式化を検出する条件を先に書いた。登録簿は、載せる項目を B に限り、肥大を抑える。

## 5. 自案が失敗する条件

1. **`size-attestation` の形骸化**: 超過 PR の 9 割以上が「読み切れた」で、かつ超過 PR のリバート率・差し戻し率が通常 PR より高い。→ 自己申告は信頼できない。深度の引き上げを機械の観測(手戻り)へ寄せる。EV の新規マークの見直しで検出する
2. **事実上の目安のみ化**: 差し戻し(「読み切れなかった」)がほぼゼロで、超過通過が常態になる。→ 結果は EV-0033 の再設定条件と同じ。2 四半期で判定し、予約どおり目安のみへ移る。この移行は失敗ではなく、条件の履行である
3. **母集団が採れない**: 判定完了時間を機械取得できない運用(外部レビュー基盤、1 名体制)で、自己申告の時間が捏造される。→ 層別で除外できるが、1 名体制の較正は永久に弱いまま残る。この弱さは解消できない
4. **再評価の儀式化**: 「材料が空でない維持」が毎回同文で、実際には誰も見ていない。→ 材料欄が前回と同一の記録が 3 回続いたら警告する、などの検出は可能だが、読まれないこと自体は防げない
5. **宣言の回避**: `generationChange: false` を常に宣言する。→ 暦の下限(四半期)が受け止める。ただし暦の下限だけでは、現行の暦の見直しと大差ない
6. **専用 ref の運用負荷**: マージ後の追記ワークフローが保護設定や権限で動かない案件がある。→ 記録が欠ける。欠けたことを検出する試験(テンプレートの `test-*.mjs`)が要る
7. **算定版の乱立**: 版を増やすほど母集団が薄くなる。→ 版の変更は較正の会の議題に限る
8. **登録簿の漏れ**: 能力依存の定数のうち登録されなかったものは、再評価の対象外のまま残る。→ 本案は網羅を主張しない。漏れは、発見のたびに登録簿へ追加する
