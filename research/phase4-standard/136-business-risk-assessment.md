## 2. A. 事業投資の意思決定で何を問うか

### 2.1 ステージゲート法の2層構造(Cooper)

**確認**(二次情報が複数一致。Cooper 本人の解説論文の PDF 本文は抽出不能のため一部は二次)。

- ゲートの判定基準は2種類に分かれる。**must-meet(必達)** はチェックリスト形式の Yes/No 質問であり、不適合案件を早期に落とすためのもの。単一の合意された「No」が Kill を意味する
- **should-meet(評点)** は「単に許容可能な案件」と「優れた案件」を区別するための望ましい特性であり、スコアカード形式で採点して合算する。合格点はフェーズ開始時に決める
- Gate 2 の入力は事業ケース(business case)。Gate 3 は **Gate 2 と同じ must-meet / should-meet の基準集合を、より確度の高いデータでより厳格に再適用する**
- スコアカードの標準6基準は「戦略適合」「製品優位性・競争優位」「市場の魅力度」「技術的実現可能性」「シナジー・中核能力」「財務的報酬とリスク」
- **初期のスクリーニングには財務基準を入れない**。その段階では十分な情報が存在しないため

出典: [Cooper, The Stage-Gate Idea-to-Launch System (Wiley Online Library)](https://onlinelibrary.wiley.com/doi/full/10.1002/9781444316568.wiem05014) / [Cooper & Edgett, Stage-Gate and the Critical Success Factors for NPD (BPTrends, PDF)](https://bptrends.info/wp-content/publicationfiles/07-06-ART-Stage-GateForProductDev-Cooper-Edgett1.pdf) / [Idea-to-Launch (Stage-Gate) Model: An Overview (PDF)](https://media.transformanceadvisors.com/pdfs/Stage-Gate-Model.pdf)

**本標準との同型性**: 7.7.3 の「必達基準は1項目でも不合格なら中止・保留」「評点基準は複数案件の優先順位付けに用い、1項目の低評価では中止としない」は、Cooper の must-meet / should-meet と構造が一致します。7.7.3 は本標準が独自に到達した構造ですが、**外部の先例と同型であることは補強材料になります**。

### 2.2 スコアカード方式の実効性: 財務手法より優れるという実証

**確認**(査読誌の掲載。要旨・二次要約で確認、本文は有償)。

Cooper, Edgett, Kleinschmidt によるポートフォリオ管理の実務調査では、次が報告されています。

- **財務手法は最も多用され最も厳密に見えるが、成果は最も悪い**。低価値の案件が並び、資源に対して案件数が多すぎ、パイプラインが渋滞する
- **戦略的手法とスコアリング手法が最良のポートフォリオを生む**
- 高業績企業は財務的手法への依存を下げ、戦略的手法へ寄せ、かつ複数手法を併用する傾向がある

出典: [Cooper, Edgett & Kleinschmidt (1999) New product portfolio management: practices and performance, JPIM](https://onlinelibrary.wiley.com/doi/10.1111/1540-5885.1640333) / [Cooper et al. (2001) R&D Management](https://onlinelibrary.wiley.com/doi/abs/10.1111/1467-9310.00225) / [Stage-Gate International 解説](https://www.stage-gate.com/blog/portfolio-management-fundamental-for-new-product-success/)

**既知の限界**(二次): スコアカードは基準の重みづけの根拠が弱く、採点者の合議に依存します。今回の調査では、スコアカードの偏りを定量した査読研究には到達できませんでした(**未確認**)。

### 2.3 「なぜ自社がやるのか」を問う枠組み

**二次**。right to win は「競争市場で五分を超える勝率を持てる能力」と定義され、固有の優位性・独自のケイパビリティ・戦略ポジションの組み合わせとして説明されます。Zook と Allen は『Profit from the Core』(2001)で、中核事業を徹底的に活用する企業に right to win が蓄積すると論じています。Strategy&(PwC)は right-to-win exercise を診断手法として公開しています。

出典: [The Right to Win (strategy+business)](https://www.strategy-business.com/article/10407) / [Strategy& right-to-win exercise (PDF)](https://www.strategyand.pwc.com/gx/en/unique-solutions/cds/strategyand-right-to-win-exercise.pdf) / [Profit from the Core (Wikipedia、書誌確認用)](https://en.wikipedia.org/wiki/Profit_from_the_Core)

**様式で問える形になっているか**: 診断手法としては3問形式が流通しています(「勝つ権利があるか=真に不公平な優位を作る資産を持つか」「勝つ意志があるか=全社の成長戦略と整合するか」「勝つ道筋があるか=最終到達点は何か」)。ただしこの3問形式の出典はコンサルティング会社のブログであり、**一次情報としては弱い**(二次)。様式化する場合は、抽象的な問いのままでは記述が形骸化します。後述の 6.4 の理由により、**「自社の何の資産・能力が、他社にはなく、この案件の成否を左右するか」という指示語つきの1問**へ落とすのが現実的です(これは筆者の解釈)。

### 2.4 公的セクターの先例: HM Treasury Green Book / Five Case Model

**二次**(HM Treasury 原本の PDF 本文は抽出不能。NHS 等の公的機関が配布する解説 PDF と複数の解説で一致)。

- 英国政府の事業ケースは5つの case で構成される。**Strategic Case**(変革の説得力ある根拠があるか)、**Economic Case**(最も費用対効果の高い選択肢は何か)、**Commercial Case**(調達・パートナーシップの成立性)、**Financial Case**(支払可能性とキャッシュフロー)、**Management Case**(実行可能性とガバナンス)

出典: [Public Sector Business Cases using the Five Case Model (NHS England 配布 PDF)](https://www.england.nhs.uk/mids-east/wp-content/uploads/sites/7/2014/10/bus-cas-five-cas-mod-guide.pdf) / [The Green Book, Five Case Model (Global Infrastructure Hub)](https://www.gihub.org/resources/publications/the-green-book-five-case-model/) / [APMG International 解説](https://apmg-international.com/article/five-case-model-smarter-public-investment)

**未確認**: uplift の具体的な率(解説記事には「標準的な案件で1〜15%」との記述があるが、HM Treasury 原本で率の表と適用条件を確認できていない)。この数値は本標準では使いません。

**注目点**: Five Case Model は「金額の1点見積り」ではなく、**Strategic Case を独立した case として最初に置く**構成です。財務(Financial Case)は5番目です。2.1 の「初期スクリーニングに財務基準を入れない」および 2.2 の実証結果と方向が一致します。

## 3. B. リスクマネジメントの標準枠組み

### 3.1 ISO 31000:2018

**二次**(ISO の Online Browsing Platform および ISO カタログページは HTTP 403 で取得不能。以下は ISO 公式カタログの書誌情報と複数の解説の一致による)。

- ISO 31000 はリスクマネジメントの**原則・枠組み・プロセス**を提供する。組織の規模・活動・分野を問わず使用できる
- プロセスは連続する段階で構成される。「適用範囲・状況・基準の確定」→「リスク特定」→「リスク分析」→「リスク評価」→「リスク対応」→「モニタリング・レビュー・報告」
- このうち**リスクアセスメントはリスク特定・リスク分析・リスク評価の3つから成る**
- **認証規格ではない**。ガイドライン(guidelines)である

出典: [ISO 31000:2018 Risk management — Guidelines (ISO カタログ)](https://www.iso.org/standard/65694.html) / [ISO 31000:2018 Risk Management Guidelines (PECB ホワイトペーパー)](https://pecb.com/en/whitepaper/iso-310002018-risk-management-guidelines) / [ISO's risk management framework (NC State ERM Initiative)](https://erm.ncsu.edu/resource-center/isos-risk-management-framework)

**未確認**: 条項番号(第4章 原則、第5章 枠組み、第6章 プロセスという構成は解説記事で一致するが、ISO 本文で確認できていない)。**原則の個数についても解説間で表現が揺れる**(「11の原則」と記述する解説がある一方、ISO 31000:2018 が原則を8つに整理したと記述する解説もある)。本標準で条項番号や原則の個数を引用してはなりません。

### 3.2 ISO 12100 との構造的な異同

ISO 12100 側の情報は本標準の既存記述(`deliverable-templates.md:462-470, 536-544`)およびその調査メモ `research/phase4-standard/122-safety-risk-assessment.md` に依拠します。

| 観点 | ISO 12100(テンプレ9 が参照) | ISO 31000 |
| --- | --- | --- |
| 適用対象 | 機械類の設計 | 組織のあらゆる活動 |
| 保護対象 | 人体の傷害および健康障害 | 組織の目的の達成 |
| リスクの定義の向き | 危害(負の事象)のみ | 目的に対する不確かさの影響。**上振れも含む** |
| アセスメントの段階 | 危険源の同定 → リスクの見積り → リスクの評価 | リスク特定 → リスク分析 → リスク評価 |
| 低減の順序 | 3ステップメソッド(本質安全設計 → 保護方策 → 使用上の情報) | リスク対応の選択肢(回避・低減・移転・保有など)。優先順位は規定しない |
| 尺度 | 尺度と重みを規定しない | 同様に規定しない |
| 認証 | 適合性の主張が可能な設計要求 | ガイドラインであり認証しない |

**構造的には3段階が同型**です(特定 → 分析/見積り → 評価)。決定的に違うのは**保護対象**と**リスクの向き**の2点です。ISO 31000 は上振れ(機会)を含み、ISO 12100 は含みません。

### 3.3 COSO ERM(2017)

**二次**(COSO 原本は有償。複数解説の一致による)。

- 5つの構成要素は「ガバナンスとカルチャー」「戦略と目標設定」「パフォーマンス」「レビューと改訂」「情報・伝達・報告」
- 全体で**20の原則**を持つ
- 2017年版は ERM を**戦略・パフォーマンス・価値創造と不可分**なものとして位置づける。「パフォーマンス」の構成要素は、戦略および事業目標の達成に結びついたリスクの特定・評価・対応・報告を扱う
- 20の原則は規範的なチェックリストではなく、組織の規模・業種・複雑性に応じた形で達成すべき成果である

出典: [COSO's ERM Framework (NC State ERM Initiative)](https://erm.ncsu.edu/resource-center/cosos-erm-framework/) / [COSO ERM Framework 2017: The 5 Components and 20 Principles](https://medium.com/@humerahfarooqui.com/coso-erm-framework-2017-the-5-components-and-20-principles-896ed258ca46)

**ISO 31000 との使い分け**(筆者の解釈、後述の考察へ): ISO 31000 は「個々のリスクをどう扱うかのプロセス」、COSO ERM は「組織全体でリスクを戦略へ結びつける体制」に重心があります。個別案件の企画書に載せるのは前者の3段階です。後者は本標準の第3章(会議体・B-1〜B-4)の領域に対応します。

### 3.4 事業リスクの分類体系

**未確認**。「戦略・財務・運用・法務・レピュテーション」という4〜5区分は実務で広く流通していますが、**ISO 31000 も COSO ERM もリスクの分類体系(taxonomy)を規定していません**。今回の調査で、標準文書に基づく単一の分類体系は確認できませんでした。

日本の実務で分類が事実上定まる場は、**有価証券報告書の「事業等のリスク」**です。金融庁「記述情報の開示に関する原則」(平成31年3月19日)は、事業等のリスクについて次を具体的に記載することを求めています。

- 経営者が認識している主要なリスク
- 当該リスクが顕在化する可能性の程度や時期
- 顕在化した場合に経営成績等へ与える影響の内容
- 当該リスクへの対応策
- 開示に当たっては、リスクの重要性および**経営方針・経営戦略等との関連性の程度**を考慮すること

出典: [記述情報の開示に関する原則(金融庁、PDF)](https://www.fsa.go.jp/policy/kaiji/sustainability03.pdf) / [「事業等のリスク」の開示(金融庁 2021年4月、PDF)](https://www.fsa.go.jp/news/r2/singi/20210416/03.pdf) / [「事業等のリスク」の開示例(金融庁 2026年3月27日、PDF)](https://www.fsa.go.jp/news/r7/singi/20260327/03.pdf)

**この4項目は本標準のテンプレ6 のリスク表の列(リスク・影響・方針・判断者)とほぼ対応します**。対応していないのは「顕在化する可能性の程度や時期」と「経営戦略等との関連性」の2つです。

出典: [経済産業省 リスク新時代の内部統制(J-GLOBAL 書誌)](https://jglobal.jst.go.jp/detail?JGLOBAL_ID=200902229166831163)

## 4. C. 投資家・株主への説明性

### 4.1 国際統合報告フレームワーク

**二次**(IFRS 財団の日本語訳ページは ifrs.org へ 301 リダイレクトし、リダイレクト先に内容要素の一覧はありません)。

- フレームワークは「指導原則(Guiding Principles)」と「内容要素(Content Elements)」の2本柱で構成される
- 内容要素は8つ。「組織概要と外部環境」「ガバナンス」「ビジネスモデル」「リスクと機会」「戦略と資源配分」「実績」「見通し」「作成と表示の基礎」
- 「戦略と資源配分」は「組織はどこを目指すのか、また、どのようにそこに辿り着くのか」を扱う。短期・中期・長期の戦略、既存の戦略、資源配分計画、および実績の測定方法を含む
- 日本語訳は日本公認会計士協会が翻訳し2014年3月に発行。IIRC の枠組みは現在 IFRS 財団の管理下にある

出典: [IFRS - Integrated Reporting](https://www.ifrs.org/issued-standards/integrated-reporting/) / [IFRS - Integrated Reporting framework](https://www.ifrs.org/issued-standards/integrated-reporting/framework/) / [International IR Framework January 2021 (PDF)](https://integratedreportingsa.org/ircsa/wp-content/uploads/2021/01/International-IR-Framework-2021-with-changes-highlighted.pdf) / [JPX ESG Knowledge Hub 国際統合報告フレームワーク](https://www.jpx.co.jp/corporate/sustainability/esgknowledgehub/disclosure-framework/04.html)

**未確認**: 「戦略と資源配分」の内容要素の条項番号および要求事項の正文。フレームワーク原本 PDF の本文抽出に失敗しました。

### 4.2 コーポレートガバナンス・コード 原則5-2

**確認**(東証の上場会社向け FAQ が原則5-2 を引用しており、その引用と複数解説が一致)。

原則5-2 は、経営戦略や経営計画の策定・公表に当たり次を求めます。

- **自社の資本コストを的確に把握する**
- 収益計画や資本政策の基本的な方針を示す
- 収益力・資本効率等に関する目標を提示する

## 6. E. 記述の質を機械判定しない制約下で何を検査するか

### 6.1 本標準の既存の答え

5.7.4 は既に**存在検査と質的判定を分離**しています(`human-ai-boundary.md:311-323`)。

- 要求事項1: 記述の実質性を機械的に判定して承認可否を自動決定してはならない
- 要求事項2: 自動判定は人間への提示(注意の喚起)に限る
- 要求事項3: **欄の形式的な欠落は機械検査してよい**

機械検査してよい対象として「欄が空欄」「『確認していない事項』に『なし』と記載」「直前の同種の記録と記述が一致」の3つが列挙されています。**この設計は企画書にもそのまま適用できます**。新しい設計原則は要りません。

### 6.2 投資判断における予測の精度: 定量された実証

**確認**(査読誌に掲載された研究。要旨および論文の書誌情報で確認)。

Flyvbjerg らによる交通インフラ 210 件(1969〜1998年)の需要予測の精度検証。

- **鉄道案件の10件中9件で旅客需要が過大予測**であり、**過大の平均は 106%**
- **道路案件の半数で、実績と予測の差が ±20% を超える**
- 不正確さの原因は鉄道と道路で異なる。**意図的に傾けられた予測**の寄与は道路より鉄道で大きい
- **30年間の期間を通じて予測は正確になっていない**。予測者による反対の主張にもかかわらず

出典: [Flyvbjerg, Skamris Holm & Buhl (2005) How (In)accurate Are Demand Forecasts in Public Works Projects? The Case of Transportation, JAPA 71(2)](https://www.tandfonline.com/doi/abs/10.1080/01944360508976688) / [同(SSRN)](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2238050) / [同(arXiv PDF)](https://arxiv.org/pdf/1303.6654)

参照クラス予測(reference class forecasting)については、Flyvbjerg (2006) が次を述べています(**確認**、arXiv の要旨で確認)。

- 不正確さは**楽観バイアス**と**戦略的過小表示(strategic misrepresentation)**で説明される
- 参照クラス予測は「比較可能な案件の参照クラスにおける実績に基づいて予測する」ことで、**この両方を迂回する**
- 2002年のノーベル経済学賞を受けた不確実性下の意思決定理論に基礎を置く

出典: [Flyvbjerg (2006) From Nobel Prize to Project Management: Getting Risks Right, Project Management Journal 37(3), pp.5-15 (arXiv)](https://arxiv.org/abs/1302.3642)

実務適用の第一例は 2004年のエディンバラ・トラム 2号線の費用推計です。推進側の見積りは基礎費用 £255 million に対し予備費と楽観バイアス分として 25% を上乗せしたものでしたが、**比較可能な鉄道案件 46 件の参照クラスは、推進側の見積りが楽観的であることを示しました**(**二次**、論文本文未取得)。

出典: [Curbing Optimism Bias and Strategic Misrepresentation in Planning (European Planning Studies 16(1))](https://www.tandfonline.com/doi/full/10.1080/09654310701747936)

参照クラス予測自体への批判的検討も存在します(**未確認**、要旨のみ)。

出典: [Reference class forecasting: promises, problems, and a research agenda moving forward (2025)](https://www.tandfonline.com/doi/full/10.1080/09537287.2025.2578708)

### 6.3 「精度を装った数字」を要求することの害

2.2(財務手法が最悪の成果)と 6.2(予測は体系的に過大かつ30年改善しない)は、同じ結論を別方向から支持します。

### 7.1 Issue #122 で何が起きたか

オーナーの指摘は2つの要素を含んでいました。第1に**企画フェーズに経営リスクアセスメントが要る**という主旨。第2に**その手法の一例として ISO 12100 がある**という例示です。#122 の成果物は第2の要素だけを実装しました。ADR-0011 は ISO 12100 の適用範囲を検証して独自規定へ落とす判断をしており、その判断自体は妥当です。しかし**第1の要素は実装されずに残りました**。

| 3 | 受益者と市場の実在 | 誰の何がどれだけ変わるか | 既存「目的と価値仮説」。測れない表現の禁止規定を活用 | 既存 |
| 4 | 投資対効果 | 費用と効果はいくらか。**その数字が外れる条件は何か** | 既存の投資対効果の表。行を追加(8.4) | 既存 + 行追加 |
| 5 | リスクと受容 | どのリスクをどう扱うか。**いつ顕在化しうるか** | 既存のリスク表。列を追加(8.3) | 既存 + 列追加 |
| 6 | 中止条件 | どうなったら止めるか | テンプレ6 に**中止条件の欄**を追加。7.7.3 の必達基準5項目を企画時に案件へ具体化したもの | 追加(7.7.3 の前借り) |

観点1と2について、記述の指示を具体にすることを提言します。**因果の物語を書かせてはなりません**(4.5 の BSC 批判)。書かせるのは「対応する戦略目標の識別子」と「対応が成立しなくなる条件」です。

観点4の財務は、Stage-Gate と Five Case Model の双方で**最初のスクリーニングの主役ではありません**(2.1、2.4)。G-1 の判定基準1の順序は変えなくてよいものの、確認方法の列に「観点1・2が空欄または前案件と同一の場合、基準1の判定に進まない」旨を書くことを提言します。これは 5.7.4 要求事項3が認める**形式的な欠落の機械検査**の範囲に収まります。

### 8.3 ISO 31000 と ISO 12100 の2系統になることの是非: **分けたままにする**

**統一しないことを提言します**。ただし呼称を分けます。

- テンプレ9(第6章)は現状どおり「AIエージェント安全リスクアセスメント」とし、ISO 12100 の手順を参照した規定であるという位置づけ(ADR-0011)を維持する
- 企画側の観点5は**「リスクアセスメント」と呼ばない**。「事業リスクの特定と受容方針」とする。ISO 31000 の3段階(特定・分析・評価)と構造は同型だが、**規格名を引用しない**

根拠は3点です。

- **保護対象が違う**(3.2)。ISO 12100 の保護対象は人体の傷害、企画側は組織の目的の達成である。両者を1つの表に混ぜると、危害の深刻度尺度(Hs / Ex / Oc / Av)と事業影響を同じ列で扱うことになり、どちらの判定も鈍る
- **リスクの向きが違う**。ISO 31000 は上振れを含み、ISO 12100 は含まない。統一すると、テンプレ9 に機会を書く余地が生まれ、SR4 の判定が緩む
- **ISO 31000 の条項番号を本文で確認できていない**(3.1)。原則の個数さえ解説間で揺れる。この状態で規格名を引用すると、ADR-0011 が避けた「準拠の誤主張」を企画側で再現する

ADR-0011 が採った「手順の参照であって準拠ではない」という立場を、**企画側では規格名の引用ごと落とす**という一段強い形で適用する提案です。2系統ではなく、**規格を参照する系統は1つ(テンプレ9 のみ)**になります。

### 8.4 定量化を義務づけるべきか: **金額の1点見積りは義務づけない**

現行のテンプレ6 の「期待効果(年): 価値仮説の金額換算と算定根拠」は**単一の年額を求める構造であり、修正すべき**と提言します。義務づけるのは金額そのものではなく次の3点です。

1. **算定根拠**(現行どおり維持)
2. **レンジまたは参照した過去案件**。自組織の過去案件の実績値を1件以上挙げる。挙げられない場合は「参照できる過去案件なし」と書かせる
3. **前提が崩れる条件**。どの前提が誤っていたら効果が出ないか

根拠は3点です。

- 交通インフラ 210 件で**鉄道の10件中9件が過大予測、過大の平均は 106%**、道路の半数で ±20% 超の乖離、30年で改善なし(6.2)。単点の予測は体系的に偏る
- **財務手法に依拠したポートフォリオ管理は成果が最も悪い**(2.2)。厳密に見える数字が判定の質を上げるわけではない
- Green Book は uplift という**手続き**で補正している(2.4)。見積りを正確にするのではなく、偏りを制度で吸収する設計である

また、行政事業レビューシートの**短期アウトカムと長期アウトカムを分けて段階的に設定する**方式(5.2)を、期待効果の欄へ取り込むことを提言します。年額1本より検証可能性が高くなります。

**ROE 8% 等の外部の数値を本標準の初期値として書かないこと**も併せて提言します(4.4)。伊藤レポートの 8% は提言値であり、検証された閾値ではありません。事業基準は各組織が定める、という現行の立場を維持すべきです。

### 8.5 記号を新設する必要があるか: **不要**

新記号を作らないことを提言します。根拠は3点です。

- 8.1 のとおり変更はテンプレ6 の欄と G-1 の確認方法に収まる。**識別すべき新しい判定・ゲート・レベルが生じない**
- 判定の総数を増やさない原則に沿う
- 既存記号との衝突リスクが実在する。事業リスクの分類に記号を割り当てると、次の読み違えが起きる

| 作りたくなる記号 | 衝突する既存記号 | 誤読の内容 |
| --- | --- | --- |
| B-1〜B-5(Business risk) | **B-1〜B-4**(会議体) | 会議体の識別子と完全衝突 |
| BR1〜BR5 | R1〜R3(リスク区分) | R 系の派生と誤読される |
| ER1〜ER5(Enterprise risk) | EN-1〜EN-3 | E 始まりの既存が2系統あり判別困難 |
| SR-B1 等 | SR1〜SR4(安全リスク) | 安全側の記号と混同。8.3 の分離方針に反する |
| G-0 / G-1a | G-1〜G-8 | ゲートの追加と誤読される |

リスクの分類が必要な場合は、**記号ではなくリスク表の列の値(語)として持つ**ことを提言します。列名は「区分」とし、値の初期集合は「戦略」「財務」「運用」「法務・規制」「レピュテーション」「AI 固有」とします。ただし**この6区分に標準文書の裏づけはありません**(3.4)。初期値であり組織が変更できる、と明記すべきです。

分類の各行に何を書かせるかは、金融庁「記述情報の開示に関する原則」の4項目に寄せることを提言します(3.4)。既存の列(リスク・影響・方針・判断者)に対し、**「顕在化しうる時期」の1列を追加**すれば、有価証券報告書の「事業等のリスク」の記載事項と対応が取れます。投資家説明性を、開示制度と同じ語彙で満たす設計になります。
