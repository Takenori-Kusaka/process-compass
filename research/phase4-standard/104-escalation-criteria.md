# 調査メモ: エスカレーション基準と報告様式（Issue #104）

- 調査日: 2026-08-05
- 対象 Issue: #104 「予算・スケジュール超過時におけるエスカレーション基準の策定」
- 目的: 発火条件の閾値、報告様式、決裁後のポートフォリオ調整の連携方法を定める

---

## 1. 調査結果

### 1.1 逸脱の閾値と段階的なエスカレーション

実務では、逸脱の大きさに応じて報告先を段階的に上げる方式が用いられる。代表的な設定例は次のとおりである。

| 対象 | 段階1 | 段階2 | 段階3 |
| --- | --- | --- | --- |
| 予算 | 10% 超過 → プログラム管理者 | 20% 超過 → ポートフォリオ責任者 | 30% 超 → 経営スポンサー |
| スコープ | 5% 変動 → 管理者 | 15% 変動 → 部門責任者 | 25% 超 → 運営委員会 |
| 日程 | 1週間の遅延 → プロジェクト責任者 | 2週間の遅延 → プログラム責任者 | クリティカルパスへの影響 → スポンサー |

閾値は「自動的にエスカレーションを発火させる条件」として定義される。判断を待って報告するのではなく、条件に該当した時点で報告が発生する構成である。

### 1.2 エスカレーション体制表に必要な要素

エスカレーション体制表(マトリクス)は、次の要素を定義する必要がある。

- 発火条件(トリガー)
- 深刻度
- 責任者
- 応答時間
- 決裁権限

加えて、各段階の関係者の連絡先・役割・責任、および連絡手段・頻度・様式を含める。

### 1.3 運営委員会と PMO の役割

- 運営委員会(SteerCo)は統治構造における上位の意思決定層であり、戦略的な監督と影響の大きい判断を担う。デリバリーチームの権限を超えた課題が上がった際に、スコープ変更・リソース配分・リスク解消の方向を示す。
- PMO は、権限を超えた課題を適切な意思決定層へ接続する構造化された経路を提供する。

### 1.4 記録の要求

エスカレーションは、課題ログ・決定ログ・リスクログ・変更ログのいずれかに記録する。状況報告の様式には、RAG 状態・予算差異・マイルストーン遵守・主要リスクを一貫した構造で含める。

## 2. 設計判断

### 2.1 閾値は初期値として示し、企画時に確定する

1.1 の値は業界の一般的な設定であり、事業規模によって妥当な水準が変わる。本標準では初期値として提示し、企画承認(G-1)の時点で組織が確定して記録する方式を採る。欠陥トリアージの定量指標(#100)と同じ構成である。

### 2.2 品質側の発火条件を追加する

1.1 は予算・スコープ・日程の3軸だが、AI 協調開発では品質側の劣化が先行指標になる。次を追加する。

- 独立レビューの差し戻し率が基準を超えた状態
- 同一箇所での修正の反復(AI が同じ箇所を繰り返し修正し収束しない状態)
- ゲート判定の期限超過率が基準を超えた状態

差し戻し率の警戒方向は両側である。高すぎる場合は手前の工程の品質問題を示し、ゼロが続く場合は形骸化を示す。この点は既に第4章「ゲートの健全性を計測する」に記載がある。

### 2.3 エスカレーションレポートの様式（Issue の問いへの回答）

Issue の問いは「現場と経営層の認識ギャップを最小限にするため、AI が要約すべき標準様式はどうあるべきか」である。認識ギャップの主因は次の2点にあると整理した。

1. 現場は経緯を語り、経営層は選択肢を求める
2. 現場は技術的事実を述べ、経営層は事業影響への換算を求める

したがって様式は、**経緯を最小化し、選択肢と事業影響への換算を必須とする**構成にする。具体的には次の5項目とする。

| 項目 | 内容 | 分量の上限 |
| --- | --- | --- |
| 1. 状態 | 何が基準を逸脱したか。数値で示す | 3行 |
| 2. 原因 | 直接原因と、判明していれば背景要因 | 5行 |
| 3. 事業影響 | 期日・費用・利用者・契約への換算 | 表 |
| 4. リカバリ選択肢 | **必ず3案**。各案の到達点・費用・期日・残るリスク | 表 |
| 5. 推奨と決裁事項 | 起案者の推奨案と、決裁者に求める判断 | 3行 |

**選択肢を3案とする理由**: 1案は決裁ではなく承認の要求になり、2案は二者択一の圧力になる。3案あると、期日を守る案・品質を守る案・範囲を削る案という異なる価値の比較が成立する。

AI はこの様式のうち、1〜4 の草案を生成できる。5 は人間が記入する。推奨の提示は結果責任(A)を負う人間の行為であり、AI へ委譲できない。

### 2.4 決裁後のポートフォリオ調整

Issue が求める「他プロジェクトの凍結・要員の再配分を PMO が調整するための情報連携インターフェース」については、本標準では次の最小要件のみを規定する。

- エスカレーションの決裁結果に、影響を受ける他案件の一覧を必ず含める
- 要員・予算の移動を伴う決裁は、移動元の案件の責任者へ通知する
- 移動により実施できなくなる事項を記録する

理由: 具体的な連携手段(ツール・帳票)は組織の既存 PMO 運用に依存し、標準が指定すると導入障壁になる。標準は「何を伝えるか」を規定し、「どう伝えるか」はテーラリングに委ねる。予算配賦と中止判断の詳細は #124 で規定する。
