# 調査メモ: マクロライフサイクルとステージ移行ゲート（Issue #99）

- 調査日: 2026-08-05
- 対象 Issue: #99 「DR0/DR1/DR2 とマイクロループを接続するマクロライフサイクル設計」
- 目的: 事業ステージの区分・移行ゲート・部門間移管の基準を、国内外の実務慣行を根拠に定める

---

## 1. 調査結果

### 1.1 日本の製造業におけるデザインレビュー（DR）の実態

国内製造業で用いられる DR は、**設計の節目ごとの審査**であり、一般に次の4段階で運用される。

| 段階 | 名称 | 審査内容 |
| --- | --- | --- |
| DR1 | 開発企画フェーズ | 市場調査・顧客ニーズ分析に基づく開発の妥当性、競合差別化、事業性。着手可否を判断する |
| DR2 | 構想設計フェーズ | 開発計画の明確化、どの技術・部品・プロセスで実現するかの評価 |
| DR3 | 詳細設計フェーズ | 生産設備を用いた試作へ進めるかの評価 |
| DR4 | 量産移行フェーズ | 量産試作へ移行できるかの審査 |

DR は「企画→基本設計→原理試作→詳細設計→一次試作→量産試作」の各節目で、企画・開発・設計・製造・品質・購買の関係者が一堂に会し、各観点から基準充足を確認したうえで次段階へ進む方式である。

### 1.2 Stage-Gate プロセス（国際的な枠組み）

- イノベーションプロセスを離散的なステージに分割し、その境界に置いた**ゲートで go / kill / hold / recycle を判断する**枠組みである。
- Discovery（ステージ0）から Launch までの6段階を基本形とし、各ゲートで正式なゲート会議を開く。
- ゲート判断の基準は6項目が定石とされる: 戦略適合、製品・競争優位、市場魅力度、技術的実現性、シナジー・コアコンピタンス、財務的リターンとリスク。
- Gate 4 では「スケールを支持する証拠があるか」を評価し、通過すると最終承認とロールアウト計画へ進む。
- 2026年時点の潮流として、**ステージゲートによる統治とアジャイルの反復を組み合わせたハイブリッドが、統治構造を犠牲にせず市場投入までの期間を約30%短縮する**と報告されている。また、資料の自動集約・テンプレートの事前入力によりゲート準備時間が40時間超から4〜6時間へ短縮された事例がある。

### 1.3 新規事業のステージ運用（国内）

- 新規事業開発は不確実性が高く、仮説検証サイクルを反復して学びの量を最大化する運用が前提とされる。
- ステージごとに評価基準と想定成果物を定め、基準を満たした段階で審査を受ける方式が用いられる。
- 最終ステージは EXIT（部門化・会社化）であり、新規事業の枠組みを離れて独立した事業部または別会社となる。

出典:
- https://fintan.jp/page/6884/
- https://alphadrive.co.jp/knowledge/article/jigyo-procedure/

### 1.4 規制領域（IEC 62304）

- ソフトウェア安全クラス（A/B/C）を、故障が引き起こす危害の大きさで分類する。**安全クラスが、ライフサイクル活動に要求される厳格さを直接決定する**。
- すべての要求・設計判断・テストが特定のリスクへ遡れることを要求する。要求→設計→実装→検証のトレーサビリティを文書で示す必要がある。
- ISO 13485 を明示的に参照しており、IEC 62304 の全活動は品質マネジメントシステムの傘の下に置かれる。

## 2. 設計判断

### 2.1 名称の衝突を回避する（Issue 記載からの変更）

Issue #99 は事業ステージを「DR0: 探索期 / DR1: 価値確立期 / DR2: スケール期」と記述している。しかし 1.1 のとおり、**国内製造業では DR1 が「開発企画フェーズの設計審査」を指す**のが一般的であり、同じ記号が異なる対象を指すことになる。製造業を含む JTC へ提示する標準としては、この衝突は現場の誤解を生む。

したがって次のとおり変更する。

| 区分 | 本標準での記号 | 名称 |
| --- | --- | --- |
| 事業ステージ | S0 / S1 / S2 | 探索 / 価値確立 / スケール |
| ステージ移行ゲート | SG-0 / SG-1 / SG-2 | 探索完了 / 価値確立完了 / スケール完了 |
| 工程ゲート（既存） | G-1〜G-8 | 企画承認〜リリース決裁 |

Issue が用いた DR0 / DR1 / DR2 は、S0 / S1 / S2 の別称として用語定義に併記し、検索性を保つ。既存の製造業 DR 体系（DR1〜DR4）との対応表も本文に置く。

### 2.2 ステージゲートと工程ゲートを別の軸として扱う

既存の G-1〜G-8 は**1つの開発サイクル内の工程ゲート**であり、事業ステージの移行判断とは判断の性質・判定者・頻度が異なる。両者を同じ記号体系に混ぜると、次の不整合が生じる。

- G-2（要件合意、価値責任者が48時間で判定）と、ステージ移行判断（投資委員会が月次で判定）が同じ記号になる
- テーラリングでゲートを省略する規則が、事業判断まで省略してしまう

そこで**二軸構成**を採る。

- 縦軸: 事業ステージ S0 → S1 → S2（不確実性の低減段階）。境界に SG-0 / SG-1 / SG-2
- 横軸: 各ステージ内で有効化する工程ゲート G-1〜G-8 の組（ステージが上がるほど有効化される数が増える）

これにより、既存の G 体系を維持したままマクロなステージ統治を追加できる。

### 2.3 部門間移管を SG-1 の要件に組み込む

Issue の問い「企画部門が作成した荒い事業意図を、開発部門が精緻な技術コンテキストへ変換するための移行ゲート基準」に対しては、次を採用する。

移管は**文書の受け渡しではなく、受入側による再構成の完了をもって成立**させる。1.4 のトレーサビリティ要求（要求→設計→実装→検証）と同じ考え方であり、受入側が自分の言葉で要求を再構成できない限り、移管は完了していないと扱う。

具体的な合格基準は本文（第2章）に規定する。

### 2.4 ステージによって AI協調ループの回し方を変える

Stage-Gate とアジャイル反復のハイブリッドが有効という 1.2 の知見を、本標準では次の形で採用する。ステージが上がるほど、反復の速度より記録の厳格さを優先する。

| 観点 | S0 探索 | S1 価値確立 | S2 スケール |
| --- | --- | --- | --- |
| ループの主目的 | 学習 | 適合 | 品質と再現性 |
| 独立レビュー | 任意 | コア機能に必須 | 全件必須 |
| 判断記録(ADR) | 主要な選択のみ | コア機能は必須 | 全件必須 |
| コンテキスト基盤 | 案件層のみ | 恒久層の整備開始 | 恒久層の維持が必須 |
