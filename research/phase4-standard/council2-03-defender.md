## #244 決裁の場で「伝わるか」を扱う規定が無い

### 弁護の骨子

**この Issue は、自分が提出したと主張するデータを提出していません。**

`community/evidence-ledger.md:44` の EV-0019 の差し替え条件は次のとおりです。

> **投影を用いた決裁3件分の記録**と、決裁者が不足を指摘した項目の一覧

Issue の表題は「EV-0019 の差し替えデータ1件分」と書いています。しかし本文が自ら次を認めています。

> 本案件が附属書G を使えなかった理由は #233(クローズ済)と #239 と同根です(案件の KB は 2026-08-10 生成、附属書G は 08-12 新設)

**提出されたのは、投影を用いなかった決裁4回の記録です。** 差し替え条件が求めているのは、投影を用いた決裁の記録です。**件数が1/3 なのではありません。0/3 です。**

これは体裁の問題ではありません。ADR-0045 決定1 が禁じた形そのものです。

> **どの観測が得られたらどちらへ判定するか**

投影を用いなかった決裁が3回棄却されたという観測は、次の2つの仮説の**両方と整合します**。

| 仮説 | この観測と整合するか |
| --- | --- |
| 附属書G の8項目が不足している | 整合する |
| 附属書G が案件へ届いていなかった(#239 の配送問題) | **整合する** |

**分離できません。** そして Issue 自身が後者を明記しています。ADR-0046 決定3 が「適用0件は両方の仮説と整合する」として回避の直接検出条件を併置した論法が、そのまま当てはまります。

**さらに、Issue 自身の表がこの分離を後者へ倒しています。**

> | 1 | 何を承認してほしいかが1行も無い | **防げた**(G.3 の提示順) |

**1回目の棄却は、附属書G を読んでいれば起きませんでした。** これは附属書G が不足している証拠ではなく、附属書G が届いていない証拠です。

G.2 は「出所を持たない項目を加えてはなりません」と定め、8項目すべてに正本の欄を対応づけています。Issue の提案6「名前 + 一言 + アーキテクチャ図」について、Issue 自身が次を認めています。

## #245 中核の価値仮説に根拠を付ける工程が、着手決裁の前に無い

### 弁護の骨子

**標準は「増やすな」と明示的に書いています。** `lifecycle.md:76` です。

> **SG-0 の判定基準を増やしてはなりません。** 基準を増やすと、投資継続の判定に実装の詳細が持ち込まれます

Issue の案2 は、これを「基準の追加ではなく確認方法の明示だ」と整理して回避しようとします。**しかし G-1〜G-8 の様式では、確認方法は不合格状態と差し戻し先を伴います。** 確認方法・不合格状態・差し戻し先の3点を置けば、それは実質的に判定基準です。**Issue 自身が「この整理が成立するかは標準側の判断です」と書いており、成立を主張していません。**

**案3(G-1 に基準を1点足す)は、二者択一に落ちます。**

| 確認方法をどう書くか | 帰結 |
| --- | --- |
| 「根拠が記載されている」= 欄の充足 | **本案件で既に起きたことが再現する。** 観点4 に「金額の算定は行わない」と書いて G-1 を通過した事例がある。欄は埋まる |
| 「根拠が妥当である」= 内容の判定 | **5.7.4 要求事項1 に反する。** 記述の実質性を判定して承認可否を決めることになる |

**どちらの側にも出口がありません。** これは #245 の設計上の欠陥ではなく、G-1 の設計思想です。`gate-criteria.md` は「欄の空白は機械的に検査します(記述の内容は機械が判定しません)」と定めています。

### 変更を採ると何を失うか

**ADR-0031 は、まさにこの論点を審議して結論を出しています。** 検討した選択肢に「S0 探索ステージと SG-0 に委ねる」があり、次のとおり書かれています。

> SG-0 の基準「事業仮説が実証データで支持されている」は欄への記述より強い要求であり、**この整理自体は正しい**

**標準は既に「S0 で実証する」を正しい整理として採用しています。** #245 が報告しているのは、S0 探索6本がすべて技術検証になったという**案件側の探索設計の問題**であって、SG-0 の基準の不足ではありません。SG-0 の基準1 は最初から「事業仮説が実証データで支持されている」です。

**そして案件は、その基準を「未検証」と自ら申告したうえで通過させました。** ADR-0028 の `unmet` は、まさにその申告が消えずに残るための機構です。#245 は「`unmet` がゲートの通過を阻止しない」と書きますが、**阻止しない設計は意図されたものです。** `gate-criteria.md` が明記しています。

> **前提が崩れていることを理由に判定を停止しません。** 可視化し、受容の決裁を求めます

**未達で止める設計へ変えると、ADR-0028 が守ってきた「未達と省略の区別」が壊れます。** 未達の宣言が通過を止めるようになれば、書き手は未達と書きません。省略として処理するか、書かなくなります。**前ラウンドで現場側自身が示した「装置を増やすほど回避と未記録の確率が上がる」機序が、そのまま働きます。**

1. **S0 探索の設計が技術偏重になったことは、標準のどの条項の不在に帰責されるのか。** SG-0 基準1 は事業仮説を要求している。基準はあり、探索がそれに応えなかった
2. **`unmet` を通過阻止へ変えた場合、未達の申告件数が減らないと考える根拠は何か**

### 弁護できない部分を切り出します

標準は SG-0 を3項目で定義し、生成物は2項目で出力しています。**「事業仮説が実証データで支持されている」が落ちています。** これは判断の是非ではなく、複製の欠落です。#238 / #239 と同じ family に属する不具合です。

## #246 「利用者が使い方に気づけるか」を問う工程が無い

### 弁護の骨子

**これは製品設計の要求であって、開発プロセスの要求ではありません。**

Issue が引く一次情報(総務省 令和7年版 情報通信白書 図表Ⅰ-1-2-9、IPA『DX動向2025』図表2-12)は、いずれも**生成AI という製品カテゴリの需要側の実測**です。**開発プロセスの適合性を測ったものではありません。**

**この2つの間には、標準が越えてはならない線があります。** 標準が「利用者が用途に気づけるか」を判定基準に置くと、**標準がプロダクトの良し悪しを判定し始めます。** ADR-0014 決定9 が総合スコアと成熟度ラベルを排したのは、標準の出力が組織内の評価材料へ転用されることを避けるためでした。**同じ構造が、案件の成果物の側でも生じます。**

**そして 5.7.4 が塞いでいます。** 「見て気づけるか」は記述でも欄でもなく、体験の質です。機械では判定できません。人が判定するなら、**ゲートに主観的な品質判定が1つ入ります。** `gate-criteria.md` の全ゲートは、これを避けるために確認方法を突合と充足で構成しています。

### 変更を採ると何を失うか

**案1(観点3 に欄を1つ足す)を採ると、ADR-0031 決定4 が守った線が消えます。**

ADR-0031 は、需要側を問う欄を独立させる案(観点3b)を明示的に却下しています。

> ADR-0016 決定2 が観点を6つと固定しているため、新 ADR による決定の変更を要する。**得られる差分のうち2行は決定4 で、1行は決定5 で回収でき、残りは決定6 の理由により採らない項目である**

**「気づく経路」は、ADR-0031 が却下した「チャネル(到達経路)」と同じ形です。**

> **チャネルの欄を設ける** — 到達経路は単体流通の成否を左右する。ただし「**こう届けばこう売れる**」という因果の連鎖の記述であり、ADR-0016 決定4 が禁じた形式に該当する

「利用者がこう見ればこう気づく」は、「こう届けばこう売れる」と同型の因果の連鎖です。**書き手は検証していない連鎖を書きます。** ADR-0031 は既にこの判断を下しています。

**案2(SG-1 の基準1 に確認方法を置く)は、範囲が SG-1 に留まりません。** SG-0 / SG-1 / SG-2 のいずれにも確認方法がないのは、ステージ移行ゲートが工程ゲートと**判定の粒度が違う**ためです。SG-1 だけに確認方法を置けば、次は SG-0 と SG-2 が問われます。そして SG-0 には「増やすな」の条項があります。

### 提案側が答えていない問い

1. **受入基準86件に UI の基準が0件だったのは、標準のどの条項が原因か。** 何を受入基準にするかは案件が決める。標準は EARS 記法の形式を定めており、対象の選定は定めていない
2. **「気づけるか」を判定する主体は誰か。** 判定者(価値責任者)がプロダクトデザインの妥当性を判定できる根拠は何か

### 弁護側の対案

**案3 の後段には賛成します。**

> 受入基準を満たすことと利用者が使えるようになることが別であることを、どこかに明記する

**これは規定の追加ではなく、限界の明示です。** ADR-0041 決定1・決定3 が採った「網羅を主張せず、どちらの向きに漏れるかを書く」と同じ形です。**受入基準の節に2〜3行を置けば足ります。判定も会議体も様式も増えません。**

## #241 投資対効果の様式が収益前提になっている

### 弁護の骨子

**この Issue は、標準が正しく振る舞った事例を、標準の欠陥として報告しています。**

Issue が引く一次資料は次のとおりです。

> Stage 1(Foundational)で避けるべきこと: "**Avoid demanding fully formed ROI proof** before the OSPO function has stable processes or data"(LF, *Measuring OSPO Value* 2026-06, p.26 Table 3)

そして Issue 自身が認めています。

> **本案件の「金額の算定は行わない」は、一次資料が Stage 1 で推奨する扱いと一致していました。欠陥ではありませんでした。**

**標準の観点4 は、この記述を受け入れて G-1 を通しました。** 観点4 の欄は「初期開発費 / コンテキスト基盤の初期整備費 / 運用費(年) / 期待効果(短期) / 期待効果(長期) / 算定根拠 / 参照した過去案件 / 効果が出ない条件」であり、**金額を要求する文言はどこにもありません。**

「期待効果(長期)」の注記は `<幅で記載する。単一の年額を書かない>` です。**単一の年額を禁じています。** 「参照した過去案件」の注記は `<無い場合は「参照できる過去案件なし」と記載>` です。**無いことを書ける様式です。**

**収益前提の様式ではありません。**

### 変更を採ると何を失うか

> **差し替え条件**: 自組織の実測4四半期分、または行数上限そのものを検証した研究
