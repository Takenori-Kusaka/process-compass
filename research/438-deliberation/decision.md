# 議長の裁定(#438 Vale の導入の検討)

- 審議の重さ: **軽**。本リポジトリの検査の道具の選定で、採用者への新しい義務は無い(`survey-438.md` 第5節)
- 入力: `survey-438.md`(実行での確認を含む)、`council-01-drafter.md`、`council-02-opponent.md`

## 裁定

1. **日本語の文書に Vale を入れない**(2委員)
   - Vocab の reject は、既定のままでは日本語の語を1件も検出しない(実行で確認。`\b` が日本語の文字の間に立たない)
   - nonword の独自規則にすると、check-tone と同じ検出になり、検査の経路が二重になるだけ。さらに照合が部分文字列の正規表現になり、除外の理由も強制できない
   - #108 は Vale を検討したうえで見送っている
2. **既存の検査を強める(B2)**(2委員)
   - provision-forms.yaml に「異表記 → 正表記」の区画を足し、check-provisions で検査する
   - 登録の項目ごとに、自己試験(prh の specs に相当)を置く(反対の委員の条件)
   - 区画を足すときは、第1章 1.7.4 と provision-forms.md を合わせて改める
3. **理由の無い除外の印が素通りする欠陥を直す**(反対の委員が実行で確認)。B2 の前提になる
   - check-tone.mjs:40 は、tone-ok の理由を確かめていない
   - check-provisions.mjs:78 では、`<!-- retired-ok: -->` の閉じの `-` が理由の `\S` に当たる
4. **用語の一覧は、道具と切り離して別に決める**(2委員)。#438 が公式用語に挙げる5語(外殻・内殻・RACI・不変条件・ピットイン)は、どれも第1章 1.4 に無い。本件ですぐ登録するのは、決定のある ADR-0027 の名称(通称・正式名称と、使わない語「統合プロセス」)だけとする。用語の一覧の決め方は、既存の #328(参照と語の食い違い)へ論点として足す
5. **英語の検査は、locales.en を足すときに選び直す**(2委員)。そのときは Vale を候補に含める。いま英語の頁は無い
6. ADR-0118 を新設し、道具の選定と採らない案を書く

## 採らない案

| 案 | 理由 |
| --- | --- |
| 日本語に Vale(A) | 既定では検出 0 件。独自規則にすると既存の検査と二重になり、除外の理由も強制できない |
| textlint の prh だけ | 置き換え先の無い禁止語に向かず、既存の登録の4つ組(理由つきの除外・ADR の実在)を失う |
| 手動・目視 | #108 の一括是正が要った経緯のとおり、すり抜ける |
| Warning の段階運用 | 既存の検査は落とす形で運用しており、警告だけの経路を足すと読まれない |
| 用語の一覧を本件で決める | 道具の選定と別の決定で、規範の語の確定に当たる |
