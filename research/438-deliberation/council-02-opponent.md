## 1. 論点A: Vale を導入するか

- **推す案: 導入しない**(#108 の見送りを維持。`108-tone-guardrail.md:49-52`)
- 理由
  - 既定の Vocab は日本語の語を0件しか検出しない(S:73)。#438 の中核の主張「accept/reject で宣言的に統制」は日本語で成り立たない(S:123)
  - 効かせる方法は2つとも欠陥がある。大域の `WordTemplate` は英語の語の境界を壊す(S:77)。#438 の目的2「英語展開」と正面から衝突する。規則ごとの `nonword: true` は `check-tone.mjs` と**同じ検出の集合・同じ部分文字列の誤検出**になる(S:81, S:90)。得るものが無く、検査の経路だけが二重になる(`108-tone-guardrail.md:51`)
  - 除外の理由を強制できない(S:89)。§0 の欠陥を直せば B2 は強制できるが、Vale では構造上できない
  - 探せる範囲が狭い。規則データ・準拠テンプレートの .yaml/.json の値を探せない(S:95。公式文書の記述による推定で、未実行)。`lint:provisions` 検査6 の範囲を置き換えられない
  - 組み込みの `Vale.Spelling` は docs 全体で 128 件、すべて日本語の文の中の英字(S:94)。切るか大量の accept を抱えるかで、どちらも保守の負担になる
  - Issue の No-Gos は「Warning 運用」を求める。止めない検査は無視される。信頼性の軸では、止める検査(既存の3つ)より弱い
- 認める点: Vale は英語では語の境界が効き、既成のスタイルがある(S:116)。`scope: table.cell` も書ける(S:91)。PR への注記は reviewdog 等で両者とも出せる(S:126。未実行)ので、差にならない
- 採らない案: Vale を日本語へ今入れる案。`lint:tone` を Vale へ移す案(検出は同じで、除外の規律だけを失う。S:134)

## 2. 論点B: textlint の prh か、既存の検査を強めるか

- **推す案: B2(既存の検査を強める)。ただし §0 を直すことが前提**
- 理由
  - 語の登録簿は既に `provision-forms.yaml` にあり、句・廃した日・廃した決定・代わりに書くことの4つ組と、ADR の実在の検査13 を持つ(S:41)。prh の辞書を別に置くと、**登録簿が2つになる**(どちらが正本かの規則が要る)。異表記の検査を足すなら、同 yaml に「異表記 → 正表記」の区画を足す(S:133)
  - 範囲は docs・規則データ・準拠テンプレートの全文(S:113)。prh は textlint の対象(docs)だけ
- B1(prh)を落とす理由: 置き換え先の無い禁止に向かない(S:102)。辞書へ入れる「異表記の一覧」が無い(§4)。道具を先に入れると、辞書の中身を道具の導入者が決めることになる
- B1 について認める点: `--fix` と項目ごとの `specs` の自己試験(S:103)は B2 に無い。B2 で区画を足すなら、登録の項目ごとに「当たる例・当たらない例」を持たせ、`test:` の段で試す形を同時に入れる。これを欠くなら、B2 は prh より信頼性で劣る
- 採らない案: prh を足し、`provision-forms.yaml` と併存させる案(正本の二重化)

## 3. それ以外の案

## 4. 用語の一覧(公式用語と異表記)を先に決める作業

- **推す案: #438 の道具の選定と切り離し、用語の決定を先に行う。道具はその後**
- 理由
  - #438 が挙げる公式用語のうち、外殻・内殻・RACI・不変条件・ピットインは第1章 1.4 に無い(S:13, S:54)。「ゲート」だけが 1.4 にある(`overview.md:103`)。「#108 等で整理された公式用語」の一覧は存在しない(S:124)
  - 一覧の無いまま accept/reject や辞書を作ると、道具の設定ファイルが事実上の用語の定義になる。1.4 の外に正本ができ、1.4 と食い違っても誰も検出しない
  - 1.4 へ語を足すことは標準の本文の変更で、道具の選定(軽)とは審議の性質が違う。定義の追加が採用者へ新しい義務を課さないかを、その審議で確かめる
- 扱い: 既存の open Issue に用語の整理を扱うものがあればそこへコメントで寄せ、無ければ起票する。#438 の受け入れ条件の「Vocab の策定」は、この作業の完了まで**保留**と明記する
- 採らない案: 道具の導入と同時に一覧を作る案(用語の決定が道具の都合で決まる)
