# #438 会議体(軽) 委員1: 起案

- 日付: 2026-11-11
- 材料: `research/438-deliberation/survey-438.md`(以下「調査」)、Issue #438 本文、`research/phase4-standard/108-tone-guardrail.md`、`scripts/check-tone.mjs`、`src/data/provision-forms.yaml`、第1章 1.4・1.7.4
- 立場: Issue の目的(用語の統制・トーン・CI の速さ・英語展開)を、既存の検査の規律を落とさずに満たす案を起こす

## 論点1: Vale を導入するか(A)

- **推す案**: 日本語の文書には導入しない。英語のロケールができた時点で、英語の文書に限って再審議する(調査の案 D)
- 理由
  - Vocab の既定では日本語の語を1つも検出しない(調査 §2.2 試験1、L69-75)。効かせる方法は2つあるが、どちらも信頼性を下げる。大域の `WordTemplate` は英語の語の境界を壊す(試験2、L77)。`nonword: true` の独自規則は `check-tone.mjs` と検出の集合が同じで、差は除外の仕組みだけ(試験3、L79-83)
  - その除外の仕組みが劣る。`vale off/on` の対は理由を強制できない(調査 L89)。本リポジトリの規約は「理由のない除外は認めない」(`style-guide-tone.md:38`)。移すと、この規律を失う(調査 L134)
  - 登録の情報が痩せる。`reject.txt` は語の列だけで、廃した日・廃した決定(ADR)・代わりに書くことを持てない。`provision-forms.yaml` の `retiredPhrases`(L58 以降)は4つ組で持ち、検査13 が ADR の実在まで確かめる(調査 L41)
  - 探せる範囲が狭まる。Vale はコードのコメントしか見ず、規則データと準拠テンプレートの .yaml/.json の値の中の廃した句を探せない(調査 L95。未実行の推定)。`lint:provisions` の検査6 はこれを探す(調査 L26)
  - #108 の見送りの理由(`108-tone-guardrail.md:49-52`)は、2026-11-11 の実行でも成り立った。覆す事実は見当たらない
- 他の案を落とす理由: 「Vale を足し、`lint:tone` と並べる」は検査の経路を二重にする。同じ正規表現を2か所で保守することになり、片方だけ直す食い違いの温床になる
- 採らない案: Issue のスコープの `.vale.ini`・`Vocab/ProcessCompass`・`vale-action` のジョブ。組み込みの `Vale.Spelling` は、日本語の文の中の英字で 128 件の誤検出を出す(調査 L94)ので採らない

## 論点2: textlint の prh か、既存の検査を強めるか(B)

- **推す案**: B2。既存の `lint:provisions` の登録簿 `provision-forms.yaml` に「異表記 → 正表記」の区画を足し、`check-provisions.mjs` で検査する。トーンは `lint:tone` のまま保つ
- 理由
  - 異表記の対にも「正表記を決めた決定(1.4 の項目か ADR)」を持たせられる。検査13 と同じく、決定の実在を機械が確かめる(調査 L133)。表記ゆれの是正は用語の決定に従属するので、決定へ辿れることが信頼性の要である
  - 範囲が docs・規則データ・準拠テンプレートの全文に及ぶ(検査6、調査 L26)。テンプレートへ複製した語の表記ゆれも止まる
  - 除外は `retired-ok: 理由` の規律に乗る(`check-provisions.mjs:34`)。理由の無い印を無効にできる
  - 置き換え先の無い禁止(めっちゃ・TODO)は `lint:tone` の `RULES`(`check-tone.mjs:17`)が既に担う。異表記と禁止を別の区画に分ける形は、prh の得意・不得意(調査 L101-102)とも一致する
- 他の案を落とす理由(B1: prh)
  - `--fix` と `specs` の自己試験は優れる(調査 L101-103)。ただし辞書は決定への参照を持てず、除外の理由を強制できない(調査 L111)。登録簿が `provision-forms.yaml` と prh の辞書の2か所に割れる
  - prh の `specs` に当たる自己試験は、B2 でも区画の各項目に「当たる例・当たらない例」を持たせて検査に組み込めば得られる。起案はこれを B2 の要件に含める
- 採らない案: 区画を足さず、異表記を `retiredPhrases` に混ぜる形。「廃した言い回し」と「表記ゆれ」は意味が違い、読み手が区別できなくなる

## 論点3: それ以外の案

- **推す案**: C(手動)は採らない。#108 の起票の経緯どおり、すり抜ける(調査 L109)
- CI の速さ(Issue の課題3)は、既に満たされている。`lint:tone` 約 0.8 秒、`lint:provisions` 約 1.3 秒(調査 L25-26)。Vale で速くなる余地は無い(調査 L115)
- PR の注記(reviewdog 等)は未実行(調査 L126)。本件の判断に要らないので、本件では扱わない
- Issue の No-Gos の「Warning から段階的に」は採らない。既存の検査は検出を即ち失敗とし、正当な使用は理由つきで除外する。この規律を Warning に緩める理由は無い。新しい区画は、登録した語の既存の出現を是正するか理由つきで除外してから有効にする
- 採らない案: textlint と Vale の責務の分担(Issue のスコープ末尾)。Vale を入れないので、分担を定めない

## 論点4: 用語の一覧(公式用語と異表記)を先に決める作業

- **推す案**: 道具の選定(本件)と用語の決定を分ける。本件の範囲は「異表記の区画の仕組み」まで。正表記の一覧そのものは、別の審議で決める
- 理由
  - #438 の挙げる5語(外殻・内殻・RACI・不変条件・ピットイン)は、1.4 の用語の定義(`overview.md:92` 以降)に1つも無い(調査 L54)。採る語の一覧は存在しない。一覧の無いまま accept/reject を書くと、検査が用語の決定を代行してしまう
  - 1.4 へ語を載せることは、本標準の定義の改訂である。採用者の読み方を変えるので、条項の審議として扱う
- 本件ですぐ登録できる語: ADR-0027 が既に決めた名称(「統合プロセス」を使わない、通称・正式名称の表記)。決定があるので、区画の最初の項目にできる。ADR の頁の歴史の記録(調査 L48)は範囲から外す
- 後継: 「1.4 に載せる公式用語と異表記の決定」は、既存の open Issue があればそこへ寄せ、無ければ起票する(所有者の判断)
- 採らない案: 調査の5語を、本件の中で正表記として登録すること。決定の無い登録になる

## 論点5: 英語展開への備え

- **推す案**: 今は何も足さない。英語のロケール(`locales.en`)を足す Issue の受け入れ条件に、「英語の文書の用語・トーンの検査を選ぶ(Vale を候補に含める)」を書く
- 理由
  - 今、英語の頁は無い(調査 L116)。対象の無い検査は、効いているかを実行で確かめられない
  - 英語では Vale の語の境界が効き、既成のスタイル(Google 等)も使える(調査 L110・L116)。その時点で選べば、日本語の `WordTemplate` の衝突(試験2)も起きない
  - #108 の調査も、英語の禁止語の一覧を別に定義すると予告している(`108-tone-guardrail.md:81`)
  - B2 の異表記の区画に英語の正表記(`PIT-IN`)を持たせれば、英語の表記ゆれは今の基盤でも止まる(prh の試験で同じ対が当たった、調査 L101)
- 採らない案: 英語の頁が無いうちに Vale の英語スタイルを配備すること
