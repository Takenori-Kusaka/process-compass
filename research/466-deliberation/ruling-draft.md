**裁定**

1. **値は L1 のまま維持します**。外部の新しい報告は自己報告で期間も短く(X-10〜X-13・X-35)、ADR-0101 の却下の理由(自組織の測定が無い)を覆しません
2. **書き方は、起案委員の案と規格委員の案を合わせます**。次の 3 つを区別して書きます
   - **既定(初期値)**: 採用した時点では、すべての範囲が L1 です。根拠は「その範囲について自組織の実測がまだ無いこと」です(規格委員の案)。エージェントの能力の記述は、日付つきの前提(5.3)に残します
   - **上限**: リスク区分で決まります(5.4.4。R1=L1、R2=L2、R3=L3 は登録した種別だけ)。実績では緩和しません(HAB 107)
   - **落ち先**: 登録や引き上げの条件が欠けた変更・止めた種別は、L1(運用形態では協働)へ戻ります(起案委員の案。5.4.6 の停止と同じ)
3. **「人が触る場所」を 1 つの表にして 5.4 に置きます**。中身は既存の定めの索引で、新しい義務は足しません。表には次を並べます

4. **自律レベル L2 の読みを固定します**。「監視者」の列は、エージェントの実行の監視を指します。G-6 は、どのレベルでも第4章のとおり掛かります。G-6 の判定の時点を移すのは 5.5.4 だけです。L2 を G-6 の受け皿と読むと、5.5.4 と並ぶ 2 つ目の経路になります。ADR-0101 決定2 はこれを禁じています

**採らない案**: ベースラインを L2 以上へ上げる案(5 委員一致で不採用。X-08 は予測にすぎない)。R ごとの上限をそのまま既定にする案(現場委員)は、R2 を初日から L2 にすることになります。しかし L2 は G-6 を減らさないので、ボトルネックは解けません。しかも統合点の定義が無いまま、監視の水準だけが下がります。既定を置かずに採用者へ選ばせる案は、規格委員の言うとおり既定値と天井を失います。

### 論点2 委任と L2 の条件(仕分けの詳細は §3 の表)

**委員の集計**

- 委任の 7 条件を外すべきだとした委員はいません(5 対 0)
- 慣性を疑われたのは E0 の値です。3か月(EV-0147)、0件(EV-0154)、同時保有 3 件(EV-0011)、最小標本 30(EV-0145)。5 委員が一致しました
- 条件3・4・6 で機械が閉じない部分は、外さずに開示します(規格・品質監査・弁護の 3 委員)。結果の形で書き直す案(起案・現場の 2 委員)は、§3 で個別に裁きます

**議長が足す事実(会議体が見ていない、最も重い所見)**

会議体は「委任の実害はマージが既定で無効なこと」と見ました。議長が autonomy.mjs と本文を読むと、**マージを有効にしても、登録した種別が動き続けられない仕掛けが 2 つあります**。どちらも推定(コードの読み)で、実行では確かめていません。

- **A. 差し戻し率 0% による停止が、健全な機械的な種別に当たる**
  - 何が起きるか: 窓の変更が 30 件以上あり、判定基準を引いた差し戻しが 0 件だと、種別を止めます。戻すには登録の判定をやり直します
  - 所在: HAB 195・224-225、autonomy.mjs 405-415、IMPL-0285
  - なぜ当たるか: 母数は「種別の規則の範囲に入る変更」の全部です。ところが委任した後は、G-6 を判定するのは抜き取った k 件(当月全件と 5 件の少ないほう)だけになります
  - 結果: 委任に向くと標準が挙げる種別(TG 431。依存パッケージのパッチ更新・表示文言・スタイル)は、差し戻しが 0 件であることが健全な状態です。この種別ほど毎月止まり、**毎月の登録のし直しという、人の手作業が生まれます**
- **B. タスクの記録を持たない種別は、手戻り率を測れず止まり続ける**
  - 何が起きるか: 手戻り率の母数が 30 件に届かない間と、基準値が未設定の間は、種別を止めます
  - 所在: autonomy.mjs 冒頭 25-30 行、IMPL-0517・0291
  - なぜ当たるか: 母数はトレーラ(Spec: F-NNN / Task-N)を持つタスクです。依存の自動更新の PR は、ふつうこのトレーラを持ちません
  - 結果: 母数が 30 件に届かず、止まり続けます

さらに、標本 30 件が窓に揃うまでは「判定不能」として止まります(TG 343、IMPL-0286・0291)。月ごとの評価なので、早くても翌月の評価の日までは協働です。

**裁定**

1. **委任の 7 条件は、1 つも外しません**。値も変えません。外したときに起きる事象は、他の条件では受けられないからです(§3)
2. **A と B は、条文と実装の欠陥として、この束で直します**(ADR-0272)
   - 差し戻し率: 委任した種別では、母数を「G-6 を判定した変更(事前と事後の抜き取り)」にします
   - 手戻り率: タスクの記録を持たない変更の数え方を決めます。決め方の選択肢は §7 の O-3 に置きます
   
   これは新しい経路ではありません。5.4.6 の検知が、測るつもりの量(人の確認の形骸化)を測るように直すものです。ただし、直す前に実行で確かめます(fixture で、健全な種別を 3 か月流す)
3. **条件4 の「取り消しを実行した実績」の読みを固定します**。対象のリポジトリで、その種別の配布の経路を使い、取り消しを演習として実行した記録も、実績に数えます(現場委員の案)
   - 理由: この条件の目的は「戻せることの実証」です。実運用で事故が起きるのを待つ理由はありません
   - 閉じ方: 機械が確かめるのは記入の有無までで、いまと同じです(IMPL-0035)。内容は登録する者が判定します(manual。EV-0279)
4. 条件3 の後半(「既存のテストで検出できる」)は、**文を変えません**
   - 理由: 文はすでに結果の形です。登録の根拠の 3 点目に所在を書かせる仕組みも、すでにあります(HAB 597)
   - 現場委員の「過去にテストが失敗した実績」へ書き直す案は採りません。失敗が起きた種別ほど登録できることになり、誘因が逆になります
5. L2 の条件(5.4.5)の扱い
   - 条件1(3か月)は、既定値のまま残します。登録の経路(3か月を課さず、条件3・4 の実証で置き換える)との差の理由を本文に書きます(規格委員の案)。理由は、R2 の変更は取り消しに人手を要し、登録の経路のような取り消しの実証を持たないことです。件数と事象で書き直す案(起案・現場・品質監査の 3 委員)は採りません。ボトルネックは L2 にはありません(論点1 の裁定4)。測定の無いまま期間の要件を外す立証の責任は、外す側にあります(弁護委員)
   - 条件4 は、「AI 起因の Sev1・Sev2 が期間内に無い」へ書き直します。5.4.6 の 1 行目と同じ数え方にします(5 委員のうち 4 委員が重大度で書くことを支持し、弁護委員も拒んでいない)
   - 条件6 と条件7 は束ねません(起案委員の案は採らない)。条件6 は切り戻しの手順、条件7 は実行の単位ごとの強制の所在で、別の統制です(ADR-0170)

### 論点3 「作るのを止める」の前の手当て

**委員の集計**: 「止める」を床として残すことは、5 委員が一致しました。止める前の手当てを明文化することは、起案・現場・品質監査・弁護の 4 委員が賛成しました。規格委員は「順を入れ替えない」と述べましたが、手当てを前に置くことには反対していません。

**確かめた事実**

- GC 2601-2614: 制御1(同時保有の上限)と制御2(差し戻して生成を止める)。値は EV-0011(E0)です
- GC 2632-2636: 帯域が足りないときの手段の順は「分割の総量を減らす → 労力を下げる(レビューパッケージ。#464 は未実装)→ 人数を増やす」です
- **template の数え方(規格委員の要確認への答え)**
  - review-queue.mjs は、開いている draft でない PR の、未応答の指名をすべて数えます。委任の判定を見て除く分岐はありません(155-188 行。`delegation`・`Delegated` の語はファイルに無い)
  - template の CODEOWNERS は `* @OWNER` です。コードオーナーは、すべての PR へ自動で指名されます
  - したがって、**委任の範囲の PR も、同時保有数に数えられます**。マージが既定で無効の間は、委任の範囲の変更も協働として人の承認を待つので(delegation.yml 19 行)、数えるのは正しい扱いです
  - 有効にした後は、マージされるまでの間(G-5 が完了するまで)だけ数えられ、応答の催促(IMPL-0681)も当たりえます。推定(コードの読み)
  - 標準(GC 2606)の「判定待ちとして同時に抱える件数」は、G-6 を事後へ移した変更を数えるかどうかを書いていません

**裁定**

1. **「作るのを止める」は、床として残します**。止めずに積み上げると、形だけの承認が増えます(X-09・X-11)。その害は、止めることの害より大きいと判断します
2. **止める前の手当てを、既存の受け皿の中で、手段の順の前に 1 行足します**。「委任の登録(5.5.4)と、機械が導いた範囲での深さの配分(GC 1531 の要求事項2)を使える変更があるかを見直す」。新しい義務ではなく、既存の経路を指すだけです
3. **制御1 の数え方を明記します**。G-6 を事後へ移した変更(5.5.4)は、判定待ちに数えません。事後の抜き取りの負荷は、条件6 の件数(k)として別に表れます。template の review-queue.mjs では、該当の判定を「該当(G-6 を事後へ移す)」とした PR を、数える対象と催促の対象から除きます
4. **リスクの順に並べることは、手引きで勧めるにとどめます**(R1 と CL1 以上を先に読む。X-42)。確認の対象を減らさないので、H.4 条件4 には当たりません。要求事項にはしません。ラベルは template がすでに付けています(IMPL-0212)
5. 「機械の検査の強化で人の確認の対象を減らす」(Issue の候補)の答えは、§4 に書きます

## 4. H.4 条件4 の扱い

**裁定: 維持します。本文は変えません。ADR も足しません。**

- 事実: 条件4 は「AI の推定による判定を検出の層として数える条件」の 4 つ目です。決定論的な検査は、同じ表で「検証に数える」とされています(ADR-0056 60-70 行)。しかも ADR-0056 74 行は、「条件4 に委任の範囲という除外を置かない。委任で人の事前確認が無いのは、AI の通過によるのではなく、5.5.4 の 7 条件による」と、すでに明記しています。GC 1535 も「AI のレビューを通過したこと」と、範囲を限って書いています
- したがって、起案委員の言う「5.5.4 との衝突」はありません。層2 の案は、ADR-0056 にすでに書かれています。品質監査委員の言う「本文の誤読」も、本文の側ではなく、chair-notes の初めの版と Issue の言い換えの側にありました(chair-notes の訂正の節で直し済み)
- 規格委員が提案した、条件4 の範囲を補う ADR は採りません。補う中身が、ADR-0056 74 行と GC 1535 にすでにあるからです。同じことを 2 か所に書くと、片方だけが改められて食い違う危険が増えます
- **Issue の候補「機械の検査の強化で人の確認の対象を減らす」への答え**
  - 決定論的な検査で減らせるのは、次の 2 つに限ります
    - 逐行に読む深さの配分(GC 1531 の要求事項2。すでに許されている)
    - 委任の条件3 を通じた、判定の時点の移動(5.5.4)
  - 確認の範囲(パス1 で見る差分の全体)は、狭めません(ADR-0101)
  - AI の判定の通過を理由にすることは、どの経路でも許しません(5 委員一致)
  - 「人が触る場所」の表(論点1 の裁定3)に、この対応を 1 行で載せます

## 7. 所有者にしか決められない点
