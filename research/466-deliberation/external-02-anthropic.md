# #466 外部の調査(追加): Anthropic の公開の実務

確かめた日: 2026-11-27。取得は WebFetch(本文を取得して要約させる道具)による。逐語の引用は取得結果の中の引用符つきの箇所で、「要約」と付けたものは逐語でない。出典の下書きは `sources-draft/NEW-A01〜A15.yaml`(A-NN と対応。番号は push の直前に付け直す)。

## 0. 結論の先出し(事実のみ。判断は会議体)

- **Anthropic の公開の実務は、2 つに割れる**。(i) AI のレビューを検出の層に置き、承認は人に残す実務(Code Review・SDLC の手引き)。(ii) **AI のレビューの通過(`claude/code_review = pass`)を条件に、必要な人数を 2 人から 1 人へ下げ、Claude が承認する**方針(Claude Approvals の既定の例)。(ii) は H.4 条件4 と正面から当たる
- 一方、同じドキュメントが**分類器の答え(AI の推定)に依る軽減は、PR の本文で誘導されうる**と警告し、重要なパスには「分類器を読まない規則で、著者以外の人 1 人」を勧める(A13・A14)。軽減の道具を提供しつつ、その危険を自ら開示している
- 「リスクの段で人の承認を変える」は、公開の仕組みでは**パス(決定可能)・変更行数・作成者・対象ブランチ**という決定可能な条件と、**分類器の AI 評価(リスクが low など)**の両方で書ける。後者は推定である。ウェビナー(A-03)は「作成者でなく変更で段を決める」とだけ書き、段の中身は取得できなかった
- 数値の大半は Anthropic の自己報告で、方法の記載が薄い。独立の実測は取得できなかった(未確認)

### A-10 〜 A-14 Claude Approvals(ドキュメント一式。公開ベータ)

- (e) **自ら開示する危険**(A-13・A-14): 「`A run reads text that the pull request's author wrote, and that text can try to steer the classifier's answer.`」。条件が分類器の答えを読む規則は、PR の文で必要人数を下げられうる。**重要なパスは、分類器を読まない規則で「著者以外の人 1 人」を求めよ**。著者が席を埋める `seats: 1`、`seats: 0`、機械ユーザー、bot を許す一覧、`reuse` は、人の確認なしの併合になりうる、と一覧する。Claude の承認が GitHub の必要承認 1 件を満たしうる点も警告
- (f) **観察モード**: 方針は `mode: observe` で始め、チェックの表示が人の判断と合ってから強制へ移す。観察モードでは Claude は承認せず、チェックは通過扱い。観察も課金される
- 読み分け: 人数を下げる条件は 2 種が併存する。決定可能な条件(パス・行数・作成者)と、AI の推定(`claude/code_review`、`repo/change_risk`)。**AI の推定を条件にする設計は仕様上ある**。ただし、それが誘導されうる、と同じ文書が述べる

## 3. 論点への含意(支える証拠と、支えない・逆の証拠)

### 論点 (1) R2 の人の確認を事後へ移す
- 支える: 分類器やパスで人数を段にする仕様が公開されている(A-10〜A-13)。Intercom の 19% 自動承認で停止が減ったとの報告(A-04。自己・外部の報告で方法不明)。観察モードという移行の型がある(A-12)
- 支えない・逆: **「事後」へ移す(併合の後に人が見る)実務は、取得した範囲に見つからなかった**。公開の実務の軽減は、併合の**前**に人数を下げる形で、事後の確認ではない(未確認)。A-04 は自動承認の**事後の抽出検査**(リスク重みづけ)を人の役割に置くが、事後の確認で人の事前確認を置き換える記述ではない。人が止めた事例(A-04)、AI の誘導の危険(A-13・A-14)、保護された範囲の固定(A-11)は、移す範囲を限る側の証拠
- 条件の型として使える: 観察モード(強制の前に、機械の判定と人の判断の一致を見る)(A-12)。「人 0 人」を許す設計は警告つきで、既定には置かれていない(A-10 の既定の例は 1 人以上)

### 論点 (2) H.4 条件4 の扱い
- 条件4 を支える: 同じ Anthropic が、AI の通過に依る軽減は PR の文で誘導されうると書く(A-13・A-14)。検証エージェントは近道をする(A-05)。テストが通っても人のレビューが要る(A-07。古い)。人の関門が障害対応エージェントを止めた(A-04)。コード中の指示で変えられない基準を置く(A-01 の REVIEW.md)
- 条件4 に逆: Anthropic 自身の既定の例が、AI の通過で 2 人→1 人にする(A-12)。ただし、既定は観察モードで始まり、強制するかは採用側が決める。実績の数値(見逃しの率、軽減の下での障害率)は公開されていない(未確認)
- 区別の手がかり: 軽減が「決定可能な条件」に依るか、「AI の評価」に依るか。A-14 は後者を重要なパスで使わないよう勧める

### #464(人へ渡す情報を絞る・順位づける・まとめる)
