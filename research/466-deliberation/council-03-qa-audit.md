## 1. 論点ごとの見解

### 論点1 ベースライン L1 は妥当か

- **説明に耐えるのは「全件の事前承認」ではなく「承認が実際に働いた証拠」である**。監査人は承認の有無でなく、承認が内容を見た証跡(挙動要約・差し戻し・所要時間)を問う。形だけの承認(Rootly: merged 3,661 件の 24.4% が 500 行/時より速い承認。単一組織の自己報告。Claude Code: 人の阻止率 17% → 5%。ベンダの対照実験)は「統制が働いていた証拠」にならない。**全件の事前承認が件数の増加で形骸化するなら、監査の立場では、その既定は説明の資産でなく負債になる**
- ただし、緩める側の実測は弱い。Rootly はシャドー未開始、Ona は欠陥率の報告なし、Rewind は 1 週間・revert 0(いずれも自己報告・短期。X-35)。**事故の実測も無い。どちらにも決定的な証拠が無い**。この状態で既定を動かす理由は、緩和の安全でなく「全件の既定は形骸化が実測されている」ことだけである
- 私の見解: **L1 は「実績が無い範囲の出発点」としては残す。変えるべきは、L1 が永続の既定になっている構造である**。内部調査のとおり、template は登録した種別以外すべて L1(autonomy.mjs)、委任のマージ実行は undelivered(IMPL-0026・0235)、窓の標本 30 に届かない小規模は常に止まる(推定)。つまり標準が本筋と指定した通路(5.5.4・L2)が、実装では通れない。**問題は出発点でなく、出発点から出る道が閉じていること**
- ベースラインの文(HAB 70)は、根拠水準マークも ADR も無い。監査人が最初に突くのはここである。**E0 のマークを付けて開示する**(採用者への新しい義務ではない)。5.4.8 の再評価期限(2027-08-05)を待たず、今回の審議の結果を書く
- 既定を L2 以上へ上げる案は採らない(§6)。R の上限は実績で緩和しない(HAB 107)、R2 を委任へ上げる根拠にしない(EV-0040 差し替え条件)と既に決まっている

### 論点2 委任と L2 の条件の仕分け

- 結論の骨子: 委任の 7 条件は、**すべて「外したとき説明できなくなること」を持つ**。慣性と言えるものは見当たらない。ただし、**手続きでなく結果で書き直せるもの**(条件3・4・6)と、**機械で閉じないのに閉じたように読めるもの**(条件3 の「検出できる」、条件4 の「実績」)がある。後者は条件を足さず、根拠水準で開示する(既に EV-0040 E1 / EV-0279 E0)
- L2 の条件(5.4.5)に慣性の疑いが集まる。**条件1(連続 3 か月)は E0 で、登録の経路では既に課されない(5.5.4 条件3・4 で置換済み)**。標本の足りなさは条件2・3 の窓(2 か月・最小標本 30)が受けるので、期間は重複する。結果(標本の件数)で書き直せる。条件7(停止手段の所在)は有効性を確かめず、記入の有無だけを見る。**監査の立場では「所在の記入」は統制の証拠でなく、統制の所在の表示である**。開示で「確かめていない」と書き続ける限り、残してよい
- 詳細は §2 の表

### 論点3 「作るのを止める」の前に置ける手当て

- 監査の立場では、**「止める」は最も説明しやすい統制である**。承認の山が無ければ、形だけの承認は生まれない。代償は速さだけで、信頼性は損なわない。したがって「最後の手段」に下げることはよいが、**手当てが効かないときに必ず働く床として残す**。止めずに積み続けて形だけの承認に落とす選択肢が、監査上は最悪である(Rootly の無言の承認、Claude Code の阻止率の低下)
- 止める前に置ける手当ての順(監査の立場から、確認の対象を減らさずに負荷を下げるものを先にする)
  1. **リスク順の並べ替え**(R1・CL1 以上を先に読む。X-42)。確認の対象は減らさない。説明の資産が増える
  2. **分割の総量・規模の上限・レビューパッケージ**(GC 2632〜2636 の順。#464 は未実装・未測定。効果を断定しない)
  3. **5.5.4 の通路を実際に通れるようにする**(#361 の実機確認、窓の標本の扱い)。R3 の定型変更だけは事後へ移る。これは既存の経路の中で書ける(ADR-0101 決定2 に反しない)
  4. **確認の対象の縮小は、検査の強化でなく影響範囲の縮小で行う**(実行環境の隔離・権限の限定。Stripe の devbox は自社の主張、PocketOS は二次報道で、いずれも逸話以上に使わない)。R の定義(取り消しが自動化された手段で完結・影響が組織内)に当たる範囲が広がるだけで、人の確認の条件は変えない
  5. 人を増やす・代理を指名する(SLA の既存の定め)
- 「機械の検査の強化で人の確認の対象を減らす」は、§3 のとおり、AI の推定には当てはめない。決定論的な検査は、5.5.4 条件3 の中で既に事後移行の条件になっている

## 3. H.4 条件4 の扱い — 維持する

**文言を確かめた**(assurance-case.md 392〜411 行)。条件4「通過を理由に人の確認を減らさない」は、**「AI の推定による判定を検出の層として数える」ための 5 条件の 1 つ**である。決定論的な検査(AI が書いたテストの実行・静的解析・変異試験)は別の行で「検証に数える」と書かれている。つまり、条件4 は**機械の検査一般**でなく、**AI の推定**の通過を理由にした削減を禁じている。議長の覚えは「機械の検査の通過を理由に」と広く書くが、範囲は既に限られている。

- **AI の推定には維持する**。理由は三つ
  1. 誤りが相関する。文脈を切り離した再レビューが注入欠陥の約 73% を見逃した(FND-0079。単著・単一モデル)。Rootly の過去検査では、人が指摘した 19 件のうち AI が完全に指摘したのは 1 件、見落とし 3 件(うち 2 件は移行・認証。提案段階の自己報告)
  2. 検出率を測っている組織が少ない。ADR-0101 は「自組織の測定が無い」を理由に、検出率を前提にした人の確認の配分を却下した。**外部の新しい実測は自己報告・短期で、この理由を覆さない**
  3. 事故後の説明が壊れる。「AI が通したので人は見なかった」は、職務分離でも独立の確認でもない(H.4 の 754 行 「数えない: AI と bot のアカウントの承認」)
- **決定論的な検査には、既に別の場所で受けている**。5.5.4 条件3(G-5 通過 + 既存のテストで検出できる)が、R3 の定型変更の事前確認を事後へ移す根拠である。ここは条件4 と矛盾しない。**追加の経路は要らない**
- **範囲を限る・置き換えるは採らない**。限る必要が無い(既に AI の推定に限る)。置き換えるなら「検出率が一定以上なら減らしてよい」になるが、測定を前提にする経路は 5.5.4 の外の第 2 の経路になる(ADR-0101 決定2)
- 議長へ: 条件4 の趣旨が誤読されて「機械の検査の強化は人の確認を減らせない」と読まれている。**編集の指摘**(文言の食い違い)として、決定論的な検査との区別を一文で明示する程度の直しを提案する。意味は変えない

## 4. 既定を動かす場合の、監査の立場の下限

既存の定めを引く。**新しい義務は足さない**

| 下限 | 所在 | 外せない理由 |
| --- | --- | --- |
| 職務分離: 作成を指示した者が自分の変更を承認しない。AI・bot の承認は数えない | GC 1395〜1402 の基準4、H.4(754 行)、HAB 602 | 内部統制の最小の要素。SOX の IT 全般統制の実務も同じ(X-20。二次) |
| R1・CL1 以上・規制業は、人の事前の確認 | HAB 5.4.4(R1→L1)、委任条件1(IMPL-0596)、不変条件(HAB 76〜81) | 取り消せない・危害がありうる範囲を、事後で説明することはできない |
| 事後の抜き取りの実施と記録。月次、当月全件と 5 件の少ないほう。実施者が作成者と同一なら独立は不成立と開示 | HAB 5.5.4 条件6、TG 286・446、IMPL-0597 | 事前を外した代償。抜き取りが無い期間は「統制が無かった期間」 |

| 根拠水準の開示(E0 を E0 と書く) | ADR-0026 | 「確かめていないこと」を隠さない。L1 のベースライン文へ付ける |

## 5. 最大の危険と、起きたとき誰が何を失うか

- **最大の危険**: 事前の承認を事後の抜き取りへ移したとき、**形だけの承認が事後の抜き取りへ移るだけで終わること**。R3 は自己記載で通りうるので、R1 相当の変更が R3 と書かれ、母集団に入らない(選び方が恣意で当該変更が抜き取りに当たらない)、k が不足したまま月が過ぎる、という複合が起きる。事故後に「抜き取りは実施していた」としか言えず、当該の変更が事前にも事後にも人の目に触れていなかったと分かる
- 誰が何を失うか
  - **独立レビュアの席の責任者(人)**: 結果責任は人に残る(不変条件1)。事後に見たはずの変更を見ていなかった責任を負う
  - **出荷判定者・事業決裁者**: 期間の開示への受容の記名(G-8)が、実態と食い違う開示の記名になる
  - **採用組織**: 監査人に「統制が働いていた」と示せず、内部統制の不備になる。顧客・規制当局への説明の信用を失う
  - **標準**: 委任が undelivered のまま「本筋」と書く表示と実態の食い違い。独立の突合の「高」に当たる
- 逆向きの危険もある。**全件の事前承認を既定のまま据え置くこと**。形骸化(24.4%・阻止率 5%)が起きても監査人には「承認はあった」としか言えず、承認が働いていなかったことが事故で露見する。どちらも信頼性を落とす。**事後の抜き取りは、既定が動かない小さな範囲でだけ、k と実績の記録つきで通す**のが、説明に耐える最小の動きである

## 6. 採らない案

- **ベースラインを L2 以上へ引き上げる**: 根拠が E0。「2026-11 のエージェントは賢い」は予測であって実測でない(X-08・X-36)。受付の「採らないこと」に当たる
- **AI の推定の通過を理由に人の確認を減らす(H.4 条件4 の置換)**: 誤りの相関(X-38)と、検出率の自組織の測定の欠如(ADR-0101)のため
- **検出率の閾値つきの緩和**: 測定を前提にした 5.5.4 の外の経路になる(ADR-0101 決定2)。再審の条件は、複数の採用組織の運用の測定が揃うこと
- **R2 を実績で委任へ上げる**: EV-0040 の差し替え条件が明示している。実績の薄い範囲では上限を動かさない
- **CL0 の条件を外す、または規制業を委任から外す条件を緩める**: 独立の根拠は未確認だが、外す根拠はもっと無い。規制の下限は独立した検証である(X-30)
- **論点の外の差分を事後の抜き取りへ回す**: ADR-0101 が 5 委員一致で却下した(#172 の棄却と同形)
- **抜き取りの率を標準が固定値で課す**: 率を支える測定が無い(EV-0342)。標準は「記録が残ること」と「不足の期間を開示すること」までを課す
- **Rootly・Ona・Rewind・Meta RADAR の自己報告の値を、条件の値として取り込む**: 短期・自己報告・対照なし。Vercel の 58% は頁が取得できず未確認なので、根拠に使わない
- **「作るのを止める」を廃止して待ち行列へ積む**: 形だけの承認を増やす。説明の最悪の形
