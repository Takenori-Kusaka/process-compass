## 1. 論点ごとの弁護と、譲る点

### 論点1 ベースライン L1

**弁護する点**
- (a) 外部の新しい証拠は覆す力に欠ける。X-10〜X-13 は自社の自己報告で、観察は1週間〜数か月(Rewind 1 週間、Rootly はシャドー未開始、Ona は欠陥率の報告なし。X-35)。ADR-0101 の却下の理由「条件4 を外すに足る自組織の測定が無い」は、2026-11-27 時点でも立っている
- (b) 既定は最も弱い採用者に合わせる。採用者には CL1 以上・規制業が入る。弱い側へ既定を置いて強い側が上げる(5.4.5 は申請と判定で上がる)形は、規格の役割に合う。逆(L2 を既定にして弱い側が下げる)では、下げ忘れが事故になる
- (d) 悪化の観測は一貫して存在する。Faros の PR あたりインシデント 3 倍(X-02)、DORA 2025 の安定性との負の関係(X-03)。いずれも「確認の有無」との関係は測られていない相関だが、「確認を減らせば良くなる」側の測定はもっと無い
- DORA(X-18)が外すのは「外部の形式的な承認」で、ピアレビューは残す。L1 の「人が全て確認」は G-6 の独立レビュア(ピアレビュー)であり、CAB ではない。DORA は L1 の反証にならない
- 期限: HAB 379-385 の再評価は 2027-08-05。外部の測定が出揃う前に、その前倒しで原則を動かす理由は薄い

**譲る点(根拠は強まる)**
- **L1 の既定の文(HAB 70)に ADR も根拠水準マークも無い**(internal.md 0-2)。E0 を E0 と開示していない。ADR-0026 に反する。弁護できない。少なくとも「根拠水準 E0・見直し期限」のマークを付ける(L1 を維持する場合でも)
- 「2026-08-05 時点のベースライン」という書き方が、L1 を決定でなく観測のように読ませる。決定として書き直すこと自体は拒まない
- 人のレビューの形骸化は実測がある(X-09: 阻止率 17%→5%。X-11: 無言の承認 24.4%)。「全部を見る」と「効いている」は別、という指摘は正しい。ただしこれは**承認を外す根拠でなく、件数と変更の大きさを減らす根拠**(後述 (e))
- template は L2 を支えず、登録しない種別は全部 L1(autonomy.mjs)。標準が「R2→L2」と書き、実装が通れないのは不整合。**標準の側を直す(template の現実に合わせて文を限る)か、template を直すかは、会議体が決める**。弁護はどちらも妨げない

### 論点2 委任と L2 の条件

- 弁護の骨子: 委任の7条件は ADR-0054 決定4 の一体の設計で、EV-0040(E1)が全体を支える。「条件の緩いほうだけが使われる」(ADR-0054 120 行、ADR-0101 93 行)は、**条件を1つずつ外すことにも当たる**。条件を束から外すと、残りが形の上で満たされたまま、外した条件が受けていた事象が素通りする
- 譲る点: E0 で、経緯も見つからず、機械が閉じない条件は、E0 のまま「慣性」の疑いを拒めない。下表で個別に示す
- CL0 かつ R3 の絞りが Meta・Rewind・Ona より狭い、との指摘(external.md 論点2)は、**半分は正しい**。ただし先例は全て、認証・認可・移行・依存・インフラ・課金を常に人に残す(X-11〜X-13)。この標準も R1 を人確定に残す。広い(RADAR は下位 5〜50%)側は、**ベンダが自社の測定(33.1 万件)で運用する組織**の話で、採用者一般の既定にならない。ADR-0054 EV-0040 の差し替え条件「R2 の上限を委任へ上げる根拠にしない」は維持する

### 論点3 「作るのを止める」の前の手当て

- (c) 制御2 はリーン・カンバンの WIP 制限(GC 2614)。確認されない変更の在庫は、時間とともに陳腐化(基底の変化・再 rebase)し、未確認のまま積み上がる。止めることは**信頼性のために流れを守る**手段である。X-09・X-32 は、確認待ちが長いほど承認が形骸化すると示す。止めなければ、形骸化した承認が増える
- 外部の先例が無い(X-43)ことは、廃止の根拠にならない。先例が無いことと、有害であることは別
- 譲る点: (1) 制御2 は「最後の手段」でなく手段の順の(1)に置かれ(internal.md 3)、(2) の#464 は未実装(template に IMPL なし)。**手当ての順が、実装できていない手当て(レビューパッケージ)を前提にしている**。(2) が無い間、止める以外の手当てが機能しない。この点は Issue の指摘が正しい。弁護の側は「止める」を外さず、**止める前の手当てを標準の側で先に明文化すること**には賛成する
- (3) template の「作るのを止める」は通知のみ(IMPL-0682)で、実機未確認。標準が書く止めは、実装では止まっていない。**標準の記述と実装の差を、根拠水準マークと undelivered で開示すること**が先で、条文を弱める理由ではない
- 制御1 の既定 3 件(EV-0011)は E0。値は自組織の測定へ差し替える条件が既に書かれている。弁護しない(値は動かしてよい)。値を動かしても、**止めるという構造**は維持する

## 3. H.4 条件4 の扱い: **維持する。ただし何を禁じているかを正確に書き直す(範囲の明確化)**

**事実の確認(議長の覚えの訂正を含む)**: ADR-0056 のH.4 条件4 の文脈(62-74 行)は、「**AI の推定による判定**(AI レビュー、AI による受入基準の充足判定)を検出の層として数える条件」の5つのうちの4つ目である。同じ表で、**決定論的な検査(AI が書いたテストの実行、静的解析、変異試験)は「検証に数える」**とされ、条件4 の対象ではない。つまり条件4 が禁じているのは「**AI レビューの通過を理由に人の確認を減らすこと**」であり、**「機械の検査の通過」一般ではない**。chair-notes.md と Issue の論点3 は、この2つを一括りにしている。

- 維持する理由(a)(d): ADR-0101 106 行の却下の理由(自組織の測定が無い)が立つ。LLM 間の誤りの相関と、文脈を切り離した再レビューの見逃し(X-38。単一の研究だが一次の実測)。作成者自身の AI が通過させたことで人の確認を減らす経路は、5.5.4 の7条件(判定の時点を移す)以外では**H.4 が閉じた**。除外を置かないと明記したのも、条件の緩い別経路を作らないためである(ADR-0056 74 行)
- 範囲を限ることは**拒まない**。決定論的な検査(G-5)と実行可能な保証は、すでに「検証に数える」であり、担保水準 L1・L2(GC 2254-2262)と「深さの配分」(GC 1524-1541: 根拠が機械の導出か実行可能な保証である場合)がその受け皿である。**これは条件4 の例外ではなく、条件4 の本来の射程の外**。この読みを条文に明示するのは編集の指摘(意味を変えない)に近い
- 置き換えは弁護できない形で拒む: 「AI の検出率を前提に人の確認を配分する」は、ADR-0101 が5委員一致で採らないと決めた。置き換える案は、まず自組織の測定(欠陥注入の検出率の値の開示。条件1)を満たす経路を作ってからである。Rewind・Rootly のシャドー段階(X-11・X-13)は、その測定を先に置く型で、条件1 と整合する

## 4. 引き上げ・緩和の案に付ける歯止め(譲る場合)

案が通るなら、次を条件にする。いずれも既存の定めを引く

1. **受け皿は 5.5.4 と L2 の内側**(ADR-0101 決定2。「条件の緩い別経路を置かない」HAB 565)。新しい経路・新しい登録を作らない(ADR-0054 の登録の統一 102 行)
2. **R1 の人確定と上限は変えない**。「この上限は実績によって緩和されません」(HAB 107、HAB 537)と、EV-0040 の差し替え条件(R2 の上限を委任へ上げる根拠にしない)
3. **緩める規則の追加・範囲の拡大は統制の弱化**(ADR-0054 213 行、ADR-0038 決定1)。規則は基底ブランチから読み(ADR-0115)、2つの記名を要する(215 行)。AI の名義の記名は受け付けない(208 行)
4. **値を緩めるときは根拠水準マークで開示**(ADR-0026)。E0 の値を別の E0 で置き換えない。置き換える値は「組織が G-1 で定め、自組織の観測で見直す」と書き、標準が数を決めない
5. **決定可能な条件だけを機械にする**(受付の裁定)。自由な文の意味(「既存のテストで検出できる」「抜き取りの中身」)は manual か adopter で、根拠水準を開示する
6. **引き下げは自動を保つ**(5.4.6、HAB 188。EV-0154・0155 の見直し 2027-10 まで)。緩めるほど引き下げの検知を強める
7. **実装が通れないものを本筋と書かない**。template で undelivered の経路(IMPL-0026・0235・1013)は、標準の本文で「実環境で未確認」を維持する(ADR-0028 決定7: 委任は未達を解消しない)
8. **承認の比率・自動承認の比率を検知条件にしない**(ADR-0059)
9. 外部の証拠は一次の実測だけを根拠水準の根拠にする。X-04・X-15・X-34・X-41 などの要約のみ・未確認は根拠にしない

## 5. 最後まで弁護する点と、その理由

1. **R1・R2 の人確定・協働の上限と、委任の CL0 条件**。失うのは、CL1 以上や規制業の採用者(人身・財産)と、その利用者である。委任の事後確認は、取り消せない被害には間に合わない。EV-0040 は「線の位置の測定が無い」を認めており、**測定が無いまま線を動かす側に立証責任がある**
2. **委任の条件4(取り消せる)と条件6(事後の抜き取り+自動引き下げ)**。外すと委任は「承認の廃止」になり、判定の時点を移す条件(ADR-0054 88 行)が空になる。失うのは、後から事故が出たときの追跡と、引き下げの発火の機会である
3. **H.4 条件4 の本体(AI の推定による判定を、承認に数えない)**。失うのは、作成した AI と同じ盲点を持つ AI の通過で、人の確認が減る組織。LLM 間の誤りの相関(X-38)があり、独立性の設計は条件1・2・3 が担っている
4. **作るのを止める構造**。失うのは確認する人と、確認を待つ変更の鮮度。止めなければ確認の質が下がる(X-09・X-32)。流れを速く見せて、形だけの承認で積み残す設計になる
5. **既定が最も弱い採用者を守る側にあること**。「安全重要度の高い製品の採用者が、既定のまま読んで安全な側にいる」ことに価値がある。強い採用者は5.4.5・5.5.4 で上げられる

## 6. internal.md・external.md・Issue・議長の覚えの事実の誤り

- **chair-notes.md・Issue の論点3「機械の検査の通過を理由に人の確認を減らさない」(H.4 条件4)は言い過ぎ**。ADR-0056 の本文は「AI の推定による判定」を検出の層として数える条件の1つ。決定論的な検査は同じ表で「検証に数える」(ADR-0056 62-70 行)。したがって「機械の検査の強化で人の確認の対象を減らす」(Issue の候補)が条件4 と**正面から当たる**とは限らない。当たるのは AI レビューの通過を根拠にする案。ただし GC 1524-1541 の「根拠が機械の導出か実行可能な保証である場合に限る」は残るので、決定論的な検査で減らせる範囲は既に定められた範囲(深さの配分)にとどまる
- internal.md 8 の表で、委任5・7 を「できる(機械が検出)」とするのは template の判定であり、R3 の自己記載(委任2)の穴(下限規則の網羅性は未検証。internal.md 9-6)が、委任全体の機械の閉じ方の弱点である。表の「できる」は条件単独の話で、全体の自己記載の穴を同時に読むこと
