### 1.2 「作るのを止める」の扱い(§6): 条件つき賛成

- P の線引き(手を止めない/取り込みは止める)は、GC 2622「帯域を理由に判定を省略しない」と整合する。**所有者の理由は「人と AI のリソースを待たせない」であり、取り込みを緩めることまでは言っていない**。分けた読みは所有者の決定を覆さない
- 規格としての書き方: 「判定依頼を積み増さない」の文は、**満たすべき結果**(上限を超えた判定待ちを作らない/作成側が手待ちにならない)を要求にし、**手段**(何を代わりにやるか、順序)は手引きへ置く。P §6 の 2・3 は手引き。1 は要求
- 条件: 「上限に達した間に、G-6 を要しない作業へ回る」を要求の文に書くと、R1・R2 を担当する者が R3 だけに偏る誘因になる(X-09・X-11 の形だけの承認)。**要求にするのは「積み増さない」だけ**にし、回る先は手引きにとどめる
- 取り込みの床(R1・R2・コア機能は確認者が空くまで取り込まない)は動かさない。規格として、ここを緩めると「速さのために判定を飛ばさない」(GC 2622)が崩れる

### 1.3 既定値を置かない扱い(§7): 条件つき賛成。P の選択肢より既存の型で書く

- **規格の書き方は既にある**。第1章 1.7.7 の型「組織が定める値」は「記録が無いとき: 当該の基準を満たさない。参考の値は効かない」と書く。O-5(b) はこの型への移し替えで足りる。(i)〜(iv) の新しい仕組みを足さずに済む(足さずに済ませられないかの先の検討)
- ADR-0081 決定4(第4章 要求事項1 が値・観測の窓・最小標本数・決め方・次の見直しの時期の 5 つを G-1 の記録に求める)も、既にある。**未設定の受け皿は、新しい欄ではなく要求事項1**
- 未設定のときの振る舞い: 1.7.7 の型の「基準を満たさない」を、O-2 の決定(止めず、当月の全件を事後に確かめる)で受ける。**P の (iv) は新しい案ではなく、O-2 と 1.7.7 の組合せの帰結として書く**。標準が既定の挙動を持つことになるのではないか(P §9-3)に対しては、「挙動の既定」と「値の既定」は別で、後者だけを置かないと答える。ただし 1.7.7 の第2文型(置き換えずに用いても統制を弱めない値は既定値としてよい)の読みを改めるかどうかを裁定で明記する。V4・V7 は「置き換えずに用いても統制を弱めない」とは言えない根拠(E0)なので、型の移動は 1.7.7 の文と矛盾しない
- **規格上の最大の穴**: 最小標本数(V7)の既定値を外すと、ADR-0081 決定5 の「最小標本数を下げてはならない」と「偶然の変動で発火が決まる」の根拠が、数の無い禁止になる。採用者が 1 件と決めれば、判定不能は消え、検知は偶然に依る。**数の下限は既定値と同じ働きをする**ので置かない(O-5 に従う)。代わりに、要求事項1 の「決め方」に、標本数の根拠を書かせ、保証の開示に「採用者が決めた最小標本数」をそのまま出す。manual として開示し、根拠水準マークを付ける
- **V2・V3(引き下げ側)**: **(b) を推す**。V2・V3 は統計の閾値ではなく規則である(DI V2。ADR-0081 決定4 の「重大度による規則であって統計の閾値でない」)。規則を採用者が決める値にすると、「2 件までは下げない」が書けて安全に触れる。EV-0154 の根拠は規則の根拠へ書き直す(EV の識別子は再利用しない)。V4 は対象に含める(窓の長さ。長くする向きだけ許す構成が既にある)。P の推奨と同じ。ただし、これは所有者の決定文の解釈なので、裁定の案を ask で上げるときに明示する
- 1.7.7 の「参考の値」(示す値は効かない)を、V1・V7・V8・V9 に置くかは、所有者の「既定値を置かない」を広く読むなら置かない。置くと template が値を読んで既定として使い、効く(DI §5 の注意)。**置かない**

### 1.4 置き換えの記録の置き場(§8): 案4 を推すが、形を改める

- **事実**: index.md ルール3 の語彙は「一部置き換え(→ ADR-MMM の決定 n)」で、後継は ADR 番号を要する。ルール4 は「決定を変えるときは新しい ADR で置き換える」と定め、状態の節だけ書き換えを許す。ルール5 は両側が互いを指すことを求める。所有者の「新しい ADR を起こさない」は、ルール3・4 の文面と直接ぶつかる
- ADR の範囲を別の Issue で審議するなら、**その結論までの間は、ルールの文面を黙って破らず、暫定の例外として明示する**のが規格の運用として最も辿りやすい。P の案4 と同じ向き
- **改める点**:
  1. 例外の文は index.md のルール3 の直下に 1 文。「ADR の範囲の審議(#NNN)の結論までの間、新しい ADR を起こさない改廃は、状態の節に『一部置き換え(→ Issue #466 の裁定 n)』と書き、裁定の記録の所在を併記してよい」。**#NNN と終期(その Issue の結論の日)を併記**する。番号の無い暫定は恒久になる
  2. 置き換えの対象は、**ADR-0158 だけでなく ADR-0081 決定5 と ADR-0158 決定1・2**(O-2)、**ADR-0081 決定4 の「2か月」の既定値**(V4。O-5)、ADR-0129 の関連の決定(O-3 の分子の数え方。確認が要る)に及ぶ。ADR-0158 は決定3(母数に数える)・決定4 の手段の 4 つのうち「基準値の記録」・決定5(4点目)を**維持する**ので、置き換えは決定ごとに書く(「一部」の語で足りる)
  3. **ADR-0158 と ADR-0081 の採らなかった案・課さないと決めたことの行も、取り下げる行を明示する**。事実: ADR-0158 は「移行の猶予(一定期間は止めない)」「手戻り率の判定不能・基準値の未設定で止めない」を採らなかった案に載せ、ADR-0081 は「判定不能の窓を…自動では下げないとする扱い」を課さないと決めた。O-2(b) はこれらの行の**却下を覆す**。置き換えの記録が決定の行だけを指すと、却下表が現行の決定と読み違えられる。「却下を覆した行」を裁定の記録に表で列挙し、ADR 側の状態の節からその表を指す
  4. ADR は本文を書き換えない。状態の節の書き方は、ADR-0112 の状態の節(「次の決定を補います」と表で関係を示す)の前例がある
  5. 研究の記録は GitHub Pages に公開されない。**状態の節の指す先は、コミットを固定した GitHub の URL**とする。リポジトリ内の相対パスだけだと読み手が辿れない
  6. 裁定の記録の側に、置き換えた決定の番号(ADR-0158 決定 n)を書き、ルール5 の「互いを指す」を保つ
- 検査: `check-adr-links.mjs` は状態の行の「置き換え(→ ADR-N)」の順方向だけを検査する(P §8 の読み)。暫定の例外の形は番号を含まないので検査をすり抜ける。**所在の存在の検査(裁定の記録のファイルの実在)は、決定可能な条件なので足してよい**。ただし新しい検査は「足す」に当たる。足さなければ置き換えの記録は manual と開示し、終期の Issue で拾う。私は、終期の Issue の本文に「暫定の置き換え一覧」を置くことで足さずに済ませるのを推す

## 3. 規格委員から見た最大の危険

- **危険**: 暫定の例外と置き換えの記録が終期なしに残り、ADR を読んだ人が ADR-0158・0081 の古い決定を現行と読む。または、却下表の「採らなかった案」が現行の決定の裏返しとして残り、取り下げた行が「課さないと決めた」と読まれる(ADR-0028 の「課さないと決めた」と「書かれていない」の区別が崩れる)
- **起きたとき**: 標準を引いて開発する採用者が、止まるはずの種別の停止を見て、標準の食い違いと判断する。内部監査者が、却下表を根拠に是正を求める。失うのは標準の自己整合への信頼で、1 件の食い違いが「他の ADR も当てにならない」へ広がる
- 第2の危険: 最小標本数の既定値を外した結果、採用者が小さい値を置き、判定不能が消えて L3 が偶然の変動で動く。失うのは委任の担保で、採用者の運用の事故を標準が防げなかったことになる。1.3 の「決め方の記録+開示」で受けるが、manual の限界は残る

## 4. 採らない案と理由

- 案B: 効く升が無いか(S0・S1)、効く升が既存の禁止(ADR-0101 決定2・却下表、GC 2628)に当たる。ADR-0112 決定2 を主な理由にしない(1.1.1)
- 案C: 5.4.5・ADR-0081 決定6・第8章の非対称(緩める向きは判定と記録)に当たる。ADR-0030 は類推の引用
- 案D・E: 1.1.1
- 新しい ADR の起票: 所有者の決定。ただし暫定の例外には終期を付ける(1.4)
- P の (iii)(template に例の値を置く): template の値が効くので既定値と同じ。(i)(必ず決めさせる): /process-init の質問が増える。V7・V9・V4 は O-4 の対話の中で、委任を有効にする採用者にだけ聞く
- 5.2 の記号の変更: 本束の範囲外(1.5)
- ADR-0158 の置き換えだけを書く: 範囲を狭く書く。ADR-0081 決定5・決定4 の「2か月」・却下表の行に及ぶ

## 5. 起草の案の事実の誤り・不足

1. **P §3 案A の本文の変更が「ベースラインは L1」の文だけ**。5.4.2 の表の L1 の欄(HAB 66「人間が全ての変更を確認する」)が残ると、規範の読みが変わらない。欄を改める変更が要る
2. **P §3 案B の「ADR-0112 決定2 に当たる」は範囲を誤る**。決定2 は軸C・軸E の強化が軸B の緩和に優先する決定で、標準品質・CL0 の S0・S1 には直接当たらない。当たる理由は診断6 の構造と ADR-0101
3. **P §3 案C の「ADR-0030 と矛盾」は直接でなく類推**(ADR-0030 は安全重要度の設計による引き下げ。「自動的に緩む経路は設けない」は、第8章の非対称の例示として ADR-0081・ADR-0158 決定4 が引く)。P §10 の未読の開示は適切だが、§3 の本文は断定している
4. **P §8 の置き換えの範囲が不足**。ADR-0158 の「採らなかった案」(移行の猶予、止めない)と ADR-0081 の「課さないと決めたこと」(N-5)が、O-2(b) で覆る却下の行である。置き換えの記録に、却下を覆した行の一覧が要る
5. **P §7 は 1.7.7 の「組織が定める値」の型を引いていない**。(i)〜(iv) を新たに立てているが、記録が無いとき「当該の基準を満たさない」とする既存の型で足りる。V7 の値の無い下限の穴(1.3)も書かれていない
6. **P §8 の「ルール3 に暫定の例外」に終期が無い**(「別 Issue で決めるまで」は番号が無い)。#NNN と終期を併記する
7. P §2.1 の S1・R1 の升は、IMPL-0469 の注記の読みで、試験や本文では未確認(P §10 が既に開示。私も確かめていない)
