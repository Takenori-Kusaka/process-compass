# #466 会議体 意見書 01 — 起案委員

- 日付: 2026-11-27(外部の記述は 2026-11-27 時点)
- 立場: 人が触る場所を「全部の変更」から「決めた場所だけ」へ絞る経路を、本筋として起案する
- 前提: 本文・template は変えない。ADR-0101 決定2 に従い、案はすべて 5.5.4 か L2 の中で書く(別の経路は作らない)
- 読んだもの: intake・chair-notes・internal・external。H.4 条件4 の所在は ADR-0056 71 行・assurance-case.md 411 行
- 根拠として使わないもの: X-15(Vercel。未確認)、X-17・X-31(記憶による)、X-08(予測)

## 1. 見解と案

### 論点1 ベースライン L1

**見解**: 「ベースライン L1」は、2 つの意味を一文に抱えているため、いまのままでは妥当と言えない。
- 意味A「宣言のない変更は全件を人が見る」(安全側の既定)。これは妥当。外す理由がない
- 意味B「決められた場所 = 全部の変更」(目標の姿)。これは一文の要約と食い違う。根拠も無い(HAB 70 に根拠水準マークも ADR も無い。出所は #109 だけ。internal §0-2)
- 実装も B に倒れている。template は登録した種別以外すべて L1。委任のマージ実行は undelivered(IMPL-0026・0235)。つまり本筋として指定された 5.5.4 と L2 が、実装では通れない(chair-notes)

**案の骨子**(現行の文言 → 案):
1. 「2026-08-05 時点のベースラインは L1」 → 「**触る場所の宣言がない変更は L1**(全件を人が見る)。触る場所は、5.5.4 の登録(R3)と L2 の宣言(R2 の統合点)で、構成に宣言する」。L1 を目標でなく、宣言を欠いたときの落ち先と書く
2. R1 の上限 L1、R2 の上限 L2、R3 の上限 L3(ADR-0054 決定3)は変えない。ADR-0054 の EV-0040「R2 の上限を委任へ上げる根拠にしない」も守る。つまり**上限は上げず、上限の内側で通れる道を実装まで通す**
3. 5.4.8 の 1 年の再評価(2027-08-05)を待たず、ベースラインの文へ根拠水準マークを付ける(E0。出所 #109 のみ)。マーク無しで置くのが、実証を欠く判断の開示漏れである

**採らないこと**: 上限の引き上げ。「2026-11 のエージェントは賢いから」(受付の禁止。X-08 は予測にすぎない)。

### 論点2 委任と L2 の条件

見解: 条件の数を減らす案ではなく、**条件を結果で書き直し、機械で閉じるものは機械へ、閉じないものは開示へ**移す案。総じて信頼性を支えているのは「取り消せる」「事後に確かめる」「止まる」の 3 系統で、慣性で重いのは「期間・件数の値(E0)」と「同じ事象を二重に問う条件」。個別は §2 の表。

要点:
- 委任 1〜7 は**1 つも外さない**。外すと起きる事象(CL1 以上の人身危害、戻せない変更、事後確認の消滅)が、他の条件では防げない
- ただし条件 3 の「既存テストで検出できる」は自由な文の主張で、機械で閉じない。条件 3 から切り離し、結果(検出された事例・変異の結果などの証跡)で書き直す
- 条件 6 の抜き取りは、**外す事前確認の代わりに事象を防ぐ中核**である。現状は件数 k の不足を表示するだけで合否に使わない。件数は決定可能な条件なので、**不足の月は登録した種別を停止する**に改める(中身の良し悪しは機械で閉じないので manual のまま)
- L2 の引き上げ条件は、7 つを **5 つに束ねる**(条件 1 の「3か月」を件数の窓へ、条件 6 と 7 を 1 つの結果へ。表を参照)

### 論点3 「作るのを止める」の前の手当て

**見解**: 現行の手段の順(分割 → 労力 → 人数。GC 2632-2636)は、すべて「人が全部触る」前提の内側の手当てである。最も効く手当ては、順の外にある「**触る対象を減らす**」で、それは論点2 の 5.5.4 と L2 を通す(新しい経路ではない)ことだ。

**案の骨子**:
1. 流入の制御の文言に、止める前の手当てとして「触る場所の宣言を見直す(5.5.4 の登録・L2 の宣言を満たせる変更があるか)」を、(1)分割の前に 1 行足す
2. 止める引き金を、同時保有数 3(E0・EV-0011)の固定値だけでなく、結果で書く: 「判定に要する時間が、5.6 の承認時間/規模の比で読み切れる量を超えた」。値は E0 のままマーク
3. 「作るのを止める」自体は最後の手段として残し、**止めた事実と理由を記録する**(止めずに形だけの承認で流す方が信頼性を下げる。5.6、X-32)
4. 先例が無い(X-43「条項で既定にした先例は確認できなかった」)ので、根拠水準マークを付ける

## 3. H.4 条件4 の扱い

**案: 範囲を限る(明示して)。維持でも置き換えでもない。**

- 現行: 「通過を理由に人の確認を減らさない。合否条件に入れない」(ADR-0056、assurance-case.md 411 行。ADR-0101 が維持)
- 衝突の所在: 委任の条件 3a は、G-5 の通過を、事前の人の確認を事後へ移す条件の 1 つにしている。だから条件4 は、黙って読むと 5.5.4 と衝突する。黙って迂回しない。**5.5.4 は通過だけで外すのでなく、通過+取り消せる+事後の抜き取り+識別の組で外す**。この読みを明文にする
- 案: 条件4 を次の 2 層にする(条文は書かない)
  - 層1(全体に維持): 通過・AI の確認を、人の承認として数えない。通過だけを理由に人の確認を減らさない。L2 の採点による深さの配分も、自組織の検出率の測定が無い間は条件4 のまま(ADR-0101 却下表 106 行の理由を維持)
  - 層2(範囲を限る): 5.5.4 の 7 条件をすべて満たした登録種別に限り、**事前の確認を事後へ移す**ことは、条件4 に反しない。移すのは判定の時点で、承認の代用ではない(HAB 547-551 が既にそう書く)
- 理由: (a) 条件4 を字義どおり全面に当てると、5.5.4 は実質成り立たない。本筋の経路が例外の形になる(所有者の問2) (b) 置き換えるには、ADR-0101 が求めた自組織の測定が無い (c) 範囲を明示すれば、「通過した」ことだけを理由にした緩和(外部の自動承認の型。X-11 の「無言の承認」24.4%)を、標準が禁じたまま残せる
- 注意: この限定は、**ADR-0056 の本文を書き換えず**、新 ADR で置き換える形になる(CLAUDE.md の規定)。ADR-0101 を支える却下の理由は動かさない

## 4. 自分の案の最大の危険

**危険: 条件 6(事後の抜き取り)が形骸化したまま、委任の範囲だけが広がる。**

- 抜き取りの選び方と中身は機械で閉じない。k の不足を停止にしても、k 件を「見た」という形だけの確認が積まれうる(X-32: 人の承認の 24.4% が読む速さより速い。阻止率 17%→5%)。事前の確認を事後へ移した分、事故は本番側で見つかる
- 外部には、確認を外した結果の独立した実測が無い(X-35)。Ona・Rewind・Rootly の「revert 0」は短期で自己報告。安全側の反論はここを突く。これを覆す実証を、私の案は持たない
- 起きたとき:
  - **本番の利用者**: 取り消し可能と登録された変更の欠陥を被る(R3 の定義上、組織内に収まるはず。だが R3 は自己記載で通りうる。誤記載があれば R1・R2 の被害が出る)
  - **席の責任者(独立レビュアの責任者・登録者 B-4)**: 抜き取りを担った者が、見落としの結果責任を負う。結果責任は人(不変条件)
  - **採用組織**: 失った信頼は、標準全体が失う
- 緩和: R3 の記載を作成指示者以外が確かめる(R1・R2 と同じ。RR 1114 の拡張)案を検討したが、**新しい義務を置くので採らず、重い審議の対象**として議長へ送る。当面は条件 2 の機械の規則と事後の抜き取りで補う

## 5. 採らない案(検討して落とした)

1. **ベースラインを L2 へ上げる案**。上限は上げないと決めた(ADR-0054 決定3、HAB 107「実績で緩和されません」)。template が L2 を支えず(IMPL-0594 の note)、実装のない文を足すだけになる
2. **R2 の上限を委任へ上げる案**。EV-0040 の差し替え条件が明示的に禁じる
3. **リスク層別の自動承認を、5.5.4・L2 と別に置く案**。ADR-0101 の却下表(92・93 行)と同形。「条件の緩いほうだけが使われる」
4. **AI の確認の通過を人の承認に数える案(Ona・Rewind・Rootly の型の直輸入)**。ADR-0028 決定7 と衝突。外部の証拠も自己報告・短期で、X-38(LLM 間の誤りの相関)が不利
5. **「3 か月」「0 件」「3 件」を、証拠なしに別の値へ置き換える案**。E0 の値を別の E0 の値に替えるだけ。値は据え置いてマークを足す
6. **条件 6 の 4 条件のうち 1 つを外して数を減らす案**。受け皿の信頼性を下げる。数の少なさは採否の理由にならない(CLAUDE.md)
7. **「作るのを止める」を廃止して通知だけにする案**。形だけの確認を許す。最後の手段として残す
8. **所有者の問2(第7章の例外承認で受ける)**。7.3 は R1 の G-6 未達を受ける逸脱で、本筋の経路を例外の形に置くことになる。**採らない**(本筋は 5.5.4・L2 の中で書く)
