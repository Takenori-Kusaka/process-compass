## 4. 「当月の全件を事後に確かめる」の受け皿

結論: **新しい様式・欄を足さずに受けられる**。

- 誰が: 独立レビュアの席の責任者(事後監査の手続 TG 452 の実施者。席から名簿を引ける場合だけ数える。`whoKey('independent-reviewer')`)
- 何で: 既存の抜き取りの記録 = G-6 の判定記録で、確定の形態が「委任」、対象が当該 PR(`aggregate-evidence.mjs` 5575-5600 行)。**記録の様式は同じで、月の件数の定め(k)だけが n に上がる**。記名・日付の欄は足さない
- 数え方: 既存の `samplingMonthly`(IMPL-0597)が月ごとに n・k を出す。試作は、判定不能の月だけ定めを n にした(02)。本文は「不足を差し戻しの条件にしていない」(合否に数えない)と書くので、O-2 を採るなら、ここを「判定不能の月に限り、止める根拠にする」へ改める(本文の変更)
- 1〜2 名の体制: 席の責任者本人による抜き取りは「独立に数えない」(TG 452。`bySeat` が偽になる)。この体制は、判定不能の間に止まる側へ倒れる。これは正しい(独立の確認が無いまま止めずに進めない)が、小規模で O-2 の恩恵が出ないことを書く必要がある(Q5)
- 機械が確かめないもの(従来と同じ): 抜き取りの選び方・確認の中身。全件なので「選び方」の論点は消える

## 5. 未解決の設計上の問い(議長が決める)

- **Q1 ADR-0158 の置き換えの切り方**: 試作は「`postHoc` の記録を渡したときだけ止めない」にした。渡さないと従来どおり止まる(安全側。未配線の間は何も変わらない)。ADR-0158 決定1(判定不能で止める)を「止めるが、全件の事後確認を満たせば止めない」へ書き換える形になる。決定2 の戻り方(判定可能な窓)は残る
- **Q2 `postHoc` の供給元**: 試作は純関数の側だけ。`readAutonomyRecords` は `aggregate-evidence.mjs` を読めない(`aggregate-evidence` が `autonomy` を読むので循環)。選択肢: (i) 判定記録からの月ごとの n・k の導出を `autonomy.mjs` 側(または新モジュール)へ移す (ii) 呼び出し側(`check-delegation.mjs`・`aggregate-evidence.mjs`)が導いて渡す。(i) の場合、PR 一覧と G-6 の判定記録を読むので、`check-delegation.mjs` の実行時間と権限(`statuses: write`・`checks: read` のまま足りるか)を確かめる
- **Q3 種別ごとか全体か**: n・k は全体(委任した全 PR)で数える。判定不能は種別ごとなので、複数の種別があるとき、他の種別の確認が足りない月で止まる(あるいは足りていると見る)。種別への帰属(PR → 規則 → 種別)を足すか
- **Q4 罠C の条件**: 試作は「マージの経路を有効にしているときだけ除く」。裁定の案の 3 は無条件に読める。無条件にすると、有効でない間は人の承認を待つ PR が数えられず、レビュア負荷を過少に見る。また、判定が「該当」でもマージが失敗して PR が残る場合は、催促から外れたままになる(除外は 0681・0979 も含めた。数える側だけにするなら、除外を同時保有数に限る)
- **Q5 猶予の月数**: 1 か月。0 だと月初の翌日から止まる。決めるなら E0 のマーク(新 EV)。標準に「猶予」という新しい定義を足すか、0 にして足さないか
- **Q6 再修正の印**: 取り消しは `git revert` の標準の文でよい。再修正に `Fixes: <ref>` を採るのは試作の選び。「同じ箇所を黙って直す」は数えない(`REWORK_UNCOUNTED` の開示を 1 項足す)。再修正を数えず、取り消しだけにする選択もある(印の定義が減る。所有者の方針に近い)
- **Q7 低量の種別の恒久化**: 月の変更が少ない種別は、窓を長くしない限り判定不能が続き、全件の確認が恒久になる(窓は 2 か月、最小標本 30 なら月 15 件未満)。全件を人が確かめる運用の負荷が、委任の便益を超える種別が出る。値は変えない前提なので、手引きで窓を長くすることを示すか
- **Q8 母数の混在**: タスクと変更を足して 1 つの比にした(`n = taskN + plainN`)。種別が両方を持つとき、単位が混じる。別々に比を出す選択もある(`taskN` と `plainN` は出力に残してある)
