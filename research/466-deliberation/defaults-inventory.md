## 3. 値が無いときの挙動

### 実行で確かめたもの(scratch の複製)
- **V7 MIN_SAMPLE を消す** → `generate-profile.mjs` の import が SyntaxError で、`test-check-delegation.mjs` が起動すらしない。**フォールバックなし・落ちる(b)**。
- **V7 MIN_SAMPLE = 0 に変える** → `test-check-delegation.mjs` の 21 場面が NG(「窓が最小標本数に満たない(判定不能)」ほか、D-0 の生成の表を含む)。**試験は 30 を固定している**。基準 83 場面は現状 PASS。
- **V8 `DEFAULT_LOAD_LIMIT` を消す** → `review-queue.mjs` が ReferenceError で落ちる(b)。
- **V8 `DEFAULT_LOAD_LIMIT = 0`** → `test-review-queue.mjs` の 2/55 件が NG(「3件目までは出ない」「4件目で知らせる」)。**3 を固定している**。
- **V8 `queueActions` へ渡す `loadLimit`**(5件の未応答の指名を持つレビュア1名): 未指定/3 → 2件の通知。`null`・`NaN`・`0` → **5件の通知(全件が超過扱い。厳しい側)**。`Infinity` → 0件(通知なし)。通知は PR への知らせで、**指名は外さず、止めない**。
- **V4 observationWindow 未設定**: `observationWindowAt({}, day)` = 2、`observationWindowProblems({})` = 問題なし。**既定へ落ちる(a)**。`months: null` は構成の検査エラー(「2 以上の整数」と「history を書く」)。
- 既存の試験の通過(基準線): `test-review-queue.mjs` 55 件、`test-check-delegation.mjs` 83 場面。いずれも日付を入力で与える作りで、今日の日付で通った。

### コードの読みだけ
- **V7 の下流**(autonomy.mjs:417-418・436・444・482・633): `n < MIN_SAMPLE` は、差し戻し率の窓では `stop('第2区分','unmeasurable',…)`、手戻り率の窓も同じ。**「判定不能 = 適用の条件の欠落として止める」(c)**。ADR-0158(O-2 が一部置き換える対象)と同じ形の停止。
- **既存の先例(未設定 → 止める)**: 手戻り率の基準値が無いとき、`state='基準値未設定'` → `stop('第2区分','unmeasurable',…)`(autonomy.mjs:436・447)。つまり template には「値を採用者が決めるまで委任を止める」型が**すでに1つある**(ADR-0129)。決める経路は /process-change の種別 settings。
- **V8 の起動**: `review-queue-control.yml` は env が空文字なら `Number('')` が 0 → 既定 3(:357)。未設定でも3が効く(a)。

## 5. 扱いの選択肢の材料(値ごと。判断はしない)

整合の事実を先に置く。
- **O-2**(決定): 判定の材料が揃うまで止めず、当月の全件を事後に確かめる。理由「アサインしたリソースを空いたまま待たせることは不可能」。(ii) は O-2 と同じ向き。(iii)(i) は、値が無い間に流れを止め得るので、O-2 の理由と緊張する。(i) は止めるのが「初期化の完了」で、運用のリソースを待たせる止め方とは別(初期化の前は運用が無い)。
- **ADR-0028**: 未達(unmet)を省略(omitted)と区別し、**解消されるまで表示し続ける。期間で消さない**。(ii) は「未設定」を判定せず表示するので、表示し続けるなら整合。表示が消える設計(一定期間で未設定を黙認)は ADR-0028 が退けた案(:54)と同じ型。(iv) は例の値が既定として効くなら実質 (a) で、省略と未達の区別を持たない。
- **1.7.7**(overview.md:454-460): 3型のうち「組織が定める値」は「記録が無いとき = 当該の基準を満たさない。参考の値は効かない」。「既定値」は「既定値が効く」。「例」は「何も効かない」。**O-5 の決定は、E0 の値を「既定値」から「組織が定める値」(参考の値つき・つきなし)か「例」へ動かすことと読める**。1.7.7 の箇条は「検知・発火・停止を起動する値のうち、置き換えずに用いても統制を弱めない値は既定値としてよい」と書く。V3・V4・V8 の起動値は、この箇条に当たるかが論点(弱める向きの置き換えが可能なら当たらない [推定])。
- 「組織が定める値」の型で記録が無いときは「当該の基準を満たさない」= **満たさない側に倒す(iii)が 1.7.7 の既定の読み**。

## 7. 気づき(事実と推定)

1. **事実**: 標準は第4章の要求事項1 で、5.4.6 の閾値と最小標本数を G-1 で組織に記録させている。template は最小標本数の欄を持たず、「下げられない」と明記している。**O-5 は標準の既に書いていることに近く、不足は template 側の欄**。
2. **事実**: 未設定で止める先例が template にある(手戻り率の基準値。ADR-0129)。値を採用者が決める経路は /process-change settings として既にある。
3. **事実**: V8 の流入1 は「止めない通知」(IMPL-0682)で、O-2 の理由と衝突しない。衝突しうるのは流入2(生成を止める)と V7 の「判定不能で止める」。
4. **事実**: 標準側で V6(四半期)と V4(2か月)が二重。値を外すときに、どちらが正かを決める必要がある。
5. **推定**: V3(1件)・V4(2か月)は「安全に当たる」場合は重の審議へ上がる。O-5 の対象を引き上げの値(V1・V2)に限るのか、引き下げ(V3・V4)を含むのかは、所有者の決定文からは読み取れない。
