- 所在: `research/457-deliberation/ruling.md` L36(「読む順序は G-6 の手順(判断の前に作成側の主張を読まない)が既に担う」)、L175(「読む順序は入力の分離(3.5.4)による」)、L180 の採らないと決めたことの一覧

- 直し方: ruling.md の L175 の下か L180 の一覧へ、「人の判定者に作成側の理由を後に読む順序を課す案は採らない(round1-ruling。附属書C が勧めに止める。新しい義務で本件の裁定の外)。L36・L175 の『3.5.4』『G-6 の手順が既に担う』は round1-ruling で 3.5.3 と、人には課さない、へ置き換える」の趣旨の補記を足す。採用済み ADR ではないので補記でよい

**L-b SRC-0773 の readLevel と、本文の範囲の主張の出所**

- 所在: `research/sources/SRC-0773.yaml`(readLevel=secondary、verification=partial)、5.5.1 の段落「ISO/IEC/IEEE 42010(SRC-0773。目次だけを読みました)が求める理由は、システムの単位の判断に掛かります」、ADR-0267 のコンテキスト
- 根拠: 読んだものは一次の規格の公開サンプルの目次で、二次資料ではない。一方、「対象は architecturally significant な判断」という範囲の主張は目次から出ず(サンプルに本文は無い)、verification の note が「二次資料に依る」と書く二次資料は台帳に無い。本文は「目次だけを読みました」と開示しているので、根拠の弱さは読み手から見える。ただし「システムの単位の判断に掛かります」は断定で、その出所を辿れない。題目(システムのアーキテクチャ記述)から導ける範囲に止まるなら、目次で足りる
- 直し方: どちらか。(1) 本文と ADR の文を「規格の題目と目次(5.2.12・6.10)から、アーキテクチャの記述の単位の判断に掛かると読みました」へ弱め、SRC-0773 の summary から二次資料に依る範囲の主張を外す。(2) 範囲の主張を残すなら、依った二次資料を SRC として登録する。readLevel は、目次の水準を表す語が語彙(full / section / abstract / secondary / snippet)に無いため、secondary のまま note で「一次の目次」と明記するのでもよい
