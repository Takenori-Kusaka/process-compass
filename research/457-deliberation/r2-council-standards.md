# #457 再審議(重): 規格委員の意見(2026-11-27)

立場: 規格委員。既存の規格・ADR との整合、外部調査の根拠の選別、新しい ADR の要否。入力は `r2-intake.md`・`r2-options.md`・`r2-external.md`・ADR-0267・`ruling.md`。所有者の意見も受付の推す案(1-B・2-A・3-A)も、正しいという前提では扱わない。

## 1. 外部調査の主張の選別

`r2-external.md` の主張を、裁定の根拠に使ってよいかで分ける。選別の基準は、出典台帳(`research/sources/`)に抜き書きがあるか([確])。台帳の `readLevel` が `secondary` か `abstract` の出典は、規範の根拠にしない。

読み取り:

- **論点3 の「版は構成管理の識別子」を、外部の規格で支える必要は無い**。本標準の本文(5.8.2 L1158〜1165、3.13.5、incident-response)が自らそう書いている[確]。外部の二次資料に依って新しい主張を足すと、ADR-0026 の水準を偽る。外部は「所有者の意見と食い違わない背景」として添えるに止める
- 外部調査が「見つけられた」のは、**成果物の鎖**(要求・設計・コード・試験)に限る。「調査」「入力」を含む一続きの追跡を規格が求める、という根拠は無い。ただし、無いから採らない、でもない。採否は信頼性の論証で決める(§2〜4)

## 2. 論点1: 一続きの追跡

### 採る案: 1-B の修正版

内容は次のとおり。

1. **新しい要求事項・様式・欄を足さない**(1-C・1-D を退ける)。「追跡」という新語を条文へ入れない。本標準の語彙は「トレーサビリティ」「判断記録」「検証の記録」で、所有者の語「チケットのように」は条文に使わない
2. 道筋(変更 → `Spec` → 受入基準 → タスク → 検証の記録 → 理由 → 判断記録 → `Agent-Run`)は、**手引き**に「後から辿る順序」として置く。読み手は保守・インシデント対応・内部監査。条文に置かない理由は、ADR-0267 が「条文は結果と証跡まで、時点・手順は手引き」と決めた線(「採らないと決めたこと」の最終行から2つ目)と同じである
3. H.3 は**2行のまま**にし、「何をしたか」の行の「止める場所」の列と「証跡」の列を、道筋に合わせて書き換える。1行化(1-B の案の1つ)は退ける。理由: ADR-0266 決定3・5 の「最も弱い止め方」の導出は行ごとの区分に依る。「何をしたか」は機械の記録(拒否・パスの差)で、「なぜ」は人の記録で、止め方の区分が違う。1つの升に混ぜると導出が粗くなる[確。r2-options 案1-B の「信頼性の失」と一致]
4. K1(Issue の番号・`setup` の変更は目的へ辿れない)は、道筋の限界として手引きに**開示**する。欠陥として直さない(#286 の意図した経路)
5. K3(検証の記録 ↔ 受入基準の識別子)は、**条文にしない**。G-6 基準6 の確認方法は触らず、準拠テンプレートの様式の例と手引きに「識別子で引くと辿れる」と勧める。理由: 検証の記録は人の欄で、識別子の違反で差し戻すと形式だけを満たす記入に寄る(FND-0020)。ADR-0267 が基準2・3 の範囲を守る線に触れる。**ただし**、識別子の「存在」は決定可能な条件で、機械の検査にできる。裁定の閉じ方の規則(機械にするのは決定可能な条件だけ)に照らすと、機械にしてよい。しかしそれは G-5 の新しい検査で、採用者への新しい義務になる。今回は採らず、「採らないと決めた」と記録する
6. K7 は**修正する**。`pr-workflow.md` L123 の「選択の時点のコミットのメッセージへ書く」の勧めを、「PR の本文(Draft の段階から書き足す)か、PR を経ないコミットのメッセージ」へ改める。IMPL-1052 の注記も同じに改める。D1 で降ろす前に直す
7. K8 は、**結果の側を条文の範囲で確かめ、手段は手引きへ**置く。5.8.2 は「変更単位ごと」に記録するとしている。その「変更単位」が、既定ブランチへ入る単位(スカッシュ後の1コミット)を指すかが、本文で明示されていない[推。L1167・L1011 の「変更単位」は定義を持たない。実装の列では PR の単位とコミットの単位が混ざる]。これを定義の欠けとして扱い、ed か軽の直しとして「既定ブランチに残るコミットが、生成の条件を持つこと」を結果として書く。(a) PR の本文の末尾へ写す、(b) スカッシュの設定を変える、の選択は手引き・テンプレートに置く
8. K8 を直すまでの H.3 の表示: 「何をしたか」の行の「止まらない部分」に、事実の文で「複数コミットのスカッシュでは生成の条件のトレーラが既定ブランチへ残らない(IMPL-1033 の注記)」を足す。区分は `未達` にしない(IMPL-0207 は降りている。降りた統制の既定の運用での欠けで、降りていない規定ではない)。区分は「機械が示し人が止める」を `開示` の併記に改める。理由: ADR-0028 の `未達` は「降りていない規定」で、意味を広げると未達と省略の区別が崩れる。**これは議長が突合で確かめる点**(下の §6)

### 退ける案と理由

| 案 | 退ける理由 |
| --- | --- |
| 1-A(現状維持) | K7・K8 が残る。標準が勧める記録が、勧めどおりに書くほど失われる。規格の立場として放置できない |
| 1-C(要求事項) | 採用者への新しい義務。外部の規範が求めるのは成果物の鎖([確] SRC-0525 §5.7.4)で、その鎖は本標準が既に G-4 基準6(AC ↔ タスク)・テストの識別子で持つ。足りない K3 は、規範の「リンクは整合を意味しない」(SRC-0554。注記は再確認が要る)が示すとおり、識別子の義務化では閉じない |
| 1-D(チケットの様式) | 既存の記録と内容が重なり、食い違いの源になる。「ステップ」の欄を AI が書くと 5.8.6 要求事項8 と衝突する。「調査」「入力」を1枚で求める規格は読めた範囲に無く、根拠が無いまま新しい様式の義務を課すことになる |
| H.3 の1行化 | 区分の導出が粗くなる(上記) |

### 残る懸念

- K7・K8 は**本文の読みだけ**で、実行で観測していない。特に K8 で、スカッシュのマージが `Co-Authored-By` を残す場合がある、という記憶がある[推。ホスティングの既定の挙動で、未確認]。観測の前に H.3 の表示を書き換えると、逆の誤表示を作る。**観測を裁定の前に置く**
- 手引きの道筋は守られたかを機械が確かめない。破られたとき失うのは、後から説明する保守・インシデント対応・内部監査で、書いた者は失わない(書いたつもりのまま)。これは ADR-0267 の限界と同型で、`EV` で開示する
- X1(標準のテンプレ7 に「変更の対象パス」の列が無い)は本件の範囲外。ed か軽として別に扱う。本審議では扱わない

## 3. 論点2: 「何を調査したか」の範囲

### 採る案: 2-A + 2-C

- ADR-0267 決定1・6 を保つ。広げない
- 調査の結果が判断を決めたときの置き場を、手引きで示す: 設計上の選択は判断記録のコンテキストと代替案(2.6)、確かめていない言明は機能仕様の前提・前提の台帳、作業上の選択は 5.5.1 の「依った資料の所在」。**5.5.1 は既に所在を求めている**(`human-ai-boundary.md` L447。r2-intake §4)ので、判断を左右した調査は残る。残らないのは、判断に効かなかった調査だけである
- **採らないと決めたこと**を、ADR-0269 に表で記録する: 全変更で調査・読んだ資料を残す(2-B)、実行の記録の保持を標準の義務にする(2-D)。「書かれていない」と「課さないと決めた」を読み手が区別できるようにする

### 退ける案と理由

| 案 | 退ける理由 |
| --- | --- |
| 2-B | ADR-0267 が退けた「全ての作業上の選択に理由」と同じ欠点(読む量、定型文、ADR-0072)。AI が書く「調べたこと」は作成側の主張で、検証に数えられない(FND-0147 [確]) |
| 2-D | 会話の全文に秘密・個人情報が入りうる(ADR-0267 決定6 の理由)。ADR-0126 決定5・IMPL-0512 の線を変える。**採用者への新しい義務で、費用・基盤差(IMPL-0511)を実測で支える材料が無い**。K5・K6 は未達・開示として残る |

### 残る懸念

- 所有者の意見の「何を調査したか」は、AI の読んだ資料の事実を指すなら、本標準の記録の外(実行の記録、採用者の保持)。判断の根拠としての調査なら 5.5.1 の所在・2.6 に既にある。**この2つを読み手が区別できる説明**を手引きに置く。置かないと、所有者の期待と標準の記録がまた食い違う
- 規格の側の裏付けは弱い。「調査を残すことを求める規格は見つからなかった」は、否定の確認ではない。ただし 2-A は新しい義務を足さない案なので、外部の根拠が弱いことは採否を左右しない。**義務を足す側(2-B・2-D)にこそ、強い根拠が要る**。それが無い

## 4. 論点3: モデルの版

### 事実の確認([確])

- 5.8.2 の本文は既に、記録の目的を「条件の特定と影響範囲の絞り込み」とし、「再現ではない」「正しさの根拠は検証の記録」と書く(`human-ai-boundary.md` L1158・L1163・L1165)。「再現できると外部へ説明してはなりません」(L1175)もある。**本文は、版をブラックボックス化の説明の証跡にしていない**
- 食い違うのは次の3か所だけである。(i) H.3 の行「何をしたか」が、止める場所に「生成の条件」、証跡に項目7(共著者の不一致)を置く(`assurance-case.md` L298)。(ii) ADR-0012 決定3 の理由文「版を記録しない生成は再現できず、検証の対象を特定できない」。(iii) 境界の2か所(提案書の型 L96「監査対応」、H.5 問11)
- 版の役の全数(r2-intake §3): 30 か所のうち説明に当たるのは H.3 の1か所だけで、他は影響範囲・変化点・測定・供給者の管理

したがって所有者の意見のうち、「版を説明・追跡の証跡にする価値は無い」は**本文と一致する**。「版自体を記録する価値は無い」は、**一致しない**。後者は 3.13.5(宣言と実態のずれの機械の検出)、incident-response 手順1・2、safety-verification 要求2 を失う。**3つ目は安全に当たる**ので、本件の審議では扱えない。

### 採る案: 3-A + 3-D の表示側

1. 記録は残す。**位置づけを「担当者の記録」へ改める**: 影響範囲の特定・変化点・宣言と実態のずれの検出・供給者の管理。3-A の1〜3(H.3 の行の書き換え、境界2か所への目的の併記、ADR の置き換え)を採る
2. H.3 の「何をしたか」の行から、版(生成の条件)を外す。「止める場所」は拒否の記録・計画と実際のパスの差・検証の記録。版は、変化点・影響範囲を扱う別の行か、C10 側の表示に置く。行を新設するときは `scripts/check-failure-projection.mjs` の検査(列・IMPL の実在・区分)に通す(ADR-0266 決定5。EV-0357 の範囲内)
3. ADR-0012 決定3 の**理由文だけ**を ADR-0270 で置き換える。決定3 の要求(版・指示・検証の記録を求める)は置き換えず、補う。ADR の運用(`adr/index.md` の規則3)に従い、ADR-0012 のステータスに「一部置き換え(→ ADR-0270 の決定 1。理由文のみ)」と書く。ADR-0270 のステータスの表にも ADR-0012 を書き、両側が互いを指す状態にする(規則5)。これで X2(5.8.2 L1158 との食い違い)が解ける
4. 「版の記録が影響範囲の絞り込みに使えた実績が無い」(E0)は、問11・問22 の開示を保つ。ADR-0270 に新しい EV は足さず、既存の E0 を引く(新しい実証を欠く判断は無い)
5. 3-D の K8 の修正と IMPL-1034 は、論点1 の K8 と同じ。版を残す以上、既定の運用で落ちない記録にする
6. 規範の語を足さない。理由: 本文の L1158・L1163〜1175 が結果を書き済みで、足すのは表示と ADR の理由文だけ。規範の語を足すなら、`scope-marking.md` に従い、適用範囲は節の見出しへ併記するか、行の中に書く。限定を別の段落へ置かない。今回は足さないので不要

### 退ける案と理由

| 案 | 退ける理由 |
| --- | --- |
| 3-B(版の記録をやめる) | 穴が5つ開く。3.13.5 の機械の検出は、申告だけだと「申告しないほうが楽な側へ崩れる」(本文の理由)。FND-0059(E2)は指定と実際のモデルが違った事例。**安全関連部の要求2 は安全に当たるので、本件では扱えない**。記録の費用はほぼ自動(IMPL-0207・1019)で、やめて得るものが小さい。所有者の方針のうち、判断軸は信頼性で、負担ではない |
| 3-C(期間の記録で代える) | 並行の実行・下位の担当で複数のモデルが動くと、期間で一意に決まらない。宣言と実態のずれの検出の入力が無くなる。ADR-0126 決定5 を変える |
| 3-D 単独 | 表示の位置づけを欠くと、説明の証跡と読まれ続ける |

### 残る懸念

- 識別子が固定の挙動を指さない提供者がある。版は「期間を区切る印」としてしか働かない。この限界は 5.8.2 が「同じ出力は得られない」と既に書いているが、**影響範囲の絞り込みの精度への含意**(同じ版でも挙動は同じとは限らない)は書いていない。影響範囲は「同じ条件の変更の一覧」であり、問題の再現の保証ではない、と ADR-0270 の影響に一文で明記する(新しい規範にはしない)
- 版の記録は、平時は読まれない記録である(#467)。費用がほぼ自動であることを根拠に残す。#467 の点検で、読まれた実績が出なければ見直す(見直しの契機を ADR-0270 に書く)
- 所有者の意見を一部不採用とする。ADR に「版を記録する価値は無い、は採らない。理由: 3.13.5・incident-response・safety-verification 要求2 が依る」と書く

## 6. 議長への勧めと、突合で確かめる点

1. **観測を先に**: K7(複数コミットの PR をスカッシュし、途中のメッセージが残らないか)と K8(トレーラが落ちるか。`Co-Authored-By` が残る場合があるか)を、準拠テンプレートの既定の設定で実行して確かめる。結果で H.3 の表示と手引きの文面を決める。これは「実行での確認が欠陥を見つける」という過去の記録に合う
2. 論点1・2・3 は、上の案で足りる見込み。**会議体の他の委員が割れたとき**に、重へ上げる点は次の2つに限る: (i) K3 を条文にする案(採用者への新しい義務)、(ii) 版の記録をやめる案(安全に当たる)。それ以外の割れ方は議長が裁定してよい
3. 所有者の意見への回答の形: 「目的・ゴール・調査・手順・入力に基づく達成を追えること」は、既存の記録が既に持つ。足りないのは辿る道筋の記述と、K7・K8 の2つの切れ目である。「版を証跡にする価値は無い」は、説明の証跡としては本文と一致し、担当者の記録としては採らない。**この二重の回答を明記する**
4. 独立の突合で確かめる点: (a) H.3 の行の書き換えが `check-failure-projection.mjs` を通るか、(b) ADR-0012 の一部置き換えが ADR の規則3・5 を満たすか(両側が互いを指す)、(c) 手引きの道筋の各行番号が `lint:refs` で実在するか、(d) K8 の表示を `開示` とした区分が ADR-0028 の `未達` の定義と矛盾しないか
5. 本審議で調べて確かめたこと([確])と推測([推])の区別は、各節に記号で付けた。推測のまま裁定の根拠にしないもの: スカッシュのマージの既定の挙動、「変更単位」の定義の欠け、外部の二次資料に依る規格の条項番号
