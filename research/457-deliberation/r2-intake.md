## 0. 要約

- 一続きの追跡(目的 → ゴール → 調査 → ステップ → インプット → 結果)の要素は、調査を除いて既存の記録にある。**1本に読む道筋を本文はどこにも書いていない**。附属書H H.3 は「何をしたか」と「なぜ」の2行に分けて投影している
- 変更から辿る鎖の切れ目は **8か所**(§2)。重いのは2か所で、どちらも**既定のスカッシュのマージ**による。(K7) 手引きは理由を「選択の時点のコミットのメッセージ」へ書けと勧める。ところがスカッシュのメッセージは PR の本文で、途中のコミットのメッセージは既定ブランチに残らない。(K8) 途中のコミットに付く `Agent-Run`・`Agent-Assets`・`Co-Authored-By` も、同じ理由で落ちる。標準の記録の側も、この限界を開示している(IMPL-1033)
- モデルの版が本文で担う役は、ほぼ全部が「影響範囲の特定」「変化点・宣言と実態のずれ」「測定の有効性」「供給者の管理」である(§3)。**ブラックボックス化への答え(説明)として表示している箇所は、はっきりしたものが1か所**ある(附属書H H.3 の投影の行「何をしたか」、assurance-case.md L298)。境界のものは2か所(提案書の型 L96 の「監査対応」、H.5 問11 L994)。ほかに、採用済みの ADR-0012 決定3 が、版の記録の理由を「再現」で書いている(5.8.2 L1158 と食い違う)
- 変更ごとの版の記録をやめると、穴が開く場所は5つ: 宣言と実態のずれの機械の検出(3.13.5)、インシデントの影響範囲の絞り込み(incident-response 手順1・2)、内部監査の観点17、安全関連部の要求2(safety-verification L121。**安全に当たる**)、保証の開示 項目7 の共著者の警告。適合性確認(3.4.2)・変化点の起票(3.13.1)・供給者の管理(3.12)は、変更ごとの記録ではなく宣言した担い手の識別(D-0 表7)に依るので、穴は開かない

## 4. 「調査」を残す既存の規定と、ADR-0267 の範囲

| 規定 | 所在 | 調査を残すか |
| --- | --- | --- |
| 5.5.1 の理由の形 | `human-ai-boundary.md` L447「依った受入基準の項目・規約・制約の所在か、退けた案とそれを退けた理由」 | 理由の根拠として**依った資料の所在**を残す。範囲は退けた案がある選択と外部の制約に従った選択だけ |
| 判断記録(テンプレ2) | `deliverable-templates.md` L656(コンテキスト)・L662(比較した代替案、最低1つ) | 設計上の選択について、調べた案を残す。S2 は全件必須(`lifecycle.md` L236) |
| 機能仕様の前提・前提の台帳 | `deliverable-templates.md` L626、テンプレ10 | 確かめていない言明を残す。確かめた事実は本文へ |
| G-6 基準6 | `gate-criteria.md` L1402 | 検証の手順と結果(調査ではなく確認) |
| 実装計画 | テンプレ7 | 調査の欄は無い |
| AI の確認の入力 | `assurance-case.md` L476、ADR-0124 決定5 | AI のレビューが読み込みうる入力を列挙して残す(生成の側には無い) |

ADR-0267 は「調査の過程は残さない」と字句では書いていない。書いているのは、(決定1)理由を残す範囲を退けた案がある選択と外部の制約に従った選択に限ること、(決定6)開発の道具としての AI の会話・推論の経緯の保存を課さないこと。採らなかった案は、全ての作業上の選択に理由を求める案(読む量・定型文・ADR-0072)、会話の全文の保存の義務(秘密・個人情報、5.8.2 が指示の全文を求めない判断と矛盾)、「差分から読み取れない選択」を基準にする案(書き手の主観)。根拠は、AI の自己説明が実際の原因と一致しない研究(SRC-0769、要旨のみ、転用)と FND-0147(作成側の説明が判定を歪める)。

## 7. 所有者の方針に照らした点

- 細かい定義を増やさない / 条文は結果と証跡まで: 論点1 は「結ぶ道筋」の問題で、記録の新設ではない。手引きと H.3 の投影で足りる見込み(r2-options.md)
- 新しい条項を足さずに済むか: K3 の識別子での参照だけは、条文(G-6 基準6 の確認方法)を触る案と、様式の注記に止める案に分かれる
- 破られたとき誰が何を失うか: K7・K8 が破られると、後から説明する者(保守・インシデント対応・内部監査)が、理由と生成の条件の両方を既定の運用で失う。書いた者は失わない(書いたつもりのまま)
- 記名欄を求めない: どの案も記名欄を足さない
- #467・#466: 論点2 を広げる案は、全変更へ書く量を足す。#467 の「読まれない証跡」の点検の対象になる。論点3 の記録をやめる案は負担をほぼ減らさない(自動のため)
