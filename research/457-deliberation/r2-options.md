# #457 再審議: 論点ごとの対案(2026-11-27)

入力: `r2-intake.md`(内部の調査。切れ目 K1〜K8、版の役の表)、`r2-external.md`(外部の調査)、ADR-0267。会議体で競わせる材料として、各論点に2つ以上の案を置く。推す案は「推す」と書くが、対案も同じ強さで書く。判断軸は信頼性で、変更量の少なさを理由にしない。

## 前提の整理(どの案でも変わらない点)

- K7・K8(スカッシュで理由とトレーラが落ちる)は、論点の採否と関係なく、**表示と実態の食い違いに当たりうる欠陥**である。ADR-0267 の手引き(`pr-workflow.md` L123)と、降ろす予定の IMPL-1052 が、失われる場所への記録を勧めている。どの案を採っても、D1 で降ろす前に直す必要がある。直し方は論点1 の案に含めて比べる
- 所有者の「すべての記録を取るのではなく」は、ADR-0267 の決定1・6 と同じ向きである。対立は「調査」と「モデルの版」の2点に限られる

## 論点1: 一続きの追跡として読める形にするか

### 案1-A 現状を保つ(H.3 の2行のまま)

- 内容: H.3 の投影の行「何をしたか」「なぜそう作ったか」を残す。追跡の道筋を書かない。K7・K8 は手引きの記録先の文だけ直す
- 信頼性の得: 新しい文が無いので、条項間の食い違いが増えない
- 信頼性の失: 決裁者・監査人が「1つの変更を後から説明できるか」と問うと、答えが2行と7つの記録に散る。辿れることを本標準が主張していないので、辿れないときに欠陥と判定できない
- ADR との矛盾: 無い。新しい ADR は要らない

### 案1-B 既存の記録を結ぶ道筋を、手引きと H.3 に置く(条項を足さない)— **推す**

- 内容:
  1. H.3 の2行を1行「AI の作業がブラックボックスになる(何を目的に、何に基づいて、どう確かめたか)」へ寄せるか、2行のまま止める場所の列に鎖を書く: 変更 → トレーラ `Spec` → 機能仕様の目的・受入基準 → タスク → 検証の記録(G-6 基準6)→ 作業上の選択と理由(5.5.1)→ 判断記録(`ADR:`)→ 実行の識別子(`Agent-Run`)。モデルの版は、この行から外して C10・変化点の側へ置く(論点3)
  2. 手引き(`pr-workflow.md` か `agent-trace-control.md`)に「1つの変更を後から辿る順序」を置く。読む者は保守・インシデント対応・内部監査。新しい欄・様式を作らない
  3. K1(Issue 番号・`setup` の変更は目的へ辿れない)を、道筋の限界として同じ場所に開示する
  4. K7 の修正: 理由の記録先の勧めを「PR の本文(変更の概要)、または PR を経ないコミットのメッセージ」へ改める。「選択の時点で書く」の狙い(後付けの作文を避ける)は、Draft の段階で PR の本文へ書き足す形で保つ。IMPL-1052 の注記を同じく改める
  5. K8 の修正: 2つの形が競う。(a) テンプレートが PR の本文の末尾の段落へ、PR のコミットの `Agent-Run`・`Agent-Assets`・`Co-Authored-By` を写す(機械。決定可能)。(b) スカッシュの設定を「コミットのメッセージを含める」へ変え、トレーラの読み方を合わせる(PR の本文を末尾の段落で読む既存の検査と衝突する)。いずれも実行での確認が要る。直すまで、H.3 の「最も弱い止め方」に「複数コミットのスカッシュでは生成の条件が落ちる」を `未達` として出す(ADR-0028)
- 信頼性の得: 所有者の求める「チケットのように読める」を、記録を増やさずに満たす。辿る道筋を書くと、辿れない箇所(K1〜K8)が欠陥として見えるようになる。K7・K8 は、標準が自ら勧める記録が既定で失われる欠陥で、放置すると後から説明する者が、書いたはずの理由と条件の両方を失う
- 信頼性の失: 道筋は手引きで、守られたかを機械は確かめない(K3 の識別子は文のまま)。H.3 の行を1行にすると、「何をしたか」の機械の記録(拒否・パスの差)と「なぜ」の人の記録の止め方の区分が1つの升に混ざり、最も弱い止め方の導出(ADR-0266 決定5)が粗くなる。2行のまま列だけ書き換える形のほうが区分を保てる
- ADR との矛盾: 無い。ADR-0266 の投影の編集、ADR-0267 決定7 の降ろしの範囲。K8 の (a) は新しい機械の処理で、ADR-0126 決定5(観測とフックの形)の延長として足りるかを議長が判断する。新しい ADR は、原則を変えないので要らない見込み(ADR-0269 を使うなら、K7・K8 の記録先の決定を残す用途)
- #467 の観点: 書く量を増やさない。読む順序を示すだけ

### 案1-C 「変更の追跡」を要求事項として置く

- 内容: 第6章か 5.8.2 に「各変更から、目的(機能仕様)・受入基準・検証の記録・理由の記録・生成の条件へ、識別子で到達できること」を要求事項として置く。G-6 基準6 の確認方法に「検証の記録は受入基準を識別子(F-NNN/AC-N)で引く」を足す(K3)。識別子の有無は決定可能で、機械の検査にできる
- 信頼性の得: 追跡を主張できる。FND-0108(E2)によれば、対応の検査が決定論的に成り立つのは ID で明記したときだけで、識別子の要求はこれに合う。FND-0106・0239(E1、規範)の「手順 → 結果」の鎖と同じ形になる
- 信頼性の失: 採用者への新しい義務(G-6 の差し戻しの理由が増える)。検証の記録は人の欄で、識別子の形式の違反で差し戻すと、形式だけを満たす記入へ寄る(FND-0020 の「提出のための作業」)。文書・設定の変更(K1)では受入基準が無く、例外の規則が要る
- ADR との矛盾: ADR-0072(量の歯止め)と緊張する。G-6 の判定基準を変えるので、ADR-0267 の「採らなかった案 C・D」(G-6 の範囲を守る)と同じ線に触れる。新しい ADR(0269)が要る
- #467 の観点: 全変更の人の欄に形式を足す。#467 の点検の対象

### 案1-D チケットの様式を新設する(所有者の語のとおり)

- 内容: 変更ごと(またはタスクごと)に「目的・ゴール・調査・ステップ・インプット・結果」の欄を持つ様式を置く。実装計画のタスクの行を広げるか、PR の様式に節を足す
- 信頼性の得: 1か所で読める。読む者の探す手間が最小
- 信頼性の失: 既存の記録(機能仕様・タスク・検証の記録・理由・トレーラ)と内容が重なる。重なると、片方だけを直して食い違う。欄の多くを AI が埋めることになり、ステップの欄は 5.8.6 要求事項8(操作の要約を AI に生成させない)と衝突する。AI が書く調査・ステップは捏造しうる(FND-0228、OWASP ASI09)
- ADR との矛盾: ADR-0072、5.8.6 要求事項8、ADR-0267 決定6。新しい ADR が要り、要求事項8 を変えるなら重の審議がさらに要る
- #467 の観点: 最も負担が増える

## 論点2: 「何を調査したか」を残す範囲を ADR-0267 より広げるか

### 案2-A 広げない(ADR-0267 を保つ)— **推す**

- 内容: 理由を残す範囲は、退けた案がある選択と外部の制約に従った選択のまま。調査の過程・読んだ資料の一覧は残させない。採らないと決めた旨を、所有者の意見への回答として新しい ADR(0269)か ADR-0267 の再検討の記録に残す
- 信頼性の得: 5.5.1 の理由の形(L447)は、既に「依った受入基準の項目・規約・制約の**所在**」を求める。判断に効いた調査は、所在として残る。効かなかった調査を残しても、後から読む者の要る情報は増えない。AI の自己申告の「何を調べたか」は、実際の作業と一致しない(SRC-0769、要旨のみ、転用)か捏造しうる(FND-0228)
- 信頼性の失: AI が「読まずに書いた」場合を、記録から見分けられない。過少申告(退けた案を書かない)は防げない(ADR-0267 の限界のまま)
- ADR との矛盾: 無い
- #467 の観点: 負担を増やさない

### 案2-B 全変更で「調べたこと・読んだ資料・退けた案」を残す

- 内容: 5.5.1 の理由の範囲を全変更へ広げ、調査の欄を足す
- 信頼性の得: 所有者の意見の字句に最も近い。後から読む者が、AI が何に基づいたかを読める
- 信頼性の失: ADR-0267 が採らなかった「全ての作業上の選択に理由」と同じ欠点(読む量、定型文、重要な選択が埋もれる)。書くのは AI で、記録は作成側の主張にとどまり、判定に数えられない(FND-0147)。確かめる手段が無い記録を全変更へ課すことになる
- ADR との矛盾: ADR-0267 決定1 を置き換える。ADR-0072 と矛盾する。新しい ADR が要る
- #467 の観点: 全変更の負担が増え、読まれない証跡の典型になりうる(FND-0070、E2)

### 案2-C 範囲は広げず、調査の結果を既存の器へ寄せる

- 内容: 調査が判断を決めたときは、(i) 設計上の選択なら判断記録のコンテキストと代替案(テンプレ2、S2 では全件必須)、(ii) 確かめていない言明なら機能仕様の前提・前提の台帳、(iii) 作業上の選択なら 5.5.1 の所在、へ書く、と手引きで示す。条項を足さない
- 信頼性の得: 調査の記録を、読む者が既に読む器に置く。器ごとに確かめる者(G-3・G-2・確定の場の人)がいる
- 信頼性の失: 手引きなので守られたかは manual。器の選び方を書き手が誤ると散る
- ADR との矛盾: 無い(ADR-0101 の境に従う)。案2-A と両立し、組み合わせられる

### 案2-D 調査を自己申告でなく機械の記録で残す(実行の記録の保持を求める)

- 内容: `Agent-Run` が引き当てる実行の記録(読んだファイル・実行したコマンドを含む)の保持を、採用者に委ねる(IMPL-0512)のをやめ、本標準の要求にする。期間は組織が定める
- 信頼性の得: 「何を読んだか」を AI の申告ではなく実行の事実で残せる。FND-0228 の捏造の経路を避けられる。K5・K6 も同時に閉じる
- 信頼性の失: 会話の全文に秘密・個人情報を含みうる(ADR-0267 決定6 の理由)。保管の費用。読む者はインシデント・監査のときに限られる。実行基盤ごとの差(IMPL-0511)
- ADR との矛盾: ADR-0267 決定6 と ADR-0126 決定5(保持は採用者)を置き換える。重の審議の対象(採用者への新しい義務)

## 論点3: モデルの版を、ブラックボックス化の証跡から外し、位置づけ直すか。記録をやめるか

### 案3-A 記録を保ち、表示だけを位置づけ直す — **推す**

- 内容:
  1. H.3 の行「何をしたか」(`assurance-case.md` L298)から「生成の条件」を外し、C10・変化点・影響範囲の側の表示に置く。この行の証拠の列「項目7(宣言した担い手と、コミットに記録された共著者の不一致)」も、変化点のずれの検出であって説明ではないので移す
  2. 境界の2か所(提案書の型 L96「監査対応」、問11 L994)は、目的(影響範囲の特定・宣言と実態のずれ)を併記する
  3. ADR-0012 決定3 の「再現できず」を、新しい ADR(0270)で「版の記録の目的は、影響範囲の特定と、宣言と実態のずれの検出である。説明・再現の証跡ではない」に置き換える(範囲の外の発見 X2 の解消)
  4. 版の記録が影響範囲の絞り込みに使えた実績が無いこと(E0)は、問11・問22 の開示を保つ
- 信頼性の得: 所有者の「モデルの版を証跡にする価値はない」のうち、説明の証跡としての価値の否定を採る。r2-external も、版を説明の証跡にする規格は開発の道具としての AI には見つからないとする。一方、変更管理・影響範囲の特定の役(r2-intake §3 の 25 か所)は残る。記録の費用は自動でほぼ無い
- 信頼性の失: 記録は残るので、平時は読まれない記録が残る(#467 の観点)。ただし費用がほぼ無い
- ADR との矛盾: ADR-0012 決定3 の理由文と食い違う点を、新しい ADR で解く。ADR-0266 の投影の編集は範囲内

### 案3-B 変更ごとの版の記録をやめる

- 内容: 5.8.2 のモデルの識別と、変更単位の「モデルの識別子と版」を削る。担い手の識別は D-0 表7 の宣言だけで持つ
- 信頼性の得: 記録の項目が減る。提供者の別名・非決定性のため、版が固定の挙動を指さないという限界(r2-external 問3)を、記録の側で引き受けなくて済む
- 信頼性の失: r2-intake §3 の穴5つが開く。とくに、(1) 宣言と実態のずれの機械の検出(3.13.5)が申告だけになる。FND-0059(E2)は指定と実際が違った事例を記録している。(2) safety-verification 要求2(安全関連部の構成管理)が根拠を失う。**安全に当たる**。(3) インシデントで点検の範囲が出荷済みの全変更になる(incident-response 手順1)
- ADR との矛盾: ADR-0012 決定3、ADR-0126 決定5 を置き換える。安全関連部の要求の変更を含むので、重の審議の上でも別の議題として扱う必要がある

### 案3-C 変更ごとではなく、期間の記録で代える

- 内容: 変更ごとの版をやめ、D-0 表7 の宣言と、その改訂履歴の日付(3.13.4)で「いつからいつまでどのモデルか」を持つ。影響範囲は期間で絞る
- 信頼性の得: 影響範囲の特定の役を、粗くだが保つ。変更ごとのトレーラに依らないので、K8(スカッシュで落ちる)の影響を受けない
- 信頼性の失: 宣言と実態がずれたとき(FND-0059)、期間の記録は実態を表さない。ずれの検出(3.13.5)の「実際に動いたモデル」の側の入力が無くなる。下位の担当・並行の実行で複数のモデルが動く構成では、期間で一意に決まらない
- ADR との矛盾: ADR-0126 決定5 を変える。safety-verification 要求2 の扱いを別に決める必要がある

### 案3-D 記録を保ち、確かさを上げることを先にする

- 内容: 表示の位置づけ(案3-A の1・2)に加えて、K8 の修正(論点1 案1-B の5)と IMPL-1034(導出元からの自動の記録、#361)を先に進める。説明の証跡からは外す
- 信頼性の得: 「記録しているが既定の運用で落ちる」状態を解く。残す以上、欠けない記録にする
- 信頼性の失: テンプレートの作業が要る。IMPL-1034 は提供者の文書と実機の確認が未了
- ADR との矛盾: 無い(ADR-0126 の延長)。案3-A と両立する

## 議長が決めるべき点

1. K7・K8 を本 Issue の範囲で直すか(どちらも ADR-0267 の降ろしの前提を崩す欠陥。D1 で IMPL-1052 を降ろす前に要る)。K8 の直し方を (a) PR の本文へ写すか、(b) スカッシュの設定を変えるか。どちらも実行での確認が要る
2. K8 を直すまでの間、H.3 の「最も弱い止め方」に `未達` として出すか(表示と実態の食い違いの「高」に当たるかを、独立の突合で確かめる)
3. 論点1 で、H.3 の2行を1行に寄せるか、2行のまま列を書き換えるか(区分の導出の粗さとの兼ね合い)
4. K3(検証の記録 ↔ 受入基準の識別子)を、条文(1-C)にするか、様式の注記に止めるか
5. 論点2 を広げない場合に、その決定を新しい ADR に残すか、ADR-0267 の再検討の記録に残すか
6. ADR-0012 決定3 の食い違い(X2)を、本件の ADR-0270 で置き換えるか、別の Issue へ回すか
7. 範囲の外の X1(標準のテンプレ7 に「変更の対象パス」の列が無い)の分類(ed か軽)と寄せ先
