# #457 再審議: 品質監査委員の意見(2026-11-27)

立場: 品質監査。問いは「半年後の不具合、または顧客監査で『この変更は誰が何を根拠に作り、誰が確かめたか』と問われたとき、追跡が切れていると何が証明できないか」。判断軸は信頼性。

確かさの記号: **[確]** 本文・台帳の行を自分で読んだ / **[調]** r2-intake・r2-external の記述に依る(再確認していない) / **[推]** 推測。実行での確認はしていない。

所有者の意見は、論点3 の「証跡としての価値は無い」の半分と、論点2 の「全記録ではなく」は支持できる。論点1 の「チケットのように辿れること」も方向は支持できる。ただし「調査を残せば信頼できる」とは言えない。自己申告の調査は、監査では証拠にならないからである。

## 1. 切れ目ごとに、何が証明できないか

追跡の鎖: PR → トレーラ `Spec` → 受入基準 → タスク → 検証の記録 → 理由の記録 → 生成の条件。

| 切れ目 | 顧客監査・半年後の不具合で証明できないこと | 証拠の性質 |
| --- | --- | --- |
| K1 `Spec` が Issue 番号か `setup` | 文書・設定・基盤の変更が、どの目的・受入基準に基づいたか。Issue は標準の記録ではない [調] | 経路として意図されている。範囲の限界として開示すれば足りる |
| K2 目的は機能の単位 | この変更が機能の目的のどの部分のためか。ただし受入基準まではタスクで辿れる [調] | 低い |
| K3 検証の記録が受入基準を識別子で引かない | 「この受入基準を、この検証で満たした」の対応。文で結ばれており、後から読んだ者が推定するしかない [調] | **自己申告**。テストと受入基準は識別子で結ばれるのに、人の検証の記録だけが文である |
| K4・K5・K6 調査・作業ごとの指示・実際の手順 | AI が何を読み、どんな指示で、どの手順を踏んだか。実行の記録は採用者が保持を決める(IMPL-0512)ので、保持されていない組織では証明できない [確: IMPL 台帳の記述を調で読む] | 実行の記録が残る組織では機械の証拠。残らない組織では何も無い |
| **K7** 理由の記録先 | 理由は、勧めどおり「選択の時点のコミットのメッセージ」へ書くほど、スカッシュのマージで既定ブランチから消える。**[確]** `pr-workflow.md` L123 の勧めと `git-strategy.md` L130・L131(スカッシュ既定・ブランチ自動削除)を、この作業ツリーで読んだ。消えることの観測は **[推]**(実行していない) | 書いた者には書いたつもりが残り、読む者には無い。**最も悪い形の欠け** |
| **K8** トレーラが落ちる | 複数コミットの PR で、どのモデルの版・指示資産の版・実行で作られたか。IMPL-1033 の注記が「複数コミットのスカッシュではトレーラが落ちて数えない」と自ら書いている **[確]** | 標準が限界を注記しているのに、H.3 の投影は「機械が示し人が止める」と表示している [調] |

重さの見立て。顧客監査で最も痛いのは K7・K8 である。理由も生成の条件も、既定の運用で消えるのに、書く側は気づかない。K3 は次に重い。K1・K2 は開示で足りる。K4〜K6 は設計上の限界で、論点2 に回す。

### 表示と実態の食い違いが残る箇所

1. **H.3「何をしたか」の止め方の表示と K8**。H.3 は生成の条件を止める場所として表示しているが、既定の運用(スカッシュ)ではトレーラが落ちる。ADR-0028 により、降りていない統制は `未達` で表示し続ける。**これは巡の数に関わらず直す対象**(CLAUDE.md の「表示と実態が食い違う高」)。
2. **IMPL-1033 の `state=delivered`**。注記は限界を書いているが、状態は delivered で、検査は `Agent-Run` を持つコミットだけを数える。スカッシュで落ちたコミットは、警告の行にも出ない(「数えない」)。つまり**検査が通ることは、欠けが無いことを意味しない**。[推] これが「高」に当たるかは、独立の突合で確かめる。私の見立ては、少なくとも注記を H.3 の「最も弱い止め方」へ出す必要がある、である。
3. **K7 の IMPL-1052**。D1 で降ろす前に直さなければ、欠陥をそのまま準拠テンプレートへ降ろす。降りれば「降りた」と表示される。
4. **モデルの識別の記録(`Co-Authored-By`)は、AI の担い手が自分で書く(IMPL-0176、manual)[調]**。導出元からの自動は未達(IMPL-1034)。モデルが自分の版を正しく知っているとは限らない。[推] FND-0059 が記録する「指定と実際が違った事例」は、まさにこの検出を要する。現状の 3.13.5 のずれの検出は、申告された共著者と宣言の突合であり、**実際に動いたモデルとの突合ではない可能性がある**。ここは確認が要る(私は 3.13.5 の機械の入力の源を読んでいない)。

## 2. 論点1: 追跡を一続きにするか

### 採る案: 1-B の変形(条項を足さない)

1. **道筋を手引きに置く**。読む者(保守・インシデント対応・内部監査)が辿る順序と、各段の所在、および辿れない箇所(K1・K3・K4〜K6)を同じ場所で開示する。
2. **H.3 は2行のまま、列を書き換える**。1行へ寄せる案は退ける。理由: 「何をしたか」(機械の記録)と「なぜ」(人の記録)では止める側が違い、1つの升に混ぜると最も弱い止め方の導出(ADR-0266 決定5)が粗くなる。監査では、どちらが機械でどちらが人かを区別して見たい。
3. **K7**: 勧めを「PR の本文(変更の概要)へ、Draft の段階から書き足す。PR を経ないコミットはコミットのメッセージへ」へ改める。時点の勧め(後付けの作文を避ける)は保てる。
4. **K8**: 直し方は実行での確認を経て決める。候補は3つあり、信頼性の見立ては次のとおり。
   - (a) テンプレートが PR の本文の末尾へ、PR 内のコミットのトレーラを機械で写す。決定可能だが、PR の本文は人も編集できる。写しは**導出の写し**であって原本ではない。改ざんの防止は閉じない(manual / adopter で開示)
   - (b) スカッシュの設定を、コミットのメッセージをマージコミットの本文へ含める形にする。[推] こうすると K7(理由)も K8(トレーラ)も、マージコミットの本文に残る可能性がある。ただしトレーラは本文の途中に出るので、末尾の段落を読む既存の検査(intake が衝突を指摘)は読めない。**1つの設定で両方に効く可能性があるので、実行で最初に確かめる価値がある**
   - (c) マージ方式をスカッシュ以外(リベース等)にする。1タスク=1コミットの履歴の性質(git-strategy)を失う。退ける
   決める前に、複数コミットの PR で実際に何が残るかを観測する。ここは**調べて確かめた事実ではなく、確かめるべき仮説**である。
5. **K8 を直すまで H.3 に `未達` を出す**。議長の問い2 への私の答えは「出す」。

### K3 の扱い: 条文にせず、様式の注記に止める

- 退ける案: 1-C(G-6 基準6 の確認方法に識別子を足す)。識別子の有無は決定可能な条件なので、機械の検査にはできる。しかし、人が書く検証の記録は、識別子を付けるだけで中身が空でも通る。FND-0108(E2)が支持するのは「対応が ID で明記されたときだけ検査が決定論的になる」ことで、**対応が正しいこと**までは支持しない。Automotive SPICE の「リンクの存在は整合を意味しない」[調] とも合う。形式を要求事項にすると、差し戻しが形式の不備に寄る(FND-0020)
- 採る形: 様式(テンプレートの「検証方法と結果」)の例を、受入基準の識別子で引く書き方にする。条文は触らない。識別子の有無を機械で見るのは、採用者が望む場合の追加の検査に止める
- 監査の観点の残る懸念: 識別子があっても、検証の記録は自己申告である。独立性は G-6 の判定者が担う。ここは本件で強くならない。**強くならないことを開示する**

### 退ける案の理由

- 1-A: 辿れない箇所を欠陥と判定する根拠が無いまま残る。K7・K8 も直らない
- 1-C: 上のとおり。採用者への新しい義務に対して、得られる証拠価値が小さい
- 1-D: ステップの欄を AI が書けば、5.8.6 要求事項8(操作の要約を AI に生成させない)と衝突する。人が書けば、既存の検証の記録との二重の記録になる。FND-0228 のとおり、AI が書く根拠は捏造しうる

### 新しい条項を足さずに第7章の例外承認で受けられるか

K1(Issue 番号・`setup`)は例外承認では受けない。ADR-0267 が、全変更に常態で掛かる記録を 7.3 で受けると台帳が例外で埋まり G-7 の突合が働かなくなる、と退けた線と同じである。意図した経路は、範囲の限界として開示する。

## 3. 論点2: 調査を残す範囲

### 採る案: 2-A + 2-C

- 広げない。ただし理由は「安いから」ではない。**自己申告の「何を調べたか」には証拠価値が低い**からである。AI が書く調査の記録は、実際に読んだものと一致する保証が無い(SRC-0769 は要旨のみ・転用 [調]、FND-0228 [調])。人が書けば、後付けの合理化になりうる(これを直接測った研究は見つかっていない [調: 未確認])
- 判断に効いた調査は、5.5.1 の所在(依った資料の所在)、判断記録の代替案、前提の台帳のいずれかに既に残る。2-C は、この器の選び方を手引きで示す
- **証明できないことの表を、道筋の手引きに置く**(2-A の実質的な追加)。例: 「AI が何を読んだかは、実行の記録を保持した組織でだけ示せる」「退けた案を書かなかった(過少申告)ことは検出できない」。ADR-0267 は限界を持つが、顧客監査で聞かれる形で書かれていない。**書かれていないことと、課さないと決めたことの区別**を読み手に与える(CLAUDE.md の却下の明記)

### 退ける案

- 2-B: ADR-0267 が退けた案と同じ欠点に加え、全変更に自己申告を足す。形骸化の典型
- 2-D(実行の記録の保持を標準の要求にする): 機械の証拠という意味では、4案の中で**監査上の価値が最も高い**。ここは認める。しかし採用者への新しい義務で、会話の全文に秘密・個人情報が入りうる。本件で入れる議題ではない。**退けるのではなく、別の Issue で調べる**ことを勧める(安全関連部だけに掛ける案も含む)。本件で採らないことは ADR に書く
- 「調査」を設計上の選択へ寄せる案: ADR-0101 の境に従い、2-C の中で扱う

### 残る懸念

AI が読まずに書いた場合を、記録から見分けられない。実行の記録が無い組織では、この穴は閉じない。H.3 に限界として開示する。

## 4. 論点3: モデルの版

### 採る案: 3-A + 3-D、それに1点を足す

1. 説明の証跡から外す。所有者の「証跡にする価値は無い」は、**説明の証跡としては正しい**。版を記録しても再現できない(非決定性・別名。r2-external 問3 [調])。5.8.2 も既にそう書いている(L1158)。外すのは、表示の誤りを直すことである
2. 位置づけ直す先は、担当者の記録(影響範囲の特定・変化点・供給者の管理・検出率の測定の有効性)。規格・実務の版の記録は、ほぼ全てこの目的である(r2-external 問3 [調]。規格本文は未読)
3. **ADR-0012 決定3 の「再現できず」を置き換える**(X2)。5.8.2 と食い違う。採用済み ADR は書き換えず、新しい ADR で置き換える
4. 3-D を先にする: K8 の修正と IMPL-1034。**足す1点**: 記録の「確かさ」を開示する。モデルの識別は AI の担い手の自己申告(manual)で、実際に動いたモデルの観測ではない(上の食い違い4)。位置づけを改めても、この証拠価値の低さは変わらない。「影響範囲の特定に使える」と書くなら、使えるのは**申告が正しい範囲に限る**と併記する

### モデルの版の記録をやめた場合に開く穴(3-B の検討)

| 穴 | 失うもの | 代替 |
| --- | --- | --- |
| 宣言と実態のずれの機械の検出(3.13.5) | 申告だけの運用になる。3.13.5 自身が「申告しないほうが楽な側へ崩れる」と書く [調] | 実行の記録からの別の照合。保持は採用者(IMPL-0512)。変更ごとの記録より弱い |
| インシデントの影響範囲の絞り込み | 点検の範囲が出荷済みの全変更になる(incident-response 手順1)[調] | 宣言の改訂履歴の期間で粗く絞る(3-C)。絞り込めた実績は無い(E0)ので、**やめても実績が失われるわけではない**が、能力も得られない |
| 内部監査の観点17 | 「宣言と実際のモデルの一致」を確かめる入力が無くなる | 無い |
| 検出率の測定の有効性(観点12・27 の系統) | 測定が有効だったモデルの版の根拠が、宣言だけになる | 宣言と採点の記録で代えうるが、実態との照合が無い |
| **safety-verification 要求2** | 安全関連部の「モデルの版と指示を構成管理下に置き、成果物から参照できる」要求が根拠を失う。[確] 要求2 の本文を読んだ | 代えられない。**安全に当たり、重の審議の外の別の議題** |

結論: 3-B は退ける。3-C も退ける。期間の記録では、実際に動いたモデルの入力が無くなり、3.13.5 のずれの検出が成り立たない。並行の実行・下位の担当で複数のモデルが動く構成では、期間で一意に決まらない [推]。

### 残る懸念

- 版の記録で影響範囲を絞れた実績は無い(本標準自身が E0 と開示)。実績の無い記録を保つ根拠は、規格・実務の目的の一致と、記録の費用がほぼ無いこと(自動)に依る。**効果の実証ではない**。根拠水準のマーク(ADR-0026)で開示を保つ
- 自動の記録(IMPL-1034)が降りるまで、モデルの識別は自己申告に止まる

## 5. 議長への勧め

1. K7・K8 を本件の範囲で直す。直し方は、(b) のスカッシュの設定が K7・K8 に同時に効くかを、実行で最初に確かめる。確かめるまで、H.3 に `未達` を出す。IMPL-1052 は D1 の前に直す
2. 論点1 は 1-B の変形(2行のまま、列を書き換える。K3 は注記に止める)
3. 論点2 は 2-A + 2-C。2-D は別 Issue へ。「証明できないこと」を開示する
4. 論点3 は 3-A + 3-D。ADR-0012 決定3 は新しい ADR で置き換える。モデルの識別の記録の確かさ(自己申告)を併記する
5. 独立の突合へ渡す点: (i) IMPL-1033 の `delivered` と実態の食い違いが「高」か、(ii) 3.13.5 の機械の入力が実際に動いたモデルの観測か申告か、(iii) 論点3 の表示の移し替えで、H.3 の証拠の列が空にならないか
6. 重へ上げる論点は無い。ただし 2-D と safety-verification 要求2 は、本件の範囲を越えるので別の議題とする
