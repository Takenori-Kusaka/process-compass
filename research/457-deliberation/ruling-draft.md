# #457 裁定の案(議長の案。会議体の前)

入力: `intake.md`(内部の調査・外部の調査)。審議の重さの案は **重**(intake §1)。

## 0. 問いの立て直し

Issue は「なぜ」を G-6 基準3 だけが担うとみて、その範囲の狭さを問う。調べると、全ての変更に掛かる記録が既にある(5.5.1 の作業上の選択の記録、IMPL-0024)。欠けているのは範囲ではなく、**その記録が「何を選んだか」だけで足り、「なぜ」を求めていない**ことである。テンプレートの PR の様式は「何を、なぜ」と注記で求めており、標準より先に出ている。

## 1. 所有者の 3 つの問いへの答え

### 問1 条文は結果と証跡まで、手順は手引きへ

- 条文に置くのは結果だけにする。「変更ごとに、担い手が採った作業上の選択と、その選択を採った理由が、変更から到達できる記録に残っている」
- 証跡: コミットのメッセージ、または PR の本文。置き場・様式・分量の下限は問わない(G-6 基準6 と同じ書き方)
- 手順(どの選択を書くか、書き方の例、「差分から読み取れる選択は書かない」)は、フェーズ5 の PR 運用リファレンス(手引き)へ置く

### 問2 新しい条項を足さずに第7章の例外承認で受けられないか

- **受けられない(適用の対象でない)**。第7章 7.3 は、ゲートの判定基準を満たさないまま進める手続である。#457 は満たさない基準の話ではなく、記録の中身の話である
- ただし、**新しい条項も足さない**。既存の 5.5.1 の「記録」の中身を明確にするだけで受ける(案 B)。新しい席・新しいゲートの基準・新しい様式は置かない

### 問3 破られたとき誰が何を失うか

| 破られ方 | 失う者 | 失うもの |
| --- | --- | --- |
| 理由が残らない | 後任の保守者、障害の調査者、決裁者へ説明する品質保証の担当 | その構造が制約によるものか偶然かを区別する手段。偶然の構造を守り続けるか、隠れた制約を壊す |
| 理由が残らない | 5.5.1 の「確定の場でまとめて確認する」人 | 選択を評価する材料。確認が「選んだ内容の一覧を眺める」操作に縮退する |
| AI が書いた理由が実際の原因と違う | 後から読む者 | 誤った前提。→ 理由を作成側の主張として表示し、検証の根拠に数えないことで受ける |
| 全変更に ADR・長い理由を課す | レビュア・技術判断者 | 注意の配分(5.7.5)。重要な選択が量に埋もれる(ADR-0072・FND-0063) |

記録の負担は、書き手が AI であれば小さい。形骸化の危険は**書く側より読む側**にある(量が増え、読まれなくなる)。そこで書く範囲を「差分から読み取れない選択」に限る。

### 推す案 B の文案(条文の骨子。文言は実装の担当が整える)

5.5.1 の表の行「承認済みの受入基準とスコープの内側にある選択」の扱いを、次の趣旨にする。

- 担い手が決めて、**選んだ内容と、その選択を採った理由を**、変更から到達できる記録(コミットのメッセージ、PR の本文など)へ残す。置き場・様式・分量の下限は問わない
- 差分から読み取れる選択は書かなくてよい
- 記録した理由は作成側の主張として扱う。検証の根拠に数えず、独立レビュー(G-6)の判定の入力にしない(入力の分離)
- 人は変更ごとの確定の場で、記録された選択と理由をまとめて確認する(既存)

## 3. 統制の閉じ方

- **機械にしない**。記録先がコミットのメッセージでもよいため、PR の「変更の概要」の節の存在を必須にすると条文より狭くなる。理由が書かれているか・正しいかは自由な文の意味で、決定可能でない
- **manual**: 確かめる者は、5.5.1 の確定の場の人と、出荷判定者(G-7 で抜き取るとき)
- **presence**: テンプレートの `CLAUDE.md` の常駐の行(IMPL-0024、claude-md-resident.json の core)に「理由」の語が入ることは、既存の presence の検査で閉じる
- **根拠水準マーク**: 新しい EV(番号は実装の時点の次の空き。現在の最大は EV-0350)。対象「作業上の選択の理由を1文で残すことが、後からの説明を支え、形骸化しないこと」。水準 E0。差し替え条件: 採用組織で、理由の欄が定型文(「最適なため」など)で埋まった割合、後の障害の調査・保守で理由の記録を引いた件数、理由が実際と違っていた件数

## 7. #456 の投影の「ブラックボックス化」の行へ渡す結論

AI の作業のブラックボックス化は、三つの記録で防ぐ。「何をしたか」は、生成の条件(モデル・指示資産の版・実行の識別子。5.8.2)と、拒否の記録・計画と実際のパスの差(5.8.6 要求事項5・10)が機械で残る。「なぜそうしたか」は、全ての変更で担い手が作業上の選択とその理由を変更の記録へ残し(5.5.1。#457 で理由を明示。テンプレートへの降ろしは未達)、設計上の選択は判断記録として G-3 で判定する(2.6。要否の規則に当たる変更は S1 以降で機械が止める)。コア機能と R1 では、人が先に方針を書く(段階1〜3)。「誰が確かめたか」は、作成を指示していないレビュアの挙動要約(G-6 基準2)と、コア機能の理解の保持者 2 名以上(3.4.3)が担う。限界として、作成側の理由は主張であり検証の根拠に数えない。AI の会話の全文は保存を課さず、保持は採用者に委ねる(IMPL-0512)。理由の記録が形骸化しないことは実証していない(暫定 E0)。
