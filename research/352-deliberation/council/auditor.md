# #352 会議体 委員「品質監査」の意見

- 日付: 2026-11-15。立場: 適合の主張を外から確かめる監査。何も実装していない。ほかの委員の意見は読んでいない
- 読んだもの: `internal.md`、`external.md`、Issue #352、1.10.2 の表と注記(`overview.md:640-680`)、3.4.3 要求事項2〜9 と周辺(`roles-responsibilities.md:244-278`)
- 読んでいないもの(internal.md の所在表の記述に依る): 3.5.2 の D-1 の本文、3.5.3、5.6.2、テンプレ11 の本文、各 ADR の本文。該当の判定は、これらの記述が正確である前提
- Issue の「ADR-0082」は ADR-0083 と読む

## 0. 結論の表

判定の物差し(5 節で定義)は4つ。(T1) 構造上避けられない構成が、許される体制(2名を含む)に有るか。(T2) 措置を確かめる者が、離脱する本人ではなく、記録で指せるか。(T3) 措置が守る危険を同程度に覆うか、覆えないなら限界を条文に書けるか。(T4) 決定可能な部分を機械で閉じられるか。4つすべてを満たしたものだけを列挙へ入れる。

| 規定 | 列挙へ | 一言の理由 |
| --- | --- | --- |
| 出荷判定者 × 事業決裁者 | **入れない** | 2名は分けられる(T1 不成立)。1名は確かめる者がいない(T2 不成立)。同程度に覆う措置は、第三者の受容そのもので、それは分離であって代償ではない |
| AI維持管理者 × AI運用担当者 | **入れない** | 同上。2名では分けられる。1名では措置を承認する本人以外がいない |
| 欠陥注入の時期と箇所の秘匿 | **入れない** | 措置ではなく「未測定」の開示(附属書I ③)が既にある。措置を足すと「測れた」と読まれる |
| 認証情報を席ごとに分けられない構成 | **入れない** | 採用者が分けられる(T1 不成立)。ADR-0035 決定2 の「代償措置つきの逸脱」は措置が無く、許可の名に当たらない |
| AI の担い手の名義の共有・未申告 | **入れない** | 採用者の選択で解ける。申告と照合は決定可能で、機械で閉じられる |
| コア機能の理解の保持者が1名以下(3.4.3 要求事項6・7) | **入れない** | 措置の候補(登録・受容)は自己申告で、守る危険(属人化)を覆わない。扱いの手続であり措置ではない |
| 層1 の記名者 × 事業決裁者(テンプレ11 要求事項5) | **入れない** | 1名の組織は措置を確かめる者がいない。組織の中の1名の体制は、上位の者の記名で解ける |
| 判定記録の置き場の履歴を規則で止めていない構成 | **入れない** | 小さい体制の問題ではない。プラン依存で #329 の系統。範囲外 |

体制の扱い(論点2)の推し: **(a) 主張できないままにして、理由を明記する**。(b)・(c) は採らない。(d) として、食い違い(論点3)の直しと、再検討の契機の明記を足す。

最大の懸念は、列挙の是非ではなく**表示と実態の食い違い**(5 節の K-3)。構成に欄が無い4つの離脱を機械が数えず、「適合の主張」と出しうる。「高」に当たり、巡の数に関わらず直す。

## 1. 規定ごとの判定(論点1)

### 1.1 監査として列挙への追加を判定する4つの基準

D-1 の条項(許可の語、適用の条件と失効、代償措置、限界の明記)と、外部の先例(PCI DSS 付録B・C、Green Book OV4.14、SOC 2 CC5.1)から導く。

- **T1 構造上の必然**: 許される体制(CL0・規制業以外の1〜2名)に、採用者がどう構成しても避けられない構成が有ること。避けられるなら、避けるのが標準の要求で、避けない選択は逸脱でなく不適合である。避けられない構成だけが、閉じた列挙の対象になる
- **T2 措置を確かめる者**: 措置の実施を、離脱している本人以外の者が、記録で確かめられること。「誰が、何の記録で」を条文に書けない措置は、措置に数えない。自己申告・自己受容は措置ではなく表示である。PCI 付録B の「評価者が毎年審査する」が先例で、外部資格者の審査と、1名の組織の自己審査は前提が違う(external.md C1 の注意)
- **T3 危険の被覆**: 職務の分離が守る危険を、措置が同程度に覆うこと。覆えないなら、D-1 のように「独立性の回復ではない」と条文で限界を言う。同程度に覆う措置が「本人以外の者の受容」であれば、それは分離そのもので、離脱は解消している。解消していない離脱の措置は、定義により弱い
- **T4 閉じ方**: 措置のうち、決定可能な条件(存在・値の一致・日付・本人でないことの突合)と、決定できない条件(実質の独立、十分性)を分け、後者を manual・adopter で開示すること(5 節)

PCI の「他で既に求める統制は代償に数えない」(付録B 3・4a)も採る。他条項の遵守を、この離脱の措置に数えてはならない。

### 1.2 出荷判定者 × 事業決裁者(適用: 3名未満の体制)

- 危険: 異議を書く者と残存リスクを受容する者が同一になり、G-8 の受容が自己完結する(`assurance-case.md:973`)
- 2名: 分けられる(T1 不成立)。分けない選択は決定の記録に記名する(ADR-0122 決定5)。避けられる離脱を、措置の名で許すと、分ける動機が下がる。監査として、避けられる離脱に条件つきの許可を出す条項は、規範の抜け穴になる
- 1名: 必ず兼ねる(外部の確認者を置ける席は独立レビュアに限る。ADR-0127 決定1)。措置の候補を挙げる。(i) 受容の事後の抜き取り再検査、(ii) 外部の者による受容の追認。(i) は誰が抜き取るか。本人なら自己申告で、本人以外なら「体制の外の者」で、確かめる者の独立を標準が保証できない。(ii) は追認する者が受容者として実質に入れ替わるので分離に当たる。ADR-0127 決定1 が席を限った趣旨と逆に働く
- 結論: **入れない**。限界の文を、1.10.2 の注記ではなく 3.5 の本文に1行足す(論点3)
- 採らない案: 「外部の者の事後の追認」を措置とする案。理由は、追認する者が分離の席に実質入るため、標準が席の限定(ADR-0127 決定1)で塞いだ経路を、措置の名で再び開く

### 1.3 AI維持管理者 × AI運用担当者(適用: 1〜2名の体制)

- 危険: 案件の都合で、全社の統制(モデルの接続・予算・停止条件)を緩める経路(`roles-responsibilities.md:331`)
- 2名: 分けられる(T1 不成立)。兼ねる2名の体制では、もう1人が事業決裁者として居る。変更の承認を本人以外に求める措置は書けるが、そうして書いた措置は「2名で分ける」と同じ形になる
- 1名: 承認する本人以外が居ない(T2 不成立)
- 措置の候補のうち、決定可能なもの: 停止条件・予算の下限値を層1 が記名で固定し、構成の値が下限を下回る変更を機械が拒否する。これは有益だが、**離脱の代償ではなく、独立の統制**で、兼務の有無に依らず課せる。#352 の範囲外。#356 や別の Issue の候補として、後継の記録に残すだけにする(新しい義務になるので、ここでは足さない)
- 結論: **入れない**

### 1.4 欠陥注入の時期と箇所の秘匿(適用: 1〜2名の体制)

- 秘匿は兼務の規定でなく、測定の成立条件。成立しない層は「測定値として記録しない。未測定として扱う」(附属書I ③、`adoption-guide.md:487`)と決まっている。これは措置でなく、**測れなかったことの開示**
- 外の者が注入すれば成り立つ余地を、条文は書いていない(internal.md 3 節)。これは「常に当たる」でも「必ず外れる」でもない
- 措置を足すと「検出能力が測れた」と読めてしまう。OpenSSF Scorecard が合否と別の「結論なし」を返す先例(external.md B3)は、未測定の開示を支える
- 結論: **入れない**。未測定の開示で足りる。K-1 の幅(1名で常に当たるか)は、論点3で直す

### 1.5 認証情報を席ごとに分けられない構成

- 規模を問わない。1名でもトークンは分けられる(`overview.md:649` と同じ趣旨)。構造上の必然ではない(T1 不成立)。プラン・ツールの制約で分けられない場合は、#329 の系統(配備の統制がプランに依る)に属する
- ADR-0035 決定2 は「代償措置つきの逸脱」と書いたが、措置を書いていない。ADR-0083 決定8 が読み替えて、形の上は解けている
- 措置の候補(文脈の自己申告の印をコミットに付ける)は、自己申告で措置に数えない。機械が分けて読める認証情報の別(アカウント・トークンの識別子)は措置でなく、要求そのもの
- 結論: **入れない**。「許可と読める余地」(X-10)は、**無い**。ADR-0035 の「逸脱」の語は、閉じた列挙の定義(`overview.md:168`)に照らして、許可として働かない

### 1.6 AI の担い手の名義の共有・未申告(Issue の一覧に無い行)

- 採用者の選択で解ける。申告と実行環境での照合は決定可能で、機械で閉じる(IMPL-0308・0430)
- 結論: **入れない**。列挙に無い離脱のまま、解けば消える。小さい体制の論点ではない

### 1.7 コア機能の理解の保持者が1名以下(3.4.3 要求事項6・7)

- 危険: 属人化(組織の継続)。出荷ごとの品質の確認ではない
- X-10 の「境界にある」を、監査として判定する。要求事項6 の文は、(i)「是正の期限と責任者を登録」は、直す計画であって、危険を覆う措置ではない。(ii)「層1 の権限者が期限つきで受容」は、1名・小さい体制では権限者が本人か、本人が任命した者で、確かめる者が独立でない(T2 不成立)。(iii) 要求事項7「出荷を止めない」と表示は、**開示**で措置でない。(iv) 委任(L3)の停止(5.4.6、ADR-0081 決定6)は措置でなく、**帰結**で、既に効いている。措置に当たりうる文は、**措置に数えない**
- 適用の条件(どの場合に認めるか)が無い、許可の語が無い、限界の文が無い。D-1 の4要素のうち、備わっているのは「期限つきの失効」だけ
- T1: 1名で必然。2名は、2人とも確認の記録を持てば解ける(避けられる)
- 結論: **入れない**。6 は「扱いの手続」であって離脱を補う措置でない、と本文に明記する(論点3)。ADR-0081 の帰結(委任の停止)は変わらない
- 弱点として、期限つきの受容は、体制が増えない限り更新が続く(internal.md 2 節 (d))。更新が続く受容を「期限つき」と呼ぶのは、監査として実質のない統制。入れない結論は、この点を悪化させない。ただし更新の回数の上限を新しく課すなら新しい義務で、別の審議に属する

### 1.8 層1 の記名者 × 事業決裁者(テンプレ11 要求事項5)

- 1名の組織: 記名者は本人で必然。措置を確かめる者が居ない
- 組織の中の1名の体制: 上位の者が記名すれば当たらない(避けられる)
- 結論: **入れない**。「1名の体制は常に当たる」(1.10.2 の注記)は、組織の中の1名では誤りで、直す(論点3)

### 1.9 判定記録の置き場の履歴を規則で止めていない構成(Issue の一覧に無い行)

- 体制の規模と関係が薄く、プランに依る。措置の候補(外部へのミラー、署名タグ)は機械で読めるが、新しい義務。#329 で扱う
- 結論: **入れない**。範囲外として #329 へ寄せる

## 2. 1名・2名の体制の扱い(論点2)

### 2.1 推す案: (a) 主張できないままにして、理由を明記する

理由は3つ。

1. **監査の対象が無い**: 1名の体制では、どの措置も確かめる者が本人になる。第三者が確かめられない主張を、標準が「逸脱を伴う適合の主張」の名で認めると、読み手は第三者の確認があるものと読む。PCI は外部の評価者が審査する。1名には対応する者が居ない(external.md C1)
2. **先例の型**: 1名体制に適合を明示した規格は確かめた範囲に無い(external.md 0 節)。SLSA は単独の体制を下位の水準で止める(T4)。ISO 26262・DO-178C は独立性が要る水準で主張させない。「主張できない」は、監査の世界で通常の状態
3. **適用と主張は分かれている**: ADR-0068 決定6・1.2 は1名の体制を適用の組織に含め、「含めることは成立条件を満たすことを意味しない」と書く。主張できないのは矛盾でない。述べられるのは適用の表明まで、で、開示つきの利用は妨げない

注意: これは「1名の体制を排除する」のではない。採用はできる。第1版が未発行のいま、どの構成も主張できない(1.10.3)ので、1名だけが不利な状態ではない。

### 2.2 採らない案

- **(b) 列挙に入れて「逸脱を伴う適合の主張」を可能にする**: 1 節のとおり、確かめる者を置けない。かつ、1名の体制を2つの主張へ導くには、常に当たる2組(出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者)の**両方**へ措置が要る(internal.md 3 節)。ADR-0082 決定1「効果を定義できない代償措置を置かない」と、ADR-0028 決定6「代償措置は未達の解消として扱わない」の型にも反する
- **(c) 体制の規模でプロファイルを分ける**: 29110 のように最初から別の要求の組を作る型(T3)。採らない理由は、(i) 本標準の区分は CL とリスク区分 R が軸で、規模は軸でない。ADR-0039 は CL・R を案件・変更の単位で分けている。規模のプロファイルを足すと3軸目になる。(ii) 軸E は CL1 以上と規制業で1〜2名の構成を認めない。規模のプロファイルが働くのは CL0・規制業以外だけで、範囲が狭い。(iii) 29110 は安全重要を対象外にする。本標準は CL を持つので型が合わない。(iv)「適合」の意味が増える。規模のデータは受け取らないと決まっている(`tailoring-guide.md:181`)。観測の根拠が無いまま新しい軸を足すのは、EV-0160 の観測を待つ方針に反する
- **(d) の一部**: 「実行可能であれば」の条件つき(T1 型、ISO 19011)にして、満たせないときは努力義務にする。条件が開いており機械の検査にならず、「適合」と「列挙に無い離脱」の線を曖昧にする(external.md O4)

### 2.3 ADR-0029・ADR-0081 との矛盾

- ADR-0029: 認めるのは3名未満の G-7 の兼務だけで、「ほかへ広げません」。(a) はこの文を保つ。矛盾しない。ただし 3.5.2 の「この例外ではなく」(`:580`)と 3.5 `:456` の「例外をこれらへ広げません」の趣旨を、**なぜ広げないか**(T1〜T3)まで書くと、「書かれていない」と「課さないと決めた」の区別がつく(コアポリシー)
- ADR-0081: 保持者1名以下の帰結(第1区分、該当する種別の委任の停止)は変わらない。矛盾しない。ただし K-4(第8章「極小規模での事後監査への切替」と、`:274` の組み合わせで、1名の委任がどうなるか)は、internal.md が確かめきれていない。**未確認の点として残す**。(a) はそれを動かさないので、#352 の結論には影響しないが、受け入れ条件「矛盾しない」を言い切るには、ここの確認が要る(実装を見ていない別の文脈の突合に回す)

## 3. 現行の条文の中の食い違いの直し方(論点3)

方針: 意味を変えず、事実に合わせる編集で済む部分と、決定が要る部分を分ける。

### 3.1 1.10.2 の注記と条文の幅(K-1)

- 現状: 注記は4つの規定が1名の体制で「常に当たる」と書く
- 事実: 字義どおり常に当たるのは、出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者の2つ。保持者は `:274` の宣言による。テンプレ11 は1名の組織で当たり、組織の中の1名の体制では決まらない。欠陥注入は決まらない(internal.md 3 節)
- 直し: 注記を「常に当たる2つ(根拠: 席の数え方)」と「当たりうる3つ(それぞれの条件)」に分ける。結論(1名は主張できない)は2つだけで導かれるので、帰結は変わらない。意味を変えないので**編集の指摘**(会議体不要)に当たる。ただし「当たりうる」を「常に」に揃えて条文を変える案は採らない。条文は「場合があります」で正しい
- 加えて、`:274` の「1名体制では常に1名以下」は、保持者の定義(本人以外の確認の記録を持つ人)が体制の内に限る語を持たないので、「体制の内の保持者」と書いて揃える。これは意味を足すので、編集でなく定義の欠け(軽の審議)

### 3.2 ADR-0035 決定2 の「代償措置つきの逸脱」(K-2)

- 採用済みの ADR の本文は書き換えない。ADR-0083 決定8 が読み替えを書いている
- 直し: #352 の結論の ADR(新)に「ADR-0035 決定2 の逸脱の語は、措置が無いので閉じた列挙の許可に当たらない。許可としての読みを採らない」を明記する。3.5.3 の `:628` の「本標準は代償措置を定めていない」はそのまま残し、「許可でない」と1行足す
- 採らない案: 認証情報へ措置を新設して決定2 を後付けで満たす案。1.5 のとおり自己申告で、T2 に反する

### 3.3 3.4.3 要求事項6・7(措置に当たりうる文があるのに適用の条件が無い)

- 直し: 要求事項6 に「この登録と受容は、離脱を認める条件でも補う措置でもなく、扱いの手続である。逸脱ではない」を足す。`implementation.md:108` の読み(手続であり措置でない)を本文へ上げる
- 理由: 本文に書かれていないと、読み手は「期限つきの受容」を措置と読んで、1名の体制が「逸脱を伴う適合」へ進めると誤読する。**表示と実態の食い違い**の予防。意味は変えない(既に手続と実装が読んでいる)ので、編集の指摘に近い。ただし文言が「是正の期限」で終わるだけで、**受容の更新の回数・上限**を定めない点は、そのまま残す(新しい義務になるため)

### 3.4 ほかに見つけた食い違い

- 1.10.2 の注記の末尾「別の Issue で審議します」(`:676`)は、#352 の結論で閉じる。閉じ方は「入れないと決めた(根拠 ADR)。再検討の契機は 5.3」。書かれていないのではなく、課さないと決めたと読めるように書く
- 列挙の一致を標準側で確かめる検査が無い(internal.md 6 節)。1.10.2 の表と template の `CLOSED_DEVIATIONS` の一致は template の試験に依る。入れない結論なら変更は無く、この欠けは #352 の範囲外。後継へ寄せる(新規起票は実行で確かめた欠陥だけ)

## 4. 自分の推す案の弱点と、根拠水準マークで開示する点(論点4)

弱点:

1. **T1 の前提**: 「2名は分けられる」は、分けるコスト(人員の専門性、実際に両方の席を担える者がいるか)を見ていない。分けられない2名が実在すれば、避けられない離脱が増える。実証が無い
2. **T2 の物差し**: 「本人以外が確かめる」を措置の成立条件にしたのは、PCI の外部評価者を標準の言葉に移したもの。本標準の自己適合(第一者)の構造では、本人以外の者(同僚)が確かめても独立と言い切れない。D-1 の抜き取りも、誰が抜き取るかが同じ弱点を持つ。**D-1 自体を同じ基準で見直すと弱い**可能性がある。ここでは動かさない(ADR-0029 の決定、発行前の見直しは別の審議)が、基準を一貫させると D-1 の確かめる者の欄が空であることが露見する
3. **排除の影響**: 1名の体制を主張から外すことで失う採用者の数は未観測(EV-0160 は E0)。「採用者が限られる」は市場の事実で、信頼性の論拠でない(external.md O1)ので判断軸には使わないが、実害の大きさを私は知らない
4. **T3 の「同程度」**: 危険の被覆の程度を測る方法が無い。「同程度に覆えない」は監査人の判断で、機械で閉じない
5. **幅の食い違い**: 3.1 の「当たりうる3つ」を残すと、1名の帰結が条文と注記で二重になり、読み手が混乱する。注記を細かくするほど保守の負担が増える

## 5. 統制の閉じ方(論点5)

### 5.1 機械の検査にできる決定可能な条件

| 条件 | 検査の対象 | 状況 |
| --- | --- | --- |
| 席の責任者の同一性(出荷判定者 = 事業決裁者、AI維持管理者 = AI運用担当者) | 名簿と構成の席の割当の一致 | 既に機械が読む(`seatDeviations`) |
| 3名以上の兼務の拒否 | 構成の拒否 | 既に機械(IMPL-0114) |
| 席ごとの認証情報の識別子が重ならないこと | 構成の欄の値の一致 | **欄が無い**(#354)。欄を足せば決定可能 |
| AI の担い手の名義の申告と実行環境の照合 | 申告と記録の一致 | 既に機械(IMPL-0308・0430) |
| 保持者の数(本人以外の確認者・日付・周期内) | 台帳の件数 | 決定可能。欄が無い |
| 技術負債台帳の登録の有無、期限、責任者の記入、期限切れの記載の欠落 | 存在・日付 | 決定可能 |
| 層1 の記名者 = 事業決裁者の一致 | 名簿との突合 | **欄が無い** |
| 判定記録の置き場の履歴の規則 | ホスティングの API | 決定可能。プランに依る(#329) |
| 列挙の表と template の `CLOSED_DEVIATIONS` の一致 | 標準側の検査 | **無い**(後継へ寄せる) |

### 5.2 manual・adopter にして開示する条件

| 条件 | 種別 | 開示 |
| --- | --- | --- |
| 受容の実質(自己完結していないか) | manual | 保証の開示の項目1(「方針を定めた者と受容する者が同一である」の定型の表示) |
| 外部の確認者・名簿の外の確認者の独立 | manual | 確認の記録に所属・役職、プロセス内部監査の観点6 |
| 属人化の危険の大きさ(保持者の育成の実質) | manual | 保証の開示の項目5・7、単一障害点の一覧 |
| 欠陥注入の秘匿が実際に守られたか | adopter | 未測定の開示(附属書I ③、項目6) |
| 「離脱を入れない」という標準の選択の根拠 | 標準 | 根拠水準マーク(4 節) |

機械が閉じない条件を機械で閉じたように見せない。「欄があること」と「欄の値が本当であること」を分ける。

### 5.3 最大の懸念: 機械の名の出力が離脱を数えない(K-3)

- 構成に欄が無い4つ(保持者の数、認証情報の分離、層1 の記名者 × 事業決裁者、欠陥注入の秘匿)は、`claimStatus` が数えない。これら4つだけが残る構成で、機械は「適合の主張」「逸脱を伴う適合の主張」と出しうる(internal.md 5 節)。本文は「述べられるのは適用の表明まで」と定めるので、**表示と実態が食い違う**
- 現状は第1版が未発行で、実際に主張を述べられる構成が無い。いまのうちは実害が出ない。ただし発行の後は「適合」を出す機械の信頼性が、そのまま標準の信頼性になる
- 直し方: (i) 欄を足す(#354)。または (ii) 欄が無い離脱は、機械が「適合」と出さず「未判定(manual の確認待ち)」と出す。(ii) は決定可能で、すぐ入れられる暫定。発行の前に (i) か (ii) のどちらかを閉じることを、#354 の完了の条件に加える
- 巡の数に関わらず直す(表示と実態が食い違う「高」)。#352 の結論は template を変えない「入れない」なので、この件は #352 で閉じず、#354 の優先順位を上げて閉じる

### 5.4 入れない結論での template への影響

- `CLOSED_DEVIATIONS` は D-1 の1件のまま。列挙の表も変わらない
- 変わるのは本文(1.10.2 の注記、3.4.3 要求事項6、3.5.3 の1行、3.5 の限界の1行)と、新 ADR、根拠水準マーク、台帳の再生成
- 回帰の全量は、本文だけの変更なら不要。`npm run check` で足りる。template の試験は関係しない(template を変えないため)
