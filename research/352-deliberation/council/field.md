## 1. 規定ごとの結論

### 1.1 評価の基準(現場の目)

- 代償措置が**実際に回る**か。回るとは、小さい体制の人が、定常の作業の中で、追加の時間をほぼ掛けずに実施し、第三者が記録で確かめられること
- 措置の実施者と確かめる者が**同一人物**になるなら、その措置は牽制として働かない。働かない措置を「代償」と呼んで逸脱へ入れれば、適合の名が実態を超える(ADR-0029 の「独立性の回復として扱わない」と同じ線)
- 措置が**制約をさらに増やす**ものなら、実害は小さい体制が最も受けやすい。例: 決定の度に追加の突合を課す措置は、1名では週の作業量の1割を超えうる(単一の見立て。4 節で開示)

### 1.2 入れるもの: コア機能の理解の保持者(3.4.3 要求事項6・7)

なぜこれだけ入れるか。D-1 の4要素(許可の語、適用の条件と失効、代償措置、限界の明記)に対し、既存の文が措置を3つ持つ。

- 技術負債台帳への登録(期限・責任者)。期限を過ぎた受容は記載の欠落(`assurance-case.md:566`)で、機械が数えられる
- 該当する種別の委任(L3)の停止(5.4.6、ADR-0081 決定4・6)。**これは実質の牽制である**。保持者が1名のあいだ、AI への任せ方を自ら狭める。小さい体制にとっては痛みのある措置で、形だけとは言えない
- 保証の開示の項目5・7 と単一障害点の一覧への表示

欠けるのは、許可の語と適用の条件だけである。ここは新しい義務ではなく、既存の扱いに名前と境界を与える作業になる(ただし 4 節のとおり、審議の段は議長が決める)。

条文案(3.4.3 要求事項6 を次のとおり置き換える):

> 6 コア機能の理解の保持者が**ちょうど1名**の状態は、次の4つをすべて満たす場合に限り、逸脱(D-2)として認める。(1) 是正の期限と、確認を受ける予定の者の名を技術負債台帳(テンプレ3)へ登録する (2) 層1 の権限者が期限つきで受容する。**受容する者は、保持者本人であってはならない** (3) 該当する種別の委任(L3)を、5.4.6 のとおり止める (4) 保証の開示の項目5・7 に、受容の更新の回数とともに表示する。条件を満たさない状態と、保持者が0名の状態は、逸脱ではない(後者は 3.4.3 要求事項5 の後継不在のうち、保持者がいない席として扱い、列挙に無い離脱のままとする)

措置を誰が何の記録で確かめるか。

| 措置 | 確かめる者 | 記録 |
| --- | --- | --- |
| 台帳への登録と期限 | 機械 | 技術負債台帳の行(期限・責任者・予定者)。期限切れは記載の欠落 |
| 受容者が保持者本人でない | 機械(名簿の ID の一致)。同一人物の複数名義は機械で閉じない(4・5 節) | 受容の記名と、保持者の確認記録(要求事項8)の被確認者 |
| 委任の停止 | 機械(構成の委任の欄。欄が無ければ undelivered) | 構成と判定記録 |
| 更新回数の表示 | 機械 | 保証の開示の項目5・7 |
| 受容の判断の妥当性 | 層1 の権限者(manual) | 受容の記名と理由 |

1名の体制がどうなるか。受容者が本人以外という条件で、**1名の体制はこの規定の逸脱へは入れない**。入れれば、受容者=保持者=記名者となり、「期限つきの受容」は自分が自分に出す延長になる。是正の期限は体制が増えない限り果たせず、更新が続く。実害の例: 毎月、台帳の期限を自分で延ばす作業だけが増え、手戻りは何も減らない。

2名の体制がどうなるか。保持者が1名(もう1人は着任したばかり、など)の期間は、もう1人が受容者になり、委任を止めつつ主張を続けられる。保持者が2名になれば離脱が消える。**現場で最も多い実態に合う**。

### 1.3 入れないもの

**出荷判定者 × 事業決裁者**(行2)

- 理由1: 守るのは「異議を書く者と残存リスクを受容する者が別の自然人である」という前提(ADR-0056 決定5)。兼務は前提を壊す。措置で補えるのは周辺(記録・抜き取り)だけで、「受容の自己完結そのものは消えない」(`assurance-case.md:973`)
- 理由2: D-1 は G-7 が単独で実行できるから認められた(ADR-0029)。G-8 の受容は単独で達成できない。基準が逆である
- 現場の例: 1名が「抜き取り確認」を措置として置いても、確認するのも記録するのも自分で、結果は常に「問題なし」になる。措置を増やしても手戻りは減らず、記入の有無の検査に落ちる(ADR-0082 決定1 が退けた型)
- 2名なら人を分ければよい。分けない選択は決定として記名する(現行どおり)

**AI維持管理者 × AI運用担当者**(行3)

- 理由は行2 と同じ。守るのは全社の統制(接続・予算・停止条件)を案件の都合で緩める経路を断つこと。1名が両方を持てば断てない。措置の候補(第三者による接続設定の定期確認)は、確かめる者が体制の外に要る。1名の体制にそんな者はおらず、外に頼むなら「外部の確認者」の席(独立レビュアに限る。ADR-0127 決定1)の話になり、#352 の外へ出る

**層1 の記名者 × 事業決裁者**(行5)

- 1名の組織は、上位者がいないから本人が記名する。ここへ代償措置を書くと、「自分が自分の方針を、自分で確認する」措置になる。**開示(項目1「方針を定めた者と受容する者が同一である」)で足りる**。主張の可否は変わらなくても、読み手には十分に伝わる
- 組織の中の1名の体制で、上位の者が層1 を記名するなら当たらない。この区別を 1.10.2 の注記に書く(3 節)

**認証情報の分離**(行6)

- 現場の実態: 1名でも、実行主体ごとにトークン・アプリを分けることは数十分でできる。分けない理由は怠慢や費用であって、規模ではない
- 逸脱に入れると、「分けていないが逸脱として適合を主張した」構成を認めることになる。ADR-0035 決定2 が「代償措置つき」と書いたが、措置は一度も書かれなかった。**書かれなかったものは、措置が無いと判断すべきである**。措置を新しく発明すると、効果を定義できない措置になる
- 費用で分けられない事情(有償の席が増える等)は、Green Book OV4.17(費用だけでは統制を実施しない理由にならない)に当たる。採らない

**AI の名義の共有・未申告**(行7)・**判定記録の置き場**(行8)

- 行7 は専用の名義を作って申告し、照合すれば解ける。措置を置く意味が無い
- 行8 は、2.4 に述べる実害が小さい体制に偏る。ただしプラン依存の問題で、#329 の「配備の統制がプランに依る」と同じ型。#329 の結論に従う。ここでは**単独で列挙へ入れない**

**欠陥注入の秘匿**(行4)

- 附属書I 要件③は「見つける者が注入した者と同じ層は、測定値として記録しない。その層は未測定として扱う」と書く。つまり**扱いは既に決まっている**。この状態を「列挙に無い離脱」としても数えると、同じ事実が二重に主張を妨げる(未測定と離脱)
- 直しは、離脱の表からの削除ではない(それは主張を緩める向きの変更で、議長の裁定が要る)。まず「成立しない場合」の定義を、注入者を体制の外(別の採用者の同業者など)に置ける経路を明記する側で直す。1名でも、導入前の検証の1回だけなら外の者に頼める(IMPL-0162)。経路が実在すれば「成立しない」は減る
- 経路が使えない場合は未測定として開示する(要件③)。これを離脱と見るかは議長の裁定に委ねる。私の推しは、**離脱の表から外して未測定へ一本化**。ただし未検証(4 節)

## 2. 1名・2名の体制の扱い

### 2.1 主張できないことの実害(現場の例)

- 例1: 1名の受託開発者が、発注元の調達から「本標準への適合」を求められる。全項目を実施しても、述べられるのは「適用の表明」までで、実施した1名と何もしていない組織の表示上の差が小さい。**差が出ないなら、標準を実施する動機が薄れる**
- 例2: 動機の薄れた先に、**名目の2人目**を名簿へ載せる偽装が起こりうる。家族や知人を出荷判定者に置く(ADR-0122 に、同一人物の複数名義を記録つきで受ける先例がある。名簿の外の確認者は ADR-0127 が席ごとに限る)。標準が実態の分かれ目を作ると、分かれ目をまたぐ偽装が出る。これは主張の可否の線を引く限り避けにくい
- 例3: 小さい体制ほど、全部の離脱が「構造的」(人数の問題)なのか「選べる」(トークン・名義・置き場)なのか区別されないまま、適用の表明に並ぶ。選べる離脱を直す動機が失われる

### 2.2 主張できることの実害

- 例4: 1名が自分を出荷判定者・事業決裁者・受容者・記名者として、自己の抜き取りを措置に「逸脱を伴う適合の主張」を出す。読み手(発注元・監査)は「適合」を信じて発注する。事故のとき、「適合していた」が盾になる。**実態は受容が全部自己完結している**。これは標準が他組織の規格として負うべき信頼性を直接損なう(コアポリシー)
- 例5: 措置が形だけになると、実施者は措置を「やった記録」だけを残す。記入の有無の検査に落ち、手戻りは減らず、オーバーヘッドだけが残る(ADR-0082 決定1 の型)
- 例6: 外部の先例は、1名への具体的な代償を認めていない(`external.md` C5「確認できず」)。PCI の代償統制は外部の評価者が審査する。自己審査の1名には当てはまらない

### 2.3 推す案: (a) + (d)

- (a) 1名は主張できないままにする。理由は 1.3 のとおり、失われるのが措置で補えない前提(受容の分離)だから。外部の先例の骨組みでも、独立性が要る水準では主張できない型(T4。SLSA、26262、DO-178C)が支える
- (d) 主張の名を増やさず、適用の表明に載る離脱を機械が**2つに分けて出す**。
  - 構造的な離脱: 人数が減れば消える(行1〜5。保持者・兼務・記名者)
  - 選べる離脱: 構成の選択で消える(行6〜8。認証情報・名義・置き場)
  - 意図: 例1 の「差が出ない」と、例3 の「直す動機の喪失」に答える。1名が「選べる離脱がゼロ」と示せれば、調達の読み手に、残る問題は人数だけだと伝わる
  - 範囲: 名は変えない。**新しい義務は課さない**。表示の分類の追加である
- (b) を推さない理由: 例4 と例6。1名の自己牽制を措置と呼ぶ先例が無い
- (c) を推さない理由: プロファイルを分けると、「適合」が体制の規模で意味の違う語になる。ADR-0068 決定6 と 1.2 は「適用」と「主張」を分けている。ここへ規模別の要求の組を足すと、第8章 軸E(CL1 以上と規制業は1〜2名を認めない)と二重になる。29110 は安全重要を対象外にする型で、本標準の区分との対応が先例から導けない
- ADR-0029 との矛盾: 無い。D-1 は3名未満の G-7 兼務だけで、(a)(d) は触れない。行1 の追加は「広げません」の文(`:580`・`:456`)に当たらない(兼務の組を足すのではなく、別の項目 D-2 を足す)。ただし文面の整合を 3.5.2 に注記する
- ADR-0081 との矛盾: 行1 の条件(3)が委任停止を維持する。委任停止の「該当する種別」の読みと、第8章の極小規模への事後監査の関係は、internal.md K-4 のとおり**未確認**。ここで確かめられていない

## 3. 現行の条文の中の食い違いの直し方

### 3.1 1.10.2 の注記と条文の幅

- 食い違い: 注記は4つが「常に当たる」と書く。字義で常に当たるのは、出荷判定者×事業決裁者、AI維持管理者×AI運用担当者(席の責任者は体制の内に数えるため)。保持者は `:274` の宣言による。注入は「場合があります」。テンプレ11 は「1名の組織」
- 直し方: **条文へ揃える**。注記は条文の要約であり、要約が条文を超えてはならない。注記を次の形に直す
  - 常に当たる: 出荷判定者×事業決裁者、AI維持管理者×AI運用担当者
  - 当たる場合がある: 保持者(受容者が保持者本人のとき、または保持者が0名のとき)、注入の秘匿(注入者を体制の外に置けないとき)、テンプレ11(1名の組織のとき)
- これは意味を変えない編集に近いが、「常に」を外すと1名の帰結の根拠が2つに減る。帰結は変わらない(internal.md 3 節)
- `:274` の「1名体制では代理者も置けない」の宣言は、保持者の定義(本人以外の者が日付を付けて理解を確認した記録を持つ人)に「体制の内」の限定が無いこととずれる。**外部の者が保持者になりうるか**は新しい義務ではなく定義の問題だが、緩める向きなので議長の裁定と #351 の結論を待つ。ここでは直さない

### 3.2 ADR-0035 の「代償措置つきの逸脱」

- ADR-0083 決定8 の読み替えで形は解けている。**措置は書かれていないので、無いものとして扱う**(1.3)
- 採用済み ADR は書き換えない。新しい ADR(本件の裁定)で、ADR-0035 決定2 の「代償措置つきの逸脱」は措置を持たず、列挙に無い離脱として扱う旨を明記して置き換える。3.5.3 の「本標準は代償措置を定めていない」は維持する

### 3.3 3.4.3 要求事項6・7 の「適用の条件が無い」点

- 1.2 のとおり、要求事項6 に許可の語と4つの条件を置く。要求事項7(出荷を止めない・表示し続ける)は、D-2 になっても維持する
- 1.10.2 の表から保持者の行を削り、D-2 の行を閉じた列挙の表(`:635-637`)に足す。注記の「2名の体制が主張に至る6条件」の4つ目を「保持者が2名、または D-2 の条件を満たす」に直す
- 「別の Issue で審議します」(`:676`)の文は、本件で閉じる

### 3.4 Issue の一覧に無い2行

- 審議の範囲に含める。入れない結論を、理由とともに残す(却下は成果)

## 4. 推す案の弱点と、実証を欠く点

弱点:

1. 行1 の条件(2)「受容者が保持者本人でない」は、名簿の ID では機械で閉じるが、**同一人物が2つの名義を持つ**ことは閉じない(ADR-0122 は3名の同一人物の記録つき承認を受ける先例)。偽装は残る。adopter の申告にして開示する
2. 行1 の更新に上限を置いていない。上限の根拠が無いからである。更新の回数を開示するだけでは、延長が続く弊害を止めない
3. (d) の分類(構造的・選べる)は、調達の読み手が読む保証が無い。読まれなければ例1 は解けない
4. 行4 の「離脱から外して未測定へ一本化」は、主張を緩める向きで、5 委員の議論と議長の裁定が要る
5. 行8 は、小さい体制に偏る実害を持つのに、本件では何も解かない
6. 偽装(例2)は、(a) でも (b) でも出る。標準は偽装を機械で防げない

根拠水準マーク(暫定)で開示すべき点:

- 行1 の D-2 は、実施の実績が無い。保持者の最低数 2 の根拠は E2(EV-0071)で、「ちょうど1名なら逸脱として認めてよい」という線は未検証 → `:::caution[暫定 EV-NNNN / 見直し 2027-XX]` を新設。見直しの契機は、EV-0160 の観測(主張をできなかった採用者の件数)に結ぶ
- 「1名の追加の突合は週の作業量の1割を超える」という見立ては**単一の実務の見立て**。数値は条文に入れない。入れるなら E0 でマークする
- 「名目の2人目の偽装が起こる」は予想であり、観測は無い(第1版未発行)。条文の根拠にしていない。(d) の動機の説明に留める
- 外部の先例: 1名の開発者への代償を認める規格は見つからなかった(`external.md` C5)。これは「無い」の証明ではない。その空白を根拠に (b) を退けているので、確度は中程度

## 5. 統制の閉じ方

機械の検査にできる(決定可能な条件):

| 条件 | 判定 |
| --- | --- |
| 保持者数がちょうど1(0・2以上と区別) | 構成の欄の値(欄は #354 が持つ。現状は undelivered) |
| 台帳に是正の期限と予定者の名があり、期限が未経過 | 存在・日付の比較 |
| 受容者の ID ≠ 保持者の ID | 名簿の ID の一致 |
| 該当する種別の委任が停止の状態 | 構成の値 |
| 受容の更新回数の表示の存在 | 開示の出力の存在 |
| 離脱の分類(構造的 / 選べる)の出力と、本文の表の一致 | 値の一致 |

manual にして開示する:

- 受容者の判断の妥当性(自由な文の意味)
- 予定者が実際に保持者になる見込み(是正の実効)
- 確認記録の質(本人以外の者が日付を付けて確認した、の実質)

adopter にして開示する:

- 同一人物の複数名義(改ざんの防止は機械で閉じない)
- 注入者が体制の外にいること(誰が外の者かは自己申告)

順序の制約: **#354 が先**。構成に欄が無い状態で D-2 を足すと、機械は保持者の数を読めず、`claimStatus` が「逸脱を伴う適合の主張」を実態より緩く出しうる。表示と実態が食い違う「高」に当たるので、D-2 の機械の検査は undelivered の表示つきで先に載せ、#354 の後に delivered へ上げる。template の `CLOSED_DEVIATIONS` と `category: 'unlisted'` の既存構成は、移行の経路が要る(internal.md 5 節)。標準側に表と `CLOSED_DEVIATIONS` の一致を確かめる検査が見つからない点は、D-2 を足す前に埋める。

審議の段の所見: 行1 は「採用者への新しい義務」ではなく既存の扱いの名付けだが、離脱を逸脱へ移す(主張の可否が変わる)ので、**重**の範囲に当たるかは議長が決める。行2〜8 を「入れない」とする結論は現状維持で、決定の記録(採らない案の記載)があれば足りる。
