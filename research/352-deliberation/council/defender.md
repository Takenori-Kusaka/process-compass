## 1. 規定ごとに、入れるか

### 1.0 総論(全規定に共通の論拠)

1. 列挙に無い離脱は罰ではない。「適合」という名を、実態が伴う状態にだけ許すための区別である。入れないことで失うのは名であり、適用の表明と記録・開示は残る(1.2・1.4、ADR-0068 決定6 は適用と主張を分けている)
2. 規格は、離脱に道を用意するとき、**外部の評価者が十分性を審査する**(PCI 付録B)か、**努力義務に落として代償を書かない**(ISO 19011、SOC 2)かのどちらかである。自己が自分の代償の十分性を判定する型は、外部の調査に見当たらない。1名・2名で列挙へ入れると、判定者の独立が最初に崩れる。これは本標準が D-1 で「独立性の回復ではない」と自ら認めた限界を、より重い場面へ持ち込むことになる
3. 1名の開発者に規格が認める個別の代償は、確認できなかった(external.md 確かめられなかった点6)。先例の無い措置を本標準が発明すると、#313 Q-3「新しい条件を発明しない」に反する。#352 が問うのはその発明の可否であり、可否の答えが「発明の根拠が無い」なら、入れないことが裁定である
4. ADR-0082 決定1: 「兼務で失われる牽制を、どの措置が補うかを特定した記録がありません。何を確かめるかを定義できない確認は、記入の有無の検査に落ちます」。措置を足すほど、検査が実質を確かめず、名だけが「逸脱を伴う適合」へ上がる。信頼性の軸ではこれが最悪の帰結である(記入の有無で適合を名乗れる)
5. EV-0160(閉じた列挙の運用)は E0 で、観測が無い。ADR-0083 決定7 は「同じ離脱が繰り返し主張を妨げていれば、条件と措置を定めて加えるかを改訂で検討」と観測を契機に置いた。第1版は未発行なので観測はゼロである。観測の無い拡張は、実証を欠く条項を増やす(ADR-0026 の趣旨に反する)

### 1.1 3.4.3 要求事項6・7(保持者1名以下)

最も入れる案が強い規定なので、最も丁寧に反論する。

- 形は近い(登録・期限つき受容・表示・委任の停止)。それでも入れない理由:
  - 守る危険が違う。D-1 の G-7 は出荷ごとの品質確認で、措置(突合・抜き取り)が目的に直接効く。保持者は組織継続の危険で、期限つき受容は危険を**先送り**する手続であり、補わない。期限を過ぎれば記載の欠落になる設計は、先送りが解決でないことを条文自身が認めている
  - 1名の体制では是正の期限を果たせず、受容の更新が続く(internal.md 2 節)。更新が続く状態を「逸脱」の名で適合へ数えると、恒久の離脱が恒久の適合の主張になる。D-1 は3名以上で失効する構造(一時的な状態)だが、ここには失効する条件が無い
  - 5.4.6 と ADR-0081 決定4・6 が、既に「委任(L3)を止める」という帰結を付けている。ここへ列挙入りの意味を足すと、委任の停止と主張の可否が二重の仕組みになる。止める範囲の読みは未確認(K-4)で、確かめないまま重ねるのは危ない
- 入れるなら必要な文案は次のとおり。採らない案として記録する
  - 条件: 「保持者が1名以下で、是正の期限と責任者が技術負債台帳に登録され、層1 の権限者が期限つきで受容している間に限り、逸脱として認める」
  - 措置と確認者・記録: 台帳の登録(確認者: 層1 の権限者、記録: 台帳の行と受容の記名)。期限の超過の検査(機械。日付の比較)
  - 弱点: 層1 の権限者が1名の組織では本人なので、受容の自己完結(確認者の独立性が無い)。措置の効果(属人化の緩和)は測れない。EV-0071(最低数2)は E2
  - よって採らない。ただし「入れない」と「現行の文が曖昧」は別で、1.10.2 の食い違いは 3 で直す

### 1.2 出荷判定者 × 事業決裁者

- ADR-0029 の基準は「1人で目的を達成できるか」である。G-7 は突合と判定が単独で実行できる。G-8 の異議と受容は、書く者と受容する者が別の自然人であることを前提にする(ADR-0056 決定5)。前提が欠ける場合は G-6 と同じく目的が欠ける。ADR-0029 の自らの線引きを守るなら、入れない
- 3.5.2 が「この例外ではなく」「広げません」(`roles-responsibilities.md:580`)と書く。広げないと明記した条項を、同じ版で広げる整合は取れない
- ADR-0122 決定4・5 は、2人以上での兼務を決定として記名で受け付け、1名の自己の決定も記録つきで受け付ける。開示は既にあり、足りないのは**名**だけである。名のために措置を発明する理由が無い

### 1.3 AI維持管理者 × AI運用担当者

- 守る危険(案件の都合で全社の統制を緩める経路)に対し、効果を定義できる措置が思いつかない。「別の者が事後に確認する」は、確認者が体制の内に居ないと成立せず、居れば兼務は不要
- 1名は両方の席を本人が持つ。2名は分けられる。構成の選択で解ける範囲が広く、例外を設ける必要が小さい

### 1.4 欠陥注入の秘匿

- そもそも離脱の表に置くのが正しいかを疑う。附属書I 要件③ は成立しない層を「未測定」と定め、保証の開示の項目6・成立条件5 へ出す。つまり**効力と表示の扱いは別の所で定まっている**。条文は外の者が注入すれば成り立つかを書かない(internal.md 3 節)
- 直し方: 「常に当たる」から外し、「注入する者を体制の外に置けない構成のとき」と限定する。表に残すなら、扱いは未測定であって列挙の対象ではない旨を行に書く(限定を別の段落へ置かない。#226)

### 1.5 テンプレ11 要求事項5(層1 の記名者 × 事業決裁者)

- 席ではなく組織の最高位の者の記名なので、「1名の組織」でのみ必ず当たる。組織の中の1名の体制では、上位の者の記名で解ける。措置を足す以前に、**対象を正しく書き直す**のが先
- 入れない理由は 1.2 と同じ(受容の基準を自分で定め、自分で受容する。措置で回復しない)

### 1.6 資格情報の分離

- ADR-0035 決定2 は「代償措置つきの逸脱」と呼びながら、条件も措置も挙げなかった。実装(3.5.3 `:628`)は「本標準は代償措置を定めていない」と書き、ADR-0083 決定8 が列挙に無い離脱と読み替えている。つまり**呼び名だけが許可で、内容に許可が無い**
- 分けるかどうかは採用者が選べ、1名でもトークンは分けられる。選べる離脱を許す理由が最も弱い規定である。入れない
- 直し方は 3 で示す

### 1.7 Issue の一覧に無い2行

- 審議の範囲に含める。含めたうえで入れない。どちらも採用者の構成の選択(専用の名義、ルールセット)で解ける。解ける離脱は、解いた構成が適合へ至る道であり、例外は不要
- 範囲に含める理由: 一覧に無いことで審議から漏れると、「Issue が挙げた5つだけが原因」という誤読が定着する。列挙に無い離脱の全行が対象と明記するほうが、読み手が「課さないと決めた」を区別できる

## 2. 1名・2名の体制の扱い

推し: **(a)**。ただし単なる放置にしない。次を併せて書く。

- 1名の体制は適用の表明(1.2、ADR-0068 決定6 は含めることが成立条件を満たすことを意味しないと明記)まで。2つの主張は、第1版以前でも以後でも出せない
- 理由を明記する: 出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者が必ず同じ人になる(ADR-0127 決定1)。そのうえで、**この帰結は条項から導かれる**(internal.md 3 節。1つで足りる)ので、列挙をどう動かしても、2組の両方に措置を書かない限り帰結は変わらない
- 2名の体制は現行の6条件で主張に至る。残るのは D-1 だけで、2名向けに足す必要が無い
- (b)「列挙へ入れて主張を可能にする」: 1.0 と各規定の反論のとおり。「逸脱を伴う適合」という名が、独立性の無い構成に与えられる。EV-0160 の観測も無い
- (c)「体制の規模でプロファイルを分ける」: 外部の先例(29110 は安全重要を対象外にする。本標準の CL・R との対応は導けない)があるだけで、実証を欠く。「適合」の意味が増える(external.md O3 の弱点)。第8章 軸E が CL1 以上と規制業の1〜2名を認めない点と、プロファイルが別の線を引く点で食い違いを生む。ADR-0068 が「適用」と「主張」を分けた設計は、プロファイルを要せず、小さい体制を適用に含めたまま主張だけを締める。(c) はその設計の二重化になる
- (d) そのほか: 名を作る案(例: 「簡易適合」)は、「適合」と「適用の表明」の間に第三の主張を足すだけで、市場のための名である。採らない
- ADR-0029 との矛盾: 無い。3名未満の G-7 の兼務だけを認め、ほかへ広げない、という ADR-0029 の線を、そのまま維持する
- ADR-0081 との矛盾: 無い。保持者1名以下の委任の停止は列挙と無関係に効く。ただし「止める範囲」の読み(K-4)は別に確かめる必要があり、本意見は確かめていない(弱点に記す)
- 所有者の確認(X-9)が記録に無い。「帰結として受け入れる」を、本審議の記録として所有者へ確かめ直す

## 3. 現行の条文の中の食い違いの直し方(弁護しない)

### 3.1 1.10.2 の注記(`overview.md:660`)の幅

- 食い違い: 注記は4つの規定が「常に当たる」と書くが、字義どおり常に当たるのは2つ
- 直し方(文案): 「常に当たる」を2つ(出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者)に限る。残る規定は表の行の中に限定を書く
  - 保持者1名以下: 「保持者の数が1名以下である機能がある構成」(コア機能を持たない案件には当たらない旨も書く)
  - 欠陥注入の秘匿: 「注入する者を体制の外に置けない構成」
  - 層1 の記名者: 「1名の組織」(組織の中の1名の体制では、上位の者が記名するなら当たらない)
- 人数の数え方は #351 が未決なので、「体制の内」の定義は #351 に依ると書き、ここで決めない
- ADR-0083 決定7 の「常に当たる」の語は、新しい記録(追記)で訂正する。採用済みの本文は書き換えない

### 3.2 ADR-0035 決定2 の「代償措置つきの逸脱」

- 食い違い: 措置が書かれていない。ADR-0083 決定8 の読み替えで形の上は解けているが、「許可に当たるか」が #352 へ送られたまま
- 直し方: #352 の裁定の記録(新しい ADR か ADR-0083 への追記)で、「ADR-0035 決定2 の『代償措置つきの逸脱』は、列挙に無い離脱の意であり、措置は定めていない」と述べる。K-2 を閉じる
- 3.5.3 の `:628`「本標準は代償措置を定めていない」は正しい。変えない

### 3.3 3.4.3 要求事項6・7

- 食い違い: 措置に当たりうる文があるのに、適用の条件が無い
- 直し方(文案): 要求事項7 の末尾へ「この手続は離脱の許可ではない。期限つきの受容の間も、この状態は列挙に無い離脱として 2 つの主張を妨げる」を足す。「是正の期限」は直すべき状態として扱う語であり、認める語でないことを明示する

## 4. 弱点と、根拠水準マークで開示すべき点

私の案の弱点は次のとおり。

1. 市場の事実: 1名の体制を恒久的に排除する。これは信頼性の論拠ではない。採用者が離れる、または名乗らずに「実質的に従っている」と言い出す(偽の主張)危険がある。名が無いことを理由に統制が下がるなら、逆効果になりうる
2. 観測の欠如: 「入れない」も実証に基づかない判断である。EV-0160 の E0 に拠る。入れる案と同じく、暫定である
3. 3.4.3 は最も入れる案が強い。是正の期限が体制の増加でしか果たせない以上、「受容の更新が続く」状態を適合に数えない選択は、1名の組織にとって実務上の拘束が重い。私は組織継続の危険と品質確認の危険を分けたが、この線引きは調査に根拠が無い(私の議論であり、外部の先例に無い)
4. 機械が読まない4つの離脱(コア保持者、認証情報、層1、欠陥注入)がある限り、`claimStatus` は「適合」または「逸脱を伴う適合」と出しうる。本文は妨げると書くが機械が数えない。入れないと決めても、表示と実態の食い違いが残る。これは巡の数によらず直す対象(表示と実態が食い違う「高」)に当たる。#354 の順序を守る
5. 外部の先例は二次情報が多い(PCI のみ原文)。「自己審査の型が見当たらない」は、見つからなかっただけで不在の証明ではない
6. ADR-0081 の委任停止の範囲(K-4)を確かめていない

開示の案:

- 暫定マーク `:::caution[暫定 EV-NNNN / 見直し 2027-05]`: 「閉じた列挙を D-1 だけに保つ判断は、採用者の観測に基づかない。主張をできなかった採用者の件数を集める経路は未整備(#338 の裁定により規模のデータを受け取る経路を持たない)」。見直しの契機は EV-0160 の観測
- 暫定マーク: 「保持者の最低数 2 を離脱の判定に使う根拠は E2(EV-0071)」。既存のマークの再掲で足りるかは議長が決める
- 識別子は連番で再利用しない。追加後は `npm run evidence:write`

## 5. 統制の閉じ方

### 5.1 機械の検査にできる決定可能な条件

- 1.10.2 の閉じた列挙の表の項目と、template の `CLOSED_DEVIATIONS` の項目の**識別子の集合の一致**。現状、この一致を確かめる検査は見つからない(internal.md 6 節)。「入れない」を選ぶ場合ほど、列挙が D-1 だけであることを両側で固定する検査が要る(一致は値の存在・構文の検査で閉じる)
- 1.10.2 の「列挙に無い離脱」の表の行が参照する節番号・ADR 番号・規定の実在(`npm run lint:refs` の延長)
- 注記が挙げる規定名が、表の行に実在すること
- 3.4.3 の期限つき受容: 技術負債台帳に是正の期限と責任者が登録されているか(存在)、期限が過ぎていないか(日付の比較)、期限超過が記載の欠落として出るか。ただしこれらは**手続の遵守**の検査で、主張を回復する検査ではない
- `claimStatus` が、構成に欄のある離脱(席の兼務2組、AI の名義、記録用ブランチ)を数えること。既存

### 5.2 manual または adopter にして開示する条件

- 保持者の「理解の確認」の実質(本人以外が日付を付けた記録の中身): manual。自由な文の意味
- 層1 の記名者が最高位の者かどうか: adopter(採用者の申告)。根拠水準マークで開示
- 欠陥注入の秘匿が成立しているか(注入者が体制の外か): adopter
- 資格情報が席ごとに分かれているか: 現在、構成に欄が無く機械が読まない。manual。#354 が欄の要否を持つので、それまで `undelivered` の表示を消さない(IMPL の状態を `undelivered` に保つ)
- 受容の自己完結(同一人物による異議と受容): 機械で閉じない。保証の開示の項目1 への表示(定型)で開示し、閉じたとは言わない
- 「措置の十分性」を機械で確かめるとは言わない。仮に列挙へ入れるなら、十分性は manual、記録の有無だけ機械という切り分けになるが、有無の検査だけの統制は ADR-0082 決定1 が退けた型である。これも入れない理由の1つ

## 6. 採らない案(記録用)

| 案 | 採らない理由 |
| --- | --- |
| 3.4.3 要求事項6・7 を列挙へ入れる | 措置は先送りで、失効の条件が無い。受容の自己完結 |
| 兼務の2組へ措置を新設して入れる | 効果を定義できず、記入の有無の検査に落ちる(ADR-0082 決定1)。独立性は措置で回復しない |
| 資格情報を「許可」として確定する | 内容の無い許可。採用者の構成の選択で解ける |
| 1名向けのプロファイル(C) | 適用と主張を分けた ADR-0068 の設計の二重化。外部先例は安全重要外 |
| 1名向けの第三の主張の名 | 市場のための名。信頼性の根拠にならない |
| 要求を「実行可能であれば」へ条件つきにする(O4) | 条件が開いていて機械の検査にならない。「適合」と「列挙に無い離脱」の線が曖昧になる |
