## 論点1 規定ごとの判断

### 1.1 入れるかどうかの判定基準(本意見が使う物差し)

外部の先例のうち、条件が具体で原文を読めたのは PCI DSS 付録B・C だけである。これと、本標準の先例 D-1(ADR-0029)を合わせて、次の6つを「入れてよい最小の条件」とする。1つでも満たさなければ入れない。

| # | 条件 | 出どころ |
| --- | --- | --- |
| P1 | 満たせない理由が、正当で文書化された制約である(都合や費用ではない) | PCI 付録B 入口、Green Book OV4.17【抜】 |
| P2 | 離脱の後も、要求の目的の一部は1人で達成できる。欠けるのは独立性など、特定できる一点だけ | ADR-0029 の G-7 と G-6 の線引き |
| P3 | 措置は、ほかの要求で既に求めている統制を数えない(above and beyond) | PCI 付録B 3・4a【原】 |
| P4 | 措置の十分性を、離脱の当事者ではない者が、記録で確かめられる | PCI 付録B(評価者の審査)【原】 |
| P5 | 措置が回復するのは何で、回復しないのは何かを明記する。「他へ広げない」を明記する | D-1 の `:580`・`:589`、ADR-0029 |
| P6 | 適用の条件と失効が、決定可能な値で書ける | D-1 の「3名未満。3名以上で失効」 |

PCI は外部の資格者が十分性を判定する。本標準は自己申告の宣言であり、P4 を満たす第三者を前提にできない。この差が、P4 の厳しさの根拠である。外部の確認者を置ける席が独立レビュアに限られる(ADR-0127 決定1)ことも、P4 を満たせる規定を絞っている。

### 1.3 3.4.3 要求事項6・7 を入れない理由(最も迷った規定)

internal.md は、この規定だけが措置に当たりうる文(登録・期限つき受容・表示・L3 の停止)を持つと整理した。私は次の3点で、措置ではなく是正の手順と読む。

1. 期限つきの受容と是正の登録は、離脱を解消するまでの管理である。PCI 付録B 1・2 の「元の目的と同程度の防御」には当たらない。受容している間も、理解の保持者がいない危険(属人化)は同じ大きさで残る
2. 防御として働くのは L3 の停止(ADR-0081 決定6)だけである。これは 5.4.6 が独立に定めており、離脱を列挙へ入れても入れなくても働く。措置として数えるなら P3 により「ほかの要求で既に求める統制」になる
3. 1名では是正の期限が果たせない(`:274`)。期限つきの受容を延々と更新するだけの状態を「逸脱」と呼ぶと、逸脱の定義(条件と代償措置を定めて認めたもの)が内側から崩れる。P6 の失効が成立しない

2名以上で保持者が一時的に1名以下になる場合(退職の直後など)は、実態として是正中の不適合である。ISO の監査や認証で、是正計画つきの軽微な不適合を適合と呼ばない扱いがあるのは私の知識の範囲で、原文は確認していない(外部の調査は触れていない。【未】)。仮にこの型を採るなら「逸脱」ではなく別の語が要り、閉じた二分(逸脱 / 列挙に無い離脱)に三つ目の区分を足す。語彙の増加は ADR-0083 の設計と衝突するので、今回は採らない。

採らない案(記録): 「2名以上で、期限・責任者・受容・L3 停止がそろえば、期限内に限り D-2 とする」。理由は上の1と2。EV-0071(最低数2。E2)の実証が弱いことも、新しい許可を置く支えにならない。再検討の契機は、EV-0160 の観測で「一時的な欠員」で主張を失った採用者が繰り返し現れること。

### 1.4 兼務の2組・層1の記名者を入れない理由

- 3.5.2 は D-1 を「他の禁止の組み合わせへ広げません」と書き、`:456`・`:388` は代償措置を定めていないと書く。ADR-0082 決定1 は「何を確かめるかを定義できない確認は記入の有無の検査に落ちる」として措置を置かなかった。同じ状況で今回だけ措置を足す根拠が、調査に出ていない
- 考えうる唯一の措置は、体制の外の者(組織上の任命権者など)の共署による受容である。PCI の外部評価者に最も近い。ただし (i) ADR-0127 決定1 の席の限定と衝突する、(ii) 体制の人数の数え方(#351)に触れる、(iii) 新しい採用者への義務になる。いずれも「重」の領域で、本件の範囲を超える。採らないと決めた案として記録する。契機は、外部の共署を求める採用者の需要が観測されること
- 2名の体制では、別の人を置けるので P1 を満たさない。入れると、分けられる者が分けずに逸脱を名乗る道ができる(D-1 の「3名未満」は人数で閉じているが、分けるかどうかは選べる点が違う)。ここが ADR-0029 の「1人で目的を達成できるか」の線を、この2組は越えている

### 1.5 欠陥注入の秘匿

兼務の組ではなく、測定の有効条件である。附属書I ③は、成立しない層を「未測定」として開示するところまで定めている。これは OpenSSF Scorecard の「結論なし」(【抜】SRC-0574)に似た、合否とは別の第三の状態である。したがって措置を足して逸脱にする必要は無い。

気になる点: 未測定として既に開示される離脱を、さらに「列挙に無い離脱」として主張も妨げる二重の扱いが適切かは、今回は決めない。緩める向きの変更であり、新しい義務の変更にも当たるので、別の Issue(#356 が最も近い)へ寄せる。

### 1.6 資格情報の分離と、一覧に無い2行

- 資格情報: 採用者が席ごとにトークンを分ければ解ける。「解けない」のは、プラン・基盤の制約があるときだけである。PCI の型なら「制約の証明」を入口にするが、その制約の種類と代わりの措置を調べた記録が無く、書けば新しい条件の発明になる(#313 Q-3)。入れない
- AI の名義: 専用の名義を申告し、実行環境で照合すれば解ける。入れない
- 判定記録の置き場の履歴: 「ルールセットを使えないプラン」という費用・基盤の制約を含むため、P1 を満たしうる唯一の行である。しかも「ハッシュの照合を定期的に外へ記録する」など、決定可能な条件で措置を書けそうに見える。それでも、今回入れない。理由は (i) その措置で履歴の書き換えを検出できるという実証が無い、(ii) #329(プランに依る統制)が同じ問いを持っており、そこで先に決めるべきである、(iii) 観測が無い。Green Book OV4.17 は費用だけを理由に統制を省くことを認めない。制約と費用を分ける作業が先に要る

## 論点2 1名・2名の体制の扱い

### 推し: (a) 主張できないままにし、理由を明記する

| 案 | 判断 | 先例の型 | 理由 |
| --- | --- | --- | --- |
| (a) 主張できないまま | 推す | T4(SLSA。単独メンテナは最上位を主張しない。【二】) | 1名で満たせない規定は、いずれも目的が「独立した他者」を必要とする。措置は独立性を回復しない(ADR-0029 自身が `:589` で認めている) |
| (b) 列挙に入れて「逸脱を伴う適合」を可能にする | 退ける | T2 | 上の1.2のとおり P4 を満たす措置が無い。ADR-0029 の「広げません」、ADR-0028 決定6(代償措置を置いても未達の状態の名を変えない)と矛盾する |
| (c) 規模でプロファイルを分ける | 別の Issue へ。今回は採らない | T3(29110、DO-178C のレベル別の独立性) | 新しい要求の組を定めることは、採用者への新しい義務に当たる。軸E(CL1 以上と規制業は1〜2名を認めない)と整合する形は作れるが、先例は安全重要を対象外にしており、対応は導けない |
| (d) 条件つき要求(ISO 19011 型の「実行可能であれば」) | 退ける | T1 | 条件が開き、機械で閉じない。「適合」と「列挙に無い離脱」の線が曖昧になる |

(a) の中身として、次を明記することを推す。

1. 1名の体制は、適用組織に含める(ADR-0068 決定6、1.2)。適用と主張は別である
2. 主張できない理由は、「禁止」ではなく「独立した他者の関与を要する目的が、1名では成り立たないこと」である。そのうえで、1名が述べられるのは適用の表明までで、各要求の状態(充足・未達・離脱)は開示できる
3. 「恒久的に」とは書かない。「現行の条項の下では、体制が増えるまで」と書く。第1版は未発行で、EV-0160 の観測によって改訂の道が残るため
4. 「規格に、1名の開発者への代償統制を認めた先例は、確かめた範囲に無い」(external.md C5 の最終行)を、根拠水準マークの対象にする(論点4)

## 論点3 現行の条文の中の食い違いの直し方

編集の指摘(ed)に当たる。会議体で決めず、議長が直し、独立の突合を1回行う形を推す。

| 食い違い | 直し方 |
| --- | --- |
| 1.10.2 の注記「1名の体制: 次の4つの規定が常に当たる」と、各条項の幅 | 常に当たると確かめられた2つ(出荷判定者 × 事業決裁者、AI維持管理者 × AI運用担当者)に絞って書く。残る3つは別の文に分ける。保持者は「コア機能を持つ案件で、保持者が常に1名以下」。層1 は「1名の組織で」。欠陥注入は「注入を体制の外の者に委ねられるかを条文が定めないため、成立しない場合がある」。1名が主張できないという帰結は、2つで足りるので変わらない |
| ADR-0035 決定2「代償措置つきの逸脱として記録」と、3.5.3「代償措置を定めていない」 | 採用済みの ADR の本文は書き換えない。本件の ADR に「ADR-0035 決定2 の『逸脱』は、閉じた列挙の語としては誤りで、列挙に無い離脱の意である。ADR-0029 と同じ扱いという記述は、措置が無いので当たらない」と書く。ADR-0083 決定8 の読み替えを、この ADR で再確認する |
| 3.4.3 要求事項6・7 が措置に当たりうる文を持つのに、適用の条件が無い | 要求事項7 の後に1文を足す。「要求事項6 の登録・受容・表示は、離脱を解消するまでの扱いであり、離脱を補う措置ではない。受容しても列挙に無い離脱は消えず、述べられる名も変わらない」。ADR-0081 の L3 の停止が措置でない旨は、書かない(5.4.6 の領分) |
| 1.10.2 の「別の Issue で審議します」(`:676`) | 審議の結果を書く。「入れないと決めた」旨と、再検討の契機(論点4 の観測)を明記して、「書かれていない」と「課さないと決めた」を区別させる |

## 論点4 弱点と、実証を欠く点

### 本案の弱点

- 採用者の幅を狭める。1名の事業者が本標準に従う動機が弱まる。ただしこれは市場の事実で、信頼性の論拠ではない(external.md O1 の弱点)。判断軸は信頼性であり、この弱点では覆さない
- 29110 や SOC 2 CC5.1 は離脱の道を用意している。「道が無い」型は安全重要の領域に偏る(external.md)。私の案は、本標準を安全重要寄りの型で運用することを意味する。非安全重要(CL0、規制業以外)の1名にも同じ扱いを課すことの妥当性は、実証が無い
- 外部の共署(論点1.4)は、唯一の等価に近い措置の候補を、今回は検討の外へ出す。後継の Issue が起票されないと、案が消える。#351 または #329 へのコメントで足す
- 2名の体制のうち、別の人を置けない事情(一人が休職する期間など)を扱えない。ここは (a) の帰結どおり、適用の表明までである
