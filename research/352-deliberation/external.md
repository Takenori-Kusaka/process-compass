## 0. 骨格(裁定ではない)

規格は「小さい体制では満たせない」を、次の4つの型で扱っている。

| 型 | 内容 | 先例 |
|---|---|---|
| T1 | 要求自体を「実行可能であれば」の条件つきにし、満たせない場合の努力義務を書く | ISO 19011 §4 e)【抜】、SOC 2 CC5.1【抜】、米連邦 Green Book OV4.14【抜】 |
| T2 | 満たせないことを認め、制約の証明・同等の防御・評価者の審査・毎年の再審査・報告への記載を条件に、代わりの統制を認める | PCI DSS 4.0.1 付録B・C【原】、FedRAMP deviation【二】 |
| T3 | 規模・リスクで別のプロファイル(別の要求の組)を定める | ISO/IEC 29110【抜】、SLSA のレベル分け【抜/二】、DO-178C のレベル別の独立性【抜/二】 |
| T4 | 主張できないままにし、できる範囲の水準だけを主張させる | SLSA(単独メンテナは Level 1〜3 で止まる)【二】 |

「1名体制でも適合を主張できる」と明示した規格の先例は、確かめた範囲に無い。

## A. 適合の主張と部分適合・テーラリング

### A1. ISO/IEC/IEEE 12207:2017 / 2026
- 箇条4 は 4.2 Full conformance(4.2.1 成果への完全適合、4.2.2 タスクへの完全適合)と 4.3 Tailored conformance の2つの主張を持つ【原: 目次】。SRC-0731・SRC-0642・SRC-0491 に既にある。2017 年版の目次は iTeh の公開プレビュー(NEW-1: cdn.standards.iteh.ai/samples/63712/0bc6d9107eeb46d88dbc7b628b12cf4b/ISO-IEC-IEEE-12207-2017.pdf、15 頁)でも再確認した【原】。
- テーラリングの手順の所在: 2008 年版は規定の附属書 A「Tailoring Process」、2017 年版は 5.5.4、2026 年版は 5.5.5【二: 検索結果の目次の要約。2017 の 5.5.4 は未確認】。「附属書A」は 2008 年版の構成である可能性が高い。
- 含意: 12207 は「完全」と「テーラード」の2段で、本標準の「適合」「逸脱を伴う適合」と型が同じ(2段の構造自体を支える)。テーラードの条件(根拠の記録・合意)の本文は【未】(公開プレビューが箇条4に届かない)。
- 確かめられなかった点: 4.3 の原文、テーラリングの根拠を誰が承認するか、主張にテーラリングの内容を載せる要求の有無。

### A2. 15288 / ISO/IEC 17050 / ISO/IEC Directives Part 2
- 15288: 原文は【未】(調べていない)。
- ISO/IEC 17050-1: 供給者適合宣言は第一者の attestation(ISO/IEC 17000 の declaration)。対象は製品・工程・マネジメントシステム・人・組織。2004 年版は 2010 年版(EN ISO/IEC 17050-1:2010)に置き換えられ内容は同一とする記述がある【二: 販売ページの要約。現行版の位置づけは未確認】(NEW-4)。宣言の内容要素(識別・発行者・対象の記述・適合の文)は第三者の目録の列挙【二】で原文【未】。含意: 宣言は「どの要求に対する適合か」を特定させる。例外を使ったかを書かせる明文は確認できず【未】。
- Directives Part 2: 原文を読んでいない【未】。

### A3. ISO 9001:2015 4.3(適用不可能の正当化)
- 要旨: 適用できない要求は QMS の適用範囲に文書化して理由を示し、適用不可能としたことが「製品・サービスの適合を確実にする組織の能力または責任に影響しない場合に限り」適合を主張できる【二: 複数の監査用チェックリスト・解説が同じ言い回しを引く。ISO の原文は OBP が 403 で読めず【未】】。
- 含意: 「除外してよいが、除外しても目的を損なわないこと」を主張の条件にする型。T2 に近いが、閉じた列挙ではなく「目的への影響の有無」という開いた判断である点が本標準の方式と異なる。
- 確かめられなかった点: 2026 年版(SRC-0542 ほか)の 4.3 の文言。

### A4. IEC 62304 / ISO 26262-2 / DO-178C / CMMI
- IEC 62304: 適合は、ソフトウェア安全クラスに応じたプロセス・活動・タスクをすべて実施すること。判定は文書の検査【二: GlobalSpec の一覧の要約】(NEW-5)。クラス別に要求が増減する型(T3)。公開範囲に独立性を課す文言は無い【抜 SRC-0525】。
- ISO 26262-2:2018 6.4.5 テーラリング: 安全計画にテーラリングを定め、機能安全の達成に適切かつ十分である根拠を示し、根拠は確認レビューまたは機能安全アセスメントで審査される。影響分析に基づけば満たされる【二: 実務家の解説。規格の本文は【未】】(NEW-6)。
- ISO 26262 の確認措置の独立性: ASIL に応じて定められる【抜 SRC-0526 §7.1】。I0〜I3 の定義の表は公開部分に無く【未】、第三者の ASIL との対応表は検証できなかったので使わない。
- DO-178C: 独立性を要する目標の数はレベルで違う(A: 16/31、B: 7/31、C・D: 0)【抜 SRC-0689(二次)】。独立性は作成者以外の者が検証する職責の分離【抜 SRC-0676】。代替手段(FAA AC 20-115D が適合手段として認める補足文書)は強制ではない【抜 SRC-0529】。本文の「代替手段」の条件は【未】。
- CMMI: 導入の手引き v4.0 は差の特定と段階的な改善【抜 SRC-0669】。適合の主張の例外の扱いは調べていない【未】。

## B. 小さい組織への配慮

### B1. ISO/IEC 29110(VSE)
- VSE は 25 名以下【抜 SRC-0329 §1】。Generic Profile Group は Entry・Basic・Intermediate・Advanced の4つで、Entry は小規模案件(例: 6 人月以下)と創業期の VSE【抜 SRC-0330 §2】。安全重要ソフトウェアを開発しない VSE が対象【抜 SRC-0533 抄録】。
- 型: T3(プロファイルを分ける)。小さい組織には最初から別の要求の組を用意し、「主張できない」状態を作らない。ただし安全重要の領域は対象外で、26262 等の独立性要求と重ならない。
- 確かめられなかった点: SI 工程の検証・妥当性確認の担い手と独立性の条文(有償で未読)。基本プロファイルが1名の開発者を許すか。

### B2. ISO 19011:2018(内部監査の指針。ISO 9001 の小規模組織向け手引きの代わりに確認できた範囲)
- 「小規模組織では内部監査員が被監査活動から完全に独立できない場合があり得るが、偏りの除去と客観性の促進に全力を尽くす」【抜 SRC-0331 §4 e) 原文】。独立は「実行可能であれば(if practicable)」【抜】。
- 型: T1。要求を条件つきにし、満たせないときは努力義務に落とす。代償の具体は書かない。
- ISO 9001 の小規模組織向け手引き自体は未読【未】(TH02-Q1 の partial と同じ)。

### B3. SSDF・SLSA の水準
- SLSA v1.2 Source Track: Level 4 で保護ブランチへの変更に2名以上の信頼された人の合意を要求(MUST)。信頼された人=組織が認可した人間【抜 SRC-0416 原文】。trusted robot には方針の恒久的な例外(例: 2名レビューなしのマージ)を与えてよい(MAY)【抜 SRC-0416 原文】。
- 設計の意図: 2者レビューを最上位にしたのは、単独メンテナのプロジェクトが Level 1〜3 までは採らずに進めるため。対象は企業と成熟した OSS【二: slsa.dev の検索結果の要約。原文は【未】】。
- 型: T3 兼 T4。単独体制は下位水準を主張し、最上位は主張できないまま。例外の付与は robot に限られ、人の単独体制の代償としては書かれていない。
- SLSA 作業草案: 2者レビューの上に人数を足すのは収穫逓減で、2名の共謀は対象外【抜 SRC-0688】。
- SSDF v1.1: PS.1.1(コードを最小権限で保護)、PO.5.1(環境を分けて保護)【抜 SRC-0718】。人数を課す条項は確認していない。NSA・CISA の CI/CD の手引きは二者の規則と職務の分離を求める【抜 SRC-0716】。
- OpenSSF Scorecard の Code-Review: 変更が bot だけで判定材料が無いとき「結論なし(inconclusive)」を返す【抜 SRC-0574 原文】。単独メンテナの扱いは確認できなかった【未】。合否とは別の第三の結果を返す先例。

## C. 職務の分離ができないときの代償統制

### C1. PCI DSS v4.0.1 付録B・C【原】
読んだ版: Middlebury の写し(NEW-2: https://www.middlebury.edu/sites/default/files/2025-01/PCI-DSS-v4_0_1.pdf)を pdftotext で読んだ。公式の listings.pcisecuritystandards.org の URL は 404 だった。公式ブログ(NEW-3: https://blog.pcisecuritystandards.org/pci-dss-v4-0-compensating-controls-vs-customized-approach)で要点を再確認。写しと公式の版の一致は未照合。
- 入口: 「正当で文書化された技術上または事業上の制約(legitimate and documented technical or business constraints)」により要求を明示のとおりに満たせない場合に限る。
- 基準(付録B): 1 元の要求の意図と厳密さを満たす。2 同程度の防御(元の要求が防ごうとしたリスクを相殺する)。3 「above and beyond」: 他の要求を満たしているだけでは代償統制ではない。4a 審査対象の項目について既に必須の要求は数えない。5 要求を満たさないことで生じる追加のリスクに対処する。6 現在と将来の要求に対処し、過去に漏れた要求は遡って補えない。
- 手続: 評価者が毎年の評価で十分性を審査・確認する。評価の後も有効性を保つ工程と統制を置く。結果は報告書(ROC・SAQ)の該当要求の節に記載し、提出先へ同封する。付録C の様式は「制約」「代償統制の定義」「目的」「識別されたリスク」「検証」「維持」の6欄。
- カスタマイズドアプローチとは別の経路で、代償統制はカスタマイズドアプローチでは使えない(付録D)。同一要求でも部品ごとに混在できる【原: 公式ブログ】。
- 含意: T2 の最も具体的な先例。本標準が代償措置を列挙へ入れるなら、条件は「制約の記録」「元の目的の明示」「追加リスクの明示」「検証」「維持」「毎年の再審査」「報告への記載」の組になり得る。「他で既に求める統制は代償に数えない」「遡及不可」は、職務の分離の代償に他条項の遵守を数えさせない根拠になる。
- 注意: PCI の評価者は外部の資格者で、十分性の判定を第三者が行う。1名の組織が自分で判定する構造とは前提が違う。

### C2. COSO・Green Book・J-SOX・SOC 2
- Green Book 2025 OV4.14: 小規模組織は権限が集中して職務分離が難しい。追加のレビュー段階や無作為抽出した取引の確認などで統制の設計により対応できる【抜 SRC-0419】。OV4.17: 費用だけでは統制を実施しない理由にならない【抜】。
- SOC 2 CC5.1: 「経営者は両立しない職務を分離し、分離が実際的でない場合は代替の統制活動を選び整備する」【抜 SRC-0538 原文】。T1 + 代替統制(基準は経営者の選択で、PCI ほど具体でない)。
- COSO の生成AI補足: 職務分離は「AIの設定を構成する権限」と「出力を承認する権限」の分離。独立検証は「人または自動」【抜 SRC-0535】。J-SOX は職務分掌を「複数の者」の間の分担として書く【抜 SRC-0537】。
- COSO・SOX の小規模事業体向け手引きの原文は未読【未】。

### C3. ISO/IEC 27001:2022 附属書A 5.3 / NIST SP 800-53 AC-5
- 5.3: 相反する職務と責任の領域は分離する。目的は不正・誤り・統制の迂回の低減。何を分けるかは組織が決める【二: ベンダーの解説。原文と ISO/IEC 27002 の手引き(小規模組織の記述の有無を含む)は【未】】(NEW-7)。
- AC-5: 組織が定義した職務を識別・文書化し、アクセス権限を職務の分離を支えるよう定義する(Rev 5、中・高ベースライン)【二: 写し。NIST の公式カタログは取得できず【未】】。二重承認は AC-3(2)・CM-5(4)【二】。代償措置の手引きは AC-5 本文に確認できなかった。
- 含意: どの職務を分けるかを組織が識別して文書化させる型。1名体制の扱いは書かれていない【未】。

### C4. 医療・自動車・航空の独立性
- IEC 62304: 公開範囲に独立性要求は無い【抜 SRC-0525。不在の確認ではない】。
- ISO 26262: 確認措置の独立性は ASIL に応じ、組織上の独立を指す【抜 SRC-0526】。1名の開発者に認める代償の記述は確認できなかった【未】。アジャイルは安全方策や基本的な文書・プロセスの省略には使えない【抜 SRC-0527 §5.2 NOTE 1】。
- DO-178C: 高いレベルほど独立性を要する目標が多い【抜 SRC-0689】。ツールが人の検証と同等になり得る(DO-330 の適格性の経路)【抜 SRC-0676】。
- 含意: 安全重要の規格は、独立性を代償で緩めるのではなく、水準で要求を増減する(T3)。独立性が要る水準で1名体制は主張できない。

### C5. 規格が認める代償・認めない代償(確かめた範囲)
| 区分 | 内容 | 根拠 |
|---|---|---|
| 認める | 追加のレビュー段階、無作為抽出の事後確認 | Green Book OV4.14【抜】 |
| 認める | 代替の統制活動(経営者の選択) | SOC 2 CC5.1【抜】 |
| 認める | 偏りの除去・客観性の促進の最善努力(独立できないとき) | ISO 19011【抜】 |
| 認める | 元の意図と厳密さを満たし追加リスクに対処する別の統制(外部の評価者が審査) | PCI 付録B【原】 |
| 認める | 自動化(trusted robot)への2者レビューの恒久的な例外 | SLSA【抜】 |
| 認めない | 他の要求の遵守だけを代償とすること | PCI 付録B 3・4a【原】 |
| 認めない | 過去に漏れた要求の遡及的な補完 | PCI 付録B 6【原】 |
| 認めない | 費用だけを理由とする統制の省略 | Green Book OV4.17【抜】 |
| 確認できず | 1名の開発者に対する具体的な代償の一覧 | 規格に見当たらない【未】 |

## 選択肢と外部の先例の対応(#352)

選択肢の名は、議長が裁定するための仮のもの。
- O1 列挙へ入れない(現状。1名・一部の2名は恒久的に主張不可)
- O2 条件と代償措置を定め、列挙へ入れる(逸脱として適合を主張可)
- O3 規模・構成でプロファイルを分ける(要求の組を別に定める)
- O4 要求自体を条件つきにする(「実行可能であれば」+努力義務)

| 選択肢 | 支える先例 | 対立する先例・弱点 |
|---|---|---|
| O1 | SLSA(単独は Level 4 を主張しない)、ISO 26262・DO-178C の高水準(独立性が要る水準では主張できない)、Green Book OV4.17 | 29110・SOC 2・PCI は離脱の道を用意しており、「道が無い」型は安全重要の領域に偏る。小さい体制を恒久的に排除すると採用者が限られる(信頼性の論拠ではなく市場の事実) |
| O2 | PCI 付録B・C(条件の組が最も具体)、FedRAMP deviation【二】、12207 の tailored conformance | PCI は外部の評価者が審査する。自己審査なら判定者の独立が崩れる。条件を機械の検査で閉じられるかは先例から分からない |
| O3 | 29110 の4プロファイル、DO-178C のレベル別の独立性、SLSA のレベル | 29110 は安全重要の領域を対象外にする。本標準の区分(CL・R)との対応は先例から導けない。プロファイルが増えると「適合」の意味が増える |
| O4 | ISO 19011、SOC 2 CC5.1、Green Book | 条件が開いており機械の検査にならない。代償の内容が経営者の選択に任される。努力義務は「適合」と「列挙に無い離脱」の線を曖昧にする |

組合せ: PCI は O2 のなかに「他の要求を代償に数えない」「遡及不可」を含む。SLSA は O3 のなかに trusted robot への例外(O2 の一種)を持つ。単独の型だけで運用している規格は少ない。
