# 会議体の議題(#375 名簿へ足すのと同じ変化点で任命すると記名が拒否される)

入力: Issue #375、`survey-375-1-internal.md`(内部)、`survey-375-2-external.md`(外部)、`survey-375-3-probe.md`(実行での確認と案(a) の試作)。前段の決定 ADR-0079 決定7(#296 の付記)、ADR-0055 決定3、ADR-0089 決定3、ADR-0106、ADR-0107。

## 前提として確かめた事実(要旨)

- Issue の記載の訂正: 4c2e109 は作業ブランチのコミットで、main では 4af67c5。#319 の ADR は ADR-0089。印は d3a21a7 で #375 へ付け替え済み
- 原因: `namingProblems`(generate-profile.mjs L5058)が、この変化点で足す確認の記録(L5429)の前の構成で評価される。本人以外の記名かどうかは L5216〜5232 がこの変化点の入力で照らしており、2つの検査の時点が食い違う。評価の位置は付記の前後で変わらず、付記で `aiNameBlocked` が記録の有無を見るようになって結果が変わった
- 標準(G-6 gate-criteria.md L1017、D-0 表5)・ADR-0079 決定7・#296 の会議体のどれも、確認と使用(任命・記名)の前後を定めていない。前の変化点での確認を求める意図の記述も無い
- 外部: 21 CFR 11.100(b)、NIST SP 800-63A-4、800-53 IA-12(1)・AC-2 c は「確認を終えてから付与する」論理の前後を求めるが、別の取引に分ける要求は見た範囲の原文に無い。800-63A は1セッションで確認から加入まで終える形を基本とする。Entra・Okta は1つの申請の中に段を直列に並べ、禁じるのは自己承認。CODEOWNERS・Kubernetes RBAC は変更前の状態で判定するが、対象は判定の規則や操作者の権限で、付与される者の前提条件ではない
- 実行での確認(probe):
  - 案(a)(同じ変化点の確認を数える)の試作で、本人の記名・AI の名義の記名・名簿に無い人の記名・記名なし・AI 名どうしの相互の確認は、現行と同じ理由と件数で拒否されたまま。既存の試験は変わらない
  - L5058 だけを直す(a1)では足りない。確認したその変化点の `changeLog` の `nameOverrides` と [上書き] の行(L5345・L5454)も同じ変化点の確認を数えておらず、a2 の範囲まで直す必要がある。分けた経路(案(b))でも、確認の変化点で同じ食い違いが出る
  - 別の回帰の候補: `clampSeats` の ctx(L700)が `changeLog` を持たないため、前の変化点で本人以外が正しく確認した人でも、委任の席の責任者にできない(p302 では受け付けた)。案(a)・(b) のどちらでも残り、案(b) の手順は委任の席では成り立たない
  - 帰属の検査(`decisionRecordFindings`)は、同じ PR に入れた2件の記録を同じ PR で照合する。変化点を分けても前後の保証にはならない
  - p302 で開いていた自己確認の経路(X-decider と記名なしの確認)は #296 の付記で塞がれ、試作も開け直していない

## R-1 同じ変化点での確認と使用

- 問い: 名簿へ足すのと同じ変化点で、本人以外が記名した氏名の確認を、その変化点の任命・記名の判定に数えるか。案(a) 数える(評価の時点をこの変化点の記録を足した後の構成に揃える)、案(b) 前の変化点での確認を要する、案(c)〜(f)(内部調査 §5.4)。回帰か決定か

## R-2 評価の時点を揃える範囲

- 問い: 案(a) を採るなら、どの検査を「この変化点の記録を足した後の構成」で照らすか(`namingProblems`・`decidedBy`・`nameOverrides`・[上書き] の表示・適合性確認の実施者と承認者)。一般原則として書くか、検査ごとに決めるか

## R-3 委任の席(`clampSeats`)の回帰の候補

- 問い: 前の変化点で正しく確認した人を委任の席の責任者にできないことを、本件で直すか。回帰か

## R-4 記録・開示・ADR

- 問い: 同じ変化点で確認して使った旨を記録・開示で区別するか。帰属(ADR-0106)の前後を保証しないことの開示。新しい ADR、EV・IMPL、回帰スイートの印(#375、見直し 2026-12)の外し方、採らない案
