## 1. 採る案と理由

### 1.1 第6章と 3.10.4: 範囲で分ける(案A を修正して採る)

誤っているのは**第6章の一文の範囲**である。3.10.4 は個別の規定(対象・様式・T-1・指標・pre-review-closed の閉じ条件・ADR-0075 決定9 が束ねる)で、第6章の一文は「合議化の防止」を目的にした一般文である。目的(判定は単独、会議で決めない)は 3.10.4 でも守られる。3.10.4 の応答は「記載」の義務で、**反映の義務ではない**(採用しない場合も理由を残すだけ。決めるのは判定者)。両者の目的は両立し、衝突するのは「対応義務はない」という**範囲の広い否定**だけである。

したがって次のようにする。

- 「対応義務はない」を、3.10 の対象の**外**のコメントに限る。適用範囲は規範と同じ行に書く(#226。限定を別の段落へ置かない)
- 応答の義務と反映の義務を分けて書く。「応答の記載」は 3.10 の対象、「反映」は常に提出者と判定者が決める
- 「不採用に一言の理由を残す」は、全てのコメントに掛かったままにする(両方の規定が一致している部分。削らない)

### 1.2 3.10.2 と 7.4: 参照の誤りでも、定めの欠けでもなく、「定めないと決めた」の未記載

3.10.2 の「限る」は必要条件の宣言として正しい。7.4 に定めが無いのは参照の誤りでなく、**短縮の幅(下限・時点)を本標準が決めていない**ことの未記載である。コアポリシー「書かれていない」と「課さないと決めた」の区別に当たる。そこで:

- 本束(軽)では、3.10.2 に「短縮の下限の日数は、本標準は定めない。短縮した場合に残す記録の項目は、7.4 の例外承認の台帳の行(#445)で定める」旨を、規範と同じ段落内の一文で書く。新しい義務を課さない
- 7.4 側に「事前レビュー期間の短縮」の項を足さない。7.4 は「一部のゲートを後追いに回す」手続で、短縮の幅は 3.10.2 の関心である。両方に書くと食い違いの元が増える
- 下限の数値を置くか、短縮後の日程を台帳の行の必須欄にするかは**採用者への新しい義務**に当たる。本束では決めない。#445(台帳の行の欄を定める Issue)へコメントで繰り入れる(「後継は既存の Issue へ寄せる」の方針)。これが入った後に、T11 の機械検査を降ろす

### 1.3 IMPL-0212: 追う規定を分け、delivered の分を delivered にする

マークが追う内容は二つあり、片方は降りている。

- (a) 区分の下限と確定者(3.8.1 要求事項2・3)は IMPL-0062 が delivered。`check-pr.mjs` の検査 5・7 が実在し、試験(214 場面)は通る。IMPL-0212 が「区分の下限の照合はあるが…引き下げの記名の検査は無い」と書く現在の note は、**確定者(指示者以外の名簿の人)の検査が実在することを書いていない**ため古い
- (b) ラベルの自動付与(フェーズ5)は未実装のまま。T8 に残す

**文案**: IMPL-0212 の note を「自動付与の検査は無い」へ狭め、「確定者の検査は IMPL-0062 が追う」を足す。引き下げの記名の席は、フェーズ5 が「技術判断者」、3.8.1 要求事項3 と `check-pr.mjs` が「指示者以外の自然人」と**異なる**。両者の関係は本束で裁定する(後述 5)

## 3. 採らない案と理由

- **第6章の一文の削除(案B)**: 通常のコメントの扱いが書かれなくなる。「書かれていない」と「課さないと決めた」の区別が消える
- **3.10.4 を緩めて第6章に合わせる(案C)**: T-1・指標・pre-review-closed・ADR-0075 決定9 の前提を壊す
- **7.4 に短縮の項を足す(調査の 4.3(a))**: 短縮の幅の定めを 7.4 と 3.10.2 の二箇所に持つと、次の食い違いの元になる。短縮の幅は 3.10.2 の関心
- **3.10.2 の参照を外し 7.3 へ付け替える(4.3(b))**: 7.4 は 7.3 の特殊形で、外部の不可逆な期日という限定が乱用を抑える。7.3 一般に開くと、社内の目標日で期間を縮められる(7.4 の「適用できない期日」を空洞化する)
- **短縮の下限の数値を置く**: 実証がなく、根拠水準マークが要る。置く合理性を示す調査がまだ無い。重へ上げる条件(a)(b)に当たる
- **IMPL-0212 の note に「検査は有る」と書くだけにする**: ラベルの自動付与が未実装である事実と、席の食い違いが隠れる
- **pre-review-closed を採用者の既定の必須チェックにする案(P2)を本束で決める**: 外部の調査が要る。本束の範囲外。T2 のまま Issue に残す

## 6. 自案の弱点

- 2.1 の文案は、3.10 の対象を「B-1〜B-4 と工程ゲート、標準変更と AI を除く」と書き直す。**対象の定義を第6章と 3.10.1 の二箇所に持つ**ことになり、次の食い違いの元になる。参照だけ(「3.10.1 の対象」)にする方が頑健だが、読み手が第6章だけを読んだときの意味が薄くなる。反対の委員の指摘を待つ
- 第6章の「すべてのレビュー」に、3.10 の対象外のレビューがどれだけあるかを数えていない。もし対象外がほぼ無いなら、第6章の一文は実質的に不要で、案B(削除)の方が信頼性が高い可能性がある。私は「書かれていない」の区別を重く見て採らなかったが、確かめていない
- 3.10.2 の「定めない」は、現状の追認でもある。短縮が無制限になりうる穴を塞がない。3.10.8 の警戒サインが穴埋めを担うが、それは指標であって統制ではない。#445 の結果次第で、先送りの害が出る
- IMPL-0212 の「delivered の分を分ける」は、確定者の検査の拒否場面(AI の名義・指示者自身)を 1 つずつ確かめていない。試験の全体が通ったことと、`確定した者` の場面が 13 あることしか根拠にしていない
- T 一覧への T2 の営業日の依存の指摘は、実装を見ていない推測である
- 提供者(Claude Code)のフックの仕様は未確認(T1)。外部の調査をしていない
- 5 の「席の食い違い」は、両者が矛盾でなく別の統制(一次ラベルの引き下げと、最終の区分の確定)の可能性を排除しきれていない
