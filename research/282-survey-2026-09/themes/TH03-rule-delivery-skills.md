## 結論

- 段階的開示(名前と説明だけ常時ロード)は Claude Code・Codex・Kiro・Agent Skills 仕様の共通仕様。一覧予算は Claude Code が文脈窓の 1%、Codex が 2%。本数と選択精度の関係をベンダーは測定値で示していない [FND-0031](E1)
- Google Antigravity は常時有効な規則に合計 20,000 トークンの予算を置き、超過分を大きいファイルからポインタへ自動降格。GitHub Copilot の手順書にバイト・トークンの上限は無く、長さの数値は推奨プロンプト内の「2 ページ以内」だけ(2026-09-30 取得)[FND-0197](E1)
- 常時ロードと段階的開示の比較測定が初めて付いた。Qwen の 3 モデル・32k 窓で、常時ロードは 100 本で全試行が文脈超過により失敗、段階的開示は 1 条件を除き選択成功率が並ぶか上回る(2026-09-28 公開、査読前、合成のスキル検索課題。遵守は未測定)[FND-0201](E2)
- スキル選択精度は臨界規模の後に急落(半減本数は GPT-4o-mini 91.8、GPT-4o 83.5)。主因は本数単独より意味の紛らわしさ。階層ルーティングで +37〜40pt。測定は GPT-4o 系のみ [FND-0032](E2)
- スキル本文の注入は 4 モデルすべてで平均 Pass@2 を 1.3〜4.2 ポイント下げ、費用を 72〜394% 増やした(Web-Bench)。長さだけでは説明できず、SkillsBench の +16.6pt とは逆向き [FND-0199](E2)
- 常時ロードから外した規則・スキルは起動されないことがある(自発的な読み込み 3.5%、Vercel の社内評価で 56% が未呼び出し。後者は自己申告・標本非開示で単独では E0)。反証として SkillsBench の呼び出し率 46.4〜99.2% [FND-0033](E2)。常駐の指示に参照先を書くと読まれた実演は n=1 [FND-0204](E1)
- 同時に課す指示が増えると完全遵守率は低下(IFScale 500 個で 68%、VeyraBench はルール 80 個で実質ゼロ)[FND-0034](E3)。2026 年モデルの追試は閾値の約 2,000 個への移動を報告、ただし指標は狭い [FND-0035](E2)
- 規則数を 0 から 50 へ増やしても課題合格率は安定(Claude Code+Opus 4.6)。測ったのは合格率で遵守率ではなく、FND-0034 の反証には当たらない [FND-0200](E2)
- #269/#274 の「16 万バイトは守り切れず黙って落ちる」を同規模で測った外部研究は無し。ETH の統制比較は「指示はよく守られ、長さの有意な影響なし」と逆向き [FND-0037](E2)。ベンダーの 200 行推奨は測定の裏付けなし [FND-0039](E0)
- 「黙って落ちる」が指す機構は不遵守・量の上限・設定不備の 3 系統。Antigravity は設定に不備のある規則を警告なく破棄すると原典が明記 [FND-0198](E1)
- 指示書は強制でない文脈、というのがベンダー公式の位置づけ。hooks・権限・静的解析へ移して守られた事例が複数 [FND-0040](E2)。ただし決定的な層にも破れ方の報告 [FND-0041](E2)
- 成果物・工程単位の分割の先例(Spec Kit、cc-sdd v3、AI-DLC 2.0、OpenSpec)は入口やプロファイルで絞る設計。BMAD は PRD の create / edit / validate を単一スキルへ統合し(2026-05-17)、2026-08-09 の版で出荷経路のレビューは自前のプロンプトへ戻した。作成・レビュー・テストの 3 本を揃える先例も、分割の効果の比較測定も束に無し [FND-0044] [FND-0202] [FND-0203](E1)
- スキル・エージェント設定を経由する供給網の実害を観測(3,984 スキル中 13.4% に重大な問題、npm マルウェアが SessionStart フックを設置)[FND-0045](E2)

## TH03-Q1 階層化と段階的開示の推奨値・選択精度の実測

**答え**: 2026-09-30 時点で、Claude Code・Codex・Kiro・Google Antigravity と Agent Skills 仕様は段階的開示を採り、一覧や常時ロードの予算を仕様で定めています。GitHub Copilot の手順書には数値の上限がありません。本数が増えると選択精度がどれだけ落ちるかを測定値で示したベンダーは、依然としてありません。実測は査読前の研究 4 本です。量を増やすと選択精度・効果が落ちる方向は 2 本で一致し、常時ロードとの比較では段階的開示が 1 条件を除いて並ぶか上回りました。一方、スキル本文の注入そのものが課題合格率を下げた測定も加わりました。falsifier(ベンダーが階層化を勧めず、実測でも悪化しない)には該当しません。選択精度の相転移を Claude・GPT-5 以降の世代で再現した測定は、なお知見にありません。

**根拠**

- 仕様上の量: メタデータ約 100 トークン/本、本文 5,000 トークン未満推奨、description 上限 1,024 文字、SKILL.md 500 行未満 [FND-0031] [SRC-0194#c1] [SRC-0194#c2] [SRC-0194#c3]
- Claude Code の一覧予算: 文脈窓の 1%。description と when_to_use の合計を 1,536 文字で打ち切り。溢れると呼び出し頻度の低いスキルから説明を削除 [SRC-0193#c1] [SRC-0193#c3] [SRC-0193#c10]
- Codex の一覧予算: 文脈窓の 2%(不明時 8,000 文字)。説明文を短縮し、さらに多いと一部スキルを一覧から外して警告 [SRC-0351#c1] [SRC-0351#c2]
- ベンダー自身の明記: 短縮で照合に要るキーワードが失われうる [SRC-0193#c2]。一覧の全スキルは使われなくても毎ターン文脈を消費 [SRC-0193#c4]
- OpenAI の 2026-09-11 の手引き: 複数手順を持つスキルのルート文書を最小のルーターにする構成 [SRC-0214#c1] [SRC-0214#c2]
- Kiro(2026-09-02 更新の文書): auto モードは説明文と依頼の一致で読み込む、スキルと同じ仕組み [SRC-0224#c3] [SRC-0224#c7]
- Google Antigravity(日付表記なし、2026-09-30 取得): 規則ファイルは 1 本 24,000 バイトで打ち切り。常時有効な規則は合計 20,000 トークンの予算を共有し、超過時は大きいファイルから本文の注入をやめ、パスと説明だけのポインタへ自動降格。model_decision の規則は段階的開示 [FND-0197] [SRC-0606#c1] [SRC-0606#c2] [SRC-0606#c3] [SRC-0606#c4]
- GitHub Copilot(日付表記なし、2026-09-30 取得): 手順書にバイト数・トークン数の上限は無し。長さの数値は cloud agent に指示ファイルを書かせる推奨プロンプト内の「2 ページ以内」だけ。パス別指示は対象ファイルに一致したときだけ加わり、AGENTS.md は最も近いものが優先 [SRC-0605#c1] [SRC-0605#c3] [SRC-0605#c2]
- 常時ロードと段階的開示の比較(Workday、2026-09-28 公開、Qwen の 3 モデル・32k 文脈窓、ライブラリ 5/20/50/100 本): 常時ロードは 100 本で 3 モデルとも全試行が文脈超過により失敗。段階的開示は 1 条件を除き選択成功率が並ぶか上回る [FND-0201] [SRC-0609#c1] [SRC-0609#c2]
- スキル本文の注入の統制実験(2026-08-24 公開、公開の Web 開発スキル 31 本、Web-Bench の 50 プロジェクト・1,000 課題、4 モデル): 対象スキルの注入で平均 Pass@2 が 1.3〜4.2 ポイント低下、トークン費用が 72〜394% 増。改善したスキル×プロジェクトの組は 17〜36% [FND-0199] [SRC-0607#c1]
- 選択精度の統制実験(2026-01-08 公開、GPT-4o 系、5〜200 本の合成スキル群): 臨界規模まで安定し、その後急落。精度半減の本数は GPT-4o-mini 91.8、GPT-4o 83.5。粗→細の階層ルーティングで GPT-4o-mini が +37〜40pt [FND-0032] [SRC-0355#c1] [SRC-0355#c2] [SRC-0355#c4]
- SkillsBench(2026-02-13 公開、87 タスク×18 構成): 人手スキルで合格率が平均 +16.6pt。1 タスクあたり 1 本で +18.0pt、2〜3 本で +19.0pt、4 本以上で +10.1pt。網羅的な長文スキルは +0.7pt [FND-0032] [SRC-0354#c1] [SRC-0354#c2] [SRC-0354#c3]
- 起動されない実測: RepoComplianceBench(2026-07-29 公開、49 リポジトリ・106 Issue・4 エージェント)で、常時ロードされる AGENTS.md 以外のルールファイルを自発的に読んだ実行は 3.5% [FND-0033] [SRC-0313#c1]
- Vercel の社内評価(2026-01-27 公開): スキルは評価の 56% で未呼び出し。8KB の文書索引を AGENTS.md に常駐させた構成が合格率 100%、明示指示付きスキルは最大 79% [SRC-0359#c1] [SRC-0359#c2]

**限定条件・反証**

- 相転移の測定は GPT-4o 系のみの査読前研究。Claude や GPT-5 世代では未検証。劣化の主因は本数単独より類似スキル間の意味の紛らわしさ [SRC-0355#c3]

- 反証: SkillsBench ではタスク同梱スキルの呼び出し率が 18 構成で 46.4〜99.2%。発見は多くの場合ボトルネックではないとの結論 [SRC-0354#c4]
- Vercel の評価は標本非開示の自己申告(単独なら E0)[FND-0033]
- Anthropic の原典記事(2025-10-16)はスキル 1 本に束ねられる文脈量を事実上無制限とするが、一覧側の劣化は対象外 [SRC-0353#c2]
- 実行面による差: Kiro CLI は読み込みモード非対応で steering の全ファイルを読み込み、Claude Code の @path 分割は文脈量を減らさない [FND-0038] [SRC-0224#c2] [SRC-0350#c4]
- Workday の比較は Qwen2.5-7B-Instruct・Qwen3-8B・Qwen3-14B のみで、課題は合成のスキル検索。Qwen3-8B・20 本では常時ロード 0.68 が段階的開示 0.38 を上回り、遅延は段階的開示がわずかに悪化(Qwen3-8B・50 本で 15% 増)。測ったのは選択の成否で、本文の遵守ではない [FND-0201] [SRC-0609#c3] [SRC-0609#c4]
- スキル注入の実験が測ったのは課題合格率で、選択精度ではない。Claude は 2025-05 版の Sonnet 4 のみ。劣化の機序はモデルで分かれ、同じ長さの無関係スキルで損失の大半が再現するモデルと、長さは中立でも内容が Pass@2 を下げるモデルがある。反証は SkillsBench の +16.6pt [FND-0199] [SRC-0607#c2] [SRC-0607#c3] [SRC-0354#c1]
- Antigravity・Copilot とも、上限値と「2 ページ」の根拠となる測定は非開示。降格された規則が読まれる保証は書かれておらず、スキルの本数や一覧予算に当たる数値も両文書に無し [FND-0197]
- 「起動されない」への限定: 常時ロードされる copilot-instructions.md から ADR の照合を指示したデモリポジトリ(2026-03-01 公開、ADR 3 本)で、Copilot Code Review が ADR 違反を 7 回指摘。エージェントは ADR に反する指示に従わず、先に ADR を更新するよう求めた。対照の無い著者自身の実演(n=1)[FND-0204] [SRC-0561#c1] [SRC-0561#c3]
- Issue との関係: #275 の原則 8(常時ロードしない)は FND-0031・FND-0197・FND-0201 が支持し、FND-0033 が「ロードしない規則は読まれない場合がある」と限定。#272 の索引ツリー案は階層ルーティングと同型だが、測定対象はスキル選択であり ADR 索引ではない [FND-0032]

## TH03-Q3 ルール数・指示量と遵守率の関係

**答え**: 同時に課す指示が増えると全指示の完全遵守率が下がることは、独立した 3 研究で一致しています(E3)。2026 年モデルでは結果が割れます。キーワード包含の追試は閾値が約 2,000 個へ移ったと報告しますが、規則の遵守を測った VeyraBench では Claude Sonnet 5 を含む 5 モデルがルール 80 個で完全応答率が実質ゼロでした。falsifier(最新モデルでは再現しない)の成否は課題の種類で分かれます。長文脈での劣化は 2026 年前半のフロンティアモデルでも再現しています。2026-09-30 の追加では、規則数を 0 から 50 へ増やしても課題合格率は安定したという統制実験が加わりました。ただし測ったのは合格率で遵守率ではなく、falsifier には当たりません。
