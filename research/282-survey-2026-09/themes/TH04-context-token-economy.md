## TH04-Q1 単価・キャッシュ課金構造と「57%」の成立

### 答え

2026-09-23 取得の Anthropic 公式単価表では、#274 が用いた Opus 5 の単価と書き込み倍率は原典どおりです。「費用の過半がキャッシュ読み取り」という構造は外部の実測とベンダー言明が同じ方向を示しますが、57% という値そのものは読み取り 0.1 倍の世代と高頻度の長時間セッションを前提にした値です。falsifier(公式値が異なり過半にならない)には Opus 5 世代では該当しません。

### 根拠

- Opus 5 / Opus 4.8 は百万トークンあたり入力 $5 / 出力 $25 / 読み取り $0.50 / 5 分書き込み $6.25 / 1 時間書き込み $10 [FND-0046] [SRC-0100#c1]
- 倍率は読み取り 0.1 倍、書き込み 1.25 倍(5 分)・2 倍(1 時間)[FND-0046] [SRC-0099#c1]
- 個人 1 名・21,770 往復のログで推定請求額の 70.1% が読み取り [FND-0047] [SRC-0124#c1]。個人 1 プロジェクト・2026-08 の 34,125 リクエストで 65.5% [FND-0047] [SRC-0272#c1]
- Anthropic は 2026-09-22 の発表文で、読み取りがエージェント・コーディング作業の費用の過半を占めると記述 [FND-0047] [SRC-0101#c1]
- OpenHands と SWE-bench Verified による 8 モデルの軌跡分析で、キャッシュ有効時も入力トークンが費用を支配 [FND-0047] [SRC-0115#c1]
- 3 社・500 超のエージェントセッションの統制実験で費用 41〜80% 減(モデル別 28〜81%)[FND-0048] [SRC-0114#c1] [SRC-0114#c3]

### 限定条件・反証

- 2026-09-01 追加の Fable 5.1 は読み取り 0.025 倍($0.25)、2026-09-22 追加の Opus 5.5 は 0.05 倍($0.20、入力 $4 / 出力 $20)。#274 の 57% は Opus 5 が turn の 73% を占める 0.1 倍前提の値で、新しい倍率では比率が変わる [FND-0046] [SRC-0099#c2] [SRC-0100#c2]

## TH04-Q2 常時ロードする文脈量の上限・推奨と、費用・品質への影響

### 答え

Anthropic の原典は数値上限を示さず「最小の高シグナルなトークン集合」を原則とします。製品仕様には行数・バイト数・トークン数の値があり、2026-09-30 取得分では超過時に本文をポインタへ降格する仕様も確認しました。外部実測は常駐文脈と費用の関係を複数報告しています。品質の側は、スキル注入が課題合格を下げた統制実験が 1 件加わりましたが、量だけでは低下を説明できず、規則 0〜50 本では合格率に有意差がありません。常時ロードの指示書規模(数万トークン)で遵守率を直接測った出典は、なお束にありません。falsifier(上限が示されず関係も観測されない)には費用の側では該当しません。

### 根拠

- 原則は数値なし [FND-0050] [SRC-0102#c1]。Claude Code 公式文書は CLAUDE.md を 1 ファイル 200 行未満とする目安を提示(根拠の実測は非提示)[FND-0050] [SRC-0104#c2] [SRC-0350#c1]
- MEMORY.md は先頭 200 行または 25KB を超えた分を読み込まない [FND-0050] [SRC-0350#c3]。Codex の AGENTS.md は連結合計 32KiB(既定)到達後のファイルを読み込まない [FND-0050] [SRC-0212#c1]
- Kiro では AGENTS.md が常時読み込まれ、Kiro CLI は steering の全ファイルを読み込む [FND-0050] [SRC-0224#c1] [SRC-0224#c2]
- Google Antigravity は規則ファイルを 1 本 24,000 バイトで打ち切り、常時有効な規則の合計が 20,000 トークンを超えると大きいファイルから本文をパスと説明だけのポインタへ降格(2026-09-30 取得)[FND-0208] [SRC-0606#c1] [SRC-0606#c2] [SRC-0606#c3]。Cursor Bugbot はレビュー規則を 1 本 30,000 字で打ち切り、合計 100,000 字が上限 [FND-0208] [SRC-0615#c3]
- CLAUDE.md を置かない最小構成で、Claude Code はプロンプト到達前に約 33,000 トークン(うち約 24,000 がツール定義)を送信。OpenCode は約 7,000 [FND-0051] [SRC-0110#c1] [SRC-0110#c2]
- 個人プロジェクトの 2026-08 実測で、文脈に入れた 1 トークンが平均 50.8 回読み直された。常駐文脈を 36.4K(推計)から 15.0K へ減らした費用差は月約 41% という試算 [FND-0051] [SRC-0272#c1] [SRC-0272#c2]
- 外したつもりの残骸 1,061 トークンが 36 日で 33.5M トークンの読み直しを生んだ [FND-0051] [SRC-0272#c4]。GMO ペパボの個人環境では起動時ロードが 114,847→19,232 トークン(-83%)[FND-0051] [SRC-0360#c2]
- SWE-bench Lite 300 件と CTXbench 138 件・4 エージェントの統制比較で、文脈ファイルは課題成功率を概して改善せず、推論費用を平均 20% 超増やした [FND-0052] [SRC-0206#c1]
- 公開の Web 開発スキル 31 本を Web-Bench(50 プロジェクト・1,000 課題)で 4 モデルに注入した統制実験(査読前、2026-08-24 公開)で、対象スキルの注入は平均 Pass@2 を 1.3〜4.2 ポイント下げ、トークン費用を 72〜394% 増やした。改善したスキル×プロジェクトの組は 17〜36% [FND-0206] [FND-0199] [SRC-0607#c1]
- Claude Code と Opus 4.6 による SWE-bench Verified の統制実験(査読前、2026-04-13 公開)で、規則数を 0〜50 の 7 水準で変えても課題合格率は 59〜67% の帯に収まり、50 規則(66.7%)と 0 規則(60.3%)の差は有意でなかった(p=0.227)。分散の主因は本数ではなくどの規則を引いたか [FND-0205] [FND-0200] [SRC-0608#c1] [SRC-0608#c2]
- Workday の技術報告(査読前、2026-09-28)で、32k の文脈窓では 100 本の常時ロードが Qwen の 3 モデルとも文脈超過で全試行失敗。50 本(Qwen3-14B)では段階的開示がプロンプトを 14,875→2,719 トークン(-81.7%)に減らし、スキル選択の成功率は 0.13→0.72 [FND-0207] [SRC-0609#c1] [SRC-0609#c2]
- 入力長による性能低下は Chroma(18 モデル)、Anthropic 所属著者の実験(800K トークン後の危険行動を 2〜30 倍見逃す)、VeyraBench(64〜128k まで天井、その先で急落)で再現 [FND-0053] [SRC-0118#c1] [SRC-0117#c1] [SRC-0325#c3]

### 限定条件・反証

- 「長いファイルは遵守を下げる」はベンダーの記述で、測定の提示は無い [FND-0050]。統制比較ではファイルの長さは結果に有意な影響を与えなかった(測定量は課題成功率と費用で、プロセス規則の遵守率ではない)[FND-0052] [SRC-0206#c4]
- 劣化が測られた帯域は 128k 超〜800K。VeyraBench では 64〜128k まで劣化が無い [FND-0053]
- 41% は実測ターン数×差分トークン×公式単価の試算で、36.4K は反実仮想、/clear の時期は仮定。33,000 トークンは企業ブログの計測 1 件 [FND-0051]
- 費用・トークン量の実測はいずれも応答品質や遵守率への影響を測っていない [FND-0051]
- スキル注入の劣化は量だけでは説明できない。同じ長さの無関係スキルで損失の大半が再現するモデルと、長さは中立でも内容が Pass@2 を 1.1〜1.4 ポイント下げるモデルに分かれた。+394% は DeepSeek のみで他 3 モデルは +72〜91%。Claude は Sonnet 4(2025-05 版)の 1 種で、注入文書のトークン量の絶対値はカードに無い。反対方向に SkillsBench(人手スキルで合格率 +16.6pt)[FND-0206] [SRC-0607#c2] [SRC-0607#c3]
- 規則数の実験は測定量が課題合格率で遵守率ではなく、50 規則は 16 万バイト級より小さい。無作為・並べ替え・分野違いの規則ファイルも精選した規則と同等で、著者は文脈のプライミングと解釈。外的妥当性は単一ベンダー・単一モデル・Python のバグ修正に限る [FND-0205] [SRC-0608#c3] [SRC-0608#c5]
- 段階的開示の比較は合成のスキル検索課題・Qwen の小型 3 モデルのみで、Claude・GPT 系は未測定。Qwen3-8B・20 本では段階的開示 0.38 が常時ロード 0.68 を下回り、遅延は +15%(同・50 本)。文脈超過は 32k 窓の条件。0.13→0.72 と -81.7% の値は検証役の抜粋では未確認 [FND-0207] [FND-0201] [SRC-0609#c3] [SRC-0609#c4]
- Antigravity・Bugbot の上限値は根拠の測定が非提示で、降格された規則が読まれる保証は書かれていない。単位がバイト・トークン・字と揃わず、製品間の直接比較はできない。GitHub Copilot の「2 ページ以内」は推奨プロンプト内の制約で、読み込み上限ではない [FND-0208] [SRC-0605#c1]
- 反証: Vercel の社内評価(自己申告・標本非開示)ではスキルが評価の 56% で呼ばれず、8KB の索引を AGENTS.md に常駐させた方が合格率が高かった [FND-0051] [SRC-0359#c1] [SRC-0359#c2]
- 反証側: IFScale の 2026 年追試では同時制約の上限が 200〜300 個から約 2,000 個へ移った(名詞包含の指標に限る)[FND-0053] [SRC-0357#c1]
- 文脈ファイルの研究は査読前の単一研究(v2 2026-06-23)、Python のみ、2026 年後半のモデルでは未検証。16 万バイト級の常時ロードは測っていない [FND-0052] [FND-0037]
- Anthropic は 2026-07-24 の記事で、Claude 5 世代向けに Claude Code の system prompt を 80% 超削除し社内評価で計測可能な劣化は無かったとする(標本非開示、自己申告)[FND-0050] [SRC-0278#c1]

## TH04-Q3 定額プランの上限による停止リスクと損益分岐

### 答え

ベンダー規約は上限到達時の選択肢を 3 つに限り、定額のみで稼働を保証する規約はありません。Anthropic は自動実行を別枠クレジットへ移す改定を一時停止しており、自動実行は当面、定額の利用上限を消費し続けます(一次資料で確認)。Enterprise プランは全利用を API 単価で課金し、制約は利用上限ではなく支出額になります。枯渇で作業が止まった一次事例は複数ありますが、いずれも n=1 の逸話で並列エージェントが契機です。損益分岐を直接扱う出典は公開単価からの試算 1 件(E0)で、測定に基づく分析は束にありません。falsifier(停止の外部報告が無い、損益分岐の議論が存在しない)にはいずれも該当しません。

### 根拠

- claude.ai・Claude Code・Desktop は同一の上限を共有し、消費量の計算方法は非公開。到達時の選択肢は「リセットを待つ・プランを上げる・usage credits を買う」[FND-0054] [SRC-0107#c1] [SRC-0107#c2] [SRC-0268#c2]
- Claude Code の週次上限は 2026-05 からの暫定 +50% が 2026-09-14 に基準比 +25% の恒久値へ変更(暫定比で約 17% 減)。2026-09-22 には 5 時間枠を引き上げ [FND-0054] [SRC-0108#c1] [SRC-0108#c2] [SRC-0101#c3]
- GitHub Copilot は 2026-06-01 からトークン量×公開 API 単価の課金へ移り、上限後に安価モデルへ落とすフォールバックを廃止 [FND-0054] [SRC-0292#c1] [SRC-0292#c2]
- Anthropic はヘルプセンター(記事の日付表示 2026-06-16)で、Agent SDK・claude -p・第三者アプリの利用を月額クレジットへ移す改定(発効予定 2026-06-15)の一時停止を告知。これらの利用は当面、定額プランの利用上限を消費し続ける [FND-0209] [SRC-0610#c1] [SRC-0610#c2]
- Anthropic の Enterprise プランは席料がアクセスだけを賄い、全利用を API 単価で別課金。席ごとの利用上限も同梱トークンも無く、統制手段は管理者が組織・利用者単位に設定する支出上限(2026-09-30 取得)[FND-0210] [SRC-0611#c1] [SRC-0611#c2] [SRC-0611#c3]
- Max 20x 利用者が 26 体のサブエージェントで残りの週次枠(約 15%)を 20 分で消費 [FND-0055] [SRC-0109#c1]
- 2026-06-01、並列エージェントが親の Opus・xhigh 設定を継承し、5 時間枠と Extra Usage $200 を一晩で消費 [FND-0055] [SRC-0275#c3]
- エムスリー(2026-09-01 公開)で、バックグラウンドのエージェントが 5 時間枠を使い切りメインの作業が停止 [FND-0055] [SRC-0268#c1]
- FinOps Foundation の文書(2026-06-03 更新)はトークンを「請求単位であって価値単位ではない」とし、失敗・破棄した実行も費用に数える「成功アウトカム当たり費用」を推奨 [FND-0056] [SRC-0120#c2] [SRC-0120#c3]
- DX の集計(500 超の組織、2026-07-22 発表)で、四半期 AI 支出の中央値は 1 年で約 28 倍(約 $1.5K→$44K)、新機能に充てる時間の比率は 57〜58% で横ばい [FND-0056] [SRC-0469#c1]
- Morph(モデル提供ベンダー)の試算では、Max 5x($100)は Opus 4.8 の API 単価換算で月 約 111 件のバグ修正または約 26 件の機能実装で損益分岐し、対話利用では稼働日あたり約 1 件を超えると定額が従量を下回る [FND-0211] [SRC-0612#c1] [SRC-0612#c2]

### 限定条件・反証

- 従量側で予算が尽きた事例として、Microsoft の一部門がトークン課金で年間の AI 予算を早期に使い切り、2026-06-30 までに Claude Code の利用停止を指示したという報道がある(孫引きで一次未確認、単独なら E0)。Enterprise の席ベース契約の現在の扱いはカードから判定できない [FND-0210] [SRC-0612#c5]

## TH04-Q4 モデル階層の使い分けと費用・品質

### 答え

主要ベンダーは 3 層構成を続け、用途別の使い分けを推奨しています。ただし推奨に費用・品質の測定は添えられておらず、階層の使い分けを統制して測った独立研究は束にありません。n=1 の比較では費用が下がり時間が延びました。falsifier(有意差を生まない実測が主流)の判定に足る測定がありません。
