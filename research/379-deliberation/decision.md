# 議長の裁定(#379 記録用ブランチ records の写しを、書き込み権限を持つ者とジョブが書き換えられる)

入力: 議題 `council-00-agenda.md`、調査 `survey-379-1-internal.md`・`survey-379-2-external.md`、意見 `council-01-drafter.md`(起案)・`council-02-field.md`(現場)・`council-03-qa-audit.md`(品質監査)・`council-04-standards.md`(規格)・`council-05-defender.md`(弁護)。

## 0. 骨格

5 委員とも、防止ではなく検出を選んだ。admin(個人所有では所有者)はルールセットを外せ、GitHub の上では書き換えを防げない(外部調査)。弁護の委員も、実装が EV-0185 の開示と逆を向いていること(写しを API より優先して数える、records を正として突合する、署名の無い author の一致を裏づけに数える)を欠陥と認めた。

内部調査の向きの誤りを、起案と品質監査の委員が訂正した。G-6 の差し戻しの記録を消すと率が下がり、0% の継続で停止の側へ倒れる。危ないのは偽の差し戻しを**足して** 0% の継続を切り、引き下げを避けることである(autonomy.mjs)。R-4 はこの向きで決める。

## R-1 要求の形 — 裁定: 「記録を残さずには書き換えられない場所」へ改め、検出を要求する

- 写しと様式の置き場を、「成立した記録を、記録を残さずには書き換えられない場所」とする(5 委員)
- 検出の要求(起案・現場・規格・品質監査):
  1. 置き場の履歴が連続し、巻き戻しも削除もできない(既存のルールセットの non_fast_forward・deletion)
  2. 成立した記録の変更・削除・名前の変更と、マージより前に置かれた写しを、出荷の集約が履歴の走査で検出し、欠落として数える
  3. 出荷ごとに置き場の先頭の識別子を基底ブランチの出荷の証跡へ記録し、次の集約が今の先頭の祖先であることを確かめる(巻き戻しの検出)
  4. 規制業と CL2 以上は、置き場への書き込みごとにホスティングが検証した署名を要する(準拠テンプレートの records-signed.json)。署名の無い書き込みを欠落にする(規格)
- 訂正は、元の記録を指す訂正の記録を足す形に限る。起きた書き換えは、例外承認でだけ受け入れる(弁護・現場)
- 防止の一般要求、外部の WORM・透明性ログは課さない。規制業での外部の記録は推奨とし、残余を開示する。課さないと決めた旨と理由を本文に書く
- 誤検出の対策(現場): 置き場を整形・自動修正・改行の変換の対象から外す設定を準拠テンプレートに既定で置き、AI の担い手による置き場の既存ファイルの編集を拒否する

## R-2 写しと API の突合 — 裁定: 不変の欄はホスティングの記録を正とし、G-6 は突合を通った記録で数える

- 不変の欄(レビューの識別子・user.id・commit_id・submitted_at)はホスティングの一次記録を正とし、不一致を欠落にする。写しにだけあるレビューは欠落にする(5 委員)
- 本文・状態は写しを取った時点の値を記録とし、ホスティング側の変化(マージ後の編集・取り下げ)は所見にする。アカウントの削除(ghost)と API を読めない場合は欠落にせず「照合できなかった」として件数を開示する(弁護・起案)。ただし照合できなかった写しで G-6 を数えない(品質監査)
- 出荷の後は基底ブランチの複製を正とし、mergeRecordSources と G-7 基準5 の向きを改める(5 委員)
- 存在しない PR 番号の写し(品質監査 P-3)は、ホスティングで PR を照合できなければ数えない

## R-3 様式の帰属 — 裁定: 候補 (b) を採る

- 署名の無い author の一致を、判定記録の帰属の裏づけに数えない。本文の「弱い裏づけ」の文を削る(5 委員)
- 署名はホスティングの検証で確かめ、committer と author の両方を数値の識別子で照らす(introducedBacking と揃える)。照らすのは置き場で様式を足したコミット。名義の共有(ADR-0107)の扱いを揃える
- 「記名者本人の push」は、push の主体を機械が読める場合に限る(現場・規格)
- 裏づかない判定記録は今までどおり欠落にせず、自己申告として開示する
- 保証の主張の成立条件4(G-7 と G-8 を別の自然人が記名)は、帰属を裏づけた記名だけで判定する(品質監査 P-8・起案)

## R-4 先取りと、列挙の漏れ — 裁定

- 写しの先取り: (i) 写しの取り出しの処理は、既存の写しと不変の欄が食い違えば失敗し、衝突を記録する(一致すれば成功で終える。再実行は正当に起きる)、(ii) マージより前に置かれた写しを履歴の走査が欠落にする、(iii) ホスティングとの突合で写しにだけあるレビューを欠落にする(起案・現場・規格・品質監査)
- 委任の判定が数える G-6 の差し戻しの記録を、効力を持つ記録の列挙と用語の定義に加える(起案・現場・品質監査)。帰属を確かめられない差し戻し(偽の差し戻しを含む)は数えない。この向きは停止の側へ倒れ、偽の差し戻しで 0% の継続を切る経路を塞ぐ。規格・弁護の「足すと緩む向きに働く」は、内部調査の向きの誤りに基づくため採らない
- roster-ids の提案は、ホスティングで照合した値に限る(列挙には加えない)

## R-5 開示と記録 — 裁定: 候補 (c) を (a)(b) と組で採る

- 書き込みの主体を限れないこと(ジョブのトークンはワークフローを限れない、admin はルールセットを外せる)を、構成ごとの固定の文と走査の件数で保証の開示の項目1 に出し、外部へ渡す開示にも載せる
- ADR-0109 を新設し、ADR-0070 決定5 の「書き換えられない場所」を置き換える。ADR-0106 の a1 の却下は維持する
- EV-0185 は、本 ADR で置き換えて削除する(識別子は再利用しない)。新しい EV: EV-0224(検出を選び防止を課さない判断と、検出の技術的前提)、EV-0225(写しと API の突合の欄の分け方と誤検出)、EV-0226(署名の無い author の一致を数えない判断の運用の負担)、EV-0227(差し戻しの記録を効力を持つ記録とする判断)
- IMPL-0353 は規定を改め、検出の実装が降りたら delivered にする。IMPL-0128(記録の帰属)は署名の無い一致を数えない規定へ改める。新しい IMPL は IMPL-0432 以降
- 準拠テンプレートへは本件で降ろす

## 範囲外の申し送り

- gate-g5・ship-evidence の verify が `pull_request` で PR の側の定義を読む(品質監査)。既存の #371(同じ PR でワークフローとゲートの検査を書き換えて検査を緩められる)の論点として扱う
- generate-profile.mjs:2841 のコメントが ADR-0106 決定6 と食い違う(現場・規格)。本件の実装で直す

## 採らない案

- 防止の一般要求、外部の WORM・透明性ログの義務(GitHub の上で手段が無く、admin がルールセットを外せる。規制業でも推奨にとどめる)
- 写しを API より優先して数える現行の扱い
- records を正とする突合の向き
- 署名の無い author の一致を「弱い裏づけ」として数えること
- 候補 (c) の単独の採用(数え方が変わらない)
- 差し戻しの記録を効力を持つ記録に入れない案(偽の差し戻しの経路が残る)
