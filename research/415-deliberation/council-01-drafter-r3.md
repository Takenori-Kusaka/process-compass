## Q1 N 案に賛成か

### 結論

**条件つきで賛成する**。ただし N 案のままでは、次の4つが欠ける。

1. **最初の判定が遅い**。途中の判定の契機は 7.7.4・7.7.6・7.7.5 の再判定だけである。7.7.4 の行は「期間予算の残20%未満、かつ不合格」なので、確定の直後に乙になっても、B-2 が見るのはステージの終わり近くになる。SG の検査を外して失う「早く見つける」働きを、別の形で取り戻す必要がある
2. **保留の抜け道**(M2-2 の本体)は、SG を外しても途中の判定に残る。乙・丙のまま「保留」と判定すれば、7.7.5 は継続にしか掛からないので、回数に数えない
3. **2.10.6 の十分条件**(区分が乙・丙なら見込みが立つ)を残すと、手順1 の「不足」を何で測るかで H2-4 が戻ってくる
4. **判定者**(M2-5)が N 案の契機ごとに書かれていない

### 案(本文へ入れる形)

N 案の 1〜7 に、次の4点を足す。

(a) 7.7.3 の途中の判定の契機に、初回の判定を足す。

```markdown
- ステージ移行ゲートで次ステージの SC-M を確定した後、到達の見込みを初めて算定できた時点(観測の窓の中の単位期間が3に達した時点)で、材料の集計の担い手は会議体(B-2。B-2 を置かない体制では事業決裁者)へ必達基準2 の判定を求める。区分が甲であれば、判定は持ち回りでよい
```

(b) 7.7.3 に、SG で判定しないことを明記する(「書かれていない」と「課さないと決めた」を分ける)。

```markdown
**ステージ移行ゲート(SG)では、必達基準2 を判定しません**。次ステージの SC-M の規模は、第2章 2.10.1(計画容量の 60% 以下)と 2.10.2(実測スループットに対する作業単位の個数で合意)によります。終わるステージの SC-M を完了したかは、ステージ移行ゲートの判定基準(第2章 2.4)で判定します。
```

(c) 7.7.5 要求事項4 に、保留を足す。

```markdown
必達基準に不合格がある状態での保留(第3章 3.7.3)も、継続と同じく1回と数える
```

(d) 2.10.6 の十分条件の段落を、手順の順序を変えない形で書く。手順1 で足りるかは、2.10.6 の見込み(全層の残り)で測る。区分は手続を始める契機にだけ使う。

```markdown
第7章 7.7.3 の到達の見込みの期間の組が乙または丙になったときは、見込みが立ったものとします。手順の順序は変えません。手順1 で足りるかは、本節の見込み(全層の残る作業単位)で評価します。必達基準2 の区分は、第7章 7.7.3 の判定する者が扱います。
```

(e) 判定者を契機ごとに書く(M2-5): 7.7.4 の上程と (a) の初回の判定は会議体、7.7.6 は点検の実施者の記録を会議体が判定、7.7.5 の再判定は継続を判定した会議体とする。7.6 の段階2 の事業決裁者の決定は、必達基準2 の判定に当たらない(7.6 は到達の見込みに結び付かないため)。

### 理由

1. **SG の検査は、2.10.1 を裏から置き換えていた**(M2-12)。60% の上限は EV-0150 の差し替え条件で見直す規則であり、7.7.3 の甲の条件で規模の上限を引き締めるのは、規模の規則を2つ持つことになる。上限が足りないなら、2.10.1 を直接直すのが筋
2. **H2-2・H2-3 は、SG を「禁止」にしたことから出た**。禁止だと、最小値0のときに継続を出す手が無く、残る逃げ道は同じゲートでの置き換えだけになる。途中の判定は4値で出せるので行き詰まらない。乙で継続すれば 7.7.5 に数える
3. **初回の判定(a)で、早く見つける働きを取り戻す**。品質監査の第2巡の案(S1 の最初の期の終わりを最初の判定の期限とする)と同じ向きで、全ステージへ一般化した。SG-0 の後もこの規定で S1 の初回が判定されるので、H2-1 は「S0 の初回は SC-M が無いので算定できない」(N 案4)だけで閉じる
4. **7.6 と必達基準2 は測る対象が違う**。7.6 は全層の逸脱の段階、必達基準2 は SC-M の足切りである。値が違うことは欠陥ではない。第1巡で起案と弁護が「別の値を使うのは欠陥」とした前提を改める。逆向きの食い違い(7.6 は重いのに必達基準2 は合格)は、同じスループットから作る限り、SC-M だけの遅い側の端が全層の見込みより楽観になることが少ないため、起きにくい。ただし実証は無い(E0。EV-0200 の差し替え条件に「7.6 の段階3 の間に必達基準2 が甲だった件数」を足す)
5. **保留を数える**(c)。SG の延長(M2-2)を外しても、途中の判定の保留が同じ抜け道になる。不合格のまま投資を続ける点で、継続と保留は区別できない

## Q2 M2-6 期日・予算の延長で甲に戻す継続を 7.7.5 に数えるか

### 結論

**数える**。甲に戻した手段で分ける。

- **SC-M の縮小で甲に戻した継続**: 数えない(範囲を絞って到達できる計画へ戻すことは、7.7.3 が常に併置を求める正当な選択。縮小の累計は 7.6 の SC-M の変動率が拾う)
- **予算の追加か期日の延長を含めて甲に戻した継続**: 1回と数える(不合格に対して資源を足して続けることは、継続の偏りの定義そのもの)
- 根拠水準のマークを付ける(数え方は実証が無い)

### 案(本文へ入れる形)

7.7.5 要求事項4 の必達基準2 の文を改める。

```markdown
必達基準2 は、継続の判定で確定した変更を当てた後の区分が乙または丙であるとき、または予算の追加か期日の延長を含む変更で区分を甲に戻したときに、1回と数える。SC-M の縮小だけで甲に戻した継続は数えない
```

```markdown
:::caution[暫定 EV-0202 / 見直し 2027-05]
**対象**: 7.7.5 要求事項4 の回数を案件の中で通算し、数え直さず、保留を数え、予算の追加か期日の延長で甲に戻した継続を数え、SC-M の縮小だけで甲に戻した継続を数えない判断。
**根拠の水準**: E0(なし)。
**差し替え条件**: 2 期分の、甲へ戻した継続の件数(手段ごと)と、その後に SC-M を完了しなかった件数。上限に達した件数と、その後の判定。SC-M の縮小だけで甲へ戻した継続を繰り返し、7.6 の SC-M の変動の発火を経なかった案件がある場合は、数え方を見直す。

投じた資源が大きいほど中止が遅れる傾向は、Simonson と Staw(1992)ほかの実験で確かめられています。手段で数え方を分ける判断を確かめた資料はありません。
:::
```

### 理由

1. 突合 M2-6 のとおり、7.6 の予算の閾値は配賦に対する超過で測るため、配賦を足すたびに基準が動き、延長の累計を何も拾わない
2. 予算・期日の追加は、拡大(escalation)の文献が問題にする行為そのもの(外部調査 §1.13)。縮小は逆向きで、到達の量を減らして方針を変える行為である
3. 縮小を数えないことの抜け道(少しずつ削る)は、7.6 の SC-M の変動率(段階2 で 15%、段階3 で 25% 超)が、直近の確定からの累計で拾う(`EE:217`)

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 甲に戻した継続はすべて数えない(第2巡の裁定のまま) | M2-6。予算・期日を延ばし続ける経路が残る |
| 甲に戻した継続をすべて数える | 範囲の縮小にまで上限を消費させ、縮小を避けさせる。7.7.3 の併置の要求と当たる |
| 7.6 の予算の基準を当初の配賦に固定して延長の累計を拾う(突合の例) | 7.6 は ADR-0095 のまま(N 案3)。配賦の基準を変えると 7.7.1 の配賦と閾値の意味を同時に変える。回数で拾うほうが局所的 |

## Q3 N 案で採らない第2巡の定めを ADR にどう書くか

### 結論

ADR-0099 は未採用(未追跡のファイル)なので、決定の本文は N 案の形で書き直してよい。撤回した定めは「検討した選択肢」に、**一度採ってから撤回した**経緯と、撤回の理由になった突合の所見を書く。本文側にも、課さないと決めたことを (b) の文で残す。

### 案(ADR-0099「検討した選択肢」に足す行)

| 選択肢 | 出した者 | 採否と理由 |
| --- | --- | --- |
| ステージ移行ゲートで、判定の時点ごとの表(継続・移行/保留/中止)により必達基準2 を判定する | 突合(第1版 H-1)・起案(第2巡) | 第2巡で採り、第3巡で撤回。SG-0 が S0 の初回に入るかが割れ(第2版 H2-1)、SG-1・SG-2 の判定の語と衝突し(M2-3)、中止と定常運用への移行で記録が定まらない(M2-9)。終わるステージの完了は 2.4 の判定基準が問い、次ステージの規模は 2.10.1・2.10.2 が受け持つ。代わりに、確定の後に初めて算定できた時点で判定させる |
| ステージ移行ゲートで、区分が甲でない計画を確定しない | 起案(第2巡) | 第2巡で採り、第3巡で撤回(起案も撤回に同意)。2.10.1 の 60% の上限を 7.7.3 から実質的に置き換え(M2-12)、最小値0の窓で継続を出せなくし(H2-2)、同じゲートでの端の取り方の置き換えを唯一の逃げ道にする(H2-3)。規模の上限が足りないなら、EV-0150 の差し替え条件により 2.10.1 を直接見直す |
| 7.6 の予算・日程の見込みを、到達の見込みの遅い側の端で測る | 5 委員(第1巡)。前提は「7.6 と必達基準2 が別の値を使うのは欠陥」(弁護) | 第1巡で採り、第3巡で撤回。SC-M だけの見込みは SC-B・SC-P を削っても動かず、段階1 の吸収がすべて段階2 へ流れ、ADR-0095 が採らなかった案と同じ帰結になる(第2版 H2-4)。7.6(全層の逸脱の段階)と必達基準2(SC-M の足切り)は測る対象が違い、値が違うことは欠陥ではないと前提を改めた |
| 2.10.6 で、区分が乙・丙なら手順1 の結果を待たずに 7.6 へ起票する | 起案(第2巡) | 第2巡で採り、第3巡で撤回。2.10.6 の順序の規定(手順を入れ替えない、手順1 で不足したら起票)と当たる(H2-4)。区分は手続を始める契機にだけ使う |
| 7.6 の予算・日程を、全層の残りで到達の見込みの記録から測る | 突合(第2版 H2-4 の案 b) | 採らない。7.6 は ADR-0095 のまま 2.10.6 の見込みで発火させれば足り、新しい記録へ結び付ける利点が無い |

- 「ADR-0095 との関係」は「補う」のままでよい(N 案で 7.6 を変えなくなるため)。影響の節から、7.6 の閾値の確定し直し(M2-10)の文を外す
- 経緯の節に「第2巡の起案が SG の検査を置き、第2版の突合がその組み合わせの矛盾を示し、第3巡で範囲を狭めた」と一段落書く。後の読み手が、SG での判定を足す提案を再び出したときに、却下の理由をたどれるようにするため

### 理由

- 採らないと決めたことを明記する(コアポリシー)。とくに SG での判定は「足せば信頼性が上がる」と見えやすく、再提案されやすい。撤回の理由(規模の規則の二重化と行き詰まり)を表に残さないと、同じ矛盾を繰り返す
- ADR が未採用のうちは、決定の本文を書き直してよい。採用済み ADR の書き換えの禁止には当たらない

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 撤回した定めを ADR に書かない(最終形だけを書く) | 再提案のときに理由をたどれない。「書かれていない」と「課さないと決めた」が区別できない |
| 第2巡の形で ADR-0099 を採用し、N 案を ADR-0100 で置き換える | 未採用の ADR を、採用してから置き換える理由が無い。矛盾を含む決定を一度でも規範にしない |
