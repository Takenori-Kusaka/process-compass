## (1) H-1 判定の時点ごとの「比べる対象」と「残り」

### 結論

判定の時点ごとに、比べる対象(どの SC-M か)と残り(どの期間・予算か)を、7.7.3 に表で定めます。到達の見込みの記録には「比べる対象」の欄を足し、記録ごとにどの行に当たるかを書かせます。

| 判定の時点 | 比べる対象(残る SC-M) | 残り(期間・予算) | 記録を作る者・頻度 |
| --- | --- | --- | --- |
| ステージの途中(7.7.4 の検知、7.6 の段階の評価、2.10.6 の見込み) | 進行中のステージの SC-M の残り | そのステージの期日までの残る期間、そのステージに配賦した期間予算・要員予算の残り | D-0 表1 の担い手が、**7.7.2 の期(単位期間)ごと**に作り直す。版を残す |
| 7.7.6 の棚卸し | 同上 | 同上 | 棚卸しの時点の最新の版を引く。古ければ作り直す |
| SG の「継続 / 移行」 | **次ステージの SC-M の案** | 同じ判定で確定しようとする次ステージの期間・期間予算・要員予算の案 | SG の材料として担い手が作る |
| SG の「保留(継続検証)」 | 進行中のステージの SC-M の残り | 延長の案(延ばす期間と、足す予算) | 同上 |
| 終わろうとするステージの結果 | 必達基準2 で判定しない。SC-M を完了したかは**実績**として「見積りと実績の差」の節に書く | — | — |

- SG の「継続 / 移行」で区分が乙・丙になるのは、**次ステージの案そのものが、観測から見て届かない**場合です。このとき、案を直す(SC-M を減らす、期間・予算を足す)か、乙のまま継続と判定して 7.7.5 の要求事項を満たすかを、会議体が選びます
- 終わろうとするステージで SC-M が残っていることは、必達基準2 の丙として扱いません。それは見込みではなく起きた事実です。この事実はステージの途中で 7.6 と 7.7.4 が拾っているべきものです。拾えていなかった場合は、その件数を EV-0200 の差し替え条件の「見逃し」として数えます

### 理由

- **ステージの途中こそ、必達基準2 が効く時点です**。SG だけで判定すると、ステージの終わりにならないと判定が働かず、「間に合わない」と分かっても誰も止められません。7.7.4 の担い手が「裁量なく起票する」(`exception-escalation.md` 7.7.4)ためには、**その期の区分が記録に存在している**必要があります。そのため、作り直す頻度を 7.7.2 の期に揃えます。7.7.2 の消化の指標は期ごとに測っており、完了件数は機械が数えられます。期ごとの作り直しは、現場で回る頻度です〔推: 記録の大半は担い手(AI でよい)の転記〕
- **SG での判定は「ほぼ常に甲」になるので無意味だ」という指摘(突合 H-1)には同意しません**。次ステージの SC-M は計画容量の 60% 以下に置きますが、計画容量は実測の**平均的な**速さから出ます。遅い側の端は窓の中の**最小値**から出ます。窓の中で最も遅い期が平均の6割を下回るチームは、SG でも乙になります。〔経〕1〜2 名の体制、AI の担い手を替えた直後、受託で顧客の確認待ちが多い案件では、こうした変動は珍しくありません。SG の判定は、**「次の案が、自分たちの観測した遅い期にも耐えるか」を確かめる検査**として意味を持ちます
- SG で予算の案を遅い側の費用より小さく置くと、その時点で乙になります。これは裁定 R-3(稟議で上側を下回る額を示して受容しても判定は変わらない)と同じ向きで、正しい結果です。足りない予算を自覚して継続するなら、7.7.5 の記名と理由が残ります
- 終わろうとするステージを見込みで判定しないのは、残る期間がほぼ 0 で区分が自明になるからです(突合 H-1 のとおり)。見込みの判定に実績を混ぜると、記録の意味が曖昧になります

### 譲れない点

- 到達の見込みは、**ステージの途中で期ごとに**作り直す。SG の時点だけの記録にしない(突合 H-2 と同旨)
- SG では、次ステージの案を判定の対象にする。終わろうとするステージの SC-M の未完了は、実績として別に書く
- 記録ごとに「比べる対象」(表のどの行か)を書く。どの残りと比べたかが読めない記録を、判定の材料にしない

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| SG だけで必達基準2 を判定する(現行の実装) | 残りが定まらず、判定が縮退する(突合 H-1)。ステージの途中の 7.6 と 7.7.4 が読む記録が無くなる(突合 H-2) |
| SG で、終わろうとするステージの SC-M を比べる対象にする | 残る期間がほぼ 0 で、区分が自明になる |
| SG では必達基準2 を判定しない | 次ステージの案が観測に耐えるかの検査が無くなり、届かない案を確約として通す経路が残る |
| 作り直しの頻度を組織に任せる | 作り直さない期に 7.7.4 の検知の材料が無くなる。担い手が「作り直すかどうか」の裁量を持つ |

## (2) H-3 S0 の初回の判定

### 結論

1. **S0 の初回の必達基準2 は「判定の材料なし(S0 の初回)」と記録し、合格とも不合格とも書かない**。7.7.5 の要求事項4 の回数に数えない
2. 裁定の「7.7.9 の見積りの幅で代える」は採らない
3. S0 の初回の期間予算は、**打ち切りの枠**として扱うと 7.7.3 に書く。期間か予算のどちらかが尽きた時点で、SG-0 の判定を求める(会議体への判定要求)。尽きたことを理由に、S0 の初回の延長を価値責任者が決めてはならない
4. S0 の初回の外で実測が無い場合(観測の窓の単位期間が3つに満たない、作業単位の定義を変えた直後など)は、**材料なしを不合格として扱う**。必達基準1 の「測定が行われていない」を不合格とする定めと同じ型にする。ただし作業単位の定義の変更と、3.13.1 の変化点3・4 の直後は例外とし、例外を使ったことを記録に書かせる(下記の理由)

### 理由

- **突合 H-3 のとおり、現行の実装は S0 の初回を無条件の甲にします**。残る SC-M が 0 個だからです。裁定はこれを「常に不合格になる」と読んで代替を置きましたが、前提が逆でした〔確: `lifecycle.md` 2.10.2 要求事項2、`exception-escalation.md` 7.7.9 要求事項8〕
- **7.7.9 の見積りの幅で代えない理由**: 単位が合いません。7.7.9 の見積りは G-1 の時点の案件全体の値で〔確: 7.7.3 の新しい段落が自ら書いている〕、S0 の初回の残りとは比べられません。ステージ分を切り出す手順を書けば、その切り出しは人の配分の作文になります。本標準は「判定は人の見積りではなく、記録された観測から」と決めたばかりです〔確: 裁定 R-1〕。その例外を S0 の初回にだけ置けば、最も不確かな区間で人の見積りが判定に戻ります
- **S0 の初回に疑似の SC-M(例: SG-0 の判定基準の材料に当たる作業単位)を置かない理由**: 2.10.2 要求事項2 は、実測が無い段階で確約範囲を置かないと定めています。疑似の SC-M は、名を変えた確約範囲です。どの作業単位を「SG-0 の材料」に数えるかは価値責任者が途中で動かせ、比べる対象が交渉の対象になります
- **打ち切りの枠にする理由**: S0 の初回は探索の区間で、止める手段は「枠を使い切ったら判定を求める」が最も単純で、確実に回ります〔推〕。1〜2 名の体制でも、期日と配賦額が決まっていれば誰でも確かめられます。7.7.4 の消化進捗比(受入基準で数える)は S0 の初回でも働きます。また 7.6 の予算・日程の段階は、S0 の初回では到達の見込みの記録を持たないため働かなくなります(突合 H-2)。その空白を打ち切りの枠で埋めます
- **S0 の初回の外の材料なしを不合格にする理由**: 測ることは担い手の務めです〔確: D-0 表1「フローの観測と見込みの報告」〕。測らないことで合格・保留を得られるなら、測らないほうが得になります。必達基準1 は同じ理由で「測定が行われていない」を不合格にしています〔確: `exception-escalation.md` 7.7.3 の表〕
- **作業単位の定義の変更と変化点の直後を例外にする理由**: 本標準が見込みに使うことを禁じる期(定義が違う期。2.10.2 要求事項4 は同じ定義を用いると定める)を除くと、窓が一時的に空になります。これを不合格にすると、定義を正しく直したチームが罰を受け、定義を直さない動機が生まれます。ただし例外には期限を付けます(窓の単位期間が3つたまるまで)

### 譲れない点

- S0 の初回を**無条件の甲にしない**(現行の実装を直す)
- S0 の初回の判定に、人の見積り(7.7.9 の幅の切り出し)を入れない
- S0 の初回には、尽きたら判定を求める打ち切りの枠を置く
- S0 の初回の外で、測らないことが合格・保留につながる経路を残さない

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 7.7.9 の見積りの幅で代える(裁定 R-1) | 単位が合わない。最も不確かな区間で人の見積りが判定に戻る |
| S0 の初回に疑似の SC-M を定義する(突合 H-3 の第1案) | 2.10.2 要求事項2 と当たる。比べる対象を途中で動かせる |
| S0 の初回の材料なしを不合格にする(第1巡の本委員・品質監査の案に近い形) | SG-0 と S0 の初回の途中の判定がすべて不合格になり、7.7.5 の回数を実測の無いことで消費させる。裁定の懸念のこの部分は正しい |
| S0 の初回の外でも、材料なしを回数に数えない | 測らないことが得になる |

---

補足(1 の根拠の確認): 計画容量は「観測の窓で測った、単位期間あたりの完了スループットの**平均** × 当該ステージの単位期間の数」と定義されています〔確: `overview.md` 1.4 の用語の表〕。遅い側の端は同じ窓の**最小値**です。このため、SG の「継続 / 移行」で次ステージの案が乙になるのは、最小値 < 平均 × 0.6 のときです(SC-M を上限の 60% に置いた場合)。SG での判定が常に甲になるわけではありません。

## (3) H-4 7.7.5 要求事項4 の数え直し

### 結論

1. **数え直しの条件を必達基準2 に限る**(括弧の中に入れる)。必達基準1・3〜5 は数え直さない
2. **数え直すのは、SC-M・予算・期日を変える判定が記録され、かつ変えた後の到達の見込みが甲になったときに限る**。変える判定を記録しただけでは数え直さない(突合 H-4 の直し方に同意)
3. 甲になったかは、**変えた時点の同じ観測の窓**で算定し直して確かめる。数え直しのために窓の取り方・端の取り方を変えてはならない(端の取り方は既に「当該ステージの中で変えない」)
4. 丙の継続に要する変更(7.7.3)は、それだけでは数え直しの理由にならないと明記する。変えた後に乙なら、回数は続く
5. 数え直しても、それまでの回数を記録から消さない。判定記録に「数え直し(前の系列 n 回、変えた判定の記録の所在)」を書く
6. SC-M を削って甲にすることを繰り返し、ステージのゴールが痩せていく経路は、**7.6 の SC-M の変動率**で拾う。そのことを 7.7.5 の解説に書く。新しい回数の上限は足さない
7. SC-M を変える判定は、2.10.6 のとおり事業決裁者または B-2 が行う。価値責任者が SC-B・SC-P を削ったことは、SC-M を変える判定に当たらず、数え直しの理由にならない

### 理由

- **現行の文言では、上限が働きません**(突合 H-4)。丙の継続には SC-M・予算・期日の変更が必須なので、丙の継続は毎回数え直されます。7.7.5 は要求事項4 を「最も強い歯止め」と書いています。現場では、SC-M を1件動かす判定を添えれば毎回数え直せると分かれば、それが定型になります〔経〕。歯止めが定型の手続で外れるなら、歯止めではありません
- **「変えた後に甲」を条件にする理由**: 数え直しを認める正当な場面は、「案を観測に合わせて直し、直した案が観測から届く」場面だけです。これは SG の「継続 / 移行」で次ステージの案を判定するのと同じ検査です((1) の表)。基準を揃えると、現場は1つの規則で覚えられます
- **同じ窓で確かめる理由**: 変えた直後に新しい観測は無いため、新しい窓を待つと数え直しが1期以上遅れます。同じ窓で算定し直せば、担い手が裁量なく判定できます。窓や端の取り方を変えて甲を作る経路は、変更の禁止で塞ぎます
- **必達基準2 に限る理由**: 必達基準1(事業仮説の反証)や必達基準4(法規制の阻害要因)の不合格は、SC-M・予算・期日を変えても解消しません。それらを数え直す理由はありません
- **回数を消さない理由**: 数え直しが何度起きたかは、継続の偏りの観測そのものです。EV-0200 の差し替え条件(7.7.5 の上限に達した件数)を数えるにも、系列の履歴が要ります
- **新しい上限を足さない理由**: SC-M を削って甲にすることは、ゴールを小さくして届かせる正当な選択です(2.10.6 の順序の延長)。削りすぎは 7.6 の SC-M の変動率が既に測っており〔確: `exception-escalation.md` 7.6 の箇条「SC-M の変動率は、直近の確定からの追加と削除の累計で測る」〕、段階に応じて判定者が上がります。同じものを別の回数で二重に縛る理由はありません

### 譲れない点

- 変える判定の記録だけで数え直さない
- 丙の継続を、上限の外に置かない
- 数え直しの履歴を記録から消さない

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 現行の文言(SC-M・予算・期日を変える判定の記録で数え直す。全必達基準に掛かる) | 上限が働かない(突合 H-4) |
| 数え直しを一切認めない | 案を観測に合わせて直し、届くと確かめた後も古い回数が残る。案を直す動機が消え、直さず中止へ流れるか、上限の手前で判定を先延ばしにする〔推〕 |
| 数え直しを、変えた後の次の期の観測で甲になったときに限る | 担い手の判定は裁量なく出せるが、1期以上遅れる。その間の 7.7.4 の検知が、古い系列で起票され続ける。同じ窓での算定と端の取り方の固定で、作文の経路は塞げる |
| 数え直しの回数に別の上限を置く | 7.6 の SC-M の変動率と二重になる |
| ステージの切り替えで数え直す(起案の第1巡の案) | 裁定のとおり採らない。ただし SG で次ステージの案が甲と判定されれば、(3) の結論2 で数え直される。結果として、正当な場合だけステージの境界で数え直しが起きる |

## (4) M-1〜M-3

### M-1 比べる組ごとの区分の組み合わせ

**結論**: 「組のうち最も悪い区分を、案件の区分とする」を 7.7.3 に足します(突合の直し方に同意)。様式の「区分」欄は、**組ごとの区分**(期間 / 期間予算 / 要員予算)と、最も悪い区分の両方を書かせます。受託の定額契約などで費用の組を測れない場合は、その組を「未測定」と書きます。案件の区分は、測った組のうち最も悪い区分とします。そのうえで「費用側未測定」を区分と並べて表示させます(第1巡 R-1 結論7)。

**理由**: 必達基準2 の不合格の定義は「残る予算**または**期間」です。どれか1つでも届かなければ届きません。組ごとの区分を書かせるのは、会議体が判定(SC-M を減らすのか、予算を足すのか、期日を延ばすのか)を選ぶ材料になるからです。最も悪い区分だけでは、どの残りが足りないのかが分かりません。

**譲れない点**: 記入者が組を選べる余地を残さない。未測定の組を「甲」と書かせない。

**採らない案**: 期間の組だけで区分を決める(予算が尽きても期日内なら合格になる)。組ごとの区分の多数決(「または」の定義に反する)。

### M-2 スループットの最小値が 0 のとき、最小標本数との関係

**結論**:

1. **完了 0 の単位期間を、窓から除いてはならない**。最小値が 0 のとき、遅い側の端は「到達しない」とし、区分は乙(速い側でも届かなければ丙)とする
2. 0 の単位期間が生じやすい体制(1〜2 名、休暇・顧客の確認待ちで止まる期がある体制)には、**単位期間を長く取ること**で対処する。単位期間は 2.10.2 要求事項4 で組織が記録する値である。7.7.3 の解説に、単位期間を短く取ると最小値が 0 になりやすいこと、そのときは単位期間を見直すことを書く。単位期間の変更は作業単位の定義の変更と同じく、変えた後の窓で算定し直す。**当該ステージの中で、区分を変える目的で単位期間を変えてはならない**
3. **第4章「閾値の設定と較正」の最小標本数(既定 30 件)は、必達基準2 の判定に掛けない**と明記する。7.7.3 が借りるのは観測の窓だけとする。代わりに、窓の中の単位期間が3つに満たない場合を「材料なし」とする((2) の扱い)
4. EV-0201 の差し替え条件に、0 の単位期間の件数と、0 を理由に乙となった判定の件数を加える

**理由**:

- **0 を除かない理由**: 除けるなら、遅い期を「例外の期」として除く経路が開きます。止まった期は実際に起きた事実で、止まる期のあるチームは、到達の見込みも実際に不確かです〔推〕。乙は継続を禁じないため、記名と理由を書けば続けられます。偽の不合格の損失は記録の手間と 7.7.5 の回数で、差し替え条件で観測します
- **単位期間で対処する理由**: 1〜2 名の体制で、単位期間を1週間に取れば休暇の週は 0 になります。2週間や1か月に取れば 0 は稀になります〔経〕。窓の中の期の数は減りますが、最小値と最大値の取り方はそのまま使えます。新しい規則を足さず、既存の記録の値の選び方で対処できます
- **最小標本数を掛けない理由**: 第4章の要求事項1 は、適用を「傾向の確認と第5章 5.4.6 の検知条件に用いる閾値」と定めています〔確: `gate-criteria.md:1928`〕。その解説が問題にしているのは比率の不安定さです〔確: `gate-criteria.md:1932`〕。必達基準2 の見込みは比率ではなく、件数の最小値と最大値です。件数が少なければ幅は広がり、乙になりやすくなります。少ない件数を、判定を保守側へ倒す形で正直に反映します。逆に 30 件を掛けると、1〜2 名の体制では四半期に 30 件の完了に届かないことがあり〔経〕、その間は必達基準2 が常に「材料なし」となります。(2) の規則では材料なしは不合格なので、小さな体制が恒常的に不合格になります。規則を守るほど判定が意味を失います

**譲れない点**: 0 の期を除かない。最小標本数の不足を、材料なしや合格へ落とす経路にしない。

**採らない案**: 0 の期を窓から除く(遅い期を除く作文の経路)。0 のとき「実測なし」とする(測ったのに材料なしになり、(2) の規則と当たる)。最小標本数 30 件を掛ける(小さな体制で必達基準2 が恒常的に働かない)。単位期間を本標準が一律に定める(作業単位の定義と同じく組織に依る)。

### M-3 2.10.6 との整合

**結論**:

1. 2.10.6 に「期日に間に合わない見込みは、第7章 7.7.3 の到達の見込みの記録の遅い側の端で評価する」を足す(突合の第1案)。価値責任者が手続を始める点(区分が乙・丙になった時点)は、7.6 の発火と同じ記録とする
2. 2.10.4 の2指標(進捗率・滞留期間)は、2.10.6 の見込みの**補助の材料**として残す。滞留の通知は、見込みの記録がまだ乙になっていない段階の早い兆候として使う。2.10.6 の文言を「2.10.4 の2指標**と到達の見込みの記録**によって評価します」に改める
3. 単位の違いを明記する。到達の見込みは作業単位の件数で数える(ADR-0098)。7.7.2 の進捗率は受入基準の数で数える。7.7.3 の「2.10.6 の見込みと同じ材料による」は、「同じ作業単位の記録による」と言い直す。7.7.2 の進捗率(消化進捗比)は変えない
4. 到達の見込みのスループットは、**全層(SC-M・SC-P・SC-B と計画外)の完了件数**で数えると明記する(1.4 の完了スループットの定義どおり)。見込みは「残る力をすべて SC-M に向ける」前提の値になる。この前提を 7.7.3 の解説に書く

**理由**:

- **2.10.6 を揃えないと、裁定 §0 で確かめた事実(7.6 と必達基準2 が別の値を使いうる)と同じ食い違いが残ります**(突合 M-3)。価値責任者が「まだ間に合う」と評価して手続を始めない間に、同じ記録の遅い側で 7.6 が発火する、という状態が起きます
- **全層で数える前提を書く理由**: 2.10.6 の手順1(SC-B → SC-P を削る)と見込みの関係が、これで説明できます。見込みは、既に全力を SC-M に向けた場合の値です。乙は「全力を SC-M に向けても遅い期には届かない」ことを意味し、手順1 は、その前提を実際に成り立たせる作業になります。手順1 だけで甲に戻ることは期待できず、乙が続けば 2.10.6 の手順2(期日)と 7.6 の段階2 へ進みます。2.10.6 の順序と、見込みの読み方が一致します〔推〕
- **2.10.4 の指標を補助として残す理由**: 滞留期間は、件数の最小値が下がる前に兆候を出します。早い兆候を捨てる理由はありません。ただし評価の結論(間に合わない見込みが立ったか)は、記録の区分で決めます。価値責任者の評価に裁量を残すと、継続の偏りが入ります

**譲れない点**: 2.10.6・7.6・7.7.3・7.7.4 で、「間に合うか」を1つの記録の遅い側で見る。

**採らない案**: 2.10.6 を対象外とし、ADR-0099 にその旨を書く(突合の第2案。食い違いを記録するだけで、残す理由が無い)。SC-M の完了件数だけで見込みを数える(SC-P の作業を並行させるほど見込みが悪化し、手順1 の効果と見込みの関係が読めなくなる。1.4 の定義とも外れる)。
