## 問い(1) H-1: 判定の時点ごとの「比べる対象」と「残り」

### 結論

7.7.3 に、判定の時点の種別ごとに 3 つの量を定義する表を置きます。対象のステージ、残る SC-M、比べる残りの 3 つです。判定記録の節「到達の見込み」に「判定の時点の種別」の欄を設け、どの行で算定したかを書かせます。

| 判定の時点 | 対象のステージ | 残る SC-M | 比べる残り(期間 / 予算) |
| --- | --- | --- | --- |
| ステージの途中: 7.7.2 の期ごとの算定、7.6 の段階、7.7.4 の検知、7.7.6 の棚卸し | 進行中のステージ | 進行中のステージの SC-M のうち未完了の個数(直近の確定からの増減を含む。7.6 の変動率と同じ数え方) | 予定したステージの終了日までの期間 / 当該ステージに配賦した期間予算・要員予算の残り |
| ステージ移行ゲート(SG)の「継続(移行)」 | 次のステージ | 同じ判定で確定する次のステージの SC-M の個数 | 同じ判定で確定する次のステージの期間 / 次のステージの期間予算・要員予算の配賦額 |
| SG の「保留(継続検証)」 | 延長する現在のステージ | 現在のステージの SC-M のうち未完了の個数 | 保留の解除条件に書く延長の期間 / 延長に配賦する予算 |
| SG で終わるステージそのもの | 必達基準2 の対象外 | — | — |

- **SG で終わるステージの到達は、必達基準2 で測らない**。SC-M を完了したかは、SG の判定基準そのものが測る(2.4)。この旨を書く。書かれていないのではなく、課さないと決めたことを読み手が区別できるようにする
- **SG の「継続」は、確定しようとする値で算定する**。判定者が SC-M・予算・期間を案から変えたときは、変えた後の値で算定し直し、その区分を記録する。案の値の区分だけを記録して、別の値で確定してはならない
- **ステージの途中の算定は、7.7.2 の指標を測る期ごとに、D-0 表1 の担い手が行う**。7.6・7.7.4・7.7.6 は、直近の期の算定の記録を読む。記録の置き場は判定記録ではなく、期ごとの「到達の見込みの記録」とする。判定記録の節は、その記録の版を引いて区分を写す。記録の日付が直近の期より古い場合は、「到達の見込みの記録が無い」に当たる(H-2 への答えを兼ねる)
- **検証可能性**: 判定の時点の種別、対象のステージ、残る SC-M の個数、比べる残り、観測の窓、算定に使った記録の版。この 6 項目が判定記録に在れば、第三者が区分を再計算できる。規格として検証できる書き方になる

### 理由

- 指針 第2部の検証可能性〔未〕は、同じ記録から同じ合否が出ることを求める。時点の種別を書かないと、同じ案件の同じ日に「終わるステージで丙」と「次のステージで甲」の両方が言えてしまう
- SG の「継続」の検査は自明に甲になる、という突合の指摘には同意しません。遅い側の端はスループットの最小で作ります。2.10.1 の計画容量は平均で作ります(`overview.md` 1.4)。最小が平均の 60% を下回る案件では、SC-M ≤ 60% でも乙になります。予算を案より削れば、この組はさらに乙・丙になります。したがって SG での必達基準2 は、**配賦の案が確約範囲を賄えるかの検査**として意味を持ちます。7.7.9 要求事項2 が見張る「目標からの逆算」を、確定の場で観測から突き合わせる唯一の点になります
- 外部の作法との対応: IPA UK 7.8 は各ステージゲートで、これから負担する額の包絡を閾値と比べる〔一次〕。NASA はベースラインを確定する時点で JCL を求め、途中では超過率で引き金を引く〔一次〕。確定の時点と途中の時点で比べる量が違うことは外部でも普通であり、時点ごとに定義を書き分けるのが作法に合う
- 期ごとの算定を置かないと、7.7.4 の第2行は、検知の時点に区分の無い条件になります。担い手が裁量なく起票すること(`exception-escalation.md` 7.7.4 の箇条)が成り立ちません

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| SG では必達基準2 を判定しない(途中の判定だけに限る) | 配賦の案が SC-M を賄えるかを確定の場で検査する点が消える。逆算した予算が観測と突き合わされないまま確定する |
| SG でも終わるステージの SC-M で判定する | 残る期間がほぼ 0 で、区分が自明になる。SG の判定基準と二重になる |
| 途中の算定を 7.6・7.7.4 の発火の都度に限る | 7.7.4 の第2行は区分を発火の条件に含むので、発火の前に区分が要る。都度の算定では、発火の条件が循環する |
| 判定記録の節に算定の全量を毎回書く | 期ごとの記録と判定記録の値が二重になり、食い違いの源になる。判定記録は版を引いて区分を写す |

## 問い(2) H-3: S0 の初回

### 結論

1. **S0 の初回は、必達基準2 を適用外とする**。行に併記する(#226 の作法。「2 … (適用: SC-M を置くステージ。S0 の初回は適用外)」)。判定記録には「合格」ではなく「適用外(S0 の初回)」と書く。7.7.5 の回数に数えない
2. **「実測が無い間は 7.7.9 の見積りの幅で代える」を削る**。7.7.9 の見積りは案件全体の値で、ステージの残る SC-M の見込みとは単位が合わない(突合の指摘に同意)。案件全体の見積りからステージ分を切り出す規則を作ると、その規則が新しい人の見積りになり、R-1 の裁定(観測から算定する)と逆向きになる
3. **S0 の初回の予算・日程の歯止めは、見込みではなく実績で掛ける**と 7.6 に書く。着手決裁の後から SG-0 までの区間で、7.6 の予算の段階は、配賦した予算に対する消化済みの額と確定済みの支出の和で測る。日程の段階は、企画書に書いた SG-0 の予定日に対する経過で測る。これは、着手決裁の前の区間が累計消費で測る作法(7.6「着手決裁の前に消費した分の扱い」)と同じ型である
4. **S0 の初回の後でも SC-M が置けない場合**(SG-0 で次ステージを「継続検証」とした場合など)は、問い(1)の表の「保留」の行に従う。保留でも SC-M が無ければ同じく適用外とし、3 の実績の歯止めを当てる
5. 裁定 R-1 の「実測が無ければ不合格にすると S0 の初回の SG が常に不合格になる」という前提は、誤りでした。事実は、無条件の合格です。ADR-0099 に、前提を改めた旨を書く

### 理由

- **適用外は、無条件の合格より検証可能**。SC-M が無いと、残る SC-M の個数は 0 になります。区分は常に甲で、記録上は合格に見えます。これは、判定が行われたように見えて何も検査していない状態です。「適用外」と書けば、検査していないことが記録に出ます。7.7.6 の棚卸しでも、合格と読み違えられません
- **S0 の初回に到達の見込みを作文させない**。2.10.2 は、S0 の初回の計画容量を「実測なし」とし、確約範囲を置かないと定めています(`lifecycle.md:487`)。測れないものを測ったことにさせないのが、2.10.2 と ADR-0019 の趣旨です。S0 の初回のゴールに SC-P の一部を指定させる案(突合の例示)は、2.10.2 が置かないと決めた確約範囲を別の名で置き直すことになります
- **歯止めを外さない**: 適用外にすると、S0 の初回は予算の到達を検査しない区間になります。この区間を 7.6 の実績の段階(3)で覆います。これは信頼性のための代わりであり、省略ではありません。7.7.4 の第1行(消化進捗比)は、S0 の初回にも計画した受入基準があれば働きます
- 外部の作法: 探索の段階に確率的な見込みを求める一次資料は見つかっていません。英国の事業評価は、初期の段階では幅が広いことを前提に、ステージごとに見直します(IPA UK 7.5 の「各ステージで幅を目標の閾値と比べる」〔一次〕)。幅を作れない段階で幅を求めない作法と読みます(本委員の解釈。〔確〕ではない)

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 7.7.9 の見積りの幅で代える(現行の実装) | 案件全体の値で単位が合わない。ステージ分の切り出しが新しい人の見積りになる |
| S0 の初回のゴールを、SG-0 の材料に当たる SC-P の作業単位と定義する | 2.10.2 が置かないと決めた確約範囲を、別の名で置き直す。SC-P の増減は価値責任者の裁量なので、ゴールを価値責任者が動かせる |
| S0 の初回は不合格とする(品質監査・現場の第1巡の案) | 実測が無いことで 7.7.5 の 3 回を消費させる。消費が案件の実態ではなく区間の性質で起きる |
| 適用外とし、代わりの歯止めを置かない | S0 の初回の着手決裁から SG-0 までが、予算の到達を誰も検査しない区間になる |

## 問い(3) H-4: 7.7.5 要求事項4 の数え直し

### 結論

数え直しを、計画の変更の記録で起こさないようにします。次のとおり定めます(必達基準1〜5 に共通)。

1. **数える単位**: 同一の必達基準について、判定の時点で不合格であり、判定が中止でなかった判定の件数。継続の形(同じ範囲のまま、範囲の縮小、期日・予算の変更)を問わない。保留も数える
2. **数え直す条件**: 不合格で継続した後の判定で、同一の必達基準が合格したとき(必達基準2 は区分の甲)。この合格は、変更を決めたのと同じ判定の中の算定では足りない。**変更の後に、少なくとも 1 期の観測を経て算定した記録**であることを要する
3. **丙の継続に要する変更**(SC-M・予算・期日のいずれかを変える判定)は、数え直しの理由にならない。その判定も 1 に数える
4. 4 回目に当たる判定は、中止または保留しか選べない。保留の後の再判定も、同じ数えを引き継ぐ。現行の「3回を超えて継続と判定してはならない」はそのまま残す
5. 案件の中で数える。ステージの移行では数え直さない。ただし、SG でステージのゴール(SC-M の完了)が判定されれば、2 の合格の条件(SG の「継続」の行の算定)を満たしうる。その場合は 2 による

### 理由

- **継続の偏りへの処方と向きを揃える**: Simonson & Staw 1992 は、事前に定めた最低の目標を「後の結果で歪められないように」置くことを求めます〔一次〕。現行の実装は、判定者が SC-M を 1 件動かす記録で上限を戻せます。このため、上限は判定者が自ら解ける錠になっています(突合 H-4)
- **再ベースラインは上限の外へ出る道ではない**: 51 U.S.C. §30104 は、超過が 30% を超えた事業について、新しいベースラインの報告に加え、継続に議会の法による承認を求めます〔一次〕。ベースラインを引き直したことを、引き金の解除として扱いません。本標準でも、計画を変える判定そのものを、上限の回数に数えるのが同じ作法です
- **「観測を経た合格」に限る理由**: 変更を決めた判定の中で算定し直すと、判定者は自ら選んだ値で甲を作れます。SG の「継続」の行の算定(問い1)は確定の場の検査であり、数え直しには使いません。変更の後の 1 期の観測で甲になって初めて、到達の見込みが改善したと記録で言えます
- **必達基準1〜5 に共通にする理由**: 数え直しの条件を必達基準ごとに書き分けると、どの条件がどの基準に掛かるかの読み違いが起きます(突合 H-4 の括弧の外の誤り)。「不合格で継続した後、同じ基準が合格するまでの継続を数える」は、どの基準にも同じ意味で読めます
- 判定の多発は、最小スループットで端を作る既定(EV-0201)の副作用です。その解き方は、端の作り方(問い4の M-2)で行います。数え直しを緩める形では行いません

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| SC-M・予算・期日を変える判定の記録で数え直す(現行の実装) | 判定者が自ら上限を戻せる。丙の継続は上限に一度も届かない |
| 数え直しを必達基準2 に限り、条件を「変えた後の見込みで甲になったとき」とする(突合の直し方) | 変えた判定と同じ判定の算定で甲を作れる。観測を経ない甲で戻せる。他の基準の数え直しの扱いが書かれないまま残る |
| 案件の中で一度も数え直さない | 観測で到達が回復した案件が、過去の不合格で中止を強いられる。上限が偽の中止を生む |
| ステージの移行で数え直す | ステージを移すたびに上限が戻り、最長 3 ステージの歯止めが無期限になる |

## 問い(4) M-1〜M-3

### M-1 区分の組み合わせ

**結論**: 比べる組は、期間の見込みと残る期間、費用の見込みと期間予算の残り、費用の見込みと要員予算の残り、の 3 つです。組ごとに区分を出して記録させます。**案件の区分は、組のうち最も悪い区分とします**(丙 > 乙 > 甲)。この一文を 7.7.3 と ADR-0099 決定2 に置きます。様式の区分の欄は、組ごとの 3 欄と、案件の区分の 1 欄にします。

**理由**: 必達基準2 の文言は「予算**または**期間」で、どれか一つの不足で到達できません。最も悪い区分を取る規則は、この論理和をそのまま区分へ写したものです。組ごとの欄が無いと、案件の区分だけを書かれたときに、どの組が効いたかを再計算できません。

**採らない案**: 組の区分の多数決、または期間の組だけを主とする案。どちらも、予算の不足を期間の余裕で隠す。区分の間の合算(費用の 2 組の残りを足す)も採らない。第1巡で、区分を合算すると流用を隠すとした理由と同じ。

### M-2 スループットの最小値が 0 になるとき、最小標本数との関係

**結論**:

1. **端の既定の作り方を、単位期間ごとの最小・最大から、同じ長さの区間の完了件数へ改める**(既定値。1.7.7)
   - L = 残る期間の単位期間の数と、観測の窓の単位期間の数のうち小さいほう
   - 遅い側の端の完了の量 = 窓の中の、連続する L 期間の完了件数のうち最小のもの × (残る期間 ÷ L)
   - 速い側の端の完了の量 = 同じく最大のもの × (残る期間 ÷ L)
   - 期間の組の区分は、この 2 つの量を残る SC-M の個数と比べて出す(割り算をしない)
   - 費用の見込みは、残る SC-M を賄うのに要する期間を同じ区間の速さから出し、単位期間あたりの費用の実績を掛ける
2. **0 の単位期間を窓から除いてはならない**。休暇・障害の期間も、残る期間に同じことが起きうる観測である
3. 連続する L 期間の完了が 0 の区間がある場合は、その組の遅い側の端は「収まらない」とする。区分は乙か丙で、定義の上で定まる。これは本当の停滞であり、偽の不合格ではない
4. **第4章「閾値の設定と較正」の最小標本数(要求事項3)は、到達の見込みに掛けない**と 7.7.3 に書く。参照するのは、観測の窓の長さの定めだけとする。記録には、窓の中の完了件数を書く。EV-0201 の差し替え条件に、「0 の単位期間を含む窓の件数」と「窓の中の件数が 30 件未満だった判定の件数と、その後の到達の結果」を加える

**理由**:

- 単位期間ごとの最小値で割る現行の既定は、1 期でも完了 0 があると遅い側の端が無限大になります。1〜2 名の体制では、休暇の 1 期だけで、窓が入れ替わるまで乙が続きます。この期間の判定は 7.7.5 の回数を消費します。問い(3)で数え直しを締めた以上、この偽の不合格は偽の中止に直結します。端の作り方を直すのが筋です
- 同じ長さの区間の最小は、「残る期間と同じ長さで、過去に最も遅かったときの量で足りるか」を直接問います。割り算をしないので 0 で定義が崩れません。0 の 1 期は区間の中で薄まり、区間全体が止まったときだけ「収まらない」になります。記録だけで再計算でき、分布の推定も要りません
- 最小標本数の要求事項3 は、比率の閾値の安定のための定めです(「比率は母数が小さいほど不安定」`gate-criteria.md:1931`)。到達の見込みの端は比率の推定ではなく、観測された最悪と最良の区間の量です。この要求事項を掛けると、1〜2 名の体制ではほとんどの窓が 30 件に届きません。必達基準2 は常に「実測なし」に落ちます。その結果、問い(2)で S0 の初回に限った適用外が、小さな体制では全期間に広がります。どちらの定めが誤りかを決めると、要求事項3 は誤りではありません。ただし、その掛かる範囲が書かれていません。そこで 7.7.3 の側に、掛けない旨と理由を書きます
- ただし、件数が少ない窓の端が信頼できるかは測られていません。E0 のまま開示し、差し替え条件で測ります

**採らない案**:

| 案 | 採らない理由 |
| --- | --- |
| 0 の単位期間を窓から除く | 除く判断に裁量が入り、楽観側へ偏る。残る期間にも同じ 0 が起きうる |
| 最小値が 0 のときは「実測なし」とする | 停滞という最も重要な観測を、判定の無い状態へ変える |
| 最小標本数に満たない窓は「実測なし」とする | 1〜2 名の体制で必達基準2 がほぼ常に適用外になる |
| 単位期間ごとの最小・最大のまま、0 の期間には次に小さい値を使う | 規則が恣意的で、根拠を示せない |
| モンテカルロの分位点を既定にする | 分布の推定と乱数の種を記録しないと再計算できない。置き換えとしては認める(G-1 の記名による。現行の実装のとおり) |

### M-3 2.10.6 との整合

**結論**: 2.10.6 に、「期日に間に合わない見込みは、第7章 7.7.3 の到達の見込みの期間の組の区分で評価する。区分が乙または丙のとき、間に合わない見込みが立ったものとする」と書きます。2.10.4 の 2 指標(進捗率・滞留期間)は、見込みを算定し直す契機として残します。見込みそのものの判定には使いません。7.7.3 の「2.10.6 の見込みと同じ材料による」は、「2.10.6 が挙げる材料のうち、残る作業単位の個数と実測スループットによる」に改めます。

**理由**:

- 7.6 を遅い側の端で測ると決めたので、7.6 の起点になる 2.10.6 の見込みも同じ値にしないと、0 の事実(二つの判定が別の値を使う)が 2.10.6 と 7.6 の間に残ります。同じ量の定義は一箇所に置き、他は引くという作法(第1巡 R-3)をここにも当てます
- 進捗率は受入基準の数で、到達の見込みは作業単位の個数で数えます。単位が違うので、進捗率で見込みを判定すると、7.7.3 と別の物差しになります。進捗率は、算定し直す契機として残せば、2.10.4 の役割(停滞の検知)を壊しません
- 2.10.6 の手順1(価値責任者が SC-B・SC-P を削る)は、区分の算定に影響しません。区分は SC-M だけで数えるためです。このため、手順1 で区分は戻りません。乙・丙のとき手順1 だけで足りることはなく、7.6 の起票へ進みます。これは 2.10.6 の「手順1で不足する場合」と整合します。ただし、価値責任者が SC-P・SC-B を削って SC-M の作業単位の完了を早める余力を作ることはありえます。その効果は、次の期の観測に現れます

**採らない案**: 2.10.6 を対象外と ADR に書くだけで済ませる案。7.6 と 2.10.6 の値の食い違いが残り、裁定が 0 で欠陥と認めた型を自ら残すことになる。2.10.6 の見込みを進捗率で判定したまま、7.6 だけを区分で測る案も、同じ理由で採らない。
