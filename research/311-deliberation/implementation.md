## 3. 裁定からの逸脱と理由

| # | 逸脱 | 理由 |
| --- | --- | --- |
| 1 | 理解保持者数による停止は、保持者が2名以上へ戻った時点で解ける(標準は「5.4.5 の条件を再度満たすまで戻さない」) | 運用引き継ぎ文書は、保持者が減った日付を持たない。登録日との前後を比べられないため、登録日で戻す形にできない。IMPL-0284 の注記と ADR-0081 の影響に開示した。登録の判定を経て戻したかは、人が確かめる |
| 2 | 差し戻し率の分子は、G-6 の判定記録だけから数える(PR のレビューの差し戻しを数えない) | 判定基準の番号を引いたかを読めるのは、判定記録の「差し戻しの理由」の節だけである。対象を既定ブランチの履歴へ対応づけられない差し戻しは数えず、件数を注記に出す |
| 3 | 窓(2か月)と最小標本数(30件)は定数であり、組織が G-1 で長くした窓を構成に持たない | 裁定は窓を長くすることを認めている。構成の欄と、その変更の手続(統制の向き)を設計する必要があり、本 Issue の範囲を超える。別 Issue を起こす |
| 4 | 欠陥の台帳・運用引き継ぎ文書が無い構成では、登録した変更種別をすべて止める | 第1区分を判定できない範囲に L3 を置かない(5.4.6 の後段と同じ理由)。既存の採用者は、台帳と引き継ぎ文書を置くまで委任が止まる |
| 5 | AI 起因の欄は、欠陥の台帳に置いた(運用の障害の台帳ではない) | 準拠テンプレートに運用の障害の台帳が無い。ポストモーテムは補助ファイルで書き方を定めるだけである。台帳に運用の Sev1・Sev2 の行も足すと様式に書いた。出荷前の欠陥の Sev1・Sev2 の行も、AI 起因が「なし」でない限り止める |
| 6 | 手戻り率は降ろしていない(IMPL-0291 undelivered) | 不採用となった変更(マージされなかった PR)は既定ブランチの履歴から読めず、組織が G-1 で定める基準値を構成に持たない。表示し続ける |
| 7 | D-0 の生成区間には、停止の原因と直近の評価を書かず、所在を書く | 生成区間は構成だけから決める(`check-d0` が一致を確かめる)。停止は記録から判定のたびに導くため、構成からは決まらない |
| 8 | 浅い取得のときは、差し戻し率を判定できないものとして止める | 窓の母数を数えられない。ワークフローは履歴の全体を取得する |
| 9 | 上限が L3 未満の場合の構成の整合の検査(`configIntegrityProblems`)は足していない | `config.mjs` から自律レベルの導出を呼ぶと循環の依存になる。登録の拒否(`/process-change`)と委任の判定(条件 5.4.6)の2か所で止める |

## 6. 別に起こす Issue

1. **審査の保証水準(L0〜L2)と AI自律レベル(L1〜L3)の記号の衝突**: 同じ「L」と数字が別の尺度を指す。名称の変更は ADR を要し、本 Issue の範囲を超える(N-6 の6)
2. **手戻り率の集計の実装**: 不採用となった PR を含めて、タスク(`Spec: F-NNN / Task-N`)ごとの変更の再作成を数える手段。G-1 の基準値を構成に持つかも含める(IMPL-0291)
3. **差し戻し率の窓と最小標本数を、組織の G-1 の値として構成に持つ**: 窓を長くすることは裁定が認めるが、テンプレートは定数である。構成の欄と、変更の統制の向き(窓を長くするのは緩める向きか)を決める
4. **理解保持者の減少の日付の記録**: 保持者数による停止を、登録の判定で戻す形にするため(上記 3 の 1)
5. **PR のレビューの差し戻しの扱い**: G-6 の判定記録を残さない差し戻しを分子に数えるか(上記 3 の 2)
6. #339(`basis.detection` が文字列で通る)と #340 の事象2(`self-heal start` の呼び忘れ)は、各 Issue で扱う(本 Issue では触れていない)
