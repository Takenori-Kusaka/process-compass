## 前提として押さえた事実(起草に効くもの)

1. 5.4.4 は「委任の範囲、L3 の適用範囲、標準変更カタログは同じ登録を指す」と定める。**テンプレートは自律レベルの語を持たないが、L3 は委任の登録として既に実装されている**。テンプレートに欠けているのは「レベル」という構成項目ではなく、登録した変更種別に掛かる引き下げの機構である

## N-1 実行層へ降ろすか(IMPL-0104)

**結論**: (d) 組み合わせ。次の4点を降ろす。

1. **テンプレートが支えるレベルを宣言し、構成で主張させない**。テンプレートは「登録した変更種別の外は L1、登録した変更種別は L3」だけを支え、L2 を支えないと README・生成する CLAUDE.md の構成の節・D-0 節12 に明記する。自由に書けるレベルの欄は置かない(機械が強制できない宣言は、偽の主張の置き場になる)。テーラリングエンジンの `maxAutonomyLevel` は、`generate-profile.mjs` が読み、`PROCESS-PROFILE.md` に「適用できる最大レベル」として出す。上限が L1 のとき(CL3 の安全関連部など)、`/process-change` は登録を拒否する(現行の CL1 以上で委任不可の規則と重なるが、出所を規則データに揃える)
2. **第1区分の検知と、登録した変更種別での自動の引き下げ**を実装する。AI 起因の Sev1/Sev2(定義は N-6)が登録した変更種別の変更に結びついたら、委任の判定(`delegation.mjs`)はその種別を該当なしとして扱う。状態を別ファイルに持たず、**判定のたびに既定ブランチの欠陥の台帳と登録の記録から導く**(停止の記録を書き忘れる経路を作らない)。戻すのは登録の判定のやり直し(5.4.5 の後段。登録日が事象より後の登録)だけ
3. **第2区分の期間集計**を `aggregate-evidence.mjs` に実装する。差し戻し率(G-6 のレビュー状態)と手戻り率(N-2 で機械で数えられる定義へ直す)を、登録した変更種別ごとと全体で、窓・件数・最小標本数・判定不能の別とともに保証の開示へ出す。登録した変更種別で発火条件を満たしたら、2 と同じく委任の判定から外す
4. **D-0 節12 に「AI自律レベル(構成から生成)」の列を足す**。値は手で書かず、構成と登録から生成する。IMPL-0104 の note が「D-0 を内部監査で確かめる」と書きながら欄が無い食い違いを、ここで解く

IMPL-0104 は分けて付け直す(同じ番号を再利用しない)。仮: IMPL-0284(第1区分と登録した変更種別の引き下げ。`delegation`)、IMPL-0285(第2区分の集計と開示。`evidence-aggregation`)、IMPL-0286(テンプレートが支えるレベルの宣言と上限の写し。`process-init`)。IMPL-0104 は「分割した」旨の note で `state` を据え置くか、#314 の扱いに従って退役させる。

**理由**:
- 5.4.6 の規範は「発火しない引き下げを備えているものとして扱ってはならない」である。テンプレートは委任(=L3)を登録させながら引き下げを持たないので、テンプレートどおりに委任を使うと、この規範に反した状態が既定になる。undelivered の表示を続けること((c))は、規範の違反を表示しているだけで、解消していない
- 外部の先例(外部 F-07 Claude Code の 3/20、F-16 Argo の失敗時の自動の切り戻し)は、**記録または短い窓で判定できる事象**の自動の縮退を支える。第1区分はこれに当たる。第2区分の自動の措置は先例の外だが(外部 §5 D1)、引き下げの対象を「登録した変更種別の委任の停止」に限れば、措置は委任の判定の拒否1つに収まり、取り消しも登録の判定という既存の経路で足りる
- 状態を記録から毎回導く形は、ADR-0054 決定4・5.5.4 の「行為する AI 自身に判定させない」とも、既存の委任の判定(ワークフローが既定ブランチの構成で判定する)とも同じ形である

**落とす案**:
- (a) の「構成にレベルを持たせる」部分: テンプレートは L2 を実現する構成を持たない。L2 と書ける欄を置くと、書かれた値と実際の監視が一致しない。宣言は上限という運用形態の考え方(5.5.3)をレベルに写しても、テンプレートには上限を下回らせる機構が無い
- (b) 単独: 「L1 だけを支える」は事実に反する(委任は L3 の登録である)。L1 だけと宣言すると、委任の機能そのものを外すことになり、ADR-0054 決定4 と矛盾する
- (c): 上述のとおり。表示は未達の開示として正しいが、既定の構成が規範に反する状態を残す

**文の案**(5.4.6 の末尾、IMPL-0104 の位置に置く本文。ですます調):
> 登録した変更種別(5.5.4)での引き下げは、登録の停止とします。登録の停止は、同じ登録を指す委任の停止を兼ねます(5.4.4)。停止は、検知の記録から判定のたびに導きます。停止を記録する手順を別に置きません。停止した種別を戻すのは、5.4.5 の登録の判定だけです。

テンプレートの README(である調):
> - 本テンプレートが支える AI自律レベルは、登録した変更種別の外の L1 と、登録した変更種別の L3 である。L2 を支えない
> - 自律レベルを構成に書く欄は無い。D-0 節12 の自律レベルの列は、構成と登録から生成する

**矛盾の検査**: 5.4.4 L94-97・5.5.4・ADR-0054 決定4 と整合。5.4.6 L185「第2区分の計測ができない範囲へ L2 以上を適用しない」は、テンプレートでは「集計が判定不能の種別の登録を停止する」(N-5)で機械化される。ADR-0059 決定4(IMPL-0104 を undelivered で付ける)は、事実の記録としては維持され、本件の新 ADR が後を継ぐ。
**根拠**: 内部 §1.3・§3・§4、外部 F-07・F-09・F-16、自分で D-0 節12 と `config.mjs` を確認。

## N-2 第2区分の3行目(重複率・手戻り率)の措置の強さと定義

**結論**:
1. **誤っているのは「検討する」の側である**。「検討する」は、誰が・いつまでに・何を記録するかを持たず、満たしたかを確かめられない。規範の語として成り立たない
2. **重複率を 5.4.6 から削る**。定義が無く計算できない量に、検知条件・登録の前提を課さない。課さないと決めた旨を本文と新 ADR に書く。連動して 5.5.4・第8章 L293・附属書H L685・テンプレートの `basis.detection.duplicationRate` を外す(既存の記入は警告して無視し、拒否しない)
3. **手戻り率の分子を機械で数えられる定義へ改める**。「やり直したタスク」= 同じタスクを指す変更(トレーラ `Spec: F-NNN / Task-N`)が、最初の変更の取り込みまたは不採用の後に、再び作られたタスク。1 Task = 1 変更単位の規則(テンプレ7)があるので、2つ目の変更の存在がやり直しの記録になる。計画表への手書きの「やり直し」は廃する
4. **手戻り率の行は「期限つきの判定」とする**。検知は自動。検知から判定の期限(D-0 節5)までに、引き下げない旨の判定がステアリングコミッティ(B-2、5.4.5 の判定者)の記名と理由で記録されなければ、引き下げが発火する。**人が何もしなければ下がる**ので、非対称は保たれる

**理由**:
- 節冒頭の「自動」は、監督の劣化が申告されないことに依る(L149)。この理由が当てはまるのは 0% の継続(静かな劣化)であって、手戻り率の高止まりは作業者に見えている。一方で手戻り率は仕様と文脈の品質でも動く(`metrics.md` L228 の警戒サイン、外部 F-13)。無条件の自動は誤発火を増やし(外部 F-19)、条件のない「検討」は統制にならない。**既定で発火し、記名の判定でだけ止められる**形が、両方の欠点を避ける。外部 F-15(SRE の事前合意の方針)・F-16(判定不能は人へ)と同型だが、既定の向きを引き下げに置く点でそれより強い
- L189「人間の点検を挟むと、引き下げは判定になります」は、点検しないと下がらない構成への批判である。本案は点検しなくても下がるので、L189 の懸念に当たらない
- 重複率の計算方法を会議体で新たに作る案もありうるが、量を定義し、較正の手段を持たないまま検知条件に置けば、ADR-0059 が承認の比率を外した理由(量が監督の劣化だけを映さない)がそのまま当てはまる。作るなら、別の Issue で定義・観測・較正を経てから足す

**落とす案**:
- 全行を自動に揃える: 手戻り率は分子の機械的な定義を得ても、仕様の品質で動く量である。誤発火が続くと解除の慣行が生まれる(外部 F-19)
- 3行目を「検知して人へ渡す」だけにする(既定で発火しない): 受け取った人が何もしなければ何も起きない。「検討する」と同じ欠陥が残る
- 重複率を残して定義を後回しにする: 定義の無い量の「算出の所在」を登録の前提にしている現状(前提 4)が続く。記入の有無だけを確かめる検査(#339)では、この欠陥は見つからない

**文の案**(5.4.6 の表。体言止め):

| 検知する状態 | 初期値 | 措置 |
| --- | --- | --- |
| AI が起因となった Sev1 または Sev2 が発生した | 1件 | 該当範囲を少なくとも1段階引き下げる |
| 独立レビューの差し戻し率が0%のまま推移した | 直近2か月の窓 | 形骸化の疑いとして引き下げる |
| 手戻り率(運用メトリクスの手戻り率)が基準を超えた | 組織が G-1 で定めた値 | 判定の期限までに、引き下げない旨の判定が記録されなければ引き下げる |
| コア機能の理解保持者数が1名以下になった | — | 該当機能を L1 へ引き下げる |

表の後(ですます調):
> 3行目の検知は自動で行い、判定の期限([テンプレ0](...) D-0 の判定の期限)を起算します。期限までに、5.4.5 の判定者が、引き下げないことを記名と理由で記録した場合に限り、引き下げは発火しません。記録が無いまま期限を過ぎた場合は、引き下げが発火します。この判定を、AIエージェントが起案してはなりません。
>
> **変更の重複率を、引き下げの検知条件に置きません**。本標準は、この量を定義していません。定義の無い量に閾値と算出の所在を課しても、計測は始まらないためです。この扱いは意図的な決定です。

節冒頭 L149 の書き換え:
> 引き下げは、判定を待たずに発火します。表の3行目も、判定が無ければ発火します。**引き上げは判定を要し、引き下げは判定が無くても起こる**という非対称を意図的に設けます。

**矛盾の検査**: ADR-0059 決定(3つの検知条件)と 5.5.4・テンプレートの `basis.detection` の形を変えるので、ADR-0059 の該当部分を置き換える新 ADR が要る(採用済み ADR は書き換えない)。ADR-0079(手戻り率はタスク単位・行の帰属に依らない)とは整合する。`metrics.md` L228 の算出方法と L312 の「手で数える」を改める。3.11.7 は N-6 で扱う。
**根拠**: 内部 §4・§5-1・§5-7、外部 F-13・F-15・F-16・F-19。重複率の定義が無いことは grep で自分でも確認。

## N-3 閾値の根拠の開示

**結論**:
1. **「1件」に EV を付ける**。性格は「統計の閾値ではなく、事象の重大度による規則」と明記する(外部 F-18)。差し替え条件は、誤発火(引き下げの後の点検で、監督の劣化と無関係と確かめた件)と見逃し(引き下げなかった範囲で後に同種の Sev1/Sev2 が続いた件)の観測
2. **「1名以下」にも EV を付ける**。冗長が無い状態の定義としては自明だが、「その状態なら L1 へ下げることが流出を減らす」という主張は検証されていない。1件の行と同じ扱いにそろえる
3. **5.4.5 の条件4「0件」は、1件の規則と同じ EV の対象に含めて名指す**(引き上げの側の鏡像であり、別の値ではない)。条件2「上下いずれの逸脱もない」は値ではないので EV を付けず、文を「組織が G-1 で定めた範囲を、期間中に上下いずれにも外れていない」に直す
4. **2か月の数え方を、窓として定める**。差し戻し率0%の行に限り、観測の窓を直近2か月(移動窓)とし、その窓の件数が最小標本数以上で、差し戻しが0件のときに発火する。「継続」は窓の長さで表し、四半期の窓を2か月で区切る数え方はしない。EV-0146 の対象の書きぶりを、新しい EV で「窓の長さ」として出し直す(採用済みの EV は書き換えず、置き換える)
5. **「組織が定めた値」の開示の対象**は、値・窓・最小標本数・決め方(初期値のまま / 2四半期の実測からの置き換え)・次の見直しの日付の5点とし、G-1 の記録の必須欄にする。テンプレートの `check-g1.mjs` が欄の有無を確かめる

**理由**: 外部の値(3/20、5%、2倍、20%)はどれも根拠を示さない(外部 §5 D3)。本標準が E0 を開示すること自体が差になる。開示しないまま置くのは、CLAUDE.md の根拠水準の規約にも反する。2か月の数え方は、機械が実装するときに必ず一意に決める必要があり、決めないまま降ろせば実装者が決めることになる。NIST MANAGE 2.4 は閾値の存在と見直しを求め、値を組織に委ねる(外部 F-03)ので、開示の対象は値の決め方と見直しの周期になる。

**落とす案**:
- 「1件」は自明なので EV 不要: 自明なのは「重大な事象が起きた」という事実であって、それを引き下げの理由にすることの効果ではない
- 2か月を四半期の窓で数える(四半期の窓が2つ続けて0%なら発火): 実質6か月になり、EV-0146 の値を黙って3倍にする
- 組織の値を数値だけ記録する: 2四半期の置き換え(第4章 要求事項2)をしたかが読めない

**文の案**:
> :::caution[暫定 EV-0154 / 見直し 2027-10]
> **対象**: 5.4.6 の AI が起因となった Sev1・Sev2 の初期値(1件)と、5.4.5 の条件4 の初期値(期間内に0件)。
> **根拠の水準**: E0(なし)。この値は統計の閾値ではなく、事象の重大度による規則です。
> **差し替え条件**: 採用組織で、この行によって引き下げた範囲のうち、後の点検で監督の劣化と無関係と確かめた件数と、引き下げなかった範囲で同種の事象が続いた件数の観測。
> :::

窓の文(ですます調):
> 差し戻し率0%の行は、第4章の観測の窓に代えて、直近2か月の移動窓で判定します。窓の中の変更の件数が最小標本数に満たない場合は判定不能とし、発火させません。判定不能の扱いは「判定不能の窓」によります。

**矛盾の検査**: EV-0146 の本文は書き換えず、置き換えの EV を出して旧番号を退役させる(evidence-marking の規約に従う。番号は再利用しない)。第4章 要求事項1〜3 と整合。
**根拠**: 内部 §0・§5-3、外部 F-03・F-18。EV-0146 の現行の文面は本文で自分で確認。

## N-4 附属書H C6 と内部監査の観点

**結論**:
1. **C6 の「支える条項」から 5.4.6 を外す**。主張「低下は権限の制限として作動する」を支えるのは 5.6.2 と 7.9 である。5.4.6 は C9(事後)に既に挙がっており、そこに残す。「主張の崩れを示す観測」の「差し戻し率 0% の継続と検出率の低下の同時発生」は、運用メトリクス L298 の組み合わせとして残す(観測は条項でなくてよい)
2. **H.7 の「統制が作動した記録」の行の監査の列を「観点23」へ付け替える**。観点23 を新設する: 「AI自律レベルの適用範囲が、検知条件の計測と整合しているか。発火すべき検知に、引き下げまたは記名の判定の記録が対応しているか」。逸脱の例: 計測の所在が無い種別が登録されている / 判定不能の窓が続く種別で委任が続いている / 3行目の検知に記名の判定も引き下げも無いまま期限を過ぎている / 理由の記載が無い差し戻しが、0%を避ける時期に集中している
3. **C6 の主張は狭めない**。根拠を正しく指せば、主張の文面と条項の強さは一致する

**理由**: ADR-0054 決定4 と ADR-0059 の却下案(「検出率の低下を検知条件に置き換える」)は、判定の履歴の集計と検出能力の測定を意図して別の量とした。C6 に 5.4.6 を挙げると、この分離に反して同じ低下に2つの措置が付くように読める。観点10・12 は委任と適合性確認の失効を見る観点で、自律レベルの適用を見ない(`process-audit.md` で自分で確認)。IMPL-0104 の note が「内部監査で確かめる」と書く以上、対応する観点が要る。附属書H は「論証のために新しい検査を足さない」と定めるが、観点23 は論証のためではなく 5.4.6 自身の規範(発火しない引き下げを備えているものとして扱わない)が求めるものである。

**落とす案**:
- 5.4.6 に検出率の低下の行を足して C6 に合わせる: ADR-0059 が却下済み。根拠に合わせて主張を直すべきで、主張に合わせて条項を足すべきではない
- 観点10 に含める: 観点10 は委任の範囲への該当を見る。L1・L2 の適用(委任でない範囲)の整合が抜ける

**文の案**(観点の表。体言止め):
> | 23 | AI自律レベルの適用範囲が、5.4.6 の検知条件の計測と整合しているか。発火すべき検知に、引き下げまたは記名の判定の記録が対応しているか | 計測の所在が無い変更種別が登録されている。判定不能の窓が続く範囲で L2 以上が続いている。手戻り率の検知に、判定の記録も引き下げも無いまま期限を過ぎている |

**矛盾の検査**: 附属書H の C9・L685 と整合。H.7 の表の「観点10・12」を「観点23」へ直す。附属書H が引く観点番号は `npm run lint:refs` の対象なので、観点の追加と同じ変更で直す。
**根拠**: 内部 §2.1・§5-4・§5-5、自分で附属書H L213・L235・L712 と観点1〜22 を確認。

## N-5 最小標本に満たない窓(#340 事象1 を含む)

**結論**:
1. **判定不能を、計測できない状態として扱う**。窓の件数が最小標本数に満たないことは、5.4.6 の「計測できない」に当たる。新しい定数は置かない
2. **判定不能の窓が生じた範囲では、L2 以上の適用を保留する**。登録した変更種別では、登録を保留する(委任の判定から外す)。保留は検知による引き下げではないので、判定不能が解けた窓(最小標本数に達し、発火条件を満たさない窓)で自動に解除する。ただし保留中に発火条件を満たした場合は、引き下げとして扱う
3. **受け取る席と開示**: 判定不能は `/pit` が技術判断者(`state:needs-tech`)へ注記で出す。保証の開示の項目3 に、確定の形態の内訳と並べて「委任のうち、検知が判定不能で保留した種別と期間」を出す(既存の記録からの投影。人に新しい記述を書かせない)
4. **ゲーミング**: 新しい機械の規則は足さない(課さないと決めた)。手当ては既存の禁止(判定を通すための分割の禁止)と、観点23 の逸脱の例(理由の無い差し戻しの集中)と、運用メトリクス L294・L298 の組み合わせの観測とする

**理由**:
- 小さいチームで第2区分が発火しないこと自体は、統計として正しい(外部 F-18)。問題は、発火しない状態で委任が続くことである。これは 5.4.6 L174・L185 の規範にそのまま反する。判定不能を「計測できない」と読めば、既存の規範だけで結論が出る
- 保留を自動で解除するのは、判定不能が劣化の検知ではなく、検知の能力の欠如だからである(外部 F-16 Argo の Inconclusive は一時停止で、再開を許す)。解除を判定に掛けると、件数の少ない期間が来るたびに登録の判定をやり直すことになり、判定が形骸化する
- 小さいチームは、第4章 要求事項2 に従い、2四半期の実測から最小標本数を自組織の値へ置き換えられる。置き換えの記録は N-3 の G-1 の欄で開示される。値を下げすぎることへの歯止めは、見直しと観点15(閾値の無承認の変更)が担う
- 差し戻しの件数を基準番号つきに限る機械の規則も考えたが、G-6 の差し戻し率の定義(Changes requested の付いた PR の比率)を変えることになり、運用メトリクスとの量の同一性が崩れる。採らない

**落とす案**:
- 判定不能を「継続」に数えない(現行)だけで止める: 発火しない引き下げを備えているものとして扱う状態が残る(#340 事象1 そのもの)
- 判定不能が2窓続いたら停止する: 新しい定数(2窓)が要り、その根拠が無い。1窓で保留し自動で解除する案のほうが値を足さない
- 判定不能を引き下げとして扱い、登録の判定で戻す: 上述のとおり判定の形骸化を招く

**文の案**(5.4.6「計測できない検知条件がある場合」に追加。ですます調):
> 窓の中の件数が最小標本数に満たない窓を、**判定不能の窓**と呼びます。判定不能の窓は、計測できない状態として扱います。判定不能の窓が生じた範囲では、L2 以上の適用を保留します。登録した変更種別では、登録を保留します。保留は引き下げではありません。最小標本数に達し、検知条件を満たさない窓が得られた時点で解除されます。保留の期間と範囲は、保証の開示の項目3 に表示します。
>
> 判定不能を避ける目的で変更を分け、または差し戻しを行うことを、検知の手当てとして認めません。これらは内部監査の観点23 で確かめます。差し戻しの件数を数える規則を、この目的で変えることはしません。

**矛盾の検査**: 5.4.6 L183(満たない窓は発火させず継続に数えない)と整合し、その帰結を補う。第4章 要求事項3 と整合。保証の開示の項目3 の導出元(判定記録)に、委任の判定の記録を足すことになる。
**根拠**: 内部 §4 末尾、外部 F-16・F-17・F-18。#340 は issues-context の記述のみ。
