## 2. 所見

### X-1 停止を導く元の記録(欠陥の台帳・運用引き継ぎ文書)が、委任の経路から書き換えられる(重大)

- 根拠
  - `template/scripts/gate/config.mjs:918-932` の `NEVER_DELEGATED` は、`docs/gates/**` と `docs/D-0-governance.md` を含む。一方で、`docs/defect-ledger.md` と `docs/handover.md` を含まない
  - `template/scripts/gate/autonomy.mjs:43-44, 181-214` は、この2つのファイルだけから第1区分の停止を導く
  - `broadPathReason('docs/**')`・`broadPathReason('docs/defect-ledger.md')` はどちらも `null` を返す。範囲の広すぎる指定として拒まれない(探査で確かめた)
  - 停止は種別ごとにかかる(`autonomy.mjs:178` の `applies`)。止まっていない種別 B の規則が `docs/**` を含めば、人の事前の確認を経ずに機械がマージする変更で、次の書き換えができる。種別 A の Sev1 の行の AI 起因を「あり」から「なし」へ改める書き換えと、引き継ぎ文書へ保持者の行を足す書き換えである。どちらも種別 A の停止を解く。将来の停止を防ぐ書き換えにもなる
- 評価
  - #311 の設計は「停止を状態として持たず、記録から導く」である(ADR-0081 決定6、`human-ai-boundary.md:230`)。記録は停止の入力となり、統制の一部になった。判定の記録(`docs/gates/**`)を委任の範囲から外しているのと同じ理由が、2つのファイルにも当たる
  - 停止を解く書き換えは、5.5.7 の「統制の弱化」に当たる。それが判定を経ない経路で起こりうる
- 修正の案
  - テンプレート: `NEVER_DELEGATED` に `docs/defect-ledger.md` と `docs/handover.md` を足す。`test-check-delegation.mjs` に「欠陥の台帳に触れる変更は委任に該当しない」の場面を足す
  - 標準: 5.4.6「登録した変更種別での停止」に、「停止を導く元の記録の変更を、委任の範囲に入れない」を置くかを決める。条項の新設なので、コアポリシーの手順(調査・議論・突合)で扱う。それまでは、テンプレートの側の修正だけを先に入れてよい。厳しくする向きの修正だからである

### X-2 理解保持者数による停止が、登録の判定を経ずに解ける。「記録から日付を読めない」という理由は成り立たない(中)

- 根拠
  - 標準 `human-ai-boundary.md:237` は、戻る条件を「保持者数を回復したうえでの、5.5.4 の登録の判定」と定める。`:196` は「引き下げた範囲は、5.4.5 の条件を再度満たすまで戻しません」と定める
  - テンプレート `autonomy.mjs:13-14, 212` は、保持者が2名以上へ戻った時点で停止を解く。登録日との比較をしない
  - IMPL-0284(`human-ai-boundary.md:244`)は `state=delivered check=machine` のままで、この差を note に書いているだけである
- 評価
  - 引き下げの性質を持つ停止が判定を経ずに戻るのは、5.4.6 の非対称と 5.5.7(`:528`「緩める向きは判定を要し」)に反する
  - `implementation.md` 3 節の1 は「保持者が減った日付を記録から読めない」を理由に挙げる。しかし `delegation.yml` は今回 `fetch-depth: 0` で履歴の全体を取得するように改められた。`autonomy.mjs` も同じ git の履歴を既に読んでいる。登録日の後に `docs/handover.md` の版を遡れば、保持者が1名以下だった版のコミット日を得られる(`git log --format='%H %cs' -- docs/handover.md` と、各版の `git show`)
  - 実装マークの規則(`implementation-marking.md:52`「マークは規定ごとに付ける」)に照らすと、実装していない部分は note で済ませず、マークを分けて表示し続けるべきである
- 修正の案(どちらか)
  1. `readAutonomyRecords` が、登録日以降の `docs/handover.md` の版を履歴から読む。保持者数が1名以下だった最後の版の日付を `core.rows[].droppedAt` として返し、`registeredAt > droppedAt` のときに限って停止を解く。この場合の試験も足す
  2. 実装しないなら、「保持者数による停止を登録の判定で戻す」を独立した IMPL(`state=undelivered`)に分け、IMPL-0284 からこの部分を除く。どちらの場合も、ADR-0081 の影響の節にある理由(日付を読めない)は改める

### X-3 原因を特定できない Sev1・Sev2 の停止が、原因を特定しないまま「登録し直し」で解ける(中)

- 根拠
  - 裁定 N-6 の5 は「Sev1・Sev2 の原因が特定されるまで、該当範囲の登録した変更種別を止める」と定める
  - 標準 `human-ai-boundary.md:236` は、戻る条件に「または事象の日より後の登録の判定」を足した
  - テンプレート `autonomy.mjs:192` も、AI 起因が「特定できない」または空欄の行について、`registeredAt > d.date` なら停止しない
  - 探査で確かめた。Sev2(特定できない、2026-10-05)の後に `registeredAt=2026-10-06` とすると、L3・停止なしになる
  - `implementation.md` 3 節の逸脱の一覧に、この項目が無い
- 評価
  - 原因を特定できない事象は「AI 起因でないものとして扱わない」(`:181`)。それでも、登録の判定で原因の特定を飛ばせる。そのため、停止の性質が「適用の条件の欠落」(条件が回復すれば戻る)から外れている
  - 登録の判定を、5.4.5 の条件4(AI 起因の事象が期間内に0件)と整合させて行えるのかも、書かれていない
- 修正の案: 標準 `:236` から「または事象の日より後の登録の判定」を外す。あわせて `autonomy.mjs:190-200` の `cause-unknown` の分岐で、登録日による解除をやめる。残す判断をするなら、裁定からの逸脱として ADR-0081 に理由を書く。この選択は緩める向きになるため、会議体の判断を経る

### X-4 D-0 の生成区間が、同じ行に「L3」と手戻り率の「未計測」を並べる。様式の規定に反する(中)

- 根拠

  - `human-ai-boundary.md:219` は、「第2区分の計測ができない範囲へ、L2 以上を適用しません」と定める
  - テンプレート `scripts/init/generate-profile.mjs:2103` は、登録した変更種別の行に `L3(停止中は L1)` と、手戻り率の所在 `未計測(準拠テンプレートは集計しない)` を同時に出す。試験 `test-check-delegation.mjs` の「生成: D-0 の表に…」は、`/未計測/` が出ることを期待値にしている

- 修正の案

  - 標準: `deliverable-templates.md:131` に「計測の所在が準拠テンプレートの外にある場合は、その所在を書く」を足し、「未計測」と区別する

### X-5 「直近2か月の窓・毎月の評価」と、第4章の窓の初期値(四半期)・組織の値との関係が書かれていない。毎月の周期は根拠水準の開示を欠く(中)

- 根拠
  - 第4章 `gate-criteria.md:1666` は、窓の初期値を四半期、最小標本数の初期値を30件とする(EV-0145)。要求事項1(`:1662`)は、5.4.6 の検知条件の窓を組織が G-1 で定めるとする
  - 5.4.6 `human-ai-boundary.md:182` と `metrics.md:199` は、「毎月、直近2か月の窓で評価する」と固定の書き方をする
  - `:215` は「観測の窓を長くしてかまいません」とする
  - EV-0146 の対象は「0%のまま推移した期間の初期値(2か月継続)」だけである(`evidence-ledger.md:139`)
  - テンプレート `autonomy.mjs:36, 38` は、窓と最小標本数を定数にしている
- 問3 への答え
  - 30件: 既存の値(第4章の初期値、EV-0145)。新しい値ではない
  - 2か月: 既存の値「2か月継続」(EV-0146)を、観測の窓として読み替えたもの。値は新しくない。ただし「窓の長さ = 継続の期間」という読み替えと、第4章の四半期を 5.4.6 では使わないことは、本文のどこにも書かれていない
  - 毎月の評価: 新しい規定で、EV が付いていない
- 評価
  - 読み手は、第4章の四半期の窓と 5.4.6 の2か月の窓のどちらが掛かるかを決められない
  - 組織が窓を長くした場合、「2か月継続」が何を指すかも決まらない
- 修正の案
  - 5.4.6 の数え方の行に、「0%の継続の行では、観測の窓は継続の期間(初期値2か月。EV-0146)とし、第4章の窓の初期値(四半期)に代える。組織が窓を長くした場合は、継続の期間も同じ長さとし、第4章の要求事項1 の記録に含める」の趣旨を書く
  - EV-0146 の対象に、窓としての読みと評価の周期(毎月)を足す。または新しい EV を付ける
  - テンプレートの定数は、X-8 の子 Issue で扱う
