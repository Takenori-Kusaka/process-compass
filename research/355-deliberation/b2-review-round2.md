### 中-A 軸E の CL0 の升と S0 の G-7 の省略

- 事実: 直しは軸E の表の CL0・CL1 の升に「不要(附属書F F.2 の Q1 が『はい』の案件は必須。第4章 G-7 基準7)」を書いた。第8章 軸B は、S0 で標準品質かつ CL0 の構成で G-7 を省略する(L575〜588。CL1 以上は S0 でも G-7 を適用、r-e-cl1)。「軸の間の優先」(L533)は、軸E の強化が軸B の緩和に優先すると定める
- 帰結: S0・標準品質・CL0 で Q1 が「はい」の案件では、軸E の升が G-7 基準7 を必須とし、軸B が G-7 そのものを省く。L533 で読むと「この案件は S0 でも G-7 を適用に戻す」になる。これは裁定(b2-decision.md 2.1、ADR-0159 決定4)が扱っていない義務であり、S0 の省略の前提(L579 の3つ)にもエンジンにも無い。ADR-0159 決定4 の「新しい義務ではない」の根拠は「F.7 の記録を附属書F が既に求めている」ことで、記録の義務には当たるが、G-7 の適用を戻すことまでは支えない
- CL1 は r-e-cl1 で S0 でも G-7 を適用するため、食い違いは CL0 の升だけに出る。附属書F F.2 の図・F.7(「安全関連部の検証では、次を記録します」)・ADR-0039(リスク区分と CL の単位の区別。軸E の升も Q1 も案件の単位)とは食い違わない
- 安全の論点を含む。ただし割れた点は「升の参照先の書き方」であり、直し方 (1) は義務を足さない
- 直し方の案(議長が選ぶ)
  1. CL0・CL1 の升の括弧を「附属書F F.2 の Q1 が『はい』の案件は、附属書F F.7 の記録を要する。G-7 を適用する構成では基準7 で判定する」に改める。記録の義務の出所を附属書F に置き、G-7 の適用を戻す読みを消す。S0・標準品質・CL0 で Q1 が「はい」の案件に G-7 を戻すかは、ADR-0159 の影響に「未決」として書く
  2. S0 の省略の前提に「F.2 の Q1 が『いいえ』」を足す。採用者への新しい義務で、安全に当たるため重の審議を要する。本束では採らない
- 開示で閉じる案: (1) を採り、残る S0 の穴を ADR-0159 の影響に未決として書く(EV-0305 と同じ扱い)。後続は #448(F.7 の様式)の審議へ寄せる

### 中-B IMPL-1005 の有効な例外の行の条件

- 事実: IMPL-1005 の note は、期限超過の行を数えない条件を「状態が未返却、承認した者・理由・期限が記入され、期限が突合の日以後で、『対象』に当該の行の ID を書いたもの」とする。IMPL-0786(テンプレ3)と 7.3・基準5 は、例外承認の成立に「承認した者が名簿の人で、作成を指示した者でない」と「本人のアカウントの操作による帰属の裏づけ」を加える
- 帰結: この条件のまま降ろすと、検知した変更の作成を指示した者が自分で期限を延ばした行を、機械が有効と数える。7.3 の例外承認の成立の条件より弱い受け皿が1つできる。IMPL-1005 は undelivered で、表示と実態の食い違いではない(計画の文の欠け)
- 直し方の案: IMPL-1005 の note の条件に「承認した者が名簿の人で、検知した変更の作成を指示した者でない(IMPL-0786・第4章 G-7 基準5 と同じ)」を足す。機械で決められる条件(値の一致)で、裁定の範囲に収まる。編集の指摘として議長が直してよい
- 開示で閉じる案: 直さない場合は、IMPL-1005 の note に「成立の条件は IMPL-0786 に揃える」と1文を書き、降ろす担当へ渡す

### 低-A 「対象」の第3の型

- 7.3 の「対象」は「例外を適用する変更または成果物。変更の場合は PR の番号またはコミットの識別子」。IMPL-0602(delivered)は、exception-paths.md が「対象が変更かゲートの判定か」で書き方と照合を分けると書く。台帳の行の ID は、どちらの書き方にも無い。集約の既存の対応づけ(IMPL-0786)は、D-NNN を対象とする行を変更に対応づけないので害は無い
- 直し方の案: gate-criteria.md の延長の文に「(7.3 の『成果物』として、元の行を指す)」を足す。exception-paths.md に第3の書き方が無いことを IMPL-1005 の note に表示する
- 開示で閉じる案: IMPL-1005 の note への表示だけで閉じる

### 低-B 結び付けの向き

- 7.3 は、承認し直された元の行を数えない条件として「元の行に、承認し直した行の識別を書く」を置く。直しは、新しい行の「対象」に元の行の ID を書き、元の行の返却目安を書き換えないとする。向きが逆で、元の行の備考への書き込みを求めるかどうかが書かれていない
- 元の行は区分「類似検知」で例外の行ではないため、7.3 のこの文は直接は掛からない。食い違いではなく、2つの型の並存である
- 直し方の案: テンプレ3 の箇条に「元の行の備考に延長の行の ID を書いてよい。数えない判定は延長の行の『対象』で行う」を足す
- 開示で閉じる案: 直さず、IMPL-1005 の note に「判定は延長の行の『対象』だけで行う」と書いて閉じる

### 低-C エンジンの構成の値

- r-e-cl2 は `q-criticality` が cl2・cl3 のときだけ g-ship の `safetyVerificationRecord` を required にする。F.2 の Q1 はエンジンの入力でない(D-0 表10 の記録)。CL0・CL1 で Q1 が「はい」の案件の構成には、この値が出ない。試験(test-tailoring-engine.mjs L331)も「CL0 では追加しない」を固定している
- 基準7 の適用は D-0 の記録から人が読む(ADR-0159 決定4、IMPL-0045・IMPL-1004)と決めてあるため、規定の誤りではない。ただし、構成の値を見る者は CL0・CL1 の案件で基準7 が掛からないと読む
- 開示で閉じる案: IMPL-1004 か IMPL-0045 の note に「構成の safetyVerificationRecord は CL だけで決まり、F.2 の Q1 を反映しない。適用は D-0 表10 から読む」を足す
