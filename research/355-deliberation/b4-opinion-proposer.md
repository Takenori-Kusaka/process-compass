## 1. IMPL-0048(期間ごとの保証の開示)

- **規定**: `human-ai-boundary.md` L504 の直前の段落「期間の開示に対応する受容と異議の記録が無い状態は、記載の欠落として扱います」。マークは L504(`undelivered check=manual plan=scheduled`)
- **実態**: 論理は在る(期間の切り方・G-8 の記録の「対象」に起点と終点・差し戻しは欠落・委任を使わない構成は成功終了)。**だが試験が無い**。調査(research.md)は「試験が期間の場面を覆うかは未確認」としたが、覆っていない。方針2は「試験で確かめられる範囲は delivered」と置くが、**いまは確かめる試験が無いので、試験を足すまで delivered と呼べない**
- **起案**
  1. **試験を足す**: `template/scripts/gate/test-assurance-period.mjs`(新設)。形は `test-direct-commit-rules.mjs`(集約の本体を一時リポジトリで流す)と `test-ship-evidence-steps.mjs`(workflow の `run:` を bash で動かす)。R1-02 の穴(純関数と静的確認だけで、結線を壊しても通る)を作らないため、集約の本体と workflow を通す

     - 結線: `assurance-period.yml` の「期間を決める」の `run:` を取り出して bash で動かし、不正な日付で終了コード 2、省略時は前月の1日と末日を出す。`needed` の手順が `aggregate` の手順の `if:` に結ばれていること、`aggregate` の `run:` が `|| true`・`continue-on-error` を持たないこと、`permissions` に `checks: read` があること

  3. **マーク**: `state=delivered check=machine target=evidence-aggregation test=template/scripts/gate/test-assurance-period.mjs`。`plan`・`issue`・`review` を外す。note は「期間を指定して出力し、期間の受容と異議の記録を確かめる。確かめるのは集約の論理と workflow の手順の結線まで。定期の実行(cron)と手動起動は、実際の GitHub 上で確かめていない(EV-NEW1)」

## 2. IMPL-0136(文書だけの変更の判定完了時間の SLA)

- **規定**: `gate-criteria.md` L2006「…散文のファイルは行数の算定から除外し、判定完了時間の SLA で判定する」。マークは L2008
- **実態**: 算定からの除外は IMPL-0049 が実装済み。除外した変更の判定完了時間は、集約が出さない。`reviewMinutes` は全 PR に付く(L2161)が、観測は `size:over` の PR にしか使わない(`size-observation.mjs`)。SLA の値は標準に既定値が在る(2営業日。L2203)。**値を採用者の入力として必須にする必要は無い**
- **起案(観測の追加。合否に使わない)**
  1. `measureCommitSize` に `docOnly`(変更の全パスが `DOC_ONLY_DIRS` またはリポジトリ直下の `*.md` に当たる。判定は L343 の既存の関数を共有し、定義を二重にしない)を足す。`excluded` は生成物・ロックファイルも数えるので、これでは代用できない
  2. `summarizeSizeObservation` に `docOnly: { count, minutes: [ ≤1日, ≤2日, ≤4日, >4日, 取れない ] }` を足す。**区切りは時計時間**
     - 開示する近似(根拠水準マーク EV-NEW2): `reviewMinutes` は「作成から最後の承認」で、標準の定義(レビュー依頼から判定の確定)の上側の近似。ドラフトの期間・AI 名義の承認が入る(0章)
     - 決定可能な一方向の読み: **時計時間が48時間以内なら、営業日では必ず2営業日以内**(営業日の時間は時計時間以下)。超えたものは、営業日の数え方(休日・組織の暦)が組織固有で、機械は超過と断定しない
  3. 出荷の保証の開示(`assurance-disclosure`)の同じ観測の節に出す(`renderSizeObservation`)
- **マーク**: 規定の文(「SLA で判定する」)は1つで、機械が判定する形には降りない。方針1に従い、**`state=delivered check=manual target=evidence-aggregation`**。note は「文書だけの変更の判定完了時間の分布を観測として出す。機械は SLA の超過を判定しない。確かめる者: 出荷判定者が、保証の開示の観測で48時間を超えた変更を営業日で数え、超過は7.5の措置に回す」。`plan`・`issue`・`review` を外す
  - この記載は出荷判定者に**新しい読む義務**を置くかが境目。出荷判定者は保証の開示を既に突合する(G-7)ので、**読む表が1つ増えるだけで新しい義務ではない**と私は読む。反対委員が新しい義務と読むなら、`plan=adopter`(判定は運用メトリクスのゲート滞留時間)へ改め、観測の追加は残す、が私の第2案
- **試験(結線まで)**: `test-size-observation.mjs` に純関数の場面を足すのは足場にすぎない。**集約の本体を通す場面**を `test-assurance-period.mjs` と同型の一時リポジトリで1つ足す: 文書だけの PR(docs/ の md)と製品コードの PR を混ぜ、`evidence.json` の `sizeObservation.docOnly.count` が文書だけの PR の件数に一致し、製品コードの PR を数えないこと(`IMPL-0136:ng` = 文書だけを製品コードの PR と取り違えると落ちる、`:ok` = 一致)。`machine` にはしない(判定しないので `manual`)が、`manual` でも観測が出ることを試験で固定する
- **標準の文**: 「判定完了時間の SLA で判定する」の主語がない。直しは**入れない**(重の境目に近づく)。note に実態を開示する
- **採らない案**: (b) SLA 値を D-0 や構成に持たせて超過を所見にする(標準に既定値が在り、組織が別の値を置く場合の入力は新しい義務。**重**。採るなら、値の変更が弱化に当たるかの突合も要る)。(c) の `adopter` 一本(観測が出せるのに出さない理由が無い)

## 3. IMPL-0159(承認に要した時間と変更規模の比)

- **規定**: `human-ai-boundary.md` L636「承認に要した時間と変更規模の比を継続して計測する」。マークは L639。目的は rubber stamp(要約を伴わない承認)の兆候
- **実態**: 規模は `measureCommitSize`(全 PR)、時間は `reviewMinutes`(全 PR)が既に持つ。**欠けているのは全 PR の分布の出力**。観測は `size:over` にしか出ない。**`approvalMinutes` は AI 名義の承認も数える**(0章)。人の承認の時間が目的なので、AI の承認で時間が短くなる/長くなる誤りがある
- **起案(観測の追加。合否に使わない)**
  1. 全 PR の記録に `humanApprovalMinutes`(人の承認だけ。`humanApproverAccounts` と同じ集合の最後の承認。取れなければ null)を足す。既存の `reviewMinutes` は IMPL-0100 の観測が使うので**変えない**
  2. `summarizeSizeObservation` に `approvalPace: { measured, perHundredLines: [ 区間ごとの件数 ], bottomQuartile, median, unmeasured }` を足す。分母は算定された行数(0行の PR は分母が無いので別に数える)。区切りは固定の値でなく生の中央値と下位四分位を主にし、値の解釈(何分/100行が rubber stamp か)は標準が置かない
  3. 前回の集約との比較は出さない(`size-observation.mjs` 冒頭「課さないと決めた」を維持)。「継続して」は、出荷ごとに `evidence.json` が残ることで読み手が系列にする。系列を機械が見るのは採らない
- **根拠水準マーク(EV-NEW3)**: 作成から承認までの時計時間は、レビューの実時間を表さない(夜間・休日で膨らむ)。比の水準に実証が無い。**したがって比は傾向の表示で、警戒の条件に使わない**と標準本文へ1文足す(あるいは note だけ。本文へ足すと「課さない」の明示になり、読み手が区別できる)
- **マーク**: `state=delivered check=manual target=evidence-aggregation`。note は「出荷ごとに、承認の所要分と算定行数の比の分布を観測として出す。人の承認だけを数える。時計時間の近似で、判定には使わない。傾向の読みは機械が行わない。確かめる者: 品質保証の機能が四半期ごとに系列を読む」。旧 note の「PR と判定記録から手で集める」は削る
- **試験**: 集約の本体を通す。人の承認(通過)と AI 名義の承認が混在する PR を流し、`humanApprovalMinutes` が人の承認の時刻を採ること(`IMPL-0159:ng` = AI の承認を数える実装で落ちる、`:ok`)。承認の無い PR は `unmeasured`
- **採らない案**: (b) 手で集めるまま `adopter`(機械で出せるものを出さない理由が無い)。(c) 0136 と1つの関数に束ねる案は、定義の異なる2つの量(依頼から判定の確定/承認から規模)を1つにするので採らない。ただし `summarizeSizeObservation` の同じ節に並べる

## 4. IMPL-0230(生成物の劣化の4指標)

- **規定**: `roles-responsibilities.md` 3.11.7「AI維持管理者は、生成された変更の性質を継続して計測します」(表の4指標)と「個人の指標と保守性の指標は必ず対で確認します」。マークは L1545
- **実態**: template に4指標の算出は無い。重複・移動の検出は履歴の解析と外部の道具を要し、窓・標本数・閾値は組織が定める(IMPL-0268)。**5.4.6 の入力にしない**と標準が明記済み
- **起案: `plan=adopter`**。理由は4つ
  1. **「対」の相方がテンプレートに降ろせない**: 個人の指標を集める機能は、`metrics.md` 原則4「**個人へ絞り込む機能を実装しない**」(L225)と衝突する。準拠テンプレートが個人の生産性の指標を計算すると、標準の自己矛盾になる。採用者が自組織の合意と原則1〜3(対抗する指標・目標値にしない・用いない用途の明示)の下で行うのが筋
  2. **機械で閉じない**: 「対で確認する」は自由な文の意味で、確認の有無は機械が決められない(CLAUDE.md の統制の閉じ方)。4指標の定義と窓は組織固有で、準拠テンプレートが既定を置く実証が無い。参考値の算出(私案の (b))は、定義が動くと値が動き、合否に使わないとしても「計測した」という表示を生む
  3. **`impl-no-adopter.yaml` に載らない**: 3.11.7 は人へ戻す席・停止・統制の弱化の検出ではない。採用者の実装の有無で統制が消える型ではなく、傾向の確認である
  4. **規定は課したまま**: adopter は規定を消さない(定義)。AI維持管理者が計測する義務は標準に残る
- **ADR-0137(束4)の決定の文の案**(束ごとに1本。規定ごとに理由と採らない案):
  - 「決定1: 3.11.7 の4指標の継続計測と個人の指標との対の確認(IMPL-0230)を、`plan=adopter` とする。準拠テンプレートは算出を実装しない。理由: 個人の指標を準拠テンプレートが集めないこと(第6章 運用メトリクス 原則4)、4指標の定義・窓・標本数が組織固有であること、対の確認の有無が機械で閉じないこと。採用者に求めること: AI維持管理者が、自組織が定めた定義と窓で4指標を継続して計測し、個人の指標とは個人を絞り込まずチームの単位の指標と対で確認し、結果を傾向の確認に用い、5.4.6 の検知条件の入力にしない」
  - 「決定2: IMPL-0136・IMPL-0159 は、出荷の保証の開示に観測を足して `delivered check=manual` とする(合否に使わない)」「決定3: IMPL-0048 は試験を足して `delivered check=machine` とし、実機の定期実行は未確認として EV-NEW1 で開示する」
  - 採らなかった案: 4指標のうちリポジトリ単位の2指標を参考値として出す(定義の動きが値を動かす。実証が無い)、個人の指標との対を準拠テンプレートが算出する(原則4と衝突)、AI維持管理者の計測を `scheduled` のまま表示し続ける(ADR-0084 決定4: 降ろす手段が無い規定を `scheduled` と表示し続けない)
- **マーク**: `state=undelivered check=manual plan=adopter decision=src/content/docs/adr/0137-….md の決定1`。note は旧 note から「準拠テンプレートに計測の手段が無い」を「実装しない(ADR-0137 決定1)」に改め、「確かめる者」の語は残す(採用者の AI維持管理者。点は採用者の運用)。`issue=355`・`review` は外す(adopter の `scheduled` の期日を持たない)
- **試験**: 検査(`npm run check` の `check-impl`)が `decision=` の実在を確かめる。追加の機械の試験は無い。台帳に「採用者が実装する」と出る
- **降ろす案を採るべきとは考えない**。採るなら重(新しい義務を準拠テンプレートへ、かつ ADR の原則4の変更の要否を含む)
