## 1. 裁定

### 1.1 IMPL-0241: 第3の形を採る(一致の不一致だけを合否にし、取り出せない・届かないは「未確認」の値にする)

**起案の「合否にする」を骨にし、反対の「null と届かない版を合格に数えない」を全部入れる**。結果は3値(一致・不一致・未確認)。欠落(gaps)に数えるのは不一致だけ。

1. **対象の機能**: 出荷の範囲の変更(PR の `specsTouched` と PR を経ないコミット)が `specs/F-NNN/spec.md` を変えた機能で、範囲の先端にそのファイルが在るもの。G-4 が構成で有効でない(`isActive('g4')` が偽)ときは見ない
2. **式(#334 6章1 の「最新の」を改める)**: その機能の**効いている G-4 の通過の記録のいずれか**が対象とする版の3節と、範囲の先端の3節が、節ごとに一致すること。「効いている」は既存の `g4Approved` と同じ条件(様式: 通過で、後の差し戻しに打ち消されていない。写し: 通過・`headMatch`・`judgeOk !== false`・打ち消されていない)を使い、定義を二重にしない
   - 理由: 「最新」は、様式と写しの間の前後を要する。集約は「様式と写し(レビュー)の間の前後は比べない(判定日時の形が違う)」と定めている(`supersededByLater` の注記)。判定日時の空欄(fix-round2)でも決まらない。「いずれか」は前後を要さず決定可能。**#334 6章1 の「最新」のほうを誤りとする**
   - 開示する限界: 判定済みの古い版へ戻した変更は一致になる(その本文は判定を通過している)
3. **節ごとの結果**
   - 両側が文字列で等しい → 一致。等しくない → 不一致
   - 片側だけ null(節を足した・消した・見出しを変えた) → 不一致
   - 両側 null → **一致に数えない**。ファイルの全文(同じ正規化)が等しければ一致(変わっていないことは決定可能)。等しくなければ未確認
4. **版に届かない場合は未確認**: 様式の「対象」に版が無い(`F-012` だけ)、`PR #34` の写しが無い、判定の版のコミットのオブジェクトが取れない。写しの判定は `commit_id`、様式は「対象」のコミット、`PR #N` は写しの `head_sha` で読む
5. **未確認は欠落にしない**。件数と理由を evidence.json と保証の開示に出し、出荷判定者が突合する(manual)。通過の記録が1件も無い機能は、既存の G-7 基準5 の欠落(`specsWithoutG4`)がそのまま当たる(`specsTouched` は `p.specs` に入る。L2326)。新しい行は足さない
6. **正規化は表示(IMPL-0520)と同じ規則のまま**(改行・行末の空白・端の空行だけ)。行内の空白・表の整形の差は不一致で、欠落になる
7. **見出しの定義を改める**: 「前提」「スコープ外」も「受入基準」と同じ前方一致にする(`spec-sections.mjs` の `OTHER_HEADING`。空白なしの「#前提」を見出しに数えない点は残す)。表示と集約は同じ関数を使う
8. **マークを2つに分ける**(規定の文が表の2行に分かれている)。3節と G-4 は `delivered check=machine`。判断記録の2点(G-3)は IMPL-NEW1 として `undelivered` のまま

理由。

- **決定可能か**: 「変わった」を「定めた正規化の後の文字列が一致しない」と定義すれば、値の一致で閉じる。機械は意味を判定しない
- **偽の FAIL を受け入れる理由**: 第4章「確定した版を変える場合」は、戻り幅を「G-4 の判定者が 2.10.8 で判定する」「提出者と担い手は、戻り幅を選びません」と定める。整形だけの変更かを決めるのは G-4 の判定者で、機械の正規化が先に「意味は同じ」と決めると、この規定と逆になる。閉じ方は、判定者が変更後の版を対象に判定記録を1件書くこと。見逃し(統制の穴)と、判定1回(記録が残る)を比べ、厳しい側を採る。表示と同じ関数なので、PR の時点で表示が出た変更だけが出荷で不一致になる
- **未確認を欠落にしない理由**: 変更が無くても判定のやり直しを機械の都合で課す形になり、取得の深さという環境で合否が変わる。見出しの無い機能仕様を出荷の失敗にすると、見出しの存在を出荷の条件にする新しい義務になる(採るなら重)
- **所見だけにする案(反対)を採らない理由**: 標準は既に「出荷判定(G-7)の証跡の集約: 合否にする」と書いている(`gate-criteria.md` L341、#334 で確定)。所見に留めると、標準の文のほうを弱めることになる。反対委員の挙げた害(null の偽の合格、届かない版)は 3〜5 で除いた。残る害は行内の空白・表の整形の偽 FAIL で、上の理由で受け入れる
- **マージのコミットで版を代用する案(起案 (a))を採らない理由**: 基底が同じ仕様の別の節を先に変えていると、マージ後の木は判定していない変更を含み、代用が偽の合格を作る。`commit_id` のオブジェクトで読めば、この場合は不一致になる

### 1.2 IMPL-0023: 規定の文で2つに分ける。検出は delivered/machine、起票は delivered/manual

3.13.5 は「次の3組のずれを機械で検出します」と「検出したずれは、3.13.3 の起票として扱います」の2文に分かれる(方針1 の条件を満たす)。

- **検出(IMPL-0023)**: 試験を足したうえで `delivered check=machine`。条件は、検出を純関数に切り出し、偽の合格の経路を試験で固定し、限界を note と本文に書くこと。試験が入らなければ `manual` に留める(規約 L75〜76)
- **起票(IMPL-NEW2)**: 「起票するのは人で、機械は起票せず構成も書き換えない」と標準に明記する。降ろし先は集約の案内の文。`delivered check=manual`
  - 起案の読みを採る。機械の起票は、構成の書き換えの経路を変化点の手続に限る規定(3.13.4 要求事項1)と決定者の記名に反する
  - 反対の「`undelivered plan=scheduled` のまま」は採らない。機械で閉じる形は (c) 案しか無く、この束では採らない。降ろす手段を決めていない規定を `scheduled` と表示し続けることは、ADR-0084 決定4(ADR-0126 の突合の表「降ろす手段の無い規定を `scheduled` と表示し続けない」)に反する
  - 方針1 との関係: `check=manual` は機械の確認を主張しない(規約「機械は確かめない。確かめる者と時点を note に書く」。先例 IMPL-0250・IMPL-0240)。反対委員の「文言を出すだけ」という指摘は、note に「起票されたか・前回のずれが残っているかを機械は見ない」と書いて開示する
- 担い手の識別の部分一致は変えない(版の無い共著者名をずれに数えると警告が常に出る。実証は無く、EV-NEW2 で開示)
