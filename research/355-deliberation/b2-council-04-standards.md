# #355 束2 委員 04(規格)の意見書

2026-11-17。立場: 安全規格・ISO/IEC/IEEE・既存 ADR との整合。入力は議題、内部・外部の調査。条文・ADR は一部を確かめた(exception-escalation 7.3、human-ai-boundary 5.8.3、ADR-0084 R-6 の表)。規格本文は有償で、外部の調査と同じく抜き書き・改訂案による。根拠水準は各項に書く。

## 0. 総論(規格の立場の3点)

1. 規格(61508・26262・DO-178C・62304)は**項目と結果の文書化を定め、様式と置き場を組織に任せる**。よって「項目の存在・非空・理由つき該当なし」を機械、「中身の妥当性」を人とする分担は規格の型に沿う(SRC-0763、SRC-0437。根拠水準: 二次・改訂案)。
2. 規格が求めるのは**製造者・組織の検証**であり、標準の集約が代わりに確かめることではない。ゆえに「集約が確かめない」は規格違反でない。ただし本標準が基準7 に「欠落がない」と書く以上、**表示と実態の食い違い(ADR-0084 の強く読まれる問題)**は開示が要る。
3. 安全の統制を `adopter` に倒す根拠は規格側に無い(外部 Q2)。ただし「manual で全体を人が確かめる」は、規格の実務(存在は記録の検査、妥当性は独立した評価)と整合する。

## 1. IMPL-0045(基準7 安全の検証記録)

- **判定: 採る(manual を維持し、機械は存在・非空まで。adopter にしない)**。
- 降ろし方: 全体を `manual`(ADR-0084 R-6 が退けた「降りた部分と降りていない部分に分ける」に従い、分けない)。機械の検査(存在・非空・「該当なし」は理由つき)は、**構成が安全関連のときだけ**、別の文に書かれた決定可能な条件として置く場合に限り別マークにできる。ただしこの分けは ADR-0084 の型と当たるため、**1つのマークの note に「機械は6見出しの存在・非空まで。妥当性は閉じない」と開示する**形を採る(分けない)。
- state=undelivered を維持するか: 機械の範囲を実装しない間は undelivered のまま。scheduled の期日は#448 の様式(IMPL-0933)の裁定に従属させる。
- A1(#448 と束ねるか): **様式の裁定は #448 に任せ、本束は「検査の強さ」だけを決める**。様式が無いと存在を検査できないので、本束の plan は #448 の裁定を前提にする旨を note に残す。二重に様式を決めない(食い違うと規格の「項目は同じ・様式は組織」の型が崩れる)。
- A2: adopter 不可。理由は、安全は ADR の原則の変更・採用者への義務に当たり、かつ F.14 の「標準は適用規格を決めない」ため、**項目の内容は機械で判定しない**。内容を閉じない統制は manual と開示する(CLAUDE.md の統制の閉じ方の規則どおり)。
- A3(例外承認): 7.3 は「判定基準を満たさない場合」を受けるので、基準7 も形式上は対象。しかし**安全度の高い案件で基準7 を例外承認で通す可否は条文に無い**。規格(61508 の HR を採らないときの理由の詳述)は「採らない自由」を認めるが**理由と独立した評価を要する**。本委員は「許す。ただし新しい条項は足さず、F.7 の6項目のうち『独立した評価』を欠く例外承認は 7.3 要求事項2・3 の理由・影響に書かせる」案を取る。「許さないと明記」は 5.8.3(AI に担わせない領域)の型で、**安全の人の最終判断は 5.8.3 が既に不変**だから、基準7 の例外まで禁じる条項は二重になる。却下案: 許さないと明記(5.8.3 と重複、新しい条項)。ただし許す旨を条文に書かず、**手引きに「安全関連での基準7 の例外承認は、独立した評価の記名を残す」と1行**に留める。根拠水準: 暫定(単一規格の類推)。
- A4(CL と F の適用): **人が判定**。F.2 は人の判断で、CL は案件ごと(ADR-0039)。機械は構成の `q-criticality` を**入力の読み取りとして使い、F.2 の判断を置き換えない**。cl の値が「安全関連なし」のとき機械は「対象なし」を出すが、その根拠の確かさは G-7 の既存の欠落(仮判定の出荷)に任せる。IEC 62304 4.3 の「分類は必須・記録の方法は製造者」と同型。
- 破られたとき: 事故時に検証の記録を示せない(採用組織・利用者)。**ここは細かく書く価値がある**(安全)。ただし細かさは項目(6つ)までで、見出しの順序や様式は書かない。
- 削れる条項: F.7 の項目とゲートの基準7 は同じことを2回書く。基準7 は「F.7 の記録が判定記録に添付されている」に縮め、項目は F.7 に一本化する(編集)。

## 2. IMPL-0044(基準6 AI 品質指標の確認)

- **判定: 基準6 は「確認の記録が在る」までを残し、合否にしない。adopter にしない**。
- 規格の観点: AI 品質指標に直接対応する安全規格は無い(外部 §5)。ISO/IEC 25010 系の保守性は特性の定義であって閾値を定めない、という型が近い。**標準が「合否にしない」と決めている以上、機械が欠落を失敗にする形は整合しない**(内部 §2.2)。
- B1: 「確認」は**傾向の確認の実施の記録**。閾値の記録は G-1 の要求(IMPL-0977 / #450)で、本束では重ねない。
- B2: 基準から外す案(9基準を8にする)は、**G-7 の番号体系を変える**。ADR・手引き・template が基準番号を引く(lint:refs の対象)ため、外すより「基準6 の値を『傾向の確認の記録が在る(良否は問わない)』」に改める方が既存と整合する。外す案は退ける(理由: 番号の参照の連鎖と、基準9「未達は値として受ける」との対称を壊す)。
- B3(adopter): 0230 と同じ理由は、**算出が組織の履歴に依る指標**に当てはまる。0044 の「確認の記録」は算出でなく人の確認なので、adopter は当たらない。`scheduled` + 存在の検査(manual)とする。
- 根拠水準: 暫定(記録の置き場の先例は調べた範囲に無い。外部 §5)。:::caution で開示。

## 3. IMPL-0046(基準8 知財潔白性)・IMPL-0548

- **判定: 採る(実施と結果の記録を求める)。「検知の結果で止める」は課さないと明記する**。
- 外部の根拠: 検知の実施記録を求める根拠は十分(利用者側の責任、日本の依拠性の推認)。結果で止める根拠は無い(Copilot coding agent も Block 非対応)。
- C2: 「合否にしない」と「期限超過の未処理が残る出荷は止める」は**別の統制**と条文で明記する。前者は検知の結果、後者は持ち越しの管理(7.3 の回収の期限と同型)。基準8 に含めたまま同居させると、読み手に検知の結果が合否と読める。分けて書く。
- C1: 台帳へ識別する欄(区分「類似の検知」または対象の値)を**新設する**。識別が無いと期限超過を機械が出せず、「止める」文が実質 undelivered になる。adopter にするのは却下(外部 Q6: 利用者責任の整理と整合しない)。新設の最小形は既存の区分に値を足すだけで、区分を増やさない案を優先(既存の条項を削れないかの要請)。
- Q5(偽の一致): 現状は空のコマンドでも「実施あり」と数える(IMPL-0995)。**この食い違いの開示は必須**(根拠水準マーク)。道具の識別を記録へ要求するかは、道具の水準を標準が指定できないので「道具の名称と実施日を記録する」までに留め、水準は指定しない。
- C3: IMPL-0548 は識別の欄が同じなので**本束に入れる**。
- 破られたとき: 推認の防御は記録だけ(L1180)。細かく書く価値あり。ただし道具・手順は手引き。

## 4. IMPL-0042(基準3 受容した負債の記録漏れ)

- **判定: 0043 と同じ型で全体を manual(D2)。結合の義務は課さない(D1)**。
- 理由: ADR-0084 R-6 が「降りた部分と降りていない部分に分ける」を退けている。先例(0043、ADR-0138)と揃える。負債の行へ PR を書く義務は、**チェック項目を付けなかった妥協を検出できず、偽の安心を生む**(ADR-0084 L177)。穴を開示した上での任意の結合は手引きに回す。却下案: 結合の義務(漏れの一部しか見えず、検出の穴が強く読まれる)。
- 小さいチーム: 記録者と突合者が同じ人になることを根拠水準マークで開示する。独立の確認は規格(61508 の検証の独立性)の型だが、本標準が小さいチームに課すかはテーラリング(別の裁定)。

## 5. IMPL-0136(SLA の判定)

- **判定: E1 は (b) 観測+7.5 の措置。(a) 合否は採らない**。ISO/IEC 20000-1 の型(測定・監視・報告・未達時の処置。規格本文は未読で二次)に整合する。観測を判定と呼ばない ADR-0137 決定3 とも整合。ADR-0058(上限超過は止めず確認)の趣旨にも合う。
- 条文の直し: 「SLA で判定する」→「判定完了時間の観測を出し、超過は 7.5 の措置につなぐ」。これは意味の確認であって新しい義務ではない(軽の範囲)。意味を変える点を ADR に書く。
- E2: **#445 へ一本化**(催促・通知・代理は IMPL-0979・0681 が追う)。束2 では二重に決めない。
- E3: 営業日の暦は**必須の入力にしない**。入力が無いときは「判定しない」と開示する。新しい義務は課さないと明記。
- E4: 担い手への指示の文書(CLAUDE.md・AGENTS.md)を散文として SLA だけで通すかは、**実行層の挙動を制約する文書は行数の上限から外せない**側に私は立つ。ただしこれは ADR-0072 の趣旨の再解釈なので本束で裁定せず、先送り(足りないもの: 指示文書の変更を R 区分で扱う既存条項との突合)。

## 6. IMPL-0981(3.11.7 の対)

- **判定: R2 を採る。R3(削除)を次点として落とす理由を書く**。
- 理由: 外部 Q9 のとおり、先例は「個人を単位に測らず、チーム/リポジトリ単位で緊張関係のある複数の指標を見る」。metrics 原則1(対抗する指標と対で配置)が既に標準内の根拠。R2「保守性の指標は、単独で提示せず、採用者が使う生産性・速度の指標と並べて確認します」は、対の相手を定義せず、個人の語を消し、metrics 原則4(個人へ絞り込まない)と矛盾しない。
- 却下: R1(読み替えは新しい対の相手を持ち込む)、R3(兆候の記述は残る価値があり、原則1 との結びつきも失う。ただし R2 が降ろせないと分かれば R3 へ)、R4(推奨に改めても降ろし先が無い)。
- **「個人の指標」の定義は採らないと決めた**(所有者の決定どおり)。理由は細かい定義の増加と個人評価への転用の危険。SPACE の一次を読めていないので、定義案の再開に外部の根拠は無い。
- F2: **意味の変更として ADR に書く**(「個人」→「採用者の生産性・速度の指標」は意味が変わる)。編集の指摘では扱わない。
- 降ろし先: 「単独で提示しない」はレポートの出力の問題で、機械の検査は難しい。manual + 手引き。根拠水準: 暫定(先例は DORA の二次)。

## 7. 横断(G: 基準3・6・7・8 の「欠落 0 件」と基準9 の非対称)

- **開示する(根拠水準マーク)。基準の文を揃える案は却下**。揃えると全基準を「未達は値として受ける」に倒すか全基準を厳しくするかになり、いずれも ADR の原則の変更に当たる(重)。本束で扱う範囲を超える。
- 機械の検査の範囲を、今回は**決定可能な条件(存在・非空・日付の比較)だけ**とする。意味の判断(F.7 の妥当性、検知の良否、負債の漏れ)は manual か adopter で開示する。

## 9. 必ず通す問い

1. 条文は結果と証跡まで: 0045 は6項目、0046 は実施と結果・期限、0042 は台帳に在ること。手順(見出し様式、突合の手順、3つの選択肢の表)は手引き。
2. 例外承認で受けられるもの: 道具が無い(0046)、F.7 を採用者の様式で持つ(0045)は 7.3 で受ける。新しい条項は足さない。
3. 細かく書く:安全(0045)と推認の防御(0046)だけ。0044・0136・0981 は細かく書かない。
