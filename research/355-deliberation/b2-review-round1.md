## 所見の詳細と直し方の案

### 高-1 t3 の standard の文字列が標準に無い

- 事実: `template-fields.yaml` の t3 に `standard: 区分は**負債 / 例外 / 未解決**のいずれか` がある。標準の本文は `区分は**負債 / 例外 / 未解決 / 類似検知**のいずれか` に改まった。`check-template-fields.mjs` は `standardText.includes(field.standard)` で部分一致を見る。太字の閉じの位置が変わったため、旧い文字列は本文に無い(grep で0件)。方向1 の検査が失敗し、`npm run check` の `test:fields` が落ちる。実装の記録は `test:fields` を流していない(drift の検査と lint だけ)
- 表示の食い違いもある: template の `03-debt-ledger.md` は「区分 | **負債** / **例外** / **未解決** のいずれか」と書いている。区分「類似検知」を除いて列挙するため、標準と逆の指示になる。ADR-0040 により omit では登録できない
- 直し方の案
  1. standard を `区分は**負債 / 例外 / 未解決 / 類似検知**のいずれか` に改める(template の側は `未解決` のままで通る)
  2. 「類似検知」の欄を必須欄に足すのは、template を直す後続(IMPL-0548)と同じ作業で行う。それまでは、IMPL-0548 の note に「template の欄の書き方は区分を3つに限って列挙しており、標準と逆の指示になっている」と書いて表示する
  3. push の前に `npm run test:fields` を流す

### 高-2 「読まれずに通る散文の検知」の未達が台帳から消えた

- 事実: 旧い IMPL-0136 の note の末尾には「読まれずに通る散文の検知も降りていない(ADR-0092 決定7)」があった。新しい note には無い。ADR-0092 決定7 は「AI が生成した大量の散文が読まれずに通ることの検知(IMPL-0136・IMPL-0159)は、未達の表示を続ける」と書く。ADR-0137 のコンテキストの表は、この決定7 を補い、「散文の検知は降りず、IMPL-0136 が未達として表示し続ける」と書く。IMPL-0159 の note は製品のコードに限る。ほかに散文の検知を表示するマークは無い(「読まれずに通る」「読まずに通る」で src/content/docs を検索。ADR 3件と metrics.md だけ)
- 0136 の意味は「散文の変更にも SLA を掛ける」へ移った。このため、ADR-0092 決定7 が 0136 に負わせた未達が、どのマークにも乗らなくなった。CLAUDE.md の「降りていない規定は消さずに表示し続ける」に当たる。採用済み ADR の記述(0136 が表示する)と台帳の実態が食い違う。巡の数に関わらず直す類の「高」
- 直し方の案(どちらか。議長が選ぶ)
  - (a) IMPL-0136 の note に「読まれずに通る散文の検知は降りていない(ADR-0092 決定7・ADR-0137)」を戻す。SLA の措置と別の主題が1つのマークに同居する欠点は残る
  - (b) 散文の検知を新しいマークに分ける(state=undelivered、決定の所在は ADR-0092 決定7)。ADR-0137 に追記して、表示の担い手が移ったことを示す。主題が分かれ、#445 へ移した 0136 と混ざらない。突合の側は (b) を推す
- 合わせて、ADR-0159 の「影響」の降りていない規定の列挙にも、この件を書く

### 中-1 基準7 の適用の読みと 軸E の表の食い違い

- 事実: 新小節は「安全関連ソフトウェアは、D-0 表10 の『附属書F F.2 の回答』が『はい』の案件と、安全重要度が CL2・CL3 の案件である。両者が食い違う案件は、安全関連として扱う」と書く。第8章 軸E の「区分ごとの調整」の表(tailoring-guide.md L1099)は「安全適合性の検証記録(附属書F) | 不要(CL0) | 不要(CL1) | 必須 | 必須」と書く。CL0・CL1 で Q1 が「はい」の案件に、新小節は F.7 を求め、軸E の表は不要とする。附属書F F.2 の図は、Q1 が「いいえ」なら「本附属書の適用外」とする。CL2 で Q1 が「いいえ」の案件では、軸E(必須)と F.2(適用外)が前から食い違っていた
- ADR-0039 との関係: 基準7 の適用は案件の単位で決まる。CL も F.2 も案件ごとの記録で、変更ごとのリスク区分から適用外を導く形ではない。ADR-0039 決定4 とは食い違わない。ただし、ADR-0159 決定4 の「CL から F.2 の判断を導かない(ADR-0039)」の引用は当たらない(ADR-0039 はリスク区分と CL の単位の区別を決めた ADR)。低-2 を参照
- 裁定の評価: 和集合の読みは、表10 の段の下限の規則(F.2 の Q1 が「はい」なら判定の結果に依らず段3)と同じ向きである。安全の側へ倒れており、信頼性の判断として妥当である。ただし、軸E の表の「不要」と F.2 の「適用外」の2か所が直っていない。読み手は表を見て CL1 は不要と読み、基準7 を外す
- 直し方の案: 軸E の表の行に「CL0・CL1 でも、附属書F F.2 の Q1 が『はい』の案件は必須(第4章 G-7『基準3・6・7・8 の記録』。ADR-0159)」を行の中に書く(#226 の規約: 限定は行の中)。F.2 の図の「本附属書の適用外」の近くに、CL2・CL3 の案件では基準7 が掛かる旨を書く。CL0・CL1 の案件への新しい義務に当たるかを、ADR-0159 の決定4 に一文で書く(議長の裁定は「新しい義務ではない」。軸E の「不要」と並べると義務が増えて見えるため、根拠を残す)

### 中-2 「類似検知」の期限の延長と機械の規則

- 事実: L1219 は「期限を超過した行の期限の延長は、第7章 7.3 の例外承認で受けます」と書く。新小節の基準8 と IMPL-1008 は、区分「類似検知」の行で期限が過ぎ、状態が未返却のものを欠落に数える。延長を承認した例外の行を見て除く規定は無い。テンプレ3 の「期限を延ばす場合は、行を書き換えず、新しい行で承認し直す」は区分「例外」の行の箇条である。区分「類似検知」の行の返却目安を書き換えることは禁じていない
- 結果: 7.3 で延長を承認しても、元の行は期限を過ぎた未返却のままで、機械は止め続ける。止まりを避けるには返却目安を書き換えるしかない。承認なしの書き換えでも機械は通す。問い2(7.3 で受ける)の受け皿が、機械の規則に結線されていない
- 直し方の案: 延長の記録の形を決める。案として、区分「例外」の新しい行を立て、「対象」に「類似検知」の行の ID(D-NNN)を書く。元の行の返却目安は書き換えない(テンプレ3 の書き換えの禁止を「類似検知」の行へ広げる)。IMPL-1008 の note に、有効な例外の行が対象とする行は欠落に数えない旨を書く。機械で決められる条件(ID の一致・状態・期限)なので、machine で閉じられる

### 中-3 新小節の「集約は次の範囲だけを見ます」と template の現状

- 基準3: 新小節は「集約が見るのは、技術負債台帳の有無と、区分『例外』の行と変更の突合だけ」と書く。template の criteria[3] は「技術負債台帳 あり/なし(台帳の有無だけを見た)」であり、`gates/G-7.md` の手順1 も「機械が台帳の有無しか見ない」と書く。区分「例外」の行と変更の突合(aggregate-evidence.mjs L2568 以下)は、G-6 の未達と基準5 の欠落を例外承認で受ける処理で、基準3(受容した負債の記録漏れ)を確かめない。基準3 の機械の範囲を過大に書いている。IMPL-0042 の note も同じ文を持つ
- 基準7・8: 「数える」「見る」を現在形で書くが、template の criteria[7] は `machine: 'not-checked'`、criteria[8] はライセンス検査の記録の有無だけである。IMPL-1007〜1006 が undelivered を表示しており、台帳は正しい。ただし、小節の書き出しの文は template の挙動の記述として読める(基準4 の記録の同じ文は、delivered の挙動の記述だった)
- 基準7 の案内: template の criteria[7] の humanReconcile は「構成の安全重要度: q-criticality」を出し、判定者を CL で案内している。新小節の「CL だけから導かない」と逆向きである。IMPL-0045 の note は手順が無いことしか書かず、この案内の食い違いを表示していない(裁定の 7章 2 と実装の記録には一覧として書いてある)
- 直し方の案
  1. 基準3 の箇条を「集約が見るのは、技術負債台帳の有無だけである」に改める(IMPL-0042 の note も同じ)
  2. 書き出しを「集約が見る範囲は、次のとおりとします。基準7・8 の機械の部分は降りていません(IMPL-1007〜1006)」の形にして、規定と現状を分ける
  3. IMPL-0045 の note に「集約の基準7 の行は、構成の安全重要度(q-criticality)だけを判定者へ示しており、F.2 の回答を示さない」を足す

### 中-4 ADR-0137 への追記が無い

- ADR-0137 の見直しの契機は「#355 の重の審議で、IMPL-0136 の SLA の判定と IMPL-0981 の直し方が決まったとき」である。決定3 は 0136 を `issue=355 review=2027-02` に保つと書き、影響の節は「IMPL-0136 と IMPL-0981 は undelivered のまま台帳に出続ける」と書く。ADR-0159 は 0136 を `issue=445` へ移し、0981 を adopter にした。ADR-0159 は「ADR-0137 を置き換えない」と書く。ただし ADR-0137 の側には、決まったことが書かれていない。同じコミットの ADR-0139 には「追記(2026-11-17): … 決定は変えていません」の先例がある
- 直し方の案: ADR-0137 のステータスへ「追記(2026-11-17): 見直しの契機の2点目は ADR-0159 決定6・7 が満たした。IMPL-0136 は #445 へ移り、IMPL-0981 は adopter になった。決定は変えていない」を足す。高-2 で (b) を採る場合は、散文の検知の表示の担い手が移った旨も書く

### 低-1 テンプレ3 の段落

- 新しい段落「区分『負債』『未解決』『類似検知』の行は、『承認した者』を『—』としてよいです。…」の直後に空行が無く、「区分『例外』の行は、第7章 7.3 が…」と1段落になる。L735 の箇条「区分『負債』『未解決』の行では、『対象』と『承認した者』を『—』としてよい」と重なり、類似検知の扱いが2か所に分かれる
- 直し方の案: 空行を入れる。「—」の扱いは L735 の箇条へ寄せる。たとえば「区分『負債』『未解決』の行では『対象』と『承認した者』を、区分『類似検知』の行では『承認した者』を『—』としてよい」の1行にまとめる

### 低-2 「CL だけから導きません」の文と ADR-0039 の引用

- 「基準7 の適用を、安全重要度(CL)だけから導きません」は、直前の箇条(CL2・CL3 なら安全関連)と矛盾して読める。言いたいのは「CL0・CL1 であることを理由に、F.2 の Q1 が『はい』の案件で基準7 を外さない」である
- 直し方の案: 文をその意味へ改める。ADR-0159 決定4 の「(ADR-0039)」は「(ADR-0039 と同じく、別の軸の判定で置き換えない)」とするか、外す

### 低-3 3.11.7 の原則の引用

- metrics.md の「設計の原則」の表(原則1〜5)は、「三識メトリクス(AI協調の習熟度)」の節の中にある。全体の原則は冒頭の「単独の指標で判断しない(対になる指標とセットで見る)」である。文意はどちらとも合う
- 原則4(個人へ絞り込む機能を実装しない)との整合: R2 の文は個人の語を消し、「個人の単位の指標を定義せず、その収集を求めません」と書く。原則4 と整合する。採用者が並べる相手に個人の単位の指標を選ぶことは禁じていないが、それを禁じると新しい定義になり、所有者の方針(定義を増やさない)と当たる。直さなくてよい
- 直し方の案: 引用を「運用メトリクスの原則『単独の指標で判断しない』」に改めるか、三識の節の表であることが分かる語にする

### 低-4 「類似検知」の行の返却目安の形

- テンプレ3 の例は返却目安を「<時期/条件>」と書く。条件の形で書かれた「類似検知」の行は、IMPL-1008 が期限を比べられない
- 直し方の案: テンプレ3 の新しい段落に「区分『類似検知』の行の返却目安は日付で書く」を足す(L1213 の「期限を付します」の具体化で、新しい義務ではない)。読めない期限の扱い(欠落にする)を IMPL-1008 の note に書く

### 低-5 保証の開示の項目5

- 項目5(残存リスク・既知の不具合・状態が有効の例外)の導出元は「基準1〜3 の記録、7.8」で、基準8 の台帳の行を含まない。集約も負債・例外・未解決だけを数える。期限内の未処理の「類似検知」の行は、出荷の開示のどこにも出ない
- 直し方の案: 項目5 に含めるかを議長が決める。含めるなら template の一覧(7章)へ足す。含めないなら、課さないと決めた旨を ADR-0159 に書く

### 低-6 根拠水準マークの文体と出典

- EV-0306 の本文の「SPACE の一次資料は読めていない。」が「である調」である(枠の本文はですます調)。「読めていません」に改める
- EV-0305 の対象は「文化庁…と、検知の道具の実務」と書くが、出典の識別子が無い。裁定は SRC-0760・0782 を挙げている。追跡のため、識別子を本文に足す

### 低-7 IMPL-1009 の見出しの adopter 不可

- `impl-no-adopter.yaml` に登録したのは新小節だけである。見出し「類似の検知の実施記録」は基準8 の知財の記録で、ADR-0159 決定5 は adopter にしないと決めた。将来この見出しのマークを adopter に移す変更を、検査が止めない
- 直し方の案: 同じ why で鍵を足す

### 低-8 IMPL-1008 の位置

- 裁定 4.1 の2 は NEW2 を新小節に置くとしたが、実装は L1219(期限超過で止める文)の直後に置いた。文の所在に合わせた置き方で、問題は無い。実装の記録の「裁定との差分」に書かれていないため、記録に足す
