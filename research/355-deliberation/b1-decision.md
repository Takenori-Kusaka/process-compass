## 1. 裁定

### 1.1 IMPL-0043: 第3の形を採る(基準は出荷判定者の判定として降ろす。機械は未記入の検出までを別の文・別のマークで持つ)

1. **「完備」の定義は足さない**。標準に足すのは、基準1・2 と同じ型の「基準4 の記録」の段落で、判定者と機械の分担を書く(4.2)。完備を判定するのは出荷判定者のままで、機械の検出は「未記入」と呼ぶ。「記入が在ることは完備を意味しない」と本文に書く
2. **(a) 意味を変える直しか**: 変えない。3項目は基準4 の文と第6章の様式が既に求める。未記入の文書は現在も完備でない。機械が欠落に数えても、採用者の義務は増えず、減らない(判定者の判定は残す)。軽に収まる。**議長がこれを新しい義務と読む場合は、0043 と IMPL-NEW1 だけを束2 へ残す**
3. **(b) 初期セルとの一致は決定可能か**: 決定可能(値の一致)。比べる基準は、その案件のリポジトリの `templates/05-handover.md`(採用者が様式を改めれば基準も追従する)。採る。ただし閉じるのは「様式のまま」だけで、1字の書き換えと「TBD」は通る(実行で確認)。機械のマークの note・本文・EV-NEW1 で開示し、検出の名を「未記入」に限る。基準の様式が無いリポジトリは、空欄だけを見て「初期の文と比べていない」を結果に出す(欠落にしない)
4. **(c) 全セル非空**: 採らない。根拠が無く(起案も E0 と書く)、正当な空のセルを欠落にする。記入の条件は「初期セルの集合に無い非空のセルが1つ以上」
5. **(d) 障害時連絡先の欄**: template の欠落であり、対応表の登録漏れ。0043 と別の不具合として直す(軽。テンプレートの不具合)。基準4 が名指す3項目の1つを書く場所が無く、標準の様式の「エスカレーション順序」を落とした理由が `omit` に無い(ADR-0040 決定3)。0043 の検査より先に、別のコミットで直す
6. **標準の様式どおりの文書も読む**: 「## 監視項目」「## 障害時の連絡先・体制」「## 復旧手順」(箇条書き)で書いた文書を、記入ありと読む(束3 0章の轍を踏まない)
7. **マーク**: IMPL-0043 は基準4 そのものを指し続け、`delivered check=manual`(確かめる者: 出荷判定者)。機械の未記入の検出は IMPL-NEW1 `delivered check=machine`

理由。

- 反対の「`undelivered`・`scheduled` を保つ」は採らない。内容の充足を機械へ降ろす手段は無く、手段の無い規定を `scheduled` と表示し続けることは ADR-0084 決定4 に反する(束3 1.2 と同じ)。`adopter` は人の判定には当たらない。基準1・2(IMPL-0040・0041)は、機械が材料と一部の欠落を出し、判定者が判定する形を `delivered check=manual` と書いており、基準4 をこれに揃える
- 起案の案A(0043 を machine、内容を新しい manual のマーク)は、台帳の「G-7 基準4」の行が「機械が確かめる」と出る。反対委員の言う偽の安心に当たる。番号の向きを逆にする
- 反対の実質(白紙が通る・「完備」と表示しない・置き場が一意でない)は、3・1・5 で全部入れた
- 方針1 との関係: 規定の文は、表の行(判定)と新しい段落(機械の扱い)の2つに分かれる。`check=manual` は機械の確認を主張しない

### 1.2 IMPL-0132: 3検査を `delivered check=machine` にする。初期セルの比較を採る。「前の記録との一致」は所見として出し、別のマークで manual

1. **対象**: `context/decisions/` の、状態が採用・一部置き換えの判断記録。保管領域は見ない。本リポジトリの `src/content/docs/adr/` は標準の ADR で、`check-decisions.mjs` は読まない(対象外でよい)
2. **欄**: 事業影響の5項目(G-3 基準5)。節の見出しは「事業影響」「事業への影響」で始まるもの、1つ目の欄は「影響を受ける利用者・業務」「影響する利用者と業務」のどちらも読む。**節が無い・行が無い記録は失敗**(緩めない。R2-01)
3. **空**: 空白、「—」「-」、全体が `<…>` の形、**その案件の `templates/02-adr.md` の同じ欄の初期の文と一致**、「取り消しの可否」に3つの選択肢のうち2つ以上が残る、のいずれか。初期セルを採る理由は 0章の3行目(見ないと白紙が通る)
4. **単一の値**: 区切り(`〜`・`~`・「から」・「ないし」、数字に挟まれた `-`・`–`。日付は除く)の前と後がともに空でなく、正規化の後に同じでないものを幅とする。それ以外は単一(「以内」「以上」「約」「程度」だけの記載を含む)。偽の FAIL(「最短 10 分、最長 2 日」)は、失敗の文で「下限〜上限」の形を案内して閉じる。様式の手引きも「下限〜上限」と書く
5. **「なし」**: NFKC・空白・文末の句点を除いて、なし・無し・特になし・該当なし・n/a のいずれかと一致。「不明」「TBD」、理由つきの「なし(…)」は通る(限界。標準の文は「なし」を名指す)
6. **既存の記録への当て込み**: template に判断記録の実例は無い(README だけ)。実際の採用者の記録での偽の FAIL の量は実証が無い(EV-NEW2)。旧い記録で落ちたものの直し方は、置き換える判断記録を起こすこと(採用後に書き換えてよいのは状態の行だけ)。失敗の文に書く
7. **前の記録との一致**: 所見として出す。失敗にしない。定義は「『影響を受ける利用者・業務』『顕在化が分かる兆候』のいずれかが、番号が前の判断記録(保管領域を含む)の同じ欄と、正規化の後に一致する」。回復の欄と選択式の欄は比べない(正当に重なる)。置き換えの対はその旨を添える。G-3 の判定者が所見を読む(IMPL-NEW2 `delivered check=manual`)
   - 失敗にしない理由: 全部を置き換える判断記録は、正当に同じ影響を書く。失敗にすると言い換えを促す
   - 出さない案(反対の `undelivered` 維持)を採らない理由: 表は「検査する」と書き(ADR-0024 決定12)、降ろす形が決まらないまま `scheduled` を保つことになる。所見は偽の FAIL を作らない

### 1.3 IMPL-0042: 束2(重)へ移す。この束では note と `review=` だけを直す

2委員の一致を採る。標準が既に求める欄だけでは結合できない(記録漏れは台帳に無い事実。負債・未解決の「対象」は「—」でよい)。部分降ろしは採らない。この束では、(1) note を実態へ合わせ (2) `review=2027-02` へ改め (3) `gates/G-7.md` へ「機械は台帳の有無しか見ない。記録漏れは出荷判定者が PR のチェック項目と台帳を突合する」の1行を足す(現行の `criteria[3].humanReconcile` と同じ内容で、判定者の手順に無い)。`state` は動かさない。

### 1.4 反対委員の注文(presence と完備): この束の裁定の記録と ADR-0138 に留める。規約は直さない

裁定の文: **「規定の文が完備・欠落 0 件・内容の充足を求めるとき、機械が確かめるのが単位の有無・非空・様式の初期の文との不一致までであれば、その規定を `delivered check=presence` とも `delivered check=machine` とも書かない。規定の全体は `manual`(判定者)で表示し、機械の部分は、標準に別の文が在るときだけ別のマークにする」**。規約(`implementation-marking.md`)へ足すと、`delivered check=presence` の 103 件のうち当たるものの表示を遡って見直すことになる(note に該当の語を持つものが9件以上)。棚卸しを伴うので、規約の直しは #355 へコメントで残す。

### 1.5 重へ上げる点

- 無い(0042 は受付の裁定のとおり束2 へ移す)
- 議長に読みの確認を求める点が2つ。(i) 1.1 の2(基準4 の段落は新しい義務でない)(ii) 1.2 の7(表の「検査する」を所見と読み、人の列を「—」から「所見を読む」へ改めることは、ADR-0024 決定12 の具体化であって原則の変更でない)。どちらかを採らない場合、その規定だけを束2 へ残す
- 所有者にしか決められない点: 無い。安全に当たる点: 無い

- **(ii) 1.2 の7(「前の記録との一致」を所見として出し、表の人の列を「—」から「所見を読む」へ改める)は、この束では採らない**。標準の表は「検査する」と書いており、所見へ読み替えると標準の文の意味が変わる。人の列を改めると、G-3 の判定者に所見を読む務めが足される。小さくても採用者への新しい務めで、2委員はこの形を審議していない。裁定の案が自ら、束3 の R2-01 の型(妥当に見える読み替えが審議を経ずに入る)を戒めている。**IMPL-NEW2 は `undelivered check=manual plan=scheduled issue=355 review=2027-02` で新設し、所見の出力は実装しない。表の文は直さない**。直し方の候補(失敗にする/所見にして判定者が読む/課さないと決める)は、束2 と同じ重の審議に残し、#355 へコメントで残す。note には「定義が標準に無く、全部を置き換える判断記録は正当に同じ影響を書くため、一致を失敗にする式を置けない」と書く
