## 1. 観測の値が誤る経路(0136・0159 共通。実行の結果)

`approvalMinutes(d)` は「作成日時から、APPROVED の最後の提出日時まで」の暦の分。

| 場面 | 結果(分) | 何が誤るか |
| --- | --- | --- |
| 金 17:00 作成 → 月 10:00 承認 | 3900 | 暦で 2.7 日。標準の SLA は「2営業日」。営業日なら 1 営業日未満。**偽の超過** |
| 10 分で承認 → 3 日後に再承認(rebase・追加コミット後) | 4320 | `Math.max` が古い承認を含め最後を採る。初回の応答は 10 分。**偽の遅延** |
| bot・AI 名義の承認だけ | 1 | `state` だけで数え、人かを見ない。集約の別の箇所(L2150)は `isAiLogin` で人の承認を選ぶ。時間だけ人を選ばない。**偽の「速い承認」(形だけの承認の偽の検知)** |
| 承認 → 差し戻し | 5 | 差し戻しを無視する。最終の判定の確定ではない |

- 標準の SLA の定義は「レビュー依頼から、判定の確定まで」(`gate-criteria.md` L2203)。実装の起点は PR の作成、終点は最後の承認。起点・終点・暦の3つが定義とずれる。draft で長く置いた PR は起点が早すぎて膨らむ
- 実装の注記は「上側の近似」と書く。**上側の近似は、超過の判定には偽の超過しか生まない**(速すぎる偽の合格は出ない)。観測として分布を出す用途なら許容できるが、閾値と比べた瞬間に偽の FAIL を量産する
- 規模の数え方: `measureCommitSize` はマージコミットの差分。squash でない merge や、基底の変動で変わる。文書だけの PR の識別(`DOC_ONLY_DIRS`)は決定可能だが、文書と製品コードが混ざる PR は規模の経路へ落ちる
- 既存の IMPL-0100(delivered, manual)は同じ値を超過 PR について既に開示している。新しい観測を足しても、**この誤りは新しくは生まれず、広がるだけ**。直すなら IMPL-0100 の出力も変わる

## 2. IMPL-0048(期間ごとの保証の開示の定期実行)

### 切り分け

| 部分 | 決定可能か | 現状 |
| --- | --- | --- |
| 期間の切り方・欠落の条件(記録が無い・差し戻しなら欠落) | 可(値の一致・存在) | 実装あり。**試験が無い** |
| 委任を使わない構成で成功終了(`period-needed.mjs`) | 可 | 実装あり。**試験が無い** |
| workflow の結線(cron の式・手順の順・`needed` の条件・権限) | 可(静的確認+対の試験。#333 の `workflowProblems` の型) | 結線の試験なし |
| cron が実機で動くか、権限・トークンで通るか | 不可(採用者の環境) | 注記に「2026-10-01 時点で確かめていない」 |
| 受容と異議の記録の内容の妥当性 | 不可 | 存在までしか見ない |

実測: `template/` 内で `period-from`・`period-needed` を引く試験ファイルは0(grep)。`assurance-period.yml`・`period-needed.mjs`・`aggregate-evidence.mjs`・`preflight.mjs` にしか現れない。

### 距離と害

- workflow が在ることと、規定(期間ごとに区切って出し、受容と異議の記録が無ければ欠落)が満たされることの間には、(a) 試験の空白、(b) 実機の未確認、(c) 実行されないことを検出する者が居ないこと、の3つがある。(c): 集約が失敗するのは**走ったとき**だけで、cron が走らない・Actions が無効・スケジュール実行が止められた場合は何も出ない。ADR-0109(検出であって防止でない)の型だが、「走らない」ことを検出する手が無いのは開示すべき限界
- 設計上、**初回の実行は必ず失敗する**(workflow 冒頭の注記)。月次の赤が「通常」になる。赤に慣れた採用者は本物の欠落を見落とす。これは実装の欠陥というより、表示が「成功=規定を満たす」と読めてしまう害
- `delivered check=machine` と書くと、読み手は「期間の開示が毎月出て、記録が無ければ止まる」と読む。今の根拠は手元の集約の1回の実行だけ。**R1-02 と同じ型**(結線を試験が確かめていない)。束3 の高の所見が、ほぼそのまま当たる
- 実証の水準: 実機は E0(確かめていない)。試験で閉じる範囲は、足して初めて言える

### 推す結論

- **今の状態では delivered にしない**。`undelivered`・`plan=scheduled` のまま、note を「降りた部分(期間の指定で出力・欠落の条件。手元の集約)と、確かめていない部分(試験なし・実機なし)」に分けて直す
- 束4 の実装で次の試験を足すなら、**その試験が通った後に限り**マークを分ける。(i) 論理: `delivered check=machine test=...`(集約の本体を流す対。違反=記録なしで欠落、差し戻しで欠落。適合=受容ありで通る、委任なしで needed=false)。(ii) 定期の実行(cron が実機で動くこと): `undelivered` を残すか、`delivered check=manual` で確かめる者を「採用者の出荷判定者(初回の実行の後)」にし、EV マークで「実機未確認」を開示。cron の静的確認(式・結線)は machine にできるが、**それを「定期の実行が届いた」と呼ばない**
- 採らない案: 方針2 の「試験が空のまま delivered」。実機の確認を準拠テンプレートの検査に数えない点は同意するが、その場合の `check=` は machine でなく manual、確かめる者は採用者

## 3. IMPL-0136・0159(観測の値)

### SLA の値を誰が決めるか

- 標準が既定値(応答1営業日・判定完了2営業日)を書く(L2203)。D-0 で採用者が値を変える経路があるかは**確かめていない**(要確認)。営業日で比べるには、休日の暦という**採用者の入力**が要る。これを必須の入力にすると、採用者への新しい義務(重へ上げる条件に該当、受付の裁定どおり)
- したがって合否・超過件数を出す案(research.md 0136 の候補 b)は、休日の暦なしに作ると暦の日数で偽の超過を出す(1章)。**採らない**。出すなら生の分布(中央値・最大・件数)だけで、閾値と比べない。標準の「判定完了時間の SLA で判定する」は判定を求める文で、分布の観測は判定ではない

### IMPL-0136

- 降りるのは「観測の追加」の部分だけ。規定の文は「SLA で判定すること」。**判定が降りていない**ので `undelivered` のまま(方針1)。note に「降りた部分: 文書だけの PR の識別と所要時間の分布(追加するなら)。降りていない部分: 起点を依頼時刻にそろえる・営業日・閾値の比較」を書く
- 判定の滞留は、標準が別に定めるレビュー SLA の措置(L2222: 判定完了時間の超過に 7.5 の措置)に依る。**そこは人と運用メトリクスの経路で、集約の観測が代わるものではない**。観測が在ることで「滞留は機械が見ている」と読まれる害を避けるため、観測の見出しに「判定ではない」と書く
- 偽の安心の例: 文書だけの PR の分布が「中央値 3 時間」と出て、実際は最後の承認だけを見て初回の応答は 3 日待ち。分布が良く見えて SLA 違反が隠れる(最後の承認は終点としては遅いほうに偏るので、この向きは主に再承認と、承認が先に付いて後から差分が足された場合)

### IMPL-0159

- 規定の文は「承認に要した時間と変更規模の**比**を**継続して**計測する」。(1)「比」: 分子が待ち時間なので、小さな PR は比が極端に大きく、大きな PR は小さい。比の中央値は読み速度を表さない。規模の区間ごとの時間の分布のほうが意味を持つ(`size-observation.mjs` は既に区間を持つ)。比そのものは**誤解を生む形**。(2)「継続して」: `size-observation.mjs` 冒頭は「前回の集約との比較は出さない(課さないと決めた。何を判断するかを書けないため)」と決めている。**継続=比較を課さないと決めた既存の決定と衝突する**。降ろすなら、この決定を新しい決定で置き換える必要があり、軽の範囲を超える
- 個人の評価への転用: 集約の `humanApprovers` は PR ごとに login を持つ。観測が承認者の login を出力に持たないこと(今の `size-observation.mjs` は番号と時間だけ)を**壊さない**。承認時間と規模の比は、個人別に切ると「速く承認する人」の順位表になる。`metrics.md` 原則4(個人へ絞り込む機能を実装しない)・原則5と、ADR-0094 の「個人の評価への転用の経路になる」を理由にした不採用に照らし、**承認者別の内訳は永続的に出さない**と note に書く
- 時間の入力を、人の承認(`isAiLogin` で除外)・最終の head に付いた承認の最初に直す案は、IMPL-0100 の既存出力も変える。直すなら 1 章の表の偽の値(bot の 1 分、再承認の最大)が除かれるが、それでも暦の時間である限り「形だけの承認の検知」の根拠には足りない(夜間・週末)
- 結論: 全 PR の時間の分布を足すことはできるが、**規定の「比」「継続」は降りない**。`undelivered` のまま

## 4. IMPL-0230(生成物の劣化の4指標)

- 規定の文は2つ: (A) 4指標を継続して計測する、(B) **個人の指標と保守性の指標を必ず対で確認する**。(B)の「個人の指標」は標準のどこにも定義が無い(grep: `roles-responsibilities.md` 3.11.7 にしか現れない)。定義の無い語を機械は読めない。決定不能
- (B) と既存の原則の矛盾: `metrics.md` は「個人の評価に使わない」「個人へ絞り込む機能を実装しない」「チーム間の順位を出さない」を定める。(B)は、個人の生産性指標を**集めて見る**ことを前提にする。ただし(B)は、保守性の値と対にして見るだけで評価に使うわけではない、と読めば両立する。**この両立を明記した条項はない**。「個人の指標を集める」こと自体が、`metrics.md` 原則4と衝突する余地がある。これは条項の文と ADR の原則の関係で、**重へ上げる点**
- 同じく `metrics.md` の第1原則「自動集計できる指標だけを正式指標にする(手集計は続かない)」と、0230・0159 の「手で集める」は、字面で衝突する。0230 の4指標が「正式指標」でなければ逃げ道はあるが、その区別も書かれていない
- adopter に改めると何を求めたことになるか:
  - 採用者に「4指標の算出法の定義(標準は例を運用メトリクスに置くだけ)・閾値・窓・標本数を決め、計測し、傾向を見る」ことを求める。標準は今もこれを AI維持管理者の職務として求めているので、**新しい義務ではない**。ただし「算出する手段を自分で用意せよ」は、template が降ろすのをやめる代わりに採用者に課すものとして明記が要る(`implementation-marking.md`: adopter は「規定は課したまま」)
  - 統制が消える型か: adopter にすると、採用者が実装しなければ**何も起きず、何も検出されない**。0230 は閾値も遮断も無い傾向の確認なので、消えて困る合否は無い。ただし「消えても誰も気付かない」点は、`impl-no-adopter.yaml` が adopter 不可とする「統制の弱化の検出」とは別。傾向の観測は統制ではない、と ADR に**根拠つきで**書けるかが分かれ目。書けなければ adopter にしない(ADR-0084 決定4: 理由を書けない規定は scheduled)
  - (B)は adopter に委ねても決定不能のまま。採用者は「個人の指標」を自分で定義することになり、**個人の指標の収集を標準が採用者へ促す形**になる。この点が最も危うい
- 降ろす場合の対の扱い: 降ろす(template が個人の指標を集める)案は**採らない**。`metrics.md` 原則4と衝突し、ADR-0094 の不採用の理由と同じ。降ろすなら重

### 推す結論

- (A)と(B)の2つに分けることはできる。(A)は決定可能な定義にできれば機械で算出できるが、**閾値・窓は採用者が決める**(IMPL-0268)ので「算出して表示する」までで、判定ではない。(B)は定義が無く、機械でも adopter でも降りない
- **束4 では 0230 を adopter にしない**。理由: adopter にすると、(B)の「個人の指標」の定義と `metrics.md` との関係を決めないまま、採用者へ個人の指標の収集を促す形になる。`undelivered`・`plan=scheduled`・`review=2027-02` を保ち、note に「(B)は定義がなく決定不能。`metrics.md` 原則4との関係が未決」と書き、**(B)の扱いを重の審議へ送る**
- 採らない案: adopter+ADR(統制が消えるだけの型。かつ個人の指標の扱いが未決のまま採用者へ移る)。リポジトリ単位の 2 指標の参考値を出す案(research.md 0230 の b)は、規定を降ろしたことにならないので表示を変えない。出すのは別の判断(束の外)

## 5. 重へ上げるべき点

1. **0230(B)**: 「個人の指標」の定義と、`metrics.md` 原則4・ADR-0094 の不採用の理由との関係。ADR の原則の変更または新しい条項に当たる。受付の裁定の条件(個人の指標との対の扱いが残ったら重)に**該当する**。束4 は 0230 をここで止める
2. **0159「継続して」**: `size-observation.mjs` の「前回との比較は出さない(課さないと決めた)」を覆すかは、既存の決定の変更。覆す案が残ったら重(覆さないなら undelivered のまま)
3. **0136 の営業日・閾値**: 休日の暦と SLA の値を採用者の入力にする案が残ったら重(受付の裁定のとおり)。この意見書は、その案を採らない

重にしない点: 0048 の試験の追加とマークの分割、0136・0159 の観測の追加と note の直し(いずれも新しい義務を課さない)
