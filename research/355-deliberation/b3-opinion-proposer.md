## 1. IMPL-0241(版の変更と判定記録の整合)

**規定の文**: `gate-criteria.md` L341 の表の2行目(「確定した版から受入基準・前提・スコープ外が変わった機能仕様に、変更後の版を対象とする G-4 の判定記録があること」。出荷の集約は「合否にする」)。マークは同 L334。G-3 の2点(判断記録の書き換え、G-3 記録の無い置き換え)は ADR-0078 L133 と、マークの note にだけ在る。

**実態**: 集約に検出は無い。`spec-sections.mjs`(`specSections`・`changedSpecSections`、80 行)は #334 で置かれ、PR の時点の表示(IMPL-0520、delivered)だけが使う。集約側に使える部品は在る: `gateJudgementsOfCopy`(L548。対象の版 commit_id と headMatch を持つ)、`targetOfForm`(records.mjs L308。セルを返すだけ)、写しの `merge_commit_sha`。

**起案: マークを2つに分ける**(方針1: 規定の文が分かれるときだけ分ける)。
- 表の2行目(受入基準・前提・スコープ外と G-4)は、機械の式で閉じる。マークは `check=machine state=delivered test=template/scripts/gate/test-aggregate-spec-recheck.mjs`(新規)。note は「機械が確かめるのは3節の文字列が判定記録の版と出荷の範囲の先端で一致すること。変更が意味を変えるか、判定の内容が妥当かは確かめない」。
- G-3 の2点は新しいマーク(番号は議長が付ける)へ移し、`state=undelivered check=manual plan=scheduled issue=355 review=2027-02`。理由: (i) 書き換えの検出は判断記録のファイル全体の一致で見るしかなく、状態欄の正当な更新(「置き換え済み」)が偽の陽性になる。偽の陽性を避ける定義は未試作。(ii) 置き換え側の G-3 記録の有無は、式の部品が揃えば機械で見られるが、`check-decisions.mjs` の置き換えの参照との結合が要り、この束の範囲を越える。実証を欠く判断(EV で開示)。
- 標準の文の直し: 表の2行目の「(準拠テンプレートには降りていない。IMPL-0241)」を削る。ADR-0078 L43・L133 の「機械の検出は無く」は、G-3 の2点について残し、3節の変更については直す(「受入基準・前提・スコープ外は集約が検出する」)。`assurance-case.md` L938 の「機械は検出しない」を改める(#334 申し送り8)。

**式**(#334 6章1): 機能ごとに「最新の G-4 の判定記録(通過)が指す版の3節 = 出荷の範囲の先端の3節」。範囲の先端に当該 `specs/F-NNN/spec.md` が無い機能は対象外。不一致は欠落(gaps)に数え、文には機能、節の名、判定記録の所在を出す。

**実装で決める3点への答え**:
- (a) 版の解決: 対象が `F-012 / PR #34` の形のときは、写し pr-34.json の `merge_commit_sha` を使う(gh を呼ばない。headMatch が成立している判定だけを対象にするので、マージ時の木は判定の版と同じ内容になる。前提は L575 の既存の検査)。コミット形式(commit_id)は `git show <commit>:specs/F-NNN/spec.md` を使う。解決できない場合(写しが無い、オブジェクトが取れない)は欠落にせず「未確認」の行を出し、出荷判定者の確認を manual として開示する。squash でオブジェクトが浅い取得に無い場合があるかは未実証。実装の試作で確かめる。
- (b) 正規化: 表示と同じ規則(行末の空白・先頭と末尾の空行だけを除く)を使い、それ以上に緩めない。合否では、偽の陽性(表の整形だけで受け直しを要求する)は無駄な G-4 を1回生むだけだが、偽の陰性(意味の変更を見逃す)は統制の穴になる。信頼性の軸で、厳しい側を採る。偽の陽性は欠落の文に差分を出して開示する。
- (c) 複数の記録: 判定日時の最新を採る。判定日時が空の記録が混じるときは、選べないので「未確認」とし、欠落にはしない代わりに、その機能は出荷判定者が確かめる。最新が差し戻しで、それより前の通過が在る場合は、通過の版でなく「最新の判定が通過でない」を所見にする(`test-next-records.mjs` の「最新の判定」の先例に揃える。先例は同じ人の差し戻し→通過を最後の1件にする)。

**空欄の候補(fix-round2)への答え**: 判定者・判定日時・D-0 の版の空欄を一般に欠落にする案は、この束では採らない。理由: (i) D-0 の版の空欄は既に `recordsWithoutD0`(L2978)が拾っている。(ii) 判定者の識別は judgeOk(席の責任者との突合)で別に見ている。(iii) 判定日時の空欄は、本式の選択に必要な場合だけ「未確認」にする。空欄の一般の欠落化は、既存の記録の様式に新しい必須を課すことになり、採用者への新しい義務に近い。別の Issue の対象にする。標準 L346 の「集約が欠落にしないため出荷判定者が確かめる」は、判定者・D-0 の版の空欄については維持する。

**合否にする時点**: 出荷判定(G-7)の集約の時点だけ。PR の時点は合否にしない(#334 の裁定どおり。変えない)。

**試験の案**(`test-aggregate-spec-recheck.mjs`。`g5MissingText`・`coverageScopeText` の流儀で、git と gh を呼ばない純関数+対):
1. 3節が一致 → 欠落なし。受入基準の変更 → 欠落。前提・スコープ外も同様。表の整形だけの変更 → 欠落(厳しい側を試験で固定)。
2. G-4 の記録が無い機能(G-2 のみ通過) → 欠落ではなく「G-4 の記録なし」の別の行(#334 申し送り4。後述の採らない案に関わる)。
3. 記録が複数 → 判定日時の最新。判定日時が空 → 未確認。版が解決できない → 未確認で欠落にしない。
4. 範囲の先端に spec.md が無い → 対象外。
5. 表示(IMPL-0520)と集約が同じ `specSections` を使うことの静的確認(定義の二重化を防ぐ)。
変える template のファイル: `scripts/gate/aggregate-evidence.mjs`(新関数の追加と gaps への接続)、`spec-sections.mjs`(変更が要れば正規化関数を export)、試験の新規ファイル、`package.json` か `scripts/gate/` の試験の結線(check-impl が `templateTestWired` で確かめる)。

**根拠水準**: 「3節の一致で決定可能」は #334 でも未試作。EV を1件、`見直し 2027-02` で足す。差し替え条件: 実際の判定記録つきの履歴で、偽の陽性・偽の陰性の率を数えたとき。EV-0260 の差し替え条件(表示が出た PR のうち G-4 記録が在った割合)は、本実装で数えられるようになる。note を直す。

## 2. IMPL-0023(宣言と実態のずれ)

**規定の文**: `roles-responsibilities.md` L2203「検出したずれは、3.13.3 の起票として扱います」(3.13.5)。マーク L2228。

**実態**: 検出は在る。人数と担い手の識別は `aggregate-evidence.mjs` L4596〜4610 の drift に入り、レポート L6113 が「体制の変化点として起票してください」と出し、L6383 が警告(warn)にする。D-0 の版の不一致は L3008 が記載の欠落に数える。drift の試験は無い(上記)。欠けているのは「つなぐ」の定義と、drift の試験。

**起案((a) 案の範囲)**:
- 規定の読み方を決める: 「起票として扱う」は、検出したずれを人が変化点(/process-change)として起こす義務であり、機械が Issue や構成を書き換えることではない。機械が起票すると、構成を書き換える唯一の経路を /process-change とする規定(3.13.4 要求事項1)と、決定者の記名の規定に反する。この読みを標準へ明記する(「機械が起票することはしない。出荷の集約が、起票を促す文を出す」)。
- マークを2つに分ける(規定の文が分かれる): (i) 検出(D-0 の版=欠落、人数・識別=警告)は `state=delivered check=machine test=template/scripts/gate/test-aggregate-drift.mjs`(新規)。note で、人数と識別は警告に留まり合否にしないこと、機械が確かめるのは検出と文の出力までとする。(ii) 起票されたか、は `undelivered` のまま採らない、ではなく下の(iii)。
- (iii) 「つなぐ」: レポートの文を、起票の案内に具体化する。ずれを出す行に、/process-change の種別と補助ファイルの所在を併記する(識別の行は既に performer.md を案内している。人数の行に、種別 team-size 相当を案内する。種別名は実物で確かめて使う)。機械が確かめるのは、案内の文が出ることまで。起票されたか、起票が適切かは確かめず、manual(出荷判定者。確かめる者: 出荷判定者、出荷判定の時点)。この manual の部分は新マーク(議長が番号を付ける)として `undelivered plan=scheduled review=2027-02` で残さず、`check=manual state=delivered` とするのが妥当と考える: 規定の降ろし先は「出荷判定者の突合」と「案内の文」であり、降ろし先が在る。ただし方針1 に従い、機械が存在までしか確かめないものを delivered と呼ばない: (iii) は check=manual と note で、機械が確かめないことを明記する。この形が方針1 に適うかは議長の裁定を求める。
- 試験の案: 人数の超過→drift に1行、宣言内→無し。共著者が宣言に無い→drift、宣言の版の部分一致→無し。drift が在っても gaps に数えない(警告に留まる)ことの対。外部向けの出力で内容を伏せる(L6116)。

**(c) 案(2回連続の警告を欠落に数える)は採るべきでない**。理由は2つ。(1) 新しい合否の条件を採用者に課すので重に当たる。(2) 偽の陽性が多い。共著者の記録には人が含まれ(note に「人の共著者を含む場合がある」)、drift は警告として設計されている。連続の判定は前回の出荷の記録(loadPrevious、L3357)の読み込みに依存し、範囲の取り方で変わる。実証は無い。重へ上げる点は無い((a) 案の範囲に収める)。

## 3. IMPL-0498(層ごとの G-6 の承認の数え方)

**規定の文**: `gate-criteria.md` L2139〜2142。manual の IMPL-0250 が /gate の注記で降り、集約の側の IMPL-0498 が undelivered。

**採否の案**: 数え方を変える案(中間の層を取り込んだと検出した PR の承認を G-6 に数えない)は**採らない**(重へ上げない)。
- 理由1: 偽の陰性。署名の無い squash・リベースで取り込みの形が消える(research.md の決定可能性)。IMPL-0491 の note が既に「マージのコミットの親の到達で検出する案は、手動のスタックの正当な同期と区別できないため採らない(ADR-0126 決定2)」と裁定済みで、同じ検出を数え方の合否に使うのは、その裁定と衝突する。
- 理由2: 偽の陽性で承認を数えなければ、正当な同期をした PR が欠落になる。
- 理由3: 集約は検出(IMPL-0248)を既に開示している。数え方を変えるより、開示した検出を出荷判定者が G-6 の承認の突合に使う運用で足りる。この判断は実証を欠く(単一の実装での分析)。EV で開示する。
- 残す: マークは `undelivered check=manual plan=scheduled` のまま、`review=2027-05` を維持する。note に「採らない案と理由」を1文足す(数え方を機械に任せない旨、IMPL-0248 の検出を出荷判定者が使う旨)。「書かれていない」と「課さないと決めた」を区別するため、標準 L2139 付近に「機械が承認を数えから外すことは課さない」と明記する案を、議長に諮る。標準の義務の変更ではなく開示であり、編集の指摘に近い。

## 5. 採らない案とその理由

- IMPL-0241: G-3 の書き換えを判断記録ファイルの全文一致で機械にする案(状態欄の正当な更新で偽の陽性)。版の解決を gh に頼る案(CI に権限と網の呼び出しを足し、写しで足りる)。表の整形を除く正規化(偽の陰性)。G-4 の記録が無い機能を欠落にする案: G-2 のみの通過は、仕様の確定から実装中の状態でありうる。出荷の範囲に spec.md の変更が入っている機能に限り、別の行(「G-4 の記録なし」)で出し、欠落にはしない(既存の「記録が無い=未判定」の先例による。第4章の G-4 の義務そのものは変えない)。空欄の一般の欠落化(新しい必須)。
- IMPL-0023: Issue の自動起票(権限の拡大、構成の書き換えの経路の規定に反する)。2回連続の警告の欠落化((c) 案)。
- IMPL-0498: 承認の数え方を機械で変える案。adopter への降格(スタックを使わない採用者には不要だが、ADR-0084 決定4 の登録簿に当たるかを確かめていない。採るなら ADR に理由の記録が要る)。
- 共通: 存在までの検査を delivered と呼ぶ案(方針1 に反する)。
