## 1. 所見

### R1-01【高】強制層・構成だけの変更が「文書だけの変更」として数えられ、比からも消える

- 所在: template `scripts/gate/aggregate-evidence.mjs` L2171(`docOnly: prFiles.every(isExcludedFromSize)`)、`size-observation.mjs` L42〜47・見出し、標準 `gate-criteria.md` の IMPL-0136 の note「降りた部分: 文書だけの変更の識別」
- 事実(実行): `isExcludedFromSize` は文書のほか「強制層・構成のファイル」も真にする(`check-pr.mjs` L343 の注記のとおり)。直に呼ぶと `.github/workflows/zz.yml`・`scripts/gate/zz-extra.mjs`・`process.config.json`・`.claude/settings.json` が真、`package-lock.json`・`yarn.lock` は偽。探針で、ワークフローだけの PR と、`scripts/gate/` の 300 行の `.mjs` だけの PR(人の承認が作成の 3 分後)を流すと、どちらも `docOnly: true` になり、品質レポートに「算定から除いた**文書だけの変更** 3 件。… 24 時間以内 2」と出た。比の表・`points`・`noDenominator` のどこにも出ない
- 何が食い違うか: 見出しと note は「文書だけ」と表示するが、実態は「算定から除く全ファイル」。統制の設定を 3 分で承認した変更が、文書の観測に紛れる。規定の文(第4章「文書の置き場…にある散文のファイル」)とも合わない。コードの注記「生成物・ロックファイルだけは当たらない」は正しいが、強制層が当たることを書いていない。裁定 4.1-2 が既存の関数を文書の判定と読んだことに由来する
- 直し方の案: `check-pr.mjs` に散文の文書だけを真にする関数(文書の置き場の文書・データの拡張子と、直下の `*.md`。強制層・構成は偽)を置き、`docOnly` はそれで判定する。強制層・構成だけの変更は `noDenominator` へ入れ、表示を「算定行数が 0(強制層・構成・ロックファイルだけの変更を含む)」にする。通しの試験に、ワークフローだけの PR が `docOnly` に入らない場面を足す

### R1-02【中】gh で読めない PR は観測の母数から消え、節は「取れなかった 0 件」と出す

- 所在: `size-observation.mjs` L196〜199(比を持たないものの行)、`aggregate-evidence.mjs` の PR の対応づけ(今回の差分より前の挙動)
- 事実(実行): 偽の gh が全て失敗する場面では `total: 0`、表は全区間 0 件、「人の承認または規模を取れなかった 0 件」。9 件のマージ済みの PR が在る。偽の gh が 1 件だけ壊れた JSON を返す場面では、その PR が `prs` から消え(`total` 8)、`unmeasured` に数えられず、欠落の一覧に「#7」を含む文も無かった
- 直し方の案: 観測の節に、範囲のマージコミットのうち PR の記録を読めず観測に入らなかった件数を出す(既存の `unreadable` の流儀)。0 件の表だけを出さない。出せないなら IMPL-0159 の note と EV-0271 の対象に「gh で読めた PR だけが母数」と書く
- 確かめていない: 読めない PR が欠落の一覧に別の文(コミットの識別子)で出るか

### R1-03【中】IMPL-0048 の試験は「結果が未記入・判定の値でない」記録を固定していない

- 所在: template `test-assurance-period.mjs` L139〜163、`aggregate-evidence.mjs` L3334〜3336
- 事実(実行): 破壊 B(`else if (result !== '通過')` を無効にする)で 32 件すべて通過。結果の欄が空の記録で期間の開示が受容された扱いになっても、試験は落ちない。マークの note は「結果が通過の G-8 の記録が無い状態を記載の欠落にする」と書く
- 直し方の案: `// IMPL-0048:ng` に、結果が空欄の記録と「保留」の記録の場面を足す

### R1-04【中】文書と製品のコードが混ざった PR を、どの試験も流していない

### R1-05【中】「最後の人の承認」の「最後」を固定していない。AI の名義の判定は偽の gh の形に依る

- 所在: `test-approval-pace.mjs` L39〜44・L92、`aggregate-evidence.mjs` L2089、`config.mjs` L3094
- 事実(実行): 破壊 C(`Math.max` → `Math.min`)で全て通過。人の承認が2件ある PR が試験に無い
- 事実(読み): AI の名義は `aiAccountCheck`(`is_bot`、login の語、名簿の確認)で決まる。偽の gh は `author.is_bot: true` と `[bot]` 付きの login を返す。実機の `gh pr view --json reviews` がこの2つを返すかは、実装の担当も確かめていない。探針では `dave-ai`・`robotnik`(bot の印なし)は人に数えられ、2 分の承認が最小値 3.3 に出た。印も語も無い AI のアカウントは人に数わる(G-6 と同じ判定。新しい穴ではないが、note「AI 名義の承認は数えない」の支えになる)
- 直し方の案: 人の承認が2件(120 分・600 分)の PR を足す。EV-0271 の対象へ「AI の名義の判定が、実機の gh の応答(`is_bot`・login の形)で働くという前提」を足す

### R1-06【中】workflow の結線の試験は `|| true` の字面だけを見る

- 事実(実行): 破壊 D(集約の `run:` の末尾へ `|| echo failed`)で 32 件すべて通過。本体の `stepDefect`(`impl-inventory.mjs` L531)も `|| true`・`|| :` だけを見るので、既存の流儀と同じ穴
- 直し方の案: 集約と period-needed の `run:` の行が `node scripts/gate/….mjs --period-from "$PERIOD_FROM" --period-to "$PERIOD_TO"` と**完全一致**することを確かめる(`||`・`;`・`&&` を含まない)

### R1-07【中】IMPL-0230 の adopter と IMPL-0268(#441・scheduled)の境が書かれていない

- 所在: ADR-0137 決定4・「課さないと決めたこと」、`gate-criteria.md` L2407・L2438
- 事実(読み): 第4章 L2407 は「AI 生成行の短期書き換え率」を「短期間で書き換えられた行の比率を AI が生成した範囲に限定したもの」と定める(別の量だが同じ履歴の解析)。IMPL-0268 は、その期間の集計を #441 で降ろす計画のまま。ADR-0137 は「準拠テンプレートは算出を実装しない」「リポジトリ単位の2指標の参考値を算出しない」と決めたが、IMPL-0268 に触れない。裁定 3章は未突合として独立の突合へ渡していた
- 判定: いまは矛盾しない(量が違い、0268 の note も「採用者が集計の手段に窓と最小標本数を備える」と書く)。#441 が準拠テンプレートに行の帰属の集計を入れると、ADR-0137 の「課さない」と衝突する
- 直し方の案: ADR-0137 の表へ IMPL-0268 の行を足す(「3.11.7 の4指標は採用者。第4章の AI 生成行の短期書き換え率の窓は #441 で別に決める。#441 が準拠テンプレートに算出を入れるなら本 ADR を置き換える」)。#441 へコメントで残す

### R1-08【低】適合の場面は件数の差で確かめ、終了コードの検査は空回りしている

- 事実(実行): 0章のとおり、いまは対が期間の欠落だけで分かれる。ただし試験は件数(`n0 - 1`)しか見ない。足し引きが同数なら通る。「終了コードは 0 でない」(L142)は、足場に無関係の欠落が 5 件あるため常に真で、期間の欠落が終了コードを変えることは固定していない(欠落 → 終了 1 の結線は L6491 の読みで確かめた)
- 直し方の案: 適合側の欠落の集合が「違反側の集合 − 期間の欠落の1文」と一致することを確かめる。L142 の検査は名前を「足場の欠落を含む」と改めるか外す
- 記録の食い違い: `b4-implementation-template.md` は「欠落が 18 件残る」と書くが、evidence.json の欠落は 5 件(違反側 6 件)だった

### R1-09【低】既存の表示が「最後の承認」のまま

- 所在: `size-observation.mjs` L186。「超過 PR の判定完了時間(作成から最後の承認まで。上側の近似)」「取れなかった(PR の作成日時または承認の日時が記録に無い)」
- 事実(読みと実行): 値は人の承認だけになった。AI の名義だけの承認でも「日時が記録に無い」と出る。IMPL-0100 の note は直っている
- 直し方の案: 「最後の人の承認」「人の承認が無い場合を含む」に改める

### R1-10【低】「人の承認」は G-6 に数えた承認者に限られる

- 事実(読み): `humanApprovers` は、先頭の版に結び付き、書き込みの権限があり、写しと突合できた承認者(L2124〜2160)。古い版への承認だけの PR、写しを数えなかった PR は、人が承認していても `unmeasured` になる。見逃す向きで、偽の値は出さない。探針で、古い版への承認(4 分)は数えられず、先頭への承認(700 分)が出た
- 直し方の案: 表示の「人の承認または規模を取れなかった」に「先頭の版への承認に限る」を足す

### R1-11【低】IMPL-0136:ng の正規表現が狭い / 通しの試験名が中身より広い

- `(を超過|超過した|超過 [0-9])` は「超過: 2 件」「超過は 2 件」を通す。「超過」の語は見出しの定型句を除いて 0 回、と数える形にする
- 「login を観測・品質レポート・外へ渡す開示に出さない」は、品質レポートを見ていない(G-6 の表に login が正当に在るため)。観測の2節を切り出して確かめるか、名前から外す

### R1-12【低】IMPL-0159 の note「PR ごとの組で保証の開示の観測に出す」

- 事実(実行): `points` は evidence.json の `assurance.sizeObservation` にだけ在り、品質レポートと外へ渡す開示には表だけが出る。期間の開示(`--period-from`)には、この節が出ない。note の「出荷のたびに」とは合う
- 直し方の案: note を「区間ごとの分布を保証の開示に、PR ごとの組を evidence.json に出す」に改める

### R1-13【低】ADR-0137 のコンテキスト「集約は承認に要した時間を出していなかった」

- 事実(読み): 超過 PR の判定完了時間(IMPL-0100)は既に出ていた。出していなかったのは規模との比。「規模との比を出していなかった」に改める

### R1-14【低】test-approval-pace.mjs は Windows で終了コード 0 の SKIP

- 事実(読み): CI は ubuntu-latest で動くので空洞ではない。IMPL-0159・0136 は `manual` で `test=` を持たず、`check-impl` はこの試験の結線を合否に使わない。Windows の自前の実行環境を使う採用者では、通しが黙って抜ける
- 直し方の案: SKIP の行を残し、純関数の試験(`test-size-observation.mjs`)が Windows でも login の不在を確かめていることを冒頭の注記に書く
