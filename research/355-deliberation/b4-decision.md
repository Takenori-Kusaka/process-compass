## 1. 裁定

### 1.1 IMPL-0048: マークは分けない。試験を足して `delivered check=machine`、実機は根拠水準マークで開示する

- 2委員は「試験が無い間は delivered と呼べない」で一致し、実行もそれを裏づけた(期間の経路を流す試験は 0 本)。**試験が通ることを、マークを変える条件にする**。足せなければ `undelivered` のまま note だけ直す(起案の退路 `delivered check=manual` は採らない。試験の無い表示の変更は R1-02 と同じ型)
- **マークを分けない理由**(方針1): 5.5.4 の段落は「区切って出す」「記録が無ければ欠落」を定め、定期の起動の仕組みを別の文で課していない。cron が実機で動くかは規定の文ではなく、実装の根拠の水準である(方針2、#333 の先例)。`undelivered` を1つ足すと「準拠テンプレートに未実装の部分が在る」と読めるが、足す実装は無い
- **反対委員の (c)(走らないことを検出する者が居ない)は採り、開示する**。機械は、期間が過ぎたのに開示が出ていないことを検出しない。確かめるのは、期間の開示を突合して記名する出荷判定者の席(5.5.4 の表「委任しない席」。既存の規定)である。note と本文に書く
- 「初回の実行は必ず失敗する」こと、期間と無関係の欠落でも赤になること(0章)は、赤への慣れを生みうる。EV-NEW1 の対象に含める

### 1.2 IMPL-0159: 降ろす(`delivered check=manual`)。式は標準が既に定めている

- 規定の文は「**計測する**」で、判定を求めていない。算出の方法は `metrics.md` L202 が既に定める(「PR の Ready 化 → 承認の時間差と差分行数の散布」。警戒サインは「規模に対して極端に短い承認の続発」)。反対委員の「分子が待ち時間で読み速度を表さない」は、実装でなく**標準の定義への異議**であり、この束では扱わない。ただし次の点は採る
  - **比は規模の区間ごとに出す**(小さい変更の比が発散するため)。区間は既存の `LINE_LABELS`。値は 100 行あたりの分の最小・下位四分位・中央値と件数。閾値と比べない。前回との比較は出さない
  - **承認者別の内訳を出さない**。evidence.json の PR ごとの組(番号・算定行数・分)にも login を持たせない。試験で固定する(`metrics.md` 原則4)
  - **人の承認だけを数える**。AI 名義の承認は判定でない
- **「継続して」と `size-observation.mjs` の「前回との比較は出さない」は衝突しない**と裁定する。計測の継続は、出荷の集約のたびに値が出ることで満たす。比較と傾向の読みは機械が行わず、品質保証の機能が読む(旧 note が既に名指す者。新しい義務でない)
- **時計時間の近似は一方向にだけ効く**: 作成から最後の人の承認までは、承認者が掛けた時間の上限である。短い値は「短かった」と確定でき、長い値は何も言えない。警戒サインが短い側なので、近似は見逃す向きにだけ誤る。起点が標準(Ready 化)と違う点(draft の期間を含む)とともに EV-NEW3 で開示する
- **既存の `reviewMinutes` も人の承認だけに直す**(反対委員が実行で示した「AI 名義の承認だけで 1 分」は、delivered の IMPL-0100 の出力の誤り)。起案の「変えない」は採らない
- 文書だけの変更は算定行数が 0 で、比を持たない(ADR-0072 決定3。課さないと決めた量)。件数だけ出す
- `check` は `manual`(IMPL-0100 の先例。機械は値を出すが、兆候の有無を確かめない)

### 1.3 IMPL-0136: 降ろさない。観測は足すが `undelivered` のまま、判定は重の審議へ残す

- 規定の文は「SLA で**判定する**」。SLA の措置(催促・通知・代理判定者の指名。L2219〜2222)は PR が開いている間に働くもので、出荷の時点の分布は判定でも措置でもない。**観測だけでは delivered と呼べない**(反対の読みを採る)
- 起案の `delivered check=manual`(出荷判定者が 48 時間超を営業日で数え 7.5 へ回す)は採らない。取り込み済みの変更に代理判定者は指名できず、効かない確かめを出荷判定者へ足すだけになる
- **足りないもの**: (a) 依頼の時刻を起点にした経過の算出 (b) 営業日の暦(採用者の入力) (c) 開いている PR への定期の判定と催促・通知。(b) は採用者への新しい義務で、(c) は SLA の節そのもの(未棚卸し)の降ろし方である。**この束では降ろさず、重の審議(束2 と同じ扱い)へ残す**。`plan=scheduled issue=355 review=2027-02`
- 観測(文書だけの変更の、作成から最後の人の承認までの時計時間の分布)は足す。見出しに「観測。SLA の判定ではない」と書く。機械に許す読みは「48 時間以内なら 2 営業日以内」の一方向だけで、「超過」の語と件数は出さない
- 規定の文は直さない。参照だけ足す(編集の指摘。4.2)。「判定する」の主語と、文書だけに固有の判定を置くのかは、重の審議で決める

### 1.4 IMPL-0230: 規定の文で2つに分ける。計測は adopter、「個人の指標との対」は降ろさず重へ

3.11.7 は「継続して計測します」(A)と「個人の指標と保守性の指標は必ず対で確認します」(B)の2文に分かれる(方針1 の条件を満たす)。

- **(A) IMPL-0230 → `plan=adopter`**(ADR-0137)。4指標の定義・窓・標本数は組織が G-1 で定める(第4章「閾値の設定と較正」要求事項1)。値は傾向の確認にだけ使い、合否にも 5.4.6 にも使わない(3.11.7 の本文)。`impl-no-adopter.yaml` の6節に当たらない。同じ型の先例は IMPL-0394(期をまたぐ推移を採用者が比べる。ADR-0102)
- **(B) IMPL-NEW1 → `undelivered plan=scheduled issue=355 review=2027-02`**。反対の読みを採る。「個人の指標」は直前の文から「個人の生産性指標」を指すが、定義も収集の条項も無く、`metrics.md` の原則(個人の評価に使わない・個人へ絞り込む機能を実装しない)との関係が書かれていない。adopter にすると、未決のまま採用者へ個人の単位の指標の収集を促す形になる
- **起案の ADR の文案(「個人を絞り込まずチームの単位の指標と対で確認し」)は採らない**。adopter の決定の中で (B) の意味を書き換えている。妥当に見える読み替えが、条項の審議を経ずに入る経路になる(R2-01 と同じ型)
- **(B) の文は、この束では直さない**。直し方は3つ在る((i)「個人の」を外しチームの単位の生産性の指標との対にする (ii)「個人の指標」を定義し条件を置く (iii) 対の確認を課さないと決め not-imposed へ移す)。どれも意味を変え、(ii) は原則に触れる。2委員はどれも審議していない。編集の指摘ではない
- それまでの害を抑えるため、事実だけを EV-NEW4 で開示する(4.2)

## 4. 実装の指示

準拠テンプレートを触るので直列。template のコミットは bundle へ退避する。

### 4.1 template

1. 新規 `scripts/gate/test-assurance-period.mjs`(`gate-g5.yml` の `run:` へ足す。`|| true`・`if:`・`continue-on-error` を付けない)。足場は `test-direct-commit-rules.mjs` の `workspace`。コミットの日付は `GIT_COMMITTER_DATE` で固定し、`TZ=UTC` で流す(深夜の実行で期間の境がずれないように)
   - `// IMPL-0048:ng`: 委任の席の構成・期間中にコミット・G-8 の記録なし → 出力に「期間の開示(起点〜終点)に対応する受容と異議の記録がありません」、evidence.json の欠落に同じ文、終了コード非 0。続けて、差し戻しの記録 → 「受容されていません」。別の期間を対象にした通過の記録 → 「記録がありません」。起点と終点を「と」で並べた対象 → 対応づけない
