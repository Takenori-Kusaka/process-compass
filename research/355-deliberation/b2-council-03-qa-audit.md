## 0. 監査の観点(全規定に共通)

監査人が次の3点を答えられない規定は、降ろしたと言えない。

1. **何を見れば満たしたと言えるか**(証跡の所在)。所在が採用者ごとに違うなら、様式でなく「所在を採用者が宣言する欄」を要る。
2. **機械が見たのは何で、人が見るのは何か**(境界の表示)。機械が「存在」しか見ないのに判定表が「欠落 0 件」と読めるなら、読み手は強く取る(ADR-0084 L177)。**表示と実態の食い違いが、本束の最大の監査上の欠陥**である。基準 3・6・7・8 は、いま全部これに当たる。
3. **未達を数えられるか**。見えない記録漏れは、数えるのでなく「機械は見ていない」と開示する。

総論の立場: 機械の検査は「存在・非空・構文・日付」の決定可能な条件に限る。中身の妥当性は人で、その人の確認が**記名の記録として残る**ことを監査の対象にする。人の確認は残る証跡が無いと、監査では「やっていない」と区別できない。

## 1. 規定ごとの意見

### 1.1 IMPL-0045(基準7。争点 A1〜A4)

- **A2 判定: 採る**。`manual` を維持し、`adopter` にしない。機械の範囲は「構成が安全関連 ⇒ F.7 の6項目の見出しの存在と非空(「該当なし」は理由つき)」まで。内容の妥当性は閉じない。
  - 理由(監査): `adopter` にすると、基準7 の確認が採用者の実装の有無で消える。外部の調査 Q2 のとおり、規格は集約が確かめることを求めないが、**標準が基準に「欠落がない」と書く以上、確かめない実装は表示との食い違い**になる。安全は損失が重く(事故時に検証記録を示せない)、`impl-no-adopter` の理由に実質が当たる。
  - 落とす案: `adopter`(統制が採用者の実装の有無で消える。F の適用が採用者の規格に依ることは、**内容**の判定を機械が持たない理由であって、存在の検査を持たない理由にならない)。
- **A4 判定: 人**。「安全関連か」は F.2 の人の判断。機械は `q-criticality` の値から**候補を出す**だけにし、「対象なし」で通す場合は、構成の値と判定者の記名を判定記録に残す。監査人が見るのは「対象なし」の根拠の記名。CL の値と F の適用の1対1は確認できていない(ADR-0039)ので、機械が「CL=0 ⇒ F 非適用」と決めると F.2 の判断を奪う。
  - 落とす案: 機械が決める(CL は案件ごと、F.2 は人。確認できていない対応を決定可能な条件と呼べない)。
- **A1 判定: 束ねる(条件つき)**。0045 の機械の検査は F.7 の記録の置き場が定まらないと検査対象を持てない。IMPL-0933(#448)と別々に決めると、置き場の定義が二重になる。ただし #448 は review=2027-05 で待てないので、**本束は「置き場の宣言」までを決める**: 判定記録(テンプレ4)の添付という既存の条文の語を使い、6項目の見出しの存在・非空を検査する。様式の細部(欄の順序、書式)は #448 に残す。こうすれば 0933 が後で細部を決めても本束の検査は壊れない。議長が #448 の IMPL-0933 のマークに「0045 の検査が参照する」と追記して結ぶ。
  - 落とす案: 完全に分ける(同じ欠けを二重に追い、置き場の語が食い違う)。完全に #448 へ寄せる(束2 の 0045 が 2027-05 まで undelivered のまま、安全の統制が一番遅れる)。
- **A3 判定: 既に決着。新しい条項を足さない**。基準7 の例外承認は ADR-0153 / 7.3(L69)で「承認者の独立と件数の別記を課さない」と決めてあり、**課さないと決めたことが書いてある**。内部の調査の「条文に書いていない」は、7.3 の該当行を見落とした読みと見る。ここで禁止を足すのは ADR-0153 を覆す新 ADR を要し、EV-0295 の差し替え条件(CL1 以上で基準7 を指す例外が1件観測)を満たしていない。
  - ただし**監査上の穴が1つ残る**: 例外承認で基準7 を外した場合、機械の criteria[7] が `not-checked` のままだと、例外承認の行と基準7 の状態が結ばれない。例外の行が「項目番号」で基準7 を指す(要求事項2)ので、**集約が基準7 を指す例外の行を拾って「例外承認で外した」と表示する**のは構文で閉じる(区分「例外」の行の対象に PR 番号があるため。内部の調査 §2.4)。これは新しい義務でなく表示の改善。これを実装の項目に足す。
- **state・check・plan の案**: state=undelivered を維持して plan=scheduled。機械の範囲が確定するまで delivered と呼ばない。`check=manual` のまま、note に「機械は存在・非空だけ。内容の妥当性は独立した評価(F.7 第6項目)で人が確かめる」と書く。全体を1マークにし、降りた部分と降りていない部分に分けない(ADR-0084)。
- **破られたとき**: 事故時に検証記録を示せない(採用組織・最終利用者)。細かく書く対象。
- **小さいチーム**: 6項目を1ファイルに収める。1人で書いて1人で読む場合、独立した評価の項目(第6項目)が空になる。ここは「該当なし」でなく**空なら欠落**とする。「独立した評価は行っていない」と書いた場合は記載として存在するが、監査人は事実を知る。

### 1.2 IMPL-0044(基準6。争点 B1〜B3)

- **B2 判定: 基準を残し、値の文を直す**(先送りでなく採る)。条文の「下記に従う」は、監査人が何を確かめるか答えられない。基準6 の「確認」を、**結果と証跡**で書き直す: 「閾値が G-1 で記録されていること、傾向の確認を実施した記録が在ること。値の良否は判定しない」。外す案は、G-7 の判定表から AI 品質指標が消えて、傾向確認が出荷の場から外れる。標準が「傾向の確認に留める」と決めているのは**合否にしない**ことで、**確認しない**ことではない。
  - 落とす案: 基準から外す(確認が出荷判定の場から消え、採用者が見落としても記録に残らない)。保証の開示の観測に寄せる案は、観測は値を出すだけで確認の実施を示さないので、確認の証跡にならない。
- **B1 判定: 両方**。確認の定義は(1)閾値の記録(G-1)、(2)傾向の確認の実施の記録。(1)は IMPL-0977(#450)が追うので、**本束は(2)だけ決め、(1)は #450 を参照する**。
- **B3 判定: scheduled(adopter にしない)**。0230 の劣化の4指標は算出が組織の履歴に依る(ADR-0137 が adopter)。0044 が求めるのは**確認の記録の存在**で、算出でない。算出を求めないので、adopter にする理由が無い。機械の範囲は記録の存在と、記録が閾値の記録(G-1)を指しているか。**値の判定を機械に入れてはならない**(合否にしないと標準が決めている。機械が失敗にすると標準と矛盾する)。
- **根拠水準**: 「確認の記録の置き場を作る」先例は調べた範囲に無い(外部の調査 §5)。EV で開示する。
- **破られたとき**: 劣化の傾向を後から検証できない。損害は小さく、遅れて出る。細かく書かない。
- **小さいチーム**: 確認の記録は1行(日付、確認した者、傾向の所見の有無)でよい。

### 1.3 IMPL-0046(基準8。争点 C1〜C3)、IMPL-0548

- **C2 判定: 別の統制と明記する**。「合否にしない」は検知の**結果**、「期限超過で出荷を止める」は未処理の**持ち越し**。基準8 の文で両者を分けて書く。監査上、「検知の結果で止める」と誤読されると、採用者は結果を隠す誘因を持つ(結果が合否に響くなら記録しない方が得)。分けて書くことは誘因の設計でもある。
- **C1 判定: 新設する(識別の欄を台帳に足す)**。台帳の区分に「類似の検知」を足すか、既存の区分の「対象」に検知の指摘であることを示す値を許すか、のどちらか。内部の調査のとおり、期限超過は日付と状態で閉じる(構文)。識別が無いと、機械は「どの行が類似の検知の指摘か」が分からず、**止めるという条文を実行できない**。条文は止めると言い、実装が止められないのは、表示と実態の食い違い(最も重い型)。形は議長と起案委員が決めるが、**監査人の要件は**「検知の指摘の行が機械で識別できる」「期限超過が判定日と比べて機械で出る」の2つ。
  - 落とす案: 新設しない(adopter)。外部の調査 Q6 のとおり、利用者側に責任が残る日本の整理と、侵害主張を受けたときの記録が唯一の防御である点から、統制を消すのは適さない。
- **C3 判定: 入れる(IMPL-0548 は本束)**。識別の欄が 0046 と同一の設計判断で、別の回に分けると欄の形を二度決める。
- **実施記録の偽の一致の開示**: 現状 `license-scan.json` の有無だけで、空のコマンドでも「実施あり」と数える(IMPL-0995、#330)。これは**基準8 の「類似の検知の実施記録」を満たしたと誤認させる**。本束では #330 の修正を待たず、(a)実施記録に道具の識別(名前と版)を非空として要求する、または(b)現状が実施の有無だけであることを根拠水準マークで開示する、の少なくとも(b)をする。(a)は新しい義務だが小さく、決定可能な条件(非空)。監査の立場は(a)を推す。道具の水準は指定しない。
  - 落とす案: 道具の水準を標準が指定する(道具が組織ごとに違う。外部の調査 Q5)。
- **破られたとき**: 侵害主張時に講じた措置を示せない。細かく書く対象。
- **state・check・plan**: undelivered / manual / scheduled を維持し、識別の欄が入った時点で機械の範囲(実施記録の存在、台帳の期限)を降ろす。

### 1.4 IMPL-0042(基準3。争点 D1・D2)

- **D2 判定: 0043 と同じ型(全体を manual)**。ADR-0084 が分けないと決めている。先例に従う。
- **D1 判定: 課さない(結合キーの義務を課さない)が、穴を開示する**。理由は監査の核心: 「記録漏れの検出」は、**台帳に無い妥協は定義上、機械から見えない**。PR のチェック項目が付いた PR で台帳の行が無いものだけを欠落にする結合は、チェック項目を付けない妥協を見逃す。これを「記録漏れ 0 件を確かめた」と表示すると偽の安心になる。一部しか見られない検査に、全体を確かめたという名前を付けてはならない。
  - ただし**監査人として捨てがたい点**: 区分「例外」は既に PR 番号で結ばれている。負債の行の「対象」に PR を**書いてよい**(任意)と許し、書いてあるものだけを突合する形は、新しい義務でなく表示の改善で、検出の穴の開示とセットなら有益。義務にしない。
  - 落とす案: 課す(チェック項目のない妥協は見えない穴が残り、義務を課した重さに見合う検出が得られない。「記録漏れ 0 件」の語を強める)。
- **開示**: 基準3 の欄に「機械が見るのは台帳の有無と区分『例外』の突合まで。記録漏れの検出は出荷判定者が PR のチェック項目と台帳を読んで行う。台帳に書かれない妥協は検出できない」と書く。根拠水準マークでなく、条文内の限定として書く(適用範囲の書き方 #226 に従い、基準の行の中へ)。
- **小さいチーム**: 台帳を書く者と突合する者が同じになる。監査として独立は求められない(7.3 と同じ「課さないと決めた」型)が、**同じ人が書いて突合した場合は、記録にそう残る**(確認者欄)ことを求める。
- **破られたとき**: 返却が追えない。損害は遅れて出る。細かく書かない。

### 1.5 IMPL-0136(SLA の判定。争点 E1〜E4)

- **E1 判定: (b)観測 + 7.5 の措置**。「SLA で判定する」の「判定する」を、合否にしない。外部の調査 Q7 と ADR-0137 決定3 のとおり、観測は実績の報告で、判定でない。ISO/IEC 20000-1 が求める型(監視・報告・未達の処置)に当たる。(a)の合否は、散文の変更を時間で止めることになり、行数から外した趣旨(ADR-0072)と当たる。
  - 文の直し: 「判定完了時間の SLA で判定する」を「判定完了時間を SLA に照らして観測し、超過は 7.5 の措置につなぐ」に改める。**この直しは意味の変更(合否 → 観測)に近い**ので、編集の指摘では扱わず、ADR に書く。
  - 落とす案: (a)合否(上記)。(c)「管理」と曖昧に書く案(監査人が何を確かめるか答えられない)。
- **E2 判定: 一本化**。催促・通知・代理判定者の指名は #445(IMPL-0979・0681)に任せる。本束は「SLA の観測と 7.5 への接続」の文だけ決める。二重の決定は食い違いを生み、監査人はどちらが正か答えられない。
- **E3 判定: 暦を必須にしない。入力が無いときは「判定しない」と開示**。暦を必須にするのは新しい義務(重)。入力が無いまま時計時間で超過を出すと、週末をまたぐ偽の超過が出て、**偽の不適合の記録**が残る。偽の記録は監査上、無い記録より悪い。入力が無いとき集約は「営業日の暦なし、超過は判定しない」と表示する。
- **E4 判定: 先送り(何が足りないかを書く)**。担い手への指示の文書(CLAUDE.md・AGENTS.md)と PROCESS-PROFILE.md を散文に数える当否は、独立に論じる価値が大きい(行数の上限から外れる効果が大きい)。足りないのは、(1) ADR-0072 の趣旨が実行層の指示文書を含むかの確認、(2) 指示文書の変更が実際に「判定完了時間」だけで通された事例の有無。本束で結論を出さない。ただし暫定として、指示文書の変更は 3.11.4(指示資産の分量)の管理下にあることを確かめ、散文の行数の除外が指示資産の分量の上限を迂回しないことを確かめる(条文 L2184 末尾に「掛からない」と書いてある点は迂回に見える。ここは議長が確認する)。EV で開示する。
- **破られたとき**: 文書のレビューが滞る(小さい)。ただし文書が実行層の指示なら大きい(E4 に集約)。
- **state・check・plan**: 識別と分布の観測は delivered 済み。残りは #445 に寄せ、0136 のマークは「観測と 7.5 の接続まで」に note を直す。

### 1.6 3.11.7 の文(IMPL-0981。争点 F1・F2)

- 前提: 「個人の指標」を定義する案は**採らないと決めた**(所有者の決定。理由は、細かい定義を増やさないことと、個人の評価への転用の危険)。裁定にこれを明記する。
- **監査の立場の核心**: 現行の文「必ず対で確認します」は、**対の相手が無く、確認の証跡も定義できない。誰も守れず、破られても検出できない**。内部監査で確かめられない「必ず」は、適合の主張を弱くする(守っていない者を見つけられないのに義務の形をしている)。
- **F1 判定: R2 を採る**。文を「保守性の指標は、単独で提示せず、採用者が使う生産性・速度の指標と並べて確認します」の趣旨に改める。metrics 原則1 の参照を添える。対の相手を**定義せず**採用者に委ね、個人の語を消す。外部の調査 Q9(チーム/リポジトリ単位で緊張関係のある複数の指標を並べる)とも整合する。
  - ただし**監査の要件**: 「並べて確認」の証跡が残らないと R2 も確かめられない。証跡は、保証の開示または傾向確認の記録(0044 の記録)に「並べた指標の名前」を1欄書くことで足りる。0044 と欄を共有するのが最小。新しい様式を足さない。
  - 落とす案:
    - R1(読み替え): 新しい対の相手を標準が持ち込む。意味を変え、定義を置かないという決定の趣旨に反する。
    - R3(削る): 兆候の記述は残る価値があり、課さないと決めるより、確認できる形に直す方が適合を主張できる。ただし R3 に実質があることは認める。R2 の証跡の欄が実装で 0044 と共有できないと分かったら R3 へ倒す(その場合、「課さないと決めた」と明記する)。
    - R4(推奨に改める): 検査も降ろしも無い文を条文に残すと「書いたが守られない規定」が増える。台帳が undelivered を表示し続けるだけで、統制として何も足さない。
- **F2 判定: 意味の変更として ADR に書く**。「個人の指標」の語を消し、対の相手を個人の指標から採用者が使う指標に替えるのは、確認の対象が変わる。編集の指摘で扱うと、変更の理由と所有者の決定(定義しないと決めた)が残らない。
- **IMPL-0981 の処置**: マークは delivered にならない(manual)。note を直し、EV-0277 の差し替え条件を満たしたとして更新する。
- **破られたとき**: 保守性の劣化を単独で見落とす。損害は小さい。細かく書かない。

### 1.7 G(基準 3・6・7・8 の「欠落 0 件」と基準9 の非対称)

- **判定: 開示する(根拠水準マーク)。基準の文を揃えることは採らない**。揃えるには重の別件を要し、本束の範囲を超える。ただし「開示する」だけで済ませず、**判定表に直接**: 基準 3・6・7・8 の値の欄の末尾に「機械が確かめる範囲は集約の出力の『機械の確認』欄に表示する」旨を1行足し、集約の出力側が「機械で確かめた / 人が確かめる」を基準ごとに区別して表示する(`humanReconcile` が既にあり、足りないのは表示の統一)。
