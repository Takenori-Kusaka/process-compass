### 2.3 IMPL-0046(基準8 知財潔白性)

- 条文: 基準8「ライセンス検査の結果、類似の検知の実施記録と結果、判定できなかった項目の台帳記録。欠落 0 件」。類似の検知は**合否条件にしない・実施と結果を記録する**(L1160〜1166)。当該の変更単位で処理できないときだけ台帳へ記録し、期限を付し、**期限超過の未処理項目が残る出荷は止める**(L1196〜1198)
- 条文内の緊張: 「合否にしない」と「期限超過で出荷を止める」が同居する。止めるのは検知の結果ではなく**未処理の持ち越し**で、別の統制だと読める。ただし機械が「どの台帳の行が類似の検知の指摘か」を識別できないと、止められない
- template: criteria[8] は `evidence/license-scan.json` の有無だけ(L5307)。空のコマンドでも「実施あり」と数える(IMPL-0995。`issue=330`、review=2027-05)。類似の検知の実施記録の置き場・様式は無い。`gate-g5.yml` に「類似検知は合否条件にしません」の注記、`08-ai-sla.md` L86 に同じ文。台帳の区分は負債・例外・未解決の3つで、類似の検知を置く区分が無い(IMPL-0548 が追う)
- 規格・法令: 日本の著作権法の依拠性の推認(L1180)が前提。類似の検知の**道具は組織ごとに違う**(商用か否か。L1169 に事業者が補償要件を外した実例)。外部の調査の領分
- 決定可能な範囲: 実施記録の存在・台帳の期限日付と状態(「返却の目安」が日付で、判定日より前で、未返却)は構文で閉じる。既に D-0 節15 の受容の期限切れに同型の実装がある(research.md L79〜86)。識別する欄が無いのが唯一の欠け

### 2.4 IMPL-0042(基準3 受容した負債の記録漏れ)

- 状態: 束1 の裁定(`b1-decision.md` 7章 / ADR-0138 決定4)で、note と `review=2027-02` だけ直し、束2 へ移した。出荷判定者が PR のチェック項目(`PULL_REQUEST_TEMPLATE.md` の「受容した妥協・仮実装を技術負債台帳へ記録した」)と台帳を突合する手順は `gates/G-7.md` に足してある
- 構造: 区分「例外」は「対象」に PR 番号が必須で、既に変更と突合されている。区分「負債」「未解決」の「対象」は「—」でよく、結合キーが無い。**台帳に無い妥協は、定義上、機械から見えない**(記録漏れの検出は事実の判定で、機械で閉じない)
- 結合にする場合の最小の形は、負債の行の「対象」へ PR を書けるようにし、PR のチェック項目が付いたのに台帳の行が無い PR を欠落にする、の1つ。**付けなかった妥協は検出できない**ので、検出の穴は残る。この穴を開示せず delivered と呼ぶと、強く読まれる(ADR-0084 L177)
- 先行の整合: ADR-0084 は IMPL-0042・0043 を「降りた部分と降りていない部分に分けない」と決めた。ADR-0138 は 0043 を manual で全体を降ろしたが、0042 は動かしていない。束2 で 0042 を manual で降ろすなら 0043 と同じ型になる(全体を manual、機械の部分は別の文があるときだけ別マーク)
- 小さいチーム: ソロ・数名では、台帳と PR を同じ人が書き、突合する者も同じ人になりうる。記録漏れを見つけるのは本人の自覚に頼る。独立の確認(2人目)はテーラリングで効く範囲が変わる

### 2.6 3.11.7「個人の指標と保守性の指標は必ず対で確認します」(IMPL-0981)

- 文脈(L1673〜1696): 4指標(重複・移動・短期書き換え・相互参照密度)を挙げ、「典型的な兆候は、個人の生産性指標が改善する一方でこれらの値だけ悪化する組み合わせ」と書く。直後の文が対の要求。すぐ下で「これらの値は傾向の確認に用い、5.4.6 の入力にしない」(IMPL-0230 が adopter)

### (2) 珍しい構成・抜け道は第7章の例外承認で受けられないか

- 7.3(L26〜36): 例外承認の対象は「ゲートの判定基準と、7.3 を名指した条項」。基準 3・6・7・8 は判定基準なので**対象になる**。要求事項は5つ(記名の承認・満たさない基準の項目番号と理由・影響と対処・回収の期限と責任者・追跡)
- したがって「安全関連だが F.7 を採用者の様式で持つ」「類似の検知の道具が無い」は、**様式を一律に課さなくても、基準を満たさない理由と期限を持つ例外承認で受けられる**。この道があるので、機械の検査を強い義務にしなくても、抜け道が承認なしに通ることは防げる
- ただし例外承認が受けるのは「満たさない基準」であり、「満たし方が標準の様式と違う」ではない。満たし方の違いを許すのは基準の文(「F.7 の項目に欠落がない」)の読みである。この点は会議体で分ける必要がある
- 安全: 7.11 停止の申し立てと 5.8.3 は `impl-no-adopter` で守られるが、基準7 の例外承認は別。安全度の高い案件で基準7 を例外承認で通すことを標準が許すかは**条文に書いていない**。許さないなら、書く必要が出る(新しい条項。重)
- 小さいチーム: 例外承認の承認者が必要で、承認者が1名しかいない構成では記録が形式になりうる。7.3.1 の経路の使い分けを要確認(今回は未読)

## 4. 既存の条項を削れないか

- 0981: 対の文は、metrics 原則1 と L2634 の「対」の先例があり、4指標が傾向確認にしか使われない以上、削っても失う統制は小さい。削る案(R3)に実質がある。ただし「個人の生産性が上がる一方で保守性が悪化」は兆候の記述として有益で、文を残す価値がある
- 0136: 「判定完了時間の SLA で判定する」は 7.5・#445 の既存の措置に一本化し、散文の SLA 固有の判定を置かない案。ADR-0072 は行数でない管理を選んだので、時間の管理は残す
- 0044: 基準6 の値「下記に従う」は、節が「合否にしない」と定めるので、基準としては空に近い。基準から外し、傾向の確認は節で完結させる案がある。外すと G-7 の9基準が8基準になる。基準9 の「保証の開示」に観測として出す形(0159 のように)に寄せる案もある
- 0046: 「期限超過の未処理が残る出荷を止める」は基準8 の外の統制に見える。止める文は IMPL-0548 と合わせて整理できる
- 条文でなくマークの削減: 4件の `review=2026-11` を更新する必要がある(今月切れる)。年月は議長が決める

## 5. 小さいチームでどう省けるか

- 1〜3名の体制では、独立した確認者がおらず、記録を書く者と読む者が同じになる。F.7 や類似の検知の記録は**書くことは省けない**が、様式の重さは省ける(見出し6つ、1ファイルに収まる)
- 機械の検査は存在・非空だけなので、小さいチームの負担は書く時間だけ。台帳の結合キー(0042)は、PR を1行書く程度
- 安全関連でない案件(多数)では、基準7 は「対象なし」で通す。このとき「対象なし」の根拠(構成の `q-criticality`)の確かさが問題で、仮の判定のままの出荷は既に別の欠落になる(L3487)
