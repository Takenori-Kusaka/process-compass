## 1. IMPL-0043(G-7 基準4。標準 L1436 の1行、マーク L1446)

### 1.1 規定の文

「運用引き継ぎ文書 | 完備(監視項目・障害時連絡先・復旧手順)」。表の前の段落は「『完備』は記録の完備を求める要求」と書く。**「完備」が記載の有無までか、内容の十分性までかが、文のうえで定まっていない**。これが本件の要(定義の欠け。軽の範囲)。

### 1.2 起案: 機械で閉じる範囲

集約が `docs/handover.md` を読み、3項目それぞれを次で判定し、満たさない項目を `gaps` に出す。

1. 見出しが在る(監視=「4. 監視」、復旧手順=「3. 動かしかた」の「切り戻し」の行、障害時連絡先=1.4 の template の直し)
2. 表なら、**白紙の様式のセルと同じでも空でもない**セルだけの行が1行以上ある。手引きの文のままと `<…>`・「…」のままを未記入とする。比べる基準は同梱の `templates/05-handover.md` の初期セル。**全セル非空**を求めるかは議長が決める。起案は「全セル非空」を採る(「AI(判断は人)」だけの行を記載に数えないため)が根拠は無い(EV-NEW1、E0)
3. 見出しは集約の定数に持ち、`templates/05-handover.md` に実在することを試験が確かめる(`org-assurance.mjs` が節2 を番号の正規表現で読む先例と同じ。採用者が見出しを改めると「見出しが無い」欠落になる=偽の欠落側に倒れる)

manual にする範囲: 監視の閾値の妥当性、連絡先の実在と到達、復旧手順の実行可能性、切り戻しの実績。

### 1.3 マークの形(方針1)

- **案A(推す)**: 標準へ1文を足して規定を2つに分ける。「出荷の証跡の集約は、3項目のいずれかの節が無いもの、節が様式の初期文・空欄・プレースホルダのままのものを、記載の欠落に数えます。内容が運用に足りるかは出荷判定者が読んで判定し、機械は判定しません」。「完備」の読みの定義であり、基準2(台帳が無い・読めない台帳を記載の欠落にする。IMPL-0041)と同じ型。採用者に新しい記入は課さない(3項目は標準の様式が既に求める)。マークは `IMPL-0043`(欠落の検出)を `delivered check=machine test=…`、`IMPL-NEW1`(内容の十分性)を `delivered check=manual`(確かめる者: 出荷判定者。`gates/G-7.md` の手順1 へ「3項目の内容を読む」を足す)に分ける

## 3. IMPL-0042(G-7 基準3。標準 L1435、マーク L1445)

### 3.1 結論: 新しい義務を置かずに降ろす形は無い。束2(重)へ移す

標準が既に求める欄だけで結合できるかを、様式と `template-fields.yaml` で確かめた。

- 結合に使える欄は「対象」。標準が必須にするのは区分「例外」の行だけで、その行は既に PR・コミットと集約が突き合わせている(L2403〜2559)。区分「負債」「未解決」は「—」でよい。妥協の記録漏れは定義のうえで**台帳に無い事実**であり、台帳だけを読む機械には見えない
- 既存の信号は PR 本文のチェック項目「受容した妥協・仮実装を技術負債台帳へ記録した」だけ。「付いている ⇒ その PR の台帳の行がある」は、妥協の無い PR にも行を作らせる(偽の行の誘因)。「付いていない」は書式の不備でしかない。**どの形も妥協の有無を著者の自己申告に頼り、漏れを見つける力が無い**(実証は無い)
- 見分ける力を持たせるには、PR に「妥協: なし / あり(D-NNN)」の宣言を必須にする、または負債の行の「対象」に PR を必須にする義務が要る。いずれも採用者への新しい義務(重)

### 3.2 束1 で行うこと

- note は実態(有無のみ)に合っているので直さない。`review=2026-11` は今月切れるので、束2 へ移す際に議長が年月を決める(起案は 2027-02)
- 束2 への申し送り: 案(a) 「妥協: なし / あり」の宣言(PR 本文)と台帳の行の結合。案(b) 機械で閉じないと記録して manual か `adopter`(出荷判定者が PR と台帳を突合。`G-7.md` に手順が無い現状を直す)。(b) は G-7 の降ろす順序の登録簿に当たるので `adopter` の可否は突合で確認する
- `gates/G-7.md` へ突合の手順を足すのは義務を増やさないが、機械は何も確かめないので `delivered` とは呼ばず、state は動かさない
