# #355 束2 委員05(弁護)の意見書

2026-11-17。立場は弁護(採用者・個人の側。課さない・別の形で受ける案を最も強く立てる)。判断軸は信頼性で、安さ・変更量は理由にしない。入力は議題と b2-research-internal.md・b2-research-external.md・intake-ruling.md・b1-decision.md 7章。条文は gate-criteria.md L1160〜1200・L1529 付近を確かめた。実行での確認はしていない。

## 0. 弁護の総論(先に)

1. 弁護が守るのは「新しい義務を、実証なしに採用者へ課さない」ことであって、統制を消すことではない。消す案(adopter 化・削除)は、**規格に根拠が無い**(外部 Q2・Q6)場合は出さない。
2. 4件のうち、条文が**既に**求めている結果(0046 の「期限のない記録を認めない」「期限超過で出荷を止める」、0042 の「記録漏れ 0 件」、0045 の F.7 の添付)は、課さない案の対象ではない。降ろし方を選ぶだけである。弁護が争うのは、**条文に無い物**(置き場・様式・区分・暦・結合の欄)を標準が新設する点に限る。
3. 機械が閉じる範囲は存在・非空・構文までにとどめる。それ以上を機械の検査と呼ぶと、表示と実態が食い違う(ADR-0084 L177)。この食い違いこそ採用者の信頼を損なう。

## 1. 規定ごとの意見

### 1.1 IMPL-0045(基準7。安全の検証記録)

- **判定: 採る(`undelivered manual` を維持。降ろす範囲は存在・非空・理由つき「該当なし」まで。adopter 化は課さない案としても採らない)**
- 弁護の最強の案: 様式も置き場も新設しない。F.7 は既に「ゲート判定記録(テンプレ4)に添付」と標準が定める。したがって降ろすのは、判定記録の中に F.7 の6項目の欄を持つこと(標準が既に求める物の写し)と、安全関連の構成のとき**空欄を欠落に数える**ことだけにする。専用ファイル・専用ディレクトリ・見出しの書式は課さない。規格は項目を定め様式を組織に任せる(外部 1.2)ので、これが規格の流儀に最も近い。
- 採らない案とその理由
  - adopter 化: 規格に根拠が無い(外部 Q2)。安全で採用者の実装の有無により統制が消える型で、`impl-no-adopter` の理由に実質が当たる。弁護でも安全は譲らない。
  - 専用の置き場と様式の新設: #448 の IMPL-0933 の範囲であり、採用者への新しい義務。実証が無い。
  - 内容の妥当性を機械で判定: F は規格を標準側で決めない(F L14)。閉じない。
- A1(#448 との境): **分ける**。理由は変更量でなく信頼性である。束2 で F.7 の様式を決めると、#448 の13件(様式全体の棚卸し)と食い違う危険がある。束2 は「判定記録の欄の存在」までに限り、様式の細部は #448 に残すと note に書く。
- A3(基準7 を例外承認で受けるか): 弁護は「許さないと明記」を**新しい条項**として足すことに慎重である。ただし7.3 が安全関連でも基準7 を例外承認の対象にできるかは、条文に書かれていない(内部 §3(2))。弁護は**先送り**を求める。足りないのは、7.3・5.8.3・ADR の原則で安全関連の例外承認がどう扱われるかの突合である。突合の結果、許すと読めてしまうなら、その場合に限り「安全度の高い案件の基準7 は例外承認で通さない」を書く(この1文は安全であり、課さないとは言わない)。
- A4: **人が判定する**。CL は案件ごと(ADR-0039)で、F.2 は人の判断。機械は構成の宣言値(`q-criticality`)と判定記録の欄を**突き合わせるだけ**にする。「安全関連でない」と宣言した根拠が空なら欠落、とするのは構文で閉じる。
- 破られたとき: 事故時に検証の記録を示せない(採用組織・最終利用者)。細かく書く価値のある規定である。

### 1.2 IMPL-0044(基準6。AI 品質指標の確認)

- **判定: 課さないと明記する(機械の欠落判定を課さない)。マークは `plan=adopter` に改める。基準6 の行は残す**
- 理由: 標準の節が「合否条件にしてはならない・傾向の確認に留める」と定める。これを「欠落 0 件」の形の基準で機械が欠落に数えると、標準が禁じた合否に近づく。算出は組織の履歴に依る(0230 と同じ型)。外部の調査は「記録の置き場を作ること自体の先例は調べた範囲に無い」とし、Goodhart の面でも合否にしない方針は筋が通る。
- 採らない案
  - 機械が存在・非空を欠落に数える(scheduled): 指標を良い方向へ偽装する圧力を、記録の義務が生む。外部(DORA)が指す虚栄化の入口になる。
  - 基準6 を基準から外す: 9基準を8基準へ減らすのは、基準番号の参照(附属書H・D 等)に及ぶ。それより、**基準を残して値の読みを節に委ねる現状の構造が、開示として正直**である。外す案は否定せず、先送りの余地を残す(足りないのは、基準番号の参照の洗い出し)。
- B1: 「確認」は閾値の記録(G-1)と傾向の確認の2つに分かれる。閾値は #450(IMPL-0977)が追う。束2 では傾向の確認だけを扱い、閾値は #450 に任せる。
- adopter にする根拠水準: 実証は無く、外部の先例の不在による判断。`:::caution` で開示(暫定 EV-NNNN、見直し 2027-05)。
- 破られたとき: 劣化の傾向を後から検証できない。直接の事故は無い(内部 §3(3))。細かく書く価値は小さい。
- 注意: これは「統制を消す」案に見える。しかし統制の実体は G-1 の閾値の記録と、承認の時間と規模の比(IMPL-0159。delivered)に既に降りている。基準6 の行が機械に何も求めないことを、降りていない規定の台帳へ出さないために adopter にするのではなく、**標準自身が合否にしないと決めた以上、それを機械が欠落にすること自体が標準と矛盾する**から、である。

### 1.3 IMPL-0046(基準8。知財潔白性)と IMPL-0548

- **判定: 採る(降ろす。新しい区分も置き場も新設しない)。adopter 化は採らない**
- 弁護の最強の案: 条文は既に「記録には期限を付す・期限のない記録を認めない・期限超過の未処理が残る出荷は止める」と書く。**新しい義務は無い**。欠けているのは識別だけ(C1)。台帳の区分を足すと様式の変更になり採用者に波及する。代わりに、**既存の区分「未解決」を使い、「対象」の欄の値に類似の検知の指摘であることを示す**(値の規約は手引きへ)。区分の新設は採らない。識別の欄が使えるかは、台帳様式の欄の実在を確かめてから決める。
- 機械の範囲は、実施記録の存在と、台帳の「返却の目安」が判定日より前で未返却の行(構文で閉じる。D-0 節15 に同型の実装がある)まで。道具の識別は要求しない(Q5。道具は組織ごとに違う)。ただし、空のコマンドでも「実施あり」と数える偽の一致(IMPL-0995)は、**開示する**(根拠水準マーク)。道具の識別の義務を課す案は、実証が無いので採らない。
- C2: 「合否にしない」と「止める」の同居は**矛盾でない**。止めるのは検知の結果でなく未処理の持ち越しで、標準の文が既に「持ち越すのは判定であって、対処ではありません」と書く。条文は直さず、IMPL-0046 の note に別の統制であることを書く(編集の指摘の範囲)。
- C3: **IMPL-0548 を入れる**。同じ識別の欄の問題なので、別々に決めると食い違う。0548 の「区分が無い」の note は、上の方式で「区分は新設しない。既存の区分で受ける」と更新できる(その場合、0548 は降ろす先の調整だけになる)。
- 採らない案
  - adopter 化(Q6): 日本の整理では責任が利用者側に残る。推認の防御は記録だけ(L1180)。統制を採用者の実装の有無に委ねてはならない。
  - 「検知の結果」で止める: 世の中に根拠が無い(Q4)。標準もしない。
  - 区分の新設: 変更量ではなく、実証が無い様式の強制だから採らない。
- 破られたとき: 侵害主張を受けたとき措置の記録を示せない(採用組織)。細かく書く価値がある。

### 1.4 IMPL-0042(基準3。受容した負債の記録漏れ)

- **判定: 課さないと明記する(結合の義務)。マークは 0043 と同じ型で全体を `manual` のまま、`undelivered` を維持して note に穴を書く**
- 理由: 「付けなかった妥協は検出できない」(内部 2.4)。負債の行の「対象」へ PR を書く義務(D1)を課しても、検出できるのは「チェック項目は付けたのに台帳に無い」PR だけで、自覚して付けた者しか対象にならない。偽の安心を生み、ADR-0084 L177 の「強く読まれる」問題を起こす。小さいチームでは、台帳を書く人・PR を書く人・突合する人が同じで、結合は形式化する(内部 §5)。
- 採らない案
  - 結合の義務(D1 の課す側): 穴を開示すれば一部の機械検出に価値はあるが、義務の増加に見合う実証が無い。実証なしの判断なので、採るなら暫定マークが要る。弁護は採らないが、会議体が採るなら、穴の開示(delivered と呼ばない)を条件とする。
  - 機械の部分を別マークに分ける(D2): ADR-0084 が退けた分け方。
- 第7章: 記録漏れの検出は事実の判定で機械で閉じない。出荷判定者の手引き(`gates/G-7.md`)の突合で受ける。これは束1 で足し済み。
- 破られたとき: 技術負債の返却が追えない。遅れて出る損害(内部 §3(3))。

### 1.5 IMPL-0136(文書だけの変更の SLA の判定)

- **判定: (b)「観測+7.5 の措置」の読みを採る。(a)合否は課さないと明記する。降ろしていない部分は #445 へ一本化(E2)**
- 読み: 外部 Q7 のとおり、観測を出すのは「判定」でなく「実績の報告」。ADR-0137 決定3 の「観測を判定と呼ばない」と整合する。(a)は新しい合否条件で、ADR-0072 の趣旨(行数でない管理)と当たる。
- E2: 催促・通知・代理の指名は IMPL-0979・0681 と同じ欠け。二重に決めると食い違う。**一本化**。束2 は「SLA で判定する」の読みだけを裁定し、措置は 7.5 に委ねると note に書く。
- E3(営業日の暦): **必須の入力にしない**。入力が無いときは「判定しない」と開示する。暦の必須化は採用者への新しい義務で、外部に先例も無い。時計時間の偽の超過(束4 の実行で確認済み)は、判定でなく観測として出すので害が小さい。
- E4(CLAUDE.md・AGENTS.md・PROCESS-PROFILE.md を文書に数えるか): これは弁護が**引かない**点。実行層の指示は「散文」として SLA だけで通すと、行数の上限から外れる効果が大きい。弁護は採用者に有利でも、この点は信頼性が勝つ。数えない(行数の対象に残す)側が筋で、独立に論じる価値がある。ただし数え方を変えるのは新しい条項になりうるので、**先送り**(足りないのは、現行の「文書」の定義の突合と、実行層の指示を行数から外した場合の実例)。束2 では決めず #355 の残りに回す。
- 破られたとき: 文書のレビューが遅れる。小さい。ただし実行層の指示では大きい(内部 §2.5)。

### 1.6 3.11.7 の文(IMPL-0981)の直し方

- **判定: R2 を採る。R3(削る)を第二候補とし、R1・R4 は採らない。「個人の指標」の定義は、所有者の決定により採らないと決めた**
- 裁定に明記する文(案): 「個人の指標を標準で定義する案は採らない。理由は、細かい定義を増やさないことと、個人の単位の指標の定義が個人の評価へ転用される危険である(所有者の決定 2026-11-17)。」
- 理由: 現行の文は、文字通りに降ろすと運用メトリクスの原則(個人へ絞り込む機能を実装しない)と**衝突**する。守れない文は、破られても検出できず、誰も守れない(内部 §3(3))。R2「保守性の指標は、単独で提示せず、採用者が使う生産性・速度の指標と並べて確認します」は、metrics 原則1(対抗する指標と対で配置する)に一致し、外部 Q9(個人を単位に測らず、緊張関係のある複数の指標を見る)にも沿う。対の相手を定義しない。
- 採らない案
  - R1(読み替え。チームの生産性の指標を対の相手にする): 新しい対の相手を持ち込む。意味の変更で、定義を要する。
  - R3(削る): 有力。兆候の記述を残して要求だけ削れば、課さないと明記できる。ただし「単独で提示しない」は metrics 原則1 に既にあるので、R2 は新しい義務にならず、R3 と実質が近い。弁護は R2 を先にするが、会議体が R3 を採っても反対しない。
  - R4(推奨に改める): 守れない文を弱くしても、守れないままである。降ろさないなら削る方が正直。
- F2: **意味の変更として ADR に書く**。「個人の」を消すだけでなく、対の相手が変わる(個人の指標→採用者の生産性・速度の指標)ので、編集の指摘では扱えない。
- 根拠水準: 外部は「個人の指標を必ず対で確認する」の直接の先例が見つからなかったとする。SPACE の一次は未読。R2 は先例のある方向(複数指標の緊張)に寄せる案だが、採用者の指標の範囲を標準が定めないので、`:::caution` で開示する。

## 2. 横断

- G(基準3・6・7・8 の「欠落 0 件」と基準9 の「未達は値として受ける」の非対称): **開示する**(根拠水準マーク)。基準の文を揃えるのは重で、実証が無い。
- 第7章で受けられるか(必ず通す問い2): 0046 の道具の欠如、0042 の記録漏れの見えない穴、0044 の指標の不在は、7.3 の例外承認(満たさない理由と期限)で受けられる。ただし例外承認は「満たさない基準」を受けるもので、「満たし方が標準の様式と違う」を受けない。満たし方の違いは基準の文の**読み**で受ける。この区別を手引きに1行書く(新しい条項は足さない)。0045 は上の A3 で別扱い。
- 既存の条項を削れるか(必ず通す問い): 3.11.7 の対の文(R2/R3)と、0044 の機械の欠落判定(課さない)の2つ。足すのは、0045 の欄の存在(標準が既に求める物)だけ。
- 小さいチーム: 追加の書く負担は、0045 の判定記録の欄(既に添付が必要)と、0046 の「対象」の値の規約のみ。独立の確認者が要る案は採っていない。
- 破られたときの重さ: 細かく書くのは 0045・0046 のみ。0044・0042・0136・0981 は短く書く。
- template: 本束では触らない。及ぶ分は、0045(判定記録の欄)、0046(台帳の対象の規約)、0044(adopter 化に伴う集約の note)。

## 3. 弁護の弱点(自己申告)

- 0044 の adopter 化は、統制の実体が他の IMPL(0977・0159)に降りていることに依る。#450 の IMPL-0977 が進まないと、閾値の記録が降りない。この依存は開示する。
- 0046 の「未解決」の区分の再利用は、台帳様式の欄の実在を未確認のまま書いた。確かめて使えなければ、区分の新設を第二案とする(その場合は新しい様式の義務なので、根拠水準マークで開示)。
- 0042 の「課さない」は、検出の穴を残す。穴の開示を条件にする。
