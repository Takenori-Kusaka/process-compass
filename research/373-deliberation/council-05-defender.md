## 先に認める欠陥(弁護の範囲の外)

弁護の委員として、次の3つは今の標準の欠陥であり、守らない。

1. **初回の判定に、判定者も根拠も残らない**(内部 2.2、5.1)。引き下げには4つの要求事項を課す(`tailoring-guide.md:847`、ADR-0030 決定)のに、最初から低く答えた場合は何も残らない。ADR-0030 自身が「設計を変えた事実の記録がない引き下げは、回答の書き換えとして扱います」と書き、書き換えを最も避けたい帰結と呼ぶ(ADR-0030「コンテキスト」「引き下げの非対称性との関係」)。初回の回答が無記録であることは、この論理に穴を開けている。下げる操作より、初めから低く答える操作のほうが軽い。これは非対称の逆転である
2. **テンプレ9 の要否が第6章と軸E・規則データで食い違う**(X-a。`deliverable-templates.md:1678-1689` と `tailoring-guide.md:854`、`rules-criticality.yaml` の `r-e-cl2`)
3. **「承認済みの本表」を前提条件にしながら、様式に承認の欄が無く、機械の検査も実装の印も無い**(内部 5.2。`lifecycle.md:312` の「前提条件の充足は、人の確認ではなく機械的な検査によって判定する」。3b の作成者は技術判断者だが承認者が書かれていない `lifecycle.md:288`と食い違う)

以下で守るのは「**判定の確認に組織上の距離の段を課さない**」という一点である。記録・記名・段1 の確認までは、課すべきだと考える。

## R-1 CL の判定の確認を求めるか、誰が、どの段で

### 推す案

案(e)を軸に、(f)(g)を重ねる。

1. **判定の記録を、CL0 を含むすべての区分で必須にする**。欄は次の4つ
   - 判定者(記名。AI の名義は受け付けない。`tailoring-guide.md:87` の緩める向きの記名と同じ扱い)
   - 想定できる最悪の帰結(軸E の判定基準の語で書く)
   - 1つ上の区分に当たらない理由(CL3 は不要)
   - リスク対策を入れる前の帰結か、設計で下げた後の帰結か。後者なら「設計によって区分を下げる」の4要求の記録へのリンク
2. **判定者と別の自然人による確認(段1)を求める**。段は CL の値から導かない。すべての区分で同じ段1 とする
3. 段1 の確認者を置けない体制は、未達として表示する(R-2)。拒否はしない
4. 事後の検出として、附属書H の内部監査に「CL の判定と、その根拠の記録」の観点を足す(案 f)。保証の開示に判定者・確認者を出す(案 g)

### 理由

- **循環は、段の距離ではなく「要否を CL から導かない」ことで断てる**。内部 6.3 の整理のとおり、循環を断つ条件は確認の要否と段を判定の結果から導かないことである。段1 をすべての区分に一律で課せば、CL0 と答えても確認は外れない。断つために距離は要らない
- **記録の型は、外部調査で唯一、外部の審査者が無くても機能する部分**である。FDA は低い区分(Basic)にも区分の記述と理由を求め、判定は対策の前のリスクで行う(外部 2.2、一次)。付録 A はソフトウェアを含まない機器にさえ「理由と結果」を書かせる。本標準に当局は居ないが、理由の欄そのものは当局が居なくても成立する
- **ADR-0030 の設計思想と同じ**。ADR-0030 は個別の審査制を「1〜2名の体制に審査の相手がいない」として退け、「要求事項を満たしたかどうかを記録で検証する形」にした(ADR-0030「検討した選択肢」)。初回の判定にも同じ形を当てる。ADR と矛盾しない
- **CL2・CL3 の境界は、外の制度が既に確かめる**。CL2 の判定基準は「適合性評価または第三者認証の対象」(`tailoring-guide.md:840`)であり、規制への該当という外から確かめられる事実で決まる。CL2 以上と判定した案件には、独立した安全性の評価(段2・段3)が既に掛かる(ADR-0088 決定2)。距離が要るのは「低く判定して外の制度から逃げた」場合だが、それを本標準の内部の距離で捕まえるより、該当の事実を理由の欄に書かせるほうが確かめやすい。ただし、CL3 の製品がすべて外部の評価を受けるとは限らない(**未実証**)

## R-2 1〜2名の体制と、組織の外の確認者

### 推す案

1. **拒否しない。段1 の確認者が置けなければ、未達として表示する**。ADR-0028 決定1〜6 の未達の扱い(冒頭に表示、出荷の証跡と品質レポートに載せる、消す操作を置かない)をそのまま当てる。CL0 の案件は、未達のまま G-8 の受容で出荷できる今の作りを変えない
2. 2名の体制では、判定者でない側の人を段1 の確認者にする。軸A の表で 2名は内部で段1 が届く(`tailoring-guide.md:221`)。2名の CL0 の採用者は、外部を探さずに満たせる
3. 1名の体制では、**理由の欄の必須化を確認の代わりにはしない**。理由の欄は全区分の必須として R-1 で既に課す。1名の体制の確認は未達のまま残す。外部の確認者(他チーム・別部門・社外コミュニティ。`tailoring-guide.md:196` の G-6 の調達先と同じ)を名簿へ登録すれば未達が解ける道を示す
4. 理由の欄には、ADR-0030 が列挙した「**設計で下げられない危害**」(人体への危害、外部へ出た情報、外部との間で確定した取引、第三者の資産・環境への物理的な影響)に当たるものが無いことの確認を含める。1名でも答えられる閉じた問いであり、CL0 の誤判定の典型を拾う
5. 開示: 保証の開示に「CL の判定: 判定者 / 確認者 / 確認者の不在(未達)」を出す(案 g)。受け入れる側が、確認されていない CL0 の判定であることを読める

### 理由

- **確認の相手がいない体制は CL0 に集まる**(議題の前提)。これは欠陥ではなく、ADR-0028 が「1〜2名の利用を想定から外す」案を「個人開発は最も導入しやすい入口であり、ここを閉じると標準そのものが試されない」として退けた結果である(ADR-0028「検討した選択肢」)。確認を拒否の条件にすれば、この却下を実質で覆す。覆すなら新しい ADR で ADR-0028 の理由を否定する必要があり、その根拠(CL0 の 1〜2名の案件で誤判定が実際に起きている観測)は無い(**未実証**)
- **未達の表示は「確かめていない」を隠さない**。信頼性の軸で見て、確認の相手がいない体制に形だけの確認(AI の確認、自分の再確認)を認めるより、未達と書くほうが読み手を欺かない。ADR-0028 決定7 は AI レビューを承認に数えない。同じく、CL の判定の確認にも AI を数えない
- **ADR-0030 は、同じ理由で外部の審査を退けている**(「引き下げの可否を個別の審査制にする」は「1〜2名の体制に審査の相手がいない」)。初回の判定に外部の確認を必須にすれば、引き下げより初回の判定のほうが重くなり、今度は逆向きの非対称になる

## R-3 テンプレ9 の要否と確認

### 推す案

1. **食い違い X-a は、第6章の適用条件を正とし、軸E の表と規則データを第6章へ合わせる**
   - 軸E の表の行(`tailoring-guide.md:854`)を「CL0・CL1: 第6章の適用条件による。CL2・CL3: 適用条件に依らず必須(G-1 の前提条件)」と読む形へ直す
   - 規則データに、第6章の4条件(物理的な危険源、R1 の変更種別、本番到達、L2 以上)から `safetyRiskAssessment: required` を立てる規則を足す。今は `r-e-cl2`(`rules-criticality.yaml:42-50`)が CL2・CL3 でだけ立てる
2. **様式に承認の欄を足す**(承認者・日付)。承認者は技術判断者と別の自然人とする。段は課さない(段1)
3. **G-1 の前提条件(承認済みの本表があること、SR4 が残っていないこと)の機械の検査を、実装の印で開示する**。降りるまでは `state=undelivered`
4. **テンプレ9 の確認者に組織上の距離の段を課さないと決め、その旨を明記する**。CL2 以上の案件では、独立した安全性の評価(段2・段3)の範囲にテンプレ9 を含めるかを決め、含めるなら評価者がテンプレ9 を読む。テンプレ9 のために別の段の確認者を新設しない
5. X-b(製品の危害を下げた引き下げの記録を、エージェントの危害の様式へ書かせている。`tailoring-guide.md:941`)は、引き下げの記録の置き場を区分に依らず ADR とする方向で直す。テンプレ9 には製品の危害の欄が無いため

### 理由

- **第6章を正とするのは、テンプレ9 の対象が CL と別の物だからである**。テンプレ9 は開発に使う AI エージェントが引き起こしうる危害の評価であり(`deliverable-templates.md:1656-1658`)、製品の最悪の帰結(CL)とは対象が違う。CL0 の社内ツールでも、本番の資源へ届く L2 のエージェントは本番のデータを壊せる。危険源はエージェントの権限と到達範囲で決まり、製品の区分では決まらない。軸E が CL0・CL1 を「不要」と書くのは、対象の取り違えである
- 弁護の立場から見ても、これは新しい負担ではない。第6章は既に4条件で必須と定めている。規則データが降ろしていないだけであり、降ろすことは既存の規範を実行層へ届けることである(CLAUDE.md の #222 の原則: 降りていない規定は表示し続ける)
- **承認の欄は、標準自身が「承認済み」を前提条件にしている**(`lifecycle.md:288`「作成し、承認を得る」、`deliverable-templates.md:1689`)。承認者の欄が無い前提条件は、満たしたかを誰も確かめられない。欠陥として認める
- **段を課さないのは、ISO 26262 の HARA の類比がテンプレ9 に当たらないからである**。内部 2.4 X-c のとおり、HARA に当たるのは CL の判定と附属書F F.2 であって、テンプレ9 ではない。#318 の起草の委員の R-1 案は、テンプレ9 を HARA に見立てて段を掛けた(`research/318-deliberation/council-01-drafter.md:79-82`)が、その前提の取り違えが、裁定で落とされた実質の理由だと読む(裁定に理由は書かれていない。この読みは弁護の委員の推定)
- テンプレ9 の中の危うい決定は、既に別の席が持つ。SR2 以上の残留リスクの受容は R1 の決定であり、決裁者は 3.8.2 で特定する(`deliverable-templates.md:1737`)。受容の決裁という最も重い判断には、既に決裁の手続がある。そのうえに距離の段を重ねる根拠は、外部調査にも無い。ISO 12100 は機械の設計者のリスクアセスメントの手順であり、評価者の組織上の独立を定める規格ではない(本標準の 1.3 の参照の用途も「手順」に限る。`overview.md` 1.3 の表)

## R-4 記録・機械の検査・ADR

### 推す案

1. **q-criticality の記名と根拠**
   - 初期化の時点では名簿が無く、記名できる席が無い(内部 5.1)。そこで、初期化の回答には R-1 の理由の欄(最悪の帰結、1つ上の区分に当たらない理由、対策の前か後か)を必須とし、空なら初期化を完了しない
   - 判定者の記名と段1 の確認は、**最初のゲート判定より前**の変化点で埋める(案 h の置き場)。埋まるまでは、構成の冒頭に「CL の判定: 未確認」を表示する。G-1 の判定記録の材料に、判定の記録へのリンクを置く
2. **区分を下げる操作の根拠の記録の機械の検査**
   - 緩める向きの行(`generate-profile.mjs` の `AXIS_ORDER` による「区分を下げる。根拠の記録を要する」)に、ADR と受入基準の必須制約への参照を必須の値として持たせ、**参照先の実在**を機械で確かめる。中身の妥当性は人が確かめる
   - 参照が無ければ、その差分を ADR-0030 のいう「回答の書き換え」として扱い、構成の変更を通さない
3. **「R の判定に段を課さない」を、課さないと決めた事項として明記する**。#318 の弁護の委員の提案(`research/318-deliberation/council-05-defender.md:44`)が裁定にも ADR-0088 にも載らなかった穴を、本件で埋める。理由: R は変更ごとの判定で件数の単位が CL と違う(ADR-0039)。全変更に距離を掛けると 1〜9名の体制は全件が未達になる。課す根拠の測定が無い
4. **新しい ADR を1つ起こす**。ADR-0088「影響」の最終箇条の「決めていない事項」を決着させる。決定に含めるもの
   - CL の判定の記録(4つの欄)を全区分で必須にする
   - CL の判定の確認は段1 とし、CL の値から導かない
   - **CL の判定の確認に組織上の距離の段(段2 以上)を課さないと決めた**。理由を書く
   - テンプレ9 の要否は第6章の適用条件を正とする。承認の欄を足す。テンプレ9 の確認に距離の段を課さないと決めた
   - R の判定に段を課さないと決めた
   - 引き下げの記録の置き場の変更(ADR-0030 の要求事項1 を置き換える場合)
5. **EV**: 「段1 と記録で足りる」判断を `:::caution[暫定 EV-NNNN / 見直し 2027-10]` でマークする。水準は E0 に近い(外部規格の型からの類推で、本標準の案件での観測が無い)。見直しの時期は EV-0180 と揃える。差し替えの条件: (1) 内部監査で CL の判定の誤りが見つかった件数と、そのうち段1 の確認を経ていた件数 (2) ISO 26262-2 表1・IEC 61508-1 表4 の原文の照合で、判定の確認の独立の規定が本標準の CL0・CL1 の案件に当たるかの再判断
6. **IMPL**: 次を `state=undelivered` の実装マークで表示する。q-criticality の理由の欄と未確認の表示、引き下げの参照の実在の検査、テンプレ9 の要否の規則(4条件)、テンプレ9 の承認と SR4 の G-1 の前提条件の検査。降ろし先は `src/data/impl-targets.yaml` の既存の登録から選ぶ(新しい降ろし先が要るかは起案の委員が確かめる)
7. **#357 との関係**: 段1 の確認は「判定者と別の自然人か」で判定でき、#357 が設計する名簿の欄(直属の上長・部門・法人・リリースの権限)を要しない。本件は #357 の降ろしを待たずに降ろせる。#357 へは「CL の判定の確認者とテンプレ9 の確認者には段2 以上を課さないと決めたので、名簿の確認者の種類を増やす必要は無い」と書き置く。あわせて #357 の書き置きの番号の誤り(IMPL-0178・0338 → IMPL-0184・0344、ADR-0087 → ADR-0088)を訂正する
8. **附属書H に観点を足す**: 「CL の判定の記録の4つの欄があり、確認者(または未達の表示)があるか」「引き下げに4要求の記録があるか」。実施者は「案件に関与していない担い手」であり、距離の段とは別の独立を持つ。事後の検出の経路として名指す

### 理由

- 本件で欠けているのは距離ではなく、**記録・記名・確認の席そのもの**である(内部 6.0 の前提1・2)。距離の議論は、記名の席がある前提で初めて成り立つ。席の無いまま段を課せば、#357 の降ろしまで機械が確かめられるのは段1 だけであり(IMPL-0344 の注記、内部 4)、段の規範は表示だけの規範になる。席と記録を先に降ろすほうが、確かめられる範囲が広い
- 「課さないと決めた」と明記するのは、コアポリシー(却下は成果。書かれていないと課さないと決めたを区別する)による。ADR-0088 が「決めていない」と書いたままでは、採用者は段2 以上を求めるべきか読み分けられない
- 引き下げの参照の実在の検査は、ADR-0030 の要求事項2 が「これを欠くと、低減の根拠は次の反復で失われます」と書く要の部分を機械へ降ろすものである。人に求める文だけでは、内部 7 の確認点3(根拠が無くても通る)が残る

- 弁護の委員の推す一連の案は、**段2 以上を課す案と比べて、CL0・CL1 の低い判定の誤りを判定の時点で捕まえる力が弱い**。段1 の確認者は判定者と動機を共有しうる。この弱さを補うのは、理由の欄の具体性と事後の監査であり、どちらも効き目の観測が無い(**未実証**)。見直しの観測で、段1 を経た誤判定が見つかれば、段の議論を再開する。その条件を ADR の「影響」に書く
