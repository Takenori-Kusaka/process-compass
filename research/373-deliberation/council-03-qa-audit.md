# #373 会議体 委員意見: 品質監査(監査・品質保証部門の立場)

- 日付: 2026-11-05
- 立場: 監査・品質保証部門。低い判定で確認を逃れる循環、判定の根拠の記録、記名、機械で確かめられるかを重視する
- 入力: `council-00-agenda.md`、`survey-373-1-internal.md`(以下「内部」)、`survey-373-2-external.md`(以下「外部」)。条項は作業ツリーで読み直した行番号で引く(内部調査の行番号から第8章は約 20 行ずれている)
- 判断軸は信頼性。変更量の少なさを採否の理由にしない

## 監査の目から見た問題の芯(前置き)

監査は「記録に残っていない判断」を検証できません。現状の CL の判定は、次の3点で監査不能です。

1. 判定者が本文に無い(内部 2.2。`tailoring-guide.md:833-848` の軸E は基準と規則だけを持ち、誰が判定するかを書かない)
2. 初回の判定に根拠の記録が無い。引き下げには4要求(`tailoring-guide.md:937-944`)があるのに、最初から低く付けた判定は根拠も記名も残らない。ADR-0030 は「設計を変えた事実の記録がない引き下げは、回答の書き換えとして扱います」(`adr/0030-...:56`)と書くが、初回の回答には照らす記録が無い
3. プロセス内部監査の観点(附属書H H.3、`assurance-case.md` の観点1〜28)に、CL の判定の妥当性を問う観点が無い(内部 2.5)

しかも CL0 の判定は、委任・1〜2名の構成・S0 の G-6/G-7 の緩和・独立した安全性の評価・テンプレ9 をまとめて外す(内部 2.5、`tailoring-guide.md:851-860` の表)。**影響が最大の判定が、記録が最小**です。監査の側から言えば、この状態で「CL0 の案件」の保証の開示を受け取っても、何を保証しているかを説明できません。

## R-1 CL の判定の確認を求めるか、誰が、どの段で

### 推す案

次の4つを一体で採る。内部調査の (e) を全区分の土台に置き、(d) ではなく判定とは別の入力で段を上げる形(外部の型B)を重ね、(f)・(g) を事後の検出と開示に使う。

| # | 内容 | 外部の型 |
| --- | --- | --- |
| R1-a | **判定の記録を全区分で必須にする**(CL0 を含む)。欄は、判定者の記名、想定した最悪の帰結、**1つ上の区分に当たらない理由**、構成要素ごとの判定(最も高い区分を全体とする規則の適用の跡)、附属書F F.2 の適用の判定と切り分けの根拠。最悪の帰結は**リスク低減の設計を入れる前**で書き、設計で下げた分は引き下げの4要求の記録として別に書く | 型E(FDA §V・§VI.A) |
| R1-b | **確認者を、判定の結果に依らず置く**。判定の記名者と別の自然人(段1 以上)が確認し記名する。AI の確認は数えない。この段1 は CL0〜CL3 のすべてで同じ | 型A の形(結果に依らない値)を、内部で届く段で採る |
| R1-c | **確認の段を、判定とは別の入力で上げる**。次の入力が「はい」で、かつ判定がそれより低い場合に限り、確認者の段を上げる。(1) 物理的な危険源を持つ機器・設備を制御する(テンプレ9 適用条件1、附属書F F.2 の Q1)のに CL2 以下と判定 → 段3 以上。(2) 規制業・適合性評価の対象の候補に当たるのに CL1 以下と判定 → 段2 以上 | 型B(IEC 61508-1 表4 の構造。未確認の前提あり) |
| R1-d | **記録の無い判定は判定として扱わない**。記録または確認の記名が無い間、G-1 の審議を開始しない(機械で確かめる)。確認者がいない体制は確認を「未達」と表示する(R-2) | 型D の変形 |

判定者は、変化点で区分を決める者と同じ D-0 表1「体制と運用形態」の決定者とする(`tailoring-guide.md:87` の緩める向きの決定者、`template/.claude/skills/process-change/kinds/axis.md` の `decidedBy`)。初回と変化点で判定者が違うと、監査で記名の権限を照らす先が2つになる。

### 理由(所在つき)

1. **循環を断つには、確認の要否と段を判定の結果から導いてはならない**(内部 6.3)。R1-b は段1 を結果に依らず置くので、CL0 と判定しても確認を逃れられない。R1-c は CL ではない入力で段を上げるので、CL を低く付けても段は下がらない。外部の調査の範囲で「低い判定だから確認が要らない」とした規格は見つかっていない(外部 7)
2. **記録の欄が「上の区分に当たらない理由」であること**が監査上の要点である。「CL0 である理由」は「社内ツールだから」の一行で埋まる。「CL1 の基準(個人の権利・利益への実質的な影響、`tailoring-guide.md:839`)に当たらない理由」は、否定すべき対象が決まっているので、監査が中身の有無を判定できる。FDA は Basic でも判定と理由を必須欄にし、文書の無い機器にまで「Rationale … Outcome」を書かせる(外部 2.2、付録 A 例1)
3. **対策前の帰結で書かせる**のは、ADR-0030 の区別(設計による引き下げと回答の書き換え)を初回の判定にも及ぼすためである。初回から「取り消せるから CL0」と書けば、引き下げの4要求(受入基準の必須制約、`tailoring-guide.md:942`)を経ずに同じ結果が得られる。これが現状の抜け道で、FDA の "assessed prior to implementation of risk control measures"(外部 2.2 §V)はこの抜け道を塞ぐ規定である
4. **R1-c で段を上げるのは「外れたものが重い」場合に限る**。物理的な危険源の制御は、本標準が附属書F を規定にした理由そのもの(`safety-verification.md:8`)であり、そこで CL3 未満と判定することは、ISO 26262 で HARA の結果が QM でも I3 で確かめる場面に当たる(外部 1。翻訳草案での一次)
5. **機械で確かめられる**。R1-a の欄の有無、R1-b の記名者と判定者が名簿の別人であること(IMPL-0080 と同じ段1 の照合)、R1-c の入力と判定の組み合わせ、R1-d の G-1 の前提条件は、いずれも構成と記録の存在の照合で判定できる。段2・段3 の判定は #357 の名簿の欄を待つ(R-4)

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| (a) 全区分に最上段(型A を I3 相当で) | 1〜2名と 3〜9名の体制のほぼ全件で確認が恒常的に未達になる(`tailoring-guide.md:216-226` 軸A の内部で届く段)。**常に点灯する未達の表示は情報を運ばず、監査の抽出条件にも使えない**(未実証)。段の高さより、記録の中身を監査が照らせることを先に確保する方が、信頼性に効く |
| (b) 求めない | 循環が残る。採るなら「課さないと決めた」と書く必要があるが、ADR-0030 のコンテキストが名指した誘因(実態は CL1 のまま回答を CL0 へ書き換える)を承知で残す理由が見つからない |
| (c) CL0 の判定にだけ確認を求める | 「上位は下位を包含する」(`tailoring-guide.md:845`)を崩す。CL1 と判定して CL2 の要求(テンプレ9・附属書F・独立した安全性の評価)を逃れる経路も同じ構造であり(内部 3.2、#318 起草の委員)、CL0 だけ塞いでも循環の半分が残る |
| (d) 外す側の区分が求める段 | 段を結果(判定 CLn)から導くので、循環を完全には断たない。CL1 と判定すれば段2、CL0 と判定すれば段1 で済むので、**CL0 と判定することが最も確認を軽くする**。影響が最大の CL0 の判定が最も弱く確かめられる形は、監査の立場で採れない。加えて CL1 の判定に一律に段2 を課すと、CL2 の要求が本来かからない CL1 の 3〜9名の案件が外部の確認者なしでは未達のまま出荷できなくなる(ADR-0028)。この重さを正当化する測定が無い |
| (f) 事後の検出のみ | 監査は四半期であり(`assurance-case.md:997`)、判定の誤りを見つけたときには G-1 以降の成果物が CL0 の前提で作られている。事後の検出は判定時の確認の代わりにならない。**併用として採る**(R-4) |
| (g) 開示のみ | 開示は確認が無いことを読めるようにするだけで、確認そのものを生まない。**併用として採る**(R-2・R-4) |
| (h) 置き場を G-1 にする | 単独の案ではなく R1-d の置き場として採る。初期化の時点では名簿が無く記名できない(内部 5.1)ため、確定を「最初のゲート判定より前」の変化点に置く |

### 条件と留保

- R1-c の段(段3・段2)と入力の選び方は、ISO 26262 の表1・IEC 61508-1 表4 の構造からの類推で、**未実証**。EV-0180 と同じ制約(原文未読)を受ける。新しい EV でマークし、差し替え条件を「確認で判定が上がった件数・確認者が指摘した件数の観測」とする
- R1-c の入力そのもの(物理的な危険源の有無、規制業)も自己申告であり、循環は残る。ただし CL の判定より客観的な事実の質問で、偽ると事実の虚偽になる。残る循環は R-4 の監査の観点で拾う。**入力の自己申告を誰が確かめるかは解いていない**と明記する
- R1-b の段1 は「別の自然人である」ことしか保証しない。確認の中身の質は保証しない。確認者が見る観点(上の区分の基準を1つずつ否定できているか、構成要素の列挙に漏れが無いか)を様式に固定し、確認者が自分の言葉で書く欄にする(AI に生成させない。`gate-criteria.md:109` と同じ扱い)
- 対象は CL の判定と附属書F F.2 の切り分けに限る。テンプレ9 は R-3 で別に扱う(テンプレ9 は製品の HARA ではない。内部 2.4)

## R-2 1〜2名の体制と、組織の外の確認者

### 推す案

| # | 体制 | 扱い |
| --- | --- | --- |
| R2-a | 2名 | 判定の記名者でない側の人が確認する(段1)。内部で届く(`tailoring-guide.md:220` 軸A「2名: 段1」)。**確認を省略へ倒さない** |
| R2-b | 1名 | 確認者がいない。外部の確認者(名簿へ登録した、判定の記名者と別の自然人)を置ければ確認とする。置けなければ、判定の確認を**未達**として表示する。CL0 で R1-c の入力に当たらない案件は、ADR-0028 の型どおり、未達のまま G-8 の受容で出荷できる |
| R2-c | 1〜2名で R1-c の入力に当たる(物理的な危険源の制御、規制業の候補) | 確認の段(段2・段3)は内部で届かないため外部から調達する。**届かない間は出荷しない**。CL1 以上の未達と同じ扱いにする |
| R2-d | 全体制 | 保証の開示に「CL の判定: 判定者 / 確認者 / 段 / 未達の別」を出す(内部 (g)。準拠テンプレートの保証の開示の項目7、`template/scripts/gate/aggregate-evidence.mjs:4536-4542` の人の照合を、記録の照合へ置き換える) |
| R2-e | 全体制 | 判定の記録の欄(R1-a)は、確認者の有無に依らず必須。記録の無い判定は R1-d により G-1 を開始させない。**理由の欄を空で通す既定値を置かない** |

### 理由(所在つき)

1. **「確認者がいない」ことと「確認しなくてよい」ことを分ける**のが ADR-0028 の型である(未達と省略の区別)。1名の CL0 で判定の確認を省略として扱えば、この体制で CL0 の判定が誤っていても、記録の上は何も欠けていない状態になる。監査は欠けていないものを抽出できない
2. **2名の体制を R2-b と同列に扱わない**。2名なら段1 は内部で届く。届くものを未達にも省略にもしない。ADR-0030 が個別審査を退けた理由は「1〜2名の体制に審査の相手がいない」(`adr/0030-...:65`)だが、2名の体制には判定の記名者と別の人がいる。審査制(可否を他人が決める)ではなく、記録への確認の記名であり、ADR-0030 の退けた案と同じではない
3. **R2-c で出荷を止める**のは、R1-c の入力に当たる案件の CL0 の判定は、規格の型で言えば最も遠い確認が要る判定であり(外部 1、ISO 26262 の HARA は QM でも I3)、ここで自己受容による出荷を認めると、低い判定 → 確認の未達 → 自分で受容、の循環が1人の中で閉じるからである。G-8 の受容者が判定者と同じ人である限り、受容は確認の代わりにならない
4. **開示を記録から出す**。現状の項目7 は「構成の安全重要度」を表示するだけで、判定を誰が確かめたかを読めない(内部 5.3)。受け入れる側(発注者・利用者)が CL0 の主張の重さを判断する材料は、判定の確認の有無しかない

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 1名の CL0 にも外部の確認者を必須にし、無ければ出荷させない | ADR-0028 が退けた「1〜2名の利用を想定から外す」(`adr/0028-...:53`)と同じ帰結になる。個人開発の入口を閉じると、標準そのものが試されない。R1-c に当たらない CL0 の案件では、未達の開示と事後の監査で足りると判断する(未実証) |
| 確認の相手がいない体制では、未判定を最上位(CL3)とみなす(型D の直訳) | 1〜2名で CL1 以上は初期化で拒否される(`tailoring-guide.md:965`)。最上位の既定値は、記録を書いた1名の利用者まで拒否する。既定値が働くべきは「記録が無い」場合であり、「確認者がいない」場合ではない。前者は R1-d で G-1 を止めて扱う |
| 理由の欄の必須化だけで確認者を求めない(型E のみ) | FDA・EASA の型は、理由を当局が審査することを前提にしている(外部 7 の推測)。外部の審査者のいない本標準の案件では、理由の質を確かめる者がいないまま「書いた」ことだけが残る。欄の必須化は R2-e として採るが、確認の代わりにしない |
| 1名が時間を置いて自分で再確認する(冷却期間の自己確認) | 同じ自然人であり、段1 の定義(別の自然人、`overview.md:184`)に当たらない。確認に数えると、段の定義そのものが崩れる |
| AI に判定を点検させ、確認に数える | ADR-0088 決定2(AI の確認はどの段にも数えない)と矛盾する。AI による点検は確認者の材料としては使ってよいが、確認の記名にはならない |

### 条件と留保

- R2-c の「出荷しない」は、R1-c の入力の選び方に依存する。入力を広く取りすぎると、1〜2名の CL0 の多くが出荷不能になる。入力は「物理的な危険源の制御」と「規制業の候補」の2つに限り、件数の観測で見直す(**未実証**。新しい EV で開示する)
- 外部の確認者に段1 を超える要件(資格・利害の無いこと)を課すかは決めていない。R1-c に当たらない案件では段1 で足りるとし、資格は求めない(ISO 26262 も評価者の資格証を求めない、外部 6。二次の抜粋)
- 名簿へ外部の確認者を登録する欄は #357 の範囲である(R-4)

## R-3 テンプレ9 の要否と確認

### 推す案

| # | 内容 |
| --- | --- |
| R3-a | **要否の正は第6章の4条件とする**(`deliverable-templates.md:1678-1689`)。軸E の表の行(`tailoring-guide.md:854`)の CL0・CL1「不要」を、「第6章の適用条件に該当すれば必須(G-1 の前提条件)」へ改める。CL2・CL3 は条件に依らず必須のまま(`tailoring-guide.md:922`「CL2 以上 × 安全リスクアセスメントの省略: 許容しない」と整合) |
| R3-b | 規則データ(`src/data/tailoring/rules-criticality.yaml:42-50` の `r-e-cl2` だけが `safetyRiskAssessment: required` を立てる)に、4条件を見る規則を足す。構成に入力の無い条件(本番環境への到達など)は入力を足すか、入力が無い間は「該当の有無を未判定」として G-1 の注記に出す |
| R3-c | 様式に**承認の欄**(承認者の記名・日付・承認した版)を置く。承認者は作成者(技術判断者、`lifecycle.md:288`)と別の自然人(段1)。AI の名義を受け付けない |
| R3-d | **テンプレ9 の確認に段2 以上は課さない**と決め、その旨と理由を明記する |
| R3-e | 軸E の「設計によって区分を下げる」要求1 の記録先(CL2 以上はテンプレ9、`tailoring-guide.md:941`)を、R1-a の CL の判定の記録へ移す(全区分で同じ置き場)。テンプレ9 には製品の危害を書く欄が無い(内部 2.4 X-b) |
| R3-f | `lifecycle.md:310-312`(SR4 が残る案件は G-1 を開始しない、前提条件の充足は機械的な検査で判定する)に、今は実装の印が無い(内部 5.2)。`state=undelivered` の実装マークを付けて台帳へ出す |

### 理由(所在つき)

1. **テンプレ9 の対象は AI エージェントの危害で、その大きさはエージェントの構成で決まる**(`deliverable-templates.md:1656-1658`)。本番に到達できる L2 のエージェントは、社内ツール(CL0)の案件でも本番のデータを壊せる。CL0 だから不要とする軸E の表は、危害の源(エージェントの権限)と判定の尺度(製品の最悪の帰結)を取り違えている。第6章の4条件の方が対象に合う
2. **食い違いを放置すると、監査はどちらに照らすかを決められない**。現状、CL0 で L2 以上の案件は、第6章では必須、軸E と規則データでは不要で、準拠テンプレートの構成にはテンプレ9 の要求が現れない(内部 5.2 補足)。採用組織が規則データに従うほど、本文の要求事項に反する。検査が黙って通すのは監査上最悪の形である
3. **承認の欄が無ければ「承認済みの本表」(`deliverable-templates.md:1689`)を確かめられない**。G-1 の前提条件を機械的な検査で判定するという規定(`lifecycle.md:312`)が、確かめる対象の欄を持たない。欄があれば、承認の記名の有無・承認者と作成者が名簿の別人であること・承認した版が現行の版であることを機械で照合できる
4. **R3-d で段を課さない理由**: (1) テンプレ9 は製品の HARA ではなく、ISO 26262 表1 の HARA の I3 の類推が当たらない(内部 2.4 X-c)。外部調査は開発に使うエージェントの危害評価に独立の距離を課す規格を挙げていない(外部 6)。(2) テンプレ9 の重い帰結(SR2 以上の残留リスクの受容)は R1 の決定として 3.8.2 の決裁者が受ける(`deliverable-templates.md:1737`)。受容の判断はすでに別の者に置かれている。(3) 製品の安全側の距離は R-1 の CL の判定の確認と、ADR-0088 の独立した安全性の評価が担う。#318 の起草の委員の案(テンプレ9 の確認者を評価者と同じ段以上、`research/318-deliberation/council-01-drafter.md:79-82`)は、テンプレ9 を製品の安全評価と読んだ前提に立つため採らない
5. **R3-e** は X-b の解消である。製品の最悪の帰結を下げた根拠を、製品の危害の欄の無い様式へ書かせると、監査は根拠の欄を特定できない。R1-a の記録には「最悪の帰結(対策前)」の欄があり、引き下げの前後をそこに並べられる

#### R4-d 「R の判定に段を課さない」の明記

- **採る**。課さないと決めたこととして新しい ADR の「検討した選択肢」と本文に書く
- 理由: (1) R は変更ごと、CL は案件ごとで単位が違う(ADR-0039)。HARA の類推が当たるのは案件ごとの CL の判定である。(2) R の判定にはすでに確定者の記名と区分の下限の規則があり、G-6 の PR 単位の検査が照合する(`roles-responsibilities.md:957`「区分の下限と確定者」、`gate-criteria.md:760-762`)。判定を低く付ける循環は、下限の規則(判定とは別の入力)で塞がれている。(3) 変更ごとに距離の段を課すと、1〜9名の体制は全変更が未達になる(#318 擁護の委員、`research/318-deliberation/council-05-defender.md:44`)
- 留保: 理由(2) は下限の規則が R1 の変更種別を漏れなく列挙していることを前提にする。列挙の網羅性は**未実証**
