# #373 会議体 委員の意見: 規格(ISO 26262-2 表1・IEC 61508・IEC 62304・FDA・EASA AMC 20-115D・EN 50716 との整合)

- 日付: 2026-11-05
- 立場: 外部規格との整合を重視する。判断軸は信頼性。変更量の少なさは理由にしない
- 入力: `council-00-agenda.md`、`survey-373-1-internal.md`(以下「内」)、`survey-373-2-external.md`(以下「外」)、標準の本文、ADR、`research/318-deliberation/`
- 読みの区分の注意: ISO 26262-2 表1 は GB/T 34590.2 の意見募集草案(SRC-0675、`partial`)で読んだもので、EV-0180 と同じ制約を受ける(内 76行)。IEC 62304・IEC 61508・EN 50716 は二次または記憶に依る(外 52-64行、115-127行、131-141行)。一次で読めたのは FDA ガイダンス(外 66-88行)と EASA AMC 20-115D(外 92-111行)だけである

## 先に置く読み: 規格の「低い判定」には2種類ある

外部の規格を本件へ当てる前に、区別しておくべきことがあります。

1. **安全の範囲の中での低い判定**: ISO 26262 の QM は、道路車両の E/E システムという安全の範囲に入った item の中で、ハザードに ASIL を付けない判定である。表1 はこの判定を含む HARA の確認レビューを、QM の列でも I3 とする(外 25-34行)
2. **安全の範囲に入るかの判定**: EN 50716 の Basic Integrity(外 135-140行)、DO-178C の Level E、IEC 62304 の適用の有無は、ソフトウェア側の規格の外(システム側の工程、または規制当局)で決まる。ソフトウェアの規格の内側には、この判定を独立の評価者が確かめる仕組みが無い(外 140行、103-104行)。FDA は判定者を申請者とし、確かめるのは当局の審査である(外 80-84行)

本標準の CL0(「経済的な損失や業務の中断にとどまる」、`tailoring-guide.md:838`)は、2 の「安全の範囲に入らない」判定に近い。一方で、F.2 Q1「対象に人身への危害が生じうる制御があるか」(`safety-verification.md:38`)が「はい」の案件で CL を低く付けるのは、1 の QM に近い。**ISO 26262 表1 の「QM でも I3」を、CL0 のすべての判定へ移すのは類推の取り違えになる**。逆に「CL0 は安全の範囲の外だから確認が要らない」とするのも誤りである。調べた規格はどれも、最も低い判定を確認の外に置かない(外 168行)。範囲の外の判定は、別の主体(システム側の工程・当局)が確かめている。本標準の想定する案件には当局がいないことが多いため、その代わりを組織の中に置く必要がある(外 88行)。

## R-1 CL の判定の確認を求めるか、誰が、どの段で

### 推す案

次の4つを組み合わせて採る。内部調査の案 (d)(境界の確認)を基礎にし、F.2 Q1 が「はい」の案件にだけ型A(結果に依らない最上段)を重ねる。

1. **判定記録をすべての CL で必須にする(CL0 を含む)**。欄は次のとおり
   - 判定者の記名
   - 想定できる最悪の帰結。**設計による低減の前**の帰結で書く
   - 1つ上の区分(CL0 なら CL1、CL1 なら CL2、CL2 なら CL3)に当たらない理由
   - F.2 Q1 の回答と根拠。「はい」なら F.2 の切り分けの範囲と根拠(`safety-verification.md:52-61`、218行)
   - 適合性評価・第三者認証の対象かどうかの確認の結果(CL2 の判定基準そのもの。`tailoring-guide.md:840`)
2. **判定者を、D-0 表1「体制と運用形態」の決定者とする**。区分を変える変化点の決定者(`tailoring-guide.md:87`、内 95行・193行)と同じ者を、初回の判定にも当てる
3. **確認の段を、判定の結果ではなく「判定によって外れる区分」が求める段で決める**(案 d)
   - CL0 と判定する(CL1 を外す)ときの確認: 段1(判定者と別の自然人)。CL1 は段を求めないため
   - CL1 と判定する(CL2 を外す)ときの確認: 段2 以上。CL2 の独立した安全性の評価が段2 を求めるため(`tailoring-guide.md:856`)
   - CL2 と判定する(CL3 を外す)ときの確認: 段3 以上。CL3 が段3 を求めるため(同)
   - CL3 の判定: 外す区分が無い。ただし下記 4 が掛かる
   - 区分を設計で下げる場合(`tailoring-guide.md:926-941`)も、下げた先の区分の判定として同じ規則で確かめる
4. **F.2 Q1 が「はい」の案件では、CL の判定・F.2 の切り分け・設計による区分の引き下げの確認を、判定の結果に依らず段3 以上とする**(型A。ISO 26262-2 表1 の HARA の行と同型)

AI の確認はどの段にも数えない(ADR-0088 決定2 と同じ。`overview.md:118`)。理由を書いて低い段で代える経路も置かない(同、`tailoring-guide.md:225`)。

### 理由

- **循環を断つ条件を満たす**: 確認の段を判定の結果(CL)から導くと、低く判定すれば確認も弱くなる(内 249-250行)。案 d は「外れる区分の要求」で段を決めるため、CL1 と判定して CL2 の段2 を逃れるには、段2 の者の確認が要る。**守られている扉と同じ強さで、扉を開けない判定を確かめる**ことになる。ADR-0088 が CL2 に段2、CL3 に段3 を課した以上(内 22-26行)、その要求を段1 以下の者の判定だけで外せる状態は、ADR-0088 の段を無効にする
- **型B と同じ構造である**: IEC 61508-1 は、全体の安全ライフサイクルの段階 1〜8 の評価の独立性を、判定した SIL ではなく結果の重大さで決める(表4、8.2.18。外 116-123行、二次)。判定に使う尺度とは別の尺度で確認の強さを決める点が案 d と同じである。ただし段階 3(ハザードとリスクの分析)が表4 の対象に入るかは未確認(外 123-124行)
- **F.2 Q1 の「はい」は、ISO 26262 の安全の範囲に入った item に当たる**: 人身への危害が生じうる制御を含む案件で CL を付けることは、ISO 26262 の HARA で ASIL を付けること(QM を含む)と同じ位置にある。この範囲では、表1 は QM でも I3 とする(外 25-34行)。本標準の段3(組織上独立)は、I3 の「管理・資源・リリース権限で作成部門から独立」(外 22行)と軸が一致する(`overview.md:118`)
- **低い判定にも理由の欄を必須にするのが規制当局の型である**: FDA は Basic Documentation を選ぶときにも区分の記述と理由を求め、ソフトウェアを含まない機器にさえ「Rationale / Outcome」を書かせる(外 76行、79行。一次)。判定はリスクコントロール措置の**前**のリスクで行う(外 72行)。欄 1 の「低減の前の帰結」はこれに倣う。設計で下げた後の区分は、ADR-0030 の4要求の経路(`tailoring-guide.md:926-941`)で別に記録する。IEC 62304 が「クラスを下げられるのはソフトウェアの外の手段だけで、その実装と有効性の検証が要る」とする読み(外 55行、二次)とも整合する
- **判定を開発から切り離す航空の型(型C)の、組織の中での代わりになる**: AMC 20-115D ¶9.b.2 は、ソフトウェアレベルをシステム安全評価が割り当てるとする(外 98行、一次)。ソフトウェア側が自分のレベルを決めない。本標準の採用者に別の工程を持つ組織は少ないため、「判定者と別の、外れる区分の段の者が確かめる」で代える
- **CL0 の判定の誤りの帰結が最も大きい**: CL0 は委任・1〜2名の構成・S0 の緩和・評価と段の不要・テンプレ9 の不要をまとめて開く(内 136行)。それなのに判定者・確認者・根拠の規定が無い(内 88-96行)。初回の判定の根拠が残らないため、誤った初回の判定を検出する経路も無い(内 129-134行)
- **「上位は下位を包含する」(`tailoring-guide.md:845`)を崩さない**: 判定記録と確認はすべての CL に掛かり、CL が上がるほど段が上がる。CL0 にだけ確認を置く案 (c) と違い、上位が下位の要求を欠く升ができない

### 条件と留保

- **未実証**: 案 d の段の割り当て(外れる区分の段で確かめる)は規格の構造からの類推であり、本標準の案件での観測は無い。ADR-0026 のマーク(新しい EV、水準 E1)で開示する。差し替え条件は、ISO 26262-2 表1・IEC 61508-1 表4・EN 50126-2 の原文の照合と、確認で見つかった判定の誤りの件数の観測
- **未確認**: IEC 61508-1 表4 の対象に段階 3(ハザードとリスクの分析)が入るか(外 123行)。入らないと分かっても、型B の根拠を失うだけで、循環を断つ論理(ADR-0088 の段を無効にしない)は残る
- **未確認**: ISO 26262-3 の HARA の節に「全ハザードが QM でも HARA を作り確認に付す」旨の文言があるか(外 37行)
- 留保: CL1 と判定する案件(3〜9名が多い)は、段2 の確認者を内部に持たないことが多い(`tailoring-guide.md:222`)。CL1 の未達は出荷しない(`tailoring-guide.md:875`、ADR-0028)。現場の委員の見積り(CL1 の採用者のうち外部の確認者が要る割合)を見てから、未達の扱い(出荷を止めるか、判定の確定を止めるか)を決めること。ここで負担を理由に段を下げることは推さない。下げるなら、段2 の要求を段1 の判定で外せることを承知した理由が要る
- 留保: 欄 1 の「適合性評価の対象かどうか」は、法令の該当の判断であり、本標準が判定の基準を与えられない。確認の結果と、確かめた法令・規格の名を書かせるに留める

## R-2 1〜2名の体制と、組織の外の確認者

### 推す案

1. **1〜2名の体制にも、R-1 の判定記録と確認を免除しない**。型は変えない(`tailoring-guide.md:234` の「1〜2名の体制でも、型は変えません」と同じ方針)
   - 2名: CL0 の判定の確認(段1)は、判定者でない側の人が担える(`tailoring-guide.md:220`)。内部で満たせる
   - 1名: 段1 は内部で届かない(`tailoring-guide.md:219`)。外部の確認者を人の名簿へ登録して満たす。登録の無い間は、CL の判定の確認を**未達**として表示する
2. **未達の扱いは ADR-0028 による**。CL0 の案件は、未達を構成書の冒頭・出荷判定の証跡・品質レポートへ載せ(ADR-0028 決定2・3)、G-8 の受容で出荷できる。CL1 以上は 1〜2名の構成そのものを認めない(`tailoring-guide.md:226`、247行)ため、1〜2名で確認の未達が出荷を止める升は生じない
3. **理由の欄は必須にするが、確認の代わりにしない**。判定記録の「1つ上の区分に当たらない理由」は、1名の体制でも書く。理由を書いたことを、確認の未達の解消として扱わない(ADR-0028 決定6、ADR-0088 決定2「理由を書いて低い段を選ぶ経路は置かない」)
4. **外部の確認者の要件は段だけで定め、資格証を求めない**。登録には、判定者からの段とその根拠(指揮系統・資源・リリースの権限の3つ。`overview.md:118`)を書かせる
5. **保守側の既定値**: 判定記録と確認の欄が空の構成を、確認済みとして読まない。1名の体制で外部の確認者を登録していなければ、空欄ではなく「未達」と表示する(ADR-0028 決定4「未記入は未記入として表示する」)
6. **開示**: 保証の開示(出荷の証跡の集約の項目7、内 132行・209行)に、「CL の判定: 判定者 / 確認者 / 段 / 未達」を出す。受け入れる側と出荷判定者が、CL0 の判定を誰がどの距離で確かめたかを読めるようにする

### 理由

- **I3 相当を社内で満たせない組織は、外部へ委ねるのが規格の実務である**: ISO 26262 の I3 は、社内に別部門の無い小規模な供給者では外部の評価機関が担う(外 46行、推測として記載。外 176行)。DNV など第三者が HARA のレビューを提供している(外 45行、本文未読)。EN 50716 の評価者は顧客・供給者・第三者のいずれでもよい(外 160行、#318 のメモ、二次)。規格は「確認の相手がいないなら確認しなくてよい」とは書かない
- **人数の下限は規格に無い**: 判定の確認に関わる人数の下限を課す規格は、読めた範囲に無い(外 162-163行)。要るのは距離であり人数ではない。1名の体制を、人数を理由に確認の外へ出す根拠は規格側に無い
- **当局のいない案件で、当局の代わりになる最小の者を置く**: FDA・EASA は、申請者の判定を当局の審査・PSAC の合意で確かめる(外 83行、110行)。本標準の CL0 の案件には当局がいない。1名の体制で、判定を判定者以外の誰も読まない状態を、規格は想定していない
- **ADR-0030 との緊張は、未達の表示で解ける**: ADR-0030 は「引き下げの可否を個別の審査制にする」案を「1〜2名の体制に審査の相手がいない」として退けた(`adr/0030-criticality-reduction-by-design.md:65`)。退けたのは、**審査の通過を引き下げの条件にする**形である。推す案は、確認が届かないことを未達として表示し、CL0 なら G-8 の受容で出荷を許す。判定の可否を審査に掛けないため、ADR-0030 の却下の理由に当たらない。ただし ADR-0030 の「要求事項を満たしたかどうかを記録で検証する形にした」(同 65行)の記録が、確認者のいない記録で足りるとは書かれていない。新しい ADR で、ADR-0030 の4要求の記録にも R-1 の確認が掛かることを補う
- **ADR-0014 決定10 との緊張**: 決定10 は摩擦を「CL2 以上または R1 に関わる判定へ限定」する(`adr/0014-criticality-axis-and-proposal-output.md:43`)。CL の判定は、その摩擦をどこへ掛けるかを決める判定であり、決定10 の「判定」の集合の外にある(内 232行)。摩擦を掛けないと、決定10 の限定そのものが確かめられない入力の上に立つ。新しい ADR で、決定10 の限定は CL の判定に及ばないことを明記する

## R-3 テンプレ9 の要否と確認

### 前提の確認

テンプレ9 は、開発に使う AI エージェントが引き起こしうる危害の評価である(`deliverable-templates.md:1656`、内 106行)。ISO 12100 の手順を参照した本標準の規定で、適合を主張しない(ADR-0011 決定1。参照先は ADR-0043 で IEC 61508 と ISO/TR 14121-2 の併記)。製品の HARA ではない。**ISO 26262-2 表1 の HARA の行を、テンプレ9 へ直接に当ててはならない**。HARA の類比が当たるのは R-1 の CL の判定と F.2 の切り分けである(内 123行)。

### 推す案

1. **要否は第6章の4条件を正とし、軸E の表を誤りとして直す**(X-a)
   - 軸E の表「安全リスクアセスメント(テンプレ9)」の行(`tailoring-guide.md:854`)を、「CL0・CL1: 第6章の適用条件による / CL2・CL3: 必須(適用条件に依らない)」へ改める
   - 規則データ `rules-criticality.yaml` の `r-e-cl2`(内 212行)は CL2 以上の必須として残し、第6章の4条件(物理的な危険源・R1 の変更種別・本番到達・L2 以上。`deliverable-templates.md:1683-1687`)から要否を導く規則を足す
2. **テンプレ9 の様式に承認の欄を置く**(承認者の記名・日付・版)。承認者は作成者(技術判断者。`lifecycle.md:288`)と別の自然人とし、段1 とする。承認者の席は G-1 の判定者(事業決裁者。`lifecycle.md:290`)を既定にする案を推す。ただし席の選び方は起案の委員の案と突き合わせる
3. **テンプレ9 の確認に、R-1 の段を重ねるのは次の部分だけとする**: テンプレ9 が**区分の引き下げの根拠**(RRS1、`tailoring-guide.md:941`)を持つ場合、その部分の確認は R-1 の規則(外れる区分の段)による。テンプレ9 の全体(エージェントの危害の評価)には段2 以上を課さない
4. **製品の区分の引き下げの記録の置き場を、テンプレ9 から CL の判定記録(R-1)へ移す**(X-b)。テンプレ9 には製品の危害の欄が無い(内 122行)。ADR-0030 決定1(CL2 以上は安全リスクアセスメントへ記録)は、新しい ADR で置き換える

### 理由

- **第6章の4条件は、判定の結果に依らない属性で要否を決める**: 条件は、エージェントの到達範囲・自律レベル・変更種別・物理的な危険源という、案件の CL とは別の入力である。R-1 の循環の議論(内 250行の (3)「判定とは別の入力」)と同じ構造で、CL0 と判定することでテンプレ9 を逃れる経路を作らない。型B(判定とは別の尺度で決める。外 148-149行)に当たる
- **軸E の表の CL 依存には、決定の記録が無い**: テンプレ9 を扱う ADR(ADR-0011・ADR-0043・ADR-0030・ADR-0088)のどれも、CL0・CL1 でテンプレ9 を不要とすると決めていない。ADR-0088 は本論点を「決めていない事項」とする(`adr/0088-organizational-distance-steps-and-cl1-stage-relaxation.md:222`)。第6章の4条件は規範の本文であり、軸E の表はそれを狭めて写した表と読める。どちらが誤りかの判定は、記録のある側(第6章)を正とする
- **危険源はエージェントの側にあり、製品の CL では下がらない**: 本番に到達できる L2 以上のエージェントの危害(情報・資産・権利の損失)は、製品が CL0 でも起こる。IEC 61508 が評価の独立性を判定した SIL でなく結果の重大さで決める考え方(外 121-123行、二次)とも、製品の区分で要否を決めない点で合う
- **「承認済みの本表」を前提条件にする以上、承認の記録が要る**: 第2章は承認済みの本表を G-1 の前提条件とし、充足を機械的な検査で判定すると定める(`lifecycle.md:309-312`)。様式に承認の欄が無いと、検査が確かめる対象が無い(内 201-202行)。FDA が「リスクマネジメントファイルが適切な者に評価されたこと」を示させる(外 78行、一次)のと同じく、評価が誰に読まれたかを記録に残す
- **テンプレ9 全体に段2 以上を課さない理由**: エージェントの危害の評価の確認に距離の段を課す外部の規格は、読めた範囲に無い。#318 の起案の委員の案(テンプレ9 の確認者に CL2・CL3 で評価者と同じ段。内 155行)は、テンプレ9 を HARA と同じ位置に置いた前提に立つ。その前提は、テンプレ9 の対象がエージェントの危害であることと合わない。ただし引き下げの根拠を持つ部分は、製品の区分を外す判定そのものなので、R-1 の段を掛ける(推す案の 3)
- **置き場を移す理由**: ISO 26262 は HARA と後段の成果物を分け、確認の強さを成果物ごとに変える(外 26-29行)。製品の区分の引き下げの根拠を、製品の危害の欄を持たない様式に置くと、確認の強さ(R-1 の段)を成果物の単位で掛けられない

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 軸E の表を正とし、第6章の4条件を CL2 以上へ狭める | CL0 と判定するだけでテンプレ9 を逃れる循環を新しく作る。エージェントの危害は製品の CL で下がらない。狭める決定の記録も無い |
| テンプレ9 の確認に、CL2・CL3 で評価者と同じ段を全体に課す(#318 の起案の委員の案) | 上記の理由。テンプレ9 は HARA ではない。引き下げの根拠の部分に限って段を掛ければ、循環は断てる |
| 承認の欄を置かず、G-1 の判定記録が読んだことで足りるとする | G-1 の判定記録は G-1 の前提条件の充足を確かめる側であり、前提条件(承認済みの本表)を満たす記録にならない。前提条件と判定を同じ記録にすると、前提条件が判定の中へ溶ける |

   - 未確認: ISO 26262-2 表1 の「影響分析」の行が、item の水準の影響分析(既存の item を改変するときのライフサイクルのテーラリング)か、変更要求ごとの影響分析(ISO 26262-8 の変更管理)か。後者なら、表1 は変更ごとの判定にも I3 を課していることになり、(ii) は崩れる。原文の照合を差し替え条件とする
   - 本標準で item の水準の影響分析に当たるのは、変化点5(安全重要度の入力の変化)の後の再テーラリング(`tailoring-guide.md:86`)である。これは R-1 の判定記録と確認の対象に含める

   - X-a の判定(第6章が正、軸E の表が誤り)

7. **#357 との関係**: 本件は規範を決め、#357 へ「確認者の種類に CL の判定の確認者を足す」ことを渡す。名簿の欄(直属の上長・所属の法人・部門・リリースの権限)は共通に使えるかを #357 の側で確かめる(内 181行)。#357 の書き置きの番号の誤り(IMPL-0178・0338 → IMPL-0184・0344、ADR-0087 → ADR-0088。内 173行)は、#357 へ訂正のコメントを残す

### 理由

- **判定記録の必須化と G-1 の前提条件**: FDA は判定と理由を提出の様式の必須欄にする(外 76行、一次)。IEC 62304 は分類を文書化しないまま進めることを最上位の扱いで塞ぐ(外 59-61行、記憶に依る、未確認)。どちらも「判定の記録が無いまま、低い判定の帰結だけを受ける」状態を作らない。本標準では G-1 の前提条件にするのが最も近い
- **機械が確かめる範囲を、所在と記名に限る**: 内容の妥当性を機械で確かめる規格は無い。ISO 26262 の確認レビューも人が行う。機械には、確認が行われうる形(記名・所在・段1)までを持たせ、残りを降りていない規定として表示する(#222)
- **R の判定の明記**: 擁護の委員の提案(内 149行)は、#318 の裁定にも ADR-0088 にも載っていない(内 156行)。「書かれていない」と「課さないと決めた」を区別するコアポリシーにより、どちらかに決める必要がある。課す根拠(変更ごとの判定に距離を課す規格)は読めた範囲に無いため、課さないと決め、未確認の点を EV で開示する
