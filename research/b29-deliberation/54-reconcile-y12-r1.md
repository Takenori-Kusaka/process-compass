### 3. 高: 原因を特定できない行に登録外の ID があるとき、停止の理由が誤った戻し方を書く

- 所在: `template/scripts/gate/autonomy.mjs:314` 付近(`unregDText` を cause-unknown の stop にも付ける行)。注記 `autonomyNoteLines` の `defectUnregistered` の行(`:1027` 付近)も同じ文
- 根拠: 種別を2つ(2つ目の登録日 2026-10-10)、Sev1・AI 起因「特定できない」・2026-10-05・列が「存在しない種別」の行で `autonomyState` を動かした。2つ目の種別は事象の日より後に登録していても L1 のまま止まる(cause-unknown)。それなのに停止の理由は「原因を特定するまで止める」の後に「取り下げた種別の行なら、残りの種別は事象の日より後の登録の判定で戻る」と続く。§1.6 は「原因を特定できない行は、原因を特定するまで止まる(既存の規則のまま)」と決めた。1つの文の中で表示と実態が食い違う。試験の「原因を特定できない行で登録外」は停止の有無だけを見るので、この食い違いを捕まえない

### 4. 中: 基準値を記録した後も、効く日までは「基準値が無い。記録すると戻る」と出る

- 所在: `template/scripts/gate/autonomy.mjs:414`(stop の文)、`:546`(`reworkTextBody` の「基準値が未設定」)
- 根拠: fixture で基準値を判定の日(2026-10-20)に記録した構成を動かした。L1 で「評価の日 2026-10-01 に効く手戻り率の基準値が無い…記録すると…(次は 2026-11-01)から戻る」と出る。手戻り率の行も「基準値が未設定」で、記録済みの 20% を出さない。L1 と次の日付は正しい。ただし、記録した採用者が、同じ値を記録し直す空振り(同じ値は履歴に積まれず何も変わらない。探りで確かめた)へ誘われる。観測の窓は、効いていない新しい値を「次の評価の日から」で併記している(ADR-0129 決定2)。基準値は「観測の窓と同じ形で記録し、同じ効力日を持つ」(ADR-0129 決定3)のに、この併記が無い
- 直しの案: `reworkBaselineInfo` の次の記録(recordedAt ≥ 評価の日)を拾い、「記録済みの基準値 x%(記録した日 d)。次の評価の日 YYYY-MM-01 から効く」を stop の文と表示へ出す。試験を1つ足す

## 観点ごとの結果

1. 指示書との対応: 所見 1・2・3。指示書から外れた点はどれも妥当と判断した
   - Sev1・Sev2 に絞ったこと: 停止の走査はもともと Sev1・Sev2 だけを数える。Sev3 の行に登録外の ID があっても何も止めないので、絞っても穴は開かない。注記を Sev3 にまで出すと、効かない警告になる。§1.6 の「空欄と同じ扱い」は停止の向きの話で、注記の対象までは決めていない。Sev フィルタを外す mutation では「Sev3 は止めず注記にも出さない」の場面が落ちた
   - 既存の場面「ほかの変更種別だけの Sev1 は止めない」: 指す先の `決済` を登録した種別に改めた。意味(登録した別の種別だけを指す行は、自分の種別を止めない)は保たれている。登録外の側は場面 G・H が止める側で固定しており、期待は弱まっていない
   - IMPL-0291 の note から「決め方」を外したことは実態に合う。ただし、コードと README に残っている(所見 1)。impl-inventory.yaml の2か所の書き換えは実態に合う
   - ADR との突合: ADR-0129 の本文(`:55`)が書く向きは「上げるのは緩める向き」だけで、「外す」の向きは書いていない。旧い実装の「外す=緩める」は ADR の決定ではない。ADR-0158 決定1(判定不能・読めないで止める)と決定2(未設定で止める。戻るのは記録した日より後の評価の日)は、rSmall・rUnset・rBad を L1 へ改めたことと、注記の文に合う

   - 過去の評価の日へは遡らない。`reworkAt(m)` が、評価の日 m に効く値を使う
   - 観測の窓を長くするのは緩める向きで(`rank -wb`)、同じ決定者の経路に乗る
