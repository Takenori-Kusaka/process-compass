## R-1 受注側の見積書・提案書の記録の置き場

### 結論

**規律する。ただし受注側の様式は置かず、2 者の記録を互いの証人にする**。

1. **発注側の企画書(テンプレ6)で受け止める(#407 起案を、版の識別子つきで採る)**。テンプレ6「見積りの記録」に行「受注側の提案(受託の発注側)」を置き、受注側の見積書・提案書の**識別子・版・提示日**と、提示された**段(参考値か確定か)・前提・幅・含む範囲**を、提示されたとおりに写す。幅が無ければ「提案に幅なし」、前提が無ければ「提案に前提なし」と書く。発注側が自分で幅を付けたり補正したりした値は、同じ欄に混ぜず、別の欄「発注側が採った値と、提示値との関係」に書く
2. **この行は G-1 の後に書き換えず、追記だけにする**。再見積り・契約変更で新しい版が提示されたら、新しい行として足す(旧行を残す)。7.7.9 の要求事項3 の「上書きしない」を、総費用の内訳の列からこの行へ広げる
3. **受注側(本標準を採用する受注側)への要求は、軸D の受注側の列に 1 行で置く**。行「顧客へ示した見積り」: 顧客へ示した見積り・提案の各版を、提示した版のまま識別子を付けて残し、上書きしない。記録する事項は、識別子・版・提示日・段・前提・幅と根拠・含む範囲と含まない範囲。契約の修正ごとに、比べた元の版と新しい版を記録する。**様式・置き場の形は定めない**(受注側の社内の文書体系に置く)
4. **7.7.9 の要求事項11 を受注側の価格に掛けない**。要求事項11 は組織の中の決裁者へ「示す」規定で、受容の記名の場は発注側のテンプレ6 にしかない。受注側の提示額の決め方(原価・予備・利益)は本標準の外と明記する。その代わり、**受注側の提示が幅を持たない・上側でない場合は、発注側の企画書でそれが見える**(結論1の「提案に幅なし」)ので、発注側が自分の見積り値を幅で書き、上側を下回る額で稟議するなら発注側の要求事項11 の受容が起動する。受容の主体は、費用を負う発注側の決裁者に一本化する
5. **主体を限らない文(要求事項6・8〜10・12)は、そのまま受注側にも掛かる**ことを、軸D の注記で 1 文だけ示す。要求事項6 の「委託先の評価」は、発注側の業者選定・委託先の評価に精度目標を使わせない文として読む

### 理由

- **受注側の見積りは契約の基礎文書で、変更の費用の妥当性は元の見積りとの比較で争われる**(外部 §1.2 IPA 第二版 第4条、§1.4 第38条の解説)。元の版が残らなければ、受注側は説明責任を果たせず、発注側は変更の費用を監査できない。規格も、契約の修正ごとに影響された項目をベースライン化し根拠を明らかにすることを求める(外部 §8、JIS X 0160:2012 附属書F.3.3.3.1・F.3.3.5.2)
- **受注側の様式を置かない理由は「量」ではなく「正本が 2 つになる」こと**。見積書の控えは税法で既に保存義務がある(外部 §11)。受注側の見積書そのものが正本であり、本標準の様式へ写させると、写しと見積書のどちらが正本かが割れる。ADR-0091 の却下理由(`adr/0091-...md:91`「重ねて書くと、どちらが正本かの食い違いの元」)と同じ観点
- **改ざんを防ぐ仕組みは、相手方の記録に写しを持たせること**。受注側が社内で見積書の版を差し替えても、発注側の企画書の G-1 の版(テンプレ4 の「参照した企画書の版」DT:693 で固定されるコミット)に提示値が残る。逆に発注側が企画書を書き換えれば、受注側の見積書と食い違う。片側だけの記録は、記録した側の利害で動きうる。2 者の記録を互いの証人にする構成が、監査で最も強い
- **要求事項11 を受注側へ掛けると、受容の場が無いまま規範だけが残る**(内部 K-10)。場の無い受容は、監査人には「受容した」とも「していない」とも確かめられない。確かめられない規範は、遵守の主張だけを生む

### 監査で確かめられること

- 受託の発注側の案件で、テンプレ6 の行「受注側の提案」が空でないこと(識別子・版・提示日、または「提案に幅なし」「提案に前提なし」)。機械の検査で存在を確かめられる
- G-1 の判定記録が参照した企画書の版と、現行の企画書とで、行「受注側の提案」の既存の行が書き換わっていないこと(追記だけであること)。IMPL-0366 の版の比較をこの行へ広げれば機械で確かめられる
- 契約変更の判定記録が、比べた元の見積りの版と新しい版を名指ししていること。名指しされた版が、企画書の「受注側の提案」の行に存在すること(突き合わせは人が行う)
- 受注側が本標準を採用している場合、契約の修正ごとに元の版と新しい版の記録があること(受注側の内部監査・プロセス内部監査で確かめる)
- 発注側の見積り値が受注側の提示値と違う場合、その関係が別欄に書かれていること

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 受注側の見積書・提案書の新しい様式を第6章に置く | 見積書そのものが正本で、写しの様式は正本を 2 つにする。保存は税法が既に課す。必要なのは保存ではなく「版を固定して比べられること」で、それは軸D の 1 行と発注側の写しで満たせる |
| 本標準は受注側の見積りを一切規律しない(受注決裁と同じくゲートの外、TG:618) | 受注決裁が本標準のゲートでないことと、受注側の提示が発注側の G-1 の入力になることは別の話。提示値は発注側の見積り値の出所になる(EE:399 の実測が無い間の代替値の出所でもある)。出所を追えない入力は G-1 の判定材料として監査できない |
| 7.7.9 の要求事項11 を受注側の提示額に掛ける | 受容の記名の場が受注側に無い。場を作ると、受注側の価格決定(原価・利益)を本標準が規律することになり、ADR-0069 決定6 の「契約の法的な性質を本標準が抱えない」と同じ理由で扱えない |
| 見積書の保存期間を本標準が定める | 法令(法人税法 7 年、取適法 2 年)が既にある。本標準が独自の期間を置くと、短い方へ誤読される。「法令の期間を下回らない」とも書かない(書くと本標準が法令の遵守を保証する形になる。H.9 問16 AC:848 と同じく、法令の帰結は各組織の法務が扱う) |
| 「出所」とだけ書かせる(#407 起案のまま) | 版と提示日が無い出所は、後から別の版に差し替えても区別できない。改ざんを検出できない |

### 反論されうる点

- 「本標準を採用しない受注側には何も掛からない。軸D の 1 行は空文になる」: 掛からないのは事実。だから結論1(発注側の写し)を主にした。受注側が採用しなくても、発注側の企画書の上で提示値と版は残る
- 「提案に幅なし」と書かせても、発注側が受注側の一式見積りをそのまま見積り値にするのは止められない: 止めない。止めるのは要求事項11(発注側の決裁者が上側を下回る差を記名で受容する)で、「幅なし」の記載はその受容が起動すべきことを監査人に見えるようにする
- 追記だけの行は長くなる: 版の数だけ行が増えるのは、変更の数だけ記録があるということで、減らすべき量ではない

## R-2 S0 の初回の確約範囲と請負の契約

### 結論

**2.10.2 の要求事項2(S0 の初回は SC-M を置かない)は変えない。衝突は軸D の側、契約変更の起点の定義で解く**。

1. **契約変更の起点を「契約で固定した範囲の変更」に改める**(TG:575・578)。「契約で固定した範囲」は SC の層ではなく、項目(受入基準の識別子)に付く属性とする。SC 記号を増やさない。契約に固定した範囲が無ければ「なし」と書く
   - TG:575: 「確約範囲(SC-M)の変更」の行の受託の列は、「契約で固定した範囲の変更(SC-M の変更を含む)を契約変更の起点として扱う」とする
   - TG:578: 「計画範囲・調整枠の調整は契約変更を伴わない」を、「**契約で固定した範囲に含まれない** SC-P・SC-B の調整は契約変更を伴わないことを契約に明記」へ限定する
   - LC:614(2.10.8): 「受託開発では、契約で固定した範囲の変更が契約の変更に直結する」とし、G-4 を経ない SC-P の組み替え(2.10.5)でも、契約で固定した範囲の項目に触れるものは 2.10.8 の「契約に影響」の枝へ入れる
2. **契約で固定した範囲の変更の判定者は、SC-M の変更と同じ席にする**(7.6 の段階に写す。価値責任者は起票し判定しない)。S0 の初回でも、契約で固定した範囲の項目は、価値責任者の単独判定で削除・入れ替え・追加できない
3. **S0 の初回に契約で範囲を固定するときは、「実測に裏付けられない固定」と記録する**。企画書のスコープ3層の節に「契約で固定した範囲(受入基準の識別子、契約の版)」と「実測なし」を書き、事業リスクと受容方針(DT:1022)に 1 行置く。SC-M とは呼ばない(7.7.9 要求事項8 と同じ)。必達基準2 は EE:402 のまま「対象外(SC-M なし)」で、契約で固定した範囲を到達の見込みの対象に入れない
4. **契約類型を本標準が選ばないことを、TG:590-597 の「定めないこと」に明記する**。請負・準委任・多段階契約のどれを使うかは当事者が決める。ADR-0069 決定6 の延長。多段階契約の手引きは本文に置かない(例3 TG:1025 のまま)
5. **「実測が存在しない段階」を、実行する組織の実測で定義する**。2.10.2 の要求事項2 を「当該案件を実行する組織の、同じ作業単位の定義による実測が存在しない段階(S0 の初回を含む)」とし、要求事項4 に「実測の主体(どの組織の、どの期間の実測か)」を記録させる。EE:399・EE:402 の「S0 の初回など」「S0 の初回は」もこの定義へ揃える(内部 K-6・K-7)
6. **ADR-0099 が送った「委託が主の案件の見込み」はここで決める**: 到達の見込みの実測は、実行する組織(委託が主なら受注側のチーム)の実測とする。実行する組織が替わった時点(委託先の交代、内製から委託へ)で観測の窓を新しくし、単位期間が3つ揃うまで「算定できない」と記録する(第 3 巡の裁定の「算定できない」をそのまま使う)。根拠水準 E0 でマークする
7. **偽装請負の注記は新たに足さない**。TG:655-659 の既存の注記を参照する

### 理由

- **SC-M を実測なしで置く案(内部 B1(a))は、確約の量を見積りの巧拙に戻す**。LC:496 は「確約の量を支えるのは見積りの巧拙ではなく、実測された完了の速さ」とし、ADR-0019 決定3 の根拠である。契約が範囲を固定することは当事者の商取引の判断であり、それを本標準の確約(SC-M)と同じ語で呼ぶと、必達基準2・7.6 の SC-M の変動率(EE:218)が実測の裏付けの無い量を基準に回り出す
- **監査人の要請は「契約で固定したものが黙って変わらない」ことで、それを SC-M と呼ぶことではない**。起点を「契約で固定した範囲」に置けば、S0 の初回でも、S1 以降に SC-M の外まで契約で固定した場合でも、同じ規則で外殻の変更管理が起動する。LC:605 の既存の枝(契約に影響すれば B-2)と整合し、新しい場を作らない(2.10.3 の「場を別に設けない」に触れない)
- **0 章の事実 2・3 の穴が塞がる**。S0 の初回の SC-P の追加の上限の無さ(LC:543)は、契約で固定した範囲の外に限られる。EE:222 の「相手方との合意が外の歯止め」は、契約で固定した範囲の変更として復活する
- **案 B1(c)(TG:578 を S0 の初回に課さない)は、穴を逆向きに開ける**。契約に「SC-P の調整は契約変更を伴わない」と書かないだけで、何が契約変更かは決まらない。黙って変わる経路は残る
- **案 B1(d)(衝突を開示して当事者に委ねる)だけでは足りない**。契約類型を選ばないことは正しい(結論4)が、選ばないだけでは「契約で固定した範囲を変えたとき本標準の記録が動かない」穴が残る。類型を選ばずに、どの類型でも成り立つ起点を置く
- **実測の主体を定義しないと、新しい委託先の初回に SC-M を置ける字面が残る**(内部 2.4)。要求事項4 は既に「合意・計画容量・実測に同じ定義を用いる」と求めており、別の組織の実測を流用することは同じ定義の要件と緊張する。主体を記録させれば、流用したかどうかを監査で確かめられる。主体の定義を広げても、契約で固定した範囲の経路(結論1)があるので、S1・S2 の受託で範囲を固定できなくなるわけではない
- 外部 §14 の最も根拠の強い組合せ(2-E: 契約類型は選ばず、どの範囲を何の根拠で確約したかを記録させる)と一致する

### 監査で確かめられること

- 受託の案件で、企画書(S0 の初回)または SG の判定記録に「契約で固定した範囲」(識別子の一覧と契約の版、または「なし」)があること
- 契約で固定した範囲の項目が、ある時点の版から消えた・入れ替わった・増えたとき、対応する 7.6 の判定記録(判定者は SC-M と同じ席)と契約変更の記録があること。**項目の識別子の集合の差分を版の間で取れば機械で検出できる**(SC-M の変動率の算定と同じ型)
- S0 の初回に契約で範囲を固定した場合、「実測なし」と事業リスクの行があること
- 要求事項4 の記録に実測の主体があり、実行する組織が替わった後の到達の見込みが「算定できない」から始まっていること
- 兼務の体制(EE:222)で自己の判定をした受託の案件で、契約で固定した範囲の変更に相手方との合意の記録があること

### 採らない案

| 偽装請負の注記を本件の箇所に重ねて書く | TG:655-659 に既にある。重ねると正本が割れる |
| 委託が主の案件の見込みを再び別 Issue へ送る | 3 回目の送りになる。実測の主体を定義すれば決められる |

### 反論されうる点

- 「契約で固定した範囲の変更を SC-M と同じ席で判定させると、S0 の初回の発注側の価値責任者の裁量が狭まる」: 狭まる。契約で固定したのは当事者自身であり、固定した項目を単独で動かせる状態こそが穴である。裁量を残したいなら、契約で固定しなければよい(固定しないことも結論4 で当事者が選べる)
- 「契約で固定した範囲は契約書が正本で、本標準の記録は写しになる。正本が 2 つになるのでは」: 写すのは識別子の一覧と契約の版だけで、条項の中身は写さない。版の照合ができれば足り、R-1 と同じく 2 者の記録を互いの証人にする構成である
- 「実測の主体の定義を広げると、委託先の交代のたびに SC-M が置けず、S2 の案件が止まる」: 止まらない。SC-M が置けない間は契約で固定した範囲の経路で確約を管理できる。逆に、交代した委託先に前任の実測で SC-M を置くことは、確約の根拠を偽ることに当たる
- 「実行する組織の交代」の境界(どこまでが同じ組織か)は判断が要る: 判断を記録させる(要求事項4 の実測の主体)。境界の判定基準は定めず、E0 でマークし、見直しの材料は交代の事例の記録とする

## R-4 記録

### 結論

1. **新しい ADR を起こす**(例: ADR-0100「受託の見積りの版と、契約で固定した範囲を契約変更の起点にする」)。採用済み ADR の本文は書き換えない
2. 既存の ADR との関係
   - **ADR-0019**: 決定3(実測が無い段階では確約範囲を置かない)は維持。ADR-0019 の「影響」で足した軸D の行(SC-M の変更を契約変更の起点とする、`adr/0019`:64)を、「契約で固定した範囲の変更(SC-M を含む)」へ改める。決定ではなく影響の行を改めることを、新 ADR に明記する
   - **ADR-0069**: 決定6(類型ごとの読み替えの表を置かない)を維持し、「契約類型を本標準が選ばない」を TG の「定めないこと」に足す。決定6 の延長であって変更ではない
   - **ADR-0091**: 決定5(受注側の営業について新しい規定を置かない)は、見積もり・提案の形と段階を #407 へ送ったうえでの決定。本 ADR が軸D の受注側に 1 行足すのは、その送り先での決定であり、決定5 と矛盾しないことを書く。却下(`adr/0091`:91、提案の範囲を G-2 まで確約範囲に数えない明記)も維持(契約で固定した範囲は SC-M ではない、で整合)
   - **ADR-0093**: 決定7 の送りを本 ADR で閉じる。要求事項3 の「上書きしない」をテンプレ6 の「受注側の提案」行へ広げることは、要求事項3 の適用の拡張として本 ADR に書く(ADR-0093 は書き換えない)
   - **ADR-0099**: 「本件で決めないこと」の「委託が主の案件の見込み(#414)」を本 ADR で閉じる(R-2 結論6)
3. **「本件で決めないこと」の節に、別 Issue への送りを置かない**。決めないものは「定めない(恒久)」と書く: 受注側の提示額の決め方、契約類型の選択、多段階契約の手引き、見積書の保存期間、受注側の見積書の様式、確約を見積工数の比率で抑える値
4. 根拠水準: 2 者の記録を互いの証人にする構成の効き目(E1。IPA 第二版 38条の解説、JIS X 0160 附属書F は方向を支えるが、本構成の実証は無い)、実行する組織の交代で観測の窓を新しくする判断(E0)を、それぞれ暫定マークで開示する
5. 突合: TG:575・578・590-597、LC:487・489・543・614、EE:222・399・402・604、DT:996-1003・1046・1211-1371、`template-fields.yaml`、`rules-dev-form.yaml` を、起案の後に突合する(`npm run lint:refs`・`npm run check`)

### 理由

- 2 回送られた論点を 3 回目に送らない唯一の方法は、決めないものを「定めない」と恒久に決めて書くこと。送りの文言(「#NNN で扱う」)が残る限り、読み手は「書かれていない」と「課さないと決めた」を区別できない
- ADR-0099 の送りは議題に載っていなかった。ADR の「決めないこと」は送り先の議題に自動では載らないので、送り先の ADR で名指しして閉じる

### 監査で確かめられること

- 新 ADR の「本件で決めないこと」に Issue 番号の送りが無いこと
- ADR-0091 決定5、ADR-0093 決定7、ADR-0099:116 の各送りに対し、新 ADR が名指しで閉じていること
- 暫定マークが台帳(`community/evidence-ledger.md`)に出ていること

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| ADR-0093 か ADR-0069 への追記で済ませる | 採用済み ADR は書き換えない(第 3 巡の裁定で品質監査が同じ理由で退けた ADR-0099 の却下の行と同じ) |
| ADR を起こさず本文の改訂だけにする | 契約変更の起点の変更は、あとから変えにくい方針の変更(ADR-0019 の影響の行を改める)で、記録が要る |
| 受注側の見積りを「定めない」と決めて ADR に書くだけにする | 「定めない」も成果だが、R-1 の理由(出所を追えない入力は G-1 で監査できない)から、定めないと G-1 の入力の監査性が欠ける。定めない対象は受注側の様式と価格に限る |

### 反論されうる点

- 「ADR-0019 の影響の行を改めるのは、実質的に ADR-0019 の置き換えでは」: 決定3・7 は変えない。改めるのは軸D の表の 1 行の対応づけで、置き換えの範囲を新 ADR に限定して書く。範囲を明示すれば、読み手はどの決定が生きているかを区別できる
