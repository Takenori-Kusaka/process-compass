# 会議体の議題(#414 受注側の見積書・提案書の記録の置き場と、S0 の初回の確約範囲と請負の契約の関係)

入力: Issue #414、`survey-414-1-internal.md`(内部)、`survey-414-2-external.md`(外部)。#407 / ADR-0093 の会議体(現場)が残した 2 点を決める。同日の #415 / ADR-0099(第 3 巡の裁定。`research/415-deliberation/decision.md` 末尾)で、S0 の初回は必達基準2 の「対象外(SC-M なし)」と決まった。

## 前提として確かめた事実(要旨)

- **論点1**: 第8章 軸D の表に、見積もり・提案・価格の行が無い。7.7.9 の記録の置き場は発注側のテンプレ6・テンプレ4 に固定されている。受注側に掛かりうるのは置き場を持たない要求事項6・8〜10・12 だけで、要求事項11(上側を下回る差の受容)は受注側に受容を記名する場が無い。#407 の起案の「発注側の企画書に受注側の提案を出所として書き、幅が無ければ『提案に幅なし』と書く」案は本文に入っていない。この論点は ADR-0091 決定5 → #407 → #414 と 2 回送られている
- **論点2 の核心**: 次の 3 つを同時に満たすと「全範囲を契約変更なしに動かせる契約」を求めることになり、請負と合わない。契約類型を扱わないとした既存の決定(第8章、ADR-0069 決定6)と緊張する
  - 2.10.2 要求事項2: S0 の初回は SC-M を置かず、全体が SC-P
  - 軸D: SC-P は契約変更を伴わないと契約に明記する
  - 軸D: 契約変更の起点は SC-M の変更だけ
- 契約で固定した範囲は SC-M ではないので、変えても 7.6 も B-2 も起動しない。契約と本標準の記録が別々に動く
- 「新規の受託案件はほぼ全件が S0 の初回」は未検証。S0 は事業ステージで、受託の例3 は S2。実測スループットの主体(どのチームの実測か)が定義されていない。「S0 の初回」の書き方が揃っていない
- テンプレ8(AI-SLA)に、軸D が契約に求める事項の欄が無い。規則データ `rules-dev-form.yaml` の受託・委託の規則にも無い。準拠テンプレートに受託のプロファイルは無い
- **外部**: IPA モデル契約〈第二版〉は見積りを仮試算・試算・概算・確定の 4 段に分け、構想〜要件定義の見積りは参考値とする。提案書・見積書は個別契約の基礎(第4条)、変更の費用は従来の見積と比べて判断する(第38条の解説)ので受注側は元の見積りを残す必要がある。反復型では当初見積と実績を突き合わせ、超えたら契約を見直す旨を契約に書く。JIS X 0160(12207)は提案書の作成を供給プロセスの活動とし、契約の修正のたびに根拠を示させる。CMMI・PMBOK は見積りの根拠(前提・幅・信頼水準)の記録を求める(二次)。見積書の保存は税法で既に義務。IPA アジャイル版は準委任を前提とし、請負は確定している部分だけに限るよう勧める。Agile Contracts Primer は固定価格・固定範囲を避け、拘束しないバックログの添付、多段階・可変、目標原価型を示す。確約する範囲を見積工数の一部に抑える設計(DSDM 60%、Primer の例 約20%)は実証されていない

## R-1 受注側の見積書・提案書の記録の置き場

- 問い: 受注側が顧客へ示した見積り(段・前提・根拠・幅)を、本標準が規律するか。するなら置き場(受注側の企画書・提案の記録・テンプレ8・D-0)と、変更・実績との突合。発注側の企画書に受注側の提案を出所として書かせる案(#407 の起案)の採否。7.7.9 要求事項11 の受注側への掛け方。課さないなら、その理由

## R-2 S0 の初回の確約範囲と請負の契約

- 問い: 上の 3 規定の衝突をどちら側で解くか(2.10.2 要求事項2 / 軸D の SC-P の契約上の扱い / 契約変更の起点)。契約で固定した範囲を本標準の層とどう結ぶか(契約範囲の変更が 7.6・B-2 を起動するか)。多段階契約を本文で扱うか。契約類型を課さないこと(ADR-0069 決定6)との関係。準委任の偽装請負の注意を併記するか。「S0 の初回」の書き方と実測の主体
