- 委員の立場: 品質保証・プロセス内部監査。見るのは、職務の分離が記録の上で成立しているか、監査人が名簿と席を記録から確かめられるか、代替の統制が理由とともに記録されているか、章とテンプレートが一致しているか
- 入力: `issues-context.md`、`council-00-agenda.md`、`survey-312-1-internal.md`(以下「内部」)、`survey-312-2-external.md`(以下「外部」)。他の委員の意見書は読んでいない
- 自分で確かめたもの(2026-10-23、`work/312`、テンプレート `33ace03`): 本文 3.5・3.5.1・3.5.2、軸A L140〜192、テンプレ0 表5〜表7、G-7、フェーズ5 `pr-workflow.md`・`label-mailbox.md`、ADR-0037・ADR-0066・`adr/index.md` の運用ルール5、テンプレートの `MAILBOX`・`next.mjs` L570〜590・`config.mjs` の `headcountProblems` と呼び出し元・D-0 節1・節2・`handoff.md`
- 根拠の表記: [内部] は内部調査、[外部] は外部調査、[確認] は自分で原文を読んで確かめたもの。[推論] はそのどれにも当たらない自分の判断

## 監査の立場から見た、本件の核心

本件の5つの所見は、監査人が分離の成立を記録から判定できない状態を作っています。

1. 同じ組(価値責任者×技術判断者、5〜9名)を、様式は「不可」、機械は「可」と扱っている。監査人がどちらを基準に突合しても、もう一方の記録から不適合が出る
2. 既定の写像は、独立レビュアと出荷判定者に1つのレーンを与えている。3.5.1 の第1の理由は、レーンごとに認証情報を分けることだった。レーンを共有すると、G-6 の承認と G-7 の記名が同じ認証情報から出られる。ADR-0066 決定2(G-7 の記名者 ≠ G-6 の承認者)を、アカウントから人への対応づけで確かめる前提が崩れる [確認・推論]
3. 名簿の様式が標準に無い。そのため G-6 の確認者の有無、体制の人数、所属のいずれも、標準の様式だけでは監査できない

信頼性の軸で判断すると、どの議題も「機械と様式と本文が、同じ記録を同じ基準で見る」状態へ戻すことを優先します。変更量は採否の理由にしません。

## P-1 価値責任者×技術判断者の兼務の境界

### 結論

人数の区分は軸A の3区分(1〜2名 / 3〜9名 / 10名以上)に揃え、**5名の境界は廃止**します。内容は次のとおりです。

- 1〜2名: 許容
- 3〜9名: 非推奨。兼務する場合は、理由と代替の統制を D-0 に記録することを要件にする
- 10名以上: 禁止(現状の機械の規則を維持)
- 事業決裁者×価値責任者にも同じ型を当てる。ただし 10名以上でも禁止しない。禁止しないことを、意図的な決定として明記する

### 理由

- **5名は監査できない境界**です [内部 1.7・2.1、確認]。3.13.1 の変化点にも、設問 `q-team-size` にも、`headcountProblems`(3名・10名だけを見る)にも5名がありません。越えたことを手続も機械も捉えず、変化点の記録も残りません。EV マークも無く、開示の要件を満たしていません
- **記録を課さない「非推奨」は、監査では「課さないと決めた」と区別できません**。3〜9名の兼務が意図的か見落としかを、記録から判別できません。外部の内部統制の枠組みは、分離できない場合に**代替の統制と理由の記録**を求め、人数でも費用でも免除しません(SRC-0544、SRC-0419 c2、SRC-0538、ISO 27002 の手引き)[外部 F6〜F10]。3.5.2 はすでにこの型(条件・記録・D-0 への明記)です [確認]
- **10名の禁止は維持**します。機械・スキル・第8章が一致しており [内部 1.8]、外すと #338(軸の変更)を先取りします。ただし EV-0148 の対象にこの禁止は入っていません [確認 L160〜166]。**新しい EV で別に開示**し、EV-0148 の対象は広げません(見直しで何を測るかが追えなくなるため)
- **失われる牽制**は、価値の要求(G-2・G-4)と技術上の制約(G-3)のせめぎ合いが1人の中で閉じることです [外部 F12]。代替の統制は、この緊張を記録へ出させるものにします。兼務者の G-3 の判定記録に採らなかった選択肢と受入基準への影響を書かせ、その記録を兼務者以外の人の確認の対象に含めます。代替の統制は独立性を回復しません(3.5.2 と同じ立場)
- **事業決裁者×価値責任者**は、「小規模」に人数が無く、規則データにもエンジンにもありません [内部 6.4]。禁止を広げる根拠は無く、G-8 の自己完結は出荷判定者×事業決裁者の禁止がすでに止めています。3名以上は非推奨・記録とし、10名以上でも禁止しないことを却下の決定として明記します

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 5名に揃える | EV が無い。変化点・設問・機械を新設しても、5名の外部の根拠は無い [外部 5]。根拠を欠く境界を1つ増やすことになる |
| 10名に揃え、3〜9名は「非推奨」だけにする | 兼務が意図的か見落としかを、記録から判別できない。監査で不適合を検出できない |
| 人数をやめ、代替の統制だけにする | 10名の禁止は機械で強制済み。外すと #338(軸の変更)を先取りする。10名以上で牽制が失われても許す根拠も無い |
| 5名・10名の2段を明文化する | 5名の欠陥(監査できない・EV が無い)がそのまま残る |
| 境界を採用組織が自分で決める | ADR-0044 決定4 と第8章 L170 が退けた型(自己申告で規則を外せる) |

| 組み合わせ | 可否 | 理由 |

> 非推奨の兼務は禁止ではありません。兼務する場合は、上の4項目を D-0 体制図へ記録します。記録の無い非推奨の兼務は、記載の欠落として扱います。代替の統制は独立性を回復しません。判断の偏りを、後から検出できる状態にするだけです。

EV は新しい番号で2つ付けます(E0。見直し 2027-10)。

- 1つ目の対象: 10名以上での価値責任者×技術判断者の禁止

## P-2 3.5.1 の既定の写像

### 結論

ADR-0066 の分離(独立レビュア ≠ 出荷判定者)は**正しいものとして維持**します。写像を直し、独立レビュアと出荷判定者を**別のレーン**に、事業決裁者を価値責任者と別のレーンに置きます。レーンの写像そのものは残します。新しい ADR で ADR-0037 の写像の表と「圧縮は設計」の判断を置き換え、両側のステータスが互いを指すようにします(`adr/index.md` の運用ルール5)。

### 理由

- **ADR-0066 の分離は監査の上で必要です**。G-7 の基準5 は G-6 を含む全ゲートの通過記録を突合します [確認]。兼ねると、突合の対象の記録を作成者自身が突合します。外部に一般の要求は見当たりませんが [外部 F14・Q2]、これは「作成者 ≠ 確認者」の2者分離を G-7 の突合に当てはめた結果です。EV-0103(E1)で開示済みで、誤りとする材料はありません
- **レーンの共有は、人の単位の兼務より監査を難しくします** [確認・推論]。3.5.1 の理由1 は、強制が成り立つのを認証情報を分けた場合に限っています。QM レーンを共有すると、G-6 の承認と G-7 の記名が同じ認証情報から出られます。G-7 の成立条件4 はアカウントを名簿の人へ対応づけて確かめるため、その対応づけが成り立ちません。席の責任者が別の人でも、記録の上で区別できなければ分離を確かめられません
- **3.5.1 の条件1 に、自分の既定が反しています** [内部 2.2、確認]。条件を正とし、既定を直します
- **事業決裁者を PO レーンに置くことも同じ条件に反します** [内部 2.2]。G-1・G-2・G-4・G-8 の記名が1つの認証情報に集まります
- **写像の欠け**: 文脈オーナーと AI運用担当者の行が無いと、「書かれていない」か「経路を課さないと決めた」かを区別できません [内部 6.1]。ADR-0037 はこの2つにラベルを設けないと決めています [確認]。行を置いて「ラベルなし」と明記し、AI運用担当者を Platform レーンへ置かないことも書きます
- **レーンの写像は残します**。認証情報を分けることが分離の唯一の機械的な担保だからです。写像をやめて案件に委ねる案は、割り当て先のないロールを再び生みます(ADR-0037 のコンテキスト)

| 案 | 落とす理由 |

| ADR-0066 を置き換え、兼務を許す | 突合する記録を自分で突合する構成になる。誤りと判断する材料が無い。ADR-0066 が却下した「表示で済ませる」形へ戻る |
| レーンの共有を許し、条件1 を「人の単位の禁止だけ」に改める | 認証情報が分かれず、承認とアカウントの対応づけが成り立たない。監査で分離を確かめられない |

## P-3 `dev-done` の受け手

### 結論

- `state:dev-done` の受け手は**独立レビュア(G-6)だけ**にします
- `state:ready-to-merge` を付けるのは、G-6 の判定記録を書いた独立レビュアに限ります
- 出荷判定者は、PR ごとのラベルを受信箱に持ちません。受け手は出荷の範囲の証跡の集約(G-7)とします
- 差し戻しは両方の席に残します。独立レビュアは G-6 の差し戻しに `qm-blocked` を使います。出荷判定者の差し戻しは、出荷の範囲の判定記録で行います

### 理由

- G-6 は変更ごと、G-7 は出荷ごとの判定です(G-7 の基準5「全ゲートの通過記録」)[確認]。文書の「出荷判定者(QM)」は QM レーンへの圧縮の名残で、`next.mjs` L579 はすでに独立レビュアを指しています [確認]
- 同じラベルが2つの受信箱にあると、「誰も拾わなかった」「両方が拾った」を記録から説明できず、「自分の受信箱だけを見る」規則の下で責任の所在が決まりません
- 出荷判定者が `ready-to-merge` を付けられると、G-6 の記録が無い PR に通過の合図を出せます。証跡の集約が欠落を止めますが、合図の遷移は判定記録の順序(G-6 → G-7)に揃えておくべきです

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 出荷判定者を受け手にする(現在の文書) | G-6 の判定者が受け取らない。P-2 で席を分けたことと合わない |
| 両方を受け手にする(現在の機械) | 拾う責任が決まらない。監査で説明できない |
| G-7 用の新しいラベルを足す | 出荷判定は PR 単位ではない。語彙を増やす理由(伝達の欠落)が無い。ADR-0037 の原則5 |

### 文の案

遷移の表(`label-mailbox.md`)は次のとおりです。

| 現在のラベル | 次に動く席 | 行為 | 次のラベル |
| --- | --- | --- | --- |
| `state:dev-done` | 独立レビュア | G-6 の判定記録を書き、通過とする | `state:ready-to-merge` |
| `state:dev-done` | 独立レビュア | G-6 の判定記録に差し戻しを書く | `state:qm-blocked` |

本文は次のとおりです。

> 出荷判定者は、PR ごとの受信箱のラベルを持ちません。出荷判定(G-7)は、出荷の範囲の証跡の集約を材料に行います。ラベルの遷移は、判定記録を書いた後に行います。ラベルの遷移は判定の成立要件ではありません。

テンプレートの `MAILBOX` は、`qa-gatekeeper` の inbox から `state:dev-done` を、hands から `state:ready-to-merge` を外します。`pr-workflow.md` L33 と `handoff.md` L10 の「出荷判定者(QM)へ」は「独立レビュアへ」に改めます。

## P-4 人の名簿

### 結論

テンプレ0 の表5 を「**人の名簿と席**」(表5-1 席、表5-2 人の名簿)に改めます。番号は変えず、本文と ADR-0065 の「表5(人の名簿と席)」の参照をそのまま正しくします。名簿の必須の欄を `template-fields.yaml` に登録します。IMPL-0278 の注記は実装と合っていないため改めます。

### 理由

- **名簿が無いと、標準が課す分離を記録から検査できません**。確認者の有無(ADR-0065 決定5)、人数(第8章 L156)、所属による 10名以上の規則(IMPL-0084・0085)、G-7 の成立条件4 は、どれも名簿を前提にしています [確認]。本文と ADR-0065 は、存在しない表を名簿として参照しています [内部 3.2]
- 外部の先例があります(ISO 13485 5.5.1・8.2.6、NIST AC-5、安全計画)[外部 F5・F6・F16]。ISO 9001 5.3 は文書化を求めませんが、本標準は分離の規則を自ら課しており、それを確かめるために名簿が要ります [外部 Q3]
- テンプレートは `people[]` と D-0 節1 の名簿の表を持っています [確認]。標準が様式を持たないと、「テンプレートが標準の部分集合である」という関係(ADR-0040)が逆転します。テンプレートにしか無い欄に、本文の規定が依存することになります

### 他の案を落とす理由

## P-5 表の記号の語彙

### 結論

1.7.3 の語彙に**揃え**、記号は足しません。○ は「許容」、△(避けたい)は「非推奨」とし、限定は括弧に書きます。テンプレートの D-0 節2 の「可」「不可」も揃えます。

### 理由

- 1.7.3 は升の語をその語彙に限っています [内部 4]。△ は「禁止」とも「非推奨」とも読め、P-1 の割れはこの揺れから生じています
- 語彙を足すと強さの段階が増え、判定の根拠が分かれます。様式の語が本文と違うと、様式の記録を本文の基準で突合できません

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 1.7.3 に △ を足す | 「非推奨」と区別できる意味が無い。語彙を増やす理由が無い |
| 様式は自由な語のままにする | 様式の記録が監査の突合対象なので、語が違うと突合できない |

### 文の案

- 3.5 の表: P-1 の文の案のとおり
- 写像の条件1: P-2 の文の案のとおり(「△」を消す)

ADR-0037 L64 は「△(避けたい)」を引いています。P-2 の新しい ADR に、ADR-0066 の決定3 と同じ形の読み替えの表を置き、「△(避けたい)は非推奨と読む」と書きます。採用済みの本文は書き換えません。
