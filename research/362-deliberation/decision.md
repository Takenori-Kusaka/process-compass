# 議長の裁定(#362 既定ブランチが main でないリポジトリへ準拠テンプレートを持ち込む)

- 審議の重さ: **軽**
- 受付の理由: 採用者へ新しい義務を課さず、持ち込める範囲を広げる変更である。強制層のワークフローを案件ごとに変える経路(調査の方式 C)が生じる場合は重へ上げる条件とした。裁定は C を採らないので、軽のまま扱う
- 入力: `survey.md`(内部の調査と実機の確認 O1〜O8)、委員1(起案)`council-01-drafter.md`、委員2(反対)`council-02-opponent.md`
- 2委員の結論は割れていない。委員1 は方式 G を推した。委員2 は G か F'(集約のジョブ ID も替える F)を、条件 K-1〜K-10 つきで受け入れた。どちらも E と素の F を退けた

## 0. 骨格

判断軸は、必須チェック `gate-g5` が黙って満たされる経路を作らないことです。実機で、push の絞りを外してジョブの `if:` で既定ブランチに絞る形(E)は、PR の検査が落ちる変更をマージさせました(O4)。名を式で替える形(F)は塞ぎましたが、その成否は skipped のジョブの名の表示という文書に無い振る舞いに依ります。G は、push を契機とするワークフローに名が `gate-g5` のジョブを1つも置かないので、表示の振る舞いがどう変わっても `gate-g5` の check run が生じません。故障の向きが構造で決まる案を採ります。

## R-1 方式 — 裁定: G(push の契機を別のワークフローに分け、`gate-g5.yml` を再利用で呼ぶ)

- `gate-g5.yml` から `on.push` を外し、`on.workflow_call` を足す。`pull_request` と `workflow_dispatch` は残す(委員1・委員2)
- 新しい強制層のワークフロー `gate-g5-push.yml` を置く
  - 契機は `on.push.branches: ['**']`。タグの push では起動しない(委員2 K-3)
  - ジョブは1つで、ID と名は `default-push`。式の名を使わない(委員1)
  - 条件は `if: github.ref == format('refs/heads/{0}', github.event.repository.default_branch)`。`ref_name` で書かない(タグと区別しないため。SRC-0730 c3。委員2 K-3)
  - `uses: ./.github/workflows/gate-g5.yml`。権限は `gate-g5.yml` の現在の値を呼び出し側で与える
- `gate-g5.yml` の中の push の分岐(契約検査の `github.event.before` との比較)は変えない。呼ばれた側の `github` コンテキストは呼び出し側の事象を指す。実機で確かめる(下記 R-5 の T3)
- 採らない
  - A(止めたまま): Issue の問題が残る。初期化の後の改名で push の契約検査が黙って止まる穴(委員2 §3)も塞がない。G はこの穴も塞ぐ
  - B(`branches` に式): 不正なワークフローになり、どのブランチへの push でも失敗の実行が出る(O1)
  - C(初期化が `branches:` を書く): 強制層の定義を案件ごとに変える。ADR-0085 が退けた理由がそのまま当たる。改名のたびに強制層の変更が要る
  - D(名の列挙): 列挙の外を持ち込めない。列挙した既定ブランチでないブランチの push で、契約検査が既定ブランチの履歴でない比較をする
  - E(絞りを外し `if:` で絞る): 迂回を作る(O4)。テンプレートの集約は `if: always()` で、未設定の分岐で `exit 0` するため、時間の窓に依らず success の `gate-g5` が付く見込みもある(委員2 §1.1)
  - F(集約の名を式で替える): 迂回は塞いだ(O6)。ただし skipped のジョブの名をジョブ ID へ戻す振る舞いに変われば、迂回が黙って戻る(委員2 §1.2)
  - F'(F に加え集約のジョブ ID を替える): どの振る舞いでも止まる側へ倒れる点は G と同じ。ただし9つのジョブへ同じ条件を書き写すことになり、`g5-aggregate.mjs` はジョブの `if:` を確かめない(委員2 §1.2)。集約のジョブ ID は契約検査と保証の開示が読む契約であり、変えると既存の採用者に版の切り替えを求める。G はどちらも生じない
  - H(改名の手引きだけ): A と同じく問題が残る

## R-2 事前点検 — 裁定: 名で止める項目を外し、push の契機の形をファイルから読んで止める項目へ置き換える

- 止める項目 `default-branch`(名が `main` でない)を外す
- 代わりに止める項目 `push-trigger` を置く。ファイルを読んで、次のいずれかなら止める(委員2 §3 の1。委員1 §2 の `gate-g5-push.yml` の欠け)
  - `gate-g5-push.yml` が無い
  - `gate-g5-push.yml` の形が R-1 と違う(契機・ジョブ・条件・呼び先)
  - `gate-g5.yml` が `on.push` を持つ(旧版の複製。`branches: [main]` を残したまま持ち込むと、名が `main` でないリポジトリで push の契約検査が黙って走らない)
  - `gate-g5.yml` が `on.workflow_call` を持たない
  - テンプレートのどのワークフローにも、集約のほかに ID か名が `gate-g5` のジョブがある
- 同じ確かめを、契約検査(`verify-gate-contract.mjs`)も PR と push のたびに行う。初期化の後に `gate-g5.yml` へ push の契機を戻す変更を検出する
- 既定ブランチの名と読み方は、事実として点検の結果に残す。読み方が「現在のブランチ」のとき(`origin` の HEAD も手元の `main` も無い)は、読み違いの可能性を告げる注記を出す(止めない)
- 採らない
  - 単に外す(委員1 の当初の案の一部): 旧版の `gate-g5.yml` を持ち込んだリポジトリが素通りする(委員2 §3)。置き換えの項目で塞ぐ
  - 「既定ブランチが `main` でない」を告げる項目にして一覧へ載せさせる(委員2 §3 の2): 名は、既定ブランチが出荷の系列かどうかの手がかりにならない(`main` を既定にして別のブランチから出荷する型も同じく止まらない)。止める理由の無い事実を一覧の照合に掛けると、対処の要る事項と誤読される(委員1 §2)。既定ブランチの主系列を適用の開始と出荷の範囲の基準にすることは、第1章 1.10.1 と第5章がすでに定めている。第5章の本文に、既定ブランチの名を問わないことと、この基準を併記する
  - 契約検査で既定ブランチの名と push の契機の名を照らす(委員2 §3 末尾): G では push の契機が名を持たないので、照らす対象が無い。代わりに上の形の検査で足りる

## R-3 付随の修正 — 裁定

- `/pit`(`next.mjs`)の既定ブランチの読み方を、`origin` の HEAD を先に読む形へ直す(委員1 §3.1・委員2 K-6)。`trunk` のリポジトリで済んだタスクを数えない欠けは、事前点検を外した時点で表に出る
- `adoption-trial.mjs` の env-check の後退(`main`・`master`)は、`gh repo view` を先に読むので、本件では改めない。後退は gh が読めないときだけ使われ、そのときは項目の多くが未確認になる
- 出荷の証跡(`ship-evidence.yml`)と env-check の項目3 は、ワークフローの名 `gate-g5` で実行を探している。push のワークフロー `gate-g5-push` を先に探し、見つからなければ `gate-g5`(手動の起動)を探す形へ改める(委員1 §3.4・委員2 §1.3)
- テンプレートのワークフローの一覧(`TEMPLATE_WORKFLOWS`)、逆向きの追跡の登録(`impl-targets.yaml` または `impl-untraced.yaml`)、標準の本文(第4章 IMPL-0238、第5章の事前点検の表と本文、`ci-gates.md` の未実行の記述、EV-0167 の対象)を改める
- 常駐の規則の核の文言「トランクベース。main は常にリリース可能に保つ」は、本件で改めない。核の文言の変更は標準の規定の書き換えである(ADR-0084 決定2)。既定ブランチが `main` でない案件では、字義どおりに読めない既知の食い違いとして ADR と第5章に記録する(委員1 §3.3・委員2 K-9)。改めるかは、標準のブランチ戦略の語の扱いとして別に扱う
- 既定ブランチでないブランチでの `workflow_dispatch`(委員2 §1.5): 現状の A にもある経路の疑いで、G は広げも狭めもしない。実機で確かめ(R-5 の T11)、確かめた結果を実装の記録に残し、範囲の外として申し送る。本件では塞がない(本件の受け入れ条件の外で、塞ぐ形の審議を経ていない)

## R-4 ADR — 裁定

- 新しい ADR を置き、ADR-0085 の事前点検の止める項目のうち「既定ブランチが `main` でない」を置き換える(一部置き換え)。ADR-0085 の本文は書き換えない

- 採らない方式(A・B・C・D・E・F・F'・H)を表で残す

## R-5 確かめること — 裁定

静的な試験(`template/scripts/gate/` の試験として、違反と適合の対を持つ):

- 形の検査の適合(テンプレートの実物)と違反の変異: `gate-g5.yml` に push を戻す、`workflow_call` を外す、`gate-g5-push.yml` を消す、`branches` を外す・タグを足す、条件を `ref_name` にする、呼び先を変える、呼び出し側のジョブの名か ID を `gate-g5` にする、別のワークフローに名 `gate-g5` のジョブを足す
- 事前点検: 既定ブランチが `trunk` で止めない。`gate-g5-push.yml` が無い・旧版の `gate-g5.yml` で止める
- `/pit`: 既定ブランチが `trunk` で `origin` の HEAD を持つリポジトリで、既定ブランチを `trunk` と読む

実機(既定ブランチ `trunk` の一時のリポジトリ。**テンプレートの実物の `gate-g5.yml` で**。委員2 K-1・委員1 §4.2):

## R-6 根拠水準のマーク — 裁定
