# 議長の裁定(#413 欠陥の検出工程の集計で、AI の指摘から起票された欠陥と人が確定した欠陥を区別するか)

入力: `council-00-agenda.md`、`survey-413-1-internal.md`、`survey-413-2-external.md`、`council-01-drafter.md`〜`council-05-defender.md`。新しい ADR は ADR-0102。

## 0. 前提として確かめた事実

- 起票者の問い(AI の起票で上流の検出が水増しされる)の手前に、より重い欠陥がある。指標「欠陥の検出工程」には算出元が無い(`bug.yml` に「検出ゲート」欄が無く、集計も実装マークも無い)のに、附属書H(C4・C9・H.7・H.9 問5・EV-0062)は運用中の観測として引いている(品質監査・弁護・現場・規格・起案の 5 委員一致)
- 水増しの経路の大部分は、警戒サインが比率(G-7 以降の検出比率)になっていることから生じる。上流の起票が分母を膨らませる(品質監査)
- 重大度の定義が 2 つあり、交差する。障害対応(`incident-response.md`)の Sev1〜Sev4 は初動の緊急度で、Sev2 は「回避策なし」。欠陥トリアージ基準(第4章)の Sev1〜Sev3 は 1.4 の用語で、Sev2 は「回避策あり」。主要機能の障害で回避策がある運用の事象は障害対応で Sev3 になり、ポストモーテムが書かれず、欠陥の台帳に行が足されず、委任が止まらない(弁護・規格)
- 「人確定」は自律レベルの語で、欠陥の確定に使うと衝突する(5 委員一致で使わない)

## R-1 算出元

**裁定**:

- 算出元の正本を欠陥の台帳(`docs/defect-ledger.md`)1 つにする。Issue の様式は正本にしない(5 委員一致。Issue の様式の必須欄は API からの起票に効かず、PR の中で直した欠陥は Issue にならない)。`bug.yml` は報告の入口に留める
- `metrics.md` の「起票テンプレートで必須化」は事実に反するため削る(5 委員一致)
- 指標を、マージの後に見つかった確定した欠陥の件数(工程ごと: 出荷前の検証 / 出荷判定(G-7) / 運用)に改め、同じ期間に取り込んだ変更の件数と並べて示す。警戒サインを比率でなく件数の推移にする(品質監査・規格・現場)。PR の中で直った指摘は数えない(G-6 の検出能力は第5章 5.6.2 の欠陥注入が受け持つ)
- 附属書H の観測から外さない(5 委員一致。外すと EV-0062 が反証の経路を失う)。台帳の集計を引く形に直す。集計の手段が無い構成では「未測定」と開示する
- 欠陥の台帳に列「検出した工程(出荷前の検証 / 出荷判定 / 運用 / 特定できない)」を足す。既存の列「検出の時点(出荷前 / 運用)」は変えない(弁護。ADR-0081 と委任の停止の判定が読む)。2 つの列が食い違う行は集約が示す
- EV-0062 の差し替え条件を、観測できる量(運用で確定した欠陥の件数の推移)へ改める

**採らない案**: `bug.yml` に検出ゲートの欄を必須で足す(API の起票に効かず、PR 内の検出が漏れる)。PR の中の検出を全件記録させる(記録の負担に見合う検出の情報が無い。G-6 は欠陥注入で測る)。指標を附属書H から外す。検出の時点の 2 値を置き換える(起案。委任の停止の入力を変える)。比率の警戒サインを残す。

## R-2 数える母集団

**裁定**:

- 「不具合の報告」(観測された異常の申し立て。AI の指摘・利用者の報告・監視の警報を含む)と「欠陥」(修復または置換を要すると確定した不備)を、第1章 1.4 の用語として分ける(起案・規格)
- 指標に数えるのは確定した欠陥だけとする(5 委員一致)。確定は、台帳の行に「処分」(欠陥 / 欠陥でない / 重複 / 取り下げ)と「確定した者」(人の氏名。AI の名義は不可)と確定日を書くこと。処分の無い行は未処分とする(品質監査・規格・起案)
- AI のレビューの指摘の「採用」・適用を、欠陥の確定とみなさない(5 委員一致。正しいが価値の低い指摘も採用される)
- 確定した者に、作成を指示した者を含めてよい(5 委員一致。欠陥と認める判断は、承認と誘因の向きが逆)。ただし「欠陥でない」「取り下げ」の処分には理由を書く。運用の報告について、原因の変更の作成を指示した者が「欠陥でない」「取り下げ」と処分した行は、集約が「指示した者による処分」と示す(現場。独立を要件にする品質監査の案は採らない。下記の統制を処分で解かないことで足りる)
- 統制は処分で緩めない。G-7 基準2(未解決の欠陥)と委任の停止(5.4.6)は、処分によらず現行どおり台帳の行を読む(規格・起案)。測定と統制の母集団を分ける
- 起票の経路(人 / AI の層 / 機械の検査 / 利用者 / 運用の事象)を列として記録する(現場・品質監査・規格・起案)。ただし経路ごとの件数を指標にせず、対外にも出さない(弁護の懸念を受ける。ADR-0092 決定4 が「AI の指摘の件数」を採用しない指標にしたことと整合させる)。列の用途は、監査と原因の分析に限る。集約が出すのは未処分の件数の合計まで
- 確定した者の欄を、個人の評価に用いない(起案。5.6.2 の個人単位の集計の禁止と同じ理由)
- 語は「人確定」を使わず、「処分」「確定した者」とする

**採らない案**: AI が出所の報告を一律に除く(AI が見つけ人が確定した実際の欠陥を落とす)。経路ごとの件数を出す(弁護。ADR-0092 決定4 の裏口になる)。確定した者を作成を指示した者以外に限る(品質監査の一部。1〜2 名の体制で確定できない)。AI の報告を全件人が再現してから確定する。未処分の件数に警戒サインを付けて指標にする(現場)。処分で統制(G-7 基準2・委任の停止)を解く。

## R-3 工程の帰属

**裁定**: 欠陥は、その欠陥についての報告が最初に記録された時点で進んでいた工程に数える(現場・品質監査・規格・起案。ODC の opener の考え方)。確定した時点・確定した者のゲートでは決めない。AI の層は工程として立てない(5 委員一致)。不採用(欠陥でない)とした報告の後に下流で顕在化した欠陥は、顕在化した工程の新しい報告として数える(弁護の指摘を、この規則の帰結として明記する)。

**採らない案**: 確定したゲートへの帰属。AI の層を工程とする。台帳に「原因のゲート」(本来捕まえるべきだったゲート)の列を足す(現場・品質監査)。理由: 事後検証の判断であり、台帳には既に「原因の変更」の列があり、ポストモーテムが原因と再発防止を記録する。検出の事実の台帳に判断を混ぜない。

## R-4 重大度

**裁定**: 本件で揃える(5 委員一致)。誤っているのは障害対応の側(4 委員)で、1.4 が定義する記号 Sev1〜Sev3 を、別の尺度(初動の緊急度)に使っている(品質監査は「同じ名を付けた点」が誤りとした。結論は同じ)。

- 欠陥の重大度の正本は、欠陥トリアージ基準(第4章)の 3 段階とする
- 障害対応の 4 段階は、初動の尺度として残し、名と記号を「初動の緊急度 U1〜U4」へ改める(「等級」は ADR-0056 が保証の水準に使わないとした語、「E」は根拠の水準の記号と衝突するため避ける)
- ポストモーテムは、緊急度 U1・U2 の事象に加え、原因の欠陥の重大度(トリアージ基準)が Sev1・Sev2 の事象に必須とする(弁護・起案。回避策のある主要機能の障害の穴を塞ぐ)
- 台帳の重大度は、ポストモーテムでトリアージ基準により人が判定して書く。緊急度を重大度へ写さない
- 第4章の「重大度の判定には AI エージェントを参加させてよい」を「AI は判定の材料と案を示してよい。台帳の重大度は人が確定する」へ改める(5 委員一致)
- `bug.yml` の重大度の選択肢の文言をトリアージ基準に揃える

**採らない案**: 障害対応の 4 段階へ統合する。R-4 を別の Issue へ送る(5 委員一致で本件で揃える)。

## R-5 記録と降ろし先

**裁定**: ADR-0102 を起こす。ADR-0092 決定7 の送りへの答えとして位置づけ、ADR-0028・0075・0081・0092 は書き換えない。

- 準拠テンプレート: 欠陥の台帳(列: 検出した工程・起票の経路・処分・確定した者・確定日、注記)、`bug.yml`(重大度の文言、任意の起票の経路)、出荷の証跡の集約(確定した欠陥の工程ごとの件数・未処分の件数・2 列の食い違い・指示した者による処分)、障害の補助ファイル(緊急度の記号、ポストモーテムの条件)
- 降ろし先を登録する: `bug.yml`(template-file)
- 期ごとの推移の集計(期間をまたぐ)は、準拠テンプレートに置き場が無ければ降りていない規定として表示する
- 根拠水準のマーク: マージ後に限る境界と件数の警戒サイン(E1)、確定した者に作成を指示した者を含める判断(E0)、報告が最初に記録された工程への帰属(E1)
- 新しい監査の観点は足さない(品質監査。附属書H の方針と整合)

## 残るリスク(送りではない)

- 処分の記名だけで確定とすると、定型の記名に収束しうる。内部監査の既存の観点と 7.7.8 で見る(弁護)
- 件数の少ない体制では、件数の推移から傾向を読めない。件数と期間の分母を並べて示すにとどめる

## 突合の後の訂正(2026-11-04、`crosscheck.md`)

独立の突合(高 2・中 9・低 9)を受けて、次のとおり訂正しました。

- **H-1**: 集計が台帳の全期間の累計を数え、出荷の範囲の変更件数と並べていた。確定日で出荷の範囲(期間の指定ではその期間)に絞って数え、未処分の件数は現時点の行数と明示した。試験に範囲の外の行の対を足した
- **H-2・M-1〜M-3**: 障害対応の意味の「重大度の判定」「Sev 判定」「Sev1 事象」が、こんなときどうする・開発避難訓練・運用フェーズの概要・リスクカタログ・導入の手引き・第3章・D-0 の見直しの契機・障害時の補助ファイルに残っていた。初動の緊急度の語へ揃えた
- **M-4**: 原因の欠陥の重大度をポストモーテムの中で判定すると、ポストモーテムの要否の判定が循環した。復旧の後、緊急度によらずすべての事象について人が判定し、要否をこの判定で決めると改めた。分担の表の置き場を記録の行へ移した
- **M-5**: 1.4 の「不具合の報告」に、G-7 基準2 と委任の停止は確定を待たずに台帳の行を読む旨を書き、「確定した欠陥」の定義の循環を解いた
- **M-6**: PR の中で直った指摘は台帳に書かないと改め、「出荷前の検証」をマージの後・出荷判定の前の検証と定めた
- **M-7**: 補助ファイル `artifacts/defect-ledger.md` に新しい列と、処分・確定した者は人が書く旨を降ろした
- **M-8**: 2 つの列の照合を処分の有無によらず行い、検出の時点の空欄を示し、「特定できない」を食い違いに数えないようにした
- **M-9**: 指示した者の照合を名簿の同一人物(personKey)で行い、確かめられない行を黙って落とさず示すようにした。試験を足した
- 低: 重大欠陥の流出の数え方を本文に揃えた(検出の時点が運用)、確定日を数える条件にした、ADR の「影響」を置き場に合わせた、「下の」を「上の」へ、警戒サインに原因のゲートの特定を戻した、EV-0062 に IMPL-0394 を引いた、EV-0207・0209 に見直しの向きを書いた。確定した者を名簿と照合しない点と、「不具合」「確定した者」の語の重なりは記録にとどめる(確定した者は人の名簿の外の者もありうる。語は 1.4 で定義した)
