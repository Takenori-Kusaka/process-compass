- 所在: `template/scripts/gate/verification-trace.mjs:351-405`(`readDefectStages`)、`template/scripts/gate/aggregate-evidence.mjs:4394-4397`、`src/content/docs/phase6-operation/metrics.md:183`、`src/content/docs/phase4-process-design/gate-criteria.md:1949`(IMPL-0392 の note)、`adr/0102-*.md:36`

- 推奨: 集約の範囲(`--from`〜`--to` の期間)に確定日が入る行だけを数える。確定日が範囲の外の行は、累計として別に出す。確定日の無い行は数えずに注記へ出す。品質レポートの文言を「範囲内に確定した欠陥」とする。試験に、範囲の外の確定日の行が数えられないことの対を足す。IMPL-0392 の note に「範囲は確定日による」と書く

### M-8 「検出の時点」と「検出した工程」の食い違いの検出が、確定した行に限られ、空欄も見ていない

- 所在: `template/scripts/gate/verification-trace.mjs:400`、`template/templates/defect-ledger.md:17`・`:25`
- 事実: 食い違いは処分「欠陥」の確定した行でしか調べない。裁定 R-1 は「2 つの列が食い違う行は集約が示す」とし、行を限っていない。未処分の行も委任の停止に効くため、食い違いの影響は確定の前のほうが大きい。さらに「検出の時点」が空欄の行は調べない(`when` が空なら飛ばす)。様式は空欄を「運用」として委任を止める。報告の時点で行を足し、検出した工程「出荷前の検証」だけを書いて検出の時点を空にした AI の報告の行は、未処分のまま委任を止め、食い違いとしても出ない。逆に、検出した工程「特定できない」と検出の時点「運用」の組は、食い違いとして出てしまう
- 推奨: 処分によらず全行で照合する。空欄は「運用」として照合する(委任の判定と同じ読み)。「特定できない」は照合から外す。様式の 20 行(報告の時点で行を足してよい)に「検出の時点も書く。空欄は運用として委任を止める」と添える。試験に、空欄の検出の時点と未処分の行の対を足す

### M-9 「指示した者による処分」の照合が、文字列の完全一致で、出荷の範囲の PR しか引かず、試験も無い

- 所在: `template/scripts/gate/verification-trace.mjs:380-381`、`template/scripts/gate/aggregate-evidence.mjs:2825-2831`、`template/scripts/gate/test-defect-stages.mjs`(該当の場面なし)、IMPL-0392 の note(`gate-criteria.md:1949`)
- 事実: `instructorsOf(...).some((n) => n === by)` は完全一致である。`instructedBy` は名簿で解けない記名(アカウント名など、`unresolvedInstructors`)を含み、集約のほかの箇所は `personKey`・`samePerson` で照合している。また `prs` は今回の出荷の範囲の PR だけなので、原因の変更が前の出荷にあれば見つからない。どちらの場合も、黙って「示さない」になり、判定できなかったことが出ない。運用の報告の原因の変更は、たいてい前の出荷にある。試験は D-5 の原因 `#1` が PR に当たらないため、この経路を通っていない。IMPL-0392 は「示す」と delivered にしている(EV-0208 の差し替え条件の観測もこの出力による)
- 推奨: `personKey`/`samePerson` で照合する。範囲の外の PR は GitHub から引くか、引けない行を「原因の変更の作成を指示した者を確かめられない行」として注記に出す。試験に、範囲の内の PR を原因とする「欠陥でない」の運用の行と、範囲の外の行の対を足す
