# 会議体 品質監査委員の意見: #340 要求事項5 の L2 への適用

- 日付: 2026-11-17。立場は監査人。他の委員の文書は読んでいない(独立)
- 読んだもの: intake.md、research.md、research-external.md。本文と ADR-0158 の原文は確かめていない(受付と調査の引用を前提にする)。前提が違えば結論が動く点は各論点に書く
- 判断軸は信頼性。安さ・変更量の少なさは理由にしない
- 監査の問い: 採用者が「要求事項5 を満たす」と主張したとき、残る証跡がその主張を支えるか。支えない主張を、標準が黙って許していないか

## 0. 結論(先に)

- 推す案: **案 B の型(5.4.5 の条件に1行足す)に、案 C の証跡(既存のテンプレ9)を結ぶ組み合わせ**。新しい記録は作らない。条件7は「テンプレ9 に、実行の単位ごとの停止条件を強制する手段の所在が書かれている」を B-2 が確かめる、とする。名称は便宜上「案 BC」
- 落とす案: 案 A(L3 に限る)。案 B 単独(新しい記録を作る形)
- 組み合わせは受付の案の外である。**議長が案として立てるか裁定してほしい**。立てない場合の次点は案 C(1文足す形)だが、B-2 の確認項目が表に無いまま「再評価で確かめる」と書くと、確かめた証跡が残らない(下の P2)
- 機械で閉じる条件は無い。全部 manual。有効性は開示で閉じる(P3)

## 1. 所有者の3問への当て方

### (1) 条文は結果と証跡まで

- 結果: 既に要求事項5 にある。足すのは「いつ(5.4.5 の判定)」と「何が残るか(実行の単位ごとの所在、または該当なし(理由))」だけ
- 条文に書かないもの(手引きへ): 遮断の実装方法、3種の停止条件の数値の決め方、製品ごとの設定の場所。外部の調査で、手段は製品ごとに別の場所にあると分かった(N-1〜N-8)。条文が手段を指定すると、1年で陳腐化する
- 条文に書かないもの(課さないと決めて明記): 有効性の機械の検査、遮断が発動した実績の提出

### (2) 例外承認で受けられないか

- 受けられない(7.3 が要求事項5 を名指さない。調査 2.1)。この点は異論なし
- 新条項も要らない。珍しい構成(自作の基盤、外部サービス、強制できない単位)は、所在の欄に書く、「該当なし(理由)」と書く、強制できない単位は L1 に留める、の3つで受かる。**抜け道の封じのために条項を増やさない**。「所在」の質は、テンプレ9 が既に持つ RRS3(文章だけは強制と認めない)で締まる
- 注意: 「該当なし(理由)」は自己申告で最も崩れやすい。理由の欄を空にさせない(存在の検査)ことと、内部監査の抽出で理由を読むこと、の2つで足りる。理由の内容の妥当性まで条文化しない

### (3) 破られたとき誰が何を失うか

- 失う者は費用の負担者(受託では発注側でありうる。ADR-0114)と、適合の主張の信頼。取り消せない損失ではなく、安全関連部は L1 固定なので人の安全にも直接は及ばない
- したがって**細かく書くのは「適合の主張の信頼」に響く部分だけ**。具体的には、「記録がある」と「遮断が働く」の取り違えを防ぐ開示。遮断の仕様や値は細かく書かない
- 例外: CL1・CL2 の案件は L2 が唯一の引き上げ先で、遮断の照らしが1つも無い(調査 3.4)。ここは信頼の穴なので、照らしを置く理由として重く数える

## 2. 論点ごとの意見

### P0 範囲: E3 を含めるか

- 立場: **本件の裁定は L2 に限り、E3 は分離してよい。ただし沈黙で分離しない**
- 理由(監査): 要求事項5 の直後の段落は L と E の2軸に対応すると書く。L2 だけを閉じて E3 に触れないと、採用者が「要求事項5 は満たした」と主張したときの範囲が曖昧になる。E3 の前提条件の表には停止条件の行が無い(調査 2.2)ので、E3 は実際に照らされていない
- 分離の条件: (a) 新 ADR に「E3 は本決定の範囲外。照らしは無い」と明記する。(b) 要求事項5 の段落(または台帳の実装マーク)に、E3 側が未達であることを `state=undelivered` 相当で表示し続ける。(c) 既存の open Issue へコメントで寄せる(新規の起票は実行で確かめた欠陥のみ、の方針どおり)
- 含める案の弱点: 照らしの時点(`ai-environment.md` の段階導入の目安)も記録の場所も別で、E3 の事実調査(E3 の運用実態)を本件は行っていない。調べずに条を書くのは、コアポリシー違反になる
- 落とす案: 黙って L2 だけ決める(適合の主張の範囲が曖昧なまま残る)

### P1 要求事項5 は L2 に掛かるか

- 立場: **掛かる**。条文の自然な読みどおり
- 理由: 「遮断の手段を持たないまま自律水準を上げる構成を認めません」は、文言上 L1 からの引き上げ全般に掛かる。L2 は定義上、自己修正ループに依る唯一のレベルで、暴走の場所と重なる(調査 3.1)。外部には「L2 では遮断が要らない」という根拠が無い(外部 3.2)。外部は段階で線を引かず、L3 だけに課す設計は本標準の固有(外部 4 節)
- 案 A を落とす理由: (1) 採用済みの文言を縮める。縮めるなら縮める根拠が要るが、根拠が無い。(2) CL1・CL2 の唯一の引き上げの手段に照らしが無くなる。(3) 「要求事項1 が覆う」は、判定の時点に確認が無いことの説明にならない。要求事項1〜3 は L1 から掛かるのに、L1 では何も確認されていないのが現状であり、そこで 5.4.5 が確認の最初の機会になる
- 補足: 外部に有ることも、課す根拠にならない(外部 4 節)。課す理由は本標準の内部、つまり L2 の定義と CL の上限にある。これは**暫定の根拠水準マークを付けて開示する**(P3)

### P2 照らす時点と証跡

- 立場: **時点は 5.4.5 の B-2 の判定。証跡は既存のテンプレ9。確認項目は 5.4.5 の条件の表に1行**(案 BC)
- 監査の論拠:
  - 証跡は1か所に置く。新しい記録を作ると、テンプレ9 の「時間上の限界」・RRS1 の実装場所と同じ事実が2か所に書かれ、食い違ったときにどちらが正か決められない。監査人は食い違いを見つけた時点で、両方を信用できなくなる
  - テンプレ9 は L2 以上で必須、承認済みが G-1 の前提(適用条件4)なので、**判定の時点で既に存在する**はずの証跡である。新しい様式を採用者へ増やさない
  - しかし案 C のように「再評価で確かめる」の1文だけでは、B-2 が何を確かめたかが判定の記録に残らない。5.4.5 の判定は条件1〜6 の表で確認する構造なので、その中に行が無いと、確認の漏れが外から見えない。**確認項目は表に置く**。この点で案 C 単独を落とす
  - 案 B 単独を落とす理由: 上の二重記入。ただし条件7の文言(実行の単位ごとに所在、または該当なし(理由))は案 B のものを採る
- 条件7の置き方(条文の形の案): 「テンプレ9 の時間上の限界の欄(または RRS1 の実装場所)に、3.12.10 の実行の単位ごとの強制の手段の所在が書かれている。使わない単位は該当なし(理由)」。B-2 は存在と所在の具体性(RRS3 でないこと)を確かめる
- 要確認の突合点(議長へ):
  1. テンプレ9 の「時間上の限界(自律実行の上限)」の欄が、停止条件3種の強制の所在を書ける欄かどうか。目的が安全リスクアセスメントで、費用の遮断と違う(案 C の弱点)。**様式の欄の意味を変えるなら、準拠テンプレートの様式に及ぶ(直列)**。欄を増やす場合は `template-fields.yaml` の両方向の検査に載せる。ここは起案役と規格役の裁定を仰ぐ
  2. **L3 との重複**。L3 は L2 以上でもあるのでテンプレ9 も必須である。L3 の登録の根拠の4点目(ADR-0158)とテンプレ9 に、同じ所在を2回書かせている可能性がある。ADR-0158 の4点目を「テンプレ9 の該当欄の参照で足りる」と読めるか、読めないなら二重を許す理由を書く。ADR の原則に触れるので、決定の改廃にするか注記にするかを議長が決めること
  3. 条件の表が「条件1〜6」の連番で、条件6 が引き下げと切り戻しである。条件7を足すと IMPL・lint:refs・観点23 などの参照が動く。`npm run lint:refs` で番号の実在を確かめる
- 準拠テンプレートへの降ろし方: 後述の 3 節

### P3 統制の閉じ方

- 立場: **全て manual。機械で閉じる条件は無い。有効性は開示で閉じる**
- 理由: テンプレートは L2 を表せない(IMPL-0289)ので、「L2 の案件のテンプレ9 に所在がある」という条件すら、テンプレート側は L2 かどうかを知らない(IMPL-0454 は manual)。決定可能に見える条件(欄が空でない)も、**適用の対象(L2 か)が決まらないので機械の検査にならない**。ここで機械の検査に見せかけると、表示と実態が食い違う
- 閉じ方の線引き:

| 統制 | 種別 | 理由 |
| --- | --- | --- |
| B-2 が判定時に条件7 を確かめる | manual | L2 が構成で表せない |
| 内部監査の観点23 に「遮断の所在の記録の存在」を足す | manual | 抽出で適用中の L2 を拾う |
| テンプレ9 の欄の存在 | 既存の presence(IMPL-0874)のまま | 欄が増えるなら template-fields.yaml に両方向で載せる |
| 強制の有効性(実際に止まるか) | **adopter。undelivered として表示** | 決定可能でない。自由文の意味や改ざんの防止は機械で閉じない(コアポリシー) |
| 「該当なし」の理由の妥当性 | adopter | 同上 |

- 保証の開示の線: 「B-2 が判定した L2」と並べて、**「遮断の所在の記録が存在する。有効性は確かめていない」と書く**。ここを省くと、記録の存在を遮断の実効と読まれる(適合の主張の信頼が失われる)。これが本件で最も細かく書くべき一点
- 根拠水準マークが要る記述(`:::caution[暫定 EV-NNNN / 見直し YYYY-MM]`):
  1. 「L2 の判定時に遮断の所在を確かめることが、L2 の暴走の費用を減らす」: 外部に直接の根拠が無く、考察(外部 3.2)。単一事例は FND-0102・Replit
  2. 「記録の存在で足りる」: 有効性まで確かめない選択。実証が無い
  3. 移行の猶予の長さ(P4)
- 見直しの契機を付ける: 外部の穴(EUR-Lex 原文、OWASP ASI10 の PDF、IEC 61508 など。外部 6 節)が埋まったとき。追加の抜き書きを `research/sources/` に残す

### P4 既存の L2 の運用への移行

- 立場: **即時停止にしない。ただし期限の無い猶予にしない**
- 理由: 損失は費用と信頼で、取り消せないものではない。即時にすると適合の主張が一斉に崩れる。一方、再評価(引き上げの判定)は引き上げるときにしか走らない。L2 のまま運用を続ける案件は、判定の機会がもう来ず、永久に照らされない。**L3 に猶予が無かった(ADR-0158)ことは、L3 が登録の時点で必ず通る門を持つからで、L2 の運用中の案件は同じ門を持たない**。ここは L3 と事情が違う
- 案: 施行の日以降、(a) 次の引き上げ・ステージ移行の判定、(b) 次の内部監査(観点23)、(c) テンプレ9 の次の改版、の**いずれか早い方**で記録を求める。それまでは保証の開示に「遮断の所在: 未記録」と出す(適合の主張を偽らない)。期限は内部監査の1周期を上限に置く
- 落とす案: 次の引き上げ判定まで猶予(上の理由で、照らしが来ない案件が残る)。即時(取り消せない損失が無いのに、全案件の主張を同時に無効にする)
- 猶予の長さは実証が無い。暫定マークで開示

### P5 「自律実行」の語

- 立場: **語を定義しない。要求事項5 の対応先の文を L と E の語で書き直す**
- 理由: 3通りの用例(7.11 は走っている実行、enablement は L2 以上、compute-strategy は E3 近傍)を1つに定義すると、他の用例を壊す。定義を増やすと、細かい定義が増える(テンプレートは標準を体現する、の記憶にある線引き未決の問題)。監査人が検査できるのは「L1 より上への引き上げの判定の時点」という検査可能な語で、「自律実行」という曖昧な語ではない
- 形: 直後の段落の冒頭で「要求事項5 の解禁は、L1 より上への引き上げ(5.4.5・5.5.4)と、E3 の解禁を指す」と対応づける。要求事項5 の表の文は動かさない。表の文を直すなら、編集の指摘ではなく意味の変更になりうるので、議長が分類する
- 落とす案: 触らない(監査人が検査の対象を特定できない)

## 3. テンプレート(template/)への降ろし方

この束では触らない。次の束へ送る内容だけを書く。

| 内容 | 降ろし方 | 備考 |

## 4. 採らないと決める事項(記録の案)

- 5.4.5 の判定で、強制の有効性を機械で確かめる(決定可能でない)
- 外部に L2 の遮断を直接求める基準が無いことを、課さない根拠にする(不在は根拠でない。有ることも課す根拠でない)
- CL ごとに L2 の照らしを書き分ける(ADR-0039。ただし CL1・CL2 の唯一の手段であることは**課す理由として使う**。これは CL から適用外を導く話ではなく、適用の必要を導く話であり、ADR-0039 と矛盾しないかを突合で確かめる)
- 例外承認で強制の欠如を受ける(7.3 の対象外)
- 新しい独立の記録様式を作る(二重記入)
- 「自律実行」の語を定義する

## 5. 残る不確かさ(監査人として)

- 本文と ADR-0158 の原文は読んでいない。条件の表の構造(連番か、行ごとの判定か)と、テンプレ9 の欄の実際の中身は、議長か規格役が確かめること
- 案 BC は受付の案に無い。競わせて落とす前に、起案役が別案(例えば、条件7を置かず B-2 の判定の記録の様式にテンプレ9 の確認欄を足す)を出すかもしれない。どちらも「確認項目を判定の側に残す」点では同じで、私の主張の核はそこにある
- 外部の「無い」の確認は不在の証明で弱い(外部 1.3)
