## 1. 問いの特定

**問い**: 第3章 3.12.10 要求事項5「停止条件を強制できない環境で、AIエージェントの自律実行を解禁してはならない」は、AI自律レベル L2 への引き上げ(第5章 5.4.5 の B-2 の判定)にも掛かるか。掛かるなら、L3 の登録(ADR-0158 決定5)と同じく**強制の手段の所在の記録**を判定の時点で求めるか。

- 決まっていること: 停止条件の強制そのものはレベルに依らず要求事項1〜3 が課す。L3 の登録には所在の記録を求める(5.5.4 の4点目)。準拠テンプレートは L2 を支えない(ADR-0081 決定6)ので、L2 の規定はどれも manual になる(調査 2.1・5 節)
- 未決のこと: 5.4.5 の判定の時点で、遮断の手段を照らすか(ADR-0158 決定8)。条件の表(条件1〜6)に遮断の行は無い。条件6 は引き下げと切り戻しの手順で、3.12.10 とは別物(調査 3.2 節)
- L2 の定義の所在: `human-ai-boundary.md:67`(5.4.2 の表)。監視者は「人間が統合点を確認する」、フォールバックは「人間および自己修正ループ」(調査 3.1 節)

**受付で見つけた隣の論点**: 要求事項5 の直後の段落は、第5章の自律水準**と**フェーズ5 の実行形態の段階導入(E1〜E3)の両方に対応すると書きます(2026-08-07 の新設の時点から)。E3 の解禁の前提条件の表(`ai-environment.md` 段階導入の目安)にも、停止条件の強制の行がありません(調査 2.2 節)。同じ文の読みなので、本件の範囲に含めるかを議長が受付で決めてください(論点 P0)。

## 2. 所有者の方針の3問

### (1) 条文に書くのは満たすべき結果と残る証跡まで。手順は手引きへ

- 結果は既に条文にある(要求事項5 の「してはならない」)。足りないのは、**L2 で照らす時点と、残る証跡**である。L3 では ADR-0158 がそれを登録の根拠に置いた
- L2 の照らしの時点の候補は 5.4.5 の B-2 の判定だけである(7.7.8 要求事項6 も拡大の判断点を 5.4.5 と 5.5.4 と名指す。調査 3.3 節)
- 証跡の候補は2つ。(a) 新しい記録(申請への添付)。(b) **既存のテンプレ9**。L2 以上で必須、G-1 の前提条件、引き上げの判定で再評価を伴う(IMPL-0861)、「時間上の限界(自律実行の上限)」の欄と、RRS1 の実装場所の欄がある(調査 3.3 節)
- 遮断の実装の手段(実行基盤の設定、接続経路の上限)は手引き(compute-strategy「実行の強制停止の実装」)に既にある。条文へ上げない

### (2) 珍しい構成や抜け道は、新条項でなく第7章の例外承認で受けられないか

- 例外承認では受けられない。7.3 の対象はゲートの判定基準と 7.3 を名指した事項に限り、要求事項5 は 7.3 を名指さない(`348-340-q-deliberation/decision.md` 0 節で議長が本文を確かめた)
- 受けなくても、珍しい構成は既存の道で受けられる。自作の実行基盤や外部のサービスは、所在に書けば足りる。強制できない単位は L1 で使う。新しい経路は要らない
- 3.12.10「停止したときの扱い」の停止条件の緩和は第7章 7.4 による。ただし、これは値の緩和であり、遮断の手段の欠如を受ける経路ではない

### (3) 破られたとき、誰が何を失うか

- L2 では人が統合点しか見ず、定義の上で自己修正ループに依る(調査 3.1 節)。統合点の間の反復が、複数の機能で並行して無人で回る。遮断が無いと、費用は有界でなく、並行の数だけ増える。3.12.7 の総量の統制は事後にしか効かない
- 失う者: 費用の負担者(ADR-0114 で契約に記録する者。受託では発注側でありうる)と、適合の主張の信頼。保証の開示が「B-2 が判定した L2」と出す範囲で、遮断が働いていないことになる
- 安全: 安全関連部は R1・L1 固定であり、L2 が掛かるのは安全関連部の外である。人の安全へ直接は及ばない。ただし **CL1・CL2 の案件で L1 より上へ上げる手段は L2 しかない**(CL2 の上限は L2。L3 は CL0 だけ)。ADR-0158 の照らしは CL0 にしか届かず、CL1・CL2 の案件の自律の引き上げには遮断の照らしが1つも無い(調査 3.4 節)
- 取り消せない損失ではない。損失は費用と信頼であり、遮断の欠落として有界でない点が要点である

## 3. 審議の重さ: 重(指揮役の指定を、理由とともに確かめた)

重の4つの当たりのうち、次の3つに当たります。

## 4. 外部の調査の問い(3つ)

既存の出典で足りる分は調査 6 節(FND-0001・0002・0175・0102、SRC-0241・0495・0623・0087)。台帳に無いものを問います。

1. **製品の実務**: 主要なエージェントの実行基盤(Claude Code、GitHub Copilot coding agent、OpenAI Codex、Devin、Factory、Cursor の background agents など。2026-11 時点)は、無人・非同期・並行の実行を有効にする条件として、反復回数・時間・費用の上限を**実行基盤の側で強制**しているか。それは自律度の段階(監督付き → 非同期)と結び付けられているか、全段階に一律か
2. **規格・公的指針**: 自律の段階を上げる前提条件として、停止(中断)の手段を求める規格・指針はあるか。候補は EU AI Act 第14条4項(e)(stop の手段)、ISO/IEC 42001 附属書A、NIST AI RMF・AI 600-1、ISO/IEC 22989 の自律の段階、IEC 61508・ISO 13849 の安全機能の前提、OWASP Agentic(ASI10)、CoSAI。段階ごとに書き分けるか、一律か
3. **監督付きの並行実行(HOTL)での遮断**: 人が統合点だけを見る形(L2 に当たる)で、人の監督を機械の遮断の代わりに数える実務・指針はあるか。逆に、監督の有無に依らず機械の遮断を求める根拠(自動化への過信、統合点の間の無人の反復)はあるか
