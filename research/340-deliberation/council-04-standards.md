## 0. 規格の観点の総括

1. 外部は段階で線を引いていない(第14条4項(e)、NIST MANAGE 2.4 は一律。製品は上限を段階の前提にしない)。よって案 A(L3 に限る)を外部の整合で支えることはできない。L3 だけに課す根拠は本標準の内部(ADR-0158)にしかない
2. 同時に、案 B・C の「引き上げの判定の時点で確かめる」も外部が求めたものではなく、本標準の選択である。外部が求めるのは手段の有無まで。この非対称(どの案も外部の裏付けは無い)を、根拠水準マークで正直に開示する
3. 規格の書き方の原則(要求事項は結果、証跡は既存の記録、手順は手引き)に最も合うのは、新しい記録を作らず既存の記録に結ぶ案 C を土台にする形である
4. ADR-0158 との矛盾は、案 A が最も大きい(「自律水準を上げる構成を認めません」を縮める。決定8 が送った論点そのもの)。案 B・C は決定5・8 と矛盾しない。決定8 は「L3 に限るとも、L2 へ広げるとも決めていない」ため、新 ADR で閉じれば足り、ADR-0158 の本文は書き換えない

## 2. 論点ごとの立場

### P0 範囲: E3 の解禁を本件に含めるか

- 立場: 含めない。既存の open Issue へコメントで寄せる(新規の起票は実行で確かめた欠陥だけ)
- 理由
  - 軸が違う(ai-environment.md:23 は L と E を独立に設定すると書く)。照らしの時点(E3 の解禁の前提条件の表)も記録の場所も別で、1つの会議体で両方を決めると、突合の対象が倍になり、独立の突合の質が下がる
  - 外部の整合の面でも、E(実行形態)に対する外部の直接の根拠は同程度に薄い(製品の上限の強制は実行形態ごとに別。Copilot の 59 分は基盤固定、Claude Code は print モードの旗)。E3 を急いで同じ型に揃える利点は無い
- ただし条件: 本件の結論が要求事項5 の文を触る(P5)なら、**E3 の扱いを「決めていない」と明記して残す**。「書かれていない」と「課さないと決めた」の区別を保つ(コアポリシー)。ADR に「E3 は本件の範囲外で、別 Issue で扱う。要求事項5 の対応先に E が残る点は現状維持」と書く
- 落とす案(含める): 同じ文の読みという点は正しいが、含めると P2 の時点の候補が2系統になり、manual の統制が2本になる。分離のコストより混ぜたときの欠陥の方が大きい

### P1 要求事項5 は L2 に掛かるか(条文の読み)

- 立場: 掛かる(L1 より上へ上げる判定の全般に掛かる)。L2 に掛けない読みは採らない
- 理由
  1. 文の読み: 直後の文は「遮断の手段を持たないまま自律水準を上げる構成を認めません」。「上げる」に L2 を除く限定語は無い。L3 だけの読みは、後から足した ADR-0158 の3文に引きずられた縮小である
  2. 外部: 段階で線を引く規格・製品は確認できなかった(research-external 4 節の帰結1)。外部に不在であることは課さない根拠にならず、有ることも課す根拠にならない。この点は両方向で等価
  3. 内部: L2 は定義の上で自己修正ループに依る唯一のレベルで(5.4.2)、3.12.10 が想定する暴走の場所と重なる。さらに CL1・CL2 の案件で L1 より上へ上げる手段は L2 しかない(調査 3.4)。案 A は、この範囲の遮断の照らしを0にする
  4. 規格上の整合: 上位のレベルほど厳しい要件を課す構造(L3 は4点目を要す)は保たれる。L2 に求めるのは L3 より軽い照らし(既存記録の確認)にとどめれば、段階の逆転は起きない
- 落とす案: **案 A**。理由は上記。加えて、ADR の原則(採用者の義務の範囲)を縮める変更を、外部の裏付け無しに行うことになる。「新しい義務が無い」は強みに見えるが、要求事項1〜3 は L1 から既に掛かっており、L2 で足りるのは義務ではなく**照らす時点**である。時点を置かないと、義務はあっても検出されない
- 注意(誠実に): 案 A に立つ読みも、要求事項1〜3 が全レベルに掛かる以上、遮断が無い構成は既に不適合という点では一貫する。案 A の弱点は「不適合を判定の時点で見つける機会を L2 で捨てる」ことで、義務の有無ではない

### P2 照らす時点と証跡の置き場

- 立場: **案 C を土台に、5.4.5 に1文(時点の指名)を足す。新しい記録の様式は作らない**。案 B の条件7(新規の記録)は落とす
- 具体
  - 時点: 5.4.5 の B-2 の判定。テンプレ9 の再評価(IMPL-0861。判定に伴う再評価)で確かめる、と既存の結びを使う。7.7.8 要求事項6 が 5.4.5 を判断点と名指す既存の構造とも合う
  - 証跡: テンプレ9 の「時間上の限界(自律実行の上限)」欄と RRS1 の実装場所。L2 以上で必須・G-1 の前提という既存の強制力をそのまま使う
  - 条文に書くこと(案): 「L2 への引き上げの判定では、3.12.10 の実行の単位ごとに、停止条件を強制する手段の所在を、テンプレ9 の再評価で確かめる。所在を示せない単位は、L1 で使う」。結果(強制の所在が示せる)と証跡(テンプレ9)だけ
- 理由
  - 規格の原則: 同じ事実を二度記録させない。条件7 を新設すると、テンプレ9 の欄と二重の記入になり、後で食い違う(2つの記録のどちらが正本かが分からない)
  - 既存の語彙・規定との整合: 「実装場所を書く。文章だけは RRS3」(:2143)が、所在の記録の質の規則として既にある。ADR-0158 決定5 の「場所と手段の名」「機械は記入の有無まで」「有効性は確かめない」と同型で、新しい思想を持ち込まない
- **突合で必ず潰す弱点(案 C への条件)**
  1. テンプレ9 の目的は安全リスクアセスメントで、費用の遮断とは目的が違う。「時間上の限界」欄が、3.12.10 の3種(反復・時間・費用または同等)を実行の単位ごとに書かせる欄になっているかを、本文で確かめる。**ならない場合に欄の意味を変えると、準拠テンプレートの様式(template-fields.yaml の双方向検査)に及び、直列の Issue になる**。この束ではテンプレートに触らない前提のため、条文は「欄に書く」でなく「テンプレ9 の記録のどこかに、実行の単位ごとの所在が示されていること」と**欄を指名しない書き方**にする。欄の細分化は手引き
  2. L3 の記録(5.5.4 の登録の根拠の4点目)との置き場所の分裂。L2 → L3 へ上げるとき、同じ所在を二度書かせないために、**4点目はテンプレ9 の該当記録を参照して足りる**と手引きで示す。ただしこれは ADR-0158 決定5 の変更ではなく、記録の実体の置き場を妨げない運用の説明にとどめる。決定5 の「記録は所在を示すだけ」と矛盾しない
  3. CL0 で L2 を採るときもテンプレ9 は必須(適用条件4)なので、範囲は合う。CL1・CL2 でも合う
- 落とす案
  - 案 B(条件7 の新設): 二重の記入。ただし「テンプレ9 が無い・形骸化している」場合の保険にはなる。この点は弁護委員が突く可能性があるので記録する。規格の観点では、保険のために記録を二つ持つ方が信頼性を下げる(正本が曖昧)と判断する
  - 強制の有効性を機械で確かめる: 決定可能でない(ADR-0158 と同じ)
  - 要求事項5 を削る・要求事項1 へ吸収: 要求事項1 は「強制する」義務、5 は「解禁の時点で照らす」義務で役割が違う
  - 例外承認で受ける: 7.3 の対象外。かつ適合の主張の信頼を損なう
  - CL ごとの書き分け: ADR-0039 に反する

### P3 統制の閉じ方

- 立場: manual(B-2 の判定と内部監査の観点23)。機械で閉じる条件は無い。準拠テンプレートは L2 を支えない(ADR-0081 決定6、IMPL-0289)
- 実装マーク: `target=` は adopter か manual の既存の降ろし先のみ(impl-targets.yaml に登録のもの。登録外は使えない)。state は undelivered を維持して表示し続ける(消さない)。IMPL-0861(テンプレ9 の再評価。delivered・manual)に、強制の所在の確認を含む旨を足す形を第一候補とする。新しい IMPL を増やすか、既存の注記を広げるかは実装の段で決める(規格の観点では、マークの数を増やさず既存の統制に結ぶ方が追跡しやすい)
- 内部監査の観点23: 「適用中の L が 5.4.5 の判定と計測の手段に裏づけられているか」に、遮断の所在を一句加える。自由な文の意味の確かめは manual と開示する
- 根拠水準マーク: **要る**(下の 3 節)。manual の統制は、判定者が省いても機械が検出しない。この限界を表示する(「機械は何も確かめていない」旨)。ADR-0158 の IMPL-0983 の表示の型を使う
- 採らないと決めたことの記録: 「5.4.5 の判定の時点で強制の有効性を機械で確かめることはしない」を明記する(課さないと決めたのであり、書かれていないだけではない)

### P4 既存の L2 の運用への移行

- 立場: 移行の猶予は置くが、無期限にはしない。**次の B-2 の判定(引き上げの再評価・ステージ移行)の時点、または内部監査の次の周期のいずれか早い方で照らす**。即時の停止は課さない
- 理由
  - L3 で猶予を置かなかったのは、機械が止める経路(登録の停止)があるから。L2 は manual で、即時と次の判定の間に実質の差が出ない(機械が検出しない)。即時を条文に書いても、誰も検出しない約束になる(表示と実態の食い違い)
  - ただし、要求事項1〜3 は L1 から既に掛かっており、猶予中の L2 は既存の義務の不履行を黙認するものではない。猶予が解くのは**照らす時点**であり、義務ではない。これを明記して、猶予が義務の免除と読まれないようにする
  - 猶予の上限を置かないと、判定が来ない案件(ステージ移行が無い長期運用)で永久に照らされない。観点23 の周期を上限にする
- 根拠水準マーク: 要る。「いずれか早い方」の選択に実証が無い(単一の判断)
- 落とす案: 即時の照らし(検出手段が無く、実態と食い違う)。猶予無し(L3 と揃うが L3 は機械の停止を持つ)。猶予の期間を数値で決める(根拠の数値が無い。周期への結びにとどめる)

### P5 「自律実行」の語

- 立場: 語は定義しない。要求事項5 の文を L と E の語で書き直す。7.11 などの他の用例は触らない
- 書き直しの案: 「停止条件を強制できない環境で、AI自律レベルを L1 より上へ、または実行形態を E3 へ上げてはならない」
- 理由
  - 規格の用語の規律: 一語一義。「自律実行」は3義あり(7.11 は走っている実行、enablement は L2 以上、compute-strategy は E3 に近い)。定義すると3つのうち2つを誤用に変える。既に別の語(L・E)で書ける概念に新しい定義語を足すと、細かい定義の増加(テンプレ体現の方針の懸念)になる
  - 7.11 の用例はレベルを問わない「走っている実行」で、要求事項5 の意味ではない。触らなければ無用な改訂を避けられる
  - 手引き(enablement.md:317)の「自律実行」は L2 以上の意味で、書き直した要求事項5 と整合する。手引きは任意で修正してもよいが必須でない
- 注意(編集か否か): 「自律実行を解禁」→「L1 より上へ」は、直後の文の既存の読みと一致させるもので、意味を変えない可能性が高いが、**P1 で L2 に掛けると決めると、読みを確定する効果を持つ**ため、編集の指摘として会議体なしで直すのでなく、本件の結論に含めて決める
- E の部分は P0 で範囲外と決めるなら、書き直しは「実行形態を E3 へ」を残すだけで、E3 の照らしの時点は決めない。ここは現状維持
- 落とす案: 語を定義する(一語一義に反し、定義の増加)。触らない(用例が3通りのまま、P1 の結論が読み手に伝わらない)

## 5. テンプレートへ降ろす場合(この束では触らない)

| 層 | 降ろし方 |
