## 1. 改め

### 1.1 出力の約束(論点1。閾値の無い構成を含む)

- 段のコマンドは、決まった形の1行で **スコア(数値)か「対象の変異体なし」を示す値**、と **生き残りの一覧の所在(空でない文字列)** を出す。行が無い・スコアが数値でも「なし」の値でもない・所在が空、のどれかなら段は失敗(未測定を通さない)
- 「対象の変異体なし」の値は通す(閾値があっても比較しない)。理由: 文書だけ・設定だけの R1 の変更が偽の失敗になると、`true` を置く逃げを採用者に教えることになる
- 閾値(`ci.mutationThreshold`)は**基底ブランチの構成**から読む。設定があるときだけ比較して合否に使う(回答 44)。無いときは「閾値なしで通過。走った事実と所在だけを証跡とし、検出力が足りるとは主張しない」と段の出力に1行で出す
- 出荷の集約(G-7 の材料)は、**構成に閾値が無いこと**を注意の1行で出す(構成の値を読むだけ。決定可能)
- 採らない: (a) 所在の実在を機械で確かめる(所在は URL・CI の成果物でもありうる。決定可能でない。manual で開示)。(b) 閾値なしで通った R1 の PR の件数を集約で数える(段のジョブのログの保持に依る。構成の注意1行で足りる)。(c) PR ごとに注意の注釈を積む(現場の委員の指摘。出力の1行にとどめる)

### 1.2 G-5 で止めることと H の帰結(論点2)

- 附属書H の「検証に数えない」の文は**変えない**。G-5 を経ない変更・閾値なしの通過・対象なしの構成の受け皿として残る
- IMPL-1029 のマークの note に「G-5 の段の通過は、検出力を測ったことの十分条件ではない」と書く。条文へ一句を足す案(弁護)は採らない(note の開示で足りる。条文を増やさない)
- 案と委員の引用の節番号(H.3 か H.4 か)は、実装の担当が現物で確かめて記録する。`npm run lint:refs` を通す

### 1.3 R1 の判定の源(論点3)

- PR の経路: 本文の区分(`riskClassOf`)と下限(`riskFloorOf`)の高いほう。PR の本文はイベントのペイロードから読む(fork の PR でも読める形にする。読めない形しか無ければ実装の記録に書いて議長へ返す)
- push の経路: **トレーラ `Risk:` と下限の高いほう**(起案・規格・弁護)。下限は push の範囲の変更ファイルから決定可能。トレーラは書く者が省けるため、下限を併せる
- **判定の入力が読めないとき(本文も変更ファイルも取れない)は、必須の側に倒す**(段を必須として扱う)。適合の主張の信頼に響くため。浅い checkout で差分が取れない失敗は、ワークフローの取得の深さで避け、試験で固定する
- 採らない: (a) 下限だけで R1 を決める(人が上げた R1 を落とす)。(b) push の経路を確かめない(現場。出荷の集約が欠落として扱うのは事後で、段の必須とは別の統制)。(c) R2 と書いて段を省いた PR の件数を集約に出す(品質監査。区分の確定は 3.8.1 の確定者と G-6 の既存の統制。機械で閉じない旨を manual で開示)
- squash マージの後にトレーラが残るかは、実装で確かめる。確かめられなければ根拠水準マークで開示する

### 1.4 移行と template の既定(論点4)

- 7つのアダプタに空の `mutation`・`regulatory` を置く。既定のコマンドは置かない(依存の追加は採用者の G-3 の技術選定)
- 段が必須でない PR で段が空のとき、「R1 の変更の PR では、この段が空だと G-5 が失敗する」と注意を1行出す(規格。取り込みの日に気づける)
- 手引き(`kinds/settings.md` と README の移行の注意の1項)に、終了コードで合否を返せることを外部の調査で確かめた道具だけを例として置く(node: Stryker。python: cosmic-ray。go は例を置かず「外部の記録を照らすコマンド」を案内する)。時間の上限を勧める文は手引きにだけ置く
- PR ごとの増分実行の所要時間と費用は公開の実測が無い(`research-ext-1.md` 点1)。**根拠水準マーク(新しい EV)で開示する**
- 採らない: (a) スタックごとの既定のコマンド。(b) 取り込みから一定期間は注意にとどめる(回答 43 と食い違う)。(c) `true`・`echo` の類を型で見分けて注意に出す(列挙が閉じない。既存の段に同じ検査の先例があるときだけ、それに揃える。先例の有無は実装の担当が確かめて記録する)。(d) CHANGELOG.md の新設(指揮役の決定)

### 1.5 外部の記録を照らすコマンド(論点5)

- 機械が見るのは §1.1 の出力の約束だけ。道具のある言語でも外部の記録を使えることを明記し、コマンドの実質・記録の真正・新しさは **manual**(確かめる者: G-6 の判定者)で開示する
- 採らない: (a) 記録の日付・mtime の検査。(b) 対象のコミットの SHA の照合(必須でも任意でも採らない。報告の標準の形式に欄が無く、`echo` で満たせる。任意の照合は「照合した」の表示が実態より強く見える)。(c) 署名・attestation(先例が無い)

### 1.6 条文と ADR(規格の委員の指摘)

- 附属書H H.1 の追加文に、対象なしの構成の限定を**同じ文の中に**書く(適用範囲の書き方 #226。限定を別の段落へ置かない)
- 附属書F F.6 の 7.3 の名指しの改めに「閾値を定めている場合」を入れる
- F.6 の表の「優先」と H.1 の「必須」の語の差は、意味を変えない範囲で揃える(編集)。意味が変わるなら直さず、実装の記録に書いて議長へ返す
- ADR-0244(仮番号): ADR-0151 決定1 の必須の段の集合を R1 について広げること、ADR-0224 決定13 の一部の置き換え、**ADR-0224 決定6(案件の条件での閾値の必須)の範囲は変えないこと**、課さないと決めたこと(R1 だけの構成の閾値・既定のコマンド・猶予期間・SHA の照合・注意にとどめる・安全案件だけ)を並べる
- R2 の週次は別のマーク(undelivered)に分ける(案のとおり)。読み違いを避けるため、note に「R1 の PR ごとの段とは別」と書く
