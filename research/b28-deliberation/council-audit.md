# IMPL-1029 会議体 品質監査の委員の意見(その1)

作成 2026-11-20。立場: 抜け道と証跡の欠けを突く。前提(回答 43・44、指揮役の決定)は覆さない。
現物で確かめたこと: template に mutation の段は未実装。push の経路の R1 の源は、出荷の集約のトレーラ Risk: 読み(aggregate-evidence.mjs 2769 行)だけ。H.1 が結ぶ「検証に数える」の条文は、現物では H.4 の表(assurance-case.md 332 行)にある。案の「H.3」は節番号の誤りの疑い。

## 論点1 閾値の無い構成での証跡の確かめ方

- 結論: **修正**。案の「出力の約束(行の存在と構文)」だけでは、閾値無しの構成で `echo "score=0 survivors=none"` でも満たせる。閾値が無いとき、段が通るのに足る条件が「出力に行が在る」だけになり、C4「検出力を測っている」の主張の根拠が実質ゼロになる
- 機械で足せる決定可能な線(echo を完全には防がないが、偽の通過を難しくする。細かさを増やさない範囲):
  1. 生き残りの一覧の所在が**実在するファイルを指す**ことと、スコアの数が**その一覧(または報告)と矛盾しない**こと(件数 0 なのにスコア < 100 など、再計算できる範囲だけ)
  2. スコア欄が数値で、`NaN`・空・`n/a` を失敗にする(「未測定」を通過に混ぜない)
  3. 段がスコアを出さず終了コード 0 だけの場合は、「測定していない」を**注意でなく失敗**にする(R1 では)。通過と未測定を区別する
- 閾値無しで通す場合の注意文は、PR のコメントか集約の件数に**残す**。ジョブのログだけでは G-6 の確認者が見ない。「合否を判定していない」の R1 の PR 数が G-7 に出ない限り、閾値無しは「静かな通過」になる
- 破られたとき: 出荷判定者と採用者の顧客が、R1 の変更を「測った」と読む根拠を失う。失うのは判定者の信頼
- 閉じ方: 1〜3 は機械。コマンドが本当に変異を作ったかは manual(EV-0339 で開示)。確かめる者は G-6 の確認者
- 安全・信頼への響き: 1〜3 は適合の主張の信頼に響く。ただし「一覧の所在が実在する」までで止め、記録の真正を足さない

## 論点2 G-5 で止めることと H.3(実は H.4)「検証に数えない」の重ね方

- 結論: **案に賛成(H.4 を保つ)+修正(節番号)**。一本化して H.4 の文を削ると、止まらない経路(論点3の push)で「数えない」が唯一の歯止めになる。保つ
- 追加の修正: H.1 に足す1文と H.4 の文が**同じ条件を二度書く**形は避け、H.4 から H.1 を指す現行の形を保つ。「G-5 が通れば条件を満たす」と読める書き方にしない。G-5 の通過は「段が空でない・出力が在る」までで、「検出力を測った」の十分条件ではない。この区別を H.1 の1文に入れる(表示と実態の食い違いの芽)
- 破られたとき: 段が `true` 相当で通ったのに H.4 の条件を満たしたと読まれる。失うのは C4 を引く者
- 閉じ方: 条文の書き分けは文面の問題で機械の外。adopter の開示(note)で足りる

## 論点3 R1 の判定の源と push の経路

- 結論: **修正**。「高いほう」の採用は賛成。穴が3つある
  1. **R2 と書く逃げ**: 人が低く確定すると段が必須にならず、空のまま通る。案は「3.8.1 の確定者と G-6」に任せるが、これは R1 を R2 と書いたとき**証跡が何も残らない**ことを意味する。最小の補強: 段が必須でないために注意で通った PR(段が空 かつ 区分 R2/R3)の**件数を集約に出す**。数え上げだけで、定義は増えない
  2. **push の経路**: トレーラ `Risk: R1` を書かないコミットは、段が必須にならない。トレーラが無いコミットは出荷の集約が欠落にする(既存)ので、案は「欠落側が拾う」前提になる。この前提を note に明記する。トレーラ `Risk: R2` と書いて R1 の変更を通す逃げは、PR の経路の R2 と同じ型で、manual
  3. **PR の本文の編集**: `edited` で再実行される(gate-g5.yml)が、**マージ後の編集**は走らない。マージ後に R1 を R2 へ書き換えても、段のジョブの結果は変わらない。実害は出荷の集約が本文を読み直すか次第。集約が本文を読むなら実態と一致、読まないなら表示と実態の食い違い。実装前に確かめるべき点
- 下限だけの案は採らない(案のとおり。人が上げた R1 を落とす)。push の経路を確かめない案は、PR を経ない変更が欠落になる前提に依存するので、前提が崩れたとき(トレーラ付きの偽の R3)に抜ける。採らない
- 破られたとき: R1 の変更が測られずに出荷される。失うのは採用者の顧客と、C4 を引く判定者
- 閉じ方: R1 か(本文・下限・トレーラ)は機械。低い確定は manual。ただし 1 の件数の表示は機械で足せる

## 論点4 既存の採用者の移行と template の既定

- 結論: **案(空を置く)に賛成+条件**。既定のコマンドを置くと採用者の技術選定(G-3)を奪う。外部の調査でも、道具の合否の意味は言語ごとにばらつき、mutmut は終了コード未確認、gremlins は版で不安定。template が既定を置くと、**合否を返さないコマンドが標準の既定になる**。置かない
- 条件: **空を置いた状態の template を新規採用者が使い始めたとき**、最初の R1 の PR まで気づかない。初回の G-1 / process-init の時点で「R1 の変更が出る前に mutation の段を決める」ことを `/pit` か process-init の出力に出す(手引きの1行。新しい検査は足さない)。落ちてから気づく運用は、期限のある PR で `true` を入れる動機になる
- **最大の抜け道は `true` / `echo` を段に置くこと**。空は失敗でも `true` は通る。案は EV-0339 の差し替え条件に件数を入れるが、**件数を数える機械が無い**。決定可能な一部(コマンドが `true`・`:`・`echo` だけ、`exit 0` を含む)を**注意として表示**するのは機械で閉じる。失敗にはしない(正当な外部コマンドを落とす)。表示だけで、閉じない部分の開示を補う
- 一定期間の注意とどめは採らない(回答 43 と衝突、ADR-0151 の採らない案と同型)
- 破られたとき: 採用者が `true` で通した R1 の変更。失うのは出荷判定の信頼
- 閉じ方: 空・キー無しは機械。`true` 類の表示は機械(表示のみ)。実効性は manual

## 論点5 外部の記録を照らすコマンドで機械が見る範囲

- 結論: **案に賛成(出力の約束だけ)+開示の強化**。外部の調査で、報告に対象のコミットを持つ欄は無く、真正性の先例も無い。SHA を書かせる案は `echo` で満たせて信頼を足さない(案の採らない理由に同意)
- ただし開示が弱い。外部の記録の経路は「道具の無い言語」の許しなのに、**道具のある言語でも使える**。許しの範囲が道具の無い言語に限られる根拠が機械に無い。結果、Stryker のある JS 採用者が「外部の記録」で段を済ませられる。これは抜け道。対処は2択: (a) 範囲を限らないと明記する(最も正直。manual で確かめる者は G-6 の確認者)、(b) 限る条件を機械に置く(決定不能)。(a) を採る。採らない案として (b) を記録する
- 追加で機械が決定可能に見られる最小: 記録のファイルが**当該 PR の実行より後に更新されたか**(mtime)。ただし checkout で mtime は崩れ、echo で満たせるため**採らない**。この「採らない」を記録する
- 破られたとき: 古い記録・別の変更の記録が通る。失うのは C4 を引く者
- 閉じ方: manual。EV-0339 と note で開示

## 追加の指摘

1. **変異体ゼロ**: 文書のみ・テストのみの R1 の PR で、道具が「変異体なし」でエラーになる(cargo-mutants、PIT の既定)。R1 の変更が実際にコードを含まないとき段が偽の失敗をする。逆に、道具が 0 件で成功して終了コード 0 を返すと、**対象の変更を何も測らずにスコア欄だけ満たして通る**。出力の約束に「変異体の総数」を含めず、0 件の通過を R1 で注意として出す(総数を出させるのは細かい定義の増加。安全への響きは小さいので、**数を要求せず、0 件と読める出力の表示だけ**にとどめる)
2. **段のジョブが success で終わる前提**(U4b): 必須でなければ注意で success。R1 の判定が段のジョブ内で失敗(gh の取得失敗、本文の読み取り不能)したとき、**R1 を判定できなかった→必須でない→通る**になる経路を作らない。判定不能は**失敗側**に倒す。これは取り消せない操作の前の歯止めに当たる重要な点
3. **PR の番号の受け渡し**: 段のジョブに PR の番号と基底を渡す配線(U4a の唯一の追加)。fork の PR や、番号が空の push で、R1 の判定が空振りしないこと。空振りは必須でなくなる経路
4. 条文の「証跡は G-5 の段の出力」は、ジョブのログの保存期間(GitHub の既定)を超えると失われる。出荷判定時に見えるか。集約が取り込まない限り、証跡は「あるはずのもの」になる。evidence に残す案(U6 で採らない)と整合させて、**保存の所在を note に書く**(manual、開示)
5. 節番号: 案と intake が引く「H.3」は現物で H.4。IMPL-0996 など他の番号と併せ、清書前に突合(編集の指摘。会議体は要らない)

## 案に無い採らない判断の提案

- `true` 類の失敗化: 採らない(正当なコマンドを落とす)。表示のみ
- mtime・SHA・署名の機械検査: 採らない(echo で満たせるか、決定不能)
- 閾値を R1 で必須: 方向が決まったので論じない
