# 束 B28 会議体 弁護の委員の意見(IMPL-1029)

作成 2026-11-20。立場は「案が退けた選択肢の側」。覆さないもの: 回答 43・44(段が空なら G-5 失敗、7.3 で空を受けない、注意にとどめない、安全案件だけにしない、R1 だけの構成に閾値を必須にしない)、指揮役の決定(移行の注意は README、CHANGELOG.md は新設しない)。以下の「反対・修正」は、その内側での弁護である。

## 論点1(置き換え後) 閾値の無い構成で、スコアと生き残りの所在を残すことを機械がどう確かめるか

- **結論: 修正**。案は「出力の約束(行の存在と構文)を機械が見て、注意に『合否を判定していない』と出す」。これは足りるが、閾値なしの通過を**数えて見える**ようにする一手が抜けている。
- 弁護する案: 閾値なしで通った R1 の段の件数と、そのときのスコアを、段のジョブの出力に加えて G-7 の集約(U4b)にも注意として件数だけ出す。乙(件数を集約に出す)は R1 の空の段では所有者が採らなかったが、これは**空ではなく閾値なし**の通過で別の対象である。回答 43 と食い違わない。
- 理由: 閾値なしの段は「走った事実」だけで合否が無い。`echo "score=0 survivors=./x"` で満たせる(案自身が認めている)。だから通過の**件数**が EV-0339 の差し替え条件(常に成功するコマンドの件数)を測る唯一の手がかりになる。件数が見えなければ、開示した差し替え条件が観測できず、根拠水準マークが形だけになる。
- 破られたとき: 出荷判定者と採用者の顧客が、C4 の「検出力を測っている」を、走っただけの段で読む。失うのは主張の信頼。
- 閉じ方: 件数の表示は機械(ジョブ結果の数え上げ。決定可能)。スコアが実際の測定かは manual(G-6 の確認者・内部監査の抜き取り)で、EV-0339 に開示する。
- 追加の指摘: 閾値なしで通ったとき、注意が PR の画面にしか残らないと、後から数えられない。段の出力を evidence へ残す案は U6 で ADR-0243 が採らなかった(結び付けの誤りの経路が増える)。件数だけなら、結び付けを要しない(ジョブの結果の数え上げで足りる)ので、(b) の理由に当たらない。

## 論点2 G-5 で止めることと H.3「検証に数えない」の重ね方

- **結論: 案(H.3 を保つ)に賛成。ただし「H.3 を消す」案を弁護して、消さない理由を条文で確かめるよう修正を求める**。
- 弁護する案(H.3 を消して G-5 に一本化): 同じ帰結が条文の2か所にあると、読み手が「どちらが効くか」を迷う。G-5 で止まるなら H.3 は死文で、死文は適合の主張の信頼を下げる。現場の委員の指摘は正しい。
- それでも H.3 を保つ理由: G-5 を経ない経路がある。(a) push の経路でトレーラ `Risk:` を付けず R2 と書いた変更、(b) 段の閾値なしの通過(論点1)、(c) 外部の記録を照らすコマンドの通過。いずれも G-5 は通るが、「検出力を測った」とは言い難い。H.3 は**保証の主張の側**で、この3経路の受け皿になる。消すと、この3経路に何も残らない。
- 修正: H.3 の文に「G-5 の段を通過した R1 の変更のうち、閾値を定めていない構成と、外部の記録を照らすコマンドの通過は、検出力を測ったことの確認を G-6 の確認者に求める」と一句を足し、死文でなく**残りの穴の受け皿**だと分かる書き方にする。これは新しい義務でなく、既存の G-6 の確認の範囲の明示である。
- 破られたとき: H.3 を読んで R1 の変更を信頼する者が、形だけの通過を「測った」と読む。失うのは適合の主張の信頼。
- 閉じ方: G-5 の失敗は機械。H.3 の受け皿は manual(G-6)で、IMPL-1029 の note に開示する。

## 論点3 R1 の判定の源と push の経路

- **結論: 修正**(案の「本文と下限の高いほう」は支持。push の経路が弱い)。
- 弁護する案 (i) 下限だけで R1 を決める: 人の判断に依らず、本文の編集で逃げられない。案は「人が上げた R1 を落とす」と退けたが、**落ちる側は安全側**(段を要求しすぎる側)である。逆に高いほうの採用は、本文を高く書けば段を要求できる一方、低く書いた誤りは下限が拾う。つまり「高いほう」は下限を内包するので、(i) は案より弱い。ここは案に賛成する。
- 弁護する案 (ii) push の経路は確かめない: 案は push はトレーラ `Risk: R1` だけを見る。トレーラを書かなければ段は必須にならず、書く者の自己申告に依る。下限(`riskFloorOf`)は変更ファイルから決定可能なのに、push の経路では使わない理由が案に無い。**修正: push の経路でも下限を使う**(トレーラと下限の高いほう)。変更の一覧は push の範囲の差分から取れる。PR の経路と同じ関数を呼ぶだけで、新しい定義を増やさない。
- 弁護する案 (ii)' push を確かめない案そのものは採らない。PR を経ないコミットは出荷の集約で欠落になる、との議長の理由はあるが、欠落になるのは G-7 で、G-5 の時点で止まらない。遅く止まるほど手戻りが大きい。
- 追加の指摘(抜け道): 本文の区分の編集は `edited` で再実行されるが、**マージ後に本文を編集しても出荷の記録は変わらない**。段の判定がマージ前の本文に依る点を、manual の統制として開示する(3.8.1 の確定者と G-6)。
- 破られたとき: 安全関連の変更が R2 と書かれて段を免れる。失うのは出荷判定者と顧客の、R1 に対する保証。取り消せない操作(出荷)に響く。
- 閉じ方: 下限と区分の高いほうは機械(決定可能)。人が下限に当たらない R1 を低く確定したことは manual。

## 論点4 既存の採用者の移行と template の既定

- **結論: 反対(部分)。弁護する案は「スタックごとの既定のコマンドを置く」**。
- 案は7つのアダプタに空を置く。結果、取り込んだ全採用者の最初の R1 の PR が落ちる。落ちた採用者が最初にすることは道具の選定で、G-3 の判断だから、と案は言う。
- 弁護: 空を置く設計は、採用者が最も忙しい時(R1 の変更の期限)に落とす。急いだ者は `true` や `echo` を書く(案が認める抜け道)。既定のコマンドは、**抜け道の動機を減らす**。依存の追加が G-3 の判断を奪う、との懸念は、既定を「無効の見本」ではなく**手引きの例(コメントの形)**として置けば、判断を奪わない。
- 外部の調査が支える点: 道具は node(Stryker JS)・python(mutmut)・go(gremlins 等)で成熟度に差があり、gremlins は版で終了コードが食い違う報告がある。つまり**既定を置けるのは node と python だけ**で、go は置けない。7つ一律の既定は成り立たない。これは弁護にも不利な事実で、正直に記す。
- 修正案: 既定のコマンドは置かないまま、`kinds/settings.md` と README に node・python の例を書く(案の「置くなら手引きに例」を、置く方向に倒す)。もう1つ、**「走るコマンドが変異体ゼロ(文書のみの PR)で失敗する」問題**を案が見ていない(論点の追加の指摘参照)。
- 「取り込みから一定期間は注意にとどめる」は、所有者が採らなかった「注意にとどめる」の変形で、回答 43 に反する。弁護しない。
- 破られたとき: 取り込んだ採用者が、落ちた段を `true` で埋める。EV-0339 の差し替え条件の「常に成功するコマンドの件数」が増える。失うのは主張の信頼。
- 閉じ方: 在否は機械。コマンドが実際に変異を作るかは manual。例の正しさは手引き(adopter)。

## 論点5 外部の記録を照らすコマンドで機械が見る範囲

- **結論: 修正**(案の「出力の約束だけ」は支持。ただし「記録のコミットとの一致まで見る」案を弁護して、見せかけの安心を避ける線を引く)。
- 弁護する案(記録の日付・先頭のコミットの一致まで見る): `echo` で満たせるのは確かだが、**満たすには少なくとも当該のコミットの SHA を知っている必要がある**。出力の約束だけなら、過去の PR の記録を使い回しても満たす。SHA の一致は、使い回しという最も起きやすい誤りを(悪意でなく)機械で拾う。改ざん防止ではなく、**取り違えの防止**として価値がある。議長の「改ざんは機械で閉じない」は正しいが、取り違えまで閉じない理由にはならない。
- ただし外部の調査では、報告の形式(mutation-testing-report-schema)に対象のコミットの欄が無く、先例も無い。標準の側で欄を定めると、新しい様式を作ることになり、採用者の負担が増える。
- 修正: 一致を**必須の合否にしない**。照らすコマンドが SHA を出力に含めた場合だけ、基底の差分の先頭と比べて食い違えば失敗にする(含めなければ注意で通す)。これは「機械が見る範囲を広げる」でなく「採用者が自発的に出した値を、出したなら見る」で、新しい義務を課さない。
- 破られたとき: 古い記録で R1 を通す。失うのは主張の信頼。ただし意図的な偽造は閉じない旨を note に書く(EV-0339)。
- 閉じ方: SHA の構文と一致は機械(決定可能)。記録の真正(署名・証明)は manual。先例が無いことは根拠水準マークで開示する。
- 細かい定義を増やすか: 増える(任意の欄1つ)。響くのは適合の主張の信頼だけで、安全・取り消せない操作には響かない。増やす価値が低いと判断されるなら、議長の案に従って構わない。

## 追加の指摘(案に無い欠陥・抜け道)

1. **変異体ゼロの PR**(外部調査 §2.2・§4): R1 の変更でも、変更が変異対象を含まない(設定ファイルだけ、テストだけ)とき、PIT の `failWhenNoMutations` や cargo-mutants の「変異体なし」エラーで段が失敗する。R1 を必須にしたことで、採用者が**偽の失敗**に遭い、`true` で埋める動機が生まれる。段の出力の約束に「対象の変異体が 0 件」を正規の結果として含めるか、手引きに道具ごとの扱いを書くか、のどちらかが要る。機械の線: 「0 件」の行の構文は機械、0 件が正しいかは manual。響く先は、抜け道の動機(適合の主張の信頼)。
2. **差分の基底の欠け**: cargo-mutants は diff が作業木と合わないと終了コード 5 で落ちる(`fetch-depth: 0` が要る)。`PIT_IN_DIFF_BASE` を渡すだけでは、浅い checkout で段が落ちる。gate-g5.yml の段のジョブの checkout の深さを U4a の配線に含める。響く先は、偽の失敗(同上)。
3. **R2 の週次を undelivered で開示する扱い**は支持する。ただし H.1 の表の R2 の欄は「週次の定期実行」と読め、読み手が template で動くと誤解する。H.1 の直後の1文に「R2 の週次は本標準が求めるが、準拠テンプレートは起動を置いていない」を入れるか、マークだけで足りるかは、議長の判断に委ねる。響く先は適合の主張の信頼。
4. **F.6 の表の「優先」と H.1 の「必須」の語の差**: 議長は「食い違いでない」とする。弁護: 条文の語が違えば、安全案件の読み手は F.6 の「優先」を優先の度合いと読み、H.1 の必須と衝突する。F.6 の表の文言を「H.1 により必須。増分の範囲は優先」に直す1語の編集で、会議体を要さない(編集の指摘)。
5. **集約の `skipped`**: 段のジョブが success で終わる設計(必須でなければ注意)は、ジョブ自体が skipped になる経路(`if:` の条件)を避ける前提に立つ。ADR-0224 決定8 の skipped の扱いと、R1 の判定のための PR 番号の受け渡しの失敗(gh の失敗)が、段を成功扱いにしないことをテストの ng に加える。判定の材料が取れないときは**失敗側に倒す**(取れなかった R1 を R2 として通さない)。取り消せない操作(出荷)に響く。
