# 束 B28 U4a の「議長へ返す点」への裁定

裁定 2026-11-20。対象は `impl-u4a.md` の「議長へ返す点」1〜4 と、現物で見つけた1点。

1. **判定の入力が読めない範囲**: 実装のとおり採る(変更ファイルが取れなければ、本文があっても読めない扱いで必須の側)。下限を出せないまま本文だけで R2 と判定すると、下限の R1 を落とすため。`ruling-1.md` §1.3 の「本文も変更ファイルも取れない」は「本文か変更ファイルのどちらかが取れない」に改める。採らない: 本文だけで判定して注意を出す(規格の委員の案)
2. **squash マージ後のトレーラ**: 実環境で確かめていない。IMPL-1029 の note に「push の経路でトレーラが落ちた場合、人が R1 と確定して下限が R2 以下の変更は、push の経路では段が必須にならない。PR の経路の段の実行に頼る」と開示する(manual)。新しい根拠水準マークは足さない(値や前提ではなく、機械が閉じない範囲の開示であるため note で足りる)。実環境の確認は #361 の範囲(既にある実環境の検証の Issue)。U4b で note を足す
3. **手元の実行**: U4b の担当が `g5-local.mjs` がこの段を呼ぶかを確かめる。呼ぶなら、手元の実行は「判定の入力が無い。CI で判定する」と注意を出して、空の段を失敗にしない(手元は G-5 の判定の場ではない)。CI のワークフローはこの扱いを使わない。手元かどうかの見分けは、既存の g5-local の仕組み(あれば)に揃え、新しい環境変数を足すときは gate-g5.yml がそれを設定していないことを契約検査か試験で固定する。呼ばないなら何もしない
4. **test-aggregate-wiring の全量で 1 件 NG(IMPL-0925 の TBD)**: U4b の担当が原因を突き止める。U4a は様式09 を変えており、NG の文は模擬環境の TBD に触れているため、無関係とは決めない。U4a の変更が原因なら直す。時計・順序に依る偽の落ちなら、原因と再現の条件を記録する
5. **graphify-out の変更がコミットに入っている**(現物で確認。21e717c1 か 307529de): graphify-out は CI が自動で更新する。push の準備で origin/main の版へ戻す(本体のコミットに含めない)。以後の担当は `graphify update` を流さない
