### 1.3 マークの state と検証の種別

- **IMPL-1029**(assurance-case.md 91 行): U4a・U4b・U6 の後に `state=delivered check=machine test=template/scripts/gate/test-adapter.mjs`、`target=g5-adapter` のまま。note の範囲は **R1 の変更ごとの実行だけ**に絞り、次を書く: 「R1 は PR の本文の区分と区分の下限の高いほう、push はトレーラ Risk:。人が区分を低く確定したことは確かめない(3.8.1 の確定者と G-6)。段が空なら失敗、7.3 で受けない。閾値は案件の条件に当たる構成だけ必須。外部の記録を照らすコマンドの記録の真正・新しさ・範囲は確かめない(EV-0339)」

### 1.4 機械で閉じる条件と閉じない統制

- 閉じる(決定可能): R1 か(本文の区分・下限・トレーラ)、段のコマンドが空でないか・キーがあるか、閾値の在否と型、出力の行の存在と構文、スコアと閾値の数の大小、台帳の行の約束の構文、段のジョブの結果
- 閉じない(manual・開示): コマンドが実際に変異を作り検出を測るか、増分が当該範囲を覆うか、外部の記録の真正と新しさ、閾値の較正、人が区分を低く確定したこと。開示は EV-0339(広げる)と IMPL-1029 の note。確かめる者: G-6 の確認者、内部監査の抜き取り
- 採らない機械の検査: 外部の記録に当該 PR の先頭のコミットの SHA を書かせて照らす。`echo` で満たせ、改ざんを防がない。細かい定義を増やすだけで信頼を足さない(方針の「統制の閉じ方」)

### 1.5 移行の注意の文案(CHANGELOG の所在は §5 の問い2)

> **process-compass #445 の更新(IMPL-1029 ほか)を取り込むとき**
>
> この更新から、**リスク区分 R1 の変更を含む PR では、G-5 の段 `mutation`(変異試験)のコマンドが空だと G-5 が失敗します**(標準 附属書H H.1。安全・CL3 の案件に限りません)。取り込む前に次を行ってください。
>
> 1. アダプタ(`adapters/<スタック>.json`)の `commands.mutation` に、変異試験を実行するコマンドを書く。差分に絞る実行を勧めます(基底のコミットは環境変数 `PIT_IN_DIFF_BASE`)。道具の無い言語では、外部で実行した記録を照らすコマンドを置けます。どちらも、スコアと生き残った変異の一覧の所在を出力に出す必要があります
> 2. 閾値(`ci.mutationThreshold`)は、附属書F の適用が「はい」の案件と CL3 の案件では必須です(未設定なら G-5 が失敗します)。それ以外では任意で、定めた場合だけ合否に使います。書く経路は `/process-change`(種別 settings)だけです
> 3. スコアが閾値に届かない場合は、第7章 7.3 の例外承認を技術負債台帳へ記録します(行の書き方は ADR-0243)。段が空のままの通過には例外承認を使えません
> 4. 取り込みまで R1 の PR が無い案件でも、取り込んだ後の最初の R1 の PR で落ちます。R2・R3 の PR は落ちません
>
> 新しく落ちるのは「R1 の PR で段が空(またはキーが無い)」「閾値を定めたうえでスコアが下回り、例外承認の行が無い」の2つです。要求事項の検査を変える更新なので、従う版の切り替え(`/process-change` 種別 edition)と同時に取り込みます。

## 2. U6 の ADR-0243 の骨子(軽。ADR-0224 決定7 の実装の約束)

- **題**: ミューテーションの閾値割れの 7.3 の例外承認を、台帳の行の約束で見分ける
- **コンテキスト**: ADR-0224 決定7 と F.6 は閾値割れを 7.3 の対象とした(本件で R1 にも広げる)。降りている IMPL-0996(`unjudgedGateExceptions`。exception-expiry.mjs 361〜373 行)は、G-5 を対象とする例外の行を常に記録の欠落にする(「標準より厳しい」template の選択。ADR-0153 決定2・ADR-0222)。段のジョブと集約が閾値割れの行を見分ける約束が無い
- **決定(案)**
  1. 閾値割れの例外承認の行は、区分「例外」・ゲート G-5・対象 `PR #<番号>`・内容の先頭 `ミューテーションの閾値割れ(スコア <値> / 閾値 <値>)` で書く(ADR-0200 決定2 と同じ型)
  2. 段 `mutation` は、スコアが閾値に届かないとき、台帳(基底ブランチと PR の先頭の両方を読む。check-pr の `exceptionFor` と同じ読み)に、この PR を対象とし、承認の数が 7.3 を満たす行があれば、注意を出して通す。無ければ失敗
  3. IMPL-0996 を改める: G-5 を対象とする行のうち、決定1 の印を持つ行は欠落にしない。印の無い G-5 の行、規制要件の段(`regulatory`)の不合格の行は、従来どおり欠落(ADR-0224 決定7)
  4. 機械が確かめるのは、印の構文・対象の PR・承認の数・行に書いたスコアが閾値より小さいことまで。行のスコアが段の実際の出力と一致するかは確かめない(段の出力は実行ごとに変わり、記録へ結べない)。開示する
  5. 印の無い閾値割れの行は見分けない(ADR-0200 決定5(a) と同じく開示し、検出しない)。その行では段が失敗のまま
- **課さないと決めたこと**: 閾値割れの行の承認者の数を 7.3 より増やすこと、規制要件の不合格の 7.3、段が空・閾値未設定の 7.3
- **採らない案**: (a) IMPL-0996 を G-5 全体について外す(段の外の G-5 の失敗まで 7.3 で解ける) (b) 段の出力を evidence に残して集約が照らす(記録の経路が増え、PR ごとの実行の記録を出荷の集約へ結ぶ仕組みが要る。費用でなく、結び付けの誤りの経路が増えるため) (c) 印を求めず内容の語で探す(誤検出。ADR-0217 は条件で見分けたが、閾値割れは行の条件だけでは G-5 の他の行と区別できない)
- **影響**: IMPL-0996 の note の「標準より厳しい」の範囲を書き直す。IMPL-0931 の note の「7.3 の経路は成立しない」を外す。F.6 の 284 行の文(§1.1)と揃える。手引き `.claude/skills/gate/reference/exception-paths.md` に行の書き方を足す
- 審議の重さ: **軽**(intake-2 §1.5 のとおり。記録の書き方の約束で、7.3 の対象は ADR-0224 と回答 43 で決まっている)。ただし決定2 は IMPL-1029 の R1 の段にも掛かるので、ADR-0244 の会議体の後に確定する
