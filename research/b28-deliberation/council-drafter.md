# 束 B28 会議体 起案の委員の意見(IMPL-1029)

作成 2026-11-20。立場: 裁定の案(ruling-draft-1.md)を守る側。弱い所は自分で直す案を出す。読んだもの: answers-1.md、ruling-draft-1.md、intake-1.md §2・§3、research-ext-1.md §0・§3.6・§4、現物は adapter.mjs(54・74 行)、gate-g5.yml(ジョブの構成)、附属書H H.4。覆さない前提: 回答 43・44、README に1項(CHANGELOG は新設しない)。

## 総評

案の骨(結果と証跡だけを条文に置く、R1 は本文と下限の高いほう、空は 7.3 で受けない、機械は決定可能な条件だけ)は維持する。直すのは4点: (1) 閾値が無い構成の「通った」が何を意味するかの開示、(2) 変異体が 0 件の R1 の PR という偽の失敗、(3) push の経路で下限を使わない非対称、(4) R1 を判定できないときの閉じ方。(2) と (4) は案に無い。

## 論点1(置き換え後): 閾値の無い構成で、スコアと生き残りの所在を残すことを機械がどう確かめるか

- **結論: 案に賛成、ただし修正2点**
- 機械で閉じる範囲(決定可能): 段の出力に (a) スコアの行が数として在る(0〜100)、(b) 生き残りの一覧の所在の行が在り、その所在が実在する(ファイルなら存在、URL なら構文だけ)。閾値が未設定なら、比較の行は出さず「閾値を定めていないため合否を判定していない」を注意に出す
- 修正1(偽の失敗を防ぐ): 変異体が 0 件の実行(文書だけの R1 の PR、テストだけの変更。外部の調査 §4 は cargo-mutants と PIT で既定が異なると報告)に、出力の約束で「変異体 0」を明示する行を許す。許さないと、必須の段が正しい変更で落ち、採用者は `true` や `echo` を置いて逃げる。これは H.1 の「必須」を空洞化させる最も現実的な経路である。「0 件」は件数の行 = 0 を機械が見るだけで、決定可能
- 修正2(閾値が無いときの「通った」の意味を開示): 閾値が無いとスコア 0% でも通る。これは案の帰結なので、隠さず開示する。具体策は新しい検査ではなく、(i) 注意の文にスコアの値を必ず含める、(ii) 集約(G-7 の材料)にスコアと「閾値なし」を並べて出す。後者は表示だけで決定可能、G-6 の確認者が目で見る材料になる。H.1 の1文と C4 は「検出力を**測っている**」であって「足りている」ではない。閾値が無い構成の主張はその強さに留まる旨を、EV-0339 の対象の文に書く(新しい EV は作らない)
- 破られたとき: 偽の出力の行(`echo`)を置かれると、C4・H.3 を読む出荷判定者・事業決裁者が、測っていないのに測ったと信じる。機械では閉じない(スコアの真偽は決定不能)。**manual で開示**: 確かめる者は G-6 の確認者と内部監査の抜き取り。EV-0339 の差し替え条件に「R1 の変更で常に成功するコマンド(`true` や固定の `echo`)が段に置かれた件数」を入れる案はそのまま支持する
- 細かい定義の追加への影響: 「変異体 0」の行は、取り消せない操作・安全には響かない。偽の失敗が抜け道を生むことによる適合の主張の信頼に響く。よって1行だけ足す価値がある。出力の行は U4a の約束の範囲内で、新しい欄は足さない

## 論点2: G-5 で止めることと H.3「検証に数えない」の重ね方

- **結論: 案に賛成(H.3 を保つ。一本化しない)、ただし H.3 の文は改めない**
- 現場の委員の言う「死文になる」は当たらない。H.3 が働き続ける場面は少なくとも3つある。(a) G-5 を経ない変更(push の経路で R1 を判定できなかった場合、直接 push)、(b) 閾値が無い構成でスコアが低いまま通った場合(段は通るが「検出力を測っている」と言える水準かは別)、(c) 外部の記録を照らすコマンドの記録が偽の場合。止めるのは機械の層、H.3 は主張の層で、役割が違う
- 一本化(H.3 を削り G-5 だけにする)は採らない。理由は、G-5 の失敗は採用者の構成に依存し、標準の主張は構成に依存しない側に置くべきだから。弱める根拠の実証も無い(ADR-0224 の子-a を採らなかった理由と同型)
- 破られたとき: H.3 を削ると、G-5 の外で通った R1 の変更が「検証に数える」へ流れ込む。C4 を読む者が失う
- 直す点: 重ねても二重の判定にならないよう、IMPL-1029 の note に「H.3 は G-5 を経ない変更と閾値なしの構成の主張を受ける」と1行書く。条文は変えない。manual 開示(確かめる者: 出荷判定者の C4 の確認)

## 論点3: R1 の判定の源と push の経路

- **結論: PR の経路は案に賛成。push の経路は修正(トレーラだけでなく下限も使う)**
- PR: 本文の区分と下限(基底の構成の規則)の高いほう。下限を基底の構成から読むので、PR 自身が規則を弱めて逃れることはできない(現物の riskFloorOf の読み)。人が低く確定した R1 は機械で閉じない(3.8.1 と G-6。既存の統制)で、案のとおり
- push の修正: 案は「トレーラ `Risk: R1` だけ」。トレーラは人が書くので、書き忘れや `R2` と書いた R1 を落とす。push の範囲の変更ファイルは決定可能に読めるので、下限の規則を同じ関数に掛け、トレーラと下限の高いほうを採る。PR の経路と同じ式にして、2つのジョブの判定が食い違わない(案が PR で高いほうを採った理由と同じ)。トレーラが無いコミットは、出荷の集約が既に欠落として扱うので、ここでは増やさない
- 要確認(実装で): squash マージで PR のトレーラがコミットに残るか。残らないなら push の経路は下限だけが頼り。これは実装の担当が実行で確かめる事項で、確かめるまで note に「トレーラの有無に依る」と書かない
- 追加の指摘(閉じ方): R1 を判定できないとき(gh の失敗、PR の本文が取れない、構成が読めない)は、**判定できないを R1 とみなして段を必須にする(閉じる側に倒す)**。注意で通すと、取得の失敗が抜け道になる。決定可能で、安全側
- 追加の指摘(古い本文): 再実行(re-run)は元のイベントの本文を使う。`edited` で再起動する設計(gate-g5.yml 22 行)は新しいイベントでは効くが、失敗した実行の再実行は古い本文を読む。段のジョブは `gh api` で現在の本文を読むほうが確実。既存の pr-rules も同じ型なので、実装で pr-rules の読み方に揃える
- 破られたとき: R1 を R2 として通すと、採用者の R1 の変更が変異試験なしで出る。損なうのは C4 を読む者。manual 部分(人の区分の確定)は G-6 と内部監査で受ける

## 論点4: 既存の採用者の移行と template の既定

- **結論: 案に賛成(空を置く。既定のコマンドは置かない)、ただし失敗の文を移行の導線にする**
- 既定のコマンドを置かない理由は案のとおり、道具の導入は依存の追加で G-3 の技術選定。加えて外部の調査 §4 のとおり、道具の終了コードが合否を意味する程度は道具ごとにばらつく(cargo-mutants は未捕捉 1 件で 2、Stryker の break 閾値は既定 null、mutmut・gremlins は未確認)。template が1つを選ぶと、その道具の既定の挙動(閾値なしで常に成功など)を標準の成果として配ることになる。**例は手引き(README と kinds/settings.md)に道具ごとの注意付きで置く**。アダプタ JSON には置かない
- 「一定期間は注意にとどめる」は採らない(回答 43 が「注意にとどめる」を採らなかった)。ただし取り込みの時期は採用者が制御できる(従う版の切り替えと同時、案の移行の注意の最後の段落)ので、猶予は版の切り替えの側にすでにある
- 修正(安い導線): 空で落ちるときの失敗の文に、README の該当項のアンカーと「設定する」「道具の無い言語は記録を照らすコマンド」の2択を出す。これは文言だけで、機械の強さを変えない。破られたとき(導線が無い)、採用者は最短の逃げ道である `true` を置く
- 追加の指摘: アダプタ `none`・`undetermined` や対象なし(`targetState` が present でない)では、ALWAYS 以外の段は「実施しない」で通る(adapter.mjs 54 行以降の既存の動作)。R1 の PR でもコードが在る構成がこの経路で通れば、H.1 の「必須」に穴が残る。R1 で必須のとき、対象なしを通す条件を実装の担当に確かめさせる。コードが無い(文書だけ)の構成なら通ってよい。確かめる前に note へ書かない
- 開示: 移行の注意の4項(案 §1.5)で足りる。ADR に「R1 だけの構成の閾値は求めない。求める案は所有者が採らなかった」を明記する(answers-1 §2)

## 論点5: 外部の記録を照らすコマンドで機械が見る範囲

- **結論: 案に賛成(出力の約束だけ。コミット SHA の照合は採らない)**
- 理由は実証に基づく。外部の調査 §3.6: 報告に対象のコミットの欄が無く(スキーマ上)、取り込んだ報告が当該コミットで実行されたかを突き合わせる先例も、真正性(署名・attestation)の先例も、本調査では見つかっていない(後者は検索していない)。先例の無い照合を標準が定めると、採用者に未検証の義務を課すことになる。また SHA を書かせる照合は `echo` で満たせて、改ざんを防がない(CLAUDE.md の統制の閉じ方: 自由な文の意味や改ざん防止は機械で閉じない)
- 同じ穴は外部の記録に限らない。通常の段も `echo` で満たせる。外部の記録だけを特別扱いして重く見る理由は無く、EV-0339 の1つの開示で足りる
- 機械の範囲: 論点1 の出力の約束(スコア、所在、変異体 0 の行)に揃える。記録の所在が実在することまで(ファイルなら存在)。**日付の新しさは見ない**(基底より後かは、再実行や再利用の防止にならず、定義が増えるだけ)
- 手引きの注記: 記録に実行時のコミットを含められる形式(Stryker のレポートに版を持たせる運用など)を使う場合は、採用者が自分の閾値と記録の両方を G-6 で見る。標準は先例が見つかるまで要求しない。「採らない」ことを ADR に書く(書かれていないと課さないの区別)
- 破られたとき: 古い記録や他のコミットの記録で通すと、C4 の読み手が当該変更の検出力を誤認する。manual で開示(確かめる者: G-6 の確認者・内部監査の抜き取り)。EV-0339 に「外部の記録の件数」を足す案は、数えられる(段が外部の記録のコマンドか)かを確かめてから。数えられないなら足さない

## 追加の指摘(案に無い欠陥や抜け道)

1. **変異体 0 件の偽の失敗**(論点1)。影響: 適合の主張の信頼。必須の段が正しい変更で落ちると、逃げ道の `true` が広がる。出力の約束に1行足す。重大度は中
2. **R1 を判定できないときの閉じ方**(論点3)。取得の失敗を注意で通すと抜け道。必須として扱う。重大度は中
3. **段が「走らなかった」と「走って通った」の区別**。案は、必須でなければ段の中で注意を出して success で終わる。G-7 の集約は success しか見ないので、「R1 でなく走らなかった」と「R1 で走った」が同じ緑に見える。集約が段の出力の行(必須だったか・スコア)を転記する表示を足すと、確認者の目に届く。表示のみで、新しい義務ではない。軽微
4. **F.6 の表「優先」と H.1「必須」の語の差**。案は食い違いではないとする。読み手が2つの条文を並べたときの誤読の経路になるので、F.6 の表の注に「R1 の変更ごとの実行は H.1 による」と1句足す(編集の指摘の扱い。意味を変えない)。安全・取り消せない操作には響かず、適合の主張の読みやすさだけ
5. **R2 の週次を分けて undelivered で表示する案**(§1.3)は支持する。IMPL-1029 の note と1つのマークに混ぜると、降りていない部分が降りた印に隠れる。「降りていない規定は消さずに表示し続ける」に合う
6. **ADR-0243 の決定2 が R1 の段にも掛かる件**。案が書くとおり、ADR-0244 の会議体の後に確定する。閾値が無い構成では 7.3 の経路は閾値割れが起きないので、この決定の対象は閾値ありの構成だけになる。note に書く
7. **EV-0339 の対象を広げる**案は支持する。ただし、対象に「閾値が無い R1 の構成は『測っている』であって『足りている』ではない」を入れる。新しい EV を作らず、差し替え条件に実測の件数(`true` の置かれた件数、変異体 0 の件数)を入れる

## 採らない案(起案の側から記録する)

- 既定のコマンド(Stryker・mutmut 等)をアダプタに置く: G-3 の技術選定を奪う。道具ごとの終了コードの差(外部の調査 §4)を標準の成果に取り込む
- 外部の記録へ SHA・日付の照合を課す: `echo` で満たせる。先例が無い。改ざんを防がない
- H.3 を削って G-5 に一本化: 論点2
- 閾値割れの「注意のみ」への緩和: 回答 43 が採らなかった

## 機械で閉じる / 開示する の整理

| 事項 | 区分 |
| --- | --- |
| R1 の判定(本文・下限・トレーラ・取得失敗は R1 とみなす) | 機械 |
| 段が空・キー無し | 機械 |
| スコアの行の在否と数の範囲、所在の実在、変異体 0 の行 | 機械 |
| 閾値の在否と型(案件の条件の構成のみ必須) | 機械 |
| スコアの真偽、増分が範囲を覆うか、外部の記録の真正・新しさ・当該の変更か、閾値の較正、人が低く確定した R1 | manual(EV-0339、IMPL-1029 の note。確かめる者: G-6 の確認者・内部監査) |
| 閾値が無い構成の「通った」の強さ | adopter+開示(EV-0339 の文、注意の文にスコアを含める) |
| 対象なしの構成を R1 で通す条件 | 実装で確かめてから決める(未確定) |
