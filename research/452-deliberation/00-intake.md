## 4. 測ること(台本は試行の後、リポの削除の前に回す)

台本(scratchpad に置き、リポジトリへは入れない): 既定ブランチの第1親の各コミット C(初期化の後)について、次を出す。

- `changed(C)`: `git diff --name-status C^ C`(名前の変更は前後とも)
- 読み方ごとの計画の和 `U_k(C)`(`readPlanTargets` を import して使う):
  - **R1**: C^ の時点の全計画の全タスクの glob の和(規定の字義。「既定ブランチへ入った計画の和」)
  - **R2**: R1 から状態が「完了」のタスクを除いた和
  - **R3**: C^ の時点の、C のトレーラ `Spec` が名指す機能の計画だけの和
  - **R4**(対照。採らない前提): C の時点の計画の和(同じ変更で計画を広げられる形。要求事項3 の「広げられない」に反するため、差を示すためだけに数える)
- 外れたパス `changed(C) − U_k(C)` を、置き場で分類して数える: `specs/**`、`docs/**`(判定記録・証跡・adoption-trial)、`context/**`、ロックファイル(`package-lock.json` ほか)、`package.json`、テストのファイル(`.claude/guard.json` の testPatterns)、fixture、`README.md`・`CHANGELOG.md`、`.github/**`・`scripts/gate/**`(強制層。guard-write が別に止める)、その他
- 補助(採るかは会議体で決める): 試行の clone だけに、書き込みを止めずにファイルの道具のパスを書き出すフックを置き、**コミットしなかった書き込み**も数える。IMPL-0200 の note の「拒否しない動作の形を作らず」は準拠テンプレートの機能の話で、試行の測定の道具は当たらないと読むが、反対の読みもありうるため議題にする
- 規定の読みの欠けの観測: 作業のブランチから既定ブランチの計画を読むとき、手元の `origin/<既定>` が古いと直前に入った計画が見えない。G-4 の PR を取り込んだ直後に実装を始めた回で、`git fetch` の前後で U が変わった件数を数える

## 6. 審議の重さ(案): 軽

理由: 既にある要求事項3(ADR-0126 決定3)を降ろすための、読み方と既定の一覧の決定である。採用者への新しい義務は課さない(範囲の拒否は既に規定)。安全・法令に掛からない。外部の調査は EV-0251 の 2026-11-12 の調査(`research/358-deliberation/survey-external.md`)を使い、新たには行わない。

重へ上げる条件:
- 実測の結果、計画の和を境界にする原則が成り立たないと分かり、要求事項3 か ADR-0126 決定3 を変える案が出たとき(ADR の原則の変更)
- 計画の様式に新しい必須の書き方(例: 置き場の列の必須化)を課す案が出たとき(採用者への新しい義務)

所有者の方針(2026-11-16)の3つの問い:
1. 読み方と一覧の具体は条文に書かない。準拠テンプレートの既定(強制層の設定の値)と手引きに置き、条文は今の結果の規定のまま
2. 珍しい置き場は既定の一覧を増やさず、採用者が強制層の変更(`state:needs-platform`)として足す
3. 誤った遮断で失うのは採用者の作業(フックを外す動機)。広すぎる一覧で失うのは、担い手が範囲の外へ書けないという主張の信頼。後者が適合の主張に響くため、一覧は小さく保つ向きで裁定する

会議体: 起案と反対の2委員。議長の裁定、既存の決定(ADR-0126・ADR-0222・IMPL-0205・IMPL-0198)との突合、独立の突合、採らない案の記録は省かない。
