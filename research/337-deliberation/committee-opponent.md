# #337 反対委員の意見

日付: 2026-11-17。役: 反対委員(起案委員の案は読んでいない)。対象: 受付(`intake.md`)と Issue の前提。統制を緩める向きには特に厳しく当たる。実行(template/)は未確認で、文書と台帳の突合のみ。

## 総評

受付の見立て「条項を足さずに受けられる」は、論点3 は支持、論点1〜2 は一部の語の整理に限れば支持、「遮断は害を直接止める条件に限る」という一般原理の新設には反対する。理由は、それが ADR の原則の変更に当たり(軽の範囲を超える)、かつ根拠が薄いため。

## 論点1 「200 行は遮断、PR の規模は遮断しない」

### 反対意見
1. **前提が誤読に近い**。`gate-criteria.md:2128` の「上限を遮断として運用してはなりません」は規模(RC-01)の較正に関する文で、指示資産の分量(RC-07)には掛からない。:737 の G-5 基準6 は別の定数を別の根拠で扱う。「向きが逆に読める」は受付の言うほど深刻でなく、食い違いというより**適用範囲が書かれていないだけ**。直すなら `scope-marking`(#226)の流儀で、基準6 の行に「値は組織が定める(3.11.4)。値が未設定なら判定しない」と併記する編集。意味は変えない。
2. **受付の「揃えるべきか別」という結論の置き方に賛成だが、論拠が弱い**。「母集団を観測して較正する定数だけが収縮する」という説明は、RC-07 には当てはまらない(指示資産の長さの母集団は、遮断で打ち切られても、短く保つこと自体が目的)。つまり「規模は遮断しない、分量は遮断する」の差は、較正の母集団の有無ではなく、**超過の害が直接か間接か**で説明するほうが正確。ただし、それを原理にすると下記2に当たる。
3. 同じ原理で RC-07 を観測へ下げる案が出るなら、採らない。変えた指示資産だけ(IMPL-0501)に限られ、採用者が値を置いたときだけ働く。既に十分に弱い。

### 代案
- 編集の指摘として処理する(会議体不要の分類 ed)。基準6 の行へ値の所在を併記し、:2128 の段落に「本節は規模(RC-01)の話で、RC-07 は 3.11.4」と一文足す。
- 論点1 は「軽」でなく**編集**に降ろせる。

### この条件なら賛成
意味(遮断する/しない)を変えず、値の所在の併記だけに限る場合。

### 見落とし
- 受付は RC-07 の登録簿の記述を「参考の値」と書くが、登録簿(`roles-responsibilities.md:2033`)の定数の語は「コンテキストの目安(200行・6,000トークン)」で、**トークン数の側**を扱っていない。6,000 トークンの使い方は不明のまま。
- IMPL-0312 の undelivered(変えていない超過を拾わない)は、開示済みでも「採用者が置いた上限が、触らない限り効かない」穴を残す。緩める向きに倒れる既存の弱さで、本 Issue で触るなら強める向きの検討が要る。

## 論点2 登録簿に「使い方」の列を足し、基準を置く

### 反対意見
1. **一般原理「遮断は、害を直接止める条件に限る。較正の母集団を観測する定数を遮断に使わない」の新設は、ADR-0047 の原理の変更**(一般化)で、受付は「ADR の原則の変更」を重の条件に挙げながら、論点2 で自分の案がそれに当たることを見ていない。軽で扱えない。
2. **原理は反例を持つ**。RC-05(自己修正3回)は「害を直接止める」とは言えない(失敗の反復を止めるのは、費用と暴走の抑止であって、害の直接の遮断ではなく、値は実証が無い)。RC-06 のカバレッジの下限の合否は、「テスト網羅の代理指標」で、直接の害ではない。原理を書けば、既存の遮断が原理に照らして不適格になる。原理を書かないなら、基準を置く意味が薄い。
3. **使い方の列は自己申告の表になる**。列の値が「遮断」「観測」と書かれていても、実際の挙動(テンプレート・エンジン)と食い違ったとき、誰が検出するか。機械で閉じるのは「列が存在する・語彙に収まる」だけ(受付も認める)。意味の一致は閉じないので、**列を足すと「標準が言う使い方」と実装がずれても、存在検査は通る**。表示と実態の食い違い(「高」)を生む装置になりうる。
4. 列を足すのは「様式の補い」と受付は言うが、登録簿は第3章の要求事項に相当する。**採用者が自分の登録簿を持つのか、標準側だけか**が不明。後者なら採用者への義務は無く、列は読み手への情報にすぎず、信頼性への寄与は小さい。

### 代案
- 列は足さず、**RC-01〜08 の各行の「担っている保証と、移った先」の欄に、既に使い方が書かれている**(例: RC-01 は確認と R2、RC-04 は観測、RC-05 は停止)ことを確かめ、欠けている行(RC-02・RC-03・RC-06・RC-07 の「遮断か否か」)だけ文言で補う。列の新設より行の文言の補いのほうが、様式の変更(ADR-0040 の template-fields の両方向検査)を起こさない。
- 原理は書かず、**判断の記録**(「ADR-0047・0058 が扱ったのは規模・所要。他の定数には及ばない」)を ADR の本文を変えずに登録簿の注で示す。

### この条件なら賛成
列を足す場合は、(a) 使い方の値が実装の挙動(IMPL の target)と対応づけられ、`lint:refs` 相当で IMPL の実在まで検査する、(b) 原理の文を書かない、の両方を満たすとき。

### 見落とし
- 登録簿は RC-09〜12 を「依らない」としている。「揃えるべき」の議論に含めると、能力に依らない定数まで遮断/観測の基準に巻き込む。範囲を RC-01〜08 に限ると明記すべき。
- RC-06 の 80/90 は EV-0143(E0、`evidence-ledger.md:232`)。**根拠が無い値を遮断に使っている**ことは、遮断/観測の整理ではなく、根拠水準マークでの開示で受けるのが既存の流儀で、本 Issue の主題と混ぜると論点がぼやける。

## 論点3 ADR-0065 の代償措置

### 反対意見(主に受付への補強)
1. 受付の「ADR-0065 影響5つ目は ADR-0088 で置換済み」は正しい(ADR-0065 ステータス欄)。したがって Issue の前提(「不揃いを前提にしたまま」)は**古い**。ただし受付は「必要なら読み替えの新 ADR 1本」とするが、**不要**。ADR-0088 決定5 と `gate-criteria.md:1024-1036` が既に、終了の行・由来の記録・黙って下げない、を定めている。新 ADR は決定の重複を生む。
2. **90% を観測へ下げる向きの案が出たら反対**。代償措置の本質は「独立レビューを欠く体制の穴を機械で補う」で、観測へ下げれば穴が開く(適合の主張を受け取る側が失う)。ADR-0028 決定6(代償措置は未達の代わりにならない)とも整合しない。
3. 逆に **90% を引き上げる/義務化する向き**も、E0 の値を義務にするので反対。現状の「参考の値、基準値は組織が定める」が妥当。

### 代案
変更なし。Issue へ「ADR-0088 決定5 で置換済み。残る論点は EV-0143 の根拠水準の見直し(2027-10)に帰す」と記録して閉じる。

### この条件なら賛成
受付の「条項を足さずに受けられる」に賛成。ただし新 ADR は書かない。

### 見落とし
- 受付が挙げた確認(b)「`ci-strict` が下限をどう導くか」は、遮断になるのが組織の置いた値か、テンプレートが 90 を初期値に置くか(IMPL-0346)で結論が変わる。テンプレートが 90 を初期値として置き、採用者が触らなければ、**実質は標準が 90 を遮断に使っている**。「参考の値で標準は課さない」という受付の説明は、この確認を経るまで採れない。未確認のまま decision に書かない。

## 論点4・5(範囲外、一言)

現状維持に異論なし。ただし論点5 の「新材料が無ければ維持」には補足: 統制を緩める向きの案しか出ていない以上、維持は妥当。論点4 は、事象の記載が無い Issue の提案を閉じることで足りる(却下の旨を明記)。
