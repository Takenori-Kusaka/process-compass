## 1. 項目ごとの反対意見

### 項目1(基準値の欄と一致の検査) — 骨格は賛成。3点を直す

1. **様式は4つとも直す**(P1)。`test-brief-thresholds.mjs` か `test-init-g5.mjs` に、4様式すべてに行があることの検査を足す
2. **二重の記録を作らない**。起案は 175 行の括弧から「カバレッジ」を残すとしたが、残すと自由記述の値と新しい行の値の2か所に基準値が書かれる。食い違ったとき、機械は行だけを比べ、人は自由記述を読む。括弧を「(変更失敗率・差し戻し率。カバレッジの基準値は下の行)」へ改める。175 行の文に依る検査・マークは無い(`差し戻し率・カバレッジ` は template・標準・src/data のどこにも引かれていない。IMPL-0590 は行の名「安定性指標の閾値」だけを引く)
3. **行の必須の扱いが抜けている**。起案は契約検査だけを書き、`check-g1.mjs` の `REQUIRED_ROWS` に触れない。そのままだと、新しい企画書が行を未記入のまま G-1 を通り、契約検査は notes を出し続けるだけになる(比べる経路が永久に働かない)。範囲の行と同じく、G-1 を通過する前の企画書では必須にする(`g1Dependent`)。ただし G-1 を通過済みの企画書に行が無い場合は、範囲の行の先例(`briefScopeRowState` の `gap` → `aggregate-evidence` の gaps で G-7 を失敗)に**倣わない**。理由: 範囲は #296 で新しく記録を求めた事項だったが、基準値は既に「安定性指標の閾値」の自由記述で記録されている。新しい行は記録の構造化であって新しい記録の要求ではない。既存の採用者の G-7 を落とすのは新しい失敗を課すことになる。通過済みの欠けは契約検査の notes だけにする
4. 契約検査の比較の位置(起案の `verify-gate-contract.mjs` の 5.5 節、範囲の照合の直後)・決定可能な条件の切り分け・IMPL-0994 の target を `gate-contract` へ改めることは賛成。ただし代償措置の間に企画書へ 90 と書いた場合のメッセージに「代償措置の下限は基準値に含めない(第4章 G-5)」の案内を入れる(最も起こりやすい食い違い)

### 項目2(`?? 80`) — 起案に反対。失敗にする

起案は「失敗にしない。由来の無い値として警告する」とした。反対する。

- 第1章 1.7.7 の表は、組織が定める値について「記録が無いとき: 当該の基準を満たさない。**参考の値は効かない**」と定める。G-5 基準3 の基準値は組織が定める値(`gate-criteria.md:1059`)。`?? 80` は参考の値を黙って効かせる。警告を足しても参考の値が効くことは変わらず、1.7.7 と逆の挙動を表示で覆うだけになる(表示と実態の食い違いを、表示で正当化する形)
- 起案の反対理由(既存の構成が突然落ちる)は事実でない(P4)。値の無い構成は手で消した場合だけで、その場合に止めるのが 1.7.7 の求めである。採用者への新しい義務ではない(値を記録する義務は既にある)
- 決定可能: `typeof ci.coverageThreshold === 'number' && 0..100`。機械にしてよい
- 置き場所: `coverage-check.mjs` の `evaluateCoverage` で、値が数でなければ `fail`(`measured: false, reason: 'ci.coverageThreshold が無い'`)。`verify-gate-contract.mjs` の 5.5 節(g5 が omitted でないとき)で problems。`adapter.mjs:114` は子の検査器へ渡す環境変数で、契約検査と coverage-check が先に落とすので `?? 80` を残してもよいが、「値は coverage-check と契約検査が確かめる。ここは子へ渡すだけ」と注を書く。値を空にすると子の検査器の読み方が分からない(確かめていない)ので変えない
- 項目1 の「構成に値が無い: notes」は、この項目で problems になるので消える(項目1 の分岐から外す)
