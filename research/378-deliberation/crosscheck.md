## 1. 結論の要約

重大度「高」の所見はありません。移した場面のうち、空振りで通る場面は見つかりませんでした。50 場面はすべて移っており、判定の式は、記録された改め(h2・i1・i3・i8)と下の所見 F-3(j1)を除いて元と同じか、空振りの止め(`must`・`g.ext &&` など)を足した分だけ強くなっています。

重大度「中」は4件です。どれも、本件で足した仕組み(`kind: 'precondition'` の除外と `inputs` の欄)が、ADR-0089 決定2・決定3 の人の確認の経路から外れていること、または記録の欠けです。

| 番号 | 重大度 | 要旨 |
| --- | --- | --- |
| F-1 | 中 | `kind: 'precondition'` の除外に歯止めが無い。ADR-0089 決定2「各場面は決定を持つ」の例外であることが ADR の注記に無い |
| F-2 | 中 | `changed-scenes.mjs` が `inputs` と `kind: 'precondition'` を拾わない。変更ごとの人の確認(決定3)から漏れる |
| F-3 | 中 | j1 の判定の式を改めたのに `changed` が無く、DISPOSITION.md の (3) にも無い。裁定 R-3 の「限り」と食い違う |
| F-4 | 中 | survey.md が引く `implementation.md` が無い。R-5 の数の報告と、直した後の h2 の変異の確認の記録が無い |
| F-5〜F-11 | 低 | 引いた決定の当て方、再生の [前提] の弱さ、対照の欠け、名前の不整合など |

## 3. 所見

### F-1 中: `kind: 'precondition'` の除外に歯止めが無く、ADR-0089 決定2 の例外として記録されていない

- 所在: `scripts/regress/run.mjs` の `decisionScenes`・`fixesTable`、`suite/lib.mjs` の `check` の `opts.kind`、ADR-0089 のステータスの注記
- 根拠
  - ADR-0089 決定2 は「各場面は欄 `fixes` に、固定する決定を1つ以上持つ。決定を持たない場面は、実行役(`run.mjs`)が失敗にする」と定める。これまで [代役](`kind: 'harness'`)も除外されず、決定を持っていた
  - 本件の run.mjs は、`kind === 'precondition'` の場面を決定の検査と `fixes.md` から除く。`kind` は `check` の任意の引数であり、名前の `[前提]` との対応も、`pre()`(落ちたら止める)を通ったことも確かめない。どのスクリプトでも、決定を固定する場面に `kind: 'precondition'` を付ければ、決定の検査を黙って外せる
  - 全場面が precondition のスクリプトも通る。run.mjs の検査は「場面の記録が無い」だけで、決定を固定する場面が1つ以上あることを求めない
  - `test-run.mjs` の追加は、除外が効くことだけを確かめる。除外を悪用した形(名前に [前提] が無い precondition、precondition だけのスクリプト)が落ちることは確かめない
  - ADR-0089 の注記は「本 ADR の決定は変えません」と書くが、決定2 の検査の対象から1つの類を外したことに触れていない。decision.md 3 節は「矛盾ではない」と判断しているが、その判断が ADR の側からは読めない
- 直し方の案
  - run.mjs で、`kind: 'precondition'` と名前の先頭 `[前提] ` を両方向で対応させる(片方だけなら失敗)
  - スクリプトごとに、precondition でない場面が1つ以上あることを求める
  - `test-run.mjs` に、上の2つの失敗の場面を足す
  - ADR-0089 の注記に「決定2 の検査は、前提の段の確認(`kind: 'precondition'`。名前は `[前提]`)を除く。除く理由は、決定を固定しないこと」を1文で足す。決定2 の変更に当たると判断するなら、新しい ADR で置き換える

### F-2 中: `changed-scenes.mjs` が `inputs` と `kind: 'precondition'` を拾わない

- 所在: `scripts/regress/changed-scenes.mjs` の 3 と 4(`/\b(changed|knownFailure|dependsOn)\b/` と `s.changed` の行)
- 根拠
  - ADR-0089 決定3 は、変わった場面の一覧(旧・新・引いた決定)を PR の本文と CI の要約へ出し、人が確かめるとする。累積の `changed.md` では代えない、とも書く
  - 本件は、期待値と別に「入力を改めて通した」を記録する `inputs` を足した(裁定 R-3)。入力を足して通す形は、期待値を改めるのと同じく、場面が何を確かめるかを変える。ところが `changed-scenes.mjs` は `inputs` の行を拾わず、`inputs.md` は累積である。変更ごとの人の確認に、入力の改めが出ない
  - 同じく、場面に `kind: 'precondition'` を足して決定の検査から外す変更も、`changed-scenes.mjs` に出ない(F-1 と合わせると、決定の検査を外す変更が人の目に触れない)
- 直し方の案: `changed-scenes.mjs` の 3 の正規表現に `inputs` と `precondition` を加え、4 に `inputs` の行(引いた決定・改めた入力・元の入力のときの結果)を足す。`test-run.mjs` または対応する試験で確かめる

### F-3 中: j1 の判定の式を改めたのに、`changed` が無く DISPOSITION.md にも書かれていない

- 所在: `lib-r3.mjs` の scenSteps の j1(`trialOnly` を集める行と check)、`DISPOSITION.md` の fix288-r3 の行の (3)
- 根拠
  - 元の式: `g.ev.gaps.filter((x) => /adoption-trial/.test(x)).length === 0`(欠落の文に「adoption-trial」の語が無いこと)
  - 移した式: 製品の PR の後の、`docs/adoption-trial/` だけを変えたコミットの識別子を集め、8 件以上あり、その先頭 7 字が欠落の文に現れないこと
  - 裁定 R-7(反対 7)がこの改めを求めたので、改めること自体は裁定どおりである。いまの集約の欠落の文は `コミット <先頭 8 字>: …` の形で、照合は空振りしない(`aggregate-evidence.mjs` の 2606〜2614 行で確かめた)
  - しかし裁定 R-3 は「判定の式を改めるのは、後の決定が語や所在を改めたと特定できる場合に限り、`changed` に残す」とする。j1 の改めは後の決定によるものではなく、`changed` も無い。h2 は同じく裁定 R-7 による改めで `changed`(ADR-0089 決定5)を持つ。j1 だけ扱いが違う
  - 新しい式は、記録のコミットの識別子に依らない欠落(記録の置き場 `docs/adoption-trial/` のパスを含む別の理由の欠落)を拾わない。元の式より強い面と弱い面の両方がある。この判断が記録に無い
  - DISPOSITION.md の (3)「期待値を改めた場面は h2・i1・i3・i8」は、j1 を落としている
- 直し方の案
  - j1 に `changed` を付ける。`from` に元の式の字面、`by` に引ける決定(元の場面が固定する ADR-0057 決定11 と S23 を注記)を書く。引ける決定が無いと判断するなら、裁定 R-3 と R-7 の関係(R-7 の欠陥の直しは R-3 の「限り」の外で行う)を decision.md に追記する
  - 元の式の語の照合を残す(識別子の照合と併せて、欠落の文に `docs/adoption-trial/` が現れないこと)か、残さない理由を注記する
  - DISPOSITION.md の (3) に j1 を加える

### F-4 中: `implementation.md` が無く、R-5 の数の報告と直した後の変異の確認が記録に無い

- 所在: `research/378-deliberation/`(`survey.md` 3.5 末尾が `implementation.md` を引く)
- 根拠
  - survey.md 3.5 は「直した後の結果は `implementation.md` にある」と書くが、このファイルは作業ツリーに無い
  - 裁定 R-5 は「一覧の数は、元の場面・[前提]・[代役] を分けて報告する」とする。報告の場所が無い。survey.md 3.4 の数(r3-scen は [前提] 16 など)は試作の時点のもので、いまの宣言(r3-scen は [前提] 51・[代役] 4)と合わない
  - 裁定 R-7 の h2 の直しの根拠は変異 M1 の確認だが、直した後の h2 が M1 で落ちることの記録が無い。直しの効き目が記録の上で確かめられていない
  - DISPOSITION.md の行も、[前提]・[代役] の数を書いていない
- 直し方の案: `implementation.md` を置き、(1) スクリプトごとの数を元の場面・対照・[前提]・[代役] に分けた表(上の 2 節の表と同じ形)、(2) 直した後の変異 M1〜M3 の結果(とくに h2 が M1 で落ちること)、(3) 流した環境とテンプレートの版を書く。置かないなら survey.md の参照を改める

### F-5 低: `inputs` の `by` が、入力を足した根拠でない決定を引いている

- 所在: `r3-succession.mjs` の `riskInput`(`by: 'ADR-0057 決定11'`)、`lib-r3.mjs` の `performerInput`・`baseInput`(`by: 'ADR-0054 決定9'`)
- 根拠
  - lib.mjs の注記は `inputs` を「後の決定・様式に合わせて足した・改めた入力」とし、`inputs.md` は `by` を「引いた決定」の列に出す
  - 区分の下限の規則は、INPUT_ORIGIN と裁定 R-4 が「期待の文から逆算・推定した」とする入力である。裁定 4 節も、A2 について「引ける決定も無い」と書く。ADR-0057 決定11 は場面が固定する決定であり、入力を足す根拠ではない。`inputs.md` の読み手は、決定11 がこの規則を求めたと読む
  - AI の担い手は、ADR-0054 決定9 が求めるのは条件2〜5 の確認の記録であり、担い手を置くこと自体は逆算である(INPUT_ORIGIN.performer)。`by` が両方を1つの決定に帰している
- 直し方の案: `inputs` に出所の欄(`origin: '元' | '規定' | '逆算'`)を足し、逆算の入力は `by` に場面が固定する決定を書いたうえで `origin: '逆算'` と明示する。または `what` の先頭に「逆算した入力(引ける決定なし)」と書く

### F-6 低: 再生の [前提] が q の終わりの状態しか確かめない

- 所在: `lib-r3.mjs` の scenSteps(`if (replay) pre(...再生 q...)`)
- 根拠
  - 裁定 R-1 は「再生が前提を満たしたこと(類型E を数えた、表7 が実測あり、など)を [前提] の場面で確かめる」とする
  - 実装の再生の [前提] は、q の最後の記録に「転記は不要」の語があることだけを見る。`r2.ok` も、類型E の判定の行(q2 の正規表現)も見ない
  - i の再生の終わりの状態(`seeded-errors.json` の人の層が本来の tally の測定値 3 に戻ったこと)と、j の再生の終わりの状態(製品の PR と G-6 の判定記録のコミット)は確かめない
  - 後の段の場面は、置き換えの空振り(`must`)と A2 の [前提] で多くの崩れを拾うため、空振りで通る場面は見つからなかった。ただし、再生の崩れが「場面の前提の崩れ」でなく「場面の失敗」として現れ、原因を読み違える余地がある
- 直し方の案: 再生の終わりに、i は `seeded-errors.json` の `human.detected === 3`、q は `r2.ok` と類型E の行の正規表現、j は G-6 の判定記録のファイルが HEAD にあることを [前提] で確かめる

### F-7 低: 逆算した入力の一部に対照が無く、記録ごとの扱いがそろっていない

- 所在: `lib-r3.mjs` の INPUT_ORIGIN、`DISPOSITION.md` の (2)、j8 の check
- 根拠
  - 裁定 R-4 は「逆算・推定した入力には、外すと場面の前提が変わることを確かめる対照の場面を置く」とする。一方で R-4 の出所の分けは、表7 の列「復旧の目安」の値を推定に入れている。この値に対照は無い。INPUT_ORIGIN は同じ値を「元」の項に注記で入れており、R-4 の分けと食い違う
  - INPUT_ORIGIN.successorOthers(節9 の出荷判定者以外の代理者)は「逆算」だが、裁定 R-4 の列挙にも DISPOSITION.md の (2) にも無く、対照も無い。j10 の書式(出荷判定者だけを挙げる形)はこの入力に依る
  - j8 は、層1 の育成の担当(逆算の入力)の字面から期待の文を逆に決めた場面だが、`inputs` を持たない。同じく逆算の入力に依る A2 は `inputs` を持つ。DISPOSITION.md の (2) は育成の担当を「足して通した」入力に挙げながら、場面の列挙に j8 を入れていない
- 直し方の案: 表7 の「復旧の目安」と successorOthers に対照を置くか、置かない理由(場面の判定に効かないこと)を INPUT_ORIGIN と DISPOSITION.md に書く。j8 に `inputs` を付けるか、付けない理由(逆算の入力が期待の文そのものを作ったこと)を注記する

### F-8 低: v9「(前提)構成の変更が通る」の扱いが [前提] の規則とそろっていない

- 所在: `lib-r3.mjs` の verifySteps の7
- 根拠: 元の 50 場面の1つであり、場面の数に入れるのは元のとおりである。ただし名前は「(前提)」で、`kind` を持たず、`fixes.md` で ADR-0057 決定11 を固定する場面として数えられる。決定を固定しない確認を決定の対応表に載せることになり、F-1 の規則(名前と kind の対応)を入れると、ここで食い違いが出る
- 直し方の案: 元の場面として残すなら名前の「(前提)」を runner の規則と区別できる形にし、決定を固定しない理由を注記する。または `pre()` に替え、元の 50 の数から外すことを DISPOSITION.md に書く

### F-9 低: 置き換えの空振りの一部が [前提] の失敗として記録されない

- 所在: `lib.mjs` の `clRecord`(`throw`)、`lib-r3.mjs` の `adopter` の D-0 節16
- 根拠: 裁定 R-5 は「入力の置き換えの空振りは、[前提] の場面の失敗として記録してから止める」とし、`throw` だけで止める案を退けた(4 節)。`clRecord` は空振りで `throw` する。run.mjs が場面の外の中断として失敗にするため黙っては通らないが、どの入力が外れたかが場面の記録に残らない
- 直し方の案: lib-r3.mjs の側で `clRecord` を try で包み、捕まえた理由を `pre(..., false, e.message)` で記録する

### F-10 低: 「注入の分岐でテストが落ちる」の [前提] が、落ちた理由を見ない

- 所在: `lib-r3.mjs` の trialSteps の d(`pre(... d 注入の分岐では製品のコードのテストが落ちる, !t.ok ...)`)
- 根拠: 裁定 R-2 の意図は、注入が製品のテストに効いたことを確かめることである。`!t.ok` は、構文の誤りや読み込みの失敗でも満たされる
- 直し方の案: 出力に AC-1・AC-2・AC-3 の失敗の名前が出ること(注入した類型ごとに落ちるテスト)を照らす

### F-11 低: 文書と検査の注記の小さな食い違い

- `ADR-0089` の注記は「退避物に無かった採用者の製品のコードは作り直し」と書く。作り直したのは製品のコードに加えて D-0・層1・企画書・引き継ぎ文書などの入力の全体であり、DISPOSITION.md の (1) のほうが正確である。注記は (1) に合わせるとよい
- `check-fixes.mjs` の冒頭の注記は `changed` の `by` だけを挙げる。正規表現は `inputs` の `by` も拾うため検査は効いているが、注記と試験に `inputs` が無い。裁定 R-3 の「`by` の実在は `changed` と同じ検査で確かめる」が、意図して満たされたのか偶然なのかが読めない
- 再生の j は集約の前で戻る。元の連鎖では j の集約が `evidence/` を書いた状態で scen2 が流れた。`evidence/` は無視の対象で、判定する場面への影響は見つからなかったが、元と状態が違う点として注記しておくとよい
- DISPOSITION.md の (2) は「対照の場面(n・f・t)で固定した」と書くが、t は (2) が挙げる7場面のどれの対照でもない(育成の担当は j8 に効く。F-7)

## 4. 確かめて問題が無かった点

- R-1: 3本が単独で流れ、`adopter()` と `trialSteps()` の後に、r3-scen の本体と同じ関数(`scenSteps`・`verifySteps`)を `quiet` で再生する。h は状態を残さないため再生しない。元の段0 は作らない。採らない案は decision.md に明記されている
- R-1 の再生が元の連鎖の状態を作るか: 元の scen の i・q・j と scen2 の v1〜v4 の状態を変える手順が、同じ字面で再生される。scen2 の v7 以降は元でも `git checkout`・`git clean` で戻しており、再生しないことで状態は変わらない(`git clean -qfd` は無視の対象を消さない)
- R-2: 製品のコードは `fixtures/adopter-r3/` から写す。注入は `INJECTIONS` の1か所から当て、写した後に各行の中身を [前提] で確かめる。注入の分岐の差分が4行だけであること、`main` でテストが通ることを確かめる
- R-3: `changed` の `from` に元の式の字面と補足の番号、`by` に決定の番号がある(h2・i1・i3・i8)。v4・v6 の欄の名の改めは `inputs` に移っている。run.mjs は `inputs.md` を `changed.md` と分けて書く
- R-4 の対照 n・t・f は、それぞれ足した入力を外した採用者で、元の場面と逆向きの観測を確かめる。n の否定の場面(転記の案内が出ない・基準集合が出ない)は、同じスクリプトの q3・q4・j6 の肯定の場面と同じ語を照らすため、語が変われば肯定の側が落ちる。空振りで通る否定ではない
- R-5: `pre()` は失敗で `done()` を呼んで止まる。拒否の [前提] は `reasons()` の1件の中で語を照らす。止まったことは終了コードと宣言の一覧の不一致で現れる
- R-7: h2 は「同じ秒」だけになり、2つの子へ同じ `REGRESS_NOW` を渡すため、必ず同じ秒に始まる。同一人物の tally は [前提] になった。j1 は識別子で照らす(F-3 の記録の欠けを除く)。q1 の前に宣言の時刻と類型E の日付の前後を [前提] で確かめる。区分の下限の規則は製品の PR の前の別の PR。`@regress` の `fixes` に `#378` は無い
- ADR-0089 決定1 の「p302 との一致」が確かめられないことは、DISPOSITION.md と ADR の注記の両方に書かれ、過大な主張は無い。決定5(時計)とは、宣言の時刻を置き、テンプレートに時刻の入口を足さない点で合う
- 引いた決定の実在: `node scripts/regress/check-fixes.mjs` は「112 件がすべて実在する」で通った(この突合の中で流した唯一のコマンド)
