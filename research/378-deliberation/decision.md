# #378 議長の裁定

- 対象: Issue #378(所有者の決定 2026-11-05「すべて覆う」)。fix288-r3 の 50 場面を `scripts/regress/` へ移す方法
- 審議の重さ: 軽。受付の理由は、標準の条項の改廃ではなく回帰の試験の範囲の判断であり、採用者への新しい義務を課さず、規格の引用も要らないこと
- 材料: `survey.md`(内部の調査と実行での確認)、`council-01-drafter.md`(起案)、`council-02-opponent.md`(反対。起案を読まずに書いた)
- 日付: 2026-11-12
- 方針: 2委員の一致点を採る。割れた点があれば作業を止める

## 1. 割れたかどうかの判定

論点ごとに、2委員の立場を突き合わせました。結論として、**割れた点は無い**と判定します。論点1 だけは手段が違って見えるため、判定の理由を書きます。

- 起案は「3本に分け、連鎖の状態を作らない形」を、**連鎖の状態に依存する場面が無いことを実行で確かめる**条件つきで採りました。依存が見つかった場合は「単独の形でその状態を前提として作る」としています(council-01 1 節の条件の2つ目)
- 反対は、実行で依存を確かめました。r3-verify・r3-succession の記録は類型E を数えず、節6 の類型E の行を「基準を満たさない」と出します。元の前提(scen の q で類型E を数えた後の記録)とは中身が違います(council-02 1 節)
- したがって起案の条件は満たされず、起案自身の規則によって「前の段の状態を前提として作る」形になります。これは反対の推す丙(前の段の状態を変える手順を、判定なしで再生してから場面へ入る)と同じです
- 起案は「判定せずに段だけを流す形」を、前の段の失敗が後の段へ流れるとして退けていました。丙は、再生した状態を [前提] の場面で確かめ、満たさなければ止めます(論点5 で両委員が一致)。起案の退けた理由は丙には当たりません

ほかの論点も、片方の委員が足した要求を、もう片方が退けていません。片方だけが挙げた欠陥は、もう片方の立場と矛盾しないため、直します。

## 2. 裁定

### R-1 分け方(論点1)

- 3本(`r3-scen`・`r3-verify`・`r3-succession`)に分け、それぞれ単独で流す
- 各スクリプトは、採用者のリポジトリの作成(`adopter()`)と導入前の検証の a〜g(`trialSteps()`)に続けて、**元の連鎖で前の段が状態を変えた手順を、判定なしで再生する**
  - r3-verify: scen の状態を変える手順(i の同一人物の tally と戻し、q の実施日の直しと D-0 表7 の転記、j の製品の PR と G-6 の判定記録)
  - r3-succession: 上に加えて scen2 の状態を変える手順(記録の生成と人が書く欄の記入のコミット。v7 の構成の変更は元でも戻している)
  - 再生の手順は r3-scen の本体と同じ関数を使う(手順が2か所に分かれて食い違う形を作らない)
  - 再生が前提を満たしたこと(類型E を数えた、表7 が実測あり、など)を [前提] の場面で確かめる
- 元の段0(テンプレートの更新を PR で取り込む)は作らない(両委員一致)。作業用の複製がいまのテンプレートから作られ、取り込む差分が無い
- 採らない案: 元の連鎖を1本で流す(両委員とも退けた。前の段の失敗が後の段を不明な状態で判定させる)、3本が前の段の場面を判定として流す(同じ決定の場面が重なる)、a〜g の後の状態だけで流す(試作。元の前提と記録の中身が違う)

### R-2 製品のコード(論点2)

- 構成管理の下の固定の本文(`fixtures/adopter-r3/`)を写す(両委員一致)
- 欠陥注入の置き換えを `INJECT_LINES` から導き、1か所にする(反対 丁(1))
- 注入の分岐の差分が、注入の記録の4行(`inspection.js` の 6・16 行、`permission.js` の 3・4 行)だけを変えたことを [前提] で確かめる(反対 丁(2))
- `main` で `node --test` が通り、注入の分岐で落ちることを [前提] で確かめる(反対 丁(3))。PR の本文の「node --test が通過」を事実にする
- 入力の書き換え(D-0 の前付け、企画書の連鎖の置き換えを含む)は、すべて空振りしたら止める(起案 D1・D2)
- 採らない案: 本文を文字列として持つ(読みにくくなるだけ)、テンプレートの雛形から作る(試験の対象が入力を黙って変える)、元の本文を探して戻す(退避物に無い)

### R-3 期待値の出所(論点3)

- 期待値の基準は、元のスクリプトの判定の式(退避物に字面で残る)とする(両委員一致)
- 判定の式を改めるのは、後の決定が語や所在を改めたと特定できる場合に限り、`changed` に残す。`from` には元の判定の式の字面を書き、補足の番号(S26・S32・S35)を書く(両委員一致)。`by` は決定の番号まで書く(検査が決定の番号の無い ADR を落とす。`ADR-0066 決定3`)
- **入力の変更は、期待値の変更と別の欄で記録する**(反対)。場面の記録に `inputs: [{ by, on, what, without }]` を持たせ、run.mjs が `inputs.md`(期待値の改めの `changed.md` と同じ形の表)へ書き出す。`by` の実在は `changed` と同じ検査で確かめる
  - v4・v6 の欄の名の改めは、入力の変更として `inputs` に移す(反対の分類。起案の求めた `by` の形を満たす)
- いまの出力を期待値へ写すことはしない(ADR-0089 決定3)

### R-4 逆算した入力と対照(論点4)

- 作り直した入力を出所で分け、`lib-r3.mjs` の注記と DISPOSITION.md に書く(両委員一致)
  - 元の置き換えの文字列から読んだもの: 注入の行、D-0 節9 の「品質保証部 課長」、D-0 表7 の行、`tests/README.md`、AC-1〜AC-3
  - 現在の規定が要求するもの: 合否の基準の行「実環境の統制の確認」、D-0 の様式の直し(`lib288.mjs` と同じ)
  - 期待の文から逆算した、または推定したもの: 区分の下限の規則(規則があったことは `bcaf3da` の場面集 #6 で裏付けられる。パスと下限の値は推定)、開発者の席の AI の担い手と適合性確認・条件2〜5 の記録、層1 の育成の担当の値、表7 の列「復旧の目安」の値
- 逆算・推定した入力には、**外すと場面の前提が変わることを確かめる対照の場面**を置く(両委員一致。起案は区分の下限、反対はそれに加えて AI の担い手と育成の担当)
  - 区分の下限の規則が無い採用者: 場面集 #6 が「止まらなかった」、記録が「10 / 11」
  - AI の担い手を置かない採用者(元の `setup.mjs` の席の入力): AI の層が「AI の担い手の宣言なし」で未測定、D-0 表7 への転記の案内が出ない、基準集合の依存が出ない(元の入力でいまどう動くかを固定する)
  - 育成の担当に名簿の氏名を書いた層1: 外部向けで氏名を伏せる
- 入力を足して通した場面(i6・q3・q4・q5・j6・j7・A2)は `inputs` に記録する(反対 高1)。調査の 2.4 の「食い違う場面は無かった」は、元の入力に対しては成り立たないため改める

### R-5 [前提] の場面(論点5)

- 場面の一覧に入れる(両委員一致)
- `kind: 'precondition'` を付け、固定する決定の対応表(`fixes.md`)と、決定の有無の検査から除く(反対)。run.mjs を改める
- [前提] が落ちたら、そのスクリプトを止める(起案)。止めたことは、終了コードと場面の一覧の不一致で現れる
- 入力の置き換えの空振りは、[前提] の場面の失敗として記録してから止める(起案の「止める」と、反対の「場面の記録に残す」の両方を満たす)
- 拒否を確かめる [前提] は、終了コードだけでなく拒否の理由の語を照らす(反対)
- 一覧の数は、元の場面・[前提]・[代役] を分けて報告する

### R-6 DISPOSITION.md(論点6)

- fix288-r3 の行を「移さなかったもの」から外し、「移したもの」の表へ置く(両委員一致)
- 行の中に、作り直した入力の出所、入力を足して通した場面、期待値を改めた場面、連鎖の前提の扱い(再生)、省いた段0、名前から件数を外した j2・B3 の元の名前、p302 との一致は確かめられないこと(当時の出力が無い)、旧い表示の「一部だけ」が実際より多くを主張していたこと、を書く
- ADR-0089 の「影響」の「fix288-r3 の 50 場面を表示し続ける」は、本文を書き換えず、ステータスの節の後ろに日付つきの注記を足す(ADR-0110 の注記と同じ形)

## 4. 採らない案(まとめ)

| 案 | 理由 |
| --- | --- |
| 覆わない・一部だけ覆う | 所有者の決定(すべて覆う)で退けられている |
| 元の連鎖を1本で流す | 前の段の失敗が後の段を不明な状態で判定させる。1本の早期の終了で後ろの場面がまとめて消える |
| a〜g の後の状態だけで scen2・scen3 を流す(試作) | 元の前提と記録の中身が違う(類型E を数えない記録)。実行で確かめた |
| 連鎖の比較を常設の実行にする | 丙で前提を作り直すため、比較は要らない。同じ場面の名前が2つの実行に重なる |
| 食い違う場面に落ちることを期待する印を付ける | 決定どおりの挙動を欠陥として表示し続ける |
| 区分の下限の規則を置かず、A2 の置き換えを「10 / 11」にする | 期待値を入力に合わせて改める形であり、引ける決定も無い |
| 入力の変更を `changed` に混ぜる | 期待値の改めと入力の改めを読み手が区別できない |
| 置き換えの空振りを `throw` だけで止める | どの入力が外れたかが場面の記録に残らない |
| テンプレートを直して場面を通す | 本件の範囲の外。必要が出たら報告する(本件では出なかった) |
