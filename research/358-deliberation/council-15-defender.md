## 総論(3つの前提)

1. **本標準の「機械検査」は、すでに決定論的な検査の意味で定まっている**。附属書H の C3 は「合意済みの検査を全件通過」を主張とし、H.4 の表は「決定論的な検査」と「AI の推定による判定」を分け、後者を判定に数えない。ADR-0012 決定2 は AI の出力を未検証の入力とする。したがって、3.11.5 の文言が LLM の判定を「機械検査」と称させる、という懸念(反対委員 B)は、現行の条項の組み合わせの上では既に閉じている。誘因を塞ぐために 3.11.5 を改める必要は無い
2. **本標準は、検出の範囲が限られた機械の検査を、範囲の開示つきで規定として扱ってきた**。5.8.6 要求事項10(パスの差、合否に使わない)、5.8.5 の後の段落(機械の検出の一覧)、要求事項9(拒否 0 件を根拠にしない)、ADR-0084 決定1(「この確かめは、試験の中身が規定を正しく確かめていることを示さない」)、決定5(「文の所在の追跡であり、従うことを示さない」)、ADR-0124 決定2(検出の範囲と 0 件のときの定型の文)。「機械で完全に判定できないものは機械検査の項目にできない」は、本標準の既存の型と合わない
3. **弱める向きの変更の非対称**。3.11.5 の後段は「足す側を軽く、外す側を重くする非対称は、意図した設計」と書き、ADR-0074 決定3 はこれを保つ。条項から検査の項目を外すことは、条項の水準で検査を外す変更である。外す理由が「判定できない」だけで、外した後に何がその場面を止めるかを書かないなら、ADR-0074 決定4 の記録(止めていた場面・外した後に止めるもの)を条項の側で欠くことになる

## H-1: 3.11.5「変更時に機械検査する」の3点

### 推す案

- **3点の項目は維持する**。現行の文言は「変更時に機械検査する。検査項目は…の3点」であり、「機械が判定を確定する」「合否を決める」とは書いていない。項目は「何について機械の検査を置くか」を定め、各検査の検出の範囲は、総論2 の型で実装の側が開示する。この読みで、3点はいずれも降ろせる
  - 総分量: 数える。上限の値は採用者(ADR-0084 決定3・4。IMPL-0222・0312 は adopter)。値が無ければ「上限未設定」と出し続け、通過と出さない(L-4 と同じ)
  - 既存の記述との矛盾: 決定論的に拾える矛盾の形を検査する。(i) 同じ節の中で核の文言の否定と肯定が並ぶ、(ii) `[機械]` の印を持つ行に、名指す検査・フックが実在しない(設定と指示の食い違い。instrlint の「死んだ規則」と同じ型の逆向き)、(iii) 常駐の規則の一覧の `omit` に移した規則が、指示資産に残っている、(iv) 同じ名前の値(回数・行数・日数)が指示資産の2か所で異なる。これは「矛盾の一般の判定」ではなく、**矛盾の機械の検査**である
  - 導出できる内容: 木の図・依存の一覧の形を検出する(起案 B-3 と同じ)
- **条項へ足すのは、強める向きか中立の1文に限る**(認める改めの限り)。3.11.5 の3点の箇条の直後に次を足す。項目を削らず、機械検査の位置づけを既存の H.4・5.8.6 要求事項9 の型へ揃えるだけの文である
- 起案・反対の案(矛盾を機械検査から外し、AI維持管理者のレビューへ移す)は採らない(下記)

### 条項の文言の案(足す文)

> 機械検査の各項目は、検出できる形を定めて実装し、検出の範囲を開示する。検出が 0 件であることを、矛盾や導出できる内容が無いことの根拠にしない。AI の推定による判定は、機械検査に数えない(材料として示すときは、機械検査の結果と区別して示す)。検出の範囲の外は、AI維持管理者が変更のレビューと要求事項4 の棚卸しで扱う

## H-2: 5.8.6 要求事項3「書き込みはタスクの対象のパスに限る」と隔離

### 推す案

- **「タスクの対象のパスに限る」は、人が確定した実装計画のタスクの対象のパスの範囲に限る、と読める**。文言は「実装計画のタスクの対象のパスに」であり、「作業中の1つのタスクの」とは書いていない。既定ブランチの先端の(G-4 を経た)計画の、全タスクの対象パスの和を許可の範囲とする読みは、文言の内にある。反対委員の改めの案「計画の対象のパスの和」は、現行の文言の一つの読みであって改めを要さない
- この読みで、要求事項6 の懸念は生じない。範囲を決めるのは人が承認して既定ブランチへ入れた計画で、担い手はタスクを宣言しない。範囲は計画の変更(人の承認)でだけ変わる
- **タスクの外の書き込み(仕様・計画・判定記録の起案、`Spec: setup`)の範囲は、文言に無い。この欠けは認める**。改めの限り: 要求事項3 に「タスクの外の作業の書き込みの許可は、成果物の置き場の固定の一覧に限る。一覧は強制層の設定に置き、要求事項6 により人が変える」を足す。許可の範囲を足す向き(緩める向き)の変更であるため、一覧を強制層に置くことと、一覧の変更を人の操作に限ることを同じ文に入れ、緩みを一覧の外へ広げない
- タスク単位の限定(作業中のタスクだけ)は要求事項3 の強い読みとして残す。降ろす手段の候補は「人の操作で作業中のタスクを指定する印(担い手は書けない置き場)」で、降ろすまでは要求事項10(パスの差)で補う
- テンプレートへ降ろすもの
  1. guard-write に、Edit・Write・NotebookEdit の許可の一覧の外への書き込みを遮断する機能を足す(一覧 = 計画の対象パスの和 + 成果物の置き場の固定の一覧)。権限設定の既定は確認(ask)で拒否にならず、`auto` のもとでは人の確認でもないため、フックの遮断で拒否を作る
  2. 秘匿情報の経路の読み取りを ask から deny へ上げる(強める向き。要求事項1 の「接触」の一部。要求事項4 は満たさない旨を注記)
  3. sandbox の設定は**例として置いてよいが、delivered にしない**(反対委員に同意)。ネイティブの Windows で隔離せず、Edit・Write・MCP・フックは隔離の外(P1)
  4. `permissions.blockWritesOutsideWorkingDirectories`(v2.1.314 以降、全モードで拒否)を置く。`denyInsteadOfPrompting` は利用者・管理の設定でしか効かないため採用者へ案内する。いずれも版と挙動を実機で確かめてから表示を決める

### 採らない案と理由

| 案 | 採らない理由 |
| --- | --- |
| 要求事項3 を「計画の対象のパスの和」へ書き換える(反対) | 現行の文言の読みの一つで、書き換えると強い読み(タスク単位)を条項から消す。最小権限(AC-6)の「任務に必要な範囲」から遠ざかる向き |
| 担い手が作業中のタスクを宣言して範囲を開く(起案 D-2 の一部) | 範囲が担い手の操作で決まり、要求事項6 の最後の文により要求事項1 の拒否が成立しなくなる |
| sandbox で delivered と表示する | 所有者の環境(ネイティブの Windows)で効かない。表示が担保を上回る |

### マークの扱い(IMPL-0200 の分け方)

| 部分 | state | 理由 |

| ファイルの道具の書き込みの既定の拒否(計画の和 + 固定の一覧) | 実装・試験の後に delivered、check=machine | フックで作れる。Bash の書き込みは止めない旨を注記 |

## H-3: IMPL-0491(git merge と push の組による既定ブランチ以外への取り込み)

### 推す案

- **条項(取り込み先が既定ブランチになるマージだけを行う)と ADR-0124 決定4 を維持する**。CLAUDE.md へ禁止の行を足すことは、別のマーク(`claude-md-resident`、delivered、presence、単位: 行、`[機械]` を付けない)として置く。0491 本体は `undelivered` のまま
- 0491 を delivered にしない。主題は「AI の担い手の拒否」で `target=guard-bash-hook` であり、指示文の行では降りない(5.8.6 要求事項2・3.11.3)
- `plan=scheduled` は、手段の候補を名指せるなら ADR-0084 決定4 と食い違わない。候補: guard-bash が `git push` の時点で、送るコミットの範囲(`origin/<branch>..HEAD`)のマージのコミットの第2以降の親が、既定ブランチの追跡の参照から到達できるかを調べ、到達できない親を持つマージを含む push を拒否する。ADR-0124 が退けたのは「他の層を引数にした `git merge` の拒否」(引数では既定ブランチからの同期と区別できない)で、親の到達の可否で区別する形は退けていない [推論。実機で確かめていない。追跡の参照が古いときの誤った拒否と、文字列の迂回の余地を確かめる]
- 候補が実行で成り立たないと分かった時点で、ADR-0124 決定4 の型(scheduled・adopter のどちらも事実に反する)に従い、マークの主題を「降りていない」の開示へ改める新 ADR を置く

### 採らない案と理由

- 指示文の行で 0491 を delivered にする(起案): 表示が担保を上回る。ADR-0124 決定4 の「`git merge` と `git push` の組は降りていない」と食い違う
- `plan=adopter`: ADR-0124 決定4 が「採用者も実装できない」とした(.git を読み取り専用にする隔離は全てのコミットを止め、作業ができない)

### 採用者への影響

- 表示は変わらない(undelivered)。指示文の行が足され、担い手に規則が届く経路ができる。適合の主張は揺れない

## H-4: 生成の条件の自動の記録(IMPL-0207)

### 推す案

- 5.8.2 の「観測できる事実」「人の転記に頼らず、導出元から自動で記録」を満たす形として、**SessionStart の観測の記録(反対の条件 (1))と、git の `commit-msg` フックによるトレーラの付与**を推す。`commit-msg` は git の側の仕組みで(`git interpret-trailers`)、担い手のコマンドを書き換えず、人のコミットにも同じく効く(記録が無ければ「記録なし」を書く)
- 値は SessionStart が作業ツリーごとのファイル(`.gitignore`)へ書いた `session_id` と指示資産の木の hash・未コミットの有無。同じ作業ツリーで複数のセッションが動いていれば推定せず「曖昧」と書く
- 置き場はコミットのトレーラ(版管理に入る)。実行の記録(transcript)の保持は採用者による(別のマーク、plan=adopter)
- Claude Code 以外の基盤は plan=adopter(ADR-0084 決定4 の IMPL-0279 と同じ型)
- 実機で確かめるまで `undelivered plan=scheduled`

### 採らない案と理由

- `updatedInput` による `git commit` の書き換え(起案): 確認の画面と実行の食い違いの経路になり、5.8.6 の冒頭の「人が見る範囲」の考え方に反する。複合のコマンド・`-F`・`--amend` で担い手のコミットを壊しうる
- 履歴からの導出(e2): 近似であり、5.8.2 の「観測できる事実」に当たらない(反対に同意)

### 採用者への影響

- `commit-msg` フックは `core.hooksPath` の設定を要する。採用者の既存のフックとの共存を案内する。セッションの識別子の公開の可否は案件ごとに異なるため、トレーラに値を入れるかを構成で選べる形にし、入れない場合は「記録なし」と表示する(記録したとは示さない)

## H-6: CLAUDE.md の行数と 3.11.3 の文言

### (a) 足す行を相殺する条件

- **置かない**。200 行は参考の値で、上限は採用者が定める(ADR-0084 決定3・4、EV-0088)。テンプレートが相殺の条件を自らに課すことは、実証の無い値を事実上の上限として扱うことで、ADR-0084 の決定と食い違う。量そのものに上限を置かない考え方は ADR-0074 決定1 の型とも同じ(同 ADR の対象は検査装置で、指示資産への適用は類推)
- ただし、手順の性質を持つ行を再利用層(スキル)へ移すことは、3.11.3 の層の分け方(定型作業の手順は再利用層)を理由に行ってよい。行数を理由にしない
- 総分量の検査(H-1)で、テンプレートの出荷時の行数を出し、採用者が上限を定めたときに超過が見えるようにする。ADR-0126 に「参考の値を超えて出荷する理由」を根拠水準のマークつきで書く(起案に同意)

### (b) 3.11.3「遵守が必須の規則を誘導層に書いてはならない」

- 現行の文言には、標準自身が既に与えている読みがある。5.8.6 要求事項2 は「指示ファイルにだけ書いた範囲は、拒否できたものとして扱わない(第3章 3.11.3)」と、3.11.3 を「だけ」の意味で引く。3.11.3 の注意書きは「強制が必要な規則は強制層へ降ろします」。ADR-0084 決定2 は常駐の規則の行を降ろし先(presence)とする。この組み合わせの上では、指示文の行は規則を担い手へ届ける経路であり、遵守の担保の層として置くことではない
- それでも、太字の文を字面だけで読むと食い違う(反対委員の指摘は正しい)。**改めを認める。ただし弱めない向きに限る**。反対の案「誘導層だけに置いて担保されたものとして扱ってはならない」は、強制層へ降ろす努力の義務を落とし、「開示すれば指示文だけで足りる」を許す読みを生む。また「人の確認の所在を併記する」は新しい義務で、本件の根拠が無い

### 条項の文言の案(3.11.3)

> **遵守が必須の規則を、誘導層だけに書いてはなりません**。強制層へ降ろします。降ろす手段が無い規則は、誘導層に書いた記述を担保に数えず、降りていない規定として表示し続けます([第5章 5.8.6](/process-compass/phase4-process-design/human-ai-boundary/) 要求事項2 と同じ扱い)。

- 採用者への影響: 字面の読みで「必須の規則を指示ファイルから除いた」採用者は、規則が担い手に届く経路を失っていた。改めの後は、除く必要が無いことと、降りていない表示を続ける義務が明らかになる。強制層へ降ろす義務は変わらない

## H-7: IMPL-0492(入力の記録の保持)

### 推す案

- ADR-0124 決定5(「四半期の抜き取りまで残すことは、まだ降りていない。実行の記録の保持の既定に頼らない」)を維持する。f1(`record-copy.yml` が記録用ブランチへ写す)を主とし、実機の確認まで `undelivered plan=scheduled review=2027-05`
- 確認の項目: (1) 成果物の取得を PR の先頭の SHA と一致する `ai-review` の実行に限る、(2) バイト列のまま写し sha256 を照合する、(3) スクリプトを実行しない、(4) `actions: read` を足す変更の陰性の確認、(5) 閉じた PR を抜き取りの母集団に含むかを H.12 と照らし、含むなら閉じたときも写す、(6) 写した記録を抜き取りの時点で取り出せること(取り出しの試行)
- 他の形
  - 非公開のリポジトリで保持を 400 日まで延ばす: 部分の手段として案内してよい。公開のリポジトリで成り立たないため、これを delivered の根拠にしない
  - 入力の一覧(パスと sha256)を PR のコメントへ残す: 一覧は既定ブランチの版から作るため PR の内容に依らないが、書き込みの権限を持つ者が編集・削除できる(ADR-0124 決定2 がラベルを退けた理由と同じ)。採らない
  - 抜き取りの周期を短くする: H.12 の改めで、本件の範囲を超える。採らない

### 採用者への影響

- 表示は変わらない。公開のリポジトリの採用者には、確認が済むまで、抜き取りの母集団から欠けうる期間を抜き取りの記録に書くよう注記で案内する(反対に同意)

## 範囲外: `auto` の権限のモードのもとでの ask

- 確認(ask)を拒否にも人の確認にも数えない。IMPL-0199 の注記に掛かる。H-2 の推す案(フックの遮断と deny への引き上げ)はこの前提で組んだ。起票はせず、既存の open Issue へ申し送る
