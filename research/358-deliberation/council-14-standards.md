## 0. 全議題に掛かる前提

- **版と移行**: `src/data/edition.yaml` は `edition: null` で、本標準は第1版を発行していない。ADR-0083 決定1 により、作業中の版は適合の主張にも逸脱を伴う適合の主張にも名指せない。したがって本件の条項の改めは、どれも**既存の適合の主張を失わせない**。経過措置(移行期間・旧規定の併存)は要らず、置かない。要求事項を変える改めであるため、第1版の発行の後に同じ改めをするなら N を上げる対象になる、とだけ記録する
- **適用の表明への影響**: 作業中の版への適用の表明(配布物のコミットつき)をした採用者は、次の配布物で条項が変わる。各議題の「採用者への影響」に、表明の後に何が変わるかを書く
- **マークの意味**: `delivered` は「準拠テンプレートへ降りた」。採用者はこれを「準拠テンプレートを使えば当該の規定の手段がある」と読む。マークは**規定の単位**で付ける。1つの規定のうち手段がある部分と無い部分があるなら、条項の文で部分を分けてからマークを分ける。条項が分かれていないままマークだけを分けると、マークがどの文を指すかが判定できない
- **「拒否」の語**: 5.8.6 は「拒否」を定義していない。権限設定の確認(ask)は人へ戻すか、`auto` のもとでは分類器が許す(範囲外の論点)。いずれも「実行しないで終える」ではない。H-2 で定義を足す

## H-2 5.8.6 要求事項3「書き込みはタスクの対象のパスに限る」と隔離

### 推す案

- **要求事項3 を改める(安全の論点)**。現在の文は、(i) 作業中のタスクを誰が実行環境へ伝えるか、(ii) タスクの外の書き込み(仕様・計画・記録の起案、`Spec: setup`)の範囲、のいずれも定めず、shall の対象が判定できない。`survey-external.md` §2.1 [確認] では、読んだ提供者のどれもタスクの単位の許可パスを持たない。NIST SP 800-53 AC-6 と OWASP LLM06 [確認] は「任務に必要な範囲」と「許可の判断をエージェントの外で強制する」を求めるが、粒度を定めない。本標準が粒度を定めるなら、範囲を決める者まで書かなければ要求事項6 と組にならない
- 改め方の核は「**範囲は人が確定したものから導く。エージェントは人が確定した範囲の中で狭めることだけをしてよい**」である。担い手がタスクの印を置いて範囲を選ぶ形(起案の D-2)は、選べる範囲が人の確定した集合の中に限られ、広げる操作を持たないなら要求事項6 に当たらない。この区別を条文に書けば、起案と反対の対立は条文の上で解ける
- 「拒否」を定義する。確認(ask)を拒否に数えない

### 採らない案と理由

| 案 | 採らない理由 |
| --- | --- |
| 文言を据え置き、guard-write の実装で読みを決める | 読みが実装に依り、採用者ごとに適合の判定が割れる |
| 「作業ディレクトリに限る」へ緩める | 作業ディレクトリは強制層の置き場を含む。要求事項6 の担保を条文から落とす |
| タスク単位の限定を要求事項から外し、要求事項10 の差の検出だけにする | 事後の検出は要求事項1 の「実行時に拒否」を満たさない。人が確定した計画の和で実行時に限ることはできる |
| 隔離(sandbox)を delivered にする | ネイティブの Windows で隔離しない、Edit・Write・MCP は隔離の外(`survey.md` P1)。効かない環境の採用者に担保があると読ませる |

### 条項の文言の案(要求事項3 を置き換え、定義を表の後に足す)

> 3 | 書き込みとネットワークは既定を拒否とし、許可する範囲を列挙する。書き込みの許可は、(a) 人が確定した実装計画の対象のパスと、(b) 計画の外の作業の置き場として案件が構成に列挙したパス、に限る。(b) の一覧は版管理下の実行環境の設定に置き、変更は要求事項6 による。実行環境は、作業中のタスクが特定できる場合に、許可を当該のタスクの対象のパスへ狭めてよい。エージェントの操作は許可を狭めることだけができ、広げてはならない。ネットワークの許可は必要な宛先に限る。コマンドの実行は許可リストによる

> 本節の「拒否」は、操作を実行せずに終えることをいう。人または分類器の応答を待って実行を許す設定(確認)は、拒否に数えない。

- 判定できるか: (a)(b) の和はファイルで列挙でき、許可の外の書き込みが止まるかは試験で確かめられる。「狭めることだけ」は、印の操作が許可の集合の部分集合しか作らないことを試験で確かめられる
- 「人が確定した実装計画」は既存の語(G-4 を経て既定ブランチにある計画)で、新しい語を作らない

### テンプレートへ降ろすもの

- guard-write に、(a)(b) の和の外への Edit・Write・NotebookEdit を遮断する機能を足す。タスクの印は狭める向きだけ
- 秘匿情報の経路の読み取りを ask から deny へ上げる(要求事項1 の接触の一部。要求事項4 は満たさない旨を注記)
- sandbox の設定(`filesystem.denyWrite` に強制層、`network.allowedDomains`)は、効く基盤を注記に書いた**例**として置く
- `denyInsteadOfPrompting`(確認を拒否へ変える)は利用者または管理の設定だけで効く(`survey-external.md` §2.1 [確認])。案件の設定に置けないため、採用者への案内に回す

## H-3 IMPL-0491(git merge と push の組による既定ブランチ以外への取り込み)

### 推す案

- **マークの主題を改める**。現在の IMPL-0491 は `target=guard-bash-hook` で「AI の担い手の拒否」を主題にしている。しかし gate-criteria の本文は「本標準は、既定ブランチ以外へ取り込むマージを拒否する設定を課しません」と書き、ADR-0124 決定4 も拒否を課さない。**本文が課していない拒否を、降りていない規定として表示している**。これは ADR-0084 決定4 の降ろす順序の第1段「表示の誤り」に当たる
- 本文が課すのは禁止(取り込み先が既定ブランチになるマージだけを行う)であり、AI の担い手へこの禁止を届ける手段は指示文の行しかない。0208・0257 と同じ型で、`claude-md-resident` delivered presence(単位: 行)が事実どおりの表示になる
- 識別子は再利用しない規則のため、0491 の番号を保ったまま target と注記を改める(台帳の追跡を切らない)

### 採らない案と理由

| 案 | 採らない理由 |
| --- | --- |
| undelivered `plan=scheduled` のまま | 降ろす手段の見込みが無い(ADR-0084 決定4・ADR-0124 決定4) |
| `plan=adopter` | 採用者にも拒否の手段が無い。ホスティングのルールセットは push とマージを区別しない(ADR-0124 決定4)。資格情報の範囲で push を1本に限る形(`survey-external.md` §4 [確認])は手動のスタックの運用を止めるため、拒否の手段とは言えない |
| 行に `[機械]` を付ける | ADR-0124 決定4 の開示(`git merge`+`git push` は降りていない)と矛盾する |

### 条項の文言の案(gate-criteria の「課しません」の段落の末尾に足す)

> AI の担い手には、この禁止を指示ファイルの規則として届けます。指示ファイルは遵守を保証しません(第3章 3.11.3)。`git merge` と `git push` の組による取り込みは、実行時にもマージの後の検出(PR を経ないため)にも掛かりません。

- 新しい要求ではなく、既存の限界の開示を本文へ上げるもの。注記だけの開示は台帳の読み手にしか届かない
- 採用者への影響: 義務の変化は無い。台帳の降りていない件数が1件減り、限界の開示が本文に載る

## H-4 生成の条件の自動の記録(IMPL-0207)

### 推す案

- **SessionStart の観測の記録**(`session_id`、開始の時点の HEAD、指示資産のハッシュ、未コミットの変更の有無)を採る。5.8.2 は「観測できる事実」「導出元から自動で記録」を求めており、履歴からの導出(e2)は観測ではない近似のため採らない
- **コミットへの結びつけは `updatedInput` によらない**。確認の画面に出たコマンドと実行されるコマンドが食い違う形は、人の確認の対象を実行の直前に変えることで、5.8.6 の確認の考え方と相容れない。代わりの候補は git の `commit-msg` フックが SessionStart の記録からトレーラを足す形(`survey-external.md` §3 [確認]: commit-msg フックはメッセージのファイルを書き換えられる)。コマンドは変えず、結果はコミットに残り誰でも読める。同じ作業ツリーで複数のセッションが動く場合は、推測で1つを選ばず「特定できない」と書く。この形も実機で確かめていない
- 置き場: 結びつけ(トレーラ)は版管理に入る。SessionStart の記録そのものは端末ごとのファイル(`.gitignore`)。識別子は不透明な値だけを書き、URL を書かない(非公開のセッションの所在が公開の履歴へ出る問題。`survey-external.md` §3 は苦情を [未確認] とするため根拠にはせず、設計上の予防として置く)

### 条項の文言の案(5.8.2 の「指示資産の版」の行の「記録する内容」を改める)

> 参照した恒久層コンテキストと指示ファイルのコミット、およびコミットに無い変更の有無。リポジトリの外の指示(利用者の範囲の指示ファイル)は、版を記録できない旨を示す

- 現在の「コミット」だけでは、未コミットの変更と利用者の範囲の指示が欠ける。欠けを書かせないと、記録が条件を特定したように読まれる。観測できる事実の追加で、判断は含まない
- 実行の識別子の**引き当て先(実行の記録)の保持**は、今回は課さない。5.8.2 は鍵の記録までを求めている。保持の期間を支える実証が無く、提供者の基盤ごとに異なる。「課さない」と ADR に明記し、注記で「識別子の記録は引き当て先の保持を保証しない」を開示する

### マークの扱い(IMPL-0207 を分ける)

- Claude Code の実行の識別子と指示資産の版: undelivered `plan=scheduled`(実機の確認まで)。確かめた後は、トレーラの有無を `pr-rules` が確かめる試験で delivered machine。注記: 値が真の実行を指すかは確かめない
- Claude Code 以外の基盤: undelivered `plan=adopter`。理由: 識別子の取り出し方が基盤ごとに異なる(ADR-0084 決定4 の IMPL-0279 と同じ型)
- 採用者への影響: 文言の改めで、未コミットの変更の有無を記録する欄が増える。自動で記録するため、人の作業は増えない。手作業で記録している採用者には欄が1つ増える

## H-5 IMPL-0198 の check と要求事項6

### 推す案

- **0198 を3つに分ける**。現在の1つのマークは、要求事項5(拒否の記録)、強制層への書き込みの遮断、要求事項6(許可範囲の変更をさせない)の3つの規定を束ねている。規定の単位でマークを付ける原則に反する
- 要求事項5 と、Edit 系の道具による強制層の遮断は、`test-guard-write.mjs` の対と `settings.json` の結線の場面を条件に delivered machine
- **要求事項6 は delivered にしない**。要求事項6 の最後の文は「この条件を満たさない実行基盤では、要求事項1 の拒否は成立しない」で、Bash の経路(リダイレクト・`node -e`)が開いている限り条件を満たしていない。反対委員の「delivered manual」は、満たしていない規定を降りたと表示することになる。正しい表示は undelivered で、Bash の経路は H-2 と同じく、隔離の効く基盤では `filesystem.denyWrite` に強制層を置く形を `plan=scheduled`(実機の確認まで)、ネイティブの Windows は `plan=adopter`

採らない案と理由:

- 1つの machine とする案: 試験が確かめない Bash の経路まで機械の担保があると読ませる
- 要求事項6 を delivered manual とする案: manual は「降りたが機械で確かめない」の意味で、降りていない部分の表示に使えない

### 条項の文言・採用者への影響

- 改めない。要求事項6 の文は判定できる(エージェントの操作で許可範囲が変わるかを、経路ごとに試せる)
- 台帳で要求事項6 が降りていないと表示される。採用者は自らの基盤で要求事項6 を満たしたかを、隔離の設定で確かめる必要が明らかになる

## H-6 CLAUDE.md の行数と 3.11.3 の文言

### (a) 相殺の条件

- **相殺を条件にしない**。3.11.4 要求事項1 の上限は組織が定める値で、参考の値 200 行は 1.7.7 により記録が無ければ効かない。準拠テンプレートが自らに 200 行を課すことは、参考の値を上限として扱うことで、ADR-0084(IMPL-0222・0312 は adopter)と食い違う
- 代わりに、H-1 (a) の総分量の検査がテンプレートの出荷の時点の行数を出す。採用者が上限を記録したときに超過が見える
- 採用者への影響: 参考の値の 200 行をそのまま上限に記録した採用者は、テンプレートの取り込みの直後から総分量の検査で落ちる。`/process-init` で上限を記録するときに現在の行数を並べて出すことを、テンプレートへの申し送りとする。行数と遵守の関係に実証が無いことは EV-0088 が既に開示している

### (b) 3.11.3 との食い違い

- **食い違う**。3.11.3 の「遵守が必須の規則を誘導層に書いてはなりません」は、文字どおりには書くこと自体を禁じる。準拠テンプレートの CLAUDE.md は、強制の手段の無い禁止(5.8.5 の禁止事項、本件の 0208・0257・0282・0491 の行)を書いている。一方、5.8.6 要求事項2 は「指示ファイルにだけ書いた範囲は、拒否できたものとして扱わない」と書き、こちらが本標準の意図(同節の caution「必ず守られるという前提で統制を設計してはなりません」)に合う
- 用語の欠け: 「遵守が必須の規則」は定義が無い。同じ節の表は強制層の対象を「違反を許容できない規則」と書く。語をそろえる

条項の文言の案(3.11.3 の太字の文を置き換える):
> **違反を許容できない規則を、誘導層だけに置いてはなりません**。違反を許容できない規則は、強制層へ降ろします。強制層へ降ろす手段の無い規則は、誘導層に書いてよいものとします。その場合は、規則ごとに、機械で止まらないことを示します。誘導層に書いたことを、規則が守られた根拠として扱ってはなりません。

- 判定できるか: 規則ごとの印(テンプレートでは `[機械]` の有無)の有無を読めば決まる。最後の文は記録の文を読めば決まる
- 採らない案: 「誘導層に書いてはならない」を据え置き、注記で読み替える案。注記の読みは台帳の読み手にしか届かず、条文と準拠テンプレートが食い違ったままになる
- 採用者への影響: 印を付ける義務が増える(機械で止まらない規則の明示)。準拠テンプレートは既に付けている。現在の文に文字どおり適合する採用者は、指示ファイルに禁止を1つも書かない者だけで、実在を想定しにくい

## H-7 IMPL-0492(入力の記録の保持)

規格の側の発見:
- **マークが指す規定の文が、本文に無い**。IMPL-0492 の注記は「四半期の抜き取りまで残すこと」と書くが、H.4 の本文にこの文は無い。H.4 の条件5 は「直近の四半期の記録から抜き取り」を求めるので、保持は論理の帰結ではあるが、shall の対象が条文に無いマークは、何を満たせば降りたかが判定できない
- 附属書H(1010 行)は「記録の保管期間を定める。本標準は定めない。自組織の文書管理規程による」とする。保持の**期間**の値を本標準が定めないことと、**確認の時点まで取り出せること**を求めることは両立する

### 条項の文言の案(H.4「確認側へ渡した入力の記録」の末尾に足す)

> 入力の記録は、条件2〜5 の確認(四半期の棚卸し)の時点まで、取り出せる状態で残さなければなりません。実行の基盤の保持の既定に頼ってはなりません。保管期間の値は組織が定めます(H.9 の問11)。

- 後半の「頼ってはなりません」は ADR-0124 決定5 の「実行の記録の保持の既定に頼らない」を条文へ上げるもの

### 推す案(表示と確認の項目)

- 実機の確認まで undelivered `plan=scheduled`。`review=` は確認の予定に合わせて改める
- 確認の項目: (1) 成果物の取得を PR の先頭の SHA と一致する `ai-review` の実行に限る、(2) バイト列のまま写し、写した側で sha256 を照らす、(3) 写した内容を実行しない、(4) `actions: read` を足すことの陰性の確認(3b)を記録する、(5) 成果物が無い・照合が合わない場合は写さずに「入力の記録なし」を記録する(欠けを消さない)、(6) **抜き取りの時点で記録用ブランチから取り出せることを試す**(写せたことと取り出せることは別)、(7) マージされずに閉じた PR が抜き取りの母集団に入るかを H.12 と突き合わせてから確認する

### 採らない案と理由

| 案 | 採らない理由 |
| --- | --- |
| リポジトリの公開・非公開で分け、非公開は保持の設定(400 日まで)を採用者に委ねる | 保持の設定は設定の上限と組織の設定に依り、案件から確かめにくい。運ぶ形は公開・非公開のどちらでも同じ手段で成り立つので、分ける利点が無い |
| マージの時点で入力の記録を作り直す | 別の時点の値で、観測した入力ではない(反対委員と同じ) |
| 抜き取りの周期を短くする | H.12 の改めで、本件の範囲を超える |

### 採用者への影響

- 条文に保持の要求が載ることで、自ら AI レビューを差し込んでいる採用者に「確認の時点まで取り出せること」の確認が要る。現在もマークの注記で同じことを求めていたが、条文に無いため適合の判定に使えなかった。新しい義務の種類ではなく、既存の条件5 の前提の明文化である

## 範囲外: `auto` のもとでの ask

- H-2 の「拒否」の定義は、ask を拒否に数えないことを条文で定める。これで IMPL-0199 の注記の読み(確認つきに置く)が拒否の担保ではないことが条文の上で決まる。IMPL-0199 の注記に「確認は拒否に数えない(5.8.6 の定義)。`auto` のもとでは人の確認でもない」を足すことを、本件の実装で行ってよい。起票はしない
