### B 指示資産の保守(3.11.3〜3.11.5)

- IMPL-0221(3.11.3)「遵守が必須の規則を誘導層に書いてはならない」。CLAUDE.md は規則ごとに `[機械]` の印を付けるが、規則を足す側(起案する AI と AI維持管理者)への禁止を置いていない
- IMPL-0223(3.11.4 要求事項2)追記は「同種の誤りが2回以上発生した、またはレビューで指摘された」場合に限る。回数は既定値(1.7.7)
- IMPL-0224(要求事項5)ディレクトリ構成・依存一覧・自動生成できる概要を指示資産に書かない
- IMPL-0227(3.11.5)次の4つを1つのマークに束ねている
  1. 指示資産の変更に、所有者定義による AI維持管理者のレビューを必須とする
  2. 変更時に機械検査する。検査項目は「総分量が上限内か」「既存の記述と矛盾しないか」「コードベースから導出できる内容でないか」の3点
  3. 個人の作業環境に固有の指示を版管理から除外する
- 関連する既存の決定
  - ADR-0084: 分量の上限(IMPL-0222・IMPL-0312)は降ろさない。値を支える実証が無く、採用者が値を定める(plan=adopter)
  - ADR-0087(#317): CODEOWNERS の雛形の役割の行を AI維持管理者へ割り当てた。行はコメントのまま(`@ai-maintainer` は置き字)。雛形の注記「雛形の行を有効にする道具の側の扱いは #358 で検討中」
  - #54: `/process-init` は `.github/CODEOWNERS` を書き換えない。記録の置き場の所有者は、PROCESS-PROFILE.md に「CODEOWNERS の案」として席の責任者のアカウントから起こし、人が写す(`codeownersProposal`)
  - ルールセット: `team.json` は `require_code_owner_review: false`、`regulated.json`・`safety.json` は `true`
  - 統制の設定(`CONTROL_FILES`。gate-g5-base が AI維持管理者本人の承認を要する)は強制層の置き場で、CLAUDE.md・`.claude/skills/` を含まない。ADR-0073 の陰性の確認は統制の設定に掛かる規定で、誘導層の変更に陰性の確認の記録を求める条項は無い
- 3.11.5 の機械検査の3点の判定可能性
  - 総分量: 数えられる。上限の値は組織が定める(ADR-0084)。値が無ければ判定できない
  - 既存の記述との矛盾: 自然言語の規則どうしの矛盾を決定的に判定する手続は無い。常駐の規則の検査(`claude-md-resident.mjs`)は規則の欠落を検出するが、矛盾は検出しない
  - コードベースから導出できる内容: 一般には判定できない。ディレクトリの木の図(`├──`)・依存の一覧(パッケージ名と版の列)のような形は検出できるが、検出しなかったことは「導出できる内容でない」ことを示さない
- 個人の作業環境に固有の指示: Claude Code の個人用ファイルは `CLAUDE.local.md` と `.claude/settings.local.json`(提供者の文書の確認は §3)。テンプレートの `.gitignore` はどちらも無視しない

### C 外部ツールの統治(3.11.6)

- テンプレートは `.mcp.json` を置かない。権限設定は MCP の道具の許可・拒否を持たない
- `graft` は MCP サーバーを登録する(`graft init`)ため、CLAUDE.md は `graft init` を実行しないことを定める
- 統制の設定(`CONTROL_FILES`)にも CODEOWNERS の雛形にも `.mcp.json` は無い。`.mcp.json` を足す PR は、AI維持管理者の承認を経ずに入る

### D 実行環境の拒否の既定(5.8.6 要求事項3・4)

- `.claude/settings.json` は `allow` にコマンドの許可リストを置き、`deny` に保管領域の読み取り・graft の送信の形・ホスティングへの書き込みを置き、`ask` に秘匿情報の経路の読み取りと強制層の編集を置く
- 書き込み: Edit・Write の既定は確認(提供者の文書の確認は §3)。拒否ではない。強制層は guard-write のフックが遮断する(IMPL-0198)。タスクの対象のパスに限る仕組みは無い
- ネットワーク: `wget` は確認、`curl` と `WebFetch` は限っていない
- 秘匿情報: `.env` 等の読み取りを確認に置く(IMPL-0199)。5.8.6 要求事項4 は「読み取りの制限だけに頼ってはならない。参照できない位置へ置く」を求めるため、確認に置くことは要求事項4 を満たさない
- フェーズ5 `agent-trace-control.md` は「書き込みの範囲とネットワークの既定の拒否は、まだ降りていない」と開示している
- 要求事項3 の「書き込みの許可は実装計画のタスクの対象のパスに限る」は、作業中のタスクと、その対象のパスを、書き込みの時点で実行環境が知ることを要する。テンプレートの実装計画には「変更の対象パス」の列があり(IMPL-0205 が読む)、`self-heal.mjs start --spec --task` は自己修正の間だけタスクを知る。タスクの外の作業(仕様・計画・記録の起案、`Spec: setup` の変更)の書き込みの範囲は計画に無い

### E 生成の条件の自動の記録(5.8.2)

- 項目: モデルの識別子と版(Co-Authored-By。IMPL-0176・0177)、指示資産の版(参照した恒久層コンテキストと指示ファイルのコミット)、実行の識別子
- 出荷の集約は、出荷の範囲の指示資産の最終変更のコミットを出す(IMPL-0178)。成果物ごとの対応は無い
- 降ろし先 `agent-run-record`(`scripts/gate/agent-run-record.mjs`)は `kind: planned` で実体が無い

### F 入力の記録の保持(H.4。IMPL-0492)

- `ai-review.yml` は入力の記録(inputs.json)を成果物へ上げ、`retention-days: 90` を指定する。注記は「四半期の抜き取りまで残ることは、この手順では保証しない」
- 抜き取りは四半期ごと(3.11.4 要求事項4・H.12)。四半期の初めの実行は、四半期の終わりの抜き取りの時点で最大で約 92 日を経る。90 日の保持では、抜き取りの時点で消えている実行がありうる
- 記録用ブランチ(`records`)へ写す経路は `record-copy.yml` にある(マージを契機に承認レビューの写しを置く。`contents: write`、pull_request_target で既定ブランチの定義を動かす)。AI レビューのジョブは read の権限だけで、記録用ブランチへ書けない
- 記録用ブランチへ運ぶには、`record-copy.yml` が別のワークフローの実行の成果物を読む(`actions: read` の権限)手順を足すことになる。書き込みの権限を持つワークフローへの変更で、実機の確認(GitHub Actions)が要る

### G 書き込みの遮断のフックの試験(IMPL-0187・0198)

- `.claude/hooks/guard-write.mjs` に試験が無い。`test-guard-bash.mjs` は guard-bash を試験し、gate-g5.yml の contract ジョブから実行される
- フックは自身の位置からリポジトリの根を決め(`ROOT`)、`.claude/guard.json` を読む。テンプレートの `guard.json` の `protectedPatterns` は空で、構成の生成(`generate-profile.mjs`)が強制層のパターンを書く。試験は、生成が書く形の guard.json を一時の置き場に置く必要がある

§1 への帰結:

- D: 書き込みの既定の拒否は、権限設定では「確認」にしかならない(P2)。隔離の書き込みの制限はシェルだけに掛かり、Edit・Write に掛からない(P1)。タスクの対象のパスに限る拒否は、リポジトリの設定だけでは作れない。ネットワークの既定の拒否は、隔離の許可する宛先の一覧で近づけるが、ネイティブの Windows では効かず、WebFetch・MCP は隔離の外(P1・P2)。秘匿情報を参照できない位置へ置くことは、リポジトリの外の配置の問題
- E: 実行の識別子は、文書の上ではフックの入力の `session_id` で取れる(P3)。コミットへ結びつけるには、`git commit` を検出して入力を書き換えるか、記録を別に書く実装が要る。いずれも実機で確かめていない
- F: 公開のリポジトリでは 90 日を超えて成果物を保てない(P6)。四半期の抜き取りまで残すには、成果物の外(記録用ブランチ等)へ運ぶしかない
- B・C: 個人用のファイルの除外は `.gitignore` で置ける(P5)。外部ツールの一覧は `.mcp.json` に置けるが、利用者の範囲のサーバーは案件で止められない(P4)
