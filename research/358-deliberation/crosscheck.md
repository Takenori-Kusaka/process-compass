### X-1(中)guard-write は、NTFS の短い名前と既定のストリームの名前を通す

- 所在: `template/.claude/hooks/guard-write.mjs` の照合(`rel` の算出と `globToRegExp`)、IMPL-0198 の注記
- 事実: ネイティブの Windows(NTFS)の一時の置き場で、フックを Write の入力で起動し、同じパスへ Node の `fs.writeFileSync` で書いた。`.claude/SETTIN~1.JSO`(8.3 の短い名前)と `.claude/settings.json::$DATA`(既定のデータストリーム)は、フックが終了コード 0 で通し、実際に `.claude/settings.json` の中身を書き換えた。大文字と小文字を変えた形は直っている(終了コード 2)。H-2 は「NTFS・APFS は区別しないため強制層の遮断を通りうる」を理由に大文字と小文字を直したが、同じ「別の綴りが同じファイルを指す」類の経路が残る。IMPL-0198 の注記は「照合は大文字と小文字を区別しない(NTFS・APFS で同じファイルを指すため)」とだけ書き、残る経路を開示していない
- 直し方の案: 照合の前にパスを正規化する。`::$DATA` など `:` 以降のストリームの指定を落とす(または `:` を含むパスを拒否する)。対象が既にあれば `fs.realpathSync.native` で長い名前へ解決し、無ければ親のディレクトリを解決してから照合する。`~` と数字を含む成分を拒否する形でもよい。試験に両方の場面を足す。直さない場合は、IMPL-0198 の注記にこの2つの経路を開示する

- 事実: README の「記録用ブランチの初期化」によると、`record-copy.yml` の初期コミットが止まるのは `records-signed.json` を適用した後に限る。適用の前に最初のマージを通す方法(方法1)では、record-copy がブランチを作る。案内の「GITHUB_TOKEN では作れないため、最初のマージの前に作らないと承認レビューの写しが作られず」と、README・第5章の「ブランチが無いまま最初のマージを通すと、写しが作られず…止まります」は、この条件を落としている。案内は同じ文の括弧で方法1を挙げており、文の中で食い違う。初期化の後に失敗した実行を再実行すれば写しが置かれることも書かれていない。案内の参照先の見出し(「記録用ブランチの初期化」)は実在する。案内の出る条件(規制業か CL2 以上で、ローカル・origin のどちらにも records が無い)は `recordsSignatureRequired` と一致する
- 直し方: 3か所の文を「`records-signed.json` を適用した後に、ブランチが無いまま最初のマージを通すと」と条件を付けて書く。案内に「止まった実行は、初期化の後に再実行する」を足す

### Y-4(低)X-7 の一時の置き場の削除が効いていない

- 所在: `template/scripts/gate/test-guard-write.mjs` の `TMP_DIRS`・`sandbox`
- 事実: `TMP_DIRS` は宣言と最後の削除のループにだけ現れ、`sandbox` は作った置き場を `TMP_DIRS` へ入れない。試験を1回流すと、`%LOCALAPPDATA%\Temp\guard-write-*` が 50 件から 55 件に増えた。裁定 X-7 の「一時の置き場は、試験の最後に消す」が満たされていない
- 直し方: `sandbox` で `TMP_DIRS.push(dir)` する。途中で例外が出ても消えるよう `try/finally` か `process.on('exit')` で消す

### Y-5(低)別の綴りの拒否が、強制層でない置き場まで止める

- 所在: `guard-write.mjs` の「0.」の節(保護の型の最初の成分を集めて `roots` にする)と `normalizeTarget` の `:` の扱い
- 事実: `roots` は `.claude`・`.github`・`scripts`・`adapters`・`records` になる。そのため、解けない成分に `~` と数字があるパスは、保護の型に当たらなくても止まる。手元で `scripts/build~2.mjs` と `.claude/skills/v~2/SKILL.md` が終了コード 2 になり、「強制層の下を指すパス」と出た(`scripts/build.mjs` と `.claude/skills/` は試験で通す側に置かれている)。裁定・ADR-0126・IMPL-0198 は「強制層の置き場の下」で拒否するとしており、それより広い。また `:` を除く処理は Windows に限らず走る。POSIX では `:` は正当な名前の文字なので、たとえば Linux の `records/gates/a:b.md` が止まる。IMPL-0198 は「NTFS の代替データストリームの記法」と書いている
- 直し方: 疑わしい成分を任意の1成分として、保護・追記だけの型のどれかに当たりうるときだけ拒否する。`:` の除去と拒否は `process.platform === 'win32'` に限る。通す側の試験に `scripts/build~2.mjs` を足す

### Y-6(低)正規化の分割と末尾のドットの注記が、実際の動きと合わない

- 所在: `normalizeTarget`(`rest.split(/[\/]+/)`、注記「Windows は末尾のドットと空白を落とす」)、試験「末尾のドットでも遮断」
- 事実: 分割の正規表現は `/` だけを区切りにする。Windows では `path.resolve` が `\` の区切りを返すので、成分ごとの処理はされず、残り全体が1成分として扱われる(結果としてストリームの除去は最後の成分に効いている)。末尾のドットについては、`bypass.mjs` で Node の `fs.writeFileSync` が `.claude/settings.json.` を別のファイルとして作った(`dir /x` に別の項目として出る。本体は書き換わらない)。`.claude./settings.json` は ENOENT で書けない。つまり、この環境の Node では末尾のドットは同じファイルを指す綴りではない。フックが止めるのは安全側の誤りで実害は小さいが、注記と試験の名前が誤った事実を固定している
- 直し方: 区切りを `/[\/]+/` にする。末尾のドットの注記を「Win32 の API の正規化に頼る道具に備えた安全側の拒否」と事実に合わせるか、処理と試験を外す

### Y-7(低)EV-0252 の書式と ADR-0126 の記録が欠ける

- 所在: `ci-gates.md` 665〜673 行の EV-0252、ADR-0126 の「番号」の行と「落ちうる検査と直し方」の表
- 事実: 書式(`community/evidence-marking.md`)は、対象・根拠の水準・差し替え条件の3項目を連続した行に置き、補足は空行を挟んで後に書くと定める。EV-0252 は補足の段落を根拠の水準と差し替え条件の間に置いている。台帳(`evidence-ledger.md`)は差し替え条件を正しく取り込んでおり、`lint:evidence` も通る。同じ配置の EV は既存の 242 件のうち 20 件ある(多くは ADR)。識別子は未使用の連番で、見直しの期限・根拠の水準の呼称・各項目の句点は正しい。このほか、ADR-0126 の「番号」の行が EV-0252 を挙げていない。X-9 で足した失敗(上限の値が正の整数でない)が「落ちうる検査と直し方」の表に無い
- 直し方: 補足の段落を差し替え条件の後へ移す。ADR-0126 の番号の行に EV-0252 を足し、表に `pr-rules` の行(「上限の値が正の整数でない」→「`.claude/guard.json` の値を正の整数か null に直す。強制層の変更」)を足す
