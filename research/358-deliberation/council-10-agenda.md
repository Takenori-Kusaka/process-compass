## 2. 議題

### H-1: 3.11.5「変更時に機械検査する」の3点(S-1)

- 事実: 総分量は数えられる(値は組織)。「既存の記述と矛盾しないか」「コードベースから導出できる内容でないか」は、決定的に判定する手続が無い(survey.md §1 B)。2委員とも条項を改めるべきとした
- 問い: (a) 条項を改めるか。改めるなら文言の案(機械検査と人の確認の分け方、AI の確認を使ってよいか、その記録の位置づけ。ADR-0012・附属書H H.4 との関係)。(b) IMPL-0227 の分け方と各マークの state・check

### H-2: 5.8.6 要求事項3「書き込みはタスクの対象のパスに限る」と隔離(S-2・S-3)

- 事実: 権限設定では Edit・Write の既定は確認で、拒否にならない。隔離はシェルだけ。タスクの外の作業(仕様・計画・記録の起案、`Spec: setup`)の書き込みの範囲は計画に無い。担い手がタスクを宣言して範囲を開くなら、要求事項6(許可範囲の変更を担い手にさせない)に触れうる
- 起案の案: guard-write が既定ブランチの先端の実装計画の対象パスで書き込みを限る。シェルとネットワークは sandbox で扱い、限界を開示する
- 反対の案: 要求事項3 は定義が欠けており、改める(安全の論点)。sandbox を delivered にしない
- 問い: (a) 要求事項3 を改めるか。改めるなら文言(タスクの外の範囲、範囲を開く者)。(b) テンプレートへ何を降ろすか(guard-write による限定、sandbox、秘匿情報の読み取りを deny へ上げる)。(c) IMPL-0200 の分け方と各マークの state

### H-3: IMPL-0491(git merge と push の組による既定ブランチ以外への取り込み)(S-4)

- 事実: ADR-0124 決定4 は拒否の設定を課さない。フックは既定ブランチからの同期と区別できず止めない。CLAUDE.md にこの禁止の行は無い
- 問い: 指示文の行で `delivered`(機械の担保なし)と表示するか、undelivered のまま残すか(その場合の plan。ADR-0084 決定4)、条項・マークの主題を改めるか

### H-4: 生成の条件の自動の記録(IMPL-0207)(S-5)

- 起案: SessionStart で記録し、`git commit` に `updatedInput` でトレーラ(Agent-Run・Agent-Context)を足す
- 反対: `updatedInput` で書き換えない(確認の画面と実際のコマンドが食い違う)。SessionStart の観測の記録に限る。履歴からの導出は近似で採らない
- 問い: どの形を降ろすか、実機で確かめていない間の表示、Claude Code 以外の基盤の扱い、記録の置き場(版管理に入るか)

### H-5: IMPL-0198 の check と要求事項6(S-6)

- 事実: 試験(`test-guard-write.mjs`、37 場面)は Edit・Write・NotebookEdit の遮断と記録を確かめる。Bash からの書き込みは遮断しない(フックの限界の注記)
- 問い: 0198 を1つの machine とするか、分けるか

### H-6: CLAUDE.md の行数と 3.11.3 の文言(S-7・S-8)

- 問い: (a) 足す行を相殺する条件を置くか。(b) 3.11.3「遵守が必須の規則を誘導層に書いてはならない」と、強制の手段が無い禁止を指示文の行で置くこと(テンプレートの CLAUDE.md の多数の行)は食い違うか。食い違うなら文言の案
