1. 2委員がそろって条項の改廃(S-1)を求めた。受付で「条項を改める案が出て割れたら重」とした論点で、改める向きでは一致したが、改め方は審議していない
2. 反対委員が 5.8.6 要求事項3 の改廃(S-2)を安全の論点として求め、起案と割れた。安全は重の対象である
3. S-3〜S-8 で結論が割れた

重の審議は、外部の調査(`survey-external.md`)→ 5 委員の会議体(`council-10-agenda.md`、`council-11`〜`15`)→ 議長の重の裁定(本ファイル「重の裁定」)の順で行う。§1 の一致は、会議体の出発点として渡す。

## 重の裁定(2026-11-12)

入力: `survey-external.md`、`council-10-agenda.md`、`council-11-drafter.md`・`council-12-field.md`・`council-13-qa-audit.md`・`council-14-standards.md`・`council-15-defender.md`。§1 の一致(L-1〜L-7)は覆さない。L-5 には現場委員の条件(graft のスキルの案内を同じ変更で改める)を付ける。

番号: ADR-0126、EV-0250・EV-0251、IMPL-0501〜0512(取り込みの際に付け直すことがある)。

### H-1 3.11.5 の機械検査(5 委員のうち4名が改めるべき。弁護は項目を残して範囲を開示する案)

**裁定: 条項を改める**。「機械検査する」の対象を、決定的に判定できるもの(総分量、形で特定できる導出内容の検出)に限り、矛盾と、形で特定できない導出内容は AI維持管理者のレビューで確かめて記録する。AI の判定は H.4 の検出の層として材料に使ってよいが、機械検査にもレビューにも数えない。検出が 0 件であることを、導出できる内容が無いことの根拠にしない。総分量の上限が未設定なら「上限未設定」と出し、通過に数えない。「所有者定義により」は手段を CODEOWNERS に限り、team の体制(require_code_owner_review が偽)で必須にならないため、「AI維持管理者本人の承認を必須とする。手段は所有者定義に限らない」へ改める。

- 弁護の案(項目を残し「形の検査」として降ろす)は採らない。矛盾の形(核の文言の否定など)を検出しても「矛盾しないか」を判定したことにならず、条項の文言どおりの主張を採用者にさせる。外す向きの変更であることは認める。代わりに、確かめる行為そのもの(レビューと記録)は残し、統制を消さない(ADR-0074 の非対称に反しない)
- IMPL-0227 を5つに分ける: 0227 承認の必須(delivered machine)、0501 総分量(delivered machine)、0502 形の検出(delivered machine。合否に使わない)、0503 矛盾・導出のレビューの記録(delivered manual)、0504 個人用のファイルの除外(delivered machine。追跡されたら G-5 を失敗させる)
- 形の検出の範囲(ディレクトリの木の図)は実測で選んでいない。EV-0250 で開示する。依存の一覧の形は、版の固定の記述(graft@0.12.1)を誤検出するため検出しない(現場委員)

### H-2 5.8.6 要求事項3 と隔離(5 委員とも、範囲を「人が確定した計画の対象パスの和」と「人が定めた計画外の置き場」に限る読みで一致。改めの要否で弁護だけが「現行の文言の内」)

**裁定: 条項を改める**。現行の文言は「タスクの対象のパス」で、担い手がどのタスクかを選べる構成では境界にならず、タスクの外の作業の範囲も定めていない。改めた文言: 書き込みの許可は、既定ブランチへ入った実装計画の対象パスの和と、強制層に列挙した計画外の置き場に限る。担い手は範囲を狭められるが広げられない。タスクごとの超過は要求事項10 の差で示す。あわせて「拒否」を「操作を実行せずに終えること」と定め、確認(ask)を拒否に数えない(規格委員)。

- テンプレートへの降ろし方: guard-write による限定は、計画の読み方(既定ブランチの版)と計画外の置き場の既定の一覧を決める実測が無く、誤った遮断で採用者がフックを外す危険がある。本件では降ろさず `undelivered plan=scheduled`(IMPL-0200)に残す。隔離(sandbox)は delivered にしない(ネイティブの Windows で効かず、Edit・Write は隔離の外)。隔離が効く基盤のシェルとネットワークは IMPL-0506(scheduled)、ネイティブの Windows のシェル・MCP・WebFetch は IMPL-0507(adopter)、要求事項4 の秘匿情報の配置は IMPL-0508(adopter)
- 秘匿情報の経路の読み取りは、構成の生成が既に deny に置く。初期化の前の権限設定も ask から deny へそろえる(IMPL-0509。delivered presence)。IMPL-0199 の注記を、deny と、`auto` のもとでは ask が人の確認でないことに改める
- 現場委員が実行で見つけた欠陥: guard-write は大文字小文字を変えたパス(`.CLAUDE/Settings.json`)を保護の型に照合しない。NTFS・APFS は区別しないため、強制層の遮断を通りうる。本件で直す(照合を大文字小文字を区別しない形に)。試験に場面を足す
- 改めた要求事項3 には実装の先例が無い(外部の調査: タスクの対象のパスに限る実装は、読んだ提供者のどれにも無い)。EV-0251 で開示する

### H-3 IMPL-0491

**裁定: マークの主題を、CLAUDE.md の禁止の行へ改める**(起案・規格)。本文は拒否の設定を課さず(ADR-0124 決定4)、PR を経ない push は検出に掛からないと既に書く。課していない拒否を `scheduled` と表示するのは ADR-0084 決定4 の表示の誤りである。`claude-md-resident` の行として delivered presence にし、`[機械]` を付けない。

- 品質監査・弁護・現場の案(マージのコミットの第2親が既定ブランチから到達できるかで検出する)は採らない。手動のスタックで上の層が下の層を取り込む正当な同期と、禁じた取り込み(上の層を下の層へ併合して push)は、同じ形のマージのコミットになる。区別できない検出は、誤検出か見逃しのどちらかを常に生む

### H-4 IMPL-0207

**裁定: `updatedInput` による書き換えと、履歴からの導出は採らない**(5 委員とも)。採る形は、SessionStart で観測した値(実行の識別子・開始の時点の HEAD・指示資産の要約値・コミットに無い変更の有無)の記録と、git のフックによるトレーラの付与。いずれも実機で確かめていないため、本件では降ろさず `undelivered plan=scheduled`(review 2027-02)。Claude Code 以外の基盤は IMPL-0511(adopter)、実行の記録(引き当て先)の保持は IMPL-0512(adopter)。5.8.2 の表の「指示資産の版」に、コミットに無い変更の有無と、利用者の範囲の指示は版を記録できない旨を足す(規格委員)。

### H-5 IMPL-0198

**裁定: 分ける**(5 委員とも)。0198 は Edit・Write・NotebookEdit による強制層への書き込みの遮断と拒否の記録に限り、delivered machine。要求事項6 のうちシェルの経路(許可範囲を Bash から変える)は IMPL-0510(undelivered scheduled)。0198 を根拠に要求事項6 の全体の適合を主張していた採用者は、主張を改める必要がある(ADR-0126 に影響として書く)。IMPL-0187 は machine。試験に、権限設定の PreToolUse の結線の場面と大文字小文字の場面を足す。

### H-6 CLAUDE.md の行数と 3.11.3

- (a) **相殺を条件にしない**(反対委員以外の5名)。参考の値を事実上の上限にすると ADR-0084(値は組織が定める)と食い違う。行数と文字数は IMPL-0501 の表示で出し続け、ADR-0126 に開示する。主題が同じ行は統合してよい(行数を理由にしない)
- (b) **3.11.3 を改める**(全員が字面の食い違いを認めた)。採る文言は規格委員の案を基に、弁護委員の条件(強制層へ降ろす義務を落とさない)を入れる: 違反を許容できない規則を誘導層だけに置いてはならない。強制層へ降ろす手段が無い規則は、機械で止まらないことを示して誘導層に書いてよく、書いたことを守られた根拠にしない。降ろす手段が無い規則は、降りていない規定として表示し続ける

### H-7 IMPL-0492

**裁定: 実機の確認まで `undelivered plan=scheduled`**(全員)。記録用ブランチへ運ぶ形を主とし、確認の項目(PR の先頭の SHA と既定ブランチの定義で走った実行に限る、再実行の成果物の選び方、バイト列のままの写しと sha256 の照合、スクリプトを実行しない、`actions: read` を足す変更の陰性の確認、マージせずに閉じた PR の扱い、取り出しの試行)を注記に書く。H.4 に保持の要求(条件の確認の時点まで取り出せる状態で残し、実行の基盤の保持の既定に頼らない。期間は組織が定める)を足す。マークの注記にしか無かった要求を本文へ上げる(規格委員)。非公開のリポジトリの保持を構成から延ばす案(現場委員)は、確認の項目を満たす代わりにならないため本件では採らない

## 独立の突合への裁定

議長の裁定(2026-11-12)。独立の突合の所見は `crosscheck.md`(X-1〜X-10)にある。

- **X-1**: 直す。guard-write は、照合の前にパスを正規化する。`::$DATA` などの代替データストリームの記法を除き、存在するパスは realpath(`fs.realpathSync.native`)で長い名前へ解く。解けないときに、`.claude` などの保護の下で 8.3 の形(`~` の後に数字)や `:` を含むパスは拒否する。`bypass.mjs`・`bypass2.mjs` の経路を ng の試験で固定する
- **X-2**: 直す。gate-criteria の 672 行(G-5 基準6)と、IMPL-0222・0312 の注記を、IMPL-0501 に合わせる。変えたファイルだけを数えることも明記する
- **X-3**: `.mcp.json` は統制の設定として承認の対象に残す。ただし、陰性の確認の記録を求める対象からは外す。止める仕組みではないので、書く中身が定まらないためである。**採らない案は「CONTROL_FILES から外す」**。外部ツールの追加が承認なしで通るようになるため採らない
- **X-4**: CR-103 の核の文言を照合する範囲を直し、「書いたことを守られた根拠にしない」の句まで照合する
- **X-5**: IMPL-0503 の注記から、内部監査に足した四半期の抜き取りの義務を外す。裁定の外である
- **X-6・X-10**: 文言を事実に合わせる
- **X-7**: test-guard-write の保護の一覧は、構成の生成が書く保護の型から取る。一時の置き場は、試験の最後に消す
- **X-8**: 照合は大文字と小文字を区別しない。下位の `.claude/skills/` と `.claude/output-styles/` も対象にする
- **X-9**: 上限の値が不正なときは、設定の誤りとして知らせる(失敗させる)
- **追加の確かめ(事実のみ。直さない)**: 指示資産の変更の承認が数える本文の編集の記録(`edited_by`)は、出荷の集約では写し(`docs/records/reviews/pr-N.json`)にしかない。写しが作られない、または `edited_by` を欠く構成の有無は、報告に書いた
