## B-4 標識の可視性と秘匿(K-1)

- 判定: **条文の第2層・第1層を結果の文へ改め、印の置き場を手引きへ移す。印を見つける者に見える場所に置く構成を選んだ採用者は、その層を「未測定」で受ける**
- 条文の直し方(案。文面は起案委員に委ねる)
  - 第2層: 注入したコミットは、機械が識別できる印(識別子と期限)を持つ。印を含む変更の、本番のブランチへの取り込みを、取り込みの前または出荷の前に機械が拒否する。標識の失われる履歴の書き換えをしない。**印がメッセージにあることは条文に書かない**
  - 第1層: ブランチ名の例(`drill/`)を条文から外し、「演習の変更は本番への取り込み先を持たない」を残す
  - 要求事項2(時期・箇所を知らせない)は動かさない
- 現場の理由
  - 現行の条文が印の置き場までを決めていることが K-1 の原因である。置き場を手引きへ移すと、条文は衝突しない
  - 小さい体制で実際に回るのは、可視の印(現行の `Seeded-Error:`)である。外の台帳と内容の指紋(案 C)は、台帳を持つ機構(CI の秘密)と登録の手間が要り、フォークの PR では秘密が渡らない。注入する者=見つける者の体制では、台帳が秘密にならない(`b-research.md` 3.2)
  - 可視の印を選ぶと、注入された PR と分かる。測定は歪むが、**歪みの代償は測定の側(未測定の開示)が払い、流出の統制(第2〜4層)は緩まない**。これが「安全を緩めず、秘匿を満たせない構成が現に在る」という現場の事実に、条項を足さずに合わせる形である
  - 3名以上で注入する者と見つける者を分けられる採用者は、外の台帳(案 C)を選べる。これは手引きの選択肢で、義務ではない
- 落とす案(各1行)
  - A 現行(印はメッセージ必須): 条文が可視を要求し、要求事項2と衝突する。K-1 の原因
  - B git notes: 既定で push されず、squash・cherry-pick で失われる(実験)。第3層の前提が崩れる
  - C 外の台帳 + 指紋を必須にする: 小さい体制で秘匿にならず、秘密の経路が要る。必須にはしない(選択肢に残す)
  - D 要求事項2を「箇所」に限る: 主張を緩める向きで、「注入された PR か」の判別が測定を歪める(TIP の問題と同型)
  - E ブランチ名を外すだけ: 第2層が残る。採るが、単独では足りない(上の直しの一部)
- 破られたとき: 印が見えて注入が識別されれば、保証の開示の読み手が測定値の信頼を失う(未測定の開示で受ける)。印が効かず流出すれば、利用者と採用者が取り消せない事故を負う(出荷の走査 IMPL-0047 が止める)
- 例外承認: 受けるのは、印の文字列を説明に含むコミットの偽の失敗だけ(ADR-0139 の裁定のとおり)
- 根拠水準: 印を人の目から隠したまま機械が拒否する先例は無い(`b-research.md` 1.2)。「可視の印 + 未測定の開示」も実証が無い。暫定マーク(採用者の走査の記録と「未測定」の件数が差し替え条件)

## B-5 7.9 の発動を何から数えるか(K-2)

- 判定: **範囲・類型で数える。制限は範囲の承認者全員に掛ける。発動と解除の判定と記録は、7.9.6 のとおり人(品質保証の機能)が行う。機械は発動も解除もしない**
- 条文の直し方(案)
  - 7.9.1: 「見逃した」の主語を、見逃した類型に対応する範囲とする
  - 7.9.2: 「検出能力の低下を検知された者」を「検出能力の低下が測定された範囲の承認者全員」へ改める。独立レビュア2名の目的は、その範囲の単独承認を数えないことで変わらない
  - 5.6.2 の識別子の禁止と整合する。7.9.6 の「機械による発動は行わない」とも整合する(7.9.6 は既に二層を書いている)
  - IMPL-0118 の制限の記録の「対象の人」は、範囲の承認者全員を指すと読む。注入の台帳と検査の出力へ人の識別子を戻さない(戻す方向を条文に明記)
- 現場の理由
  - 小さい体制では範囲と人がほぼ一致する(1〜3名)。人で数えると「誰が見逃したか」が台帳に現れ、報告の抑制と測定の隠蔽が起きる(5.6.2 の想定した逆効果)
  - 範囲全員への制限なら、誰も名指しされず、心理的に受け入れやすい
- 小さい体制で発動したあと(現場の事実)
  - 2名独立レビュアを組めない。7.9.4 の例外決裁(7.4 の手続、7.9.5 の枠1件消費)に入る。枠は補充されない(7.9.5 要求事項2)。枠が尽きれば出荷は止まる。**測定の失敗が、出荷停止に直結する**。これは条文の想定どおりで、新しい条項は足さない。ただし、注入をやめたくなる動機になる。手引きに「枠の残りと、解除に要する連続2回の検出の見込みを、発動の記録に添える」と書く(手引き。条文には義務を足さない)
  - 件数が足りず発動に達しにくいことは、条文が開示を求めている(5.6.2)
- 落とす案
  - 人で数える: 5.6.2 の識別子の禁止・措置の組み込みの禁止と衝突する
  - 二層(機械が範囲で数えて知らせ、誰を制限するかは人が決める): 「誰」を人が決めると結局個人が名指しされる。7.9.6 が既に二層を書いているので、範囲全員への制限で足りる
- 破られたとき: 数える単位が人になれば、レビューする個人が人事上の不利益を負う(最も重い)。範囲で数えて小さい体制で発動しなければ、測定の妥当性だけを失う
- 根拠水準: 閾値は EV-0064(E1)のまま。「範囲全員に掛ける」は推論。暫定マーク候補

## B-6 5.6.2 の手順の文を、結果と証跡の文に改め、手順を手引きへ移すか
