## 0. 監査から見た全体の所見

1. **A の裁定で降ろす 0047・0192 が、本件で唯一、機械が確かめる証跡を残す。** 残る規定は、証跡の形を決めないと内部監査で「やった」と「やっていない」を区別できない。「降りていない」と表示され続けること自体は正しいが、adopter に回す規定には監査の観点を付けて渡す
2. **5.6.2 は台帳と出力から識別子を外すと定める。この結果、監査は「注入した者と見つけた者が別か」を台帳から確かめられない。** 監査が確かめられる単位は、人ではなく**席(役割)と範囲・類型**である。B-1・B-3・B-5 はこの一点で整理できる
3. 流出(取り消せない)の止めは 0047・0192 の記録、測定の妥当性は blind の表示。**監査が重く見るのは、表示と実態の食い違い**(「測定値」と載るが実は秘匿が成り立たない)。これは ADR-0133 が既に守っており、本件で緩めない

## 1. 争点ごとの意見

### B-1 注入者=発見者の層を「未測定」とする要求を本文に置くか

- **意見: 採らない(新しい義務は課さない)。ただし「標準は課さず、template が推奨を実装する」を注記で開示する(第三の置き方)を採る**
- 理由(監査): 適合の主張を読む者は、標準を読む者と template の出力を読む者が同じとは限らない。template だけが強い状態(K-3)は、「標準に適合」と「template の表示」の食い違いを監査の所見にする。開示すれば食い違いは消える。条項にすると 1.10.2 の離脱と二重の扱いになり、どちらで監査してよいか迷う
- 確かめ方: 集約の層ごとの `blind` の値(決定可能。存在)。`blind` を誰がどう決めたかは自己申告である。監査は、注入者と見つけた者の**席が別か**を、体制の席の割当(ロスター)で見る。人の同一性は台帳に無いので見ない。この確かめは manual で、`check=manual` と書き、機械で閉じるとは言わない
- 破られたとき: 保証の開示の読み手が、測れていない値を測れたと読む。適合の主張の信頼に響くので、**表示の規則(blind: false を測定値にしない)は細かく書く**。ほかは書かない
- 落とす案: 条項化(新義務。重の中でも採用者に最も響き、離脱と二重になる)
- 根拠水準: 席の別による確かめが監査に足りるかは実証が無い。暫定 EV を付ける(差し替え条件は、採用者の監査記録で席の別が確かめられなかった事例)

### B-2 1.10.2 から秘匿の不成立の行を外すか

- **意見: 外さない(残す)**
- 理由(監査): 1.10.2 の表は、適合の主張が止まる条件の一覧である。内部監査の観点(附属書・内部監査)は、この表の行を点検項目にしている可能性が高い。行を外すと、点検項目が静かに消え、適合の主張が緩む向きに変わる。決定から2日で、新しい証拠も無い(`b-research.md` B-2 の記述どおり)。ADR-0133 の「再び検討する契機」にも当たらない
- 副次の確認: 行を残したまま B-1 の開示を足しても矛盾しない(離脱=主張の停止、未測定=値の扱い)。この関係を1文で示すとよい
- 落とす案: 未測定への一本化。測定の成立条件と離脱の性質の違いは理解できるが、緩める向きの変更を、実証を欠いて行う理由にならない
- 参照の突合: `npm run lint:refs` が表の行を引く節を検査するか、突合の担当が確かめる(未確認)

### B-3 注入する者を体制の外に置けることを条文に書くか

- **意見: 条文には書かない。手引き(フェーズ5)に構成の例として置く。置くなら監査の記録項目を添える**
- 理由(監査): 条文は所属を定めておらず、1.10.2 の行は「分けられない場合」に当たるので、外の者が注入すれば当たらないと読める。書くと、外部の注入者の同意・守秘・流出の経路の条件を書き始めることになる(UMN の件は、条件を欠いた外部の注入が害になる例)。細かい定義が増える
- 手引きに載せる証跡(組織の単位で、個人の識別子は含めない): 注入者の区分(体制内・体制外)、周知の範囲の記録の所在、注入の期間、流出の経路を開けていないことの確認者の席。いずれも manual
- 小さい体制の道: 例外承認では受けない(5.6.2 の免除に第7章を使うことは条文が定めていない。`b-research.md` 4 章(2))。外部の注入者を使う道は、手引きの例で足りる
- 落とす案: 条文化(上記)、「先例が無いから道を示さない」(小さい体制を締め出す。調査は先例が無いと言うだけで、害があるとは言っていない)
- 根拠水準: 小規模のソフトウェアで外部が注入する実務の先例は見つかっていない。暫定 EV。手引きなので新しい義務にならない

### B-4 K-1 標識の可視性と秘匿

- **意見: 案 A を条文に固定せず、結果の文に改めて標識の置き場を手引きへ移す(案 E の趣旨を広げた形)。案 C(外の台帳と指紋)は採らず先送り。秘匿が成り立たない構成は、ADR-0133 のとおり blind: false で未測定にする(適合は止めない)**
- 条文に残す結果: (1) 注入は製品の履歴・出荷の範囲に残らない。**取り込みの前または出荷の前**に機械が確かめる。(2) 確かめた記録が残る(0047・0192 の走査の記録)。(3) 「4層あるので流出しないと記録してはならない」は維持する
- 理由(監査):
  - 監査が確かめられるのは、標識の置き場ではなく**走査の記録**である。メッセージの標識でも外の指紋でも、記録の形(`scanRun`・`residual`・`range`)は同じに保てる
  - 案 C は、台帳を CI の秘密にする経路が無く(`ship-evidence.yml` に入力が無い)、台帳に触れる者は秘匿できない。さらに**台帳を持つ者だけが拒否の根拠を持つので、監査が拒否を再現できない**。証跡の再現性が下がる
  - 案 D(秘匿を箇所に限る)は、要求事項2 の意味を変え、「注入された PR か」の判別が測定を歪める。新しい義務の変更でもある
  - 流出(取り消せない)と秘匿(値が失われる)は、どちらも値を失うが、重さは前者が上(`b-research.md` B-4)。K-1 の衝突では、前者を機械で確保し、後者は開示で受ける
- 取り込み前の拒否が効かない構成(ルールセットを使えない・保護ブランチの外で出荷する): 新しい条項を足さない。既存の「保護の欠落」の表示と、第7章の例外承認で受ける(`decision-draft.md` と同じ)
- 破られたとき: 流出は製品の利用者と採用者が失う(書く)。秘匿の破れは測定の妥当性だけ(未測定の開示で受ける。細かくは書かない)
- 落とす案: A 固定(K-1 が残る)、B(squash・cherry-pick で注記が失われ、第3層の前提が崩れる)、C(上記)、D(上記)。E 単独は第1層の識別だけで足りない
- 根拠水準: 「結果の文にすれば標識の形は手引きに移せる」は条文の構成についての判断で、実証は無い。走査の有効性は EV-NEW1(手元の git の実行のみ)に依存する。GitHub 上の squash の挙動は未確認。暫定

### B-5 K-2 7.9 の発動を何から数えるか

- **意見: 案3(二層)を採る。機械は範囲・類型で数えて「発動に当たる」と知らせ、誰の権限を制限するかは品質保証の機能の手続とし、判断の記録を残す。7.9.1・7.9.2 の主語は、意味を変える編集として本文で直す**
- 理由(監査):
  - 案2(人で数える)は、**台帳に識別子が無いので、監査が数えを再現できない**。5.6.2 の禁止と衝突する。小さい体制では範囲と人が近いが、条文は人で数えられる前提を置けない
  - 案1(範囲・類型だけ)は、7.9.2 の「検知された者」との食い違いを残す。主語を直すだけでは、対象者を誰がいつ決めたかの証跡が残らない
  - 案3 は、制限の記録(IMPL-0118。「対象の人」を必須とする)に、決定者の席と根拠(発動に当たった範囲・類型・回数の参照)を結び付けられる。**人を特定する判断は人の手続に置き、機械には組み込まない**ので、5.6.2 の「措置を組み込まない」とも整合する
- 小さい体制: 件数が足りず発動に達しにくいことは、条文が「件数の不足」として既に開示している。数える単位を決めても発動しない場合がある。これは欠陥ではなく、未達の表示で受ける
- 破られたとき: 見逃しが続く範囲の権限が制限されないまま出荷が進む(安全に響く)。ただし 7.9 は運用中の継続の注入が前提で、template に台帳が無い(A の裁定)。**書くのは「発動に当たったのに制限の記録が無い」場合の検出と、記録の欄だけ**にする
- 落とす案: 案2(監査で再現できず、禁止と衝突)、案1(対象者の決定の証跡が残らない)
- 根拠水準: 閾値「連続2回」は EV-0064(E1、間接)。二層の運用が回るかは実証が無い。暫定

### B-6 5.6.2 の手順の文を結果と証跡の文に改めるか

- **意見: 改める。ただし B-4 の裁定の後、同じ裁定の中で行う。「してはならない」と結果は条文に残す**
- 理由(監査): 手順を条文に書くと、監査は手順の遵守を見ることになり、結果の証跡(閉じた記録・削除の記録)を見ない監査になる。結果と証跡の文にすれば、確かめる対象が記録に変わる。IMPL の番号と意味は、意味を保てば保てる(ADR-0076)
- 改文の例(証跡の形):
  - 報告: 「報告に要する操作を通常の指摘より重くしない」(結果)。証跡は、報告の件数と日時の記録(識別子なし)
  - 演習の変更: 「判定の記録を採取した時点で閉じる」→「閉じられた記録がある」
  - ブランチ: 「期限で削除する」→「期限を超えて残る演習用ブランチが無い」(これは第3層が既に期限超過の未回収で止める)
- 落とす案: 手順を条文に残す(監査が手順の遵守の確認に偏る)、先に B-6 だけ決める(B-4 に従属し、作り直しになる)
- 手順そのものはフェーズ5 に既にある。足す必要は無い

## 2. B を待つ6規定の案

## 3. 内部監査の観点に足すもの(案。数は最小)

1. 走査の記録の存在と `residual` が 0 であること(machine で確かめた結果を、監査は記録で見る)
2. 層ごとの `blind` の値と、注入者・見つけた者の**席が別か**(ロスターで)
3. 注入者の区分(体制内・体制外)と周知の記録の所在(導入前の検証は 0161 の欄)
4. 範囲・類型ごとの見逃しの回数と、発動に当たる場合の制限の記録(識別子ではなく範囲で)
5. 台帳と出力に個人の識別子が無いこと(manual。採用者の台帳を抜き取りで見る)

5項目に絞る。既存の観点を削れるかは、内部監査の観点の本文を読んでいないので、突合の担当が確かめる

## 4. 3つの問いへの総括

1. **結果と証跡まで**: B-4・B-6 で標識の形・手順を条文から手引きへ移す。条文に残すのは、結果(出荷範囲に残らない)・禁止・走査の記録
2. **例外承認で受けられるか**: 注入者=発見者は 1.10.2 の離脱、外部の注入者は手引きの例、取り込み拒否が効かない構成は保護の欠落の表示と第7章。新しい条項は足さない。5.6.2 の免除に第7章を使うことは認めない(7.9.4 の枠を消費し、免除でもない)
3. **破られたとき誰が何を失うか**: 細かく書くのは、流出(利用者と採用者・取り消せない)、blind の表示と実態の食い違い(主張の読み手)、7.9 の発動に当たるのに制限が無い状態(安全)の3つだけ。頻度・難度・内外・併用は書かない

## 5. 新しい条項の削減
