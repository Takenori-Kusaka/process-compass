# #447 重の審議 委員意見: 現場(practitioner)

- 日付: 2026-11-17。前提: 所有者の回答(案 イ)。これを覆す意見は 7 節にだけ分ける
- 開いた原文: human-ai-boundary.md 5.4.5(条件5・条件7 の段落・登録の段落)・5.4.7・5.5.4、roles-responsibilities.md 3.4.3、deliverable-templates.md テンプレ0 表5 の下の力量確認の表・テンプレ11「確認の周期と後継」、gate-criteria.md「類似の検知の実施記録」(先例)。読んだ調査: research-practice.md(ソフトウェア分野に実施記録の前例は見つからず、自己申告の記録は質を示さない)

## 0. 現場から見た要点

- ソロ・2〜5名では、記録の務めが重いこと自体より、**書く人と実施した人と確かめる人が同じ**になることが問題である。記録は残るが、中身は誰も照らさない。大組織では逆に、範囲が多く、実施者が多く、誰の仕事かが散る
- 続く形の条件は3つ。(1) **1件1行・追記だけ**で書ける (2) 範囲ごとに**1回の実施が複数人・複数範囲を覆える** (3) **書かないことの損**が、止まるのでなく開示に出る(案 イ の「止めない」と一致)
- 記録だけ書く抜け道は**機械で閉じない**。閉じたふりをしない。開示の表示を「実施の記録がある」とし、「AI を用いずに実施した」とは言わない。manual + 根拠水準マークで開示する

## 1. 記録の置き場と必須の項目

**置き場: 新しい様式を作らない。テンプレ0(D-0)の表5 の下の「席の責任者本人の力量の確認」の表と同型の追記表を1つ足す**(「AI を用いない実施の記録」)。

- 理由: 同型の先例(確認日・確認した者・記録の所在)が既に D-0 に在り、保証の開示の項目7 も同じ表を読む。新しい文書は誰も開かない。類似の検知の実施記録(G-7)も「事項を定めて既存の台帳に置く」形で、先例に合う
- 追記表は体制の変化点に数えない(3.13.1 の列挙に無い。2.10.5 の調整の記録と同じ扱い)。ただし**条文に明記する**。書かないと D-0 の改訂が変化点を起こすと読まれ、書く側が避ける

必須の項目(所有者の回答の3つ + 1つ):

| 項目 | 内容 | 現場の理由 |
| --- | --- | --- |
| 実施の日 | 日付 | 頻度との比較の唯一の機械の入力 |
| 対象領域 | L2 以上を適用する範囲の識別子(5.4.5 の引き上げの判定または 5.5.4 の登録で名指した範囲) | 自由な文にすると突合できず、「全社」と書いて逃げる |
| 実施者 | 自然人の名(1名以上) | 1回で複数人が実施してよい。人ごとに1行を要求しない |
| 記録の所在 | 成果物・PR・Issue・コミットなど、実施の跡への参照 | 所有者の3項目に**足す**。無いと「日と名前だけ書いた」記録と区別が付かない。内容は審査しない。空欄は許し、空欄のとき開示に「所在なし」と出す |

- 所在を必須の項目に入れないのは、ソロで「所在」を毎回作る手間が形骸化の最大の原因になるためである。**欄は置き、空でも記録は成立する**。空欄は開示に数える(4 節 表示の語)
- 実施者の本人以外の確認は**課さない**(3.4.3 要求事項2 は力量の確認で本人以外を求めるが、5.4.7 は機会の確保であり確認ではない。ソロと2名体制で満たせない)。代わりに、実施者が責任者本人のみであることを開示に出す(4 節)
- 記録は**範囲×実施**の単位。人ごと・日ごとに分けない。大組織は範囲ごとの担当が1行を書き、複数人の実施は実施者の欄に並べる

## 2. 「頻度を過ぎた」の判定

決定可能な条件にできる部分とできない部分を分ける。

**機械で閉じる(決定可能)**

- 入力: テンプレ11 の頻度の値、範囲の一覧(L2 以上を適用する範囲)、範囲ごとの記録の実施の日、比較日
- 比較日 = 保証の開示を作る日(出荷判定の日)。範囲ごとに「最後の実施の日 + 頻度 < 比較日」なら過ぎた
- 起算日 = 範囲の適用開始日(5.4.5 の引き上げの判定日または 5.5.4 の登録日)。**起算日から頻度1期間のあいだは、記録が無くても表示しない**。これを置かないと、登録した直後の全範囲が赤になり、現場は表示を無視する
- 頻度の値の形: 「N日 / Nか月 / N週」のように**数と単位**で読める値に限る。読めない値(「適宜」「四半期ごとに実施」等)は**空欄と同じ扱い**にする。テンプレ11 の例「四半期に1回」は数と単位に直せる形に改める(例: 3か月)。他の行(演習の頻度など)が自由な文で通っているなら、そちらとの差が出る。差は template の項目で揃える

**表示の場合分け**(保証の開示の項目7。止めない)

| 状況 | 表示 |
| --- | --- |
| L2 以上を適用する範囲が無い | 表示しない(掛からない義務を表示しない) |
| 範囲があり、頻度が空欄または読めない | 「AI を用いない実施の頻度を定めていない」 |
| 範囲があり、頻度があり、範囲に記録が無く、起算日から頻度1期間を過ぎた | 「実施の記録が無い」+範囲名 |
| 最後の実施が頻度を過ぎた | 「実施が頻度を過ぎている」+範囲名・最後の実施の日 |
| 範囲があり、頻度内に記録がある | 表示は「実施の記録あり(最後の実施の日)」に留め、**AI を用いずに実施した、とは言わない** |
| 実施者が全件、席の責任者本人のみ | 注記「実施者は責任者本人のみ」(ソロの体制では常に出る。非難でなく状態の開示) |

**機械で閉じない**: 実施の中身が AI を用いないものだったか。記録の所在が実在し、内容が実施の跡か。manual とし、根拠水準マークで開示する(6 節)。プロセス内部監査が抜き取りで所在を開く(新しい観点は足さない。既存の台帳の抜き取りに含める扱いは手引き)

## 3. 5.4.5 の「兼ねる」の読み

**案 イ を採る限り、読みに依らず条文が成り立つ形で書く**。そのうえで、読みも固定する。

固定する読み: **登録の判定は、条件5 を兼ねない。条件5 は5.4.5 の上表の手続(引き上げ)でだけ照らし、登録の経路には常時の記録と開示で掛ける**。

根拠は原文の2点。

1. 5.4.5 の登録の段落の最後の項は「5.4.6 の引き下げと 5.4.7 の能力維持措置は、**登録した変更種別にも適用する**」と別に書く。条件5 を登録の判定が兼ねるなら、この項の 5.4.7 の部分は要らない。別に書いたのは、兼ねないからと読むのが自然である
2. 条件7 の段落が「登録した変更種別の L3 では、5.5.4 の登録の根拠の4点目が同じ役割を持つ」と**条件ごとに登録側の対応を書く**。条件5 に同じ対応が無い。兼ねるが全条件を含むなら、条件7 にこの書き分けは要らない

現場の理由: 兼ねるとすると、B-4 の登録の判定(1回きり)で実施記録を照らすことになる。登録の時点で記録を求めると、初回の登録が実施記録の作成待ちになり、登録の件数が減る。**止めない**(所有者の回答)と食い違う。兼ねないなら、登録は止まらず、開示が継続して照らす。大組織でも、B-4 は登録の判定の道具で、5.4.7 の継続的な照らしには向かない。

- 読みの固定は 5.4.5 の意味を定める編集に当たる。**5.4.5 の登録の段落の最後の項に1句を足す**: 「5.4.7 の能力維持措置は、登録した変更種別にも適用する。条件5 は登録の判定では照らさず、実施の記録(5.4.7)で受ける」。固定した読みを所有者が採らないなら、この1句だけ戻せばよい(条文は読みに依らない)
- 兼ねると読んだ場合の差: 登録の判定でも条件5 が照らされる。常時の記録があるので重複するが矛盾はしない。4 節の文案はこの読みでも成り立つ

## 4. 条文の文案: 5.4.7 の該当の段落の全文

現行の「機会を確保したことの実施記録を、本標準が名指す時点は、5.4.5 の…(未決…)」の段落を、次で置き換える。

> 機会を確保したことは、案件の実施の記録で示します。L2 以上を適用する範囲ごとに、実施の日・対象領域・実施者を、実施のたびに追記します。実施の跡への参照(記録の所在)も書いてよいです。置き場は[第6章 テンプレ0](/process-compass/phase4-process-design/deliverable-templates/)の「AI を用いない実施の記録」の表です。この表は追記だけで、体制の変化点に数えません。一度の実施が複数の範囲または複数の人を覆うときは、範囲ごとに1行を書き、実施者を並べてかまいません。
>
> 保証の開示の項目7 は、L2 以上を適用する範囲ごとに、最後の実施の日が[テンプレ11](/process-compass/phase4-process-design/deliverable-templates/)の層1 に定めた頻度を過ぎているとき、または実施の記録が無いときに、その旨を表示します。範囲の適用開始日(5.4.5 の引き上げの判定日または 5.5.4 の登録日)から頻度1期間のあいだは、記録が無くても表示しません。頻度が空欄または数と単位で読めない値のときは、「AI を用いない実施の頻度を定めていない」と表示します。表示は出荷を止めません。範囲の適用開始日、実施の日、頻度の比較は、日付と値の比較で決まります。
>
> 実施の記録は、実施したことの申告です。実施の中身が AI を用いないものだったかを、機械は確かめません。表示も「実施の記録あり」にとどまり、AI を用いずに実施したとは言いません。記録の所在が実在するか、実施の跡であるかは、プロセス内部監査が抜き取りで確かめます。実施者が席の責任者本人のみの記録は、その旨を注記します。本人以外の確認は求めません。
>
> 5.4.5 の条件5 は、引き上げの判定の時点で、その範囲の実施の記録があることを照らします。登録した変更種別の L3 は、5.5.4 の登録の判定で条件5 を照らさず、上の実施の記録と表示で受けます。頻度の値、頻度を過ぎたことを理由に登録した変更種別または引き上げた範囲を止めること、頻度を満たせない期間を第7章 7.3 の例外承認で受けることは、課しません([ADR-0178](/process-compass/adr/0178-scope-procedure-records-backlog-review-and-ai-free-practice-frequency/))。

注記: 3つめの段落の「プロセス内部監査が抜き取りで確かめる」は新しい観点を足さない。既存の台帳の抜き取りに含める扱いは手引きで示し、条文には**確かめる主体の名指しだけ**を置く。内部監査に新たな責務を課すと見られるなら、その句を「確かめることを妨げません」へ弱める。

## 5. 採らない案と理由

- **実施者の本人以外の確認を必須にする**: ソロと2名体制で満たせず、実施が止まるか偽の確認者が立つ。調査(research-practice 3 節)の自己申告の限界は、本人以外の確認でも解けない(同僚も AI 使用を観測できない)
- **記録の所在を必須にする**: 毎回の成果物の紐付けが形骸化の最大の原因。欄は置き、空欄は開示に数える
- **新しい様式・新しい文書**: 誰も開かない。D-0 の同型の表で足りる
- **人ごと・日ごとの記録**: 大組織で件数が爆発し、書き直しが発生する。範囲×実施で足りる
- **起算日の猶予なし**: 登録直後に全範囲が赤になり、表示が無視される。猶予は日付の比較で決定可能
- **実施の中身の審査(AI 不使用の証明)**: 機械で閉じない。証明を求めると、記録の偽装か実施の回避が起きる(METR の継続研究の 30〜50% の回避)
- **頻度切れで範囲を止める・引き下げる**: 所有者の回答が止めないとしている。破られたとき失うものも、技能維持の外側の層が薄くなることで、中核は 3.4.3 が守る
- **登録の判定で条件5 を照らす(兼ねる)**: 3 節の理由。所有者が案 ウ を採らなかったことと整合する
- **「四半期」「適宜」等の自由な文の頻度を受ける**: 比較が決定可能にならず、実際は空欄と同じ扱いにするしかない。値の形を数と単位に絞る

## 6. 根拠水準マークの要否と見直しの時期

**要る。2つ付ける。見直しは 2027-05**(IMPL-0978 の review と揃える)。

1. 「常時の実施の記録と頻度切れの表示が、機会の確保を促す」という判断
   - 根拠の水準: E0。ソフトウェア分野に実施記録の前例が無く(research-practice 2 節)、記録が完了率の達成に変質する報告が近い領域に在る(3 節)
   - 差し替え条件の案: 2 期分の保証の開示で、(a)「実施が頻度を過ぎている」「実施の記録が無い」の表示が出た範囲の割合、(b) 表示の直後に実施の記録が足された範囲の割合、(c) 記録の所在が空欄の割合、(d) 実施者が責任者本人のみの割合。(b) が高く (c) も高いなら、記録を作る行動に変質している兆し。機会の確保の質は測れないので、結論でなく兆しとして読む
2. 「兼ねない」の読みと、条件5 を登録で照らさない判断
   - 根拠の水準: E0(原文の書き分けからの読み)
   - 見直しの契機: 所有者が読みを変えたとき、または登録の件数に対して表示が出る範囲の割合が高く続くとき

台帳は `npm run evidence:write` で再生成する。実装マーク IMPL-0978 の `check=manual` は変えない。頻度と起算日の日付の比較部分は IMPL-1021 が machine にできる(IMPL-1021 の note に「比較の日付と値の形は決定可能。降ろした後に machine」を足す)。

## 7. 3.4.3 の「研究が無い」の文の更新

**要る。結論(本標準は頻度の値を定めない)は変えない**。research-practice 4.1 のとおり、頻度と維持の関係を測った研究が無いという点は2026-11-17 時点で成り立つ。更新するのは文の形である。

- 日付を付ける(agentic-freshness の規約)
- 「無い」の範囲を狭める: 頻度と維持の関係(用量反応)を測った、ソフトウェア開発者の研究が見つからない。AI 支援が技能の形成・維持を下げうる研究(Shen ら 2026、Budzyń ら 2025)は在るが、周期を決める粒度ではない
- 現場の注意: 「研究が無い」を理由に頻度の記録を軽く扱う読みを防ぐ。「頻度の値は定めない。実施の記録と頻度切れの表示は課す(5.4.7)」を1句足す。3.4.3 の力量の確認(周期の失効)と 5.4.7(機会の確保)は別の統制で、同じ周期を共有しないことも1句で添える

## 8. 所有者へ返す懸念(案 イ を覆す意見ではない)

- 案 イ はソフトウェア分野に前例が無く、実測が無い。本意見は、開示だけで止めない形に収めて損失を下げ、E0 を開示する形に倒した
- 5.4.5 の読み(3 節)は所有者の確認を要する。兼ねないと読む場合、5.4.5 に1句の追加が要る
- ソロ体制では、実施者は常に本人のみで、注記が毎回出る。非難に見える表示になる。表現の最終の判断は所有者に委ねる
