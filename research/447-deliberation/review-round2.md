### R2-1(中)実施者が空欄の行が数える行になる

- 所在: `human-ai-boundary.md:346`(「実施者の名がすべて人の名簿にあり、AI の名義を1つも含まないこと」)、IMPL-1022 の note(`:375`)、様式の注記(`deliverable-templates.md:511`)
- 根拠: 改める前は「実施者が人の名簿にある行」で、空欄は満たさなかった。「すべて」に改めたことで、名が0個の行は「すべて名簿にある」「AI を1つも含まない」を空の真として満たす。様式の注記の「名簿に無い名または AI の名義を含む行は数えない」も、空欄の行を外さない
- 影響: 日付と範囲の名だけを書いた行で「AI を用いない実施の記録が無い」が出ず、最後の実施の日も進む。表示が減る向き。降ろし先が「すべて」を字義どおり実装すると起きる。判定の条件(決定可能性)の欠け
- 直し方の案: 本文を「実施者の名が1つ以上あり、そのすべてが人の名簿にあって、AI の名義を含まないこと」に改め、IMPL-1022 の note と様式の注記(「実施者が空欄の行」を数えない行に足す)を揃える。義務は増えない(空欄は改める前から数えなかった)

### R2-2(中)1期間に2回以上の値の扱いが本文と表示の降ろし先に無い

- 所在: IMPL-1020 の note(`deliverable-templates.md:1803`)だけにある。本文 `human-ai-boundary.md:348`、テンプレ11 の行(`deliverable-templates.md:1771`)、IMPL-1021(`:1805`)、ADR-0179 決定2 には無い
- 根拠: 「1回あたりの期間の長さとして読めない値」の字義では、「3か月に2回」は1回あたり 1.5か月として読める。読めない値とする定めは、様式の行の降ろし先(qa-policy-template)の note にあり、表示を出す降ろし先(evidence-aggregation)の IMPL-1021・1022 にも、規範の本文にも無い。template の `parseInterval` は「3か月に2回」「1年に2回」を 3か月・12か月と読み、回数を捨てる
- 影響: 集約を降ろす者は IMPL-1021・1022 と本文を読む。`parseInterval` を流用すると、定め(読めない値 →「頻度を定めていない」を常に出す)より表示が減る(3か月を過ぎるまで何も出ない)。本文の字義(1.5か月)とも割れる。標準の中で判定が3通りに読める
- 直し方の案: 本文の箇条の「読めない値」の後に「1期間に2回以上を求める値(例: 3か月に2回)は読めない値とする」を置き、テンプレ11 の行と IMPL-1021 の note に同じ句を足す。IMPL-1021 に「`parseInterval` は回数を捨てるので、そのまま流用しない」を1句書く。ADR-0179 決定2 は「空欄・1回あたりの期間の長さとして読めない値」のままでよい(本文が定義を持つ)

### R2-3(中)条件5 の参照が引き上げの判定に基準日を持ち込む

- 所在: `human-ai-boundary.md:134`(条件5「当該の範囲の数える行(5.4.7)がある」)と `:346`(「実施した日が実在の日で保証の開示を作る日以前であること」)
- 根拠: 5.4.5 の引き上げの判定は保証の開示を作る日に行うものではない。参照した数える行の条件の基準日をそのまま当てると、判定の時点に保証の開示が無いとき決まらず、ある場合も過去の開示の日か次の開示の日かが割れる
- 影響: 機械の検査にしうる条件が決定可能でなくなる。引き上げの判定は止める側の判定なので、読みによって通る・通らないが割れる
- 直し方の案: 条件5 を「当該の範囲の数える行(5.4.7。基準日は引き上げの判定の日)がある」に改める。義務は増えない
