## 1. 立場と全体の見立て

1. **Filetto の 21,116 行は、量の問題である前に「生成の規則の問題」である**。量を生んだのは、ADR の範囲が「方針・原則」まで広がるテンプレートの文言、G-3 の判定対象が ADR そのものと書かれていること、探索の記録の置き場が無いこと、の 3 つである。**量を測る指標を足しても、この 3 つは止まらない**。現場の代表として、量の観測より先に、生成の規則(D-1〜D-4、D-11)を直すことを主張する
2. 一方で、**ADR を減らす方向の案の多くは「決めるべきことが漏れる」側へ倒れる**。可逆な決定の除外(D-4)、実装計画への吸収(D-3)、文書量の警戒値(D-9)はどれも、書くべき判断記録を書かない、別の置き場へ逃がす経路を開く。現場は楽になるが、後任者と監査が困る。これらは採らない
3. 読む側が持ちこたえるために効くのは、**AI が古いものを読まないこと**と、**人が読む量の上限が構造で決まること**である。前者は保管領域への移動と、読み込みからの除外の実装(D-5・D-15 の 12)で、後者は原則を短い恒久層に置くこと(D-1)と、探索の記録を判定の入力にしないこと(D-11)で得る。どちらも数値の閾値に頼らない
4. 文書量の観測は「新しい指標」としては採らない。ただし**既存の指標「レビュー所要時間の分布」を文書だけの変更にも掛ける**(D-8)。2 万行を短時間で通した承認は、文書でも素通しである。対の指標は既にあり、指標の総数も増えない
5. 原則4(class-lock)と原則9 は、件数の義務を退け、**「同種が再び出たら、機械へ移すか、観点に置くか、移さないかを決めて 1 行残す」**と、**統制の設定を変えるときに止まるべきものが止まることを確かめる**、の 2 つに絞る。装置を自動で増やす規定は置かない

### D-1 立ち戻る先(原則・軸・ポリシー)

現場の目線で何が起きていたか。Filetto の事業決裁者は「困ったら立ち戻る軸」を ADR の束に探し、案と却下理由が並ぶ文書を読まされた。AI の側も同じで、軸が無いと、毎回 ADR の束から推測するか、軸に反する案を平然と出す。その結果、設計判断のたびに「なぜ前と違うのか」の差し戻しが起きる。**立ち戻る先が 1 枚に無いことは、手戻りの原因であり、読む量の原因でもある**。

採る内容。

- 置き場: 第5章 コンテキスト基盤の恒久層。`context/standards/` に置く(既にあるラベルに様式を与える)
- 様式: 原則ごとに「名前・文・理由・含意」の 4 項目(TOGAF 9 の Table 20-1 と CDDO の構成が一致する型)。**案と却下理由を書かない**。比較は判断記録の仕事である
- 量: 3.11.4 要求事項1 の 200 行の上限を掛ける(指示資産として AI に常駐させる以上、同じ上限が要る)。原則の数の上限は置かない(TOGAF の 10〜20 は経験則で、根拠が無い)

- ステージ: 2.6 の表の「コンテキスト基盤」行に合わせる。S0 は求めない(案件層のみ)、S1 で整備を開始、S2 で維持が必須

- 基準1 の「設計案」: テンプレ2 には既に「## 非機能への影響」欄がある(私が確かめた)。基準1 の確認方法を「判断記録の非機能への影響欄」へ改め、`integrated.yaml` の `deliverables` を「判断記録(ADR)案(AI 起案+人レビュー済み)」1 つにする。**設計案の様式を新設しない**

### D-3 設計判断の記録の置き場

**判定: 採る。3-A。独立の ADR を `context/decisions/` に置く。加えて「G-3 の判定記録は判断記録の内容を再掲しない」と書く。**

### D-4 ADR にする基準と「可逆な決定を除く」

**判定: 採る。(a) 可逆性で記録の要否を分けないと明記する。(b) G-3 に掛ける選択の下限を置く。(c) テンプレートの「方針、原則」の語を外す。**

(a) 可逆な決定の除外を課さない。

- 可逆かどうかの評価は G-3 基準3 の中身である。要否の判定の前に置くと、起案者(多くは AI に起案させた本人)の申告で決まる。ADR-0044 決定4「適用範囲を閾値で切る形は、閾値の判定を自己申告にすることで要求そのものを無効化します」は、同じ形を退けている
- 3.8.1 の区分の下限は、**変更のパス**から導く。G-3 は実装の前に掛かるので、判断の時点では変更のパスが無い。下限の仕組みでこの論法は解消されない
- 外部で可逆性によって変えているのは手続の重さで、記録の要否ではない(Amazon・国内 1 社。調査 2.3)。記録を不要にする先例は見つかっていない
- 現場の目線: 「あとで戻せると思った決定」が、データが溜まって戻せなくなるのは、小さな案件ほど起きる。戻せる間に理由を残しておかないと、戻すときに何を前提にしていたかが分からない

(b) 本数が増える本当の原因への手当てとして、**G-3 の起動条件を下限の形で置く**。

- 現状は、2.6 の S0「G-3 の判定の対象とした選択」が G-3 へ定義を預け、G-3 側に起動条件が無い(調査 1.6 の 8)。範囲が決まらないので、AI は迷えば全部を ADR にする。テンプレートの「方針、原則」がそれを後押しする
- 文の案(第4章 G-3 の節の冒頭):

> 次のいずれかに当たる技術上の選択は、G-3 に掛けなければなりません。
>
> - 3.8.1 の R1 の該当条件(外部との契約・公開インタフェース・データ形式、認証・認可・個人データの取扱い、事業継続)に影響する選択
> - コア機能の構造(データの持ち方、モジュールの境界、外部サービスへの依存)を決める選択
>
> これに当たらない選択を G-3 に掛けるかは、技術判断者が決めます。掛けなかった選択は判断記録を要しません。

- これは「除外」ではなく「下限」である。下限の条件は R1 の語彙で、実装の後に差分から観測できる。G-6 で、下限に当たる変更に判断記録が無いことが見つかる。低く申告しても後から見える点が、除外と違う
- 2.6 の S2「全件必須」は「G-3 に掛けた選択の全件」と書き直す。何の全件かが書かれていない(調査 1.6 の 13)

(c) テンプレートの「技術選定、方針、原則、外部との契約に関わる設計」を、本文 2.6 の「設計上の選択」へ改め、「原則と規約は恒久層(`context/standards/`)」と書く。D-15 の 1 で詳述する。

落とした案。

| 案 | 落とす理由 |
| --- | --- |
| 4-A 現状維持 | テンプレートの「方針・原則」と G-3 の起動条件の不在が残り、本数が増える原因が残る |
| 4-C 可逆な決定を本文で除く | 上の (a)。ADR-0044 決定4 と正面から当たり、覆す材料が無い |
| 4-D 区分で重さを変える | 区分は変更ごと(ADR-0039)で、設計判断の時点に確定しない。重さを変える必要は、5.7.3 が比較を R1 に限ることで既に一部ある |

### D-5 ADR の索引

**判定: 採る。1C(機械で生成した一覧)と 1G(全部を置き換えた・廃止した ADR を保管領域へ移す)。**

- 現場で起きていること。がんばりクエストは 7 か月で 70 本を超えた。AI は数分で ADR を書く。番号順の平らな一覧では、どれが今も効いているかを人も AI も開かないと分からない。本プロジェクトのサイトの一覧も同じで、状態を表示しない
- 一覧は人のため。番号・題・状態・後継・一部置き換えの範囲の 5 列を、`decisions/` の状態欄から**機械で生成する**。手で保守しないので、ADR-0025 決定4(別置きの表は陳腐化する)には当たらない。生成元の状態欄が誤っていれば一覧も誤るので、D-6 の検査と組にする
- 移動は AI のため。テンプレート自身が「参照対象に残したまま『古い』と注記する方式は採りません。注記は読まれず、古い記述がそのまま使われます」と書いている(私が確かめた 7 行目)。この論理は ADR にも同じく当たる。**全部を置き換えた ADR と廃止した ADR は、保管領域へ移す**。削除ではないので ADR-0025・3.11.4 要求事項7 と整合する。本文は書き換えない(移すのはファイルの場所で、本文ではない)
- 一部を置き換えた ADR は移さない。一部が今も効いているからである。D-6 の両側リンクで、どの決定が効いているかを示す
- 移す判断は ADR-0025 決定10(外す判断を AI に行わせない)に従う。状態を置き換え・廃止にするのは技術判断者の G-3 の判定の結果であり、移動はその機械的な帰結として扱う
- **前提**: 保管領域がエージェントの読み込みから実際に除外されていること。テンプレートの `settings.json` の `deny` は空である(私が確かめた)。D-15 の 12 を本 Issue で直さなければ、1G は効かない

### D-7 ADR の総量・参照実績の観測

**判定: 課さないと明記する。証跡の集約の表示は「数」から「状態つきの一覧」へ改める。決める場所は運用メトリクス(フェーズ6)。**

- 本数・行数を指標にすると、下げる圧力が「書くべき判断記録を書かない」「Issue や PR 本文へ逃がす」へ働く。対になる指標は「判断記録の充足」だが、これはコア変更の `ADR:` トレーラの比率で、トレーラだけ付けて中身の薄い ADR を書く経路を塞げない。手続2(対の指標を指定できない指標は採用しない)を満たせない
- 読み込み実績を ADR へ広げる案(3D)は、0 回の ADR を何の候補にするかが決まらない。ADR は読まれなくても経緯として残す性質を持つ。「外す候補」にすれば D-5 の 1G と別の基準で ADR が移り、何にも使わなければ「眺めるだけの指標」になる
- 証跡の集約の「判断記録(ADR): N 件」は、README を数え、状態を区別しない(私が `aggregate-evidence.mjs` 272・3871 行で確かめた)。**数を出すこと自体が「参考値として測ることはできない」に当たる**。数ではなく、番号と状態の一覧(所在の目録)を出す。監査が要るのは「どの判断記録が効いているか」で、本数ではない
- 受入条件の「第7章メトリクス」は、運用の健全性の指標体系がある**フェーズ6 の運用メトリクス**と読む。7.7.2 は予算統制の入力で、閾値を G-1 で確定する義務が掛かり、ADR の本数は費用ではない。議長に、受入条件の読みとして記録することを求める

文の案(`metrics.md`、「判断記録の充足」の表の直後)。

> 判断記録の本数・行数・参照実績を、指標にも警戒サインにも置きません。本数を下げる圧力は、書くべき判断記録の欠落と、別の置き場への退避を生みます。判断記録の量への対処は、記録の範囲(第4章 G-3 の起動条件)と、置き換え済みの記録の保管(コンテキスト基盤)で行います。

落とした案: 3B(数の表示に留める)は「参考値は成立しない」に当たる。3C(正式指標)は対の指標が無い。3D は上記。3E(「判断記録の充足」の中身を広げる)は、リンク欠落は D-6 の機械の検査で失敗させるので、指標に混ぜる必要が無い。3F(7.7.2・7.7.8)は ADR の本数が費用でない。

根拠水準: 観測しない判断の根拠は、量と害の関係の測定が無いこと(FND-0070、ADR の参照頻度の測定は無い)と、逆向きの Goodhart の推論(測定なし)。**暫定マーク E0 / 見直し 2027-10**。差し替え条件: 採用案件で、AI が置き換え済みの決定に従った件数、または判断記録の欠落が出荷後に見つかった件数が、本数の増加と連動して増えるという観測。

### D-13 同種の不具合の昇格(class-lock)

**判定: 採る。件数の閾値と「3 件目を機械で止める」義務は課さないと明記する。代わりに「再発を見たら、移す先を決めて記録する」ことを要求する。**

現場の目線。AI に実装を任せると、同じ類型の誤りは人の速度ではなく AI の速度で繰り返す。「3 件目」は 1 日で来ることもある。件数は待ちの長さを決めるだけで、漏れを防がない。一方、「3 件目で必ず機械で止める」を義務にすると、機械で止められない類型(設計の妥当性・仕様との一致。ci-gates が自ら人の本務と書く)に義務が掛かり、満たせない義務が並ぶか、形だけの検査が足される(FND-0097)。

3. 機械で止める形にしてよいのは、実効的な偽陽性が無く、修正可能なものに限る(Google の Error Prone の条件。ADR-0025 決定2 と同じ軸)。満たさない類型は観点表に置く
