## 新しい所見

### 高-A IMPL-0972 の note「読めないときは失敗にしない」が、3つの経路で実態と食い違う(表示と実態。**直す**)

- **所在**: `template/scripts/gate/check-pr.mjs` の `decisionG3Reach`(`declarers(reviews)` を呼ぶ末尾の行、`info.number == null` の行、写しの `copy` が null の行)。表示は lifecycle.md の IMPL-0972 の note「ホスティングの記録や記録用ブランチを読めないときは失敗にせず、確かめられない旨を注意に出す」と、関数の注記
- **実行で確かめたこと**(作業用のスクリプトから直接呼んだ。3場面とも `ok: false`)
  1. この PR で足した判断記録で、PR のレビューを読めない(`reviews: null`)。さらに記録用ブランチも読めない。理由の文は「基底ブランチと記録用ブランチに G-3 の判定記録が無く、この PR に…レビューも無い」となる。読んでいないものを「無い」と書く。ほかの検査は、`reviews` が配列でないときに `readable: false` として扱う(check-pr.mjs 1305・1412 行)。この経路だけが失敗にする。CI ではレビューを取る段の失敗で `PR_REVIEWS` が空になり、手元の実行では常に空になる
  2. 判断記録が PR を経ずに入り、記録用ブランチを読めない。様式が記録用ブランチにあっても読めていないのに、「PR を経ずに入っている」として失敗にする
  3. 記録用ブランチは読めるが、その PR の写しが無い(record-copy の前に入った PR、写しの衝突 `b.conflicts`)。理由の文は「PR #5 に宣言行…のレビューが無い」となる。写しが無いことを、レビューが無いことと書き違える
- **判定**: 1巡目の高-1 と中-4 の直し方は「読めないときは失敗にせず」だった。直しはこれを基底の判断記録の経路にしか入れていない。それなのに note は全体に効くと書く。表示と実態が食い違う。偽の通過ではなく偽の失敗であり、理由の文が誤った直し方へ導く
- **直し方の案**(決定可能な条件だけで閉じる)
  - (a) `reviews` が配列でない(この PR のレビューを読めない)ときは、`ok: null` で返す。ほかの検査と同じ扱いにする
  - (b) 記録用ブランチを読めないときに、この PR で足した判断記録と PR を経ない判断記録を `ok: null` にしてはならない。`available: false` は「まだ無い」と「取得に失敗した」を区別しない(records.mjs 361 行)。null にすると、記録用ブランチの無い初期の案件が G-3 を経ずに通る。失敗は残し、理由の文を「記録用ブランチを読めない(<reason>)。様式をそこへ置いたなら、読める環境で再実行する」に改める。note の約束は「基底へ入っている判断記録で、入れた PR の記録や写しの置き場を読めないときは失敗にしない」に狭める
  - (c) 写しが無いときは、理由の文を「PR #N の写し records/reviews/pr-N.json が記録用ブランチに無い」に改める。失敗は残す。写しが判定記録の持続する受け皿だからである(記録用ブランチの様式を置けば受ける、と文に添える)。衝突の記録(`b.conflicts` の pr が N)がある PR は、写しを読めないものとして `ok: null` にする
  - 試験: (a) `reviews` 無しで注意になる(ok)。(b) この PR の判断記録で、記録用ブランチを読めないときの文(ng)。(c) 写しが無いときの文(ng)と、衝突のある写し(注意)。それぞれ `:ok`・`:ng` を別の行に置く
- 3巡目が無いため、議長はこの直しを関係する試験(`test-check-pr.mjs`)で確かめて閉じる。(b) を「note を狭めるだけ」で済ませる場合、関数の注記の「読めない(…記録用ブランチを読めない)ときは失敗にせず」も同じく狭める
