### 高-1 IMPL-0972 の (ii) が、準拠テンプレート自身の「G-3 の判定記録」の定義と食い違う

- **所在**: `template/scripts/gate/check-pr.mjs:1052-1060`(`prApprovers`。`state === 'APPROVED'` だけを数える)、`:1061-1071`(基底に在る判断記録で、`prOfCommit` の `approvers` を数える)
- **根拠**: `template/.claude/skills/gate/reference/recording.md:38-41` は、G-3 の受け皿を「判定者本人のレビューの本文」とし、「**状態は問わない**(APPROVED / CHANGES_REQUESTED / COMMENTED)。作成者本人の判定者は COMMENT で提出する」「**宣言行の無い承認は取り込みの事務であり、G-2・G-3・G-4 に数えない**」と書く。宣言行の読み方は `records.mjs` の `parseDeclaration`(54 行)にある。実装は宣言行を読まない。この食い違いから2つの誤りが起きる
  - 偽の通過: 宣言行 `G-3: 通過` の無い、名簿の人の素の承認で通る。テンプレートの定義では、これは G-3 の判定記録ではない。2.6 要求事項4 は「G-3 の判定記録を要する」なので、`state=delivered` の表示が実態を超える
  - 偽の失敗: 作成者本人が判定者のとき(1名の体制や、技術判断者が自分で ADR の PR を開く場合)、テンプレートの手順どおりに COMMENT で `G-3: 通過` を出しても数えない。様式を records ブランチに置いた場合も、(i) は基底の `docs/gates/` だけを読むため数えない(impl-A の「できなかった点」1)。手順に従った採用者の PR が G-5 で落ちる
- **由来**: 裁定 §3.1 の条件 (ii) が「承認のレビュー」と書いたことによる。実装は裁定に従っている。裁定の誤りである
- **直し方の案**: (ii) を「宣言行 `G-3: 通過` を1行目に持つレビュー(状態は問わない)で、書き手が名簿の人であり、AI の名義・bot でないもの」に改め、`parseDeclaration` を使う。基底に在る判断記録の場合は、ホスティングの `approvers` ではなく、記録用ブランチの写し `records/reviews/pr-<N>.json`(`parseCopy`)の宣言行を読む。(i) は `g1PassState` と同じく、基底の `docs/gates/` と記録用ブランチの `records/gates/` の両方を読む。記録用ブランチの様式は、判定者の記名が名簿の人へ対応づくものに限る(records.mjs 524 行の理由と同じ)。記録用ブランチを読めないときは失敗にせず、「判定記録を読めない」と出す(#359 高-1 の前例)。試験は、ng に「宣言行の無い承認だけ」を、ok に「作成者本人の COMMENT の宣言行」「記録用ブランチの様式」を足す

### 高-2 IMPL-0211 が `.github/CODEOWNERS` だけを読み、ほかの正規の置き場を使う採用者の全 PR を落とす

- **直し方の案**: 基底で `CODEOWNERS_PLACES` を順に読み、最初に見つけたもの(効いているもの)を検査する。3か所のどれにも無いときだけ失敗にする。失敗の文には、検査したファイルの所在を出す。試験の ok に「根の `CODEOWNERS` だけがある」場面を足す

### 中-4 IMPL-0972 で、PR を経ずに入った判断記録や、導入前の判断記録を指すトレーラが恒久に落ちる

- **所在**: `template/scripts/gate/check-pr.mjs:1064-1067`
- **根拠**: 判断記録を最後に変えたコミットに PR が無い場合は失敗になる。導入前の取り込み・直接の push・テンプレート以前の判断記録がこれに当たる。ホスティングを読めない実行でも失敗する。このとき採用者は、`docs/gates/` に G-3 の様式を置くしかない。ところがテンプレートの手順では、`docs/gates/` へ様式を運ぶのは出荷判定(G-7)の PR だけである。その間、その判断記録を指すトレーラを持つ PR はすべて落ちる。基底に在る判断記録の経路(`prOfCommit`)には、ok の試験も ng の試験も無い
- **直し方の案**: 高-1 の直しで、記録用ブランチの様式を読む。そうすれば、導入前の判断記録の G-3 も `records/gates/` で受けられる。ホスティングを読めないときは失敗ではなく「確かめられない」の注意にする(ほかの帰属の検査と同じ扱い)。試験に「基底の判断記録 + 写しの宣言行(ok)」「基底の判断記録 + PR 無し + 様式無し(ng)」を足す
