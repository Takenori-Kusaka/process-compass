## 2. 委員の意見

### 2.1 起案(欄を足さない。記録から機械で数える)

1. 構成に欄を足さない。保持者の数と層1 の記名者は、標準が既に記録の正本を定めている(運用引き継ぎ文書の節2、層1)。構成に同じ値の欄を足すと、正本が2つになる。構成は `/process-change` でしか変わらず、引き継ぎ文書は出荷ごとに変わるので、2つは必ず食い違う。食い違ったとき、甘い側(構成の「2名」)が記録の示す離脱を隠す。自己申告の写しは、適合の主張の信頼を下げる
2. 集約の `claimForRange` は、既に読んでいる `continuity.core` と `policy.signerIsBizApprover` を、列挙に無い離脱として名へ重ねる。同じ出力の中で開示の表と名が食い違う現状は、表示と実態の食い違いである
3. 認証情報は、構成の名義の申告から決まる部分を `claimStatus` で数える。兼務を禁止した組(3.5 の表)の2つの席の担い手が、同じ専用のアカウント(数値の識別子)を申告した構成は、1.10.2 の「席ごと」の読みでも 3.5.3 のレーンの条件1 の読みでも離脱に当たる。決定可能である
4. 秘匿は機械にしない。「注入する者と見つける者を分けられない」は構造の判断で、`blind: false` は1回の測定の記録、理由は自由な文である。注記に足して人が確かめる(B-1)
5. PROCESS-PROFILE.md は構成だけから生成し、生成の後に変わる記録を読まない(読めば生成の時点の値が古びる)。注記は残し、集約が数える項目と人が確かめる項目を分けて書く

### 2.2 反対(どちらかへ寄せる)

1. 欄を足すべきだという立場: 構成書と CLAUDE.md の生成区間は、採用者とエージェントが最もよく読む表示である。そこで名が決まらず「人が確かめます」と出続けるなら、項目2 は閉じない。保持者の数と層1 の記名者を `/process-change` の欄にし、記録との食い違いを契約検査で落とせば、正本の二重は検査で抑えられる
2. 機械にするなという立場: 集約が手で書く表(引き継ぎ文書の節2)を解いて名を下げると、表の書き崩れ(列の名・確認日の書式)で、離脱でないものを離脱に数えて主張を妨げる。名は構成だけから決まる今の性質を保ち、開示の表にだけ出せばよい
3. 認証情報について: 禁止の組に限ると、1.10.2 の「席ごと」より狭い。狭い方だけ機械にすると、残りが「機械が見たので無い」と読まれる

### 2.3 割れた点と、議長への案

| 割れた点 | 案 | 採らない案と理由 |
| --- | --- | --- |
| 構成に欄を足すか | **足さない** | 反対1: 食い違いを契約検査で落とすには、契約検査が引き継ぎ文書と層1 を読む必要があり、それなら欄を介さず記録を直接読めばよい。欄は採用者に二重の記入を課し(新しい義務)、記入の時点で古びる。構成書の表示の弱さは、注記を「集約が数える」と書き分けて補う |
| 集約が記録から名を下げるか | **下げる**。ただし記録を読めない・解けないときは名を下げず、注記に残す | 反対2: 書き崩れで誤って下げる危険は、読めない・解けないを「下げない(注記)」へ倒すことで避ける。逆向き(離脱があるのに適合と出す)は主張の信頼を損ない、受け取る者が気づけない。誤って下げる向きは採用者が気づいて直せる |
| 認証情報を禁止の組に限るか | **限って機械にし、残りは注記に残す**。1.10.2 と 3.5.3 の食い違いは本件で揃えない(6 の所有者の判断) | 反対3: 注記に「機械が数えるのは禁止の組の同じアカウントだけ」と書き、残りを人に確かめさせることで、無いと読まれる誤りを避ける |

## 3. 議長の裁定の案

1. **構成に欄を足さない**。理由は 2.3 の1行目。受け入れ条件「足さない理由を記録している」をこれで満たす
2. **記録から決まるものは機械で数える**(決定可能な条件だけ)
   - (a) 集約の `claimForRange`: 運用引き継ぎ文書の節2 で保持者(既存の数え方)が1名以下のコア機能がある、または層1 があり `signerIsBizApprover` が真のとき、列挙に無い離脱として `unlistedDepartures` と `blockers` に足し、名を「適用の表明」へ下げる
   - (b) `claimStatus`: 兼務を禁止した組の2つの席の担い手が、同じ数値の識別子の専用のアカウントを申告した構成を、列挙に無い離脱(`derived: 'performer-credential-shared'`)に数える。構成だけで決まるので、PROCESS-PROFILE.md の名にも効く
3. **機械にしないもの**(manual。注記と IMPL の undelivered で表示し続ける)
   - 欠陥注入の秘匿の不成立(構造の判断。自由な文)
   - 引き継ぎ文書・層1 が無い、または解けないときの保持者と層1 の記名者
   - 層1 の記名者と事業決裁者の氏名の表記が違う場合(`samePerson` の照合の外)
   - 禁止の組でない席どうしの認証情報の共有、ホスティングのアカウントの外の認証情報(トークンの権限の範囲など)
4. **閉じ方**: 2 は機械の検査(値の一致と数の比較)。3 は manual。秘匿は根拠水準のマークを要さない(既定の帰結の表示であり、実証を欠く値を新たに置かない)。新しい ADR は**要さない**(ADR-0133 の決定の実装であり、標準の原則・義務を変えない。欄を足さない決定と理由は本記録と IMPL の note で開示する)。議長が ADR を要すると裁定する場合は ADR-0147 を使う
5. 範囲の終点の扱い: 既存の IMPL-0308 の「範囲の時点の未達と兼務は範囲の終点の構成で読む」に合わせ、記録も範囲の終点で読むのが整合する。現在の `continuityState`・`readPolicy` は作業ツリーを読む。実装の担当が、終点のコミットの記録を読めるかを確かめ、読めなければ作業ツリーで読むことを note に書く
