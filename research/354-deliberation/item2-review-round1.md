## 所見

### 高-1 書き崩れと層1 の欠けで、保持者を「0 名」と数えて名を下げる(表示と実態の食い違い)

- **所在**: `template/scripts/gate/aggregate-evidence.mjs:5346-5350`(`continuity.core.filter((c) => c.holders.length <= 1)`)。表示の側は ADR-0147 決定2 と「検討した選択肢」の3行目、`overview.md` の IMPL-0521 の note、`generate-profile.mjs:3654` の注記
- **根拠**: 上表の B・C・D・K。`continuityState` は、数えない保持者(`uncounted`。周期が空欄、確認日の書式、確認者の列なし)を `holders` に入れない。集約はその数だけを見るので、2名を書いた記録が「0 名」の離脱になる
  - ADR-0147 決定2 は「記録が無い・解けないとき(引き継ぎ文書なし、節2 にコア機能の記載なし、**層1 なし**)でも、名を下げない」と書く。B は層1 なしで名を下げる。B の `unverifiable` は記名者の項目しか出さず、保持者を下げた理由が層1 の欠けだと読めない
  - ADR-0147 の採らない案の3行目は、「書き崩れ(列の名・確認日の書式)で、離脱でないものを離脱に数えて主張を妨げる」ことを理由に挙げる。実装は D(確認日の書式)と E(列の名)で、まさにその誤りを起こす
  - 構成書の注記は「記録が無い・読めないときは数えません」と書く。C・K(層1 の周期が読めない)で数える
  - 離脱の文は「決済 0 名。本人以外の確認つきで数えた」と出る。書いた2名が数えられなかった理由(周期・書式)が出ず、採用者が直す手がかりにならない
- **反対の読み**: 標準 第3章 3.4.3 要求事項8 は「理解の保持者に数えるのは、本人以外の者が日付を付けて理解を確認した記録を持つ人に限る」と定める。テンプレ11 も、周期が空欄なら「理解の保持者も数えない」と書く。この読みでは、E・F(確認者の列が無い・空欄)は書き崩れではなく、確認の記録を欠いた本物の離脱である。D(書式だけの違い)と B・C・K(層1 の欠け)は、記録そのものはあるので「解けない」に当たる。どこまでを離脱に数えるかは議長が裁定する
- **直し方の案**: 決定可能な規則で2つに分ける
  1. 書いた保持者の名(`holders` と `uncounted` の和の異なる名)が1名以下 → 離脱に数える(どう読んでも2名に届かない)
  2. 書いた名は2名以上だが、数えた保持者が1名以下 → 理由ごとに分ける。確認者の列なし・空欄・本人(要求事項8 を欠く)は離脱。周期の欠け・層1 なし・日付の書式は `unverifiable` に出して名を下げず、数えなかった理由を出力に書く
  3. 2 の線引きを変えるなら、ADR-0147 決定2・採らない案の3行目・IMPL-0521 の note・構成書の注記を同じ線へ揃える。実装と表示のどちらを直すかは議長が裁定する。揃えないまま閉じない(表示と実態が食い違う「高」)

### 中-2 裁定の案 2.3 の2行目の理由が、自らの規則と食い違う

- **所在**: `item2-decision-draft.md` 2.3 の2行目。ADR-0147 の採らない案の3行目が同じ理由を写す
- **根拠**: 理由は2つの文から成る。(1)「書き崩れで誤って下げる危険は、読めない・解けないを下げないへ倒すことで避ける」。(2)「逆向きは受け取る者が気づけない。誤って下げる向きは採用者が気づいて直せる」。(2) の非対称は、読めないときこそ下げる側へ倒す理由になり、(1) の規則と逆を指す。また「解けない」が決定可能な一覧として定義されていない。ADR は3つ(引き継ぎ文書なし・節2 の記載なし・層1 なし)を挙げるが、反対2 が挙げた危険(列の名・確認日の書式)はこの一覧に入らない。このため、反対2 への応答として成り立っていない。高-1 はこの定義の欠けから生じた
- **補足**: 引き継ぎ文書が無い場合は、既存の記録の欠落(`aggregate-evidence.mjs:3306`)が名を下げる。「無いときは下げない」が効くのは、実際には G-7 を省いた構成と期間の集約に限られる。理由の文はこれに触れていない
- **直し方の案**: 「解けない」を決定可能な一覧で定める(高-1 の案の2)。(2) の非対称の文は、採らない理由ではなく、下げない場合に注記を出す理由として書き直す。逆向きの見落としを注記で開示する、という関係にする
- **2.3 の他の行**: 1行目(欄を足さない)の理由は成り立つ。契約検査で食い違いを落とすには記録を読む必要があり、欄は写しになる。3行目(禁止の組に限る)も成り立つ。標準 第3章 3.5.3 は、条件1 を「人の単位の兼務を認める場合(3.5.2 の例外を含む)にも当てる」と書く(`roles-responsibilities.md:589`)。このため、D-1 の下で開発者 × 出荷判定者の担い手が同じアカウントを申告しても、離脱に数えることと矛盾しない

### 中-3 範囲の終点の記録は読める。「読めない」とした前提が誤り

## 裁定どおりか(観点ごとの結論)

- **構成に欄を足していないか**: 足していない。`process.config.json` の欄と `/process-change` は変わっていない。`claimStatus` は既存の `separations` と `performerAccount` だけを読む

- **名を下げる向きの誤り**: 書き崩れと層1 の欠けで下げる(高-1)。記録が無い場合(J、引き継ぎ文書なし)は下げず、注記に出す
- **表示と実態**: IMPL-0521 の「記録が無い・解けないときは名を下げず」と、構成書の注記の「読めないときは数えません」は、B・C・D・K で実態と食い違う(高-1)。終点の記録は「読めない」とした前提が誤り(中-3)
- **ADR-0147 と既存の ADR**: ADR-0133 とは矛盾しない。決定4(受容しても離脱は消えない)と同じく、集約は受容を見ずに数える。ADR-0029 とも矛盾しない。3.5.3 の条件1 は、3.5.2 の例外の下でもレーンを分けることを求める。ADR-0081 決定6(委任の停止)は、同じ `holders.length <= 1` を数えない保持者も含めて使う(`autonomy.mjs:822`)。高-1 を「下げない」向きで直すと、委任の停止と名で、同じ記録の読みが分かれる。分かれることは許されるが(帰結が違う)、ADR-0147 に書く。採用済みの ADR の本文は書き換えていない(ADR-0083 は参照だけ)
- **人の欄**: ADR-0147 に承認者などの人の欄は無く、AI が埋めた欄は無い。試験の記名は架空の名簿の人で、採用者の欄ではない
