# #354 の残り3マーク(IMPL-0120・IMPL-0309・IMPL-0986)の起案(束 B12・軽・起案委員)

審議の段: 軽。外部の調査は不要(新しい義務を課さない。既存の ADR と実装の突合だけ)。

## 0. impl-plan-issues の仕組み(確かめたこと)

- `scripts/check-impl-plan-issues.mjs` は `src/content/docs/` の実装マークから `issue=` を読み(`scripts/lib/plan-issues.mjs` の `marksWithIssue`)、番号が閉じている・実在しない・PR のときに失敗する。`npm run check` には入っておらず、main への push 後のワークフローで走る(#354 を閉じて落ちた run 44019116097・44025188001 の原因)
- `--issue 354` は gh を使わず、`issue=354` を持つマークを列挙して、1件以上で終了コード 1、0件で 0。**案を採って3件の `issue=` が無くなれば、緑になる**(`state=delivered` は `issue=` を持たない。`plan=adopter` は `decision=` を持ち `issue=` を持たない)
- 付け替え先を open の Issue にしても緑になるが、規定が降りない。後継は既存の open の Issue へ寄せる運用に従う前に、まず降ろせるかを問う
- `plan=adopter` の条件(`check-impl.mjs`・`implementation-marking.md`): 節が `impl-no-adopter.yaml` の登録に当たらないこと(1.10.x と G-8 は当たらない。確認済み)、`decision=` が記録の所在を指すこと。採用者に委ねる理由と求めることは、`decision=` が指す記録に書く

## 1. IMPL-0120(適用の表明に併記する事項の様式)

3問への答え。
1. 条文が求める結果は、併記する事項(従う版と作業中なら配布物のコミット、未達と記録の欠落の件数、逸脱と列挙に無い離脱の一覧、例外承認の件数)が表明と同じ場所に出ること。文を書くのは人(責任者の名義で述べるため)。機械が出すのは**値**までとする
2. 例外承認では受けられない。転記の誤りで適合の主張の信頼が崩れる(3問目)
3. 破られたとき失うのは、受け手の適合の主張への信頼。転記の誤りで件数が食い違うことは現に起こりうる。決定可能な値の出力なので、機械にできる

案: **(a) 機械の出力として降ろす(値の行まで)**。新しい規則は足さず、集約が既に持つ値を1行にまとめる。
- `template/scripts/gate/aggregate-evidence.mjs` の品質レポート「5. 残存リスク…」(6176 行付近)に、既存の「この範囲で述べられる名」「範囲の第7章の例外承認の件数」の行と並べて、「適用の表明に併記する事項」の1行を足す。値は `evidence.claim` と `A.residual` から取る
  - 従う版(`claim.edition`)。作業中の版のときは標準のコミット(`source.commit`)を添える
  - 未達のゲートの件数(`claim.unmet.length`)と、記録の欠落の件数(集約の gaps の合計。実装者が既存の出力から数え方を1つ選び、数えない種別を同じ行に書く)
  - 逸脱の一覧と列挙に無い離脱の一覧(`claim.listedDeviations`・`claim.unlisted`)
  - 例外承認の件数は IMPL-0573 の行を参照する(重ねて数えない)
- `evidence.claim` へ同じ値を `statementFacts` として出す。**表明の文そのものは出さない**(責任者の名義を AI が書かない)
- 試験: 違反と適合の対(作業中の版でコミットの識別が欠ける構成は「識別なし」と出る / 発行済みの版で未達が1件の構成は件数1と出る)を `test-edition-end.mjs` に足す。`check=machine test=...`
- 降ろさない部分(理由つき): 表明の**文の型**(どの語で述べるか)は標準 1.10.2 と附属書 H.8 が正で、template は複製しない。文を書いたこと・件数を書き写したことは manual のまま。note に「確かめる者: 表明する者」と書いて開示する
- マークの変更: `undelivered` から `delivered`、`check=machine`、`issue=`/`plan=`/`review=` を外す。note を「値の行は出す。文は出さない」へ改める

代案と却下: 全面を adopter にする案は、値の出力が集約に既にあるので採らない(転記の誤りの余地を残す理由が無い)。表明の文を機械が書く案は、名義の問題と ADR-0083 の「表明する者が述べる」に反するので採らない。

## 2. IMPL-0309(同じ案件で適用を再開する経路)

3問への答え。
1. 満たすべき結果は、再開した場合に終了と再開の間が記録の欠落として表示され、件数が最初の開始から数えられること(標準 1.10.4)。手順は手引きでよい
2. 例外承認には当たらない(再開は第7章の対象でない)。ただし、**再開は新しい案件として始め直す**道が既にある(適用の単位は案件)。同じ案件の再開は稀
3. 破られたとき失うのは再開後の件数の信頼。ただし template は終了の後の構成の変更を notice のほかは拒むので、**黙って再開することは起きない**(安全側に倒れている)。再開の経路を機械にすると、終了の記録を覆せる操作が増え、1つの事象という定め(ADR-0083 決定2)を弱める

案: **(d)+(c) 降ろさず、`plan=adopter` で開示する**。
- マーク: `state=undelivered check=manual plan=adopter decision=<新 ADR>`。ADR-0083 決定2 は「再開の経路は持たず、undelivered として表示します」と記録しているが、採用者に求めることを書いていない。採用済みの ADR は書き換えないので、新 ADR(4 節)に採用者に求めることを書く
- 求めること(新 ADR): 再開する採用者は、終了と再開の間を記録の欠落として表示し、件数を最初の適用の開始から数え、その確認を表明する者が手で行う
- 手引き(c): `template/README.md` 460 行の「同じ案件で適用を再び始める記録は、まだありません。」の後ろに1文足す(「再開する場合は標準 第1章 1.10.4 に従い、終了と再開の間を記録の欠落として表示し、件数を最初の適用の開始から数えます。この確認は表明する者が手で行います」)
- 採らない案: `/process-change` に種別 `resume` を足す案。終了の記録を覆せる操作が増え、ADR-0083 決定2 と ADR-0068 決定3(途中の状態を置かない)の型に反する。頻度(稀)に比べ、定義が増える

## 3. IMPL-0986(配備の資格情報を参照に結び付けていない構成)

3問への答え。
1. 満たすべき結果は、配備の資格情報を参照に結び付けていない構成が列挙に無い離脱として数えられ、7.3 の例外承認を経たものは離脱に数えず例外承認の件数に数えられること
2. 例外承認が既に受けている部分がある: 「例外承認の件数に数える」は IMPL-0573(delivered)の集約が台帳の行から数える。残るのは「離脱に数える」側だけ
3. 破られたとき失うのは適合の主張の信頼と、配備(取り消せない操作)の統制。細かく書くに値する。ただし**template は配備のワークフローを持たない**(ADR-0090 決定6。IMPL-0985 は adopter)ので、離脱を読める記録が template の側に無い。残る手段は構成に自己申告の欄を足すことだが、これは ADR-0147 決定1 が採らなかった型(記録の正本が2つになり、自己申告の値が記録の示す離脱を隠しうる)と同じ

案: **(d) 降ろさず `plan=adopter` で開示する**。#329 の T-1(構成に欄を新設)は採らない。
- マーク: `state=undelivered check=manual plan=adopter decision=<新 ADR>`。note は「述べられる名は、この離脱を数えない。構成に欄を足さない(理由は新 ADR と ADR-0147 決定1)。確かめる者: 配備のワークフローを足す採用者(配備の資格情報が参照に結び付いているか、結び付いていなければ 7.3 の例外承認があるかを、表明の前に確かめる)」へ
- 採用者に求めること(新 ADR): 配備のワークフローを足すときに、IMPL-0985 の突き合わせと同じ時点で確かめる。結び付けていない構成で適合の主張を述べない。例外承認を経たものは、台帳の区分「例外」の行(対象が配備のワークフローと配備先)に残す
- #329 への申し送り(コメント): T-1 は採らない。T-2 の README の語は、`template/README.md` 659 行が G-8 の2つの形で既に書き改めてあるので、残りの語があるかを実装の担当が確認する。T-3・T-4 は #445、IMPL-0987 は #329 のまま
- 付け替えの代案(`issue=329` へ付け替え、scheduled のまま持つ)は、降ろす見込みの無い項目を計画に積む形になり、先送りになるので採らない。ただし議長が「欄を足す」を採るなら、この案を使う(#329 は open で、本文の範囲「G-8 の成立条件と配備の統制」と合う)
- 弱点(開示): 離脱の検出が採用者の確認に依る。述べられる名は、配備の資格情報の離脱がある構成でも「適合の主張」と出しうる。note と新 ADR に明記し、台帳に出し続ける。IMPL-1004(#446)が認証情報の離脱の機械の外の部分を manual で開示する扱いと同じ型
