## 5. 後継の Issue の下書き(起票していない)

### 案1: 実際の GitHub 上での持ち込みの検証の計画(node・python・go)

- 目的: 保守者が用意した典型的なリポジトリ(node・python・go。既存の CI・ブランチ保護・`CODEOWNERS` を持つもの)へ準拠テンプレートを持ち込み、出荷までを通す。`env-check` が実環境で6項目とも確認済みか対象外に至った記録を、少なくとも1件ずつ残す
- 確かめること: 事前点検の止める・告げるの分け方(EV-0167)、4値と項目の読み方(権限の範囲・API の形。EV-0168)、必須チェックの発行元 `integration_id` を固定するか(R-4)、G-8 ごとの機械の読み取りの設計(IMPL-0324)
- 受入基準: 言語ごとに、持ち込みの手順に無い作業の一覧と、`env-check` の記録(確認済みに至らなかった項目と理由)が `research/` にある。EV-0169・EV-0170 の差し替え条件の材料になる
- 関係: EV-0107・EV-0169・EV-0170、IMPL-0324(`issue=315` を本 Issue へ付け替える)

### 案2: 既定ブランチが `main` でないリポジトリへの対応

- 背景: `gate-g5.yml` の push の契機が `main` 固定のため、事前点検は既定ブランチが `main` でないリポジトリを止める(R-2)。改名できないリポジトリ(外部の連携が既定ブランチ名に依存する等)は持ち込めない
- 論点: push の契機を構成から生成する案は、強制層のワークフローを案件ごとに変える経路を作る。契機を `${{ github.event.repository.default_branch }}` で書けるか、ルールセットの対象との組で確かめる
- 受入基準: 採る方式と採らない方式を ADR に残し、事前点検の止める項目を改めるかを決める

### 案3: python アダプタの前提と複数スタック(#330 と重なる)

- 背景: python アダプタは `pip install -e ".[dev]"` とリポジトリ全体への ruff を前提にする。既存の python のリポジトリの構成(poetry・uv、部分的な静的解析)と合わない場合がある。複数のスタックを持つリポジトリは、構成のアダプタが1つしか持てない
- 論点: 事前点検が言語の目印を告げるだけで、アダプタの前提との突き合わせをしない。差分の網羅率(言語を跨ぐ共通の報告形式)を受け皿にするか
- 受入基準: #330 と範囲を分け、事前点検で前提の不一致を告げるか、アダプタを改めるかを決める

### 案4(案1 に含めてよい): G-8 ごとの実環境の機械の読み取り

- IMPL-0324 を降ろす。ship-evidence のワークフローへ渡す gh の認証(読み取りの権限の範囲)を決め、記名した確認の記録との乖離を検出の層として出す(確認済みには数えない)

### 案5: 出典カード SRC-0650〜SRC-0669 の原文の照合(突合 X-9)

- 背景: 13 件は要約を経て読んだもので、`quote` が無く、`verification.status: partial` である(台帳の規則では【二次】)。EV-0167・EV-0168 と ADR-0085 に二次情報である旨を書いた
- 行うこと: ネットワークの届く環境で `node scripts/research-ledger.mjs verify --ids SRC-0650,...,SRC-0669` で照合し、目隠し抽出で `quote` を埋める。SRC-0663(`bypass_actors` の鍵の欠落)と SRC-0666(CODEOWNERS の挙動)を先に行う

### 解釈で決めたこと(8 節)

1. X-17: 裁定は「旧来のブランチ保護で gate-g5 を必須にしている場合を確認済みとして読む」とした。旧来の保護が管理者に適用されない構成は、管理者が規則を通らずにマージできる。ルールセットのバイパスの主体を不一致とした決定4 と同じ扱いにするため、この場合は数えないとした。G-6 が有効な構成では、承認の規則(数・古い承認の失効・最後の push の後の承認・コードオーナー)も、ルールセットと旧来の保護を合わせて満たすことを求めた
2. X-2: 一覧の有無は、適用の開始のコミットの木で確かめる(`git cat-file -e`)。一覧の SHA-256 は記録に書くが、開始の後の一覧の変更とは突き合わせない(一覧は開始の後も改めうるため)
3. X-6: 取り込みの記名者が AI維持管理者の席の責任者その人であることは、確かめない(AI の名義でないことまで)。席の照合は、取り込みの PR を受ける AI維持管理者が行う。形式の版が現行でない構成の取り込みは拒否し、先に `migrate` を求めた
4. X-14: 既存の `CODEOWNERS` の判定は、効く1か所がテンプレートの置き場で、コメントでない行のパスの並びがテンプレートと同じなら、テンプレートの側とした。所有者の名は見ない。既存の `CODEOWNERS` が偶然 `* @team` の1行だけなら資産として告げない。その場合も、テンプレートの側で上書きすれば `@OWNER` で止まる
5. X-4: 「主系列の根」は `git rev-list --first-parent --max-parents=0 HEAD` の根とし、ほかの根を1件ずつ一覧の行にする。一覧の所在は `根のコミット <先頭12桁>` とした
6. X-2 の記録は IMPL-0319 に含めず、新しい IMPL-0327 とした。1.10.1 の要求事項(一覧と記名)を、開始の後に初期化を経ない経路で確かめる働きであり、事前点検の節に置く規定だからである
