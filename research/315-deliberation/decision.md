# 議長の裁定(#315 既存のリポジトリへ準拠テンプレートを持ち込む)

入力: `issues-context.md`、`survey-315-1-internal.md`、`survey-315-2-external.md`、`council-00-agenda.md`、`council-01`〜`05`。新しい ADR は ADR-0085。番号の起点は EV-0166・IMPL-0313・SRC-0650。

## 0. 全体の方針

- 規格の作法に従います。標準に置くのは、結果として判定できる要求事項です。持ち込みの手順は準拠テンプレートの文書に置きます。どの委員もこの分担には反対しませんでした(擁護者も、手順を標準に置かない点では一致)。
- 判断軸は「統制が黙って外れる経路を残さないこと」です。会議体と調査は、失敗を出さずに統制が外れる経路を5つ見つけました(目印の無い CLAUDE.md、フックの登録の欠け、CODEOWNERS の置き場の重なりと `@OWNER`、push の契機が `main` に固定、env-check の `checks-only` の穴)。どれも、手順の文書だけでは塞がりません。
- ADR-0068 決定7 の「手順の全体は定めない」は保ちます。ただし、「定め」の3件の位置付けと、持ち込みの要求事項の不在は、ADR-0085 で一部置き換えます。

## R-1 手順の置き場と、標準に置く要求事項

**裁定**: 標準(第1章 1.10.1 の適用の開始)に、持ち込みの要求事項を結果の形で置きます。手順はテンプレートの文書(`template-repository.md` の手引きの節と、テンプレートの README)に置きます。

要求事項(既存のリポジトリで適用を始める場合に限る):

1. 適用の開始の記録に、**既存の統制の資産の一覧と、資産ごとの扱い**を含める。資産は、エージェントの指示ファイル(`CLAUDE.md`・`AGENTS.md`・入れ子のもの)、CI のワークフローと必須チェック、ブランチ保護とルールセット、`CODEOWNERS`、カバレッジの測定、使う言語とアダプタ。扱いは「取り込む・置き換える・残して並存する・対象外とする」のいずれか
2. 扱いの確定は、技術判断の席の責任者(人)が記名で行う。AI は一覧を起案してよいが、扱いを確定しない
3. 初期化の事前点検が検出した資産は、一覧に現れなければならない(機械で照合する。一覧の網羅性を人の申告だけに頼らない)
4. 統制に効くファイル(指示ファイル・`CODEOWNERS`・強制層のワークフロー・フックの登録)が、テンプレートの規則を欠いたまま適用を始めない
5. 開始より前の履歴に、適合の主張を及ぼさない(1.10.1 の再掲ではなく、出所を問わないことの明記)

- 擁護者の「棚卸しは判定できない」への答え: 判定の対象は一覧の網羅性の申告ではなく、(a) 記録の有無と記名、(b) 事前点検が検出した資産との照合、です。どちらも判定できます。
- 規格の委員の「第8章の宣言に要求事項5を足す」は採りません。宣言は体制と構成の申告で、開始の記録とは時点が違います。持ち込みの棚卸しは開始の記録の一部として置く方が、ADR-0083 決定5(開始の時点)と一致します。
- 手順の全体を標準に置く案は採りません。根拠(実 GitHub での通しの検証、python・go の試行)が今も無いためです。段階の展開(資産ごとに順に適用する)は採りません。1.10.1 と矛盾し、部分的な適用を適合と読ませるためです。
- テンプレートの README 485〜494 行の2つの誤用は直します。記録の無い判定は「未達」ではなく「記録の欠落」です(ADR-0083 決定3)。更新の取り込みの判断は「例外承認等」ではなく、強制層の変更です(R-6)。
- 根拠: 外部(CMMI Adoption Guidance v4.0 の、現状の対応付け → 差 → 実際に使われているかの確認)、内部(事実1〜6)。要求事項1〜4 に実走の裏付けは無いため EV(E1。単一事例の手元の試行と、会議体の推論)を付けます。

## R-2 初期化の事前点検(検出し、止め、告げる)

**裁定**: 初期化の前に、何も書き込まない事前点検(`scripts/gate/preflight.mjs`)を置きます。`configured: true` を書く前に実行し、止める項目が1つでもあれば初期化は構成を書きません。点検は事実を読むだけで、設問の回答を検出の結果で埋めません(スキルの「ファイルから技術スタックを推測しない」規則と両立)。

| 区分 | 項目 |
| --- | --- |
| 止める | 目印の無い既存の `CLAUDE.md`。常駐の規則を欠く `CLAUDE.md`。テンプレートの入口でない独自の `AGENTS.md` と、入れ子の指示ファイル(扱いの記録が無い場合)。`CODEOWNERS` が2か所以上にある。`@OWNER` の残り。既存の `.claude/settings.json` に `guard-write` などテンプレートのフックの登録が無い。既定ブランチが `main` でない(`gate-g5.yml` の push の契機が `main` 固定のため)。共通の祖先の無い履歴の併合(根のコミットが2つ以上) |
| 告げる(一覧へ載せることを求める) | カバレッジの測定の欠落(`coverage` のスクリプト・集計ファイル)。アダプタの外の言語、複数のスタック。既存のワークフローとコミットの件数。`.gitignore` にテンプレートの行が無い |

- **初期化のフックの登録の欠け(現場 F-1・F-2)は欠陥として直します**。初期化は既存の `.claude/settings.json` へフックの登録を併合し、契約検査はフックの登録の存在を確かめます。禁止事項3 の機械の遮断が黙って外れる経路だからです。
- `@OWNER` の残りは、事前点検に加えて契約検査でも落とします。開始の後に戻した場合も止めるためです。
- 既定ブランチが `main` でない場合は止め、案内します。push の契機を初期化が書き換える案は、強制層のワークフローを案件ごとに変える経路を作るため本件では採らず、後継の Issue で検討します。
- **カバレッジの欠落は止めません**。G-5 の該当の基準が未達として表示されるため(ADR-0028)、黙っては外れません。品質保証の委員の「受容の記録が無ければ止める」は採りません。未達の表示と二重になり、止める理由になりません。
- **既存の違反の基準線(新規の違反だけを止める記録)は新設しません**。現場の委員は4条件付きで提案しましたが、閾値の緩和と機械で区別できず、基準を満たさないまま進める4つ目の経路になります(擁護者・品質保証・規格の3委員)。既存の違反は、未達・前提の受容・例外承認の既存の3経路で技術負債台帳へ載せます。カバレッジの不足は既存の `coverageScope: changed` で受けます。この却下を本文に明記します。

## R-3 併合した履歴と、適用の開始の境

**裁定**:

- 開始より前の履歴は、**出所を問わず**集約の対象の外とし、件数だけを「要求事項の対象外」と併記して出します。「テンプレート由来」の識別による免除はやめます。識別を誤ったときに製品の変更が開示から消える向きの誤りを生むためです。トレーラ・作者・ファイル一覧との照合による識別は採りません(トレーラは出所を証明しない。外部 SLSA Source v1.2)。
- 開始の境は、**既定ブランチの第1親の連鎖の上**で、`configured: true` の最初のコミットとします。併合した別の履歴の中にある `configured: true` のコミットを開始にしないためです(品質保証 V-4)。ADR-0083 決定5 を補います(書き換えない)。V-4 は実装の前に再現の試験で確かめ、再現しなければその旨を記録して規定だけを置きます。
- 開始の後に共通の祖先の無い履歴を併合した場合、その履歴のコミットは製品の変更として扱い、免除しません。擁護者・規格の委員の「安全側に数える」を採ります。
- 本件で新しい条項は 1.10.1 への1文(出所を問わない)だけです。

## R-4 実際の GitHub 上での検証

**裁定**:

- 検証の計画(誰が・どのリポジトリで・何を)は標準に置かず、後継の Issue と `research/` に置きます。保守者が用意した典型的なリポジトリ(node、python、go)で行います。
- env-check の結果を4値にします。**確認済み / 不一致 / 未確認(理由: 権限不足で読めない・実行していない)/ 対象外**。対象外を確認済みに数えません。読めた空の一覧と読めなかった場合を区別します。規格の委員の「2値に理由」は採りません。「対象外」と「確認済み」の重なり(V-1)がまさに2値の欠陥だからです。
- **`checks-only` の穴を塞ぎます**。G-6 が無効の構成でも、必須チェック `gate-g5` の適用を確かめます。既存の条項(附属書H 項目4、`gate-criteria.md` 597 行)に対するテンプレートの欠陥です。
- 確認の項目に、旧来のブランチ保護との重なり、効いている `CODEOWNERS` の所在と `codeowners/errors` の結果、ルールセットのバイパスの主体を足します。必須チェックの発行元(`integration_id`)の固定は、実走で確かめてから規定にします(後継の Issue)。確かめていないことは記録に書きます。
- 頻度: 人の記名の確認は、持ち込みの時点と強制層の変化点に行います。G-8 ごとに機械が読み取り、乖離を検出の層として出します(確認済みには数えない)。定期の再確認の周期は課しません(EV で開示)。
- EV-0107 を node と python・go に分け、差し替え条件に「env-check が実環境で確認済みに至った記録を少なくとも1件」を加えます(ADR-0045 決定1 の向きを書く)。
- Evaluate モードを前提にしません(Enterprise Cloud の文書にしか現れない)。

## R-5 旧い版で生成した構成の移行

**裁定**:

- 構成に**形式の版**(`formatVersion`)を持たせます。`schemaVersion`(ハッシュ連鎖の有無)の意味は変えません。契約検査は、知らない版(既知より大きい `formatVersion`・`schemaVersion` を含む)を拒否します(V-5・F-7)。
- 移行は `/process-change` の種別 `migrate` とし、版ごとに現行の版への直接の変換を持ち、PR で出します(Copier・Terraform の型)。移行はゲートの状態・席・閾値の値を変えません。値を変える必要がある場合(A-3 で落ちる構成など)は、記名を伴う構成の変更へ渡します。
- 読み込み時の既定値の補いは、結果が同じか厳しくなる場合に限ります。緩める向きの補いは移行の PR で人が確定します。
- 猶予の期間は置きません(A-3 の判断を維持。1.10.1 と ADR-0083 決定1 に矛盾し、成立しないと分かっている状態を通すため)。
- 版の欄の無い宣言と D-0 は遡って書き換えません。次に改めるときに版を書きます。
- 規格の委員の指摘(1.10.3 で旧い版の主張を続けられる一方、テンプレートは最新の検査で落とす)を採ります。テンプレートは、自身の検査が実装する標準の版を宣言します。要求事項の検査を変えるテンプレートの更新を取り込むことは、版の切り替え(1.10.3)と同時に行います。第1版の発行前のため、今は実害がありません。

## R-6 テンプレートの更新の取り込みと、既存の採用者を壊す変更

**裁定**:

- 構成に、取り込んだテンプレートのコミット(`template.commit`)を道具だけが書きます。あわせて、強制層のファイルの要約値を記録し、不一致を表示します(合否には使わない)。記録は来歴の主張であって証明ではないことを明記します。擁護者の「部分的な複製で証明にならない」はこの開示で受けます。値を持たない場合より、乖離を見える形にする方が信頼性が高いと判断します。
- 取り込みはファイルを複製する PR で行い、強制層の変更として扱います(`state:needs-platform`、陰性の確認)。取り込まないことは許します。取り込まないことは例外承認ではありません。
- 既存の採用者を落とす変更を出す保守者の義務(落ちうる検査と直し方の列挙、書き込まずに試す手段の同梱、猶予なし)を `community/standard-editions.md` に置きます。採用者への要求事項ではなく、保守の手続です。
- テンプレートの git のタグは要求しません(コミットで足りる)。
- 配布物の真正性と受け取り側の検査は #332 へ渡します。本件は記録と告知までです。
