# #334 起案の委員の意見

立場は信頼性である。頼った結果、手戻りが減り、決めるべきことが漏れないかで選ぶ。変更量の少なさは理由にしない。

## 論点1 判定記録の整合の検査を PR の時点で走らせるか

### 推す案: 1-A(出荷の集約のまま)に「PR の時点では課さないと決めた」を明記する

### 理由

- 判定記録は PR の時点で基底に無いのが通常である。判定者が `records` ブランチへ直接 push し、基底の `docs/gates/` へは出荷の PR が複製を運ぶ(research.md 2.2)。PR の時点で見る対象が構造上存在しない
- 1-B が足す価値は、`records` への直接 push には効かない(PR を経ない)。複製を運ぶ PR は既存の `verify` が集約を再実行して見ている。残る範囲は「機能 PR が `docs/gates/` を直接変える」場合だけで、その事例を実行で確かめていない。確かめていない欠陥のために検査を足すと、重複した検査が二箇所で食い違う保守の負担と、「PR で通ったから良い」という誤った安心を生む
- 1-C は実行で偽の失敗 16 件が出た(research.md 3.1)。出荷判定の完備確認を途中の PR に課すことになり、決定可能な条件では除けない。ADR-0106 の区分も変える。採らない
- 1-D は迂回できる統制である。機械でも必須でもない手順を「統制」と呼ぶと、読み手が検査があると誤解する。採らない
- #254 の突合が既に「check-pr は判定記録を読まない。空欄の判定記録は出荷時まで機械では止まらない」と開示している。これを標準の本文(第4章)に「課さないと決めた」と書き直すことで、「書かれていない」と「課さない」の区別が付く。これが成果である

### 変更の所在

- 標準 第4章の判定記録の帰属を述べる節(ADR-0106 の区分に隣接する `gate-criteria.md` L118 付近)に、判定記録の整合(欄・空欄・日時の前後関係)の機械の確認は出荷の集約(G-7)で行い、PR の時点では課さない旨を1文。ADR-0106 の補足として足す。新 ADR は不要(原則を変えない)
- 空欄の判定記録が出荷まで main に残りうる残余リスクは、根拠水準マークではなく、実装マークの note へ書く(既存の IMPL に紐づく。新規 IMPL は作らない)
- template は変更しない。state は既存のまま(集約が delivered)

### 反論への答え

- 「空欄が出荷まで残るのは信頼性に欠ける」: 残るが、出荷判定(G-7)で必ず止まる。止める場所が出荷にあり、途中で止める効果は偽の失敗の常態化と引き換えになる
- 「1-B は害がない」: 害は小さいが、効果が実証されていない。実証されたら #355 または新規の欠陥として起票する

### 採らない案

1-B(重複と未実証)、1-C(偽の失敗。重)、1-D(迂回可能で統制にならない)。

## 論点2 G-4 の版から受入基準・前提・スコープ外が変わったのに判定記録が無い状態

### 推す案: 2-A(出荷の集約で拾う)を閉じの統制とし、2-B(PR の時点では差分の表示だけ・合否にしない)を足す。条件付き

### 理由

- 閉じの統制は 2-A である。出荷の時点では判定済みか未判定かが確定しており、「版の識別子を解析 → `git show <版>:specs/F-NNN/spec.md` の3節と現行の3節の文字列比較 → 差分後の G-4 判定記録の有無」はすべて決定可能(値の一致・存在・構文)である。自由な文の意味は見ない。差分が意味を変えるかの判断は人に残し、manual と開示する
- 2-C は採らない。差分があって G-4 の承認レビューが無い状態は、PR の時点では通常の「判定待ち」と区別できない。判定者が承認するまで必ず失敗する。ADR-0078 の 2.10.8(受け直しのために内側のループを止めない。逸脱は未判定の版のまま次の工程ゲートへ進むこと)と X-1 に反する。区別できない条件を機械の合否にしない、という原則による
- 2-D は採らない。K-1 の機械の確認を削ることになり、IMPL-0107 の残り(確定の後の変更)が manual のまま、誰も見ない状態に戻る
- 2-B を足す理由は、手戻りの低減である。受け直しを忘れた版は出荷の集約まで見つからず、後ろの工程の成果物が未判定の版の上に積み上がる。PR の時点の表示は、差分の検出が決定可能で、判定の有無を読まないので偽の失敗が出ない
- 2-B は新しい義務にならない。表示のみで、合否・必須チェックにしない。したがって軽のまま閉じられる(intake.md の(b))。重へ上げる必要はない

### 条件(2-B が成立するための歯止め)

- 確定前の仕様を編集する PR(G-4 の前の草稿)で毎回表示すると雑音になる。表示の対象は、base の `spec.md` の `## 承認` 表に G-4 の通過の行が在る場合だけに絞る。この行の存在は決定可能である。この絞り込みが実装で決定可能に書けないなら、2-B は採らず 2-A のみとする
- 表示が見られたかは確かめられない。表示を見て動くのは manual であり、実装マークの check は manual とする

### 変更の所在

- 標準 第4章「確定した版を変える場合」の節(適用: G-2/G-4 の確定した版がある機能)に、機械の確認の置き場を明記する。出荷の集約が閉じの確認、PR の時点は表示のみで合否にしない、合否にしない理由は2.10.8。第2章 2.10.8 の本文は変えない(整合を確かめるだけ)
- 実装マーク IMPL-0241: `state=undelivered check=manual issue=355` のまま。集約の実装(版の解析と節の比較)が済むまで undelivered。note に「PR の時点の表示は別の IMPL」と書く
- 2-B を採る場合は、新規の実装マークを1件足す。target は check-pr.mjs の降ろし先(`src/data/impl-targets.yaml` に実在するもの)、`state=undelivered`、check=manual、実装は check-pr.mjs の改修。#355 には混ぜない。起票は議長が決める
- template: `scripts/gate/check-pr.mjs` に、PR が変えた `specs/F-NNN/spec.md` の3節の本文差分の検出と表示。`aggregate-evidence.mjs` に版の解析と節の比較

### 反論への答え

- 「表示だけでは効かない」: 効かない場合があるのは認める。合否にすると判定待ちと区別できず、2.10.8 に反する。効かない部分は出荷の集約が閉じる
- 「実証が無い」: 差分の検出が決定可能という判断は条件の分析で、判定記録が在る状態の試作は行っていない(research.md 3.4)。根拠水準マーク(暫定)で開示する

### 採らない案

2-C(判定待ちと区別不能・2.10.8 に反する・重)、2-D(K-1 の削除)。
