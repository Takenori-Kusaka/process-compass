# #334 反対の委員の意見

立場: 検査を増やす方向への反対。判断軸は信頼性。作成 2026-11-15。裏取りは intake.md・research.md、`gate-criteria.md` L318〜330、`assurance-case.md` L938。

## 結論

- 論点1は **1-A を採る**。1-B・1-C・1-D は落とす
- 論点2は **2-A を維持し、2-B を条件付きで足す**。2-C・2-D は落とす
- 重へ上げる必要はない。1-A、2-A、2-B はどれも新しい義務を課さず、ADR-0106 と 2.10.8 に触れない

## 論点1 判定記録の整合

### 1-A 出荷の集約のまま(残す)

- 実行で確かめた事実が支える。判定記録の整合は、記録が揃った出荷の範囲でしか意味を持たない。PR の時点では判定記録が基底に無いのが通常である(research 2.2)。ADR-0106 は、判定記録を事後でよいと既に決めている
- 空欄の記録が出荷まで main に残る(事例1)のは実害である。ただし出荷判定 G-7 の前に必ず拾われる。残る危険は「出荷前に空欄が見えない」ことで、「出荷後まで見逃す」ことではない
- 付ける条件: 第4章または IMPL-0241 の note に「PR の時点では課さないと決めた」と理由付きで書く。#254 の突合は `research/` に記録が無いので、この明記が唯一の記録になる

### 1-B 構文だけを PR で見る(落とす)

- 判定記録は `records` ブランチへ直接 push され、PR を経ない。基底の `docs/gates/` へ入るのは出荷の PR だけで、そこでは既存の `verify` が集約を再実行している。新規の検査が働く場面が残らない
- 「空欄」「日時の前後」の定義が check-pr.mjs と集約の2か所に分かれる。定義が食い違えば、PR は通って出荷で落ちる。偽の合格は偽の失敗より悪い
- 「決定可能」ではあるが、働く場所がない。機能 PR に出る表示は、読む人のいない通知になる

### 1-C 集約を必須チェックに(落とす)

- 実行で 16 件の欠落が出た。どれも出荷判定の完備確認で、途中の PR で満たせない。常に赤いチェックは、検査を無視する習慣を作る。ADR-0106 の区分も崩す。重の対象だが、実行の事実だけで却下できる

### 1-D 手元の部分検査(落とす)

- 部分検査の入口が集約に無い(research 3.2)。入口を作れば、1-B と同じく定義が二重になる。迂回できる検査は統制に数えられない。作るなら manual と開示するだけで、統制の増分はない

## 論点2 受入基準の書き換え

### 2-A 出荷の集約で拾う(維持)

- 事後の検出という ADR-0036 の構造に合う。判定が済んだか未判定かが、出荷の時点で確定している
- 「決定可能」を保つ定式化を勧める。「判定記録の対象の版を解析し、その版の3節と現行の3節を比べる」より、**「最新の G-4 の判定記録が指す版の3節 = 現行の3節」** が決定可能である。「変わった」の判定を履歴の差分に頼らず、2つの文字列の一致に落とせる
- 決定不能が残る点が3つある。(a)対象が `PR #34` のとき、マージ後のコミットへの解決に `gh` が要る。squash や履歴の書き換えで版が消えることがある。(b)空白・改行だけの差を「変わった」と数えるか。正規化の規則を決めないと、偽の失敗か見逃しのどちらかが出る。(c)同じ機能の G-4 の記録が複数あるときの選び方(判定日時の最新)。この3点は実装で決め、決められない部分は manual と開示する
- 遅い点は認める。変更が main に入ってから出荷まで、判定を受けていない版が存在する。2.10.8 が禁じるのは「未判定の版のまま次の工程ゲートへ進むこと」で、その検出が事後になる。この窓は ADR-0106 の区分が受け入れたものと同じ種類である。開示は IMPL-0241 の `undelivered` を維持して行う
- 付ける条件: 試作で確かめるまで「決定可能」を実証済みと書かない。research 3.4 のとおり未実証なので、根拠水準マークで開示する

### 2-B 差分の表示だけ(条件付きで残す)

- 偽の失敗は起きない。合否に使わない表示は、IMPL-0187 の「G-5 が PR へ一覧を出す(合否に使わない)」と同じ型で、先例がある
- 落とし穴がある。PR の base は、G-4 で確定した版ではない。同じ機能の仕様を複数の PR で直す場合、base 自体が未判定の版になりうる。初稿の PR は毎回3節が変わるので、常時表示されて雑音になる。雑音の表示は読まれなくなる
- 付ける条件: (1) **base の spec.md に `## 承認` の記載が既にあるときだけ**表示する(文字の存在で決定可能)。(2) 表示の文言は「確定した版との差分」ではなく「この PR の base からの差分」と書き、断定しない。(3) 合否に使わない、正本は出荷の集約である、と書く。(4) これは**統制ではなく注意喚起**であり、IMPL-0241 は `undelivered` のまま残る。表示を足したから delivered とは言わない
- 効果は限られる。G-4 の判定は、その PR の承認レビューで行われる。承認者は差分をその場で読む。表示が守るのは、判定を経ずに別の PR で書き換わる経路だけで、その経路を止めるのは 2-A である

### 2-C PR で合否に(落とす)

- 差分があると、判定者の承認まで必ず失敗する。「判定待ち」と「受け直し忘れ」を機械では区別できない。2.10.8 の「受け直しのために止めない」と X-1 に衝突する。1名体制や委任の扱いも別に要る。新しい義務で重

### 2-D 置かない(落とす)

- `assurance-case.md` L938 は既に「機械は検出しない(出荷判定者の突合と内部監査による)」と開示している。2-D は現状を追認するだけに見える。だが IMPL-0241 を消せば、ADR-0028 の「未達を消さず表示し続ける」に反する。「書かれていない」と「課さないと決めた」の区別が、読み手から失われる。K-1 の機械の確認を、検討の記録なしに削ることにもなる

## 逆方向の正直な指摘

- 1-A と 2-A だけでは、判定を経ない版が main に滞留する窓を、機械では閉じない。窓の長さは出荷の間隔に等しい。これは信頼性の欠点である。閉じる手段が 2-C しかなく、2-C は判定待ちと区別できないので、採らない。残る窓は開示で受ける
- 2-A は #355 の実装が済むまで `undelivered` である。済むまでの間、L938 の開示と出荷判定者の突合が実体の統制になる。その旨を IMPL-0241 の note に書く
