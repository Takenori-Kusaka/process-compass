### 論点2 確定した版からの受入基準・前提・スコープ外の変更を PR の時点で検出するか

1. **閉じの統制は出荷の集約(2-A・IMPL-0241)のまま**。実装は #355。`state=undelivered` を保つ

## 2. 理由

### 2.1 論点1

- 判定記録は、様式は `records` ブランチへ直接 push され、基底(`docs/gates/`)へは出荷の PR が複製を運ぶ。PR の時点の基底に見る対象が無い(research 2.2)
- 集約を PR で走らせると、判定記録の整合と無関係な欠落 16 件で失敗した(research 3.1。実行で確かめた事実)
- 1-B が働く場面は、既存の `ship-evidence-verify` と重なる出荷の PR だけである。「空欄」「日時の前後」の定義を2か所に持つと、PR で通って出荷で落ちる食い違いを作る(反対の委員)
- 残る危険(空欄の判定記録が出荷まで残る)は G-7 の集約で必ず止まる。この窓は開示する

### 2.2 論点2 で合否にしない理由

- G-4 の判定は、その PR の承認レビューとして**後から**付く。差分があって判定が無い状態は、PR の時点では「判定待ち」と「受け直しの欠け」を区別できない。区別できない条件を機械の合否にしない
- template に同じ理由の先例が既にある。`check-pr.mjs` 冒頭の検査8(G-6 の承認者の数)は「合否にはしない。pr-rules はレビューの前に走り、承認はその後に付くため、失敗にするとすべての PR が承認まで赤になる」と書く(L88〜93)
- 第4章「確定した版を変える場合」L328 は、受け直しのために内側のループ全体を止めないと定める。合否にすると判定まで必ず止まる

### 2.3 2-B の条件を改めた理由(実物を読んで分かったこと)

委員の条件(基底の `## 承認` の表の G-4 の通過)は決定可能だが、表示の絞り込みに使うと**黙って出ない場合**を作る。信頼性の側で劣る。

- `spec.md` の `## 承認` の表を読むスクリプトは template に1つも無い(`scripts/` を grep して確認。`approved_at` を読むのは D-0 用の `check-d0.mjs` と `generate-profile.mjs` だけ)。様式自身が「本欄は転記であり、判定記録を正とします」と書く(`templates/01-feature-spec.md` L85)。誰も確かめない転記を条件にすると、転記を忘れた仕様で表示が出ない
- 様式の初期値のセルは `通過 / 差し戻し / 未判定` で、「通過」の文字を含む(L83)。委員の「記載が既にあるとき」「文字の存在」では、未記入の様式がすべて当たる
- 承認の後に表を埋めるコミットを同じ PR へ足すと、PR の先頭が承認レビューの `commit_id` からずれる(IMPL-0129 はこのずれを「確定していない版を取り込んだ」として欠落に数える)。したがって表は、別の PR で後から埋まるか、埋まらない。**この点は台帳の文からの推論で、実行では確かめていない**
- 標準は、G-2 だけを通過した仕様の3節の変更にも G-4 の判定を求める(L319・L325、IMPL-0241 の note「G-2 または G-4 で判定した版」)。G-4 の行で絞ると、この場合に出ない

改めた条件(分岐点にファイルが在る)は、委員が挙げた雑音(初稿の PR で毎回出る)を除く。初稿は分岐点にファイルが無いためである。残る雑音は「判定を受けないまま基底へ入った草稿の変更」で、表示の文を条件つき(「基底の版が通過した版なら」)にして受ける。**黙って出ないより、条件つきで出るほうを採る。**

「いま実装して実行で確かめられるか」: 確かめられる。`analyzePr` は分岐点と先頭のファイルを読む関数(`atBase`・`atHead`)と変更の一覧(`all`)を既に持ち、`test-check-pr.mjs` の `scenario()` で違反と適合の対を足せる。判定記録・`gh`・`records` ブランチを要さない。

### 2.4 ADR を新設しない理由

- 基準は「あとから変えにくい決定か」。本件が決めるのは検査の置き場で、原則を足さず、既存の決定(ADR-0036・0078・0106)と本文 L328 から導ける。記録の経路が変われば(例: 判定記録が PR を経る構成)、後の Issue が実行の事実で見直せる
- 見直して 2-C・1-C を採る場合は、新しい義務で重になり、その時点で ADR が要る。本件の「課さない」は、その審議を妨げない
- 「課さないと決めた」は、第4章の本文に理由つきで置けば、読み手が「書かれていない」と区別できる。ADR-0078 の本文は書き換えない

### 5.2 template

**(1) 新しいファイル `scripts/gate/spec-sections.mjs`**(節の取り出しの定義を1か所に置く。#355 の集約が同じ定義を使えるようにし、反対の委員の「定義の二重化」を避ける)

- `export const SPEC_FILE = /^specs\/F-\d+\/spec\.md$/`
- `export const CONFIRMED_SECTIONS = ['受入基準', '前提', 'スコープ外']`
- `export function specSections(text)` → `{ 受入基準: string|null, 前提: string|null, スコープ外: string|null }`
  - 改行を LF に揃える
  - コードフェンス(行頭が ``` または ~~~ の行で開閉)の中の行は見出しに数えない
  - 節の見出し: フェンスの外で `^##\s+(受入基準|前提|スコープ外)\s*$` に一致する行(階層2、見出しの語は完全一致。様式 `templates/01-feature-spec.md` L19・L33・L40 の形)
  - 節の本文: 見出しの次の行から、フェンスの外で `^#{1,2}\s` に一致する次の行の直前まで(無ければ末尾まで)
  - 同じ見出しが複数あれば、出現順に本文を改行でつなぐ
  - 比較の形: 各行の行末の空白を除き、先頭と末尾の空行を除く。それ以外(行内の空白、途中の空行、表の整形)は変えない
  - 見出しが無い節は `null`。`text` が `null` なら3節とも `null`
- `export function changedSpecSections(baseText, headText)` → 一致しない節の名の配列(`null` と文字列の不一致、文字列どうしの不一致)

## 8. 統制の閉じ方

| 統制 | 別 | 根拠・開示 |
| --- | --- | --- |
| 判定記録の整合(欄・空欄・日時の前後・台帳の欠落) | machine(出荷の集約。既存) | PR の時点では課さない(本裁定)。出荷までの窓は標準の文で開示 |
| 確定した版から3節が変わった機能に、変更後の版の G-4 の判定記録が在ること | 現状は manual(出荷判定者の突合)。machine は IMPL-0241 `undelivered`(#355) | `assurance-case.md` L938 と IMPL-0241 が開示 |
| PR の時点の表示が、条件の PR で出ること・合否を変えないこと | machine(IMPL-0520、`test-check-pr.mjs`) | 条件は存在と文字列の一致だけ |
| 表示を読んで G-4 の判定を受けること | manual(G-4 の判定者・提出者) | IMPL-0240(gate-skill)が既に manual で持つ。表示の効果は EV-0260 で開示 |
| 基底の版が判定を通過した版か、変更が意味を変えるか | 機械にしない | 自由な文の意味と、基底に無い判定記録に依る。表示の文で「確かめていない」と書く |
| 採用者へ委ねるもの(adopter) | なし | 新しい義務を課さない |
