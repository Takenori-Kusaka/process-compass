# 会議体 委員12 現場(#357 重の審議)

- 日付: 2026-11-12
- 立場: 現場。1〜2名の体制、受託(発注側・受注側)、3〜9名、10名以上の採用者が、実際に欄を埋め、検査に当たったときに何が起きるか(記入の負担、誤記入、迂回、止まる現場)から評価する。問いは「現場で信頼性が上がるか」
- 入力: `council-10-agenda.md`、`intake.md`、`survey.md`、`survey-external.md`。標準の本文は所在を示した箇所を読んで確かめた。他の委員の意見は読んでいない
- 表記: 所在は `ファイル:行`。【推】は推測。判断軸は信頼性で、変更量の少なさを理由にしない

## 現場の見方の前提(全議題に共通)

1. **黙って捨てる・黙って通す挙動が、現場の信頼性を最も下げる**。採用者は「書いた・通った」ことを「確かめられた」と読む。E7(未知の欄だけの変化点が `result=no-change` で記録される。`survey.md:334`)と E5(制限の範囲を書いても残らない。`survey.md:108`)は、記入した本人が穴に気づけない形である
2. **「external」の語の誤読が最も起きやすい誤記入である**【推】。受託の受注側の採用者にとって、発注側の人は文字どおり「社外の人」なので、名簿に `external: true` と書く。標準の「外部の確認者」(3.5)は「体制の外で確認だけを引き受ける人」であり、別の意味である。X-1・O-1(`survey.md:357,367`)は、悪意ではなくこの読み違いで起きる。検査の文言で、この読み違いを名指しで正す必要がある
3. **自己申告の値で「満たす」と表示すると、現場はその表示を根拠に判断を止める**。表示が確かめた範囲を超えない形を選ぶ
4. **止める検査は、直し方を1つの操作で示せる場合に限って置く**。直し方の分からない停止は、構成の書き換えや検査の迂回を招く【推】

## 議題1 外部の確認者を責任者に置ける席の限定(論点 E、IMPL-0463、X-2)

### 1-a 拒むか、置き場

- **結論: 採る(拒む)。置き場は変化点の入口と、構成の整合(namingProblems → 集約の欠落)の両方**
- 理由
  - 条項は既に確定している(`roles-responsibilities.md:418`)。穴の帰結は人数の誤り(X-1)に留まらず、氏名の確認で本人の記名が有効になる(O-1、`config.mjs:487-491`)。人数の誤りは、兼務禁止・G-6 の適用・氏名の確認の3つへ連鎖する
  - 入口だけで拒むと、既に該当する構成は出荷の証跡の集約を通り続ける。誤った人数のまま保証の開示が出る。任命権者の前例(`config.mjs:1515-1525`、集約でも欠落)と同じ置き場にするのが、採用者から見て一貫する
- 現場で起きること
  - 1名・受託(受注側): フリーランスの開発者が、発注側の担当者を価値責任者に置き、「社外の人」として `external: true` と書く(E1c と同じ形。`survey.md:147`)。現在は通り、体制は1名と数えられ、氏名の確認を本人の記名で済ませる。拒否が入ると、初回の記入で止まる。**拒否の文言が「発注側の人も体制の内(external: false)として載せる。外部の確認者は独立レビュアの席にだけ置ける(第3章 3.5)」と言えば、1回の書き直しで直る**。文言が「external の人を置けない」だけだと、採用者は発注側の人を名簿から外す・独立レビュアに付け替えるなどの迂回をする【推】
  - 3〜9名・内製: 社外のコンサルタントを出荷判定者に置いている構成(確認1a)。拒否されると、社内の人へ付け替えるか、コンサルタントを体制の内として数えるかを決めることになる。これは本来の判断であり、止まってよい
- 採らない案
  - 入口だけで拒み、既存の構成は注意にとどめる: 既存の構成が誤った人数のまま出荷を続け、保証の開示が実態と食い違う。注意は読まれずに流れる【推】。採らない
  - 拒まず、外部の確認者を人数に数える(区分の印を無視する): 外部の確認者を独立レビュアに置く(イ)の効果(人数に数えない、`roles-responsibilities.md:420`)と両立しない。採らない
- 新しい義務: 無い(条項は既存)。機械の強制が新しい
- EV: 不要(条項の効果は既存の規定の帰結)

### 1-b 外部の確認者が D-0 表1 の決定者になる経路(X-2)

- **結論: 採る。IMPL-0463 の範囲として明記し、同じ拒否で塞ぐ**
- 理由: 事業決裁者の席は「ほかの席」(`roles-responsibilities.md:418`)に含まれ、1-a の拒否で同時に塞がる。ただし、IMPL-0463 の note が人数だけを書くため(`roles-responsibilities.md:425`)、採用者と後の審議者は、決定権の穴が残っていたことと、それを塞いだことを読めない。:417 は独立レビュアの席の外部の確認者だけを対象にするので、この経路は 1-a でしか塞がらないことを note に書く
- 現場で起きること: 小さな会社で「社長は社外取締役で、名目上の決裁者」という構成を `external: true` で書くと、その人が緩める向きの決定権を持つ(E1b、`survey.md:146`)。採用者はこれを穴と思っていない。拒否の文言に「事業決裁者は D-0 表1 の決定者であり、体制の内の人とする」と書く
- 採らない案: allowedDeciders で外部の確認者を全席の決定者から除くだけにする(席の配置は許す): 人数の誤り(X-1)が残る。採らない
- 新しい義務: 無い
- EV: 不要

### 1-c 既存の構成の移し方

- **結論: 条件つきで採る。「区分を体制の内へ改める」変化点を1回で受け付け、直し方を拒否の文言に出す**
- 現場で起きること・条件
  1. **記名者**: 区分を内へ改めることは締める向き(人数が増え、本人の記名による氏名の確認が無効になる向き)である。D-0 表1「体制と運用形態」の決定者の記名で受け付ける。その決定者自身が外部の確認者として載っている場合(X-2 の構成)も、締める向きなので、その人の記名で受け付けてよい。ここを拒むと、決定者が誰もいない構成になり、採用者は直す手段を失う
  2. **人数の境界をまたぐ場合**: 1名→2名、2名→3名以上へ移ると、チーム規模の回答と名簿が食い違う(headcountProblems、`config.mjs:1608-1618`)。区分の改めとチーム規模の回答の改めを**1つの変化点で**通せるようにする。2回に分けると、間の状態で別の検査(兼務禁止、G-6 の適用)に当たり、採用者は順序を探して止まる【推】
  3. **過去の記録**: 1名と数えていた期間に本人の記名で済ませた氏名の確認を、遡って無効にしない。改めた変化点から先に新しい数え方を当て、保証の開示に「区分を改める前の期間の氏名の確認は本人の記名による」と残す。遡って無効にすると、過去の出荷の記録がすべて欠落に落ち、採用者は記録を書き換える動機を持つ
- 採らない案: 猶予の期間を置き、その間は注意にとどめる: migrate の「猶予の期間は置かない」(`template/.claude/skills/process-change/kinds/migrate.md:9`)と食い違う。猶予は期限まで放置される【推】。採らない
- 新しい義務: 無い
- EV: 「遡って無効にしない」は判断であり実証が無い。要らない(過去の記録の扱いは ADR-0109 の検出の原則の帰結として書ける)

## 議題2 3名以上の体制で外部の確認者を独立レビュアの席の責任者に置く扱い(論点 F)

- **結論: 認める。(イ)の3条件を人数によらず掛ける**
- 理由
  - 3〜9名の体制では、独立レビュア × 開発者の兼務を拒む(`roles-responsibilities.md:382-386`)。3名全員が開発をする小さなチームでは、独立レビュアの席に座れる内の人がいない。外部の確認者(社外のセキュリティ専門家、親会社の別部門)を席に置けないと、採用者は開発から形式上外した名ばかりの内の人を独立レビュアに置く【推】。これは独立を下げる迂回である
  - 3名以上で(イ)の条件を掛けない読みを採ると、3名未満より3名以上の方が外部の確認者を席に置きやすくなり、規模に対する統制の向きが逆になる
  - テンプレートは既に3名以上で受け付けている(E2、`survey.md:188`)。認めない場合は、今通っている構成を落とすことになり、上の迂回を誘う
- 現場で起きること
  - 3〜9名・内製: 外部の専門家を独立レビュアの責任者に置く。任免の記名、3.4.1 の力量の確認、書面の合意の3つを記録する(議題3)。合意は委託契約の条項の写しで足りることが多い【推】
  - 10名以上: 外部の確認者を独立レビュアの席に置く必要は少ない。置くなら同じ3条件
  - 外部の確認者で人数を満たしたことにはならない(O-3、`survey.md:359`)。この挙動は維持する
- 採らない案
  - 3名以上では認めない: 上の名ばかりの迂回を誘い、既存の構成を落とす。採らない
  - 認めるが(イ)の条件は3名未満だけに掛ける: 規模の向きが逆になる。採らない
- 新しい義務: 3名以上で外部の確認者を席に置く採用者に、(イ)の3条件の記録を課す。**新しい義務である**。ただし今は「定めていない」空白(`roles-responsibilities.md:419`)であり、空白のまま受け付ける方が信頼性は低い
- EV: (イ)の3条件の根拠は EV-0104(E1)。3名以上への拡張は、規模で独立の条件を変えない規格の書き方(IEC 61508・ISO 26262 は人数でなく距離と力量で書く。`survey-external.md:143`)に支えられるが、本標準の体制での実証は無い。**EV を付ける**(E1、差し替え条件: 3名以上で(イ)を採った構成の件数と、名ばかりの内の独立レビュアの所見の件数)

## 議題3 (イ)の条件の記録(論点 A、IMPL-0116)

- **結論: 採る。構成の独立レビュアの席に、既存の `competence`(3.4.3)とは別の欄として、3.4.1 の力量の確認と書面の合意の記録の所在を持たせる。機械が確かめるのは記録の有無と形式まで**
- 理由
  - 置き場の候補のうち、テンプレ8 は受託だけの様式であり、1名の内製の採用者には存在しない。社内の手順に委ねる現状は、1名の採用者には「誰も確かめない」と同じである
  - 既存の `seats[].competence` は 3.4.3 要求事項1(AI を使わずに判断できる力量)の記録である(`survey.md:34-36`)。同じ欄に載せると、1件の記録で 3.4.1 と 3.4.3 の2つが満たされたと読まれる。現場では、1つの欄があれば1つの記録しか書かない【推】
  - 構成の席に置けば、任免の変化点と同じ操作で記入できる。記入の時点が任免の決定の時点と一致する(条項の「任免の決定の時点で確かめる」と同じ)
- 欄の形(現場の提案)
  - 例: `seats.independent-reviewer.externalAppointment = { competence: { confirmedAt, confirmedBy, record }, agreement: { agreedAt, record } }`
  - `record` は所在(URL・パス・文書番号)。合意書は個人情報・対価を含みうるので、リポジトリの外の所在を許す(ADR-0060 決定2「守秘・対価・利害の中身には立ち入りません」と同じ向き。`adr/0060-…md:64-76`)
  - `confirmedBy` は 3.4.1 の確認者。1名の体制では決定者(=本人)が確認する。これは 3.4.1 の「確認済みの者がいない体制では、確認を依頼した本人が確認してよい」(`roles-responsibilities.md:140`)に当たるので、議題4 と同じ区別で表示する
- 現場で起きること
  - 1名・内製: 知人のエンジニアに独立レビュアを頼む。任免の変化点で、相手の過去の差し戻し記録の所在と、席の規定に従う旨のメールの所在の2行を書く。負担は小さい
  - 受託(受注側): 受注側が契約した外部のレビュアを置く。合意は受注側との契約の写し。**発注側にこの確認をさせない**(第2集 問13、`survey-external.md:29`。議題8)
  - 誤記入: 3.4.3 の記録の所在を両方の欄へ写す。機械は中身を確かめないので見逃す。出力に「3.4.1 の確認は差し戻し記録による(3.4.3 とは別)」と書いて、写しを抑える
- 強制の強さ
  - 新しい任免(外部の確認者を独立レビュアの席の責任者に置く変化点): 2つの記録が無ければ拒む。その時点で直せる
  - 既存の構成: 欄が無いことを「(イ)の条件の記録が無い」として保証の開示の項目7 に未確認として出す。出荷を止めるかは議題10 の扱いに従う
- 採らない案
  - 既存の competence へ流用: 2要求の混同。採らない
  - テンプレ8 へ置く: 内製に様式が無い。採らない
  - 社内の手順に委ねる(現状維持)を ADR に書く: 1〜2名の採用者には確かめる人がいない。信頼性が上がらない。採らない
  - 合意書の本文を構成へ取り込む: 守秘・個人情報の扱いを本標準が抱える。採らない
- 新しい義務: 条項(:416)は既存。記録の置き場を構成に定めることは、記録の形式の指定であり、採用者に新しい記入を課す(**軽い新しい義務**)
- EV: 不要(記録の有無の検査で、閾値を持たない)

## 議題4 席の責任者でない確認者の力量と、件数・区別の出力(論点 B、IMPL-0117)

- **結論: 採る。名簿の行に力量の確認の記録の所在を持たせ、集約が件数と区別を保証の開示の項目1 に出す。「依頼した本人による確認」は自己申告の印ではなく、記録から導く**
- 理由
  - 3〜9名・10名以上では、席の責任者でない人が日常的に承認する。条項は件数の表示を求めるが(`roles-responsibilities.md:138`)、今は誰も数えていない。採用者が手で数える手順は続かない【推】
  - 名簿は人の正本であり、人ごとの属性を置く場所として一貫する。別の記録にすると、名簿と別の記録の2つの正本ができ、異動・退職でずれる(ADR-0087 決定3 と同じ理由。`survey.md:323`)
- 欄と判定(現場の提案)
  - `people[].reviewCompetence = { confirmedAt, confirmedBy, record }`。`confirmedBy` は名簿の人で、AI の名義でない
  - 「依頼した本人による確認」の判定: `confirmedBy` の人が、確認の時点で自らの確認の記録(席の `competence`・3.4.1 の記録・`reviewCompetence`)を持たないとき、その確認を「依頼した本人による確認」として区別して出す。印(`selfRequested: true`)で書かせない。印は付け忘れ・付けない選択で区別が消える
  - 件数: 項目1 へ「力量の確認の記録が無い確認者による確認 N 件」「依頼した本人による確認の確認者による確認 M 件」の2行
- 現場で起きること
  - 10名以上: 導入の直後、全員の記録が無いので、ほぼ全件が「記録が無い確認者による確認」に出る。**これは事実であり、表示を抑えない**。出荷を止めない(条項 :141)ので現場は止まらない。件数が多いままなら、内部監査が手順の不在として拾う
  - 3〜9名: 最初の1人を誰が確認するかで止まる。条項の「依頼した本人が確認してよい」がこの初期化の経路であり、上の導き方で区別が出る
  - 受託: 受注側の確認者の力量を、発注側が経歴書・面談で確かめて可否を決める形は、第2集 問13 で「判断されることがある」(`survey-external.md:29`)。`confirmedBy` は確認者と同じ組織の側の人とするよう案内に書く(機械では確かめない)
- 採らない案
  - 別の記録(確認者の台帳ファイル): 正本が2つになる。採らない
  - 「依頼した本人」を作成を指示した者の記名で判定: 条項の「依頼した本人」は確認者の力量の確認を依頼した人であり(`survey.md:68`)、変更ごとの指示者とは別。採らない
  - 降ろさない理由を ADR に書く: 件数の開示は条項の要であり、手で数えない現場では開示が空になる。採らない
- 新しい義務: 条項(:133-141)は既存。名簿の欄へ記録することは記録の形式の指定(**軽い新しい義務**)
- EV: 既存の EV-0105(E0)の範囲。新しい閾値は無い。追加不要

## 議題5 2名必須の制限(論点 C、IMPL-0118、X-3)

- **結論: 条件つきで採る。制限の記録に範囲(パスのパターン)・対象の人・根拠・記録した者を必須で持たせ、解除の記録の形を足し、集約が範囲の承認者数を上げる。「機械による発動は行わない」とは両立する**
- 理由
  - 今は範囲を書いても捨てられ(E5)、承認者数は1のまま(確認3)。制限は記録の上だけの存在で、対象の人の単独の承認がそのまま数えられる。検出能力の低下を検知した範囲で、確認が1人のまま出荷される。信頼性の穴として最も直接的である
  - 7.9.6 の「機械による発動」(`exception-escalation.md:740`)が禁じるのは、測定の結果から機械が制限を始めることである。人が記録した発動から集約が人数を数え直すのは、発動の記録の帰結であり、発動ではない。この読みを裁定に書く
  - パス単位で承認者数を上げる前例(コア機能の `coreReviewerCount`)が既にある(`survey.md:122`)
- 数え方の読み(議長へ確かめを求める)
  - 現場は、**対象の人の承認を、範囲内では単独で数えない**読みを推す。範囲内の変更に対象の人が承認したら、別の独立レビュアの承認がもう1件要る。対象の人が承認しない変更は、通常どおり1名で数える
  - 理由: 「制限するのは人ではなく権限の範囲」(`exception-escalation.md:680`)と ADR-0067 決定2「検出能力の低下を検知された者の承認を単独では数えない」(`adr/0067-…md:44-48`)に沿う。範囲の全変更に2名を課す字義の読みは、低下していない別の確認者まで止め、3〜9名でも範囲の変更が出荷できなくなる
  - 7.9.2 の表の字義(「該当する範囲について、独立レビュアを2名必須」)と、どちらの読みを採るかは議長が決める
- 欄と挙動(現場の提案)
  - 発動: `{ kind: notice, event: restriction, scope: [パスのパターン], person: <名簿の id>, basis: <測定結果の所在>, recordedBy: <名簿の id>, notice: { to, at } }`。scope・person・basis・recordedBy が無ければ拒む(O-4 の記録した者の欠けも塞ぐ)
  - 解除: `event: restriction-lifted`、`basis` に連続2回の検出の記録。期間の経過で解除する仕組みは置かない(7.9.3)。解除を記録しない限り、集約は制限中として数え続ける
  - 時点: 集約(G-7)だけで気づくと、出荷の直前に手戻りが出る。/pit(next.mjs)と PR の検査で「この変更は制限中の範囲に触れ、対象の人の承認だけでは足りない」を先に出す。ブランチ保護への反映は求めない(GitHub の required reviewer rule はチーム単位で、プランの条件も不明。`survey-external.md:186`)
- 現場で起きること
  - 3〜9名: 品質保証の機能が、見逃した欠陥の類型をパスのパターンへ写す。**狭すぎる範囲(迂回)と広すぎる範囲(止まる)の両方が起きる**【推】。範囲を書いた者と根拠を記録させ、内部監査で妥当性を見る
  - **1〜2名: 独立レビュアは多くて1名(外部の確認者)で、2人目がいない。制限が発動すると範囲の変更は 7.9.4 の例外でしか通らない。7.9.4 の要求事項2 は B-2 の決定者の記名を求めるが、1〜2名の体制は B-2 を置かないことが多い**【推】。この体制で例外を誰が記名するかは本件の議題の外だが、範囲の承認者数を機械で上げると、この空白が即座に現場を止める。議長は、降ろす前にこの空白を後継(既存の Issue)へ送るか、本件で決めるかを裁定する必要がある
- 旧い記録: 範囲を持たない既存の restriction の通知で、解除の記録も無いものは、「範囲の記録が無い制限が継続中」として保証の開示の項目1 に未達として出し、再記録を求める。全リポジトリを範囲とみなして止めることはしない(根拠の無い範囲で止めると、採用者は記録そのものを消す)
- 採らない案
  - 範囲を持たせず、確かめる者と時点を社内の手順に委ねる(現状): 制限が記録の上だけになる。採らない
  - ブランチ保護・ルールセットでの強制を必須にする: プラットフォームとプランに依る。必須にはせず、使える採用者の任意の追加とする
  - 範囲を変更種別・欠陥の類型で表す: 集約が判定できない。パスのパターンを必須、類型は根拠の欄に添える
- 新しい義務: 条項(7.9.2・7.9.6)は既存。範囲・対象の人・記録した者の記入と、解除の記録は、7.9.6 の記録の形式の具体化。**新しい義務は無い**(記録の対象は既に 7.9.6 にある)。「対象の人の承認を単独で数えない」の読みを採るなら、7.9.2 の表の文言を合わせて改める
- EV: 範囲をパスで表すことの妥当性(類型とパスの対応)は実証が無い。**EV を付ける**(E0〜E1、差し替え条件: 制限中の範囲の外で同じ類型の欠陥が見つかった件数)

## 議題6 組織上の距離の段2 以上(論点 D、IMPL-0184・0344・0452・0080、X-7)

### 6-a 名簿に上長・部門・法人・リリースの権限の欄を足すか

- **結論: 採らない(名簿へ組織の属性の欄を足さない)。記録の段と根拠を比べ「距離は機械では確かめていない」と開示する IMPL-0450 の形へ揃える。加えて、構成から導ける部分だけを機械で確かめる**
- 理由
  - 現場の名簿は、採用者が手で書く。上長・部門・法人を足しても、値は自己申告で、異動のたびに古くなる。10名以上の会社では人事のシステムが正本であり、名簿へ写すと正本が2つになる(ADR-0087 決定3 の理由。`survey.md:212`)。鉄道の解説も「役割の割当てを組織の変更に追随して文書化」を求める(`survey-external.md:117`)が、名簿への写しは追随しない【推】
  - 1〜2名・小さな会社には上長がいない、または社長1人が全員の上長である。欄があると、空欄・「なし」・社長の名で埋められ、値から段は導けない
  - 調べた規格は、段を計画で宣言し、指名された責任者の報告で残す。自己申告の属性で「満たす」と判定する例は無い(`survey-external.md:137,141`)
- 機械が確かめてよい部分(構成から導ける)
  - 確認者・評価者が、出荷判定者・事業決裁者の席の責任者でないこと(段2 の「対象のリリースの権限を持たない」のうち、席から導ける部分。`survey.md:235`)
  - 2名の体制の内の確認者は段1 を上限とする(既存。`test-cl-judgment.mjs:189-190`)。同じ上限を、内の人が2名以下のすべての構成に当てる【推】
  - 段3・段4 を求める構成で、評価者が名簿の外部の確認者として登録されていること(`tailoring-guide.md:1003` の「外部の評価者を人の名簿へ登録して満たす」)
- 現場で起きること: 安全性の評価者・判定の確認者は、判定記録に段と根拠の文を書く(既存の様式。`deliverable-templates.md:778-781`)。機械は値を比べ、導ける矛盾(リリースの権限を持つ者が段2 と書いた等)だけを失敗にする。距離そのものは、評価の責任者と内部監査が確かめる
- 採らない案
  - 名簿に上長・部門・法人・リリースの権限を足して段を導く: 自己申告の値で「満たす」と出し、異動でずれる。名ばかりの delivered になる。採らない
  - 人事のシステム(ディレクトリ)と連携して上長の属性を取る(Entra の例。`survey-external.md:134`): 採用者の環境に依り、準拠テンプレートの範囲を超える。採らない(採用者が任意で足すことは妨げない)
- IMPL の扱い: IMPL-0344・0452・0184 は「名簿の欄で段2 以上を確かめる」を降ろす先として書いている。欄を足さないと決めるなら、**降ろさないと決めた部分(距離そのもの)を note に「課さないと決めた」と書き、確かめる者(評価の責任者・内部監査)を名指す**。導ける部分を降ろした範囲だけを delivered とする。「まだ降りていない(IMPL-0344)」(`tailoring-guide.md:1009`)の文を、決めた内容へ改める
- 新しい義務: 無い(欄を足さないため)
- EV: 「段2 以上の距離は人が確かめる」は判断であり、規格の書き方(計画と報告)に支えられる。EV は ADR-0088 の EV-0180 の範囲で足りる

### 6-b 自己申告の属性で「段を満たす」と出すこと

- **結論: 採らない。出力は「記録の段は段N(記録による。距離は機械では確かめていない)」の形に限る**
- 理由・現場: 安全性の評価の判定者は、集約の出力を見て出荷を決める。「段2 を満たす」と出れば、追加で確かめない【推】。IMPL-0450 の既存の文言(`test-cl-judgment.mjs:194`)と同じ形に揃える
- 採らない案: 「満たす」と出し、注記で自己申告と添える: 注記は読まれない。採らない
- 新しい義務・EV: 無い・不要

### 6-c ADR-0069 決定2 の範囲と既存の `team`

- **結論: 名簿は決定2 の字義(「席と受信箱」。`adr/0069-…md:53`)の外と読む。ただし本件では名簿に組織の属性を新たに足さない(6-a)ので、原則の変更は要らない。`team` は表5-2 の「所属」として現行のまま使う。IMPL-0462 の note の「席と名簿」の語(X-8)は「席と受信箱」に直す**
- 現場: `team` は10名以上の規則(コア機能の別の所属の承認)で既に使われ、無ければ「判定できない」(`survey.md:223`)。これを決定2 の迂回と読むと、10名以上の既存の規則が根拠を失う。現行の読みを維持する
- 採らない案: 名簿を決定2 の範囲に入れ `team` を廃す: 10名以上の規則が成り立たない。採らない
- 新しい義務・EV: 無い・不要

### 6-d 安全性の評価者の段の欄を集約が読まない(O-5)

- **結論: 採る。集約が安全性の評価者の段の欄を読み、求める段と比べる(判定の確認者と同じ形)**
- 理由・現場: テンプレ4 に段の欄があるのに誰も読まない(`aggregate-evidence.mjs:1150`)。CL2 以上の採用者は欄を埋めるが、空欄・低い段の記入も通る。同じ「段」の欄で、片方は比べ、片方は読まないのは、記入者に「この欄は飾り」と教える【推】
- 旧い記録: CL1 以上は「未達のまま出荷しない」(`tailoring-guide.md:1003`)。段の欄が空の記録は未達とする。直し方は「判定記録に段と根拠を書く」の1つで示せる
- 採らない案: 読まないまま開示だけする: 既に開示している(IMPL-0344)が、記入の誤りを拾えない。採らない
- 新しい義務: 無い(記入は既存の様式)
- EV: 不要

## 議題7 受託の構成で価値責任者を発注側に置く(論点 I、IMPL-0462)

- **結論: 条件つきで採る。名簿の欄では検出しない。テンプレ8 第9項に「価値責任者(発注側が選任した者)」の行を足し、構成の価値責任者の席の責任者と氏名で照らす**
- 理由
  - 名簿に `organization: 発注側/受注側` を足す案は、受注側の採用者が自分で「発注側」と書けば通る。多重の下請・出向では「発注側」がどこを指すかが割れる(#359 の採らない案。`survey.md:315`)
  - テンプレ8(AI-SLA 合意確認書)は双方が合意する文書であり、相手方の確認を経る。名簿の自己申告の印より、記録の出所が強い。席の責任者の組織を様式に書く前例が第9項に既にある(`deliverable-templates.md:1361`)
  - モデル契約は所属を「甲が選任する」の選任者で書く(`survey-external.md:79`)。行の題を「発注側が選任した価値責任者」とすれば、多重の下請でも「契約の相手方が選任した者」と一意に読める
- 現場で起きること
  - 受託(受注側): 締結の時点で、第9項に発注側の担当者の氏名を1行書く。構成の価値責任者の席に同じ人を置く。食い違えば失敗。受注側の自社の人を価値責任者に置く誤り(「代わりに決めておきます」の運用)がここで止まる
  - 受託(発注側がリポジトリを持つ): 同じ照合が働く
  - 誤記入: 氏名の表記ゆれ(旧字・空白)で偽の失敗が出る。照合は名簿の既存の氏名の照合と同じ正規化を使う
- 旧い構成: 第9項に行が無い既存の受託の構成は「判定できない」として出す。ADR の採用の後に締結・改訂したテンプレ8 からは欠落に数える。境界は記録を入れたコミットの時刻で決める(ADR-0109、IMPL-0449 の前例。`tailoring-guide.md:962`)
- 議題1 との関係: 議題1 の拒否で、発注側の価値責任者は `external: false` として載る。区分(内か外か)と選任者(発注側か受注側か)は別の値であり、両方が要る(`survey.md:321`)
- 採らない案
  - 名簿に組織の欄: 自己申告で、名ばかりの delivered。採らない
  - 降ろさない理由を ADR に書き、G-2 の判定で人が照らす(#359 の暫定の1行): 1〜2名の受託では、G-2 の判定者が価値責任者本人であり、自分の所属を自分で照らすことになる。信頼性が上がらない。採らない(本件で降ろすまでの暫定としては残してよい)
- 新しい義務: テンプレ8 第9項に必須の行を1つ足す。**新しい記入の義務**(軽い)。条項(`tailoring-guide.md:594`「必須」)は既存
- EV: 不要(照合で閾値を持たない)

## 議題8 発注側による受注側の席の責任者の任免への関与(論点 G。法令)

- **結論: 扱う。外部の制約の注記に第3集 A7・第2集 問13 を足し、受託の構成では受注側の席の任免を受注側の決定者が行い、発注側へは氏名と交替理由を通知する形を、記録の既定とする**
- 理由(現場で最も重い所見)
  - **本標準の既定に従うと、受託の構成で A7 の形の記録が自動的にできる**。D-0 表1「体制と運用形態」(責任者の任免)の既定の決定者は事業決裁者である(`deliverable-templates.md:209`)。受託では事業決裁者の席を発注側に固定する(G-1・G-8。`tailoring-guide.md:654,661`)。したがって、既定のまま運用すると、受注側の技術判断者・独立レビュア・AI維持管理者の任免の変化点に、発注側の人の記名(decidedBy)が残る(`survey.md:275`)。これは「発注者が特定の者を指名して業務に従事させる」(第3集 A7。`survey-external.md:21`)と記録の上で同じ形である
  - 扱わないと明記するだけでは、上の既定が残る。採用者は本標準に従った結果として、実態の判断の材料に読まれうる記録を残す(記録は突き合わされる。`survey-external.md:40`)
  - 決定ではなく通知とする形は、IPA のモデル契約 第3条第5項(`survey-external.md:34`)と同じで、法令の該当性を判断せずに書ける。ADR-0069 決定3(法令は外部の制約の注記。`adr/0069-…md:55-57`)は、注記の形を求めるが、本標準が自らの記録の形を選ぶことは妨げない。「本標準に従って運用していることは、区分の判断の根拠になりません」の文は維持する
- 現場で起きること
  - 受託(受注側)の小さな会社: 担当を替えるとき、受注側の代表が任免の変化点に記名し、発注側の担当者へ「氏名と交替理由」の通知を記録する。発注側の承認を待たない
  - 発注側が「この人は外してほしい」と言った場合: 本標準の記録には現れない。運用の実態は本標準の範囲外であり、注記で A7 を示すにとどめる
  - 発注側の席(価値責任者・出荷判定者・事業決裁者)の任免は、発注側の決定者が行う。自社の人の配置であり、関与の論点に当たらない【推】(`survey-external.md:54`)
- 記録の形の変更点
  - 受託の構成では、D-0 表1「体制と運用形態」の行を、発注側の席の任免と受注側の席の任免の2つの決定者に分ける。または、受注側の席の任免の決定者を受注側の席の責任者(既定は受注側の技術判断者)とする
  - 機械: 受託(受注側)の構成で、受注側の席の任免の変化点の決定者が、テンプレ8 第9項の発注側の人(議題7 の行)と一致すれば、注意を出す。拒否はしない(実態を機械は知らない)
- 採らない案
  - 扱わないと明記する: 本標準の既定が A7 の形の記録を作り続ける。採らない
  - 注記だけ足し、記録の形は変えない: 採用者は注記を読んでも、表1 の既定の決定者が発注側の人であることに気づかない【推】。採らない
  - 機械で拒む: 当事者が実態として適法に運用している場合(受注側の決定を発注側の人が代理で入力する等)を区別できない。採らない
  - 契約の個別の適法性の判断: 本標準の所管の外(受付の範囲。`intake.md:41`)
- 新しい義務: 受託の採用者に、受注側の席の任免の決定者を受注側に置くことを課す。**新しい義務である**(D-0 表1 の既定の変更)。安全・法令に触れるので、重の扱いが妥当
- EV: 法令の解釈に依る記述であり、実証の対象ではない。出典(SRC-0636・SRC-0671・SRC-0638)を引く。第2集の厚生労働省の PDF は目視の照合をしていない(`survey-external.md:25`)ので、注記にその旨を書く。EV は不要。照合の状態の開示を要す

## 議題9 内部監査の観点6 に「名簿の完全性」を足すか(論点 H。新しい義務)

- **結論: 採る。新しい観点を立てず、既存の観点6 の所見の例と確かめる事項に「書かれるべき人(組織上の任命権者)が名簿の外にいないか」「名簿の区分(体制の内・外部の確認者)が実態と合っているか」を足す**
- 理由
  - ADR-0122 の自分に関わる変更の例外は「体制の内に当事者以外で記名できる者(組織上の任命権者を含む)がいない」体制に限る(`roles-responsibilities.md:2045-2053`)。任命権者を名簿に書かなければ、その条件が満たされたように見える(`survey.md:300`)。**書かないことが例外の条件を作る**ので、現場では悪意なく起きる(「社長はプロジェクトに関わっていないから書かなかった」)【推】
  - 現行の観点6 は「書かれた人が実在するか」の向きだけで(`assurance-case.md:261`)、欠けた記載を誰も見ない。機械は書かれていない人を知らない。監査で1つの問い(「あなたを任免できる人は誰か。その人は名簿にいるか」)を立てるのが、唯一の検出の経路である
  - 議題1 の拒否で区分の誤りの一部(席の責任者)は機械が拾うが、席を持たない承認者を external と書く誤りは監査でしか拾えない
- 現場で起きること
  - 1〜2名: 内部監査は外部の者か、本人が行う。追加は「組織図・契約書と名簿を突き合わせる」1項目で、負担は数分【推】
  - 10名以上: 人事の在籍の記録との突合(`deliverable-templates.md:156` が既に求める)と同じ作業の中で行える。追加の負担は小さい
- 採らない案
  - 足さず、抜け道を IMPL-0483・0342 の note で開示するだけ: 開示しても、誰も確かめない状態は変わらない。採らない
  - 名簿の完全性を機械で確かめる: 名簿の外の人を機械は知らない。採らない
  - 独立の観点として新設: 観点6 の突合と同じ材料・同じ時点である。分けると突合が2回になる。採らない
- 新しい義務: **内部監査の新しい義務である**(確かめる事項の追加)
- EV: 名簿の外の任命権者・上長を名簿と突き合わせることを独立の監査項目として名指す公的な文書は見つかっていない(`survey-external.md:214,219`)。NIST AC-2(l)(人事の異動との整合)・AC-5 が近い。**EV を付ける**(E1、差し替え条件: 観点6 でこの所見が出た件数と、ADR-0122 の例外を使った構成の件数の比)

## 議題10 欄の無い旧い構成の互換と、名簿の未知の欄(論点 J)

### 名簿の未知の欄

- **結論: 採る(拒否へ改める)。拒否の文言に、書ける欄の一覧を出す**
- 理由・現場
  - E4・E7(`survey.md:333-334`)は、採用者が「上長を書いた」と思っている構成を作る。記録は `no-change` で、本人は気づかない。拒否なら、その場で「書けない」と分かる
  - 新しい版で書いた欄を旧い版のテンプレートが黙って消す経路(`survey.md:339`)も、拒否なら旧い版で止まる。消えるより止まる方が信頼性が高い
  - buildConfig が保存の時点で未知の欄を落としてきたため、保存済みの構成に未知の欄は無いはずである【推】。手で構成を編集した採用者だけが当たる。その場合も、文言で欄の名を示せば直せる
- 採らない案: 落として警告(Kubernetes の Warn。`survey-external.md:226`): 警告は流れる。席・governance と同じ Strict に揃える。採らない
- 新しい義務・EV: 無い・不要

### 欄の無い旧い構成の表示

- **結論: 一律の扱いを決めず、欄ごとに「緩める向きの補いは無い」(`migrate.md:9`)の原則で決める。欠けを満たしたとは読まない。境界は記録を入れたコミットで決める(ADR-0109)**
- 欄ごとの扱い(現場の提案)

| 欄(議題) | 旧い構成の表示 | 理由 |
| --- | --- | --- |
| (イ)の記録(議題3) | 保証の開示の項目7 に「(イ)の条件の記録が無い」と未確認として出す。出荷は止めない。次の任免の変化点からは必須 | 既存の外部の確認者を即座に席から外させると、独立レビュアが空になり G-6 が成立しなくなる。止めると、より独立の低い状態へ戻る |
| 席の責任者でない確認者の力量(議題4) | 条項どおり「記録が無い確認者による確認」として件数に出す | 条項自身が欠けの読み方を定めている(`roles-responsibilities.md:138`) |
| 制限の範囲(議題5) | 「範囲の記録が無い制限が継続中」を未達として項目1 へ | 範囲を推測して止めない。記録を消す動機を作らない |
| 安全性の評価者の段(議題6-d) | 未達。CL1 以上は出荷しない | 条項が既に定める(`tailoring-guide.md:1003`) |
| テンプレ8 の価値責任者の行(議題7) | 境界より前は「判定できない」、後は欠落 | IMPL-0449 の前例 |
| 外部の確認者の席の限定(議題1) | 欠落(直し方を文言に出す) | 人数・決定権の誤りは出荷の開示の信頼性を直接に損なう |

- 採らない案
  - 一律に未確認(注意): 人数の誤り(議題1)のような重いものまで流れる。採らない
  - 一律に欠落: (イ)の既存の構成で、独立レビュアを外す方へ採用者を押す。採らない
  - 猶予の期間: migrate の原則と食い違う。採らない
- 新しい義務・EV: 無い・不要

## 範囲外の所見(後継へ)

- **1〜2名の体制で 7.9 の制限が発動したときの例外決裁者**: 7.9.4 の要求事項2 は B-2 の決定者の記名を求める(`exception-escalation.md:703`)。B-2 を置かない体制で誰が記名するかが定まっていない【推】。議題5 で承認者数を機械で上げると、この空白が現場を即座に止める。既存の open Issue へ寄せて送るか、本件で決めるかを議長が裁定する

## 議長への要点(15 行以内)

1. 議題1: 拒む(入口と構成の整合の両方)。拒否の文言で「発注側の人も体制の内(external: false)」と名指す。external を「社外の人」と読む誤記入が現場の主因【推】
2. 議題1-c: 区分の改めは締める向きで、外部の確認者だった決定者本人の記名でも受ける。人数の境界の改めと1つの変化点で通す。過去の氏名の確認を遡って無効にしない
3. 議題2: 3名以上でも認め、(イ)の3条件を人数によらず掛ける(新しい義務、EV を付ける)。認めないと名ばかりの内の独立レビュアを誘う
4. 議題3・4: 3.4.1 の記録を既存の competence(3.4.3)と別の欄に置く(席・名簿の行)。「依頼した本人による確認」は印でなく記録から導く
5. 議題5: 範囲・対象の人・根拠・記録した者を必須に、解除の形を足し、集約で承認者数を上げる。「機械による発動」には当たらない。数え方は「対象の人の承認を範囲内で単独で数えない」を推す(字義との選択は議長)
6. 議題5 の前提の空白: 1〜2名は2人目の独立レビュアがおらず、7.9.4 の例外は B-2 を要する。降ろすと即座に止まる。裁定か後継へ
7. 議題6: 名簿へ上長・部門・法人の欄を足さない(自己申告・異動でずれる)。記録の段を比べ「距離は確かめていない」と出す形に揃え、席から導ける矛盾(リリースの権限)だけ機械で拾う。降ろさない部分は「課さないと決めた」と IMPL の note に書く
8. 議題6-d: 安全性の評価者の段の欄を集約が読む(O-5 を解消)
9. 議題7: 名簿の組織の欄でなく、テンプレ8 第9項の「発注側が選任した価値責任者」の行と席の氏名を照らす
10. **議題8(最重)**: 本標準の既定(表1 の任免の決定者=事業決裁者、受託では発注側に固定。`deliverable-templates.md:209`、`tailoring-guide.md:654,661`)に従うと、受注側の席の任免に発注側の記名が残り、第3集 A7 の「指名」の形の記録が自動的にできる。注記の追加に加え、受注側の席の任免は受注側が決め発注側へ通知する形を既定にする(新しい義務)
11. 議題9: 観点6 の中に「任命権者が名簿の外にいないか・区分が実態と合うか」を足す(新しい監査の義務、EV を付ける)。書かないことが ADR-0122 の例外の条件を作るため
12. 議題10: 名簿の未知の欄は拒否へ。旧い構成の表示は欄ごとに決め、欠けを満たしたとは読まない(表を参照)
