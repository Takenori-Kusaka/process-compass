## 裁定

### 裁定1 外部の確認者を責任者に置ける席の限定を降ろす(議題1。全員一致)

- 独立レビュア以外の席の責任者に `external: true` の人を置く構成を、`namingProblems` で拒む。変化点の入口・契約の検査・出荷の証跡の集約(記録の欠落)の3か所で効く。任命権者を席に置かない既存の拒否と同じ層である
- X-2(外部の確認者が D-0 表1 の決定者になる経路)は、構成の決定者が席(`governance.structureDecider`)で表されるため、同じ拒否で塞がる。表1 に席を介さない氏名を書く経路は、準拠テンプレートに無い(`config.mjs:1406-1413`)。IMPL の note と ADR に明記する
- 移し方: 区分を「体制の内」へ改める変化点は、既存の記名の規則(ADR-0110・ADR-0122)による。当人の記名の扱いを特別に緩めも締めもしない。区分の訂正と回答 `q-team-size` の訂正を1つの変化点で行える(既存の入口がそうなっている)。猶予の期間は置かない
- 氏名の確認の人数(insiderCount)は、構成の現在の名簿から導くため、訂正の後は訂正後の人数で判定される(品質監査の指摘。追加の実装を要しない)
- 拒否の文言に「受託で発注側に置く席の人も、体制の内(external: false)として載せる」を名指す(現場の指摘)
- 新しい義務: 無し(3.5 の採用済みの条項を降ろすだけ)

採らない案: 変化点の入口だけで拒む(既存の構成が集約で素通りする)/ 移行の猶予を置く(条項は #370 で採用済み)/ 当人の記名を移しのために特別に受け付ける(記名の規則を論点ごとに分けると、どの規則が効くかを読み手が追えなくなる)

### 裁定2 3名以上の体制でも(イ)を認め、3条件を人数によらず掛ける(議題2)

- 3.5 の(イ)の3条件の箇条の適用を「外部の確認者を独立レビュアの席の責任者に置く体制(規模によらない)」と明記する。(ア)(イ)の表と「既定は(ア)」は「適用: 3名未満の体制」のまま残す
- 3名以上の体制で(イ)を採ると、その体制の G-6 は外部の確認者が担う。外部の確認者は体制の人数に数えない(既存)ので、3名の境界の判定は変わらない
- 根拠: 条件を掛けない現状は、3名以上の方が3名未満より緩い逆転(品質監査)。外部の規格は外部の評価者を規模で限らない(規格)。禁じると開発から形式上外しただけの名ばかりの内の独立レビュアを誘う(現場)
- 新しい義務: あり(3名以上で(イ)を採る採用者に3条件)。EV は新設する(EV-0253。ADR-0083 決定6 に従い、既存の EV の対象を黙って広げない)

採らない案: 3名以上では(イ)を禁じる(独立の強い構成を奪う。弁護・現場)/ EV-0104 の対象を広げる(差し替え条件が3名未満の観測で書かれている)

### 裁定3 (イ)の条件の記録を、3.4.3 の competence と別の欄で降ろす(議題3。全員一致で別の欄)

- 力量の確認(3.4.1)は、名簿の人の行の `reviewCompetence: { confirmedAt, confirmedBy, record }` に置く(裁定4 と同じ欄)。3.4.3 の `seats[].competence` へは流用しない(2つの要求を1つの記録で満たしたと読ませない)
- 書面の合意は、独立レビュアの席の `agreement: { at, record }` に**所在だけ**を置く。本文は構成へ写さない(ADR-0087 決定3)
- 外部の確認者を独立レビュアの席の責任者に置く変化点は、名簿の行の `reviewCompetence` と席の `agreement` の両方が無いと拒む
- 既存の構成で、外部の確認者が独立レビュアの席の責任者でありながら記録の無いものは、出荷の証跡の集約で**記録の欠落**とする。3条件は ADR-0060(2026-10)から条項であり、新しい要求ではない。G-6 の状態(`required`)は変えない(test-roster-rules.mjs:76-79 の固定を保つ。弁護の指摘)
- (イ)に暫定任命の経路を開かない。3.4.1 の暫定任命は「確認済みの者による併記」を要し、(イ)を要する体制には併記できる者がいないため、暫定任命は成立しない(品質監査・規格の対立はこの読みで解く)
- 機械が確かめるのは記録の有無、確認した者が本人でなく AI の名義でないこと、確認日の形まで。力量の中身と合意の中身は確かめない

採らない案: 3.4.3 の competence へ流用 / 記録の欠けを(ア)へ落とす(緩める向き。品質監査)/ 旧い構成を未確認にとどめる(条項は前から掛かっていた。弁護の案)/ 合意の本文を構成へ写す(正本の二重化)

### 裁定4 席の責任者でない確認者の力量と、件数・区別の出力を降ろす(議題4)

- 名簿の人の行に `reviewCompetence`(裁定3 と同じ欄)を置く。独立した人の確認に数えた承認ごとに、承認した者の記録を引く
- 出荷の証跡の集約は、保証の開示の項目1 に2つの件数を出す。「力量の確認の記録が無い確認者による確認」と「依頼した本人による確認」。出荷は止めない(3.4.1 のとおり)
- 「依頼した本人による確認」は、承認した者の `reviewCompetence.confirmedBy` が、その変更の作成を指示した者と同じ人である確認と定義する。3.4.1 の文に「確認を依頼した本人(その変更の作成を指示した者)」と明記する。確認者に申告の印を書かせない(現場・品質監査)。作成を指示した者を「依頼した本人」とする等式を、条項に書いて明示する(弁護の「条項に無い等式」の指摘への応答)
- 新しい義務: 無し(3.4.1 は採用済み)。記録の置き場が構成に定まる

採らない案: 依頼した本人を申告の印で書かせる / 条項の語を「確認済みの者がいない体制での確認済みでない者による確認」へ置き換える(規格の案。条項の語の意味を変えるため本件では採らず、定義の明記で足りる)

### 裁定5 2名必須の制限を記録し、集約で確かめる(議題5)

- 種別 notice の `event: "restriction"` に `restriction: { id, person, paths, basis, recordedBy }` を必須にする。解除は `event: "restriction-release"` と `restriction: { id, basis, recordedBy }`。`recordedBy` は名簿の自然人(7.9.6 の品質保証の機能)。期限の欄は置かない(7.9.3)
- 出荷の証跡の集約は、解除されていない制限の範囲(`paths`)に触れる変更で、独立した人の確認に数えた承認が2名に満たないものを、**独立した人の確認に数えない**(コア機能の承認者の数と同じ扱い。R1 は例外承認を要し、G-6 を適用する体制の PR を経ないコミットは記録の欠落になる)。数え方は 7.9.2 の字義(範囲の変更はだれが承認しても独立レビュア2名)を正とする。字義は ADR-0067 決定2 の目的(対象の人の承認を単独で数えない)を含み、より厳しい(規格)
  - 実装の時の訂正(議長): 当初は「記録の欠落」と書いた。実装で、承認者の数が要求に満たない変更の既存の扱い(数えない)に載せるほうが、ADR-0067 決定2 の語(単独では数えない)と一致し、コア機能の扱いとも揃うと判断して改めた
- 強制する承認の数(`reviewersRequiredOf`・ブランチ保護)には入れない。ADR-0088 決定6 の固定を変えず、範囲の限定(7.9.2「適用の範囲」)を全 PR へ広げないため(弁護)
- 7.9.6 に「発動と解除は人が記録する。記録された制限を出荷の証跡の集約が照らすことは、機械による発動に当たらない」を足す
- 範囲の無い旧い発動の記録(従来は範囲を捨てていた)は、集約が「範囲を判定できない制限」として保証の開示の項目1 に出し、範囲を記録し直す変化点を案内する。欠落にはしない。範囲を捨てたのは準拠テンプレートであり、採用者の記録の欠けではないため
- 1〜2名の体制では2人目の独立レビュアがいないことが多い(現場)。この場合は範囲の変更が欠落になり、既存の例外承認(7.3)による。条項は変えない。帰結を ADR に書く

採らない案: 対象の人の承認だけを単独で数えない(字義より緩い)/ 強制する承認の数を上げる(全 PR に掛かる)/ 範囲の無い旧い記録を全範囲の制限とみなす(品質監査の案。準拠テンプレートの欠陥の帰結を採用者へ負わせる)/ 期限の欄

### 裁定6 段2 以上は名簿から導かず、記録の段を比べ、構成から導ける反証だけを機械で拾う(議題6。全員一致で名簿から導かない)

- 名簿に直属の上長・部門・法人・リリースの権限の欄を足さない。値は自己申告で異動のたびにずれ、属性から独立を「満たす」と判定する規格の例が無い(外部 問1・問7)
- 段の判定は、記録に書いた段と根拠を求める段と比べ、「段2 以上の距離は機械では確かめていない」と出す IMPL-0450 の形に揃える。距離そのものを確かめるのは人(出荷判定者・内部監査)と名指す
- 構成から導ける**反証**だけを機械で拾い、段を引き下げて数える(満たす向きには使わない)
  - 確認者・評価者が出荷判定者または事業決裁者の席の責任者 → 段2 以上に数えない(リリースの権限を持つ)
  - 確認者・評価者と、実装の責任者(開発者の席の責任者)または判定者が、名簿の `team` で同じ値 → 段3 以上に数えない(作成の部門から独立していない)
- 第1章 1.4 の段2 の「リリースの権限」に定義を足す: 出荷判定者・事業決裁者の席の責任者、および出荷を確定させる操作の権限(保護の迂回を含む)を持つ者
- O-5 を直す: 安全性の評価者の段の欄を集約が読み、CL2 は段2、CL3 は段3 と比べる。届かなければ記録の欠落(CL2 以上は第8章で未達のまま出荷しない)。段階「最強」の検証の担当者の行も、氏名が書かれていれば同じく比べる(IMPL-0184)
- ADR-0069 決定2 の対象は字義どおり「席と受信箱」であり、名簿はその外と読む(5 委員一致)。IMPL-0462 の note の「席と名簿」は誤記として直す(X-8)
- IMPL-0344・0452・0184 は、記録の段の比較と反証の検出を delivered にし、距離そのものの照合は「課さないと決めた」(`plan=adopter`)と書いて表示し続ける
- 根拠水準: 反証の2つの規則は類推(EV-0254)

採らない案: 名簿の属性から段を導く / 自己申告の属性で「段を満たす」と出す / `team` を満たす向きに使う / 体制の内の人の段4 を反証にする(受託では受注側が別の法人でありうる)

### 裁定7 受託の価値責任者は、テンプレ8 の行と席の責任者を照らす(議題7。全員一致で名簿の欄を採らない)

- テンプレ8(AI-SLA 合意確認書)の「判定の置き先と結果の受け渡し」の節に「価値責任者(発注側が選任した者)」の行を置く(IPA アジャイル版モデル契約 第4条第2項の型)
- 準拠テンプレートは、受託・委託の構成で、行が空欄なら注記、構成の価値責任者の席の責任者と氏名が食い違えば出荷の証跡の集約で記録の欠落とする。一致は「発注側の人であることは機械では確かめていない」と出す
- 空欄を欠落にしない理由: 行は本件で足す。次の締結(改訂)から記入する(ADR-0069 の前例。規格)。空欄の間は注記で案内する
- 新しい義務: あり(受託・委託の採用者に1行の記入)

採らない案: 名簿に `organization: orderer|vendor`(#359 裁定2 が退けた案。2値の自己申告で多重の下請・出向を誤る)/ 空欄を欠落にする

### 裁定8 受託の構成では、席の責任者の任免を、その人が属する側の組織が決め、相手へ通知する(議題8。3対2 の割れを裁定する)

割れの要点: 起案・現場・品質監査は「受注側の席は受注側が決め、発注側へは通知」を条項にする案。規格は注記と開示を確実とし、通知の形は表1 の「決定者を1人に定める」原則の変更と指摘。弁護は注記と開示だけ。

裁定:

- **外部の制約の注記**に、疑義応答集 第3集 A7・第2集 問13(発注者が特定の者を指名・就業を拒否することは配置の決定への関与とされる)を足す(全員一致)。時点を書き「〜とされています」の形にする(ADR-0069 決定3)
- **開示**: D-0 表1 の既定(体制と運用形態の決定者=事業決裁者=受託では発注側)のままでは、受注側の席の任免に発注側の人の記名が残り、A7 の例示と同じ形の記録になることを本文に書く(全員一致)
- **条項**: 受託・委託の構成では、席の責任者の任免を、その人が属する側の組織で任命の権限を持つ者が決定する。相手の組織へは、氏名と交替の理由を通知として記録する。D-0 表1「体制と運用形態」の行のうち、任免に限り組織ごとに決定者を置く
- 理由は法令への適合ではなく、**決裁の権限の出所**である(規格・品質監査)。発注側の人は受注側の要員を任命する権限を持たず、その記名は権限の無い任免の記録になる(C1 責任)。受注側の人が発注側の価値責任者を任命する逆向きも同じ。法令の評価を含まない(ADR-0069 決定3 と両立する)
- 原則の変更: 表1 の「決定者を1人に定める」を、受託・委託の任免に限って組織ごとに分ける。ADR-0127 に記録する。弁護の「決定者1名の原則に反する」は、原則そのものが単一の組織を前提にしていたことの帰結であり、組織をまたぐ構成では1名の決定者が相手の組織の任命の権限を持たない。原則の側を直す
- 準拠テンプレートは名簿に所属を持たないため、どちらの側の任免かを判定できない(裁定6・7 で所属の欄を採らない)。機械は確かめず、受託・委託の構成で任免の変化点を記録するときに、通知の記録の所在を案内する1行を出すにとどめる。IMPL は `state=undelivered plan=adopter`(確かめる者: G-2 の判定者と AI-SLA の締結者)
- 根拠水準: EV-0255(E0。組織をまたぐ任免の記録の誤りを観測した資料は無い)
- 新しい義務: あり(受託・委託の採用者)

採らない案: 注記と開示だけ(本標準の既定が権限の無い任免の記録を作り続ける)/ 発注側が受注側の任免を承認する形(A7 の形そのもの)/ 所属の欄を足して機械で確かめる(裁定6・7)/ 後継へ送る(重の審議の範囲で突合できる)

### 裁定9 内部監査の観点6 に所見の例を3つ足す(議題9)

- 附属書H H.3 の観点6 に、次の所見の例を足す(規格の3つの限定に従う)
  1. 載せるべき人の欠け: 表5-2 が全員を載せると定める人(席の責任者・席の責任者でない担い手・外部の確認者)が名簿に無い

  3. 例外の条件の偽り: 自分に関わる決定の例外(ADR-0122)や1名の自己の任命の例外を使う体制で、組織の記録(登記・組織図・委任の記録)に任命の権限を持つ者がいる
- 「組織上の任命権者を名簿に載せていない」こと自体は所見にしない(ADR-0122 決定2 が推奨にとどめた)

### 裁定10 名簿・notice の未知の欄を拒否へ改める。形式の版は上げない(議題10)

- 名簿の要素と種別 notice の未知の欄を、変化点の入口で拒む(黙って捨てない)。保存された構成に手で書かれた未知の欄は、契約の検査で注意にとどめる(保存の時点で既に捨てられているため、通常は生じない)
- 旧い構成の表示は欄ごとに決めた(裁定1・3 は欠落、4 は件数、5 は判定できない、6 は欠落・未達、7 は注記)
- 形式の版(`formatVersion`)は上げない。新しい欄はすべて省略できる欄で、旧い版の構成の意味を変えない(`config.mjs:2760` の「読み込みで既定値を補うのは判定が同じか厳しくなる場合に限る」に当たる)。旧い版の準拠テンプレートが新しい欄を捨てる経路は残るが、それは版を戻す操作であり、取り込みの記録(ADR-0085 決定6)で追える。並行する #358 も名簿を触るため、版を上げるなら取り込みの時に一度で上げるのが安全である(申し送り)

採らない案: 版を上げる(品質監査・起案。上の理由で本件では採らず、#358 との取り込みの時の判断へ申し送る)/ 未知の欄を捨て続ける
