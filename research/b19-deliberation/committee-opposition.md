# 束 B19 会議体 反対の委員の意見

作成 2026-11-18。立場: 反対(案の正しさを前提にしない)。対象: `intake.md`(議長の裁定の案)。標準も template も変えていない。実物は IMPL-0978・1020〜1025・0298、ADR-0179・0184、D-0 とテンプレ11、`org-assurance.mjs`、`generate-profile.mjs`、`aggregate-evidence.mjs`、`template-fields.yaml`、`impl-targets.yaml`、`implementation-marking.md`、`handoff.md` を読んで確かめた。

審議の重さ「軽」と、ADR を起こさない判断には反対しない(条項の新設・改廃は無い)。以下は降ろし方への反対である。

## 所見

### O-1 読めない値の判定が「黒名簿」で、決定可能に閉じていない(重大度: 中)

- 所在: intake §2.1「1021・1022 の判定」の `parsePracticeInterval`、試験 IMPL-1021:ng
- 主張: 案は `parseInterval` に渡す前に、回数 2 以上・漢数字・「数回」「複数回」・幅・0 を弾く。弾く語を列挙する方式は完全にならない。`parseInterval` は文字列のどこかに「N日・週・か月・年」「半年」「四半期」「毎月」「毎年」があれば値を返すので、「毎月1回、繁忙期は2回」「2か月に1回、または随時」「半年ごと(重要案件は毎月)」のような自由な文が、先頭の語で読めてしまう。「回」の数が 2 以上かを、最初の一致だけで見るか全一致で見るかも案は書いていない。読み違いは、表示が出ない側(緩い側)へ倒れる。これは IMPL-1020 の「不利な側へ倒す」と逆向きで、表示と実態の食い違いになる
- 代案: 判定を白名簿にする。読める値を、数字+(日|週|か月|年)、半年、四半期、毎月、毎年、年に1回、月に1回と、それぞれに「ごと」「に1回」を付けた形の全体一致に限り、それ以外はすべて読めない値とする。読めない値は値を併記して表示するので、白名簿に倒れても失うものは小さい(利用者が値を書き直す)。決定可能な条件として閉じる。試験は白名簿の各形(ok)と、混在する自由文(ng)で対にする

### O-2 基準日に `releaseDay` を使うと、標準の条文と実態がずれ、出力にその旨が出ない(重大度: 中)

- 所在: intake §0 の6、§4 末尾、「採らない点」の時計の案
- 主張: 標準 5.4.7 と ADR-0179 決定2 は「保証の開示を作る日」と書く。案は `releaseDay`(範囲の終点のコミットの日。期間の開示では期間の末日)を使い、緩い側へずれうることを認めたうえで、IMPL-1022 の note への開示で足りるとする。しかし(1)読み手が見る保証の開示そのものには、どの日で照らしたかが出ない。note は台帳にしか無く、開示の読み手は「頻度を過ぎていない」を、作る日で照らした結果と読む。(2)「時計に依らない」という理由は半分しか成り立たない。`aggregate-evidence.mjs:4355` は `toDay || new Date()` で、終点の日が取れないときは時計に落ちる。(3)標準の文言と template の挙動の食い違いを、標準の側からは読めない
- 代案: 項目7 の塊の見出しか各行に「照らした基準日: YYYY-MM-DD」を必ず併記する(開示で食い違いを閉じる)。`toDay` が空で時計に落ちたときは、その旨も併記する。標準に 1 文足すかは議長が決める(意味を変えるなら軽の範囲を超えるので、足さないなら note と出力の併記で開示して閉じる)

### O-3 H-4 が、読み手の見る 節13 の行と別の実物(`config.changeLog`)で照合している(重大度: 中)

- 所在: intake §2.1「H-4」、試験 IMPL-0298:ok
- 主張: 利用者が指すのは D-0 節13(表8)の行である。節13 は構成から生成され、理由は `decidedBy` が埋まった行にだけ「決定した者(理由)」として出る(`generate-profile.mjs:3417` 付近。`decidedBy` が無い発生の行は「決定なし(発生)」で理由を出さない)。案は `config.changeLog[]` に `isFilledValue(e.reason)` の記録が 1 件でもあれば通す。すると(1)発生の行で `reason` を持つだけの記録が、D-0 に理由が見えないまま「指した先がある」と通る。(2)同じ日に複数の記録があるとき、別の変化点の理由で通る。351 の裁定の根拠(参照が消えた行を指し、理由の履歴が失われる)は、D-0 に見える理由の話である
- 代案: 照合の条件を「その日付の記録のうち `decidedBy` と `reason` がともに埋まっているもの」にそろえる(節13 に実際に出る形)。同じ日に複数あるときは「1 件以上」でよいと明記し、当該の兼務の決定かどうかは manual(内部監査)と note に書く。案が自分で引いた manual の線は正しいので維持する

### O-4 実施者の列を必須欄に登録しない案は、ADR-0179 の必須の 3 点を 1 点落とす(重大度: 中)

- 所在: intake §2.2「実施者の列は名を変えるので、見出し行の登録は先頭の2列までにとどめる」
- 主張: ADR-0179 決定1 は「必須はこの3点だけ」とする。登録を 2 列までにすると、template が実施者の列を落としても `test:fields` は通る(集約は「記録が無い」を出すので害は表示に出るが、様式の必須欄を機械が見る原則 ADR-0040 から、3 点のうち 1 点だけ保証しない形になる)。「名を変える」は登録できない理由にならない。`template-fields.yaml` は `standard` と `template` の文字列が違う登録を許す(「AI自律レベルの適用」の登録がその例)
- 代案: 3 列とも登録する。標準側は `実施者(表5-2 の人)`、template 側は `実施者(節1 の人の名簿の人)`

### O-5 台帳・降ろし先・他の IMPL の note の食い違いを直す作業が一覧にない(重大度: 中)

- 所在: intake §3 の表
- 主張: 降ろすと次の記述が実態と食い違う。案は IMPL-1020〜1025・0978・0298 の note だけを直す。(1)`src/data/impl-targets.yaml` の `d0-template` の description「…の表(IMPL-1023。予定)」と `evidence-aggregation` の description「…の表示(IMPL-1022。予定)」。(2)IMPL-0070 の note「5.4.7 の頻度の行は含まない(IMPL-1020。降りていない)」、IMPL-0071「…IMPL-1021 が追い、降りていない」、IMPL-0777「…IMPL-1023。降りていない」。(3)標準本文の「(2026-11-17 時点)無い」の類の注記。残すと「降りていない」と表示され続け、表示と実態の食い違いになる(高に当たりうる)
- 代案: §3 の各順に「上の記述の更新」を足し、`grep -rn "降りていない\|2026-11-1[78] 時点" src/content/docs src/data` で残りを出して直す。独立の突合の観点にも入れる

### O-6 IMPL-1024 の「.github/ の変更は AI維持管理者の承認を経る」の根拠が手引きに無い(重大度: 中)

- 所在: intake §2.1「1024 の手引き」
- 主張: 案は「`.github/` の変更は強制層であり、AI維持管理者の承認(`state:needs-platform`)を経る」と書く。`handoff.md` で `needs-platform` を引くのは「遮断の解除・閾値の緩和・強制層の縮小」(:15、:51 の表)で、警告を必須へ上げる(強める向き)は載っていない。強める向きに同じ承認を課すと、手引きが新しい義務を作る(失うのは生産性だけで、方針の問い 3 の 3 つに当たらない)。逆に、実際に承認が要るなら出典を示す必要がある
- 代案: この 1 文を削るか、出典を示してから書く。確かめられなければ「昇格の変更の承認の経路は採用者の定めによる」とだけ書く

### O-7 範囲に関する試験の対が足りない(重大度: 中)

- 所在: intake §3「試験の対」
- 主張: 違反と適合を分ける対が欠けている。(1)D-0 の表が L1 と書く 3 つの理由(`allowed` が偽、上限が L3 未満、手戻り率が未計測)のうち、案の試験は `allowed` が偽と種別の登録なしだけ。残る 2 つが無いと、「表と項目7 が食い違わない」ことを固定した理由(採らない点)が試験で守られない。(2)複数の実施者のうち 1 名だけが名簿に無い行(標準は「そのすべて」)。(3)実在しない日付の行(2026-02-30)。(4)最後の実施の日の判定で、数えない新しい行が、数える古い行より後にあっても、古い行から頻度を数えること。(5)層1 に行そのものが無い案件(既存の採用者がテンプレートを更新した直後)と、層1 自体が無い案件。案は「空欄」としか書かず、この 2 つの扱いが決まっていない。(6)組織の外へ渡す形で実施者の名が出ないこと
- 代案: 上の 6 点を対に足す。(5)は、行が無い層1 を「空欄」として表示する(出す側)と決めて固定する。層1 が無い案件は、層1 が無いこと自体が別の欠落として出るので、重ねて出さないと決める

### O-8 L3 の範囲の導き方を共有化する変更は、生成の経路を同時に動かす(重大度: 低)

- 所在: intake §2.1「範囲」、§3 順 2
- 主張: `renderAutonomyTable` を新関数に寄せると、すでに試験された D-0 生成区間(`check-d0`)の経路を触る。共有する理由(表と判定が食い違わない)は正しい。しかし、生成物が 1 バイトも変わらないことが受け入れ条件なのに、案は `test-init-g5` を挙げるだけで、前後の差分が空であることを固定していない
- 代案: 代表の 4 構成(allowed 偽・上限が L3 未満・手戻り率未計測・L3)で、変更の前後の生成区間が一致する試験を足す。新関数は種別の id の配列だけを返し、表の文字列を作らない

### O-9 読めない値の追加の定義(幅・0)が、同じ表の他の行と整合しない(重大度: 低)

- 所在: intake §2.1「1020 の行」の箇条、§1 の 4
- 主張: 標準が読めない値として例示するのは「1期間に2回以上」だけ(`deliverable-templates.md:1771`)。案は「3〜6か月」の幅と 0 を足す。同じ表の他の行(演習・退出の予行・縮退の実測・力量の確認)は、「3〜6か月」を長い側の 6 か月として読む。同じ層1 の表の中で、同じ字面を行によって読み分けることになる。幅の読み違いで失うものは小さく、細かい定義を足す理由が弱い
- 代案: 0 以下(決定可能で、常に頻度切れになる値)だけを足す。幅は、白名簿(O-1)の結果として「白名簿に無いので読めない」と導き、箇条に別の定義を書かない

### O-10 基準日より後の実施を数えない扱いの利用者向けの説明が無い(重大度: 低)

- 所在: intake §2.1「1023 の表」の記入の手引き
- 主張: 基準日が `releaseDay`(範囲の終点の日)なので、終点より後の実施日の行は、その出荷の集約では数えず、後の出荷で初めて数える。手引きに書かないと、利用者は「書いたのに数えられない」と見る
- 代案: 記入の手引きに「出荷の範囲の終点の日より後の実施は、その後の出荷の集約で数える」と 1 文足す(新しい義務ではない)

### O-11 IMPL-1025 の `reason` の書式「条件2: …/条件3: …」は、機械が見ない書式を足す(重大度: 低)

- 所在: intake §2.1「1025 の手引き」
- 主張: manual なのに書式を決める。方針の問い 1(結果と証跡まで。手順は手引きへ)に合うのは、照らした結果が理由に残ることまで。区切りの書式は手順の細部で、細かい定義の増加に当たる。書式を満たせば足りると利用者が読む
- 代案: 「条件2〜7 のそれぞれについて、照らした結果を理由に書く」とだけ書く。書式は例示にとどめる

## 他の委員に議論を求める点(私は結論を出さない)

- IMPL-1023 の置き場(§0 の3)は ADR-0179 決定1 の「直下」を字面どおりに守らない。案は ADR を起こさず、template-fields のコメントで開示する。生成区間の直後に `###` を使わず太字の見出しで置き、`after` の正規表現を変える代案もある(この場合は直下になる)。いずれでも IMPL-1023 の note に所在と理由を書くこと
- 範囲の判定の「L3 の行」は、停止中(`L3(停止中は L1)`)の範囲を含む。停止中は一時的に L1 なので「L2 以上を適用する範囲」から外れる読みもある。決定可能な条件(表の静的な文字列)に揃えた案を支持するが、含める旨を note に 1 文書くこと

## 案に同意する点

- 審議の重さを「軽」とし、ADR を起こさないこと。いずれも ADR-0178・0179・0184 の内側の降ろし方である
- 1021 で `parseInterval` を直に使わず、1022 で `intervalEnd` を直さずに別関数 `practiceDue` を新設すること。月末の繰り越しと回数の捨てを避けられ、既存の失効の日を動かさない
- 1021・1022 を `gaps`・`cycleNotices`・組織継続の側の状態に入れないこと(ADR-0179 決定2 の「止めない」「受容を求めない」)
- 0978 を 1020〜1023 が揃った後に `delivered check=manual` とし、確かめる者に実施の中身を置かないこと(ADR-0179 決定4、EV-0322)
- 1024・1025 を manual にすること。`implementation-marking.md` が「手順の文を持つファイルの実在だけを確かめる検査は manual」と定める。1025 を構成の欄と `config.mjs` の検査で閉じない判断も、統制の閉じ方の裁定に合う
- 1025 の降ろし先を既存の `process-change-skill` へ付け替え、新しい降ろし先を作らないこと
- H-4 で、指した行の意味(当該の兼務の決定か)を manual のままとすること、日付の字面を 1 つに絞ること
- 参照の字面を B16 が決めていなかったと正直に記録した点(§0 の1)
- 実施者の区切りに「・」を使わないこと、AI の名義を `aiNameBlocked` で弾くこと
- 試験の目印を `IMPL-NNNN:ng` / `:ok` の別の行にし、`intervalEnd` なら通ってしまう日付(基準日 2026-02-28 と 03-01)で対を作ること
- template と本体の push を対で行う順序
