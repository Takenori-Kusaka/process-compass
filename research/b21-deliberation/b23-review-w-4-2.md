### H-2(高)版が読めないと失敗にする処理が、template 自身の squash の取り込みで正しい案件を止める見込み

- 所在: `check-g1.mjs` 326〜333 行、`template/CLAUDE.md` 192 行(「マージは squash」)、`.claude/skills/implement/reference/commit.md` 9 行、`.github/workflows/gate-entry.yml` 69 行
- 根拠: 判定の受け皿は判定者本人の承認レビューの本文で、判定は取り込みの前に行う。このとき「参照した企画書の版」に書くのは PR のブランチの上のコミットになる。G-1.md 31 行・様式 04 18 行は、取り込んだ後のコミットを書けとは求めていない。squash で取り込んでブランチを消すと、そのコミットは既定ブランチから辿れなくなる。`actions/checkout` の `fetch-depth: 0` は、ブランチとタグの参照だけを取る(refs/pull/* は取らない)と見る。そうなると、その後の PR と週次の実行では `git show <版>:docs/D-0-governance.md` が読めず、「確かめられません…失敗として扱います」が出続ける。直しの前は、同じ場合が注意だった(1巡目 L-2)。同じ版を使う 7.7.9 の書き換えの検査(213〜217 行)は、今も読めないときを注意にしている。check-g1 の中で扱いが揃っていない
- 確からしさ: 実物の GitHub では確かめていない(note も実物は未確認と開示している)。checkout が取る参照の範囲と、squash の後にコミットが辿れなくなることからの推論である。判定者が取り込みの後のコミットを書く運用なら起きない。ただし、その運用はどこにも定められていない
- 直しの案(**直すべき**。議長が案を選ぶ): (i) gate-entry.yml で `git fetch origin '+refs/pull/*/head:refs/remotes/origin/pull/*'` を足し、PR の先頭のコミットも取得の範囲へ入れる(失敗の扱いは裁定どおりに保てる)。(ii) G-1.md・SG.md・様式 04 に「取り込んだ後の既定ブランチのコミットを書く」と定める(G-1 の判定の後に記録を書き直す手順が要る)。(iii) 辿れない版のときだけ注意に戻す(裁定の「止める側に倒す」と逆になるので、採るなら裁定の変更として記録する)。どの案も採らない場合は、少なくとも note と G-1.md に「squash で取り込むと版が辿れなくなり、以後は失敗する」と開示する。しかし表示と実態が合っても、正しい案件を止める点は残る
