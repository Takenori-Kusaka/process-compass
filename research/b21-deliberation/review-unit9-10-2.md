### M1 判定の終点(`isApproved`)が、AI 名義の承認を除いていない。除くのはボットだけである

- 根拠: `review-queue.mjs` の `isApproved` は、`user.type === 'Bot'` か、末尾が `[bot]` の login だけを除く。`aggregate-evidence.mjs:1950・2227` は、判定完了時間の終点に人の承認だけを数える。AI 名義は `aiAccountCheck(config, login, bot)`(`config.mjs:3201`)で除く。AI の担い手を通常のアカウントで動かす構成では、AI の承認で判定の超過の通知が止まる。note(IMPL-0979)は「ボットでなく…aggregate-evidence の数え方に寄せた近似」とだけ書き、AI 名義の扱いを開示していない
- 再現: `node cx3.mjs <写し>`。`claude-agent`(bot=false、COLLABORATOR)の APPROVED で `isApproved` は true を返す
- 影響: G-6 の合否は gate-g5 が人の承認で判定するため、統制は外れない。止まるのは通知だけ。ただし、AI の承認で代理の指名の求めが黙る
- 直しの案: `isApproved(pr, { config })` で `aiAccountCheck` を使う。決定可能な条件なので、機械で閉じられる。直さない場合は、0979 の note へ「AI 名義の承認(構成の AI の担い手の名義)は除いていない」と書けば開示で閉じられる

### M2 「条文の読みが割れている」という申告は、割れていない。0979 の note と #445 への寄せは過大な表示になる

- 直しの案: 0979 の note の「D-0 節5 と3.9.1 の「上程の受理日から起算」は別の読みで、条文の読みが割れている(会議体の上程に係る3.9.1 を PR に当てない)」を、「D-0 節5 が引く3.9.1 の「上程の受理日から起算」も、PR では上程=レビュー依頼と読み、同じ起点になる」に改める。直さない場合も、#445 へのコメントは割れとして寄せない
