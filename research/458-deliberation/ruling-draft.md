## 0. 結論の要約

1. 試行の承認と採用の承認は**別の決定**である。附属書D §7 はこの2つを分けて書く。I.12 の「最終決裁者 = 層1 の記名者」は採用の承認であって、試行の開始の承認ではない
2. 試行の間の出荷判定の署名の意味は、**第4章 G-7 が正本**である。既存規程の該当条項は、規程の改定(案件に限る附則を含む)か、サンドボックスの対応表で G-7 に置き換える。手段は採用組織が選ぶ。本標準が求めるのは結果(試行の出荷判定より前に、署名の意味が既存規程と G-7 とで二重になっていない)と、その証跡(どの文書で置き換えたかの記録)だけである
3. 層1 の記名を T-1 の開始の条件に**しない**。「試行に限った暫定の層1」という区分も**作らない**。層1 なしの試行の帰結(全変更が品質保証の対象外。§6 の成立判定の記録は対象外の件数だけになる)を附属書D §7 に書く。試行の前に層1 を得る採用者の選択(所有者の意向)は妨げず、成立判定を試行で評価するならその選択が要ることを手引きとして示す
4. 承認者の組を本標準で定め**ない**。附属書D §7 は「事項ごとに要る権限」を書き、氏名・記名欄を置かない。誰がその権限を持つかは採用組織の職務権限規程による
5. 中止の条件に当たったとき、試行の責任者は他の承認を待たずに元の手順へ戻してよい。止める者を増やす上乗せ(QA 部長も止められる)は妨げない。止めるのに要る承認を増やす上乗せ(QA 部長の記名が無いと止められない)は、3.13.3・7.7.8 要求事項7 の非対称と食い違うため、してはならない形として示す

## 7. 準拠テンプレートの変更の要否

**要る(この束では変えない)**。

- 論点1 の「どの文書で置き換えたかを試行前チェックリストに記録する」は、チェックリストの行を改める(または足す)ことを要する。チェックリストの文は標準と `template/templates/trial-checklist.md` の両方向で一致を検査される(IMPL-1002、check-template-drift.mjs)。本体の側だけ行を変えると `npm run check` が落ちる

- 束 D1 で改める行の案: 「既存規程の免除を要する場合、サンドボックス申請が承認され、免除の期限が記録されている」を、「既存規程が本標準と食い違う場合、規程の改定(附則を含む)またはサンドボックスの承認で解消し、解消した文書と、サンドボックスでは免除の期限が記録されている。出荷判定の署名の意味の条項を含む」へ。ADR-0116 決定2 の文を置き換えるため、ADR-0265 に経緯を書く
- 閉じる前の注意: issue=458 の降りていないマークが残るため、#458 は束 D1 の実装まで閉じない(閉じる前に計画のマークを確かめる)。または D1 の Issue へ計画を移してから閉じる
