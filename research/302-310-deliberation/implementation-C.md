### 0.1 文末(1.7.1)

| 種類 | 本文(ですます調) | 箇条書き・表(である調) |
| --- | --- | --- |
| 要求 | 〜します/〜とします/〜によります/〜しなければなりません | 〜する/〜とする/〜による/〜しなければならない |
| 禁止 | 〜しません/〜してはなりません | 〜しない/〜してはならない |
| 推奨 | 〜することを推奨します/〜することが望ましいです | 〜することが望ましい/〜を推奨する |
| 推奨しない | 〜しないことを推奨します | 〜しないことが望ましい/非推奨 |
| 許容 | 〜してよいものとします/〜して差し支えありません | 〜してよい/〜してもよい |
| 可能性・能力 | 〜できます/〜場合があります/〜ことがあります | 〜できる/〜場合がある |
| 外部の制約 | 〜とされています/〜と定められています | 〜とされている |

- **平叙の動詞文(「〜します」「〜しません」)は要求として読まれる**。説明のつもりの文を「〜します」で書かない。理由は「〜ためです」「〜からです」、事実と定義は名詞で結ぶ「〜です」、補足は `:::note` に書く
- **「〜できます」を許容に使わない**。許容は「〜してよいものとします」。「〜できます」は能力・可能性に限る
- **依頼の形(「〜してください」)と「〜すべきです」は使わない**。`npm run check`(`lint:provisions`)が、本文 8 章と規定の附属書(B・D・F・H)で落とす
- 主語が「本標準」の文(「本標準は〜を課しません」)は、課さないと決めたことの表明として読まれる。課さないと明記する箇所は、この形で書く
- 要求事項を、名詞で結ぶ文(「最小体制は3名です」)と注記に書かない。効かせる事項は「〜とします」で書く(A-6 の「最小体制は 3 名」が該当する)
- 法令は「〜とされています」の形で書く(B-5 の決定と同じ形。1.7.1 の「外部の制約」の行)

### 0.2 表の升の語(1.7.3)

- 工程ゲートの状態の升は **適用・簡略・統合・省略・未達** の 5 語だけ。限定は括弧で添える(「適用(コア機能)」「統合(G-4 へ)」)
- 規定の強さの升は **必須・禁止・推奨・非推奨・許容・不要**
- **「省略可」「任意」「どちらでもよい」は使えない**。本文 8 章と規定の附属書では、升でも地の文でも `lint:provisions` が落とす

### 0.3 附属書の種別(1.5)

| 附属書 | 種別 | 本文からの引き方 |
| --- | --- | --- |
| A・C・E・G・I | 参考 | 「附属書X 参照」。**要求・禁止の文末(〜なければなりません/〜てはなりません)と実装マークを置けない**(`lint:provisions` が落とす) |
| B・D・F・H | 規定 | 「附属書X によります」 |

- 新しい要求事項を、参考の附属書(とくに附属書C・E・I)へ足さない。本文か、規定の附属書へ置く。参考の附属書からは「第N章 x.y 参照」と所在を書く
- A-7(「第三者レビュー」の定義を附属書から第1章 1.4 へ移す)は、この決まりと同じ向きである

### 0.4 同じ事項は 1 か所に書く(1.7)

- 数値・手段の列挙・判定基準を 2 か所に書かない。正本でない側は「第N章「節名」によります」と引く
- 条項を改めて古い言い回しを廃したときは、`src/data/retired-phrases.yaml` に句を登録する。`npm run check`(`lint:provisions`)が、公開ドキュメント・規則データ・準拠テンプレートに句が残っていれば落とす
