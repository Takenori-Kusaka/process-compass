# #370 会議体(軽) 委員2: 反対の委員

2026-11-05 時点の作業ツリーで読んだ。調査は `survey-370.md`(以下 SV)。TG = `phase4-process-design/tailoring-guide.md`、RR = `roles-responsibilities.md`、DT = `deliverable-templates.md`。判断軸は信頼性に置く。変更量は採否の理由にしない。

## 論点1 人数を組織をまたいで合計で数える読み(SV 2.1)を採るか

**推す案**: 採る。ただし (a) の表に、合計で3名に達した時点の帰結の行を必ず入れる。その行で明文の欠けが見つかれば、軽では埋めずに未決として開示する。

**理由**
- 価値責任者を「体制の外」と読む経路は塞がっている。外部の確認者は統制を緩める向きの決定権を持たない(RR:416)。価値責任者は G-2・G-4 の判定者である(TG:650・:652)。この2つは両立しない。組織上の任命権者も「体制の外の人」である(DT:306)。残る区分は「体制の内」だけになる。SV 2.1 の読みは、既存の文から一意に導ける
- 名簿の「所属」の欄は10名以上で必須である(DT:152・:431)。1つの名簿に複数の所属の人が載ることを、標準は既に想定している。合計で数える読みは、この欄の設計と合う

**SV の読みの弱点(欠陥と認める)**
1. **3名の境界で、未達の表示が拒否に変わる**。発注側が価値責任者の丙のほかに、事業決裁者の丁を置いたとする。体制は3名になる(SV A4・S3b)。3〜9名の独立レビューの升は「チーム内の、作成を指示した者と別の人」であり(TG:159)、未達の経路を持たない(SV 3.3 の7、S9 は拒否)。受注側1名が G-6 を受注側に置く構成は、発注側の人数が1名増えただけで「未達として表示」から「構成できない」へ変わる。受注側の判断と関係のない、相手方の体制の変化で詰む
2. **この詰みは、置き先の限定を事実上つくる**。3名以上の委託では、G-6 を受注側に置くと、受注側が第三者の外部の確認者を置くしかない。ところが (イ)(外部の確認者を独立レビュアの席の責任者に置く置き方)の書面の合意・任免の記名・力量の確認(RR:415)は、受注側で完結するのか発注側の決定者を要するのかが書かれていない。ADR-0069 決定2(`adr/0069-…md:50` 置き先をいまの許容より狭めない)に、規定の組み合わせが実質で抵触するおそれがある
3. **3.5.2 の例外は3名で失効する**(RR 3.5.2 条件1)。A3 の構成(丙が独立レビュアと出荷判定者を兼ねる)は、発注側が丁を加えた時点で禁止の兼務になる(RR:326)。委託の契約の途中で発注側の体制が変わると、受注側の構成が違反に落ちる。この変化を受注側へ知らせる経路が無い。変化点の記録(`/process-change`)は、受注側のリポジトリでは発注側の人事を拾わない
4. **10名の境界は、小さい発注側を詰ませる**。受注側9名と発注側の価値責任者1名で10名になる。出荷判定の升は「QA部門・専任」になる(TG:160)。G-7 は発注側に固定である(TG:655)。発注側が1名の会社なら、出荷判定の席を発注側で満たせない。SV 5節の末尾が「波及を突合で確かめてから決める」と書いた点を、本委員は未解決の欠陥と認める。(a) の表は、この行も置くべきである

**他の案を落とす理由**
- 受注側だけで数える案: 価値責任者の区分を決められない(上の理由)。受注側1名を「1名の体制」と読むと、RR:1994 の自己の任命の例外や 1名に常に当たる規定(`overview.md:641`)が委託の受注側に誤って掛かる。却下
- 発注側だけで数える案: 開発者の席の責任者が名簿から落ちる。却下

**新しい義務**: 読みの明文化は課さない(既存の帰結)。上の弱点1〜3のうち、3名以上の委託で G-6 を受注側に置くときの (イ) の決定者を定めることは**新しい義務**である。定めるなら**重へ上げるべき**。軽では、表の該当の行へ「明文なし」と書き、`:::caution` で開示するに留める。弱点3の発注側の体制の変化を受注側へ知らせる義務も新しい義務であり、課すなら重である。

## 論点2 置き先(テンプレ8 第9項)と表5-2 の区分の対応を、どちらの側で書くか

**推す案**: テンプレ8 第9項の側へ書き、表5-2 の側には参照の1行だけを置く。あわせて、SV 2.4 の2点目の読みを訂正する。

**SV の読み違い(訂正)**
- SV 2.4 の2・3.3 の5は「席の責任者は外部の確認者に当たらない」と書く。この読みは広すぎる。RR:415 の (イ) は、外部の確認者を**独立レビュアの席の責任者**に置く置き方を認めている。外部の確認者が席の責任者になれないのは、独立レビュアの席の**ほか**の席である(RR:416 が統制を緩める向きの決定権を与えないため)。したがって S4(丙を外部の確認者として独立レビュアの席に置く)は、丙が価値責任者を兼ねない限り、(イ) の3条件のもとで正当な構成になりうる
- この訂正を入れずに「発注側の席の責任者は外部の確認者に当たらない」と書くと、(イ) と矛盾する条項ができる

**理由(第9項の側を推す)**
- 置き先は開始の前に決める契約上の事実である(TG:645・DT:1356)。区分は名簿の上で人数を数えるための事実である(DT:149)。読む順は「置き先を決める → 置いた側の人の区分が決まる」である。逆向きには導けない
- 表5-2 は内製を含む全ての開発形態に掛かる。委託に固有の対応を表5-2 へ書くと、内製の採用者が読む欄に、関係の無い条件が増える
- 第9項に書く内容は、次の対応の1行で足りる。G-6 を「発注側」に置いた場合、確認する発注側の人は体制の内の人である。G-6 を「受注側」に置き、受注側が体制の外の人に確認を頼む場合に限り、その人は外部の確認者である

**他の案を落とす理由**
- 表5-2 の側で書く案: 上の2つ目の理由で落とす
- 両方に全文を書く案: 2か所の文が分かれて改訂されると食い違う。参照の1行に留める

**新しい義務**: 課さない。発注側の人を「外部の確認者」として受注側の名簿へ載せることを**禁じる**なら、新しい拒否の組になり、締める向きの義務である。禁じるなら重へ上げるべきである。本委員は、軽では禁じない。禁じない理由は、(イ) の経路を委託だけ閉じる根拠を、調査が示していないためである

## 論点3 ext-vo の穴を #370 で扱うか、#357 と合わせるか

**推す案**: 穴の塞ぎ方(テンプレートでの拒否または注記)は #357(OPEN「外部の確認者と2名必須の制限と組織的な独立を、構成の欄で表す」)へ送る。#370 では、標準の側で「外部の確認者を、独立レビュアの席のほかの席の責任者に置かない」が既存の帰結であることを明文にし、降りていない旨の実装マークを付ける。

**理由**
- 穴は委託に固有ではない。内製でも、外部の確認者を価値責任者や出荷判定者の席に載せれば、人数を1名と数える(SV 3.3 の5)。#370 だけで塞ぐと、委託の構成だけを拒み、内製の同じ穴を残す。非対称が残る
- #357 は外部の確認者の席の置き方を構成の欄で表す Issue である。拒否の組を足すなら、(イ)(RR:415)の欄と同じ箇所で決めないと、(イ) の正当な構成まで拒む誤りが起きる(論点2 の訂正)
- 送るだけで済ませると、#357 が閉じるまで穴が見えない。降りていない規定は消さずに表示し続ける(本標準の運用)。このため、#370 でマーク(`state=undelivered`、`plan=scheduled`、`issue=357`)を付ける

**他の案を落とす理由**
- #370 でテンプレートの拒否まで入れる案: 上の非対称と (イ) の誤拒否のおそれで落とす。強制層の変更は AI維持管理者の承認(`state:needs-platform`)も要る
- 何も付けずに #357 へ送る案: 穴が台帳に出ない。読み手が「確かめている」と誤読する。落とす

**新しい義務**: 標準の側は課さない(RR:416 と DT:306 の帰結)。テンプレートで新しく拒む組は締める向きの強制であり、#357 の側で扱う。#357 が軽で審議されるなら、その拒否の部分は重へ上げるべきである

## 論点4 G-7 の D-1 の過剰表示(SV 3.3 の4)を別の Issue へ分けるか

**推す案**: 分ける。#370 では、SV 2.2 の表の G-7 の列を、標準の文(TG:160 の限定)どおりに書く。テンプレートの表示が標準と食い違う旨を、表の行の中で注記する。

**理由**
- 過剰表示は委託に固有ではない(SV 3.3 の4。内製の2名でも起きる)。#370 で直すと、委託の Issue で内製の挙動を変える。範囲の外である
- 「締める向きだから害が無い」とは読まない。D-1 を表示すると、3.5.2 の条件2〜4(G-7 の判定記録と突合、運用作業カタログの抜き取り確認、D-0 への明記)が、兼務の無い構成にも課される(RR 3.5.2 の表)。逸脱でない構成を逸脱として開示すると、保証の開示を読む者は、本当の逸脱を区別できない。信頼性を下げる過剰表示である
- 一方で、表示を減らす修正は緩める向きの変更である。テンプレートが「席の実際の兼務」を読む前提(`approverMode` ではなく名簿と席から導く)が正しく実装されたことを確かめてからでないと、真の D-1 を落とすおそれがある。独立の Issue で、違反と適合の対の試験とともに直すべきである

**他の案を落とす理由**
- #370 で直す案: 上の範囲の理由と、試験の対を伴わない修正の危険で落とす
- 直さずに開示だけ続ける案: 上の2つ目の理由で落とす。過剰表示を恒久にしない

**新しい義務**: 課さない。修正は標準 TG:160 に合わせるもので、義務を増やさない

## 論点5 IMPL-0342 の `issue=` を付け替えるか

**推す案**: 付け替える。#370 を閉じる**前に**、テンプレートの変化点の記録へ自己の任命を残す経路を扱う Issue を起票し、`issue=` をその番号へ替える。#370 の決定の記録には、IMPL-0342 が本件で解けない理由を1行で残す。

**理由**
- 自己の任命の例外は「本人の上に任命の権限を持つ者がいない1名の体制」に限る(RR:1994)。論点1 の読みでは、受注側1名の委託は2名以上の体制である。例外は委託の案件には当たらない。RR:1994 の末尾「より大きな組織の中の1名の体制は、任命権者が別にいるため当たらない」とも同じ向きである
- 未達の中身は、テンプレートが組織上の任命権者を席の責任者との同一で拒むために記録の経路が無いことである(SV 4節)。内製の個人事業主にも当たる。#370 の決定で降りる性質ではない
- 閉じた Issue を計画の先に持つ `plan=scheduled` のマークは、「降ろす予定」が偽になる。台帳を読む者を誤らせる

**他の案を落とす理由**
- `issue=370` のまま置く案: 上の3つ目の理由で落とす
- `plan=adopter` へ変える案: 採用者に委ねると決めた記録(`decision=`)が無い。テンプレートの欠けを採用者へ押しつける決定になり、重の判断である。落とす

**新しい義務**: 課さない。番号の付け替えだけである。ADR-0087 :159 の「`issue=317` を仮に置く」は採用済みの本文として残し、書き換えない

## 論点6 受注側が価値責任者に座る構成(S1)を確かめない旨の開示

**推す案**: TG:593 の「価値責任者は発注側に置く(必須)」に実装マークを付ける。`state=undelivered`、`check=manual`、`plan=scheduled` とし、計画の Issue を起票する。確かめる者は、発注側の価値責任者本人と、プロセス内部監査の観点6(DT:156)と書く。

**理由**
- 降りていない規定は消さずに表示する(本標準の運用)。マークが無いと、採用者はテンプレートが所属を確かめていると誤読する。S1 は受注側の自社リポジトリで、発注側を名簿へ載せずに組める(SV 2.4 の1)。これは論点1 の読みを明文にしても、文だけでは止まらない抜け道である
- ADR-0069 決定2 は「席と受信箱に組織の所属の属性を持たせない」(`adr/0069-…md:53`)。所属で確かめる実装は、この決定に当たる。ただし、所属を持たずに出せる手がかりはある。開発形態が受注側(vendor)で、価値責任者の席の責任者が開発者の席の責任者と同じ人なら、TG:593 に反する見込みが高い。`/pit` の注記(合否と段階に使わない。IMPL-0337 と同じ扱い)なら、ADR-0069 に当たらずに降ろせる。計画の Issue でこの経路を検討する

**他の案を落とす理由**
- `plan=adopter` とする案: 受注側の採用者に「自分が価値責任者に座っていないか」を確かめさせることになる。S1 を組む当人が確かめる者になり、自己確認で閉じる。落とす
- 構成の生成で拒否する案: 発注側の人が開発者の席も担う協働の委託まで拒む。所属の属性を持たない限り正誤を判定できない。拒否は ADR-0069 決定2 の置き換えを要し、重である。落とす
- マークを付けない案: 上の1つ目の理由で落とす

**新しい義務**: 標準の側は課さない(TG:593 は既存の規定)。`/pit` の注記は合否に使わない表示で、義務を増やさない。拒否へ進めるなら新しい強制であり、**重へ上げるべき**である
