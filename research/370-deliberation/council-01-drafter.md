# #370 会議体(軽) 委員1: 起案

立場: 規定として書ける形と、既存の条項・語彙との整合を重視する。調査 `survey-370.md`(以下 SV)の第6節の6論点に答える。判断軸は信頼性である。所在の略記は TG = `phase4-process-design/tailoring-guide.md`、RR = `roles-responsibilities.md`、DT = `deliverable-templates.md`、GC = `gate-criteria.md`。

## 論点1: 委託の体制の人数を、組織をまたいで合計で数えるか

**推す案**: 合計で数える読みを採り、軸A の人数の数え方(TG:166)の段落へ、委託の場合の一文を足す。起案の文は次のとおり。

> 開発形態が受託の案件では、発注側・受注側の別を問わず、D-0 表5 に記載した人のうち区分が体制の内の人を合算して数えます。価値責任者は発注側に置く席の責任者であり(軸D)、体制の内の人です。

**理由**

- TG:166 は「D-0 表5 に記載した人のうち、表5-2 の区分が体制の内の人」で数える。組織で絞る文言は無い。合計の読みは既存の文の字義どおりであり、新しい規範ではない
- 価値責任者は発注側に必須(TG:593)。席の責任者は表5-2 の3区分(DT:149)のうち、外部の確認者(席に置けるのは RR:409-417 の(イ)の独立レビュアの席だけ)にも組織上の任命権者にも当たらない。残る区分は体制の内しかない
- 表5-2 の「所属(10名以上の体制で必須)」の列(DT:428)は、名簿に所属の異なる人が並ぶことを既に想定している
- 明文が無いと、受注側が発注側を名簿へ載せずに1名の体制として構成できる(SV 2.4 の1、S1)。この構成では価値責任者の席に受注側の人が座り、TG:593 に反するのに、テンプレートも読み手も気づかない。信頼性の穴であり、明文で塞ぐ

**波及の扱い**(突合で確かめる事項として起案する)

- 10名の境界: 受注側9名+発注側1〜2名で10名以上の升へ移る。新たに当たるのは「価値責任者×技術判断者の禁止」(TG:157、RR:323)と所属の必須(DT:428)である。前者は発注側1名が G-3 を発注側に置いて技術判断者を兼ねる構成でだけ効く。この兼務の牽制は組織の別では生じない(G-2・G-4 と G-3 が1人の中で閉じるのは同じ)。合計で数えて禁止へ移ることは、TG:157 の理由に照らして正しい
- 兼務の非推奨(RR:323・:328): 3名以上で記録を求めるだけで、組織をまたいでも理由はそのまま当たる
- 1〜2名 × CL1 の不可(TG:248): 合計で数えると、受注側1名+発注側1名の CL1 案件は2名で、構成そのものが認められない。受注側だけで数えても1名で同じ結論になる。帰結は変わらない

**落とす案**

- 受注側だけで数える案: 落とす。発注側の価値責任者を数えない根拠が既存の語彙に無く、第4の区分(「相手方の席の責任者」等)を表5-2 へ新設する必要がある。表5-2 の3値を前提にした G-6 の4条件(GC:1002-1004、:1032-1034)と人数の回答の照合(IMPL-0300)をすべて組み直すことになり、整合が崩れる
- 書かずに審議の記録へ残すだけの案(SV 5 の (e)): 落とす。S1 の構成を止められない

**新しい義務**: 課さない(既存の文の字義の確定)。ただし 10名の境界を越える案件では、所属の記入と禁止の兼務が新たに当たる。会議体がこれを新しい義務と見るなら、当該の波及部分に限って重へ上げるべきである。起案者は、既存の TG:166 が既に課していると読む

## 論点2: 置き先(テンプレ8 第9項)と表5-2 の区分の対応を、どちらの側で書くか

**推す案**: テンプレ8 第9項の G-3・G-6 の行(DT:1355-1356)の側で書く。表5-2 には書かない。起案の文(第9項の注記と、TG の「判定をどちらの組織へ置くか」の表の G-6 の行の中へ同じ限定を置く)は次のとおり。

> 独立レビュー(G-6)を発注側に置く場合、確認者は発注側の、D-0 表5-2 の区分が体制の内の人とする(適用: 開発形態が受託)。受注側に置く場合、確認者は受注側の体制の内の人、または受注側が置いた外部の確認者とする(同)

**理由**

- 置き先は契約の締結時に決める事項であり(TG:645)、記録の正本は第9項である。対応の規則を置き先の記録の隣に置けば、締結の時点で読み手が一度に確かめられる
- 表5-2 は体制の種別を問わない名簿の様式であり(DT:112・:149)、委託に固有の限定を入れると、内製の採用者に関係の無い行が増える
- #226 の規約(限定を規範と別の段落へ置かない)に合わせ、限定を表の行の中に書く。TG の置き先の表の G-6 の行(TG:654)の「理由」の欄の隣へ置く形が、既存の表の構造を崩さない
- 論点1 の合計の読みを採ると、発注側の人は体制の内である。「発注側の人を受注側の外部の確認者として載せる」構成(S4)は、発注側に置いた G-6 を受注側に置いたように記録するもので、置き先と区分が食い違う。上の文はこの食い違いを規定の上で起こせなくする

**落とす案**

- 表5-2 の側で書く案: 上の理由で落とす
- 第9項に「G-6 の確認者の席と氏名」の欄を足す案、または委託の案件で所属の列(DT:428)を10名未満でも必須にする案: 記録から置き先と区分の一致を機械で確かめられるようになる。信頼性の向上はある。ただし様式の必須欄を足すことは新しい義務であり、本会議体(軽)では採れない。採るなら**重へ上げるべき**である。起案者は、上の文で規範の上の食い違いは閉じ、機械の検出の欠けは論点3 の実装マークで開示すれば足りると考え、本件では採らない

**新しい義務**: 課さない。発注側に置いた G-6 の確認者を発注側の体制の内の人に限ることは、論点1 の読みと TG:654 の「置いた側が読解の帯域を負う」から導かれる帰結の明文化である

## 論点3: ext-vo の穴(発注側の席の責任者を外部の確認者として登録できる)を、#370 で扱うか #357 と合わせるか

**推す案**: 標準の側の明文は #370 で書く。テンプレートの拒否は #357 へ送り、#370 では実装マーク(`state=undelivered`、`plan=scheduled`、`issue=357`)で未達を表示する。標準の側の起案の文(表5-2 の区分の規定 DT:149 の行の中)は次のとおり。

> 外部の確認者を席の責任者に置けるのは、独立レビュアの席に限る(第3章 3.5 の外部の確認者の置き方の(イ)、RR:409-417)。ほかの席の責任者は体制の内とする

**理由**

- 外部の確認者を席に置く経路は RR:409-417 の(イ)だけであり、その条件(任免の記名・力量の確認・書面の合意、RR:416)も独立レビュアの席のために書かれている。価値責任者・出荷判定者・事業決裁者の席に外部の確認者を置く経路は、標準のどこにも定義されていない。上の文は既存の構造の明文化であり、新しい規範ではない
- この穴は委託に限らない(内製でも他部門の人を外部の確認者として価値責任者に置ける)。ただし論点1 の合計の読みを書く以上、同じ PR で区分の側の明文が無いと、読みを書いた直後に名簿の上で迂回できる。標準の側を #370 で閉じる理由はここにある
- テンプレートで拒む組を足すことは強制層の変更で、AI維持管理者の承認(`state:needs-platform`)が要る(SV 5 の (d))。名簿の欄を扱う #357(open、IMPL-0116・IMPL-0117 が既に `issue=357`、RR:144・:422)と同じ箇所(名簿の区分と席の対応)を触るため、まとめて変える方が検査の重複と食い違いを避けられる

**落とす案**

- #370 でテンプレートの拒否まで実装する案: 落とす。#357 と同じ名簿の検査を別々に変えると、片方の変更がもう片方の前提を崩すおそれがある。信頼性の理由で1か所に集める
- 標準の側も #357 へ送る案: 落とす。論点1 の読みを書いた PR の時点で、区分の迂回が規定の上で開いたままになる
- 拒まずに注記だけにする案: 落とす。席の責任者を体制の外に置くと人数の数え方(TG:166)そのものがずれ、G-6 の4条件と出荷判定の兼務の判定が誤る。注記では誤りが止まらない

**新しい義務**: 標準の側では課さない(既存の経路の限定の明文化)。テンプレートの拒否は、標準の既存の規定を降ろすもので、新しい規範ではない

## 論点4: G-7 の D-1 の過剰表示(SV 3.3 の4)を別の Issue へ分けるか

**推す案**: 別の Issue へ分ける。#370 では SV 3.2 の結果を審議の記録に残すだけとし、標準の本文は変えない。

**理由**

- 過剰表示は、テンプレートが回答(`approverMode: value-owner-merged`)から逸脱を導き、席の実際の兼務を見ないことによる。内製の2名の体制でも同じに起きる(SV 3.3 の4、S6)。委託の読み方(#370 の主題)とは原因が独立である
- 標準の側(TG:160 の限定「価値責任者が開発者または独立レビュアの席の責任者を兼ねる構成に限り」)は正しく、直す対象はテンプレートだけである
- 直す向きは表示を減らす(緩める)向きである。緩める変更は、標準 TG:160 に合わせるものでも、誤って必要な D-1 を消さないことを suite で確かめる必要がある(メモリ「suite の fixture は過去の決定を固定している」)。#370 の PR に混ぜると、委託の読みの確認と緩める変更の確認が1つの差分に重なり、審査の焦点がぼける

**落とす案**: #370 で直す案は上の理由で落とす。放置する案も落とす。締める向きの過剰表示でも、D-1 の代償措置を要しない構成で代償措置を求め続けると、記録が形骸化し、本当に要る構成の D-1 が読まれなくなる

**新しい義務**: 課さない

## 論点5: IMPL-0342 の `issue=` を、#370 から別の Issue へ付け替えるか

**推す案**: 付け替える。テンプレートの変化点の記録で自己の任命を残す経路を扱う Issue を新たに起票し、IMPL-0342(RR:2000)の `issue=` をその番号へ移す。`state=undelivered`・`plan=scheduled`・`review=2027-04` は変えない。#370 の決定の記録には「IMPL-0342 は本件の決定で解ける性質ではない」と理由を書く。

**理由**

- 3.13.3 の例外(RR:1994)は「本人の上に任命の権限を持つ者がいない1名の体制」の決定者の任命を扱う。論点1 の読みでは、受注側1名の委託の案件は2名以上の体制であり、案件の決定者が受注側の1名になるとは限らない(SV 2.3 の4行目)。例外が当たるのは内製の個人事業主であり、委託とは独立である(SV 4)
- 実装マークの規約は、`plan=scheduled` のマークに降ろす Issue の番号を求める(`community/implementation-marking.md:56`)。#370 を閉じた後に閉じた Issue を指すマークが残ると、降ろす計画が無いのに計画があるように読める。未達の表示の信頼性が損なわれる
- 経路が無い原因は、テンプレートが組織上の任命権者を体制の外の人に限り、席の責任者との同一を拒むこと(RR:2000 の note)である。直すにはテンプレートの名簿の検査を変える。論点3 と同じく、名簿の区分を触る #357 との関係を新しい Issue の本文に書く

**落とす案**

- `issue=370` のまま置く案: 上の理由で落とす
- #370 で降ろす案: 委託の読みと無関係の強制層の変更を同じ PR に入れることになる。落とす
- `plan=adopter` へ変える案: 落とす。テンプレートが同一を拒むため、採用者の側では記録できない。採用者に委ねても降りる経路が無い

**新しい義務**: 課さない(マークの計画の所在の訂正)

## 論点6: 受注側が価値責任者に座る構成(S1)を、テンプレートで確かめない旨の開示

**推す案**: 軸D の表の「価値責任者の所属」の行(TG:593)に実装マークを付ける。起案は次のとおり。

`<!-- impl IMPL-NNNN target=config-seats state=undelivered check=manual plan=adopter decision=ADR-0069 note="受託の構成で、価値責任者の席の責任者が発注側の人であること。準拠テンプレートは席と名簿に組織の所属を持たせない(ADR-0069 決定2)ため、受注側の人が価値責任者に座る構成を検出しない。確かめる者: 要件合意(G-2)の判定の材料を整える者と、テンプレ8 第9項を締結する双方(#370)" -->`

**理由**

- 「受注側はなれない」は実行主体(誰が席に座るか)を制約する規定であり、#222 の規約では実装マークを要する。いま台帳に当たる行が無い(SV 6 の6)。降りていない規定を表示しないことは、「確かめている」と誤読させる
- 降りない原因は ADR-0069 決定2(席に組織の属性を持たせない。ADR-0069:46-53)という意図的な決定である。採用者に委ねる決定の所在として ADR-0069 を引けば、`plan=adopter` の要件(`implementation-marking.md:57`)を満たす
- 論点1・3 を採ると、発注側の人は名簿に体制の内として載る。それでも誰がどちらの組織に属するかは、10名未満では名簿に記録されない(DT:428)。テンプレートの側で確かめられないことは変わらないので、開示が要る

**落とす案**

- テンプレートで検出する案(席か名簿へ組織の属性を足す): ADR-0069 決定2 の置き換えになり、新しい義務を課す。採るなら**重へ上げるべき**である。本件では採らない
- /pit で受託の構成に一律の注記を出す案: 落とす。組織の属性が無いので、どの受託の構成でも同じ注記になり、確かめる材料を足さない。IMPL-0337 の注記(AI-SLA 合意確認書の欠け)が締結の確認を既に促している
- `plan=scheduled` にする案: 落とす。降ろす計画が ADR-0069 と両立しない

**新しい義務**: 課さない(既存の規定の未達の開示)

## 全体の起案の要旨

- 標準の本文で変えるのは3か所: TG:166 の合計の読み(論点1)、TG:654 と第9項の G-6 の置き先と区分の対応(論点2)、DT:149 の外部の確認者を置ける席の限定(論点3)。いずれも既存の文から導ける読みの明文化で、新しい義務を課さない
- 実装マークは2件: 論点3 のテンプレートの拒否(`issue=357`)、論点6 の TG:593(`plan=adopter`)。IMPL-0342 は新しい Issue へ付け替える(論点5)。G-7 の D-1 の過剰表示は別の Issue へ分ける(論点4)
- 採らないと決めたもの: G-3 を受注側1名で未達とすること、G-3・G-6 を発注側へ寄せることの必須化(SV 5 の (b)(c)。いずれも新しい義務で、ADR-0069 決定2 と RR:322 に当たる)、第9項への確認者の欄の追加と所属の必須化(論点2)、組織の属性の付与(論点6)。採るならいずれも重へ上げる
