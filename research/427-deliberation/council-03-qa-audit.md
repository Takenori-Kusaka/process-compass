# 会議体 #427 品質監査の委員の意見

- 日付: 2026-11-04
- 立場: 品質監査。較正が**記録から**確かめられるか、採点者の偏りが導入の判断をすり抜けないか、少件数・偏った集合の値で見かけの一致を作れないかを見る
- 入力: `council-00-agenda.md`、`survey-427-1-internal.md`(以下「内部」)、`survey-427-2-external.md`(以下「外部」)。本文は `rr:1510`・`rr:1523-1525`・`ac:277`・`ac:778` を読み直して確かめた
- 判断軸は信頼性。変更量の少なさを採否の理由にしない

## 0. 監査の立場から見た現行の要求事項15 の弱点(前提)

現行の要求事項15 は「一致の値・部分集合の件数・採点のモデルの版」を書かせる。監査人がこの記録から確かめられるのは「書いてあるか」だけで、**値が判断に足るかは確かめられない**。見かけの一致を作る経路は少なくとも6つある。

| # | 経路 | 現行で塞がれているか |
| --- | --- | --- |
| A | 合否の偏った部分集合で単純な一致率を書く(合格9割の集合で常に合格と出す採点者は一致 90%) | 塞がれていない(内部 5.2) |
| B | 人が不合格とした事例が0件の部分集合で測る。採点者が不合格を見抜けるかは一度も測られていない | 塞がれていない |
| C | 全体の一致は高いが、候補側の出力だけで採点者が甘い(自己優遇)。全体の値に埋もれる | 双方の出力を含めることは課すが、腕ごとの値は課さない |
| D | 人の採点者に AI の判定やどちらの腕かを見せて採点させる(係留で一致が上がる) | 塞がれていない(内部 5.5) |
| E | 部分集合で採点プロンプトを調整し、同じ部分集合で一致を測る(過適合。外部 §5 の NIST 2.1.1) | 塞がれていない |
| F | 一致を測った後で、不一致の事例を部分集合から外す | 要求事項16 は正解の改めを扱うが、部分集合の除外は対象外 |

加えて、版の別名(「latest」)を版として書けば、版の記録は形だけ満たせる(外部 §3.1)。

以下の結論は、これらの経路を**下限の数値を課さずに**塞ぐことを目標にする。数値の下限を課さないという ADR-0104 の判断は維持する。下限を課しても A〜F は塞がらない(κ の下限は E で越えられ、B では算出自体が崩れる)からである。

## R-1 何を課すか

### 結論

- 較正の**手順と記録の欄を要求事項**として課す。手引きに置かない。数値(件数・一致の下限)は課さない
- 要求事項にする中身は次の5点
  1. **算出の元になる数を記録する**: 一致の値だけでなく、人の判定(合/否)×AI の判定(合/否)の分割表の各欄の件数を、腕(現行・候補)ごとに書く。多値の採点なら混同行列
  2. **部分集合の選び方を、測る前に記録する**: 抽出の方法(無作為・層別・割れた事例の優先など)と件数を、AI と人の一致を見る前に記録する
  3. **調整に使った事例で測った値を一致の値に数えない**: 採点プロンプト・採点基準の調整で参照した事例は、一致を測る部分集合に含めない。含めた場合は「未測定」と書く
  4. **部分集合からの事例の除外は、要求事項16 と同じ扱いにする**: 一致を見た後の除外は、除外の一覧と除外前の値を併記し、緩める向きの変更として承認の記録に残す
  5. **人の採点を AI の判定に係留させない**(R-4 で詳述)
- 「未定(#427)」(`rr:1525`)は、本 Issue の決定で「定めたもの」と「課さないと決めたもの」に分けて書き換える。未定のまま残すものを作らない

### 理由

- 監査は記録からしか確かめられない。要約の値1つでは A・B・C を検出できず、分割表の件数があれば監査人が指標を再計算し、欄の空き(B)と腕ごとの偏り(C)を直接見られる。指標の選択(R-2)よりも、**元の数を残すことのほうが監査可能性への寄与が大きい**
- 選び方を測る前に記録させるのは、測った後に都合のよい部分集合を選び直す経路を塞ぐためである。臨床試験の事前登録と同じ論理で、値の下限を課さずに操作の余地を減らせる
- E は採点者の較正で最も起きやすい過適合で、外部(NIST AI 800-2 草案 2.1.1 の開発用集合と試験集合の分離、Shankar 2024 の EvalGen が部分集合へ実装を合わせる構造)が示す。手引きに置くと、調整と測定を同じ集合で回す運用がそのまま適合になる
- 手引きに置かない理由: 手引きは監査で不適合にできない。現行の要求事項15 は記録の欄を要求事項として課しており、欄を手引きへ落とすと、同じ要求事項の中で「書けば足りる欄」と「書かなくてよい欄」が混ざる

### 監査で確かめられること

- 分割表の各欄の和が部分集合の件数と一致するか
- 記録された一致の値が分割表から再計算できるか(指標の名と式が書かれているか)
- 選び方の記録の日時(コミットの時刻)が、一致の算出の記録より前か
- 部分集合の事例の識別子が、採点プロンプトの調整の記録(変更履歴・コミット)が参照した事例と重ならないか
- 除外の一覧と除外前の値が併記されているか

### 採らない案

- **手引きにだけ置く**: 監査で不適合にできず、A〜F が適合のまま残る
- **定めない(課さないと決める)**: 外部(Inspect の既定の自己採点、DeepEval の既定の閾値 0.5)が示すとおり、道具の既定に任せると較正の無い採点が導入を決める。本標準が要求事項15 を置いた理由と両立しない
- **一致の下限を「組織が定める値」(1.7.7)にする**: 記録の無い導入を不適合にできる点は利点だが、A〜F のどれも塞がない。組織が低い下限を置けば形だけ満たせ、高い下限を置けば E の動機を強める(外部 §5)。下限の型を変える前に、下限が守る対象(値の意味)が記録で確かめられる状態を作るのが先である。将来、分割表の記録が集まった時点で再検討する余地は残す(EV の差し替え条件に書く)

### 反論されうる点

- 「分割表を腕ごとに書かせるのは小規模の体制に重い」→ 件数を数えるだけで、算出は AI に任せられる。人の判断の負担は増えない。負担を理由に記録を減らせば、承認する者が読めるのは要約の値だけになる
- 「事前の記録はコミットの順で偽装できる」→ できる。ただし偽装には意図が要り、無記録の運用とは監査上の扱いが異なる。機械の検査が降りれば、時刻の前後は機械が出せる
- 「調整と測定の分離は件数を倍にする」→ 調整に使う事例は人の採点を要しない場合がある(失敗例の観察だけ)。分離できない場合は「未測定」と書けば足り、禁止ではない

## R-2 一致の指標と件数

### 結論

- **単純な一致率だけを書くことを禁じる**。偶然の一致を除く指標(Cohen の κ、Krippendorff の α、均衡化した正解率など)の**名と値**を書かせる。どの指標かは本標準が指定しない
- **人の判定の各類(合・否)ごとの一致**(感度・特異度に当たる値)を書かせる。人の判定のいずれかの類が0件なら、その類の一致は「未測定」と書く。全体の値だけで済ませない
- 上の値を、**腕(現行・候補)ごとに**書かせる。同じモデル・版で採点した場合(要求事項15 の開示の対象)に限らず常に課す
- 信頼区間(または件数から決まる不確かさ)を併記させる。算出の方法の名を書く
- 人どうしの一致(評定者間の一致)は**任意**とし、測った場合は値と人数を書き、測っていなければ「なし」と書く(要求事項13 の盲検の確定と同じ型)。人の採点者ごとの値を、人の評価に用いてはならない(5.6.2 の目的の限定を準用)
- 件数は課さない(ADR-0104 を維持)。**目標の精度(信頼区間の幅)から件数を決める旨を手引きに置く**
- 少件数の扱いは H.7 の型(少件数の値を載せない)を**そのまま持ち込まない**。要求事項15 の記録は導入の承認者が読む内部の記録で、値を伏せると承認者が判断の材料を失う。代わりに、件数と信頼区間の併記と、類ごとの「未測定」で少件数を読み手に見せる。何件から値を書くかを組織が決めたなら、それに従う

### 理由

- A の経路は、偶然の一致を除く指標で大部分が塞がる。外部(Norman 2026)は、同じ採点者で一致率と κ の差が基準集合ごとに 10〜40 ポイント違うことを示す。一致率だけでは、承認者は値の意味を読めない
- しかし κ だけでも B は塞がらない。人の不合格が0件なら κ は定義できないか意味を失い、一致率はかえって高く出る。**類ごとの一致と「未測定」の明示が、少件数・偏った集合への最も直接の対策**になる。回帰評価で問題になるのは「劣化を見逃すこと」、つまり人が否とした事例を AI が合とする誤りであり、その類が測られていない較正は導入の判断の根拠にならない
- 腕ごとの値は C を塞ぐ。導入の判断は現行と候補の差であり、採点者が候補にだけ甘ければ、全体の一致が高くても差は水増しされる。自己優遇は同じ版でなくても同じ提供者・似た学習で起こる(外部 §2.4、424-2 の類似モデル優遇)ため、同じ版の場合に限らない
- 指標の名を固定しない理由: 2者・名義なら κ、3者以上・順序なら α、偏った分布では均衡化した正解率と、作業で適切な指標が異なる(外部 §1.1)。分割表が記録されていれば、監査人は別の指標で再計算できる
- 人どうしの一致を任意にする理由: 人の採点者を2人以上確保できない体制で課すと、要求事項15 自体が満たせなくなる。測れる体制では、AI の一致を人どうしの一致と並べて読める(外部 §1.2 の Judge's Verdict)。ただし「人どうしを上限とする」扱いは研究で決着していない(外部 §1.4)ため、比べ方は手引きにとどめる

### 監査で確かめられること

- 指標の名が書かれ、一致率だけの記録でないか
- 分割表から、記録された指標の値と類ごとの一致を再計算できるか
- 人の否の類が0件の記録で、その類の一致が「未測定」と書かれているか(値が書かれていれば不適合)
- 腕ごとの欄が両方あるか。候補側の欄だけ不一致が偏っていないか(監査人が見る。合否の基準ではない)
- 人の採点者ごとの値が、人事・成績の資料に転記されていないか(5.6.2 の準用)

### 採らない案

- **κ ≥ 0.6、TPR/TNR ≥ 0.8 などの下限**: ADR-0104 の判断(支える測定が無い)を覆す材料は今回の外部調査にも無い。規格・公的指針で数値を定めた例は無い(外部 §6)。Landis・Koch の区分は恣意的と批判されている(外部 §1.1)。下限は E の動機を強める
- **固定の最低件数(例 30 件)**: 必要件数は目標の精度と採点者の予測しにくさで決まり、固定の件数の一次資料は無い(外部 §1.3)。固定すると「30 件で足りる」という誤った安心を作る。類ごとの「未測定」のほうが少件数の危険を直接示す
- **少件数の値を「未測定」へ倒す(H.7 の型の持ち込み)**: 内部の承認の記録で値を伏せると、承認者は「未測定」と「少件数で一致が低かった」を区別できない。件数と区間の併記のほうが判断の材料が多い
- **人どうしの一致の必須化**: 1〜2名の体制で要求事項15 の全体を満たせなくする。満たせない要求事項は「未測定」の常態化を招き、記録の意味を下げる

### 反論されうる点

- 「腕ごと・類ごとに分けると各欄が少件数になり、どの値も不安定になる」→ そのとおりで、それが実態である。全体の値で隠すより、不安定さを件数と区間で見せるほうが信頼性に資する。不安定なら承認者は部分集合を広げるか、AI の採点を差分に用いない判断をする(EV-0214 の差し替えの向きと同じ)
- 「信頼区間の算出法の選択で幅が変わる」→ 算出法の名を書かせれば監査人が再計算できる。算出法の指定は手引きに置く
- 「均衡化した正解率は偶然の一致を除く指標ではない」→ 厳密には違う。本結論の要点は「一致率だけを書かない」と「類ごとの一致を書く」で、均衡化した正解率は類ごとの一致の平均として後者を満たす。指標の例示の書き方は起案で整える

## R-3 偏りの統制と採点者の位置づけ

### 結論

- 位置の入れ替え・長さの統制・参照解の付与・採点基準の明示は、**特定の手法としては課さない**。代わりに、**採点の形式(対の比較・単独の採点・参照解つき)と、施した統制の一覧(施さなかったなら「なし」)を記録する**ことを要求事項15 の記録の欄に加える。手法と効果は手引きに置き、効果の数値には根拠水準マークを付ける(GPT-4 世代の測定であるため)
- 偏りの**測定**(腕ごとの一致、R-2)は課す。統制の手段を課すより、統制の結果が現れる値を課すほうが監査で確かめられる
- 採点のモデルは、5.8.7 の推定のモデル(`hab:1116`・`hab:1127`)と同じ型で位置づける。AI 実行基盤として依存先の一覧に載せ、版を固定する。席の担い手ではなく、3.4.2 と退出の予行は掛からない。**採点のモデル自身に 3.12.3 の回帰評価を課さない**。要求事項15 の較正の記録を、採点のモデルを使ってよい根拠の記録とする
- 評価の対象のモデル自身(同じモデル・版)で採点することは、禁止しない(ADR-0104 の判断を維持)。ただし、**同じモデル・版で採点し、かつ一致が「未測定」の評価は、要求事項2 の差分の根拠に数えない**。開示だけでは足りないと判断する
- 版の記録は、提供者が固定を約束する識別子(日付つきのスナップショットなど)で書く。可動の別名(「latest」など)は版の記録に数えない
- 記録に「別系統で採点したので偏りが無い」の趣旨を書かない(ADR-0075 決定12、`rr:1524`)。偏りの統制として記録できるのは、施した手段と測った値だけである

### 理由

- 手法を課さない理由: 位置の入れ替えは対の比較にしか意味が無い。参照解の付与は参照解のある作業に限られる。長さの統制は回帰モデルの当てはめを要する。手法を要求事項にすると、形式に合わない手法を形だけ施す記録が生まれる。施した統制を列挙させれば、監査人は「対の比較なのに入れ替えが『なし』」を読める
- 効果の数値(入れ替えの一貫性 65%、参照解で 70%→15%、相関 0.94→0.98)は2023〜2024年の GPT-4 世代の測定で、2025〜2026 世代での再測定は限られる(外部 §2.6)。規範の根拠には弱く、手引きの例として根拠水準マーク付きで示すのが妥当
- 「同じ版 + 未測定」を差分の根拠に数えない理由: 自己優遇は、導入の判断を**候補を採る向き**へ系統的に歪める偏りで、承認者が開示を読んでも、その歪みの大きさは記録から分からない。開示は「読めば判断できる」ことを前提にするが、未測定の自己採点には判断の材料が無い。一方、測ってあれば腕ごとの値で歪みが見え、使ってよいかを承認者が判断できる。禁止でなく「測れば使える」とするので、ADR-0104 が同じ版の禁止を採らなかった理由(どの選び方にも偏りの向きがある、`council-01-drafter.md:286`)とは衝突しない
- 採点のモデルに 3.12.3 の回帰評価を課すと、採点のモデルの評価にまた採点者が要る循環が起きる。採点のモデルの適否を示すのは人の採点との一致であり、それは要求事項15 が既に測るものである。5.8.7 が推定のモデルについて選んだ位置づけと揃えれば、採点のモデルだけが本標準の中で位置を持たない状態が解消する
- 可動の別名を版に数えない理由: 版の記録の目的は、同じ物差しで測り直せることにある。別名は提供者の差し替えを隠し、記録が形だけになる(外部 §3.1 の日本語 MT-Bench の再現不能の例)

### 監査で確かめられること

- 採点の形式と統制の一覧の欄があり、「なし」を含めて埋まっているか
- 採点のモデルの版が固定の識別子か(別名なら不適合)
- 採点のモデルが依存先の一覧に載っているか
- 同じモデル・版の開示がある記録で、一致が測られているか。未測定なのに差分の根拠として導入が承認されていないか
- 記録・保証の開示に「別系統」「異なる提供者」を偏りが無いことの根拠として書いていないか(文言の抜き取り)

### 採らない案

- **位置の入れ替え・長さの統制を必須にする**: 形式に依存し、効果の数値も世代が古い。必須にすると形だけの記録を作る
- **別系統・別提供者の採点者を求める**: ADR-0075 決定12 に反する。系統を変えた自己優遇の抑制の効果を測った研究も見つからなかった(外部 §2.6)
- **同じモデル・版での採点の禁止**: #424 で採らなかった判断を覆す材料が無い。別のモデルにも類似モデル優遇の偏りがあり、禁止は偏りを消さず、測らない理由を与える
- **複数モデルの陪審を較正の代わりにする**: 誤りが相関し、陪審の一致は人の採点との一致の代わりにならない(424-2、ADR-0075 決定11)。陪審を使うことは許すが、陪審の判定も人の採点との一致で測る
- **採点のモデル自身に 3.12.3 の全体(回帰評価・退出の予行)を課す**: 循環し、得られる情報は要求事項15 の較正と重なる

### 反論されうる点

- 「同じ版 + 未測定を数えないのは、ADR-0104 が開示で足りるとした判断の変更である」→ 変更である。新 ADR で ADR-0104 の当該部分を置き換える。開示で足りるとした #424 の裁定は、未測定と同じ版の組み合わせを個別に論じていない(`decision.md:45` は同じ版の扱いだけを決めた)。信頼性の軸では、承認者が読めない開示は統制として働かない
- 「別の版で採点し未測定なら差分の根拠に数えてよいのか」→ 数えられる形になり、穴に見える。ただし別の版の場合、偏りの向きは候補を採る向きに定まらない。それでも未測定の採点を差分に使ってよいかは、R-1 の「定めない」案と同じ論点になる。品質監査としては**未測定の AI の採点はすべて差分の根拠に数えない**案まで検討の余地があると考えるが、同じ版の場合が偏りの向きを特定できる唯一の場合であるため、まず同じ版に限って課す。この判断の根拠は単一の推論で、根拠水準マークの対象とする
- 「統制の一覧を書かせても、施さない理由を問わなければ意味が薄い」→ 一覧は監査人と承認者の読む材料で、施さない判断は採用者に委ねる。施した統制を書かせるだけで、対の比較で入れ替えが「なし」の記録は目立つ

## R-4 見直しの契機と適用範囲

### 結論

- **3.12.3 の評価では、見直しの契機を別に置かない**。要求事項15 は部分集合に候補の出力を含めることを既に課しており、候補が変われば一致は測り直しになる。この帰結を箇条で明記する(以前の評価の一致を流用できないこと)
- 一致を以前の測定から流用する場面(3.12.4 の監視、3.4.2 の確認)には、次の契機で一致を失効させる。契機で値を自動で改めず、測り直すまで AI の採点による比較を基準値との比較に用いない
  - 採点のモデルの版の変更(提供者の差し替えを含む)
  - 採点プロンプト・採点基準・参照解の版の変更
  - 評価の対象のモデル・版の変更(3.12.4 では基準値の改めと同じ場で)
  - 暦(3.12.12 と同じく半期)
- 「評価の対象の分布の変化」「評価の対象が採点者より強くなった」は**契機に置かない**。機械でも人でも発生の時点を確かめられないため、契機にすると監査で確かめられない条項になる。これらは上の「評価の対象のモデル・版の変更」で事実上捉え、手引きに兆候(採点者と人の不一致の増加など)を書く
- 要求事項15 の適用を、**AI の採点で比べる全ての評価**へ広げる。少なくとも 3.12.4 の監視の試行と、3.4.2 の過去の判定の再現の照合に掛ける
- 人の採点者について次を課す
  - 部分集合を採点した人を記名で記録する
  - 人の採点の前に、AI の採点の結果を示さない(例外なし)
  - どちらの腕(現行・候補)の出力かを伏せる。伏せられない場合(採点者が評価を実行した本人で腕を知っているなど)は、その旨を書く
  - 採点した人が AI運用担当者または導入の承認者と同一人物なら、その旨を書く(要求事項12 の開示と同じ型)

### 理由

- 候補の出力を部分集合に含める要求は、3.12.3 の範囲では分布の変化と強いモデルの問題を構造的に処理している(候補ごとに測るため)。ここに契機を重ねると条項が増えるだけで信頼性が上がらない。むしろ「流用できない」を明記しないと、前回の一致の値を書き写す記録が適合に見える
- 3.12.4 と 3.4.2 は一致の流用が起きる場面で、現行は要求事項15 が掛からない(内部 5.3)。日次の監視で採点のモデルの版が提供者の側で変わると、基準値との差が採点者の変化なのか評価対象の劣化なのかを区別できない(外部 §3.1 の「幻の回帰」)。版の変更で失効させる型は 3.4.2(`rr:186`)・5.8.7 要求事項6(`hab:1118`)・3.12.12(`rr:1793`)と揃う
- 分布の変化を契機に置かない理由: 監査で「契機が起きたのに測り直していない」を立証できない条項は、不適合にできず、適合の表示だけを生む。外部 §3.2・§3.3 の劣化は実在するが、その捕捉は版の変更(と候補ごとの測定)という観測できる事象に結びつけるほうが確かめられる
- 係留の禁止を例外なしにする理由: AI の判定を見て採点した人の一致は、採点者の一致ではなく係留の大きさを測る(D の経路)。AI の判定の列を隠すことは、どの体制でも負担なく実行できる。腕を伏せることは1人の体制で不可能な場合があるため開示に倒す
- 記名を課す理由: 人の採点が採点者の物差しになる以上、誰の判断かを辿れないと監査で正当性を確かめられない。要求事項11 は正解を記名の自然人が確定するとし、物差しの出所を辿れることを求めている

### 突合で見つけた論点(会議体で決める必要がある)

- **人の採点は要求事項11 の「正解」に当たるか**。要求事項11 は正解に「合否の判定」を含める。部分集合の人の採点は、出力ごとの合否の判定であり、AI の採点の物差しとして働く。これを正解の確定とみなすと、要求事項12(確定者は席の責任者)と要求事項13(確定者に確定前に評価対象の出力を示さない)が掛かり、出力を見て採点する行為と要求事項13 が衝突する。品質監査の意見は、**人の採点を「正解の確定」とは別の行為として定義し、記名・係留の禁止・同一人物の開示だけを課す**。ただし採点の基準・参照解は要求事項11 の正解であり、人はそれに照らして採点する、と関係を明記する。定義しないまま置くと、監査人がどちらの規則で見るかを決められない

### 監査で確かめられること

- 3.12.3 の記録で、一致の測定の日付が候補の出力の生成より後か(流用でないか)
- 3.12.4・3.4.2 の記録で、採点のモデル・採点プロンプトの版が、一致を測った時点の版と同じか。違えば測り直しの記録があるか
- 暦の契機の測り直しの記録の日付
- 人の採点者の記名、AI の判定を示さなかった旨、腕を伏せたか(伏せなかった旨)、同一人物の開示

### 採らない案

- **分布の変化・能力の逆転を契機にする**: 発生を確かめられず監査不能
- **一致の値の低下で自動的に AI の採点を止める**: 値を自動で改めない本標準の型(3.12.12、較正の歯止め)に反する。止める判断は人が記名で行う
- **3.12.3 にも暦の契機を置く**: 候補ごとに測るため冗長
- **3.12.4・3.4.2 を対象外のままにする**: 一致の流用が最も起きる場面が無統制になる
- **人どうしの一致を採点者ごとに算出して人の採点者の適格性を判定する**: 5.6.2 の個人の評価の禁止の趣旨に反しうる。採点者の物差しの質は、記名と係留の禁止で担保する

### 反論されうる点

- 「3.12.4 の日次の監視ごとに要求事項15 を満たすのは重い」→ 毎回測るのではなく、契機までは以前の一致を流用できる。重いのは契機の後の測り直しだけで、それは版が変わった物差しで比較を続ける危険と釣り合う
- 「暦(半期)の根拠が無い」→ 無い。3.12.12 との整合で置く値で、根拠水準マークを付ける
- 「腕を伏せられない1人の体制では係留が残る」→ 残る。その旨を書かせ、承認者が読む。伏せられない体制で伏せたと書く記録だけを不適合にする

## R-5 記録と降ろし先

### 結論

- **新しい ADR を起こし、ADR-0104 の決定5 を補う**。ADR-0104 は書き換えない。新 ADR は、R-1〜R-4 で定めたもの、ADR-0104 の当該部分を置き換えるもの(同じ版 + 未測定を差分の根拠に数えない)、**課さないと決めたもの**を分けて書く
- 課さないと決めたもの(却下の記録)を新 ADR と本文の箇条の双方に書く: 一致の下限(κ・TPR/TNR など)、固定の最低件数、特定の偏りの統制の手法、別系統の採点者、同じ版の採点の禁止、陪審による較正の代替、人どうしの一致の必須化、分布の変化を契機にすること。#424 の起案の「偶然の一致を除く指標を用いる」は、本 Issue で**採る**ことの記録として残す(却下の記録が無いまま消えた状態を解消する)
- `rr:1525` の「未定(#427)」を削り、上の内訳で置き換える
- EV: 次に根拠水準マークを付ける
  - 偏りの統制の効果の数値(手引き。GPT-4 世代の単一研究に依る)
  - 「同じ版 + 未測定を数えない」の判断(単一の推論)
  - 暦の契機の半期
  - EV-0214 の差し替え条件を**記録から観測できる形**へ改める。現行の「評価に現れなかった劣化が重大な欠陥を生んだ場合」は 3.12.4 が未達で観測の源が無い(内部 5.8)。腕ごとの分割表が記録されれば、「候補側に偏った不一致が記録された導入の割合」を観測できる。これを差し替え条件に加え、一致の下限を組織が定める値にするかの再検討の契機とする
- IMPL: IMPL-0407 の note を新しい欄(分割表・指標の名・類ごとの未測定・腕ごと・選び方・統制の一覧・人の採点者の記名と係留の欄)に合わせて改める。3.12.4・3.4.2 への適用と失効に新しい IMPL を付け、state=undelivered で表示し続ける。退出の予行の記録(`performer.md:44-51`)に要求事項15 の欄が無いことを IMPL の note に書く
- **#426 との順序: 本 Issue で記録の欄を先に決め、#426 は決まった欄で記録の形と置き場を決める**。逆にすると、#426 の検査が要約の値1つを確かめる形で降り、本 Issue の欄を後から足すと検査対象が二度変わる
- 内部監査の観点を足す。観点26 は正解の確定を見る観点で、採点者の較正は別の対象であるため、**観点26 を広げず新しい観点を置く**。内容は R-1〜R-4 の「監査で確かめられること」の抜き取り(分割表からの再計算、類ごとの未測定、版の識別子、係留の記録、別系統の文言)
- pit-crew の pit-wall: 本標準と**食い違いではない**と扱う。pit-wall は本標準の適合の条件でも準拠テンプレートでもなく、道具の内部の使用可否の規則(TPR/TNR ≥ 0.8)を持つことは、本標準が下限を課さないことと両立する。ただし次の3点は pit-crew へ PR で提案する(main へ直接 push しない)
  - 較正の出力に分割表を腕ごとに含める
  - 割れた事例を優先する抜き取りの値が母集団の推定として偏る(低めに出る)旨を、出力に表示する
  - TPR/TNR ≥ 0.8 の通過を、本標準の要求事項15 を満たした根拠として表示しない

### 理由

- 新 ADR にするのは、ADR-0104 の採用済みの本文を書き換えないためと、同じ版の扱いを開示から「未測定なら数えない」へ強める判断が ADR-0104 の置き換えに当たるためである
- 却下の記録を書くのは、コアポリシー(「書かれていない」と「課さないと決めた」を区別する)による。#424 の起案の指標の案が却下の記録なく消えたこと自体が、今回の議題の発端である
- #426 を後にするのは、検査は記録の欄を確かめるもので、欄が決まる前に検査を降ろすと、監査可能性の弱い現行の欄を機械が固定するためである
- 観点を分けるのは、観点26 の抜き取り(正解の出所を辿る)と、採点者の較正の抜き取り(分割表を再計算する)で監査の手順が異なるためである。同じ観点に詰めると、どちらかが抜き取られない

### 監査で確かめられること

- 新 ADR の「課さないと決めたこと」と本文の箇条が一致するか(`npm run lint:refs` の対象に ADR 番号を入れる)
- IMPL の state が実態と一致するか(未達を消していないか)
- 新しい観点が要求事項15 と 3.12.4・3.4.2 の条項を引いているか

### 採らない案

- **ADR-0104 の追補として本文を書き換える**: 採用済み ADR の本文を変えない運用に反する
- **#426 と同時に決める**: 記録の形の決定(置き場・ADR-0057 との突合)と欄の決定は論点が異なり、同時に決めると欄の議論が置き場の都合で削られる
- **pit-wall の 0.8 を本標準の既定値にする**: 既定値(1.7.7)は記録が無くても効く値で、支える測定が無い値を既定にすることは下限を課すことと同じ問題を持つ。pit-wall の値は単一の道具の設計判断で、本標準の根拠にならない
- **pit-wall の規則を本標準に合わせて削らせる**: 道具が自らの使用可否の規則を持つことは本標準と矛盾しない

### 反論されうる点

- 「新しい観点を足すと内部監査の負担が増える」→ 負担の大小は採否の理由にしない。分割表があれば抜き取りは再計算だけで済む
- 「EV-0214 の差し替え条件を変えるのは、EV の差し替え条件を後から都合よく変えることにならないか」→ 現行の条件は観測の源が無く働かない。働かない条件を置き続けることのほうが、見直しの予約を形だけにする。条件を改めた旨と理由を新 ADR に書く
