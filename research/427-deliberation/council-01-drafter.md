## 0. 総論(起案の立場)

1. **現行の要求事項15 は「一致を測れ」と言うが、測り方を何も縛らないため、測ったことが信頼の根拠にならない**。合格が9割の部分集合で「常に合格」と出す採点者は一致 90% を記録でき、要求事項15 を満たす(内部 5.2)。一致率と κ の差は基準集合で 10〜40 ポイント(外部 1.1)。採点のモデルを道具の既定に任せれば、評価の対象のモデル自身が採点する(外部 4.2 Inspect)。どれも現行の文面の内側で起こる。測定の手続が無い測定は、記録の欄を埋める作業に縮退する
2. 一次資料の方向は一致している。規格・公的指針は**人の採点との比較・不確かさの報告・版の記録**を求め、数値は組織に委ねる(外部 4.1 NIST AI 800-2 草案、6)。研究は「件数は目標の精度で決まる」「偶然の一致を除く指標を使え」「版・分布・強い生成器で採点者は劣化する」で揃う(外部 1.1・1.3・3)。したがって**手続と記録と見直しの契機を要求事項にし、数値(件数・下限)は本標準が定めない**。ここまでは ADR-0104 と同じ線である
3. ただし「下限を課さない」を「読み方を決めずに数値を書けばよい」と同一視しない。**一致の値をどう読むか(採点者を差分に用いる・用いないの判断の基準)は、結果を見る前に組織が記名で定める**。結果を見た後に基準を決めることは、要求事項16 が緩める向きとして扱う「結果を見た後の正解の改め」と同じ構造である。値は本標準が定めない。定める手続を課す(1.7.7 の「組織が定める値」。参考の値は置かない)
4. 偏りの統制は、**偏りを測る形でだけ**課す。系統を変えることは求めない(ADR-0075 決定12)。位置の入れ替え・比べる双方での一致の分割・確定した正解(採点の基準と参照解)の付与は、どれも系統に依らない測定上の統制で、決定12 と抵触しない(内部 3)
5. 較正の記録は、3.4.2 の適合性確認と同じく**識別に結びつけて失効させる**。採点のモデルの版・採点の指示(採点の基準と採点の指示の版)・推論の設定の組を「採点者の識別」と呼び、識別が変われば測り直す。本標準に既にある型(3.4.2 の失効、5.8.7 要求事項6 の版の固定と測り直し、3.12.12 の契機)の延長であり、新しい型を作らない

### 結論

- 較正の**手続・記録・見直しの契機**を要求事項にする。手引きに置かない。理由は総論1: 手引きでは、道具の既定(自己採点・閾値 0.5)に任せた評価が要求事項15 を満たしたまま残る

- 数値は本標準が定めない(件数・一致の下限・区間の幅)。**一致の読み方(採点者を用いる・用いないの基準)を、結果を見る前に、組織が記名で定める**ことを課す。1.7.7 の組織が定める値とし、参考の値を置かない

### 理由

- 手続を課すことは、本標準の既存の型と同じ強さである。5.8.7 要求事項6(閾値を技術判断者が版ごとに記名で定め、自動で変えず、版を変えたら測り直す)は、値を定めずに手続を課した先例で、採点者の較正はその直接の類比になる(内部 1.7)
- 読み方を事前に定める(要求事項2)は、ADR-0104 の「下限を課さない」と矛盾しない。本標準は値を定めない。定めるのは、値を結果の後に選ばない手続である。結果を見た後に正解を改めることを緩める向きとした要求事項16 と同じ根拠(事後の物差しの選択は、物差しが結果に合わせて動くこと)
- 1.7.7 の組織が定める値は「記録が無ければ当該の基準を満たさない」。読み方の記録が無い評価は、AI の採点を用いた差分として承認できない。これは数値を課すことと別の選択肢であり(内部 2.1)、下限の数値の根拠が無いという ADR-0104 の判断を保ったまま、事後の読み替えを塞ぐ
- 参考の値を置かない。置けば、その値が目標になる(外部 5。DeepEval の既定の閾値 0.5、Landis・Koch の恣意的な区分)。根拠の無い参考の値は、根拠水準マークを付けても運用上の既定値になる
- 未測定の受容: 未測定の AI の採点で求めた差分は、誰も確かめていない測定器の値である。現行の「未測定と書く」だけでは、承認者が読み流せる。要求事項8(退出を試していない)・要求事項12(分離が成り立たない)と同じ「開示 + 期限つき受容」の型に揃える

| --- | --- |
| 較正を手引き(参考)に置く | 道具の既定(自己採点・閾値 0.5)のまま要求事項15 を満たす評価が残る。測定の手続の無い測定値は信頼の根拠にならない |
| 一致の下限(κ 0.6・0.8 など)を本標準が課す | 値を支える測定が無い。一致率と κ の差は基準集合で 10〜40 ポイント異なり、同じ値の意味が揃わない。部分集合への合わせ込みで越えられる。導入時の高い一致が後の正しさを保証しなかった例がある(外部 3.3 Omni-Judge)。ADR-0104 の判断を維持する |
| 下限を組織が定める値にし、参考の値(例 κ 0.6)を示す | 参考の値が目標として固定される。根拠が Landis・Koch の区分しか無い |
| 件数の下限(例 30件)を課す | 固定の件数の一次資料が無い(外部 1.4)。件数は目標の精度と採点者の予測しにくさで決まる |
| 未測定の AI の採点で導入することを禁止する | 1〜2 名の体制で、人の採点の部分集合を毎回用意できない場合がある。禁止は AI の採点を記録の外へ追いやる。受容の記名で、誰が測定器を確かめずに承認したかを残す |
| 要求事項15 の表の中に全部を書き込む | 適用が差分・監視・確認の3つにまたがり、3.12.3 の表へ置くと 3.12.4・3.4.2 からの参照が不自然になる。節を分けて見出しに適用範囲を併記する(#226) |

### 反論されうる点

- 「読み方を事前に定める」は実質的な下限であり、ADR-0104 の「下限を課さない」を覆す → 本標準は値を定めない。組織の値の型の選択であり、新 ADR で ADR-0104 決定5 を補うと明記する。覆すと読まれないよう、「課さないと決めたこと」の行の文言を「本標準が値を定めること」に限ると新 ADR に書く
- 1〜2 名の体制で、AI運用担当者と技術判断者が同一人物になる → 3.12.3 の要求事項12 と同じく、同一人物でも記名で成立する。事後に読み替えないことが本旨で、分離は本旨でない。同一人物の扱いは要求事項10(基準集合の範囲)と揃える(一人で判断させない)か、議論が要る。起案は「要求事項10 と同じく二人の記名」を推す強さは無く、記名だけを課す
- 手続が重い → 判断軸は信頼性。AI の採点を使わない評価(決定論的な検査・人の採点)には掛からない。AI の採点を使う組織だけが負う

## R-2 一致の指標と件数

### 結論

- **偶然の一致を除く指標**を求める。指標は指定しない(κ・α・均衡化した正解率・感度と特異度の組のいずれか。名を書く)。単純な一致率を併記させ、単純な一致率だけの記録は「未測定」とする(3.12.13 要求事項6 (c)(d)・要求事項7)
- 部分集合の**合否の内訳**を書かせる(要求事項6 (b))。偏った集合を読み手に現す
- **区間**(信頼区間など)と算出の方法を書かせる(要求事項6 (e))。少件数の扱いは、件数の下限でなく区間の幅で読み手に現す
- 比べる双方の出力に**分けた一致**を書かせる(要求事項6 (f))。自己優遇・候補が強くなったときの劣化を、系統に依らず測る
- 人どうしの一致は課さない。測った場合は書く。個人の評価に用いない
- 件数は定めない。決め方の記録を課し、区間の幅から決める旨を手引きにする
- H.7 との整合: 要求事項15 の値は附属書H の検出能力の値でない旨を書き、H.7 の「少件数の値を載せない」(対外の開示)と範疇を分ける

### 案(文面)

3.12.13 の要求事項3・6・7 と箇条(R-1 の案(3))。加えて、**H:361 の段落の末尾へ一文を追加**

```markdown
AI の採点と人の採点の一致([第3章 3.12.13](/process-compass/phase4-process-design/roles-responsibilities/))も物差しの記録であり、検出能力の値として示しません。
```

### 理由

- κ と一致率の差は MT-Bench で平均 38.6 ポイント。一致率 85% が κ ≈ 0.48 に相当する(外部 1.1)。単純な一致率だけを許すと、要求事項15 は偏りを測る規定として働かない。Vertex AI は均衡化した正解率、pit-wall は Cohen の κ を使っており、実務で過重な要求ではない
- 指標を一つに絞らない: 2者・名義なら κ と α はほぼ一致し(外部 1.1)、偏った分布では α も誤解を招きうる。指標の選択に決着が無いので、名を書かせて読み手が判断できるようにする。合否の内訳(b)を併記させるのは、どの指標でも偏った分布の影響を読み手が確かめられるようにするため
- 区間: NIST AI 800-2 草案 3.1 が不確かさの報告を求める(外部 4.1)。区間は件数の下限を課さずに少件数の弱さを現す唯一の方法で、H.7 の「何件からかは組織が定める」とも衝突しない
- 双方に分けた一致: 要求事項15 は既に「双方の出力を含める」を課すが、合算すると片側の劣化が薄まる。Shelf Life(外部 3.3)・Omni-Judge は、強い生成器の側で採点者が劣化した例。分ければ候補の側の劣化が直接読める。系統を変えずに自己優遇を測る形で、決定12 と両立する(内部 3)
- 人どうしの一致を課さない: 同じ事例を二人以上で採点させることになり、ADR-0104 が採らなかった「二人の確定」と同じ負担になる。上限として扱う根拠も決着していない(外部 1.2)。測った組織が書けるよう欄だけ置く。5.6.2 の個人単位の禁止の理由(件数不足の値は偶然の変動)は、人の採点者ごとの一致にもそのまま当たる

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| κ に指標を固定する | 多値・順序尺度・3者以上で α が適し、二値の偏った分布では感度・特異度の組が読みやすい。固定の根拠が無い |
| 単純な一致率を禁止する | 併記は読み手の比較に役立つ。単独を禁じれば足りる |
| 人どうしの一致を併記させ、採点者の一致の上限として読む(Judge's Verdict 型) | 二人の採点の負担。上限とする根拠に決着が無い(「超一貫」の解釈が分かれる。外部 1.2) |
| 少件数の値を「未測定」へ倒す件数の閾値を置く | 件数の数値の根拠が無い。区間の幅が同じ情報を値の形で現す |
| 割れた事例を優先する抜き取り(pit-wall 型)を許して合算する | 一致の値が母集団の推定として低めに偏り、読み方の基準(要求事項2)との比較が意味を失う。上乗せは許し、分けて記録する |

### 反論されうる点

- 区間の算出は小さな組織に難しい → κ・二項割合の区間は標準の統計の道具で出る。算出の方法を書けばよく、方法を指定しない
- 均衡化した正解率は「偶然の一致を除く」指標ではない → 二値で偶然の水準を 0.5 に揃える指標として実務で使われている(Vertex AI)。厳密さを求める委員がいれば、均衡化した正解率を外し、感度と特異度の組に寄せる案も受け入れられる

## R-3 偏りの統制と採点者の位置づけ

### 結論

- **確定した正解(採点の基準と参照解)の付与を課す**(3.12.13 要求事項5)。数学の採点の失敗 70% → 15%(外部 2.1)。要求事項11 で正解を人が確定したのに、採点者がそれを見ずに採点すれば、物差しを人に結びつけた意味が失われる
- **対の比較では位置の入れ替えを課す**(要求事項5)。順で判定が変わった件数を記録する。GPT-4 でも入れ替えの一貫性 65%(外部 2.1)。Vertex AI の `flip_enabled` など実装は一般的
- 長さ・書式の統制は**行ったかを記録させる**だけにする(要求事項6 (h))。課さない
- **採点のモデルの明示の指定を課す**。道具の既定(評価の対象のモデル自身で採点するフォールバック)を指定に数えない
- 評価の対象のモデル自身・同じ版での採点は**禁止しない**。開示(現行)と双方に分けた一致(要求事項6 (f))で偏りを測る
- 採点のモデルは **AI 実行基盤**に当たり、「承認されていないモデルを用いない」に掛かる。導入の評価は本節の較正で行う(3.12.3 の要求事項1・2 の回帰評価は掛けない。循環を避ける)。席の担い手ではない(3.4.2・退出の予行は掛からない)。依存先の一覧に載せる
- 決定12 との整合: どの統制も系統に依らない測定の形で、決定12 と抵触しない。合わせた判定(陪審)は許すが、採点のモデルどうしの一致を根拠に書かない(決定11)

### 案(文面)

3.12.13 の要求事項5・6 (g)(h)・10 と箇条(R-1 の案(3))。

### 理由

- 参照解の付与と位置の入れ替えは、効果の数値を持つ統制のうち、評価の形を問わず実装でき、系統の選択に依らない。入れ替えを課す一方で長さの統制を課さないのは、長さの統制が回帰モデルの当てはめ(外部 2.2)を要し、すべての評価に当てはまる手続として書けないため。行ったかの記録は、統制の不在を読み手に現す
- 明示の指定: Inspect は指定が無ければ評価の対象のモデル自身で採点する(外部 4.2)。これは同じ版での採点の開示(要求事項15)を、記録した者自身も気づかないまま漏らす経路である。版の記録(要求事項6 (a))は、明示の指定が無ければ正しく書けない
- 同じ版の採点を禁止しない: #424 の起案の採らない案(どの選び方にも偏りの向きがある)を維持する。禁止すると決定12 の外側で「別の版を求める」を課すことになり、別の版が自己優遇を抑える効果の実測は見つかっていない(外部 2.6)。代わりに偏りを分けた一致で測る
- AI 実行基盤としての位置づけ: 5.8.7 要求事項4 と箇条(推定のモデルは AI 実行基盤、席の担い手でない、依存先の一覧に載せる)と同じ型にする(内部 5.4)。採点のモデルを 3.12.3 の回帰評価で導入させると、その評価の採点にまた採点者が要り循環する。採点者の導入の評価は、人の採点との一致そのものである

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 評価の対象のモデル自身・同じ版での採点を禁止する | 別の版・別の系統が自己優遇を抑える効果の実測が無い。決定12 の外側で版の選択を強いる。偏りは測る |
| 別の系統の採点者を求める、または推奨する | ADR-0075 決定12(求めず、推奨もしない) |
| 長さ・書式の摂動の試験(pit-wall 型の摂動4種)を課す | 摂動の作り方は評価の形に依り、手続として一般に書けない。行ったかの記録で足りる |
| 複数の採点のモデル(陪審)を課す | 誤りが相関し、実効の票は少ない(424-2)。陪審は許すが課さない |
| 採点のモデルを 3.12.3 の回帰評価で導入させる | 循環する。導入の評価は人の採点との一致そのもの |
| 採点のモデルを依存先の一覧に載せない | 採点のモデルの廃止・版の差し替えで、監視と評価が再現できなくなる。依存の事実を隠さない |

### 反論されうる点

- 位置の入れ替えは採点の費用を倍にする → 対の比較に限る。費用は採否の理由にしない
- 入れ替えて不一致を引き分けにする方式は偏りを隠すだけ(JudgeLM 批判。外部 2.1)→ 本案は不一致の扱いを定めず、**件数を記録させる**。隠すのでなく現す
- 参照解の付与は、一意の正解を持てない事例で採点を歪める → 要求事項11 は一意の正解を持てない事例の正解を「採点の基準と参照解の組」と既に定めている。与えるのは人が確定したもの

## R-4 見直しの契機と適用範囲

### 結論

- 較正の記録を**採点者の識別**(採点のモデルの版・採点の指示の版・推論の設定)に結びつけ、識別が変われば失効させる(3.12.13 要求事項8)
- 3.12.3 の評価は**評価ごと**に部分集合を採点する(要求事項9)。候補の出力を含めるには評価ごとに採点するほかない。これにより「評価の対象の分布の変化」と「評価の対象が採点者より強くなったこと」は、別の契機を置かずに、毎回の候補の側の一致(要求事項6 (f))で測られる
- 3.12.4 の監視は導入を承認した評価の較正を用い、(a) 識別の変更 (b) 正解の改め (c) 半期の暦 で測り直す。契機で読み方と基準値を自動で改めない
- 適用を **3.12.4 の監視**と **3.4.2 の過去の判定の再現の照合**へ広げる(要求事項1)
- **人の採点者は記名**。採点の前に AI の判定とどちらのモデルの出力かを示さない(要求事項4)

### 案(文面)

3.12.13 の要求事項1・4・8・9、R-1 の案(4)(5)。

### 理由

- 識別による失効は 3.4.2 の要求事項7、版の固定と測り直しは 5.8.7 の要求事項6、版の変更と暦の2契機と「自動で変えない」は 3.12.12 の要求事項1・2 の型である(内部 1.3・1.4・1.7)。外部でも、採点のモデルの版で点数が動き再現できない例(日本語 MT-Bench。外部 3.1)、NIST AI 800-2 草案の版の記録(外部 4.1)がある
- 採点の指示の版を識別に含める: 採点基準の漂流(外部 1.2 Shankar)、HELM の採点プロンプトの差し替え(外部 4.2)のとおり、指示の変更は測定器の変更である
- 監視に暦を置く: 監視は日次で採点を繰り返すが、部分集合の採点は導入時の1回だけになる。提供者の側で版の別名が差し替わる場合など、識別の変更として記録されない変化がありうる。3.12.12 と同じ半期とし、新しい周期を作らない
- 「採点者より強くなったとき」を独立の契機にしない: 強さの判定に観測の源が無い(何をもって強くなったかを定義できない)。観測できない契機は働かない(EV-0214 の差し替え条件が観測の源を欠く問題と同じ。内部 5.8)。評価ごとの候補の側の一致は、観測できる形で同じことを捉える
- 適用の拡大: 監視の試行で採点者の版が変わると、基準値との比較が採点者の差を劣化と誤認する。3.4.2 の再現の照合で AI の採点を使えば、確認の結果そのものが未較正の測定器に依る。どちらも差分と同じ測定器の問題で、要求事項2 に限る理由が無い
- 人の採点者の伏せ方: 要求事項13 が正解の確定者に評価の対象の出力を示さないのと同じ係留の制限(EV-0213 が挙げる AI の事前注釈への引きずられ)。pit-wall も腕と判定を伏せる(内部 4.2)。伏せないで測った一致は、AI の判定に人が寄った分だけ高く出る

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 監視でも毎回(日次)人が採点する | 監視の目的(日次の劣化の検知)と釣り合わない。識別・正解・暦の契機で測り直す |
| 較正の記録を評価をまたいで流用してよいとする(3.12.3) | 候補の出力が部分集合に入らず、要求事項15 の「双方の出力を含める」と矛盾する |
| 「評価の対象が採点者より強くなった」を契機に置く | 観測の源が無い。候補の側の一致で捉える |
| 暦を四半期にする | 新しい周期を作らない(3.12.11 の要求事項5 と同じ考え方)。3.12.12 の半期に揃える |
| 人の採点者を正解の確定者(要求事項12 の席の責任者)に限る | 採点は確定した正解の当てはめで、確定ではない。限る根拠が無い。記名と伏せ方で足りる |
| 人の採点の伏せ方を任意にし、記録させる(要求事項13 の盲検の確定と同じ扱い) | 盲検の確定は「草案を見る前に付ける」追加の作業だが、採点の伏せ方は採点の手順の組み方だけで、追加の件数を要さない。伏せない採点は測定の汚染であり、任意にする理由が無い |

### 反論されうる点

- 監視の半期の測り直しは小さな組織に重い → 監視で AI の採点を使う組織だけが負う。決定論的な検査で監視する組織には掛からない
- 推論の設定を識別に含めると、温度の微調整のたびに失効する → 失効させるのが正しい。測定器の設定が変われば測定値の意味が変わる

## R-5 記録と降ろし先

### 結論

- **新 ADR-0105** を起こし、ADR-0104 の決定5 を**補う**(置き換えない)。ADR-0104 の「課さないと決めたこと」の「一致の値の下限」は維持し、「本標準が値を定めないこと」と「組織が読み方を事前に定める手続を課すこと」を区別して書く
- EV は3つ(EV-0216〜0218)。IMPL は4つ(IMPL-0409〜0412)
- **#426 との順序**: 本件が記録の欄を決めてから、#426 が記録の形と検査を組む。IMPL-0407 の note は変えず、新しい欄の検査は IMPL-0410 として #426 に載せる
- 内部監査に観点27 を足す
- pit-wall: 食い違いは「割れた事例を優先する抜き取りの合算」の1点。TPR/TNR 0.8 は組織が定める値(要求事項2)の一例として矛盾しない。pit-crew へ PR で提案する(main へ直接 push しない)。本標準と準拠テンプレートの検査は pit-crew に依らない

### 案(文面)

**(1) 3.12.13 の箇条の後へ EV を3つ**

```markdown
:::caution[暫定 EV-0216 / 見直し 2027-11]
```

**(6) pit-crew への PR(本件の範囲外。別 Issue)**

- pit-wall の `calibrate/index.mjs` の抜き取り(割れた実行の優先)で、上乗せ分と無作為分の κ を分けて出す変更を提案する。`validate.mjs` の TPR/TNR 0.8 は pit-crew の組織が定める値として残してよい。陪審の別系統を、採点の正しさの根拠として説明文に書いていないかを確かめる
- 本標準の検査(`npm run check`)と準拠テンプレートは pit-crew に依らない。PR が pit-crew の main へ入るまで submodule の参照を進めない

### 理由

- ADR-0104 は「較正の手法は #427 で扱う」と後継を予約しており(決定5)、本件はその決定の補完である。決定5 の「下限は課さない」を維持するので置き換えではない。読み方の事前の記名が下限と読まれる危険は、新 ADR の「課さないと決めたこと」で「本標準が値を定めること」に限ると明記して塞ぐ
- #426 との順序: 記録の検査は欄が決まらなければ組めない。IMPL-0407 を書き換えず IMPL-0410 を別に起こすのは、#424 で決めた検査(未測定の検出・改めの併記)と本件の検査(指標・識別・失効)を、未達の理由と確かめる者が読み分けられるようにするため
- 観点27: 現行の観点26 は正解の確定だけを見る(内部 5.7)。識別の一致(記録の版と実行の版)は機械で降りるまで監査で抜き取るほかない。降りていない規定は消さずに表示する(#222)
- IMPL-0409 を即時に降ろす: 準拠テンプレートに採点者の実装は無いが、担い手の AI が記録の人の欄を埋めること・道具の既定に任せることは、テンプレートを使う案件で今すぐ起こりうる。IMPL-0404 と同じ常駐の1行で運ぶ

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| ADR-0104 を置き換える新 ADR | 決定5 の内容(人の部分集合・版の記録・正解に数えない・下限を課さない)はすべて維持する。補完で足りる |
| IMPL-0407 の note を書き換えて欄を足す | 未達の理由と降ろす単位が混ざり、台帳で読み分けられない |

| 本件の PR の中で pit-crew を直接改める | 別のセッションが開発中。main へ直接 push しない(CLAUDE.md) |

### 反論されうる点

- 本件で 3.12.13 を足すと、#426 の作業が膨らむ → 判断軸は信頼性。欄が決まる前に検査を組むと、組み直しになる
- 観点27 の「実行の記録に残る採点のモデルの版」は、採用者が実行の記録を残していなければ見られない → 見られない事実を所見にする(観点20 と同じ扱い)
