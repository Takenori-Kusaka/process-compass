## R-1 何を課すか

### 結論

1. 較正の**手順の骨格と記録と失効の契機**を、3.12.3 の要求事項(要求事項15 の細分または新しい番号)として課す。手引きに留めない。数値(件数・一致の下限・参考の値)は本標準が置かない
2. 要求事項にするのは、**欠けると記録された一致の値が読めなくなるもの**に限る。判定の基準は「承認者(要求事項3)が記録だけから、値の意味と限界を読めるか」とする
   - (a) 採点の構成の識別: 採点のモデルの固定した版(可動の別名を記録に数えない)・提供者・推論の設定・採点の指示の版・照らした正解(要求事項11 の採点の基準と参照解)の版
   - (b) 部分集合の選び方(無作為・層別・判定の割れた事例の優先など)と件数
   - (c) 一致の表し方(R-2)
   - (d) 人の採点者の記名と伏せ方(R-4)
   - (e) 失効の契機(R-4)
3. **使用可否の判断基準**を、1.7.7 の「**組織が定める値**」として置く。AI運用担当者が起案し、技術判断者が**測定の前に**記名で定める。本標準は参考の値を置かない。基準の記録が無い、または基準を満たさない採点による差分は、要求事項3 の承認の材料に「較正の基準なし」「較正の基準を満たさない」と表示し、層1 の受容の権限の段階で定めた権限者が期限つきで受容する(要求事項8・12 と同じ型)
4. 規定の書き方: 表の中は1.7.1 のである調の要求(「〜を記録する」「〜に数えない」)で書く。手引き(件数の決め方など)は表の外の箇条に「手引き」と明示して置き、要求事項と混ぜない

### 理由

- **現行の要求事項15 は、満たしても信頼性を保証しない形で満たせる**。合格が9割の集合で常に合格と出す採点者は単純な一致率 90% を書ける(内部 5.2)。基準集合で一致率と κ の差が 10〜40 ポイントある(外部 1.1、Norman ほか 2026)。記録の項目を定めない要求は、承認者が読めない数字を作らせるだけで、頼った結果「決めるべきことが漏れる」。手引きに置けば、この穴は適合を主張する組織にとって閉じない
- **値でなく手順を課すのは、外部と本標準の先例の両方と整合する**。NIST 草案は数値を置かない。本標準の「値を課さない」先例(5.8.7 の閾値、導入前の検証の合否の基準、H.7 の件数)の根拠は「支える測定が無い」「案件と版で値が異なる」で、手順と記録まで免除した先例は無い(内部 2.2)
- **組織が定める値は、ADR-0104 の「下限を課さない」と別物である**。1.7.7 は「課さない」と「組織が定める値」を別の型として区別している(`overview.md` 1.7.7 の表)。本標準は値を置かない(ADR-0104 を維持)。ただし採点の結果を見てから「この一致なら使える」と決める事後の正当化は、閾値の目標化(外部 5)より直接に物差しを損なう。導入前の検証の合否の基準を「採用者が実行の前に決める」とした先例(ADR-0057)と同じ型に揃える
- 判定の基準を「承認者が読めるか」に置くのは、要求事項15 の記録の宛先が要求事項2・3 の記録であり、読み手が AI運用担当者と層1 の権限者だからである

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 手引きだけに置く(NIST 草案と同じ強さ) | 要求事項15 の穴(偏った集合の単純な一致率)が適合のまま残る。草案は任意の実務集で、適合を主張させる規格の強さの目安にならない |
| 定めない(未定のまま) | `rr:1525` の「未定」を放置すると、読み手は「書かれていない」と「課さないと決めた」を区別できない状態が続く。どちらかに倒す |
| 一致の下限を本標準が数値で課す(κ ≥ 0.6、TPR/TNR ≥ 0.8 など) | 値を支える測定が無い。同じ値の意味が基準集合ごとに揃わない(外部 1.1)。較正の集合へ採点の指示を合わせ込めば越えられる(NIST 草案 2.1.1 の過適合の論理の当てはめ。解釈)。導入時の高い一致が後の正しさを保証しなかった例がある(Omni-Judge、外部 3.3) |
| 組織が定める値に参考の値を添える | 参考の値は事実上の下限として運用される(DeepEval の既定 0.5 の懸念、外部 4.2)。参考の値を支える測定も無い |
| 基準を満たさない採点を一律に差分の算出から外す | 基準の値そのものを本標準が支えられないのに、結果だけを硬くすると、組織は基準を低く定める向きへ動く。表示と期限つきの受容で、緩めたことを可視にする型(要求事項8・12)に揃える |

### 反論されうる点

- 「組織が定める値は、ADR-0104 の『下限を課さない』を実質的に覆す」: 本標準が値を置かない点は変えない。変えるのは「測定の前に誰が基準を決めたか」を残させる点である。ただし ADR-0104 の「課さないと決めたこと」と読み手が衝突を感じうるので、新 ADR で ADR-0104 を**補う**関係を明示し、「下限を課さない」は「本標準が値を置かない」意味だと書く(R-5)
- 「組織は基準を 0 に定めれば済む」: 済む。ただし 0 と記名で書いた記録が残り、内部監査と承認者が読める。数値を課しても合わせ込みで越えられる点は同じで、可視性で劣らない
- 「記録の項目が多く、1〜2 名の体制で負担になる」: 負担は採点の構成の識別とつながる項目で、多くは評価の道具が出力する。負担を採否の理由にしない(コアポリシー)

## R-2 一致の指標と件数

### 結論

1. **単純な一致率だけを一致の値として書いてはならない**(要求事項)。一致は、AI の採点と人の採点の**分割表**(二値なら混同行列の4つの件数。多値なら区分ごとの表)で記録する(要求事項)。偶然の一致を補正した指標(κ・α・均衡化した正解率・感度と特異度の組など)を併記する場合は、その名称と計算の方法を書く
2. 特定の指標の名を本標準は指定しない。指定しないと決めたこととして明記する
3. 一致は、**比べる双方のモデル(現行・候補)の出力ごとに分けて**記録する(要求事項)。双方の合計だけを書かない
4. **人どうしの一致**(評定者間の一致): 同じ事例を複数の人が採点した場合は、人どうしの一致を同じ表し方で併記する(条件つきの要求事項)。複数の人に採点させることは課さない
5. 件数: 本標準は件数を定めない。**手引き**として「件数は、目標とする不確かさ(信頼区間の幅など)から決め、決めた方法を記録することが望ましい」と書く。部分集合の選び方は必ず記録する(R-1 の (b))。判定の割れた事例を優先した部分集合など、無作為でない選び方の一致の値を、基準集合全体の一致として書かない(要求事項)
6. 少件数の扱い: 要求事項15 の記録(導入の承認の材料)では、件数によらず分割表を記録する。**H.7 の「少件数の値を載せてはならない」を導入の記録へ持ち込まない**。保証の開示など対外へ出す場合は H.7 による

### 理由

- **分割表を正本にするのは、どの指標も分割表から導けるからである**。指標の選び方は研究でも決着していない(κ の逆説、偏った分布での α の誤解、Landis・Koch の区分への批判。外部 1.1)。指標の名を本標準が決めると、その指標の弱点を規格が固定する。分割表があれば、承認者と監査が後から別の指標で読み直せる。ISO/IEC/IEEE などの規格の直写ではなく、測定の記録を「後で検算できる形」にする本標準自身の判断である
- **双方別の記録は、自己優遇・類似のモデルの優遇を、系統でなく測定で捉える**。採点者が一方のモデルの出力に偏るなら、双方の一致の非対称に現れる。ADR-0104 決定5 の「部分集合に双方の出力を含める」は、合計だけを書けば非対称を消してしまう。双方別にして初めて、#424 の起案が書いた「偏りを実際に測る」(内部 2.3)が記録の上で成り立つ
- **人どうしの一致は、AI の採点の一致を読む物差しである**。人どうしの一致が低い作業で AI と人の一致が低くても、採点者の欠陥とは限らない(Judge's Verdict、外部 1.2)。NIST 草案も評定者間一致の計算を例示する。ただし二人の採点を課すことは、ADR-0104 が「正解を二人で確定すること」を課さないと決めたことと釣り合わない(採点は正解の確定ではないが、負担の構造は同じ)。測った場合の記録だけを課す
- **件数を定めないのは、一次資料が一致して「目標の精度と採点者の予測しにくさ」から決まると示すからである**(PPI 系、κ の標本数設計、NIST 草案の検出力と予算の釣り合い。外部 1.3)。固定の件数の一次資料は無い
- **H.7 を導入の記録へ持ち込まないのは、対象と読み手が違うからである**。H.7 は対外の開示で、少件数の値が独り歩きするのを防ぐ。導入の承認は、件数と分割表を読める内部の承認者が行う。少件数を「未測定」へ倒すと、承認者から情報を隠すことになり、信頼性を下げる。少件数であることは分割表の件数そのものが示す

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| κ を指定して課す(#424 の起案の「κ・均衡化した正解率を用いる」の具体化) | 偏った分布で κ が誤解を招く(κ の逆説)。2 値と多値・2 者と多者で適切な指標が異なる。分割表を課せば目的は満たせ、指標の弱点を固定しない |
| 信頼区間の記録を課す | 区間の計算の前提(独立・層別・クラスタ)を規格が決められない。分割表と選び方の記録があれば区間を後から計算できる。手引きで推奨に置く |
| 人どうしの一致を課す(複数の人による採点を求める) | ADR-0104 の「二人で確定すること」を課さない判断と釣り合わず、1〜2 名の体制で成り立たない。効果を測った資料も無い |
| 人どうしの一致を AI の一致の上限・目標にする | 「超一貫」を誤って高く・低く評価する危険の両方があり、研究で決着していない(外部 1.2) |
| 最低件数だけを課す | 数値の根拠が無い。件数の下限を越えたことが、較正の十分性の主張に使われる |
| H.7 に揃えて、少件数の値を導入の記録に書かせない | 上の理由。承認者から件数と値を隠す |
| 判定の割れた事例の優先を禁じる | 割れた事例は採点者の弱点を探すうえで有効で、pit-wall も採る。禁じるのでなく、その値を全体の一致として書かないことで足りる |

### 反論されうる点

- 「分割表は指標より読みにくく、承認者は結局一致率を読む」: その危険は残る。分割表に加えて、手引きで「偶然の一致を補正した指標を併記することが望ましい」と書く。指標を課さない代わりに、単純な一致率**だけ**を書くことを禁じる
- 「多値・自由記述の採点で分割表が大きくなる」: 区分ごとの表で足りる。連続の点数は、合否の判定に使う区分へ落とした表を書けばよい(差分の算出に使うのは合否または区分であるため)。この当てはめは手引きに書く
- 「双方別にすると件数が半分になり、各側の値が不安定になる」: 不安定であることが件数から読めることが重要である。合計に混ぜて安定して見せるほうが信頼性を損なう

## R-3 偏りの統制と採点者の位置づけ

### 結論

1. **採点は、要求事項11 で確定した正解(採点の基準と参照解、または期待する出力・合否の判定)に照らして行う**(要求事項)。採点のモデルが自ら作った基準で採点した結果を、要求事項15 の採点に数えない
2. **採点の指示は指示資産として扱う**(要求事項5 の自組織のリポジトリ、版の記録)
3. **対の比較(二つの出力を並べて優劣を判定する採点)では、双方の提示の順で採点し、順で判定が変わった件数を記録する**(要求事項。適用: 対の比較の採点)。順で変わった事例の扱い(引き分け・除外・人の採点)を、測定の前に定めて記録する
4. 長さ・書式の摂動、同じ中身の書式違いによる公平性の確かめは**手引き**(行った場合は方法と結果を記録する。行わない場合に「なし」と書く)
5. **採点のモデルの位置づけ**: 5.8.7 の要求事項4 と同じ型で置く。採点に用いるモデル・サービスは 3.12.2 の AI 実行基盤に当たる。導入の承認(要求事項3)と依存先の一覧(3.12.11)の対象とする。席の担い手ではないため、3.4.2 の適合性確認と要求事項7〜9(退出の予行)は掛からない。**採点のモデルの導入の回帰評価に、別の AI の採点を用いない**。採点のモデルの回帰評価に当たるのは、要求事項15 の人の採点との一致の測定とする
6. **評価の対象のモデル自身での採点**: 禁止しない(現行の開示を維持)。開示に加えて、上の 2 の双方別の一致(R-2)が自己優遇を測る手段になる。**採点のモデルが比べるモデルと異なること(系統・提供者・版のいずれも)を、採点の正しさの根拠として書かない**(要求事項。ADR-0075 決定12 の当てはめを系統から版へ広げる)
7. 複数の AI の採点者(陪審): 用いてよい。多数決の判定を一つの AI の採点として、人の採点との一致を測る。**AI どうしの一致を要求事項15 の一致に数えない**(要求事項。要求事項11 の「AI の採点の一致を正解に数えない」と同じ線)

### 理由

- **参照解に照らす採点は、本標準の語彙の帰結である**。要求事項11 は、一意の正解を持てない事例の正解を「人が確定した採点の基準と参照解の組」と定義した。採点者がそれを使わずに採点すれば、物差しを人に結びつけた要求事項11 が採点の段で外れる。外部でも参照解の付与で数学の採点の失敗が 70% から 15% へ下がった(GPT-4 世代、外部 2.1)
- **採点の指示を指示資産にするのは、版を記録しないと物差しが共有できないからである**。日本語 MT-Bench で採点のモデルの版の違いが点数を動かし、第三者が再現できなかった(外部 3.1)。NIST 草案も表 2.2 で「採点のプロンプトの慎重な設計と試験」を例示する
- **順の入れ替えを要求事項にするのは、効果の測定があり、行ったかを記録で確かめられ、実施の方法が一意だからである**。既定の指示で GPT-4 が順を入れ替えて同じ判定をしたのは 65%(外部 2.1)。Norman 2026 は再試験の信頼性が高くても強い位置の偏りを隠すと報告する。入れ替えの不一致を引き分けにする方式が信頼性を上げないという批判(JudgeLM)があるため、扱いを規格が決めず、組織に事前に決めさせる
- **長さの統制を手引きに留めるのは、方法が一意でなく、本標準の主対象で長さが中身を担うからである**。長さを統制した AlpacaEval の手法は集計の回帰で、事例ごとの採点の統制ではない(外部 2.2)。コード・レビューの指摘では長さの差が品質の差でありうる。要求事項にすると、どの統制を行えば満たすかが決まらない
- **採点のモデルを 5.8.7 の型で位置づけるのは、既存の箇条との整合のためである**。「承認されていないモデルを開発組織で用いてはならない」(`rr:1513`)は採点のモデルに掛かる。掛かると決めないと、承認の無いモデルで差分を出す余地が残る。一方、採点のモデルの導入に採点者を要すると循環する(内部 5.4)。人の採点との一致の測定を採点のモデルの回帰評価に当てて循環を断つ
- **自己採点を禁じないのは、禁じることが偽りの安心を生むからである**。別の版・同じ提供者の別のモデルでも類似のモデルの優遇がある(424-2)。「同じ版でない」ことを満たした組織が、偏りを測ったつもりになる。ADR-0104 の裁定(開示)と、#424 の起案の「どの選び方にも偏りの向きがある」(内部 2.3)を維持する。代わりに双方別の一致で測る。主要な道具は採点のモデルを指定しないと評価の対象のモデル自身で採点する(Inspect、外部 4.2)ため、開示は維持する
- **版へ広げた禁止は、ADR-0075 決定12 の趣旨そのものである**。決定12 は「系統の違いを確認の強さの根拠として書かない」とした。根拠は、系統をまたいでも誤りが相関すること。同じ理由は版・提供者の違いにも当たる。系統だけを塞ぐと「別の版で採点したので偏りが無い」と書く隙間が残る

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 評価の対象のモデル(同じ版)での採点を禁止する | 上の理由。別の版で満たした組織に偽りの安心を与える。ADR-0104 の裁定と #424 の起案の却下を覆す根拠(新しい測定)が無い |
| 別の系統の採点者を求める・推奨する | ADR-0075 決定12(求めない・推奨しないも書かない)に反する。自己優遇の抑えに系統の違いが効くことを測った研究は見つかっていない(外部 2.6) |
| 長さ・書式の統制を要求事項にする | 方法が一意でなく、満たしたかを判定できない |
| 採点のモデルを席の担い手として 3.4.2 の適合性確認に掛ける | 席の判断を代わりに下すのでなく、測定器である。5.8.7 の推定のモデルと同じく 3.4.2 の対象の外に置く |
| 採点者を附属書H H.4 の5条件に掛ける | H.4 は確認そのものの数え方で、物差しは対象外(`ac:361`、ADR-0104 決定8)。範疇を混同する |

### 反論されうる点

- 「順の入れ替えの効果の数値は GPT-4 世代で古い」: その通りで、2025〜2026 世代の再測定は限られる(外部 2.6)。根拠水準マーク(E1)で開示し、記録された「順で変わった件数」が新しい世代でほぼ 0 である組織が複数あれば、要求事項から手引きへ移す向きの差し替え条件を置く。費用は採点の倍で、信頼性の損失より小さい
- 「版への拡張は ADR-0075 決定12 の範囲を広げる解釈で、決定の書き換えに当たる」: 決定12 は系統について定め、版については何も定めていない。版について同じ禁止を置くのは新しい決定で、新 ADR に書く。ADR-0075 は書き換えない
- 「採点の指示を指示資産にすると、3.11.4 の棚卸しの対象が増える」: 負担を採否の理由にしない。採点の指示の版が記録に無いことは、点数の再現ができないことと同じである

## R-4 見直しの契機と適用範囲

### 結論

1. **一致は評価ごとに測り、前の評価の測定を流用しない**(要求事項)。要求事項15 の「部分集合に比べる双方の出力を含める」から既に導かれるが、明文にする。これで評価の対象の分布の変化と、評価の対象が採点者より強くなる場合を、評価ごとの測定で捉える
2. **採点の構成の識別(R-1 の (a))が変われば、その識別での一致の測定は失効する**(要求事項)。3.4.2 の要求事項7 の「識別の変化で失効」と、5.8.7 の要求事項6 の「版を固定し、変えるときは測り直す」と同じ型
3. **適用を広げる**:
   - 3.12.4 の品質の監視: 監視の試行で AI の採点を用いる場合は、基準値を定めた評価(要求事項3)で一致を測った採点の構成と同じ識別を用いる。識別が変わったときは、基準値との比較の前に一致を測り直す(要求事項)。監視の試行ごとの人の採点は課さない。測り直しの間隔は 1.7.7 の**既定値**とし、既定値は 3.11.4 の四半期の棚卸しの周期とする(置き換えはテーラリングの宣言による)
   - 3.4.2 の適合性確認: 過去の判定の再現を AI の採点で照合する場合は、要求事項15 と同じ記録を確認の記録(3.4.2 の要求事項5)に含める(要求事項)
   - 要求事項7 の退出の予行: 現行のまま要求事項15 が掛かることを明記する
4. **人の採点者**:
   - 記名の自然人とする。人の採点は、要求事項12 の正解を確定する者が行う。AI運用担当者は人の採点をしない(要求事項)
   - 人の採点者に、採点の前に AI の採点の結果と、どちらのモデル(現行・候補)の出力かを示してはならない(要求事項。要求事項13 の伏せ方と同じ線)
   - 人の採点者ごとの一致を、個人の成績評価・人事に用いてはならない(第5章 5.6.2 の目的の限定を準用)
5. 「評価の対象が採点者より強くなったとき」を**独立の契機にしない**(課さないと決めたこと)

### 理由

- **評価ごとの測定は、分布の変化に対する唯一の観測できる手当てである**。安全性の評価で、分布の変化のもとで採点者が偶然に近い水準へ落ちた(Coin Flip 2026)。強い生成器の応答で採点者が劣化した(Shelf Life 2025)。導入時の一致が後の正しさを保証しなかった(Omni-Judge 86% → 不一致の 96.4% が採点者の誤り)(外部 3.2・3.3)。流用を許すと、これらをすべて見逃す
- **失効の型を揃える**: 本標準は「識別が変われば失効」(3.4.2)、「版を固定し、変えるときは測り直す」(5.8.7)、「契機は版の変更と暦。自動で変えない」(3.12.12)の型を持つ。採点の構成だけがこの外にあった(内部 5.3)。NIST 草案 2.2 の版付けの考え方(比較できなくなる変更を示す)とも一致する
- **監視へ広げるのは、基準値との比較が採点の構成に依存するからである**。採点のモデルが替われば、点数の変化がモデルの劣化か採点者の変化か区別できない。基準値を自動で改めない(3.12.4)と決めた以上、比べる物差しの側の同一性も保たなければ、基準値の固定は意味を失う。ただし日次の試行ごとの人の採点は負担でなく実施不能の水準になるため、構成の固定と定期の測り直しに置く
- **既定値に置くのは、1.7.7 の「置き換えずに用いても統制を弱めない値」に当たるからである**。提供者が固定の識別の背後で挙動を変えないことを確かめる手段が採用者に無い。四半期は既存の棚卸しの周期で、新しい周期を作らない。周期の長さに測定の根拠は無く、根拠水準マーク(E0)の対象
- **人の採点者の伏せ方は、要求事項13 と釣り合わせるためである**。正解の確定には評価の対象の出力を示さないのに、一致の物差しになる人の採点に AI の判定を見せてよいのでは、係留(AI の事前注釈への引きずられ。EV-0213 の外部根拠)が物差しに入る。pit-wall も腕と判定を伏せる(内部 4.2)
- **確定する者に採点させるのは、席の判断の物差しを席に結びつけた要求事項12 の延長である**。AI運用担当者が採点すると、導入を承認する者が物差しの側にも入り、分離が崩れる
- **5.6.2 の準用は、評定者間の一致の算出を禁じずに、目的だけを限るためである**。人どうしの一致を測ることは R-2 で認めた。測った値が人事へ流れれば、採点者が AI の判定に寄せる動機が生じ、物差しが壊れる
- **「より強くなった」を独立の契機にしないのは、観測の操作的な定義が無いからである**。強さを測る手段が採点者自身の評価なら循環する。評価ごとの測定で、強くなったことの帰結(一致の低下)を捉える

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 以前の測定の流用を、採点の構成が同じなら認める | 分布の変化と強い評価の対象での劣化(外部 3.2・3.3)を見逃す。要求事項15 の「双方の出力を含める」とも合わない |
| 監視の試行ごとに人の採点を課す | 日次以上の頻度で実施不能。課しても形骸化する |
| 監視を要求事項15 の外に置いたままにする | 採点のモデルが替わったときに、基準値との比較が無意味になることを誰も検出しない |
| 測り直しの間隔を組織が定める値にする(既定を置かない) | 記録が無いと基準を満たさない型になり、監視そのものが未達(IMPL-0408)の組織で一斉に不適合を作る。統制を弱めない既定値で足りる |
| 暦の契機を半期(3.12.12 と同じ)にする | 3.12.12 は定数の再評価で、測定器の同一性の確かめではない。監視は日次で、物差しのずれの影響が早く積もる。既存の四半期の棚卸しに乗せる |
| 人の採点者に二人目・盲検の二重採点を課す | ADR-0104 の「二人で確定」「盲検の確定」を課さない判断と釣り合わない |
| 人の採点者ごとの一致の算出を禁じる | 人どうしの一致(R-2)が測れなくなる。目的の限定で足りる |

### 反論されうる点

- 「評価ごとの測定は負担が大きく、組織は AI の採点をやめて『未測定』と書くだけになる」: そうなれば要求事項15 が「未測定」を表示し、承認者が読む。未測定のまま採点を使うことが見えるほうが、流用された古い値で安心するより信頼性が高い
- 「四半期の既定値は根拠が無い」: 無い。E0 でマークし、差し替え条件を「監視で採点の構成を固定した組織で、四半期の測り直しで一致が動いた記録が複数あれば短くする向き、動かない記録が揃えば長くする向き」とする
- 「確定する者に採点させると、席の責任者の負担が集中する」: 正解の確定と採点は同じ判断の能力を要する。負担を理由に別の者へ移すと、物差しを確定した者と採点した者で基準がずれる(基準の漂流。外部 1.2)

## R-5 記録と降ろし先

   - 導入の記録への H.7 の少件数の扱いの持ち込み
3. **EV**:

   - EV-0214: 差し替え条件の観測の源の一つ(3.12.4 の監視)が未達である(内部 5.8)ことを、本文の EV の中に書き足す。採用済み ADR と違い、EV の本文は改めてよい。識別子は再利用しない
4. **IMPL**:
   - IMPL-0407 の note を広げる(分割表・双方別・選び方・採点の構成の識別・人の採点者の記名と伏せ方の欄・使用可否の基準の有無と測定の前の記名の日付)。検査は「欄が欠けたものを未測定・較正の基準なしと出す」に留め、値の良否を機械に判定させない

5. **#426 との順序**: **#427 の決定を先に本文へ入れ、#426 がその欄で記録の形を決める**。#426 が先に形を固めると、#427 の欄を足すたびに IMPL-0407 の検査の対象が変わる

   - 判定の割れた事例を優先した抜き取りの κ を、全体の一致として出していないか(R-2 の 5)
   - 双方(腕)別の一致を出しているか(R-2 の 3)
   - 別の系統の陪審であることを、採点の正しさの根拠として書いていないか(R-3 の 6)
   - pit-wall の 0.8 を、本標準の参考の値として引かない(R-1 の採らない案)

### 理由

- **新 ADR で補う形にするのは、ADR-0104 の「課さないと決めたこと」の読み方が変わるからである**。採用済み ADR の本文は書き換えない規則のもとで、読み手が衝突を感じうる点(下限を課さない ↔ 組織が定める基準)を、後の ADR が明示的に解く必要がある
- **「課さないと決めた」の列挙は、コアポリシーの「却下は成果である」の実施である**。現行の `rr:1525` は「未定」で、#424 の起案の指標の案はどこにも却下の記録が無い(内部 2.3)。#427 で決着させないと同じ穴が残る
- **#427 を先にするのは、記録の形が規定の欄から導かれるからである**。逆順では、IMPL-0407 の検査が二度変わる
- **pit-wall の閾値を矛盾としないのは、1.7.7 の型で説明できるからである**。本標準が値を置かないことと、ある組織(pit-wall の利用者)が値を定めることは両立する。食い違うのは、値でなく測定の読み方(抜き取りの偏り、双方別、系統の根拠化)である

| --- | --- |
| ADR-0104 の追記で済ませる | 採用済み ADR の本文は書き換えない(運用ルール) |
| ADR-0104 を置き換える ADR にする | 決定1〜4・6〜9 は変わらない。置き換えると、変わらない決定の根拠の所在が二重になる |
| pit-wall の 0.8 を本標準へ取り込み、参考の値にする | R-1 の採らない案と同じ。単一の実装の値で、測定の根拠が無い |
| pit-wall を本標準に合わせて直接直す | 別のセッションが開発中で、main へ直接 push しない規則(CLAUDE.md) |
| #426 を先に進め、#427 の欄は後で足す | 検査の対象が二度変わり、降ろした検査が規定と食い違う期間ができる |

### 反論されうる点

- 「新 EV が3つ増え、台帳の見通しが悪くなる」: 判断ごとに差し替え条件が違うため、束ねると差し替えの判断ができない
- 「pit-wall の割れた事例の優先は、採点者の弱点を探す目的では正しい」: 正しい。だから禁じず、その値を全体の一致として出さないことだけを求める。PR の提案もその範囲に留める
- 「テンプレートへの即時の1行は、検査が降りていないのに規則だけを置く」: IMPL-0404 と同じ型で、常駐の規則として AI の担い手の挙動を先に縛る価値がある。検査の未達は IMPL-0407 が undelivered として表示し続ける

## 論点ごとの結論(要旨)

| 論点 | 結論 |
| --- | --- |
| R-1 | 手順の骨格・記録・失効の契機を要求事項として課す。数値は置かない。使用可否の基準を組織が定める値(参考の値なし)として測定の前に記名で定めさせ、無い・満たさない場合は表示と期限つきの受容 |
| R-2 | 単純な一致率だけの記録を禁じ、分割表を現行・候補の双方別に記録させる。指標の名は指定しない。人どうしの一致は測った場合に併記。件数は目標の精度から決める手引き。偏った選び方の値を全体の一致と書かない。導入の記録に H.7 の少件数の扱いを持ち込まない |
| R-3 | 確定した正解に照らした採点と、採点の指示の指示資産化を課す。対の比較だけ順の入れ替えを課し、長さの統制は手引き。採点のモデルは 5.8.7 の型で AI 実行基盤として導入の承認の対象にし、回帰評価は人との一致で代える。自己採点は禁じず開示と双方別の一致で測る。採点のモデルの違い(系統・提供者・版)を正しさの根拠に書かない |
| R-4 | 一致は評価ごとに測り流用しない。採点の構成の識別が変われば失効。3.12.4 の監視(構成の固定と既定値で四半期の測り直し)と 3.4.2 の確認へ広げる。人の採点者は確定する者が記名で行い、AI の判定とどちらの出力かを伏せる。「より強くなった」は独立の契機にしない |
| R-5 | ADR-0105 で ADR-0104 を補う。`rr:1525` の「未定」を定めたことと課さないと決めたことへ書き換える。新 EV 3つ、IMPL-0407 の拡張とテンプレートへの即時の1行。#427 を #426 より先に。pit-wall の 0.8 は組織が定める値として矛盾とせず、測定の読み方の食い違いだけを pit-crew へ PR で提案 |
