## 1. 立場と、全体の見立て

1. **#267・#270 の「足すのは安く、外すのは重い」は、本標準が意図して選んだ非対称である**。ADR-0055 決定5(緩める向きは記名と理由、厳しくする向きは即時。5.4.5・5.4.6 と同じ非対称)、ADR-0038 決定1・3(強制層の縮小は統制の弱化で、承認は AI維持管理者)、3.11.5(追加は誰でも、削除は集約)、Label Mailbox 原則4(検証ゲート・重要テストの削除は不可逆の操作)。外す費用を下げる案は、どれもこの 4 つの決定のどれかを覆す。**覆す材料(外す手続の重さが装置の増加を招いたことの測定)は 3 本の調査のどこにも無い**。ganbari-quest の凍結は本数の減少だけが記録され、効果は測られていない(FND-0196)
2. **装置の総量に上限を置く案は、ADR-0072 と同じ理由で落ちる**。数えるもの(本数・行数・PR の割合)はどれも定義で値が動き(FND-0229・0230・0261・0262)、外部の one-in-X-out の評価は「件数は満たされ、負担は減らない」(NAO 2016、TBS 2022)。上限を置けば、第8章 軸C・E の「+」(規制・安全重要度で検査を足す)と、「安全重要度による要求は、人員や期日の制約によって外れません」(`TG:786`)の前で、上限と要求のどちらが勝つかを決める規定が要る。**課さないと明記する**
3. **欠けているのは席ではなく、外す候補を出す場と入力と、外す PR の書き方である**。席は AI維持管理者に決まっている(冒頭の 1)。場は 3.11.4 要求事項4 の四半期の棚卸しが既にある(冒頭の 2)。入力は ADR-0056 決定10(論証を支えない検査)と ADR-0073 決定3(是正で「外す」と決めた装置)と月次の誤検知の調整。書き方は陰性の確認の記録で決まっていない(冒頭の 4)。この 3 点を現行の部品の接続として直す
4. **現行の規定どうしの矛盾が 7 つある。足す向きの規定のうち誤っているのは、限定を落とした文と、自らの手続を満たさない指標である**。「合意済みルールはすべて機械化」(統合プロセスの原則 1 の限定を落とした)、「ルール化の進み」(手続2・3 を満たさず、警戒の理由「ゲートが成長していない」が ADR-0056 決定10・ADR-0073 決定3 と逆向き)、`needs-platform` の往路と復路の語、テンプレ1 の注記の旧 6 語、軸A の「必要に応じて」、軸B の「3.9」、ADR-0073 決定3 の起点の範囲。**原則(機械化して人の帯域を空ける)そのものは守る**。これは本標準の一文「マシンは人間より速い。それでも、決められた場所では必ず人間が触る」の前半の実装である
5. **escape clause は 3 つの意味に分けて記録する**。(a) は ADR-0062 で採用済み、(b) は ADR-0028・0036・0071 で退けた形であり課さないと明記、(c) は採用者への横断の要求としては課さないと明記し、本標準の起草の手順(会議体の突合)としてだけ置く。#269 の「Pre-PMF だから」は受入基準ではなく事業ステージの判断の転用で、第8章 軸B の「本軸は、未達の表示を動かしません」と ADR-0050 決定1 が既に塞いでいる。附属書B に足す場所は無い

## 3. 論点ごとの詳細

### E-1 装置の総量に上限を置くか

**判定: 課さないと明記する。** 本数・行数・実行時間・装置に触れた PR の割合のいずれにも、上限・警戒水準・警戒サインを置かない。

理由。

- **ADR-0072 決定2 の論法が、装置にもそのまま当たる**。「害の正体は量ではなく、読まずに通ること」に対応する装置の害は、量ではなく**個々の装置が止めるべきものを止めない・止めてはならないものを止める・保守の工数を食う**ことである。前の 2 つは ADR-0073 決定3 が是正の起点に入れた。3 つ目は E-2 の棚卸しで扱う。量の指標は「打ち手の無い、眺めるだけの指標」(`MT` の ADR-0072 の文)になる
- **数える単位が決まらない**。ジョブ・スクリプト・`pr-rules` の検査の種類・リントの規則のどれを数えるかで値が変わり、同じ実証案件の中でも検査スクリプトの本数が 61・45・58 と併存した(FND-0196)。テンプレートは `gate-g5` の 10 ジョブの下に `pr-rules` の 8 種を持つ。数えると決めた単位は、統合で満たせる(カナダ TBS 2022 の当事者の指摘、調査 1 の R2。原典)
- **上限は、検査を足すと定めた現行の規則と衝突する**。第8章 軸C「+規制要件の自動チェック」、軸E「+故障挿入試験、ミューテーション試験」、1〜2 名体制の代償措置「CI 基準の厳格化」(`TG:841`)。いずれも案件の性質から導かれる規則で、「安全重要度による要求は、人員や期日の制約によって外れません」(`TG:786`)。上限に達した案件で、規制の検査と上限のどちらを優先するかを定めない限り、上限は規則として成立しない。ADR-0050 決定1 は強制層をステージで動かさないと決めており、上限で外す規則が強制層の規則なら同じ衝突が起きる
- **上限を遮断として運用する形は、ADR-0047・0058 が退けている**。遮断にしない上限は、運用メトリクスの警戒サインになり、手続1〜3 を要する(E-5 と同じ問題)
- 外部の「質で外す」型(Google の解析器の 10%、SRE の対処可能性、Meta の悪化したテスト)は、**総数ではなく個々の装置**で外す。本標準でこれに当たるのは、ADR-0073 決定2 の 3 条件(機械で失敗させる入口)と決定3 の「外す」、ADR-0056 決定10 である。採るべき外部の型は既に入っている

### E-2 減らす判断を誰が行うか。ratchet の型。非対称を保つか

理由。

- **席は決まっている**。ADR-0038 決定1「遮断の解除・閾値の緩和・強制層の縮小」が統制の弱化、決定3「強制層の変更の承認者は AI維持管理者です(3.11.2)」。3.11.3 の表は強制層を「権限設定・実行前フック・CI の必須検査」とし、3.11.5 は「統合と削除は AI維持管理者のみが行う」、3.11.8 は「指示資産の削除・統合」を AI維持管理者 A/R・技術判断者 C とする。`LM:66` は「強制層の変更が必要になった場合は … `state:needs-platform` を付与する」、`LM:294` は「強制層(`.claude/**` 等)の縮小 → `state:needs-platform`」。**Platform は AI維持管理者そのもの**(`LM:59`「Platform(AI維持管理)」)である。調査 1 の 1.6 #3 が数えた 3 つの席のうち 2 つは同じ席であり、技術判断者は技術上の妥当性(基準値の変更の承認 `GC` 355 行、月次の誤検知の調整)を見る段である。3.11.2「決定しない事項 … 技術設計の採否」は、この分担と整合する(誤検知かどうかは技術の判断、外してよいかは強制層の承認)
- **欠けているのは、廃止の候補の宛先と場である**。ADR-0056 決定10 は「改善サイクルで廃止の候補に挙げる」とだけ書き、誰がいつ挙げるかが無い(調査 1 の 1.6 #4)。一方、3.11.4 要求事項4「定期的に棚卸しし、矛盾および陳腐化した記述を削除する(四半期ごと)」は AI維持管理者の作業として既にあり、「新しい判定の場を設けません」と書く。**候補をこの棚卸しの入力へ入れれば、宛先と場が同時に決まる**。ところが運用カタログの四半期の表(`OC` 38〜44 行)に、この棚卸しの行が無い。本文が四半期と書いた作業がカレンダーに載っていない(`OC` の原則「作業はカレンダーに載せる」に反する)。直すのはカタログの側である
- **3.11.4 の適用範囲を行の中に書く**。3.11.3 の定義では強制層も指示資産であり、3.11.4 は全層に掛かると読める。しかし要求事項1(200 行)の根拠は「指示の分量が増えるほど遵守率は下がる」で、エージェントが読む記述に掛かる。G-5 基準6 とコンテキスト基盤(`context-base.md:96`)も「文脈ファイル」に当てている。要求事項5・6 も「記載」「読み込み」の語で書かれる。要求事項3・4・7 は層を問わない。**誤りは、適用範囲の限定を持たない表の行の側**であり、#226 の書式(限定は行の中に書く)で直す

- ratchet(2-F)は、業界の ratchet(違反の件数を一方向へ固定、Notion・ESLint)と対象が逆で、統合で満たせる(R2)。装置 0 本の初期の案件は何も足せない。是正の起動で「足す」と決めた検査を ratchet が止めると、ADR-0073 決定3 と当たる

### E-4 ADR-0073 との関係。意図して外すときの記録の中身

**判定: 採る(4-D を書き方に限る)。** 外す手続を軽くはしない。外す変更が現行の検査で書けない点と、起点の範囲が決まらない点を直す。総量の規定を ADR-0073 と別に置く案(4-C)は採らない。

理由。

- **外す PR が、現行の陰性の確認で書けない**。本文は「変更後の設定でも、止まるべきものが止まること」を求める(`GC`)。テンプレートの検査は結果が「止まらなかった」なら失敗させる(`check-pr.mjs:268`)。外した検査が止めていた場面を通すと、当然「止まらなかった」になる。本文の文意は「変更後に止まるべきもの」であり、外す変更では止まるべきものの集合が変わる。**外した後も止まるべき場面(残る検査、または代わりに置いた検査が止める場面)を書けばよい**。これを書かないと、外す変更は「場面を偽って書く」か「外さない」しか選べず、どちらも信頼性を損なう
- **外した場面は、外す理由とともに記録する**。ADR-0056 決定10「統制を外すときは理由を記録する」が既にある。ADR-0038 決定1 により強制層の縮小は統制の弱化で、AI維持管理者の承認を要する。検証ゲート・重要テストの削除なら `state:needs-owner` も要る(`LM:295`)。新しい手続は足さず、陰性の確認の節に「外した場面と理由」を書く行を置くだけにする
- **装置の不具合を是正の起点とする範囲を明らかにする**。ADR-0073 決定3 は「止めるべきものを止めなかった場合と、止めてはならないものを止めた場合の両方」を起点に含めるが、本文は起点の 3 項目(Sev1・Sev2、欠陥注入の見逃し、統制の弱化)の箇条の外に置き、重大度の限定を書かない。字義どおりに読むと、CI の誤検知 1 件ごとに 4 項目の是正の記録が義務になり、製品の欠陥(Sev1・Sev2 に限る)より重い。他方、運用カタログは「誤検知ルールの調整」を月次の作業にしている。ADR-0073 のコンテキストが挙げた装置の事例(検査が PR で一度も走らなかった、検証器の前提がずれていた)は、いずれも見逃しを生んだものである。**3 つの規定を両立させる読みは、「装置の不具合のうち、起点の 3 項目に当たる影響(Sev1・Sev2 の流出または停止、欠陥注入の見逃し、統制の弱化)を生んだものを起点とし、それ以外の誤検知は月次の CI ゲートの見直しで扱う」である**。ADR-0073 の本文は書き換えず、新 ADR に適用範囲として記録する。この読みが ADR-0073 決定3 を狭めると判断する委員がいれば、狭めないなら運用カタログの側を改めるべきで、どちらかを決めずに残すことはできない(4 章の問い)

落とした案。

| 案 | 落とす理由 |
| --- | --- |
| 4-A 個別の是正で足りるとし、何も足さない | 外す PR の書き方と起点の範囲の欠落が残る |
| 4-B 是正の記録の件数を第6章の観測へ出す | ADR-0073 決定1(件数を起動条件にしない)の後に、件数の観測を置くことになる。観測を置くなら手続1〜3 を要し、E-5 と同じ理由で落ちる |
| 4-C 総量の手続を ADR-0073 と独立に置く | E-1 で総量の規定を置かない。個別の「外す」と総量の「外す」が二重の判断になる |
| 4-D(全部) 外す変更の記名を軽くする | E-2 の 2-E と同じ理由で落とす。書き方は採り、記名は現行のままにする |

### E-5 「PR に占める装置修理の割合」を指標・警戒サインにするか

**判定: 課さないと明記する。**

理由。

- **定義が安定しない**。ganbari-quest で 55〜65%(FND-0230)、Filetto で「58%」が機械分類で 15.6〜45.3% と再現しない(FND-0261)。どちらの出所も分類規則を記録していない。装置比率を退けた理由(FND-0262)と同じ
- **自己申告のラベルで数えると、ADR-0073 決定1 の理由に当たる**。「何を同種とするかの分類は記録する者の申告で決まり、件数の閾値は分類によって外せる」は、「装置修理」のラベルにもそのまま当たる
- **パスで数えると、「修理」を測らない**。`check-pr.mjs` の `NON_PRODUCT` で「強制層・構成だけを変えた PR」は数えられるが、足す・直す・外すを分けない。テンプレートの更新の取り込みも分子に入る
- **判断基準と打ち手を書けない**(手続1、15939 の decision criteria)。割合が上がったときに何をするかは、「外す」なら E-2 の棚卸し、「凍結」なら E-3 で既に記録の経路がある。指標が無くても打ち手は動く。指標を置くと「眺めるだけの指標」になる
- ADR-0059 は定義の書けない比率を検知条件から外し、課さないと明記した。同じ型で書く

| 案 | 落とす理由 |
| --- | --- |
| 1-A 現状維持 | 却下が記録に残らない |
| 1-C パスで機械判定する正式指標 | 「修理」を測らない。判断基準と打ち手が書けない。上限 20 の確定(E-7)前に指標を足す。対の指標の指定(手続2)も示されていない |

### E-6 「ルール化の進み」の片側の警戒サインと、足す向きの規定

**判定: 採る。** 指標を分類別の表から外す。足す向きの規定のうち、限定を落とした文を直す。原則(合意済みの規則を機械化して人の帯域を空ける)は守る。

理由。

- **「ルール化の進み」は、正式指標として採用が成立していない**。`MT` 手続3「自動集計の実装をもって採用とする。実装前の指標を暫定として運用しない」。データ源の「`ci:` 種別のコミット」も「レビュー指摘由来」ラベルもテンプレートに無い(調査 2 の 1.3、`rule-candidate` の全文検索で私も 0 件を確かめた)。手続2 の対になる指標も書かれていない。**誤りは、手続を満たさない行が表に残っている側である**。手続3 は手続の正本で、行より上位にある。外すことは「廃止」ではなく、採用が成立していなかった行の是正であり、「廃止の判断は、値が良好であることを理由にしない」(`MT`)にも当たらない

- **両側にする案(2-B)と実装する案(2-E)は、ラベルによる自己申告の計数で、ADR-0073 決定1 の理由に当たる**。両側にしても、データ源が無ければどちらの側も点かないか、常時点く
- **G-5「合意済みルールはすべて機械化して載せる」は、統合プロセスの原則 1 の限定を落としている**。`integrated-process.md:45` は「**機械化できる検査は**すべて CI へ」と書く。何が機械化できるか(失敗させる形にできるか)は ADR-0073 決定2 の 3 条件が定める。限定を落とした G-5 と `CI` 冒頭の文が誤りで、原則そのものではない

### E-11 (c) を横断の要求にするか(#275 原則5)
