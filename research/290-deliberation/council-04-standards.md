## 1. 立場と、全体の見立て

1. **世の中に「統制・検査の本数の上限」を規範として置いた規格は無い。あるのは「質で外す」型と「外すときに正当化を書かせる」型である**。ISO 9001 は文書化した情報の量を組織に決めさせ(4.4.2「To the extent necessary」、TC 176 の手引き)、NIST SP 800-53B と GAO は外す統制にリスクに基づく理由を求める。Google の静的解析・不安定なテスト・SRE のアラートは、個々の装置の偽陽性と対処可能性で外す。本数で数える上限(one-for-one、one-in-two-out、BIT)は、実施した側の評価で「本数と負担に関係が無い」「範囲と統合で満たせる」(NAO 2016、TBS 2022 の 87%)と報告されている。**本数の上限は世の中の型から外れており、外れる理由も立たない**
2. **本標準に欠けているのは上限ではなく、外す判断の席と、外すときの記録の中身である**。ISO 9001 5.3(責任と権限の割り当て)の観点では、「CI の検査を外す判断を誰が行うか」が 3 か所に割れ、ADR-0056 決定10 の廃止の候補に宛先が無い状態は、上限の有無と独立した欠陥である。第8章 軸B が外す判断の所在として誤った節(3.9)を引いている(見立ての所見1)のは、その症状である
3. **足す費用と外す費用の非対称は、意図した設計として保つ**。外すときに記名と理由を要する形(ADR-0055 決定5、不可逆の操作の上申)は、NIST SP 800-53B・GAO・SOX の control rationalization(外部監査人が受け入れる文書化した理由)と同じ型である。直すべきは非対称そのものではなく、外す変更で陰性の確認に何を書けばよいかが無いという空白である
4. **測定の規格(ISO/IEC/IEEE 15939)に照らすと、「装置修理 PR の割合」も「ルール化の進み」も、測定方法と判断基準を書けない**。前者は 2 案件で定義が再現せず、後者は本標準自身の手続3(自動集計の実装をもって採用)を満たしていない。自らの手続に反する指標を表に残すことは、規格としての自己矛盾である
5. **escape clause は 3 つの意味を分けて記録する**。規格の用語としての escape clause は INCOSE R8 の (a)(要求文の逃げ道の句)であり、本標準は ADR-0062 で採用済みである。(a) を標準自身の規定文へ及ぼすことは ISO/IEC Directives Part 2 5.5 の型で、採るべきである。(c) を採用者への横断の要求にした規格は見つからず、標準の起草者の手順に限って採る。(b) は ISO 9001 4.3 の型が第8章に既にあり、附属書B に重ねない

## 3. 論点ごとの詳細

### E-1 装置の総量に上限を置くか

**判定: 課さないと明記する。** あわせて、規範の文に既に使われている「検査の装置」(`GC:351`)を第1章 1.6 で定義する。

文の案。

- 第6章 運用メトリクス「採用しない指標」の表に 1 行を足す:「| 検査装置の量(本数・行数・実行時間・ジョブ数)と、その増加の速度 | 本数は統合で満たせ、行数は数え方で値が動く。量と害(誤った停止・保守の工数)の関係は測られていない。量を下げる圧力は、必要な検査を外す向きにも働く | 是正の起動の記録のうち検査装置を起点とするもの、ゲート滞留時間 |」
- 同節の本文:「検査装置の量に、上限・警戒水準・警戒サインを置きません。検査装置を外す契機は、量ではなく、個々の検査の働き(止めるべきものを止めない、止めてはならないものを止める)です([第4章 G-5「是正の起動」](...))。」
- 第1章 1.6 の用語:「**検査装置**: 強制層([第3章 3.11.3](...))に置いた検査(CI の必須検査・実行前フック・権限設定)と、それを動かすワークフロー・スクリプト・規則データ。」

理由。

- **外部の型**: 規格の側は量を組織に決めさせる(ISO 9001 4.4.2「To the extent necessary」、TC 176 の手引き「プロセスの分析が必要な量を定める原動力」。二次資料・規格策定側の手引き、E1)。統制の外し方は、上限ではなく理由の記録で律する(NIST SP 800-53B、GAO。原典、E1)。ソフトウェアの実務は個々の装置の偽陽性と対処可能性で外す(Google CACM 2018、SRE 本 第6章、Meta 2020。原典、E1)
- **本数の上限の実施例は否定的に評価されている**: カナダ one-for-one は「廃止の 87% が負担に影響しなかった」「本数と削減に直接の関係が無い」、規制当局が「長く広い規則に束ねる誘因」を指摘(TBS 2022、原典)。英国 BIT は「範囲が操作されうる」(NAO 2016、要約頁)。#267 の「置換・統合は増加に当たらない」は、TBS が指摘した束ねる経路をそのまま開く
- **内部の整合**: ADR-0072(文書の量を指標にしない)の論法「量を下げる圧力は書くべきものを消す」「打ち手の無い、眺めるだけの指標」は装置にも当たる。装置は保守の工数と誤停止を生む点で文書と違うが、その害は量ではなく個々の働きに現れ、是正の起動(ADR-0073 決定3)が拾う
- **定義を置く理由**: 上限を置かないとしても、ADR-0073 決定3 は「検査の装置」を規範の文に使っている。JIS Z 8301 の構成では、規定に使う用語は定義するのが原則である。Label Mailbox の「テスト装置」、第3章の「強制層」、テンプレートの `NON_PRODUCT` が範囲の違う語を使っているため、E-2 の席を決めるにも対象の範囲が要る。範囲は 3.11.3 の強制層を軸にし、製品のテストは含めない(含めると FND-0262 の 0.35〜1.36 の揺れを再び招く)

選ばなかった案。

- 1-A 現状維持: 「書かれていない」と「課さないと決めた」が区別できず、#290 の受入条件「置かない場合はその理由」を満たさない
- 1-C 本数の上限(one-in-one-out): 数える単位(ジョブ・スクリプト・`pr-rules` の 1 行)が定まらない。統合で満たせる(TBS)。初期値は E0。規制の実施例で負担との関係が否定された型を、根拠なく持ち込むことになる
- 1-D 行数・実行時間の上限: 装置比率を退けた理由(FND-0262、定義で値が動く)がそのまま当たる。テンプレート自体が約 22,100 行で、初期値の置き場が無い。上限を遮断にすると ADR-0047・0058 と当たる
- 1-E 働きの指標を正式指標に: 方向は外部の型(質で外す)に合うが、「誤って止めた件数」を記録する仕組みがテンプレートに無く、手続3(実装をもって採用)を満たせない。是正の起動の記録が同じ情報を事象ごとに持つ。誤停止の記録が実装されたら見直す(下の暫定マーク)
- 1-F 案件が上限を宣言: 置かない宣言が既定になれば 1-A と変わらない。宣言の欄を 1 つ増やす理由になる外部の型が無い
- 1-G 判定の総数の原則を検査へ広げる: 拡張の根拠とする「原則」自体の所在が ADR-0013 に無い(E-13)。所在の決まらない原則を延長できない

根拠水準: **E1**(隣接領域の実施評価と、規格・企業の公表した実務。この文脈での測定は無い)。`:::caution[暫定 EV-NNNN / 見直し 2027-10]`。差し替え条件: 是正の起動の記録で、個々には起点に当たらない検査装置の不具合が積み重なって停止または保守の工数の増大を招いた事例(#267 の「打ち手を守る打ち手を呼ぶ」連鎖)が記録された場合、または誤停止の記録が実装され、量と誤停止の関係が観測できた場合。

### E-2 減らす判断を誰が行うか。ratchet。非対称

**判定: 採る(席を 1 つに決める)。ratchet は課さないと明記する。足す費用と外す費用の非対称は、意図した設計として保つと明記する。**

席の案。

- **CI の検査(検査装置のうち、ワークフローの必須検査と、その検査のスクリプト・規則データ)の追加と削除の結果責任を、技術判断者に置く**。根拠は本文の既存の配置にある。技術判断者は既に「起点に当たらない指摘は … 技術判断者が決めます」(`GC:320`、足す側)、「基準値そのものの変更 … 技術判断者の承認」(`GC:357`、緩める側の一部)、月次の CI ゲートの見直しと誤検知ルールの調整(`operations-catalog.md:33`)を持つ。外す判断だけを別の席に置くと、足す席と外す席が別れ、足す席には外す動機が残らない
- **強制層のうち指示資産(`.claude/**` の権限設定・フック等)は、3.11 のまま AI維持管理者**(要求事項3、3.11.5 の「削除の権限を集約する」)。AI維持管理者は CI の検査を外す変更の承認者として残る(強制層の変更の承認。`LM:294`、調査の引用)
- **ADR-0056 決定10 の「廃止の候補」は、月次の CI ゲートの見直しで技術判断者が出す**。入力は、是正の起動の記録のうち検査装置を起点とするもの、誤検知ルールの調整の記録、外す候補として挙がった `state:needs-platform` の依頼。AI は候補の提示まで(3.11.4 の「外す判断を AI に行わせてはなりません」を CI の検査にも及ぼす)
- 第3章の RACI(3.3 または 3.11.8)に「CI の検査の追加・削除」の行を足す(A = 技術判断者、承認 = AI維持管理者、C = 開発者・QA)
- `LM:87` の復路「ツールチェーンやテスト装置の修正・追加が完了」を、往路と同じ「削減・自動生成・統合・修正・追加」へ揃える(語の不一致。誤りは復路)

文の案(運用カタログの月次の行):「CI ゲートの見直し | 技術判断者 | 是正の起動の記録の確認、ルール化候補の吸い上げ、誤検知ルールの調整、**論証のどの主張も支えない検査と、是正の記録で外すと決めた検査の廃止の判断**」。第3章:「CI の検査を外す判断は、技術判断者が行わなければなりません。AI が行ってよいのは候補の提示までです。」

ratchet について:「検査装置の本数を、置換・統合を除いて増やさないという規律(ratchet)を課しません。」理由: 業界の ratchet(Notion 2025、ESLint の抑制)は違反の件数を一方向へ固定する仕組みで、規則の本数に掛ける例は無い。本数を単調非増加にすると、初期の案件(装置 0 本)は是正の起動で検査を足せなくなり、ADR-0073 決定3 の「足す」と当たる。

非対称について:「検査を外す変更は、統制を緩める向きの変更として記名と理由を要します([ADR-0055](...) 決定5)。検証ゲートと重要なテストの削除は不可逆の操作として事業決裁者へ上げます([Label Mailbox 原則4](...))。外す費用が足す費用より重いことは、意図した設計です。」理由: (1) 外部の型(NIST SP 800-53B「外した統制の理由を記録し弁護できる」、GAO「費用だけを実施しない理由として認めない」、SOX の rationalization は外部監査人が受け入れる文書化した理由を要する)と一致する (2) 本標準の不可逆性の定義(取り消せない時間帯がある)から導かれる。外していた間に通った変更は取り消せない (3) 3.11.5 は指示資産で同じ設計(追加は誰でも、削除は集約)を意図して選んでいる。

選ばなかった案。

- 2-A 現状維持: ADR-0056 決定10 に宛先が無いまま。ISO 9001 5.3 の観点で、責任と権限が割り当てられていない規定は運用されない
- 2-B AI維持管理者に寄せる: 3.11.2「決定しない事項 … 技術設計の採否」と当たる。CI の検査の採否は技術設計の一部で、基準値の変更の承認(`GC:357`)も技術判断者にある。Google の Tricorder の班(中央の席)に似せる理由は、班が解析器そのものの所有者だからで、本標準の CI の検査の所有者は案件の技術判断者である
- 2-D 四半期の振り返りで決める: 合議で記名の責任者が曖昧になる(本標準のアンチパターン「合議化」)。四半期の振り返りは検査の場で判定会議ではない(`IC:31`)
- 2-E 外す手続を軽くする: 外部の型(理由の記録)に反し、ADR-0055・Label Mailbox 原則4 を覆す材料が調査に無い。外す費用が重いことで実際に外せなくなった事例の測定も無い(ganbari-quest の 61→47 本は凍結の下で外せている)
- 2-F ratchet: 上記
- 2-G 席を置かないと明記: 決定10 の宛先の欠落が残る

あわせて、四半期の振り返りの参加者(`IC:31`)に AI維持管理者を加える。外側ループは「ゲートの追加・削除」を扱い、強制層の承認者を欠いて決めると、承認の段で覆る。

根拠水準: 席の配置は **E0**(本文の既存の配置との整合による判断。席を変えた効果の測定は無い)。非対称の維持は **E1**(外部の規範)。暫定マークは席の配置に付ける。差し替え条件: 廃止の候補が月次の見直しで挙がらないまま、是正の起動で外すと決めた検査が残り続けた件数(2 期で観測)。

### E-3 「80 点で止める」を標準の手続として持つか

**判定: 課さないと明記する。**

文の案(第4章 G-5「是正の起動」の末尾):「本標準は、検査装置の追加を期間を区切って止める手続(凍結)を置きません。案件が追加を止めると決めた場合は、外側ループの判断記録に書き、是正の起動の記録では項目3 の「置かない理由」として書きます。凍結は、出荷後の欠陥(Sev1・Sev2)の是正の記録を省く理由になりません。」

理由。

- 「80 点」には測定方法が無い(15939 の属性・測定方法を書けない)。凍結の効果も測られていない(FND-0196)
- 是正の起動の項目3 は「再発防止を仕組みで置くか。置かないなら、その理由」で、凍結はこの理由として既に記録できる。新しい手続を置く必要が無い
- 最後の文は (c) の型(E-11)を本論点に当てたものである。凍結が是正の記録の省略に読み替えられる経路を、条項の中で塞ぐ

選ばなかった案。

- 3-A 現状維持: 実証案件の判断が標準のどこに位置づくかが書かれない
- 3-C テーラリングの選択として宣言させる: 第8章に軸の外の選択を足すと、1.7.3 の「表の升は規則の結果で、組織が選ぶ余地を示さない」に反する宣言の欄になる。「80 点」の判定が自己申告で、ADR-0044 決定4 の論法(自己申告の閾値は要求を無効化する)が当たる
- 3-D error budget 型: SRE の error budget はサービスの信頼性の目標で、装置の誤停止の許容量へ移した先例は見つからない。許容量の初期値は E0。装置起因の停止を数える定義が無い(E-1 の 1-E と同じ前提の欠落)
- 3-E 追加の入口で論証の主張を名指しさせる: 主張の名指しは自己申告で、11 の主張のどれかに寄せて書ける。ADR-0056 決定10 の後半「論証のために新しいゲート・検査・様式を足さない」は、論証を理由に足すことを禁じる文で、入口の条件に転じると逆向きの読みを生む

根拠水準: **E0**(凍結の効果の測定が無い。課さない判断も同じく無測定)。見直し 2027-10。差し替え条件: 凍結を宣言した案件と宣言しない案件で、装置起因の是正の記録の件数と出荷後の欠陥の件数を比べた記録。

### E-4 ADR-0073 との関係。意図して外すときの記録の中身

**判定: 採る(4-A + 4-D)。** 総量の手続は置かず、検査装置は是正の起動で 1 件ずつ扱う。外す変更の記録の中身を第4章で埋める。

文の案(第4章「統制の設定の陰性の確認」に 1 段落):「検査を外す変更、または検査の対象を狭める変更では、陰性の確認の記録に、外した検査が止めていた場面と、外した後にその場面を止める手段(別の検査・人の確認)を書かなければなりません。止める手段を置かない場合は、その場面を止めないと決めた理由と、決めた者を書きます。外した後の設定で、別の手段が場面を止めることを確かめた結果を、止まった結果として書きます。」

あわせて新 ADR に、ADR-0073 決定3 の「装置の総量の上限は #290 で決めます」を受け、「上限は置かない。外す判断の席は E-2、外す記録は本決定」と書く。ADR-0073 の本文は書き換えない。

理由。

- 現行の陰性の確認(`GC:361`)は「変更後の設定でも、止まるべきものが止まること」を求める。意図して止めなくする変更では「止まるべきもの」が空になり、テンプレートの検査(結果が「止まらなかった」なら失敗)とも噛み合わない(調査 1.6 #9)。空白のまま置くと、外す変更は記録が書けずに滞るか、形式だけの記録になる
- NIST SP 800-53B の「ベースラインから外した統制の理由を記録し、明示的なリスクに基づく決定で弁護できる」と同じ構成にする。理由と記名は ADR-0055 の緩める向きの要件と一つの記録で満たせる(記録を 2 つにしない。#289 X-5 の裁定と同じ考え方)

選ばなかった案。

- 4-B 是正の記録の件数を第6章の観測へ出す: 観測の値を何に使うか(判断基準)を書けず、ADR-0073 決定1(件数で起動しない)との関係を注記で外す必要が生じる。E-5 と同じ理由
- 4-C 総量の手続を独立に置く: E-1 で上限を置かないので前提を欠く。個別の「外す」と総量の「外す」が二重の判断になる

根拠水準: **E1**(外部の規範の型。外す記録を求めた効果の測定は無い)。既存の EV(陰性の確認、`GC:366-372`)の対象に含めて見直す。新しい EV は付けず、既存の差し替え条件に「外す変更の記録で、別の手段が場面を止めなかった件数」を足す。

### E-5 「PR に占める装置修理の割合」

**判定: 課さないと明記する。**

文の案(第6章「採用しない指標」の表):「| 検査装置の修理の PR の割合(装置だけを変えた PR の比率を含む) | 装置の範囲と PR の帰属の規則で値が動き、2 つの案件で報告値を再現できなかった。上がったときの打ち手(足す・直す・外す・止める)を値から決められない | 是正の起動の記録のうち検査装置を起点とするもの、ゲート滞留時間 |」

理由。

- **15939 の情報モデル**(McGarry 2000 の二次資料、調査 290-2 2.6)は、属性・測定方法・基本測定量・指標・判断基準を要求する。この量は測定方法(パス・ラベル・LLM)で値が大きく動き(ganbari-quest 55〜65%、Filetto 15.6〜45.3%)、判断基準(何をしたら何をするか)を書けない。運用メトリクスの手続1 と同じ欠落である
- **外部の定義**: DORA の deployment rework rate は「インシデント起因の計画外のデプロイの比率」で、変更の対象(製品か装置か)を分類しない(原典、2024)。投資配分の実務は Issue 管理の分類から継承し、分類率 80% 超を前提にする(Swarmia、ベンダー文書)。装置の保守を独立の区分として運用する先例は見つからない
- **内部の先例**: ADR-0059(定義の書けない比率を検知条件から外し、課さないと明記)、ADR-0073 決定1(分類は申告で決まり、閾値は分類で外せる)、ADR-0072(文書の量)。パスで数える案(1-C)はラベルの自己申告を避けるが、「修理」と「追加」「削除」を分けられず、測るものが名前と一致しない

選ばなかった案。

- 1-A 現状維持: 未決のまま残る
- 1-C パスで機械判定: 上記。第4章「独自の指標名を、業界の標準指標であるかのように用いてはなりません」の観点でも、「修理の割合」と名乗って「装置のパスの変更の割合」を測ることになる
- 1-D ラベル: ADR-0073 決定1 の理由がそのまま当たる
- 1-E 正式指標にせず四半期の入力に出す: 判断基準の無い一覧は、運用メトリクス「参考として測るだけで、判断には使わない運用は成立しない」(`MT:44`)に当たる。ADR-0072 決定5 の期限超過の一覧(`IC` 手順6)が許されたのは、項目ごとに「継続・置き換え・廃止」の判断が決まっていたからで、PR の一覧には項目ごとの判断が無い
- 1-F 時間の割合(toil 型): 自己申告の調査で、手続3(自動集計)を満たさない。toil の定義は自動化できる手作業で、装置の保守は toil に入らない(SRE 本 第5章、原典)
- 1-G 計画外作業の比率(DORA 型): 単位をデプロイから PR へ移すと別の量になり、外部の定義を借りた名を付けられない。「計画外」の判定にも分類が要る

根拠水準: **E1**(外部定義と 2 案件の再計測。課さない効果の測定は無い)。EV-0123 と同じ見直し時期(2027-10)に合わせ、差し替え条件: 装置の範囲と PR の帰属の規則を固定した測定で、2 案件以上の値が再現し、かつ値の変化が是正の起動の記録で拾えなかった停止・工数の増大と対応した記録。

### E-6 「ルール化の進み」と、本文の足す向きの規定

**判定: 採る。** 「ルール化の進み」を正式指標の表から外し、「採用しない指標」に理由を書く。あわせて本文の足す向きの 3 か所を改める。

文の案。

- 第6章「採用しない指標」:「| 人の指摘から CI の検査へ移した件数(旧「ルール化の進み」) | 自動集計の実装が無く(手続3)、対になる指標を指定できない(手続2)。検査の増加を健全さとみなす前提は、検査を外すことを対策に含める規定(第4章 G-5「是正の起動」)と向きが逆である | 是正の起動の記録、月次の CI ゲートの見直しの記録 |」
- 第4章 G-5(`GC:320`):「このゲートの原則は「**合意済みのルールのうち、機械化の条件(後掲「是正の起動」の3つ)を満たすものを機械化して載せる**」です。」(「すべて」を削る)
- 第5章 CI ゲート(`ci-gates.md:240`):「CI ゲートは一度作って終わりではなく、独立レビューの指摘と是正の記録を入力に、**検査を足す・直す・外すことで見直します**。」図の「以後、人はその観点を見なくてよい」は、機械化の 3 条件を満たした場合に限る旨を添える
- 改善サイクル(`IC:26`):内側ループを「運用パラメータの調整(判定期限の見直し、委譲の追加、**CI の検査の追加と削除**)」へ。削除は緩める向きとして技術判断者の記名と理由を要すると括弧で限る。外側ループの「ゲートの追加・削除」は判定の場(ゲート)を指すと明記する(調査 1.6 #8 の空白を閉じる)
- `ci-gates.md:250` の `rule-candidate` は、本文に残し、実装マーク `state=undelivered` を付ける(#222 の方針。降りていない規定を消さない)。テンプレートの観点表がラベルに触れていない点は、実装の Issue で扱う

理由。

- **本標準自身の手続に反する**: 手続3「自動集計の実装をもって採用とする。実装前の指標を暫定として運用しない」。データ源(`ci:` 種別、レビュー指摘由来ラベル)はテンプレートに無く、値は常に 0 で警戒サインが常時点く(#289 の会議体が確認)。規格は自らの手続を自らに適用しなければ、採用者の内部監査で同じ不整合を咎められない
- **廃止の規則との関係**: 「廃止の判断は、値が良好であることを理由にしない」(`MT:61`)に当たらない。理由は手続の不充足と向きの矛盾で、値ではない
- **向きの矛盾**: ADR-0056 決定10・ADR-0073 決定3 は「外す」を後から加えた。片側の警戒サインは、それ以前の「ゲートは成長させる」前提の残りである。両側にする案(2-B)は差し戻し率・手戻り率の先例に揃うが、データ源が無いまま両側を置いても点灯の判断ができない
- **G-5「すべて」の誤り**: 「すべて機械化」と、同じ節の「機械の検査で失敗させる形にするのは 3 条件を満たす場合に限る」(ADR-0073 決定2)は両立しない。Google の静的解析の昇格条件(偽陽性ゼロ・対処可能・既存の違反の解消。CACM 2018、原典)と同じ条件を ADR-0073 が採っており、新しい側が正しい

選ばなかった案。

- 2-A 現状維持: 手続3 違反と常時点灯が残る
- 2-B 両側にする: データ源が無く、両側とも判断に使えない。「増え続ける」の窓と基準が E0
- 2-C 純増に改める: 「検査」の単位の定義が要り、E-1 で数えないとした量を別の名で数えることになる
- 2-E データ源を実装して残す: ラベルの自己申告(ADR-0073 決定1)。片側の問題が残る
- 2-F 実装マーク `undelivered` を付けて表示: 指標については手続3「実装前の指標を暫定として運用しない」と両立しない。降りていない「正式指標」は手続上ありえない。ラベル(`ci-gates.md:250`)は指標ではなく収集の手段なので `undelivered` で残す。両者を分けて扱う

根拠水準: 廃止は本標準の手続の適用で、外部の根拠を要しない(マーク不要)。G-5 の改訂は ADR-0073 決定2 の EV に従う。

### E-8 「1 PR ≈ 1 follow-up」の観測

**判定: 「PR あたりの後続 Issue 数」は課さないと明記する。流入と完了の差(バックログの純増)は先送り。**

文の案(第6章「採用しない指標」):「| PR あたりの後続の Issue の数 | 後続の起票には、見つけた不適合や負債を記録する行為が含まれる。減らす圧力は記録の抑制に向く | 負債残高トレンド、完了スループット |」

理由: ISO 9001 10.2 は不適合を記録させる側の規格で、起票の多さを悪と読む枠組みは規格に無い。量を下げる圧力が記録を消す点は ADR-0072 と同じ。

先送りの材料: バックログの純増(期間内の起票数 − 完了数)は GitHub の API で自動集計でき(手続3)、完了スループットの対の指標(手続2)になりうる。ただし正式指標の範囲と上限が #296 で決まっていない。**変更量ではなく、上限の規則の下で何を外して入れるかの判断材料が無い**ことが先送りの理由である。#296 の会議体へ候補として送る。

選ばなかった案: 4-A 現状維持(未決のまま)。4-D PR から生まれた Issue を参照で辿る(GitHub に正式な関係が無く、参照の書き方に依る。調査 290-2 5 章)。4-E 負債台帳に寄せる(台帳に載らない後続は見えないが、それを見る理由が判断基準として書けない。代わりに見るものとして採用しない指標の行に挙げた)。4-F 四半期の入力(E-5 の 1-E と同じ理由)。

根拠水準: **E1**(ADR-0072 と同じ論法)。EV-0123 の対象に含めて見直す。

### E-9 escape clause をどの意味で採否するか

**判定: 採る(1C)。** 新 ADR に 3 つの意味を分けて記録する。

- (a) 要求文の逃げ道の句(INCOSE GtWR R8「Avoid escape clauses」、29148:2011 5.2.7 / JIS X 0166 の「抜け穴」): ADR-0062 で採用済み。附属書B のチェックリストは G-2 を引く。#269 の突合(10-08)の「附属書B に記述が無い」は ADR-0062(10-13)以前の状態の記述である
- (b) チェックリストの当てはまらない項目を外す規定: E-12 で課さないと明記する
- (c) 基準が言い訳に転用されるパターンを基準の側に書く: E-11 で、標準の起草者の手順に限って採る

理由: 規格の用語として「escape clause」は (a) を指す(INCOSE R8、原典 E1)。#290 本文の (b) の読みは転記で生じたもので、起票の経緯に根拠が無い。語の混用を記録しないと、受入条件が (b) のまま読まれ、同じ取り違えが再発する。

選ばなかった案: 1A (a) だけで閉じる(#269・#275 の起票の文言 (c) に答えない)。1B (c) だけ(#290 の受入条件の文言 (b) と規格の用語 (a) が残る)。1D (b) として扱う(起票にも規格にも根拠が無い)。

### E-10 (a) の残る隙間

**判定: 採る。** 3 件を本 Issue で直し、標準自身の起草規則を置く。機械の検査は足さない。

理由。

- **ISO/IEC Directives Part 2 5.5**(現行版、取得 2026-10-23、要約経由)は、規格自身の要求事項に「客観的に検証可能」を課し、主観的な句を「shall not be used」とする。規格策定機関の立場に立つ本標準が、採用者の受入基準にだけ (a) を課し、自らの規定文に課さないのは、IPA・JIS の起草の型から外れる
- **委任は明示する**: ISO 9001 4.4.2 の「To the extent necessary」は逃げ道の句に見えるが、組織が決めることを規格が意図して委ねた要求で、決めた結果は組織の文書化した情報に現れる。本標準でこれに当たるのは「許容」(1.7.3)と「組織が定める」である。軸A の「必要に応じて」は、委任なのか規定なのかが読めない
- **機械の検査を足さない理由**: 辞書による逃げ道の句の検出の適合率は 0.70〜0.81(Femmer ら 2017、survey-308 で原典確認)で、ADR-0073 決定2 の機械化の条件(実効的な偽陽性が無い)を満たさない。説明の文と規範の文を機械は分けられない(1.7.4)。ISO の起草規則も、中央事務局の編集者と委員会の査読で運用され、機械判定に依らない。本標準では会議体の突合(E-11)が担う

- 2A・2F 附属書B を現状維持 / 課さないと明記: 附属書B 自体については採る(G-2 を引くまま)。ただし隙間 3 件と起草規則は附属書B の外の問題で、これだけでは閉じない
- 2B 附属書B に説明と書き換えの例を足す: 例が G-2 と食い違う余地を作る。テンプレ1 の注記が同じ型の直し残しを既に生んでいる
- 2C 正本を附属書B へ移す: ADR-0062 決定2 の置き換えになる。覆す材料が無い
- 2D (a) を採用者の受入基準の外(層1・D-0・テンプレ10)へ広げる: 個別の禁止(`lifecycle.md:358`・テンプレ10・インシデント対応)が既に置かれている。一般化すると機械の検査範囲の拡大を伴いうり、ADR-0062 決定3 が範囲を絞った理由(誤検出)と当たる。広げる必要を示す事例が調査に無い

根拠水準: 起草規則は **E1**(規格策定の規則。効果の測定は無い)。マークは不要と考える(標準自身の起草の規律で、採用者の挙動を制約しない)。ほかの委員が要と判断するなら E1 で付ける。

### E-11 (c) を横断の要求にするか

**判定: 採る(3C、標準の起草者に限る)。採用者には課さないと明記する。**

文の案。

- `community/provision-forms.md`(起草規則):「条項を新設・改廃する会議体は、突合の段で「この基準が、何を理由に緩める読み替えを受けうるか」を問う。見つけた読み替えは、条項の中に禁止の形(〜を理由に、〜してはならない)で書く。標準の主張が転用される経路は、附属書H H.11「残るリスク」の表に足す。」
- 新 ADR:「本標準は、採用者が書く基準(受入基準・層1 の受容の基準・テーラリングの宣言)に、転用されうる読み替えの列挙を求めません。」
- 附属書B 前文(1 文):「事業ステージの判断を未完成の理由に読み替えることは、[第8章 軸B](...)「本軸は、未達の表示を動かしません」が扱います。」(#269 の事象の所在を示す)

理由。

- **外部に採用者向けの先例が無い**: 基準の書き手に転用のパターンを列挙させる規格・指針は見つからない(FND-0113、調査 290-3 2.4、E1)。法の一般的な濫用防止規定(英国 GAAR、EU DMA 13 条 4 項)は名宛人の行為の禁止で、書き手の義務ではない
- **一般規定(3G)は本標準の判定の型と当たる**: GAAR 型は判定者が「規定の目的に照らして」判断するため、判定の基準が事後に動く。ADR-0036 決定4(当該ゲートの判定基準のみで判定する)と 5.7.4(実質を機械で判定しない)の下で、判定の再現性を保てない
- **起草者に掛けることには実体がある**: c1〜c22 の個別の歯止めは、どれも会議体が条項ごとに転用を見つけて書いたものである。手順の明文化は、既に働いている規律を書き出すことで、CLAUDE.md の「突合」の段を具体化する。#275 原則5 の宛先は標準そのものであり、起草者に掛けるのが文言にも合う
- **書かれた禁止は AI に守られにくい(FND-0094、E3)**: 採用者の基準に禁止節を足させる案(3E・3F)は、効く経路が判定者の突き合わせしか無く、5.7.4 の下では形式の記入(FND-0097)を招く。起草者の規律は、禁止を条項に書いた後、判定の場で人が照らす経路を持つ

選ばなかった案。

- 3A 現状維持: #275 原則5 が未決のまま。次の条項で転用を考えたかを誰も確かめない
- 3B 課さないと明記(全面): 起草の場で既に行っていることを書かない理由が無い
- 3D 附属書B に受入基準の転用の型を足す: #269 の事象は受入基準ではなく事業ステージの判断で、場所がずれる。推奨・記録なしで効果を測れない(EV-0095 と同じ状態が増える)
- 3E 判定基準・軸の書き方に禁止の併記を要求(採用者向け本文): 第4章「判定基準の表の行は増やさない」と緊張し、外部の先例が無い
- 3F 反例の欄を採用者の様式に設ける: テンプレ12 の「含意」は義務でない(ADR-0071 決定1)。義務の欄にすると「なし」と書かれる欄になる
- 3G 一般的な濫用防止規定: 上記

根拠水準: **E1**(隣接領域の起草実務と、本標準の既存の運用)。起草規則なので暫定マークは不要と考える。採用者に課さない判断には `:::caution[暫定 EV-NNNN / 見直し 2027-10]` を付ける。差し替え条件: 採用者の基準が転用された事例(出荷判定・内部監査の所見)が、個別の歯止めの無い条項で 2 件以上記録された場合。

### E-12 (b) 当てはまらない項目を外す規定

**判定: 課さないと明記する(4B)。**

文の案(附属書B チェックリストの直前):「このチェックリストに「該当なし」の欄を設けません。外してよい項目は、第8章の規則と、事実の記録(G-5 の「対象なし」、除外の印)に限ります。」

理由。

- **外部の型は本標準に既にある**: ISO 9001 4.3(外すなら正当化を書き、外しても適合を損なわないこと。二次資料)は第8章 要求事項2・3 と同じ構成である。航空部品業界の自己監査(ASA 2015、原典)は N/A を品質マニュアルで事前に宣言した除外に限り、外せない升を灰色にする。記入者がその場で N/A を付ける型は、監査で「印だけの記入」として不備に挙がる(CPA BC、原典)
- **内部の決定**: ADR-0028(省略は規則の結果)、ADR-0036 決定3(条件付き通過は素通しの正規経路になる)、ADR-0071 の却下(案件が範囲を宣言する欄)。覆す材料は調査に無い
- 附属書B 手順3(Unwanted を最低 1 本)が当てはまらない機能が実在するかは確かめられていない。実在が示されたら、ASA 型(4E、標準が外せる条件を事前に決める)で扱う

選ばなかった案: 4A 現状維持(却下が記録に残らない)。4C 事実の記録の N/A を附属書B に置く(外す主体が作成者になり、判定者が事実を確かめる手段が無い)。4D 理由つきの N/A を一般に許す(ADR-0028・0036・0071 と衝突)。4E 事前の宣言で閉じる(外せる条件を決める材料が無い。実在が示されたときの道として残す)。

根拠水準: **E1**。マークは付けない(既存の ADR の帰結を書くだけで、新しい値や前提を置かない)。

### E-13 調査が見つけた範囲外の誤り

**(1) 第8章 軸B と ADR-0050 の「第3章 3.9」: 本 Issue で直す。**

- 誤りの側: 第8章(`TG:476`・`:482`)と ADR-0050(`:85`)。ADR-0050 を足した版(`e8c126e`)で既に 3.9 は「会議体の運用規律」、3.11 が「AI基盤に関するロール」だった。採番の移動ではなく、当初からの誤記である
- 本 Issue で直す理由: `:482` は「規則を強制層から外す(第3章 3.9 の判断による)」で、外す判断の所在を引く文である。E-2 で外す席を決めるのに、所在を誤って引く文を残せない
- 直し方: 第8章の 2 か所を「第3章 3.11.3」へ。`:482` は「第3章 3.11 と、[第4章 G-5](...) の CI の検査を外す判断(技術判断者)による」とし、E-2 の席を引く。ADR-0050 は本文を書き換えない。新 ADR に「ADR-0050 の『第3章 3.9』は 3.11.3 の誤記であり、決定の内容は変わらない」と正誤を記録し、ADR-0050 の状態の行に正誤の所在を添える(#289 D-6 で状態の行は書き換えてよいと決めた)。規格の正誤票(JIS の正誤票、ISO の Technical Corrigendum)が本文を改訂せずに誤記を正す型と同じである
- 再発の防止: `npm run lint:refs` が ADR の本文の節番号を検査しているかを反映の担当が確かめる。検査しているのに通ったなら、節の見出しと内容の対応(番号の実在だけでなく)を確かめていないことになる

**(2) ADR-0016・0019・0021・0024 ほかの「判定の総数を増やさない原則(ADR-0013)」: 別 Issue。**

- 事実: ADR-0013 決定2 は「導入を差し引きで提案する」(組織への導入時の差し引き)で、「判定の総数」の語は無い。ADR-0016:50・0019:48 が「原則」として引き、0021・0024・0041・0051 が連鎖して引く
- 誤りの側: 引く側の ADR が、導入時の差し引きを標準の設計原則へ広げて帰属させた。ただし 6 本の ADR がこの原則で案を退けており、**原則は事実上働いている**。「引く側が誤り」と記録するだけでは、6 本の却下の理由が根拠の所在を失う
- 別 Issue にする理由: 決めるべきは、「判定の総数を増やさない」を標準の設計原則として独立に立てるか(立てるなら新 ADR に書き、6 本の引用をそれへ繋ぐ)、立てないか(立てないなら 6 本の却下の理由を見直す)である。設計原則の新設は本 Issue の受入条件(装置の総量・escape clause)の外で、調査・議論・突合を要する。E-1 の 1-G を退けた理由もここにある
- 別 Issue へ送る材料: 引用の一覧(調査 290-1 1.1 e)、ADR-0013 決定2 の本文、本意見書の E-1 1-G

## 4. 他の委員に問いたいこと

1. **起草・擁護へ**: E-2 で CI の検査の追加と削除を技術判断者に置く案は、3.11.5 の「削除の権限を AI維持管理者 1 名へ集約する」と、強制層の範囲で重なる。重なりを「CI の検査は技術判断者、指示資産は AI維持管理者、強制層の変更の承認は AI維持管理者」と切る案で、1〜2 名体制の兼務の負荷は許容できるか。AI維持管理者に寄せる案(2-B)を推すなら、3.11.2「決定しない事項 … 技術設計の採否」をどう読み替えるか
2. **現場へ**: E-1 で量の上限を置かず、外す契機を是正の起動(個々の不具合)に置いた。#267 の「打ち手を守る打ち手を呼ぶ」連鎖は、個々には Sev1・Sev2・欠陥注入の見逃し・統制の弱化のどれにも当たらない形で進んだか。当たらないなら、起点に「検査装置が止めてはならないものを止めた」(誤停止)を単独で含めることで足りるか(ADR-0073 決定3 は既に含めていると読むが、現場でそう読まれているか)
3. **品質保証と監査へ**: E-4 の「外した後にその場面を止める手段を書く」記録は、内部監査で突合できるか。外した理由に論証の主張(附属書H H.3)を名指しさせるべきか。名指しは自己申告で寄せて書けるが、監査の側から見て突合の手がかりになるか
4. **全員へ**: E-6 で G-5 の「すべて機械化」を改めることは、ADR-0073 決定2 の帰結として新 ADR に書けば足りるか。G-5 の原則の文は ADR-0073 以前の決定(どの ADR か本意見書では確かめていない)に由来するなら、その ADR の一部置き換えとして状態の行を改める必要がある
