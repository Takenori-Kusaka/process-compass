# 議長の裁定(#435 集約が G-6 の範囲(コア機能)を読まず、S0 の省略の前提3 と S1 の G-6 の範囲が本文で食い違う)

- 審議の重さ: **軽**。2委員(起案・反対)とも (c2) を推し、新しい義務を課さない
- 入力: `survey-435.md`(実行での確認を含む)、`council-01-drafter.md`、`council-02-opponent.md`

## 0. 事実

集約は G-6 の範囲(params.scope)を読まず、S1・コア機能の構成でもコア機能でない変更を欠落に数える(実行で確認)。一方、保証の開示の項目2 は「範囲の限定(コア機能)」と出す。開示が、集約の掛けていない緩和を宣言している。

## 裁定

1. **(c2) を採る**(2委員)
   - 集約は、S1 の期間の変更について G-6 の範囲(コア機能)を読む
   - S0 の期間の変更は、前提3(tailoring-guide.md:511、ADR-0065)の字句どおり全変更で数える
   - 期間は、変更の親のコミットの構成のステージで分ける(先例 aggregate-evidence.mjs:2592)
   - ADR-0065・ADR-0112 は書き換えない。この扱いは、採用済みの ADR-0112 の「S1 の G-6 はコア機能」を集約へ降ろすもので、新しい緩和ではない
2. **歯止め**(反対の委員の4つの条件を採る)
   - パスを宣言していない構成は、全変更を欠落に数え、理由を添える
   - コア機能の判定は、親の版と HEAD の版のパスの和で行う
   - 移行の後の最初の出荷は、全変更で数える
   - PR を経ないコミットは、範囲を限らない(全変更で数える)
3. **コア機能の判定の材料**は、corePathsOf(tailoring-guide.md:584 の protectedPaths と riskFloor のパスの和)に揃える(2委員)。:181 の「protectedPaths だけ」との二重の定義は欠陥と認めるが、本件では本文を揃えない(本文の定義を改めると、他の規定の読みに及ぶ)。既存の #326 へ論点として足す
4. **ブランチ保護の承認数**(generate-profile.mjs:1054 は全 PR に掛かる)は変えず、集約との差を開示する(2委員)。承認数を範囲で変えることは新しい義務になり、採らない
5. **実装の印**: tailoring-guide.md:490、gate-criteria.md:1289・:1406 に IMPL を付ける。歯止めの4点を試験で固定するまでは undelivered とし、固定したら delivered にする(反対)
6. **保証の開示の項目2**は、集約の数え方と一致する文にすぐ直す。集約が範囲を読むまでの間に開示が緩和を宣言しないようにする(反対)
7. ADR は新設しない(採用済みの ADR-0112 の集約への降ろしと、開示の訂正)

## 採らない案

| 案 | 理由 |
| --- | --- |
| (b) 本文を全変更に寄せる | S1 の採用者に新しい義務を課し、ADR-0112 決定1 を改める。重へ上げる要がある |
| (c1) 前提3 を「範囲に当たる変更」と読み直す | 新しい ADR で読み方を定める要があり、S0 の省略の前提を緩める |
| (c3) 開示で差を残す | 開示が実際の数え方と食い違ったまま残る |
| :181 の定義を本件で揃える | 他の規定の読みに及ぶ。#326 で扱う |
| ブランチ保護の承認数を範囲で変える | 新しい義務 |
