  - S1 の期間の PR の変更で、コア機能に当たらないものを G-6 の範囲の外(`outOfScope`)とする
  - 期間は、変更の親のコミット(マージコミットの第1親 `^1`)の構成の事業ステージで分ける(先例 `stageOf(before)`)

- 範囲を限らず全変更を数える場合(裁定2 の歯止め)
  1. コア機能のパスが、変更の親の版か HEAD の版の構成で未宣言 → 欠落の文に「コア機能のパス…が<版>の構成で未宣言のため、範囲を限らずに数えた」を添える

  4. PR を経ないコミット → `g6ScopeOf` を使わない。従来どおり範囲を限らない
  - 変更の親の版の構成が S0 の変更(前提3)も、理由を添えて全変更で数える
  - 親の版の構成が S1・core-only でない場合(S2 から戻した直後、CL1 の期間など)も全変更で数える
- 範囲の外の変更の扱いは、G-6 を適用しない体制と同じ(`exceptionNeeded` の第4引数)。R1 の変更は例外承認を要する。承認レビューの写しの欠落(G-6 条件5)にも数えない

## 4. 作業上の選択(裁定の範囲の中)

1. **歯止め1 は、変更の親の版と HEAD の版の両方で宣言を要する**。パスの和が空でない(片方だけ宣言)場合も、宣言の無い版があれば全変更を数える。親の版に宣言が無いのは、変更の時点でコアと非コアの区分が無かったことであり、HEAD の宣言で後から範囲の外へ出すと、(c1) を落とした理由(後から付けた区分で過去の未確認を外す)と同じ抜け道になる。HEAD に宣言が無いのは、裁定の「パスを宣言していない構成」に当たる
2. **歯止め3 の「移行の後の最初の出荷」は、出荷の範囲に親の版の構成が S0 のコミットを含むことで判定する**。移行のコミット(親の版が S0)を含む範囲が最初の出荷である。前回の出荷のタグが移行のコミットそのものに付いた場合、その出荷が最初の出荷で、次の範囲は2回目として扱う。期間の指定(`--period-from`)でも、範囲のコミットで同じに判定する
3. **項目1 の G-6 の要約の文を直した**。直さないと「事後へ移した変更と例外承認のある変更を除き、欠落として扱う」が、範囲の外の変更を欠落に数えない集約と食い違う(裁定6 の趣旨)。範囲の外の件数を括弧に入れた
4. **監査対応書式(規制業)と独立した安全性の評価の判定記録の要求は、範囲で狭めていない**。裁定は欠落の計上と開示だけを扱い、規制業の記録の要求の範囲は扱っていない。厳しい側に残した
5. **承認者の数(`reviewersRequired`、コア機能2名)の計上は変えていない**。範囲の外の PR は欠落に数えないだけで、承認の数え方そのものは同じ
