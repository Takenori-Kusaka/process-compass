# 議長の裁定(#429 AI の担い手の認証情報の共有と、名簿の数値の識別子による照合)

入力: 議題 `council-00-agenda.md`、調査 `survey-429-1-internal.md`・`survey-429-2-external.md`、意見 `council-01-drafter.md`(起案)・`council-02-field.md`(現場)・`council-03-qa-audit.md`(品質監査)・`council-04-standards.md`(規格)・`council-05-defender.md`(弁護)。

## 0. 骨格

5 委員とも、共有の構成を**禁止しない**、**黙らない**、で一致した。弁護の委員も 3 つの欠陥を認めた(1.10.2 の「席ごとに認証情報を分けている」を席の中の共有のまま字面で満たせる、G-6 で担い手が人のアカウントで出した承認を人の承認として数える、第4章 :84 の数値の識別子に実装もマークも無い)。

品質監査の委員の F-0 を裁定の前提に置く。「どのアカウントか」(数値の識別子で直る。R-4)と「アカウントの向こうで誰が操作したか」(数値の識別子では直らない。R-1〜R-3・R-5)を混ぜない。崩れるのは承認・記名を出す側の共有であり、作成の側の共有はブランチ保護と作成を指示した者の既定値が安全側に倒す(現場・弁護・品質監査 F-2)。

## R-1 共有の構成への要求の向き — 裁定: 申告を要求事項とし、共有と未申告を列挙に無い離脱とする

- 担い手ごとの**名義**(ホスティングが担い手の操作を誰の操作として記録するか)を、構成の入力として申告させる。値は「専用」「共有(名簿の誰か)」「未申告」。未申告は共有として扱う(5 委員一致)
- 判定は**能力**で行う(起案・現場): 担い手の実行環境から使える認証情報で、名簿の人のアカウントとして承認・レビュー・記録の push を作れる構成を「共有」とする。設定で拒否していても「共有」のまま。現場の「乙(手元だが隔離した環境)・丙(人と同じ環境で bot のトークンも渡す)」の区別は、この能力の定義で受ける(丙は共有)
- **専用の名義を課さない**。課さないと決めた旨と理由を本文に書く(明文の規範が無い、禁止は機械で確かめられず申告に縮む、崩れる統制を統制ごとに扱える)
- 第1章 1.10.2: 既存の行(席どうしの認証情報)とは別の行「AI の担い手の名義を名簿の人と共有する構成、または申告していない構成」を足す(起案・現場・規格・弁護の 4 名)。品質監査の「1.10.2 に入れない」は採らない。行を分けないと、2 名の体制が適合の主張の条件を共有のまま字面で満たせるため
- 置き場: 第3章 3.5.3 に小節「人と AI の担い手の名義」を新設する(起案)

## R-2 崩れる統制の扱い — 裁定: G-6 は数えて開示、効力を持つ記録は名義を共有しない人の帰属の確認を要する

- **G-6 の承認**: 名義を共有する人のアカウントの承認は、条件1〜4 を満たせば数え、件数を保証の開示の項目1 に出す。適合の主張の根拠には数えない(起案・規格・品質監査・弁護の 4 名)。現場の「数えない」は採らない。共有かどうか自体が申告であり、数えない規定は正直に申告した採用者にしか効かない(品質監査)。数えないと本物の確認を捨て、2 名の体制で G-6 を差し戻し続ける(起案)。見直しの条件を EV で置く(担い手が共有のアカウントで承認を作った事象が 1 件でもあれば、数えない側へ改める)
- **専用と申告したアカウントの承認**: 語の一致に依らず、数値の識別子で照合して数えない(起案・現場)
- **効力を持つ記録**: 名義を共有する記名者の操作(レビュー・作成・承認・署名コミット)だけでは帰属に数えない。名義を共有していない人の帰属の確認を要する。その人がいない体制では自己申告として受け付け、記録ごとに開示する(起案)。規格・品質監査の「自己申告として数える」は採らない。ADR-0106 の決定の核(事後の開示ではマージを取り消せない)と、#380 が塞いだ経路(担い手が記名者の名義で例外承認のレビューを出してその場で通す)が再び開くため。G-6 と扱いが割れる理由(開示の時点で害を止める機会と後退経路の有無)を本文と ADR に書く
- **作成を指示した者の既定値・PR の作成者の別**: 変えない。安全側に倒れることを明記する
- **後退経路の記述**: recording.md の「代筆の有無を後から確かめられる」は、共有の下では成り立たないと改める(品質監査 F-3)

## R-3 担い手の識別にアカウントを含めるか — 裁定: 含めない。別の欄に置き、変化点4 に数え、確認を失効させない

5 委員一致。3.4.2 に「権限の組は実行環境の設定を指し、ホスティング上の権限は名義の側で扱う」と明記する。構成 `seats[].performerAccount` と D-0 表7 の列に置く。名義の変更は変化点4 に数え、適合性確認を失効させない。専用から共有への切り替えは緩める向き(規格)。テンプレートの前提の割れ(recording.md と performer.md:39)を直す。

## R-4 名簿の数値の識別子 — 裁定: 要求を維持して全照合へ広げる。移行期間を置かない。「リポジトリの外側」は性質の要求へ改める

- 数値の識別子の要求を維持し、ホスティングの記録を名簿の人へ対応づけるすべての照合へ広げる(5 委員一致)
- 移行は M1(要素に `{login, id}` を許す)+ M4′(数値を記録用ブランチの写しの `user.id` から引いて人が名簿へ入れる)+ M6(食い違いの所見)。M5(ログイン名だけの照合を移行期間に数える)は採らない(現場・規格・品質監査・起案)。弁護の「件数の表示だけ M5」は M6 の所見で受ける
- 「リポジトリの外側で保守する」は、置き場の理由が本文に無く、時点の名簿の対応(IMPL-0094)とも衝突する(弁護・起案)。「名簿の変更を効力を持つ記録として扱う」性質の要求へ改める(帰属の照合は IMPL-0415、#428)
- PR 本文の `@アカウント` は検査の時点に数値へ解決して残す(5 委員)
- 品質監査 F-4(`author_association` を見ない)と F-5(PR の時点の検査が名簿に対応づかない指示者を黙って落とす)は欠陥として直す

## R-5 テンプレートの手段 — 裁定: 権限設定とフックは抑止。分離として数えない

- 主たる手段は名義の分離と、登録した識別子で担い手の承認を数えないこと(規格)。権限設定と常駐の規則は抑止であり、止めたことを記録で示せない、と明記する(5 委員)
- `gh auth token` は deny。書き込みの形の `gh api` は、権限設定の前方一致で表せる形(`-X`・`--method`)を deny、GraphQL は ask、`-f`・`-F`・`--input` による POST は Bash の PreToolUse フックで拒否する(起案・現場・品質監査・弁護。規格・品質監査の「ask」は GraphQL と、前方一致で表せない形を受け持つ層として採る)
- 常駐の規則を、宣言行のレビューから、承認・レビュー・マージ・記録の push のすべてへ広げる(5 委員)。常駐の規則の `gh pr merge` を `ask` と書いた誤り(実装は deny。品質監査 F-9)を直す

## 降ろす順序(裁定)

- 本件(#429)で降ろす: 権限設定の拡大と Bash のフック、常駐の規則、recording.md・performer.md の前提の割れ、F-4(`author_association`)、F-5(指示者の扱いの PR の時点と集約の割れ)
- 後継の Issue(#430)で降ろす: 名簿の `{login, id}` と数値の識別子による照合への切り替え、M4′ の提案、M6 の所見、`seats[].performerAccount` と契約検査、G-6・効力を持つ記録・保証の開示の項目1 での名義の扱い、`/process-init` の問い、env-check の照合、D-0 表5-2・表7 の列。理由: 照合の切り替えは、名簿へ数値を入れる経路(M4′)より先に入れると、既存の採用者の G-6 の承認がすべて同定できない側へ一度に落ち、名簿を直す手段が無いまま記録の欠落が出続ける。切り替えと移行の経路を同じ版で入れるために、一つの単位にまとめる。変更量は理由にしていない。本文の要求事項は本件で置き、降りていない規定(undelivered)として表示する

## 番号(本件で振る)

- ADR-0107(名義の申告と、共有の構成で崩れる統制の扱い)、ADR-0108(名簿の数値の識別子による照合)
- EV-0221(G-6 を数えて開示し効力を持つ記録には数えない決定、共有と未申告を離脱とする決定。E0)、EV-0222(権限設定とフックの抑止の効き目。E0)、EV-0223(名簿の移行を写しの数値で行う前提。E0)
- IMPL は実装の時点で振る

## 採らない案(要約)

- 共有の構成の禁止、専用の名義の義務(明文の規範が無く、確かめられない禁止になる)
- 推奨と開示だけ(推奨は数え方を変えない)
- 1.10.2 の既存の行への読み込み(主語が違う)
- 1〜2 名の体制の申告の免除(共有が最も起きやすい体制で開示が消える)
- 設定で拒否した共有を専用に数える(担い手が書いたプログラムから API を呼ぶ経路が残る)
- 共有のアカウントの G-6 の承認を数えない(上記)
- 効力を持つ記録を自己申告として数える(上記)
- Co-Authored-By・署名・監査ログの `actor_is_agent` を区別の証拠にする(人の名義の操作を区別しない。監査ログは Copilot 限定でプランに依る)
- 担い手の識別(3.4.2)に名義を入れる(名義の変更で適合性確認が失効し、失効が実体と離れる)
- M5 の移行期間、M2・M3 単独
- `gh api` の全面の deny(読み取りの経路を壊す)
