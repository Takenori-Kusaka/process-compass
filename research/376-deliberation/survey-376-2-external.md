# #376 外部調査 2: 任免と統制の緩和を束ねた変更要求の承認要件

- 調査日: 2026-11-05(本文の「確かめた日」は、断りがない限りすべてこの日)
- 問い: 1つの変更要求(change record)に、役割の責任者の任命と、統制を緩める変更(基準値の引き下げ・代償措置の終了)が同時に含まれるとき、承認の要件をどう決めるか
- 状態: **途中稿**。調査の途中で検索基盤(tavily)が応答しなくなり、ISO 系と ITIL 4 の原典・二次資料は読めていない。読めなかったものは「未確認」と書いた。条番号を推測では書いていない
- 凡例: 【確認】= 原典または原典を転載した頁で本文を読んだ / 【二次】= 転載・解説の頁で読んだ / 【未確認】= 読めていない / 【推測】= 筆者の解釈

## 1. 結論の先出し

1. 確認できた範囲の規格(NIST SP 800-53 Rev.5)は、**束ねた変更の承認を「最も厳しい要件に合わせる」「分割を求める」「和を課す」のどれとも明文で定めていない**【確認】。CM-3 は「構成管理の対象となる変更の種類を決めて文書化する」(CM-3 a)ことと、「セキュリティ・プライバシーの影響分析を明示的に考慮して承認・却下する」(CM-3 b)ことを求めるだけである。束ね方の規則は組織の定める事項に委ねられている【推測: 割当て(Assignment)の構造からの解釈】
2. 業界のツールの実務では、**「和(各対象の承認者の全員)」と「最も厳しい版の適用」の両方が実装されている**【確認】
   - Kubernetes の Prow approve プラグイン: 変更が触れた**すべてのファイル**について、その OWNERS の承認者の承認が要る(和)
   - GitHub rulesets: 複数のルールセットが同じブランチに掛かるとき、ルールは集約され、同じルールが異なって定義されていれば**最も厳しい版**が適用される
3. 承認の閾値を避けるための**分割を禁ずる**規定は、公的調達に明文がある(FAR 13.003(c)(2))【確認】。これは「束ね」ではなく「分割」による迂回の禁止であり、本問とは向きが逆である。束ねによる迂回(厳しい承認の要る変更を、緩い承認の変更に混ぜて通す)を名指しで禁ずる規格の条文は、本調査では**見つけていない**【未確認】
4. 職務の分離(NIST AC-5)は「職務を識別・文書化し、アクセス権限を職務の分離を支えるように定義する」ことを求める【確認】。**任命と統制の緩和を同じ承認で行うことを直接扱う文言は無い**【確認: 本文に無い】。OT の議論に「1人が複数の重要な役割を担うことの適否を慎重に検討する」とある【確認】

## 3. 本問への含意(筆者の解釈。すべて【推測】)

- 規格(NIST)は束ねの規則を組織に委ねている。したがって本標準が規則を定めるなら、それは規格の要求の写しではなく、本標準自身の判断になる。根拠水準マーク(ADR-0026)の対象になりうる
- 業界の実装では「各構成要素の承認要件をすべて満たす(和)」が既定の形である(Prow・rulesets の集約)。「最も厳しい版」は同じ種類の規則が重なったときの解決規則であり、異なる種類の要件(任免の承認者と、緩和の承認者)の間では、和として働く【推測】
- 和を課す形では、束ねても承認の要件は下がらないため、束ねによる迂回は構造上起きない。分割を求める形は、FAR のように分割による迂回を別途禁ずる必要が生じうる【推測】
- 任命と緩和を同じ承認で通すと、新たに任命された者が自らに関わる緩和を承認する経路が生じうる。AC-5 の趣旨(権限の濫用の可能性への対処)からは、その経路を塞ぐ根拠を引ける。ただし AC-5 の文言はこの場面を直接扱っていない【推測】
