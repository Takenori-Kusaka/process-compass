## 欠けているもの

### 重大

1. PoC 段階では、初期化が `guard.enabled=false` を書き込む。テストの書き換えを止める遮断(禁止事項3)を含め、フックの保護が全部外れる
2. テストの書き換えを止めるのは `.self-heal` のロック中だけで、そのロックは AI 自身が `/implement` の中で作る
3. 1〜2名の構成はルールセットが無い。3名以上でもブランチ保護の適用は人の手作業に任されており、適用されなければ G-5 はマージを止めない
4. 機械が見ていない規則がある: 変更規模の上限(PR では検査されず、委任の判定にだけ使われる)、`state:*` ラベル、ブランチ名、トレーラ `Spec:`(出荷時の集約でしか見ない)、閾値を機能変更と同じ PR で変える禁止(禁止事項6)
5. 次のコマンドを案内しない。初期化の出力にも各スキルにも案内が無い。D-0 の作成と名簿の記入が要ることも伝えない

### 中

6. CLAUDE.md の常時読み込みを縮める。生成区間は自分のロールの分だけにし、場面限定の内容はスキルへ移す
7. process-change と gate-record を、入口(ルーター)と種別・ゲートごとの補助ファイルに分ける
8. 成果物とゲートごとのスキルを足し、状態から次の一手を出す入口のコマンドを作る
9. セッションの開始時に、現在の状態と次に使うスキルをフックで注入する

### 軽(記述の誤りと食い違い)

- CLAUDE.md は「禁止事項3は settings.json で遮断」と書くが、実際はフックで遮断している
- AGENTS.md は「範囲外は既定で拒否」と書くが、初期状態では deny が空
- spec-lint の禁止語は、CLAUDE.md では6語、スクリプトでは10語
- README とスキルは「5軸」と書くが、実際の設問は8問
- README の「各スキルは構成を読む」は、spec-write に当てはまらない

## 外部調査の知見との対応

- 常時読み込みの量: 42KB は、Claude Code の目安(200行未満。E1、測定の根拠なし)と、Antigravity の1本24,000バイトのいずれも超える
- 段階的な開示: 補助ファイルへの分割が無い。ベンダー仕様が推奨する SKILL.md の500行未満・本文5,000トークン未満(E1)に照らすと、process-change は行数では収まるが、トークンは約3.6倍
- 指示文と機械: 指示書は強制でない文脈であり、フックと権限へ移して守られた事例がある(FND-0040、E2)。現状はこれに反する
- **反証**: ファイルの長さや規則の本数が課題の成功率に有意な影響を与えなかった測定がある(FND-0052・FND-0205、E2)。常時読み込みから外した規則は読まれないことがある(3.5%、FND-0033、E2)。したがって数値の目標は暫定値として根拠水準マークで開示し、外した規則は機械で担保するか、必要な時点で確実に読まれる仕組みと組で外す
