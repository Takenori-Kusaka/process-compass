# #455 会議体 意見書(品質監査)

- 日付: 2026-11-27。立場: 規定が守られたことを証跡で確かめられるか、表示と実態が食い違わないか、統制の弱化・抜け道が無いか
- 読んだもの: `decision-draft.md` 全文、`intake.md`、`template/scripts/gate/dependency-diff.mjs`(30-81 行)、`gate-criteria.md` の ADR-0151 に関わる節(1049-1065 行付近。IMPL-0234・0992・0995)、ADR-0151 本文
- 総評: 案の骨格(未登録は既存の検査、登録済みの悪性は一覧と人の確認、検証の失敗だけ機械)は妥当。ただし**「見えなくなる経路」が3つ**残っている(争点1・4・5)。いずれも条文・機械の検査・開示の追加で閉じられ、案を捨てる必要はない

## 争点1 論点(a): A1 か A2

- **賛否: A2 に賛成。ただし条件つき**
- 理由: 同じ条件の二重の検査は信頼を足さない(draft 1.2)。一方、A2 の前提は「解決が走ること」で、その前提が崩れる構成が標準の中に既にある。ADR-0151 決定1 と `gate-criteria.md:1051` は、依存の導入を「構成で選んだ未実施」とし項目4 の対象外と定めた。IMPL-0234 の note は「空の install と lock ファイルだけの構成」の筋が残ると自認している
- 欠陥(draft に無い): A2 を採ると、ADR-0261 決定1 が「未登録の名前は G-5 で捕まる」と書き、実態は install が空なら捕まらない。**ADR-0044 決定5 と同じ表示と実態の食い違いを、置き換えの ADR で再生産する**
- 条件:
  1. ADR-0261 決定1 に「解決が走る構成に限る」と同じ文の中で書く。限定を別の段落へ置かない(#226)
  2. ADR-0151 を変えて項目4 へ「依存の導入」を足す案は採らない(重で、採用者の新しい差し戻しを生む)。代わりに IMPL-E を、解決が走らない構成(install が空・アダプタ `none`・`undetermined`)では **undelivered と表示し続ける**。降りていない規定は消さずに表示する原則(#222)に沿う
  3. 試験の「レジストリを模した 404」は模擬の応答を確かめるだけで、道具の実際の挙動を確かめない。**実レジストリでの1回の確認の記録(日付・道具の版・出力)を証跡として残し、EV に見直し日を付ける**。道具の版が上がれば前提が崩れうる(IMPL-0234 が「道具の実装で保証しない」と書く型)
- 切り替えの条件(落ちないスタックで A1)は妥当。ただし議長の裁定で足りるとする点には留保する。A1 は新しい義務になるので、軽の扱いで足りるかを裁定の記録に理由つきで残すこと

## 争点2 基準9 の新設と 7.3 の例外

- **賛否: 新設には賛成。ただし対象と名称を直す。例外を認めることに賛成。「偽陽性が出たら一覧へ下げる」の条件つき採用には反対**
- 表示と実態の食い違い(draft に無い):
  - **go は `go mod verify` が来歴・署名を確かめない**。go.sum との一致、つまり最初に見た内容との同一性(TOFU)で、悪性の版を最初から取り込んだ場合は通る。基準9 の題「依存の来歴・署名の検証」に go が当たると読めるのは過大。題を「完全性・来歴の検証」とし、**検証の種類(署名・来歴の証明・ハッシュの一致)を記録に出す**。種類が違うものを同じ「検証済み」に数えない
  - `npm audit signatures` が、署名の無い版(欠落)をどう終了コードに反映するかは、案が実行で確かめていない。欠落で落ちるなら「対象外とし件数を記録」と食い違い、落ちないなら欠落が通る。**実装の段で実行して確かめ、結果を IMPL に書く**
- 空洞化の抜け道: 基準9 は「対象外の件数を記録する」だけで、**検証した件数が 0 でも通る**。`ci.dependencyRegistries` で全部を対象外にでき、python では手段が無い。通過が「検証した」でなく「何も検証しなかった」になりうる。**検証した件数が 0 のときは通過でなく未実施として項目4 に出す**(ADR-0151 の型。構成の選択なので失敗にはしない)。検証した件数・対象外の件数・対象外の理由を、基準9 の記録に必ず持たせる
- 条件つき採用(EV-C)の安定性: 「実行で偽陽性が出たら一覧へ下げる」は、採用者から見て義務が予告なく消える規定になる。**標準に書くのは、降ろし先の状態を2つに分ける形にする**。実行で偽陽性を確かめるまでは基準9 を **IMPL の state=undelivered・check=manual で出して**表示し、確かめてから delivered にする。基準の文は変えない。安定と表示の一致の両方が取れる
- 7.3 の例外: 賛成。ただし**例外で通した基準9 の件数を項目4 に出す**。例外が見えないと、止めたままの迂回が合法の抜け道に変わる。氏名の欄を足さない方針(4節)とは両立する(件数と識別子だけ)

## 争点3 cooldown を課さない判断

- **賛否: 課さない判断に賛成。ただし「何も要らない」と読まれない手当てが足りない**
- 理由: 閾値の根拠が無い(EV-B)。監査の観点では、日数の閾値を課すと、判定者が「閾値を超えたから良い」と確認を省く形骸化が起きやすい
- 欠陥: 一覧に公開日時を出すだけでは、判定者に**何をすれば満たしたかの基準が無い**。確認の記載が「読んだ」の自己申告で終わる
- 代案: 「課さないと決めた」を、採らない案の表だけでなく**条文の同じ節の中**へ書く(書かれていないのでなく課さないと決めたと読める状態を保つ、というコアポリシー)。手引きだけの勧めは、採用者が読まなければ存在しないのと同じなので、手引きの所在を条文から指す

## 争点4 G-6 基準5 の確認の範囲

- **賛否: C2 に賛成。範囲(直接は全件、推移は印のみ)には条件つきで賛成**
- 欠陥(最重要): 推移的な依存の印(初出の名前・公開者の変更・証明の退行)は**照会が成功したときにしか付かない**。照会せず・対象外の行は印が付かないので、推移的な依存の乗っ取りは、**照会が失敗した行で最も見えなくなる**。印の付かない行が「問題なし」に見える
- 条件:
  1. 「照会せず」「対象外」の行は、**印の付いた行として扱い**、確認の対象に含める
  2. 確認の記載の検査を機械で閉じる。**印の付いた項目の識別子(名前@版)が確認の記載に全て現れること**は、存在の一致で決定可能。「読んだ」の自己申告を、少なくとも全件への言及に変えられる。意味の判定(意図した部品か)は manual のまま EV-D で開示する
  3. 確認の記載が指す一覧は、**どの実行(コミット・ジョブ)のものか**を記載に含める。ジョブの要約は保持期間があり、後から辿れないと証跡にならない。`evidence/dependency-diff.json` の保持の扱いを条文の証跡の欄に明記する
- 「意図した部品か」の形骸化: 防げない。実証が無い(EV-D)と開示するのが限界。形骸化の兆候(確認の記載が全 PR で同一の定型文)を内部監査の観点で読めるようにする案は、新しい観点を立てず、既存の観点16 の確かめ方への1文で足りるかを会議体で検討してほしい

## 争点5 照会の不達の扱い

- **賛否: 一覧は不達でも通す点は賛成。「通すだけ」の現案には反対(統制の弱化に当たる)**
- 理由: 合否に使わない欄を不達で止めると、開発が止まる割に信頼が増えない。通すこと自体は妥当。問題は、**不達が続いても誰にも見えない**こと。照会先を既定で公開レジストリにする設計では、sandbox のネットワーク制限(F-6)・鍵や接続の設定ミスで、全行が恒常的に「照会せず」になりうる。そのとき来歴の統制は存在しないのに、一覧は出ており、見かけ上は動いている
- 非対称の欠陥: 基準9 は未判定で落ちるが、一覧は通る。採用者は不達の再実行を避けるために、**基準9 の対象外を広げる**方向へ誘導される(争点2 の空洞化と同じ経路)
- 条件:
  1. 一覧の先頭に「照会せず N 件 / 全 M 件」を必ず出す(欄ごとでなく一覧の見出しで)
  2. 保証の開示の項目4 に、来歴の欄の状態(実施・一部照会せず・照会せず)を出す(draft 5.1 の `g5-aggregate` に既にある。**条文に書く**)
  3. 全行が照会せずの状態の継続期間を、ADR-0151 の型で出す(継続期間の閾値は課さない)
  4. G-6 の判定者が「照会せず」の行を見たときの動作を、G-6.md に1文で書く。**再実行して解く、または印付きとして確認の対象に含める**。無視してよいと読ませない

## draft に無いその他の欠陥

- **F-3 の裁定**(条文を実装に合わせる): 方向は賛成。ただし「PR から辿れる記録」が何を指し、保持期間はどれかを条文に書かないと、後から確認の記載が指す先が消える。争点4 の条件3 と合わせて直す
- **F-4 の省略の件数**: 賛成。さらに `slice(0, 200)` は解析の前に切っているので、**解析と基準9 の入力を切った後の行にしない**ことを試験で確かめる(draft 4.1 の「検査を切らない」を試験の項目に落とす)。表示の40行と保存の200行の2段の切り捨てをどちらも出す
- **3.3 の残余**: 「CI の install で走る分は残余として開示する」とあるが、**開示の場所が無い**。保証の開示の限界の項か ADR-0261 決定6 に、場所を指定して書く。書かれなければ「書かれていない」と「課さないと決めた」の区別が崩れる
- **IMPL-E を delivered にする条件**: 「実行で確かめた後」だけでは時点の記録にならない。確かめた日付と道具の版を IMPL の note に書く(IMPL-0455 の型)

## 採らない案の表への異論

- 「基準9 を例外を認めない基準にする」: 採らないに賛成。理由に**例外件数を項目4 に出すこと**を足す(争点2)
- 「重要な依存だけ証明を必須にする」: 採らないに賛成。理由の「自己申告になる」は、基準9 の対象外の構成にも同じ弱点がある。対象外も自己申告であり、件数の開示で釣り合わせる
- 「A1(実在を独立の基準にする)」: 「課さないと決めた(条件つき)」の区分は、**未確認の前提に依るので「保留」に近い**。区分の欄に「F-2 の実行で確定」と書き、確定までは区分を確定と見せない
- 表に**足すべき案**: 「基準9 の通過を、検証した件数 0 でも通過に数える」を採らない案として明記する(上の空洞化)。「一覧の不達を通すだけで開示しない」を採らない案として明記する(争点5)
