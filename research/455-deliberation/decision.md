## 2. 採らない案(案 §6 に加える分)

| 案 | 区分 | 理由 |

| 基準9(検証の失敗 0 件)を本改訂で G-5 の合否にする | **本改訂では課さないと決めた**(EV-C の見直しで再審議) | R-2 |
| 実在を独立の基準にする(A1) | **現時点で採らない**(条件つき。落ちない構成が実行で見つかればそのスタックで採る)。「課さないと決めた」とは分類しない | 弁護の指摘 |
| ADR-0151 を変えて依存の導入の未実施を保証の開示 項目4 に出す | **採らない** | ADR-0151 の理由を覆す材料が無い。一覧の状態行で開示する(R-1) |
| CI で install スクリプトの抑止(`--ignore-scripts` 等)を必須にする | **課さないと決めた** | ネイティブの構築を要する依存で正規の構成を壊す。手元と CI の露出は 5.8.6(#452)の領分。雛形は手引きとして置く(R-5) |

## 3. 統制の閉じ方

| 統制 | 閉じ方 |
| --- | --- |
| 未登録の名前が install で落ちる | 機械(既存。IMPL-E で実行して確かめる) |
| 一覧が出ていること・欄の存在・省略の件数・状態行 | 機械(試験) |
| 一覧の欄の値(公開日時・初出・公開者・証明・検証の結果) | 一覧に出して G-6 の確認事項にする型。合否は判定しない |
| 意図した部品であること | manual(G-6)。EV-D |
| 検証の失敗を合否にすること | 課さない(本改訂)。EV-C |
| cooldown | 課さない。EV-B |
| 手元・CI の install の露出 | 本件で閉じない(5.8.6、IMPL-0200)と明記 |

## 4. 根拠水準マークと実装マーク

- EV は案 §5.3 の4本(A〜D)。EV-C の文を「検証の失敗を機械の合否にしない根拠: 私設レジストリ・ミラー・鍵の更新の時期での偽陽性が実行で未確認」に改める
- IMPL は案 §5.2 から、IMPL-B を「検証の結果の欄と失敗の印(node)」に、IMPL-C を「python・go の解析・照会・検証(undelivered)」に改める。番号は push の直前に付け直す

## 5. 所有者の方針への答え

- (1) 条文は欄・観点・状態の表示までで、道具の名前は手引きへ(案 §3.1)
- (2) 新しい行は足さない。基準8 の一覧の欄と G-6 基準5 の観点の拡張で受ける(本裁定で基準9 も置かないので、案 §3.2 より新設が1行減った)。第7章だけでは受けられない(F-7)
- (3) 失う者は案 §3.3。守るのは出荷される製品の利用者で、手元と CI の露出は本件で閉じないと書く
- 記名・氏名・日付の欄を足さない(案 §4)
