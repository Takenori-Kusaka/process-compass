## 所見

### 高-N1 直しが書いた保証の文「CI が書いた配布の履歴の上」は実態より広い(表示と実態の食い違い)

- 所在: `standard-editions.md` の「確かめられるのは、…`dist/standard` のコミットなら CI が書いた配布の履歴の上にあること」、表の1行目の括弧「(`D` が CI の書いた配布の履歴の上にある)」、条件1 の `D` の確認の目的の箇条、EV-0301 の対象「知識ベースの差し替えを検出できること」。`fix-round1.md` の採らなかった案の理由「D が CI の書いた履歴の上にあれば kb も CI の生成物」
- 事実: `merge-base --is-ancestor` が示すのは、`D` が `dist/standard` の履歴の上にあることだけである。だれが書いたかは示さない。`dist/standard` の更新はルールセットで限っていない(ADR-0090 の保守者の決定、project-management.md L113「書き込みの権限を持つ者は、`dist/standard` へ早送りの push ができる」)。N1 で4つの確認をすべて通った。手引きの限界の箇条は「保守者の権限で**既定ブランチ**へ書かれた変更」だけを挙げる。`dist/standard` への直接の書き込みは挙げていない。fix-round1 は「保守者が dist/standard へ直接書く場合は従来どおり検出しない(開示済み)」とするが、開示は手引きの中に無い
- 重大度の理由: 手引きが保証の範囲を実態より広く述べる。1巡目の高-1 と同じ型である。巡の数に関わらず直す対象
- 直し方の案(文言だけで閉じる。手順は変えない):
  1. 「CI が書いた配布の履歴の上」を「`dist/standard` の履歴の上」に改める(表の括弧と「確かめられるのは」の箇条の2か所)
  2. 限界の箇条に1行を足す。「書き込みの権限を持つ者が `dist/standard` へ早送りで積んだコミットは検出しない(`dist/standard` の更新はルールセットで限っていない。[プロジェクト運営](/process-compass/community/project-management/)。`VERSION.md` の実行の番号と Actions の実行の記録との突き合わせは ADR-0090 決定8 の候補のまま)」
  3. 条件1 の `D` の確認の目的の箇条に「`dist/standard` の履歴の外に置いた」を補う
  4. EV-0301 の対象を「…`dist/standard` の履歴の外に置いた知識ベースの差し替えを検出できること」と限る。本文に N1 を検出しないことを1文で足す
  5. ADR-0157 の選択肢の表の行(「`D` が `origin/dist/standard` の上にあることを足した」)に「`dist/standard` への早送りの書き込みは検出しない」と添える
- 機械の検査にするかの判断: CI が書いたことの確認(実行の番号の突き合わせ)は、ADR-0090 決定8 が候補として残した事項である。本件で手順へ足すと新しい手順の設計になる。本巡では足さず、開示で閉じるのが妥当である

### 高-2(持ち越し) 同梱の知識ベースの `source.commit` が辿れない

- 直しの確認: `implementation.md` L57〜59 に、B8 の順に載ったこと(指揮役の了承 2026-11-17)が追記された。手引きの「既知の食い違い」と ADR-0157 の決定3・影響で開示されている
- 残り: Issue #332 へのコメントの投稿は「指揮役が行う」とあり、投稿は確かめていない。本文の側は表示と実態が一致している(食い違いを隠していない)。食い違いそのものは B8 まで残る
- 閉じ方: 開示済みとして閉じる。指揮役がコメントの URL を `implementation.md` に追記する

### 中-1 ADR-0090 のステータスが ADR-0141 の決定4 の中身を誤って述べる

- 所在: ADR-0090 のステータスの追記「ADR-0141 は、本 ADR の決定2 が構成の状態に使った『未達』をゲートの状態の語に置き換えました」
- 事実: ADR-0141 の決定4 は、規定を満たさない構成を「列挙に無い離脱」とした(ADR-0141 のステータス L10、決定4 L48〜50)。「ゲートの状態の語に置き換えた」のではない。字義どおり読むと、構成の状態にゲートの状態の語を当てたことになり、ADR-0141 が解いた語の混同を逆に述べている
- 直し方の案(編集の指摘。ステータスの節なので採用後でも直せる): 「ADR-0141 は、本 ADR の決定2 が規定を満たさない構成に使った『未達』の語を『列挙に無い離脱』に置き換えました(2つの場合の分け方と記録の3項目は維持)」
- 閉じ方: 議長が直す。直さない場合は、本記録を開示とする

### 低-1 「未実装(降りていない、`implementation-marking.md` の undelivered)」の当て方

- 所在: ADR-0157 の決定3 の見出しの直後の箇条
- 事実: implementation-marking の「降りていない」は、実行主体を制約する規定が案件の実行層(準拠テンプレートなど)へ届いていないことを言い、実装マークと台帳で表示する。決定3 の検査は標準のリポジトリ自身の `npm run check`(`check-gate-criteria.mjs`)で、実装マークは無く台帳にも出ない(ADR-0157 は「実装マークは足さない」とする)。「undelivered」と名指すと、台帳に出るはずの状態と読まれうる。ADR-0141 の語(未達=ゲートの状態)との衝突は解けている
- 直し方の案: 括弧を「(標準のリポジトリの検査をまだ実装していない。ゲートの状態の『未達』ではない。実装マークの対象ではない)」に改め、implementation-marking の名指しを外す
- 閉じ方: 直さない場合も、ADR-0157 の影響の「実装マークは足さない」で読み手は辿れる。開示で足りる

### 低-2 `implementation.md` と `fix-round1.md` が、検査の置き場を「template の検査」と書く

- 所在: `implementation.md` L59「template の検査の実装は B8 の中で行う」、`fix-round1.md` 高-2「template の検査は B8 で実装する」
- 事実: ADR-0157 の決定3 は、検査を標準の `npm run check` に置き、テンプレートの契約検査へ入れる案を採らない(選択肢の表)。B8 で行うのは時期の都合であり、置き場は標準の側である
- 直し方の案: 「標準の側の祖先の検査(`check-gate-criteria.mjs`)の導入は、B8 の再生成と同時に行う」に改める。research の記録なので公開の本文には影響しない

### 低-3 手引きは `D` のオブジェクトの入手を書いていない

- 事実: 正本の clone に無い `D`(fork に置いた差し替えや、強制 push の時代の 14 回分の配布、project-management.md L120)は、`git show D:…` が失敗する。失敗の向き(通さない)なので安全側だが、結果を「不一致」と書くか「未確認」と書くかを、手引きは1行目について定めていない(2行目は「未確認」と定める)
- 直し方の案: 1行目に「`D` が正本の clone に無いときは、条件1 を満たさないものとする」を箇条で足す
- 閉じ方: 直さない場合は、本記録を開示とする。誤って通す向きではない
