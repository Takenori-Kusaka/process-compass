## 実機の確認の結果(Windows 2.1.326、WSL2 2.1.314。記録は research/441-443-444-deliberation/probe-444/)
確かめたこと:
- W1〜W3: SessionStart の入力と環境変数の実行の識別子が一致する。git の commit-msg フックで Agent-Run: のトレーラを足せる。--resume でも識別子は同じ
- W4: ネイティブ Windows の sandbox は feature gate が off で隔離は効かない
- W5・W6: WSL2 の sandbox は作業ディレクトリの外・設定ファイル・.git/hooks への書き込みと、許可の無い宛先への通信を拒む。allowUnsandboxedCommands:false のもとで dangerouslyDisableSandbox:true を送っても隔離のまま
- W7: 既定では template の強制層のうち .claude/hooks/ だけが守られ、他の 4 経路は書けた。permissions.deny に置いた経路は EROFS で拒否された。ask に置いた経路は書けた。sandbox の中の git commit はトレーラのフックと両立した
確かめていないこと:
- macOS とネイティブ Linux での S1〜S4(確かめる担い手が未定。EV に開示)
- 下位の担当(サブエージェント)でフックが走るか
- 利用者の範囲の指示(~/.claude/CLAUDE.md)の版の記録
- deny を確かめたのは 2 パスのみ。コミットしなかった書き込みは範囲の事後の照合で数えられない
- 初期化の前(ask の段)と guard.enabled が偽のときの経路は開いている(note と EV で開示。条文は足さない)
