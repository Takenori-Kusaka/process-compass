# 重の裁定(2026-11-12)

- 入力: `survey.md`、`survey-external.md`、議題 `council-10-agenda.md`、5 委員 `council-11-drafter.md`・`council-12-field.md`・`council-13-qa-audit.md`・`council-14-standards.md`・`council-15-defender.md`

## H-1(S-1): 誤っているのは ADR-0085 決定2 の go の句。ADR-0121 の「補う」の表の限定も誤りを引き継いでいる

5 委員が一致した。

- ADR-0085 決定2 の「go では G-5 基準3 を『実施しない』と記録するため、黙っては外れない」は誤りである。実装(coverage-check.mjs)は `coverageSummary` が null のとき code 0(通過)を返し、gate-g5 は緑になる。第4章 G-5 は実装が存在する段階で「対象なし」を用いることを禁じ、未実施を失敗に数える。「実施しない」を記録して通すことは G-5 の語彙の外の第3の通過の状態であり、ADR-0121 が (c3) として退けた形と同じである
- ADR-0121 の「補う」の表は、決定2 の理由を「製品のコードが単一のスタックの場合に限って成り立つ」と限定した。単一の go のスタックでも成り立たないため、この限定も誤りである。ADR-0121 決定4 の原則(未実施を失敗に数え、合算しない)は正しい
- 採用済みの両 ADR の本文は書き換えない。**ADR-0124** で、ADR-0085 決定2 の go の句と、ADR-0121 の「補う」の表の限定を置き換える。決定2 の結論(事前点検では止めない)は維持する
- go の基準3: `coverage.out`(coverprofile)から測る。全体の割合は文の数の割合(Σ 被覆したブロックの文の数 / Σ 文の数。`go tool cover -func` の合計と一致)。変更の範囲は、ソースを構文木で読んで各文の開始行を得て、その文を含むブロックの回数を行の被覆とする(gocov 系の方式。node・python と同じ「文の開始行」の近似。起案・品質監査・規格・弁護の4委員)
  - 採らない: 変更行に重なるブロックを文の数で重みづける方式(現場の委員)。分母の定義が本文の「文の開始行」と食い違う。ブロックの範囲の全行を被覆とする方式。割合を上へ寄せる
- 測れない構成(`coverage.out` が出ない、集計の記録の無いアダプタ)は、未実施として失敗にする。`coverageSummary` が null のアダプタを通す分岐は、言語のアダプタでは失敗に改める(none・undetermined は対象なしの扱いの規定どおり)
- 移行: 猶予を置かない(5 委員)。既存の go の採用者には、テンプレートの更新の取り込みの時点で効く。ADR-0085 決定6 に従い、落ちうる検査と直し方を ADR-0124 に列挙する。go.json の誤った note(「ワークフロー側の go tool cover の出力で行ってください」)は削る
- 根拠水準: go の文の開始行の近似と、構文木で得た文の範囲とプロファイルのブロックの対応は、手元の小さな例でしか確かめていない(EV-0246)

## H-2(S-2): 「テストのみの変更で失敗が解消」は分けて、静的な近似は名前どおりの表示として降ろす

- 静的な近似を「製品のコードを変えずに既存のテストを変えた変更」の検出として、**IMPL-0486** で降ろす(delivered・machine)。0 件のときも、近似が拾わない形(同じ PR で製品とテストを変えた場合、ローカルで解消した失敗)を定型の文で出す(4 委員)
- 「失敗が解消した」ことを確かめる部分(履歴型・再実行型)は **IMPL-0487** として undelivered・scheduled。実機の確認を要するため #361 へ寄せる
- 採らない: 静的な近似を IMPL-0204 の delivered に含める案(軽の起案。本人も取り下げた)。条項の観測の単位を「push された記録」に改める案(規格の委員)。条項の改めは新しい限定を課すため本件の範囲を超え、IMPL-0487 の実装の時点で扱う

## H-3(S-3): 落ちることを期待する印の書式をテンプレートが定め、表示する。予期せず通った場合の失敗は枠組みごとに降ろす

- テンプレートが、枠組みに依らない注釈の1行の書式を定める: `pit-in: known-failure issue=#NNN match="<照合する失敗の理由>" review=YYYY-MM`。印の付与を検出し、欄の欠けと見直しの時期の超過を表示する。合否に使わない(**IMPL-0488**。delivered・machine)
- 予期せず通った場合の失敗: pytest は `strict`(印ごとの `strict=True` か構成の `xfail_strict = true`)が無い xfail の付与を G-5(pr-rules)の失敗にする。Jest の `test.failing`・Vitest の `test.fails` は、予期せず通ると枠組みが失敗にする(**IMPL-0489**。delivered・machine)。印の付与の検出(弱体化の表示)と違い、これは試験の失敗の扱いの規定(本文 1049 行)の強制であり、本文 1046 行の「検出を合否に使わない」に当たらない
- 失敗の理由の照合と、印を持たない枠組み(go の testing・JUnit 5 ほか)は **IMPL-0490**(undelivered・adopter。decision=ADR-0124)。枠組みごとの表を ADR-0124 に置く。採用者は、照合の補助(pytest の `raises`、自前の補助関数)で実装できる
- 採らない: 印の一覧のファイルを置き場にする案(規格の委員)。印と試験のコードが離れ、試験の移動で照合が切れる。照合できない枠組みを scheduled にする案(品質監査・弁護)。テンプレートが枠組みごとの照合の部品を持つ計画が立たず、scheduled と表示し続けると降りる見込みを誤って示す

## H-4(S-4): 中間の層へのマージを拒否する設定は課さない。禁止は手順とマージの後の検出で降ろす

- GitHub・GitLab のいずれも、push を許して中間へのマージだけを拒む規則を持たない(提供者の文書で確認)。採用者も実装できない。scheduled(降ろす見込み)も adopter(採用者が実装する)も事実に反する(規格・起案の委員)
- 本文に「本標準は、既定ブランチ以外へのマージを拒否する設定を課さない」と理由とともに書く。ADR-0078 決定3(ルールセットを機能ブランチへ広げない)は維持し、ADR-0124 に記録する。見直しの契機は、提供者がマージだけを拒む手段を出したとき、または公式のスタック型 PR(下からしか着地しない)が一般提供になったとき
- IMPL-0248 の主題を「マージの後の検出」に改める。記録の写し(record-copy の base.ref)から、既定ブランチ以外へ取り込んだマージを出荷の集約で「検出あり / 0 件 / 未確認(写しが読めない)」の3値で出す。合否・出荷の失敗に使わない(delivered・machine)
- IMPL-0254 の主題を「人の手順」に改める。ルールセットの説明に、中間の層をマージしない手順(下の層から順に既定ブランチへ取り込み、上の層の基底を付け替える)と、拒否の設定が無いこと、マージの後に検出されることを書く(delivered・presence)
- 採らない: undelivered・scheduled のまま残す案(現場・品質監査・弁護)。降ろす手段の無い規定を「予定」と表示し続けると、台帳が降りる見込みを誤って示す。人がマージできることは、本文の「課さない」と検出の表示で開示する。ルールセットを ~ALL へ広げる案(作業ブランチへの push も止まる)

## H-5(S-5): AI のマージの拒否は、拒否する経路に限って delivered にする

- IMPL-0255 は、guard-bash が拒否する経路(`gh pr merge`、`gh api` による PR のマージ)に限って delivered・machine とする(5 委員)
- `git merge` と `git push` の組、スクリプトからの API の呼び出しの経路は **IMPL-0491**(undelivered・scheduled、#358 へ寄せる)。マージの後の検出(H-4)は、PR を経ない push の取り込みを拾わないことも note と本文に書く
- `gh pr create/edit --base` の付け替えは塞がない(手動のスタックの正当な操作)
- 採らない: 他の層の参照を引数にした `git merge` の拒否をフックに足す案(規格の委員)。既定ブランチからの同期と区別する手段がフックに無く、正当な操作を止める

## H-6(S-6): 採点の稼働の機械の検証は課さない。IMPL-0102 は「記録で示す」ことの人の確認へ改める

- 本文に「本標準は、L2 の採点の稼働を機械で検証することを課さない」と理由(自己申告を超えて検査できる条件が定まらない)とともに書く。ADR-0124 に記録する(5 委員が「条件を条項で定めない」)
- IMPL-0102 の主題を、L2 の宣言の根拠が「記録で示す」こと(本文の L2 の条件)を変化点の決定者が根拠の中身に照らして読むことへ改める。/process-change の種別 settings に手順を置き、delivered・manual。確かめる者: 変化点の決定者(起案・規格。品質監査も手順を delivered manual とする)
- **IMPL-0494**: L2 で規模の基準なしが効いた PR の結果に、「担保水準の根拠の中身は機械で確かめていない」旨を定型で毎回出す(delivered・machine。4 委員)
- 採らない: IMPL-0102 を adopter とする案(品質監査)。課さないと決めた規定を adopter にする規則は無い(「課さない」は plan の値にしない)。not-imposed への移行だけで済ませる案(弁護)。L2 の条件の「記録で示す」は課したままであり、人の確認の手順が要る

## H-7(S-7): 一致した部分 A〜E の最終の形

- **A(IMPL-0204)**: 検出の範囲に、基底に無い新しいテストのファイル、追加行の skip・xfail・only、削除行のアサーションと、同じ塊の中の削除と追加のアサーションの対(旧・新)を含める。0 件のときも検出の限界(列挙した語以外の弱め方は拾わない)を出す。正本は、既定ブランチのコードで計算するジョブ(gate-g5-base)の要約。PR のコメントは閲覧の便宜。ラベルは付けない。合否に使わない。本文の「機械の検出が付けたラベル」と /human-verify 順4 の語を「機械の検出の一覧」へ改める
  - 期待値の改めの根拠は、PR 本文の表(`## 期待値の改め` の `ファイル | 旧 | 新 | 根拠`。根拠は識別子 ADR・受入基準・条項に限り、Issue の番号だけは数えない)。表の無い改め、解決できない識別子を表示する。合否に使わない(4 委員。弁護の「試験のコードの注釈」は採らない: 注釈は試験の差分の中にあり、根拠を消す変更と同じ差分で消える)
- **A'(IMPL-0205)**: 計画は既定ブランチの先端から読む。差の一覧と別に、計画の「変更の対象パス」の列そのものの変更、基底の計画に無いタスク、読めない升、テストのパスを出す。合否に使わない(delivered・machine)
- **C(IMPL-0253・0155)**: ワークフローが列挙できる入力(指示ファイル・差分・PR の情報・作業ツリーにある自動読込の候補)をパスと sha256 で書き出す固定の手順を ai-review.yml に足す(IMPL-0253 を「列挙できる入力の書き出し」として delivered・machine)。記録が四半期の抜き取りまで残ること(Actions の既定の保持に頼らない)は **IMPL-0492**(undelivered・scheduled、#358)。道具にしか分からない入力(実際の起動の指示・道具の定義)は差し込み口の契約ファイルで受け、無ければ「列挙できない確認」と表示する。契約の実装は **IMPL-0493**(undelivered・adopter、decision=ADR-0124)。IMPL-0155 は、構造化された指摘の所在・根拠の欠落の表示(散文なら「構造が無いため欠落を検査していない」)を ai-review のジョブの要約に出す形で delivered・machine。中身の正しさは確かめない。PR へ書くジョブへは渡さない
- **D(IMPL-0259)**: python と go で変更の範囲を測る(H-1)。python は coverage.py の `coverage json` の文の割合を読み、`# pragma: no cover` の除外と branch の設定で割合の意味が変わる点を開示する。delivered・machine
- **IMPL-0479**: 本件では降ろさない。実機の確認を降ろす条件とし、#361 へ寄せる

## H-8: 範囲外

- `impl-targets.yaml` の id `rulesets` の二重定義: id を分け(説明の README を `rulesets-readme`、定義の team.json を `rulesets`。照合は従前どおり team.json)、`check-impl.mjs` に id の重複を失敗にする検査を足す
- python の全体の割合にテストのファイルが入る件(**IMPL-0496**): 全体の割合からテストのファイル(guard.json の testPatterns)を除いて数える。割合を上へ寄せる欠陥のため、猶予を置かず取り込みの時点で効かせ、ADR-0124 に影響を列挙する
- `test-base-judge-workflow.mjs:79` の CRLF: 試験の読み込みの側で改行を揃える。照合の正規表現は緩めない
- go・python の測れない構成の失敗は **IMPL-0495**(delivered・machine)

## H-9: 採らない案(まとめ)

上の各項の「採らない」に加えて:

- 検証の弱体化の検出・期待値の差分・パスの差・マージの後の検出を、G-5 または出荷(G-7)の失敗に使う案(本文 1046 行・1050 行)
- IMPL-0479 を実機の確認なしに delivered にする案
- go の採用者に猶予の期間・警告の段を置く案(現場の「取り込みの PR で現れる」を採り、テンプレートの中に猶予を持たない。猶予を置くと未実施の通過が続く)

## H-10: 実装の中で議長が加えた裁定

- `pytest.xfail()` の呼び出しも、IMPL-0489 の G-5 の失敗に含める。呼んだ時点で試験を終えるため `strict` が効かず、予期せず通った場合を試験の失敗とする規定(本文 1049 行)を満たす手段が無い。採用者への影響は ADR-0124 の影響の表に載せた
- 準拠テンプレートの事前点検(preflight.mjs)、構成の生成の案内(generate-profile.mjs)、`adapters/node.json` の note、本文 フェーズ5「テンプレートリポジトリ」の go を「実施しない」と記録する旨の文は、H-1 で偽になったため改めた
- IMPL-0254 は、ルールセットの説明の節という単位が `presence` の単位(欄・キー・行・ファイル)に合わないため、`manual`(確かめる者: AI維持管理者)とした
