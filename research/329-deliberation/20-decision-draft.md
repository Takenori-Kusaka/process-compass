## 1. 論点A: 「未達」は適合の主張を妨げるか

### 1.1 原文と実物で確かめた事実

| # | 事実 | 所在 |

| b | 列挙に無い離脱の定義は「記録があり、ゲートが判定されうるのに、本標準が代償措置を定めていない離脱」。未達は「ゲートの状態」(ADR-0028)。兼務のようにゲートでないものを未達へ入れると `unmet[]` の意味を壊す | ADR-0083:82,88,161 |

### 1.2 委員の読みの当否

- **起案(「区分は割れていない」)**: 誤り。起案自身が弱点(5(6))で「未達が主張を妨げるかは確かめていない」と書いた。その点を確かめると、事実 a・d のとおり、配備の「未達」は主張を妨げない。一方、事実 f のとおり、同じ型(ホスティングの機構で統制を閉じられない構成)の置き場の履歴は主張を妨げる。区分の名だけでなく、効果も割れている
- **品質監査(「割れても主張の成否は壊れず、件数の再現性が壊れる」)**: 前半は誤り。品質監査は `overview.md:646-648` の「未達」を、未達の全部と読んだ。表が書くのは「未達のゲート」だけである。件数の再現性が壊れるという後半(M-1)は正しい
- **規格(「未達の語が二義」)**: 正しい。事実 b・c・e が裏づける。ただし、規格が推した「判別の規則を 1.10.2 に1か所書いて揃える」案は、**一般の規則としては採らない**。その規則は「ゲートの判定は成り立つが、周辺の構成の条件を満たせないとき」を一律に列挙に無い離脱とする。これを当てると、ADR-0113 が意図して主張を妨げないとした確認の欠落(事実 e)まで、主張を妨げる側へ移る。ADR-0113 の決定を、本件の審議の範囲の外で変えることになる。規格の委員自身が退路とした「二義を書き分ける」案を採る

### 1.3 裁定の案

1. **二義を書き分ける**(1.10.2): 「未達のゲート」は、構成に記録したゲートの状態(ADR-0028)をいう。条項が「保証の開示に未達として記録する」と書く要求事項の不充足は、保証の開示の表示である。これは未達のゲートの件数に数えない。適合の主張を妨げるかは、その条項が定める。語は増やさない(ADR-0083 決定3・ADR-0133 決定6)
2. **配備の資格情報の不充足を、列挙に無い離脱へ移す**(1.10.2 の表に1行を足す)。理由:
   - 型が置き場の履歴と同じである。統制がホスティングの機構で閉じず、書き込みの権限を持つ者が、人の判定の場所(G-8)を経ずに配備先へ届く。置き場の履歴は G-7・G-8 の記録を書き換えられる構成で、主張を妨げる。配備の経路は G-8 の決断そのものを迂回できる構成で、現行は主張を妨げない。同じ型を逆に扱う理由は、原文のどこにも無い。信頼性の軸では、迂回の経路が開いたまま「適合」と述べられる側が弱い
   - ADR-0083 決定3 の定義に合う。G-8 の判定記録は書け、ゲートは判定されうる。本標準は条件と代償措置を定めていない。狭める措置を満たす手段に数えない定め(`gate-criteria.md:1848`)は、代償措置を定めないという意味である
   - ADR-0090 が求める記録の3項目は保つ。列挙に無い離脱は「記録と表示の規定は、各条項のとおり適用します」(`overview.md:698`)なので、記録の情報量は落ちない。品質監査が自案の弱点(5(5))で挙げた懸念は、これで解ける
   - SLSA v1.2 の型(継続して働く技術的な統制を示せない水準は主張させない。SRC-0416 に足す T329-09)と同じ向きである
3. 採用者への効果は、**新しい義務に当たる**。現行の template では主張できた構成が、適用の表明までになる。したがって所有者の判断を要する(Q1)。影響の範囲は次のとおりで、測ってはいない(EV で開示する)
   - Free の私的リポジトリは、ルールセットを使えないため、置き場の履歴の離脱で既に主張できない。本件で増える負担は無い
   - 主に効くのは、配備先が同じリポジトリの中にあり、`GITHUB_TOKEN` で書く構成である(配布用のブランチ、リリースの資産、パッケージ)。配備先がリポジトリの外にある構成と、(a)(b)+(c) を満たす構成には効かない
4. **Q1 で所有者が移さないと決めた場合の退路**: 1 の書き分けだけを行う。そのうえで、第4章 G-8 の同じ節に「この不充足は適合の主張を妨げない。G-8 の受容の対象とする」と書く。課さないと決めた事項として明記し、根拠水準マークで開示する。どちらにしても、現行の「書かれていない」状態は残さない

## 3. 論点C: G-8 は門か記録か

### 3.1 確かめた事実

- ADR-0036 決定1: 工程ゲートの判定は、判定記録の作成で成立する。記録の無い状態は未判定である。決定2: 工程ゲートの問いは「この成果物を次工程へ進めてよいか」である
- `gate-criteria.md:1690`: 「未達の多さを理由に出荷を止める判断は、このゲートではなくリリース決裁(G-8)が行います」。`:1724`: 「G-8 へ届く前に止める」
- IMPL-0237 の note は「案件のデプロイ(G-8 の後の配備)」と書く(注記であり、規範ではない)
- 配備の前に G-8 の判定記録があることを、機械が確かめる箇所は無い。template に配備のワークフローは無く、配備の実行記録を読む機構も無い(01-internal 2.3)

### 3.2 裁定の案

- 「G-8 は決断の記録であり、配備を止める門ではない」(品質監査 b・起案の弱点1)は**採らない**。G-8 は、出荷を止める判断の場所である(`:1690`)。ADR-0036 決定2 の「次工程へ進めてよいか」の判定である。この文は、両者と矛盾する。誤りは提案の文の側にある
- 書く文: 「G-8 は、配備の前に事業決裁者が行う判定であり、判定記録の作成で成立する。本標準は、配備の機構が G-8 の判定記録を確かめてから動くこと(機械による停止)を課さない。判定記録の無いまま行った配備は、G-8 を経ない出荷であり、記録の欠落として扱う」
- 現場の「配備の前に記名」は、新しい義務ではない。ADR-0036 決定1・2 の帰結である。ゲートの判定は次工程へ進む前に行い、記録が無ければ未判定だからである。明記は既存の決定の明確化として扱う。ただし、所有者が別の読みを持つ可能性はあるので、確認の問いを置く(Q2)
- 「記録の欠落として扱う」は、検出する機構が標準の側に無い。配備の実行記録は採用者の基盤にあるので、`plan=adopter` の実装マークで表示する。機械の停止を課す案(1-D)は、**今回は課さないと決めた**と明記する。理由は次の2つ。(i) 判定記録を読んで動く配備は、記録の真正性を閉じなければ、検出を門と読ませる(弁護)。(ii) 配備先は案件ごとに違い、雛形を持たない(ADR-0090 決定6)
- 緊急の修正で G-8 の前に配備する場合の扱い(第7章 7.3 の例外承認で受けるか)は、原文で確かめきれなかった。本件では定めない。独立の突合へ渡す(10 節)

## 5. 論点E: 狭める措置の欄と、原因の記録例

- 現場の案(狭める措置の欄を「なし」で通せなくする)を、2つに分けて裁く
  - 空欄を通さないこと: 既存の義務である。未達の記録には3つを「書きます」(`gate-criteria.md:1842-1846`)。保証の開示の欄の欠けは記載の欠落である(附属書H「差し戻すのは記載の欠落だけ」)。明確化として、手引きに「空欄は記載の欠落」と書いてよい。ただし、機械で確かめる欄が template の構成に無いので、`check=manual` になる
  - 「なし」を禁じること: **採らない**。措置を取ることを義務にする。これは措置を規定を満たす手段に数えない定め(`:1848`)と矛盾する(弁護の 2-C の論)。措置が無いことを正直に書く記録を、形だけの措置で埋めさせる(現場の自案の弱点)
- 弁護の案(制約が原因か機構が原因か)は、既存の規定の明確化として、**記録例(手引き)** に置く。既存の2つの場合(手段が無い・使わないと決めた)は、既に原因の種類を記録させている。`GITHUB_TOKEN` で書く構成は、多くの場合「使わないと決めた」に当たる。この読みを例で示すだけで、欄は足さない
- 1 の裁定で配備の不充足を列挙に無い離脱へ移しても、記録の3項目は残る。本節の扱いは変わらない

## 6. 論点F: リスクの受け止め(`risk-catalog.md:101`)

受け止めの欄が指してよいのは、実在する統制だけである(弁護の所見。原文で確かめた)。

| 指す統制 | 実在の所在 |
| --- | --- |
| PR を経る変更: PR ワークフロー、緊急の修正でも PR を経る運用 | 現行のまま |
| PR を経ない起動(手動の起動・起動元のブランチ上のワークフローの書き換え): 配備の資格情報を参照へ結び付ける規定と、満たせない構成の記録 | `gate-criteria.md` G-8「配備の統制と資格情報の置き場」、`ci-gates.md`「統制と資格情報の置き場」 |
| 配備の前の判定 | 第4章 G-8(判定記録。3 節の裁定) |

- 「受け止めは防止に限らない。規定を満たせない構成は記録して表示する」を同じ升に書く(品質監査)。これは受け止めの強さを正しく書くためである
- 書かないもの: 実行記録の突き合わせ(規定にも template にも無い)、環境の配備ブランチ制限が起動を塞ぐこと(公式の明記が無い推論。02-external 5-4)、env-check(狭める措置の事実を読むが、G-8 の適合の判定に使わない。IMPL-0351)
- 3-B(受け止めの文言を「資格情報の結び付き」へ強める)は採らない。統制を実装済みと読ませ、IMPL-0237 の `undelivered` と食い違う(弁護)
- 3-C(手動の起動を禁じる)は採らない。#293 X-1 の裁定と同じ理由である
- 一覧の行の直しで、統制は増えない。目的は、誤った安心を与える表示を正すことである。この目的を ADR に書く

## 7. 論点G: D-3 と ADR-0133 の再検討の契機

- ADR-0133 は、決定1 の表で「プランに依る統制の扱いは #329 の裁定を待つ」と書き、決定8 で #329 の裁定を再び検討する契機に挙げ、D-3 の文案を #329 へ送った。範囲外として返さない(規格の所見)
- 再検討の結果: ADR-0133 の理由は3つある。(i) 検出型の統制が既に必須で、措置を足すと二重になる。(ii) 2つの置き場の権限者が異なることが、機械で閉じない。(iii) 1名の体制では成り立たない。どれもプランに依らず、本件の裁定でも変わらない。**D-3 は採らない**
- 本件で決めた型(1.3 の2): 統制がホスティングの機構で閉じない構成は、契約の条件が理由でも列挙に無い離脱とし、条件と代償措置を定めない。置き場の履歴の区分は、この型でも変わらない。変わらないことが、ADR-0133 と矛盾しないことの確かめになる
- 記録の置き方: ADR-0141 の決定に、ADR-0133 決定1 の表の「#329 の裁定を待つ」に答える1項を置く。ADR-0133 の本文は書き換えない。`overview.md:709` の行は、プランの語を括弧から外し、当たる条件の列の「規則を適用していない構成」だけを残す(規範はプランを名指ししない。行の意味は変わらない)

## コンテキスト

[#329](https://github.com/Takenori-Kusaka/process-compass/issues/329) は、G-8 の成立条件と配備の統制が、契約のプランと手動の起動に依ることを問いました。審議は重です。記録は `research/329-deliberation/` にあります。

実物で確かめた事実は次のとおりです。

- 第4章・ADR-0070・ADR-0036 決定1 と準拠テンプレートの集約は、G-8 を判定記録で判定する。第5章 QMS 文書管理の承認権限の対応だけが、G-8 の操作を「実行環境の承認操作」としていた。G-7 の行は ADR-0106 で改めたが、G-8 の行は取り残されていた
- CI ゲート構成の「デプロイゲート」は、必須レビュアを使えない場合の G-8 の成立を「定めていない」と書いていた。規範が既に定めている事柄である
- 第1章 1.10.2 の述べる条件は「未達のゲート」を数える。配備の資格情報の規定は G-8 の判定基準の外にあり、不充足を「保証の開示に未達として記録」する。準拠テンプレートの述べられる名は、この不充足を数えない。同じ型の判定記録の置き場の履歴は、列挙に無い離脱として主張を妨げる
- ゲートの外の「未達」には、主張を妨げないと意図して決めた用法がある(ADR-0113 の確認の欠落)

## 決定

### 1. G-8 は判定記録で成立する。配備の環境の承認は成立に数えない

G-8 は、判定記録(第6章 テンプレ4)の作成で成立します(ADR-0036 決定1)。配備の環境の必須レビュアは、採用者が足してよい統制です。G-8 の成立には数えません。必須レビュアの承認の記録は、判定記録の代わりになりません。両者が食い違えば、成立を決めるのは判定記録です。第5章 QMS 文書管理の G-8 の行を、G-7 の行にならって改めます。兼務の扱いと発注側への固定(ADR-0035・ADR-0087)は落としません。

### 2. 配備は G-8 の判定の後に行う。機械による停止は課さない

G-8 は、配備の前に事業決裁者が行う判定です(ADR-0036 決定2)。判定記録の無いまま行った配備は、G-8 を経ない出荷であり、記録の欠落として扱います。本標準は、配備の機構が G-8 の判定記録を確かめてから動くことを課しません。課さないと決めた事項です。判定記録の真正性を閉じないまま読ませると、検出を門と読ませるためです。配備先は案件ごとに違います(ADR-0090 決定6)。

### 3. 「未達」の二義を書き分ける

第1章 1.10.2 の「未達のゲート」は、構成に記録したゲートの状態をいいます(ADR-0028)。条項が「保証の開示に未達として記録する」と書く要求事項の不充足は、保証の開示の表示です。未達のゲートの件数に数えません。適合の主張を妨げるかは、その条項が定めます。表示の語は増やしません。

### 4. 配備の資格情報の規定を満たさない構成を、列挙に無い離脱とする

第4章 G-8「配備の統制と資格情報の置き場」を満たさない構成は、列挙に無い離脱です。条件と代償措置を定めません。記録の3項目(開いている経路、経路を持つ主体と直接の書き込みの可否、狭める措置と止めないもの)は、ADR-0090 決定2 のとおり書きます。2つの場合(手段が無い、使わないと決めた)の分け方も維持します。

理由は、型が判定記録の置き場の履歴と同じだからです。統制がホスティングの機構で閉じず、書き込みの権限を持つ者が、人の判定の場所を経ずに届きます。同じ型の一方だけが適合の主張を妨げる理由はありません。

### 5. 契約の条件は区分を変えない

統制の手段を使えない理由が契約の条件でも、区分は変えません。費用がかかること、他の手段がより安いことは、満たしたものとして扱う理由になりません。本標準は、契約の条件に固有の条件・代償措置を定めません。リポジトリの外の秘密情報の置き場を、満たす形に新たに加えません。規範は製品と契約のプランを名指ししません。プランごとの提供は、手引きに日付つきで置きます。

### 6. D-3 を再検討し、採らない

ADR-0133 が #329 へ送った D-3(判定記録の置き場の要約値を、別の置き場へ追記して突き合わせる措置)を再検討しました。ADR-0133 の理由(検出型の統制と二重になる。2つの置き場の権限者が異なることが機械で閉じない。1名の体制では成り立たない)は、契約の条件に依らず、本件でも変わりません。採りません。ADR-0133 決定1 の表の「#329 の裁定を待つ」には、決定4・5 の型で答えます。判定記録の置き場の履歴の区分は変わりません。

### 7. リスクの一覧の受け止めを、実在する統制に合わせる

運用のリスクの一覧の「配備の自動化の不備」の受け止めに、PR を経ない起動を足し、第4章 G-8 の規定と記録へ辿れるようにします。一覧に書くのは、実在する統制だけです。統制は増えません。誤った安心を与える表示を正すための変更です。
