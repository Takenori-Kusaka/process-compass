## 3. 論点2: 配備の資格情報の置き場(プランに依る)

### 3.1 事実の確認

| 事象 | 実物 | 判定 |
| --- | --- | --- |
| 規範「統制と資格情報を、起動元のブランチで書き換えられる場所の中だけに置いてはならない」 | `gate-criteria.md:1823`(見出し 1821)。ADR-0090 決定1 | 事実 |
| 満たす形は (a) 参照に限った Environment の秘密情報、(b) 参照を確かめる受け手の短命の資格情報、(c) 配備先が結び付かない資格情報を拒む | `gate-criteria.md:1825-1829` | 事実。起票者の言う「外部の秘密情報の置き場」は (b)(c) で一部既に認めている(配備先がリポジトリの外なら (c) は満たされる、`:1831`) |
| 手段が無い場合は未達として記録 | `gate-criteria.md:1843-1851`。「手段が無い場合」と「使わないと決めた場合」。記録は経路・主体・狭める措置 | 事実。ADR-0090 決定2、ADR-0028 |
| 無料の非公開では Environment の秘密情報・参照の限定が使えない | `ci-gates.md:975`(2026-10-27 時点の GitHub Docs。実機では確かめていない) | 事実(未検証) |
| 本リポジトリの配布は (c) を欠き、未達として開示 | `ci-gates.md` の EV-0137 の段、ADR-0090 決定5、`src/content/docs/community/project-management.md:150-175` | 事実 |
| 実装マーク | IMPL-0237 `state=undelivered plan=adopter decision=ADR-0090`(`src/content/docs/community/implementation-ledger.md:94`)。IMPL-0351 は env-check が狭める措置の事実を読む(delivered) | 事実。降りていない規定を表示し続ける方針と整合 |

### 3.2 論点の整理

1. **未達として記録し続けて足りるか**: 記録は検出であって防止ではない。`GITHUB_TOKEN` の書き込みは、どのプランでも参照に限れない(`ci-gates.md:963`)ので、有償プランでも (c) を欠けば未達になる。プラン限定でなく機構の問題
2. **代替の手段を定めるか**: 外部の秘密情報の置き場や OIDC を受ける外部は、(b) または (a) の外部版として読める。現行の (b) は「受け手が参照を確かめる」ことを要件にし、外部の置き場が当たるかは書かれていない
3. **費用を理由に統制を省かせない**: #352 の弁護・規格が引いた Green Book OV4.17(`research/352-deliberation/decision-draft.md:84`)の論点。「使えないプラン」が制約か費用かの区別

### 3.3 取り得る案

| 案 | 内容 | 層 | 評価の材料 |
| --- | --- | --- | --- |
| 2-A | 現状維持(未達として記録)。外部の置き場を要件にしない・プラン固有の逸脱を定めない、と本文に明記する | 本文のみ | 「書かれていない」と「課さないと決めた」の区別が付く |
| 2-B | (a) を「配備の環境の秘密情報、または、リポジトリの外にあり参照を確かめて渡す秘密情報の置き場」へ広げる | 本文+template(env-check・IMPL-0237) | 外部の置き場も受け手が参照を確かめなければ (b) と同じ穴が出る。要件の書き方が難しい。手段の追加 |
| 2-C | プランに依る未達に条件と代償措置を定め、逸脱の閉じた列挙へ加える | 本文+template | **採らない候補**。ADR-0133 の理由。条件が機械で閉じない |
| 2-D | 手段が無い構成では、配備先が同じリポジトリの中にある自動の配備を採らず、手動の配備と判定記録とする、と求める | 本文(新しい義務) | 信頼性は上がるが採用者の費用が上がる。重の審議で外部の調査が要る |
| 2-E | env-check の読み取りを強め、未達の記録の「狭める措置」の欄を機械で埋める | template | 本束では扱えない。#361 と重なる |

## 4. 論点3: 配備の自動化の不備のリスクの受け止め

### 4.1 事実の確認

| 事象 | 実物 | 判定 |
| --- | --- | --- |
| 受け止めは PR ワークフロー | `risk-catalog.md:101`「配備の自動化の不備による操作の誤り / 出荷判定者 / PR ワークフロー、緊急の修正でも PR を経る運用」 | 事実 |

### 4.2 論点の整理

- risk-catalog はリスクオーナーと受け止めを示す一覧で、規範ではない。ここを直すだけでは統制は増えない。ただし、受け止めが実態(PR を経ない起動・ブランチ上の書き換え)に届かない状態は、誤った安心を与える
- 手動の起動の統制は、第4章 G-8 の資格情報の規定が既に扱う。リスクの行は、その規定への参照を欠く

| 3-B | 3-A に加え、「PR を経る運用」の文言を「PR を経る運用と、PR を経ない起動に対する資格情報の結び付き」へ改める | 本文のみ | 受け止めの強さの記述が変わる |

| 判定記録の置き場の規則 | **列挙に無い離脱**(第3の表示の区分) | `overview.md:709` |
| G-8 の必須レビュア | 「現時点で定めていない」(空白) | `ci-gates.md:956` |

三つの区分(未達・記録の欠落・列挙に無い離脱)の使い分けは ADR-0083・ADR-0133 にある。同じ型に別の区分を当てているので、「なぜ別か」を裁定で説明するか揃える。理由になり得る区別は、未達はゲートの状態、列挙に無い離脱は適合の主張を妨げる構成の状態、という点だが、書かれていない。
