### H-1(高) G-5 に足した1項が、PR を経ないコミットの G-5 の実行と ADR-0123 の取り込みの順と食い違う

- 所在: `src/content/docs/phase4-process-design/gate-criteria.md:837`(「このゲートの通過に数えるのは、当該の PR を評価した起動…の結果に限る」)
- 根拠:
  - 同ファイル「変更の要求を経ないコミット(適用: PR を経ずに既定ブランチへ入れるコミット)」(L1566 付近)は、「変更の要求を経ない体制でも、G-5 の検査を、既定ブランチへの取り込みを契機に実行する」と定める。IMPL-0238 は、1名の体制で `gate-g5-push.yml`(push を契機に `gate-g5.yml` を `workflow_call` で呼ぶ)が G-5 の検査を実行すると書く。足した1項は適用を限らずに「このゲートの通過」を PR の起動(`pull_request`・`pull_request_target`)に限るため、字義どおりでは PR を経ないコミットの G-5 は通過になりえない
  - ADR-0123 決定(L38)は、出荷の証跡の取り込み(`ship-evidence.yml`)と env-check の項目3 が `gate-g5-push.yml` の成功した実行を先に探し、無ければ `gate-g5.yml` の実行(手動の起動)を探すと定める。`ci-gates.md:960` も出荷の対象のコミットの gate-g5 の成功した実行を読む。この手動の起動の結果は、足した1項の「PR を経ない起動」に当たる。取り込みは G-5 の通過の判定ではないと読めるが、本文はその区別を書いていない
  - 裁定 8 節・ADR-0141 決定8 は、既定でないブランチの手動の起動が PR の先頭のコミットに付く経路を塞ぐことを狙う。push の契機と、既定ブランチ上の手動の起動による出荷の証跡の取り込みは、審議の対象に挙がっていない。裁定 9 節の5 は `gate-g5-base` と `record-copy` だけを確かめる点に挙げた
  - 適用範囲の書き方(#226): 限定(PR を経る変更についての規定であること)を行の中に書いていない
- どちらが誤りか: 足した1項の範囲の書き方が誤り。既存の規定(PR を経ないコミットの G-5、ADR-0123 の取り込みの順)は、本件で変えると決めていない
- 直しの案: 1項を「PR を経る変更について(適用: PR を経る変更)、PR の G-5 の通過に数えるのは、当該の PR を評価した起動の結果に限る」の形にし、PR を経ないコミットは既定ブランチへの push を契機とする実行による、と同じ行に書く。出荷の証跡の取り込み(ADR-0123 決定 L38 の手動の起動への後退)が G-5 の通過の数えに当たらないことを、ADR-0141 決定8 と IMPL-0987 の note に書く。あわせて `ci-gates.md:142` の段落の末尾の文を同じ限定にそろえる。表示と実態の食い違い(高)に当たるため、巡の数に関わらず直す

### M-2(中) ci-gates の記録例が、7.3 の記録の5つの事項と台帳の欄に合わない

- 所在: `src/content/docs/phase5-implementation/ci-gates.md` 節「記録例」(L1050 付近の第3段落)、`gate-criteria.md` G-8「この規定は、第7章 7.3 の例外承認の対象です」の段落(L1880 付近)
- 根拠:
  - 第7章 7.3 の記録は5つの事項(対象・状態・承認した者・理由・期限)を持ち、どれかが空欄なら例外承認の成立を示さない(`exception-escalation.md:47-55`)。記録例は対象・理由・想定される影響と対処・期限の4つだけを挙げ、状態と承認した者を落としている。例どおりに書いた行は成立しない
  - 「想定される影響と対処」は 7.3 の要求事項3 であり、記録の事項にも、準拠テンプレートの台帳の欄(内容・受容した理由・顕在化の兆候・返却の目安・状態・記録者・承認した者。`template/templates/03-debt-ledger.md:18-30`)にも無い。gate-criteria の「例外承認の記録の『想定される影響と対処』には、上の3つを書きます」は、存在しない欄を指す。7.3 の要求事項3 が記録のどの事項に現れるかは、既存の 7.3 の表でも欠けている(本件の前からの欠け)
- 直しの案: 記録例に状態(未返却)と承認した者(権限を持つ者の記名。作成を指示した者と AI の名義でない)を足す。記録の3項目を書く先を、台帳の欄(「内容」または「顕在化の兆候」)で名指す。7.3 の表に要求事項3 の現れる事項が無い点は、既存の欠けとして #445(exception-paths.md)か #355 へコメントで寄せる
