# #359 起案の委員の意見(軽・2委員)

調査に加えて確かめたこと:

- ADR-0084 決定4: 理由を書けない規定は `adopter` にせず `scheduled` に残す
- template-fields の検査は、第6章(deliverable-templates.md)だけを標準の正本として読む(check-template-fields.mjs:35)。試行前チェックリストは第8章にあるので、いまの検査には載せられない
- ADR-0069 決定2 が「課さない」とするのは、**席と受信箱**に所属を持たせることである。名簿(D-0 表5-2)には所属(`team`)の列がすでにある(ADR-0082)。調査 §1.2 の「席と名簿に所属が無い(ADR-0069 決定2)」は、決定の範囲を広く読み過ぎている
- 企画書に「滞留と判定する経過時間」(06-project-brief.md:169)と「作業単位の完了の条件」の例(:165)はあるが、停止条件の行は無い

## B. 一部を降ろし、残りを別のマークに分ける

**IMPL-0174(四半期の抽出)**
- 降ろす部分: `records.mjs --sample <四半期>` が四半期の判定記録の全体を母集団とし、記録された種で無作為に選ぶ(当事者に選ばせない。ADR-0116 決定5 と同じ向き)。結果の記録の様式。前の四半期の記録が無ければ next.mjs が出す
- adopter に分ける部分: 抽出の件数と確かめる者。値を支える実証が無く(IMPL-0222・0312 と同型)、確かめる者は体制で決まる。採用者には値・確かめる者・理由を層1 へ書くことを求める。値が未設定なら未達として表示する

**IMPL-0175(提示を周期で変える)**
- 降ろす部分: 並びと強調。/gate がレビュー本文の雛形と記録の草案を出すとき、確認を求める項目の並びと強調を、四半期を種にして決定的に回す。宣言行と機械が読む欄は固定のまま
- マークは gate-skill(または生成スクリプト)へ付け替える
- 表現を変える部分は別のマークで scheduled に残す。機械が言い換えると意味がずれる危険があり、本文の根拠(2015年)は文言を変えても効かないとしている。条項の見直しは範囲外の気づきとして記録する

**IMPL-0374(完了スループットの集計)**
- 降ろす部分: 集計スクリプト。完了の既定の述語を「作業単位を閉じる PR がマージされ、G-6 の通過の記録がある」とする。閉じた理由の値だけでは完了にしない。単位期間ごとに完了と閉じたが完了に当たらない件数を並べる
- adopter に分ける部分: 既定以外の完了の条件を使う採用者の述語

**IMPL-0377(到達の見込みの算定)**
- 降ろす部分: 期間の端、SC-M の残りの個数(構成 `flow.scopeLabels`)、区分の算定。IMPL-0374 の上に作る。7.7.2 の期ごとに見込みの報告の Issue へ置く
- adopter に分ける部分: 費用の実績の入力(会計の基盤への接続に依存。IMPL-0277 と同型)
- 入力が無いときに区分を「算定できない」と出さない(「算定できない」は単位期間が3つ未満の意味)

## C. 表示の誤りを先に直して降ろす

**IMPL-0283(滞留の観測と通知)**
- note の「採用者が…通知の手段を置く」は `plan=scheduled` と食い違う。表示の誤りとして最初に直す
- cron のワークフローが flow スクリプトを実行する。「着手」は割当の事象か、作業単位に結ばれた最初の PR の作成の早い方。閾値は企画書の「滞留と判定する経過時間」、実績が貯まったら IMPL-0374 の 85 パーセンタイル。通知は作業単位への Issue のコメントで、担当者と価値責任者の席のアカウントへメンション
- 通知の経路を Slack などへ替えるのは採用者の任意。閾値が両方とも無いときは未達として表示。強制層の変更なので AI維持管理者の承認を待つ

## D. 降ろす。ただし議長の突合を条件にする

**IMPL-0342(1名の体制の自己の任命)**
- テンプレートは本文より厳しい。いまのテンプレートでは個人事業主の後継者が適合できない
- changeLog に「自己の任命」の行。受け付ける条件は、変化点の後の体制の内が1名・名簿に組織上の任命権者が無い・前任の離脱の行がある・D-0「決裁の権限の出所」が個人事業主か1名で代表権を持つ法人の記載、のすべて。保証の開示の項目7 に必ず表示
- 突合の条件: ADR-0122 決定1 と 3.13.3 の例外が両立するか。両立しないなら所有者へ上げる

**IMPL-0462(価値責任者の所属)**
- 所属の属性を**名簿の行**に置く(`organization: orderer|vendor`)。必須は q-dev-form が受託のときだけで、価値責任者の席の責任者が vendor なら拒む。席と受信箱には持たせないので ADR-0069 決定2 を覆さない
- 条件: #357 の構成の設計と衝突しないかを議長が確かめる。#357 が別の形を決めているなら scheduled に残し、`issue=` を #357 へ付け替える

## 本件の ADR に書くべき決定

1. 17件の行き先
2. adopter とする部分の表(0174 の件数と確かめる者、0374 の既定以外の述語、0377 の費用の入力)。0175 の表現は scheduled に残す
3. ADR-0040 を補う: template-fields に様式ごとの正本(`standardFile`)
4. 第6章テンプレ6 に停止条件の行。G-1 通過済みの企画書は gap
5. 判断の記録の種別(3.5.5 要求事項4 の委任による)
6. 提示の回し方と記録の様式の固定を分ける
7. フローの観測の「着手」と完了の既定の述語、閾値の出所の順、通知の経路
8. 名簿の所属の属性と ADR-0069 決定2・#357 の関係
9. 1名の体制の自己の任命の受け付け条件と ADR-0122 決定1 との突合
10. 採らない案: 探索の記録の様式の新設、試行前チェックリストの第6章への移設、機械による文言の言い換え、費用の欠落を「算定できない」で出すこと、席への所属の属性
11. scripts/gate の変更は AI維持管理者の承認待ちをコミットに書く
