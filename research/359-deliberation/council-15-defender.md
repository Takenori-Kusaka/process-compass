## 議題1 IMPL-0342 1名の体制の自己の任命

**結論: 降ろす。条件は ADR-0122 決定1(IMPL-0483)と同じ水準にそろえ、法的な形態の宣言の欄など新しい属性は足さない。**

いまの状態が厳しすぎる側の未達であることは反対の委員の言うとおりです。ただし、厳しすぎる側の未達も信頼性を損ないます。

- 行き止まり: 個人事業主の事業を承継した者(新任の決定者)は、本人の上に任命権者がいません。本文 3.13.3 はこの場面を例外として認めていますが、テンプレートは拒みます。適合する手段がありません。ADR-0122 は「例外なしの禁止(2-F)」を、1名の体制で唯一の決定者が自分の行を直せない行き止まりを作り、迂回を誘うだけで統制を強めない、という理由で退けました。同じ理由がここにも当たります
- 迂回の誘い: 拒まれた採用者は、別のアカウントを「組織上の任命権者」として名簿へ足すことで通れます。この経路では自己の任命が開示されません(ADR-0122 影響の「同じ根の3経路」と同型)。禁止を続けるほど、開示されない自己の任命が増えます
- 抜け道の懸念(大きな組織の中の1名のチーム): 本文 3.13.3 は「より大きな組織の中の1名の体制は…当たらない」と明記済みです。偽って例外を使うことは、D-0「決裁の権限の出所」の記載と保証の開示の項目7 に必ず残ります。機械は「上に任命権者がいない」ことを確かめられません。これは IMPL-0483 も同じで、ADR-0122 は「準拠テンプレートは、その記載があるかを確かめる」で受け付け、残りを EV-0241・EV-0243 で開示しました。IMPL-0342 だけに一段強い要件を課すと、同じ根の2つの例外で要件が食い違います(議題 1-c)
- 外部の型: COSO・PCAOB・GAO・J-SOX は、分離できない体制を認めた上で代替の統制と開示を求めます(FX-13・FX-15・FX-19)。禁止で終わる枠組みはありません

**最小で譲れる条件(すべて)**

1. 受け付けは、変化点の後の体制の内が1名、名簿に組織上の任命権者が無い、前任の離脱の行がある、D-0「決裁の権限の出所」が空欄でない、の4つがそろう場合に限る(起案の条件のうち、記載の中身の語の一致は求めない)
2. 変化点の記録に種別「自己の任命」を残す。保証の開示の項目7 へ機械が生成して出し、採用者が抑止できない
3. 体制の内が2人以上になった時点で、例外の行は以後の変化点に使えない(ADR-0122 決定1 の「行ごとに判定」と同じ)
4. テンプレートの錠を緩める変更なので、needs-platform を経て AI維持管理者の承認を待つ(テンプレートの CLAUDE.md。新しい義務ではなく既存の手続)

**採らない案**

| 案 | 採らない理由 |
| --- | --- |
| D-0 に法的な形態(個人事業主 / 1名代表の法人)の宣言の欄を足し、空欄なら拒否する(反対) | 「決裁の権限の出所」の記載と同じ事実を2か所に書かせるだけで、確かめられる事実は増えない。自己申告の欄は偽れる。IMPL-0483 には無い要件で、同じ根の例外の条件が食い違う |
| 登記事項の参照を必須にする | 法人には登記がある(FX-17・FX-18)が、個人事業主には相当する公的記録が見つからなかった。必須にすると本文が例外として名指す個人事業主だけが適合できない。法人で登記を引くことは採用者の任意(推奨にも書かない。外部の確認の手段の選択は採用組織の事項) |
| `plan=adopter` にする | 採用者がテンプレートの錠を自分で緩めることになる(反対の委員に同意)。依存先も名指せない(ADR-0084 決定4) |
| 降ろさず待つ(現状維持) | 上の行き止まりと、開示されない迂回を残す。待つ条件(宣言の欄など)は上で退けたので、待っても条件はそろわない |

## 議題2 IMPL-0462 受託の構成で価値責任者を発注側に置く

**結論: 名簿へ所属の属性を足さない。`plan=scheduled` のまま `issue=357` へ付け替え、降りていない規定として表示し続ける。確認は契約の体制の条項による人の確認に委ねていることを、既存の出力の1行で開示する。**

- ADR-0069 決定2 の範囲(2-a): 決定2 の文言は「席と受信箱」です。名簿は文言の外にあります。しかし同 ADR の採らなかった案は、宛先を固定しない理由に「席に組織の所属の属性を足す必要がある」ことを挙げ、所属の属性を持たないことを前提に設計しています。名簿の行の所属で席の責任者を拒めば、効果は席に所属を持たせるのと同じです。文言の隙間を使うのは迂回です(反対に同意)
- 自己申告の信頼性(2-b): `organization: orderer|vendor` の2値は実務に合いません。多重の下請では元請が発注側でも受注側でもあります。出向・常駐の者、共同事業体、発注側がベンダの者を自組織へ招く運用もあります(FX-28 のプラットフォームの属性とも一致しない)。誤った値で拒めば、正当な体制が行き止まりになります。偽った値では通ります。「検出した」と見せて、実際は自己申告を写すだけです
- 外部の実務(2-d): モデル契約は、PO を発注側が選任することを契約の体制の条項と契約前のチェックリストで確かめます(FX-21・FX-23・FX-24)。名簿の属性を機械で検出する例はありません。所属は契約で決まり、リポジトリの外にあります
- #357 との関係(2-c): #370 の裁定が所属の欄の設計を #357 の構成の欄へ送りました。本件で名簿の欄を決めると、#357 の設計を先取りします

**最小で譲れる条件**

1. `q-dev-form` が受託(outsourcer・vendor)のとき既に出している受け渡しの所在の1行(generate-profile.mjs:4168-4180)の隣に、「価値責任者を発注側に置くこと(第8章 軸D)は機械で確かめない。契約の体制の条項で確かめる」の1行を出す。新しい欄・新しい検査は足さない
2. マークの note に、機械で確かめない理由(所属が契約で決まること・2値で表せないこと)と、確かめる経路(G-2 の判定者が契約の体制の条項を読む)を書く。`state=undelivered` を保つ

**採らない案**

| 案 | 採らない理由 |
| --- | --- |
| 名簿に `organization` を足し、受注側なら拒む(起案) | ADR-0069 決定2 の迂回。2値の自己申告で誤検出(行き止まり)と見逃しの両方が出る |
| 名簿の `team` に発注側・受注側を書かせる | 同じ迂回(反対に同意)。`team` の意味を変える |
| `plan=adopter` にする | #357 の設計を閉じる。規定は課したまま残るが、テンプレートが関与しない理由を本件で決める根拠が無い |
| AI-SLA 合意確認書・G-2 の様式に「価値責任者の所属」の必須欄を足す | 第6章への新しい欄で、採用者の新しい記入の義務になる。#357 の構成の欄の設計と二重になりうる。#357 で併せて審議する |

## 議題3 IMPL-0174 記述の内容の四半期ごとの抽出

**結論: 抽出の仕組みは降ろす。件数・確かめる者は本文で「組織が定めて記録する。本標準は定めない」と明記し(課さないと決めた事項)、テンプレートは既定値を持たない。結果の扱いは人の記入とし、自動の切替規則は課さない。**

- 件数を本文で定めない理由(3-a・3-b): 件数を規範として定める外部の規格は見つかっていません(FX-1・FX-3)。目安の表は2〜20件の幅で食い違い、根拠の実証がありません(FX-4〜FX-7)。少ない件数では、割合の高い形骸化しか検出できません(FX-12 の算出)。何を検出したいかは、記録の量と危険の大きさで組織ごとに変わります
- 本文の先例: 第3章(roles-responsibilities.md:226)は、AI なしの確認の事例の件数を「組織が定めて記録する。本標準は件数を定めない。下限も置かない。書き漏らしではなく、課さないと決めたもの」と書いています。ADR-0084 決定4 の表も、実証の無い値(IMPL-0222・0312)を採用者に委ねています。同じ型で書けば、反対の委員の言う「本文の定義の欠け」は「課さないと決めた」に変わり、テンプレートが値を発明する危険もなくなります
- 抽出者の独立(3-d): 外部の規範は、小規模組織で完全な独立を求めません(FX-2・FX-11)。1〜2名の体制で独立の確かめる者を求めると、抽出そのものが行えず、行き止まりになります。守るべきは「当事者に選ばせない」こと(ADR-0116 決定5、FX-9)で、これは種を記録した乱数の抽出で機械が担えます
- 結果の扱い(3-c): ISO 2859-1 の切替規則(FX-10)は製品のロット検査の規則で、記録の品質への適用は類推にすぎません。自動で件数を増やす・抽出を止める規則を課すと、根拠の無い新しい義務になります

**最小で譲れる条件**

1. 機械が四半期の母集団(テンプレートが定義を開示する。5.7.4 の検査の対象とする記録)から、記録した種で抽出する。当事者は選べない
2. 結果の記録に、件数・確かめた者・見つけた記述・扱い(是正の記録へ回したか、回さない理由)を人が書く。確かめた者が記録の当事者なら、その旨が記録に残る(禁止はしない)
3. 件数が構成に未設定、または前の四半期の記録が無いときは、/pit に未達として出す。出荷は止めない
4. 実質の無い記述を見つけたときの扱いは、既存の是正の記録(IMPL-0135 の起点「統制の弱化の検知」)へ回せることを注記する。新しい起点は作らない

**採らない案**

| 案 | 採らない理由 |
| --- | --- |
| 本文で件数を定める(EV 付き) | 外部に規範の値が無く、目安も食い違う。EV を付けても、採用者には値の義務として読まれる |
| テンプレートに既定の件数を置く | 本文が定めない値を、既定として規範に見せる(反対の条件9 と同じ懸念) |
| 確かめる者に独立を課す | 1〜2名の体制で行き止まり。外部も「実行可能であれば」(FX-2) |
| 不合格で件数を増やす切替規則 | 類推にすぎず、根拠の無い新しい義務 |

## 議題4 IMPL-0377 必達基準2 の到達の見込みの算定

**結論: IMPL-0374(完了スループット)より先に降ろさない。降りるまでは「降りていない」の表示を続ける。SC-M の母集団は採用者が名を選べるラベルで示し、スコープの幅の入力は課さない。費用の実績の入力だけを adopter に分ける。**

- 順序(4-a): 7.7.3 は「区分は…判定者は区分を書き換えません」と定めます。機械が誤った区分(閉じた件数をスループットに数えた丙など)を出すと、判定者は直せず、7.7.4 の上程や案件の中止の材料が誤ります。「算定が無い」と表示するほうが信頼できます。予測は完了スループットを入力とします(FX-29・FX-31)
- SC-M の示し方(4-b): 本文は「未完了の SC-M の作業単位の個数」と定めます。ラベルで足ります。ラベルの名はテンプレートが固定せず、構成(`flow.scopeLabels`)で採用者が選ぶ。外部の道具の幅の入力(FX-29)は本文に無い要件で、課すと新しい義務になります
- 費用(4-c): 費用の実績は会計の基盤に依存します(IMPL-0277 と同型の具体の依存。ADR-0084 決定4 の水準を満たす)。採用者に求めるのは「単位期間あたりの費用の実績の入力の所在を構成へ書くこと」だけとする

**最小で譲れる条件**

1. 計画は IMPL-0374 → IMPL-0377 の順とし、0377 の note に 0374 への依存を書く。0283 は独立に進めてよい
2. 費用の入力が無いときは、期間の組の区分だけを出し、費用の組は「費用の入力なし」と出す。「算定できない」(単位期間が3つ未満の意味)を流用しない(起案に同意)
3. SC-M のラベルが1件も無いときは「対象外」と推定しない。「SC-M を示すラベルが無い」と出す(本文の「対象外(SC-M なし)」は実測が無い間の値で、ラベルの欠けとは別)

**採らない案**: 0374 より先に閉じた件数で算定する(誤った区分を判定者が直せない)。スコープの幅と分割率の入力を課す(本文に無い義務)。費用の組を含めて全体を adopter にする(件数の算定はリポジトリの中で完結し、理由が立たない)

## 議題5 IMPL-0467 前提の判定記録を読めない着手

**結論: いまの「判定できない」(終了コード4)で止める振る舞いは安全側なので保つ。(a)(b) は第6章の既存の様式(テンプレ4 の判定記録・テンプレ2 の判断記録)のどれで読むかを本文で定めてから降ろし、新しい様式は作らない。(c) は本文で、組織が事前に定めた類型の一覧を前提とみなす形を選べるようにする。一覧を持たない採用者は、いまの停止のまま。**

- (a)(b) の置き場(5-a): 3.5.5 要求事項4 は媒体と置き場をテンプレートへ委ねます。しかしテンプレートの様式は第6章の部分集合です(ADR-0040)。テンプレートだけで新しい記録の種別を作ると部分集合を外れます。テンプレ4 は判定「通過 / 差し戻し」と差し戻し理由の欄を既に持ちます。IMPL-0381 と同じく、ゲート欄の値(または判断記録の種別)を第6章で定めれば、新しい様式は要りません。承認者への追跡(FX-34・FX-36)も、記名の欄で満たせます
- (c) の前提(5-b): 機能へ対応づけない作業単位(依存の更新・文書の修正など)を一律に止め続けると、終了コードを無視することを人が覚えます(反対の委員の形骸化の指摘)。一方、テンプレートが「needs-po を経れば前提あり」とみなすのは、本文に無い定義の発明です。ITIL の標準変更(FX-38)は、事前に承認した類型の一覧を前提にする型です。類型と前提とする判断は組織が決める事項なので、本文は「一覧を事前に定めて記録したときに限り、それを前提とみなす」と選べる形にとどめ、類型を列挙しない
- 形骸化(5-c): 「判定できない」で止めた件数を /pit に数えて表示するのは、止め方を緩めずに迂回の兆候を見せる手段です(FX-37)。表示だけで、合否には使わない

**最小で譲れる条件**

1. (a)(b) は、第6章で読む様式と欄の値が定まるまで `undelivered` を保つ。定まった後は、記名者が席の責任者のアカウントと一致することを読む
2. (c) の一覧は任意。一覧の承認の記録(誰が・いつ)が無い類型は前提とみなさない。一覧が無い採用者に、新しい記入を求めない
3. 停止の件数の表示は /pit の注記に限り、終了コードと出荷の判定を変えない

**採らない案**

| 案 | 採らない理由 |
| --- | --- |
| テンプレートだけで記録の種別を足す(起案 (a)(b)) | 第6章の部分集合を外れる(ADR-0040)。第6章に置けば済む |
| needs-po を経た作業単位を前提ありとみなす(起案 (c)) | 本文に無い定義の発明。価値責任者の判断の記録が無いまま着手できる |
| (c) の類型を本文で列挙する | 作業単位の類型は組織の運用で決まる。列挙すると合わない組織が行き止まりになる |
| 「判定できない」を警告へ下げて着手を許す | 統制が消える方向。要求事項5 に反する |
