## 議題1 IMPL-0342 1名の体制の自己の任命

**結論**: 降ろす。ただし「閉じた条件+外部で確かめられる根拠の参照+抑止できない開示」の3つを揃えた形に限る。条件は IMPL-0483(ADR-0122 決定1)と同じ判定の型にそろえる。

**理由**
- 例外は本文がすでに決めている(roles-responsibilities.md:2034、ADR-0087 決定5、EV-0179)。テンプレートが本文より厳しいままだと、個人事業主の後継者は適合できない。ADR-0122 は「例外なしの禁止」を、行き止まりが迂回を誘うとして退けた(同 ADR の採らない案 2-F)。同じ理屈がこの場面にも当たる
- 外部の統制の枠組みは、職務分離ができない小規模な体制に対して、禁止ではなく代替の統制と開示を求める(FX-13・FX-15・FX-19)
- 反対委員の「大きな組織の中の1名のチームと区別できない」は正しい。ただし、名簿の人数で見分けないことで塞げる。法人は、自己の選任が株主の決議の議事録と登記に残る(FX-17・FX-18)。根拠の参照を求めれば、第三者が確かめられる形になる

**実装の要点**
- 第6章 D-0(deliverable-templates.md の D-0 表)と `template/templates/00-d0-governance.md:334`: 「決裁の権限の出所」の隣に、行「体制の法的な形態」を足す。値は `個人事業主` / `1名で代表権を持つ法人` / `その他` から選ぶ。法人の場合は、決議の議事録か登記事項の所在(登記の日付と、代表権を持つ者が1名であること)を同じ行に書く。個人事業主の場合は、事業の主体が本人であることの根拠(開業の届出など)の所在を書く
- `template/scripts/init/generate-profile.mjs:2707-2715`: 変化点の行の種別「自己の任命」を受け付ける。条件はすべて満たすこと。(1) 変化点の後の体制の内が1名 (2) 名簿に組織上の任命権者がいない (3) 前任の離脱の行が同じ変化点の記録にある (4) 法的な形態が上の2つのどちらかで、根拠の所在が空欄でない。1つでも欠ければ、いまの拒否を保つ。ADR-0122 Y-1 と同じく行ごとに判定し、他の行を束ねた変化点は受け付けない
- 保証の開示の項目7: 自己の任命は機械が生成して表示する。採用者の設定で消せない
- `templates/00-d0-governance.md:335・442` の未達の記述を改める。強制層の変更なので needs-platform を経て、AI維持管理者の承認を得る

**残る危険**: 法的な形態を偽って宣言することは、機械では止められない。止めるのは、根拠の所在を読む外部の確認者と内部監査(3.13.5)である。例外の体制で外部の確認を推奨にとどめる点は、ADR-0122 決定1 に合わせる。暫定 EV-0251(E0)で開示する。

**採らない案**
- 降ろさない(反対): 本文が認めた例外をテンプレートが永久に塞ぐ。根拠の参照と開示の機械による生成を条件にすれば、反対委員が求めた条件(宣言の欄・開示の生成・needs-platform・IMPL-0483 との一致)はすべて満たせる。待つ理由が残らない
- 名簿の人数(1名)だけで受け付ける(軽の起案): 大きな組織の1名のチームが抜け道に使える
- adopter: 採用者が自分で錠を緩めることになる(反対委員と同じ理由)

## 議題2 IMPL-0462 受託の構成で価値責任者を発注側に置く

**結論**: 構成・席・名簿には所属を持たせない。様式 08(AI-SLA 合意確認書)第9節に行「価値責任者の席の責任者と、その者の属する組織」を足して、締結時に両当事者が記録する。検査は、行が欠けていないこと、「発注側」であること、名簿の価値責任者の席の責任者と氏名が一致することだけを確かめる。所属が本当かどうかは、G-2 の判定者が契約の体制の条項と照らす。

**理由**
- ADR-0069 決定2 が禁じたのは「席と受信箱」に所属の属性を持たせることである。名簿の `team` に所属を書かせれば、決定2 の迂回になる(反対委員の指摘に同意する)。名簿の行に `organization` を足す軽の起案は採らない
- すでに同じ型の前例がある。ADR-0087 決定2 は、AI維持管理者の属する組織を構成ではなく様式 08 第9節に記録させた(`08-ai-sla.md` の第9節の表)。価値責任者の所属も同じ置き場に置くと、決定2 にも #357 の構成の欄の設計にも触れない
- 外部の実務も、所属を機械で検出しない。契約の体制の条項(誰が PO を選任するか)と、契約前のチェックリストで確かめる(FX-21・FX-23・FX-24)。プラットフォームの「外部の協力者」という属性は、発注側・受注側の区別と一致しない(FX-28)

**実装の要点**
- 第6章 テンプレ8 第9項と `template/templates/08-ai-sla.md` 第9節に、上の行を足す。`template-fields.yaml` の t8 に登録する(ADR-0040)
- `template/scripts/gate/next.mjs:736-751` の委託・受託の注記を広げる。q-dev-form が受託・委託のとき、行の欠け・空欄・「受注側」・名簿の価値責任者の席の責任者との氏名の食い違いを出す。G-2 の前は、満たさないものとして出す。締結済みの案件は gap として出す
- `gates/G-2.md`: 判定者は、この行を契約の体制の条項と照らす、と書く(check=manual)
- マークは、行と氏名の照合を machine、所属が本当かどうかを manual として分ける

**残る危険**: 双方が合意したうえで、偽って「発注側」と書けば、検出できない。ただし、そう書いた記録が両当事者の合意として残る。暫定 EV-0252(E0)で開示する。#357 が構成に所属の欄を置くと決めた場合は、その ADR で様式との二重化を整理する。

**採らない案**: 名簿の行の `organization`(決定2 の迂回)/`issue=357` へ付け替えるだけで止めておく(#357 は外部の確認者と独立の欄を扱う Issue で、価値責任者の所属を議題に持たない。付け替えると規定が宙に浮く)/GitHub の組織のメンバーの属性で判定する(FX-28 の不一致)

## 議題3 IMPL-0174 記述の内容の四半期ごとの抽出

**結論**: 母集団・選び方・件数・確かめる者・結果の扱いを、本文 5.7.4 に定める。テンプレートは仕組みを降ろす。件数は EV で開示する。

- 母集団: その四半期に作成した判定記録の、人が記入する欄(第4章の判定記録とテンプレ4 の人が判断する項目)
- 選び方: 機械が、記録した種で無作為に選ぶ。種は四半期の識別子と、records ブランチの四半期末のコミットから決まる。当事者は選べない(ADR-0116 決定5、FX-9)
- 件数: 母集団が5件以下なら全件。それより多ければ5件。前の四半期に「実質が無い」記述が1件でもあれば、次の四半期は10件にする(FX-10 の切替規則の型)
- 確かめる者: 抽出した記録の記入者でない者(H.3 の当事者の語)。1〜2名の体制で当てられないときは記入者本人が確かめ、自己の確認として記録する(FX-2・FX-11)
- 結果: 実質が無いと判断した記述は、元の判定者へ差し戻しの所見として届ける。判定を自動では取り消さない(5.7.4 要求事項1)。所見と件数は四半期の記録に残す

**理由**: 件数を採用者に委ねると、0件か1件を選ぶ自由が残り、規定が空になる。件数を規範として定める外部の規格は無い(FX-1・FX-3)。目安の幅は2〜20件(FX-4・FX-6・FX-7)。FX-12 によると、5件で0件の場合に言えるのは「割合が37%以下」までである。そのため本文に、検出の対象は広がった形骸化で、まれな欠落ではないと書く。まれな欠落は、要求事項3 の機械検査と G-6 が受け持つ。

**実装の要点**
- 本文 human-ai-boundary.md:903 を、上の5項目の要求事項の表に改める。暫定マーク EV-0250(E0。見直し 2027-05。差し替え条件は、2四半期分の所見率と、5件と10件のときの所見の有無の比較)を付ける
- `template/scripts/gate/records.mjs --sample <四半期>`: 種・母集団の件数・選んだ記録を `records/samples/<四半期>.md` に書く。結果の様式は、記録の所在・確かめた者・実質の有無・所見とする
- `next.mjs`: 四半期の末から30日を過ぎても抽出の記録が無ければ、/pit に出す。前の四半期の所見から、次の件数を出す
- マークは、抽出と期限の表示を machine、実質の判断を manual として分ける

**残る危険**: 5件では、まれな欠落は見つからない(本文で開示する)。自己の確認は、確認の価値が低い。

**採らない案**: 件数と確かめる者を adopter にする(軽の起案。依存先が組織の外に無く、adopter の理由が立たない)/統計的な件数(22〜59件。FX-12)を課す(四半期の母集団がそれより小さい案件が多い。目的とも合わない)/判断による抽出(FX-9)

## 議題4 IMPL-0377 必達基準2 の到達の見込みの算定

**結論**: IMPL-0374 と1つの実装の単位として降ろし、IMPL-0374 を先に delivered にする。SC-M の母集団は、作業単位のスコープのラベル(`flow.scopeLabels`)で示す。企画書のスコープ3層の一覧と件数を突き合わせ、合わなければ表示する。費用の組の算定は降ろす。単位期間あたりの費用の実績の入力だけを adopter に分ける。

**理由**
- 算定の入力は、完了スループットの実績である(ADR-0099 決定1・決定3、FX-29・FX-31)。入力が無いまま算定を delivered にすると、見込みの記録が空のまま「降りている」と表示される
- ADR-0099 決定1 は「比べる対象の作業単位の個数」を割る。そのため母集団は、作業単位の集合として機械が数えられなければならない。ラベルは件数を点で与えるだけなので、企画書の一覧との突合で、付け忘れを出す。幅で与える案(FX-29)は ADR-0099 の式を変えるので採らない
- 費用は、期間の見込みに単位期間あたりの費用の実績を掛けて求める(ADR-0099 決定1、FX-30)。実績は採用者の会計の基盤にあり、依存先を名指せる(IMPL-0277 と同型)

**実装の要点**
- IMPL-0374: 取り込んだ PR が閉じた作業単位か、完了の判定の記録がある作業単位を完了に数える。それ以外は「閉じたが完了に当たらない」として並べる(反対委員の述語。閉じた操作だけでは数えない。ADR-0098)
- IMPL-0377: `scripts/gate/flow` の算定(端は ADR-0099 決定3 の最小値と最大値)が、見込みの報告の Issue へ組ごとの区分を書く。ラベルの付いた SC-M が0件なら算定せず、記録が無いものとして出す。ADR-0099 決定1 のとおり、記録が無ければ必達基準2 を満たさない
- 費用の実績が未入力の組は、「算定できない」とする(ADR-0099 決定3 の組の規則)。案件の区分は甲にならない。2期続けば /pit に出す
- 強制層の追加なので needs-platform を経る

**残る危険**: ラベルの付け忘れは、企画書の一覧が古いと検出できない。区分の閾値は EV-0200・0201 のまま。

**採らない案**: IMPL-0374 の前に降ろす(軽の起案)/見積の幅で実績に代える(FX-29 の estimate 方式。実績ではない)/SC-M が示されないとき「算定できない」で通す(付けなければ不合格を免れる抜け道になる)

## 議題5 IMPL-0467 前提の判定記録を読めない着手

**結論**: 第6章テンプレ4 に「ゲートでない判断の記録」の種別を定め、(a) 出荷判定者の差し戻し、(b) 価値責任者の判断と事業決裁者の決裁を、そこに記録させる。(c) は本文 3.5.5 に前提を定める。機能へ対応づけない作業単位の前提は、価値責任者の判断の記録とする。判断は類型の単位で前もって与えてよく、作業単位はその記録を引く。

**理由**
- 承認の記録には、誰が承認したかを追跡できることが要る(FX-34(g)・FX-36)。ラベルの遷移は記名に当たらない(3.5.5 要求事項4)。様式を第6章に先に置く(ADR-0040)。この2点は反対委員に同意する
- (c) をテンプレートで定めると、本文に無い規範を発明することになる。そのため本文で定める。類型の単位で前もって与える判断は、ITIL の標準変更(事前に承認した一覧。FX-38)と同じ型である。作業単位ごとの判断を求めると承認の経路が遅くなり、迂回が増える(FX-37)

**実装の要点**
- 第6章テンプレ4 と `templates/04-gate-record.md` に、種別「判断の記録」を足す。欄は、対象(作業単位か類型)・判断した席・記名・判断・理由・日時とする。`template-fields.yaml` の t4 に登録する
- 本文 roles-responsibilities.md:745 の後に、要求事項6 として (c) の前提を足す
- `next.mjs --pickup`(:500-592): (a)(b)(c) の記録を、席のアカウントと記名者の一致で読む。「判定できない」で止めた件数を /pit と出荷の証跡の集約に数えて出す(FX-37)
- 3つの止め方を同じ実装の単位で解き、様式が無いまま止め続ける期間を作らない

**残る危険**: 類型が広すぎると、前提が名ばかりになる。類型の定め方は内部監査が確かめる。

**採らない案**: テンプレートの側で、needs-po を経たことを前提とみなす(軽の起案。本文に無い定義の発明)/ラベルの遷移の履歴を記録とみなす(記名が無い)/様式が揃うまで「判定できない」で止め続ける(形骸化する。5-c)

## 本件の ADR(ADR-0125)に書く決定

1. 1名の体制の自己の任命の受け付け条件(法的な形態の欄・根拠の所在・行ごとの判定・開示の機械による生成)。ADR-0122 決定1 と同じ判定の型にそろえる。EV-0251
2. 価値責任者の所属は様式 08 第9節に置き、構成・席・名簿に持たせない。ADR-0069 決定2 と ADR-0087 決定2 の適用で、#357 との関係を書く。EV-0252
3. 5.7.4 の抽出の母集団・選び方・件数(5件、所見があれば次は10件)・確かめる者・結果の扱い。検出できる範囲の限定を明記する。EV-0250
4. IMPL-0374 を IMPL-0377 より先に降ろす。完了の述語、SC-M のラベルと企画書の突合、ラベルが無いときは不合格の側に倒すこと、費用の実績の入力だけを adopter にすること
5. 第6章テンプレ4 の「判断の記録」の種別と、3.5.5 要求事項6(機能へ対応づけない作業単位の前提。類型の単位で前もって与えることを許す)
6. 採らない案(上の各議題の表)。強制層の変更は needs-platform と AI維持管理者の承認を経ること
