## 議題1 IMPL-0342 1名の体制の自己の任命(3.13.3)

**結論: 降ろす。ただし受け付けの条件を ADR-0122 決定1 と同じ検証の水準で閉じ、行ごとの判定(Y-1)をそのまま当てる**

- 規格との整合: 外部の統制の枠組みは、職務分離ができない小規模の体制を禁止せず、**代替の統制と開示**を求める(COSO の owner-manager の直接の監督 FX-13、PCAOB AS 2201 FX-15、GAO Green Book FX-19)。3.13.3 の例外(記録・項目7 への表示)はこの型に合う。降ろさないと、本文が認めた例外を準拠テンプレートの利用者だけが使えない。個人事業主の後継者は、テンプレートの錠を自分で外すか不適合を受け入れるしかない。記録の無い迂回を招く方が、信頼性を損なう(1-d)
- 既存の条項との整合: ADR-0122 決定1 は「根拠は、自己の任命の例外と同じく D-0 の『決裁の権限の出所』へ書く。準拠テンプレートは、その記載があるかを確かめる」と、**2つの例外の検証の水準を明示的にそろえている**。反対の委員の「法的な形態の宣言の欄・外部の確認」を自己の任命にだけ課すと、同じ根の2つの例外で水準が食い違う。ADR-0122 決定2 は例外の体制で外部の者による確認を推奨にとどめた。登記の確認を義務にすると、この決定と矛盾する
- 反対の委員の懸念(大きな組織の中の1名のチームとの区別)への答え: 3.13.3 自身が「より大きな組織の中の1名の体制は…当たらない」と書き、形態を2つに限っている。区別の根拠は名簿ではなく D-0 の記載である。決定者が記名した D-0 に偽の形態を書くことは記録の改ざんで、内部監査(附属書H)と保証の開示の読み手が見る対象になる。機械が確かめる範囲を「記載がある」までと開示すれば、規範として書ける
- 条項の形(本文は変えない。テンプレートの受け付け条件を IMPL-0342 の note と ADR-0125 に書く)
  - 受け付けるのは次のすべてを満たす行だけ: 変化点の後の体制の内が1名 / 名簿に組織上の任命権者が無い / 前任の決定者が体制から外れる行が同じか前の変化点にある / D-0「決裁の権限の出所」が「個人事業主」か「1名で代表権を持つ法人」を挙げている(テンプレ0 の記入例 :307 にある語を使い、新しい欄は作らない)
  - 自己の任命の行は、ADR-0122 決定1 の行ごとの判定に従う。当事者以外が記名できる行と束ねた変化点は受け付けず、分けさせる(#432 再確認 Y-1)
  - changeLog の種別「自己の任命」と、保証の開示の項目7 への表示は機械が生成し、抑止できない
  - 法人は登記上の代表者の参照を D-0 へ書くことを推奨にとどめる(FX-17・FX-18。ADR-0122 決定2 と同じ扱い)
  - 錠を緩める向きの変更なので、テンプレートの needs-platform を経て AI維持管理者の承認を得る
- 根拠水準: 値を置かないので EV は要らない。残る危険(形態の宣言が事実かは機械で確かめない)は note に `check=manual` の部分として開示する
- 採らない案: 法的な形態の専用の欄の新設(テンプレ0 に欄が無く ADR-0040 に反し、ADR-0122 と水準が食い違う)/ 登記の確認の義務化(ADR-0122 決定2 と矛盾)/ `plan=adopter`(採用者に錠を緩めさせる。2委員とも退けた)/ 降ろさずに待つ(本文の例外が使えない状態を残す)

## 議題2 IMPL-0462 受託の構成で価値責任者を発注側に置く(第8章 軸D)

**結論: 本件では機械の検出を降ろさない。`issue=357` へ付け替え、それまでの確認の経路を note に名指す。ただし理由は「ADR-0069 決定2 の迂回」ではなく「ADR-0040 と ADR-0088 の送り先」である**

- 2-a ADR-0069 決定2 の範囲: 文言は「**席と受信箱に**、組織の所属を表す属性を持たせること」である。名簿は含まない。標準の様式は名簿(テンプレ0 表5-2)に**所属の欄をすでに持つ**(ADR-0082。10名以上で必須)。名簿の所属を「決定2 の迂回」とする反対の委員の読みは広すぎる。起案の委員の読みが文言に合う
- それでも本件で降ろさない理由
  - 表5-2 の所属は部門の意味で置かれた欄で、発注側・受注側の区別を定義していない。`organization: orderer|vendor` は第6章に無い値で、テンプレートが値を発明することになる(ADR-0040 決定1・4)
  - ADR-0088 は「名簿の欄(直属の上長・**所属の法人**・部門・外部の評価者)」の構成への降ろし方を #357 へ送った。所属の法人の欄はそこで設計する。本件で別の形を決めると、#357 の設計と二重になる
  - 名簿の `team` に発注側・受注側を書かせる運用も、同じ理由で禁じる(欄の意味を文書化なしに変える)
- 2-b 自己申告の検出の信頼性: 外部の実務は所属を機械で検出せず、**契約の体制の条項**で確かめる(IPA アジャイル版モデル契約 FX-21、経産省/IPA モデル契約 FX-23、JISA FX-24)。GitHub の outside collaborator の属性(FX-28)は、発注側が受注側を組織へ招く運用で一致しない。採らない
- 2-d それまでの確認の経路: 条項の方向は外部と一致する(FX-21・FX-26)。#357 までは、AI-SLA 合意確認書(テンプレ8)の締結の時点で、価値責任者の席の責任者が発注側の人であることを締結者が確かめる、と note の「確かめる者」に書く。新しい義務は足さない(既存の軸D の表の規定を、確かめる時点で名指すだけ)
- 根拠水準: 値を置かないので EV は要らない。FX-22(PO の職務をベンダへ委ねない)は二次要約で原典未読のため、本文へ引かない
- 採らない案: 名簿への `organization` 値の新設(第6章に無い)/ プラットフォームの属性による検出 / `plan=adopter`(#357 の設計を閉じる)/ ADR-0069 決定2 を名簿へ広げる読み(文言に無い)

## 議題3 IMPL-0174 記述の内容の四半期ごとの抽出(5.7.4)

**結論: 本文を改めてから降ろす。主体・母集団・選び方・件数・結果の扱いを 5.7.4 に書き、件数は既定値として EV で開示する。採用者へ委ねない**

- 規範としての欠け: いまの文は ですます調の地の文で、主体も件数も結果の扱いも無い。満たしたかを誰も判定できない。採用者へ件数を委ねると、1件でも0件でも適合になり、検証可能性が無い。本標準は値を置くとき「既定値+置き換えの条件+EV」(第1章 1.7.7。ADR-0099 決定3 の端の取り方が先例)の型を持つ。この型に載せる
- 規格との整合
  - 件数を規範で定める規格は無い。ISO 19011 A.6 と PCAOB AS 2315 は件数を決める要因だけを定める(FX-1・FX-3)。目安は2〜20件の幅(FX-4・FX-6・FX-7)で、根拠の実証は示されない → 値は EV の対象
  - 判断で選べば統計的抽出ではない(FX-9)。抽出は**記録された種による無作為**とし、ADR-0116 決定5(当事者に選ばせない)をそのまま当てる
  - 非統計的な少数の抽出は母集団へ投影できない(FX-8・FX-12)。5件で0件でも、90% の上限は 37% にとどまる。したがって**この抽出が検出できるのは、割合の高い形骸化(多くの記録が中身を欠く状態)だけ**であると本文に書く。まれな欠落の検出を目的にしない
- 条項の形(5.7.4 末尾の文を要求事項の表へ移す)
  - 主体: 監査担当(附属書H H.3 の内部監査の一部として行う)。抽出された記録の判定者・作成を指示した者は確かめる者にならない。1〜2名の体制は H.3 と同じ扱い(外部の監査担当が母集団を受け取る形、または当事者が確かめた旨の開示。FX-2・FX-11)。新しい席は作らない
  - 母集団: その四半期に作成されたゲート判定記録の、人が書く欄(テンプレ4 の表の右側の欄)。母集団の一覧を当事者が示すことは妨げない(ADR-0116 決定5)
  - 件数の既定値: 四半期ごとに5件。母集団が5件未満なら全件(HHS OIG FX-7・HUD OIG FX-6 の下端に合わせる)。置き換えは D-0 の決定者の記名による。下限は置き換えでも下げない(下限は 2〜3 件のどれにするかは議長の判断)
  - 結果の扱い: 中身の無い記述を見つけたら、その記録へ所見を記録し、次の四半期の件数を倍にする(ISO 2859-1 の切替規則 FX-10 の型)。2期続けて見つかれば第4章 G-5「是正の起動」の起点に加える。起点の追加は条項の変更なので ADR-0125 に書く
  - 結果の記録には、抽出の種・母集団の件数・抽出した件数・「母集団へ一般化しない」旨を書く(FX-8)
  - 5.7.4 要求事項1(機械が実質を判定して可否を決めない)は変えない。確かめるのは人であり、機械は抽出と期限の表示だけを担う
- 根拠水準: 件数の既定値と倍にする規則に `:::caution[暫定 EV-0250 / 見直し 2027-11]`(E0。外部の目安の値で、本標準の採用者の実績が無い)。差し替え条件は、抽出の記録に残る所見の件数と、所見を見つけた四半期の割合
- 採らない案: 件数と確かめる者の `plan=adopter`(検証可能性が無い。ADR-0084 決定4 の具体の依存先も名指せない)/ 統計的抽出(信頼95%・許容5% の59件。FX-12。四半期の母集団が小さい体制で母集団を超える)/ テンプレートだけで値を置くこと(本文に無い値の発明)/ 判断による抽出(FX-9)

## 議題4 IMPL-0377 必達基準2 の到達の見込みの算定(7.7.3)

**結論: IMPL-0374 の後に降ろす。母集団は SG で記名した SC-M の一覧を正とし、ラベルはその写しとして照合する。費用の実績の入力だけを adopter に分ける**

- 4-a 順序: 7.7.3 は区分を「値から定まる状態で、判定者は書き換えない」と定める(ADR-0099 決定3)。区分が判定を拘束する以上、入力(完了スループット)の正しさが判定の正しさになる。閉じた件数で数える集計の上で算定すると、誤った区分が拘束力を持つ。外部の予測も過去の完了の実績を入力とする(FX-29・FX-31)。IMPL-0374 が `delivered` になる前に IMPL-0377 を `delivered` にしない(反対の委員に同意)
- 4-b 母集団: 本文は SC-M を SG(または 7.6)の判定で確定すると定める(lifecycle.md:494・508)。母集団の出所は**記名した判定記録**であり、ラベルではない。ラベルは索引として使ってよいが、SG の記録の一覧と食い違えば区分を出さず、食い違いを出す(ラベルの付け替えは記名の無い SC-M の増減に当たる)。スコープを幅で入れる外部の型(FX-29)は採らない。ADR-0099 が幅をスループットの側だけに置くと決めており、変えるなら ADR-0099 の置き換えになる
- 4-c 費用: 費用の見込みの式は 7.7.3 にある。入力の「単位期間あたりの費用の実績」は会計の基盤に依存し、IMPL-0277 と同じ水準の依存先を名指せる。`plan=adopter` の理由が立つ。入力が無い組は、ADR-0099 決定3 の「算定できない組」の規則で扱う。起案の委員の「算定できないは単位期間が3つ未満の意味」は誤りで、本文はこの語を組の単位でも使う。テンプレートは新しい区分を作らず、備考に理由(入力なし / 単位期間が3つ未満)を書き分ける
- 4-d 計画: IMPL-0374 → IMPL-0377 の順。IMPL-0283 は Issue の読み出しを共有するが前提ではなく、並行してよい。3件とも `issue=359` の `scheduled` のまま、順序を note に書く
- 根拠水準: 区分と端の取り方は EV-0200・EV-0201 で開示済み。新しい値を置かないので EV は足さない。FX-32 の的中率を本文へ引かない(単一著者・査読なし)
- 採らない案: IMPL-0374 の前の算定 / ラベルだけを母集団とすること / スコープの幅の入力(ADR-0099 の範囲外)/ 費用の欠落を新しい区分で出すこと

## 議題5 IMPL-0467 前提の判定記録を読めない着手(3.5.5 要求事項5)

**結論: (a) は既存のテンプレ4 で足りるので降ろす。(b) は第6章で記録の様式を名指してから降ろす。(c) は本文の定義の欠けとして 3.5.5 で定める。止めた件数は表示する**

- 規格との整合: 前段の承認の無い後段の実行を系で止めることは 21 CFR 11.10(f)(順序の強制)の型で、手順書の指示は系の強制と同等でない(FX-34・FX-35)。承認の記録には承認した者への追跡が要る(11.10(g)、ISO 9001 8.6。FX-36)。ラベルの遷移は記名に当たらない。いまの「判定できない」で止める挙動は、この型に合う安全側である
- 5-a (a) 出荷判定者の差し戻し: G-7 の判定で「差し戻し」と書けば、テンプレ4 の「判定結果」「差し戻し理由」(満たさない基準の番号と再提出の期限)がそのまま運ぶ。新しい様式は要らない。準拠テンプレートはこの記録を前提として読めばよい(本文の変更なし)
- 5-a (b) 価値責任者の判断・事業決裁者の決裁: 3.5.5 の表は needs-po の完了を「判断を記録に残す」(roles-responsibilities.md:800)とだけ書き、様式が無い。3.5.5 要求事項4 は媒体と置き場を第4章とテンプレートへ委ねるが、**着手の前提になる記録の必須欄**を本文が持たないと、ADR-0040 の両方向の検査が掛からない。第6章「原則・判断記録・判定記録の関係」(deliverable-templates.md:54)に、この判断はテンプレ2(判断記録)か、判断者・日時・対象の作業単位・判断の3欄を持つ記録で残す、と名指す。新しい様式は作らない
- 5-b (c) 機能へ対応づけない作業単位: G-2・G-4 の前提を持たない作業の前提を本文が定めていない。テンプレートが「価値責任者の判断の記録をみなす」と決めるのは発明である。3.5.5 の要求事項5 の後に、「機能へ対応づけない作業単位の前提は、価値責任者がその作業単位の着手を判断した記録(上の (b) の記録)とする」と置く。ITIL の標準変更の型(事前に承認した類型の一覧。FX-38)は、記録を減らす代わりに一覧の承認という新しい義務を足すので、本件では採らず範囲外の気づきとして残す
- 5-c 形骸化: 止め続ければ人は終了コードを無視する。止めた作業単位の件数と理由を /pit に出し続ける(無承認の変更を数えて表示する実務。FX-37。ただし出典はベンダの解説で、本文へは引かない)。表示は既存の規定の実行で、新しい義務ではない
- 根拠水準: 値を置かないので EV は要らない
- 採らない案: テンプレートだけの記録の種別の新設(ADR-0040)/ (c) をテンプレートでみなすこと / 様式が無い間に「判定できない」を警告へ緩めること(11.10(f) の型から外れる)/ 標準変更の一覧の新設(新しい義務。外部の調査は二次資料だけ)
