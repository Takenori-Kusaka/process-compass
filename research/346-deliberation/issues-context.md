# #346 デプロイゲートの「資格情報の置き場」が、ジョブの権限で発行される短命のトークンを想定していない

- 背景: #293 の配布で、所有者の指示(2026-10-23。「github actions permission で設定するものでありキーは設定してはいけません」「github token を使わずにやりたいことを直接 permission 付与すればよくないですか?」「ルールセット緩和でいくしかないは同意です」)により、deploy key と秘密情報をやめ、GitHub Actions のジョブの権限(publish ジョブだけに `contents: write`)で `dist/standard` へ書き込む形にした
- 条項: 第4章 G-8「配備の統制と資格情報の置き場」(要求事項の正本)、`phase5-implementation/ci-gates.md`「統制と資格情報の置き場」(理由と GitHub の対応。EV-0137、IMPL-0237)。「デプロイ・配布の統制と資格情報を、起動元のブランチで書き換えられるワークフローのファイルの中だけに置いてはなりません。資格情報は、配備を許す参照(既定ブランチ、またはリリースのタグ)に限った実行環境の秘密情報に置きます」。手段が無い場合は未達として記録
- 問題: ジョブの権限で発行されるトークン(GITHUB_TOKEN)は秘密情報に置くものではない。書き込みの権限は、ブランチで書き換えられるワークフローのファイルの `permissions` から生じる。本リポジトリの配布はこの条項を満たさない(ADR-0077 決定6 に開示済み)。一方、長期の鍵を持たないことは `deliverable-templates.md` の「短命の資格情報を用いる」と同じ向きの利点
- 決めること:
  - 条項が、ジョブの権限で発行される短命のトークンをどう扱うか(認めるか、どの条件で認めるか、認めないか)
  - 認める場合、ブランチ上のワークフローから書き込みの権限に届く経路を何が止めるか(例: リポジトリの Actions の既定の権限、ルールセット、Environment)
  - 本リポジトリの配布を条項に合わせるか、条項の適用外として開示を続けるか。**所有者の指示により、鍵を設定する案は採らない**
- 関連: ADR-0077(CI の結線・配布)、ADR-0052、`.github/workflows/ci.yml`(ジョブ deploy・publish)、`scripts/check-ci-wiring.mjs`、準拠テンプレートの `delegated-merge`(Environment の秘密情報にマージのトークン)、OIDC
