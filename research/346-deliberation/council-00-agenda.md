# 会議体の議題(#346 ジョブの権限で発行される短命のトークンと、G-8「配備の統制と資格情報の置き場」)

入力: `issues-context.md`、`survey-346-1-internal.md`(内部。リモートの実状を含む)、`survey-346-2-external.md`(外部)。**所有者の指示により、鍵(deploy key・秘密情報に置く長期のトークン)を設定する案は採らない**。これは前提であり、議題ではない。

## 前提として確かめた事実(要旨)
- G-8 の規範は2文(禁止:「統制と資格情報を、起動元のブランチで書き換えられる場所の中だけに置いてはならない」、置き場の指定:「実行環境の秘密情報に置きます」)。未達は「手段を使えない場合」だけ。資格情報・秘密情報・実行環境の定義は無い。GITHUB_TOKEN・ジョブの permissions を規範の対象として扱う条項は無い。IMPL-0237(deploy-workflow、undelivered、issue=346)の降ろし先の説明は「既定ブランチに限った」で、本文の「既定ブランチ、またはリリースのタグ」と範囲が違う。「短命の資格情報を用いる」(`deliverable-templates.md`)は AI エージェントの実行環境の例示で、CI の配備を対象にしない
- ADR-0077 決定6 は GITHUB_TOKEN と publish ジョブだけの `contents: write` を採り、不適合を開示し、「#293 で別に扱う」とした。#293 の記録にその扱いは無い。方式の変更はコミット b185611 で、会議体・突合の記録が無い
- **リモートの実状**: 本リポジトリの #293 以降の変更はリモートの main に入っていない(PR 未作成の積み重ね)。リモートの main では旧 `publish-standard.yml`(最上位 `contents: write`、Environment なし、強制 push、`workflow_dispatch`)が動いている。ルールセットは空で、main と `dist/standard` は保護されていない。リポジトリは public。Environments と Actions の既定の権限は読めていない
- GITHUB_TOKEN の書き込みはブランチ・タグに結び付かない。権限は Workflow permissions の既定からワークフローの `permissions` で足し引きされ、書き込み権限を持つ者は `permissions` を書き換えられる(GitHub Docs)。Environment は GITHUB_TOKEN の権限を限らない(`environment:` を消せば規則を通らずに `contents: write` を得る)。ルールセットのバイパスに GITHUB_TOKEN を入れる公式の手段は無く、Actions を許すとどのブランチのワークフローからもバイパスできる。`.github/workflows` のパスを制限する push ルールセットは Enterprise Cloud の internal/private に限る。参照に結び付く仕組みは Environment の秘密情報と、OIDC を検証する受け手(GitHub Pages の deploy-pages が先例)だけ。2026-09 GA の「ワークフロー実行の保護」は起動する主体・イベントを限るが参照やトークンの権限を限らない
- 指針: OWASP CICD-SEC-6 は短命を優先、SEC-4(PPE)・SEC-1・SEC-5 はレビュー前のコード・CI 設定に資格情報を渡さないことを求める。SLSA v1.2 の Trusted Robot の定義に、ブランチで書き換えたワークフローのトークンは当たらない。短命であることでレビューへの結び付けの代わりにする根拠は見つからない。SSDF PS.1 は configuration-as-code を保護するコード、PO.5.1 は環境の分離
- 準拠テンプレートは contents: write もデプロイのワークフローも持たない。delegated-merge は Environment の長期のトークンで条項どおり。採用者が GITHUB_TOKEN で配備する場合の扱いは標準にもテンプレートにも無い。env-check は Environment と Actions の権限を読まない

## R-1 条項は、ジョブの権限で発行される短命のトークンをどう扱うか
- 問い: 認める / 条件つきで認める / 認めない。論点の1つ: そのトークンで届くのが「同じリポジトリへの書き込み」だけで、起動した者が自分の書き込み権限で既に直接できることを超えない場合、ブランチ上のワークフローは新しい能力を与えない(資格情報の条項が防ぐのは、起動者が持たない能力への到達)のではないか。逆に、配備先が本番・外部の環境である場合や、対象の参照が人には保護されトークンには保護されない場合は、超える。条項の目的(G-8)を「起動者が持たない能力への到達を、ブランチの書き換えで得させない」と読み直すか。「短命」は条件か(指針は短命とレビューへの結び付けを別要求とする)

## R-2 認める場合、何が止めるか。語の定義
- 問い: ブランチ上のワークフローからの書き込みを何で止めるか(配備先の参照の保護を人とトークンに同じく掛ける、Workflow permissions の既定、ワークフロー実行の保護、`.github/workflows` の CODEOWNERS とルールセット、配備を別のリポジトリへ分ける)。プランの制限(public・個人所有・Free)。資格情報・秘密情報・実行環境を 1.4 か G-8 で定義するか。IMPL-0237 の降ろし先の範囲の食い違い

## R-3 本リポジトリの配布
- 問い: 条項に合わせる(どうやって。鍵は使わない)か、適用外・未達として開示を続けるか。ADR-0077 決定6 の「#293 で別に扱う」の決着。リモートの実状(旧ワークフローが強制 push で動いている、保護が無い)に対して、所有者が行う設定の一覧。本リポジトリは個人の docs-as-code で、配布物の受け手は準拠テンプレート(`template:kb` の複製)とサイトである点の評価。EV-0137 の差し替え条件(main 以外からの起動が拒まれた記録)の扱い

## R-4 採用者とテンプレート
- 問い: 採用者が GITHUB_TOKEN で配備する場合の指針(標準 phase5 の ci-gates.md の対応表、テンプレートの雛形・env-check)。env-check が Environment と Actions の権限を読むか。テンプレートの workflows の最上位の write の権限(pull-requests・statuses・issues)をジョブ単位へ下ろすか

## R-5 記録
- 問い: 方式の変更(b185611)が会議体・突合を経ていない事実の記録。所有者の指示の記録の所在(公開の記録は「保守者の決定」とだけ書く)。新しい ADR と ADR-0077 の関係
