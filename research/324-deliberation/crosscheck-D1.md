### 意見 1: F.3 の IMPL-0918 を試し c だけで規定とした扱い

- 規定として表示する向きは保つのがよい。`worker-brief.md` 3章の裁定(迷ったら `undelivered` の側)に合い、文の後半「適用規格の特定から専門部門と行う」は主語が本附属書でない義務である。前半「本附属書の対象外」だけなら適用範囲の表明で、説明に当たる
- 直すのは降ろし先。`safety-verification-record` の description は F.7 の記録と F.4〜F.6 の試験の内容で、この判断を挙げない。F.7 の記録項目にも無いので、この降ろし先に当て続けるには標準へ記録の欄を足すことになる(判定表 1.2 の末尾の注記「新しい記録や欄を標準へ足す必要があるなら順 8」に当たる)
- 試し c が成り立つ置き場は常駐の指示である。`template/CLAUDE.md` の「一律で AI に委譲できない領域」に1行を置けば、実行主体がその場で読む。新しい記録を要しない。降ろし先を `claude-md-resident` に改め、`undelivered` のまま表示する案を推す。`none` へ直す案は採らないのがよい(表示が減る向き)
- 同じ型(c だけで成り立つ)の D-O07(3.5.5 要求事項8)・D-O11(2.10.2 行3)も、同じ裁定に揃える

### 意見 2: 附属書B が名指す `formalize-criteria` が準拠テンプレートに無いこと

- 語は標準のプロセスの定義(`integrated.yaml`)のタスクの識別子で、附属書B の題はそれを引いている。準拠テンプレートがタスクの識別子を持つ規定は無く、テンプレートの側の対応物は `/spec-write` である。食い違いではなく、題が内部の識別子を露出している形
- 棚卸しでは題を変えない(鍵が題に依り、条文は変えない定め)。マークの降ろし先(`spec-write-skill`)は合っている。題の語を直すかは編集の指摘として、鍵の付け替えと合わせて別に扱うのがよい。タスクを準拠テンプレートへ足す案は、新しい置き場を作るだけで規定を運ばないので推さない

### 意見 3: H.1 成立条件の表の条件4 の文の矛盾の候補

- 条件4 の文は第4章 G-7 の成立条件の表と同じで、実装(`aggregate-evidence.mjs` の条件4)も同じ3点(G-7 と G-8 が同じ人、G-7 の記名者が指示者・G-6 の承認者、記名が自己申告)を不成立にする。文の中の矛盾は見つからなかった
- H.5 が3名未満で出荷判定者と事業決裁者の同一を許すことは、出荷の可否の話で、条件4 は主張の可否の話である。同一なら「品質保証の対象外として出荷」になる。単位の違いと読める。ただし H.1 の体制ごとの表が2名体制にだけ「別の自然人」と書くので、読み手は 1名・3名未満の兼務との関係を H.5 まで読まないと分からない。補足の候補として条文の側の Issue へ送り、棚卸しでは直さない
- もう1点: 委任の期間の開示では G-7 を変更ごとに行わないのに、条件4 は「出荷判定(G-7)を記名した人」と書く。実装は席の責任者で代えるが、条文に読み替えが無い。これも補足の候補
- 実装の担当が挙げた「IMPL-0113 の note が G-8 の記名者の別を名指さない」は、`elsewhere` の名指しの弱さとして残る。条件4 の行の理由に、G-7 と G-8 の別を名指すマークの番号(IMPL-0438 か集約の条件4 を追うマーク)を書き足すのがよい。テンプレ11 の文とは突き合わせていない
