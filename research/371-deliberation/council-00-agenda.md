# 会議体の議題(#371 同じ PR でワークフローとゲートの検査を書き換えて検査を緩められる)

入力: Issue #371、`survey-371-1-internal.md`(内部)、`survey-371-2-external.md`(外部)。前段の決定 ADR-0087(#317。Issue 本文の「ADR-0086」は誤り)、ADR-0109、第5章 5.5.4(委任の経路は判定のコードを基底から読む)。関係の Issue #369。

## 前提として確かめた事実(要旨)

- Issue の訂正: IMPL-0334 は IMPL-0340(issue=371 へ付け替え済み)、ADR-0086 は ADR-0087
- 必須チェック gate-g5 は、ワークフローの定義も scripts/gate/ も PR の側で動く。必須チェックは名前(context)だけで送り手(integration_id)を縛らない。ルールセットの雛形に required workflows が無い。CODEOWNERS の強制層の行はコメントのまま。pr-rules は緩める向きの変更を判定せず、AI維持管理者の記名は本文のテキストの欄で、本人の操作(承認のレビュー)と結び付かない
- 「判定のコードを基底から読む」規定は、委任の経路(5.5.4、delegation.yml の pull_request_target)と G-8 にはあるが、G-5 には無い
- 同意の記録(IMPL-0340)の照合は、検査を PR の側で動かす限り同じ PR で外せる。検査の読み元を先に決める必要がある
- #369 の対象は AI レビューの指示(データ)で機構は違うが、yml が PR の側で動く限り同じ穴を持つ
- 外部: PR が書き換えられない定義を強制する仕組みは GitHub ruleset workflows・GitLab pipeline execution policy・Prow の中央ジョブ定義。いずれも定義を別のリポジトリに置き ref か SHA で固定する。GitHub・GitLab の機能は組織・Enterprise・Ultimate が前提で、GitHub のものは個人所有のリポジトリで使えない
- 3つとも、定義から PR 側の検査スクリプトを呼ぶ限り、スクリプトの書き換えは防げない(Prow KEP-2291 が原文で明記)。論点は「定義の書き換え」と「スクリプトの書き換え」の2層
- 必須チェックの送り手の指定(integration_id)が止めるのは、人や外部トークンが送る偽の status だけ。どのワークフローかは縛らない(推測)
- 規格は実装を指定しないが、SP 800-204D(制御面は個々のステップより高い信頼水準で動く、検査は迂回されうる)、SSDF PS.1.1(configuration-as-code の保護と code owner のレビュー)、SLSA L3(技術的統制の継続の証拠)から、検査の定義・ロジックの変更を自己承認させない要求が導ける
- pull_request_target は PR のコードを実行すると危険(Security Lab)。案(a) は PR のコードを実行しない範囲に限る必要がある
- 実機で確かめるべき点 E-1〜E-12(内部調査 第6節)。例: 書き換えた yml で gate-g5 が通るか、同名のジョブで必須チェックを偽装できるか、record-copy がどちらの定義で動くか

## R-1 検査の読み元

- 問い: G-5 の判定のコード(scripts/gate/ と判定に使う定義)を基底から読む構成を求めるか。案(a) pull_request_target 等で基底の検査を走らせる(PR のコードを実行しない範囲)、(b) 検査の書き換えを含む PR を別の必須の承認で止める、(c) ruleset workflows、(d) 開示で足りる、(e)〜(i)(内部調査)。個人所有のリポジトリ・無償のプランで成り立つか

## R-2 定義とスクリプトの2層と、送り手

- 問い: 定義の書き換えとスクリプトの書き換えをどう分けて扱うか。必須チェックの送り手を縛れないことの扱い(開示・別の照合)

## R-3 所有する組織の同意の記録(IMPL-0340)と AI維持管理者の記名

- 問い: 同意の記録と、強制層・検査を緩める変更の AI維持管理者の記名を、本人の操作(承認のレビュー)と結び付けて機械で確かめるか。どこで確かめるか

## R-4 #369 との分担、実機の確認、記録

- 問い: #369 との分担。実機の確認(E-1〜E-12)をいつ・どこで行うか(一時のリポジトリの作成は外部への作用を含む)。新しい ADR、EV・IMPL、開示、採らない案
