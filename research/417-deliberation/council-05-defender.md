## R-1 計画容量の単位

### 結論

1. **欠陥と認める**。2.10.1 の「容量」は定義が無く(`lifecycle.md:470`)、既定値 60%(ADR-0097 決定2)は分母が無いため計算できず、2.10.5 の「容量の上限を超える場合は不可」(`lifecycle.md:529`)は判定できない。既定値は「記録が無くても効く値」(第1章 1.7.7、`overview.md:381` 以下)であるのに、効かせる手段が無い。この状態は弁護できない
2. **本標準が量の種類を定める。量は「作業単位の件数」とする**。計画容量 = 直近の実測スループット(作業単位の件数 / 単位期間)× 当該ステージの残る期間。各層の割合 = 層に入れた項目を作業単位へ割った見込みの件数 ÷ 計画容量。これは 2.10.2 要求事項1(`lifecycle.md:478`)と ADR-0019 決定3 が既に定めた量であり、2.10.1 はそれと同じ量で書けばよい
3. **2.10.1 の「件数ではなく容量で」の趣旨は残す。文は「要求(項目)の件数ではなく、作業単位の件数で」と書き直す**。2.10.1 が退けたのは「要求の件数」(大きな要求を 1 件として SC-M へ入れても割合が動かない)であって、作業単位の件数ではない。両者を区別すれば 2.10.1 と 2.10.2 の矛盾は解ける
4. **「1 件」の定義(何を作業単位とするか)と単位期間の長さは、組織が定めて記録する**。記録先は 2.10.2 要求事項4 の「合意した規模と根拠とした実測値」とテンプレ6 のスコープ3層の表。合意と実測で同じ定義を使うことを要求事項に置く(#406 品質監査の既出案、`research/406-deliberation/council-03-qa-audit.md:42`)。単位の種類(件数)は組織に委ねない
5. **工数・見積の点数・人の時間を容量の単位にすることは採らない**(理由は下)。「単位を組織が選び、記録だけさせる」案(外部の案 D、内部 Q1-2(c))も採らない
6. **60%・20% は既定値のまま残す**。ただし EV-0150 の本文を改め、「DSDM の 60% は工数の比率であり、本標準はそれを作業単位の件数の比率へ移した。移したことにも実証は無い」と開示する。差し替え条件は「ステージごとの確約範囲の作業単位の見込みの件数と計画容量の比、確定時と終了時の SC-M の作業単位の件数、SC-M の増減の件数」と、測れる量で書き直す
7. 60% の置き換え(テーラリングの宣言、1.7.7)は、2.10.2 要求事項3「見積りの精度を根拠に上限を引き上げない」の制約の下に置くことを明記する。ADR-0097 が残した論点(「超えてはなりません」と既定値の関係、`adr/0097-...md:99`)への弁護の答えは、「置き換えるまでは 60% で超えてはならず、置き換えの記録の後は記録した値で超えてはならない。引き上げの根拠に見積りの精度を使えない」である
8. `debt-payback.md:53` の「反復の容量の 20% を返却枠の初期値」は、本件で一緒に直す。手引き(フェーズ6)なので 1.7.7 の検査の対象外だが、同じ未定義の量に依り、「反復」は ADR-0080 決定1 が定めない短い期間の計画に触れる。本標準の値にせず、「例」として書き、量は 2.10.1 の定義を引く

### 理由

- **工数・点数を採らない理由(信頼性)**
  - 分母を見積る側が動かせる。工数で容量を取ると、見積を大きく書けば容量が増え、60% の枠が広がる。これは ADR-0094 決定4 が velocity を退けた理由そのもの(`metrics.md:86` の「採用しない指標」の行)であり、容量の名で裏口から戻すことになる
  - ADR-0019 決定3 が退けた「工数の絶対値での合意」へ戻る。決定3 の根拠(工程の進行で見積の不確実性が収束するとは限らない、`lifecycle.md:483`)は崩れていない。外部も見積は平均 30% 外れると報告している〔外〕(Jørgensen 2014)
  - AI が実装する作業単位では「誰の工数か」が定まらない〔外〕(METR の RCT では人の体感と実測が逆向き)。RC-03 自身が「人の作業量」を前提にした能力依存の定数である(`roles-responsibilities.md:1728`)。能力依存の量を、ステージの確約の分母にしてはならない
- **単位の種類を組織に委ねない理由**: 組織が工数・点数を選べると、上の欠陥がそのまま入る。ADR-0095 は閾値を規範値にしない理由に「容量の単位」が案件で違いうることを挙げた(`adr/0095-...md:84`)が、これは閾値の値の話であり、量の種類まで組織に委ねると決めたものではない〔推〕。Scrum Guide が単位を定めない〔外〕のは、確約の上限という数を課していないからである。本標準は 60% を課す以上、単位なしでは判定できない(外部の案 D の弱点の欄と同じ)
- **件数を採る理由**: 2.10.2 がすでに件数で合意すると定め、運用メトリクスも件数で数える。合意・実測・配分が同じ量になり、確定時の見込みと終了時の実績を事後に突き合わせられる。Kanban Guide・Vacanti の throughput も件数〔外〕
- **2.10.1 の「件数で配分しない」の趣旨を残す理由**: 要求を 1 件として数えると、大きな要求を SC-M に入れても割合が動かない。この歪みは実在する。作業単位へ割ってから数えれば、大きな要求は多くの作業単位として割合に現れる。文を消して件数に書き換えるだけだと、この保護が消える
- **60% を残す理由**: 60% を消すと SC-M の上限が無くなり、すべてが必須の計画(2.10.1 冒頭が退けた状態)へ戻る経路が開く。組織が定める値へ移すと、記録の無い案件で上限が効かなくなる(ADR-0097 決定2 が既定値にした理由)。1.7.7 の基準でも、確約の上限は「置き換えずに用いても統制を弱めない値」に当たる。出典の量を移したことの開示は要るが、値を消す理由にはならない
- **単位期間を組織に委ねる理由**: 単位期間は反復の周期に近く、ADR-0080 決定1 が定めない領域に掛かる。長さは定めず、記録だけを求める

### 反論されうる点

- **「60% を件数の比率で使うのは出典の誤用だ」**(外部の観察「60% と件数を組み合わせると、どの出典にも支えられない」)。認める。弁護の立場は、誤用を隠さず開示したうえで既定値として残すことである。誤用を理由に値を消すと、上限の無い状態という、より信頼性の低い状態になる。反論側が「工数に戻して DSDM に忠実にせよ」と言うなら、ADR-0019 決定3・ADR-0094 決定4 を置き換える新 ADR と、AI の担い手の下での工数の意味の定義が要る。その負担は改める側にある
- **「作業単位の見込みの件数は、結局は見積りだ」**。そのとおり。SG の時点で SC-M の項目を作業単位へ割る数は見込みである。ただし、(a) 実測と同じ量なので終了時に突き合わせられる、(b) 2.10.2 要求事項3 が見積りの精度を根拠に上限を引き上げることを禁じている、の 2 点で工数の見積りより検証しやすい。見積りでない分母は存在しない、というのが弁護の認識である
- **「作業単位の大きさがばらつけば件数の比率は意味が薄い」**。認める。規模の基準値(RC-01)は遮断ではなく既定(ADR-0047・ADR-0058)であり、大きさはそろわない。ばらつきは予測の幅を広げる〔外〕(Vacanti)。弁護としては、ばらつきを抑えるために RC-01 を遮断へ戻すことには反対する(ADR-0058 が退けた経路)。ばらつきは EV-0150 の開示事項に足す
- **「SG の時点では G-4 の前なので、作業単位へ割れない」**。割る粒度は組織が定める「1 件」の定義に従い、テンプレ7 のタスクと一致させることを求めない。この点は、R-2 の「数える単位を本文で Issue・タスクのどちらとも定めない」と組で成り立つ
- **「反復の容量の 20%(負債返却)を例へ下げると、返却が始まらない」**(`debt-payback.md:54` の趣旨)。返却枠を確保する務めは価値責任者に残る。数を本標準の値にしないのは、反復の計画の方法を定めない ADR-0080 決定1 のためであり、返却の務めを外すためではない

## R-2 完了スループットに数える閉じ方

### 結論

1. **本文 2.10.2・2.10.4 は誤っていない。誤っているのは手引きの写し方である**。本文は「完了した作業単位」と書き(`lifecycle.md:478`)、運用メトリクスは「クローズした Issue の件数」と書く(`metrics.md:166`)。手引きは本文を緩めてはならず、食い違えば本文による(第1章 1.8)。手引きの「クローズ」は本文の「完了」を広げている
2. **ただし本文にも欠陥がある、と認める**。「完了」の定義が無く、手引きの読みを止められない。加えて `metrics.md:175` の「未完了のまま閉じると…滞留期間の分布に残った作業が現れます」は成り立たない。滞留期間は未完了の項目だけを対象にし(`metrics.md:165`、`lifecycle.md:504`)、閉じた項目はそこから外れる。本標準が完了スループットの歪みを捉えると称した対の指標(ADR-0079 の手続2)は、閉じ方の経路を捉えていない。**これは保証の欠落であり、定義を置く必要がある**
3. **本文で「完了」を肯定の形で定義する**。「完了とは、作業単位が、組織が記録した完了の条件を満たして閉じたことをいう。取り下げ・重複・他の作業単位への統合・範囲からの削除によって閉じたものは、完了に数えない」。完了の条件の中身(受入基準の充足、取り込み、など)は組織が定めて、規模の合意の記録(2.10.2 要求事項4)に R-1 の「1 件」の定義と並べて記録する
4. **閉じた理由を区別して記録することを要求事項に置く**。GitHub の既定は completed であり〔外〕、理由の区別を求めなければ 3 の除外は効かない(外部の観察「C は A の前提」に同意)
5. **完了に数えなかった件数(閉じた理由ごとの内訳)を、実測値と並べて記録する**。完了の件数だけを残すと、取り下げた作業と浪費が記録から消える〔外〕(Vacanti の放棄のタグ)。規模の合意の根拠の実測値に、除外の規則と除外した件数を添えさせる
6. **計画外の完了は除かない**。スループットは「完了の速さ」であり、確約の達成とは別の量である。計画外の差し込みは「確約範囲(SC-M)の変動」(`metrics.md:167`)と 2.10.5 の調整の記録で捉える
7. **数える単位(Issue・タスク(PR)・受入基準)を本文で定めない**。R-1 の 4 のとおり、組織が「1 件」を定めて記録し、合意と実測で同じ定義を使うことだけを課す。GitHub の `state_reason` や、取り込まれた PR との結び付けは、手引きの実装の例に置く
8. **`metrics.md:165-175` を直す**。算出方法を「完了の条件を満たして閉じた作業単位の件数」に改め、`state_reason` の completed のうち取り込みに結び付くものを数える例を示し、175 行の誤った論理を「閉じ方の区別が無いと滞留期間でも捉えられない」と改める
9. **準拠テンプレートへは IMPL を立てる**。集計の実装が無いこと(内部 2.2)は、`state=undelivered` で表示し続ける。集計を準拠テンプレートに持たせるかは別に決めてよいが、マークを立てずに済ませることは採らない(#222 の方針)

### 理由

- **肯定の形で定義する理由**: 除外を列挙すると、列挙から漏れた閉じ方(移送、分割による付け替え)が完了に数えられる。完了の側を条件で定義すれば、条件を満たさない閉じ方はすべて外れる。ADR-0080 が閉じた列挙を避けた理由(列挙から漏れたものに規定が掛からないと読まれる、`adr/0080-...md:30`)と同じ
- **計画外を除かない理由**: 一次資料に根拠が無い〔外〕。除くと、差し込みが多い組織ほど実測スループットが小さく出て、確約の量を過小に見積る。逆向きの歪みになる。加えて、計画内外を分けるのは記録する者のラベルに依る分類であり、本標準は「分類をラベルで行うと記録する者の申告で値が決まる」として同型の指標を退けている(`metrics.md:83`)
- **内訳を記録させる理由**: 2.10.5 で SC-B を削除した項目を閉じると、それは調整であって完了ではない。除外した件数が記録に残らなければ、確約の量の根拠(2.10.2 要求事項4)を後から監査できない。7.7.2 が「統合されなかった試行」を分母から除きつつ、その事実を消していない先例(`exception-escalation.md:359`)とそろう
- **単位を本文で定めない理由**: 本文は Issue の語を使っていない〔確〕。Issue と書いたのは手引きであり、テンプレ7 はタスク(PR)で書く。本文で Issue に寄せると、PR を作業単位にする組織や、コードの無い作業単位を持つ組織が外れる。方法中立(ADR-0080)とツール中立の要請である
- **完了スループットの禁止(比較・目標値への使用、`lifecycle.md:508`)は維持する**。閉じ方の定義を置いても、細かく分ければ上がる性質は残るためである

### 反論されうる点

- **「閉じた理由も閉じる者の申告だ。`metrics.md:83` の論法は理由の記録にも当たる」**。当たる。弁護の答えは 2 段である。(a) 本文は完了を「組織が記録した完了の条件」で定義し、条件は申告ではなく事象(受入基準の充足、取り込み)で書くよう手引きで勧める。(b) 除外した件数を併記させるので、理由の付け替えは内訳の変化として残る。それでも申告の余地は残る、と開示する。完全に機械で決める案(取り込まれた PR に結び付く Issue だけを数える)を本文に置くと、コードを伴わない作業単位が数えられなくなり、ツール中立も崩れる
- **「出口をすべて数え、完了率と破棄率を分けるべきだ」**(Carmichael、外部の案 B)。Little の法則の整合では出口派に理がある。ただし本標準のスループットの用途は規模の合意(確約の量)であり、取り下げを含めると確約を大きくする向きに歪む。用途に照らして完了の側を採り、出口の情報は内訳の記録で残す
- **「規範で完了を定義するのは Kanban Guide の DoW 型(チームに委ねる)より踏み込みすぎだ」**。本標準が定めるのは「取り下げ・重複・統合・削除を完了に数えない」という下限だけで、完了の条件の中身は組織に委ねる。下限を置かないと、2.10.2 の確約の量を支える実測が、閉じ方次第で膨らむ。確約の上限を課す本標準は、DoW を委ねるだけの Kanban Guide と立場が違う
- **「IMPL を立てても集計しないなら意味が無い」**。未達の表示は、採用者に「この規定は準拠テンプレートでは働かない」と知らせる。表示しないほうが、働いているように見える分だけ信頼性が低い

## R-3 EV-0087 の実績の記録

### 結論

1. **欠陥と認める**。EV-0087 の差し替え条件の前半「見積と実績の対応(実績 / 見積り)の実測4四半期分」(`deliverable-templates.md:1183`)は、標準のテンプレ7 にも準拠テンプレートにも無い記録を求める。ADR-0094 決定3 は作業単位 × 人の実績を課さないと決めた。条件を満たす記録が本標準のどこからも生まれないことは、#406 で弁護自身が指摘した(`research/406-deliberation/council-05-defender.md:124`)。`evidence-marking.md:61` に照らし、書けていない条件である
2. **テンプレ7 に実績の欄を足さない。任意の欄としても足さない**。ADR-0094 決定3 を維持する
3. **差し替え条件から「実績 / 見積り」を外し、後半だけを条件にする**。改めた条件: 「見積が 8 時間を超えたタスクと超えないタスクの、やり直し(テンプレ7 の状態の値)の率の差。8 時間を超えたタスクのやり直しの率が超えないタスクと差が無い場合は、目安を外す」。必要な記録は、テンプレ7 の既存の列「見積」と状態「やり直し」だけである(`deliverable-templates.md:1140-1142`、`:1177-1178`)。新しい記録を課さない
4. **起案・現場の既出案(Draft PR の作成から取り込みまでの経過時間)は採らない**。経過時間は工数ではなく、待ち・レビュー・並列が混じる(内部 3.5 の 2)。8 時間の目安の当否を測る量として不適である。さらに、目安の当否を決めるのに予実の比はそもそも要らない(下の理由)
5. **8 時間の目安そのものは残す**(ADR-0058 決定6 を維持)。外す判断は、3 の条件で出す。いま外す新しい証拠は無い
6. **準拠テンプレートの RC-03 の扱いを直す**。準拠テンプレートは見積の列を omit しており(`src/data/template-fields.yaml:671-675`)、目安が適用される欄が無い。それでも `recalibration-registry.json` は RC-03 を再評価待ちに数える(内部 3.2)。見積の列を足した採用者に限って RC-03 を数える(列が無ければ「適用なし」と表示する)よう改める。降ろし先には IMPL を立てる
7. **やり直しの率の比較は、タスクの見積の区分ごとに案件単位で集計し、担い手・人ごとに集計しない**ことを、EV-0087 の本文に書く。既存の 7.7.9 要求事項6(見積りの精度を評価に使わない)と運用メトリクスの「個人の評価に使わない」で足り、新しい禁止は置かない
8. **見直し日 2027-04 と「4 四半期分」の不整合は、条件の側を直す**。期間ではなく、比較に使ったタスクの件数(超えた側・超えない側)を開示させる。見直し日に材料が足りなければ、その事実(件数)を記録して見直す。見直し日を先へ送るだけの延長は採らない

### 理由

- **予実の比が要らない理由**: RC-03 の 8 時間が担う保証は「超えたら理由を記録する」だけである(`roles-responsibilities.md:1728`)。この目安に意味があるのは、大きいと見込まれたタスクが手戻りを起こしやすい場合に限る。それを確かめるのは「超えたタスクと超えないタスクのやり直しの率の差」であり、見積が当たったか(実績 / 見積り)ではない。見積の精度は、目安の有用性とは別の問いである。現行の条件は 2 つの問いを混ぜ、測れない側に引きずられて全体が測れなくなっている
- **実績の欄を足さない理由**
  - 作業単位 × 人の実績は、個人評価へ転用される経路になる(ADR-0094 決定3 の理由)。電子的な業績監視は業績を改善しない〔外〕(Ravid 2023)
  - 「任意の欄」でも止まらない。欄があれば合計され、報告へ流れる。本標準は「参考として測るだけ」は成立しないと書いている(`metrics.md:42-44` 付近、Ridgway 1956)
  - 予実を記録して振り返っても見積は良くならない〔外〕(Jørgensen & Gruschke 2009)。記録の利益が、転用の危険を上回らない
  - テンプレ7 の起案者は AI である(`deliverable-templates.md:1136`)。AI が実装したタスクの「人の実績時間」は、人の判断・レビューの時間か、壁時計か、定まらない。人の申告は AI 利用時に偏る〔外〕(METR の RCT)
- **経過時間を採らない理由**: 経過時間で条件を書くと、「8 時間の見積」と「数日の経過」を比べることになり、比は常に大きく出る。目安を外す・残すの判断に使えない量を条件に置けば、条件は測れても判断材料にならない。条件は判断に使う材料を書く(`evidence-marking.md:56`)
- **目安を残す理由**: ADR-0058 決定6 は、根拠が無いことを開示したうえで目安として残すと決めた。この判断を覆す新しい事実は、本件の調査に無い。#406 の規格委員も前倒しの根拠は無いとした(`research/406-deliberation/council-04-standards.md:111`)。目安を外すと、テンプレ7 の運用ルール「8 時間を超えたら理由を記録する」も消え、計画の時点で大きすぎるタスクに気付く契機が一つ減る
- **RC-03 の扱いを直す理由**: 適用される欄が無い定数を再評価待ちに数えると、採用者は使っていない定数の「残す・外す・移す」を記名で記録させられる。記録が形式になり、登録簿(3.12.12)全体の記録の信頼性を下げる

### 反論されうる点

- **「8 時間の目安は、規模の基準値(RC-01)と G-4 の分割基準(行数・ファイル数の見込み、`gate-criteria.md:509`)と重なり、独自の保証が無い。外すべきだ」**。重なりは認める。タスクの大きさの統制は行数・ファイル数へ移っている。弁護の答えは、重なっているかどうかを測る条件(3)を置いたのだから、その結果で外す、である。根拠なく外すのは、根拠なく置くのと同じ欠陥である。外す側の委員が、行数の見込みが時間の見込みの機能をすべて担うことを示せるなら、外すことに反対しない。その場合は ADR-0058 決定6 を置き換える新 ADR が要る
- **「やり直しの率の差は、件数が少なければ何も言えない」**。そのとおり。だから期間ではなく件数を開示させる(結論 8)。件数が足りないまま見直し日が来たら、「材料不足」を記録する。そのほうが、4 四半期という測れない期間を書いておくより正直である
- **「準拠テンプレートは見積の列を持たないので、条件の材料はテンプレート利用者から出ない」**。認める。条件の材料は、見積の列を持つ採用者からしか出ない。準拠テンプレートの利用者には RC-03 が適用されないと表示する(結論 6)のは、そのためである。準拠テンプレートに見積の列を戻すことは採らない。ADR-0094 決定2 が omit を登録した理由(タスクの粒度を変更の規模で扱う)が崩れていない
- **「RC-03 の前提『人の作業量に基づく見積』と、ADR-0094 決定2『担い手を問わない 1 つの値』が食い違う」**。食い違いに見えることは認める。8 時間という値は人の作業量を前提に置いた(能力依存の根拠)が、テンプレ7 に書く見積は担い手を問わない 1 つの値である。RC-03 の「依拠する前提」の欄に「値の出所は人の作業量。書く見積は担い手を問わない 1 つの値」と書き分けることを支持する

## R-4 記録

### 結論

1. **新しい ADR を 1 本起こす**(番号は次の空き、本日時点で ADR-0098)。3 点は「作業単位の定義と、その数え方・比べ方」という同じ根から生じている(内部「3 点に共通する根」)ので、1 本にまとめる
2. **既存の ADR は置き換えず、補う**。関係の表を ADR-0097 の形式で置く
   - ADR-0019 決定2・3: 補う。計画容量を作業単位の件数で定義し、60% を工数の比率から件数の比率へ移したことを開示する。決定3 の中身は維持する。ADR-0019「影響」の「置き換えの手続は定めておらず」(`:72`)は、1.7.7(テーラリングの宣言)と本 ADR で閉じたと書く
   - ADR-0058 決定6: 補う。8 時間の目安は残し、EV-0087 の差し替え条件だけを改める。目安を外す決定になった場合に限り、置き換えとする
   - ADR-0094 決定6: 本 ADR が受ける。決定3・4 は維持すると明記する
   - ADR-0097 決定2: 維持する。残した論点(2.10.1 の「超えてはなりません」と既定値の関係)に答える
   - ADR-0080 決定1: 維持する。単位期間の長さと反復の容量を定めない根拠として引く
3. **「課さないと決めたこと」を明記する**(下の表)。#406 で「velocity」が「書かれていない」状態だったのと同じ欠陥を繰り返さない
4. 実証の無い判断は根拠水準のマークで開示する。60% の件数への移し替え(EV-0150 の改訂)と、完了の定義の下限(新しい EV)

### 採らない案(弁護として採らないもの)

| 案 | 採否と理由 |
| --- | --- |
| 容量の単位を工数(人の時間)にする | 採らない。分母を見積る側が動かせる。ADR-0019 決定3・ADR-0094 決定4 と衝突する。AI の担い手の下で誰の工数かが定まらない |
| 容量の単位を見積の点数(story point)にする | 採らない。velocity の裏口になる(ADR-0094 決定4) |
| 容量を「人の判断・レビューの時間」で測る(外部の案 C) | 採らない。実証が無く〔外〕、人の時間の申告が要る。人の帯域の問題は RC-01・RC-02・RC-04 で既に扱っている |
| 単位の種類を組織が選び、記録だけ求める | 採らない。60% を課す以上、単位の種類まで委ねると判定が組織ごとの量に依り、工数・点数が入る |
| 「容量」の語をやめ、要求の件数で書き直す | 採らない。大きな要求を 1 件として SC-M に入れても割合が動かない歪みが戻る |
| 60%・20% を削る、または組織が定める値へ移す | 採らない。上限が消える、または記録の無い案件で効かなくなる |
| 計画外の完了をスループットから除く | 採らない。一次資料に根拠が無く、差し込みの多い組織で確約を過小にする。計画外は SC-M の変動で捉える |
| 出口をすべてスループットに数える | 採らない。確約の量を大きくする向きに歪む。出口の情報は除外の内訳として記録する |
| 数える単位を本文で Issue(またはタスク・PR)に定める | 採らない。方法中立・ツール中立が崩れる。組織が定めて記録する |
| テンプレ7 に実績の欄(必須または任意)を足す | 採らない。ADR-0094 決定3。任意の欄でも合計・転用される |
| EV-0087 の差し替え条件を経過時間(Draft PR の作成から取り込みまで)へ改める | 採らない。工数ではなく、目安の当否の判断材料にならない |
| 8 時間の目安をいま外す | 採らない。新しい証拠が無い。改めた差し替え条件の結果で外す |
| 準拠テンプレートに見積の列を戻す | 採らない。ADR-0094 決定2 の omit の理由が崩れていない |
| 単位期間・反復の容量の長さや方法を本標準が定める | 採らない。ADR-0080 決定1 |

### 反論されうる点

- **「1 本にまとめると、どの決定がどの論点か読みにくい」**。決定を論点ごとに番号で分け、関係の表で対象の ADR を示せば足りる。3 本に割ると、「1 件」の定義(R-1・R-2)と比べる量(R-3)が別々の ADR に散り、同じ根を持つことが読み手に見えなくなる
- **「60% の出典の量を変えたのだから、ADR-0019 決定2 の置き換えだ」**。決定2 は「計画容量の 60% を上限とする」であり、計画容量の量を定めていない。量を定めるのは補いである。ただし、出典(DSDM)の量から離れたことは補いの範囲を超える変化とも読めるので、規格の委員が置き換えとすべきと判断するなら、それに反対しない。その場合も決定2 の中身(上限を置く、実証の無いことを明記する)は維持する

## 論点ごとの結論(要約)

- R-1: 容量の未定義は欠陥と認める。量の種類は本標準が「作業単位の件数」と定め(2.10.2 と同じ量)、「1 件」の定義と単位期間は組織が記録する。工数・点数は採らない。60%・20% は既定値のまま残し、EV-0150 で工数比から件数比へ移したことを開示し、差し替え条件を測れる量へ直す
- R-2: 本文の「完了」を肯定の形で定義し(取り下げ・重複・統合・削除は数えない)、閉じた理由の区別と除外の件数を記録させる。計画外の完了は除かない。数える単位は本文で定めない。`metrics.md:166・175` を直し、準拠テンプレートへは IMPL を undelivered で立てる
- R-3: 差し替え条件の「実績 / 見積り」を外し、8 時間を超えたタスクと超えないタスクのやり直しの率の差だけを条件にする(既存の列で足り、新しい記録を課さない)。実績の欄は任意でも足さない。経過時間案は採らない。目安は残す。準拠テンプレートで RC-03 を適用なしと表示する
- R-4: 新しい ADR を 1 本起こし、ADR-0019・0058・0094・0097 を置き換えずに補う。「課さないと決めたこと」を表で明記する
