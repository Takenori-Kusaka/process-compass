## R-1 計画容量の単位

### 結論

1. **本標準が単位を定める**。容量は「作業単位の件数」で表し、**作業単位はスコープ3層に載せるバックログの項目(Issue など)と同じ単位**とする。テンプレ7 のタスク(PR)と受入基準は、容量・スループットの単位にしない(それぞれ手戻り率・進捗率の単位として残す)
2. 計画容量 = 直近の実測スループット(作業単位の件数 / 単位期間)× 当該ステージの単位期間の数。**合意(2.10.2)と実測と 60% の比率の分子・分母に、同じ作業単位の定義を使うことを要求事項にする**
3. 2.10.1 の「要求の件数ではなく容量で」を「**要求の件数ではなく、作業単位の件数で**」と改める。大きな要求は、層に載せる時点で作業単位へ分けて数える。分け方は手法を課さず、分けた結果(層ごとの作業単位の件数)を記録させる
4. **事後の比率を記録させる**。ステージ移行ゲートの判定記録に、当該ステージで完了した作業単位のうち SC-M・SC-P・SC-B・層の外(計画外)に属するものの件数を書かせ、計画時の比率と並べる
5. 単位期間の長さは**組織が定める値**とし、G-1 の時点で価値責任者が定め、テンプレ6 に記録する(1.7.7 の組織が定める値。参考の値は置かない — 暦の刻みは組織の運用に依るため)
6. テンプレ6 の「次ステージのスコープ3層」に、作業単位の定義、単位期間、実測スループットの値とその観測の期間、計画容量(件)、層ごとの作業単位の件数を足す。列名「容量の割合」と準拠テンプレートの「容量の目安」の揺れは、「容量に対する件数の比率」へ揃える
7. 組織が単位を変える(工数比で配分するなど)ことは**テーラリングの宣言として認めるが、そのときは 60%・20% も同時に組織が定める値へ移り、記録が無ければ基準を満たさない**とする。単位を変えた 60% は別の値だからである
8. EV-0150 を書き直す。補足に「DSDM の 60% は工数比である。本標準はこれを作業単位の件数の比へ移して用いており、移した値の妥当性は確かめていない」と開示する。根拠の水準は **E1 から E0 へ下げる**(間接の根拠である DSDM が、移した後の量を支えないため)。差し替え条件は「ステージごとの計画時と事後の SC-M の件数の比率、SC-M の増減の件数、SC-M の未完了の件数」とし、記録が生まれる量にする
9. A6 の「容量の上限」は「SC-M・SC-P・SC-B の作業単位の件数の合計が計画容量を超える場合」と定義し直す〔推: 意図の読み。起案に確かめてほしい〕
10. `debt-payback.md:53` の「反復の容量の 20% を返却枠の初期値」は、反復の計画を本標準が定めない(ADR-0080 決定1)以上、単位も型も持てない。**手引きの「例」と書き直し、語「初期値」を外す**。本件の範囲で直す

### 理由

1. **監査で再計算できる単位は件数だけ**。件数は Issue の一覧から第三者が数え直せる。工数・点数の比率は見積りの値に依り、見積りを書いた者しか再現できない〔推〕
2. **同じ単位を使えば、一様な分割は比率に効かない**。分子(SC-M の作業単位)と分母(実測スループット由来の容量)が同じ定義で数えられていれば、作業単位を一様に細かくしても両方が同じ倍率で増え、比率は動かない〔推: 算術上の性質〕。残る操作は**層ごとに分け方を変える**こと(SC-M を粗く、SC-B を細かく分けて SC-M の比率を下げて見せる)で、これは結論4 の事後の比率と、SC-M の項目ごとの計画件数と完了件数の突合で現れる
3. 工数比は、見積りを書く者が比率を決められる。SC-P・SC-B の見積りを膨らませれば SC-M の比率は下がる。見積りは平均約 30% 超過する〔外: Jørgensen 2014〕ので、比率の誤差そのものが 60% と 40% の余白の差と同じ桁になる。さらに AI が実装を担うとき「誰の工数か」が定まらない〔外 1.4〕。ADR-0019 決定3・ADR-0094 決定4 とも衝突する
4. 単位を組織に選ばせて 60% を既定値に残す案は、**既定値が「記録が無くても効く」という 1.7.7 の定義を満たせない**。単位が記録されていない案件では、何に対する 60% かが無く、効く値が存在しないためである。既定値として残すなら、単位も本標準が定めるしかない
5. 作業単位をタスク(PR)にしない理由: タスクは G-4 の後に作られ(テンプレ7)、スコープを確定する G-1・SG の時点には存在しない〔確: `lifecycle.md:488-490`、`deliverable-templates.md:1176`〕。合意の時点で数えられない単位は、合意の単位にできない
6. EV-0150 の水準を下げるのは、「出典の量と本文の量の不一致」を読み手が区別できる状態にするため(コアポリシー「書かれていない」と「課さないと決めた」の区別と同じ趣旨)。E1 のまま件数比で運用すると、DSDM の権威を借りて実証の無い値を示すことになる〔推〕

### 監査で確かめられること

- テンプレ6 の作業単位の定義と、実測スループットの集計に使った定義の一致(文面の照合)
- テンプレ6 の SC-M の作業単位の件数 ÷ 計画容量 が 60% 以下であること(再計算。機械でも可)
- 計画容量の算出に使った実測スループットの値が、記録された観測の期間の完了件数と一致すること(Issue の一覧から数え直す)
- ステージ移行ゲートの判定記録の事後の比率と、計画時の比率の差。SC-M の項目のうち、計画件数より多い作業単位へ分かれたものの一覧(層ごとの分け方の偏りの検出)
- 単位を変えた組織で、60%・20% を組織が定める値として記名・記録しているか(テーラリングの宣言)

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 工数比(DSDM に忠実) | 見積りを書く者が比率を操作できる。誤差の桁が余白と同じ。ADR-0019 決定3・ADR-0094 決定4 と衝突。AI 実装下で工数の主体が定まらない |
| 見積りの点数(story point)比 | velocity を採用しない指標とした判断(`metrics.md:86`)と同じ水増しの経路(点数を大きく書く)を持つ |
| 人のレビュー・判断の時間で容量を測る(外部 1.5 案C) | 人の時間の記録を課すことになり、R-3 の弊害を持ち込む。実証も無い〔外: 意見のみ〕 |
| 単位を定めず組織に記録させ、60% を既定値に残す | 結論7・理由4。既定値の型と両立しない |
| 「容量」の語をやめ、要求の件数で書く | 2.10.1 自身が指摘する大きさの不揃いを戻す。要求は作業単位より大きさのばらつきが大きい |
| 60% を外す | 外す根拠(実測)も無い。確約の上限そのものは ADR-0019 決定2 の判断であり、本件は単位の欠落の是正に留める。ただし E0 として開示する |

### 反論されうる点

- 「層に載せる時点で作業単位へ分けるのは、精度を装った見積り(2.10.2)ではないか」 → 分けることは件数の見積りであり、工数の見積りではない。分け方の誤差は事後の比率で現れ、隠れない。ただし「分ける作業が重い」という現場の反論は残る。本委員は、記録の検証可能性を優先する
- 「計画容量を過去のスループットから出すと、体制の変化(人の増減、AI の担い手の交代)を反映しない」 → そのとおり。第3章 3.13 の変化点を記録したステージでは、計画容量を出し直すか、出し直さない理由を記録させる案を足すべきと考える〔推〕。現場委員の意見を聞きたい
- 「件数比の 60% には出典が無い。それなら 60% を残す意味があるのか」 → 意味は実証されていない。だから E0 にする。残す理由は、上限が無い状態より「上限があり、記録で検証され、2027-10 に差し替えの材料が集まる」状態の方が信頼性が高いため〔推〕
- 「Issue の大きさのばらつきが大きい組織では、件数比は意味を持たない」 → 否定できない。事後の比率と項目ごとの分かれ方の記録が、その組織でばらつきが大きいことを示す材料になる。示されたら単位を変えるテーラリング(結論7)へ進める

## R-2 完了スループットに数える閉じ方

### 結論

1. **規範で「完了」を定義する**(2.10.2 要求事項1 の「完了した作業単位」と、運用メトリクスの算出方法の両方に掛ける)
   - 完了スループットに数えるのは、**完了として閉じ、その完了を閉じた者の申告以外の記録で確かめられる作業単位**に限る。確かめる記録は組織が定め、R-1 結論6 の作業単位の定義と同じ欄に書く(例: 作業単位を指す変更が取り込まれていること、価値責任者が受入基準の充足を記録したこと)
   - 取り下げ(計画しないことにした)・重複・他の作業単位への移送・スコープの調整(2.10.5 の SC-B の削除・SC-P の降格を含む)で閉じたものは数えない
   - 観測の期間の中で再び開かれた作業単位は、その期間の完了に数えない
2. **閉じた理由を、閉じるたびに記録させる**。除外の規則は理由の記録が無いと効かない(所見 A4)。理由の記録の無い閉鎖は完了に数えない(既定の completed を完了の証拠として扱わない)
3. **計画外の完了は数える**。ただし層の外(計画外)として区別し、R-1 結論4 の事後の比率の中で別に示す。スループット(予測の母数)と、確約の達成(約束の信頼性)は別の量として扱う
4. **閉じた理由の内訳を、完了スループットと並べて記録・開示する**(完了 / 取り下げ / 重複 / 移送 / 調整 / 理由なし)。内訳の比率に目標値を置かない
5. `metrics.md:175` の記述を直す(所見 A3)。完了スループットの対の指標として、滞留期間に加えて (a) 閉じた理由の内訳と再開の件数、(b) 計画時と事後の層ごとの作業単位の件数(R-1 結論4)を置く。ADR-0079 決定7 の「対の指標は滞留期間」の記述は、新 ADR で補う
6. 2022-05 より前の Issue など、閉じた理由を持たない過去の記録を実測の基礎にする場合は、その旨と件数を規模の合意の記録(2.10.2 要求事項4)に書かせる
7. 準拠テンプレートには集計の実装が無い(内部 2.2)。完了スループットの集計と閉じた理由の内訳に**実装マークを `state=undelivered` で立てる**。降ろし先は `impl-targets.yaml` の既存の id から選ぶ(候補 `evidence-aggregation`)。GitHub の `state_reason`(completed / not_planned / duplicate)は手引きに実装の例として書き、規範はツールの語を使わない

### 理由

1. 計画外・重複・調整で閉じたものを数えると、実測スループットが上がり、2.10.2 の規模の合意(次ステージの確約の量)が大きくなる。**閉じ方で確約の量を作れる**のは、監査人が最も塞ぐべき経路である〔推〕。2.10.5 の調整(SC-B の削除)が Issue のクローズで表されると、スコープを削った分がそのまま完了に数えられ、次の確約を増やす根拠になる
2. 理由を記録させないまま除外を書いても、GitHub の既定で全件が完了になる〔外 2.2〕。逆に、理由を記録させれば、閉じる者が理由を選ぶ時点で「完了と書くか」が記名の判断になり、監査で突合できる
3. 「閉じた者の申告以外の記録で確かめる」を置く理由: 完了の理由も申告である。`metrics.md:83` 前後の表が、分類ラベルの指標を「記録する者の申告で値が決まる」として退けた論法〔確〕は、完了の理由にも当てはまる。完了の側だけは、取り込まれた変更などの独立した記録で裏づけないと、申告の向きで値が動く
4. 7.7.2 は、AI 実行費用の単位あたり値の分母を「受入基準を満たして統合された変更」に限り、取り消し・統合されなかった試行を除いている(`exception-escalation.md:359`)〔確〕。同じ標準の中で、分母には除外を課し、スループットには課さないのは不整合である
5. 計画外を除かないのは、外部の一次資料のいずれも計画外の完了をスループットから除いていない〔外 2.3〕うえ、除くと「差し込みを計画外と書けばスループットが下がる」逆向きの操作を生むため〔推〕。区別は確約の達成の側で行う
6. 対の指標の穴(A3)は、ADR-0079 が手続2 を満たしたとした判断の前提を崩す。直さずに残すと、手続2 の検査が通っている形だけが残る

### 監査で確かめられること

- 完了に数えた作業単位の全件について、定義した裏づけの記録(取り込まれた変更など)が実在すること(抜き取り、または機械で全件)
- 閉じた理由の内訳。理由なしの件数。取り下げ・重複・調整の比率の期間ごとの変化(急増は閉じ方の付け替えの兆候)
- 2.10.5 の調整の記録(SC-B の削除など)と、同じ項目の閉じた理由の照合。調整で消えた項目が完了として閉じられていないか
- 再開の件数と、再開された項目が前の期間で完了に数えられていたか
- 規模の合意に使った実測スループットが、上の規則で数え直した値と一致するか

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 出口をすべて数え、内訳を併記する(Carmichael の Throughput) | 予測の母数(2.10.2 の合意)に取り下げが入り、確約の量を作れる経路が残る。内訳の併記は本案の結論4 で取り込む |
| 「完了」の定義を組織の Definition of Workflow に委ね、規範を置かない(Kanban Guide 型) | 何を除くかを組織が決められると、確約の量の算出が組織の定義で動く。除外の最低線(取り下げ・重複・移送・調整)は規範で置く。裏づけの記録の種類は組織に委ねる |
| 計画外の完了を除く | 結論3・理由5 |
| 完了の理由の記録(ラベル・close の理由)だけで完了とする | 理由3。申告で値が決まる |
| GitHub の `state_reason` を規範に書く | ツール中立を崩す。手引きの例に置く |
| 閉じた理由の比率に警戒水準を置く | 水準を置くと、理由を「完了」へ寄せる圧力になる。内訳は記録と開示に留め、監査の突合で使う〔推〕 |

### 反論されうる点

- 「理由の記録の無い閉鎖を完了に数えないのは、採用者の既存データを捨てさせる」 → 過去分は結論6 で件数を開示して使えばよい。今後の閉鎖に理由を求めることの負担は、閉じる操作で1つ選ぶことに限られる
- 「裏づけの記録を要求すると、コードを伴わない作業単位(調査・運用)が完了に数えられない」 → 裏づけの種類は組織が定める(価値責任者の受入の記録など)。種類を書かずに申告だけで足りるとする定義は認めない、という線だけを引く
- 「閉じ方の付け替え(取り下げを完了と書く)は、裏づけがあっても防げない」 → 取り下げた項目には取り込まれた変更が無いので、裏づけの規則で落ちる。防げないのは「変更を伴うが目的を果たさなかった完了」で、これは手戻り(やり直し)と再開の件数で見るしかない〔推〕
- 「スループットを目標にしない(2.10.4)なら、水増しの動機は無い」 → 目標にしなくても、2.10.2 で**確約の量の根拠**に使う以上、値を上げる動機は残る。目標の禁止は比較・評価の経路を塞ぐだけで、合意の経路は塞がない

## R-3 EV-0087 の実績の記録

### 結論

1. **テンプレ7 に実績(時間)の欄を足さない**。人の時間も、AI の実行時間も、作業単位(タスク)の粒度では記録させない(ADR-0094 決定3 を維持する)
2. **差し替え条件から「見積と実績の対応(実績 / 見積り)」を外し、記録が既に生まれる量へ改める**。改めた条件は次のとおりとする
   - 標準のテンプレ7 の「見積」に記入があるタスクのうち、8時間を超えたタスクと超えないタスクの、やり直し(テンプレ7 の状態。手戻り率の分子)の比率の差
   - 8時間を超えたタスクのうち、取り込まれた変更が規模の基準値(RC-01)を超えて「規模の確認」を経た比率
   - 比率の比較は、第4章「閾値の設定と較正」の要求事項3(観測の窓と窓の中の最小標本数)に従う。「4四半期分」は外す
3. **経過時間(Draft PR の作成から取り込みまで)を差し替え条件に採らない**。経過時間は工数と別の量であり、8時間の目安と比べられない
4. **8時間の目安は残す**。ただし RC-03 の「担っている保証」を「超えたら理由を記録する(計画の時点で、分割の要否を人に問う)」と明記し、タスクの大きさの統制は RC-01・RC-02 と G-4 の分割基準が担うことを登録簿に書く
5. 準拠テンプレートは見積の列を omit している(`template-fields.yaml:671-675`)ため、RC-03 が適用される欄が無い。**準拠テンプレートでは RC-03 を「適用欄なし」として再評価待ちの件数から外し、その旨を `/pit` の注記に出す**。見積の列を足した採用者だけが RC-03 を再評価の対象にする。実装マークを立てる(降ろし先 `process-change-skill`、IMPL-0103 と同じ)
6. 見積の値を人の評価に使わない歯止めは、既存の 7.7.9 要求事項6(見積りの精度の目標を評価に使わない)と附属書H の内部監査の観点20(`assurance-case.md:272`)で足りる。実績を取らない以上、タスク単位の見積り精度は算出できず、新しい禁止は要らない
7. 見直し期日(2027-04)に、採用組織からの材料が得られていない場合は、期日を黙って延ばさず、「材料なし」と記録したうえで、外すか延ばすかを新 ADR で判断する〔推: 根拠水準の運用規則の読み。規格委員の見解を聞きたい〕

### 理由

1. **実績の時間を課さない理由**は3つある。(a) 監視・時間記録が業績を改善する証拠は無く〔外: Ravid 2023 メタ分析〕、記録を評価に使うと測定の機能不全が起きる〔外: Austin、意見〕。(b) 自分の予実を振り返るだけでは見積りは良くならない〔外: Jørgensen & Gruschke 2009〕。記録の目的(目安の校正)に対して、記録の効果が実証されていない。(c) AI を使った作業では、人の体感の速さと実測が逆向きになった〔外: METR RCT、単一研究〕。人の申告の時間は、監査の証跡として信頼できない
2. 監査人の立場からは、**記録を課すなら、その記録の正しさを確かめる手段が要る**。申告の時間には照合する独立の記録が無い。PSP の手記録にも誤りが分析されている〔外: Johnson & Disney、結論未確認〕
3. 経過時間を採らない理由: Draft PR の作成から取り込みまでの時間には、待ち・レビュー・並列作業が混じる〔確: 内部 3.5-2〕。8時間の目安は人の作業量を前提にしており、比べる量が違う。さらに、経過時間は PR の作成者に帰属するため、タスク × 人の時間の記録に近い性質を持ち、ADR-0094 決定3 の禁止を形を変えて開く〔推〕
4. やり直しの比率は、テンプレ7 の状態とトレーラ `Spec: F-NNN / Task-N` から**既に記録される量**である(`deliverable-templates.md:1178`)〔確〕。条件の後半(手戻りの有無)は現行の条件にも含まれており、外すのは測れない前半だけである。これで `evidence-marking.md:61` の「判断に使う材料」を満たす
5. 目安を外さない理由: 8時間の目安は、計画の時点で人に分割の要否を考えさせる唯一の時間の手がかりで、規模の基準値(変更の行数・ファイル数)は実装の後にしか測れない〔推〕。独自の保証が「理由の記録」だけでも、それは計画の時点の統制であり、RC-01 とは時点が違う。ただし、この保証が手戻りを減らしているかは測られていない(だから E0 のまま残す)
6. 準拠テンプレートで、適用欄の無い定数の再評価を求めるのは、使っていない値の「残す・外す・移す」を記名させることになる。記名の記録が実態の無い判断の証跡になり、監査は再評価の記録を信頼できなくなる〔推〕

### 監査で確かめられること

- テンプレ7 の見積の欄の記入と、8時間を超えたタスクの理由の記録の有無(全件の照合が可能)
- 8時間を超えたタスクと超えないタスクの、やり直しの件数(トレーラから機械で数えられる)。窓の中の件数が最小標本数に満たない期間を判断に使っていないこと
- タスクの見積・実績・経過時間が、人事評価の規程・目標設定の様式に現れていないこと(観点20 の照合)
- 準拠テンプレートの採用者で、RC-03 の再評価の記録が、見積の列を持つ組織だけにあること

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| テンプレ7 に実績の時間の欄を足す(任意の欄を含む) | 理由1・2。任意でも、欄があれば集計され、評価へ流れる経路が開く。ADR-0094 決定3 と衝突 |
| 人の時間と AI の実行時間を別の欄で取る(外部 3.4 案E) | 同上。確立した作法が無い〔外〕 |
| 差し替え条件を経過時間に改める(#406 の起案・現場案) | 理由3。量が違ううえ、人に帰属する時間の記録になる |
| 見積の当否を完了時に区分で記名させる(外部 3.4 案C) | 区分の判断は申告であり、照合する記録が無い。8時間の境界の妥当性を確かめる材料にならない |
| 8時間の目安をいま外す | 外す根拠(手戻りに差が無い実測)も無い。保証の時点が RC-01 と違う(理由5)。外すなら ADR-0058 決定6 を置き換える判断が要り、材料を得てから行う |
| 差し替え条件をそのまま残し、2027-04 の見直しに委ねる | 規則上書けていない条件(所見 A5)を、期日まで放置することになる |

### 反論されうる点

- 「やり直しの比率の差を見ても、8時間という境界の妥当性は分からない。大きいタスクは本来難しいので、差があっても目安のおかげとは言えない」 → そのとおり。改めた条件で言えるのは「差が無ければ外す」までで、「差があるから 8時間が正しい」とは言えない。条件の文にこの非対称を書き添えるべきである
- 「準拠テンプレートが見積の列を持たない以上、材料はどこからも出ない」 → 標準のテンプレ7 を使う採用者からしか出ない。出なければ結論7 のとおり記録して判断する。準拠テンプレートに列を戻す案は、列を足した瞬間に実績の欄を求める声が出るため、本委員は採らない
- 「理由の記録だけを担う目安は、眺めるだけの定数ではないか」 → 理由の記録は計画の承認者(G-4)が読む。読まれているかは G-4 の判定記録で確かめられる。読まれていないなら、それが外す材料になる

## R-4 記録

### 結論

1. **新しい ADR を1本起こす**(番号は採番時)。名称の案: 「容量を作業単位の件数で数え、完了を裏づけの記録で数え、EV-0087 の差し替え条件を記録が生まれる量へ改める」
2. 既存の ADR との関係
   - ADR-0019 決定2 を**補う**(置き換えない): 60% の分母を作業単位の件数の計画容量と定め、「DSDM の推奨を初期値として採った」の出典の表示を、量の移し替えを開示する形へ改めたことを記録する。上限 60% の判断そのものは維持する
   - ADR-0079 決定7 の「完了スループットの対の指標を滞留期間と明記した」を**補う**: 滞留期間は閉鎖と分割の歪みを拾わない(所見 A3)ため、閉じた理由の内訳と層ごとの事後の件数を対の指標に加えた
   - ADR-0058 決定6 を**補う**: 目安と登録簿は維持し、EV-0087 の差し替え条件を改めた。準拠テンプレートでの RC-03 の扱いを定めた
   - ADR-0094 決定6 の送り先として、本 ADR で閉じたことを記録する。決定3(作業単位 × 人の実績を課さない)は**維持**し、本件でも課さなかったことを書く
   - ADR-0097 決定2 の 2.10.1 の振り分け(既定値)は**維持**し、単位を変えるテーラリングでは組織が定める値へ移ることを書く
3. 「課さないと決めたこと」に次を明記する
   - 工数比・見積りの点数による容量の配分
   - 反復(スプリント)の容量の計画の方法(ADR-0080 決定1 のまま)
   - タスクの粒度の実績の時間(人・AI のどちらも)と、経過時間による差し替え条件
   - 計画外の完了をスループットから除くこと
   - 閉じた理由の比率への警戒水準・目標値
   - 規範での GitHub の `state_reason` の指定
4. 根拠水準: EV-0150 を E0 へ書き直す。本件の判断(作業単位の件数で容量を数え、裏づけの記録で完了を数える)に新しいマーク(E0)を付ける。差し替え条件は「計画時と事後の比率の差、閉じた理由の内訳のうち理由なしの比率、裏づけの記録の欠けた完了の件数」とする
5. 実装マーク: 完了スループットの集計と閉じた理由の内訳(undelivered)、テンプレ6 の欄の追加(準拠テンプレートの企画書)、G-1 の検査による作業単位の定義・単位期間・計画容量の空欄の検出、RC-03 の「適用欄なし」の扱い
6. 範囲の外で、本件が見つけた食い違い(2.10.5 の「容量の上限」の読み、`metrics.md:165` の「着手ラベル」が準拠テンプレートの語彙に無いこと)は、本件で直すか、後継の Issue へ送ることを ADR に明記する。放置しない

### 理由

- 3 点は同じ根(作業単位・完了の定義の欠落)を持つため、1本の ADR で定義を揃えて記録する方が、後から読む者が定義の所在を1か所で辿れる〔推〕
- 採用済み ADR の本文は書き換えない(CLAUDE.md の ADR 規則)。補う関係を新 ADR に書く
- 却下は成果である。工数比・実績の欄・経過時間は、#406 でも本件でも提案されたものであり、課さないと決めた理由を残さないと、同じ提案が繰り返される

### 監査で確かめられること

- 新 ADR の「課さないと決めたこと」と、本文・テンプレートに実績の欄・工数比の記述が現れないことの一致
- `npm run lint:refs` で、新 ADR と EV・IMPL の番号の実在

### 採らない案

| 案 | 採らない理由 |
| --- | --- |
| 3 論点を別々の ADR にする | 作業単位の定義が3つの ADR に分散し、定義の食い違いが再発する |
| ADR を起こさず、本文と EV の修正だけで済ませる | 単位の決定・完了の定義・差し替え条件の変更は、あとから変えにくい決定であり、採らなかった案の記録が要る |
| ADR-0019 を置き換える | 3層・60%・件数での合意の判断は維持する。欠けていたのは単位の定義で、判断の誤りではない |

### 反論されうる点

- 「ADR-0079 決定7 の対の指標の穴は、本件の議題に無い」 → 議題 R-2 の「運用メトリクスへの降ろし方」に含まれる。完了スループットの定義を変えるなら、その対の指標の記述が誤りのまま残ることは認められない
- 「EV-0150 を E0 へ下げるのは過剰ではないか」 → 間接の根拠(DSDM)が支えるのは工数比の 60% であり、件数比の 60% ではない。水準は根拠の量に対して付けるものであり、値の名前に対してではない

## 論点ごとの結論(1行)

- R-1: 容量は本標準が「作業単位(スコープ3層に載せる項目)の件数」と定め、計画容量 = 実測スループット × 単位期間の数。合意・実測・比率で同じ定義を使い、事後の層別件数を記録する。60% は件数比へ移したことを開示し EV-0150 を E0 へ。単位を変える組織では 60% も組織が定める値へ移る
- R-2: 規範で完了を定義し、閉じた者の申告以外の記録で裏づけた完了だけを数える。取り下げ・重複・移送・調整は除き、計画外の完了は数えて区別する。閉じた理由の記録を必須にし、内訳を開示する。`metrics.md:175` の対の指標の誤りを直す
- R-3: 実績の欄は足さない。経過時間も採らない。差し替え条件を、8時間超と以下のタスクのやり直しの比率の差(窓と最小標本数つき)へ改め、目安は残す。準拠テンプレートでは RC-03 を適用欄なしとして再評価待ちから外す
- R-4: 新 ADR を1本起こし、ADR-0019 決定2・ADR-0079 決定7・ADR-0058 決定6 を補う。ADR-0094 決定3・ADR-0097 決定2 は維持。工数比・実績の時間・経過時間・計画外の除外・閉じ方の警戒水準を「課さないと決めたこと」に書く
