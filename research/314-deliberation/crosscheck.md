### X-1 ADR-0084 は ADR-0061 決定2 を「補う」のではなく一部置き換えている

- 重大度: 中
- 所在: `src/content/docs/adr/0084-check-strength-plans-and-resident-rules.md:10`(ステータス)、`src/content/docs/adr/0061-check-means-on-implementation-marks.md:10`
- 問題: ADR-0061 決定2 は「`check` を欠くマークを、検査は落としません」と定めた。ADR-0084 決定1 はこれを「落とす」へ反転させる。ADR-0061 決定1 の表の「(書いていない) 未分類」の行も無くなり、`presence` の定義(「記録・欄・ファイル・キーの有無まで」)も単位の限定で狭まった。ADR-0084 のステータスは「採用済みの ADR の決定を置き換えません」「補います」と書いており、事実と合わない。ADR-0074 決定5 は、同じ型の変更を「読み方ではなく決定の範囲の変更」として「一部置き換え」と扱い、ADR-0073 のステータスを `一部置き換え(→ ADR-0074 の決定5)` に改めた。先例と食い違う。裁定(`decision.md` の冒頭)の「補い」という語に由来する
- 提案: ADR-0084 のステータスを「ADR-0061 の決定2(未分類を落とさない)と、決定1 の表の未分類の行・`presence` の定義を一部置き換える」へ改める。ADR-0061 のステータスを `採用(2026-10-13)。一部置き換え(→ ADR-0084 の決定1)` の形にそろえる。決定3(棚卸しを行わない)は時点の決定なので「補う」のままでよい。議長は裁定の語を確かめる

- 重大度: 中
- 所在: `template/scripts/gate/test-claude-md-resident.mjs:23`(リポジトリの `CLAUDE.md` を読む)、`:57`〜`:62`(原文の文字列に依存する置き換え)、`template/.github/workflows/gate-g5.yml:107`(contract ジョブから常に実行)

### X-5 複数行の HTML コメントで常駐の規則を隠しても照合が通る

- 重大度: 中
- 所在: `template/scripts/gate/claude-md-resident.mjs` の `linesBySection`(行ごとに `/<!--.*?-->/g` を除くだけ)、`template/scripts/gate/check-context-refs.mjs` の `referencesOf`(同じ)
- 問題: 「行ってはならない作業」の表の本文を `<!--` と `-->` の2行で囲むと、表は描画上も、HTML コメントを除いて読み込む系でも見えなくなる。それでも `check-process-rules` は「常駐の規則が揃っています(16 節、規則 90 件)」と通す(写しで再現した)。行の単位の除去では複数行のコメントを外せないためである。参照切れの検査は逆の向きで、複数行のコメントの中のリンクを読んで誤検出しうる
- 提案: 照合と参照切れの両方で、行に分ける前に複数行のコメント(`/<!--[\s\S]*?-->/g`)を空行に置き換える(行番号を保つ)。変異の試験に「節の本文を複数行のコメントで囲むと規則が無いと出る」を足す

### X-6 `manual` の注記に「確かめる者と時点」が無いマークが多い。`machine` から下げたマークは機械の確かめを持つのに「機械は確かめない」と表示される

- 問題:
  - `implementation-marking.md` と ADR-0061 決定1 は、`manual` について「機械は確かめない。確かめる者と時点を `note` に書く」と定める。#314 で新たに `manual` になった 82 件のうち、確かめる者を示す語(判定者・監査・確認者・読む など)を含まない注記が、語での粗い数えで約 47 件ある。`presence` には単位の語を機械で求めたが、`manual` には同じ形の求めが無く、非対称である
  - 下げた 8 件のうち、IMPL-0311 の注記は「test-edition-end.mjs が、欄の無い D-0 で注記が出ることを実行して確かめる」と書く。IMPL-0119 は「実行して確かめた」と書く。台帳は「人が確かめる(機械は確かめない)」と表示する。迷えば弱い値という裁定には従っている。しかし、表示がもう一方の向きの誤り(試験があるのに無いと読ませる)になっている。CLAUDE.md の「判断軸は信頼性」「最小限の変更という動機は存在しない」に照らすと、対の片側を足して `machine` に保つほうが、表示も検査も強い

### X-7 振る舞いの規則に `presence`(単位: ファイル)が付いている

### X-8 参照切れの検査の範囲の外にした「逆引用符の中のパス」の理由が、範囲を広く取りすぎている

- 重大度: 中

- 問題: 外した理由は「テンプレートの例は、案件が後で作るファイルを指す」である。これは `docs/` と `context/` の下を指すパス(`docs/D-0-governance.md` など)には当たる。しかしテンプレートが持つ `.claude/` と `scripts/` の下を指すパスには当たらない。テンプレートの `CLAUDE.md`・スキル・`context/` には `.claude/`・`scripts/` を指す逆引用符のパスが 71 件あり、実在しないのは置き場の雛形(`.claude/skills/gate/gates/G-N.md`)の1件だけだった。いま検査が数える参照はテンプレート全体で3件にとどまる。`CLAUDE.md` が「規則の索引」として行末に置く所在(`詳細: .claude/skills/...`)は、すべて範囲の外にある。基準6 の「参照切れ 0 件」のうち、テンプレートで実際に参照切れの起こる経路がほとんど降りていない

- 所在: `scripts/lib/impl-inventory.mjs` の `machineTestProblems`・`templateTestWired`、`community/implementation-marking.md` の「`machine` の要件」
- 問題:
  - 目印は、試験のファイルのどこにあってもよい(コメントでよい。検査に近い位置にあることも求めない)。IMPL-0140 は `:ng` と `:ok` を同じ行の1つの検査に付けている(`test-decisions.mjs:111`)。結線の確かめは、手順の `if:` と `run: node … || true` を見ない(ジョブ単位の `continue-on-error` だけを見る)。「示さない」と開示した範囲の内側だが、手間の小さい補強が残る
  - 規約は `:ng` を「違反の入力で落ちる」と定める。一方 `machine` の定義は「違反を止めるか**件数で出す**」で、警告・一覧にとどめる規定(IMPL-0078 の承認者の数、IMPL-0203 の既存のテストの変更の一覧)は落ちない。これらの `:ng` は「警告が出る」を確かめており、規約の文と合わない
- 提案: (1) 同じ IMPL の `:ng` と `:ok` が別の行にあることを求める。(2) `run:` の行の `|| true` と、手順の `if:` を結線の不備に数える。(3) `:ng` の定義を「違反の入力で検出する(落ちる、または件数・一覧・警告に出る)」へ改める

### X-12 常駐の規則の一覧の縮小と、後置の打ち消しは機械で止まらない

- 重大度: 軽微
- 所在: `template/scripts/gate/claude-md-resident.mjs`(`omit`)、`template/scripts/gate/test-init-g5.mjs:85`〜`:99`
- 問題: `--write-resident` は追加だけで、一覧から消えた規則を足し戻さないことも確かめた(裁定どおり)。ただし、(a) `omit` の項目に理由があるかを機械は確かめない、(b) 節には `omit` が無く、節の見出しを改めると手で `sections` を直すしかない、(c) 案件が `CLAUDE.md` の行と一覧の規則を同じ変更で消すと、どの検査も落ちない(差分のレビューだけが拾う)、(d) 行末に「(当社では適用しない)」と書き足しても照合は通る(写しで確かめた)。(d) は裁定の「周りに書き足す」を許した帰結である
- 提案: `omit` の各項目に `reason` と `approvedBy`(AI の名義でないこと)を求める検査を `test-init-g5.mjs` に足す。(c)(d) は ADR-0084 決定2 と `template-repository.md` に限界として書く

### X-13 降ろす順序の第3段を注記の語で決めるため、付随的な言及を拾う

- 重大度: 軽微
- 所在: `scripts/lib/impl-inventory.mjs` の `undeliveredRank`
- 問題: `/G-7|G-8|R1/` は、IMPL-0210「(R1 は10営業日前)」のような付随の言及も第3段に入れる。申告どおりの限界だが、規約に書かれていない
- 提案: 規約の順序の段落に「第3段は注記の語(G-7・G-8・R1)で判別し、付随の言及も含む」と書く。`impl-no-adopter.yaml` と同じく、節の鍵の登録簿で決める形も検討する

### X-14 `presence` の定義の文が、単位の列挙と食い違う

- 重大度: 軽微
- 所在: `community/implementation-marking.md` の検査の手段の表(`presence` の行)、`scripts/check-impl.mjs` の `renderLedger`(台帳の件数の表)
- 問題: 表は「記録・欄・ファイル・キーの有無まで」と書き、直後の節と検査は単位を「欄・キー・行・ファイル」に限る。「記録」は単位に無く、「行」が表に無い
- 提案: 表と台帳の文を「規則を運ぶ単位(欄・キー・行・ファイル)の有無まで」へそろえる

### X-15 範囲の外の否定の件数が、限界の表に出ていない

- 重大度: 軽微
- 所在: `community/implementation-marking.md` の「検査の限界」の表、`scripts/check-skill-provisions.mjs`
- 問題: 裁定 R-5 は「件数を限界の表に出す」とした。実装は件数を検査の出力にだけ出し、表には「件数を検査の出力に出す」と書く。読み手は、出力を見ない限り規模(太字 111 行、平叙 315 行)を知らない
- 提案: 件数を台帳(自動生成)に書き出し、限界の表から引く。手書きの数値は古くなるので書かない

### X-16 逆向きの追跡の範囲の境界が開示されていない

- 重大度: 軽微
- 所在: `scripts/check-impl.mjs`(対象は `scripts/gate`・`scripts/init`・`.claude/hooks`・`.github/workflows`)、`community/implementation-marking.md` の逆向きの追跡の節
- 問題: 規則を運ぶ `.claude/guard.json`、`.github/rulesets/` の `team.json` 以外、`.github/CODEOWNERS`、`.github/actions/` は対象の外にある。規約はこれを書いていない。「どちらにも無いファイルを落とす」が、全ての実行層に及ぶと読まれうる
- 提案: 対象の外を規約に列挙する。または `.claude/*.json` と `.github/rulesets/*.json` を対象に加える

### X-17 取り込みの順序。テンプレートの main が分岐しており、取り込むと逆向きの追跡が新しいファイルを落とす

- 重大度: 中
- 所在: 親の `template` のポインタ(`feee35c` → `26eda09`)、テンプレートの `origin/main`(`5f67ed0`)
- 問題: `26eda09` と、その土台の `3834270`(#313)は、テンプレートの main に入っていない。main は #54 で先へ進み、両側が変えたファイルが 18 件ある(`gate-g5.yml`、`test-check-pr.mjs`、`check-pr.mjs`、`aggregate-evidence.mjs`、`generate-profile.mjs`、`tailoring-kb.json` など)。親の `work/314` も、親の main(`18b9bd5`。テンプレートのポインタは `397930f`)に入っていない。main 側で足された `record-copy.yml`・`records.mjs`・試験 4 本は、取り込むと逆向きの追跡に落とされる(検査は正しく働く)。`test-check-pr.mjs` の目印(IMPL-0049・0059・0062・0078・0099 ほか)は、競合を解くときに失われやすい
- 提案: テンプレートを #313 → #314 の順に main へ取り込み、競合を解いたあとで次を行う。`check-process-rules.mjs --write-resident`(追加だけ)、`npm run template:kb`、`npm run impl:write`。新しいファイルを登録簿か除外の一覧へ載せる。`npm run check` を通す。親の main はテンプレートの取り込みの後に進める

### X-18 採用者に委ねられない規定の登録簿が、裁定の「5.5」を 5.5.5 に絞っている

- 重大度: 軽微
- 所在: `src/data/impl-no-adopter.yaml`
- 問題: 裁定 R-4 は「5.5 の人が確定する判断」とした。登録簿は 5.5.5 だけを挙げる。5.5.1(人へ戻す3つの場合)と、第5章 5.8.5(AI 協調の作業で行ってはならないこと)は登録簿に無い。いま両方の節に `undelivered` のマークは無いので、実害は無い
- 提案: 絞った理由を登録簿の `why` か規約に書く。または 5.5.1 を加える
