# #335 反対の委員の意見書

立場: 調査(01)の推す案 A(現状維持+衝突の修正)・B(例示の列を分ける)に反対する側から攻める。確かめた原文は roles-responsibilities.md L841・L882・L886、ADR-0078 L56、ADR-0038 L22・L56、adr/index.md L21。

## 1. 推す案の欠陥

### 1.1 L841 と L882 の衝突(問い1)

- 衝突は実在する。調査の結論(L882 が正、L841 の「限り」が誤り)は、攻めても崩れない。
  - ADR-0078 L56 は「ガード・検証ゲート・重要テストの削除は…`state:needs-owner` の併記は取り消せない操作の定義によらず保つ」と書く。L882 の第2の条件(ガード等の削除でも併記)は、この決定の写しである。L841 の「取り消せない操作に当たる場合に限り」は、ADR-0038 L22 の旧文「不可逆4操作に該当する場合のみ」の残りで、ADR-0078 で置き換わった側である。
  - 逆(L841 が正で L882 が広げすぎ)とは読めない。L882 を狭めると、ADR-0078 決定2 の併記の維持を覆す。これは案 C であり、ADR の原則の変更になる。
- ただし調査には2つの見落としがある。
  - L841 は「強制層の**変更**」、L882 は「強制層の**縮小**」を主語にする。「限り」を外すだけでは、強制層の拡張・強化(禁止設定を足す)まで needs-owner を併記する読みが残る。直す文は「縮小のうち」と範囲を L882 へ寄せる形でなければならない。「限り」の削除だけでは足りない。
  - 調査は「意味が定まっているので編集の指摘に近い」とする。この見立ては概ね正しい。ただし「限り」を外すと、採用者から見て needs-owner を併記する場面が広がって見える(ガード等の削除は、取り消せない操作でなくても併記)。これは新しい義務に見えるが、L882 と ADR-0078 決定2 が既に課している義務を L841 が誤って狭めていたにすぎない。**新しい義務ではなく、既存の義務への是正**と書き分ける必要がある。調査はこの区別を明示していない。直しの記録に「L882 が既存の義務、L841 の過少な記述を是正」と残さないと、後で義務の新設と誤読される。

### 1.2 案 B(列を分ける)の欠陥(問い2・3)

- 残る並び(3.5.5 L882)は、混同ではなく**併記の条件が2つある**ことの表記である。「どちらの場合も同じ手続き(needs-owner 併記)に入る」を1文に置いたもので、意図的である。直後の L886 が「別の停止の事由」と明記しており、読み手は区別できる。
- 例示の列を別の表に分けると、次の誤読が生じる。
  - 手続きが異なると読まれる。実際には併記の手続きは同一であり、違いは「止まる理由」だけである。表を分けるほど、手続きの差を示唆する。
  - 例示を網羅したと読まれる。5.5.1 の列挙は例示で、閉じていない(ADR-0041・ADR-0053 決定2)。統制の弱化の側は「パスの列挙で定義しない」(ADR-0038 決定1)。例の表を2本に増やすと、2本の和集合を全体と読む誤りが増える。3.5.5 の既存の表(3性質)は、すでに「例」の欄を持つ。そこへ足せば足りる。
- 調査 6.1 の「5.5.1 に正本の例示を置くか」は、さらに危ない。現状、本文は列挙を持たず(基準だけ)、template (c) だけが列を持つ。本文に列を置くと、ADR-0053 が誤りと論じた閉じた列挙を再び正本に据える。**本文には基準だけを残し、例示の正本を作らない**ほうが筋が通る。
- 配備の例の置き場(#329 17 節)は、3.5.5 の既存の表の例の欄へ「配備の環境の保護規則の削除」を足す1行で足りる。これは3性質(遮断の解除)から導ける例であり、列の分離を要さない。配備の起動が取り消せない操作であることは、5.5.1 箇条4 が既に述べる(調査 3 章)。

## 2. 残る案と理由

**案 A′(A を修正した形)を残す。** 内容は次のとおり。

1. L841 を L882 に揃える。「強制層の縮小は…。ガード・検証のゲート・重要なテストを削除する場合と、取り消せない操作に当たる場合は needs-owner を併記する」の趣旨に直す。主語を「縮小」に合わせる。これは編集の指摘に当たる(会議体は不要。議長が直し、独立の突合を1回)。
2. 3.5.5 の既存の表の「例」の欄へ、配備の統制を外す変更を1行足す(#329 17 節の申し送り1点目。#329 の未確定の点に依らない)。
3. 例示の列を分けない理由を3.5.5 に1文で書く(Issue の受け入れ条件「分けない理由を書く」)。要点は「併記の手続きは同一で、止まる事由だけが別。例示は網羅ではない」。分けない理由は、読み手の誤読(手続きの差の示唆・網羅の装い)で、変更量ではない。
4. ADR は書き換えない(問い4)。
   - ADR-0038 L22・L56 の引用は当時の記録であり、adr/index.md L21 により本文は不変。本文側(3.5.5)へ「ADR-0038 の当時の記述は置き換わった」と注記する案は、規範の節へ歴史を混ぜるので採らない(「歴史的経緯へ隔離」の方針とも合わない)。
   - 置き換えの案内はステータスの節(採用後に書き換えてよい唯一の箇所)で行う。ADR-0038 のステータスに「決定3 の『不可逆4操作』は ADR-0053・ADR-0078 で基準へ置き換わった」と1行足す。これは規則に反しない。ADR-0078 L56 の「原則4・4.7.3」への宙に浮いた参照(#316 で消えた)も、ADR-0078 のステータスの節に案内を足す。新 ADR は立てない。判断を変えないので、置き換える決定が無い。
5. template 側(CLAUDE.md L43 が L882 の併記条件を写していない点など)は、準拠テンプレートを触る Issue の直列の規則に従い、この束で触れず、Issue のコメントへ一覧を残す。実在の差なので、後続を必ず起票または既存 Issue へ足す(「後継は既存の Issue へ寄せる」)。

## 3. 採らない案と理由

- **案 B(列の分離)**: 1.2 のとおり。手続きの差の誤示唆と網羅の装い、本文に例示の正本を作る危険(ADR-0053 の論じた誤りの再来)。信頼性の観点から採らない。分けないことで失うもの(配備の例の置き場)は、既存の表の1行で回収できる。
- **案 C(統制の弱化の併記を見直す)**: 反対のための反対をしても、正しい点は見つからない。ADR-0038 L56 とADR-0078 L56 は、検知者が許容を判断できない以上、事業決裁者への経路を併せて開くことを決めている。併記を外すと、遮断の解除をプラットフォーム担当者だけで許容できる経路が開く。安全側の義務の縮小で、重の事項。採らない。
- **案 D(統制の弱化を取り消せない操作の下位へ戻す)**: ブランチ上の編集は取り消せる(人のマージまで効果が生じない)。5.5.1 の基準(取り消せない時間帯の存在)を壊す。採らない。
- **案 E(needs-platform に一本化)**: C と同じ理由で採らない。経路が単純になることは、採否の理由にならない。
- 5案の中に、本当は正しい採らない案は無かった。ただし C の問題意識(併記の根拠が取り消せない操作の性質から来ないこと)は、現状でも L882 が「ガード等の削除でも併記」と別の条件で書くことで満たされている。根拠は ADR-0078 L56 の文で足りる。

## 4. 新しい義務・ADR の原則の変更・安全に当たる点(重へ上げる要否)

- 新しい義務: **無い**。ただし L841 の直しは、採用者の目には needs-owner の併記が増えたように見える。実際は L882 と ADR-0078 決定2 が既に課した義務を、L841 の誤った狭い記述から是正するものである。直しの記録(コミットと Issue のコメント)に「既存の義務の是正で、新設ではない」と明記する。
- ADR の原則の変更: **無い**。案 A′ は ADR-0078 決定2 を維持する。ステータスの節の追記は本文の書き換えではない。
- 安全: 案 A′ は併記の範囲を狭めない(広い側の L882 へ揃える)ので、安全側の縮小は無い。
- 重へ上げる要否: **不要**。割れた点が出るとすれば、起案の委員が案 B を推し、本意見が案 A′ を推す点のみ。これは例示の置き場所の問題で、新しい義務・ADR の原則の変更・安全のいずれにも当たらない。軽のまま議長が裁定する。裁定で採らなかった案(B)と理由(1.2)は decision に記録する。独立の突合では、L841 の直しの主語(変更と縮小)、template L43 の差の後続の所在、ADR ステータス追記の書式(adr/index.md の運用)を見るよう勧める。
