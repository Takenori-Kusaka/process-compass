いまのテンプレートで、出力を残して流した(`REGRESS_CAPTURE=1`)結果を、拒否の場面ごとに調べた。

## 4. 裁定に従えなかった点・判断を要した点

1. **R-1.1「文言の有無だけを確かめる場面を、決定の中身を確かめる形へ改めてから移す」を実施していない**。第1段は元の仕組みのまま移すことを優先し(R-1.2)、第2段の依頼の範囲に含まれていなかった。該当の場面の洗い出し(v3 の K65 の前半「不可逆4操作が残っていない」など)を後継の Issue に回す(6 節の案4)
2. **R-5 の手順の置き場**: 依頼は「research-to-docs のスキルや community の運営の文書など」とした。`community/provision-forms.md` の「起草の規則(機械で検査しないもの)」に置いた。会議体の突合の手順(緩める理由への読み替えを問う)が既にそこにあるためである。親の `CLAUDE.md` と `.claude/skills/` は変えていない。エージェントの設定・指示の層であり、エージェントの依頼だけで書き換えないため。CLAUDE.md の「却下は成果である」の箇条へ手順を引くかは、人が決める
3. **R-6「共有する一覧」の形**: 別の一覧のファイルを作らず、`gate-g5.yml` のジョブ `contract` の手順そのものを一覧として読む形にした。別のファイルにすると、`gate-g5.yml` 側もそのファイルを読むループへ書き換える必要があり、手順ごとの注記と実行の表示を失う。一覧が1か所なので食い違いが起きない。`gate-g5.yml` に足した試験は親でも流れ、足し忘れた `test-*.mjs` は失敗になる
4. **R-7 の 5.8.5 の補足**: 既存の段落の直後に箇条として置き、IMPL-0204 の注記を改めた(新しい IMPL を立てない)。期待値の改めに決定を引くことは、準拠テンプレートに検出が無いため、IMPL-0204(降りていない、#360)に含めた
5. **IMPL-0350 を delivered・manual とした**: gate-g5 は取り出した版の試験だけを実行するため、版管理の外の試験は G-5 の結果に入らない。手元の試験を PR の検証方法で根拠に挙げていないかは機械で確かめないため、確かめる者を G-6 の判定者とした
6. **K65 の直しで、常駐の規則の一覧(`claude-md-resident.json` の CR-010)の核の文言にも基準を足した**。`CLAUDE.md` の (c) の行の中に基準を書き足すと、核の文言が連続した部分文字列でなくなり、初期化の事前点検(常駐の規則の照合)が落ちたため。核を強める向きの変更で、基準の喪失そのものを機械で固定する。強制層の変更なので `state:needs-platform`
7. **入力を直した t288 系は、#312 より前のテンプレートでは止まる**。置き換えの空振りを黙って通さないための確認による。p302 との一致は第1段で確かめ済みで、第2段の直しはいまの決定に合わせるものである

## 6. 後継の Issue の起票案(起票は人の了承を得てから)

### 案1 同じ変化点で名簿へ足して確認し任命すると拒否される(scenarios の3場面)

- 事実: テンプレート `4af67c5`(#296 突合の付記)から、名簿へ足して `nameConfirmed: true` を付け、同じ変化点で技術判断者に任命すると「記名を受け付けられません: … "Claude Dupont" は モデル名または提供者名を含む」で拒否される。p302 では受け付けていた。`generate-profile.mjs` の `namingProblems(config)` が、変化点の記録(`nameConfirmations`・`decidedBy`)を足す前の構成で判定する
- 問い: 評価の順序の不具合(回帰)か、確認を先の変化点で記録させる決定か。#296 の付記は「本人以外の記名に限る」とだけ定め、同じ変化点での確認と任命を定めていない
- 受入条件の案: 決定を ADR に記録する。回帰なら評価の順序を直し、印を外す。決定なら場面の期待を決定の引用つきで改める(`changed`)。いずれの場合も、scenarios の印の Issue 番号を #319 から付け替える
