## 0. 本委員が自分で確かめた事実(調査に無いもの)

1. **スイートの場面は、テンプレートの処理を子プロセスで動かす**。`lib.mjs` は `execFileSync` で `generate-profile.mjs` などを起動する〔確: lib.mjs 2・13 行〕。したがって、外部調査が挙げる Node の `mock.timers` は、試験の側のプロセスの `Date` しか止めず、**記録の日付を書く子プロセスに届きません**。外部調査の C2 は、この形の試験にはそのまま使えません
2. **`--import` で子プロセスへ読み込ませる時計は、`Date` を止められる**。スクラッチで `NODE_OPTIONS=--import ./clock.mjs`(`Date` を差し替える 5 行)を試すと、子の `new Date()`・`Date.now()` は固定の時刻を返しました。ただし **`Intl.DateTimeFormat().format()`(引数なし)は実時刻のまま**でした〔確: Node v22.22.0、スクラッチ `f02/`〕。テンプレートの `scripts/` は、試験以外で `Intl.DateTimeFormat` を使っていません(`new Date()`・`Date.now()` は 16 か所)〔確: grep〕
3. **時計はもう1つある。git のコミットの日時**。`next.mjs`・`aggregate-evidence.mjs`・`adoption-trial.mjs`・`period-needed.mjs`・`org-assurance.mjs` は `git log --format=%cI` などでコミットの日時を読みます〔確: grep〕。`Date` だけを止めると、記録の日付とコミットの日付が食い違います。`GIT_AUTHOR_DATE`・`GIT_COMMITTER_DATE` も同じ時刻に揃える必要があります
4. **テンプレートには、場面型の試験を採用者のリポジトリで省く前例がある**。`test-init-g5.mjs` は `os.tmpdir()` の下へテンプレートを写して初期化し、構成が設定済みのリポジトリでは省きます。`@OWNER` の置き換えと、回答の JSON を作業の場所の外へ置く処理も、すでに入っています〔確: test-init-g5.mjs 1〜30・45〜100 行〕。スイートの `fresh.sh`(シェル・`tar`・GNU の `sed`)は、この形へ置き換えられます
5. **テンプレートの試験はすでに「固定する決定」を冒頭に書いている**。`test-roster-rules.mjs` の冒頭は「固定する決定:」として ADR と決定番号を列挙します〔確〕。決定と試験の対応は、新しい仕組みではなく既存の書き方の延長で持てます。ただし冒頭の列挙は場面の単位ではありません
6. **知識ベースの依存は、検査が通っている状態では消える**。`check-template-drift.mjs` は、標準から作り直した知識ベースとテンプレートの複製の一致を `npm run check` の中で求めます〔確: 冒頭のコメントと `buildKb` の読み込み〕。親の検査が通る版では、テンプレートに複製済みの知識ベースが標準と一致するため、テンプレート単独の CI でもスイートの場面は流せます〔推: 一致を求める範囲が、スイートの読む範囲を全て含むかは確かめていない〕
7. **`gate-g5.yml` は Node の版を固定していない**(`setup-node` が無い)。親の `ci.yml` は Node 22〔確〕。外部調査の `expectFailure`(v24.14.0〜)は、どちらでも前提にできません
8. **廃した言い回しの登録簿は、句ごとに由来の欄をすでに持つ**。各句に `retired`(日)・`by`(決定)・`instead` があります〔確: provision-forms.yaml 51 行〜〕。議題 R-5 の「由来の欄を持つか」は、持つかではなく、**`by` の実在を検査するか**が問いです。`by` の実在を確かめる検査は見当たりません〔確: `scripts/` の grep。`check-impl.mjs` は同じファイルの `documents` だけを読む〕

## R-1 何を、どこへ、どの形で移すか

**結論**: 場面を選んで移します。スイートはそのまま持ち込まず、テンプレートの既存の試験の形(Node だけ・`os.tmpdir()` の作業場所・`spawnSync(process.execPath)`)へ書き直し、**テンプレートの `scripts/gate/`** に置きます。場面ごとに決定の引用を持たせます。移さない場面は、理由を処分表に残します。

- 移すもの(既存の試験に無い主題〔内 1.2〕を優先)
  - 任免の記名(K60)、発効日(K65)、時刻帯(tz)、即時通知(K15・K51)、変化点の要約値の連鎖(K37)、発生の向き(K39)、AI が使えない期間(outage)、出荷判定者 × 事業決裁者(K50)、任命権者、`check-d0.mjs`
  - `unit.mjs` が呼ぶ関数のうち、直接の試験が無い 16 個。単体の試験として、主題の近い既存のファイル(`test-roster-rules.mjs` など)へ足す。場面型にしない(速く、壊れにくい)
  - stages の段階の通し(1・5・15 名)。ただし期待値は R-2 のとおり今の決定へ合わせてから
- 移さないもの(処分表に理由を書く)
  - 既存の試験と同じ主張の場面(兼務禁止・最小体制・`basis` の委任の経路など)。重複は、どちらかの期待値だけが更新されて食い違う原因になる
  - r3 の `scen*.mjs`: 採用者の製品のコード(`src/inspection.js`)を作る手順が退避物に無く、再現できない〔内 6〕。**再現できない試験を「移した」と数えない**。主題(導入前の検証)は trial と `test-adoption.mjs` が持つ
  - `ta.mjs`(trial に置き換わった古い版)、`trial-r7.mjs`(trial と本文が同一)、`tok.mjs`(判定が無い)、verify-n の N7(入力が欠落)
- 形
  - 1 ファイル = 1 主題。各ファイルの冒頭に「固定する決定:」を書き(既存の書き方。0 の 5)、**各場面の名前に引用を入れる**(例: `check('[ADR-0065 決定5] 席が未記入のあいだは未達', …)`)
  - 引用の実在は `lint:refs` の対象に足して機械で確かめる。引用の無い場面は失敗にする
  - 作業の場所は `fs.mkdtempSync(os.tmpdir())` の下。git の最上位がその場所と一致することを確かめてからコミットする(`fresh.sh` の外側のリポジトリへのコミットの危険〔内 5.1〕を、作りで無くす)
  - 偽の `gh` は、テンプレートの関数を差し替える方式(`mockgh-prs.mjs`)をやめ、PATH に置く Node の小さなスクリプト(Windows では `.cmd` を添える)にする。**偽の `gh` が呼ばれた回数を場面が確かめる**。呼び方が変わって模擬が黙って効かなくなる事態〔内 5.3〕を、失敗として表に出すため
  - 構成が設定済みのリポジトリ(採用者)では「省略: テンプレートの初期の状態が無い」と出して終える。通過とは数えない(ADR-0077 J-3、ADR-0028)
- 置き場をテンプレートにする理由: 試験の対象はテンプレートのコードです。採用者はテンプレートのリポジトリから直接作るため、親の検査だけに置くと、テンプレートの `main` に入った後退が、親がサブモジュールを進めるまで検出されません〔推〕
- 利用者の端末の `tmp/` の原本: 移した版がリポジトリへ入り、処分表が全 23 本を埋めるまでは消しません。消すかどうかは利用者が決めます(取り消せない操作)。リポジトリへ原本をそのまま「保管」として入れることはしません。Windows の絶対パスを持つ動かない試験がリポジトリにあると、流されないまま信用される資産になります

**他の案を落とす理由**
- 全場面をそのまま持ち込む: シェル・GNU・Windows の絶対パス・`pwd -W` に依存し〔内 5〕、親の CI(Linux)とこの保守者の端末(Windows)の両方で流れる保証がありません。#302〜#310 の担当が複製の中で直すしかなかった原因そのものを持ち込むことになります
- 親(`scripts/`)に置く: 上の理由で、テンプレートの後退の検出が遅れます。加えて、親の `scripts/` は廃した言い回しの検査の範囲の外です〔内 7〕
- 決定との対応表を別ファイルで持つ: 場面と表の二重管理になり、片方だけ更新されます。引用は場面の名前の中に置きます

**文の案**: 本文へは入れません(リポジトリの運用。R-7 で標準の側を扱う)。処分表は `research/319-deliberation/` の決定書へ置きます。

**矛盾**: 無し。ADR-0077 J-3(実施できなかった検査を通過として扱わない)、ADR-0028(未達と省略の区別)、ADR-0085(事前点検)と整合します。

  - matrix: 合否が変わらないまま出力が変わった〔内 2.4〕。**期待値を持たない場面は回帰を検出しない**ので、移すなら向きと下限を期待値として持たせる

  - いまの挙動(同じ変化点では拒否、2 回に分ければ通る)を場面として固定する。名前に `[未決定 #NNN]` を付け、決定を固定する場面ではないことを示す

  - 新しい Issue で、価値責任者(本プロジェクトでは利用者)が決める

- 3 件を回帰として直す / 決定の帰結として期待値を変える: どちらも、記録に無い決定を担当が書くことになります(コアポリシー: 起票者の提案が正しいという前提を置かない、の裏側。担当の解釈も前提にしない)

**矛盾**: 無し。「Issue にない作業はしない」(CLAUDE.md)に従い、3 件の判断は新しい Issue を起こします。

## R-3 時計

**結論**: 試験の側で、**子プロセスまで届く**時計の固定を行います。テンプレートの製品のコードに時刻を差し替える入口は足しません。

- 方法〔確: 0 の 1〜3〕
  - 試験の補助に `clock.mjs`(`Date` を差し替える)を置き、子プロセスを `NODE_OPTIONS=--import <clock.mjs>` と `PIT_TEST_NOW=<時刻>` で起動する
  - 同じ時刻を `GIT_AUTHOR_DATE`・`GIT_COMMITTER_DATE` に入れる(コミットの日時を読む処理が 5 本ある)
  - 時刻帯は従来どおり `TZ` で渡す(tz の場面)
  - **既定は固定の時刻**。replay の入力の日程(2026-10-01〜12-20)は、固定の時刻を 2026-10-01 に置けば書き換えずに通る〔内 3.2 追記: X=10-01 で 0 件〕
  - `2026-12-01`(v3)・`2027-03-31`(`next_review`)の直書きは、固定の時刻からの相対で書く。時限は固定の時刻の下では来ない
- 日付の境: スイートの `TODAY` が読み込み時に 1 回だけ計算される問題〔内 4.1〕は、時計を止めれば起きません。代わりに、**日付の境をまたぐ場面を 1 つ意図して置く**(23:59:59 に固定して記録 → 時刻を進めて次の記録)。偶然に任せず、境の挙動を決定(K65)として確かめる
- 時計の覆い漏れの検出: `Intl.DateTimeFormat()` の引数なしの呼び出しは止まりません〔確〕。テンプレートの処理が新しい時計を使い始めたら、固定の時刻と記録の日付が食い違い、場面が落ちます。黙って通る形ではないので、これを検出の手段として受け入れます。加えて、試験以外のテンプレートの処理に引数なしの `Intl.DateTimeFormat().format()` が現れたら落とす小さな検査を、時計の試験のファイルに置きます

**他の案を落とす理由**
- `mock.timers` / Jest の時計: 試験のプロセスの中だけに効き、子プロセスに届きません〔確: 0 の 1〕
- テンプレートに時刻を差し替える入口(環境変数など)を足す: 記録の日付は K65 の検査と監査の証跡の根拠です。製品のコードが外から時刻を受け取る入口を持てば、記録の日付を過去へずらす手段を、手順書に載った正規の機能として採用者へ配ることになります。`--import` の時計は誰でも自作できるもので、新しい能力を製品へ足しません〔推〕。強制層(`.claude/**`・CI)の変更にもならない
- `faketime`: コンテナに無く〔内 4.1〕、Windows で使えない
- 相対日付だけで書き、時計は止めない: 日付の境の問題(sweep の 68 件〔内 4.1〕)が残り、10 分の実行のたびに偶然で落ちます

**矛盾**: 無し。

## R-4 期待値を変えるときの手続

**結論**: 期待値を変える変更は、**規則を変える変更と同じ PR** に入れ、変えた場面ごとに「旧い期待値・新しい期待値・根拠の決定」を PR の本文の表に書きます。機械は「場面の引用が実在する決定を指す」までを確かめ、変更が正当かは人が見ます。

- 場面の名前の引用を、新しい決定へ替える。引用が替わらずに期待値だけが変わった行は、レビューで最初に見る行になります
- 同じ PR で規則と期待値を変えることを、**疑わしい形ではなく通常の形**とします。分けると、規則だけの PR が赤くなるか、期待値だけの PR が根拠を持たないかのどちらかになります〔外 B5: 機能変更と同じ差分の中で理由つきで人が確かめる〕
- 禁止事項3との関係: 禁止事項3は、実装が受入基準を満たさないのに、試験を緩めて通すことを禁じます。決定(受入基準・ADR)が変わったことを引用して期待値を合わせる変更は、これに当たりません。**引用できる決定の変更が無いのに期待値を変える変更が、禁止事項3に当たる候補**です。ただし両者を機械では区別できません(5.8.5 の後の段落と同じ理由。0 の 9)。区別は人が行います
- #302〜#310 の事例の位置づけ: 担当が複製の中で fixture を直したことは、直しの中身(A-4)は決定に沿っていましたが、**直した期待値が構成管理の外にあり、誰もレビューできず、元のスイートは古いまま残った**〔issues-context〕。違反の事例ではなく、構成管理の外で検証した事例として記録します。今後、決定を固定する場面の期待値は、リポジトリの中でだけ変えます

**他の案を落とす理由**
- 期待値の変更を規則の変更と別の PR にする: 上のとおり、どちらかの PR が根拠を欠きます
- 期待値の変更に毎回の別の承認者を要する: ソロ期のこのリポジトリでは承認者は利用者 1 人で、ADR の採用時にすでに見ています。同じ人の二度目の承認は手続を足すだけで、見る中身は増えません。ADR の採用の PR に表が入っていれば足ります

**矛盾**: 無し。5.8.5 の禁止事項3と後の段落(機械の検出を G-5 の合否に使わない)と整合します。

## R-5 「採らない」と決めた文と、廃した言い回し

**結論**: 反映の作業に「`template/` を手で検索する」手順は**足しません**。代わりに、決定を反映するときに、採らないと決めた事項の**一つずつ**について、固定の手段を 3 つから選んで記録します: 廃した言い回しの登録簿へ句を足す / 回帰の場面を足す / どちらもしない(理由を書く)。

- 手で検索する手順は、記録上は「検索した」の一行になり、何で検索したかが残りません。手順を増やしても、次の担当が同じ語で探す保証がありません〔推〕
- 文言の問題は登録簿、挙動の問題は場面で固定します。「条件付き通過という値は無い」のような却下は語句ではなく挙動なので、登録簿では固定できません
- 登録簿の `by` の実在を検査に足します(`lint:refs` か `check-provisions.mjs`)。由来の欄はすでにある(0 の 8)ので、欄を新設しません
- 検査の範囲
  - `zenn/`: #320 で決めます。ここでは決めません。決めるときの注意として、`ci.yml` は zenn を取得しない(突合 X-7)。範囲に入れると、取得の結線と、未取得の手元での失敗(J-3)が同時に必要になり、日々の `npm run check` が zenn の初期化を要するようになります
  - `research/`: **範囲に入れないと決めます**。調査メモは、廃した理由を書くために廃した句を引用する場所です
  - スイートを移す先(`template/scripts/gate/`)は範囲に入ります。移植の際、`t288b.mjs` の「第三者による棚卸し」(ADR-0066)〔内 7〕は書き換えるか `retired-ok:` に理由を書きます
- 部分一致の誤検出: 現行の `retired-ok: 理由` で足ります。変えません

**他の案を落とす理由**
- 手順に検索を足す: 上のとおり、形だけの記入になります
- 句ごとに由来の欄を新設: すでにあります

**文の案**(本プロジェクトの運営の頁、または ADR の運用ルールへ): 「決定を反映するとき、採らないと決めた事項ごとに、廃した言い回しの登録簿への登録、回帰の場面の追加、そのどちらも行わない理由の記録のいずれかを残す。」

**矛盾**: 無し。ADR-0077 J-3(置き場が無いのを違反なしとしない)を zenn の検討で引き継ぎます。

## R-6 CI と実行時間・知識ベースへの依存

**結論**
- 移した場面は `gate-g5.yml` の `contract` ジョブで流します(テンプレートのリポジトリでは実行、採用者のリポジトリでは「省略」と出す)
- **親の `npm run check` で、テンプレートの試験を流す**ようにします。いまは流していません(`test:template` は複製の乖離の検査〔内 1.2〕)。試験の一覧は `gate-g5.yml` と二重に持たず、テンプレートに一覧を 1 か所(例: `scripts/gate/test-all.mjs`)置き、両方がそれを呼びます
- 時間の目標: 移した場面の合計を 5 分以内〔推。実測は書き直した後〕。子プロセスの起動が大半〔内 8〕なので、場面のファイルを並行で流します。`ci.yml`・`gate-g5.yml` のジョブに `timeout-minutes` を置きます(いまは無く、止まると既定の 360 分を占有する〔内 8〕)
- sweep(768 組合せ、8〜11 分): 毎回は流しません。親で週 1 回の定期実行と手動の実行にし、**失敗したら Issue を起こす**(`issues: write`)。定期の実行が赤のまま放置されることを防ぐためです〔外 C5〕。値(週 1 回)は暫定です
- 知識ベース: 親の検査が通る版では、テンプレートの複製は標準と一致します(0 の 6)。場面はテンプレートに複製済みの知識ベースで流し、作り直しを要しません。親の `check` では、乖離の検査を場面より先に置き、乖離があるときに場面の失敗の原因を取り違えないようにします
- `gate-g5.yml` に Node の版の固定が無いこと(0 の 7)は、試験の結果がランナーの画像に依る原因です。#319 の範囲の外として、別の Issue を起こすことを提案します

**他の案を落とす理由**
- 速い検査(`check:fast`)を別に用意する: 速い方が日々の標準になり、遅い方は流されなくなります。#319 のスイートが `runall2` の外の 9 本を「手で流す前提」にして腐ったのと同じ形です〔内 1.1〕
- 親の `scripts/` だけで流す: R-1 のとおり、テンプレートの後退の検出が遅れます
- sweep を毎回: 1 回の push の検査が 10 分を超え、保守者が push 前の `npm run check` を飛ばす理由になります〔推〕

**矛盾**: 無し。`scripts/check-ci-wiring.mjs` の結線の検査に、定期の実行と `timeout-minutes` を足す必要があるかは、実装のときに確かめます。

## R-7 標準の側の規定

**結論**: 規定します。ただし「決定を固定する試験」という新しい成果物の種別は**作りません**。採用者に求めるのは、(1) 検証の根拠にする試験を構成管理下に置くこと、(2) 期待値の変更に根拠の決定を添えること、の 2 つです。既知の失敗の扱いは、既存の 5.8.5 の後の段落(`skip` 相当の付与を検証を弱める変更として G-6 に示す)で足りるとし、**新しい規定は課さないと明記**します。

- 小さなチームの立場から: 試験は普通リポジトリにあります。危ないのは、**AI の担い手が作業の場所(`/tmp`、スクラッチ)で試験を書いて流し、「確かめた」と報告し、その試験が消える**ことです。#319 はこの保守者自身の作業で起きました。AI 協調の開発で日常的に起きる形で、標準が扱う理由があります〔推。外部の A5・A6・G は試験資産を構成品目とする〕
- 「決定を固定する試験」を種別にしない理由: 採用者のどの試験が決定を固定するかの線引きを、採用者に新たに課すことになります。小さなチームでは、その線引きの記録が形だけになります。(1)(2) は試験の種別に依らず効きます
- 既知の失敗に新しい規定を課さない理由: 印の仕組み(pytest の xfail、Jest の `test.failing`、Node の `expectFailure`)は言語ごとに違い、Node では版にも依ります(0 の 7)。標準が仕組みを指定すると、テンプレートのアダプタごとに降ろし先が要ります。5.8.5 の後の段落は「`skip` 相当の付与」を検出の対象にしており、既知の失敗の印はこれに含まれます。降りていないこと(IMPL-0204、Issue 360)は、そちらで解きます

**文の案**(第5章 5.8.5 の後、または品質保証の節。番号は起案者が決める。本文は「ですます調」)

> 検証した旨を記録・報告するときは、その検証に用いた試験(試験のコード・入力・期待値)を構成管理下に置きます。作業の場所でだけ実行した試験は、検証の記録の根拠にしません。
>
> 試験の期待値を変える変更には、根拠とした決定(受入基準・設計判断の記録)を添えます。根拠を引用できない期待値の変更は、5.8.5 の禁止事項3に当たるかを、独立レビュー(G-6)で確かめる事項とします。両者を機械で区別する手段は無いため、この区別を G-5 の合否に使ってはなりません。

- 実装マーク: 2 つとも AI の担い手の挙動を制約するため `<!-- impl IMPL-NNNN … -->` が要ります。降ろし先の候補は CLAUDE.md の常駐の規則(1 つ目)と、PR の様式の「検証方法と結果」の欄(2 つ目)。降りるまでは `state=undelivered` で表示します
- 根拠水準: 数値を含まないため EV のマークは不要と判断します。「AI の担い手が作業の場所で検証して消える形が日常的に起きる」は単一事例(#319)に支えられるため、理由の文に書くなら EV でマークします
- 却下の明記: 本文に「既知の失敗の印の仕組みは規定しません。印を付けた試験は、5.8.5 の後の段落の検出の対象です」と書き、課さないと決めたことを読み手が区別できるようにします

**矛盾**
- 5.8.5 の禁止事項3と後の段落: 2 つ目の文は、禁止事項3の当てはめを G-6 へ置くもので、後の段落(G-5 の合否に使わない)と同じ構造です。矛盾しません
- ADR-0026(根拠水準)、#222(実装マーク)の規約に従います
- 採用済み ADR の本文は書き換えません。採否は新しい ADR(0089 以後)で記録します
