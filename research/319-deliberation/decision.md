# 議長の裁定(#319 決定を固定する回帰の fixture を、リポジトリの検査へ入れる)

入力: `issues-context.md`、`survey-319-1-internal.md`、`survey-319-2-external.md`、`council-00-agenda.md`、`council-01`〜`05`。新しい ADR は ADR-0089。番号の起点は EV-0181・IMPL-0350・SRC-0690。退避物は `tmp/legacy/`(git の外)と `/mnt/project-files/backup/legacy-suite-319/`。

## 0. 全体の方針

- 判断軸は「決定を固定すると主張する試験が、構成管理の下にあり、誰がいつ流しても同じ結果を出し、期待値の変更が決定へ辿れること」です。
- 今回、スイートは利用者の端末の `tmp/` にだけ残っており、クラウドの作業環境には無く、失われる寸前でした。前から落ちていた 16 件はどちらも時計が原因で、さらに #311 より前から誰も流さずに落ちていた場面が 28 件ありました。「固定している」という主張を、どの構成品目も支えていなかったことになります。
- 議題の前提の誤りを1つ訂正します。廃した言い回しの登録簿の各句は、由来の欄 `by` を既に持っています(擁護者・品質保証・規格・現場が指摘)。足りないのは、`by` の指す決定が実在するかの検査です。

## R-1 何を、どこへ、どの形で移すか

**裁定**:

1. **移す範囲**: 決定(ADR の決定・K 番号・Issue)を名指せて、期待値を持つ場面をすべて移します。手で選び抜くことはしません。移さない場面は、処置の表に理由とともに載せます(起案者・擁護者・品質保証)。
   - 廃するもの: r3(連鎖で単独で流せず、`src/inspection.js` が無く再現できない)、ta、trial-r7、tok、verify-n N7。それぞれが固定していた決定と、ほかの試験で覆われているかを処置の表に書き、覆われていないものは表示し続けます(擁護者)。
   - 期待値を持たない matrix は、matrix-sweep へ統合します。matrix-sweep に、出力の期待値をコミットして持たせます(起案者)。#318 で3行が変わっても合格のままだった原因が、期待値の欠如にあるためです(品質保証 Q8)。
   - 文言の有無だけを確かめる場面は、文言そのものではなく、決定の中身を確かめる形へ改めてから移します(規格・品質保証)。
2. **形**: まず、元の仕組みを保ったまま移します。そのうえで、凍結した時計のもとで p302(#311 の前の基準の実行)との一致を場面ごとに確かめます。一致を確かめる前に、既存の試験の形へ書き直すことはしません。書き直すと、決定が黙って変わったかどうかを比べる基準を失うためです(擁護者)。既存の試験の形への書き直しは任意とし、行う場合も同じ一致を条件にします。
   - 移植の問題は移すときに直します。Windows・GNU・シェルへの依存は Node に置き換えます。`gh` の差し替えは PATH 上の Node の代役とし、各場面が代役の呼び出しを確かめます(現場)。作業の場所は作業ツリーの外(`mkdtemp`)に作ります。`fresh.sh` が `git init` の失敗を捨てて外側のリポジトリへコミットしうる欠陥は、最上位の確認で塞ぎます。
   - 拒否を期待する場面は、短い語の部分一致ではなく、拒否の理由そのもので照合します(品質保証 Q6)。照合を強める向きの変更なので、一致の確認の対象に含めます。
   - `runall2.sh` が失敗を終了コードへ反映しない欠陥(品質保証 Q7)を直します。
3. **置き場**: 親のリポジトリの `scripts/regress/` に置きます。試験の対象は `template/` の作業ツリーで、知識ベースは標準から作り直したものです(規格)。採用者へは配りません。テンプレートの `gate-g5.yml` の試験は、いまのまま残します。
4. **決定との結び付け**: 各場面に `fixes` の欄を置き、固定する決定(ADR の決定・K 番号・Issue)を書きます。対応表は欄から生成し、手で持ちません。決定の実在は機械で確かめます(`lint:refs` の拡張)。実装マーク(IMPL)は条項と試験を結ぶもので、ADR の決定を結ぶものではないため、それと別の欄にします。正本は試験の中の欄の1か所です(規格の懸念に応える)。
5. **原本**: 退避物を `research/319-deliberation/legacy-suite/` へ、手を加えずにハッシュの一覧とともにコミットします。replay の入力を含みます。利用者の端末の `tmp/` の原本を消すかどうかは、利用者が決めます。

## R-2 いま落ちる場面の扱い

**裁定**:

1. 移す前に、落ちる場面をすべて4つに分類します。分類は「環境・時計」「決定が変わった」「回帰」「判断が要る」です。原因の分かっていない失敗には印を付けず、分析を終えるまで移しません(品質保証)。
2. 分類の草案は、移植を行ったのとは別の文脈が作ります。人が、PR の差分の確認で確定します。
3. 直し方は分類ごとに決めます。
   - 環境・時計: R-3 で直します。
   - 決定が変わった: 変えた決定(ADR-0078・0079・0085・0088 ほか)を引いて、期待値を改めます。
   - fixture・入力が決定に反する: 期待値ではなく、入力を直します。stages、t288、replay の `s4-acc3.json`(A-4 の兼務禁止。ADR-0066)が当たります。
4. **v3 の K65「取り消せない時間帯」**: 擁護者の指摘によれば、ADR-0078 は ADR-0053 決定1 の基準を維持すると書いていますが、その基準はテンプレートの `CLAUDE.md` と `.claude/` から消えています。期待値を新しい文言へ改めると、この喪失を固定してしまいます。実装で事実を確かめます。消えていれば、それは採用済みの決定に対するテンプレートの不備であり、テンプレートの側を ADR-0078 に合わせて直します(誘導層の変更。state:needs-platform の注記)。期待値は改めません。
5. **scenarios の3件**(同じ変化点で名簿へ足して任命すると拒否される): どの決定にも定めがありません。p302 では受け付けられており、拒否の原因は評価の順序(`generate-profile.mjs` の `namingProblems` が、この変化点の確認の記録を足す前の構成を検査する)にあります。回帰の疑いが濃いものの、決めるのは人です(擁護者・規格・品質保証・起案者)。新しい Issue に回します。それまでは、元の期待(受け付ける)のまま、厳格な「落ちることを期待する」印を付け、Issue の番号・照合する拒否の理由・見直しの時期を持たせます。予期せず通ったら失敗にします。期待を「拒否」へ反転する案(現場)は採りません。禁止事項3 と同じ形になるためです。
6. 「落ちることを期待する」印は自前で実装します。CI の Node 22 では `expectFailure` が黙って無視されることを、品質保証と規格の委員が実行で確かめたためです。

## R-3 時計

**裁定**:

- 試験の側で時計を止めます。`NODE_OPTIONS=--import` の先読みで `Date` を差し替え、子プロセスまで届かせます(現場・起案者が実行で確認)。git の時刻(`GIT_AUTHOR_DATE`・`GIT_COMMITTER_DATE`)も同じ時刻にそろえます。テンプレートの5つのスクリプトが、コミットの時刻を読むためです(現場)。
- スクリプトごとに、書かれた時点の時刻を宣言します。replay は 2026-10-01 とすれば、入力をそのまま使えます(起案者)。
- 日付の境・時刻帯・`next_review` の経過・`confirmedAt` は、明示した場面で試験します。
- `Intl.DateTimeFormat().format()` を引数なしで呼ぶと止まらない隙間があります(現場)。テンプレートのスクリプトがこれを使わないことを、検査で確かめます。
- **テンプレートに時刻を差し替える入口は足しません**(5委員一致)。署名した記録の日付を実行者が選べる経路になり、K65 を回避できるためです。統制の弱化に当たります。
- 時限(2026-12-01、2027-04-01)は、時計を止めると消えます。2026-12-01 より前に移し終えます。

## R-4 期待値を変えるときの手続

**裁定**:

- 決定を固定する場面の期待値を変えるには、先に存在する決定(ADR の決定・Issue)を引くことを要します。場面の `changed` の記録に、引いた決定の識別子・日付・旧い期待値を残します。自由記述の理由の欄は求めません。AI が埋められる欄は確認にならないためです(規格。`ci-gates.md` の既存の却下と一致)。決定の識別子は実在を機械で確かめられます。
- 規則と期待値は、同じ変更の中で変えてかまいません(決定 A-6 の形)。そのとき、変わった場面の一覧(旧・新・引いた決定)を PR の本文へ出し、人が確かめます。
- 機械が合否に使うのは、形の検査(`fixes`・`changed` の欄と、決定の実在)だけです。期待値の差分そのものでは失敗にしません(5.8.5 と一致)。出力をそのまま期待値へ写すモードは作りません(品質保証)。
- 決定を引かずに期待値を改めることは、禁止事項3 の「テストの失敗をテスト側の変更で解消する」に当たります。
- **#302〜#310 の扱い**: 直した内容は正当でした。手続に3つの欠陥がありました。構成管理の外で直したこと、元を更新しなかったこと、replay の入力を漏らしたことです。ADR-0066 の帰結「fixture を同時に直します」は、実際より多くを主張しています。ADR-0089 にこれを記録します。採用済みの ADR の本文は書き換えません。
- **ADR-0060 と ADR-0066 の食い違い**(品質保証 Q4): ADR-0060 は、却下の理由に「回帰の fixture が席の責任者の形を固定している」を挙げています。一方 ADR-0066 は「fixture は決定の記録ではない」とします。ADR-0089 で、fixture は決定の記録ではなく、決定を固定する試験は決定を引くことで意味を持つ、と定めます。ADR-0060 の却下がほかの理由でも成り立つかを実装で確かめ、結果を ADR-0089 に記録します。

## R-5 「採らない」と決めた文と、廃した言い回し

**裁定**:

- 会議体の決定を反映する作業に、手順を1つ足します。却下した案ごとに、次の3つのどれかを記録します。
  - 登録簿の句
  - 否定の場面(却下した挙動を試験で固定する)
  - どちらも置かない理由

  全文の検索を検査として置く案は採りません。誤検出が多いためです。
- 登録簿の `by` が実在の ADR・Issue を指すかを、機械で確かめます。`by` の ADR に句が字句どおり現れることは求めません。66 句のうち 26 句しか字句どおりに現れないためです(起案者)。`kind` の欄は足しません。用途が無いためです。
- `research/` は検査の範囲に入れません。経緯の記録だからです。`zenn/` を入れるかは #320 で決めます。

## R-6 CI と実行時間

**裁定**:

- スイートは、sweep を含めて、親の `npm run check` に入れます。通らなければ公開と配布が止まります(ADR-0077 決定1・2・5、ADR-0074 決定1)。量の上限は置きません。止まった実行を打ち切る `timeout-minutes` の設定は、量の上限ではないため置きます。
- sweep を週次や条件つきに限る案(現場・擁護者・品質保証)は採りません。#318 の3行のように、規則を変えた変更でこそ差が出ます。その変更を流さない設計は、検出の機会を失います。並列化による短縮は認めます。
- 親の `npm run check` は、いまテンプレートの試験を流していません(内部調査・現場)。`gate-g5.yml` と共有する一覧から、テンプレートの試験を流すようにします。
- 終了コードの伝搬と、作業ツリーの外の作業の場所を、結線の検査(`check-ci-wiring.mjs`)で確かめます。
- `gate-g5.yml` の Node の版の固定は、後継の Issue の候補にします。

## R-7 標準の側の規定

**裁定**:

- 第4章「判定が指す記録の保管」の隣に、次の条項を足します。G-5 の判定の根拠に数える試験(スクリプト、入力のデータ、期待値、補助のファイル)は、判定の対象と同じ版管理の下に置きます。個人の端末と、版管理から除外した場所を含みます(3.12.3 要件5 が覆わない範囲)。根拠水準は E1 とし、新しい EV を付けます。
- 第5章 5.8.5 の補足に、次の2つを足します。
  - 期待値を改めるときは、改める根拠となる決定・要求を引きます。
  - 「落ちることを期待する」印は、検証を弱める `skip` と同じ扱いとし、G-6 の確認の項目に載せます。既存の段落と IMPL-0204 に乗せます。
- 実装マークを付けます。降ろし先と確かめ方は実装で決め、ADR-0084 に従います。
- 課さないと明記するもの:
  - 「決定を固定する試験」という種別
  - 試験の枠組み
  - 時計の方式
  - 印の件数の上限
  - 期待値の差分による機械の阻止

## 7.5 分類(classification.md)への裁定

分類の草案は、移植とは別の文脈が作り、自分で流し直して確かめました。草案を採ります。人による確定は、PR の差分の確認で行います。

- **J-1**(scenarios の氏名の確認): 裁定 R-2.5 のとおりです。根の場面に厳格な印を付け、拒否の理由を照合します。連鎖の2場面は、根の場面の印に従属するものとして扱います。根が通れば連鎖も通ることを期待し、根が落ちている間は「根に従属して落ちる」とします。後継の Issue を起票するまでは、印の Issue 番号に #319 を仮に置きます。起票の後に付け替えます。
- **J-2**(matrix-sweep の向き appoint → loosen): ADR-0088 決定5 は、未達を解く変更の差分に代償措置の終了を緩める向きの行として出すと定めています。向きが loosen になるのはその帰結です。D として、決定5 を引いて期待値を改めます。
- **J-3**(K65): 本件の PR に含めます(R-2.4)。テンプレートの `CLAUDE.md` と `handoff.md` に、ADR-0053 決定1 の基準を戻します。誘導層の変更なので、state:needs-platform の注記を付けます。
- **J-4**: 分類を採ります。t288 の兼務は、ADR-0082 の記録を fixture に足して直します。場面が固定しているのは席の配置ではないため、席は分けません。事前点検の調整は、`.git/info/exclude` と `@OWNER` の置き換えで行います。調整を外すと初期化が止まることを確かめる場面を1つ置きます。テンプレートの既存の試験が同じことを確かめていても置きます。調整が黙って残らないことを、移した試験の側で保証するためです。
- **J-5**: 照合を「拒否の理由」と「差分の節」の2つに分けるのは、移植の直しとして扱います。一致表に記録します。ほかの `refused` の場面にも同じ形が無いかを、移植の側で網羅して確かめます。
- new は、入力を 75 へ改め、K40 の「下げる」場面を保ちます(草案のとおり)。
- 898 行と 900 件の差の2件は、実装で突き止めます。
