# 束 B22 会議体 — 起案委員の意見(2026-11-19)

読んだもの: 00-intake、10-research-A/B/C、roles-responsibilities.md 1267〜1290、overview.md 706〜740。ほかの委員の意見は見ていない。凡例は 立場 / 理由 / 文案 / 採らない案。

## 群A(#325)

### A1-1 下限の型
- **立場**: 条件つき賛成。数値を置かない型(全員の記名の応答)を採る。
- **理由**: 外部に根拠にできる数値が無い(調査A §2、§5)。数値を置くと E0 の新しい義務になる。会社法の型は「全員の同意で省略」を持ち、本標準の R1(3.10.5)の記名の応答と同型である。割合は端数と営業日の数えで争いが出る。
- **文案**(3.10.2 の最終段落を置き換える):
  > 期間を短縮できるのは、第7章 7.4 のファストトラックを適用した工程ゲート(G-1〜G-8)に限ります。短縮した場合、判定へ進めるのは、指名したレビュア(必須応答ロールを含みます)の全員が記名で応答(賛否いずれか)した後です。一人でも応答が無ければ、通常の期間に戻ります。起案者の応答の記載(T−1 営業日の行)は省けません。
  > 短縮した場合も、公開の時点と各応答の時点を残します。
- 数値を置かないことは暫定とし、`:::caution[暫定 EV-NNNN / 見直し 2027-05]` で開示する。「下限を置かないと決めたのではなく、根拠のある値が見つかっていない」と書く。現行の EV-0281 の「下限は未決」の文は差し替える。
- **採らない案**: 固定値(小さいチームほど重く、根拠が無い)。割合(同上、端数)。両者を全員の応答と併存させる案(会社法の型だが、条項と根拠の無い数値が増える)。

### A1-2 3.10.2 の書き方
- **立場**: 賛成。7.4 の表は変えず、3.10.2 を経路とする。
- **文案**(3.10.2 に一文を足す。7.4 の注記の代わり):
  > この短縮は、7.4 が後回しにできる行為を限定した列挙の対象ではなく、3.10.2 の事前レビュー期間そのものの短縮です。
  >
  > 第7章 B-1〜B-4 の会議体の上程の期間は、短縮できません。
- B-1〜B-4 を明記する理由は、R1 級の取り消せない決定を会議体が持つため(問3: 失うのは適合の主張の信頼)。ここは細かく書く価値がある。
- **採らない案**: 7.4 の限定列挙に事前レビュー期間を足す案。7.4 は G-6 の独立レビュー等の行為を限る表で、別の層(調査A §1.1、§4-4)。足すと 7.4 が時間の値を持たない構造まで崩す。

### A1-3 3.10.9「R1 と同じ扱い」
- **立場**: 賛成。**期間に及ばない**と読む。
- **理由**: 3.10.9 は「リスク区分にかかわらず」判定へ進めない扱いを揃える趣旨で、3.10.5 の表を参照している。T−10 まで及ぶと読むと、必須応答ロールを含む全案件の期間が倍になる新しい義務になる。
- **文案**: 3.10.9 の「3.10.5 の R1 と同じ扱い」に「(判定へ進めないことをいう。期間は 3.10.2 のリスク区分による)」を足す。**編集の指摘**として議長が直してよい(文言の読みを固定するのみ)。
- **採らない案**: T−10 まで及ぼす案。必須応答の強さは応答の記名で担保済みで、期間まで倍にする根拠が無い。

### A2-1 IMPL-0214(必須チェック)
- **立場**: 条件つき。標準は必須にしない。R1 用の `pre-review-all-responded` だけを template に**用意し、採用者が必須にするかを宣言する**(案 Q+S)。
- **理由**: R2 の `pre-review-closed` は 3.10.5 の R2(異議なしとみなして進む)と矛盾し、条文に無い義務になる(調査A §4-1)。マークを条文に合わせて R2 を落とす。R1 は 3.10.5 が「判定へ進めない」と書くので、止める装置の候補になる。ただし pre-review は Issue を対象とし PR のステータスではなく、B-1〜B-4 は PR を経ない運用がある(調査A §1.2)。既定で必須にすると、採用者の工程ゲートが新たに止まる。
- **文案(ADR の決定の箇)**: 「`pre-review-all-responded` は R1 の判定の記録の PR に紐づけられる検査として提供する。標準は既定で必須としない。必須にした採用者は構成書で宣言する。ADR-0200 決定4 の『必須にしない』は『標準は必須としない』に改める」。IMPL-0214 の note から R2 の `pre-review-closed` を外す。
- **採らない案**: 既定で必須(P)。1名の不在で止まり、管理者が回避する形に流れる。R(作らない)は、条文が止めると言い実行が止めない差を残し続けるため、R1 の限りでは採らない。

### A2-2 IMPL-0217(判定へ進めない強制)
- **立場**: 反対(機械で止める強制は作らない)。通知と記録までを降ろす。
- **理由**: 止める型は回避の経路を必ず持つ(調査A §2 の GitHub・Gerrit)。回避の入口は新しい条項を要しない。**3.10.5 が既に、応答が揃わないときの措置(3.9.3: D-0 表3 の者への通知と代理の指名)を定めている**。回避はこの代理の指名で受ける。7.3 は使えない(3.10.5 は 7.3 が名指した事項でも判定基準でもない)。よって 7.3 を新たに名指さない。
- **文案**: IMPL-0217 の note に「止める強制は作らない。条文が止めることは、判定者が応答の記名を確かめる manual の確認として残す」と明記し、`state=undelivered` を維持して表示する。降りていない旨の表示は消さない。
- **採らない案**: 7.3 を新たに名指す案(対象を広げる。回避は 3.9.3 で足りる)。

### A2-3 3名以下・ソロ
- **立場**: 条文は足さない。
- **理由**: 指名レビュアが少なければ全員の記名の応答は早く揃う(L3 型の利点)。1名不在のときは通常期間に戻るだけで、判定を止めない。必須応答ロールの担い手が置けない場合は 3.10.9 の軸A(外部)が既に受ける。
- **文案**: 手引きに「3名以下では、指名レビュアが全員であることが多い。不在の者がいるとき、短縮は使えない」と書く(条文ではなく手引き。問1)。
- **採らない案**: 小さいチーム専用の短縮条項。

## 群B(#445)

### B-1 必須になる条件
- **立場**: 条件つき賛成。条件は段ごとに別とし、機械で決定できる値にそろえる。
- **文案**: mutation と faultInjection は「CL3 の案件、または G-1 で安全関連部があると記名した案件」。regulatory は「軸C が規制業の構成」。後者の安全関連部の記名は、構成に値(`safetyRelated`、真偽)を足して機械が読む。F.2 の Q1 は構成に無い(調査B §1.2)。値の欄を足すのは template の項目として Issue に残す。
- CL2 は含めない。G-7 基準7(Q1 または CL2・CL3)と範囲が一致しないことを、ADR に「CL2 は本件では課さない。r-e-cl2 は CI の必須チェックを強化しない」と書いて開示する。
- **採らない案**: 3段とも同じ条件(規制業に故障挿入を課す根拠が無い)。CL2 まで含める案(F.4 は安全関連部、CL2 の CI は強化しない既存規則と衝突し、新しい義務が大きい)。Q1 を構成に足さない案(「条件に当たる構成」を機械が判定できず、所有者の方向を実行できない)。

### B-2 HR を失敗へ格上げする範囲
- **立場**: 賛成。理由つきの省略は残さない。
- **理由**: 理由を記録すれば省ける型を残すと、段が空でも通る。格上げは新しい義務であり、ADR に明示する。
- **文案**(F.4 の表の注に): 「CL3 または安全関連部の記名がある構成では、この HR は G-5 の失敗の条件である。省くことはできない。ただし実行の記録を照らす経路(B-3)で受ける」。入口は理由ではなく実行の記録とする。
- **採らない案**: 理由つきの省略を残す(空のコマンドで通る典型。ADR-0151 の例外の連続の懸念も増える)。

### B-3 faultInjection の中身
- **立場**: 条件つき。CI で回るものは mutation に含め、独立の段は「外部の実行の記録を照らす段」とする(1-d + 3-a)。
- **理由**: F.5 の分類で CI で回る故障挿入はミューテーションと同じ。実行時・ハードウェアの故障挿入は CI の外(調査B §1.3)。
- **文案**: faultInjection の段は、実行の記録(所在・日付・版)が在るかを照らす。無ければ失敗。実行の記録の質は機械で閉じない(B-6)。
- **採らない案**: 3-c(G-7 に回す)。所有者の方向(G-5 の段が空なら失敗)と別になる。

### B-4 閾値
- **立場**: 賛成。G-1 で案件が定めて記名する。
- **文案**: 「閾値は G-1 で案件が定め、記名する。本標準は値を定めない」(F.6 のとおり)。機械が見るのは、構成の `ci.mutationThreshold` が数値であることと、出力の算出値が閾値以上であること。未設定は欠落でなく **G-5 の失敗**とする(条件つきの段が空と同じ扱い)。
- ADR-0166(分量の上限の未設定は失敗にしない)との差は、安全が絡む段であることと明記する。
- **採らない案**: 標準が数値を置く(F.6 と自己矛盾。80/60 は表示の既定で根拠が無い。調査B §2 B2)。

### B-5 7.3 との関係
- **立場**: 賛成。線を ADR に書く。
- **文案**: 「実施しないままの通過は、7.3 の例外承認で受けない(exception-escalation.md の 7.4 の禁止の行のとおり)。実施した判定の基準割れを 7.3 で扱うことは妨げない。ただし新しい段は G-5 の8つの基準の外にあり、7.3 が記録する項目番号を持たない。段の閾値割れは G-5 の失敗として差し戻し、閾値の変更は G-1 の記名の変更として扱う」。
- 「7.3 は G-5 に使えない」と一括りに書く起案の文は不正確(調査B §4-3)。この線で直す。
- **採らない案**: 段を8基準の追加にする(「判定基準は8つのまま」の宣言を変え、G-8 の異議・保証の開示まで連動する)。基準の内訳に入れる案は、選択肢の比較で残す。

### B-6 開示
- **立場**: 賛成。開示する。
- **文案**: 「コマンドが在るが常に成功する構成は、機械で閉じない。skipped は成功とみなされる」を `:::caution[暫定 EV-NNNN / 見直し 2027-05]` で書く。機械で閉じる範囲は、コマンドが空でないこと、閾値が数値であること、出力の存在と算出値の比較。閉じない範囲は manual か adopter の確認(G-7 の判定者)とする。
- skipped は決定可能なので機械で閉じる: 条件つきの段のジョブが skipped になれば集約を失敗にする(調査B §2.1)。実装後の陰性の確認を実行で行う。
- **採らない案**: 実行の内容の意味を機械で判定する案(自由な文の意味は閉じない)。

### B-7 ADR-0151 の置き換え範囲
- **立場**: 賛成。置き換えるのは決定1 の「必須の段」の集合に条件つきの段を加える一点だけ。
- **文案**: 「ADR-0151 決定1 の『テストの実行と秘匿情報の混入検査は空を失敗にする』に、条件つきの段(mutation・faultInjection・regulatory)を加える。決定3(継続の長さの閾値を課さない)と決定4 は置き換えない。決定3 の『閾値』は継続期間であり、ミューテーションスコアの閾値とは別である」。
- ADR-0151 の「実装の開始後は空を失敗にする」を採らなかった理由(道具の無い言語)は、条件の限定(CL3・安全関連・規制業)と実行の記録を照らす経路で解く、と書く。
- **採らない案**: ADR-0151 全体を置き換える(任意の検査の扱いまで変わる)。

### B-8 規格の引用
- **立場**: 反対(規格を根拠として引かない)。
- **理由**: 規格の原文を読めていない。二次資料では ISO 26262-6 の強さが資料間で食い違う(調査B §2 B5)。規格は故障挿入を段階づけた手法の一つとして扱うように読め、CI の合否の必須の段とは書かないと見える。必須にするのは本標準の判断である。
- **文案**: ADR に「本標準の判断であり、規格の要求ではない」と書く。F.4 の既存の記述はそのまま。EV で E0 から E1 相当の開示をする。
- **採らない案**: 規格を根拠に引く(原文を読めていない主張になる)。

## 群C(#446)

### C-1 書き換えの型
- **立場**: 賛成。2項案を採る。
- **文案**(1.10.2 の列挙に無い離脱の表の行を2行に分ける):
  > | 兼務を禁止した組の席どうしの担い手が、同じ認証情報を使う構成 | 第3章 3.5.3 | 禁止の組の席どうしが、同じ実行主体の文脈(認証情報を含む)で作業する構成。体制の規模によらない |
  > | 別の自然人どうしが、同じ認証情報を使う構成 | 第4章 G-7 条件4 | 認証情報を使う自然人が複数の構成。体制の規模によらない |
  >
  > 注記(730・739 の「席ごとに認証情報を分けている」)は「禁止の組の席どうしで認証情報を分けている。別の自然人どうしで認証情報を共有しない」に揃える。
- **理由**: 害が別(権限の分離の不成立と帰属の不成立)。ADR-0107 の先例が行を分けた。(2)の主語は席の責任者でなく認証情報を使う自然人とする。
- **採らない案**: 1項案(判定の単位が混ざる)。現状維持(所有者の方向に反する)。

### C-2 人×AI・AI×AI
- **立場**: 反対(新しく課さない)。
- **文案**: 「人と AI の実行主体の共有は名義の行で扱う。禁止でない組の AI の実行主体どうしの共有は、離脱に数えない」。**課さないと決めた**旨を ADR に書く。
- **理由**: 課すと 3.5.3 条件1(禁止でない組は同じレーンに置ける)と IMPL-0299 のレーン設計に衝突する。規格側は指針であり要求事項の形ではない(調査C §2)。
- **採らない案**: 「自然人」を「実行主体」に広げる案 b(新しい義務で、レーンの定義を直す必要がある)。

### C-3 共有が避けられない場面
- **立場**: 条件つき賛成。定義で外す(案I)。
- **文案**: (2)の「当たる条件」に「共有の認証情報へ入る前に使う個人が識別され、その記録が残る場合は当たらない」を足す。NIST SP 800-53 IA-2(5) の趣旨(個人が先に認証される)に沿うが、原文は引用せず本標準の判断として書く。
- 「個人が識別される」は機械で閉じない。manual とし、根拠水準マークで開示する。
- **採らない案**: 案II(緊急用の共有を申告しなくなる動機を生む)。案III(7.3 を名指す。break-glass は期限で解けず、7.3 の対象の限定を広げる)。

### C-4 機械の線
- **立場**: 賛成。
- **文案**: 機械で閉じる=構成で宣言した数値の識別子の一致(禁止の組の担い手、名簿の別の人への同じ識別子)。閉じない=実際に誰が使ったか、申告されない共有、アカウントの外の認証情報、案Iの個人の識別。閉じない範囲は IMPL-1004 の note に manual として残す。
- 名簿の contract が拒否し、AI の共有申告を拒否しない差は、ADR-0147 の理由(拒否すると離脱を表示できない)で説明でき、揃えない。差を ADR に1文で書く。
- **採らない案**: 名簿と AI の扱いを揃える案(AI の共有申告を拒否すると構成を記録できない)。

### C-5 3.5.3 の直し
- **立場**: 賛成。666 行の理由文と 544 行の「ロールごとに」は**編集の指摘**として直す。
- **文案**: 666 行は「席ごとに分けられる」を「禁止の組の席どうしで分けられる」に、544 行は「ロールごとに」の後に「(兼務を禁止した組の席どうしは必ず)」を足す。条件1・表前文・レーンの定義は触らない。
- **理由**: 意味を変えない。3.5.3 の条件1 に揃うための語の直し。
- **採らない案**: 3.5.3 を席ごとに揃える案(所有者が不採用。レーン設計が崩れる)。

## 総括
- 新しい義務は B-1/B-2(G-5 の失敗の範囲)と C(2)の離脱の範囲の二点に絞った。A は数値を置かず、強制は通知と既存の 3.9.3 で受ける。
- 削れる既存の条項: IMPL-0214 の R2 の検査、7.4 に足す案、ADR-0200 決定4 の絶対表現。
- 各項で開示するもの: A1-1(数値が無い)、B-6(skipped と常に成功するコマンド)、C-3(個人の識別)。
