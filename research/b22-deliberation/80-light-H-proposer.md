## 1. 附属書H の表 R1 の行(assurance-case.md:86)

R2・R3 の行は、欄の中だけで条件まで書いている。それにそろえ、限定を別の段落へ置かない(適用範囲の書き方 #226)。

新しい文:

> 推奨。当該範囲を変更するたびに実行する。ただし、CL3 の案件と、[附属書F](/process-compass/phase4-process-design/safety-verification/) F.2 の Q1 が「はい」の案件では必須(第4章 G-5 の段。F.6、[ADR-0224](/process-compass/adr/0224-g5-mutation-and-regulatory-stages-required-for-safety-and-regulated/))。そのほかの案件では課さない

末尾の「課さない」は、「書かれていない」と「課さないと決めた」を分けるためである。:89 の安全関連行(「F.6 による」)は変えない。

併せて直す箇所(いずれも「R1 は必須」を前提にした文である):

- assurance-case.md:332。「R1 の変更では、変異試験で検出力を測っていることも条件に加える」は、R1 が必須であることを前提にしている。推奨に下げると、測っていない R1 の変更が「検証に数える」条件を満たさなくなる。または、条件を黙って空にする。案: 「R1 の変更では、検出力を測っていればその結果を、測っていなければ測っていない旨を、保証の開示(H.6)へ載せる。必須の案件(CL3・Q1「はい」)では測っていることを条件にする」。これは意味が動く箇所なので、委員の議論と突合の対象にする(軽の議長が、編集の指摘に落とせないと判断する材料)。
- assurance-case.md:922(C4 の行)。「変異試験は R1 で必須、R2 で週次、R3 で任意」を「R1 で推奨(CL3・Q1「はい」は必須)、R2 で週次、R3 で任意」へ。
- adoption-guide.md:181。同じ文言を同じに直す。
- gate-criteria.md:1004 と roles-responsibilities.md:1108。「R1・R2 の統制(…変異試験…)」を、変異試験を括弧から外すか「R1 は推奨」と添える。区分を R3 と書いても、CL3・Q1「はい」の必須は外れない点も 1 句足す(ADR-0039 の、案件ごとの CL と変更ごとの R を混ぜない原則に合わせる。CL3 は案件ごと、R は変更ごと)。

## 2. フェーズ5 の手引きの表(test-effectiveness.md:68)

**そろえて直す**。手引きの語として残す案は採らない。理由は3つある。

- 手引きは 5.8.4 の充足例であり、要求事項の正本ではない。本ページ冒頭(:12)が「要求事項は 5.8.4 に規定済み」と述べる。5.8.4 に R1 の変異試験の必須は無い。
- 附属書H は、この表の投影として扱ってきた。投影元だけ「必須」を残せば、読み手は手引きを要求事項と読み、食い違いが残る。
- 太字の「**必須**」は要求事項の語である。手引きの語尾は ADR-0086 の趣旨(手引きは「勧めます」)にも合わない。

文案:

> R1 | **推奨**(CL3 と、附属書F F.2 の Q1 が「はい」の案件は必須。F.6) | 当該範囲を変更した PR

:62 の「PR ごとの機械判定(G-5)へ無条件に載せると往復時間を損ないます」は、推奨と整合するので変えない。:73 の「R1 においても」は「R1 で実行する場合も」へ直す。

## 3. IMPL-1026

**マークを外す(欠番)**。残す案は採らない。

- 規定が推奨になると、IMPL-1026 が追っていた「実行主体の挙動を制約する規定」は消える。必須が残るのは、案件ごとの段(Q1「はい」・CL3)だけである。それは IMPL-0931・0763・0836・0930 が追っている。対象を改めて残すと IMPL-0931 と二重になる。降ろし先(g5-adapter)も同じ段である。
- 番号は再利用しない(実装マークの書式)。台帳には欠番が出る。取り下げた事実は ADR-0224 の決定13 に残し、降りていない規定を黙って消さない(「降りていない規定は消さずに表示する」の趣旨は、条項が残っている間の表示である。条項が改まったので、表示対象が無くなる)。

手順(実装を担当する者へ):

- assurance-case.md:91 のコメントを削除する。
- impl-inventory.yaml:40-49 の節を `status: none`、`category: elsewhere` に改める。`ids` を消し、`reason` に次の趣旨を書く。表の「変異試験」の列は、R1 は推奨、必須は案件ごとの段(F.6、ADR-0224。IMPL-0931 が追う)。R1 の変更ごとの規定は課さないと決めた(束 B22、軽の審議)。`location` に `safety-verification#F.6 ミューテーション試験` と assurance-case の当該節を置く。節 :32-39 の `none` の書式に倣う。
- `npm run impl:write` で台帳を再生成する(私は実行していない)。欠番を許す検査か、`lint` が連番を要求しないかを、実装の担当が確かめる。
- IMPL-0931 の note の「安全関連部と R1 の変更の優先」は、「R1 は推奨(IMPL-1026 取り下げ)」へ改める。ADR-0224 の影響の節(:88)の「IMPL-1026 を新しく付けた」は、取り下げた旨を足す。

## 4. ADR-0224 と採らなかった案 丑

ADR-0224 は採用の同日(2026-11-19)に束 B22 で直している。決定13 の差し替えは、同じ ADR の訂正として行い、新 ADR は立てない。置き換えるべき既存の ADR は見つからなかった。ADR-0056:62 は新しい文と矛盾しない。

決定13 の新しい文:

> 13. 附属書H の表の R1 の変異試験の欄は、附属書F F.4 の R1 の列(R、推奨)に揃える。R1 の変更ごとの変異試験は推奨であり、必須になるのは決定1 の案件(Q1「はい」・CL3)だけである。変更ごとの必須の規定は置かない。この規定に付けた IMPL-1026 は取り下げた(番号は再利用しない)。これは食い違いの解消であり、新しい義務を課さない。**全採用者の R1 の変更へ変異試験を必須にする案(丑)は採らない**(検討した案の表を参照)。

あわせて:

- :20(背景)を「附属書H の表は R1 を必須としていたが、F.4 は R(推奨)で、食い違っていた。2026-11-19 に F.4 側へ揃えた」へ改める。
- :88 の影響へ、IMPL-1026 の取り下げを書く。
- 検討した案の表(:52 付近)へ丑の行を足す。

採らなかった案 丑 の理由:

- 全採用者の R1 の変更に掛かる新しい義務で、根拠の ADR が無い。重の審議(採用者への新しい義務)に当たり、本束は軽である。
- 変異試験の道具が無い言語・基盤がある。ADR-0224 の決定1 は、この場合に外部で実施した記録を照らす形を認めた。全採用者へ広げると、道具の無い採用者が一律に「未達」になる。
- 閾値を較正する前に必須にすると、合否に使えない段が通過条件になる(test-effectiveness.md の較正の手順 :79-86。3か月の記録を前提とする)。ADR-0166 決定4 と同じ論拠である(既定の値が無いまま数えると全採用者の G-7 が落ちる)。
- F.4 は規格の推奨度を写した表で、R1 の列を HR に上げると、F.4 の他の行との整合が崩れる。CL2 を一律に含めなかった ADR-0224 の判断(附属書F の適用外へ義務を広げない)と同じ線である。
- 実証が無い。変更ごとの実行が欠陥の流出を減らす根拠も、実行時間(test-effectiveness.md:62)の負担の許容も測っていない。
- 再び開く条件: R1 で変異試験を実施しなかった変更から、十分性の不足で欠陥が出たという記録が貯まったとき。重の審議で扱う。
