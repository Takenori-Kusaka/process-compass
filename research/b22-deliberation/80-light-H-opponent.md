# 束 B22 軽の審議(附属書H の R1 の変異試験)— 反対委員の意見(2026-11-19)

立場: 方向(附属書H を F.4 に揃える。子)は覆さない。「必須」を「推奨」へ書き換えるだけでは、新しい食い違いと、保証の主張の穴が生じることを論じる。丑を採らない点にも異を唱えない。

## 1. この列が支える主張(最大の危険)

附属書H の変異試験の列(assurance-case.md:84〜88)は、次の4か所の主張・証拠の前提である。

| 所在 | 内容 | 「推奨」にしたときの影響 |
| --- | --- | --- |
| :93 | 「検出力を測っている」と述べるときの範囲は上表による。R3 は主張しない | R1 も「測っていない場合がある」に変わる。主張の範囲の文が R1 を含むままだと偽になる |
| :218(C4) | 証拠「変異スコアと生存した変異の一覧(R1 は変更ごと、R2 は週次。R3 は任意であり、無い場合がある)」 | R1 の証拠が常にある前提が崩れる |
| :332 | 決定論的な検査を「検証に数える」条件。「R1 の変更では、変異試験で検出力を測っていることも条件に加える」 | 最も重い。条件を残せば、実行されない R1 の AI 書きテストは検証に数えられず、**実質の必須が残る**(推奨と矛盾)。条件を外せば、R1 でも検出力を測らないテストが検証に数えられ、保証が弱まる |
| :922(項目4)・adoption-guide.md:181 | 「変異試験は R1 で必須、R2 で週次、R3 で任意」 | 文面の食い違い。直さなければ附属書H の内部で必須と推奨が併存する |

**案(文案)**: 「推奨」に下げるなら、:332 を二分する。「R1 の変更で変異試験を実行した場合は、検出力を測ったものとして数える。実行していない R1 の変更は、AI が書いたテストの実行を検証に数えるが、検出力は主張しない(保証の開示 H.6 に、変異試験を実行しなかった R1 の変更の件数を載せる)」。:93 も「R3 に加え、変異試験を実行していない R1 の変更」へ広げる。C4 の証拠欄の「R1 は変更ごと」には「実行した場合」を足す。
**採るべきでない書き方**: 表の一語(必須→推奨)だけを直す。:332・:922・:93・adoption-guide:181 が旧い意味を保つ。また、:332 の条件を黙って削る。保証の主張を弱める変更は H.6 で開示しなければ、利用者の信頼に反する(コアポリシー「実証を欠く判断は開示」)。

## 2. R2 との逆転

F.4 の表は R2 も R1 も「R」で同じである(safety-verification.md:163)。H の R2 は「週次の定期実行。合否条件にしない」。R1 を「推奨」に下げ、R2 の語を変えないと、R2 のほうが規定の語気が強い(実行する前提の書き方)逆転が起きる。R3 の「任意」と R1 の「推奨」の差も読み取れない(F.4 の R は、しない理由の記録を求めない)。
**案**: R1 は「推奨。行う場合は当該範囲の変更のたびに実行する。必須は、附属書F F.4 の注の条件(Q1 が「はい」・CL3)の案件だけ(適用: 当該案件)」。R2 は「週次の定期実行を勧める。合否条件にしない」、R3 は現行の「任意」のまま。段の序列が R1 > R2 > R3 と読めるよう、**頻度**(変更ごと/週次/随時)で差を書く。語の差は頻度に持たせ、強さの差は「推奨」に一本化する。
**採るべきでない書き方**: 「R1: 推奨。R2: 週次、R3: 任意」だけ。強さの軸と頻度の軸が混ざり、R2 が R1 より強く読める。「R1 は必須ではない」という否定形だけの書き方も、読み手が基準を持てない。

## 3. 他の欄の語法との整合

附属書H の表の他の欄は「求める」「求めない」「求めない(禁じていない)」「必須」「任意」を使う。「推奨」は、この表の中で初めて出る。F.4 は HR・R・— の3段で、R の定義は「推奨する」。同じ語を使うのは整合するが、:84 の表の注として「推奨は F.4 の R と同じ意味」と引く必要がある。**条件つきの書き方は要る**: 「推奨」だけでは、変更ごとなのか週次なのかの頻度が落ちる(上の案のとおり頻度を残す)。
**採るべきでない書き方**: 「任意」への置換(R3 との差が無くなる)、「勧める」「望ましい」(ADR-0086 の規定の表現形式の規則と別の語を増やす)。

## 4. IMPL-1026 を外す/残す

- **外す場合**: 追跡から「R1 の変更ごとの変異試験」が消える。しかし、推奨は実行主体の挙動を制約しない(機械で強制しない)ので、実装マークの対象外と言える。ただし、推奨になった後も R1 に変異試験を**案件ごとの条件で必須にしている段**(IMPL-0931・0836。ADR-0224 の条件)が、同じ内容を追うので、重複しない。**外すのが筋**。理由を `impl-inventory.yaml` の note と ADR-0224 に残し、台帳から落ちた事実を開示する(「課さないと決めた」と「書かれていない」を区別する原則)。
- **残す場合**: 推奨を機械で強制するかのような表示(降りていない規定)になる。note を「推奨のため降ろさない」へ変えれば state=undelivered の意味に反する。state の語彙(delivered/undelivered)に「課さない」の値が無ければ、残せない。
**案**: マークを外し、附属書H の表の直後に「R1 の推奨は実行主体の挙動を制約する規定ではないので、降ろさない。必須の段は IMPL-0931(適用: Q1 が「はい」・CL3)」と一文を書く。`plan=scheduled` の IMPL-1026 の番号は再利用しない(欠番を ledger で説明する)。
**採るべきでない書き方**: マークを黙って削除する(追跡が消えて、R-1 の再発を検知できない)。note だけ書き換えて残す(「推奨」を undelivered で表示し続けると、永久に未達のゲートに見える)。

## 5. ADR-0086・ADR-0224・ADR-0039 との整合、フェーズ5

- **ADR-0086**: フェーズ5 は参考(手引き)。本文(附属書H)が正で、手引きは本文を狭めない。test-effectiveness.md:68 の「必須」が残ると、手引きが本文より強い。ADR-0086 の趣旨(手引きに規範を置かない)にも反する。同じ束で :68 を直す。**案**: R1 の行を「推奨(必須は附属書F F.4 の注の案件)」とし、:73 の「R1 においても、対象は当該 PR が変更した範囲」を「行う場合の対象は…」に直す。:148 の CI の例の見出しも、例であることを保つ。description(:3)は変えない。
- **ADR-0224**: 決定13 の「新しい義務ではない」は、R1 の必須が無かった(=課していない)ことの裏付けになる。決定13 を「附属書H の R1 の必須は、F.4 に揃えて推奨に改める。必須は条件の案件だけ。全採用者の R1 への必須(丑)は採らない」に替える。ADR 本文は書き換えない原則のため、**追記・改訂の形式**(0224 の「改訂」節)を使い、ADR-0083 等の前例に倣う。丑を採らない理由は、(a) 道具の無い言語の扱いが未調査(F.6 の許容、R-7)、(b) CL2 の案件への義務の拡張を ADR-0224 が採っていない、(c) 実行時間(test-effectiveness.md:62)、とする。
- **ADR-0039**: R は変更ごと、CL は案件ごと。R1 を推奨にして、必須を CL3/Q1(案件ごと)だけに置くと、「CL0 の案件の R1 の変更に変異試験を課さない」ことになる。ADR-0039 は CL0 でも R1 が起きることを述べる。**CL から R の適用外を導いたのではなく、規格(F.4)の推奨度に揃えた結果**と書く。そうでなければ、ADR-0039 の原則(案件の属性から変更ごとの適用外を導かない)に反して読まれる。R1 の列の他の統制(G-6 の人の独立など)は、CL によらず掛かる。変異試験だけが案件ごとの必須になる点を表に明記する。
- 区分の下限(gate-criteria.md:1004、roles-responsibilities.md:1108): 「変異試験…は、区分を R3 と書けば外れます」。推奨になると、R1 と R3 の変異試験の差が弱まり、「低く書く誘因」が減る。文を「…(R1・R2 で課す部分)」へ直す。

## 6. 根拠水準マーク

要る。F.4 の R(推奨)は二次資料に基づき、規格原文は未確認(safety-verification.md:283)。R1 の変異試験を推奨に留めることの検出力への影響は未測定。`:::caution[暫定 EV-NNNN / 見直し 2027-05]` で、**対象**「R1 の変異試験を推奨に留め、必須を条件の案件に限ること」、**根拠の水準** E0〜E1、**差し替え条件**「R1 の変更で変異試験を実行した変更と実行しなかった変更の、出荷後の欠陥の件数の比較」。マーク追加後に evidence:write(別の担当が行う)。

## 7. 総括(採否の助言)

方向は支持する。ただし、1語の置換では足りない。同じ束で直すもの: assurance-case.md の :86・:93・:218・:332・:922、adoption-guide.md:181、test-effectiveness.md:68・:73、gate-criteria.md:1004 と roles-responsibilities.md:1108 の文言、IMPL-1026 の扱い、ADR-0224 決定13、EV の新設。直さない場合に残る食い違いは、:332 の「条件」による実質の必須が最大である。
