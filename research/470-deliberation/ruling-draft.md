## 1. 裁定の案(Issue #470「審議で決めること」の番号に対応)

### 決めること 1: 標準に置くか。置くならどの条項か

**置く。第5章 5.5.1(作業上の選択)の、理由の記録の段落の前に置く。** 新しい節・欄・様式・マーク・人の記入は足さない。新しい ADR を起こす(重。0044 と範囲を分けて一部置き換え、0267・0269 を補う)。

条文の文案(5.5.1 の「席の作業は、担い手が行います。…」の段落の後に足す。採用チーム向けの文。ADR・Issue の番号を引かない):

> 承認済みの仕様と受入基準が定めていない事項を作業上の選択として決めるときは、既にあるものに依って決めます。依る先は次の順とし、成り立つ最初の段で止めます。

【直し 1】議長の方針 3 の「流儀が悪いとき倣って広げない」は、「悪い」が担い手の好みの判定になり、頼んでいない周りの書き換え(現場の委員の場面 6)と流儀の不揃いを招く。**倣わない条件を「削らないものを損なうと分かったとき」に限る**。それ以外の質の違和感は、流儀に倣い、食い違いを 1 行で示すに留める。

【直し 2】「段1〜4 に依った選択は外部の制約に従った選択に当たる」を条文に置く。5.5.1 の外部の制約の例示(受入基準・既存の規約・依存の制約・実行環境・既存の公開インタフェース「など」)の読みを明示するだけで、理由の記録の範囲は広げない(段5 の選択は、退けた案が無ければ選んだ内容だけを記録する。全選択に理由を求めない、の線を保つ)。

### 決めること 2: 向きの中身と順。衝突の扱い

- 順は上の 5 段。順の根拠は「上位ほど人が確定済み」(起案の委員)。順は同じ事項で複数の段が成り立つときの決め方で、上位の義務(削らないもの・人へ戻す 3 つ・判断記録)を免除しない(規格の委員)
- 衝突の扱い:
  - 仕様と他の段: 仕様が勝つ。仕様の誤りが疑われるなら人へ戻す(既存の「受入基準・スコープを変える選択」)
  - 登録と流儀: 登録が勝つ。食い違いを示し、既存の箇所は直さない
  - 流儀・導入済みの部品が削らないものを損なう: 倣って広げない。直すこと・部品を更新すること(依存の変更)は、既存の経路(人へ戻す/判断記録/依存の確認)へ
  - AI が自分で調べた「業界標準」: 段に入れない。依ったなら所在を示すが、それは作成側の主張で、段2 には当たらない
- 外部の実例の「そもそも要るか」の段は置かない。頼まれていないものを作らないことは、既に「承認済みの受入基準とスコープの内側」で決まっている。段にすると頼まれたことを削る方へ転ぶ(現場の委員の場面 5)

### 決めること 3: 「人の確認なしに承認できる」と言える条件

**言えない。本件で人の確認を減らさない。** 拠り所を示せた決定と示せなかった決定で、人の確認の有無・上げ先を変えない。違いは見え方だけ(示せない決定には推測である旨が付く)。

範囲の外の決定がいま人の目に入る所と入らない所(事実):

| 決定の種類 | 人の目に入る所 | 入らない・弱い所 |
| --- | --- | --- |
| 作業上の選択(本件の段の対象) | 確定の場で、記録された選択と理由をまとめて読む。読む時点は人が触る場所の表による(取り込む前/出荷の前/委任は事後の抜き取り) | 委任の種類は抜き取りで、抜かれない変更は個別に読まれない。事業の初期の非コアでは作成を指示した本人だけが確かめる(独立でない)。AI が退けた案を申告しない過少申告は防げない |
| 設計上の選択(新しい依存・外部サービスを含む) | 判断記録。規則に当たれば取り込む前に技術設計の判定(人)。依存は独立レビューで追加の必要性を人が確認 | 規則に当たらない設計上の選択は、判断記録を書かなければ作業上の選択と同じ経路になる(書かせるのは手引きと PR 様式) |
| 人へ戻す 3 つ(人が確定する判断・受入基準等を変える選択・取り消せない操作) | 選択の時点で人へ戻る | 戻すべきかの判定は担い手がする |

推す説明(提案資料): 「AI は既にあるものへ倒して決め、拠り所を示す。人は選択のたびに呼ばれず、確定の場でまとめて読む」。

代わりの形(段に沿い拠り所を示した決定を人が読む対象から外す)を採らない理由:

1. 外部に先例が無い。個別の承認を省く先例(標準変更)の条件は反復・低リスク・実績で、仕様に無い事項はその逆になりうる。「既定に沿えば承認を省ける」と直接に述べる規格・指針は見つからなかった(external §5)
2. 拠り所は作成側の主張で、判定の根拠に数えないと既に決めている(5.5.1・0267 決定3)。外すには、この決定を変えることになる
3. 附属書H の原則2(AI の推定による判定は判定に数えない)と、0274 決定7(AI の判断を理由に人の確認を減らすことは H.4 条件4 が禁じる。減らしてよいのは決定可能な条件による場合だけ)に反する。「段に沿った」は決定可能な条件でない
4. 品質監査の委員の筋書き(上限無しの再試行に「倣った」と書かれ、確定の場の人が読み流す)のとおり、拠り所の記載が「確認済み」の印として働く害が最大になる

### 決めること 4: 降ろし先

- 準拠テンプレートの常駐の指示(`CLAUDE.md` の「人へ戻す3つの場合」に続く作業上の選択の行。核の文言を `scripts/gate/claude-md-resident.json` の `core` へ)と、実装のスキル(`.claude/skills/implement/SKILL.md` 手順3 末尾)
- 未達の理由の記録 3 箇所(IMPL-1050・1051・1052)と同じ束 D1 で降ろす。段と理由の記録は同じ行の上で働くため、別々に降ろすと食い違う
- 置くだけでは働かない実測(10 回中 0 回)への答えは、毎回届く常駐の指示に核を置くこと。常駐の文脈は費用を増やす実測(SRC-0206)があるので、段と削らないものは 5 行以内
- 終わりの短い開示(省いたこと・確かめていないこと)は、AI の出力の指示とし、欄は足さない。【直し 3】既存の器と重ならないよう、中身を次に限る:
  - 推測で決めた選択 → 既に理由の記録の「推測である旨」が受ける。終わりの開示はその要約で、別の記録にしない
  - 確かめていない前提で、仕様に影響するもの → 機能仕様の「前提」の表が受け皿(0269 決定4)。終わりの開示で人に知らせ、表への記入は既存の経路(人が閉じる)による
  - 頼まれていないので作らなかったもの → 1 行で名指す
  - **書かないもの**: 探した範囲・「探したが無かった」(0044 決定2)、何を調べたかの全件(0269 の採らない案)
- PR 様式には欄も自己チェックの項目も足さない(0271 の点検軸。「段に従った」の自己申告は写しに当たる)
- 本文の側: 5.5.1 に条文と実装マーク(新規 2 件。下の 6 章)と根拠水準マーク(新規 1 件)

### 決めること 5: 機械で閉じる範囲

- 機械: 常駐の指示と実装のスキルに、段・削らないもの・「主張であり読む範囲を変えない」の核の文言が存在すること(降ろした時点で presence)。降ろし先の実在(impl の検査)
- manual: 担い手が段の順に従ったか、所在が実在し本当に依ったか、削らないものを保ったか、倣って広げなかったか。確定の場の人と独立レビュアの扱い
- 機械で閉じない理由: 自由な文の意味と、担い手の判断の過程は決定可能でない

### 決めること 6: 特定の技術に依らない

- 条文は「実行の基盤」「導入済みの部品」「コードベースの流儀」で書き、言語・道具・クラウドの名を書かない
- 外部の実例(判断の段を与える公開のスキル)の名は、ADR の根拠と研究の記録にだけ書き、条文・テンプレートの文に書かない

## 2. 受付の 3 つの問いへの答え

1. **条文は結果と証跡までか**: 結果(決定が依った先と、その順)と証跡(既存の理由の記録の所在)まで。どう探すか・どう調べるかは書かない。順は手順に近いが、確定の場で記録から事後に照らせる「依った先」の基準として書く(照らすのは人。manual)
2. **例外承認で受けられないか**: 受けられない。7.3 はゲートの判定基準を満たさないまま進める逸脱の手続で、定めの無い事項の決め方ではない(internal §9)。0267 と 0269 も同じ理由で例外承認で受ける案を採らなかった
3. **破られたとき誰が何を失うか**:
   - 段が守られない(AI が拠り所なく自作・独自の仕様を選ぶ): 採用チームが保守の負担と見えない独自仕様を抱える。確定の場の人は差分から拠り所を推測する手間を負う
   - 段が機械的に守られる(悪い流儀・古い部品に倣う): 製品の利用者が欠陥の複製を受ける。確定の場の人は「倣った」の記載に注意を下げられる。条文の「削らないもの」「倣って広げない」「読む範囲を変えない」で抑えるが、実効は未実証で開示する

- 差し替え条件: 採用組織の変更の記録で、(a) 依った先が「既存の流儀」だけの定型の割合、(b) 倣った先の欠陥を複製した件数、(c) 削らないものを落とした件数、(d) 段の外で新しい依存を足した件数。EV-0358 の差し替え条件と同じ材料で数え、採用者へ測定の義務を課さない

## 5. 採らないと決めたことと理由

| 案・扱い | 採らない理由 |
| --- | --- |
| 案 A(置かない。理由の記録の降ろしだけ) | 所有者の確認は「組み込む」。理由の記録は依った先がある選択しか映さず、AI がどちらへ倒すかの空白が残る(規格・品質監査の委員)。定めないことは中立ではない(起案の委員) |
| 案 B(手引きと AI への指示だけ) | 規範でない頁は監査の基準にならず、同じ標準に従う組織の間で AI の既定が揃わない。指示だけが規範の根を持たないと、採用者は何に従っているかを標準から確かめられない。反対の委員の「外から見えにくい形で向きを入れる」という批判は、B にこそ当たる |
| 案 D(全段を置き、沿えば人の確認を省く) | 決めること 3 の理由 1〜4。0044 決定1 の置き換えを支える新しい証拠が無く、逆の材料(幻覚パッケージ・left-pad・OpenSSF)が揃っている |
| 案 E(器と警告だけ) | 登録の無い大半の採用者で向きが空になる。登録が無いことの警告は毎変更に出て常態化する(反対の委員の場面 4)。「採用者が上書きできる」だけを C に取り込んだ |
| 新しい依存・マネージドサービスを使う段 | 人の確認が減らずに増える(判断記録・依存の確認)。公開の実例にも無い(「数行のために依存を足さない」)。所有者の問い(ア)で回答を待つ |
| AI が自分で調べた標準に合わせる段 | 調べた標準の実在・版・適用の可否を標準の側で保証できない。本件の外部の調査自身が要約経由の取得で誤りうることを示している。登録された規格は段2 で受ける |
| 段に沿った決定の人の確認を省く・軽くする | 決めること 3。所有者の問い(イ)で回答を待つ |
| 新しい欄・マーク・人の記入(拠り所の欄、PR の自己チェック、終わりの開示の欄) | 既存の理由の記録の所在で足りる。0271 の点検軸(写し・自己申告をやめる)に反する |
| 「そもそも要るか」の段 | スコープの定めが既に受ける。頼まれたことを削る方へ転ぶ |
| 外部の実例の「強さの 3 段」 | 強さの選択は採用者の登録(段の上書き)で足りる |
| 削らないものに「アクセシビリティ」「ハードウェアの校正」を入れる | 会議体の全員一致の範囲は 4 項目。標準の本文にこの 2 つを要求する条項があるかを確かめていない。採用者は原則の登録で足せる(残る不確かさに入れる) |
| 登録が無いことの警告 | 常態化する |
| 段の順に従ったかの機械の判定・AI による採点 | 自由な文の意味は機械で閉じない |
