## 2. 理由の記録(#457 / ADR-0267・0269)

- 所在: `human-ai-boundary.md` 5.5.1(L477〜)。ADR-0267、ADR-0269。実装マーク IMPL-1050(T:CLAUDE.md の行)・1051(PR 様式)・1052(/implement 手順3)は **`state=undelivered`、`plan=scheduled issue=457 review=2027-01`**(束 D1 で降ろす予定)。
- 何を: 「退けた案がある選択」と「外部の制約に従った選択」だけ。外部の制約 = 「受入基準・既存の規約・依存の制約・実行環境・既存の公開インタフェースなど、変更の外で決まっている条件」。どちらにも当たらない選択は、選んだ内容だけを記録する(ADR-0267 決定1)。
- どう: 「理由は、依った受入基準の項目・規約・制約の**所在**か、退けた案とそれを退けた理由で示す。所在を示せない理由には、推測である旨を添える」。
- 誰が・どこへ: 担い手(AI も可)が、変更から辿れる所へ。既定は PR の本文(ADR-0269 決定2。Draft の段階から選択のたびに書き足す。PR を経ないコミットはコミットのメッセージ)。「置き場・様式・分量の下限は問わない」。
- 位置づけ: 「記録した理由は作成側の主張であり、…検証の根拠と、独立レビュー(G-6)の判定の根拠に数えない」。確定後の訂正は追記。質は manual。暫定 EV-0358(E0)。
- 拠り所を書く場所: **既にある**。「所在」(受入基準の項目・既存の規約・制約)と「退けた案」が拠り所の欄の役割を持つ。ただし、拠り所として挙げられるのは「変更の外で決まっている条件」と「退けた案」で、**「準拠した世界標準・業界標準」「倣った他の仕様」を名指す語は無い**。「既存の規約」は含む。
- ADR-0267 の採らないと決めたこと(抜粋): 全ての作業上の選択に理由を求めること、「差分から読み取れない選択」を範囲の基準にすること、理由の文字数・項目数の下限と機械の質の判定、7.3 の例外承認で受けること、など。
- ADR-0269 決定4: 調査の結果は既存の器へ寄せる。「設計上の選択を決めた調査は判断記録(2.6)、確かめないまま置いた言明を残した調査は機能仕様の「前提」の表、作業上の選択を決めた調査は 5.5.1 の理由の記録」。調査の全件の記録は課さない。
- 設計上の選択は 5.5.1 の理由の記録で代えず、判断記録(2.6)による(ADR-0267 決定5)。

## 3. 依存の実在(#455)と、依存を足すときの扱い

- `gate-criteria.md` G-5 基準8(L814): 依存の追加・更新の一覧(解決元・版の公開日時・名前の初回公開日時・公開者・署名と来歴の証明の有無・検証の結果)を機械が出す。「**この基準は合否を判定しない**」。依存の解決が走る構成では、未登録の名前は取得の失敗で G-5 が落ちる(ADR-0261 決定1。node で実行確認。python・go は未確認)。
- G-6 基準5(L1401): 「(依存の追加・更新を含む場合)**追加の必要性**と、追加・更新した依存が意図した部品であることを確認した。G-5 基準8の一覧で印の付いた行…を読んだ」。人(独立レビュア)の確認。悪意の不在は確かめない。
- 判断記録の対象: `lifecycle.md` 2.6「判断記録の範囲」(L166〜)の最初の例示が「**依存の追加・変更(ライブラリ、フレームワーク、データストア、外部サービス)**」。したがって依存を足す選択は設計上の選択で、判断記録(ADR)が要る。「選択が可逆であることを理由に、判断記録を省いてはならない」。例示は網羅でない(ADR-0041)。
- 判断記録の要否の規則(2.6 末尾の表): 規則はプロセス構成の `decisionRules` に**採用者が**置く(変更の対象パスと変更種別から導く)。規則に当たる変更は PR のトレーラ `ADR:` が要り、その判断記録の **G-3 の判定記録が取り込む前に要る**(要求事項4)。「申告で規則の対象から外してはならない」(要求事項3)。T の既定の `process.config.json` に `decisionRules` は無い(`/process-init` の設定で書く形。T:`scripts/init/generate-profile.mjs` L5517)。規則に当たらなくても設計上の選択なら判断記録を書く(T:`.github/PULL_REQUEST_TEMPLATE.md` L149)。
- G-3(`gate-criteria.md` L642〜)の基準: 2「既存資産・コンテキスト基盤と整合している」、4「代替案が最低1つ比較されている」ほか。G-3 は技術判断者(人)の判定、応答 48 時間。
- 結論(事実): **新しい依存を足すことは、(a) 判断記録の対象、(b) 規則に当たれば取り込む前に G-3(人)、(c) G-6 基準5 で追加の必要性を人が確認、という経路で人の目に入る**。依存の追加を、リスク区分 R に直接結びつける条項は見つからなかった(3.8.1 の R1 は「外部との契約・公開インタフェース・データ形式…認証・認可・個人データ…事業継続」。区分の下限の規則は採用者が置く)。
- 衝突の可能性(事実の並置): 向き 3(既製のライブラリ・マネージドサービスを使う)を AI の既定にすると、依存の追加が増え、(a)〜(c) の人の確認が増える。#470 の「人の確認なく承認できる」と、依存追加への人の確認の定めは、そのままでは両立しない。マネージドサービスは「外部サービス」として 2.6 の例示に入る。また、外部サービスの追加は、取り消しに相手方の同意を要する場合や事業継続に影響する場合に R1 に当たりうる(3.8.1。該当は変更ごとの判定)。

## 5. 人の確認なしに進めてよい範囲と、AI の独断の決定が人の目に入る場所

- 人が必ず触る場所の表: ADR-0274(#466)。第8章 軸B の後ろの「人が触る場所」の表(`tailoring-guide.md`)。凡例 = 前(取り込む前に G-6)・例(出荷までに例外承認)・記(R1・R2 の区分の確定)・後(登録した種類の事後の抜き取り)。表は既存の定めの索引で、新しい義務を足さない。
- 運用形態(5.5.2〜5.5.4): 人確定 / 協働 / 委任。委任は **CL0・R3** の登録した変更種別に限り、独立レビュアの席の責任者が事後に抜き取りで確かめる。判断・席の責任者は人(AI を責任者にしない)。
- 人が確定する 6 判断(5.5.5): R1 の決定と例外承認・委任の範囲の決定・機械で判定できない R の確定・G-7 の記名/G-8/本番反映の承認・適合性確認の承認・コア機能の理解の確認と安全の最終判断。
- 区分 R(3.8.1): R3 は「取り消しが自動化された手段で完結し、影響が組織内に留まる」。区分の下限の規則(採用者が置く)で R1・R2 の下限を導く。R1・R2 の確定は指示した者以外の自然人の記名。R3 は指示者の記載で確定してよい(自己記載の件数を開示)。
- S2 の R2 と登録していない R3(ADR-0275): 取り込む前に人が読む範囲の外では承認を待たず取り込み、出荷判定(G-7)までに全件を G-6 基準1〜6 で人が読む。
- 判定が一時的に通る条件(ADR-0272): 判定不能・値の未記録の間は、止めずに当月の全件を事後に確かめる。
- AI の独断の決定が人の目に入る場所(範囲の外の決定を含む):
  1. 作業上の選択 → PR の本文/コミットのメッセージ(5.5.1)→ 確定の場の人がまとめて確認、委任では事後の抜き取り。ただし**記録されるのは理由が要る範囲(退けた案・外部の制約)と、選んだ内容**。拠り所なく選んだものも「選んだ内容」として記録される。
  2. 設計上の選択 → 判断記録 → G-3(人)。
  3. 依存の追加 → G-5 基準8 の一覧 → G-6 基準5(人)。
  4. 全体 → G-6 基準1・2・6(挙動の要約・検証の記録は人が書く)、G-7 の証跡の集約(未読の変更は欠落)。
- レビューパッケージ(#464。`phase5-implementation/review-package.md`): 手引き。**実装マークが無く、T は生成しない**(T 内の言及は G-6 の gates/G-6.md・human-verify の手引きのみ)。含めてよいのは「対応関係」(事実)と「観点」。「結論」は含めない。判断記録や選択の理由を載せる欄の定めは見当たらない(L181 に「過去の判断が ADR に残っていなければ、節5 は差分の履歴しか出せない」)。#464 は open で、審議中。
- #466/#467 の既決(本件と突合): 人が触る場所の表(ADR-0274)・R2 の事後読み(0275)・委任を止めない(0272)・新しい義務・様式・マークを足す前に既存の定めへ寄せる(#467 方針。ADR-0271 の点検軸)。

## 9. 第7章の例外承認は「定めの無い事項の決め方」を受けられるか

事実:
- `exception-escalation.md` 7.3(L26〜): 対象は「ゲートの判定基準を満たさないまま次工程へ進める場合」。要求事項は 5 つ(権限者の記名・満たさない基準の項目番号と理由・影響と対処・回収の期限と責任者・回収までの報告)。
- 同(L49〜): 「**本節の対象は、ゲートの判定基準と、本標準の条項が本節を名指して定めた事項に限る**」。構成の条件は対象にしない。
- 記録は技術負債台帳に区分「例外」で置き、出荷判定(G-7)が突合する。5 事項のいずれかが空なら成立しない。
- ADR-0267「採らないと決めたこと」: 「7.3 の例外承認で受ける、理由を書けなかったときは 7.3 と書く」は「全変更に常態で掛かる記録を受けると台帳が例外で埋まり、G-7 の突合が働かなくなる」として不採用。
- したがって、「定めの無い事項を AI が決める」は、**基準を満たさないことではない**ので、例外承認の対象に当たらない。受けられる仕組みではない。受けられるのは、「向き(基準)を定めた上で、満たせなかった場合」になる(その場合に限り、向きが判定基準に入っているときだけ)。
