担当: 独立の突合(本体)。実装の担当の記録(impl-*.md)は読んでいない。読んだもの: owner-answers-01/02、owner-questions-01、owner-question-02・03-draft の経過、ruling.md、ruling-02.md、sources-register.md、SRC-0983/0984.yaml(該当行)、`git diff origin/main..HEAD -- src/`、template の枝 d5-470 の `git diff origin/main..HEAD`(CLAUDE.md・resident.json・implement・task-breakdown・G-6.md・settings.md・PR 様式・generate-profile・check-pr・aggregate-evidence・試験 3 本)。試験は実行していない(コードと試験の中身を読んだだけ)。

## 所見

### F-1 高: 規定 B の当たりが、確定の場(変更ごと)で手に入らない。G-6 の手引きは件数で見よと言うが、件数は出荷の時点の集計である

- 所在: `src/content/docs/phase4-process-design/human-ai-boundary.md:529`(「当たりを機械で判定する。担い手に判定させない」)、同 :538 IMPL-1081 の note(「規則は基底ブランチの構成から読む」)、template `.claude/skills/gate/gates/G-6.md:27`(「規則に当たったかは、証跡の集約の件数で見る」)、template `scripts/gate/check-pr.mjs:2435-2445`
- 問題: 規則の当たりを計算するのは `aggregate-evidence.mjs` の `choiceReviewOf` だけで、出荷判定(G-7)の集約のときに、取り込み済みの変更について後から数える。PR の検査(check-pr)は、規則を変えた PR の下限 R2 と同時変更の失敗だけを見て、その PR が規則に当たるかを出さない。確定の場の人(G-6 の判定者)には、どの変更の記録を読まなくてよいかを示す機械の判定がない。規定 B の効果(読む対象から外す)は確定の場で効くはずなのに、その場では判定が無い。人がパスの glob を自分で照らすか、全件を読むしかない。しかも G-6.md は、変更ごとの当たりを、変更ごとでない出荷時の件数で見よと案内している。集約の「外した N 件」は「規則に当たった件数」で、実際に読まなかった件数ではない。条文の「外した変更の件数」と表示の意味もずれる
- IMPL-1081 の note の「規則は基底ブランチの構成から読む」は、check-pr が当たりを判定しているように読める。実際は、基底と head の差を比べて、規則が変わったかを見るだけである
- 直し方の案: (a) check-pr(または G-5 の要約)が、基底の規則への当たりと、R1・CL1 以上・規制業で当てないことを PR ごとに出す(合否にしない)。G-6.md の案内をそれへ向ける。または (b) 降りていない経路として、IMPL を `state=undelivered`(target=pr-checks)で足す。G-6.md の文を「変更ごとの当たりは機械が示さない。glob を照らした人の判断になる」と直し、条文の「当たりを機械で判定する」の降ろし先が集約だけだと開示する。あわせて IMPL-1081 の note の「規則は基底ブランチの構成から読む」を直す

### F-2 高: 問い1 の C「いつも調べる」が、条件つき(手元の段1〜4 で成り立たない事項だけ)になった。この読みが所有者に確かめられず、ADR にも議長の読みとして書かれていない

- 所在: `human-ai-boundary.md:476`(「手元に依る先が無い事項では、自分で作る前に…調べます」)、同 :489(「段5 の調べは、段1〜段4 で成り立たない事項で…毎回行う」)、`adr/0276-*.md:52-54`(決定2「手元で足りる事項は調べない」)
- 問題: 所有者に示した選択肢では、B が「手元に何も無く自作になる大きさのときだけ、作る前に調べ」、C が「いつも調べて取り込む段を既定に入れる。多くの変更で調査と人の確認が増える」だった。所有者は C を選んだ。実装は「手元(段1〜4。コードベースの流儀を含む)で成り立てば調べない。成り立たず自作になるときは毎回」で、B から大きさの閾値を除いた形に近い。段3(流儀)が段5 より上なので、既に自作の流儀があれば調べない。所有者の考え方「未定義だからこそ、世の中にあるものへ倒す」とも向きが一部違う(流儀と標準が食い違えば流儀が勝つ)。ruling.md 1 章は両立の理屈を書いた。ただ、この読みを所有者へ確かめた記録が無い。ADR-0276 の決定2 も、所有者の C の読みであることを書かず、決定として書いている
- 直し方の案: 所有者へ1問だけ上げる(「C の『いつも』を、手元で足りないときはいつも、と読みました。手元に既存の書き方があれば調べません。これでよいか」)。回答が届くまでは、ADR-0276 の状況か決定2 に「C の『いつも』は、手元に依る先が無い事項では毎回、と議長が読んだ。所有者の確認は未」と書き、根拠水準マーク(EV-0394 の対象)にも含める。所有者が「手元にあっても調べる」と答えたら、段の順と止まり方を直す

### F-3 高: PR 様式の「検証方法と結果」の例を AC-N で引く形にした、と IMPL-1051 は言う。実際の例は直っていない

- 所在: `human-ai-boundary.md:561` IMPL-1051 の note(「検証方法と結果の例を受入基準の識別子(AC-N)で引く形は、機械で検査しない」)、template `.github/PULL_REQUEST_TEMPLATE.md:7` と :18-19

### F-4 中: 「取り消しが難しい重い変更」を R1 と読んだこと、「読まなくてよい定めは効かない」と読んだこと、決め事の範囲を 3 つと読んだことが、ADR では所有者の決定として書かれている

- 直し方の案: ADR-0276 の状況か決定9・12 の直下に、「(i) は指揮役の読み、(ii) と (iii) は議長の読み。所有者の明示の確認は未」と書く。見直しの契機は EV-0396 の差し替え条件に寄せる

### F-5 中: 準拠テンプレートの CLAUDE.md が、決め事を「(a) 人が確定する判断」に入れた。標準は別の行として置き、人へ戻す 3 つの外に置いている

- 所在: template `CLAUDE.md:48`(「(a) の人が確定する判断として扱う」)、本体 `human-ai-boundary.md:471-474`(表の「5.5.5 の、人が確定する判断に当たる選択」と、別の行の「決め事」)
- 問題: 標準では、決め事は 5.5.5 の人が確定する判断と別の行である。人確定の判断では、AI は結論を起案しない(5.5.2 人確定の行・5.5.5 項目1)。一方で決め事では、協働で扱う変更なら推す案と根拠を添えてよい(:612)。template はこれを (a) に入れたので、CL1 以上・規制業の R2・R3 でも推しを付けない、と読める。次の行の「R1 の変更では案に推しを付けず」とも食い違う。CLAUDE.md の冒頭は「次の3つに限り、自走を止め」で、標準の規定 B の文も「人へ戻す3つの場合」と書く。表の 4 つ目の行(決め事)と、3 つという数え方が揃っていない
- 直し方の案: CLAUDE.md の「(a) の人が確定する判断として扱う」を、「3つの場合とは別に、この範囲で人が決める事項として扱う(協働で扱う変更では推す案を添えてよい)」へ直す。標準の側は、規定 B の「人へ戻す3つの場合」に決め事の行を含めるかを決め、文を揃える

### F-6 中: 常駐の指示(CLAUDE.md・CR-120)が、段5 の「毎回・規模で省かない」を運ばない

- 所在: template `CLAUDE.md:46`、`claude-md-resident.json` の CR-120。本体 `human-ai-boundary.md:489`

### F-7 中: EV-0394 の外部の根拠の書き方が、出典の登録記録の限定に合わない

### F-9 中: ADR-0276 が、ADR-0273(定義が無ければ止めずに警告)と違う扱いを理由とともに書いていない

## 問題なしと確かめた項目
