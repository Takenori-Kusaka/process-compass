# #470 委員 04(規格の委員)の意見(2026-11-28)

立場: 外部の規格・実務と、標準の既存の決定との整合を問う。読んだもの: options.md、internal.md、external.md、issue-snapshot。推測は「推測」と書く。

## 前提の確認(整合の観点で)

- 外部の公的規定(A-119、英国の Code of Practice、DS-310)は「第一候補」「裁量つき」である。どれも「既定に沿えば承認を省ける」とは言わない(external §5)。先例の軽くする条件は反復・低リスク・実績で、定めの無い事項はその逆の場面になりうる
- ADR-0044 は「探す義務」と「なるべく既存を使え」を退けた。理由は、存在しないパッケージ(5〜22%)・供給網・先例が支持するのは「比較と記録」だから。external の反対側の材料(left-pad、OpenSSF の「そもそも要るか」)は、この決定を今も支える
- 一方、ADR-0044 が退けたのは「世の中から既存の部品を探し出す義務」である。**既にこのコードベース・既に導入した部品・基盤の機能へ倒す段は、探索を要しない**。ADR-0044 の範囲外と読める(推測。ADR-0044 本文の通読はしていない)

## 問い 1 採る案

**案 C を縮めた形 + 案 E の「採用者の登録が上位」だけを採る。** 案 D と案 E 単独と案 A・B は採らない。

採る内容(5.5.1 へ結果として置く):
- 定めの無い事項は、承認済みの仕様と前提 → 採用者が登録した原則・規約・適用する規格 → コードベースの流儀と既存の実装 → 基盤の機能と導入済みの部品 → 動く最小限、の順で最初に成り立つ段へ倒す
- 削らないもの(検証・エラー処理・セキュリティ・頼まれたこと)は、向きを理由に落とせない
- 世の中の標準・既製品を**探しに行く段は置かない**。ADR-0044 は維持する(直す側は C の文言であって ADR ではない。C の「導入済みの部品」は探索を含まない旨を条文に明記する)

採らない案と理由:
- **A**: 未達の #457 の降ろしだけでは、前提 3 の穴(向きの空白)が残る。5.5.1 の「所在」は、依った先がある選択しか映さない。拠り所の無い選択は「選んだ内容」だけが残り、読み手に見えない。#470 の問題は解けない
- **B**: 規範にしない案は、採用者が「標準が求める向き」を引けない。他組織が従う規格として、AI の既定を指示の側にだけ置くと、同じ標準に従うと称する組織間で AI の既定が揃わない。ただし降ろし先は B の部分(常駐の指示)を使う
- **D**: 「沿えば人の確認を省く」は、外部に直接の先例が無く(§5)、反復・実績の条件も満たさない。さらに ADR-0044 を置き換えるが、置き換える根拠となる新しい外部の証拠は調査に無い(逆に反対側の証拠が揃っている)。G-3・G-6 基準5 の人の確認を軽くすることは、ADR-0261 の供給網の決定とも衝突する。落とす
- **E 単独**: 器だけでは、登録が無い大半の採用者で向きが空になる。ただし「登録が上位」「上書きできる」は C に取り込む。値と中身を各社が定義する制約にも合う

## 問い 2 段の中身と順、衝突

順は上の 5 段。「最初に成り立つ段で止まる」。順は**同点の決め方**であり、上位の義務を免除しない。
- コードベースの流儀と業界標準が食い違う: 採用者の登録があれば登録が勝つ。登録が無ければ流儀へ倒し、食い違いを理由の記録(所在)に 1 行添える。止めない(警告の型)
- 導入済みの部品が古く脆弱: 段の順はセキュリティを覆さない。脆弱な部品を黙って使わず、更新・入れ替えは依存の変更なので従来の判断記録・人の確認へ回す。段の順で「導入済みだから」とは通せない
- 仕様の段(最上位): 仕様と他の段が衝突したら仕様が勝つ。仕様の誤りが疑われるときは人へ戻す

## 問い 3 「人の確認なしに承認できる」の条件

**言えない。置かない。** 外部に直接の根拠が無く、先例の条件(反復・低リスク・実績)も本件に当たらない。現行の線(委任は CL0・R3 の登録種別、S2 の R2 の事後読み)を動かさない。
- 拠り所を示せた決定: 従来どおり 5.5.1 の確定の場で人がまとめて確認する。負担は増えない
- 示せなかった決定: 理由の記録の既存の定めどおり「推測である旨を添える」。**警告に留める**。人へ上げる新しい経路は足さない。ADR-0036(条件付き通過という値は無い)に合わせ、通す・通さないの新しい区分は作らない
- 依存の追加・設計上の選択・公開インタフェースやデータ形式の変更: 従来どおり人。段に沿っても省かない

## 問い 4 標準に合わせる段と、既製・マネージドを使う段

- **標準に合わせる段**: 「採用者が登録した原則・規約・適用する規格」としてだけ置く(上の第 2 段)。AI が自分で調べた標準へ合わせる段は置かない。理由は、AI が調べた標準の実在・版・適用の可否を標準側で保証できないこと(慣れた探索の結果を既定にすることは ADR-0044 の趣旨に反する。推測)。AI が自分で標準に倣ったときは、PR の「何を・なぜ」に出典を書く。これは選んだ内容の記録の範囲で足り、理由の記録の範囲(ADR-0267)を広げない。条項にはしない
- **既製・マネージドを使う段**: 足さない。ADR-0044 と G-6 基準5 を維持する。足すなら人の確認が減らずに増える(前提 4)。「そもそも要るか」を最初に置く実例(OpenSSF・ponytail)と、段 4 の「数行のために足さない」は、むしろ足さない向きである

## 問い 5 降ろし先と機械で閉じる範囲

- 降ろし先: 常駐の指示(CLAUDE.md の数行。claude-md-resident.json の `core`)と実装のスキル。#457 の IMPL-1050〜1052(未達)と同じ束で降ろす。置くだけでは 10 回中 0 回という実測(前提 6d)があるので、スキルの本文だけにせず**毎回届く常駐に置く**。ただし常駐の文脈は費用が平均 20% 超増える(SRC-0206)ので、段は数行に収める
- 機械で閉じる範囲: 指示の文言の存在と、降ろし先の実在まで(決定可能な条件だけ)。AI が段を踏んだかは機械で閉じない。manual とし、根拠水準マーク(E0 暫定)で開示する。独立の試験が安全の保持を測っていない点も、マークの本文に書く
- 終わりの短い開示(省いたこと・確かめていないこと)は、新しい欄にしない。PR の本文へ AI が書く形に留める

## 問い 6 具体の筋書きと、信頼性が落ちる場面

筋書き: 業務の担当者が「注文一覧の CSV 出力を足して」と頼む。受入基準は「一覧の全列を CSV で取得できる」のみ。AI は(1)仕様に文字コードの定めが無いことに気づく。登録された原則は無い。(2)コードベースに別画面の出力の既存の実装があり、導入済みの部品を使っているので、同じ部品・同じ使い方で書く。PR の本文に「既存の出力に倣った(所在: 該当ファイル)」と書く。(3)文字コードは、既存の出力が決めている形に従う。既存に無ければ、データ形式を決める選択は 5.5.1 の人へ戻す 3 つに当たるので、手を止めて人へ問う。(4)別の CSV 部品を足したくなったが、導入済みで足りるので足さない。足りないなら設計上の選択として判断記録へ。確定の場で人は PR の本文の「所在」を読み、倣った先が妥当かをまとめて確認する。段の順は人の確認を省いていない。

信頼性が落ちる場面(推測を含む):
1. **既存の悪い流儀の増殖**: コードベースの流儀が負債(debt-payback の「AI は新規生成へ流れやすい」の逆)のとき、段 3 が負債を複製する。段 2 の登録が無い組織で起きる
2. **導入済みの古い部品への固着**: 段 4 が更新を後回しにし、脆弱な部品を使い続ける。セキュリティを覆さない旨を明記しても、AI が守る保証は無い
3. **所在の水増し**: 「既存の実装に倣った」の定型句が増える(comply-or-explain の限界。draft-11)。確定の場の人が読み流すと、拠り所の見えない決定が通る
4. **常駐の指示の費用**: 全ての作業に数行が毎回届き、効果が測れないまま費用が増える(SRC-0206)
5. **段の順を免責に読む誤読**: 「段に沿った」ことを人の確認の省略の根拠にする運用が現れる。条文は 3 の「言えない」を明記して防ぐ

## 審議の重さについての所見

採る案は、採用者への新しい義務(既定の向きを課す)なので「重」に当たると見る。外部の調査は既に揃っている。ADR-0044 との整合は、探索の有無で分けることで保てるが、この読みは通読していない ADR 本文で確かめる必要がある(独立の突合に回す)。
