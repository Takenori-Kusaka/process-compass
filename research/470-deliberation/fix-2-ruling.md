# #470 独立の突合 2 巡目の所見への議長の裁定(2026-11-28)

所見は review-2.md。3 巡目の突合は行わない。表示と実態の食い違いの「高」だけは直す。

| 所見 | 裁定 |
| --- | --- |
| N-1(高) 「プロセス構成のファイルに触れる変更には規則を当てない」と条文が言うが、コードは構成のファイル 1 つを当たりの判定から除くだけ | **コードを条文に合わせる**。変更がプロセス構成のファイルに 1 つでも触れていれば、その変更の全体に規則を当てない(PR の検査の知らせも、集約の件数も)。試験の場面を足す(構成のファイルと規則のパスのファイルを同時に変えた変更が、当たりに数えられない)。判定を無効にすると落ちることを確かめる |
| N-2(高) 安全重要度を範囲の途中で変えた構成で、確定の場で「当たる」と知らせて外した変更を、開示が「当てていない」と出し、件数を出さない | **変更ごとに数える**。集約は、変更ごとに、その変更の基底の構成(規則を読むのと同じ構成)の安全重要度・規制業で、当てる・当てないを決める。外した変更は外した件数に数え、当てなかった変更は当てなかった件数に数える。出荷の時点の構成だけで全体を「当てていない」としない。直しの 1 巡目で足した、誤った表示を正しいものとして固定した試験の場面は、正しい期待へ書き換える(本件で足した場面なので、過去の決定の固定ではない)。本体の条文の「多く見せない側に倒す」の文は消し、「件数は、変更ごとに、その変更の基底の構成で数える」に置き換える。変更ごとに数える実装ができなければ、できた範囲を正確に書き、できない部分は本体で undelivered として表示する |
| N-3(中) 積み重ねた PR では、既定ブランチに無い規則で知らせが出る | 開示して閉じる。本体の実装マークの note に 1 文(知らせは PR の基底の構成で出す。出荷の件数は集約が数える) |
| N-4・N-5(低) /implement の括弧、/task-breakdown の 1 文 | 直す |
| N-6(低) scope-ledger の分類 | 開示して閉じる(分類は記号で機械が決める) |
| N-7(低) ADR-0276 の「所有者の原文」の見出しの下に記録者の要約が入る | 直す。原文は引用だけにし、記録者(指揮役)の要約は指揮役の読みの節へ移す |
