## R-1 軸D の表の空いた行(G-1・G-2・G-5)

### 結論

3行を表へ足す。G-1 は発注側(固定)、G-2 は発注側(固定)、G-5 は「機械。置き先を持たない。検査と閾値は強制層を所有する組織が持つ」とする。発注側が企画だけを持つ形でも置き先は変えない。G-8 の理由の「既存の決裁権限規程による」を改める(R-5 と連動)。受注側の受注の可否の決裁は、本標準のゲートではないと明記する。

### 理由

- 監査は「どのゲートを、どの組織の誰が判定したか」を表から引く。表に行が無いゲートは、置き先が「決めていない」のか「課さない」のか区別できない。G-2 は TG:546 からの帰結として読めるが、帰結に頼る表は監査の照合表として使えない(内部 1.2)
- G-1 は帰結で決まる。G-1 と G-8 の判定者は同じ事業決裁者の席である(RR:19 の図)。席の責任者は1名で、G-8 は発注側に固定済み(TG:588)。したがって G-1 の事業決裁者も発注側の者になる。行を足しても、ADR-0069 決定2「判定の置き先を、いまの許容より狭めない」に触れない。G-1 にはもともと許容が書かれていない。外部 1.1(モデル契約 第二版 前書き p.7「継続を決める権限はユーザ」)とも向きが合う。ただし同所はユーザ側の見解の紹介であり、根拠としては弱い
- G-2 は価値責任者の A を移せない(G-4 と同じ理由)。外部 1.2(JISA 第17条)は要件定義書を双方の責任者の記名で確定する。本標準は判定の決定者を1名に限る(D-0 表1 の注記「決定欄に2名以上を書いてはならない」)。受注側の確認は、ゲートの判定ではなく契約上の確認行為の側で扱う。G-2 と契約上の確認行為の対応づけの欄は既にある(テンプレ8 第9項)
- G-5 は人の判定者を持たない。判定の真正性は、検査の定義と閾値を誰が変えられるかで決まる(A2)。行の中身は「置き先」ではなく、強制層の所有の節を引く形にする

## R-2 指示資産と強制層の持ち主

### 結論

1. 「強制層をどちらが所有するか」の対象を、**層と置き場で分けて**記録させる。(a) CI 側の強制層(ルールセット・ブランチ保護・必須の検査・判定基準を実装する検査・閾値・CODEOWNERS)、(b) エージェント側の強制層(権限設定・実行前フック)、(c) 誘導層と再利用層(`CLAUDE.md`・スキル)。(a) はリポジトリと CI を所有する組織、(b) はエージェントの実行環境を所有する組織の物とする。(c) は、どちらが書き、どちらが承認するかを締結時に決めて記録する(どちらかに固定しない)
2. **CI 側の強制層を緩める変更**(判定基準を実装する検査の削除・統合、閾値の緩和、ルールセットとコード所有者の縮小)には、AI維持管理者の承認(ADR-0074 決定3。変えない)に加えて、その強制層を所有する組織が指名した者の同意を要する。指名した者はテンプレ8 に記名する。AI維持管理者がその組織の者なら兼ねてよい
3. 受注側が CI 側の強制層を所有する形では、緩める変更を発注側の事前の同意にかけるか、事後に提出するかを締結時に選んで記録する。空欄は認めない。検査を外す変更の記録(ADR-0074 決定4)は、受領する記録に含める
4. 席と受信箱に組織の属性を持たせない(ADR-0069 決定2 を維持)。席と組織は、テンプレ8 の記名で結ぶ
5. テンプレ8 に第9項とは別の項「強制層と指示資産の所有」を足す。附属書H H.9 問15 との食い違いを解く
6. CODEOWNERS の雛形は、強制層と指示資産の全部を AI維持管理者の行へ直し、CODEOWNERS 自身の行を足す(実装は #358 と合わせる)。軸D が受託の構成では、コード所有者のレビューを必須にするルールセットを選ばせる

### 理由

- 監査の問い「受注側が自分の強制層を緩められないか」への答えは、いまの本文では「発注側が CI を所有すれば止まる」(TG:637)だが、A2 のとおり所有だけでは止まらない。Write の要員は、同じ PR でワークフローと検査のスクリプトを書き換えられる。止める層は、Admin が持つルールセットのコード所有者のレビューだけである(外部 3.1)。所有の記録に「緩める変更を誰が承認するか」が無ければ、所有は名目になる
- 3.11 は席を、軸D は組織を主語にする(内部 2.1)。席に組織の属性を足すと ADR-0069 決定2 と #357 の論点に踏み込む。テンプレ8 の記名で結べば、構成のデータ形式を変えずに、監査が契約の記録から人と組織を辿れる
- (c) を発注側に固定しない理由: 固定する理由が法令の区分(第1集 問7。外部 2.2 の推論)にしか無い。ADR-0069 は、法令の区分だけを理由に宛先を固定する案を落とした(「法令上の要求事項を、名前を伏せて条項にすることになる」)。同じ理由で、受注側への固定も採らない。決めて記録させることで、外部 2.3 の第3集 A2 が回避策に挙げる「役割・権限・進め方を予め明確にし合意する」の器にもなる(この一致は情報であり、適合の根拠ではない)
- (a) の緩める変更へ同意を求める理由は、法令ではなく本標準の内側にある。判定基準を実装する検査は受入れの条件そのものであり(ADR-0074 決定2)、判定される側がそれを単独で緩められると、ゲートの判定が成り立たない。兼務禁止(第3章 3.5)と同じ構造である
- (b) を実行環境の所有者に置く理由: 実行前フックは要員の端末で動く。発注側は確かめられない。T08 第3節にも「エージェントの実行環境の設定」の行がある。(b) の緩みは (a) の検査(既存のテストの変更の一覧など)でしか発注側に見えない、と開示する
- 要約値(ADR-0085)を受け渡しても、`.claude/settings.json` の緩みは出ない(A7)。要約値を「強制層が緩んでいない証拠」として受領させる案は採らない

### 落とす案

| 案 | 落とす理由 |
| --- | --- |
| AI維持管理者の席を、強制層を所有する組織に固定する | 誘導層の全部を発注側が承認する形になり、作業の方法の文書を発注側が管理する構図に近づく(外部 2.2 の推論)。実行環境の (b) を発注側は確かめられない |
| AI維持管理者の席を、作業する組織に固定する | (a) を判定される側が単独で緩められる |
| どちらの組織かを決めて記録するだけにする | 記録は辿れるが、受注側が緩められる状態を許す。監査の問い(2)に答えない |
| 席に組織の属性を足す | ADR-0069 決定2 と当たる。#357 の決定を先取りする |
| 発注側の監視(ルールセットの閲覧権限)で代える | TG:642「監視によって兼務禁止を担保する構成を採りません」と当たる。閲覧は現時点の状態しか示さない |
| 組織のルールセットの必須ワークフロー(別リポジトリの定義)を要求する | 有力な手段だが、本会議体の調査に無く、自分でも確かめていない。製品の機能名を規範にしない。テンプレートの手引きの候補として #360 へ送る |

### 文の案

第8章「強制層をどちらが所有するか」の表の後へ(本文):

「所有は、層と置き場ごとに決めます。CI の側の強制層(ルールセット、ブランチ保護、必須の検査、判定基準を実装する検査、閾値、コード所有者の定義)は、リポジトリと CI を所有する組織の物です。エージェントの側の強制層(権限設定、実行前フック)は、エージェントの実行環境を所有する組織の物です。誘導層と再利用層は、どちらの組織が書き、どちらの組織が変更を承認するかを、締結時に決めて記録します。」

箇条(である調):

- CI の側の強制層を緩める変更は、AI維持管理者の承認に加え、その強制層を所有する組織が指名した者の同意を要する。指名した者を、テンプレ8 へ記名する
- 受注側が CI の側の強制層を所有する場合、緩める変更を発注側の事前の同意にかけるか、事後に提出するかを、締結時に選んで記録する。空欄にしない
- 検査を外す変更の記録は、受領する記録に含める
- エージェントの側の強制層の緩みは、CI の側の検査が拾う範囲でしか、所有しない組織に見えない。この限界を契約の記録へ残す
- 席と受信箱に組織の属性を持たせない。席と組織の対応は、テンプレ8 の記名による

テンプレ8 の新しい項(様式。欄名の案): 「リポジトリと CI を所有する組織」「ルールセットとブランチ保護を変更できる者(管理者権限)」「エージェントの実行環境を所有する組織」「誘導層・再利用層を書く組織 / 変更を承認する組織」「CI の側の強制層を緩める変更に同意する者(所有する組織が指名)」「受注側が所有する場合の、緩める変更の扱い: 事前の同意 / 事後の提出」「確認できない状態を受け入れる場合、その旨」。

外部の制約の注記(TG:618〜)へ足す情報(文末は「とされています」): 発注者が作業の内容・順序・方法を文書で詳細に示し、受注者がそのとおりに作業する場合も、指示と同じに扱われるとされている(第1集 問7)。指示資産がこれに当たるかの公的な整理は確認した範囲に無い、と書く。

### 矛盾の検査

ADR-0074 決定3 は変えない(AI維持管理者の承認は残し、所有する組織の同意を足す)。ADR-0038 決定3 の受信箱(`state:needs-platform`)も変えない。3.11.5「統合と削除は AI維持管理者のみ」とは当たらない(同意は統合・削除を行う権限ではない)。ADR-0069 決定2 を維持する。TG:642 の「監視で担保しない」を維持する。RR:1268 の「案件の内側」は、委託でも案件(契約の範囲)の内側と読み、組織は特定しない、と注記する。

## R-3 判定の結果を受け取る者

### 結論

受け取る者の**値**は構成と `CLAUDE.md` へ写さない。値の正本はテンプレ8 だけにする。代わりに3つを降ろす。(1) 構成書と `CLAUDE.md` の生成部分へ、軸D が受託のとき「判定の結果の受け取る者と強制層の所有は `docs/ai-sla.md` 第2節・第3節」と所在を出す。(2) 軸D が受託で、様式が無い、または受け取る者の欄が空のとき、`/pit` が注記を出す(記入の有無だけ。中身は確かめない)。(3) 判定を置いた組織と作成した組織が異なるゲートの判定記録(テンプレ4)に、「結果を渡した先」と「渡した日時」の欄を置く。受け取った側の受領の確認は課さない。

### 理由

- 監査の問い「判定の結果が相手へ届いたことを示せるか」は、受け取る者の名を構成へ写しても答えられない。示せるのは、誰へ・いつ渡したかの記録である。いまはそれが判定記録に無く、差し戻しの滞留を監査で測れない(EV-0108 の差し替え条件「差し戻しから応答までの時間」も、この記録が無いと測れない)
- 値を2か所へ書くと片方だけ更新される。D-0 と構成の関係で本標準が既に採った考え方(テンプレ0「構成から導ける欄は生成してよい」の節の理由)と同じ
- 受領の確認を課さない理由: 契約で受け取る者を名指しした以上、その者へ渡した時点を起点にすれば滞留は測れる。意思表示は相手方に到達した時から効力を生じる(民法 第97条。自分の知識。今回の調査に出典カードは無い)。受領の応答を要件にすると、応答しないことで差し戻しの起点を遅らせる経路ができる
- ADR-0069 決定2「経路の中身を課さない」とは当たらない。渡した事実と日時は経路の中身ではなく、判定の結果の記録である

### 落とす案

| 案 | 落とす理由 |
| --- | --- |
| 受け取る者を `process.config.json` の席へ持たせる | 席に組織の属性を足すことになり、ADR-0069 決定2 と当たる。値が2か所になる |
| 何も降ろさない | 受託であることを構成が知っているのに、エージェントも `/pit` も受け取る者の所在を示さない。空欄の様式が通る(IMPL-0121 は欄の存在だけ) |
| 受領の確認(受け取った側の記名)を求める | 上の理由。応答しないことが滞留の起点を動かす |
| 欄の中身(実在する人か)を機械で確かめる | 組織の外の人は名簿に無いことがある。確かめられない値を確かめたことにしない |

### 文の案

第8章「判定の結果を受け取る者を決める」の箇条へ足す(である調): 「判定の記録には、結果を渡した先と渡した日時を書く。受け取った側の受領の記名は求めない」。課さないことの箇条へ足す: 「判定の結果を受け取ったことの応答を、本標準は求めない。渡した日時を、差し戻しから応答までの時間の起点とする」。根拠は E0 であり、EV-0108 の対象へ足す(新しい EV は要らない)。

## R-4 様式 08 の、標準に無い節

### 結論

1. 6 節は、テンプレ8 へ上げる。いずれも第8章・第5章の本文が「契約に定める」「締結時に決める」「契約の記録へ残す」と要求しており、標準の様式に欄が無いのは標準側の欠落である。節 10(AI 生成箇所の追跡)は項目1 の「生成部分の識別方法」へ統合する。節 3 は R-2 の新しい項にする
2. 様式 08 第4節のチェックリストを外す(A4)。提出を求める記録は第5節(提出する記録)で扱う
3. 様式 08 に項目1(AI 利用の開示)と項目6(権利と責任)を足し、必須欄に登録する。とくに「秘密情報を外部サービスへ送出することの可否」(A5)
4. 逆向きの検査を足す。様式の見出し(`## N.`)ごとに、標準の項への対応か、テンプレート独自として理由付きの登録かを持たせる。対応も登録も無い見出しは失敗にする。あわせて、標準の各項(`## N.`)が少なくとも1欄を必須として持つか、`omit` に登録されていることを確かめる
5. DT:1186「第8項は、準拠テンプレートの必須欄にしていない」を、ADR-0069 決定8 に合わせて改める(本文の誤り。ADR は変えない)

### 理由

- 監査は様式を見て「何を合意したか」を確かめる。標準の様式に欄が無い要求は、採用者が標準の様式だけを使うと抜ける。テンプレートだけにある節は、テンプレートを使わない採用者には届かない。本文が契約での決定を要求している以上、正本を標準の様式に置くのが筋である
- ADR-0086 は、頁が独自に置いた定めを1件ずつ本文へ採るか課さないと明記するかを決め、緩める向きの定めは削った。同じ手順を様式にも当てる。A4 のチェックリストは確認の基準を広げる向きで、本文と矛盾する
- 逆向きの検査が無いと、#309 で見つかったずれ(内部 4.2、ADR-0069 の「様式が双方向にずれていた」)が再発しても拾えない。ADR-0040 は「標準側の実在を確かめる向きが要」としたが、それは対応表を古くしないための向きで、テンプレートが標準から外へ出ることは見ない
- 項単位の網羅を見ないと、A5 のように項がまるごと検査の外に落ちても、省略の記録が残らない。ADR-0040 決定3「登録そのものが判断の記録」の趣旨が働かない

### 落とす案

| 案 | 落とす理由 |
| --- | --- |
| 6 節をテンプレートから外す | 本文が契約での決定を要求する事項の記入の場が消える |

| 逆向きの検査を足さない | 再発を拾えない |
| チェックリストを「提出する記録」へ移して残す | 第5節に同じ内容(ゲート判定記録・出荷の証跡)が既にある。重複は片方だけ更新される |

### 文の案

テンプレ8 の新しい項の名(案): 「強制層と指示資産の所有」「提出する記録」(既存の第5項「監査」の「提示を求める記録」とは別と注記)、「受け入れの速度」「計算資源の費用」「発注側に読解の帯域がない場合」。項目1 の表へ「記録する項目(モデルの識別子と版 / 指示資産の版 / 実行の識別子)」「記録の保持期間」を足す。DT:1186 の改め: 「第8項と第9項の欄は、準拠テンプレートの必須欄にしている(ADR-0069 決定8)」。新しい ADR を起こし、ADR-0040 決定2 の検査の表に3つ目の向き(テンプレート → 標準)と項の網羅を足すと書く(ADR-0040 の本文は変えない)。

## R-5 決裁権限規程を前提にした文

### 結論

1. 第1章 1.2 に読み方の規定を1つ置く: 「本標準が既存の決裁権限規程・稟議の運用を引く箇所は、規程を持たない体制では、D-0 表1 に記名で定めた決定者と、D-0 に記録した値を指す」
2. 読み方だけでは字義が壊れる3か所は、文を直す。RR:972(新設の禁止の範囲)、TG:588(G-8 の理由。R-1 で改める)、GC:187(期限)
3. RR:972 の禁止は「既存規程を持つ組織が、規程と別の金額体系を新設すること」に限る。規程を持たない体制は、金額区分I〜III の境界額を D-0 に記録する。D-0 にその欄を足す(内部 5.3 のとおり、いまは書く場所が無い)
4. 境界額の値・例示を、本標準は置かない(ADR-0032 のコンテキスト「境界額も定めません」と同じ向き)
5. D-0 の表2(費用の層)と 3.8.2 の金額区分の対応を、D-0 に記録させる。対応を書かないまま両方を使うと、同じ変更の決裁者が2通りに読める
6. 事業決裁者と投資決裁者(B-1)について、D-0 に**権限の出所**の欄を置く。規程を持つ組織は規程の条項、持たない体制は授権の事実(代表権、業務執行の決定、個人事業主本人、上位の組織からの委任の記録など)を書く。最初の記入の手続(3.13.3 の「初回の記入」)は既にあるので変えない(A1)

### 理由

- 監査の問い「規程の無い体制で決裁の権限の根拠を示せるか」に対し、いまの D-0 は「誰が」を記名で示せるが、「なぜその人が決められるのか」を示す欄が無い。3.13.3 の初回の記入は本人の記名で受け付けるので、出所の記録が無いと自己申告だけが残る。外部 4.1〜4.3 は、規程という形式は求めず、権限が適切な者に割り当てられていることを求める(ISO 9001 5.3、COSO 原則3、J-SOX の統制環境 ⑥)。出所の1行は、この「割り当てられていること」を示す最小の記録である
- RR:972 の禁止の目的は二重の権限体系を作らないことにある(同所の理由の文)。規程を持たない体制では、二重になる相手が無い。字義どおりだと 3.8.2 の表を使う手段が無くなり、決裁者が「一意に定まる」という第3章の成果(RR:15)が成り立たない
- 表2 と 3.8.2 の対応: 両方が金額で権限を区切る。対応を書かないと、同じ金額・同じリスク区分の変更について、表2 は「チーム層で動ける」、3.8.2 は「B-2 が決める」と読める。これは RR:972 が避けようとした二重の権限体系を、本標準の内側に作っている。どちらを優先するかを標準が決める根拠は無いので、組織に対応を宣言させる
- 値を置かない理由: 外部 4.4 のとおり、法令と判例は固定の閾値を置かず総合考慮とする。例示の値は、そのまま採られて根拠の無い既定値になる

### 落とす案

| 案 | 落とす理由 |
| --- | --- |
| 7 か所を個別に書き換えるだけ | 今後の改訂で同じ形の文が増えたとき、読み方が無い |
| 1.2 の読み方の規定だけ | RR:972 は読み替えても禁止の文が残り、規程の無い体制の経路を塞ぐ |
| 境界額の例示の値を置く | 根拠が無い。置くなら EV が要り、例示が既定値として使われる |

| 権限の出所を書かせない | 規程の無い体制で、初回の記入が自己申告だけになる |

### 文の案

第1章 1.2 の後(本文): 「本標準が既存の決裁権限規程または稟議の運用を引く箇所は、規程を持たない体制では、D-0 表1 に記名で定めた決定者と、D-0 に記録した値を指します。」

RR:972 の改め(本文): 「金額区分I・II・IIIの境界額は、本標準では定めません。既存の決裁権限規程を持つ組織は、規程に定める境界額をそのまま用い、規程と別の金額体系を新設してはなりません。規程を持たない体制は、境界額を D-0 に記録します。いずれも、企画承認(G-1)の時点で案件ごとに記録しなければなりません。二重の権限体系は、どちらに従うかの解釈を現場に委ねる結果を生みます。」

D-0 の様式へ足す欄(案): 「金額区分の境界額(区分I/II/III)と出所(規程の条項 / 本 D-0 で定める)」「表2 の費用の層と金額区分の対応」「事業決裁者・投資決裁者の権限の出所」。
