## 所見

### R-1(高・偽の合格) H.8 の「使ってよい表現」の表から語が消えても通る

- 所在: `scripts/check-claim-terms.mjs`(`sectionLines(read('assurance-case.md'), /^## H\.8\s/)` と `tableText`)、`scripts/lib/claim-terms.mjs` のヘッダ
- 再現: 写しで、H.8 の「| 使ってよい表現 | 条件 |」の表(assurance-case.md 833〜845 行)だけから語を1つずつ消し、`node scripts/check-claim-terms.mjs` を流す。「適用の表明」「適合の主張」「逸脱を伴う適合の主張」「例外承認の件数」「作業中の版」の 5 語は、消しても exit 0 になる(他の 5 語は落ちる)。scratchpad の `326-probe/probe.mjs` の `claim_allowed_only`
- 原因: `tableText` は H.8 の節の中のすべての表の行をつなぐ。H.8 には「使ってはならない表現」の表(850〜873 行)もあり、その表の理由の欄に同じ語が出る(例: 870 行「例外承認の件数の句を省き…」、869 行「逸脱を伴う適合の主張を、名を省いて…」)。#353 が懸念した「件数の句が対外の文の型から落ちる」場合が、まさにすり抜ける
- 表示と実態: `lib/claim-terms.mjs` のヘッダは「附属書H H.8 の『対外的に使う表現』の表」、裁定 14 は「H.8 の該当の表」と、1つの表を指す。実装は節の全部の表を読む。`05-implementation.md` の「片側の語を消すと落ちる」は、1 行だけの合成の入力での確認で、実物の2つの表の構成を写していない(`test-claim-terms.mjs` の `full` は 1 行)
- 1.10.2 の側: 1.10.2 の節には3つの表(主張の表と、#### 小見出しの下の閉じた列挙の表2つ)がある。今は後の2つに語が出ないため、最初の表から消すと 10 語とも落ちる(`326-probe/claim.mjs`)。ただし同じ構造の弱さを持つ
- 直し方の案: H.8 は見出し行が「| 使ってよい表現 |」の最初の表だけ、1.10.2 は見出し行が「| 述べること |」の最初の表だけを読む(`check-section-refs.mjs` の表の読みが `header` を渡す形と同じ)。試験に「同じ節に別の表があり、そこに語が残る」入力を足し、落ちることを確かめる。ヘッダの「の表」の記述と実装を一致させる

### R-2(高・表示と実態の食い違い) `provision-ok` が飛ばす検査の範囲

- 所在: `scripts/check-provisions.mjs` 41〜44 行(a7a50bc が足した「印のある行は、2〜5・7〜12 のすべての検査を飛ばす」)
- 再現: 写しで、規定の文書(roles-responsibilities.md)の末尾に「本節の値は初期値として扱います。」(検査14 廃した値の語)を置くと落ち、同じ行に `<!-- provision-ok: 試験 -->` を足すと通る。「このための新しいゲートを設けません。」(検査17 主語の無い表明)も、印で通る(`probe.mjs` の `prov14*`・`prov17*`)
- 根拠: 検査14 は 2〜5 のループの中(163 行の早期 return の後)、検査17 は 256 行で `hasMark(line0, 'provision-ok')` を見て return する。ヘッダは 14 と 17 を飛ばす範囲に含めない。裁定 2 は「ヘッダの開示に、同じ行の他の検査も飛ぶことが読めるかを確かめ、読めなければ文を直す」とし、開示を統制の閉じ方に選んだ。その開示が、印で外れる検査を少なく書いている。`05-issue-comment.md` の項目2 も「開示した」と書く
- 直し方の案: 41 行と足した文の範囲を「2〜5・7〜12・14・17」に直す(動作は変えない)。範囲を手で書く限り、印を見る検査が増えるたびにずれるので、試験(各検査の違反を仕込んだ行に印を足すと、ヘッダに書いた検査だけが外れる)を足すかは議長の裁定に委ねる

### R-3(中) 試験が検査本体への結線を守らない

- 所在: `scripts/test-scope-exempt.mjs`、`scripts/test-gate-criteria-yaml.mjs`(いずれも lib の関数だけを呼ぶ)
- 再現:
  - `check-scope.mjs` の `errors.push(...exemptProblems(exempt.exempt, USED));` を消し、存在しない見出しの登録を足すと、`check-scope` も `test-scope-exempt` も exit 0(`probe.mjs` の `scope_unwired`)
  - `check-gate-criteria.mjs` の文の一致の比較(`have.length === want.length && want.some(…)`)を無効にし、yaml の G-5 の基準1 の文を変えると、検査も `test-gate-criteria-yaml` も exit 0(`gc.mjs`)。文の一致の比較には試験が1つも無い
- 根拠: 依頼の観点「足した試験が、検査を壊したときに本当に落ちるか」。`test-section-refs.mjs` は検査を子の工程で起動して結線まで確かめる形を取り、こちらはその形を取っていない。`check-adr-links`・`check-claim-terms` も lib だけの試験で、同じ弱さがある(実データの検査は、結線が消えても通る)
- 直し方の案: `test-section-refs.mjs` と同じく、写しの入力(一時ディレクトリの yaml・md)で検査の本体を起動し、違反の入力で exit 1 になることを確かめる試験を、各検査に1件足す。検査の本体が入力の所在を引数で受けない場合は、ROOT を環境変数か引数で差し替えられるようにする

### R-4(中) 節番号が2つ以上のリンクを、番号と名の対応で黙って見ない

- 所在: `scripts/check-section-refs.mjs` 289〜292 行(`numbers.length === 1` の条件)とヘッダ 23〜24 行
- 再現: `[第3章 3.9・3.10](…roles-responsibilities/)「決裁権限マトリクス」` は exit 0(3.8 の名を 3.9・3.10 で引いている)。`probe.mjs` の `ref_two_nums`
- 根拠: ヘッダは「リンクの文に節番号もあるとき…その番号で始まる見出しが、その語を含む」と書き、番号が1つの場合に限ることを書かない。「検査しない形式」にも挙がっていない。なお、現行の対象 4 ページで番号と名の対応を検査した参照は 1 件(出力「番号と名の対応 1」)で、出力の件数は実態どおり
- 直し方の案: (a) 番号が複数のときは、名がいずれかの番号の節に含まれるかを見る、または (b) ヘッダの「検査しない形式」に「節番号を2つ以上含むリンクの、番号と名の対応」を足す。偽陽性の数は (a) を採るときに数える

### R-5(低) 05-issue-comment.md の項目9 の欠け

- 所在: `research/326-deliberation/05-issue-comment.md` の項目9
- 根拠: Issue 本文の項目「集約の確かめの残り」は3つ(手順単位の `continue-on-error`、ジョブの `if` が常に偽、過去の PR の時点のワークフローの定義)。`01-investigation.md` 110・176 行は3つ目を「開示」とした。コメント案は前の2つだけを書き、3つ目が落ちている(裁定の template の項目の節も同じ)

### R-6(低) `writeCriteria` の境界(直す前からの挙動)

- 所在: `scripts/lib/gate-criteria-yaml.mjs` の `writeCriteria`
- 再現(`gc2.mjs`): criteria の行を持たないゲート g-a へ書くと、`[\s\S]*?` が次のゲートへ進み、g-b の criteria を g-a の基準で置き換える。行末が CRLF の yaml では一致せず、何も書かない
- 根拠: いずれも旧い正規表現と同じ挙動で、書き戻しの後の検査が件数・文の不一致で落とすため、偽の合格にはならない。現行の integrated.yaml は LF
- 直し方の案: 書き戻しも YAML の文書(`YAML.parseDocument`)の該当のゲートの節点を書き換える形にするか、置換の範囲を次の `- id:` の手前までに限る。直さないなら、ヘッダに「criteria の行が在るゲートだけを書き戻す」と書く

### R-7(低) `check-adr-links` の出力の件数の読み

- 所在: `scripts/check-adr-links.mjs` の最後の出力「ADR の後継参照: 136 件を検査(…)」
- 根拠: 136 は ADR の総数で、順方向の参照(状態の行の「置き換え(→ ADR-N)」)を持つのは写しで 18 件(0009・0017・0021・0032・0035・0040・0047・0054・0056・0059・0061・0065・0070・0073・0077・0083・0084・0085)。括弧の限定があるので偽ではないが、検査した参照の数を出す方が実態に近い
- 直し方の案: 「136 件のうち、順方向の参照 N 件(M 組)を検査」と出す
