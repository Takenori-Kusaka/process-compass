## 項目 1: scope-exempt の残骸

1. **推す案の欠陥**
   - A は「その節に `LIMIT_RE` に当たる地の文が1行以上ある」ことを、登録の側で別に再実装すると読める。`check-scope.mjs:126-141` は、検出の前に `normative`・見出し・表(`|`)・箇条書き(`-`)・引用(`>`)の行を除く。別実装は、この除外と食い違えば、実在する登録を残骸と誤り(偽陽性)、残骸を実在と見る(偽の安心)
   - `LIMIT_RE` は ADR-0049 が「閉じた集合に保つ」と定めた語彙。登録の有効性を `LIMIT_RE` に結ぶと、語彙を狭めるたびに登録が落ちる。これは意図した結合だが、`LIMIT_RE` を変える Issue の費用に載ることを開示すべき
   - 「現状0件」は調査者の写しの結果で、検査本体の通過とは別。写しと本体のフィルタが同じである保証が無い
2. **残る案(A2)**
   - 検出の本体の中で、`EXEMPT.has(...)` が **真になった登録の集合**(used)を記録する。実行の最後に、`EXEMPT` のうち used でない登録を、エラーとして出す(eslint の unused-disable の型)。ページ・見出し・`LIMIT_RE` を別に確かめず、**本体と同じ判定で「効いたか」だけ**を見る
   - 登録の `reason` は `isReason`(`scripts/lib/exempt-marks.mjs`)で非空だけを確かめる。意味は見ない(A'' を採らない点は調査と同じ)

   - 警告のみ(A'): 調査と同じ。`check-scope` は警告も最後にエラーへ回す(`:210`)ため、警告だけにする設計の整合も取れない

## 項目 14: 1.10.2 と H.8 の文の型

1. **推す案(N)の欠陥**
   - **既に決定が開示している**: ADR-0134 の影響は「1.10.2 と H.8 の文の型の一致を確かめる機械の検査は無い。一致は人が確かめる」と書く。N を入れると、この記述が事実でなくなる。ADR の本文は書き換えないため、**新しい ADR か状態の節での更新**が要る
   - 件数の句は、1.10.2 では「未達のゲートの件数と、記録の欠落の件数(無い場合は 0 件…」、H.8 では「未達のゲートの件数、記録の欠落の件数、逸脱と列挙に無い離脱、…」と、**助詞も句の並びも違う**。存在の検査にできるのは語の列挙だけで、それが通っても文の型は一致していない。偽の安心を生む
   - 「登録簿(`provision-forms.yaml` の形式)に所定の句を登録する」は、新しい登録の形を足す。登録簿は別の目的(廃した言い回しなど)のもので、ここへ載せると登録簿の責務が広がる。`impl-inventory.yaml` は 1.10.2〜1.10.4 と H.8 を既に結んでおり(`:410-421`)、そちらに結合の記録がある
   - 調査自身が「1.10.2 の文の型が何かの確認は、実装を担う段が本文を読んで決める」と書く。**検査の対象が未定義**のまま採否を決められない
2. **残る案(N2)**
   - 所定の語の集合(`適用の表明`・`適合の主張`・`逸脱を伴う適合の主張`・`未達のゲートの件数`・`記録の欠落の件数`・`例外承認の件数`)が、1.10.2 の表と H.8 の該当の表の両方に出ることだけを、検査にする。語の集合は検査の側に置き、**どの語を持つかは今の本文から導く(定義を新設しない)**
   - 名前を「語の存在の検査」とし、文の型の一致を保証しないと、ヘッダと ADR-0134 の更新に書く
   - 実装の段が、本文を読んで語の集合を確定し、**両節で実際に通ることを実行で確かめる**。通らないなら、本文の食い違い(別の欠陥)として報告する
3. **採らない案**

4. **重への要否**: 要らない。ADR-0134 の「検査は無い」の更新を、新しい決定(軽の記録)にするか、状態の節にするかは議長が決める
