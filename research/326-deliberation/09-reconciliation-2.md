## 所見

### S-1(中) 検査本体の結線の試験が、2つの検査に足されていない

- 所在
  - `scripts/test-claim-terms.mjs`・`scripts/test-adr-links.mjs`(lib の関数だけを呼ぶ)
  - `08-fixes-1.md` の R-3 の行
- 再現: 写しで次の変異を加え、試験を流す
  - `check-claim-terms.mjs` の `if (t1 && t2) problems.push(...termProblems(t1, t2));` を消す → `test-claim-terms` は exit 0
  - `check-claim-terms.mjs` が読む表の見出しを `使ってはならない表現` に替える → `test-claim-terms` は exit 0。ただし、このときは `check-claim-terms` 自身が exit 1 で落ちるので、黙っては通らない
  - `check-adr-links.mjs` の `forwardProblems(...)` を空の配列に替える → `test-adr-links` は exit 0
  - 最初と最後の変異の後は、検査も試験も黙って通る
- 根拠: 1巡目の R-3 の根拠は、`check-adr-links`・`check-claim-terms` にも同じ弱さがあると書き、直し方の案は「各検査に1件足す」だった。直しは2つの検査にだけ足し、残る2つを足さない理由を `08-fixes-1.md` の「採らなかった案」に書いていない。コアポリシーの「却下は成果である。採らないと決めたことは、その旨を明記する」に照らすと、記録の欠けに当たる。今の内容で偽の合格が起きているわけではなく、守られていないのは将来の変更による回帰なので、「高」に当てない
- 直し方の案(最後の巡なので、どちらかで閉じる)
  - (a) 記録で閉じる: `08-fixes-1.md` の「採らなかった案」に次を足す。「R-3: `check-claim-terms`・`check-adr-links` の結線の試験は足していない。検査本体の呼び出しを消す回帰は試験で検出しない」
  - (b) 直す: `check-claim-terms.mjs` に文書の所在の差し替え(例: `CLAIM_TERMS_DOCS`)を足し、試験から H.8 の表の語を1つ消した写しで起動して exit 1 を確かめる。`check-adr-links.mjs` も ADR の置き場の差し替えで同じ形にする
  - 議長が (a) を採るなら、コードの変更は要らない

### S-2(低) 同じ見出しの表が先にあると、後の表を読まない

- 所在: `scripts/lib/claim-terms.mjs` の `tableText`(`findIndex` で最初の一致を取る)
- 再現: 写しの H.8 で、「使ってよい表現」の表の写しを本物の表の前に置き、本物の表から1語を消す。`check-claim-terms` は exit 0 になる(`probe.mjs` の decoy)
- 根拠: 同じ節に同じ見出しの表を2つ置く形は、今の本文に無い。作るには意図的な編集が要る。ヘッダの「節の別の表は読まない」は、見出しの違う表について正しい。見出しの同じ表が複数あるときの挙動は書いていない
- 直し方の案: 直さずに閉じてよい。閉じるなら、`lib/claim-terms.mjs` の `tableText` の注釈に「見出しが同じ表が複数あるときは最初の表だけを読む」と書く。機械で閉じたいなら、一致する見出しが2つ以上あれば落とす。どちらも決定可能な条件で、偽陽性は今の本文で 0 になる
