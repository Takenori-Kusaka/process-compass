### 現状(再現の結果)

宣言 `claude-opus-4-5` に対するずれの件数。

| 共著者の記録 | ずれ | 開示の範囲か |
| --- | --- | --- |

- マーク: 新設なし(6 の新しいマークが受ける)。IMPL-0023 の note の文だけ直す

  - 試験(`test-g5-aggregate.mjs`): ng = 集約の式を旧い形(failure・cancelled だけ)に戻すと不備が出る。ok = 現行の定義で不備 0。既存の試験7(式を `false` に置き換える目印)は式の文字列に依存するため、目印を改める
  - 実行時の振る舞いは手元で試せない。実装の段で、GitHub 上の実機の確認(一時のリポジトリ。所有者の承認が要る外部の操作)をするか、できなければ EV で開示する
- **a(手順の continue-on-error)**: 契約検査に足す。基準を実装するジョブの本文に、6 字下げ以上の `continue-on-error: true` または `continue-on-error: ${{` があれば不備とする(構文の一致)。現行の違反は 0 件。テンプレートの書き方と違って、手順の失敗を許す正当な理由がある採用者は、第7章の例外承認で受ける(条項を足さない)
  - 試験: ng = test の手順に `continue-on-error: true`、`continue-on-error: ${{ inputs.x }}`。ok = 現行の定義、基準の外のジョブ(dependency-diff)の手順の continue-on-error
- **d(手順の if)**: 機械にしない。IMPL-0142 の開示のまま(手順の書き換えは陰性の確認で人)。字面の `if: false` だけ捕まえても、式で同じことができるため
- **e(過去の時点の定義)**: 既定の案は**機械の検査(開示)**。出荷の範囲の、基底ブランチの第1親の連鎖の各コミットのうち gate-g5.yml を変えたものについて、その時点の定義を `git show` で読み、同じ `aggregateFindings` に掛ける。不備のある版があれば、項目4 の該当の検査を「期間の一部で集約の外(コミット X〜Y)」と出す。手元の git だけで決まる。第1親の連鎖を使うのは、PR の途中のコミット(rebase の取り込み)の版を数えないため
  - 試験: ng = 範囲の途中で test を needs から外し、次で戻した履歴(一時のリポジトリ)。項目4 が期間の一部の未実施を出す。ok = 範囲で定義を変えない履歴

### 反対の立場の見込み

- 実行時の success の条件は、採用者が足した正当な条件つきのジョブ(モノレポの範囲の絞りなど)を落とす。答え: 現行のテンプレートには無い。条項を足さず、第7章の例外承認で受ける(所有者の方針 (2))。基準を個別に外す規則は第8章に無く、スキップで外すことは条文が禁じる形そのもの
- e は PR の側の定義(refs/pull/N/merge)と第1親のコミットの定義が一致しない場合を見ない。答え: 開示する。第1親の連鎖は、取り込まれた定義の全部を含む
- e は費用が大きい。答え: 費用は採否の理由にしない。範囲の中で gate-g5.yml を変えたコミットの数だけ読む

### 採らない案

- `if: false` の字面の検査(01 の案 I): 式で常に偽になる形を見逃し、偽の安心を作る(04)
- 式の評価で常に偽かを判定する: 決定不能
- 手順の `if:` の検査: 同上。人の陰性の確認に残す
- 過去の時点のブランチ保護の設定を API で読む: リポジトリの外の状態で、本件の問い(ワークフローの定義)と別
