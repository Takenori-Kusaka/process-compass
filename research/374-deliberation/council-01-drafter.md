### 推す案

**案(b) 適用へ寄せる。あわせて、S1 で事業ステージにより緩めるものの所在を本文に書き、ゲートの状態では緩めないと明記する(内部調査 5.4 の d1)。**

- `:479` の段落(G-1 の S0 の簡略の中身)の後に、次の段落を置く

> S1 の出荷判定(G-7)は適用します。S1 で事業ステージによって緩めるものは、ゲートの状態ではなく、次の3つです。これ以外に、S1 であることを理由に G-7 の判定基準を外しません。

### 理由(所在つき)

1. **本標準の要求事項3 を満たせない語を升に置き続けられない。** 第8章の要求事項3 は「調整後の構成で、当該ゲートの目的が達成されることを示す」(`tailoring-guide.md:24`)である。S1 の G-7 の「簡略」は、升の括弧の限定も中身の段落も持たない(`:470`。内部調査 1.1)。規則データも `simplify` の札だけで、`param` も `value` も持たない(`rules-business-phase.yaml:49-51`)。何を省いたかが定まらない調整について、目的の達成を示す方法がない
2. **禁止事項3 の趣旨に当たる。** 「差し戻し基準のないゲートを作る」を禁じる(`tailoring-guide.md:1053`)。「簡略」の G-7 は、どの基準で差し戻すかが本文から定まらない。形式上は基準1〜9 がそのまま掛かるので文字どおりの違反ではないが、升の語が「何かを外した」と宣言するため、判定者と読み手が差し戻し基準を同じに読めない
3. **ADR-0088 が退けた理由が CL0 の S1 に当たり続ける。** ADR-0088 は「『簡略』は本文に中身が無く、定義の無い語で出荷判定を緩めることになる」(`adr/0088…:192`)として、CL1 以上の簡略を退けた。この理由は CL に依らない。CL0 の扱いは「決めていない事項」として残された(`:126`、`:219-221`)。本件はこれを閉じる場であり、同じ理由で同じ結論になる
4. **外への宣言と実際の判定の食い違いが解ける。** 準拠テンプレートは、集約・成立条件4・スキル・様式のどこでも `simplified` を `required` と同じに扱う(内部調査 4.3 の表。`template/scripts/gate/config.mjs:30-33`、`aggregate-evidence.mjs:2219`、`:2716-2727`、`:4313`、`.claude/skills/gate/SKILL.md:44`)。違いは保証の開示 項目2 に「簡略化」と出る表示(`aggregate-evidence.mjs:3279-3282`)と、変化点の順位(`generate-profile.mjs:1289`)だけである。現状は「適用として判定したものを、緩めたと開示する」状態で、保証の開示の読み手を誤らせる。信頼性の観点では、緩めていないのに緩めたと書くことも、開示の誤りである
5. **S1 の緩和は、既に基準の中へ移っている。** G-7 の基準2 は「事業ステージ別の欠陥トリアージ基準を満たす」(`gate-criteria.md:1216`)で、S1 の行を持つ(`:2060`)。初版では基準2 は「0 件」だった(内部調査 1.4)。基準3 は記録の漏れだけを問い、S1 の負債台帳は「記録+返却目安」(`tailoring-guide.md:473`)。升の「簡略」は、緩和が基準へ移った後に残った札である。重ねると同じ緩和を二度掛けたように読める
6. **G-7 の作業量は、ステージに依らず既に下限にある。** 軸C の「標準」の G-7 は「記録突合」(`tailoring-guide.md:545`)で、G-7 は再テスト・再レビューを始めない(内部調査 2.2。`gate-criteria.md:1475-1489`)。外部調査で軽いクラスから外れるとされたのは「判定の深さ」(IEC 62304 クラス A の残存異常の評価など。外部調査 S-02、二次情報)であり、本標準の G-7 はもともとその深さを持たない
7. **S1 は外部の利用者へ成果物が届く最初のステージである。** S0 の省略の前提2(「露出する利用者が、社内と実験参加者に限られる」、`tailoring-guide.md:488`)を S1 は外れる。トリアージの S1 は「限定した実利用者」(`gate-criteria.md:2060`)。ISO 9001 8.6 は規模に依らず、受入基準への適合の証拠とリリースを許可した人の追跡可能性を求める(外部調査 S-03、原文確認)。G-7 の判定記録と基準1 がこれに当たる
8. **他の条項が S1 の G-7 の中身を前提にしている。** S0 の省略の前提3 は、S0 の期間の未確認の変更を S1 以降の出荷で記録の欠落として扱う(`tailoring-guide.md:489`、ADR-0065 決定1 の所在「第4章 G-6・G-7」`adr/0065…:46`)。差し戻す席は G-7 の基準5 である(ADR-0088 `:57`)。成立条件4 は G-7 の記名を要する(`gate-criteria.md:1404`)。G-8 基準1 は G-7 の通過を要する(`:1503`)
9. **先例と同じ形である。** ADR-0063 は旧 G-3 の S0 の簡略を「適用」へ寄せた(`adr/0063…:81-83`。前提の消失は ADR-0071 `:81`)。段階の単調性(S0 省略 → S1 適用 → S2 適用)も保たれ、逆転は生じない

### 他の案を落とす理由

- **案(a) 基準ごとに中身を定義する — 採らない**
  - 実質の候補は基準4 の一部だけである(内部調査 2.2・5.1)。基準6 は合否に使わない(`gate-criteria.md:2136`)、基準7 は CL0 で既に外れる。これらを中身に数えると、何も緩めない調整を緩めたと宣言することになり、現状の食い違い(理由4)を言葉で固定するだけになる
  - 基準4(運用引き継ぎ: 監視項目・障害時連絡先・復旧手順)を S1 で一部外す根拠が本文にも外部にも無い。S1 のゴールは「継続提供できる技術基盤を確立する」(`lifecycle.md:58`)で、実利用者がいる段階で復旧手順と連絡先を欠く理由を起草できない。外部調査でも、最小のクラス・プロファイルで引き渡しの記録は残る(S-02・S-10)。基準4 の一部を外す業界の実務は見つかっていない(外部調査「埋められなかった穴」)
  - 基準ごとに省く形は、本文・ADR に先例が無い。中身を持った2例(G-1 の S0、旧 G-3 の S0)は、成果物の形か対象の範囲で限定した(内部調査 1.3)
  - 基準4 の機械への降ろしは IMPL-0043 が `undelivered`(`gate-criteria.md:1228`)で、集約は文書の有無しか見ない。基準4 の「一部」を外す規定は、降ろし先でも区別できない。降りない緩和を新設することになる
  - 起草の形として書く場合、#226 の書式で基準4 の行の中に「(適用: S1 では…を除く)」を置き、規則に値を持たせ、テンプレートの集約に分岐を足し、IMPL を新設することになる。採否はこの量では決めないが、そのどれも実証の無い値を新設する(EV が E0 になる)ことを付記する
- **案(c) 省略へ寄せる — 採らない**
  - S0 の省略の前提2 を S1 は満たさない(理由7)。前提を持たない省略を S1 へ広げることになり、ADR-0065 決定1 の型と矛盾する
  - 前提3 の差し戻しの席が S2 まで無くなる。ADR-0088 `:57` の「G-7 は G-6 の欠落を差し戻す唯一の場所」は CL に依らない。S1 では G-6 がコア機能に掛かるので、その欠落を差し戻す席も消える
  - CL0・S1 の出荷がすべて成立条件4 を満たさず「品質保証の対象外」になる(`gate-criteria.md:1411`)。トリアージの S1 の行(コア機能の Sev1 は出荷不可)を確かめる席も消える。G-8 は技術品質を蒸し返さない(`:1506`)
  - ISO 9001 8.6 の最小の記録と衝突する(外部調査 S-03)
- **案(d) 簡略の条件を変更ごとのリスク区分(R)へ寄せる — 採らない**
  - G-7 の状態は案件の構成の値であり、1.7.3 は升の語を「テーラリングの規則が定める結果」とする(`overview.md:358`)。R は変更ごとに判定し、案件の構成からは「変更ごとに判定を要する」までしか示せない(`tailoring-guide.md:1061`、禁止事項7 `:1057`、ADR-0039)。G-7 は出荷ごとの判定で、1つの出荷に R の異なる変更が混ざる。R で G-7 の状態を決めると、構成から状態が定まらず、升の語の定義と両立しない
  - 外部調査が指摘した Google LCE の型(低リスクを変更の性質で定め、短いチェックリストを当てる。S-04)は、本標準では変更ごとの層に既にある。運用形態の上限は変更ごとのリスク区分で決まる(禁止事項8 `tailoring-guide.md:1058`、第5章 5.7)。出荷判定の側へ同じ軽量化を重ねる理由は無い
- **(d3) 組織の選択にする — 採らない**。1.7.3(`overview.md:358`)と、同じ型を退けた ADR-0065 決定4(`adr/0065…:62-64`)による
- **(d4) 決めずに暫定マークで残す — 採らない**。ADR-0088 `:192` の却下の理由が当たり続け、理由4 の開示の誤りも続く。決めない理由を本文から起草できない

## R-2 軸B の升の表記と軸C の上書き

### 推す案

### 理由(所在つき)

1. **升は「規則が定める結果」と宣言されている。** 1.7.3 は升の語を「テーラリングの規則が定める結果」とする(`overview.md:358`)。`:477` も「升は、テーラリングの規則が定める結果です」とする。結果と食い違う升は、この宣言に反する。現状、S0 の G-6・G-7 の升は品質「高」・規制業の構成で結果と食い違い(エンジンは G-6 `standard`、G-7 `strengthen`)、S1 の G-7 の升も同じく食い違う
2. **括弧の限定の既存の使い方と揃える。** 現在の括弧「(CL1 以上は適用)」は、緩和を軸E が取り消す場合を書いている。軸C による取り消しだけを本文の箇条(`:494`)へ置くのは、同じ種類の情報を2か所へ分ける書き方で、升だけを読む読み手(提案ツールの利用者、PROCESS-PROFILE.md を照らす監査者)が取りこぼす
3. **強化は升へ書かなくてよい。** 適用に足す調整は、軸C の表が全ステージについて既に書いている(`tailoring-guide.md:545`「+限定的な抜き取り確認」「+規制当局向けエビデンス、AI関与範囲の明記」)。軸B の升へ重ねると、S2 グロースの「適用」も含めて全升に同じ注記が要り、軸C の表との二重管理になる。取り消し(状態が変わる)と追加(状態は適用のまま、中身が足される)を分けて扱うのが、1.7.3 の語彙(状態は 適用・簡略・統合・省略・未達 の5語)と整合する。S2 安定運用の「適用(変更影響の確認を強化)」は軸B 自身の調整なので升に書く、という区別も保てる
4. **軸C による取り消しは、規則の上で「決定」になっていない。** スクラッチ実行の結果:
   - S0 × 品質「高」の G-6 は、`r-c-high` の `set coreReviewerCount`(`rules-quality.yaml:14-16`)が「優先度の高い設定要求が省略を取り消し(対象を復活)」として戻している。**取り消しは、コア機能の2名という別の目的の設定の副作用である**。この設定を外すと、S0 × 品質「高」の G-6 の省略が黙って戻る
   - S0 × 品質「高」・規制業の G-7 は `strengthen` が `omit` を上書きするが、**`omit` が無効化した判定者の方式(`approverMode`)が戻らない**(G-7 の `params` が空。S1 では `named-concurrent` 等が残る)。試しに `r-c-high`・`r-c-regulated` へ G-6・G-7 の `restore` を足すと、`approverMode` が戻ることを確かめた(スクラッチの写し。リポジトリは変えていない)
   - ADR-0088 は、CL2・CL3 の S0 の G-7 の復帰を「副作用ではなく、この規則による決定」とするために `restore` を足した(`adr/0088…:107-114`)。軸C の取り消しも同じ扱いにしなければ、升に書いた内容を規則が保証しない
5. **試験が品質「標準」だけを走査している。** `expectG7` の全升の試験は品質「標準」だけで(`scripts/test-tailoring-engine.mjs:366-367`。内部調査 4.2)、品質「高」・規制業の S0・S1 の G-6・G-7 は固定されていない。升に書く以上、試験で固定する

## R-3 「簡略」の語の全体の扱い

### 推す案

**工程ゲートの状態としての「簡略」に、1.7.3 で定義を置く。定義は「判定基準を外さず、判定の対象の成果物の形または分量を減らして適用する」。減らすものを括弧の限定に書き、その境界を本文に書く。括弧の限定の無い「簡略」を升に置かないことを規定し、規定の表現形式の検査で確かめる。判定基準の一部を外す調整は「簡略」と書かず、外す基準の行に適用範囲を書く。**

起草する文言(案。`overview.md:354-362` の 1.7.3 の表の後の箇条へ足す):

> - 工程ゲートの状態の「簡略」は、判定基準を外さずにゲートを適用し、判定の対象となる成果物の形または分量を減らす調整に限って使う。減らすものを括弧の限定に書き(例: 「簡略(1枚企画書)」)、減らさないものとの境界を本文に書く
> - 括弧の限定の無い「簡略」を、表の升に置かない
> - 判定基準の一部を外す調整を「簡略」と書かない。外す基準の行に、適用範囲を書く([適用範囲の書き方](/process-compass/community/scope-marking/))

- 知識ベースのスキーマの動詞 `simplify` の定義(`tool/knowledge-base-schema.md:65`「簡略化する」)を、同じ定義に改める
- 規定の表現形式の検査(`scripts/check-provisions.mjs` の検査3「表の升の語」、`:10`)に、規定の文書の表の升で「簡略」の後に括弧の限定が無いものを検出する項目を足す。検査の一覧の正本(`community/provision-forms.md`)にも行を足す
- G-1 の S0 の「簡略(1枚企画書)」と `tailoring-guide.md:479` の段落は、この定義をそのまま満たすので変えない

### 理由(所在つき)

1. **現行の定義は「適用の一種」までしか言っていない。** ADR-0028 は `simplified` を「簡略化して適用する」とし(`adr/0028…:31`)、1.7.3 は語彙を並べて意味を ADR-0028 へ委ねる(`overview.md:358`)。何を減らしてよく、何を減らしてはならないかの境界が無い。このため、定義の無いまま S1 の G-7 に置かれた「簡略」が、2026-07-15 の初版から少なくとも4か月残った(内部調査 1.4)。ADR-0088 の会議体でも5立場のうち4つが中身の無さを指摘しながら、語そのものには手当てが無かった(内部調査 3.2)。再発を防ぐには、語の側に定義と検査が要る
2. **「判定基準を外さない」を定義に入れると、既存の決定と整合する。** ADR-0028 の「適用する」の一種という位置づけ、`:479` の「前節の宣言を外すものではありません」、準拠テンプレートが `simplified` を `required` と同じに判定する実装(内部調査 4.3)の3つが、同じことを言っている。定義はこれを明文にするだけで、既存の構成の判定を変えない
3. **基準を外す調整には、既に別の書き方がある。** 適用範囲は見出しか行の中に書く(#226、`community/scope-marking.md`)。G-7 の基準7 は「(安全関連ソフトウェアのみ)」と行の中に限定を持つ(`gate-criteria.md:1221`)。基準を外す調整を「簡略」の名で升に置くと、適用範囲の台帳(`npm run scope:write`)に載らず、#226 の検査を迂回する。語を分ければ、外したものが台帳に出る
4. **外部の書き方と揃う。** 外部で「簡略」の包括語だけでゲートを緩める例は無く、緩めるときは要求事項ごとの適用の有無(IEC 62304、外部調査 S-01 原文確認)か、類型ごとのチェックリスト(S-04)を伴う(外部調査「考察」)。本定義の「基準は外さない、外すなら基準ごとに範囲を書く」は IEC 62304 の型に当たる
5. **要求事項2 の「簡略化した項目」に指すものが残る。** 第8章の要求事項2 は「標準から外した項目、簡略化した項目を、理由とともに宣言する」(`tailoring-guide.md:23`)。語を廃さず定義すれば、宣言の対象(G-1 の S0)が引き続き定まる

### 他の案を落とす理由

- **(i) 語を定義せず、G-7 だけを直す — 採らない**。理由1。同じ欠陥が別のゲートで再発しても、検出する手段が無い。初版から4か月残った事実が、目視の査読に頼れないことを示している
- **(ii) 「簡略」を語彙から廃し、G-1 の S0 も「適用(1枚企画書)」と書く — 採らない**。成果物の形を減らしたことが、保証の開示 項目2 と要求事項2 の宣言から消える。G-1 の S0 は実際に記述の分量を減らしており(`:479`)、その事実を読み手へ宣言する価値がある。「適用」と書くと、減らしたことが読み手に伝わらない。廃すると ADR-0028 の `simplified` と準拠テンプレートの値も同時に廃することになるが、廃して得る信頼性の利点が無い
- **(iii) 定義の無い「簡略」を今後置かない旨だけを書き、定義は置かない — 採らない**。禁止だけでは、括弧の限定に何を書けば足りるかが定まらない。「簡略(記録は残す)」のような、減らすものでなく残すものを書いた限定でも検査を通ってしまう。定義の「減らすものを書く」が要る
- **(iv) 簡略の中身を規則データの値(`param`・`value`)に持たせることを必須にする — 採らない(本件では)**。G-1 の S0 の「1枚企画書」は様式の形であり、構成の値として機械が使う先が無い。値を持たせても降ろし先が無い値になる。降ろし先が生じたときに改めて決める

### 条件・留保

- 検査の項目は、升の「簡略」の直後に「(」があるかだけを見る形にとどまる。括弧の中身が「減らすもの」を書いているかは機械では確かめられない。**機械が確かめるのは限定の有無まで**であり、中身の適否は条項の起草と査読に残る。この限界を検査の一覧に書く
- 様式の簡略化(ADR-0040。欄を落とし `omit` へ登録する)は、ゲートの状態とは別の文脈である。定義の文は「工程ゲートの状態の『簡略』」と主語を限り、様式の簡略化を巻き込まない
- `safety-verification.md:72, 74` の「簡略化された手順」は外部規格の語であり、検査の対象(表の升)に当たらない
