## 前置き: 外部の規格が「簡略」をどう書くか

外部調査の型を、本件に効く形に言い直します。

| 規格・実務 | 軽くする書き方 | 軽くしても残すもの | 所在 |
| --- | --- | --- | --- |
| ISO 9001:2015 8.6 | 「計画した取り決め(planned arrangements)」の中身を組織が計画で決める。満たさずに出すのは権限者(と顧客)の承認つきの例外 | 受入基準への適合の証拠、リリースを許可した人の追跡可能性(a・b) | 外部 S-03 【原文確認】(EAPO 掲載の対訳版。ISO の正本ではない) |
| ISO 9001:2015 A.5 | 規模・リスクで要求事項の適用を見直せる。ただし「製品・サービスの適合の達成に失敗しない場合に限り」適用外にできる | — | 外部 S-03 【原文確認】 |
| IEC 62304 1.4 | 適合 = 安全クラスに応じて、全プロセス・活動・タスクを実施。**クラスの割当は要求事項ごとに本文に書く**。「as appropriate」を実施しないときは理由を文書化 | 包括語は使わない | 外部 S-01 【原文確認】 |
| IEC 62304 5.8(クラス A) | 残存異常の評価・作り方の文書化・全活動の完了の確認が外れるとされる | 検証の完了の確認、既知の残存異常の文書化、リリースした版の文書化、保管 | 外部 S-02 【二次情報】(規格本文と Table A.1 は未確認) |
| ISO/IEC/IEEE 12207:2017 | 適合を full と tailored に分け、テーラリングを規範の附属書 A の手続とする | テーラリングの判断の文書化と根拠(【未確認】筆者の記憶) | 外部 S-05 |
| ISO/IEC 29110(VSE) | 最小規模の組織向けプロファイル | 引き渡しの受入記録に、受入基準の検証・未解決事項・署名の欄 | 外部 S-10(テンプレートの範囲での確認。Entry と Basic の差は未確認) |
| Google LCE | 低リスクの類型を**変更の性質**で定義し、その類型に短いチェックリストを当てる。各項目の重要性は過去の障害で裏づける | — | 外部 S-04 【原文確認】(抜粋) |
| Stage-Gate XPress・Lite | 段とゲートの統合、文書の軽量化。適用条件はプロジェクトのリスク区分 | — | 外部 S-07 【二次情報】 |
| 共通フレーム2007 | 取捨選択・統合。「妥当と判断した場合には省略してもよい」 | 判断の記録を求める記述はスライドに無い | 外部 S-06 【原文確認】 |

共通する結論は1つです。**どの規格も、中身を定義しない包括語でゲートを緩めていません**(外部 考察 :219-223)。緩めるときは、要求事項ごとに書くか(IEC 62304)、類型と短いリストを定義するか(Google LCE)、統合して利用者に文書化させるか(Stage-Gate・共通フレーム・12207)です。

## R-1 「簡略」の扱い

### 推す案

**案(b) 適用へ寄せる。あわせて内部 5.4 の (d1) を必須とする**。すなわち、CL0 × S1 の G-7 を「適用」とし、S1 のステージによる緩和がどこにあるかを本文に書く。

- 緩和の所在は次の3つ。どれも既に本文にある
  1. G-7 基準2 のトリアージの S1 の行(`gate-criteria.md:2060`「コア機能は出荷不可。非コアは既知の不具合として公開すれば可 / Sev2 記録し次サイクルで返却 / Sev3 記録のみ」)
  2. 負債台帳の S1 の運用「記録+返却目安」(`tailoring-guide.md:473`)
  3. G-6 の範囲「コア機能」(`tailoring-guide.md:469`、規則 `rules-business-phase.yaml:44-48`)
- 書く内容: 「S1 で出荷判定を軽くする調整は、ゲートの状態ではなく、判定基準の中のステージ別の値(基準2・3)と G-6 の範囲に置く。G-7 のゲートの状態では緩めない」。「書かれていない」ではなく「課さないと決めた」ことを読み手が区別できる形にする

### 理由

1. **ISO 9001 8.6 が求める最小の記録は、G-7 そのものである**(外部 S-03)。8.6 a)「受入基準への適合の証拠」は G-7 基準1(`gate-criteria.md:1215`)、8.6 b)「リリースを許可した人の追跡可能性」は G-7 の判定記録の記名(保証の主張 成立条件4、`gate-criteria.md:1404`)に当たる。S1 は限定した実利用者へ成果物が届く最初のステージ(`gate-criteria.md:2060`、`tailoring-guide.md:488` の前提2 を外れる)であり、8.6 の「顧客へのリリース」が初めて生じる。ここで G-7 を中身の分からない形にすると、8.6 の2つの記録が残るかを標準が保証できない
2. **IEC 62304 型(要求事項ごとの適用)は、本標準では既に基準の中で実現している**。62304 1.4 はクラスの割当を要求事項ごとに書く(外部 S-01)。本標準の G-7 は、基準2 がステージ別の行を持ち(`:2060`)、基準7 が「安全関連ソフトウェアのみ」の括弧で外れる(`:1221`)。要求事項ごとの適用の差は基準の中に書かれている。その上にゲート全体の「簡略」を重ねるのは、62304 が使わない包括語を足し、同じ緩和を二度掛ける形になる(内部 2.2 の要点)
3. **IEC 62304 のクラス A で外れるとされる「判定の深さ」は、本標準の G-7 では全ステージで既に外している**。62304 クラス A で外れるのは残存異常の評価・全活動の完了の確認とされる(外部 S-02、二次情報)。本標準の G-7 は「判定は記録と基準の突合に限定」(`gate-criteria.md:1475`)し、出荷判定者に数値の十分性を判定させない(`:1477` 以降)。軸C「標準」の G-7 の升も「記録突合」(`tailoring-guide.md:545`)である。つまり**本標準の G-7 の適用は、外部でいう最も軽いクラスの水準に既にある**。S1 の「簡略」で削る深さが残っていない
4. **12207 の tailored conformance と、本標準の第8章 要求事項3 を満たせない**。第8章は調整に「調整後の構成で、当該ゲートの目的が達成されることを示す」(`tailoring-guide.md:24`)を求める。12207 Annex A もテーラリングの判断の根拠を記録させる(外部 S-05。本文は【未確認】)。中身の無い「簡略」は、何を外したかが無いので、目的の達成を示す対象が無い。さらに、準拠テンプレートは `simplified` を `required` と同じに判定しながら保証の開示 項目2 に「簡略化」と出す(内部 4.4、`template/scripts/gate/aggregate-evidence.mjs:3280-3283`)。**宣言と実際が食い違うテーラリングの宣言は、tailored conformance の宣言として信頼できない**
5. **ISO/IEC 29110 の最小規模のプロファイルでも、引き渡しには受入基準の検証・未解決事項・署名が残る**(外部 S-10、テンプレートの範囲)。本標準の S1 の G-7 の基準1(検証)・基準2(既知の不具合の一覧、`:2065-2073`)・記名に当たる。規模を最小にしても外れない項目と、本標準の G-7 の中核は重なる
6. **先例と整合する**。ADR-0063 は旧 G-3 の S0 の簡略を適用へ寄せた(内部 3.3)。ADR-0088 `:192` は「定義の無い語で出荷判定を緩める」ことを CL1 以上で退けた。この理由は CL に依存しない(定義が無いことは CL0 でも同じ)
7. **S0 の省略の前提3 を支える**。前提3(`tailoring-guide.md:489`)は、S0 で確認を経なかった変更を S1 以降の出荷で記録の欠落として扱う。その席は G-7 基準5 である(ADR-0088 `:57`)。S1 の G-7 を適用と書けば、前提3 の所在が本文の上でも確定する

### 他の案を落とす理由

- **案(a) 基準ごとに中身を定義する — 採らない**
  - 内部 5.1 の整理では、実質の候補は基準4(運用引き継ぎ)の一部だけである。基準6(合否に使わない)・基準7(CL0 では既に適用外)を数えると、何も省かない調整を省いたと宣言することになる。ISO 9001 A.5 の「適合の達成に失敗しない場合に限り適用外」(外部 S-03)に照らすと、基準4 を外す判断には「S1 の実利用者への継続提供に失敗しない」根拠が要る。S1 のゴールは「継続提供できる技術基盤を確立する」(`lifecycle.md:58`)であり、障害時の連絡先と復旧手順を外す根拠は本文にも外部調査にも無い。**未実証**
  - Google LCE は、チェックリストの各項目の重要性を過去の障害で裏づけさせる(外部 S-04)。裏返すと、項目を外す側にも根拠が要る。外す根拠となる事例を、外部調査は1件も持たない(外部 :212)
  - IEC 62304 型を採るなら「要求事項ごとのクラス割当」になるが、その割当は既に基準2・7 の中にある(理由2)。基準4 だけを S1 で外すための別の割当を、外部の規格は示していない(62304 のクラス A でも、リリースの活動と記録は残るとされる。外部 S-02、二次情報)
  - PRINCE2 7 が最小要件の列挙を外したとされる件(外部 S-08、二次情報・食い違いあり)は、列挙が形骸化を生む反対論である。ただし原典未確認で、本件の採否の根拠には使わない
- **案(c) 省略へ寄せる — 採らない**
  - ISO 9001 8.6 b) のリリースの許可者の追跡可能性と衝突する(外部 考察 :230)。G-7 の記名が消えると、保証の主張の成立条件4(`gate-criteria.md:1404`)を CL0・S1 の全出荷が満たさなくなる
  - G-8 は技術品質を蒸し返さない(`gate-criteria.md:1506`)。SAFe も技術的な判定と事業的な判定を分ける(外部 S-09)。G-7 を省くと、トリアージの S1 の行(コア機能の Sev1 は出荷不可)を確かめる席が無くなる。Stage-Gate 型の「ゲートの統合」を G-7 と G-8 の間で行うことは、成立条件4(別の自然人の記名)と両立しない
  - S0 の省略の前提2(露出が社内と実験参加者に限られる)は S1 で成り立たない(内部 5.3)。前提を持たないまま省略を広げることになる
- **案(d) 簡略の条件を変更ごとのリスク区分(R)へ寄せる — 本件では採らない**
  - 外部 考察 :232 の指摘(Google は低リスクを変更の性質で決める)は正しい。しかし Google LCE の単位は「ローンチ」で、本標準の G-7 の単位は「出荷の範囲」(複数の変更の集まり)である。リスク区分は変更ごとに判定する(ADR-0039 `:58-59`)。出荷の範囲に R の異なる変更が混ざるとき、ゲートの状態を変更ごとの R で決める規則が定義できない
  - Google 型の「低リスクの類型に短いリスト」は、本標準では既に**変更の単位**で実現している。軸A の事後監査への切替(`tailoring-guide.md:289` 以降。R3 の委任の変更)と G-6 の範囲である。出荷の単位でさらに R で分ける必要を示す外部の根拠は無い
  - 出荷の単位で「低リスクの出荷」の類型を作る案は、Google の型に近い別の論点として成り立ちうる。ただし類型の定義(何をもって低リスクの出荷とするか)と、その類型で外す項目の根拠(Google のいう過去の障害)の両方が無い。**未実証**。#374 の範囲では採らず、採らない旨を ADR に書く。将来、出荷の類型ごとの事例が集まった時点で別 Issue として起こせる
- **(d3) 組織の選択にする — 採らない**。升は規則が定める結果であり、組織が選ぶ余地を示さない(`tailoring-guide.md:477`、`overview.md:358`)。ADR-0065 決定4 が同じ型を退けた。ISO 9001 8.6 の「計画した取り決め」は組織が中身を決めるが、それは基準の値(既定値の置き換え、第1章 1.7.7)の側で既に許している
- **(d4) 暫定マークで残す — 採らない**。ADR-0088 `:192` の却下理由が CL0 に当たり続ける。外部調査に、定義の無い包括語でゲートを緩める例が1件も無い(外部 :219)以上、残す理由が立たない

### 条件と留保

- **採る前に実行で確かめる**: 内部 6 の1(`simplified` と `required` で集約の出力が項目2 以外で同一か)。同一でなければ、案(b) は実際に判定を厳しくする変更であり、既存の CL0・S1 の採用者への影響の説明が変わる。同一なら、本件の変更は「判定は変えず、宣言を実際に合わせる」ものになる
- 内部 6 の4(試験の落ち方)。エンジンの試験 `:367` の期待値と `:424` の否定の対は作り直す(R-4)
- 外部の根拠の水準: ISO 9001 は対訳版、IEC 62304 5.8 のクラス別適用は二次情報、12207 Annex A の本文は未確認。**本案の採否はこれらに依存しない**(理由3・4・6・7 は本標準の内部の整合で立つ)。ただし ADR に外部の規格を引くときは、根拠の水準を書き分ける
- 「S1 の緩和は基準の中のステージ別の値で足りる」という判断は、S1 の採用者の手戻りやオーバーヘッドで実証されていない。**未実証**。EV の暫定マークで開示する(R-4)
- 基準4 の運用引き継ぎ文書の**分量**は、本標準が定めていない(未確認。基準は「完備(監視項目・障害時連絡先・復旧手順)」の3項目の有無だけを書く、`gate-criteria.md:1218`)。S1 の採用者が「適用」を重く読むなら、G-1 の S0(`tailoring-guide.md:479`)と同じく、分量はステージで求めない旨を書く余地がある。これは基準を外す調整ではないので、案(a) とは別に検討できる。本委員は、書くなら「記述の分量を定めない。3項目の欠落は欠落として数える」の形に限ると考える

## R-2 軸B の升の表記と軸C の上書き

### 事実の確認

- エンジンの実行で、CL0 の軸B の升と実際の状態は次のとおり食い違う(本委員が実行して確かめた)
  - S0 × 品質「高」・規制業: G-6 `standard`、G-7 `strengthen`。升は「省略(… CL1 以上は適用)」
  - S1 × 品質「高」・規制業: G-7 `strengthen`。升は「簡略(CL1 以上は適用)」
- S0 については、升の外の箇条(`tailoring-guide.md:494`)に「品質要求が『高』以上の構成では、軸C の調整が本軸の省略に優先し、G-6 と G-7 を適用する」とある。S1 には同じ記述が無い(内部 1.1)
- エンジンの試験の全升の走査(`scripts/test-tailoring-engine.mjs:359-404`)は品質「標準」だけで、品質「高」・規制業の S1 の G-7 を固定していない(内部 4.2)

### 推す案

**緩める升(軸B が省略・簡略・範囲の限定を置く升)には、それを取り消す他の軸の条件を升の中に書く。あわせて、表の後の段落(`:477`)に軸の間の優先の規則を1文で書き、試験の走査を品質の3種へ広げる**。

1. 升の中に書く(R-1 で案(b) を採る前提)
   - G-6 の S0: 「省略(確認者を置けない体制は未達。CL1 以上・品質『高』以上は適用)」
   - G-7 の S0: 「省略(CL1 以上・品質『高』以上は適用)」
   - G-7 の S1: 「適用」(案(b) により緩和が無くなるので、限定は要らない)
   - G-6 の S1: 「適用(コア機能。CL1 以上は全変更)」は変えない。品質「高」はコア機能の承認者を2名にする設定で、範囲の限定を取り消さない(エンジンの結果も `standard/core-only`)
2. `:477` の段落に足す1文: 「升は本軸の結果です。軸C・軸E の強化と取り消しは本軸の省略・範囲の限定に優先し、その結果は各軸の表によります」。規則の優先度(軸B 10、軸C 30、軸E 50。`rules-quality.yaml:3`)の言い換えであり、新しい規範ではない
3. `:494` の箇条の後半(品質「高」以上の優先)は、升へ移した内容と重複するので、所在を升へ一本化する。前半(CL1 以上で G-6 と G-7 を適用する理由)は理由として残す
4. エンジンの試験の全升の走査に品質「高」・規制業を加え、G-7 の `strengthen` と G-6 の状態を固定する。升の文と規則が別々に動いたときに検出できるようにする

### 理由

1. **限定は要求事項の隣に書く、という書き方は IEC 62304 の型と同じである**。62304 1.4 の注記は「各要求事項に割り当てた安全クラスは、その要求事項に続く規範の本文で示す」(外部 S-01【原文確認】)。本標準も、適用範囲の限定を規範と別の段落に置かず、表の行の中に書く規約を持つ(#226、`community/scope-marking.md` が正本)。S0 の升は CL1 の限定を升の中に、品質「高」の限定を升の外の箇条に置いており、同じ規約の中で書き方が割れている
2. **升だけを読む読み手が、実際と逆の構成を読み取る**。品質「高」の S1 の採用者は、升から「出荷判定は簡略」と読むが、構成は「強化」で出る。12207 の tailored conformance は、テーラリングの結果が文書で読めることを前提にしている(外部 S-05。4.3 の本文は【未確認】)。採用者が自分の構成を本文で照合できない状態は、適合の宣言の信頼性を下げる
3. **升の文と規則の一致を、機械で固定する**。第8章は「升は、テーラリングの規則が定める結果」と書く(`:477`)。この文が真であることを確かめる試験が品質「標準」にしか無い。升の文を直しても、試験が品質の3種を見なければ、次の改訂で同じ食い違いが再び生じる

### 他の案を落とす理由

- **升の外の段落か脚注だけで直す — 採らない**。S0 の現状と同じ形で、#226 の規約(限定を規範と別の段落に置かない)と当たる。読み手が升だけで判断する場面(附属書D の提案書、道具の出力の表)で、限定が落ちる
- **軸C の中身(抜き取り確認、規制当局向けエビデンス)まで軸B の升へ書く — 採らない**。軸C の表(`tailoring-guide.md:545`)と同じ内容を2か所に置くと、正本が2つになる。軸B の升に書くのは「本軸の緩和が効かない条件」までとし、強化の中身は軸C の表に任せる

## R-3 「簡略」の語の全体の扱い

### 推す案

**語を残し、ゲートの状態としての「簡略」を第1章 1.7.3 で定義する。定義に当たらない「簡略」を本標準が置かないことを、同じ箇所に書く**。

- 定義(案): 「簡略は、判定基準を外さずに、判定の材料となる成果物の形・分量を、升の括弧に示した形へ限る調整である。升は括弧の限定を持ち、本文に、外さないもの(判定の対象・宣言)を書いた段落を持つ」
- 境界: 「判定基準を外す調整は簡略と呼ばない。基準ごとに、適用の範囲(#226 の書式)か省略として書く。対象の範囲を限る調整は『適用(範囲)』と書く(G-6 の S1『適用(コア機能)』と同じ)」
- 不作為の明記: 「本標準は、括弧の限定と本文の段落を持たない『簡略』を置かない」
- R-1 で案(b) を採ると、ゲートの状態の「簡略」は G-1 の S0「簡略(1枚企画書)」だけになる。G-1 の S0 は、括弧の限定(`tailoring-guide.md:464`)と段落(`:479`「記述の分量を減らす調整であり、前節の宣言を外すものではありません」)を既に持ち、定義に当てはまる
- 別の文脈の「簡略化」と分ける
  - 様式の簡略化(ADR-0040): テンプレートの欄を落とし、`omit` へ理由付きで登録する。ゲートの状態ではない
  - `safety-verification.md:72, 74` の「簡略化された手順」: 外部の安全規格の語。本標準の調整語ではない
  - 1.7.3 の定義の文に「ゲートの状態として」の限定を置き、この2つを含めない
- 規則データの側: `simplify` の注記(`rules-business-phase.yaml`)が、本文の升と段落の所在を指すことを求める。機械で確かめるなら、`simplify` を持つ規則の対象ゲートについて、第8章の升に括弧の限定があることを検査する(実装の可否は R-4 の IMPL で扱う)

### 理由

1. **包括語で緩めない、という外部の規格の共通点に合わせる**。IEC 62304 は適用の差を要求事項ごとに書き、包括語を使わない(外部 S-01)。Google LCE は類型と短いチェックリストを定義する(外部 S-04)。Stage-Gate の縮約は「統合」と「文書の軽量化」で、基準ごとの取捨を包括語で行わない(外部 S-07、二次情報)。本標準の「簡略」を「成果物の形・分量を限る」に限れば、外部でいう「文書の軽量化」に当たり、外部の型の1つと対応がつく。判定基準を外す調整を「簡略」と呼ぶ型は、外部に見当たらない(外部 :219)
2. **ADR-0028 の定義「簡略化して適用する」と矛盾しない**(`adr/0028-unmet-gate-distinct-from-omitted.md:31`)。ADR-0028 は `simplified` を適用の一種と定義した。本案の定義は、その「適用の一種」が何を変えてよいか(成果物の形・分量)と、何を変えてはならないか(判定基準)を足す。ADR-0028 を置き換えず、補う
3. **テーラリングの禁止事項3「差し戻し基準のないゲートを作る」(`tailoring-guide.md:1053`)と同じ筋である**。中身の無い簡略のゲートは、どの基準で差し戻すかを読み手が決められない。318 の会議体の品質保証の委員も「定義してから選ぶ順序でなければ、判定の記録が何を確かめたかを読めない」とした(内部 3.2)
4. **12207 と第8章 要求事項2・3 の宣言の信頼性**。テーラリングの宣言(保証の開示 項目2)に「簡略化」が載るとき、読み手はそれを「何かを外した」と読む(内部 4.4)。定義があれば、宣言の「簡略化」は「成果物の形を限った。判定基準は外していない」と一意に読める
5. **不作為を明記する理由**。コアポリシーは「書かれていない」と「課さないと決めた」の区別を求める。G-7 の S1 の簡略は 2026-07-15 の初版から定義されないまま残った(内部 1.4)。同じことを繰り返さない歯止めを本文に置く

### 他の案を落とす理由

- **語を廃止し、G-1 の S0 も「適用(1枚企画書)」と書く — 採らない**。G-1 の S0 は、成果物の形を実際に変える(1枚企画書)。採用者の構成と保証の開示 項目2 に、それが調整として出ることには、読み手への情報の価値がある(第8章 要求事項2「簡略化した項目を理由とともに宣言する」、`tailoring-guide.md:23`)。廃止すると、要求事項2 の「簡略化した項目」が空の概念になり、要求事項2 自体を改める必要が生じる。廃止で信頼性が上がる根拠は無い
- **語を定義せず、G-7 の S1 だけを直す — 採らない**。定義が無い限り、次の改訂で同じ形の升が足せる。歯止めが無い
- **定義を「判定基準を外してよい」まで広げる(基準ごとの簡略を許す) — 採らない**。基準を外す調整は、62304 型の要求事項ごとの適用(#226 の適用範囲の書式)か省略で書ける。それを「簡略」の名でまとめると、読み手は升だけでどの基準が外れたかを読めない。また ISO 9001 A.5 の「適合の達成に失敗しない場合に限り適用外」の根拠を、基準ごとに書く席が無くなる
- **テーラリングの禁止事項に10番目として足す — 採らない**。禁止事項は、採用者が調整で外してはならないもの(`:1049`)である。定義の無い簡略を置かないのは、本標準の書き方の規律であり、採用者への禁止ではない。採用者は升を選べない(`:477`)ので、採用者への禁止にしても意味を持たない。置き場は語彙の定義(1.7.3)が適切である

### 条件と留保

- 1.7.3 の表は「升が示すもの」の語彙で、各語の意味を ADR-0028 へ委ねている(内部 1.2)。定義を 1.7.3 の表の外の段落に置くか、ADR-0028 を補う新しい ADR に置くかは起案に委ねる。本委員は、**本文(1.7.3)に定義を置き、ADR に経緯と採らない案を置く**形を推す。規格の読み手は ADR を読まない前提で書くべきである
- 道具の頁(`tool/knowledge-base-schema.md:65` の動詞 `simplify` =「簡略化する」、例「企画承認を1枚企画書に」)の定義を、同じ定義へそろえる。`:68` と `tool/proposal-logic.md:51` の例「MVP の簡略化を取り消す」は、案(b) の後は実在しない例になるので直す
- 定義の「成果物の形・分量を限る」が G-1 の S0 以外にも当てはまる将来の升を、本委員は想定していない。将来足すときは、本案の定義に照らして会議体を開く
