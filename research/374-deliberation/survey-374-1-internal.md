### 1.3 他のゲート・ステージでの「簡略」の定義の形

本文で中身を持つ「簡略」は、過去を含めて2例だけである。

| 例 | 形 | 現在 |
| --- | --- | --- |
| G-1 の S0「簡略(1枚企画書)」 | 升の括弧の限定で**成果物の形**を示し、本文の段落で「分量を減らす。宣言(判定の対象)は外さない。様式を足さない」と境界を書く。判定基準の番号は名指さない | 有効 |
| G-3 の S0「主要な選択のみ」 | 升の限定で**判定の対象の範囲**を示す | ADR-0063 で「適用」へ寄せて消えた。ADR-0034 は「簡略化された G-3 に確定を要求すると簡略化の意味が失われる」と、簡略を理由に別案を退けていた。ADR-0071 がその前提の消失を記録した |

- どちらも、**判定基準の番号ごとに省く・残すを定める形ではない**。限定は「成果物の形」か「対象の範囲」である
- G-6 の S1「適用(コア機能)」は「簡略」の語を使わず、**範囲の限定**として書く(`set scope: core-only`)。ADR-0088 決定4 は G-6 の範囲の限定と G-7 の簡略を同じ「緩和」に並べた(`:845`)
- 様式の簡略化(ADR-0040)は「欄を落とし、落とした欄を理由付きで登録する」形で、登録そのものが判定の記録になる。ゲートの状態の簡略には、この登録の仕組みが無い

### 1.4 由来

- `git log -S` で辿ると、G-7 の S1「簡略化」は最初の版(`7fc58a2`、2026-07-15)の軸B の表から存在する(当時の升は「省略可 / 簡略化 / 標準 / 厳格」)
- 同じ版の G-7 の判定基準は5項目(消化率・**未解決の重大欠陥 0 件**・負債台帳・運用引き継ぎ・全ゲートの通過記録)だった(`4c64709` の `gate-criteria.md:81-89`)。当時は基準2 がステージに依らず「0 件」で、S1 で緩める余地が基準の外にあった
- 規則の注記「出荷判定は簡略化する(記録は残す)」は M7 の知識ベース化(`dd5c737`、2026-07-23、#59)で入った。「(記録は残す)」は、同じ版の軸A の「価値責任者が兼ねる(ただし記録は残す)」と同じ言い回しである
- その後、基準2 は「事業ステージ別の欠陥トリアージ基準を満たす」へ変わり、S1 の行を持つようになった(2.2)。**ステージによる緩和の一部は、基準の中へ移った**。升の「簡略」は、その移動の後も残っている

## 2. G-7 の判定基準の全数と、CL0 の S1 での意味

### 4.4 結論: 実装上の「簡略」は何か

- **判定の中身は「適用」と同じ**である。集約が数える欠落、成立条件4 の判定、スキルの手順、様式、`/pit` の次の一手のどれも、`simplified` と `required` を区別しない
- 違いは次の3つだけで、どれも**表示と順位**である
  1. 保証の開示 項目2(テーラリングの宣言)と PROCESS-PROFILE.md に「簡略化」と出る。外の読み手には「出荷判定を緩めた」と読める
  2. 変化点の向きの順位(simplified → required は厳しくする向き)
  3. 規則の注記「記録は残す」が PROCESS-PROFILE.md の理由に出る
- つまり現状は、**標準の本文には中身が無く、実装は適用として動き、外への宣言は簡略と言っている**。宣言と実際の判定が食い違っている。附属書H の C7(開示: 実施しなかったことが通過と区別して残っている)の逆向き、すなわち「実施したことを実施しなかったかのように開示する」状態である

- 試験: エンジンの試験(`:367`)は状態の文字列だけなので変わらない。テンプレートの試験に、外す基準の対(違反と適合)を足す
- ADR: ADR-0088 `:192` の理由「定義の無い語で出荷判定を緩める」は、定義すれば当たらなくなる。ただし、定義した中身が実質の緩和を持つか(基準6・7 だけなら持たない)を会議体で問う必要がある

### 5.2 案(b) 適用へ寄せる

- 本文: 軸B の升を「適用」へ。`(CL1 以上は適用)` の限定は不要になる。IMPL-0345 の注記(`tailoring-guide.md:498`)の「S1 の G-7 の簡略」を直す。軸E `:845` の「緩和(省略・簡略・範囲の限定)」は一般の列挙として残せる
- 規則データ: `r-b-mvp` から `g-ship` の `simplify` を外す(`rules-business-phase.yaml:49-51`)。`r-e-cl1` の `restore`(`rules-criticality.yaml:34-36`)は S0 の省略の取り消しとして引き続き要る
- 道具の頁: `tool/knowledge-base-schema.md:68` と `tool/proposal-logic.md:51` の例「MVP の簡略化を取り消す」が古くなる

### 5.3 案(c) 省略へ寄せる

- S0 の省略の前提2(露出が社内と実験参加者に限られる)は、S1 では成り立たない(2.1)。**S0 の省略を支えた前提を持たないまま、同じ省略を S1 へ広げる**ことになる。ADR-0065 決定1 の前提の型を S1 に当てると、前提2 が破れている
- S0 の省略の前提3 は「S1 以降の出荷で、S0 の期間の未確認の変更を記録の欠落として扱う」。S1 の G-7 が省略なら、欠落を差し戻す席が S2 まで無い。前提3 の所在(ADR-0065 `:46`「第4章 G-6・G-7」)が空になる

- 保証の主張の成立条件4 を、CL0・S1 の出荷はすべて満たさなくなる(品質保証の対象外として出荷。`gate-criteria.md:1411-1412`)

- テンプレート: 集約は `omitted` のとき引き継ぎ文書・負債台帳・判定記録の有無を数えない(`aggregate-evidence.mjs:2716`)。`/pit` は G-7 を飛ばして G-8 待ちへ進む(`scripts/regress/suite/stages.mjs:188`)。既存の CL0・S1 の構成にとっては**緩める向き**で、ADR-0055 決定5 と ADR-0088 決定7 により告知と採用者の記名が要る
- 試験: `expectG7` の `mvp: 'omit'`。テンプレートの回帰の場面の期待値が変わる
- 段階の単調性は保たれる(S0 省略 → S1 省略 → S2 適用)

## 6. 実行で確かめるべき点

読むだけでは確かめきれなかった点と、案を選ぶ前に実行で固めるべき点。

1. **simplified と required で、集約の出力が項目2 以外で同一か**。CL0・S1・品質「標準」で初期化した構成を2つ作り(`gates.g7.state` だけを変える)、同じ履歴で `aggregate-evidence.mjs` を実行して `evidence/evidence.json` と `quality-report.md` を比べる。4.4 の「判定の中身は適用と同じ」を、コードの読みから実行の事実へ上げる
2. **S0 由来の未確認の変更が、S1 の出荷で欠落として差し戻されるか**(S0 の前提3)。S0 で G-6 を省略して取り込んだ変更を、S1 へ移した後の出荷の範囲に含め、`g7: simplified` の構成で集約が欠落に数えるかを確かめる。案(c) の影響の大きさを測る
3. **S1 の G-6「コア機能」の範囲を集約が読むか**。`aggregate-evidence.mjs` は `gates.g6.params.scope` を読む箇所が見当たらない(`g6Applied` は状態だけで決まる。`:1328, :2219-2221`)。非コアの変更で独立した人の承認が無いものを、S1 の G-7 の基準5 が欠落に数えるなら、**実装は本文より厳しい**(本文の G-6 はコア機能だけ)。案(a3)・(d2) の前提であり、本件の外でも食い違いの候補になる
4. **案(b) の規則の変更で、どの試験が落ちるか**。スクラッチの写しで `r-b-mvp` から `g-ship` の `simplify` を外し、`node scripts/test-tailoring-engine.mjs` を実行する。予想は `:367` と `:424`。テンプレートの `test-roster-rules.mjs` と回帰(`npm run test:regress`)も同様に確かめる
5. **既存の CL0・S1 の構成への出方**。案(b) なら `pendingTightenings` が `blocking: false` の「未適用の厳格化」を出し、`/process-change` の種別 settings の空の入力で再導出できるか。案(c) なら、緩める向きの差分として取り込みで値を変えずに表示するか(ADR-0088 決定7)
6. **品質「高」・規制業の S1 の G-7**。エンジンは `strengthen`(4.2)。テンプレートの構成でも `required` になり、PROCESS-PROFILE.md の理由に軸C の注記が出るかを確かめる。軸B の升との食い違い(5.4 の d5)を、案に依らず直すかの材料
7. **S0 の G-8 基準1 の扱い**。G-7 を省略した S0 で、G-8 基準1「G-7 を通過している」を準拠テンプレートがどう読むか(`next.mjs` は G-7 が無い構成で G-8 待ちへ進む)。案(c) を採るなら S1 にも同じ読み方が広がる
8. **外部の実務の照合(内部調査の外)**。S1 相当(限定した実利用者への提供)で出荷判定のどの要素を軽くするのが業界の実務か。とくに基準4(運用引き継ぎ)の一部を外す実務があるか。案(a) の唯一の実質の候補なので、外部調査の結果で採否が決まる
