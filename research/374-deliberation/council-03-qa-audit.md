## R-1 「簡略」の扱い

### 推す案: (b) 適用へ寄せる。あわせて (d1) S1 の緩和の所在を本文に書く

CL0 × S1 × 品質「標準」の G-7 を「適用」とし、S1 のステージによる緩和は「G-7 の基準の中(基準2 のトリアージの S1 の行、基準3 の負債台帳の S1 の運用)と G-6 の範囲(コア機能)にあり、G-7 のゲートの状態では緩めない」と第8章に明記する。

### 理由(監査の立場から)

1. **外への宣言と実際の判定が食い違っている。これは監査で最も重い種類の不一致である**
   - 実装は `simplified` を `required` と同じに判定する。集約は `g7.state !== 'omitted'` で引き継ぎ文書・負債台帳・判定記録の欠落を数える(`template/scripts/gate/aggregate-evidence.mjs:2716-2727`、自分で確認)。成立条件4 も `isActive` で同一視する(内部 4.3、`:4313`)
   - 一方、保証の開示 項目2 には `simplified` を「簡略化」と載せる(`aggregate-evidence.mjs:3279-3282`、自分で確認)。顧客・監査人は「出荷判定を緩めた」と読む
   - 附属書H の C7(`assurance-case.md:214`)は「実施しなかったことが、通過と区別して残っている」を求める。現状はその逆向きで、**実施した判定を、緩めたかのように開示している**。逆向きでも、開示が実態を表さない点で C7 の趣旨(開示から実態を読める)を満たさない。保守的に外れる向きなので害は小さく見えるが、監査人は「どの基準を緩めたのか」を開示から特定できず、記録の追加の請求か、開示全体の信用の割り引きに至る
2. **「簡略」の中身が無いので、判定記録から「何を確かめたか」が読めない**
   - ADR-0028 は `simplified` を「簡略化して適用する」とだけ定める(`adr/0028…:31`)。何を落とすかは定義しない。318 の会議体の品質保証の委員も「定義してから選ぶ順序でなければ、判定の記録が何を確かめたかを読めない」と記録した(内部 3.2)
   - 第8章 要求事項2(`tailoring-guide.md:23`)は「簡略化した項目を、理由とともに宣言する」を求める。中身の無い簡略は、宣言の対象(何を簡略化したか)そのものを特定できないため、**標準自身の要求事項2 を採用者が満たせない**。採用者は「G-7 簡略化」と書くしかなく、理由の欄には規則の注記「記録は残す」しか出ない
3. **出荷の許可者の追跡可能性(ISO 9001 8.6 b))は、G-7 の記名でしか立たない**
   - 外部 S-03(【原文確認】)は、どの規模でも、受入基準への適合の証拠とリリースを許可した人の追跡可能性を記録に求める。本標準でこれに当たるのは G-7 の判定記録と基準1、成立条件4 の記名(`gate-criteria.md:1404`)である
   - 適用へ寄せれば、この2つが既に実装どおりに残っていることを、開示の上でも言える
4. **基準ごとの整理から、緩める余地は基準の外にほとんど無い**(内部 2.2・5.1)。基準7 は CL0 で既に外れ、基準6 は合否に使わず、基準2・3 は S1 の緩和を基準の中に持つ。残る基準は ISO 9001 8.6・IEC 62304 クラス A(二次情報)でも残る種類の記録である
5. **先例**: ADR-0063 が旧 G-3 の S0 の簡略を適用へ寄せた(内部 3.3)。ADR-0088 は「定義の無い語で出荷判定を緩める」を理由に CL1 以上から簡略を外した(`adr/0088…:192`)。その理由は CL に依らず CL0 にも当たる
6. **既存の構成への出方は厳しくする向き**であり、ADR-0055 決定5 により記名を待たずに再導出で適用できる。テンプレートは「未適用の厳格化」として表示し、欠落には数えない(内部 4.3、`test-roster-rules.mjs:532-536`)。移行の途中で、開示が実態より緩い状態は生じない

### 他の案を落とす理由

- **(a) 基準ごとに中身を定義する — 採らない**
  - 実質の候補は基準4(運用引き継ぎ)の一部だけである(内部 5.1)。S1 は限定した実利用者へ出す最初のステージで(`gate-criteria.md:2060`、内部 2.1)、障害時連絡先・復旧手順を欠いて出す理由が本文にも外部調査にも無い。外部調査は基準4 の一部を外す実務を見つけていない(外部「埋められなかった穴」)
  - 基準6・7 を中身に数えると、何も緩めていない調整を緩めたと宣言することになり、R-1 理由1 の不一致を固定化する。監査上は現状より悪い(宣言に根拠の無い中身が付く)
  - 基準ごとに外す形は、集約・スキル・様式に `simplified` 専用の分岐を足す。分岐が降りるまでの間、開示と判定がさらに食い違う(IMPL の `undelivered` 期間)
  - 未実証: 基準4 の一部を外して信頼性が保たれるという前提に実証は無い
- **(c) 省略へ寄せる — 採らない**
  - CL0・S1 の全出荷が成立条件4 を満たさず「品質保証の対象外」になる(内部 2.3)。限定とはいえ外部の利用者へ出す段階で、許可者の追跡可能性の席が G-8 だけになる。G-8 は技術品質を蒸し返さない(`gate-criteria.md:1506`)ので、受入基準への適合の証拠を突合する人がいなくなる。ISO 9001 8.6 a)・b) と衝突する(外部 考察)
  - S0 の省略の前提3(`tailoring-guide.md:489`)は、S1 以降の出荷で S0 の未確認の変更を欠落として差し戻すことを前提にする。差し戻す席は G-7 である(ADR-0088 `:57`)。S1 で省けば前提3 が S2 まで空になり、EV-0101 の S0 の省略の根拠が崩れる
  - 既存の構成にとって緩める向きで、記名が要る(ADR-0055 決定5)
- **(d) 簡略の条件を変更ごとのリスク区分(R)へ寄せる — 本件では採らない**
  - G-7 は出荷ごとの判定であり、変更ごとの R で G-7 の状態を変えると、1つの出荷の中に区分の違う変更が混ざったとき、判定記録が何を確かめたかがさらに読めなくなる
  - 変更の性質で低リスクを決める型(外部 S-04、Google LCE)は、本標準では既に G-6・G-5 の側(リスク区分ごとの確定の形態)にある。保証の開示 項目3 が区分ごとの件数を出す(`gate-criteria.md` 保証の開示 項目3)。G-7 の状態を R に結ぶ根拠は、外部調査にも無い
  - 「課さないと決めた」と明記し、変更の性質による出荷判定の軽量化を将来扱うなら、別 Issue で調査からやり直す
- **(d3) 組織の選択にする — 採らない**。升は規則が定める結果で組織の選択でない(`tailoring-guide.md:477`、1.7.3)。ADR-0065 決定4 が同型を退けた。監査上も、組織ごとに意味の違う「簡略」が開示に並ぶ
- **(d4) 決めずに暫定マークで残す — 採らない**。宣言と判定の食い違いが続く。ADR-0088 の却下理由が CL0 に当たり続ける

### 条件・留保

- 内部 6 の1(`simplified` と `required` で集約の出力が項目2 以外で同一か)を**実行で確かめてから**採る。コードの読みでは同一だが、実行の事実でない(未実証)。異なる出力が見つかれば、その差が「簡略」の実際の中身であり、それを開示しているかを先に調べる
- (d1) の段落で「S1 の緩和は基準の中にある」と書くとき、基準3・4 の機械の確認は `undelivered`(IMPL-0042・0043、`gate-criteria.md` 基準表の直後)である。**機械が有無しか見ないことを、緩和と混同しない**。降りていないことは降りていないとして表示し続ける
- Lightweight の懸念(外部 S-04、共通フレームの「小規模で冗長」)には、ゲートの状態でなく、G-7 の判定が「記録と基準の突合に限る」(内部 2.2、`:1475`)ことで既に応えている、と本文の段落で示す。示せないなら懸念は残ると明記する

## R-2 軸B の升の表記と軸C の上書き

### 推す案: 升ごとの部分的な括弧をやめずに、表の直下へ「軸の優先」の規定を1つ置き、全升に掛かることを書く。エンジンの試験の全升の走査に品質の軸を加える

- 表の直下の段落(`tailoring-guide.md:477` の後)に、次の趣旨を書く
  - 升は軸B だけの結果である。同じゲートに軸C・軸E が掛かるとき、軸E(安全重要度)の取り消し・強化、軸C(品質「高」以上・規制業)の強化が軸B の省略・簡略・範囲の限定に優先する。どの事業ステージでも同じ
  - 構成の最終の状態は、PROCESS-PROFILE.md と保証の開示 項目2 に出る導出の結果が正である
- 現在の升の括弧「(CL1 以上は適用)」は、ADR-0088 決定4 の決定を表す規範なので残す。ただし括弧が軸E だけを書き、軸C を書かない理由を、上の段落で読めるようにする
- S0 の前提の箇条(`:494`)の「品質要求が『高』以上の構成では…G-6 と G-7 を適用する」は、エンジンの出力(軸C の `strengthen`)と語が合わない。「適用し、軸C の強化を加える」の形に揃える(R-1 で (b) を採れば S1 の升は「適用」になるので、S1 にも同じ規定が掛かることを上の段落1つで示す)
- 試験: `scripts/test-tailoring-engine.mjs:359-404` の全升の走査は品質「標準」だけである(内部 4.2)。品質「高」・規制業 × S0〜S2 × CL0〜CL3 の G-6・G-7 を固定する走査を足す。IMPL-0345 の注記(`tailoring-guide.md:498`)は「全升で固定」と書くが、実際は品質の軸を走査していない。**注記の「全升」と試験の範囲の食い違いは、実装マークの記載が実態より広い状態**であり、監査上は R-1 と同じ種類の不一致である

### 理由

1. **表から最終の状態を読めない構成が、どの読み手にも生じている**。品質「高」・規制業の S1 で、升は「簡略」、エンジンは「強化」(内部 4.2、実行で確認済み)。監査人が第8章の表と採用者の構成を突き合わせると、構成が「標準から外れている」ように見える。正しい構成が誤って見える表は、内部監査の観点2(宣言に無い省略・逸脱の検出)の誤検出を生む
2. 升の括弧に軸C の上書きを1升ずつ足すと、S0・S1 の G-6・G-7 の4升、S2 の各升で同じ文が繰り返され、どれかを落とす余地が残る。**部分的な列挙は、列挙が全部だと読ませる**。今回の不備自体がその型(軸E は書き、軸C は書かない)である。全升に掛かる規定は1か所に置き、全升を走査する試験で固定する方が、記載の漏れを機械が検出できる
3. 優先度(軸E 50、軸C 30、軸B 10)はエンジンと規則データ(内部 4.1)にしか無い。標準の本文に優先の規定が無いと、採用者が規則データを読まずに結果を説明できない。#226 の書式(節全体に掛かる適用範囲は見出しへ併記)に照らしても、軸の間の優先は本文に置くべき規範である

### 他の案を落とす理由

- **升ごとに軸C の上書きを書き足す — 採らない**(理由2)。表の可読性も下がる
- **何もしない(エンジンの結果が正なので表は目安とする) — 採らない**。`tailoring-guide.md:477` は「升は規則が定める結果」と言い切っている。目安と読ませる文言は無く、表が誤りになる
- **表を全軸の掛け合わせの結果表に置き換える — 本件では採らない**。行と列が爆発し、知識ベースの出力(PROCESS-PROFILE.md)と二重の正本になる。最終の状態の正本は導出の出力に一本化する

### 条件・留保

- 「軸の優先」の段落は、軸A(体制)の `set approverMode` のように構造操作でない設定が上書きされない(`tailoring-engine.mjs:152` で無効化は `omit` だけ。内部 4.2)点も、誤読されないよう書き分ける。設定と状態の区別を書かないと、「軸C が勝つと判定者の方式も変わる」と読まれうる
- 段落の新設は規範の追加なので、`lint:provisions`・`lint:scope` の対象になるかを突合で確かめる

## R-3 「簡略」の語の全体の扱い

### 推す案: 語の定義を置く。定義は「中身を升の括弧の限定と本文の段落で示した調整に限る」とし、中身の無い「簡略」を置かない旨を規範として書く

- 置き場: 第1章 1.7.3 の工程ゲートの状態の語彙(`overview.md:358`、内部 1.2)。ADR-0028 の `simplified`「簡略化して適用する」は書き換えず(採用済み ADR)、新 ADR で次を足す
  1. 「簡略」は**適用の一種**であり、判定記録を作り、判定者が記名する。判定記録と保証の主張の扱いは「適用」と同じ
  2. 「簡略」の升は、**何を減らすかを升の括弧と本文の段落で示す**。示す対象は、成果物の形(G-1 の S0「1枚企画書」)か判定の対象の範囲に限る。判定基準を外す形は「簡略」と呼ばない(外すなら、基準ごとの適用範囲として #226 の書式で基準の行に書く)
  3. 中身を示せない調整を「簡略」の升に置かない。規則データの `simplify` は、本文に中身の段落を持つ升にだけ使う
- 機械の検査の候補: 規則データの `action: simplify` を持つ規則ごとに、本文の該当の升に括弧の限定があるかを確かめる(`lint:refs` か新しい検査)。降りるまでは IMPL を `undelivered` で表示する

### 理由

1. 外部の規格・実務に、包括語だけでゲートを緩める例は無い(外部 考察。IEC 62304 は要求ごとにクラスを示し【原文確認】、ISO 9001 は計画した取り決めと最小の記録を求める【原文確認】)。語の定義を置かなければ、同じ不備が他のゲート・ステージで再発する。#374 自体が、2026-07-15 の初版から定義されないまま約4か月残った語である(内部 1.4)
2. 第8章 要求事項2(`tailoring-guide.md:23`)は「簡略化した項目を、理由とともに宣言する」を求める。採用者が宣言できるのは、何を簡略化したかが標準に書かれている場合だけである。**語の定義は、要求事項2 を満たせる状態の前提**である
3. 「適用の一種」と明記すると、保証の開示 項目2 で「簡略化」と出ても、成立条件3・4 の判定が適用と同じであることを読み手が導ける(R-4 の開示の書き方と対になる)
4. 様式の簡略化(ADR-0040)と語が同じで、意味が違う(欄を落とし `omit` へ登録する)。区別を書かないと、監査人が「G-1 の簡略化」と「様式の簡略化」を同じ手続と誤読する

### 他の案を落とす理由

- **語を廃止し、G-1 の S0 も「適用(1枚企画書)」と書く — 採らない(ただし有力な対案として記録する)**。中身のある唯一の例(`tailoring-guide.md:479`)は分量を減らす調整であり、宣言の対象にするのが要求事項2 に合う。「適用(1枚企画書)」にすると、外した・減らした事実が項目2 から消え、C7(開示)の側に倒れる。語を残し、中身を必須にする方が開示の情報量が多い
- **定義を置かず、「今後置かない」とだけ書く — 採らない**。何が「中身のある簡略」かの基準が無いと、G-1 の S0 が要件を満たすかを判定できない
- **基準ごとの省略を「簡略」に含める — 採らない**。基準ごとの適用範囲は #226 の書式と範囲の台帳で既に扱える。同じことを2つの語で書く形は、台帳から漏れる

### 条件・留保

- 定義の新設は語彙の条項の改定なので、知識ベースのスキーマ(`tool/knowledge-base-schema.md:65` の `simplify` の定義)と道具の頁(`tool/proposal-output.md:52` の3分類)を同じ変更で揃える
- 「判定の対象の範囲」を限定の形に含めると、G-6 の「適用(コア機能)」(範囲の限定)との境界が曖昧になる。範囲の限定は `set scope` で値を持つ別の操作として残し、「簡略」に含めない書き方を突合で確かめる

## R-4 記録・開示・ADR

### 推す案(項目ごと)

1. **保証の開示 項目2 の「簡略化」の表示**
   - R-1 で (b) を採れば、CL0・S1 の G-7 の行は項目2 から消え、宣言と判定の食い違いが解ける
   - 残る「簡略化」(G-1 の S0)は、状態の語だけでなく**升の括弧の限定(何を減らしたか)を項目2 に出す**(例: 「簡略化(1枚企画書)」)。現状の `aggregate-evidence.mjs:3279-3282` は状態の語と `why` だけを出す。R-3 の定義(中身を升で示す)と対にし、開示から何を減らしたかを読めるようにする
   - 移行の間: 旧い構成(`g7: simplified` のまま再導出していない構成)の出荷では、項目2 に「簡略化」が出続ける。**未適用の厳格化(`pendingTightenings`)があることを項目2 の同じ行に併記する**。併記が無いと、開示は「緩めた」と言い、判定は適用、標準は適用、の三者がずれる。欠落には数えない(厳しくする向き。ADR-0055 決定5、`test-roster-rules.mjs:532-536` の型)
2. **テンプレートの変化点の順位(`GATE_RANK`、`generate-profile.mjs:1290`)**
