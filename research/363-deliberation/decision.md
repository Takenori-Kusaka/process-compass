# 議長の裁定(#363 python アダプタの前提と、複数のスタックを持つリポジトリ)

- 審議の重さ: 欠陥①②と python の形の不一致は**軽**(既存の規定への回帰の修正。実装は並行して進行中)。欠陥③(混在のリポジトリ)は**重**(軽の2委員がともに、新しい義務と ADR-0085 決定2 の理由の変更に当たるとした)
- 入力: `survey-363.md`・`survey-363-2-external.md`、軽の `council-01/02`、重の `council-11`〜`15`(起案・現場・品質監査・規格・弁護)
- Issue の参照の訂正: Issue 本文の ADR-0084 は ADR-0085。#360 本文の IMPL-0253 は IMPL-0259

## 0. 骨格

5 委員とも欠陥③を認めた(弁護を含む)。ADR-0085 決定2 の理由(88 行)は、混在のリポジトリでは成り立たない。外部: GitHub は if: で飛ばしたジョブを Success と報告し、Scorecard・SLSA も言語の網羅を見ない。塞げるのは利用者側のプロセスだけ。規格は「すべてを試験せよ」とは求めないが、無言で省くことも認めず、範囲の識別と宣言を求める(29119-2 4.1.1)。Bazel・alls-green の型は「既定は全部、除外は宣言」。

## R-1 正本の方式 — 裁定: 結果で要求し、準拠テンプレートは (c1) で実装する

- 標準(G-5)には、道具に依らない要求を置く(起案・規格)
  1. G-5 の基準1・2・3・5 の対象は、製品のすべてのスタック
  2. 宣言していないスタックの目印がある PR は、G-5 を通さない(除外を除く)
- 準拠テンプレート: 2段で降ろす(起案・弁護)
  - 第1段: PR ごとの契約検査で、製品の目印のスタックと「宣言したスタック+登録した除外」を突き合わせ、外れたら G-5 を失敗にする。検出は目印のファイルに拡張子の集計を併せる(品質監査)
  - 第2段: (c1) 複数のアダプタ。単一値の欄は有効のまま残し、追加の欄にする(弁護)。スタックごとの段を並列に回し、段を if: で飛ばさない(現場)。宣言したアダプタが対象を見つけなければ失敗にする(弁護)。カバレッジはスタックごとに同じ基準値と比べ、合算しない(5 委員。未実証)
  - アダプタの外の言語は、手書きの要素(none の経路)で受ける。手書きの要素が無ければ、第1段で失敗になる(現場・弁護)
- 採らない: (c2) 混在を止める(持ち込みの時点しか見ず誤検出が多い、止めた後の受け皿が無い)、(c3) の単独(基準1「例外なし」と両立しない)、(d) 差分の網羅率を受け皿にする(基準3 しか受けない。部品は #360 の IMPL-0259)、affected 型の選択的な実行、目印から製品かどうかを機械で推定すること、宣言の初期値の機械の埋め込み

## R-2 宣言と除外 — 裁定

- スタックの宣言は人が行う(起案・現場)。単位は「スタック × 作業の場所」(現場)
- 除外はパス単位で、区分は「製品でない」だけの閉じた区分とする。製品のスタックは除外できない(規格・起案)
- 除外には理由と人の記名を要する。AI の名義は受け付けない(品質監査)
- 除外の一覧は統制の設定に入れ、AI維持管理者の承認を要する(起案。#371 の承認の照合に乗る)
- 除外の変更と製品のコードの変更が同じ PR にあれば失敗にする(5 委員)
- 除外は基準7(秘匿情報)に効かない(起案)
- 採らない: スタック単位の除外(弁護)、新しい承認者の役(現場。既存の AI維持管理者で足りる)、混在に限った「受容の記録」の新設(品質監査の案。除外の記名と承認で目的を果たし、受容の経路を別に置くと基準1 の例外の入口になる)

## R-3 暫定の扱いと既存の採用者 — 裁定: 暫定の間も失敗にする

- 第1段は先に降ろす。第2段が降りるまでの間、宣言の外のスタックは失敗にする(gate-criteria.md 861 行の「未実施は失敗に数える」をそのまま当てる。品質監査・起案・弁護)
- 表示の語は、ゲートでは「基準1 未充足」、検査ごとには「未実施(構成のアダプタの外)」(品質監査・起案)。「検査していない」「未達」は採らない
- 旧い構成(アダプタ1つ)は、値を変えずに移行する。猶予は置かない(起案)
- 採らない: 止めずに「未充足」を表示して判定者が受け入れる案(現場)。判定者が開示を読まない傾向(未実証)が残り、基準1 と両立しない

## R-4 記録・ADR — 裁定

- ADR-0118 を新設し、ADR-0085 決定2 の理由(88 行)の射程を単一のスタックの場合に限る。ADR-0085 の状態の節に注記を足す
- EV: 複数のアダプタの実行(CI の時間)と、拡張子の集計の誤検出の率は未実証。EV を付ける
- IMPL: 本文の2つの要求に印を付ける。第1段は降ろして delivered。第2段は undelivered(issue=363 を閉じるなら、既存の #360 か #359 へ)
- #360 には IMPL-0259 への依存を書く
- 欠陥①(秘匿情報の検査の飛ばし)は、軽の実装で直す(別の Issue へは切り出さない)
- 62304・DO-178C・9001 の読みは二次資料だけで、EV に含めて開示する
