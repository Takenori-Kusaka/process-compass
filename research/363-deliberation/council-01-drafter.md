# #363 会議体(軽) 委員1: 起案

- 立場: 規定として書ける形と、既存の決定との整合を重視する
- 論点: 欠陥③(survey-363.md 表 D-3、5.4 節)。node と python の混在で node アダプタを選ぶと、わざと落ちる python のテストが走らないまま G-5 の test が通り、カバレッジも python を警告1行で分母から外して 100% で通る
- 読んだもの: `survey-363.md`、`gate-criteria.md`(G-5 の基準表 655〜668 行、集約 681 行、対象なし 822〜845 行)、ADR-0085 決定2(`0085-adoption-into-existing-repositories.md` 80〜92 行)、`template/scripts/gate/preflight.mjs` 56・253・265 行

## 1. 前提の整理: 欠陥③は何に対する欠けか

- G-5 基準1 は「全テストが GREEN」で、値は「例外なし」(`gate-criteria.md` 660 行)。「全テスト」をアダプタが選んだスタックのテストに限る読み方は、本文のどこにも無い
- 同 681 行は「集約から検査を外すことで、判定基準を外してはなりません」「判定基準を実装する検査を外せるのは第8章の調整による場合だけ」と定め、第8章は G-5 の基準を個別に外す規則を持たない
- 対象なし(822 行以下)は「対象が存在しない」場合の扱いで、python のテストが存在する混在のリポジトリには当たらない
- したがって、起案の読みは「全テスト = 製品が持つすべてのスタックのテスト」である。混在で片方のテストが走らないまま通るのは、既存の条項への違反であり、条項の空白ではない
- ただし、調査(survey 6節 221 行)が指すとおり、この読みは本文に明記されていない。明記すれば採用者に効く範囲が広がる。読みの確定を本文へ書くこと自体が重に当たる(4節)
- ADR-0085 決定2 の「カバレッジの測定の穴は止めない。node では test ジョブが失敗し…黙っては外れない」(88 行)は、単一スタックを前提にした理由である。混在では前提が崩れ、決定の理由が成り立たない

## 2. 推す案: (c1) を規定の正本とし、(c3) を降りるまでの表示として併せる

規定の文として、次の3点を起案する。

1. 本文(G-5 基準1・2・3・5 の注記): 「全テスト」「静的解析」「カバレッジ」「ライセンス検査」の対象は、製品のコードが使うすべてのスタックである。構成が持つアダプタに入らないスタックのテストは、走らなければ基準1 を満たさない
2. 準拠テンプレート(c1): 構成が複数のアダプタを持てるようにする。各アダプタに作業の場所を持たせ、各段を各アダプタで回し、集約は全アダプタの結果の論理積で合否を出す。製品でないスタック(文書の生成用の `package.json`、補助の台本など)は、構成の中で理由つきの「対象外」として宣言する(`template-fields.yaml` の `omit` と同じ型: 理由の無い除外を認めない)
3. 降りるまでの表示(c3 の位置づけの変更): c1 を実装するまで、IMPL マークを `state=undelivered` で付け、G-5 の実行時(事前点検ではない)に「構成のアダプタの外のスタックの目印」を検出したら、保証の開示 項目4 と G-5 の集約に「検査していない(構成のアダプタの外)」と出す。これは基準1 の充足を装わない表示であり、「降りていない規定は消さずに表示し続ける」(CLAUDE.md #222)と同じ扱い

推す理由(信頼性の軸で):

- 欠陥③の主な欠けは基準1(テストの実行)である。基準1 をすべてのスタックに機構として当てられるのは c1 だけ(survey 7節 257 行「D-3 を閉じる唯一の案」)
- 検出を G-5 の実行時に置くのは、開始の後にスタックが増える場合を受けるため。事前点検は持ち込みの一度しか走らない(survey 7節 242 行「効かないもの: 開始の後にスタックが増えた場合」)
- 「対象外」の宣言に理由を要求するのは、681 行の「集約から検査を外すことで判定基準を外してはならない」を、宣言による除外の経路で崩さないため。理由の無い宣言を受けると、node だけを宣言して python を黙って外す、いまの欠陥と同じ状態を作れる

## 3. 他の案を落とす理由

- **(c2) 事前点検で混在を止める**: 落とす
  - 事前点検は持ち込みの時点だけを見る。開始の後に足した python は止まらず、欠陥③は残る
  - 混在のリポジトリ(モノレポ)は持ち込めなくなる。ADR-0085 決定2 が古い併合を止めない理由(84 行「止めると持ち込みそのものができなくなる」)と同じ型の害で、既存の決定と食い違う
  - 止める条件に「複数のスタック」を置くと、文書の生成用の `package.json` のような製品でない目印で誤って止まる。G-5 の原則「実効的な偽陽性が無いこと」(gate-criteria.md 「是正の起動」の3条件)に反する
- **(c3) 単独で採る(開示だけで受ける)**: 正本としては落とす。2節の3のとおり、降りるまでの表示としてだけ使う
  - 開示しても G-5 は通り続ける。基準1 の値「例外なし」(660 行)と両立する文を書けない。「通過したが基準1 の一部を検査していない」は、対象なし(822 行以下)の「通過の根拠は対象が存在しない事実の記録」とも違い、本標準に位置づけの無い第3の状態を作る
  - これを正本にするなら、基準1 の未充足を受け入れる判断であり、ADR-0085 決定2 の理由の改めに加えて、G-5 の基準を個別に外す規則を第8章へ置くことになる。681 行の原則の変更である
- **(d) 差分の網羅率を受け皿にする**: 欠陥③の受け皿としては落とす
  - 基準3 しか受けない。落ちる python のテストが走らないこと(基準1)と、ruff が走らないこと(基準2)は残る(survey 7節 265 行)
  - ただし、c1 の下で python の変更の範囲を測るために、行単位の被覆を読む部品は要る。これは IMPL-0259 として #360 の範囲で進め、#363 からは「c1 の前提として要る」と依存だけを書く
- **(e-1) `none` に手で書く形を正規の経路として案内する**: 正規の経路としては落とす。c1 が降りるまでの当座の手段として、手引きに限界つきで書くことは妨げない
  - 実行では test は両方走った(survey 5.4)が、カバレッジは `coverageSummary: null` で未実施になる。未実施の長期化の歯止めは #330 にあり、決まっていない
- **(e-3) と (c2) は同じ**。(e-4) 何もしない: 既存の条項への違反を放置するため落とす

## 4. 新しい義務・ADR の原則の変更の有無

| 起案の要素 | 新しい義務か | ADR の原則の変更か |
| --- | --- | --- |
| 基準1・2・3・5 の対象を「すべてのスタック」と本文に明記 | 採用者に効く範囲が広がる。読みの確定だが、実質は新しい義務 | — |
| 製品でないスタックを理由つきで「対象外」と宣言 | 新しい宣言の義務 | — |
| G-5 実行時の未宣言のスタックの検出と表示 | 表示だけなら義務なし。止めにすれば新しい義務 | — |
| 構成を複数のアダプタへ広げる | 構成の形の変更。形式の版の繰り上げと `migrate`(ADR-0085 決定5) | ゲート契約(`evidence/evidence.json` のキー構造)の変更 |
| ADR-0085 決定2 の理由(88 行)の前提を混在で補う | — | 採用済み ADR の理由が崩れるため、新しい ADR で補う |

結論: **重へ上げるべき**。新しい義務(全スタックの明記・対象外の宣言)と、ADR-0085 決定2 の理由の改め・ゲート契約の変更の両方に当たる。CLAUDE.md の「重: 採用者への新しい義務・ADR の原則の変更」に該当する。

## 5. 重で審議するときの未決の問い(起案からの持ち込み)

- 未宣言のスタックを検出したとき、G-5 を止めるか表示にとどめるか。止めるなら誤検出の扱い(理由つきの対象外の宣言で足りるか)
- 「製品のスタック」の判定を人の宣言に残すこと(ADR-0085 決定2「設問の回答を検出の結果で埋めない」)と、検出との突き合わせの境
- 既存の採用者を落とす変更の手続(ADR-0085 決定6)。混在のまま node だけで通っている採用者が G-5 で落ちる
- 外部の調査: モノレポでの CI の実務(言語ごとの作業の場所、影響を受けた範囲だけ走らせる道具)。本委員は確かめていない。採否の根拠にするなら重の外部調査で取る
- 根拠水準: 混在のリポジトリでの試行は、survey の手元の1例(Windows)だけ。規定に効く値を置くなら ADR-0026 のマークで開示する
