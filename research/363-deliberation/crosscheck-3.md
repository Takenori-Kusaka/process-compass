## 3. 指摘

### X3-1 none の経路で通る混在のリポジトリでは、基準3 がどのスタックにも効かない(中)

- 所在: 第4章 G-5「製品のすべてのスタック」の最後の段落(717 行付近)、IMPL-0476 の note、テンプレートの `coverage-check.mjs` 19・252〜255 行
- 根拠: 本文は「各スタックの検査が、それぞれ集約の合否に入らなければなりません」と書き、第1段の間は「すべてのスタックのコマンドを手書きの要素に書くか…まで、G-5 を通りません」と書きます。読み手は、書けば通ると読みます。ところが none は `coverageSummary: null` で、`coverage-check.mjs` は null を「判定を実施しない」として通します。2つのスタックで1つの要約を手で指せば、裁定が採らなかった合算になります。つまり none の経路の混在のリポジトリは、基準3 を実施しないまま、または合算で G-5 を通ります。場面 J4 では、none の `stacks` だけを書き、コマンドが宣言したスタックを実際に走らせるかを機械が確かめないことも確かめました(試験の空のコマンドは別の検査で落ちる。lint・audit・licenses の空は通る)。この限界は、降りていない IMPL-0479 の note の括弧書き「(その形ではカバレッジは未実施)」にしか書かれていません。delivered の IMPL-0476 と本文には書かれていません
- 直し方の向き: 第1段の間の none の経路について、基準3(と空のままの基準2・5)が未実施で通ることを本文の段落と IMPL-0476 の note に書く。あるいは、この状態を「未実施は失敗に数える」と揃えて失敗にするかを決める。後者は `coverageSummary` が null の扱い(#330)を変えるため、#360 で IMPL-0259 と併せて扱う。機械が「宣言したスタックをコマンドが走らせるか」を確かめないことも、IMPL-0476 の確かめない範囲に足す

### X3-2 除外の記名が、担い手の識別の文字列と、名簿にない名前を受け付ける(中)

- 所在: `stack-coverage.mjs` 175〜179 行(`aiNameBlocked` だけを使う)
- 根拠: 場面 G6 で、構成の `seats[].performer` の文字列 `pitcrew-dev`(AI の担い手のアカウント)を `decidedBy` に書くと、除外が受け付けられて通過しました。場面 G7 で、名簿(`people[]`)がある構成に名簿にない `鈴木 一郎` を書いても通過しました。`config.mjs` の `nameProblems` は、AI の語に加え、担い手の識別と同じ文字列と、名簿にない名前を拒みます。ほかの記名はこの関数で確かめています。AI の語を含まない名義で動く担い手(ADR の名義の規則が想定する形)が、自分の名で除外を記名できます。AI維持管理者の承認のレビュー(#371)が2層目として残るため、高ではなく中とします
- 直し方の向き: `aiNameBlocked` を `nameProblems(config, x.decidedBy)` に替える。試験に、担い手の文字列と名簿にない名前の陰性の場面を足す。IMPL-0477 の note の「人の記名」の説明を合わせる
