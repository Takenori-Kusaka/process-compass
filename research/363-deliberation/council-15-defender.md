## 0. 認めること(弁護の前提)

- D-3 は欠陥である。G-5 基準1 は「例外なし」(gate-criteria.md 660 行)、集約から検査を外して判定基準を外すことは禁じられている(681 行)。わざと落ちる python のテストが走らずに終了コード 0 になった(survey 5.4、181〜189 行)

## R-1 正本の方式

- 推す案: **契約検査(製品の目印のスタック ⊆ 構成が受けるスタック)を正本の歯止めとし、c1 はその受け皿として後から足す**。順序は「検査が先、c1 が後」。c1 は既定の形を変えず、追加の欄で足す(単一スタックの構成は今の形のまま有効)
- 理由
  - 信頼性を決めるのは「アダプタが複数か」ではなく「宣言と実態の突合が合否に効くか」である。反対の委員も c1 単独では閉じず、穴が「宣言の漏れ」へ移るだけと認めた(council-02 2節 c1 の1点目)。突合の検査はアダプタが1つでも書ける。目印は既に検出済みで、合否に結び付いていないだけ(preflight.mjs 263〜266 行、council-02 1節3点目)
  - 検査を先に降ろせば、混在の採用者の経路は今でも1つある: `none` に手でコマンドを書く形。test は両スタックで走り、基準1 は満たされる(survey 5.4 の none の行)。カバレッジは「未実施」と記録され、黙っては外れない。開示つき通過という新しい状態(council-01 3節 c3)を作らずに済む
  - c1 の設計(束ね方・作業の場所・setup-stack の複数の実行環境)は未試行である。混在で配列のアダプタを回した実行は無い(未実証。council-02 c1 の最終点)。未試行の機構を正本の歯止めにするより、既に実行で確かめた検出(preflight)を合否へ結ぶほうが確かである
- c1 の弱点(c1 を採るときの条件にする)
  - **D-1・D-2 の穴が掛け算になる**: 今は宣言したアダプタが対象を見つけないと「対象なし」で通る(survey 0節 D-1・D-2)。アダプタを複数にすると、宣言しただけで対象を見つけないアダプタが増え、黙って通る経路が増える。条件: 宣言したアダプタが作業の場所に対象を見つけなければ、対象なしでなく失敗にする
  - **誤設定の源が増える**: スタックごとの作業の場所・実行環境の版。条件: 作業の場所に目印が無い宣言を契約検査で失敗にする
  - **束ね方**: 全スタックの合算は薄い側を薄める(council-02 c1 の3点目に同意)。条件: スタックごとに同じ基準値と比べ、スタックごとの基準値という新しい調整の欄は設けない(調整の欄は誤設定と緩めの入口になる)
  - **移行**: `adapters.stack` を配列へ置き換えると、全採用者が形式の版の繰り上げと `migrate`(ADR-0085 決定5)を通る。単一スタックの採用者に移行の失敗の機会を与える理由は無い。条件: 単一値はそのまま有効とし、追加の欄だけ足す(移行の変換を要しない形)。ゲート契約(`evidence/evidence.json`)のキーも、単一スタックでは今と同じ形を保つ
- 落とす案
  - (c2) 事前点検で止める: 採らない。持ち込みの一度しか見ず開始後の追加を塞げない。止める条件が目印のファイル名だけで誤検出が多い(council-02 2節 c2)。古い併合を止めない理由(ADR-0085 84 行)と同じ害
  - (c3) 単独: 採らない。開示つきで外すのも外すこと(681 行)。判定者が読む保証が無い(D-1 で開示されていたのに止まらなかった。survey 5.5)
  - (d): #363 の受け皿としては採らない。基準1・2 を受けず、node アダプタでは python の coverage.json がそもそも生成されない(council-02 2節 d)
  - c1 を正本の歯止めにする形(起案の 2節2): 採らない。上記のとおり突合を伴わない c1 は閉じない。c1 は受け皿として採る

## R-2 宣言と除外

- 推す案: スタックの「宣言」を新しい設問として求めない。**構成が受けるスタック(アダプタ)が宣言そのもの**で、検査は製品の目印と突き合わせる。突き合わせから外すのは、**パス単位**の除外の登録(理由・記名つき、AI の名義を認めない)だけにする
- 理由
  - 宣言の欄を別に設けると、アダプタと宣言の二重管理になり、食い違いが新しい誤設定になる
  - 除外をスタック単位(「python は道具なので外す」)にすると、後から足した製品の python まで外れる。パス単位なら、新しい目印は自動で突合に入る
  - 除外の一覧そのものが新しい「黙って外す」入口になる。条件: 除外の一覧の変更は、閾値・除外設定と同じく製品のコードとの同時変更を止める対象にし(survey 5.6 の B の型)、委任の範囲に入れない(`adapters/**` と同じ扱い。survey 1.1)
- 落とす案: 目印から製品かどうかを機械で推定する形。ADR-0085 決定2「設問の回答を検出の結果で埋めない」(89 行)と食い違い、誤検出を機械の判断で消すことになる
- 留保: 除外の登録に承認者(記名者と別の人)を要するかは、1〜2名の体制で同一人物になる。記名者1名で受け、承認者の分離は課さないことを推す(採用の障壁を根拠水準つきで開示。未実証)
- 留保: アダプタの外の言語(rust・java。preflight.mjs 60〜65 行)が製品にある場合、`none` の手書きの経路で test は走らせられる。反対の委員の「通過にしない(未達)」は、`none` で走らせた場合まで落とすなら強すぎる。ただし `none` のコマンドがどのスタックを受けるかを自己申告させると、検証できない申告が増える。この境は未決として議長に委ねる

## R-3 暫定の扱いと既存の採用者

- 推す案: 暫定は**表示ではなく検査で受ける**。契約検査(R-1)を c1 より先に降ろし、c1 が降りるまでの混在の受け皿は `none` の手書きの経路(カバレッジは未実施として記録)とする。c1 が降りていないことは IMPL の `state=undelivered` で表示し続ける
- 検査が降りるまでのごく短い間の表示の語: **「未充足」**を推す(反対の委員に同意)。「検査していない」は対象なし(gate-criteria.md 825〜847 行)と読み違えられ、中立に見える
- 既存の採用者: 混在のまま node だけで通っている採用者は、検査の導入で G-5 が落ちる。これは欠陥の是正で、落とすことを避ける理由にしない。ADR-0085 決定6 に従い、落ちうる検査・直し方(除外の登録か `none` の経路)を列挙して出す
- 採用の障壁(弁護の懸念): `none` の経路はカバレッジが未実施になり、未実施の長期化の歯止め(#330)が決まっていない。混在の採用者が未実施のまま長く留まる危険がある。c1 を遅らせてよい理由にはしない。#330 の決定に依存することを記録する
- 落とす案: 開示つきの通過を暫定に置く形(起案 2節3)。暫定が長引けば正規の第3の状態になる。#330 の未実施と同じ型の抜け道をもう1つ作る
