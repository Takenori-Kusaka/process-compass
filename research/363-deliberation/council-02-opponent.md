# #363 会議体(軽) 委員2: 反対の委員

- 論点: node と python が混在するリポジトリで node アダプタを選ぶと、python のテストが走らないまま G-5 を通る件(欠陥③ = 調査の D-3)
- 読んだもの: `survey-363.md`(以下「調査」)、`gate-criteria.md` 660・681・825〜847 行、ADR-0085 決定2(`0085-adoption-into-existing-repositories.md` 80〜89 行)、`template/scripts/gate/preflight.mjs` 41・56〜66・245〜266 行、`coverage-check.mjs` 31・161〜189 行、Issue #360 本文
- 立場: 起案されそうな案の弱点を突く。欠陥と認めるものは認める

## 1. 認めること

- D-3 は欠陥である。G-5 基準1 は「全テストが GREEN / 例外なし」(gate-criteria.md 660 行)で、「集約から検査を外すことで、判定基準を外してはなりません」(681 行)。調査 5.4 は、わざと落ちる python のテストが node アダプタで走らずに終了コード 0 になることを示した。「全テスト」が全スタックを指すと本文に書かれていない(調査 6節)ことは、欠陥を否定する理由にならない。読み方が割れる余地を残したことが、条項の側の欠けである
- ADR-0085 決定2 の理由「node では G-5 の test ジョブが失敗し…黙っては外れない」(88 行)は、単一スタックを前提にしている。混在では成り立たない。理由の前提が崩れた以上、「告げるだけ」で止まる現状は根拠を失っている
- 事前点検は既に混在を検出している(preflight.mjs 263〜266 行の「複数のスタック…構成のアダプタは1つ」)。検出の欠けではなく、**検出した事実が合否に結び付いていない**ことが欠陥の本体である

## 2. 各案の弱点

### (c3) 告げて「検査していない」を開示・集約に出す

- **開示だけでは検査が走らない**。基準1 は満たされないまま G-5 を通る。681 行は「集約から外すことで判定基準を外す」ことを禁じる。開示つきで外すのも外すことである。c3 単独は、禁止された行為に開示の札を付けるだけになる
- 「検査していない」は、G-5 の「対象なし」の表(825〜847 行)にない新しい状態である。対象なしには「実装が存在する段階で用いてはならない」(847 行)の歯止めがある。新しい状態には歯止めがない。#330 の「未実施」と同じ型の抜け道を、もう1つ正規に作ることになる
- 決定2 の理由の改めが要る(調査 7節 e-2 と同じ)。「黙っては外れない」を「外れるが見える」へ下げる改めであり、判断軸の信頼性に反する方向である
- 判定者が開示を読む保証がない。保証の開示 項目4 は合否に効かない(調査 5.5 末尾)。D-1 の secretScan でも開示はされていたが、誰も止めなかった

### (c2) 事前点検で混在を止める

- **誤検出が多い**。目印の走査は追跡しているファイルの全階層を対象にする(preflight.mjs 251〜259 行)。python の製品に、整形・秘匿検査・commitlint のためだけの `package.json` がある形、node の製品に文書の生成用の `requirements-docs.txt` がある形、`testdata/go.mod` のような検査の材料、取り込んだ第三者のコードは、どれも「複数のスタック」として止まる。テスト対象の製品のスタックかどうかを、目印のファイル名だけでは判別できない
- 止めた後の受け皿がない。複数のアダプタの経路が無いまま止めると、採用者は `none` に手でコマンドを書くしかない。この形ではカバレッジが `coverageSummary: null` で未実施になる(調査 5.4)。止める案は #330 の未実施へ押し出すだけで、基準3 を落とす
- 持ち込みそのものができなくなる型である。ADR-0085 決定2 は、共通の祖先の無い併合を「止めると持ち込みそのものができなくなる」として止めなかった(85 行)。monorepo は業界で普通の形であり、同じ理由が当たる。止めるなら、決定2 と矛盾しない理由を新しい ADR で示す必要がある
- 点検は持ち込みの時点だけで効く。開始の後に python を足した変更は止められない(調査 7節 (a) の「効かないもの」)。止める条件を置くなら、事前点検ではなく PR ごとの契約検査に置かないと閉じない

### (c1) 複数のアダプタを持てる構成にする

- D-3 を閉じうる唯一の案であることは認める(調査 7節 c)。ただし**単独では閉じない**。採用者が node だけを宣言すれば、今と同じく python は走らない。宣言と実態を突き合わせる検査(c2 か c3 の何か)と組まないと、穴の位置が「アダプタが1つ」から「宣言の漏れ」へ移るだけである
- アダプタの外の言語(rust・java など。preflight.mjs 60〜65 行)は、配列にしても受けられない。混在の片方がアダプタの外なら、c1 でも基準1 は満たせない
- 結果の束ね方が未決である。カバレッジを全スタックで1つの値にするのか、スタックごとに基準値と比べるのか。1つの値にすると、テストの厚い側が薄い側を薄める(ADR-0079 の薄まりの開示と同じ問題が、スタックの間で起きる)。決めないまま実装すると、新しい「黙って外れる」を作る
- 採用者の手数: スタックごとの作業の場所・実行環境の版の宣言、setup-stack での複数の実行環境の用意(CI の時間の増加)。手数は採否の理由にしないが、宣言の欠けは誤りの源になる
- 構成の形式の版の繰り上げと `migrate`(ADR-0085 決定5)、証跡のキー構造(ゲート契約)の変更が要る。ゲート契約の変更は ADR の原則に触れる
- 混在の形の試行が無い(E0)。配列のアダプタで python と node を同時に回した実行は、調査に無い。採るなら根拠水準マークが要る

### (d) 差分の網羅率を受け皿にする

- **混在の node アダプタでは、python の coverage.json そのものが生成されない**。node アダプタは pytest を呼ばない。d は「python で測れる形にする」案だが、python が走らない構成では測る材料が無い。D-3 には何も効かない
- 基準1(テストの実行)・基準2(静的解析)を受けない(調査 7節 d)。これは調査の結論に同意する
- 逆効果の危険: 変更の範囲の被覆を python で「測れる」ことにすると、`notMeasurable` の警告(coverage-check.mjs 165〜170 行)が消える。python が走らない構成で、警告すら出なくなる組み合わせを作りうる
- 範囲は #360 の IMPL-0259 である(#360 本文の表は IMPL-0253 と書くが誤り)。#363 の受け皿にしない

### (e-1) `none` に手でコマンドを書く形を案内する

- 調査 5.4 では test は両方走った。しかし基準3 は未実施になり、秘匿情報の検査は D-1 と同じく対象なしで通りうる。正規の経路として案内すれば、基準3・7 の欠けを案内することになる。暫定の回避として開示する以上のものにしない

## 3. 推す案

**c1 と、宣言と実態の突合を PR ごとの契約検査で止める形の組み合わせ**を推す。c3 は、それが降りるまでの暫定に限る。

- 構成に複数のアダプタ(作業の場所つき)を宣言できるようにする(c1)
- 契約検査は PR ごとに、製品のファイルの中の目印のスタックが、宣言したアダプタの集合に含まれるかを確かめる。含まれなければ G-5 を失敗にする。止める場所を事前点検だけにしない(開始の後の追加を塞ぐため)
- 誤検出は、検査の外とする目印のパスを理由・記名つきで登録する一覧(`scope-exempt.yaml` と同じ型)で受ける。登録には「テスト対象の製品のコードではない」理由を要し、AI の名義の記名を認めない。目印のファイル名だけで判別できない以上、人の判断を記録で残すほかない
- アダプタの外の言語が製品にある場合は、基準1 を満たせないことを未達(ADR-0028)として扱い、通過にしない。開示つきの通過にはしない
- カバレッジの束ね方は、スタックごとに基準値と比べる。1つの値に合算しない(薄まりを作らないため)
- 暫定の c3: 降りるまでの間、混在を保証の開示 項目4 に「基準1 未充足(構成のアダプタの外)」として出す。「検査していない」という中立の語ではなく、**未充足**の語で出す。暫定であることを根拠水準マークで開示する
- 「全テスト」は製品のすべてのスタックのテストを指すと、基準1 の本文で確定する

## 4. 重さの判定

- 推す案は新しい義務を課す(複数のスタックの宣言、目印の除外の記名、混在の未宣言での G-5 の失敗)。ADR-0085 決定2 の理由(88 行)を改め、決定5(形式の版)とゲート契約にも触れる。基準1 の読み方の確定は、採用者に効く範囲を広げる
- c2・c3 のどれを採っても、新しい義務か決定2 の理由の改めに当たる(調査 8節と同意見)
- 既存の採用者のうち、いま混在で通っているものを落とす。ADR-0085 決定6 の保守者の義務(落ちうる検査と直し方の列挙)が掛かる
- **重へ上げるべき**。軽の2委員で扱える範囲を超える。軽で閉じるなら、D-3 を範囲から外し、外したことと、その間 D-3 が黙って外れ続けることを記録する以外に道はない
