# #363 会議体(重) 委員: 品質監査

- 立場: 監査・品質保証部門。検査していないスタックが黙って通る経路、除外の記録と承認、開示の正直さを見る
- 読んだもの: `council-00-agenda.md`、`survey-363.md`、`survey-363-2-external.md`、`council-01-drafter.md`、`council-02-opponent.md`、`gate-criteria.md`(660・681・825〜847・859〜861・1408 行、134・140 行)、ADR-0085(`0085-adoption-into-existing-repositories.md` 82・83・88 行)、ADR-0028(26〜43 行)
- 判断軸は信頼性。変更量は理由にしない

## 0. 監査の観点からの前提

- 既存の規定は、走らなかった検査を**既に失敗として扱う**。「検査器の入力を欠いて実施できなかった検査は…未実施の検査として失敗に数えなければなりません」(gate-criteria.md 861 行)。保証の開示 項目4 も「未実施と通過を区別する」(1408 行)
- 混在で node アダプタを選んだときの python のテストは、「対象なし」(対象が存在しない)ではない。対象は存在し、走らせていない。性質は 861 行の未実施に最も近い。したがって現状の通過は、861 行・660 行・681 行の3つに対する違反である。条項の空白ではない
- ADR-0085 決定2 は、品質保証の委員の「受容の記録が無ければ止める」を、「G-5 の失敗と『実施しない』の記録と二重になる」として採らなかった(88 行)。混在では test ジョブが失敗せず、二重にならない。**却下の理由が混在では消えている**。本委員はこの案を混在に限って再び出す
- 外部: プラットフォームは skipped を成功と数え(SRC-A1・A2)、Scorecard は言語の網羅を見ない(SRC-C1)。外部の監査や評価はこの穴を拾わない。拾える層は本標準のプロセスしかない

## R-1 正本の方式

- **推す案**: (c1) 複数のアダプタを正本とし、PR ごとの契約検査で「製品にあるスタック ⊆ 宣言したスタック ∪ 登録した除外」を確かめ、外れたら G-5 を失敗にする。軽の委員2(council-02 3節)の組み合わせに賛成する
- 理由
  - 基準1 の「例外なし」(660 行)を全スタックへ機構として当てられるのは c1 だけ(survey 7節 (c))
  - c1 単独は穴を「宣言の漏れ」へ移すだけ(council-02 2節)。突き合わせの検査が無ければ、監査は宣言の正しさを人の申告に頼ることになる
  - 突き合わせを事前点検に置かない。持ち込みの一度しか走らず、開始の後に足したスタックを見ない(survey 7節 (a))
- 条件と留保(監査として外せないもの)
  1. **目印のファイルだけで検出しない**。`pyproject.toml` も `requirements.txt` も無い `.py` の群(台本の寄せ集め)は、目印の走査では見えない。追跡しているファイルの拡張子の集計も併せる。目印だけでは、新しい黙った経路を残す(未実証: 拡張子の集計の誤検出の率は確かめていない)
  2. カバレッジはスタックごとに基準値と比べ、合算しない(council-02 3節)。合算は厚い側が薄い側を隠す
  3. アダプタの無い言語(rust・java 等)が製品にあるときは、G-5 を通さない。開示つきの通過にしない
  4. 各スタックの各段の結果を、証跡に「走った検査の一覧」として残す。必須チェックの緑は「走った」ことを示さない(SRC-A2)
- 落とす案
  - (c2) 混在を止める: 採らない。製品でない目印で誤って止まり(council-02 2節)、止めた後の受け皿が `none` しかない。持ち込みを塞ぐ型で ADR-0085 決定2(84 行)と食い違う
  - (c3) を正本とする: 採らない。開示つきで集約から外すのは、681 行が禁じる「外す」そのもの。861 行の「未実施は失敗」とも食い違い、未実施より甘い第3の状態を作る
  - (d) を受け皿とする: 採らない。基準1・2 を受けず、python が走らない構成では測る材料が無い(council-02 2節)。逆に notMeasurable の警告を消しうる
  - (e-1) `none` を正規の経路とする: 採らない。カバレッジが未実施になる(survey 5.4)

## R-2 宣言と除外

- **推す案**: スタックは人が構成に宣言する(ADR-0085 決定2「設問の回答を検出の結果で埋めない」に従う)。機械は宣言と検出の差を出すだけで、宣言を書き換えない。差を埋めるのは「宣言を足す」か「除外を登録する」の2つに限る
- 除外の登録の欄(どれかが欠ければ登録として受けない)
  - 対象のパス(glob)、区分(道具・試験の材料・取り込んだ第三者のコード・文書の生成)、「製品のコードではない」理由の文、記名、日付
  - 記名は人の名義に限る。AI の名義は受けない(ADR-0085 決定2 の資産の一覧と同じ型。82 行)
  - 承認者: 記名者以外の名簿の人を置ける体制では、その人の承認を要る。置けない体制(1〜2名)では本人の記名を受け、自己申告であることを保証の開示に出す(gate-criteria.md 140 行の型)。黙って自己承認を通さない
- 除外の乱用を塞ぐ条件
  - 除外の登録・変更と製品のコードの変更が同じ PR にあれば失敗にする。G-5「基準値と除外設定の変更」の分離を除外の一覧へ当てる(未実証: 正当な同時変更がどれだけ止まるかは確かめていない)
  - 除外したパスの下のファイルを、製品のコードが参照していないかは機械では確かめきれない。限界として開示する
  - 除外の件数と一覧を、保証の開示 項目4 に毎回出す。登録してあることは、検査したことではない
- 誤検出の扱い: 誤検出は上の除外で受ける。理由の無い一括の除外(`**` 等、全体を覆う glob)は受けない
- 落とす案: 宣言を検出の結果で自動的に埋める形は採らない(ADR-0085 決定2 と食い違い、漏れの責任の所在が消える)

## R-3 暫定の扱いと既存の採用者

- **推す案**: c1 が降りるまでの間も、宣言の外のスタックを検出したら **G-5 を失敗にする**。表示は検査の単位で「未実施(構成のアダプタの外)」、ゲートの単位で「基準1 未充足」
- 理由
  - 861 行が既に未実施を失敗と定める。暫定の間だけ開示つきの通過にするのは、既存の条項より甘い扱いを、降りていないことを理由に作ることになる
  - 委員1 の「検査していない」(council-01 2節の3)は中立の語で、通過と並べると通過に読める。委員2 の「未充足」(council-02 3節)には賛成するが、新しい語を足すより、既に失敗の意味と開示の区別を持つ「未実施」(1408 行)を検査の単位で使う方が語彙を増やさない
- 受け皿(失敗のまま放置させないため)
  - 製品でないスタック: R-2 の除外で解消する
  - 製品のスタック: 暫定は `none` に手でコマンドを書く形を、限界つきで手引きに書く。カバレッジは未実施になり失敗に数える。通れない採用者が出ることを隠さない
  - 期限つきの受容の記録(ISO 9001 8.6 の「権限者の承認と記録」の型。SRC-D4。二次資料のみで逐語は未確認)を置くかは、**本委員の推しではなく条件つきの選択肢**として出す。置くなら、記名(人)・期限(c1 の降りる予定に結ぶ)・ADR-0028 の未達と同じく構成書の冒頭への表示・保証の開示への掲載を必須とし、通過と同じ表示にしない。ただし 681 行は基準を外せるのを第8章の調整に限るため、第8章へ規則を置く新しい ADR が要る。この規則を置かないなら、受容の経路は作らない
- 既存の採用者: いま混在で通っている採用者は落ちる。ADR-0085 決定6 に従い、落ちる検査・直し方(宣言を足す・除外を登録する)を出荷の通知で列挙する。**落ちないための黙った猶予は置かない**。猶予を置くなら上の受容の記録の形に限る
- 落とす案: 暫定の c3(開示つきの通過)は採らない。開示 項目4 は合否に効かず、D-1 でも開示されていたが誰も止めなかった(council-02 2節、survey 5.5)

  5. 採らない案と理由: (c2)、(c3) の正本化と暫定の通過、(d) の受け皿化、(e-1) の正規化、宣言の自動の補完、語「検査していない」
- EV: c1 の配列のアダプタで python と node を同時に回した実行は無い(E0。council-02 2節)。拡張子の集計の誤検出の率、除外の同時変更の検査の止めすぎも未実証。ADR-0026 のマークで開示する。EV-0170 には本件の観測を書き足し、マークは消さない
- IMPL: c1、PR ごとの突き合わせの検査、除外の登録の検査、暫定の失敗の表示に、それぞれ IMPL を付け、降りるまで `state=undelivered` で表示し続ける。暫定の失敗は c1 より先に降ろせる(既存の 861 行の適用であり、c1 に依らない)。**暫定の失敗の IMPL を c1 の IMPL に束ねない**。束ねると、c1 が遅れる間は失敗も降りない

- 重大度の見立て: 現状は既存の条項(660・681・861 行)に対する黙った違反で、独立の突合では「高」に当たる。暫定の失敗の実装を c1 の審議の終結を待たずに降ろすことを、議長に求める
