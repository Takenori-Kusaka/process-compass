## R-1 正本の方式

- **推す案**: 標準の要求事項は道具に依らない語で書き、(c1) をその準拠テンプレートでの実装とする。要求事項は次の2文
  1. 「G-5 の基準1・2・3・5 の対象は、製品のコードを構成するすべてのスタックです。構成に宣言したスタックの検査が、それぞれ集約の合否に入らなければなりません」(660 行の表の直後に注記として置く)
  2. 「製品のコードに、構成に宣言していないスタックの目印がある変更は、G-5 を通過させてはなりません。除外の一覧に理由と記名つきで載せた目印を除きます」(681 行の「判定基準を実装する検査と集約」の節に置く)
- 理由
  - 基準1 の値は「例外なし」(660 行)。走らないテストを残したまま通す読み方は本文に無い。681 行は検査を外す経路を第8章の調整に限り、第8章は G-5 の基準を個別に外す規則を持たない。したがって 1 は新しい規範ではなく、既存の規範の対象の確定である。ただし採用者に効く範囲が広がるため、重として扱う(survey 8 節)
  - 2 を置かないと (c1) は閉じない。反対の委員の指摘(council-02 2 節: 穴が「アダプタが1つ」から「宣言の漏れ」へ移るだけ)を採る。外部の型も同じで、Nx・Pants は入力の宣言から漏れたものを走らせない(survey-2 SRC-B1・B2)。GitHub は飛ばしたジョブを Success と数える(SRC-A1・A2)ため、プラットフォームに頼れない
  - 標準に「複数のアダプタ」という語を書かない。アダプタは準拠テンプレートの部品であり、ADR-0085 決定3 が実装の規則を標準の要求事項にしなかった判断(同 ADR 94〜96 行)と同じ線を引く
- 準拠テンプレートでの実装(c1): 構成の欄を `adapters.stacks: [{ "id": "node", "path": "." }, { "id": "python", "path": "services/api" }]` の形にする。各段を各要素で回し、集約は全要素の結果の論理積をとる。作業の場所(`path`)を持たせることで D-2(直下だけを見る)も同時に受ける
- カバレッジはスタックごとに基準値と比べ、1つの値に合算しない。合算すると厚い側が薄い側を薄め、ADR-0079 の薄まりがスタックの間で起きる。ただし、スタックごとの比較が判定者にとって十分かは**未実証**(混在で配列のアダプタを回した試行は無い。survey 10 節)。EV で開示する
- アダプタの外の言語(rust・java 等)は、要素の `id` に `none` を置き、手でコマンドを書く形で受ける。この形では、テストと秘匿情報検査は空を許さず、カバレッジは「記録された未実施」になる(`template-repository.md` 806〜813 行の表と同じ扱い)。基準1 は満たせるため、これを未達にしない
- **落とす案**
  - (c2) 混在を止める: 採らない。事前点検は持ち込みの時点しか見ない(survey 7 節 (a))。モノレポを持ち込めなくなり、ADR-0085 決定2 が古い併合を止めなかった理由(85 行)と同じ害を生む。止める位置を PR ごとに移すなら、それは推す案の 2 である
  - (c3) を正本にする: 採らない。開示つきの通過は 681 行の禁止に札を付けるだけで、対象なし(822 行以下)にも未実施(811 行)にも当たらない第3の通過の状態を作る。外部の規格の型も「識別・理由・記録・権限者の受け入れ」までを求め、告げるだけでは半分にとどまる(survey-2 5 節、SRC-D4。9001 の逐語は未確認)
  - (d) 差分の網羅率を受け皿にする: 採らない。基準3 しか受けず、node アダプタでは python の `coverage.json` そのものが生成されない(council-02 2 節)。IMPL-0259 は #360 の範囲として依存だけを書く
  - (e-1) `none` に手で書く形を正規の経路にする: 単独の経路としては採らない。上記のとおり、要素の1つとして使う形に限る

## R-2 宣言と除外

- **推す案**: スタックの宣言を求める。宣言は人が行い、検出は宣言との突き合わせにだけ使う
  - 宣言の経路は `/process-init` の設問と `/process-change` の種別 `settings` の `stack`(`kinds/settings.md` 11 行。判断記録を要する)。検出で設問の回答を埋めない(ADR-0085 決定2 89 行)。検出は「宣言していない目印がある」ことを告げ、止めるだけ
  - 突き合わせは PR ごとの契約検査で行い、事前点検には置かない。開始の後に足したスタックを塞ぐため(survey 7 節 (a) の「効かないもの」)。判定のコードと除外の一覧は基底ブランチから読む(ADR-0115 決定。同じ PR で除外を足して通す経路を塞ぐ)
- **除外の形**
  - 単位は目印のパス(例: `docs/package.json`)。スタック単位の除外は認めない。スタック単位だと、製品の python と道具の python を区別できない
  - 必須の欄: パス、区分(閉じた列挙: 開発の道具・文書の生成・試験の材料・製品に含めない第三者のコード)、理由、記名(自然人。AI の名義は不可。ADR-0106 の効力を持つ記録と同じ扱い)
  - 除外の一覧を統制の設定に入れる。追加と変更には AI維持管理者が本人のアカウントで出す承認のレビューを要する(ADR-0115 `--require-control-approval`)。除外は効いている検査の集合を縮める変更であり、681 行末の「効いている検査の集合が誰にも見えないまま縮む」に当たるため
  - 除外は基準1・2・3 の対象から外すだけで、基準7 には効かない。基準7 は「リポジトリ全体が常に対象」(gate-criteria.md 表の 7 行)。基準5 は、除外したパスの依存が出荷物に入らない場合に限り外れる。この条件を判別できない場合は外さない
- 誤検出: 除外の一覧で受ける。目印のファイル名だけでは製品か道具かを判別できない(council-02 2 節)ため、人の判断を記録で残すほかない。誤検出の件数は観測し、多ければ目印の規則を直す。件数を義務の起動条件にはしない(gate-criteria.md「是正の起動」と同じ)
- 対象なしの扱い: スタックごとに判断する。宣言したスタックの作業の場所に実装が無い間は、そのスタックの基準1・2・3・5 を対象なしで通せる。実装がある場所では 847 行のとおり用いない
- **落とす案**: 検出で宣言を自動で埋める形(ADR-0085 決定2 と食い違う。survey 6 節 (b-4) と同じ理由)、除外を理由だけで受ける形(記名が無ければ誰が受け入れたかを追えない。SRC-D4 の型を欠く)、alls-green の `allowed-skips` をそのまま写す形(ジョブ単位の除外で、スタックとパスの対応を持たない。型は参考にする)

## R-3 暫定の扱いと既存の採用者

- **推す案**: 届ける順序を2段に分け、表示だけで通す期間を最短にする
  - 第1段: 推す案の 2(宣言と目印の突き合わせ・除外の一覧・失敗)を先に降ろす。この時点では配列の構成が無いため、混在の採用者は `none` に手で書く形か、python 側の除外(製品でない場合だけ)で通す。`none` ではカバレッジが記録された未実施になる。黙った通過より、失敗して記録された未実施へ移る方が信頼性が高いと判断する
  - 第2段: (c1) の配列の構成を降ろし、`none` の当座の形から移行させる
  - 第1段が降りるまで(いまの準拠テンプレート): 規定に IMPL マークを `state=undelivered` で付ける。保証の開示 項目4 は、宣言の外のスタックを「**未充足**(基準1。構成に宣言していないスタック: python)」と出す。表示は合否に効かないことを同じ行に書く
- 表示の語: 「未充足」を推す。「検査していない」は落とす。本標準では「対象なし」「未実施」が**通過の状態**を指す語であり(gate-criteria.md 822 行以下、`template-repository.md` 811 行)、「検査していない」はそれらと同じ系列に読まれ、通過してよい状態と誤読される。「未達」は ADR-0028 のゲートの状態(`unmet`)の値であり、基準の1つの状態に流用すると型が崩れる。「未充足」は既存の語に当たらないため、初出の箇所で「基準を満たしていない状態。通過の状態ではない」と定義する
- 既存の採用者(1値の構成): 構成の形式の版(`formatVersion`)を上げ、`migrate` で `{ stack: "node" }` を `stacks: [{ id: "node", path: "." }]` へ変換する(ADR-0085 決定5)。移行は値を変えないため、python を足さない。足すかどうかは人の宣言による。移行の後に混在の採用者は契約検査で落ちる。保守者は ADR-0085 決定6 の義務に従い、落ちうる検査と直し方(宣言の追加・除外の登録)を列挙し、書き込まずに試す手段を同梱する。猶予の期間は置かない(決定5「猶予の期間を置かない」と同じ理由)
- **落とす案**: 暫定の期間を開示だけで続ける形(期限の無い開示は c3 を正本にするのと同じになる)、猶予の期間を置く形(ADR-0085 決定5)、旧い構成を node と python の両方に読み替える形(読み込みで値を補うのは結果が同じか厳しくなる場合に限る、という決定5 の規則には合うが、検出で宣言を埋めることになり決定2 と食い違う)
