## 0. 現場から見た前提

- 目印の走査は追跡しているファイルの全階層を見る。除くのは `node_modules`・`vendor`・`.venv`・`dist` 等だけ(preflight.mjs 68 行)。`testdata/`・`fixtures/`・`tools/`・`docs/` は除かない
- python の目印は `requirements[^/]*\.txt` を含む(同 58 行)。node の製品の `requirements-docs.txt`(文書の生成用)は python として数えられる。python の製品の直下の `package.json`(husky・commitlint・prettier 用)は node として数えられる。どちらも現場でよく見る形(一般的な観察。件数の調べは無い: **未実証**)
- npm・pnpm の workspaces、Nx・Turborepo のモノレポは `packages/*/package.json` を数十持つ。目印1つにつき宣言を1つ求める形は、宣言の手数を目印の数に比例させ、写し漏れを生む
- G-5 のジョブは `config` の出力で `if:` を掛けている(gate-g5.yml 188・242 行)。集約は `if: always()`(459 行)。GitHub は `if:` で飛ばされたジョブを Success と報告する(外部 SRC-A1・A2)。スタックごとのジョブを `if:` で飛ばす形にすると、同じ穴を作る

## R-1 正本の方式

- **推す案**: (c1) 複数のアダプタ。加えて、宣言と目印の突合を PR ごとの契約検査(既存の `contract` ジョブ、gate-g5.yml 63 行)で行い、合わなければ G-5 を失敗にする。軽の2委員と同じ結論で、次の3つの条件を付ける
  1. **CI の形は matrix**: スタックごとの段は `strategy.matrix` の並列のジョブで回し、直列にしない。壁時計の増え方は「最も遅いスタック」で決まり、「合計」で決まらない(GitHub Actions の一般的な性質。本標準の手元での計測は無い: **未実証**)。runner の分は合計で増える。ここは採用者へ開示する
  2. **飛ばさない**: 宣言したスタックの段は、変更のパスで `if:` を掛けて飛ばさない。毎回の PR で全部の宣言済みのスタックを走らせる。飛ばしは Success になり(SRC-A2)、「走ったか」を記録から読めなくなる
  3. **アダプタの外の言語にも経路を置く**: 配列の要素に、`none` と同じく手でコマンドを書く要素(作業の場所つき)を認める。rust・java が混ざる現場は普通にある。経路が無いと、採用者は製品の全体を `none` へ寄せ、node・python のカバレッジまで #330 の未実施へ落とす(survey 5.4 の none の行)。手書きの要素は基準1・2 を満たせる。基準3 は測れなければ未実施と表示し、通過に数えない
- **理由**: 欠陥③の主な欠けは基準1(テストが走らない)で、走らせられるのは (c1) だけ(survey 7節 (c))。Nx・Pants・Bazel は1つの PR で複数のスタックを走らせる前提で作られている(外部 SRC-B1・B2・B4)。現場の道具と同じ型なので、持ち込みの抵抗が最も小さい
- **(c2) を落とす理由**: 0節の誤検出で、混在でないリポジトリまで止まる。止めた後の受け皿が無く、持ち込みそのものができなくなる(ADR-0085 決定2 の 84〜85 行と同じ型の害)。持ち込みの時点だけを見るので、開始の後に足した python も塞げない
- **(c3) 単独を落とす理由**: 開示しても G-5 は通る。D-1 の secretScan は開示されていたが、誰も止めなかった(survey 5.5)。現場の判定者は、緑の集約を見たら開示の4項目めまで読まない(現場の経験。**未実証**)
- **(d) を落とす理由**: python が走らない構成では測る材料(coverage.json)が無い。基準1・2 を受けない。#360 の IMPL-0259 として進める
- **採らない案(現場から足す)**: 変更の範囲で走らせるスタックを選ぶ形(Nx の affected 型)を G-5 には採らない。選択型は入力の宣言から漏れたものを走らせない(SRC-B1・B2 の開示された限界)。CI の時間の節約は採否の理由にしない。採用者が自分の CI で affected を使うことは妨げないが、G-5 の判定の材料にしない

## R-2 宣言と除外

- **推す案**: 宣言は「スタック × 作業の場所(ディレクトリ)」の単位で求める。目印の単位では求めない。作業の場所の配下にある同じスタックの目印は、宣言済みとして数える。workspaces の `packages/*/package.json` は、直下の node の宣言1つで覆われる
- **除外**: 検査の外とする目印は、パス(glob を認める)・理由の区分・記名で登録する。理由の区分は閉じた列挙にする: 道具(整形・commit の規約用)、文書の生成、試験の材料(`testdata/` 等)、取り込んだ第三者のコード。区分に当たらない除外は認めない。記名は人。AI の名義を認めない(軽の反対の委員と同じ)
- **承認者**: 除外の一覧の変更は、閾値・除外設定と同じ扱いにする。製品のコードと同じ PR で除外の一覧を変えたら失敗にする(既存の分離、survey 5.6 の場合 B の型)。新しい承認者の役は置かない。役を足すと、ソロや2名の採用者が承認者を立てられず、除外の一覧を書かない方向へ逃げる
- **誤検出の扱い**: 契約検査の失敗の文は、目印のパスと、直し方の2つ(宣言へ足す・区分を付けて除外へ足す)を名指しで出す。直し方の分からない失敗は、現場では `none` への退避か除外の濫用を生む
- **広すぎる除外への歯止め**: glob の除外で覆った目印の数と、覆った配下のファイルの数を、保証の開示に毎回出す。`**` だけの除外、宣言済みの作業の場所と重なる除外は認めない
- **採らない案**: `package.json` の `scripts.test` の有無や依存の中身から「製品かどうか」を機械で推す形は採らない。ADR-0085 決定2 の「設問の回答を検出の結果で埋めない」に触れ、外れたときに黙って外れる。宣言の初期値を機械で埋める形も採らない。事前点検は候補の一覧を示すだけにして、人が宣言か除外かを記名で決める
- **留保**: 除外の区分の列挙が現場の形を覆い切るかは確かめていない(**未実証**)。列挙に「その他(理由を書く)」を置くかは起案に委ねる。置くなら、その他の件数を開示に出す

## R-3 暫定の扱いと既存の採用者

- **推す案(c1 が降りるまで)**: G-5 の実行時に、構成のアダプタの外のスタックの目印を検出したら、保証の開示 項目4 と集約に出す。語は「**未充足**(検査していない: `services/api` の python)」とし、主の語は未充足にする。止めはしない
- **止めない理由**: 降りる前に止めると、混在の採用者には `none` へ寄せる経路しかない。その経路は基準3 を未実施へ落とす(survey 5.4)。止めると、守れる手段の無い義務を課すことになり、現場は持ち込みを諦めるか、目印を消して通す。目印を消して通すほうが、未充足を表示しながら通るより信頼性を下げる
- **条件**: G-5 の判定者は、未充足の行を判定の記録へ書き写して受け入れを記名する(9001 8.6 の「権限者の受け入れと記録」の型。外部 SRC-D4、二次資料)。受け入れの記録が無いまま未充足の G-5 を通過にしない。期限は暫定の EV の見直しの月で区切る
- **旧い構成(文字列の `stack`)**: `migrate` で要素1つの配列へ変換する(ADR-0085 決定5)。変換は意味を変えない。c1 が降りた後、混在の旧い採用者は契約検査で落ちる。ADR-0085 決定6 に従い、落ちる検査と直し方を列挙し、事前点検の目印の事実(`facts.stacks`)から宣言と除外の**候補**を示す。候補は人が確かめて記名する。猶予の期間は置かない。未充足の表示が続く間は、それ自体が猶予の開示になる
- **採らない案**: 「検査していない」を主の語にする案。対象なし・未実施と並ぶ中立の状態に読め、通過の一種と受け取られる。基準1 は満たされていないので、主の語は未充足にする

## R-4 記録・ADR

- **ADR**: 新しい ADR を起こし、ADR-0085 決定2 の理由(88 行「黙っては外れない」)が単一スタックの前提だったことと、混在では宣言と契約検査で同じ性質を保つことを書く。ADR-0085 の本文は書き換えない。ゲート契約(証跡のキーをスタックごとに持つ)の変更も同じ ADR で決める
- **本文**: G-5 基準1・2・3・5 に「製品のすべてのスタック」を明記する。カバレッジはスタックごとに基準値と比べ、合算しない(合算は厚い側が薄い側を隠す)
- **EV**: 次を根拠水準マークで開示する。CI の時間の増え方(matrix の並列の前提を含む)、除外の区分の網羅、混在の試行が手元の1例(Windows)だけであること、判定者が開示を読まない傾向
- **IMPL**: 複数のアダプタ・契約検査・除外の一覧の分離の検査を `state=undelivered` で付け、降りるまで表示し続ける(CLAUDE.md #222)
- **分担**: 差分の網羅率は #360(IMPL-0259)。D-1(secretScan が対象なしで通る)は別の Issue へ切り出す。全アダプタに当たり、混在に依らない
- **採らない案の記録**: (c2)、(c3) 単独、(d) を受け皿にすること、変更の範囲でスタックを選ぶ形、`if:` でスタックの段を飛ばす形、製品かどうかの機械の推定、宣言の初期値の機械の埋め込み、除外の承認者の新しい役。どれも理由とともに ADR の「採らなかった選択肢」へ書く
