## 3. 現物と計画のずれ

1. **閾値割れの失敗を出すのは `mutation-stage.mjs` の `evaluateMutation`**(178 行。`adapter.mjs` は呼ぶだけ)。B28 intake の計画は `adapter.mjs` だけを挙げていた。U6 の本体は mutation-stage.mjs に入る。
2. **段のジョブは台帳を読まない**。`adapter.mjs`・`mutation-stage.mjs` に `debt-ledger`・`parseLedger` の参照は 0 件。段のジョブ(gate-g5.yml 407〜441 行)は PR の番号・作成者・先頭・レビューを受け取らず、`GH_TOKEN` も持たない。7.3 の帰属(第7章 7.3「承認した者本人のアカウントの操作で帰属を裏づける」、ADR-0106)を段で確かめるには、**gate-g5.yml の段のジョブに入力を足す**ことが要る。計画のファイルの一覧に gate-g5.yml が無かった。
3. **コマンドの終了コードが 0 でないと、段は `evaluateMutation` の前に終わる**(adapter.mjs 170 行)。README 項21 は「終了コードで合否を返せる道具(Stryker・cosmic-ray)」を案内している。道具の側で閾値を break に使う採用者では、閾値割れが道具の失敗として現れ、7.3 の経路に乗らない。移行の注意が要る。
4. **IMPL-1029 の note の「7.3 では受けない」**は、本文(assurance-case.md 97 行)の「段のコマンドが空のまま…7.3 を用いてはなりません」を指すと読めるが、単独では「閾値割れも受けない」とも読める。F.6 284 行と ADR-0244 決定5 は閾値割れを 7.3 の対象にしている。編集の直しの対象(意味を変えない)。
5. **集約(G-7)の側も変える必要がある**。`unjudgedGateExceptions`(exception-expiry.mjs 455〜465 行)は G-5 の行を常に欠落の文にする。集約の呼び出し(aggregate-evidence.mjs 2951〜2976 行)は `gateExceptionRows` に `{ label, t }` だけを積み、行の内容(印)を渡さない。ゲートの行の帰属の確かめ(`ledgerRowUnbacked(r, signer)`、2688 行)は material を渡さないため、(B) 行を入れた PR の作成者・承認者に限られ、(A) 対象の PR の上の宣言行のレビューを読まない。段で (A) で受けた行が G-7 で「帰属を確かめられない」の欠落になりうる。**aggregate-evidence.mjs に触れないと端から端まで閉じない**(B30 が変更中なので後回しの単位にする)。
6. **push の経路**: 既定ブランチへの push でも gate-g5(workflow_call)の段 mutation が走る(gate-g5-push.yml)。案件の条件に当たる構成、またはトレーラ R1 の push では段が必須になる。PR で 7.3 を受けてマージした後の push で、同じスコアの閾値割れが再び失敗になる。計画に無かった論点。
7. **週次の起動では R1 を判定できず必須の側に倒れる**(r1Of は pull_request・push 以外を unreadable にする)。IMPL-1036 を降ろすには、段に週次の型を足すことが要る。
8. ADR の番号: 0243 は空いている(本体 origin/main と作業ツリー b11・b28・b29・b30・b31 の adr/ に 0243 は無い)。B30 の作業ツリーにも無い。push の直前に照らす。
9. 範囲外の観察(実行していない。コードを読んだだけ): check-pr の `exceptionFor`(748〜811 行)は行の状態と期限の読めることを見るが、期限の超過(突合の日より前)を見ない。規模の超過の旧い行と 7.9.4 の行が、期限を過ぎても G-5 の時点で有効に数えうる。G-7 の集約は `lapsedExceptions` で欠落に数えるので出荷では漏れない。U6 の行の照合は期限の超過を見る(ruling-draft-1.md)。既存の挙動は B30 の範囲(check-pr)なので、ここでは記録だけにする。
