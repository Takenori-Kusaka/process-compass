## 1. U6a — 段 mutation が閾値割れを台帳の行で受ける

### 1.1 変える挙動

- 受ける対象は**閾値割れだけ**: 段のコマンドが終了コード 0 で終わり、`mutation-result:` の行の構文が正しく、スコアが数値で、閾値(基底の構成から読んだ値)より小さいとき。案件の条件の段と R1 の段の両方に同じく掛ける(F.6 284 行の名指しのとおり)
- 受けたとき: 段は成功で終わる。出力に `閾値割れを第7章 7.3 の例外承認 D-NNN で受けた(score=…、閾値 …、下限 …、承認した者 …)` の1行を出す(証跡)
- 受けないとき: いまと同じく失敗。候補の行(対象が当該の PR を指す区分「例外」の行)ごとに、受けない理由を出す。候補が無ければ「台帳(docs/debt-ledger.md)に `G-5 PR-<番号>` の行が無い」と、行の書き方の所在(exception-paths.md)を出す
- 受けないもの(いまのまま失敗): 段が空・閾値が未設定か数値でない・出力の行が無いか壊れている・コマンドの終了コードが 0 でない・規制要件の段(regulatory)の不合格・手動の実行(workflow_dispatch)・PR を経ない push

### 1.2 台帳の行の約束(決定可能な条件。すべてを満たす行を1つでも見つけたら受ける)

| # | 列 | 条件 | 満たさないとき |
| --- | --- | --- | --- |
| 1 | 区分 | `例外` | 候補にしない |
| 2 | 対象 | 印を除いた値が `G-5 PR-<当該の PR の番号>` と一致する(`gateExceptionTarget` が gate=G-5、subject=PR-N と読む。番号は完全一致) | 別の PR・別のゲート(`G-6 PR-12` など)・`PR #12` の形は候補にしない。`PR #12` の形で内容に印がある行は、理由「対象は `G-5 PR-12` の形で書く」を出す |
| 3 | 内容 | 先頭が印 `変異試験の閾値割れ(下限: <0〜100 の数値>)`(`*`・`` ` ``・`_` と全角を正規化して読む。`fastTrackMarkOf` と同じ読み方) | 印が無い・下限が数値でない → 受けない(理由: 段の不一致か下限の欠落) |

| 7 | 承認した者 | 記入がある・名簿の人へ対応づく(`resolveSigner`)・AI の名義でない(`aiNameBlocked`)・PR の作成者でない・作成を指示した者でない(`instructorsOf`。指示者が名簿へ対応づかなければ受けない。`exceptionFor` と同じ) | 欄が空なら「承認した者が未記入」で受けない |

| 9 | 帰属 | (A) だけ: 承認した者本人が、当該の PR の上で宣言行 `例外承認: D-NNN` のレビューを出し、レビューの対象のコミットが PR の先頭と一致する(`exceptionReviewBacking`。名義の共有の扱いも同じ関数に従う) | レビューが無い・読めない・先頭が変わった → 受けない。「レビューを出した後は gate-g5 の最後の実行を再実行する」と出す(gate-g5.yml 23〜26 行の既存の案内と同じ) |

- 行の出所: 既定ブランチの先端の台帳(check-pr の `--policy-base` と同じ点)と、PR の先頭の台帳。**基底にある ID は基底の内容で読む**(PR の中で下限や期限を書き換えても効かない)。PR の中で足した行は (A) で裏づけたときだけ数える(`exceptionFor` と同じ)
- 段の実行の日: adapter.mjs が `localDay()` を渡す。関数は日付を引数で受け、時計を読まない(回帰の時計依存を避ける)
- 判定者の欄が空・期限切れ・対象の段の不一致は、上の表の「受けない」のとおり。どれも段は失敗のままで、理由を行ごとに出す

### 1.3 段のジョブに足す入力(gate-g5.yml)

- PR の経路: `PIT_IN_PR_NUMBER`・PR の作成者(login と数値の id)・`PIT_IN_PR_HEAD`(先頭の SHA)・既定ブランチの名。レビューの一覧は、pr-rules と同じ取得の形(`gh api …/pulls/<N>/reviews --paginate`。`GH_TOKEN: github.token`)で一時ファイルへ書き、所在を渡す。取得に失敗したら空にし、段は「レビューを読めない」として受けない
- 既定ブランチの台帳: `fetch-depth: 0` で取得済み。`origin/<既定ブランチ>` から読む
- push の経路(intake-1.md §3 の6): HEAD が PR-N のマージのコミットであることを、ホスティングの記録(`gh api repos/<repo>/commits/<HEAD>/pulls` で、merged で `merge_commit_sha` が HEAD と一致する PR)で確かめられたときだけ、PR-N の行を同じ表の条件で照らす。帰属 (A) は PR-N のレビューと PR-N の先頭で見る。確かめられない(PR を経ない push・API の失敗・該当が2件以上)ときは受けない
- 閾値と PR の本文の受け取りは変えない

### 1.4 集約の照合関数の改め(exception-expiry.mjs の中だけ)

- `unjudgedGateExceptions` は、G-5 の行のうち **対象の subject が `PR-<番号>` の形で、かつ行の内容が渡されたときは印を持つ** 行を返さない(欠落にしない)。行の内容が渡されないとき(U6c の前の集約の呼び出し)は subject の形だけで判定する。ほかの G-5 の行(`G-5 P-001` など)はいまのまま常に欠落
- 欠落にしない行も、既存のゲートの行の照合(承認した者・理由・期限・帰属。aggregate-evidence.mjs 2945〜2976 行)と、期限切れの数え方(`lapsedExceptions`)、未回収の表示(項目「ゲートの判定を対象とする例外承認(未回収)」)に載ったまま。7.3 の要求事項5(回収まで報告の対象)はこれで満たす
- 印の読みと行の約束は exception-expiry.mjs に1か所で置き(例 `mutationExceptionMarkOf`・`mutationExceptionFor`)、段と集約が同じ関数を使う

## 5. ADR-0243 に並べる決定と採らない案

### 決定

1. G-5 の段 mutation の閾値割れ(コマンドの終了 0・行の構文が正しい・スコアが閾値に届かない)だけを、技術負債台帳の区分「例外」の行で受ける。案件の条件の段と R1 の段の両方に掛ける(附属書F F.6 の名指しの実装。ADR-0224 決定7・ADR-0244 決定5)
2. 行の約束は §1.2 の表の9条件。すべて決定可能で、段と集約が同じ関数で読む
3. 帰属は対象の PR の上の承認した者本人の宣言行のレビュー(先頭一致)に限る。基底の行も同じ
4. push の経路は、HEAD が PR-N のマージであるとホスティングの記録で確かめたときだけ、PR-N の行で受ける。PR を経ない push・手動の実行は受けない
5. 集約は、対象 `G-5 PR-<番号>` で印のある行を IMPL-0996 の「常に欠落」から外し、既存の 7.3 の照合と回収の追跡に載せる。ほかの G-5 の行は欠落のまま
6. [ADR-0222](/process-compass/adr/0222-b20-run-record-isolation-and-provisional-license/) 決定1 の理由の一文「対象が G-5 の判定の行は、常に例外承認として対応づけず欠落になる」を、閾値割れの行について狭める。決定1(暫定のライセンスの許可を構成で受け、台帳で受けない)は変えない。ライセンスの暫定の許可は印を持たず、本 ADR の行の約束に当たらない
7. [ADR-0217](/process-compass/adr/0217-b20-exception-use-display-and-record-checks/) の影響の節の「止めるのは、7.9.4 の行の欠落(決定2)だけである」を、枠の超過の拒否(IMPL-0630。G-5)について置き換える(ruling-u5-returns.md の4)。採用済みの ADR の本文は書き換えない
8. R2 の週次の定期実行(IMPL-1036)を、gate-g5 の外の週次の workflow で降ろし、閾値割れを合否にしない

### 課さないと決めたこと・採らない案

| 案 | 採らない理由 |
| --- | --- |
| 対象を `PR #N`(変更の行)で書かせる | 集約の変更の照合(aggregate-evidence.mjs 2900〜2943 行)が、その行を当該の PR の例外承認として対応づけ、G-6 を経ない変更の例外(区分を問わない)にも数えうる。G-5 の閾値割れの承認が、別の基準の例外として効く |
| 帰属に (B)(行を入れた PR の作成者・承認者)を段で受ける | 段のジョブにホスティングの照会を広く足す。行は1つの PR に限る記録で、対象の PR の上のレビューはいつも出せる |
| 下限を求めない | 1行が同じ PR の後のコミットのより低いスコアも通す。先頭一致のレビューで多くは塞がるが、再実行のスコアの揺れと、何を受けたかの記録(要求事項2)が台帳に残らない |
| 終了コードが 0 でなくても行が読めれば受ける | 閾値割れと道具の失敗を見分けられない(決定可能でない) |
| 受否を pr-rules(check-pr)で決める | 段の結果は段のジョブにあり、ジョブ間で結果を渡す結合が増える。check-pr は並行の束が変更中 |
| 集約が PR ごとの段のスコアと行を突き合わせる | 段の出力はジョブのログで、保持の期限がある。段の時点で受否を決め、行を台帳に残す |
| 規制要件の段の不合格を受ける | ADR-0224 決定7 のまま |
| CL1 以上の行に承認者の追加の独立(上位の者など)を課す | ADR-0153 決定3 のまま。EV-0295 の差し替え条件で再審議する |
| push の経路を一切受けない | 受けた PR のマージの後に、既定ブランチの G-5 が必ず失敗の表示になる。失敗の表示を見過ごす習慣を作る |
| 期限の書き換え(延長)を段で見る | G-7 の IMPL-0787 が範囲の始点と終点で見る。段で二重に持たない |
| R2 の週次を別の Issue へ付け替える・採用者に委ねる | 合う open の Issue が無い。先例の cron で決定可能に降ろせる |
| 週次の実行で閾値割れを失敗にする | H.1「合否条件にしない」 |
| F.6 の本文に行の約束を書く | 手順は手引きへ(所有者の方針(1))。条文は結果(閾値割れを 7.3 で受ける)と証跡(段の出力と台帳の行)まで |
