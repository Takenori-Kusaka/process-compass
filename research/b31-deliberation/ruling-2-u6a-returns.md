# 束 B33(B31 の続き)議長の裁定 その2 — U6a の実装が返した点

裁定 2026-11-26。材料: `impl-u6a.md` §議長へ返す点、`ruling-1.md`。段は軽のまま(新しい義務は無い)。

1. **作成者の排除の重複**: 行の側の判定を残す。理由: 理由の文言を早く正しく出すため(受けない理由が「作成者」と読める)。単独では陰性の確認で観測できない事実は `impl-u6a.md` と ADR-0243 の決定の注に開示する。重複は同じ部品(`exceptionReviewBacking`)の呼び出しで、別の定義を作らない
2. **`@アカウント` の指示者**: 受けない側に倒す実装を採る(段はトークンで識別子を確かめない。確かめられないものを受けると、指示者の排除が抜け道になる)。U6b の手引き(exception-paths.md)に「作成を指示した者を `@` で書いた PR では、閾値割れを台帳の行で受けられない。表示名で書くか、7.3 の例外承認を既定ブランチの台帳に先に入れる」を書く
3. **`exceptionFor` との二重の定義**: 採る。check-pr は対象の形(`PR #N`)が違い、入力の形が違う。集合の一致の試験は足さない。ADR-0243 の課さないと決めたことに1行で書く
4. **gate-g5.yml のコメント**: 実装のとおり採る
5. **mutation-stage.mjs の冒頭コメント(機械が見る範囲)**: U7 の実装の担当が、U6a と U7 の両方を反映して更新する

U6a の 5145d6b は独立の突合を経ていない。突合の1巡目は U6a・U6b・U7 の全体を見る(`ruling-1.md` §1.1 の順)。
