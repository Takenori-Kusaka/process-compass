## 結論(先に)

- 案の骨格(閾値割れだけを台帳の行で受ける・帰属は (A)・規制要件は受けない・`PR #N` の形は採らない)には反対しない。
- 削るべきは次の3つ。(i) U6a で `unjudgedGateExceptions` を先に緩めること(偽の通過を作る)、(ii) 印の下限(`下限: N`)と score ≥ 下限の機械の比較、(iii) U7 の「比較の起点=7日前」と「閾値割れは注意だけ」。
- 直すべきは、U7 の表示(delivered・machine)が実態より強い点と、U6c の前の途中の状態(下の点4)。

## 1. 台帳の行の約束(9条件)

**反対する(部分的に)。**

方針は「条文は結果と証跡まで、手順は手引きへ。機械は決定可能な条件だけ」。9条件のうち、1・2・5・6・7・8・9 は既存の `exceptionFor`・`exceptionReviewBacking` と同じ関数の再利用で、新しい定義を増やさない。反対しない。争点は 3・4 だけである。

- **下限は、守る相手がいない**。下限を書くのは行の書き手(多くは PR の作成者)で、`0〜100` を許すため `下限: 0` で任意のスコアを通す。作成者が下限を決める統制は、作成者に対する統制にならない。残る効用は「承認した後に同じ先頭でスコアが揺れて下がった再実行」だけである。しかし帰属 (A) が「先頭の SHA と一致するレビュー」を要求するので、コミットが変われば承認は失効する。同じ先頭での再実行の揺れは、承認した者が見たスコアとの差で、承認した者が段の出力(証跡の1行)で確かめる手順にできる(manual)。
- **新しい書式を足す代償**: 印の構文(括弧・数値・全角と強調の正規化)、受けない理由の文言、試験の ng が条件ごとに1つ(下限だけで3〜4個)。破られたとき失うものは「承認した者が見たより低いスコアが通る」ことで、承認者の目の前の PR の中に限られる。方針の「破られたとき誰が何を失うか」で細かさを決めると、この細かさは釣り合わない。
- **対案A(推す)**: 印は固定語 `変異試験の閾値割れ` だけ(数値なし)。下限の欄・機械の比較・ng の試験を削る。段の出力の1行(スコア・閾値・行の ID)を、承認した者が対象の PR の宣言行を出す前に読む手順を exception-paths.md に書く。下限割れの「何を受けたか」は出力の1行と台帳の受容した理由(必須欄 8)で残る。IMPL-0931 の note に「受けたスコアの妥当性は manual(確かめる者: 承認した者・G-6 の判定者)」と開示する。
- **対案B(推さない)**: 帰属 (A) のレビューだけを根拠にして、行の約束は 1・2・5・9 の4条件にする。期限・承認者の AI 名義・指示者の排除を外すと、`exceptionFor` と食い違う別の定義ができる。却下。
- **対案C(推さない)**: 既定ブランチに既に入った行だけを受ける。閾値割れの PR 自身がマージされるまで行が既定ブランチに無いので、割れた PR を通せない。循環で、7.3 の経路が成立しない。却下。
- **抜け道の確認**
  - 自分で足して自分で通す: 作成者本人・指示者は 7 で除外、(A) は承認した者本人のレビューが要る。共謀(作成者と承認者が結託)は 7.3 の既存の限界で、新しい穴ではない。反対しない。
  - 他の PR の行の流用: 対象が `G-5 PR-<当該>` の完全一致と (A) の先頭一致で塞がる。反対しない。
  - 期限 2099 年: 上限が無い。ただし `IMPL-0601` の既存の行も同じで、今回の新しい穴ではない。反対しない。ただし期限の遠さを機械では見ず、G-6 の判定者が読むと README 項23 に1文書く。低。
  - 下限 0: 上のとおり。対案A なら存在しない欄なので問題が消える。
  - 先に気付いた穴: **段のスコアは PR が自分で書く段のコマンドの出力**で、承認と下限は「コマンドが正直に走った」前提に立つ。EV-0339 の既存の限界で、行の約束では閉じない。案はこれを触れている(§1.5 最終行)ので、反対しない。

## 2. push の経路(§1.3・決定4)

**反対しない(ただし簡素化の余地を記録する)。**

- 受けない場合に失うもの: 受けた PR のマージの直後、既定ブランチの gate-g5(push)が必ず赤になる。G-7 の集約(U4b)は段のジョブの success を要求するので、**出荷判定が止まる**。直す手段は、スコアを閾値へ戻す新しいコミットだけである。つまり「7.3 で受けた」ことが、既定ブランチでは意味を持たない。誰が失うか: 受けた採用者(出荷が止まる)。7.3 の経路が実質、使えない。信頼性は上がらず、「赤を無視する習慣」だけが残る。
- 受ける場合に失うもの: 照会の API(`commits/<sha>/pulls`)が1つ増え、失敗・複数一致は「受けない」の側に倒す。失うのは速さと試験の個数だけで、安全の側の失敗である。
- 簡素化の対案: HEAD が PR-N のマージであるという照会を、`git log` の `(#N)` の解析に代えるのは決定可能でない(マージ方式に依る)。却下。案のままでよい。
- 残る穴(記録): squash でない merge commit・rebase マージでは `merge_commit_sha` の一致が崩れる場合がある。実環境の未確認(#361 の範囲)を IMPL-0931 の note に書く。中ではなく低。

## 3. U7(R2 の週次)を B31 で降ろす裁き

**反対する(降ろし方に。降ろすこと自体には反対しない)。**

- 表示が実態より強い。案の machine の検査の中身は「workflow が在る・cron が週次・空のコマンドが終了 0・行が壊れていれば失敗」である。つまり**既定のテンプレートのままでは何も測らず、緑で終わる**。それを delivered・machine と出すと、H.1 の「R2 は週次」を守ったように見える。ADR-0028(未達と省略の区別)の線では、これは「省略(未実施の事実は出力に残る)」で、出力に残るのは Actions のログ(保持の期限がある)だけである。誰も読まない。
- 実環境の事実: 定期実行は既定ブランチでしか動かず、公開リポジトリでは活動が無いと無効にされうる。案は「cron の実環境の未確認」を開示するが、**無効化されたことを検知する経路が無い**。検知できない定期実行を machine と表示するのは、H.1 の適合の主張の根拠として強すぎる。
- 「閾値割れは注意として出す」は、緑のジョブの注釈で、誰も見ない。H.1 の「合否条件にしない」は「マージを止めない」の意味で足りる。**ジョブを赤にする**ほうが見える(needs とブランチ保護に入らなければ止めない)。案が「失敗にしない」を H.1 の「合否にしない」から導くのは、読みすぎである。
- 「比較の起点=既定ブランチの7日前の最後のコミット」は、H.1 の文面に無い新しい定義である。方針(細かい定義を増やさない)に反する。H.1 は「週次の定期実行」までで、範囲は規定しない。
- **対案(推す)**: workflow は降ろす(schedule + workflow_dispatch、`PIT_IN_MUTATION_MODE=weekly`)。ただし (a) 比較の起点の新規ロジックは入れず、段のコマンドが自分の範囲を決める(コマンドの責務。方針と同じ)。(b) 閾値割れは赤にする(needs・保護に入れない)。(c) IMPL-1036 は delivered とするが check は **manual**(確かめる者: 週次の結果を読む者。workflow が動いているかの確認を G-6 の判定者の手順に1行)、note に「既定は空で何も測らない」「無効化の検知は無い」を書く。machine にできるのは「workflow の存在と形」で、それは note に分けて書く。
- 競わせた案: plan=adopter / undelivered のまま開示。**推さない**。H.1 の表の適合の主張は template に依り、cron の先例が同じ型で在る。降ろしたうえで強さを正しく表示するのが信頼に合う。undelivered は、降ろせるものを降ろさないことになる。
- 新しい EV(週次の所要時間の実測が無い)の追加は、方針どおり必要。反対しない。

## 4. U6c の前に IMPL-0931・1029 を undelivered のまま template を push する途中の状態

**反対する。案の途中の状態には、偽の通過が1つある。**

- 案 §1.4 は、U6a で `unjudgedGateExceptions` を「subject が `PR-<番号>` の形で、内容が渡されないときは形だけで判定する」と緩める。U6c の前の集約は内容を渡さないので、**印の無い `G-5 PR-12` の行も、G-7 で欠落にならない**(= 7.4 の禁止「G-5 を実施しないまま 7.3 で進める」を見る機械が一時的に弱まる)。案 §3 は「PR の側の欠落は残る」とするが、それは check-pr 側の別の統制で、G-7 の IMPL-0996 の代わりにならない。しかも「弱く見せる向きではない」という案の文は、この点では当たらない。IMPL-0996 は delivered・machine のまま表示され、実態だけが後退する。**偽の通過(安全でない向き)**で、重大度は高い。
- 逆向きの偽の欠落もある。(A) で受けた行は、U6c の前の G-7 で「帰属を確かめられない」の欠落になる。止める側なので安全だが、採用者には「段は通ったのに G-7 が赤」と見える。案はこれを開示するとしている。偽の欠落は許容できる。偽の通過は許容できない。
- **対案(推す)**: `unjudgedGateExceptions` の変更は U6c と同じ単位で入れる(U6a では触らない)。U6a・U6b だけの間は集約は常に欠落のまま(いまのまま)で、README 項23 に「段で受けた行は、U6c まで G-7 で欠落と出る」と開示する。偽の通過の窓がなくなる。順を変えるだけで、単位の数は増えない。
- もう一つの対案: U6a・U6b・U6c を B30 の push の後にまとめて1回で push する。B30 の待ちが長いなら template の中間の push 自体を避けられる。ただし、template のコミットごとの bundle 退避の規律と両立する。
- 状態表示: IMPL-0931・1029 を U6c の後まで undelivered に保つ案には反対しない(安全の側)。

## 5. 既存の決定との矛盾・突合の見落とし

- **ADR-0153 決定2 の「境は、G-5 の判定なら当該の対象の集約の結果が存在するか」**。案は「段を実施しスコアを測った後なので当たらない」と書く(§6)。しかし閾値割れを段が受けて緑にすると、gate-g5 の集約の結果は緑で存在する。つまり「集約の結果が在る」ことは、受けた行が機能したことの帰結で、**行と結果が機械で結ばれていない**(段のログは保持の期限がある。案自身が「集約が段のスコアと行を突き合わせる」を不採用にした理由)。IMPL-0996 の旧い理由「行を集約の結果へ結べない」は、閾値割れの行についても**まだ当たる**。案は「段が行を結ぶので当たらない」と書くが、結んだ証拠が G-7 に届かない。G-7 が見るのは、印と形だけである。**突合の見落とし**。対案: ADR-0243 と IMPL-0996 の note に、「G-7 は行の形と帰属を見るだけで、段がその行で受けたことの確認は、段の出力の1行(ジョブのログ)と承認した者の宣言行に頼る」と開示する。manual と明記する。中。
- **ADR-0153 決定3**(CL1 以上に追加の独立を課さない)と **決定2 の後段**(実施した判定での個々の基準の未達は妨げない): 反対しない。矛盾なし。
- **ADR-0222 決定1 の理由の一文を狭める(案の決定6)**: 採用済みの ADR の本文は書き換えない(CLAUDE.md)。案は「狭める」と書くが、実際は置き換えである。ADR-0217 の決定7と同じく「置き換え」と表現を揃える。編集。低。
