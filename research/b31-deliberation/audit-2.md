## 所見

高 0・中 0・低 3。

### 低1 「台帳が無い」と「読めない」の区別が `cat-file -e` に掛かっており、「読めない」の分岐は試験で固定されていない

- 所在: `template/scripts/gate/mutation-stage.mjs:200-203`
- 入力と起きること: `git cat-file -e <点>:docs/debt-ledger.md` は、木に台帳の項目が無いときだけでなく、項目はあるが blob のオブジェクトが手元に無い・壊れているときにも失敗する。このときは「基底に台帳が無い」へ入り、基底の行も PR の中で足した行として PR の側の内容で読む(期限・状態の書き換えが効く。ただし承認した者本人の (A) のレビューは要る)。`cat-file -e` が通った後に `git show` が失敗する場面はほぼ起きないので、「読めない」で受けない分岐は実質に働かない。外しても 232 件は通った(m4)
- 程度: 準拠テンプレートの取得は `fetch-depth: 0` の完全な複製で、blob の欠けは通常起きない。一般的な git の失敗(safe.directory など)は直前の `rev-parse` が受けない側で拾う(m3 で固定)。承認した者の目の前でしか起きないので低
- 直し方の案: 有無を木だけで判る問い(`git ls-tree --name-only <点> -- docs/debt-ledger.md`。出力が空なら無い、null なら読めない)で分け、その後の `git show` の失敗を「読めない」とする。試験は、`postBase` で基底の blob を消した(または `GIT_OBJECT_DIRECTORY` を差し替えた)場面の ng を足す。直さないなら、impl の記録に「無いと読めないの区別は `cat-file -e` による」と開示する

### 低2 ADR-0243 の ADR-0115 決定1 との突合が、偽れる材料を「PR の記録の一時ファイル」だけと書く

- 所在: `src/content/docs/adr/0243-g5-mutation-breach-accepted-by-ledger-row-and-weekly-run.md:51`
- 入力と起きること: `adapter.mjs` は段のコマンド(PR の側の試験)を走らせた後に `breachExceptionOf` を呼ぶ。PR の側のコードは、PR の記録の一時ファイルだけでなく、`${RUNNER_TEMP}/base-process.config.json`(基底の構成の写し)・作業ツリーの台帳・`.git` の参照(`origin/<既定>` が指すコミット)も書き換えられる。同じ項の末尾「基底の構成・基底の台帳は基底から読み、取れないときは作業ツリーへ倒さず受けない」は、PR の側のコードが偽らない限りの話で、読み手には基底からの読みが偽りに強いと読める
- 程度: 同じ項が「EV-0339 の manual と同じ水準で、新しい抜け道ではない」と開示しており、統制の水準の表示は正しい。列挙が実態より狭いだけなので低
- 直し方の案: 「受否の材料(PR の記録・基底の構成の一時ファイル・作業ツリーの台帳・リポジトリの参照)は、段のコマンドの後に読むので、PR の側のコードから偽れる」と列挙を広げ、末尾の文に「基底から読むのは、PR の側のコードが偽らない場合の誤りの防止で、改ざんの防止ではない」を足す(ADR の本文は採用済みでなければ直してよい。採用済みなら編集の指摘として議長が扱う)

### 低3 README と手引きの「受けないもの」に、基底の構成・基底の台帳を読む点が取れない場合が無い

- 所在: `template/README.md` の「受けないもの(失敗のまま)」、`template/.claude/skills/gate/reference/exception-paths.md`
- 入力と起きること: 基底に `process.config.json` が無い(構成を足す PR・取り込みの直後)、push の `before` が全 0(新しいブランチの最初の push)のとき、段は閾値割れを受けない。表示は「PR の記録を取れない場合」までで、この場合を挙げない。挙動は止める側で、表示より強い
- 直し方の案: 「受けないもの」に「基底(既定ブランチ・push の直前のコミット)の構成や台帳を読む点を取り出せない場合」を足す
