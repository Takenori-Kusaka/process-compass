## 2. 裁定

`draft.md` 4.1・4.2 の裁定の案を、次の1点を改めて採る。

- **開き直し**: 採らない(所有者の回答 Q2)。ワークフローは、所見のある閉じた Issue へ「この Issue を名指すマーク(識別子と所在)」をコメントし、実行を失敗にする。Issue の状態は変えない。同じ Issue へ同じ内容のコメントを繰り返さない(月次と push の契機で重ねて動くため、既に同じ所見のコメントがあれば足さない)

そのほかは案のとおり。

1. 対象は 14 件すべて(#359 が 7、#358 が 5、#289 が 1、#290 が 1)
2. 寄せ先: #326 ← IMPL-0145・0497、#355 ← IMPL-0132、#361 ← IMPL-0492、新規 X(#359 の残り)← IMPL-0283・0374・0377・0500・0175・0174、新規 Y(#358 の残り)← IMPL-0207・0200・0506・0510。寄せ先の Issue へ、受け入れ条件の案をコメントで足す
3. IMPL-0174 の `scheduled` か `adopter` かは本件で決めず、X の受け入れ条件に問いとして置く
4. `review=2026-11` の IMPL-0175・0283 は、降ろす方向を保ち 2027-05 へ延ばす
5. 検出は C + E。`npm run check` はオフラインのまま保つ。ADR-0084 の決定 R-4 の該当の1項を、新しい ADR で置き換える
6. 機械で閉じない部分(寄せ先の適否、ワークフローの実機での発火、無効化・障害)は manual とし、根拠水準マークで開示する

## 3. 採らない案

`draft.md` 4.3 の表のとおり。加えて次を記録する。

| 案 | 採らない理由 |
| --- | --- |
| 機械が閉じた Issue を開き直す | 所有者の決定。人が閉じた判断を機械が覆さない。食い違いは、コメントと失敗の表示を受けた人が、付け替えるか開き直すかを決めて解く。付け替えまで食い違いが残ることは、`implementation-marking.md` で開示する |
| #359・#358 を開き直して担い手にする | 所有者の決定。残りのマークだけを列挙した Issue のほうが、次に閉じるときの取り残しを防げる |

## 4. 統制の閉じ方

| 条件 | 閉じ方 |
| --- | --- |
| `issue=` の番号が実在し、種別が issue である | 機械(`lint:impl`。オフライン。写し `issue-index.tsv` との突き合わせ) |
| `issue=` が閉じた Issue を指さない | 機械(検査の外のワークフローと、手元の同じスクリプト)。公開は止めない |
| 寄せ先の Issue が担い手として合う | manual(付け替える者) |
| ワークフローの発火 | main へ入った後に確かめる。確かめるまで根拠水準マークで開示する |
