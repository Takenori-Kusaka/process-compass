## 3. L-7 を直さない理由

妥当。裁定と ADR-0130 決定2 の文言(コメントするジョブに付ける。`evidence-review.yml` と同じ付け方)に合う。ワークフローの契機は Issue を閉じたとき・main への push・月次・手動で、フォークの PR のコードを走らせる契機は無い。検出の手順が走らせるのは main のスクリプトで、gh の呼び出しは GET だけである。直さない理由は「ジョブを分けると成果物の受け渡しで結線の誤りの面が広がる」で、安さではなく信頼性の側の理由になっている。採らない案として `fix-round1.md` に残っている。

## 4. 試験の限界の開示

- 結線の試験は、`check-impl.mjs` のソースの文の形を正規表現で見る。変異 H のとおり、形を保って所見を捨てる編集には気付かない。`test-check-impl.mjs` にも `issueRefProblem` の陽性対照は無い
- 標準の側の開示: EV-0259 の本文は「純粋な関数と、スクリプト本体を `gh` なしで走らせる試験(終了コード 0・1・2 と `--issue`)だけを通しました」と書く。`lint:impl` の結線を試験で守っているとは、規約にも ADR-0130 にも書いていない。限界を書いているのは `fix-round1.md` だけである
- **標準での開示は要らない**と見る。規約が表明するのは「`npm run lint:impl` は番号の実在と種別を確かめる」という動作で、これは1巡目が実行で確かめている。限界は本リポジトリの道具の回帰の守りの話で、表示と実態の食い違いではない。記録(本書と `fix-round1.md`)で足りる

## 5. 新しい所見

### N-1(中) 入力を書き損ねると、黙って別の確認へ落ち、「すべて open」で exit=0 になる

- **所在**: `scripts/check-impl-plan-issues.mjs` の `argValue`(`process.argv.indexOf(flag)` の完全一致だけを見る。知らない引数を捨てる)
- **確かめ方**(実物の gh。#443 は 6 件のマークを持つ):
  - `node scripts/check-impl-plan-issues.mjs --issue=443` → 「計画の Issue は、すべて open の Issue です」exit=0
  - `… 443`(フラグを落とす)→ 同じ、exit=0
  - `… --issues 443` → 同じ、exit=0
- **中身**: 閉じる前の確認のつもりで実行した者が、H-1 と同じ表示を受け取って閉じる。gh が無ければ exit=2 で止まるが、閉じる者の手元には通常 gh がある。規約と ADR が書く形(`--issue <番号>`)そのものは正しく動くので、表示と実態の食い違いではない。「高」にしない
- **案**: 記録で開示して閉じる。直すなら、知らない引数と `--issue=` の形を exit=2 にする(決定可能な条件。規約の文は変わらない)。この直しは、範囲外の発見として既存の open の Issue へコメントで寄せる

### N-2(低) `--issue 443 444`(空白区切り)は 2 つ目を黙って捨てる

- 1 つ目だけで合否が決まる(コードの読みと、`--issue 443 444` が #443 の所見だけで exit=1 になった実行)。`--issue 99999 443` なら exit=0 になる。規約は `<番号>` 1 つ、スクリプト冒頭は `番号[,番号]` と書くので、書かれた形では起きない
- **案**: N-1 と同じ直し(余った引数を exit=2)に含める。記録で閉じる

### N-3(低・編集) EV-0259 の本文に「月次の契機」が 2 回ある

### N-5(低) 「月次の契機が補う」は、ワークフローの無効化には効かない

### N-6(低) マーク 0 件の exit=2 が、ワークフローでは「open ではないマークがあります」と表示される
