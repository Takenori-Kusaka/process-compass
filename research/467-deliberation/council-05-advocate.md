## 3. 案・実測の事実の誤り

1. **M-1**: 出所を「records への push のコミットの作者・時刻」としている。ADR-0070 / `recording.md:11-15` の出所は承認レビューの `user.id`・`submitted_at`。かつ機械が出す欄としては**既に降りている**(`gate/SKILL.md:13,73`)。欄数の削減見込み(要旨の出荷 −4×2、立ち上げ C-21 −4)は二重の数え。ただし「判定者の手入力でなくてよい」の機構が実際に働いているかの実行での確認は、していない
2. **Y-9 D-07**: 「読み手が定まらない」は誤り。`roles-responsibilities.md:1639-1641`(IMPL-0226、確かめる者: AI 維持管理者の四半期の棚卸し)
3. **Y-1 項目4**: 「機械が止める」は過大。ロックの外は一覧を出すだけで合否に使わない(`template-repository.md:403`)
4. **Y-8 D-08**: 負担が無い項目をやめる候補に数えている(空のコマンドは人の手を要しない)。実際の欠陥は「表示と実態の食い違い」。また ADR-0243 決定8 の経緯が triage に無い
5. **M-4**: `G-8.md:43`「この3行を AI が埋めない」を見落としている。標準の明示と衝突する。triage §0 の「決定可能な条件」は、機械が既定値を書くことの許可にならない
6. **G-2**: ADR-0159 決定2(結合キーを課さない)との突合が無い
7. **P-1**: 「読む機構が無い・内容は機械が確かめない」のうち、有無の数え方・マージ後の編集の比較は機械にある(内容の妥当性を見ないのは正しい)
8. **Y-4**: 標準の `pr-workflow.md:104` と `:115` が自己矛盾している点が、triage §0 の事実の表に片側(`:115,130`)だけ載っている。ここは標準の側の食い違いであり、template だけの欠陥ではない
9. 確かめきれなかった点: Y-2 の spec frontmatter の `approved_by` を読む箇所は `scripts/` に無いが、`.claude/skills/` と `.github/` の読みは全部は確かめていない(grep は scripts と .github の一部)

## 4. この案の最大の危険

**「読まれない記録は信頼性を下げる」の軸が、「記録が読まれるのは事故の後」の場面を数えていない**。判定記録や台帳の行・G-8 の 3 行は、通常は誰も読まず、出荷後の障害・監査・係争で初めて読まれる。そのとき必要なのは「判定者が自分で確かめたと言える 1 語」であり、機械の既定値(M-4・M-3「未観測」・M-1 の AI による push)は**確かめた人の不在を、確かめた記録に見せかける**。負担を減らす案が、帰属(誰が確かめたか)を薄める方向に偏っている。軸を言い直すなら、「読まれない」ではなく「**書く行為が、判断の帰属の記録そのものか**」で割るべき

## 5. 最後まで弁護する候補(やめてはならない)

1. **M-4 G-8 層1 の 3 行**: 標準が AI の記入を禁じている。1 語×3 の負担で、受容の帰属(上申の要否を人が確かめた)を保つ。移せば帰属の主張が弱まる

3. **G-2 項目7(受容した妥協の自己チェック)**: ADR-0159 が唯一の検出の経路に置いた。まとめるなら、結合キーの別審議が先
4. **Y-9 D-07**: 読み手(AI 維持管理者の四半期の棚卸し)がある。IMPL-0226
5. **Y-1 項目4**: 止まらない面(ロックの外・最小の非コア)に対する唯一の提示
6. **P-1 A-22**: 人が動かして確かめた事実の記録。集約が有無と編集を見る
7. **Y-8**: 負担ではない。IMPL-1036 を外すと標準と template が食い違う

譲る件(Y-2・Y-3・Y-5 の欄の部分・Y-6・M-2・M-7・M-10・B-13)は、読む機構が無い・同じ事実が別の記録にある・機械が同じ事実を持つ、のいずれかで、やめる根拠が強い。
