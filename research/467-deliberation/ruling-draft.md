- 入力: `intake.md`・`triage.md`・`council-01`〜`05`。委員の間で事実が食い違う点は、所在を指定して部分読みと grep で確かめた。読み取りだけの試験を 2 本実行した(§0)

## 2. 所有者へ上げる「やめる候補の上位 10 件」

「やめる」と「機械へ移す」を合わせ、効果(起きる頻度 × 欄)と確かさの順に並べた。5 つの問いの記号: 読 = 誰が読むか / 防 = 何を防ぐか / 骸 = 形骸化 / 機 = 機械で足りる / 速 = 速さ。

### 1. 機能仕様の承認表と、frontmatter の承認欄(`approved_by`・`approved_at`)をやめる(Y-2。triage A-07)

- **何を**: 仕様の起案者か判定者が、**機能ごと**に 8 欄(frontmatter 2 欄、G-2・G-4 の 2 行×3 欄)を書いている
- **なぜ**: 読・機。様式自身が「判定日の正本は判定記録。本欄は転記。食い違えば判定記録を正」と書く(`01-feature-spec.md:87`)。template 全体を grep しても、この欄を読むコードは無い(F-4)
- **失わない根拠**: 帰属の記録は判定記録と承認レビューの写しにある(ADR-0070)。事故の後に監査人が読むのも判定記録で、転記ではない。転記が残ると、食い違ったときに説明を求められる元になる。機能ごとの段階は `/pit`(`next.mjs`)が判定記録から出す
- **賛否**: 5 人中 5 人が賛成(品質監査委員の条件: frontmatter も同時に消す。採る)
- **ADR**: 要らない(様式の転記欄。`template-fields.yaml` t1 の `structure` の行を同時に消す)。§6 の ADR-0271 の決定には列挙する

### 2. PR の「AI 関与範囲」を人が書くのをやめ、トレーラから導く(Y-4。A-23)

- **何を**: 変更の作成者が、**変更ごとに** 2 欄(生成・人の確認)を書いている
- **なぜ**: 読・機。標準の PR 運用は、この欄を「**自動**」と定めている(トレーラ・実行記録から。`pr-workflow.md:115`)。template は人の空欄で、標準と食い違っている。誤りは template の側にある。読むコードは無い(F-5)
- **失わない根拠**: 生成の事実はトレーラ `Co-Authored-By`・`Agent-Run` に残る。人の確認の事実は、G-6 の承認レビューと判定記録に残る。規制業の集計元の形は、ADR-0216 が採用者に委ねている
- **賛否**: 5 人中 5 人が賛成(うち 3 人は条件つき。条件は、導出の実装までは「トレーラが正」と欄に書くこと、`ship-evidence.yml` の生成文を直すこと、規制業向けの手引き)
- **ADR**: 要らない(標準への合わせ直し)。ただし、自動導出は未実装なので、実装マーク(undelivered)を足して表示する

### 3. PR チェックリストの項目1〜3(テスト・外部インタフェース・再発明)を PR から外し、手引きへ移す(Y-5。A-27b)

- **何を**: 作成者が**変更ごとに** 3 チェックを付けている
- **なぜ**: 読・骸。読み手が定められていない。入力の分離により、G-6 の材料にもならない。同じ観点は、G-6 の `/human-verify` の順1〜3 で判定者が手がかりつきで確かめる
- **失わない根拠**: チェックを付けても、確かめた証拠にはならない。G-6 を経ない最小・非コアの変更では、確認の証跡はもともと無い。消しても悪化しない。観点の提示は `/implement` の手順に置くので、作成側からは消えない
- **賛否**: 5 人中 5 人が条件つきで賛成(条件: 観点を手引きへ移す。G-6 を経ない変更は人の確認を伴わない、と開示から読める)
- **ADR**: ADR-0271 に含める。PR 様式は `template-fields.yaml` の登録外(規格委員の確認)

### 4. PR チェックリストの項目5(閾値・除外設定を触っていない)をやめる(Y-1 の一部)

- **何を**: 作成者が変更ごとに 1 チェック
- **なぜ**: 機。pr-rules が、閾値・除外設定と製品のコードの同時の変更を失敗させる。**実行で確かめた**(F-2)

#### Y-1 項目5 PR チェック「閾値・静的解析の重大度・除外設定を、この変更で触っていない」 — やめる

- 事実: pr-rules が、閾値・除外設定と製品のコードの同時の変更を失敗させる。`test-check-pr.mjs` 338 場面の実行で、この場面が失敗になることを確かめた(F-2)

- 誰が何を失うか: 無い。禁止の規範(第4章 G-5)は残る。CLAUDE.md の常駐の規則にも残る(`claude-md-resident.json:201`)

- 誰が何を失うか: 仕様のファイルだけを開いた読み手が、承認の状態を 1 か所で見られなくなる。`/pit` が機能ごとの段階を出すので、代わりがある。事故の後の読み手(監査人)は判定記録を読むので、失わない
- 採らない案: 表だけを消し、frontmatter を残す(品質監査委員: 効力があるように読める)
- 手続: 様式 01・06 の節と frontmatter の 2 行を消す。`template-fields.yaml` の t1・t6 の行を消す(`structure` なので omit は要らない)。`status:` は残す。ADR-0271 に列挙する

#### Y-6 方針と生成結果の相違の記録(第4章「実装作業における順序」段階3) — やめる(記録の義務)

## 5. 所有者にしか決められない点

## 7. この裁定の限界と、根拠水準の開示が要る箇所

- **所要時間を測っていない**。欄の数と回数で近似した。転記の 1 欄と判断の 1 文を同じ 1 と数えている
- **採用者の実績が無い**。「読まれない」「形骸化する」は、読む機構の有無と様式の形から導いた。実際に形骸化した記録の観測は無い。外部の観測(#466 の X-09・X-32)は単一組織・ベンダの自己測定で、本件の裁定の根拠には使っていない
- **実行で確かめたのは F-1・F-2 だけ**(`test-check-pr.mjs` 338 場面、`test-guard-write.mjs` 63 件。fixture による試験で、実際の GitHub 上の実行ではない)。M-5・M-7・M-10・B-13 は、実装の段で実行して確かめることを条件にした
- **欄の数は推定を含む**。C-10・C-18・M-10・M-7 の減り(§1 の「推」)。立ち上げの合計は、実測の推定にさらに推定を重ねている
- **M-1 が実際に動いているか**(草案の文脈がヘッダを埋めるか)は確かめていない
- **ADR の全文検索はしていない**。やめる各件について、それを課した別の ADR が無いかは、委員と議長が読んだ ADR(0018・0028・0040・0058・0070・0106・0159・0216・0243・0267)の範囲でしか確かめていない。実装の段で、ADR を語で検索して突合する
- **根拠水準のマークが要る箇所**(実装の段で付ける)
  - ADR-0271 の「転記欄をやめても、事故の後の再構成に支障がない」: 読む機構の grep と、様式の注記から導いた判断。事故の後の再構成で試していない → `暫定 EV-NNNN`
  - ADR-0271 の「PR の自己チェックは確かめた証拠にならない」: 一般的な観測。本標準の採用者での測定は無い → `暫定`
  - ADR-0272 の「段階3 の記録をやめても、アンカリングを抑える効果は段階1 で保たれる」: 根拠の対照実験は、判断を先に確定する効果を測ったもので、記録の有無を測っていない → `暫定`
