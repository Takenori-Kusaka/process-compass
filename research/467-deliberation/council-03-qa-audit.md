## 2. 争点への見解

- **P-1 A-22**: 残す。判断の 1 文は人。手順と結果は実行記録の所在の参照で足りる、という案に賛成(条件つき)。「動かして確かめた人」の記録が、G-6 基準6 の唯一の証跡である。手順と結果の写しは、誤記を増やすだけ。ただし、実行記録の所在は PR の本文から辿れること
- **P-2 A-37**: 残す。要約の形(8 文字以上)しか見ない機械の限界は開示済みであり、manual として残す。件数を減らす案は #466 に回す。監査人は「見ずに承認した」ことを要約の中身から読む
- **P-3 A-29**: 条件つきで残す。超過時だけ起きる 4 欄は負担が小さい。自己申告の限界は、根拠水準マークで開示する。二重だという引く側の論拠は、A-37 が実質の証拠になるという点で一理ある。ただし A-37 は読み切れたことでなく挙動の要約なので、同じ事実ではない
- **P-4 S1 の G-2・G-4**: 残す(G-3 の反対と同じ)。2 回目が 1 回目の写しになる、という指摘は、判定者が同一人物のときの実態であって、ゲートを減らす理由にならない。同一人物の判定は、ADR で受け付ける記録つきの扱いが既にある
- **P-5 C-11**: 最小でも書く。書いても検査されない欄は、書かれない欄より悪い。ここは「やめる」でなく、**G-7 を省く最小で空欄を止める検査**(`check-d0` の表示を止めに格上げするか、manual として開示するか)を決める。triage §7-8 のとおり、欠陥として別の Issue へ。新しい義務は足さない
- **P-6 B-23・B-24**: 決断の記録は残す。比較した選択肢を、割れたときと異議があるときに限る案には、条件つきで賛成する。毎回 2 案の定型は、形だけの記録になる。ただし、これは条項の変更を伴う。「限る」と書くと、書かない場合の根拠を問われる。限定は行の中に書く(適用範囲の規約)
- **P-7 A-16**: 記録を外し、行為を手引きへ。確かめられない義務を条文に残すと、未達の表示が常時出る。手引きに下ろすと「課さないと決めた」と明記する
- **P-8 A-27b**: 消す。提示が要るなら `/implement` の作成側の手引きに置く。PR の欄は証跡として読まれない
- **P-9 A-12**: 残す。設計判断の記録は、事故の後に最初に読まれる。欄の数でなく、空欄を避けて形だけ埋める動機が問題である。「事業影響・非機能」の欄は、該当なしの書き方を様式に 1 行で示す(新しい義務ではない)

## 3. 機械へ移すときに守る条件

機械の出力を証跡にする条件を、既存の定めの所在とともに挙げる。新しい義務は足さない。

1. **出所の併記**: 値の出所(レビュー識別子・コミット・実行の識別子)を併記する。ADR-0070 と `04-gate-record.md:28` が既に定める。M-1・M-2・M-4 に共通
2. **機械の出力は判定記録に写すか、所在を書く**: 監査人は判定記録を読む。CI のログは保管期間で消える。機械の事実を人が写すことはやめてよいが、記録の側から出力の所在(実行の識別子)へ辿れること
3. **欠落は欠落と出す**: 導出できないとき(トレーラ欠落・記録が無い)は、空欄や「該当なし」にせず、「導出できない」と表示する。triage §7 の未達と省略の区別(ADR-0028)と同じ原則
4. **機械の検査にするのは決定可能な条件だけ**: コアポリシーの定めどおり。文の意味や、異議の有無のように人の記載に依る値は、人の記載を前提とすることを開示する
5. **人の判断の欄は機械が埋めない**: 結果・確認した項目・確認していない事項・挙動要約・決断の記録。ADR-0070 が既に定める
6. **改ざん**: 機械の出力を後から人が書き換えられる場所に置く場合は、書き換えが記録に残る場所(records ブランチ・PR の履歴)に置く。PR の本文の訂正は追記で行う(`pr-workflow.md` の定め)。機械で閉じない部分は manual と開示する
7. **機械が止める項目の自己チェックは、機械の存在を実行で確かめてから消す**: Y-1・Y-4 の前提。triage は存在を grep と読解で確かめたが、移した先を実行で確かめていない(triage §8)

## 4. 最大の危険

**「機械が止める」という前提の実効性を、実行で確かめずに、自己チェックを消すこと。** Y-1 は pr-rules が止めると読んで、Y-4 はトレーラが残ると読んでいる。triage の限界の節が、移した先の機械の実在を実行で確かめていないと自分で書く。IMPL の state が delivered でも、止まっていない例があれば(EV-0293 のように、内容を機械が確かめない部分)、消した後に「人も機械も見ていない」状態になる。表示は残るのに実態が無い、という最悪の組み合わせ(表示と実態の食い違い)である。実装の前に、各候補について、止まる例と止まらない例を 1 回ずつ実行して確かめること。
