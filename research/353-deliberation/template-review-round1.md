## 2. 所見

### H-1(高) 承認し直しの判定が「行のどこかに有効な行の識別がある」だけで、有効な行が未回収から外れ、期限超過の行が欠落から外れる

- 所在: `template/scripts/gate/exception-expiry.mjs` の `reapprovedBy`・`lapsedExceptions`・`countRangeExceptions`
- 根拠: `reapprovedBy` は行の全セル(`text` = 全セルの連結)に `D-NNN` があり、その行が有効・期限内なら「承認し直された元の行」とみなす。対象の一致も、どちらが新しい行かも見ない。`countRangeExceptions` は、これを**有効な行にも**当てる。実行で確かめた(2026-11-20 を突合の日とする)
  - 期限前に承認し直し、新しい行が元の行を名指す(自然な書き方)と、両方が互いを名指して**2行とも未回収から外れる**(純関数: 範囲 2・未回収 0)
  - 有効な行の内容に「D-002 と同じ事情」とあるだけで、その行が未回収から外れる(範囲 2・未回収 1)
  - 期限超過のゲートの判定の行(G-2 F-001)が、対象の異なる有効な行を内容で名指すだけで、欠落から外れる
  - 通し: 正しくは未回収 5・期限超過 3・欠落 3 の台帳で、品質レポートの句は「未回収 2 件、うち回収の期限を過ぎた 1 件」、欠落は1件だけ
- 1.10.2 が外すのは「新しい行で承認し直された元の行」だけ。IMPL-0574 の note は「承認し直しの識別が正しい行を指すか」を manual と開示するが、有効な行が外れること・付随の言及で外れることは開示していない。併記の件数と G-7 の差し戻しという、表示と実態の食い違い
- 直し方の案: 決定可能な条件で絞る。(1) 名指された行と元の行の「対象」が一致する、(2) 名指された行が元の行より後に足された行である(識別の番号が大きい、または始点の台帳に無い)、(3) 新しい行と判定した行は、元の行として外さない(相互の名指しを断つ)。3つの場面(相互の名指し・付随の言及・対象の異なる行)を回帰へ足す。意味(正しい承認か)は manual のまま

### M-1(中) 閉じた値でない状態の行が「回収済み」の側に倒れる

- 所在: `exception-expiry.mjs` の `exceptionStanding`(有効の値でも失効でもなければ `closed`)
- 根拠: 「未返却(延長申請中)」・誤記・空欄の状態の行は、期限を過ぎても欠落に出ず、未回収にも数えない(通しで確かめた)。1.10.2 の「未回収」は「回収の記録が無く、取り下げていない行」で、回収済み・取り下げの側を正で判定する定めである。変更への対応づけでは従来どおり落ちるが、ゲートの判定の行と範囲の外の行は、どこにも数えられない
- 直し方の案: `closed` は「返却済み」で始まる値と「取り下げ」だけにする。それ以外は未回収に数え、期限で比べ、閉じた値でない旨を欠落に出す

### M-2(中) 欠落は作業ツリーの台帳で、件数は範囲の終点の台帳で数える

- 所在: `aggregate-evidence.mjs` の `ledgerRows`(`fs.readFileSync(ROOT/debtFile)`)を `lapsedExceptions` と `exceptionMatch` に渡し、`claim.exceptions` は `recordAt(debtFile)`(終点のコミット)で数える
- 根拠: `--to` が HEAD より前のとき、同じ出力の中で、欠落の行の一覧と件数の句が別の時点の台帳を示す。突合の日の既定は終点のコミットの日なので、日付と台帳の時点もずれる。1.10.2 は終点の台帳で数えると定める(#354 で開示の表を終点の記録へ揃えた ADR-0147 と同じ型の食い違い)
- 直し方の案: 期限の比較に使う行も終点のコミットの台帳で読む。`--to` を HEAD より前にした通しの場面を足す

### M-3(中) 突合の日の既定が範囲の終点のコミットの日で、出荷判定の経路が日を渡さない。標準のフェーズ5 の本文に既定を書いた

- 所在: `aggregate-evidence.mjs` の `exceptionDay`、`.github/workflows/ship-evidence.yml`(202・448 行)、`.claude/skills/gate/gates/G-7.md`、本体 `phase5-implementation/ci-gates.md` の条件2 と箇条
- 根拠: G-7 基準5・7.3 は「突合の日」に効力を失っている行で差し戻す。終点のコミットの後に判定する場合(候補を切ってから日を置いて判定する場合)、その間に期限を過ぎた行を機械が出さない。ship-evidence も G-7.md も `--exception-day` を渡さず、G-7 の手順にこの引数が無い。IMPL-0574 は check=machine で、既定の日を開示しているが、判定者の手順には届いていない。また ci-gates.md の条件の表(条件2)と箇条を書き換えた。5-2 の X-4 は「条件の表は変えず」とした。`template-implementation.md` は「本文(標準)の条文は変えていない」と書くが、実態と食い違う
- 直し方の案: 出荷判定の経路(ship-evidence と G-7.md)で判定の日を `--exception-day` として明示して渡し、出力に記録する。既定を終点のコミットの日のまま置くなら、それが突合の日と異なることを G-7.md と品質レポートに出す。ci-gates.md の書き換えは、議長が編集の指摘として追認するか戻すかを決め、実装の記録の「本文を変えていない」を直す

### M-4(中) `gate-g5.yml` を全行 CRLF にし、孤立した CR を1つ入れた

- 所在: `template/.github/workflows/gate-g5.yml`(150df34)
- 根拠: 7be857f は LF。eb72483 は全 525 行が CRLF で、足した行 `- run: node scripts/gate/test-exception-expiry.mjs` の末尾が `\r\r\n`。差分が 1048 行になり(実質は2行)、`git ls-files --eol` は `i/-text`(テキストと見なさない)。読む試験は今は通るが、行の履歴が #353 に付け替わる
- 直し方の案: LF に戻し、2行だけを足した形でコミットし直す

### M-5(中) 「独立した人の確認を経ない出荷」の件数は、正の値の経路を一度も実行していない

- 所在: `aggregate-evidence.mjs` の `exceptionShipments`、`test-exception-expiry.mjs`、IMPL-0573 の note
- 根拠: 通しの試験はどれも 0 件で、純関数の試験は渡した値をそのまま返すことを見るだけ。対応づいた変更を数える加算(2か所)が実行されたことは無い。IMPL-0573 の note は開示しているが、品質レポートの句は修飾なしで「0 件」を出し、表明する者は note を読まない。根拠水準マークも無い
- 直し方の案: CI の Linux で偽の gh を置き、対応づく1件の場面で 1 件になることを確かめる。それまでは、品質レポートの句に「この件数の対応づく経路は試験で確かめていない」と添えるか、EV で開示する

### L-1(低) CLAUDE.md の生成区間の句が、数えた日と台帳の所在を欠く

- 直し方の案: 「数えた日と技術負債台帳の所在」を足す

### L-2(低) 日付として読めない `--today` を黙って捨てる。集約の最後の既定が時計

- 所在: `next.mjs` の `--today`、`aggregate-evidence.mjs` の `exceptionDay` の最後の `new Date()`
- 根拠: `--today 2026/11/20` で注記が出ず、理由も出ない。集約は git が終点の日を返さないときだけ実行の時計に依る
- 直し方の案: 読めない `--today` は注記で知らせる。時計の既定を使ったときは出力に書く

### L-3(低) 返却の目安の欄の最初の日付を期限とみなす

- 所在: `config.mjs` の `dueDayOf`(以前から)
- 根拠: 「2026-10-01 承認。2026-11-30 まで」は 10-01 を期限として期限超過になる。安全の側に倒れるが、偽の欠落になる
- 直し方の案: 様式に「返却の目安には期限の日付だけを書く」と書くか、「まで」の前の日付を取る

### L-4(低) 標準に文の無い読みを実装が決めている

- 所在: `countRangeExceptions`(終点の台帳から消えた始点の行を未回収に数える。範囲で足して取り下げた行を範囲の件数に数える。期限が読めない有効の行を `undatedDue` に分ける)
- 根拠: どれも安全の側か開示の側で、標準へ定義を足してはいない。所有者の方針(細かい定義を増やさない)には反しない。ただし議長の裁定に無い読みである
- 直し方の案: 本文へ足さない。議長が実装の読みとして追認したことを裁定の記録に1行で残す

### L-5(低) 品質レポートに意味の違う「未回収」が2行並ぶ

- 所在: 品質レポートの「範囲の第7章の例外承認の件数」の行と、続く「未回収の例外(技術負債台帳)」の行
- 根拠: 前者は 1.10.2 の意味(失効を含む)、後者は状態が有効の行。1.10.2 自体が二義を認めているが、同じ画面で数が合わない
- 直し方の案: 後者の見出しを「状態が有効の例外」とするか、意味を括弧で添える
