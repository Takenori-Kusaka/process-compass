## 1. 受け入れ条件1: 逸脱に当たるか

5委員が一致した。一致を理由にせず、条文で確かめた。

- 1.4 の定義は「閉じた列挙であり、一覧は 1.10.2 による。条項の無い離脱を逸脱と呼ばない」。1.10.2 の列挙は D-1 だけで、「表に無い離脱を、逸脱と呼びません」とある。**字義で当たらない**。問いの実質は「列挙へ足すか」である
- 足さない理由(#352 の裁定の2基準に照らす)
  - 同程度の防御でない。7.3 の回収・継続の報告は離脱を**解く**手続で、離脱が続く間の防御ではない。D-1 の代償措置(判定記録の突合・抜き取り)と性質が違う
  - 行の中身が閉じない。どの判定基準を外すかは案件ごとに開いている。#352 が D-2・D-3 を退けたのと同じ週に、より開いた行を入れることになる
  - 名が「逸脱を伴う」へ変わると、正規の経路を使うほど主張の格が下がる。`gate-criteria.md` G-7 の「正規の経路を置かないと、記録を偽る動機が生じる」と向きが当たる

### 4区分の欠け(K-1)を塞ぐ読み

1.10.1 は「満たしていない要求事項は、未達・記録の欠落・逸脱・列挙に無い離脱のいずれかとして表示する」と書く。例外承認を経た判定基準の不充足の位置が書かれていない。

- 7.2 は「基準の不充足を禁止せず、承認・記録・回収を伴う手続として扱う」。7.3 の規範(しなければなりません)は、判定基準を満たさないまま進める場合の**5つの要求**に掛かる。本標準の要求事項は「判定基準を満たすか、7.3 に従うか」である。この読みを明文にする
- ただし、読み手を誤らせないため、2つを同時に書く
  - 例外承認は「判定基準を満たした」ことにはしない(7.3 自身が「満たさないまま」と書く)
  - 例外承認は未達を解かない(`gate-criteria.md` G-6「例外承認は未達を解消しない」。既存)。未達のゲートがある範囲は、例外承認の有無に依らず適合の主張に至らない
- 7.3 の要求を欠いた例外(記入の欠け、承認した者が作成を指示した者、効力を失ったもの)は、手続に従っていない。既存の G-7 基準5 のとおり、対応づかず、記録の欠落になる

### 裁定の案: 課す

弁護の論を1つずつ当てた。

- 論1・2(受け手がいない、誠実さを罰する): 本標準は既に、適用の表明に未達と記録の欠落の件数を併記させ、併記しない表明を適用の表明として扱わない(1.10.2、EV-0106)。「途中であることは件数で表示する」(1.10.1)。同じ反論は未達の件数にも当たるが、本標準は件数の表示を採っている。例外承認だけを別に扱う根拠が無い。黙って離脱した 0 件は、見つかれば記録の欠落であり、併記の有無で有利にならない
- 論3(短い引用で落ちる): 下の「ADR-0083 との関係」で扱う。弱点として残り、開示する
- 論4(保証の側に置く設計): 保証の開示は変えない。ただし主張に添える定めが無い以上、主張の受け手に届く経路は主張の文しかない
- 論5(降りていない規定が増える): 採否の理由にしない(コアポリシー。降りていない規定は表示し続ける)

弁護の案のうち採るもの: **主張が何を述べないかの明示**。併記を課しても、件数の句を読まない受け手は残る。「適合の主張は、範囲のすべての変更が判定基準を満たしたことを述べない」を 1.10.2 に書く。

### ADR-0083 が「開示で足りる」を採らなかった理由と矛盾しないか

ADR-0083 Q-3 は、**逸脱**について「名を分けず、開示で足りるとする」を採らなかった。理由は「開示は短い引用で落ちる。名に開示を運ばせる」。本件で名を分けずに併記で受けることが、これと矛盾するかを競わせた。

| 案 | 中身 | 採否と理由 |
| --- | --- | --- |
| P. 併記(名は変えない) | 件数の句を文の型へ入れる | 単独では採らない。短い引用で落ちたとき、何も残らない |
| Q. 名を分ける(「例外承認を伴う適合の主張」) | 範囲に1件でもあれば別の名 | **採らない**。(1) 例外承認は日常の経路で、運用している組織のほぼ全部が別の名に入り、名の識別力が無くなる (2) 件数の閾値で分けるなら値が要るが、先例も実測も無い (3) #352 が第3の主張を採らなかった理由(ADR-0083 が2つに分けた直後で、名の意味を薄める)がそのまま当たる (4) 正規の経路を使うと名が変わる。記録を偽る動機を作る |
| R. 併記の無い主張を、本標準に基づく主張として扱わない | 併記を主張の成立の条件にする | **採る**(P と組にする)。適用の表明の既存の定め(未達と欠落の件数を併記しない表明を、適用の表明として扱わない)と同じ型。件数の句を落とした引用は、本標準が定める主張ではなくなる |
| S. 併記を課さない(弁護) | 述べないことの案内だけ | 採らない(上記)。案内の文は採る |
| T. 未回収だけを併記(弁護の次善) | 保証の開示 項目5 と同じ定義 | 採らない。回収済みを落とすと、範囲で判定基準がどれだけ外れたかが読めない。事後に回収した件を消せる数え方になる |

**矛盾しないとする根拠**(名に運ばせるべきものの違い):

- ADR-0083 が名に運ばせたのは、「本標準の要求事項を満たさない状態が範囲にある」ことである。逸脱を伴う範囲で「適合している」とだけ引用すると、**引用された文が偽になる**
- 例外承認は、1 節の読みにより要求事項を満たさない状態ではない。件数の句を落として「適合している」と引用しても、**引用された文は偽にならない**。落ちるのは、受け手が知りたい付随の事実である
- したがって、名を分ける理由(偽の文を作らせない)は例外承認に及ばない。付随の事実の落下は、R(併記の無いものを主張として扱わない)と、短い引用の定め(所在を添える。「例外承認なし」と読ませない)で受ける

**残る弱点(開示する)**: この区別は条文の読みに依る設計上の判断で、実証が無い。受け手が「適合」を「判定基準を満たした」と読む限り、偽でなくても誤解は起きる。短い引用で件数の句が落ちる割合の観測も無い。EV で開示し、差し替え条件を「落ちた引用が過半なら、名を分ける案(Q)を審議し直す」とする(4 節)。

### 何を、どの範囲で、いつの時点で数えるか

委員の間で数え方が割れた(承認日が範囲にあるもの / 範囲で効力を持ったもの)。台帳の欄の実物(テンプレ3: ID・区分・記録日・対象・内容・影響・受容理由・返却目安・状態・記録者・承認した者)には**回収の日の欄が無い**。「範囲の始端より前に回収されたか」は、欄からは決められない。欄を足さずに決定可能な数え方にする。

| 併記する値 | 定義(決定可能な条件) |
| --- | --- |
| 範囲の例外承認の件数 | 技術負債台帳の区分「例外」の行のうち、範囲の始点の台帳で状態が有効だった行と、範囲の中で足された行の数。適用の表明では、適用の開始から表明の時点までに在った行の数 |
| うち未回収 | 範囲の終点(表明では表明の時点)の台帳で、状態が有効の行の数 |
| うち期限超過 | 未回収のうち、回収の期限が範囲の終点の日より前の行の数。適合の主張と逸脱を伴う適合の主張では常に 0(1件でもあれば記録の欠落で主張に至らない。3 節)。適用の表明では 0 でない値を取りうる |
| 独立した人の確認を経ない出荷 | 範囲の変更のうち、独立した人の確認を経ておらず、出荷判定の突合で例外承認の記録が対応づいた変更の数(G-7 基準5。保証の開示 項目3 の「例外承認の記録あり n 件」と同じ数え方) |
| 時点と所在 | 件数を数えた日と、台帳の所在 |

- 0 件も「0 件」と書く(省略と区別する。ADR-0028)
- **採らなかった併記**: 回収済み・取り下げ・失効の件数の内訳(件数から未回収を引けば出る。各件は台帳で読む)、外した基準の項目番号の一覧、承認した者の名、G-1 の閾値の変更に使った例外の別掲(品質監査)。理由は、文が長いほど引用で落ちること、別掲が受け手の判断を変える根拠を示せないこと。G-6 だけを別掲するのは、外されたのが本人以外の目であり、保証の開示が既に同じ区分を持つためである
- **7.10 の前提の受容と 7.3.2 の未解決事項は、件数に含めない**。前提の受容は判定基準の不充足ではなく前提の劣化の受容で、有効期限と再評価を別に持つ。未解決事項は判定の外にある。採否の根拠は条文の区分だけで、実走の観測は無い(EV に含める)
- **件数・期限の長さ・再承認の回数に上限を課さない**。課さないと決めた事項である。上限を定めた規格の先例を確認できず、値を置けば根拠の無い値になる

## 3. 割れた点2: 期限を過ぎた未回収の例外

### 既存の定義に当てはめる(実物)

弁護の読み(「期限切れの例外は台帳の状態が『失効』に移り、G-7 の対応づけを満たさないので、既存の区分に落ちる」)を、条文と template の実物で確かめた。**成り立たない**。

1. **期限を過ぎたら状態が「失効」になる、と定めた条文が無い**。7.3 の記録の表は「回収済み、取り下げ、失効は、有効でない」と書くだけで、失効が何を指すか、誰がいつ移すかを定めていない。7.3 要求事項4 が求めるのは期限を**定める**ことで、期限までに回収することを要求事項として書いていない
2. **template は期限を日付と比べていない**。`aggregate-evidence.mjs` の `exceptionMatch`(2415 行付近)が見るのは、状態の値が有効を示す語と一致することと、期限が「日付として解釈できる」ことだけである。期限を過ぎて状態が「未返却」のままの行は、対応づき続ける
3. **G-6 以外の基準を外した例外には、落ちる先が無い**。ゲートの判定を対象とする行(`G-2 F-001` の形)は、有効でない状態になると照合から外れるだけで(2469 行付近)、欠落を生まない
4. 出荷判定は出荷ごとである。期限の前に出荷された変更は、次の出荷の突合の対象でない

いま期限超過を見ているのは、内部監査の観点3(「技術負債台帳の未回収の項目が、期限内に処理されているか」。manual)と、ADR-0036 の EV の差し替え条件 (c)(期限を超過した未回収の例外承認の件数)だけである。

**判定: 既存の定義では落ちない。定義を広げる。採用者への新しい義務である。**

### 両方の論(最も強い形)

**記録の欠落に数える(起案・現場・品質監査)**: 期限は 7.3 の条件の1つで、「1項目でも満たせない場合、例外を認めてはなりません」。期限までに在るはずの回収または再承認の記録が無い。新しい区分を作らず、4区分で受けられる。条件は決定可能(期限と日付の比較)。

**1.10.2 の述べる条件へ直接足す(規格)**: 記録は在る。出荷の時点では承認は有効で、対応づけは成り立っていた。事後に欠落と読み替えると、正規だった出荷を遡って不適合にする。「記録の欠落」の意味が「記録はあるが効力が無い」へ広がり、語が濁る。条件として足せば区分に触れない。

### 裁定の案: 効力を失うと定め、記録の欠落に数える

規格の案を採らない理由。

- ADR-0083 決定3 は、満たしていない要求事項の表示を4つと定めた。1.10.1 も4つのいずれかとして表示させる。主張を妨げるのに4つのどれでもない状態を作ると、この決定と食い違う。第5の区分を作るのと同じである
- 本標準には同じ形の定めが既にある。期限つきの受容は「**期限を過ぎた受容は、記載の欠落として扱う**」(附属書H H.6、G-7 基準9)。暫定のライセンスの許可は「期限を超過した暫定の許可は失効させる」(G-5)。類似の検知は「期限を超過した未処理項目が残る場合、出荷を止めます」(G-5)。期限つきの許しが期限を過ぎたら効力を失い、欠落に数える、という型は既存の設計であり、例外承認だけがこの型から漏れていた

規格の論のうち採るもの: **遡らせない**。効力を失うのは期限の翌日からで、期限の日までに終わる範囲についての主張と、期限の前の出荷判定は変えない。

定める中身(文案は 5 節):

1. 回収の期限を過ぎた例外承認は、期限の翌日から効力を失う。回収の記録、または権限者による再承認(7.3 の5要求を満たす新しい記録)があれば、この限りでない
2. 効力を失った例外承認の行(状態が有効のまま期限を過ぎた行と、状態が失効の行)は、**記録の欠落**に数える。回収するか、再承認するまで続く
3. G-7 基準5 の対応づく条件2 を「状態が有効で、回収の期限を過ぎていない」に改める
4. 同じ行の期限を書き換えて延ばすことを、再承認として扱わない(現場の案)
5. 「失効」の語を定める: 期限を過ぎ、回収も再承認もされていない例外承認の状態

**帰結(新しい義務として ADR に書く)**

- 期限を過ぎた未回収の例外が1件でもある範囲は、適合の主張と逸脱を伴う適合の主張に至らない
- 出荷判定(G-7)の突合で記録の欠落になる。回収または再承認まで、**以後の出荷が差し戻しになる**。これは Issue の受け入れ条件(主張での開示)を超えて採用者の出荷に及ぶ。所有者へ問う(4 節の次)
- 適用の表明では、記録の欠落の件数に入り、併記の「うち期限超過」にも出る

**残る弱点(開示する)**: 期限の後に回収すれば欠落は消え、期限超過だった期間は主張に残らない(台帳の履歴には残る)。期限の長さに上限が無いので、長い期限を置けば効力は続く。どちらも本件では塞がない。

## 4-2. 所有者にしか決められない点

適合の主張の文の型に句を足すことは、ADR-0083 決定3(正本は 1.10.2、H.8 は文の型だけ)の枠内の改訂で、名も主張の数も変えない。第1版の発行前で、適合の主張を述べた採用者はいない(1.10.2 の注記)。**文の型については、所有者への問いに当たらない**。

問いは1つ。Issue の受け入れ条件を超えて、採用者の出荷に及ぶ帰結である。

> **問い**: 回収の期限を過ぎた未回収の例外承認が1件でもあると、回収するか権限者が再承認するまで、(a) 適合の主張を述べられず、(b) 以後の出荷判定(G-7)で記録の欠落として差し戻しになる。この帰結を、第1版の発行までの定めとして受け入れるか。
>
> - 受け入れる(議長の案): 期限つきの受容・暫定の許可・類似の検知と同じ型にそろう
> - (a) だけ受け入れる: 出荷は止めず、保証の開示 項目5 に「期限超過」と表示する。この場合、同じ行が主張では記録の欠落、出荷では欠落でない、という2通りの扱いになるので、「記録の欠落」に数えず 1.10.2 の述べる条件へ直接足す形(規格の案)に改める。ADR-0083 決定3 の「表示は4つ」を ADR-0134 で補う必要が生じる

### 5.9 ADR-0134 の骨子(新規。採用済み ADR は書き換えない)

題の案: 「第7章の例外承認は逸脱でなく、表明と主張に件数を併記し、期限を過ぎた例外承認を記録の欠落とする」

決定:

1. 第7章の例外承認は、第1章 1.4 の逸脱に当たらない。閉じた列挙は D-1 のまま
2. 7.3 の要求事項を満たし期限を過ぎていない例外承認を経た判定基準の不充足は、満たしていない要求事項として表示しない。判定基準を満たしたことにはしない。未達は解かない
3. 適用の表明・適合の主張・逸脱を伴う適合の主張に、範囲の例外承認の件数(未回収、期限超過、独立した人の確認を経ない出荷、時点、台帳の所在)を併記する。0 件も書く。主張の名は変えない
4. 件数を併記しない表明と主張を、本標準に基づくものとして扱わない。短い引用には所在を添える。主張は、すべての変更が判定基準を満たしたことを述べないと明記する
5. 回収の期限を過ぎた例外承認は効力を失い、記録の欠落に数える(**採用者への新しい義務**)。再承認は新しい記録による。遡らせない
6. 7.3 の対象は、判定基準と、条項が 7.3 を名指した事項に限る。構成の条件は対象でない(既存の条文の確認)
7. ADR-0088 決定2 の「例外承認は従来どおり使える」は、「同 ADR が例外承認の経路を変えていない」の意であり、段に届かない未達を例外承認で通せる意でないと読む
8. 件数・期限の長さ・再承認の回数に上限を課さない。7.10・7.3.2 は件数に含めない。保証の開示(H.6)は変えない

### 根拠水準マークの案(番号は同上。`:::caution[暫定 EV-NNNN / 見直し 2027-05]`)

**EV-A(1.10.2 の箇条書きの後)**

- 対象: 第7章の例外承認を逸脱とせず、主張の名を分けずに件数の併記で開示させ、併記の無いものを本標準に基づく表明・主張として扱わない定め。数え方、独立した人の確認を経ない出荷だけを別に数える分け方、件数・期限・再承認に上限を課さない判断、7.10 と 7.3.2 を含めない判断
- 根拠の水準: E1(間接)。外部の先例のうち原文を確かめたのは PCI DSS v4.0.1 付録B だけで、ISO 9001 8.7・SOC 2・FedRAMP・CISA の様式は二次情報。件数の併記が受け手の判断を変えること、短い引用で句が落ちる割合、手続を踏む動機への影響に、観測は無い
- 差し替え条件: 採用者の対外の文書のうち適合を述べたものについて、件数の句を伴うものと伴わないものの数(EV-0160 と同じ観測の源)。伴わないものが過半なら、主張の名を分ける案を審議し直す。併記した件数と、のちに見つかった台帳の外の例外の件数。外が1件でもあれば、数え方を見直す。ADR-0036 の EV の (a)(適用件数)が併記の後に減り、記録の欠落が増えた場合は、併記が手続を避けさせていないかを見直す

**EV-B(7.3 の足した箇条書きの後)**

- 対象: 回収の期限を過ぎた例外承認が効力を失い、記録の欠落として出荷判定と主張を妨げる定め。期限の後に回収すれば欠落が消え、期限超過だった期間が主張に残らないこと。安全重要度が掛かる判定基準と、7.4 が後回しを禁じる対象を、7.3 の一般の例外承認の対象外とするかを**定めていない**こと
- 根拠の水準: E0(なし)。本標準の中の同じ型(期限つきの受容、暫定の許可)にそろえた設計で、採用者の実測は無い。template は期限を日付と比べておらず、実行で確かめていない
- 差し替え条件: 期限超過で差し戻された出荷判定の件数と、そのうち回収で解いた件数・再承認で解いた件数。再承認が過半で、再承認を重ねた行が観測されれば、期限または再承認の回数の定めを審議する(ADR-0036 の EV の (c) と同じ源)。安全重要度 CL1 以上の案件で、安全適合性の検証に例外承認を用いた事例が1件でも観測されれば、対象外とするかを審議する
