## 2. 所見

### M2-1(中) 品質レポートの「状態が有効の例外」の行だけが作業ツリーの台帳を読み、直しで足した括弧書きが実態と食い違う

- 所在: `template/scripts/gate/aggregate-evidence.mjs` の `debtRows`(`ledgerRows` = 作業ツリーの台帳)→ `residual.openExceptions`、品質レポートの「状態が有効の例外(技術負債台帳。上の件数の「未回収」は失効の行を含み、この行は含まない)」の行
- 根拠: M-2 の直しで、欠落・件数・`exceptedChanges`・`gateExceptions` は終点のコミットの台帳で読むようになった。しかし同じ節の `openExceptions`(と `openUnresolved`・`openDebt`)は作業ツリーのまま残った。直しの前は同じ節がすべて作業ツリーだったので、時点の食い違いは直しで生まれた。S10 で、件数の句は終点の台帳(D-001・D-005)、すぐ下の「状態が有効の例外」は作業ツリーの台帳(D-090・D-009・D-010)を出した。さらに、L-5 で足した括弧書きは、差は失効の行だけと述べる。実際には、承認し直された元の行(S1・S3 の D-001)と「未返却(…)」の行(`startsWith('未返却')`。S6)も含み、終点の版でもない
- 直し方の案: `debtRows` を終点のコミットの台帳(`exceptionRows`)から作る。括弧書きは「状態が「未返却」で始まる行。承認し直された元の行を含み、失効の行を含まない」とする
- 開示の案(直さない場合): 見出しに「作業ツリーの台帳。範囲の終点の版と異なることがある」と添え、IMPL-0573 の note に同じ旨を足す。括弧書きの「差は失効の行だけ」の文は外す

### M2-2(中) H-1 の「相互の名指し」の試験が、1巡目の欠陥の場面を固定していない

- 所在: `template/scripts/gate/test-exception-expiry.mjs` の「相互に名指す2行」と「通し(承認し直し)」
- 根拠: 1巡目の欠陥は、期限前に承認し直して両方が有効の行が互いを名指すと、両方が未回収から外れることだった。試験の場面は、元の行が期限超過である。この場面では、元の実装(`reapprovedBy`)でも結果が同じになる。変異の試験で確かめた。対象の一致と規則(3)を残し、「後に足された」と規則(3)を外して元の判定に近づけると、両方が有効の相互の名指しで未回収 0 になった。それでも 48 件のうち落ちるのは「元の行より前の行」の1件だけで、相互の名指しの試験は通った。規則(3)だけを外しても 48/48 が通る。通しの試験は `uncollected >= 3` で、正しい値 4 と欠陥の値を区別しない。今の実装は正しい(S1b)が、裁定の「3つの場面を試験に固定する」を満たしていない
- 直し方の案: 両方が有効の相互の名指し(期限 2026-12-25 と 2026-12-31)で未回収 1 を確かめる場面を足す。通しの判定を `uncollected === 4` にする
- 開示の案(直さない場合): IMPL-0574 の note に「相互の名指しは『後に足された行』の条件で閉じる。試験は元の行が期限超過の場面だけを固定する」と書く

### L2-1(低) 閉じた値でない状態の行は、期限内なら欠落に出ない。IMPL-0574 の note は条件をつけずに「欠落に出す」と書く

### L2-2(低) 連鎖では、元の行が直接名指した行だけを見る。外し方は欠落の文に書かれていない。期限前の承認し直しを重ねると未回収を多く数える

- 所在: `reapproverOf`・`reapprovedIds`、`lapsedGapText`
- 根拠: S4a・S4c で、D-001 は D-002 を名指しているのに欠落に出続ける。この欠落を消すには、D-001 に今の有効な行(D-003)の識別を書き足す必要がある。欠落の文には「元の行にその行の識別を書いてください」としか書かれていない。また S4b(D-002 も期限内で D-003 が承認し直した)では、規則(3)によって D-002 を外さず、未回収を 3 と数える(正しくは 2)。どちらも安全の側に倒れる
- 直し方の案: 欠落の文に「連鎖では、有効で期限内の最新の行の識別を書く」と足す
- 開示の案: IMPL-0574 の note に「承認し直しは元の行が直接名指した行だけで判定する。新しい行と判定した行は外さないため、重ねた承認し直しでは未回収を多く数えることがある」と書く
