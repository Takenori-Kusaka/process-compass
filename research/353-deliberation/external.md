## 0. 骨格(裁定ではない)

例外・特別採用・ウェーバーの開示には、確かめた範囲で3つの型がある。

| 型 | 内容 | 先例 |
|---|---|---|
| E1 | 例外は適合の主張の「内側」。主張の文書に使用を載せ、第三者または提出先に渡す | PCI(代償統制を報告書の該当要求の節に記載し提出先へ同封)【原】、SOC 2(個々の例外を試験結果の節に開示)【二】 |
| E2 | 例外は承認した「権限者」(顧客を含む)が個別に決め、記録する。主張の文言そのものには載せない | ISO 9001 8.7 の特別採用(concession)【二】、FedRAMP deviation(認可権限者が承認、POA&M に載る)【二】 |
| E3 | 例外を使うと主張の「資格」が落ちる、または別の判定結果になる | PCI の「Not Tested」は部分評価、「Not in Place」は不適合(3DS の FAQ からの類推を含む)【二】、ISO 9001 4.3(影響があれば適合を主張できない)【二】 |

「例外の件数・期限に上限を置く」と明記した規格の先例は確認できなかった(下の D6)。

## D. 例外・特別採用・ウェーバーの開示

### D1. ISO 9001 8.7 の特別採用(concession)
- 不適合な出力の処理の一つは、「権限を持つ者、および該当する場合は顧客による特別採用のもとでの使用・リリース・受入れの承認」【二: 検索結果の要約。Quality Digest ほかが引く。ISO 9001 の原文ではなく AS9100 の文脈の引用が混じる、との注記がある】。特別採用された出力は、なお不適合のままである。
- 記録: 不適合の内容、とった処置、得た特別採用、決定した権限者を文書化した情報として保持する【二: 監査員向けの解説】。承認者の記録の欠落が最も多い監査所見とする記述は二次情報【二】。
- 含意(E2): 例外(特別採用)は、使った事実と承認者を記録し、必要なら顧客(=使う側)にも承認させる。「不適合のまま受け入れた」という性質を消さない。本標準の例外承認と構造が近い。主張の文言への開示の要否は規格から読み取れない【未】。
- 確かめられなかった点: ISO 9001:2015 8.7 の原文、AS9100 の deviation permit / waiver の本文。

### D2. ISO 9001 4.3(適用不可能の正当化)
- #352 の A3 を参照。適用範囲に文書化して理由を示し、能力と責任に影響しない場合に限り適合を主張できる【二】。
- 含意(E3): 除外が目的を損なえば「適合を主張できない」。例外承認を使ってよい範囲に「目的への影響の有無」を課す型で、開示ではなく資格の側で閉じる。

### D3. ISO/IEC 17050・17021(適合の表明での例外の開示)
- 17050-1: 供給者適合宣言は第一者の attestation で、適合の対象と要求を特定する【二】。例外の使用を宣言に載せよと書く明文は確認できなかった【未】。17021(マネジメントシステム認証機関の要求)の例外の扱いは調べていない【未】。
- 含意: 宣言が「どの要求への適合か」を特定させる以上、例外で外した要求を宣言の範囲から外して特定する(=範囲の側で開示する)読み方はできるが、原文で確認していない。

### D4. PCI DSS(代償統制・カスタマイズドアプローチ・報告の状態)
- 代償統制は毎年、評価者が審査し、報告書の該当要求の節に記載して提出先へ渡す【原: PCI DSS v4.0.1 付録B p.370(#352 の NEW-2)】。
- 同一要求の中でも、定義された方法・代償統制・カスタマイズドアプローチを部品ごとに混在できる【原: 公式ブログ NEW-3】。カスタマイズドアプローチの使用は QSA または ISA が ROC に記載する。SAQ を使う主体は使えない【原: 付録D 末尾】。
- 要求ごとの報告の状態は In Place / In Place with Remediation / Not Applicable / Not Tested / Not in Place の5つ。Not Applicable は評価者が適用不可を確かめる試験の記録を要し、Not Tested は部分評価にあたる【二: PCI SSC の v4.0 報告の説明資料(NEW-8: https://www.pcisecuritystandards.org/1-6-the-new-approach-to-reporting_-approved-5-31/)の検索結果の要約。資料を開いてはいない】。
- 法的制約による「Compliant but with Legal exception」の選択肢があり、契約上の義務では使えず、使うと取得者(acquirer)または決済ブランドの追加の審査を要する【二: 同上と PCI SSC の FAQ】。
- 含意: PCI は「例外(代償統制)を使った」ことを、適合の表明(AOC・ROC)を受け取る側に必ず見える形で渡す(E1)。しかも状態を細かく分け、「例外込みで合格」と「不合格」を同じ語にまとめない。使った例外の種類(代償・カスタマイズ・法的制約)も区別して書かせる。
- 確かめられなかった点: PCI SSC 公式の ROC・AOC の様式の原文。3DS の FAQ にある「未試験の要求は Not in Place」の規則が PCI DSS v4.0 の AOC にも当てはまるか。

### D5. SOC 2 の例外の報告
- 個々の試験の逸脱(exception)は、重大性にかかわらず、試験とその結果の節に開示する。1つの例外と、監査人の全体の意見は別で、例外があっても無限定の意見はあり得る。意見が修正されるのは、逸脱の個別と合計の影響を監査人が判断した結果【二: CSA・A-LIGN・GBQ ほかの実務者向けの解説。AICPA の本文は【未】。節番号は報告により異なる(4 か 5)との食い違いがあった】。
- 含意(E1): 「例外を明示したまま、全体の適合は成り立つ」型。使った例外の数や種類と、全体の判定を別の項目にする。例外の数への上限は置かれていない(確認できた範囲)。
- 注意: SOC 2 の開示の対象は「統制が実施どおりに働かなかった(逸脱)」であり、「承認を得て離脱した(例外承認)」とは性質が違う。後者の開示の先例は PCI の代償統制・FedRAMP の deviation に近い。

### D6. FedRAMP の deviation request
- ベースラインと違う実装、または代償統制の提案を形式的に出す手続。認可権限者(機関認可では AO、JAB 認可では JAB)が決める【二: GitLab のハンドブック、FedRAMP 公式ページへの検索結果ほか。FedRAMP の公式文書の原文は【未】】。
- 3種: false positive(脆弱性が実在しない。承認後に POA&M から閉じる)、operational requirement(修復すると必須の業務機能が壊れる。高影響には認められない)、risk adjustment(リスクを下げて修復に猶予を得る。CVSS の指標を詳細に定義させる)【二】。
- 提出の時期: 発見時と毎月の POA&M の提出時【二】。
- 含意(E2): 例外を種類で分け、種類ごとに証拠の要求と使える範囲(高影響の operational requirement は不可)を変える。承認は適合を主張する本人ではなく認可権限者。承認した件が POA&M に残り、毎月、利用機関に見える。件数や期限の上限は確認できなかった【未】。
- 確かめられなかった点: 件数・期間の上限の有無。FedRAMP の最新の改訂(2025〜26 年の再編)での deviation の扱い。

### D7. SLSA・SSDF の attestation での例外
- CISA の Secure Software Development Attestation Form(NIST SSDF 基準): すべての実践を attest できないとき、代わりに実施している緩和策を文書化し、行動計画とマイルストーン(POA&M)を機関へ出す。署名は CEO または拘束力を持つ者。attestation が出ない場合、機関は OMB に延長またはウェーバーを求める【二: Davis Wright Tremaine、GSA の様式の検索結果の要約。2023 年の草案の記述が多く、最終版の POA&M 条項は【未】】(NEW-9: https://www.cisa.gov/sites/default/files/2023-04/secure-software-self-attestation_common-form_508.pdf は一覧に出たが開いていない)。
- SLSA v1.2: trusted robot に方針の恒久的な例外を与えてよい(MAY)【抜 SRC-0416】。例外の記録様式や開示の要求は確認できなかった【未】。
- 含意(E1+E2): attestation で「満たせない実践」を空欄にせず、緩和策と期限つきの計画を付けて見せる型。期限(マイルストーン)を持つ点は、本標準の「期限つきの例外承認」と対応する。

### D8. 例外の数・期限の上限、および開示の要否(まとめ)
| 論点 | 確かめた範囲の先例 |
|---|---|
| 例外を使ったことを適合の表明で開示させるか | PCI(報告書へ記載し提出先へ同封)【原】、SOC 2(試験結果の節)【二】、CISA の POA&M【二】は開示させる。ISO 9001 8.7 と FedRAMP は承認者の記録・POA&M で足り、表明そのものの文言は読み取れない【二】 |
| 例外を「逸脱」と同じ扱い(適合の別の種類)にするか | 12207 の tailored conformance は、テーラリングを使った主張を別の種類にする(#352 の A1)。PCI は代償統制を使っても In Place with compensating control として合格にでき、別の適合の種類にはしない(状態の細分で見せる)【二】 |
| 件数の上限 | 確認できなかった【未】 |
| 期限 | 毎年の再審査(PCI 付録B)【原】、毎月の POA&M(FedRAMP)【二】、マイルストーン(CISA)【二】。期限の上限(最長何か月)は確認できなかった【未】 |
| 遡及 | PCI は過去に漏れた要求を代償統制で補えないとする【原】。事後の例外承認で過去の離脱を適法化させない先例 |
| 承認者の独立 | PCI は外部の評価者、FedRAMP は認可権限者、ISO 9001 は権限者と該当する場合は顧客。いずれも主張する本人以外が承認【原/二】 |

## 選択肢と外部の先例の対応(#353)

選択肢の名は仮のもの。
- P1 例外承認を逸脱として扱う(「逸脱を伴う適合」に当たる)
- P2 逸脱ではないが、主張とあわせて使った範囲を開示させる
- P3 開示させない(承認記録のみ。主張の文言には出さない)
- P4 件数・期限に上限を置く(P1〜P3 のいずれかに足す)

| 選択肢 | 支える先例 | 対立する先例・弱点 |
|---|---|---|
| P1 | 12207 の tailored conformance(テーラリングを使った主張は別の種類) | 12207 のテーラリングは「規格の適用範囲の調整」で、本標準の期限つきの個別の不適用とは性質が違う。PCI は代償統制を使っても合格の状態にできる。閉じた列挙の趣旨(標準が条件を定めて認めた離脱だけ)と、手続で個別に承認する例外承認を同じ箱に入れると、列挙が事実上開く恐れがある(先例からは判断できない) |
| P2 | PCI(報告書へ記載し提出先へ同封)、SOC 2(例外の個別開示)、CISA(緩和策と POA&M を付ける) | 開示の粒度(件数か、要求ごとか)と、読み手が何を判断できるかは先例ごとに違う。SOC 2 は監査人の意見と例外を別にしており、本標準は監査人を持たない |
| P3 | ISO 9001 8.7(承認者の記録で足りる)、FedRAMP(POA&M と承認で足り、表明の文言は別) | 承認記録は提出先に見えない可能性。ISO 9001 4.3 は影響があれば主張自体を認めず、記録だけでは足りない型もある |
| P4 | 毎年の再審査(PCI)、毎月の POA&M(FedRAMP)、マイルストーン(CISA)は期限の再確認の仕組み | 件数・最長期間の上限を明記した先例は確認できなかった。上限を置くなら先例の裏付けなしの値になり、根拠水準マーク(暫定)の対象 |

組合せ: PCI は P2 に P4 の一部(毎年の再審査)と遡及の禁止を含む。FedRAMP は P3 に近いが、承認件が POA&M として利用者に継続的に見えるので、実質は P2 に近い。単独の P3(利用者に何も見せない)を採る規格は、確かめた範囲に無い。

## 確かめられなかった主な点
1. ISO 9001 8.7 と AS9100 の deviation permit / waiver の原文。
2. 17050・17021 が例外を表明に載せさせるかの明文。
3. SOC 2(AICPA の本文)、FedRAMP の公式の deviation 文書、CISA の最終版の POA&M 条項の原文。
4. PCI SSC の ROC・AOC の公式様式、報告の状態の公式資料(検索結果の要約のみ)。
5. 例外の件数・最長期間の上限を定めた規格: 見つからなかった。
6. SLSA・SSDF の attestation での例外の記録様式。
