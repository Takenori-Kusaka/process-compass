### 例外承認で外せるものと外せないもの

外せる(条項が例外承認を名指すもの):

- 独立した人の確認を経ない出荷(G-6 を適用する体制の緊急の変更。G-6 が未達の体制の R1 の変更)。`gate-criteria.md:1364`・`:1440-1444`
- 判定基準を満たさないままの通過一般(G-1〜G-8。未確定事項を残した通過 `gate-criteria.md:507`、「受容できないが進める」 `:592`)
- G-1 で定めた閾値の変更(`gate-criteria.md:2284`)、S2 の Sev2 の出荷(`:2264`)、判定記録の置き場で起きた書き換え・衝突・署名の無い書き込みの受け入れ(`:173`)
- 判定基準の引き下げ(第2章の手順3。`lifecycle.md:629`)

外せない、または例外承認の対象でないもの:

- 7.4 の後回しの禁止: G-4、G-5、認証・認可・データ保全の検証(ファストトラックに限った限定列挙。`:132-139`)。7.3 の一般の例外に同じ限定があるかは、条文に無い
- S2 の Sev1(「出荷不可(例外なし)」)
- 安全重要度による要求(「人員や期日の制約によって外れません」。CL1 以上と規制業は 1〜2名の構成を認めない。`tailoring-guide.md:1122`)。ただし同章 `:1023` は「例外承認の経路は、従来どおり使える」と書く
- 判定基準を満たしている成果物への適用(判定の範囲の誤り。`:63`)
- 規模の基準値の超過(例外承認を要さない。`:59`)、準拠テンプレートの更新を取り込まないこと(例外承認として扱わない。`overview.md:725`)
- **構成の条件**(席の兼務禁止、文脈の分離、名簿など)。7.3 の対象は「ゲートの判定基準」であり、構成の条件を例外承認で外す経路は書かれていない。構成の側の不充足は未達・逸脱・列挙に無い離脱で扱う
- 例外承認は未達を解かない(「未達の表示と、保証の開示への記載は残る」。`gate-criteria.md:1368`)

## 2. 1.4 の定義を文言どおりに当てはめる

定義(`overview.md:168`): 「本標準の要求事項を満たさない状態のうち、本標準が条項で条件と代償措置を定めて認めたもの。閉じた列挙であり、一覧は 1.10.2 による。条項の無い離脱を逸脱と呼ばない」

| 定義の要素 | 例外承認への当てはめ |
| --- | --- |
| (i) 要求事項を満たさない状態 | 2 通りに読める。**読み甲**: 本標準の要求は「基準を満たすか、7.3 の手続を踏むか」であり、手続を踏んだ変更は要求事項を満たしている(#313 の規格の委員の読み。`council-04-standards.md:120`)。**読み乙**: 判定基準を満たしていない以上、要求事項を満たさない状態である(7.3 自身が「満たさないまま」と書く)。判定基準の値には組織が定めたもの(G-1 の閾値)も含まれ、本標準の要求事項かどうかが基準ごとに違う |
| (ii) 条項で条件と代償措置を定めて認めた | 条件は 5 つある(7.3)。「認める」の語もある(「1項目でも満たせない場合、例外を認めてはなりません」)。代償措置に当たるかは読みが分かれる: 影響が顕在化したときの対処・回収・継続の報告は、離脱を続けるための措置ではなく、離脱を**解く**ための手続。D-1 の代償措置(判定記録の突合・抜き取り)は、離脱が続く間の措置 |
| (iii) 閉じた列挙に載っている | **載っていない**。列挙は D-1 だけ(`:637`)。「表に無い離脱を、逸脱と呼びません」(`:633`) |

- **字義の結論**: (iii) が決め手になる。現行の文言では、例外承認は「逸脱」に**当たらない**。(i)(ii) の読みに依らない。Issue の問い「当たるかを決める」は、実質は「閉じた列挙へ足すか」の問い
- ほかの 3 つの表示の区分にも当たらない
  - 未達: ゲートの状態(構成の単位。ADR-0028)。例外承認は変更の単位
  - 記録の欠落: 記録はある。G-7 は、例外承認の記録が対応づく変更を「欠落として扱わない」と明記(`gate-criteria.md:1440`・`:1442`)
  - 列挙に無い離脱: 定義は「構成の状態のうち…本標準が条件と代償措置を定めていないもの」(`:169`)。例外承認は構成の状態でなく、条件は定められている
- 1.10.1 は「満たしていない要求事項は、未達・記録の欠落・逸脱・列挙に無い離脱のいずれかとして表示する」(`:525`)と書く。例外承認を経た基準の不充足は、読み乙を採ると**4 つのどれにも入らない**(区分の欠け)。読み甲を採ると、そもそも「満たしていない要求事項」ではない

### 当たらない(現状)の帰結

- 1.10.2 の適合の主張の条件(`:613`)は、未達・記録の欠落・逸脱・列挙に無い離脱が無いこと。例外承認の有無は条件に無い。**範囲の中に例外承認を経た変更が何件あっても、修飾の無い「適合の主張」を述べられる**
  - 例: G-6 を適用する 3名以上の体制で、範囲の R1 の変更の多くを「緊急」として例外承認で出荷した場合。承認者が作成を指示した者でなく、記録の 5 事項がそろえば、欠落は 0 件
- 併記する事項(`:612-614`)にも例外承認が無い。適用の表明にも無い
- H.8 の 3 つの文の型(`assurance-case.md:819-821`)にも無い
- template の名の導出も同じ。`claimStatus`(`config.mjs:198`)は構成だけを読み、集約の `claimForRange`(`aggregate-evidence.mjs:5102` 付近)は構成の名に欠落(`gaps`)を重ねるだけで、例外の件数を読まない
- #313 がこの型の穴(開示の義務の無い主張)を理由に主張の名を分けた経緯と同じ形が、変更の単位で残っている(ADR-0083 コンテキスト「適合の主張の行に、逸脱の開示の義務がありませんでした」)

### 当たる(閉じた列挙へ足す)とした場合の帰結

- 例外承認を経た変更が範囲にあれば、名は「逸脱を伴う適合の主張」になり、「範囲にある各逸脱の識別と、代償措置の記録の所在」を併記する(`:614`)。台帳の行が識別になる
- 閉じた列挙の性質が変わる。D-1 は構成の 1 つの型で、中身が条項で決まっている。例外承認は、どの判定基準を外すかが案件ごとに開いている。列挙の行は 1 つ(「7.3 の例外承認」)でも、中身は閉じない
- 「条件と代償措置を定める条項」の欄に 7.3 を書くことになる。7.3 の回収・報告を代償措置と呼ぶかが、定義の(ii)の読みに掛かる
- 数え方を決める必要がある: 範囲の中で有効だった例外か、承認された例外か、回収済みを含むか(1.10.2 の「件数を数える範囲」は主張の範囲)
- 7.10 の前提の受容(7.3 の 5 項目を前提にする)を同じに扱うかが問われる
- template: `CLOSED_DEVIATIONS` は構成の `deviations[]` を照らす作りで、台帳の行を読まない。名の導出が台帳(または集約が既に読んでいる例外の対応づけ)を読む必要がある。層1 の印 `[逸脱]` の意味が広がる(印 `[未回収の例外]` が別にある。`deliverable-templates.md:1589`)
- 列挙の追加は N を上げる改訂(第1版の発行前のいまは版を上げずにできる)

## 4. #313 の審議でこの論点が残された経緯

- 起草の委員が未決の点として挙げた: 例外承認は「変更ごとの基準からの外れ」で、逸脱の定義に当たるか、別の区分として件数を併記させるかは「調査の範囲で決めきれない。突合の論点として残す」(`council-01-drafter.md:172`・`:281`)
- 規格の委員は案を出した: 例外承認は「本標準が定めた手続に従っている限り要求事項を満たしている。適合を主張できる。有効な例外承認の件数を主張に併記する」(`council-04-standards.md:120`・`:148`・`:155`)。この案は、逸脱を「要求事項の不充足の全体」とする同委員の枠組みの一部で、枠組みは Q-3 で採られなかった(ADR-0029 と `deviations[]` の語と逆になるため)。例外承認の部分だけを取り出した裁定は無い
- 現場の委員は「列挙の外の不充足は未達、または例外承認の経路による」と書いた(`council-02-field.md:132`)。例外承認を逸脱と別の経路として扱う前提
- 裁定 Q-3(`decision.md` 3 節)と、突合 X-1〜X-16 に、例外承認を扱う項目は無い
- 実装の記録が別 Issue へ送った: 「1.10.2 は未達と記録の欠落を数えるが、例外承認を経た未達の書き方を定めていない」(`implementation.md:188`)。これが #353

残された理由(記録から読める範囲): #313 の Q-3 は語(逸脱)の 1 義化と主張の名を決める論点で、構成の単位の離脱を棚卸しした。例外承認は変更の単位で、台帳に置かれ、棚卸しの対象(本文で「逸脱として記録する」と書く箇所)に入らなかった。
