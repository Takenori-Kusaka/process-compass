最大の弱点は、弁護する側にも否定できない。**例外承認で外した変更が何件あっても、修飾の無い「適合の主張」が成り立つ**ことである(internal 2節)。これを「欠陥」でなく「設計」と言い切れるかが、本件の分かれ目になる。本意見は、言い切れる条件を5・6節で示し、言い切れない部分を弱点として開示する。

## 1. 例外承認は「逸脱」に当たるか

### 1.1 当たらないと決める案(推す案 A')

- 字義: 1.4 の定義の(iii)は閉じた列挙への掲載を要し、例外承認は載っていない。「表に無い離脱を、逸脱と呼びません」(3.5.2)がある。**当たらないは、現行の文言の読みであり、新しい決定ではない**
- 読み甲を採る: 本標準の要求は「基準を満たすか、7.3 の手続を踏むか」の二者択一である。手続を踏んだ変更は要求事項を満たす。7.2 は「基準の不充足を禁止せず、手続として扱う」と書き、ADR-0036 は例外承認を正規の経路に置いた。**手続を満たした変更を「要求事項を満たさない状態」と呼ぶのは、自己矛盾である**
- ADR-0083 の定義との整合: 逸脱の定義は「条件と代償措置を定めて認めたもの」で、離脱が**続く間**の措置を前提にする(D-1 は判定記録の突合・抜き取り)。例外承認の回収・報告は離脱を**解く**手続で、性質が違う(internal 2節 (ii))。ここを混ぜると、定義の(ii)が「措置があれば何でも」に緩む
- #352 の裁定との整合: 列挙を広げない理由は「措置が同程度の防御で、本人以外が確かめられること」だった。例外承認は、これを**逸脱の側で満たそうとしても満たせない**。権限者が承認し、期限が来れば回収する手続は、元の基準の防御と同程度ではない(基準を外すのが目的の手続である)。さらに承認者が作成を指示した者なら記録は対応づかない(G-7)ので、本人以外の確認は別の機構で既に立っている。同程度の防御でないものを列挙に入れれば、#352 で D-2 を退けた論拠と矛盾する
- 外部の先例との整合: PCI は代償統制を使っても合格の状態にでき、別の適合の種類にしない(external D8)。ISO 9001 8.7 と FedRAMP は承認者の記録で足りる。12207 の tailored conformance は規格の適用範囲の調整で、個別の期限つきの不適用とは性質が違う(external の P1 の弱点)

### 1.2 当たると決める案(C)への反対

- 閉じた列挙の「閉じ」が壊れる。D-1 は構成の型で中身が条項で決まる。例外承認は、外す基準が案件ごとに開いている。「列挙の行は1つ、中身は閉じない」は、**閉じた列挙の定義(一覧が有限で、各行の条件が条項に固定)を名目だけ残して空にする**
- #352 の裁定は「列挙は D-1 のまま広げない」と置いた。直後に広げる根拠が、本件にあるとは読めない。広げるなら、#352 の採らない理由を新しい事実で覆す必要がある。覆す事実は見当たらない
- 「逸脱を伴う適合の主張」の名が、範囲に例外承認が1件でもあれば必ず付く。例外承認は R1 で緊急に使われ、普通の運用の一部になる。**ほとんどの実運用の組織が「逸脱を伴う」側に入り、2つの名の識別力が落ちる**。ADR-0083 が名を2つに分けた効用を損なう
- 同じ論は、前提の受容(7.10)にも波及する。7.3 の5項目を使う経路が複数あるので、1つを入れれば残りも入れる理由を問われ、列挙が増殖する

### 1.3 区分の欠け(K-1)は弁護しない

読み乙を暗に採る人が読むと、例外承認を経た不充足は 1.10.1 の4区分のどれにも入らない。ここは**条文の欠け**であり、直す。直し方は次のどちらかではなく、**読み甲を明文にする**ことである。

- 1.10.1 に「7.3 の条件を満たして承認された例外承認は、要求事項を満たしている状態として扱い、4つの区分のどれにも当たらない。承認の条件を欠いた場合は、4.2 のとおり、未達か記録の欠落で扱う」を足す
- 1.4 の逸脱の定義の末尾に「第7章の例外承認は逸脱でない」と、一覧は D-1 のみであることを示す1文を足す(定義は変えず、読み手の誤りを防ぐ)

## 2. 開示させるか(B 案の検討)

### 2.1 開示を足す案(B・E)への反対

1. **新しい義務である**。採用者への併記の義務の新設になり、コアポリシー上「重」の根拠(新しい義務)に当たる。実証がない。外部の先例で「件数の上限」を置いたものは確認されず(external D8)、件数や期限の値は暫定の根拠水準マークになる
2. **開示の目的が不明のまま足すことになる**。適合の主張の読み手は誰か、例外承認の件数を見て何を判断するのか、の想定が調査にない。PCI は提出先(取得者・決済ブランド)が審査する構造が先にあり、開示はその入力である。本標準の適合の主張は**自己宣言**で、受け取る審査者の構造が無い(external の P2 の弱点)。受け手が判断できない数字は、飾りにしかならない
3. **件数は誤読を生む**。例外承認は「満たさなかった」件数でなく、「手続を踏んで満たした」件数でもあり、件数の大小の意味が一意でない。10件の回収済みの例外承認を持つ組織と、0件だが逸脱を黙って重ねた組織で、前者の開示が悪く見える。**手続を踏む誠実さを罰する開示**になる。ADR-0036 と G-7 が「正規の経路を置かないと、記録を偽る動機が生じる」(`gate-criteria.md` 1444行)と書いた理由は、そのままこの開示にも当てはまる
4. **短い引用で落ちる**。併記は名が変わらないので、引用で落ちる(ADR-0083 が「開示で足りる」を採らなかった理由)。落ちる開示を義務にしても、効果は薄い。名を変えるのは C(1.2 で退けた)だけで、B は落ちる弱さを抱えたままである
5. 1.10.2 の「件数を数える範囲」は主張の範囲で、例外承認は変更の単位、台帳の状態は5つである。数え方(有効・承認・回収済み)が決まっていない状態で義務を足せば、**数え方の差が適合の判定に入り込む**。決める根拠が無い値は、恣意になる
6. 機械の検査にできるのは台帳の行と範囲の一致までで、**主張の文に書いたかは様式(IMPL-0120。undelivered)が降りるまで manual**である。降りていない様式の上に新しい併記を足すと、undelivered の規定が1つ増える。#354 が未完のまま義務だけが先に増える

### 2.2 現行の開示の場は足りているか

現行の開示は分散するが、**目的ごとに分けて置かれている**(internal 3節)。

| 目的 | 場 | 時点 |
| --- | --- | --- |
| 全件の状態の追跡 | 技術負債台帳の区分「例外」 | 常時。完了後も保管 |
| 出荷時の残存リスクの開示 | 保証の開示の項目5「未回収の例外」 | 出荷ごと |
| 独立した人の確認を外した R1 | 保証の開示「記録あり n 件 / 記録なし n 件」 | 出荷ごと |
| リスクの受容 | G-8(未回収の例外を受容の対象に含む) | リリース決裁 |
| 帰属の事後の確認 | 内部監査の観点2・15・28 | 監査時 |

**適合の主張は品質保証の主張ではない**(`overview.md` 623行)。例外承認の開示を保証の側に置く設計は、一貫している。主張に足すことは、この切り分けを崩す。

### 2.3 弁護しない点: 主張が単独で出回る(K-3)

- 適合の主張を単独で対外に出すと、読み手は例外承認の有無を知る経路を持たない。ここは**読み手の誤り**に当たる
- 直し方(義務を課さない): 1.10.2 の適合の主張の備考に「適合の主張は、第7章の例外承認を経た変更の有無を述べない。例外承認の状態は、技術負債台帳の区分『例外』と、出荷ごとの保証の開示(H.6 項目5)で確かめる。主張はそれらの代わりにならない」と書く。**義務でなく、主張が何を述べないかの明示**である
- 「課さないと決めた」を明記する文: 「例外承認の件数を適合の主張へ併記させることを、本標準は求めません。理由は、手続を踏んだ変更を満たさなかったものと同列に表示すれば、手続を踏む動機を損なうためです」(案)

## 3. 例外承認で外す規定の種類と、期限切れ・未回収

### 3.1 外す規定の種類(K-2は弁護しない)

internal 1節は外せるものと外せないものを一覧した。次の食い違いは**直す**。

- `tailoring-guide.md` 1122行「安全重要度による要求は、人員や期日の制約によって外れません」と、同1023行「例外承認の経路は、従来どおり使える」は、読み手に「安全重要度の要求も例外承認で外せる」と読ませうる。**直し方**: 7.3 に「例外承認の対象は、ゲートの判定基準に限る。次は対象にしない」と限定列挙を置く(S2 の Sev1、安全重要度による要求、構成の条件=席の兼務禁止・文脈の分離・名簿)。7.4 にしか限定が無い現状(internal K-2)を、7.3 の一般の例外にそろえる
- 構成の条件は、internal 1節のとおり例外承認の対象でない。構成の側の不充足は未達・逸脱・列挙に無い離脱で扱う。**例外承認で職務の分離を外す経路が無いことを、明文にする**。ここが開いていると、#352 で苦労して閉じた体制の線が、例外承認で破られる
- 限定の根拠: 安全・職務の分離に関わる規定は、元の基準の防御が代わりの措置で置換できない。#352 の「同程度の防御」の基準を、例外承認の対象外とする線引きにそのまま使える

### 3.2 期限切れ・未回収の例外

- 期限切れ: 7.3 の条件4(回収の期限と責任者)の効力が切れると、台帳の状態は「失効」に移る。**効力の無い記録は、G-7 の対応づけの4条件を満たさない**ので、R1 の独立確認を外した変更は**記録の欠落**に数えられる(`gate-criteria.md` 1440〜1456行の読み。実行での確認はしていない)。ゲートの判定基準を満たさないままの通過は、基準の側で**未達**が残る
- つまり期限切れの例外は、**既存の区分(未達・記録の欠落)に落ちる**。新しい区分も、列挙に無い離脱も要らない。この落ち方が機械で確かめられるかを、5節で扱う
- 未回収で期限内: 有効な例外承認。要求事項を満たしている状態として扱う(読み甲)。ただし保証の開示に「未回収の例外」として残り続ける
- 弱点: 「期限の長さの上限は無い」(internal 1節)。**無期限に近い期限の例外承認を、期限内の有効として扱い続ければ、実質的な恒久の不適用になる**。これは区分の問題でなく、7.3 の条件の弱さである。#330(期限の無い先送りの型)と同根で、本件では上限の値を置かない(外部に先例が無く、暫定の値になる)。代わりに、保証の開示で期限と経過日数を出す、既存の台帳の欄の読み替えに留める。これは次の6節で開示する

## 5. 統制の閉じ方

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| 台帳の例外の行の欄の存在(対象・状態・承認した者・理由・期限) | 機械 | 既存(IMPL-0038)。変えない |
| 期限切れの例外が、有効として扱われていない | 機械 | 台帳の状態と日付の比較。決定可能な条件。集約が失効を欠落に落とすかを回帰で確かめる(未実行。実施が要る) |
| 例外承認の記録と変更の対応づけ(承認者≠作成を指示した者) | 機械 | 既存(IMPL-0039) |
| 例外承認の対象が判定基準に限られること | 機械の一部 | 台帳の「満たさない基準の項目番号」が実在する G-n の基準かは、機械で確かめられる。外す理由が妥当かは manual |
| 外すのが構成の条件・安全重要度の要求でないこと | 機械の一部 | 項目番号が構成の条件の側を指していないかは、番号の一致で確かめられる。意味の逸脱は manual |
| 承認の当否・理由の質 | manual(内部監査) | 内部監査の観点2・28 |
| 期限の長さが妥当か | adopter | 上限を置かない。採用者が G-1 などで定め、保証の開示の期限の欄で見える |
| 主張の文が例外承認の有無を述べないこと | 判定不要 | 述べないことを定めたので、検査の対象が無い |
| 主張が単独で出回るときの読み手の誤り | adopter | 備考の案内を読むかは読み手による。機械では閉じない |

**開示を足さないので、IMPL-0120(表明の様式。undelivered)を新たに悪化させない**。これは A' の実利である。B なら、undelivered の対象が増える。

template に及ぶ箇所(読むだけ。本束は触れない):

- A' なら、名の導出(`config.mjs` の `claimStatus`、`aggregate-evidence.mjs` の `claimForRange`)は**変わらない**。層1 の印 `[未回収の例外]` の意味も変わらない
- 及ぶのは、7.3 の限定列挙(3.1)を足す場合の `.claude/skills/gate/reference/exception-paths.md` の記述と、期限切れの例外が欠落に落ちることの回帰の場面だけ。標準側の必須欄(`template-fields.yaml`)は、台帳の欄を変えないので及ばない
- B・E を採るなら、集約の出力、表明の様式、PROCESS-PROFILE.md の生成区間、README に及ぶ(internal 6節)

## 6. 弱点と、実証を欠く点(根拠水準マークで開示すべき点)

### 6.1 自分の案の弱点

1. **修飾の無い適合の主張が、例外承認の件数に依らず成り立つ**。例えば G-6 を適用する3名以上の体制で、範囲の R1 の変更の大半を「緊急」で例外承認から出荷しても、記録の5事項がそろえば欠落は0件で、主張に何も出ない(internal 2節)。この穴を、保証の開示と台帳に頼って塞ぐ設計は、**それらを読む読み手にだけ有効**である。主張だけを見る外部の読み手には効かない
2. 期限に上限が無い(3.2)。恒久化の恐れを、本案は開示でなく運用に委ねている
3. 読み甲を明文にする根拠は、#313 の規格の委員の1つの読みと、7.2・ADR-0036 の趣旨である。実走で、読み甲による判定が組織に受け入れられるかは確かめていない
4. 外部の先例は二次情報が多い(ISO 9001 8.7、SOC 2、FedRAMP は原文を確かめていない)。PCI だけが一次で、PCI は「例外を使った」ことを提出先に必ず見せる(E1)。**外部の先例の多数は、開示を求める側にある**。本案はこれに反する。反する理由(自己宣言であり、受け取る審査者の構造がない。件数が誤読を生む)は、論理であって実証ではない
5. 「手続を踏む誠実さを罰する開示になる」(2.1 の3)は仮説で、観測がない

### 6.2 根拠水準マークで開示すべき点

- 例外承認の件数を併記しないことの効果(手続を踏む動機が保たれる)は、実証を欠く。`:::caution[暫定 EV-NNNN / 見直し YYYY-MM]` で開示し、見直しの契機を「ADR-0036 の EV(例外承認の適用件数)の観測」に結ぶ
- 期限に上限を置かないことは、外部に先例が無いための判断であり、暫定とする(#330 の結果で見直し)
- 期限切れが記録の欠落・未達に落ちるという読みは、条文の読みで、**実行で確かめていない**(5節の回帰が要る)。確かめるまで、記述に確定の語を使わない
- 読み甲の採用そのものを暫定とする

### 6.3 採らないと決めたことの記録(却下は成果)

| 案 | 採らない理由(本意見) |
| --- | --- |
| B 例外承認の件数を主張・表明へ併記 | 目的の判断者が不在。数え方の根拠が無い。落ちる併記は効果が薄い。undelivered の規定が増える |
| C 閉じた列挙へ足す | #352 の裁定と矛盾。列挙が開く。2つの名の識別力が落ちる |
| D 例外承認があれば主張を妨げる | 例外承認を正規の経路に置いた ADR-0036 と、記録を偽る動機を避ける G-7 の趣旨に反する |
| E 未回収・R1 のものだけを開示 | 保証の開示と二重になる。部分的な併記は線引きの根拠が要る。ただし、**議長が開示を足すなら、最も害が小さい次善の案**(保証の開示の項目5と同じ「未回収」だけ、主張の備考の所在の案内を、義務でなく推奨で) |
| 件数・期限の上限の新設 | 外部に先例が無い。暫定の値は恣意になる。#330 で扱う |

次善の序列(議長が開示を足すと決めた場合に限る): E(未回収のみ、保証の開示と同じ定義・同じ時点)>B(件数)>C>D。**C と D は、本標準の既存の決定と衝突するので、採るなら ADR の原則の変更として重に扱う**。
