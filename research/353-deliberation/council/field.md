# #353 会議体 委員「現場」の意見

- 日付: 2026-11-15。立場: 標準を採用する開発組織。例外承認を日常の逃がし弁として使う側
- 読んだもの: internal.md、external.md、352-deliberation/decision.md、overview.md の 1.4・1.10.2、assurance-case.md の H.8 の文の型。Issue 本文の「ADR-0082」は ADR-0083 と読む
- 何も実装していない。ほかの委員のファイルは読んでいない。template は触れていない

## 結論(受け入れ条件3つへの答え)

1. **逸脱に当たるか: 当たらないと決める**。閉じた列挙(D-1)へ足さない。#352 の裁定の理由(措置が同程度の防御で、本人以外が確かめられること)に照らすと、例外承認は5条件の手続を踏んでも、離脱が続く間の「防御」を持たない。回収は離脱を解く手続であって、続く間の代償ではない。D-2 を退けた理由がそのまま当てはまる。1.4 に「7.3 の例外承認は要求事項の不充足を手続で扱うもので、逸脱ではない」と1文で明記する
2. **主張とあわせて開示するか: 開示させる**。ただし主張の名は変えず(第3の主張を作らない)、1.10.2 の「併記する事項」へ「範囲の例外承認の件数3つ(承認・うち未回収・うち期限超過)と台帳の所在」を足す。個々の例外の列挙は文に書かせず、台帳へ導く。期限超過の例外は、承認の効力を失った扱いにして、既存の「記録の欠落」(G-7 の承認の記録が無い変更)に寄せる。新しい区分は作らない
3. **1.10.2 と H.8 の揃え方**: 1.10.2 を正本として「併記する事項」と主張の文の型へ件数の句を足し、H.8 は文の型の1行を同じ句に直す(ADR-0083 決定3の順序)。適用の表明にも同じ件数を併記する

最大の懸念: 開示を重くすると、現場は例外承認を使わず黙って離脱する(列挙に無い離脱にもならない形で、記録に出ない)。軽くすると「例外承認を通した変更が何件あっても、修飾の無い適合」が残る。件数3つと台帳の所在だけにするのは、この両側から選んだ線である。ただし、この線の位置を支える実証は無い(論点6)

## 論点1 逸脱に当たるか

### 現場から見た前提

例外承認は、現場では「今回だけ基準を外して出す」ための経路である。使う理由はたいてい次のどれか。

- 緊急の障害対応で、独立した人の確認を待てない(G-6 を適用する体制の R1 の変更)
- 閾値の少し手前で止まった(G-1 で定めた閾値に届かない)が、期日がある
- 未確定事項を残したまま次工程へ進めたい

どれも日常で、月に数件は出る。**例外承認が逸脱になる(適合を「逸脱を伴う」と名乗らせる)なら、現場には「例外承認を1件使うと、その期間の主張の名が変わる」と読まれる**。これは悪くない面もある(隠せない)が、次の実害がある。

### 当たると決める案(internal.md の C)

- ADR-0083 の定義との整合: 定義(i)(ii)は、読み乙と、回収・報告を代償措置と読む解釈を取れば満たせる。しかし(iii)の閉じた列挙は、中身が案件ごとに開く(どの基準を外すかは自由)。列挙の行は1つでも、閉じていない
- #352 の裁定との整合: **合わない**。裁定は、列挙の判断軸を「措置が同程度の防御で、本人以外が確かめられること」に置いた。例外承認の5条件のうち、本人以外が確かめられるのは権限者の記名と台帳の存在までで、「影響が顕在化したときの対処」の十分さは確かめられない。列挙に足せば、裁定で D-2 を退けた基準を、同じ週に自分で破ることになる
- 現場の実害: 逸脱の識別と代償措置の記録の所在を、例外ごとに書かせることになる。月数件を主張の文へ並べる運用は回らない。回らない組織は、例外承認を使わず、承認を通さない離脱(記録の欠落または列挙に無い離脱)へ流れる。これは例外承認の存在理由(ADR-0036: 正規の経路を置かないと記録を偽る動機が生じる)と逆向きである

### 当たらないと決める案(A・B・D)

- ADR-0083 の定義との整合: (iii)が決め手で当たらない。internal.md の字義の結論に同意する
- #352 の裁定との整合: **合う**。列挙を広げない理由と同じ根拠で、例外承認を足さない
- ただし、当たらないだけでは、internal.md が示した区分の欠け(1.10.1 の4区分に入らない)が残る。読み甲(手続を踏んだ変更は要求事項を満たす)を採って、**区分の欠けではなく「満たしている」と整理する**のが素直である。7.3 自身が「満たさないまま」と書く点は、「判定基準を満たさないまま」であって「要求事項を満たさない」ではない、と1.4 側で言い分ける。この言い分けは条文の読みであり、実行では確かめていない(論点6)

推す: **当たらない + 読み甲を明記**。採らない案は C(理由は上記)。D(例外承認があれば主張を妨げる)も採らない。理由は論点2

## 論点2 開示させるか、何を、どこへ、いつの時点で

### 開示させない案(A)の現場の実害

1.10.2 の条件に例外承認が無いので、R1 の変更の大半を「緊急」として例外承認で出した期間にも、修飾の無い適合の主張を述べられる。5条件がそろえば欠落は0件である。具体例を挙げる。

- 3名の体制で G-6 を適用しており、四半期の R1 の変更12件のうち9件を、承認者が作成の指示者でない形で例外承認にした。台帳には9行ある。主張の文には何も出ない
- 受け手(顧客や監査役)は、台帳を見に行く理由がない。ADR-0083 が名を分けた動機(開示は短い引用で落ちる)と同じ形である

これは例外承認が「主張の抜け道」になる実害である。

### 開示を重くする案(B で全件列挙、D で妨げる)の現場の実害

- 全件を主張の文に並べさせる、または1件でもあれば主張を妨げる(D)なら、**現場は例外承認を申請しなくなる**。代わりに、承認の記録を作らずに出す(記録の欠落)、構成を直さずに運用で外す(列挙に無い離脱)、基準そのものを G-1 で緩める(閾値の変更)の方向へ流れる。どれも例外承認より見えにくい
- 例: 月に5件の緊急対応のたびに、主張の名が変わり、顧客向けの文書の差し替えが要る。担当者は「次から例外にせず、事後に直す」と言い出す。事後に直す経路は、7.3 の5条件(承認・期限・回収責任者)を持たない
- D は、7.2(基準の不充足を禁止せず手続として扱う)と、`gate-criteria.md:1444` の「正規の経路を置かないと、記録を偽る動機が生じる」に向きが当たる

### 推す形(件数3つ + 台帳の所在)

何を、どこへ、いつの時点で、を次のとおり決める。

| 項目 | 内容 |
| --- | --- |
| 何を | 主張の範囲で (a) 承認した例外の件数、(b) うち、範囲の終点の時点で未回収の件数、(c) うち、範囲の終点の時点で期限を過ぎて未回収の件数。加えて台帳の所在 |
| どこへ | 1.10.2 の「併記する事項」(適用の表明と、適合の主張・逸脱を伴う適合の主張の両方)。H.8 の文の型。保証の開示(H.6 項目5)は既存の「未回収の例外」を保つ |
| いつの時点 | (a)は範囲の期間の全体。(b)(c)は範囲の終点のコミット(未達と同じ読み方。IMPL-0308 の「範囲の終点の構成で読む」と揃う) |
| 個々の列挙 | 文には書かせない。台帳の区分「例外」の行が正本。受け手が見たければ台帳へ行ける、までを求める |

理由は現場の運用の線である。

- 件数は台帳の行を数えるだけで出る。申請のたびに文書を書き直す必要が無い。四半期の終わりに1回数える作業で済む
- 3つ目の(c)が効く。**期限を過ぎた未回収の例外が増えると、例外承認が「期限の無い逃がし弁」に変わる**。この件数が文に出れば、受け手も社内も気づく。#330(「未実施」が歯止めなく続く)と同じ型の穴を塞ぐ
- 承認者・対象の規定・期限の個別の値は、文には入れない。入れても受け手が判断できる粒度ではなく、書く側の負担だけが増える。PCI は要求ごとに記載するが、あれは第三者の評価者が書く前提で、本標準は自己宣言である。先例をそのまま持ち込めない
- 名を変えない点は、ADR-0083 の「開示は短い引用で落ちる」に弱い。件数の句が引用で落ちても、名は「適合の主張」のままで、誤読の害は、名を分けた2つの主張の間の差より小さい、と見る。この判断は実証が無い(論点6)

### 採らない案(明記する)

- 全件の列挙を文に書かせる: 採らない。回らず、離脱の見えない流れを生む
- 例外承認があれば主張を妨げる(D): 採らない。例外承認が「満たしている」手続である前提(読み甲)と合わず、正規の経路を潰す
- 件数・期限の上限: 7.3 の一般の例外には置かない。先例にも上限を明記した規格が無い(external.md D8)。上限を置けば先例の無い値になり、根拠水準マークの対象になる。期限超過の件数の開示で足りるかを、EV の観測で確かめる
- 第3の主張(例外承認を伴う適合の主張): 採らない。#352 の裁定と同じ理由(名の意味が薄まる)

## 論点3 外せる規定の種類による違い

### 種類ごとの扱い

| 種類 | 現場の使われ方 | 開示の扱い |
| --- | --- | --- |
| 独立した人の確認(G-6)を経ない出荷 | 緊急対応。最も多い | 保証の開示にある「例外承認の記録あり n 件 / 記録なし n 件」を保つ。主張の側では件数(a)(b)(c)に含め、別建てにはしない。別建てにすると文が長くなる。受け手が詳しく知りたい場合は保証の開示を見る |
| 判定基準を満たさないままの通過一般(G-1〜G-8) | 閾値の手前での出荷、未確定事項の残し | 件数(a)(b)(c)に含める |
| G-1 の閾値の変更・判定記録の置き場の受け入れ | 例外承認で外せるが、基準の引き下げそのもの | 件数に含める。ただし**閾値の変更は個別の例外ではなく基準の改訂**なので、変更の件数と日付は台帳または構成の変更の記録から引ける形を保つ(既存の観点15)。主張の文には足さない |
| 構成の条件(席の兼務、文脈の分離、名簿) | 例外承認の対象でない | 外せない。internal.md の整理に同意する。構成の不充足は未達・列挙に無い離脱で扱う。**この線を条文に明記する**ことを提案する。現場は「構成も例外承認で外せるのでは」と読む恐れがある |
| S2 の Sev1、安全重要度(CL)による要求 | 外せない | internal.md の K-2(第8章 :1122 と :1023 の食い違い)を、本件の前提として直す必要がある。直す先は #353 の範囲外とし、後継の既存 Issue へ寄せる |

### 安全・職務の分離に関わる規定を別扱いにするか

別扱いにしない。理由は2つ。第一に、安全に関わる要求は、そもそも例外承認で外せない側に置かれている(CL1 以上は人員や期日で外れない)。外せるものを「安全に関わる」と呼び分けると、境が曖昧になり、外せない側が外せると読まれる。第二に、職務の分離(席の兼務)は構成の条件で、例外承認の対象外である。外せる側は G-6 の独立確認の省略だけで、保証の開示が既に別建てで見せている。

### 期限切れ・未回収の例外

| 状態 | 扱い | 根拠 |
| --- | --- | --- |
| 期限内の未回収 | 有効な例外。件数(b)に出る。主張は妨げない | 7.3 の手続を踏んでいる |
| 期限を過ぎた未回収(失効) | **承認の効力を失ったものとして、承認の記録が対応づかない扱い**にする。当該の変更は、G-7 の記録の欠落(例外承認の記録が無い変更)と同じに数える。したがって、範囲にあれば適合の主張を妨げる | 回収の期限は5条件の1つで、過ぎれば条件が欠ける。条件が1つでも欠ければ認めない、が7.3 の既存の定め |
| 回収済み・取り下げ | 件数(a)に含む。(b)(c)には含めない | 台帳の状態で区別できる |
| 期限の延長 | 新しい承認として扱う。同じ行の期限を書き換えて延ばすことを認めない | 延長の都度、権限者の記名と理由を取り直す。台帳の行の書き換えは機械では見分けにくいため、運用(adopter)の確認に置く |

失効を「記録の欠落」へ寄せる点は、新しい区分を作らず、既存の4区分に収めるための案である。「未達」はゲートの状態(構成の単位)で、変更の単位の失効と単位が違う。「列挙に無い離脱」は構成の状態で、これも違う。残る「記録の欠落」が最も近い。ただし G-7 の記録の欠落の定義(例外承認の記録が変更に対応づかない)に「失効した承認は対応づかない」を足す必要がある。この足し方が既存の突合(X-系)と矛盾しないかは、突合の担当に確かめてもらう必要がある(私は実装を見ていない)。

現場の実害の確認。失効を主張の妨げにすると、期限を過ぎた例外が1件残るだけで、四半期の主張が出せなくなる。厳しすぎるとの反論がありうる。しかし、これは「回収の期限を守れない例外承認」への歯止めであり、それが無ければ期限の無い例外と同じになる。現場は、期限を現実的に決めるか、期限の前に延長を取り直すか、回収する。この3つのどれかを促す設計である。一方、期限が過ぎたことに気づかないまま出荷が続く運用上の事故は起きうる。件数(c)を台帳の突合で毎回数える(機械)ことで、気づきの手段は与えられる。

## 論点4 1.10.2 と H.8 の文案の骨子

文案ではなく骨子を示す。語は本標準の語彙(逸脱=閉じた列挙、記録の欠落、未達、列挙に無い離脱)に合わせる。

### 1.4

- 「逸脱」の定義に、1文を足す: 第7章の例外承認は、基準の不充足を手続で扱うもので、逸脱ではない。閉じた列挙に足さない
- 「適合の主張」の定義の「~が無い範囲に限る」の並びに、期限を過ぎた未回収の例外(=承認の記録が対応づかない変更)は記録の欠落として含まれる旨を、参照で示す

### 1.10.2 の表(適合の主張・逸脱を伴う適合の主張の行)

併記する事項の欄に、次を足す。

- 範囲で承認した例外承認の件数、うち範囲の終点で未回収の件数、うち期限を過ぎた件数(0であることも書く)。技術負債台帳の区分「例外」の所在

適用の表明の行にも同じ件数を足す。0件のときも「0件」と書かせる。**0件の明記は、書かない場合と区別するため**である(「課さないと決めた」と「書かれていない」の区別。コアポリシー)。

### 1.10.2 の本文(箇条書き)

- 件数は、台帳の行から数える。範囲の期間に承認日があるものを(a)、範囲の終点の状態が有効なものを(b)、(b)のうち期限が範囲の終点より前のものを(c)とする
- 例外承認の件数を省いた短い引用でも、名は「適合の主張」のままだが、省いて「例外承認なし」と読ませる書き方をしてはならない。1行の引用(バッジなど)には、件数の句の所在(リンク)を付ける。これは逸脱を伴う適合の主張を省略して「適合」と書かない、既存の定めに倣う
- (c)が1件以上ある範囲は、適合の主張と逸脱を伴う適合の主張をしない(記録の欠落として既に妨げられる。条文で再掲して重複を明示する)

### H.8

- 適合の主張・逸脱を伴う適合の主張・適用の表明の3つの型に、同じ句を足す。「例外承認 n 件(うち未回収 n 件、うち期限超過 n 件)。台帳: [所在]」
- 文の型は H.8 に置き、条件は 1.10.2 を指すだけにする(ADR-0083 決定3)。件数の定義(a)(b)(c)は H.8 に重ねて書かない
- 保証の開示との役割分担を1行足す: 保証の開示は出荷ごとの未回収の例外、主張は範囲の件数

### 直す順序

1.10.2 → H.8 → impl マーク(表明の様式の IMPL-0120 に件数の句を足す) → 台帳の再生成。`lint:refs` は H が引く節番号を検査するので、通るはずである。1.10.2 と H.8 の文の型の一致を確かめる検査は無い(internal.md 7節)ため、一致は manual で確かめる

## 論点5 統制の閉じ方

### 機械の検査にできる決定可能な条件

- 台帳の区分「例外」の行から、(a)(b)(c)を数えること。値の一致・存在・構文だけで決まる
- 期限を過ぎた未回収の例外が対応づく変更を、G-7 が記録の欠落として数えること(日付の比較)
- 承認者が作成の指示者でないこと(既存。IMPL-0039)
- 表明・主張の文の件数と、台帳から数えた件数の一致。様式が降りた後に、機械で比べられる

### manual または adopter にして、根拠水準マークで開示する条件

| 条件 | 区分 | 理由 |
| --- | --- | --- |
| 「影響が顕在化したときの対処」が十分か | manual(内部監査) | 自由な文の意味は機械で閉じない |
| 台帳の行が、期限の書き換えで延ばされていないこと | adopter(権限者の確認)。履歴を残す場所が Git であれば、差分の検査は機械でできる余地があるが、本束では決めない | 改ざんの防止は機械で閉じない |
| 例外にすべきでない離脱を、例外承認の記録で通していないこと(基準そのものの引き下げを個別の例外に偽装するなど) | manual(観点15) | 意味の判断 |
| 主張の文に件数を書いたこと | 様式が降りるまで manual。IMPL-0120(undelivered)に紐づけ、降りていない規定として表示し続ける | 表明の様式が #354 まで降りない |
| 件数を省いた短い引用 | adopter | 外に出る文書は組織の法務部門の確認による(H.8 の既存の定め) |

### template に及ぶ箇所(本束は触れない。挙げるだけ)

## 論点6 推す案の弱点と、実証を欠く点

### 弱点

1. **件数の句は引用で落ちる**。名を変えない以上、ADR-0083 が退けた「開示で足りる」案と同じ弱点を持つ。「例外承認の件数 n 件」の句が、名よりさらに落ちやすい。補う手は、短い引用に所在のリンクを付ける定めだけで、リンクを付けない引用は機械でも見えない
2. **件数は粗い**。1件の重い例外(独立確認の省略で出した R1 の変更)と、軽い例外(未確定事項の残し)が同じ1件に数えられる。受け手は重さを読めない。重さで分けると、論点3の種類の分類が要り、境が曖昧になる。ここでは分けないと決めたが、これは「簡便さ」を理由にしたのではなく、分類の根拠となる実証が無いためである
3. **失効を記録の欠落へ寄せる読み**は、G-7 の定義を広げる。区分の欠けを避ける代わりに、記録の欠落の意味(記録が無い)が「記録はあるが効力が無い」へ広がる。語の混ぜ方として弱い。代案は、第5の区分(失効した例外)を作る形だが、4区分を増やすことになり、1.10.1 を直す大きな変更になる。私は4区分を保つ側を推すが、これは判断である
4. **読み甲(手続を踏んだ変更は要求事項を満たす)**は、7.3 の「満たさないまま」という文言と衝突しうる。言い分けで整えるが、受け手が文言から読み乙を採れば、「満たさないものを満たすと言っている」と読まれる
5. **1名・2名の体制**では、承認者と作成の指示者が同一人物になるため、例外承認の経路そのものが閉塞する(K-4。実走で確認済み)。この体制は #352 の裁定で適用の表明までとなったので、本件の主張の開示は及ばない。ただし、**閉塞した経路を避けて、承認の記録を作らず出す誘因**は残る。本件では解けない。#352 の後継へ寄せる

### 実証を欠く点(根拠水準マークで開示すべき点)

| 点 | 暫定の理由 | 観測で見直す条件 |
| --- | --- | --- |
| 件数3つ(a)(b)(c)の形が、現場で回る負担であること | 現場の経験からの推論。採用者の実測が無い。単一の見立て | 適用の開始の後に、件数を数える作業の時間と、数え間違いの件数を数える |
| 開示が重いと黙って離脱する、という誘因の強さ | 同上。逆に、開示が軽いと抜け道になる、という強さも実証が無い | 採用者の台帳の行数と、記録の欠落・列挙に無い離脱の件数の推移を比べる |
| 期限超過を主張の妨げにする厳しさが、実務で過大でないこと | 7.3 の条件の1つとして既にあるが、実走の件数が無い | 期限超過で主張が妨げられた期間の割合を数える。高ければ延長の運用を見直す |
| 読み甲を採って区分の欠けを避ける整理が、受け手に通じること | 条文の読みの確認だけで、実行では確かめていない | 受け手の問い合わせ(「例外承認は満たしていないのか」)の件数を数える |
| 件数を落とした引用の誤読の害が、名を落とした場合より小さいこと | 推論 | 引用に件数の句が付いている割合を、公開の文書から数える |
| 先例 | PCI は一次の原文で確かめたが、ISO 9001 8.7、FedRAMP、SOC 2 は二次情報。件数・期限の上限を定めた規格は見つからなかった | 一次の原文に差し替える。上限の先例が出れば見直す |

### 議長への申し送り(裁定の材料)

- 重へ上げる理由は、採用者への新しい併記の義務(件数の句)と、記録の欠落の定義の拡張にある。後者は、割れた場合に新しい義務に当たる
- 突合で確かめてほしい点: (1) 失効を記録の欠落へ寄せることが、G-7 の4条件と、X-系の既存の決定と矛盾しないか。(2) 第8章 :1023 と :1122 の食い違い(K-2)を、本件の前に直すか、後継へ送るか。(3) 7.10 の前提の受容を、同じ件数に含めるか。私は含めない案を推す(前提の受容は離脱でなく仮定の受容で、別の経路)が、現場では例外承認と同じ「今回だけ進める」ために使われうる。ここは採否の根拠が薄い
- 採らない案の記録: C(逸脱へ足す)、D(例外承認があれば主張を妨げる)、全件列挙、件数・期限の上限、第3の主張、重さによる分類
