# #353 委員の意見: 品質監査(適合の主張を外から読む者・確かめる者の立場)

- 日付: 2026-11-15。重の審議。読んだもの: `internal.md`、`external.md`、`352-deliberation/decision.md`、Issue #353、`overview.md` 1.10.2(`:637-643`)、`assurance-case.md` H.8(`:819-821`)。ほかの委員のファイルは読んでいない
- Issue の「ADR-0082」は ADR-0083 の誤り
- 凡例: 【実】条文・調査で確かめた / 【推】私の推論で、実行での確認は無い

## 結論(受け入れ条件3つへの答え)

1. **例外承認は 1.4 の「逸脱」に当たらない**。閉じた列挙(D-1)へ足さない。#352 の裁定を維持する。ただし「当たらない」を、**開示の義務が無い**という意味にしない
2. **当たらないが、適合の主張に併記させる**(内部調査の B)。併記の中身は、主張の範囲での例外承認の件数の内訳(承認・回収済み・有効・期限超過)と、各件の識別(台帳の行)、独立した人の確認を外した件の別記。**期限超過で未回収の例外は、併記では済ませず「記録の欠落」に数え、主張を妨げる**。件数の上限は置かない
3. **1.10.2 の併記欄に例外承認を足し、H.8 の文の型を同じ語で揃える**。1.10.2 が正本、H.8 は型だけ(ADR-0083 決定3)。適用の表明にも同じ件数を足す。名は増やさない(第3の主張は採らない。#352 の採らない案と同じ)

私の立場の要約: 範囲に例外承認が何件あっても修飾なしで述べられる現状は、読む者を誤らせる【実: 内部調査 2 節】。読む者は、「適合」と読んだ時点で、判定基準は満たされたと受け取る。実際は、承認者1名の記名と台帳の1行で基準を外した変更が、範囲の大半でもあり得る。これは「何を確かめた主張か」が読めない状態で、監査の側から見て最も避けたい型である。一方、例外承認を逸脱に入れると、列挙の性質が変わる。開示は要る、列挙は広げない、の両立を取る。

## 論点1 逸脱に当たるか

### 当たると決める案(C)

- 整合しない点が3つある【実】
  1. ADR-0083 の定義の (iii) 閉じた列挙に載るかが決め手で、現状は載っていない。足すことは列挙の新設に当たる
  2. #352 の裁定の基準は「措置が元の要求と同程度の防御で、本人以外が確かめられること」。D-1 は構成の離脱で、措置の中身が条項で決まっている。例外承認は、どの判定基準を外すかが案件ごとに開いている。列挙の行は1つでも中身は閉じない。#352 が D-2 を退けた理由(閉じないものを閉じた列挙に入れない)と同じ向きの反対が立つ
  3. 例外承認の回収・報告は、離脱を**解く**手順で、離脱が続く間の防御ではない。定義 (ii) の「代償措置」に当たるかが読みで割れる
- 利点: 名が「逸脱を伴う適合の主張」に変わるので、短い引用で開示が落ちない。これは大きい
- 私が採らない決め手: 利点を取るために列挙を開くと、「列挙は閉じている」という保証そのものが弱まる。名で見せる利点は、下の論点2・5の機械の条件で部分的に取り戻せる

### 当たらないと決める案(A・B)

- 整合する点: 定義 (iii) の字義、#352 の裁定(列挙を広げない)、1.10.1 の4区分、7.2・ADR-0036(例外承認を正規の経路に置く。正規の経路が無いと記録を偽る動機が生じる。`gate-criteria.md:1444`)
- A(開示を求めない)は、読み甲(手続を踏めば要求事項を満たす)を明文にするだけ。「何件あっても修飾なし」が残るので採らない
- B が私の推す案。ただし、B は **K-1(区分の欠け)を解かない**。読み乙(判定基準を満たさない以上、要求事項を満たさない)を採ると、4区分のどれにも入らない。そこで次を明文にする
  - 読み甲を採る: 7.3 の5条件を満たして承認された例外は、要求事項の不充足ではない。ただしそれは「基準を満たした」ではなく「基準を外す手続を踏んだ」にとどまる、と書く
  - 手続の条件を満たさないもの(記名なし・理由なし・期限なし・期限超過・承認者が作成の指示者)は、手続を踏んでいないので要求事項の不充足であり、**記録の欠落**に数える(論点3)

## 論点2 開示させるか。何を、どこへ、いつの時点のものを

### 何を(併記する項目)

| 項目 | 内容 | 閉じ方 |
| --- | --- | --- |
| 承認した件数 | 主張の範囲で承認された例外の全件(回収済み・取り下げ・失効を含む) | 機械(台帳の行) |
| 内訳 | 有効(期限内・未回収)/回収済み/取り下げ/失効 | 機械(台帳の状態) |
| 期限超過の未回収 | 主張の時点で期限を過ぎて状態が有効のままの件数。0 でなければ、主張は述べられない(記録の欠落) | 機械(期限と状態) |
| 外した規定の種類 | 独立した人の確認(G-6)を外した件数と、それ以外の件数を分けて書く | 機械(台帳に「満たさない基準の項目番号」がある。G-6 に当たるかは項目番号で決まる) |
| 各件の識別 | 台帳の行の識別(PR の番号かコミット)と、承認した者の席 | 機械(存在)。当否は manual |
| 承認者と作成の指示者の対応 | G-7 が既に4条件で対応づけている。対応づかない記録は件数に出さず、G-6 の欠落になる | 機械(G-7) |

- 上限(件数・期間の最長)は**書かない**【実】。外部に上限を置く先例が確認できなかった(external D8)。値を置けば実証を欠く暫定値になる。上限の代わりに、件数を外から読める形にすることで、組織の内側の運用の圧力を働かせる【推】
- 承認した全件を数える理由: 回収済みだけを除くと、範囲の中で基準がどれだけ外れたかが読めない。PCI は過去の漏れを事後の代償統制で補えないとする【実: external D8】。事後に回収した件を消せる数え方は、同じ穴になる

### どこへ

- 適合の主張の**併記欄(1.10.2 の表)**と、H.8 の対応する文の型へ。主張の文の中に件数を書かせる。別紙へ送らせない
  - Why: 保証の開示は品質保証の主張に属し、適合の主張には付かない(`overview.md:623`、K-3)。保証の開示へ送る形は、適合の主張だけを引用されたときに情報が付いてこない
- 適用の表明にも、同じ件数を併記する(適用の開始から表明の時点まで)。表明は未達・欠落の件数を既に併記させているので、例外承認の件数も並べるのが自然
- 保証の開示(出荷ごと)は、いまの「未回収の例外」の項のままでよい。適合の主張は範囲全体の件数、保証の開示は出荷時点の未回収、と役割を分ける

### いつの時点

- 主張の範囲(期間またはリリース)の全期間の承認件数と、**主張の時点**の状態。「いつ時点か」を併記させる(主張の時点を文に書く)
- 範囲の外で承認され、範囲の中でも有効だった例外は、有効の件数に入れる(範囲に効いているため)

### 開示させないとした場合の理由は立つか

- 立たない。ISO 9001 8.7 や FedRAMP は承認者の記録で足りるが、FedRAMP は POA&M を利用者に毎月見せる実質の開示で、確かめた範囲に利用者に何も見せない規格は無い【実: external の組合せ】。本標準の主張は自己宣言で、外部の評価者がいない。評価者に当たる者がいない主張は、自分で内訳を書かせるほかに、読む者が確かめる手段が無い

## 論点3 外せる規定の種類と、期限切れ・未回収

### 種類による違い

- 例外承認で外せるのは**ゲートの判定基準**。構成の条件(席の兼務禁止、文脈の分離、名簿)は対象でない【実: internal 1 節】。この線は維持し、条文で一意にする。現状 K-2 の食い違い(`tailoring-guide.md:1023` と `:1122`)があり、安全重要度による要求を例外承認で外せるかが読めない。**外せないと明記する**ことを推す(これは新しい義務でなく、`:1122` の既存の文を 7.3 の側に引くもの。重の判断の対象)
- 独立した人の確認(G-6)を外す例外は、種類として**別記**させる。職務の分離の代替が、本人以外の確認だからである。外した件は、確認の穴が最も大きい【推】
  - ただし主張を妨げる扱いにはしない。G-6 の例外承認は ADR-0036 と `gate-criteria.md:1364` が正規の経路として置いている。妨げれば、正規の経路を置かない場合と同じ、記録を偽る動機が生じる
  - 件数を別記させ、読む者が「R1 の変更のうち、本人以外の確認を経ない出荷が何件か」を読めるようにする。保証の開示が既に「例外承認の記録あり n 件/記録なし n 件」と書かせている【実: internal 3 節】ので、その延長にとどまる
- 判定基準の引き下げ(第2章の手順3)や G-1 の閾値の変更(`gate-criteria.md:2284`)は、基準そのものを動かす。例外承認の件数に数えるが、**別行にする**ことを推す【推】。個別の変更を通す例外と、物差しを動かす例外は、読む者にとって意味が違う。この区分は暫定(根拠水準マーク)
- 安全に関わる規定: S2 の Sev1 は例外なし、CL1 以上は人員で外れない。外せない規定は、外した記録があれば**例外承認の記録が有っても効力を持たない**ので、記録の欠落でなく**列挙に無い離脱または未達**に当たる。ここは新設でなく、既存の整理を確認するだけ【推。条文の突合は議長に委ねる】

### 期限切れ・未回収

- 期限を過ぎて状態が有効のままの例外: 7.3 の要求事項4(回収の期限と責任者)・5(継続の報告)を満たしていない。手続の条件が崩れたので、読み甲の枠(手続を踏んでいる限り)から外れる
- 4区分での位置づけ
  - 未達: 当たらない(構成の単位。ADR-0028)
  - 列挙に無い離脱: 当たらない(構成の状態でない)
  - **記録の欠落**: 当たる読みが最も自然。回収・失効・延長の決定の記録が、期限までに無い。台帳には行があるが、状態の更新の記録が欠けている。機械で閉じる条件(期限<主張の時点、かつ状態=有効)で出せる【推】。記録の欠落の定義(ほかの条項での範囲)との突合は、議長の仕事として残す
- 期限の延長: 延長は新しい例外承認(新しい5条件の記名)として数える。同じ行の期限だけを書き換えた場合は、台帳の変更履歴に残り、承認の記名が無いので記録の欠落になる。この点が書かれているかは未確認【未】
- 取り下げ・失効の状態は、期限超過の逃げ道にしない。失効は「期限を過ぎて更新が無かった」と同義なので、**失効も記録の欠落の件数に入れるか**を議長が決める。私は、失効の行が主張の時点で残っていて回収の記録が無ければ数える、を推す

## 論点4 1.10.2 と H.8 の揃え(文案の骨子)

- 1.10.2 の「適用の表明」の併記欄に足す: 「範囲にある例外承認の件数(承認・有効・回収済み・期限超過の内訳)」
- 「適合の主張」の述べる条件に足す: 「期限を過ぎて回収の記録が無い例外承認が無い」(現行の「記録の欠落が無い」へ含まれるなら、含まれることを明記)
- 「適合の主張」の併記する事項に足す: 「主張の範囲の例外承認の件数(承認・有効・回収済みの内訳)、独立した人の確認を外した件数、各件の識別」
- 「逸脱を伴う適合の主張」の併記にも同じ項目を足す(逸脱と例外承認は別の列とする。混ぜない)
- 1.10.2 の下に1文: 「第7章の例外承認は、逸脱ではない。ただし範囲にある件数を上のとおり併記する。件数が 0 件のときは 0 件と書く」
  - Why: 0 件を書かせる。書かれていない(省略)と、無い(0件)が区別できないため。適用の表明が既に未達 0 件を書かせている型に揃える
- 「逸脱を採らない理由」を1.4 か 3.5 に書く: 列挙を広げない理由は #352 の理由と同じ(措置が元の規定の同程度の防御で、本人以外が確かめられる条件に、例外承認は当たらない)。**採らないと決めたことを明記する**(例外承認を逸脱として扱う案は採らない)
- H.8: 適合の主張の文の型に「[件数の内訳]」の欄を足す。逸脱を伴う型も同様。文の型の表現だけを揃え、条件は1.10.2 を引く
- 順序は 1.10.2 が先、H.8 は後。両者の文の型の一致を確かめる検査は無い【実: internal 7 節】ので、`lint:refs` の拡張が要るかは議長が決める

## 論点5 統制の閉じ方

### 機械で閉じる(決定可能な条件)

- 台帳の区分「例外」の行の数と、状態ごとの数
- 期限と主張の時点の比較(期限超過の未回収の有無)
- 台帳の行が、満たさない基準の項目番号を持つこと(存在)。G-6 に当たるかの分類
- 例外承認の記録と変更の対応づけ(G-7 が既にやっている。IMPL-0039)
- 主張の文に書いた件数が、台帳の集計と一致すること。**様式が降りた後**に限る(IMPL-0120。undelivered)。降りるまでは manual として開示する

### manual・adopter にして開示する

- 承認の当否(基準を外した理由が妥当か)。機械は判定しない(G-7 も当否は判定しない)
- 影響と対処の記述が自由な文として意味を持つか
- 承認者の権限の有無(内部監査 観点2、28)
- 台帳の行を**書かなかった**例外(記録の無い離脱)。これは機械が検出できない。変更の差分から基準の不充足を読む検査は、決定可能でない
- 承認者が実質的に独立か(席は別でも同じ人物。#352 の裁定は、同一人物の承認を記録つきで受け付ける)
- 件数の数え方の宣言(採用者が数える範囲を取り違えないか)

### template に及ぶ箇所(本束は触れない。挙げるだけ)

- `claimStatus`(`config.mjs`)・`claimForRange`(`aggregate-evidence.mjs`)に、台帳または既存の例外の対応づけから、期限超過の未回収を `gaps` へ重ねる条件
- 集約の出力に、範囲の例外承認の件数の内訳を足す
- 表明・主張の様式(IMPL-0120。#354 の順)に、件数の欄を足す
- `PROFILE.md` の生成区間・README の主張の文の型
- 層1 の印 `[未回収の例外]` の意味は変えない。`[逸脱]` の意味は広げない(逸脱に当たらないので)
- 標準側の `template-fields.yaml` は、台帳の欄を変えなければ及ばない

## 論点6 弱点と、実証を欠く点

### 推す案の弱点

1. **名は変わらない**。ADR-0083 が名を分けた理由(開示は短い引用で落ちる)が、例外承認には残る。併記で閉じる限り、「適合の主張」だけを引用すれば件数は落ちる。緩和は、期限超過を記録の欠落として名の側に反映させる点だけ。この弱点は受け入れる。開示で足りるとする代わりに、名の側で閉じる条件を機械で出せる範囲まで入れた、という位置づけである
2. **件数の上限が無い**。承認の記名1件で基準を外せる状態は変わらない。多数の例外を有効のまま回し続ける運用は、期限内である限り主張を妨げない。読む者に判断を委ねる形で、守りとしては弱い。上限を置かないことは「課さないと決めた」と明記する
3. **記録の無い離脱は検出できない**。台帳に書かれない例外は、件数に出ない。件数が 0 件の主張は、台帳を書いていないだけかもしれない。内部監査と抜き取りの突合(manual)に頼る
4. **記録の欠落の定義を広げる**。期限超過を記録の欠落に入れるのは、定義の拡張になりうる。拡張でなく既存の読みの確認か、新しい義務かは議長の判断。重に当たる
5. **小さい体制**。承認者が作成の指示者である記録は対応づかないので、1名体制の例外承認は閉塞する(K-4)。#352 の裁定で1名は主張に至らないので整合するが、2名体制で同じ2名が互いに承認する形は機械で防げない

### 根拠水準マークで開示すべき点

- 件数の上限を置かないこと、期間の最長を置かないこと(外部に先例が無く、内部に実測も無い)
- 例外承認を逸脱としない判断が、外部の出典の多くが二次情報(PCI の付録を除く)に支えられること
- 「判定基準の引き下げ・閾値の変更を別行にする」「G-6 を外す件を別記する」は、読む者が実際にそう読むかの実証が無い。EV-0160 の観測で見直す
- 期限超過を記録の欠落とする読みは、実行で確かめていない
- 外した規定の種類による扱いの差(別記にとどめ、妨げない)の線引きは、私の推論【推】

### 採らない案(明記)

- 例外承認を閉じた列挙へ足す(C): 列挙の中身が開く。#352 の理由と同じ
- 開示を求めない(A): 何件あっても修飾なしが残る
- 範囲に例外承認があれば主張しない(D): 7.2・ADR-0036 の正規の経路と向きが当たる。記録を偽る動機を生む
- 件数・期間の上限を置く: 根拠となる実証と先例が無い
- 例外の種類で主張の名を分ける(E の一部): 名が増えて意味が薄まる(#352 と同じ)。種類は併記で別記する
- 保証の開示だけに載せる: 適合の主張の単独引用で落ちる(K-3)
