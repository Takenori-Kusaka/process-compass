# Issue #353 委員「規格」の意見(重。2026-11-15)

立場: 規格策定機関。読んだもの: internal.md、external.md、`research/352-deliberation/decision.md`、Issue 本文、`overview.md` の 1.4・1.10.1・1.10.2 の該当行、`assurance-case.md` H.8 の文の型。ほかの委員のファイルは読んでいない。条項の実物は internal.md が示す所在を信頼した部分がある(下の「確認の水準」)。

## 結論(受け入れ条件3つへの答え)

1. **例外承認は 1.4 の「逸脱」に当たらない**。定義の文言(ADR-0083)は変えない。閉じた列挙(D-1 のみ)へ足さない。1.10.1 に、例外承認を経た基準の不充足の位置づけを1文足す(「7.3 の条件が満たされている間は、要求事項を満たしている」。internal.md の読み甲を明文化)。
2. **当たらないが、適合の主張と適用の表明に、範囲で効力のあった例外承認の件数と内訳を併記させる**(external.md の P2。開示させる型 E1)。0件でも「0件」と書かせる。**主張の名は変えない**。これに加え、**失効した未回収の例外承認が範囲にあれば、適合の主張を述べられない**とする(新しい義務。重の理由の1つ)。件数・期限の上限は置かない(先例が無く、値に根拠が無い)。
3. **1.10.2 を先に直し、H.8 は文の型に併記欄を足して揃える**(ADR-0083 決定3: 1.10.2 が正本)。保証の開示(H.6 項目5。出荷ごとの未回収)は変えない。併記の様式は #354(IMPL-0120)に乗るので、標準側の文は先に入れ、様式の降下は undelivered で表示し続ける。

最大の懸念: 名を変えない開示は、短い引用で落ちる。ADR-0083 が「開示で足りる」を採らず名を分けた理由と同じ形が、変更の単位で残る。採る理由(下の論点2)を弱点として開示し、EV で見直す。

## 論点1 逸脱に当たるか

### 定義への当てはめ

ADR-0083 の定義は3つの要素を同時に要る(internal.md 2節)。(i) 要求事項を満たさない状態、(ii) 条項が条件と代償措置を定めて認めた、(iii) 閉じた列挙に載る。

- (iii) は載っていない。「表に無い離脱を逸脱と呼びません」とあるので、これだけで当たらない。(i)(ii) の読みに依らずに結論が出る。
- したがって「当たると決める」とは、実質は**列挙へ足す(案C)**ことであり、定義の文言の解釈ではなく、列挙の改訂である。問いの立て方を、議長はこちらへ直すべきである。
- 「当たらない」と決めるために定義を変える必要は無い。変えるのは 1.10.1 の「満たしていない要求事項は4つのいずれかとして表示する」との整合だけである(下)。

### 当たらないと決める案(推す案)と #352 の裁定との整合

#352 が列挙を広げない理由は、措置が**同程度の防御**で、**本人以外が確かめられる**ことを列挙の入口にしたことである(decision.md 2 節。PCI 付録B・C の代償統制の条件に照らした)。例外承認を当てはめる。

- 7.3 の条件のうち「影響が顕在化したときの対処」「回収の期限と責任者」「継続の報告」は、離脱を**解く**手続であり、離脱が続く間に元の要求と同程度の防御を与える措置ではない。D-1 の代償措置(判定記録の突合・抜き取り)とは性質が違う。
- 承認者は D-0 表1の決定者であり、本人以外とは限らない。G-7 が退けるのは「作成を指示した者が承認した」記録だけで、承認者の独立は先例(PCI は外部の評価者、FedRAMP は認可権限者)の水準に届かない。
- 外される基準は案件ごとに開いている。列挙の1行(「7.3 の例外承認」)にすると、中身が閉じない列挙になり、#352 が守った閉じた列挙の性質を失う。
- よって、#352 の裁定と整合する形で**当たらない**。この結論は #352 の2つの基準(同程度の防御・本人以外の確認)を使った推論であり、7.3 が将来この2つを満たすよう改められれば変わりうる。ただし、そう改める案は採らない(7.2 の「禁止せず手続として扱う」と向きが違う)。

### 当たると決める案(C)の論理と、採らない理由

- (ii) を満たすと読むには、7.3 の回収・報告を「代償措置」と呼ぶ必要がある。呼べば、D-1 が満たす水準(同程度の防御・本人以外の確認)より弱い措置を持つものが列挙に入り、D-2(保持者の規定)を同程度の防御でないと退けた #352 の裁定と並ばない。D-2 を退けて例外承認を入れるのは一貫しない。
- 名が「逸脱を伴う適合の主張」になるため、正規の経路を使うことが主張の格を下げ、記録を偽る動機を生む(`gate-criteria.md:1444` の懸念。internal.md 5 節 D の帰結と同じ向き)。PCI は代償統制を使っても In Place のまま扱う(状態の細分で見せる)ので、先例も別の種類にまとめていない。外部の先例のうち、使用を別の適合の種類にするのは 12207 の tailored conformance だけで、これはテーラリング(適用範囲の調整)であり、個別・期限つきの承認とは性質が違う。
- 定義の文言を変えずに済むか: C は(ii)の読みを広げるか、定義の「条件と代償措置」を「条件」へ弱める必要がある。後者は D-1 の入口を弱め、#352 の裁定と衝突する。したがって C は定義の文言を**変えなければ成り立たない**。

### 主張を妨げる案(D)

7.2・ADR-0036(例外承認を正規の経路に置く)と向きが逆で、正規の経路を使うほど主張できなくなる。採らない。ただし「失効した未回収」だけは別に扱う(論点3)。

### 外部の先例の型との対応

| 案 | 型 | 先例 | 水準 |
| --- | --- | --- | --- |
| C(逸脱へ足す) | E3 に近い | 12207 tailored conformance | 二次。原文は #352 の抜き書き |
| 推す案(当たらない+併記) | E1(開示させる) | PCI 代償統制を報告書へ記載(原)、SOC 2 の例外の個別開示(二)、CISA の POA&M(二) | PCI だけ原文 |
| A・P3(承認記録で足りる) | E2 | ISO 9001 8.7(二)、FedRAMP(二) | 二次。原文を読んでいない |

E2 が成り立つ前提は、承認者が主張する本人と独立していること(ISO は権限者と顧客、FedRAMP は認可権限者)である。本標準は自己宣言であり、承認者は組織の内にいる。**E2 の前提を欠くので、E2 だけでは足りず、E1 で補う**というのが私の推論である。これは外部の調査にも明記が無く、委員の推論であり、先例の直接の裏づけではない。

## 論点2 開示させるか、何を・どこへ・いつ

### 開示させる理由

- 適合の主張は「品質保証の主張ではない」とされ、保証の開示を添える要求が無い(internal.md 3 節)。例外の開示は保証の開示に集まっているので、**主張だけを単独で外へ出すと例外の情報が付いてこない**(K-3)。
- 範囲の中に例外承認を経た変更が何件あっても、修飾の無い主張が述べられる(internal.md 2 節)。ADR-0083 が主張の名を分けた理由(開示の義務が無い主張の穴)と同じ形が残っている。
- 先例は、使った例外を表明の受け手に見える形で渡す(PCI、SOC 2)。表明そのものに書かせず、承認者の記録で足りる先例(ISO、FedRAMP)は、承認者が独立している前提に立つ。

### 何を(併記する事項)

併記する事項は、台帳から導ける**決定可能な値**に限る。

1. 範囲で効力のあった例外承認の件数(0件も明記する)
2. 状態の内訳: 有効(未回収)・回収済み・取り下げ・失効
3. うち、独立した人の確認を外したもの(G-6)の件数。G-6 が未達の体制の R1 と、G-6 適用の体制の緊急の変更を分けて出す必要は無い(件数のみ)
4. 台帳の所在(識別は台帳の行)

出さないもの: 承認者の氏名(主張は席の名前で足りる。H.6 の対外の扱いと揃える)、理由の本文、外した基準の項目の内訳(規定別の内訳は台帳に在り、主張には載せない。載せる案は、自由な文の整形になり検査できないため採らない)。

「範囲で効力のあった」の定義: 承認の日が範囲の終端以前で、回収・取り下げ・失効の日が範囲の始端以後(または未回収)のもの。承認日が範囲より前でも、範囲に重なって有効だったものは数える。範囲より前に回収済みのものは数えない。

### どこへ

- 1.10.2 の「併記する事項」に足す。適合の主張と適用の表明の両方。逸脱を伴う適合の主張にも同じ欄を足す(逸脱と例外承認は別の欄)
- 保証の開示(出荷ごと)は変えない。出荷ごとの未回収と、範囲の件数とは尺度が違うので、重ねない
- 主張の名は変えない

### いつの時点

主張の範囲の終端の時点の台帳の状態。範囲の中で承認され既に回収されたものも、内訳に「回収済み」として残る。主張の後に状態が変わっても、主張は書き換えない(主張の日付つきで読む)。

### 開示させない案(A・P3)を採らない理由

- 承認記録は主張の受け手に見えない。ISO 9001 4.3 は影響があれば主張自体を認めない型で、記録だけでは足りない型もある(external.md D8)。
- 単独の P3(受け手に何も見せない)を採る規格は、確かめた範囲に無い(external.md)。
- 採るときは、明記する: 「開示させないと決めた」と書く案として残し、読み手が「書かれていない」と区別できるようにする。ただし私は採らない。

## 論点3 外せる規定の種類と、期限切れ・未回収

### 規定の種類

- **構成の条件**(席の兼務の禁止、文脈の分離、名簿)は、7.3 の対象外(対象は「ゲートの判定基準」)。例外承認で外す経路が無いので、併記の対象にならない。構成側の離脱は未達・逸脱・列挙に無い離脱で扱う。この線引きは、条文に「構成の条件は例外承認の対象外」と明記して固定する。internal.md 1 節は「書かれていない」と読むので、**書かれていない状態を、課さないと決めた状態へ直す**。
- **安全に関わる規定**: `tailoring-guide.md:1122`(安全重要度による要求は外れない)と `:1023`(例外承認の経路は従来どおり使える)が食い違う(K-2)。主張での開示の前提になるので、これを先に直す。私の案: 安全重要度が要求する規定は、7.3 の一般の例外の対象外と明記する。これは新しい義務で、`:1122` の既存の文言に沿う方向(外れない)だが、7.3 に限定が無かったことを変える。7.4 の後回しの禁止(G-4・G-5・認証・認可・データ保全)の限定が7.3 の一般にあるかも条文に無い。**この2点は別の Issue とするか、本件の範囲に含めるかを議長が決める**。私は、開示の前提となる範囲なので含めるべきと考える。
- **職務の分離に関わる規定**(G-6 の独立した人の確認): 7.3 で外せると明記されている(`gate-criteria.md:1364`・`:1440-1444`)。外せるが、承認者が作成指示者なら記録は対応づかず、1名の体制は閉塞する(K-4)。#352 の裁定により、1名の体制は適用の表明までで適合を主張できない。よって、この種類は、適合の主張の側では件数 n(内訳の3.)に出るだけで、1名の体制の併記は表明の側に出る。**G-6 の例外承認だけを別に件数で出す**のは、独立した確認という本標準の中心の統制を外した件数が、読み手の判断の中心になるため(外部の先例は種類ごとに区別して書かせる。PCI の代償・カスタマイズ・法的制約、FedRAMP の3種)。
- **ゲートの判定基準**: 一般の外せるものは、内訳を主張に載せない(台帳に在る)。S2 の Sev1 は「例外なし」であり、外せない。これを併記の欄の説明に書く。

### 期限切れ・未回収

台帳の状態に「失効」がある。期限を過ぎて未回収の例外が、どの区分に当たるか。

| 候補 | 判断 |
| --- | --- |
| 未達 | 当たらない。未達は構成の単位(ゲート)、例外承認は変更の単位(ADR-0028) |
| 記録の欠落 | 当たらないと考える。記録は在る。出荷の時点では承認が有効だったので、G-7 の対応づけは成り立つ。事後に欠落と読み替えると、正規だった出荷を遡って不適合にする。PCI が過去の漏れを事後の代償統制で補えないとするのと逆向きの遡及になる |
| 列挙に無い離脱 | 定義が「構成の状態」であり、例外承認は変更の単位で、条件も定められている。当たらない |
| 逸脱 | 当たらない(論点1) |

**どれにも当たらない**。1.10.1 の4区分の欠けとして K-1 が残るのは、この失効未回収の例外だけになる(有効な例外承認は読み甲で解く)。

推す扱い: 新しい区分を作らず、**1.10.2 の「述べる条件」に直接足す**。「範囲の終端の時点で、失効した未回収の例外承認が無いこと」を適合の主張を述べる条件とする。理由は、期限と回収責任者を定めさせた7.3 の条件が破られた状態で、「手続の外へ出た基準の不充足」となっているので、主張を支える根拠が無いからである。有効な例外承認は妨げない(7.2・ADR-0036 の向きを守る)。

- これは新しい義務(採用者への新しい条件)であり、**重**に当たる理由の1つ。#330(期限の無い先送りの型)の歯止めにもなる。
- 区分を作らずに条件で閉じる利点: 区分の語が増えず、#352 が守った閉じた列挙に触れない。
- 弱点: 失効した後に回収すれば条件は満たされる。回収済みに遡って主張が復活するので、失効の期間の記録が主張に残らない。内訳の「失効」の件数(回収済みのうち失効を経たもの)を併記すれば足りるが、これは状態の履歴が台帳に要る(欄の追加の有無は template-fields で確認が要る。私は未確認)。

期限の上限は置かない(外部に先例が無い。置けば根拠の無い値になり、暫定のマークの対象)。7.3 の「期限を必ず定める」を維持する。

## 論点4 1.10.2 と H.8 を揃える(文案の骨子)

1.10.1:
- 追記: 「第7章の例外承認は、7.3 の5つの条件がそろい、回収の期限を過ぎない間は、要求事項を満たしていることとして扱う。逸脱ではない。1.10.2 の併記の対象である」
- 4区分の文は変えない。例外承認は4区分の外で、1.10.2 の別の欄で表示する、と書く。

1.10.2 の表(骨子):
- 述べる条件(適合の主張・逸脱を伴う適合の主張): 既存に加え「範囲の終端の時点で、失効した未回収の例外承認が無いこと」
- 併記する事項(適用の表明・適合の主張・逸脱を伴う適合の主張): 既存に加え「範囲で効力のあった例外承認の件数、状態の内訳、うち独立した人の確認を外したもの、台帳の所在。0件も0件と書く」
- 件数を数える範囲: 主張の範囲に重なって効力のあった例外承認(承認日・状態の日で決める)
- 「例外承認を使った範囲を省略して『適合』と書かない」(逸脱の省略禁止と同じ型)

H.8: 3つの文の型の末尾に、同じ文言の併記欄を足す(適合の主張「…に適合している。範囲で効力のあった例外承認は n 件(有効 n、回収済み n、取り下げ n、失効 n。うち独立した人の確認を外したもの n)。識別は[台帳の所在]」)。「使ってよい表現」の条件欄は「述べる条件と併記する事項は第1章 1.10.2 による」を維持するので、中身の重複を作らない。1.10.2 を先に直し、H.8 は型だけ。1.4 の用語の「適合の主張」「適用の表明」の末尾の列挙にも「例外承認の件数」を足す(逸脱の定義は触れない)。

## 論点5 統制の閉じ方

### 機械の検査にできる(決定可能な条件)

- 台帳の行の件数・状態の集計(区分「例外」、状態、期限、範囲との重なり)
- 失効した未回収の有無(期限 < 範囲の終端、かつ状態が有効)
- 主張・表明の併記の数が、台帳の集計と一致すること(様式が降りたあと。値の一致)
- G-6 の例外承認の件数(集約が既に対応づけている。IMPL-0039)

### manual または adopter にして、根拠水準マークで開示する

- 承認の当否、期限の妥当性、理由の質(自由な文の意味)
- 台帳に載せない例外承認の網羅(台帳の網羅は機械で閉じない。G-7 は R1 の欠落しか捕まえない)。内部監査の観点2・28と採用者の責任

- 集約の出力に「範囲の例外承認の件数と内訳」(`aggregate-evidence.mjs` の `claimForRange` の近く。例外の対応づけは既存)

## 論点6 弱点と、実証を欠く点

### 推す案の弱点

1. **名が変わらない**: 件数が多くても「適合の主張」の名は同じ。短い引用で併記は落ちる。ADR-0083 の理由と向きが同じ。対策は、併記を省略した「適合」を禁じること(省略の禁止)だが、機械では閉じない(manual)。件数が閾値を超えたら名を分ける案(E)は、先例が無く値に根拠が無いので採らない。
2. **自己宣言の限界**: 台帳に載せない例外承認は数えられない。併記の数が少ないことは、使っていないことの証拠にならない。
3. **1名の体制では例外承認が使えず**(K-4)、併記が 0 件でも意味が違う(使えないのか、使わなかったのか)。#352 の裁定で適合を主張できないので、主張の側には出ないが、適用の表明の 0 件の意味は区別できない。
4. 失効した未回収で主張を妨げる条件は、回収すれば復活する。失効の履歴が無いと弱い。
5. 「範囲で効力のあった」の数え方は、期間とリリースの2つの範囲で、承認日と回収日の端の扱いに曖昧さが残る。

### 実証を欠き、根拠水準マークで開示すべき点

- 件数と内訳の併記が、読み手の判断を変えること(実証なし。単一の設計者の推論。E1 未満)
- 失効した未回収だけを主張の条件にする線引き(値の閾値は無いが、「1件でも」に根拠が無い)
- 期限・件数の上限を置かない判断(先例が見つからなかったことは、上限が不要の証拠ではない)
- 構成の条件を7.3の対象外とする線引き(条文に書かれていない状態を、課さないと決めた状態に変える。実走の観測が無い)
- 安全重要度の要求を7.3の一般から外す点(K-2 の解消の向き。#352 と同じく適用の実走が無い)
- 差し替え条件の候補: 適合の主張を出した組織の範囲に、併記された例外承認の件数と、のちに見つかった台帳の外の例外承認の件数。外が1件でもあれば、台帳外の離脱を数える向きで見直す。

### 確認の水準

- 外部の先例は PCI 付録B だけ原文(#352 で確認)。ISO 9001 8.7、FedRAMP、SOC 2、CISA、17050 は二次または未確認(external.md)。**これらに依る主張は、型の分類の補助にとどまる**。結論の根拠は、ADR-0083 の定義の字義と #352 の裁定の2基準である。
- 条項の行番号と文言は internal.md を信頼し、1.4・1.10.2・H.8 の該当行だけを実物で見た。7.3 の全文と `gate-criteria.md` の G-7 の4条件は読んでいない。
