## 4. 受付で見つけた前提の欠け(所有者に問う)

**条件 V(公開か Pro)**: 2026-11-26 に所有者の既存の private リポジトリ2件へ `gh api repos/.../rulesets` と `.../branches/main/protection` を読んだ。どちらも HTTP 403「Upgrade to GitHub Pro or make this repository public to enable this feature.」だった。所有者のアカウントは GitHub Free で、**private のリポジトリではルールセット・旧来のブランチ保護が使えない**。コードオーナーの必須化と、private の Environment の保護も同じく使えない(`research/371-*` の外部 1.7 と同じ)。前例の #371 の実機の確認は `--public` で作った。

許しどおり private で作ると、受け入れ条件の中心(既存のブランチ保護とルールセットの重なり、env-check の9項目のうち統制の4つ、必須チェックの効き方)が確かめられない。README の「ルールセットを使えない場合」の経路を観測するだけになる。

問い Q1〜Q3 は `01-trial-plan.md` §0 にまとめた(公開にしてよいか / 別のアカウント `ganbariquestsupport-lab` を承認者・フォークの持ち主に使ってよいか / 一時の fine-grained PAT を委任のマージに置いてよいか)。
