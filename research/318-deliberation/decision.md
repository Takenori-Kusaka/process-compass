# 議長の裁定(#318 独立の強さを距離で上げる案と、S0 の残り)

入力: `issues-context.md`、`survey-318-1-internal.md`、`survey-318-2-external.md`、`council-00-agenda.md`、`council-01`〜`05`。新しい ADR は ADR-0088。番号の起点は EV-0180・IMPL-0344・SRC-0675。ツールの要件の文書の所在は `src/content/docs/tool/requirements.md`(議題の書いた所在は誤り)。

## 0. 全体の方針

- 判断軸は「独立の強さを、記録から確かめられる属性で表すこと」です。定義の無い「組織的に独立」は、小さな体制で隣の同僚に読み替えられ、監査で確かめられません(現場 F・品質保証 F1・F2)。
- 距離は、人数を**置き換えず**、別の軸として足します。5委員が一致しました。2名の目的は ADR-0067 決定1(1名の承認者の確認だけで取り込めない状態を作る)であり、強さの段ではありません。外部の調査が示す「人数で強さを上げる規格は無い」は、本標準がもう主張していない主張への反論です(擁護者)。
- 距離の段は、規格に倣い、**評価・確認の活動**(独立した安全性の評価と、5.8.4 の段階「最強」の検証の担当者)に掛けます。G-6 の変更ごとの承認には掛けません(規格の委員: 規格の段は確認の活動に掛かり、検証の独立は「別の者」で足りる。DO-178C も同じ)。
- 規格の原文を読めていない判断(ISO 26262-2 表1 は GB/T 34590.2 の公開の草案で読んだ)は、版を明記し EV で開示します。

## R-1 距離の段

**裁定**:

1. **第1章 1.4 に「組織上の距離」と段1〜4 を定義します**。判定の軸は、指揮系統・資源(予算と人事評価)・リリースの権限の3つです。

   | 段 | 名称 | 成立の条件(確認者と、実装の責任者・作成者との関係) |
   | --- | --- | --- |
   | 段1 | 別の者 | 別の自然人である(1.4「独立」) |
   | 段2 | 別の指揮系統 | 段1 に加え、直属の上長が異なり、確認者が対象のリリースの権限を持たない |
   | 段3 | 組織上の独立 | 作成の部門から、指揮系統・資源・リリースの権限の3つで独立している(1.4「組織上独立した検証」と一致させる) |
   | 段4 | 第三者 | 別の法人で、案件に利害を持たない(1.4「第三者レビュー」と一致させる) |

   - 段は数字で呼び、外部の規格の記号(I0〜I3 等)を並べません。対応は注記で情報として示します(規格の委員)。
   - 2名の会社では、段2・段3 は内部で成立しません(指揮系統・予算・リリースの権限が1つ)。体制の人数ごとに、内部で届く段と外部から調達する段を表で示します(起案者)。
2. **求める段**(暫定。新 EV、E1):
   - 独立した安全性の評価: CL2 は段2 以上、CL3 は段3 以上。
   - 5.8.4 の段階「最強」(テスト生成の検証の担当者): CL2 は段2 以上、CL3 は段3 以上。
   - G-6 の承認: 段1(現行どおり)。距離を足しません。
3. **5.8.4 と軸E の食い違いを解きます**(起案者 F6)。附属書F 要求4 と 5.8.4 は「安全関連ソフトウェアは最強」、軸E の表は CL2 を「強」とします。附属書F は CL2 から掛かる個別の要求であり、表の側を誤りとします。軸E の表の CL2 を「最強(段2 以上)」、CL3 を「最強(段3 以上)」へ改めます。CL2 には厳しくする向きの変更です。最強を CL3 に限る案(起案者)は、附属書F 要求4 を CL2 で緩めるため採りません。
4. **届かない段は未達です**。外部の評価者を名簿へ登録して満たすことができます。登録が無い間は未達として表示し、CL1 以上は第8章により未達のまま出荷しません。
5. **理由を書いて低い段を選ぶ経路は置きません**(現場・品質保証・擁護者)。基準を満たさないまま進める経路は3つ(例外承認・前提の受容・未解決事項)で閉じており(`exception-escalation.md`、`overview.md`)、4つ目を作ることになるためです。小さな体制では常に使われる逃げ道になります。IEC 61508 の型(規格の委員)は採りません。なお、例外承認の経路は従来どおり使えます。
6. **AI の確認者は、どの段にも数えません**。DO-330 のような適格性による算入の経路も作りません。本標準に道具の適格性の手続が無いためです。
7. 「組織的に独立した者」(G-6 の独立した安全性の評価・軸E・附属書F 要求5)と「組織的な独立」(5.8.4)を、段を名指す語へ改めます。`human-ai-boundary.md` の「段階的に上がります」から 1.4 を引きます。
8. ADR-0067 の「検討した選択肢」で先送りした「人数ではなく距離で上げる」と、#305 の案5 の却下の理由(距離は独立した安全性の評価に既にある)は、本件の ADR-0088 で決着を記録します。採用済みの本文は書き換えません。
9. 構成への降ろし方(名簿の欄、段の検査、外部の評価者の登録、IMPL-0080 の強化、IMPL-0184)は #357 へ渡します。本件で付ける段の実装マークは `state=undelivered plan=scheduled issue=357` とし、それまで機械が確かめるのは段1 だけであることを注記に書きます(品質保証)。

## R-2 CL1 以上の、軸B による G-6・G-7 の緩和

**裁定**: CL1 以上では、軸B による G-6・G-7 の緩和(省略・簡略・範囲の限定)を、どのステージでも適用しません(起案者の案)。

- 4委員が CL1/S0 の G-7 の適用を求め、擁護者は S1 と同じ「簡略」を求めました。「簡略」は本文に中身が無く(現場・起案者が確認)、簡略にすると、定義の無い語で出荷判定を緩めることになります。採りません。
- S0 だけを戻すと、CL1 以上で S0 が S1 より厳しい逆転(G-7 の簡略、G-6 のコア機能への限定)が残ります(起案者 F2・F3、擁護者もエンジンで確認)。ステージが進むと統制が緩む逆転は、利用者が説明できません。ADR-0065 決定3 の理由「危害の深刻度は、体制の都合でも事業ステージの都合でも下がらない」は G-6 に限る理由を含まず、G-7 と S1 にも同じく当たります。
- G-7 の省略のもとでも、出荷の証跡の集約は独立の欠落を数え続けますが、それを読んで差し戻す席が無くなります(品質保証 F3、起案者 F5)。G-7 は G-6 の欠落を差し戻す唯一の場所です(規格の委員)。
- 規則 `r-e-cl1` に、G-7 の省略・簡略の取り消しと、G-6 の範囲の限定の取り消しを足します。CL2・CL3 の S0 の G-7 の復帰を、副作用ではなく決定として規則に書きます。エンジンの試験で S0〜S2 × CL0〜CL3 の全升の G-6 の範囲と G-7 の状態を固定します。
- 軸B の表の G-6・G-7 の升と、軸E の読み方の1つ目の箇条を直します(限定は行の中に書く)。
- CL1 の S0・S1 と CL2 の S1 には厳しくする向きの変更で、第8章により即時に適用します。告知の対象です(R-5)。
- CL0 の S1 の G-7「簡略」の中身の定義は本件の範囲外で、後継の Issue の候補とします。

## R-3 ツールの要件の文書のシナリオ

**裁定**: 文を直し、エンジンは直しません。5委員が一致しました。

- シナリオ1 を、エンジンの出力に合わせて直します。確認者がいる場合は G-6 を省略し CI の厳格化を伴わないこと、いない場合は G-6 が未達で、CI の厳格化は代償措置であり代わりにならないこと(ADR-0028 決定6)、G-1(簡略)・G-3・G-8 も残ることを書きます。
- シナリオ2 の「推奨として付く」(1.7.3 と当たる)と、品質「高」の入力の欠落(品質保証 F7)も直します。
- 文書の冒頭に、要件の文書は規則の帰結を示す例で、標準の一部ではなく、正本は標準と規則データであることを書きます。
- シナリオが主張する出力を、ペルソナの試験の主張として置きます。確認者のいない変形を足します。各シナリオに試験の所在を書きます。文とエンジンの出力を機械で照合する検査は作りません(現場・擁護者)。文は例であり、主張は試験が持つためです。

## R-4 未達が解けた後のカバレッジの下限

**裁定**:

- 代償措置で上がった下限(90)を、未達の記録に属する値として、基準値(導出値の 80、または組織が較正した値)と分けて持ちます(起案者)。構成に下限の由来の欄(導出・代償措置・較正)を置きます(現場・品質保証・規格)。
- 未達を解く変更では、代償措置の終了(90 → 基準値)を**同じ差分の中に緩める向きの行として出し、その変更の記名で決めます**(品質保証・規格・擁護者)。別の記名の儀式は要しません(現場の懸念)が、黙って戻すこともしません(ADR-0055 決定5)。席を埋める変更は `/process-change` を経て記名されるため、追加の手間は差分の1行を読むことだけです。
- 「較正により変更」の表示は、由来が較正の場合だけに出します(品質保証 F4)。
- 由来の記録の無い旧い構成の 90 は、黙って下げません(ADR-0085)。取り込みの際に、由来が不明である旨と戻す候補を表示し、採用者が記名で決めます。
- 試験: 未達で 90、解けると差分に終了の行、較正の値は動かない、表示、旧い構成の5つ。
- ADR-0065 の影響の節の「90 のまま残る」は、ADR-0088 が置き換えます。ADR-0065 のステータスの節から ADR-0088 を指します。
- 80・90 の値の根拠は EV-0143 のまま #296 へ渡します。安全規格に帰しません。
- 下限を下げる決定者が `RULE_APPROVER_SEAT` であり第8章の決定者と食い違う疑い(品質保証 F5)は、実装で確かめ、食い違えば第8章に合わせます。

## R-5 既存の CL2 の構成と、緩める向きの更新

**裁定**:

1. ルールセット `safety` を足したことを ADR-0088 に決定として記録します(ADR-0067 決定5 の帰結)。IMPL-0110 の注記に書き足します。
2. `standard-editions.md` の保守者の手続を、再導出で緩める向きの差分になる更新へ広げます。差分の行、理由、採用者の記名の経路を告知し、取り込みでは値を変えずに表示し、採用者の記名でだけ適用します。ADR-0085 の却下は「黙った緩める再解釈」だけで、これと当たりません。
3. テンプレートの README に、#302〜#310 と本件の更新の告知を遡って置きます。旧い CL2 の構成(`regulated`、承認2)はそのままで不適合ではないこと、2件目の承認は保証の主張に数えないこと、`safety` へ移るには記名が要ることを書きます。
4. 軸E の読み方の「ブランチ保護が強制する承認の数は、この表の人数と一致させる」を「下回らせない。上回る承認は保証の主張に数えない」へ改めます(規格の委員)。本文が「一致」、env-check が「以上」で食い違い、「一致」のままでは旧い構成が不適合となり、採用者を緩める変更へ追い込むためです。本文の側を誤りとします。
5. 契約検査は、強制される承認の数が構成の数を上回るとき、失敗ではなく注記を出し、保証の開示に出します(起案者・品質保証)。外から見える承認2 と記録の保証1名分の食い違いを隠さないためです。
6. 黙った書き換え(`migrate` による自動の移行)と、旧い構成を不適合として落とす案は採りません。
