## R-1 独立の強さを、承認者の人数ではなく確認者の距離で上げるか

### 結論(採る案): 「距離」と「人数」を別の軸として**併用**する。距離の段を第1章に定義し、既存の「組織的に独立」の箇所をその段で読み替える。人数(CL3・規制業・「高」のコア機能の2名)は置き換えず、独立の強さではなく**取り込みの統制**として位置づけ直す

1. 第1章 1.4 に「組織上の距離」を定義する。軸は3つ(指揮系統、資源、リリースの権限)。段は4つ
   - 距離0(別の自然人): 既存の「独立」(3.5.4)と同じ
   - 距離1(別の指揮系統): 直属の上長が作成側と別で、当該の変更のリリースの権限(G-8 の決定者の席)を持たない
   - 距離2(別の部門): 管理・資源(予算と人事評価)・リリースの権限のいずれでも作成側の部門から独立
   - 距離3(別の法人): 作成側の法人と別の法人。共通の所有・役員による結び付きが無い
   - 上の段は下の段を満たす
2. 既存の「組織的に独立」の2か所に、段を割り当てる
   - CL2 の独立した安全性の評価: 距離1 以上
   - CL3 の独立した安全性の評価、および 5.8.4 の「最強」(安全関連): 距離2 以上
3. 段を下げる経路(IEC 61508 の「理由を書けば低い独立性」)は**置かない**。届かない場合は、外部の評価者(距離3)を名簿へ登録する。登録しなければ未達として表示し続ける(CL1 以上は「未達のまま出荷しない」が既に掛かる)
4. AI の確認は、どの段にも数えない(既存の「AI の確認は検出の層」を距離の語彙でも明記する)
5. 承認者の人数の規定は変えない。軸E の読み方の CL3 の行は ADR-0067 が既に「機能安全の規格が確認者の人数を求めるとは主張しない」と書いている。これを「人数は独立の強さの段ではなく、1名の確認だけで変更を取り込めない状態を作る統制である」と明記する

### 理由

- **定義が無い語は、小さな体制で必ず形骸化する**。5名のスタートアップが CL2 の「組織的に独立した評価者」を求められると、隣の席の同僚(同じ CEO に報告し、同じ予算で、同じリリース会議に出る)を書く。名簿の検査は「開発者の席の責任者・作成を指示した者・判定者と別人」まで(IMPL-0080)なので通る。標準の文面は満たし、規格の言う独立は満たさない。現場では、これがいちばん起きやすい
- #305 で距離の案を退けた理由「距離は独立した安全性の評価が既に持つ」は、規格の委員自身が「定義があって初めて成り立つ」と書いた(内部 1.3)。定義を置かない限り、その退けの理由が成り立たない
- 外部調査で、読めた規格はすべて距離で段を作り、人数で段を上げるものは無い(外部 0・8 の 1)。段の軸は指揮系統・資源・リリースの権限に収れんする(外部 1.1 の I3、5 の IEEE 1012)。現場にとっても「誰に報告するか」「誰の予算か」「誰がリリースを決めるか」は、組織図を見れば答えられる問いで、運用できる
- 段の割当て(CL2 → 距離1、CL3 → 距離2)は、ISO 26262-2 表1 の機能安全アセスメントの行(ASIL A は要求なし、B は I0、C は I2、D は I3)と、IEC 61508 の SIL3 で部門・SIL4 で組織(二次)に対応させた。CL2 は「危害は重篤ではない」ので ASIL B〜C 相当、CL3 は C〜D 相当と読んだ。この対応は本標準の推論で、実証は無い(EV で開示する)
- **段を下げる経路を置かないのは、現場で既定の逃げ道になるから**。「理由を書けば下げられる」は、小さな体制では「全員が理由を書く」に収束する。CL2・CL3 の採用者は既に外部の評価機関と付き合っている(前提の2つ目)。外から買う経路が現実にある以上、下げる経路は信頼性を下げるだけで、得るものが無い
- 人数を残すのは、外部調査の人数の知見(2名で頭打ち、1名は劣る。Porter 1997、Rigby & Bird 2013)が「1→2」には効果があることを示すため。2名は「独立の強さ」の主張に使えないが、取り込みの統制としては外す理由が無い。外すと、CL3 が CL2 に足すものが距離2 の評価だけになり、変更ごとの統制が CL2 と同じになる
- 3〜9名の体制は、距離1 に社内で届く場合と届かない場合がある(全員が代表に直属なら届かない)。距離2 には社内でまず届かない。外部 7 の「最下段は内部で、中段は小さな組織で構造的に成立しない、上段は外から買う」と同じ形になる。本文に「内部で届く段」と「外から買う段」を書いておけば、採用者は初期化の前に費用を見積もれる。見積もれない規定は、運用の途中で未達として現れ、手戻りになる

### 文の案

第1章 1.4(用語):

> **組織上の距離** 確認する者と作成する側の、組織上の隔たり。指揮系統(直属の上長)、資源(予算と人事評価)、リリースの権限(当該の変更のリリースを決定する席)の3つで判定する。次の4段とし、上の段は下の段を満たす。
>
> - 距離0(別の自然人): 確認する者が、作成を指示した者・実装の責任者と別の自然人である
> - 距離1(別の指揮系統): 距離0 に加え、確認する者の直属の上長が作成側の直属の上長と別であり、確認する者が当該の変更のリリースの権限を持たない
> - 距離2(別の部門): 確認する者が、管理・資源・リリースの権限のいずれでも作成側の部門から独立している
> - 距離3(別の法人): 確認する者が、作成側と別の法人に属し、共通の所有・役員による結び付きを持たない
>
> 承認者の人数は、組織上の距離を上げません。AI の確認は、どの段にも数えません。

軸E の表の「独立した安全性の評価」の行: CL2「必須(G-6 に重ねる。距離1 以上)」、CL3「必須(G-6 に重ねる。距離2 以上)」。5.8.4 の「最強」の行: 「強に加え、検証の担当者を実装の責任者から距離2 以上に置く」。

軸E の読み方に追加:

- 組織上の距離の下限を、理由の記録で下げない。社内で届かない場合は、外部の評価者(距離3)を名簿へ登録する。登録が無い間は未達として表示する
- 1〜9名の体制では、距離2 に社内で届かないことが多い。距離1 には、全員が同じ代表へ直属する体制では届かない。外部の評価者の費用を、G-1 の企画書の期間予算に含める
- CL3・規制業・「高」のコア機能の承認者2名は、独立の強さの段ではない。1名の確認だけで変更を取り込めない状態を作る統制である(ADR-0067)

根拠水準マーク(新 EV): 「CL2 に距離1、CL3 に距離2 を割り当てる対応。根拠 E1(間接)。ISO 26262-2 表1 は GB/T 34590.2 の公開草案で、IEC 61508 の表は二次資料で読んだ。CL と ASIL・SIL の対応は本標準の推論。差し替え条件: ISO 26262-2:2018 と IEC 61508-1:2010 の原文で、機能安全アセスメントの独立性の表を確かめる」。EV-0102 の差し替え条件のうち「原文が人数を求めているか」は、表1 に人数の規定が無かった(外部 1.1)ので、草案の範囲で一部充足と書き換える(台帳は自動生成)。

### 既存の ADR・条項との矛盾

- ADR-0067(2名の目的)と矛盾しない。むしろ「人数の主張をしない」を延長する
- ADR-0060 決定3・3.5.4「安全関連は組織上の独立を重ねる」は、語を定義するだけで向きは同じ
- **G-6 の「確認者を置けるか」(ADR-0065 決定5)とは別の判定**。G-6 の独立は距離0 のまま。混ぜない
- IMPL-0080(記名の有無と別人)は、距離1・2 を確かめていない。#357 で欄が入るまで、IMPL-0080 の注記を「距離は確かめない」と書き換えるか、別の IMPL を `state=undelivered` で立てる

## R-2 CL1 以上かつ S0 の G-7

### 結論: CL1 以上は、S0 でも G-7 を**適用**する。規則 `r-e-cl1` に G-7 の省略の取り消しを明示し、CL2・CL3 の副作用による復活を決定として固定する。軸B の表の G-7 の S0 の升に「CL1 以上は適用」を書く。試験で S0 × CL0〜CL3 の G-7 を固定する

### 理由

- CL1 の S0 の構成は3名以上に限られる(前提)。G-7 の判定者を置ける体制であり、運用できないゲートを課すことにはならない
- CL1 は「個人の権利・利益に実質的な影響」。S0 の欠陥トリアージが Sev1 を許すのは「影響が実験参加者に限定され、回避策を直接伝達できるから」だが、与信・人事評価の PoC では、実験参加者の権利がまさに害の対象で、回避策を伝えても判定の結果は戻らないことがある。S0 の論理(実験参加者だから許す)が CL1 では成り立たない
- G-7 を外すと、保証の主張の成立条件3・4 を満たさない(内部 2.3)。CL1 の案件は「未達のまま出荷しない」の対象なのに、省略は未達ではないため、その規定が掛からない。**S0 だけ、CL1 の出荷を止める仕組みが空になる**。これは信頼性の穴である
- CL2・CL3 は既に G-7 が適用に戻っている(内部 2.3)。CL1 だけ省略だと、「上位は下位を包含する」(`tailoring-guide.md:781`)は守れているが、CL1 → CL2 の境で G-7 が有無ごと変わる。現場から見ると、CL の判定を1段誤っただけで出荷判定の有無が変わる。CL1 で適用にすれば、段差は記録の追加(安全適合性の検証記録)だけになり、CL の誤判定の影響が小さくなる
- 副作用で戻っている状態を、決定と試験で固定する。固定しないと、`r-e-cl2` の G-7 への設定を誰かが整理したときに黙って省略へ戻る

根拠: 内部 2(実行結果)。CL1 の判定基準・S0 のトリアージの理由・G-7 の簡略の中身の無さは自分で本文と規則を開いて確かめた。

## R-3 `tool/requirements.md` シナリオ1

### 結論: **シナリオの文を直す**。エンジンは直さない。シナリオに対応する試験(ペルソナ1)の所在を文中に書き、要件の文書は「規則の帰結を例示する文書で、規則の正本ではない」と冒頭で位置づける

### 理由

- エンジンの出力は ADR-0028 決定6(代償措置は代わりにならない)と ADR-0065 に沿っている。シナリオの文のほうが古い。文に合わせてエンジンを直すと、代償措置を代替に数える規定を作り直すことになる
- 現場の目で一番危ないのは「独立レビューは省略し、代わりにCI基準を厳格化」の一文。2名のスタートアップがこれを読むと「CI を厳しくすればレビューは要らない」と理解する。採用の最初の10分で、本標準の中心の考え(未達と省略の区別)と逆のことを覚える。シナリオ1 は一次ペルソナで、最も読まれる文である

## R-4 未達が解けた後のカバレッジの下限

### 結論: **未達の代償措置で上がった下限は、その未達が解けたら導出値へ戻す**。記名は要しない。ただし、戻すのは「代償措置に由来し、較正していない」値だけとし、構成に下限の由来の欄(導出・代償措置・較正)を持たせる。表示の「較正により変更」は、由来が較正の場合だけに出す。試験で、(a) 未達が解けたら 80 に戻る、(b) 較正した 90 は残る、(c) S0 で未達が省略へ変わる場合は、その変化点の記名と同じ決定で戻る、の3つを固定する

### 理由

- **CL0 の1〜2名の採用者は、全員がこの状態になる**(内部 4.3。初期化では席が必ず空)。例外的な事象ではなく、この体制の採用者の標準の経路である
- そのとき現場で起きることは2つしかない。(1) 誰も較正していない 90 を守るために、価値の低いテストを足してカバレッジを上げる(指標を満たすための作業で、テストの質を下げる)。(2) 全員が種別 `settings` で「90 → 80」を記名する。全員が同じ理由で同じ記名をするなら、記名は儀式になる。**記名の重みを薄める規定は、記名が本当に要る場面の信頼性を下げる**。どちらも本標準の判断軸(信頼性)に反する
- 第8章と ADR-0055 決定5 は、人の離脱で成立しなくなった統制を「緩める向きの決定ではなく、未達の発生」として、記名を待たずに反映する。未達の代償措置はその未達に付く措置であり、未達が解けたとき代償措置が外れるのは、同じ非対称の裏側である。代償措置だけが緩める向きの決定として残るのは、発生と解消の扱いが釣り合わない
- 未達が解けること(確認者を名簿と席で示すこと)は、人の確認を増やす向き、つまり厳しくする向きの変化である。厳しくする向きの変化に付随して外れる措置まで、記名を要する理由が無い
- 例外: S0 で未達が解けると G-6 は「省略」になり、ADR-0065 の影響はこれを緩める向きとして記名を求める。この場合は、その記名の決定に下限の戻しも含める(記名を2回にしない)
- 由来の欄を持たせるのは、採用者が自分で 90 に決めた値を黙って下げないためである。下げてよいのは、標準の規則が自動で上げた値だけ

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| 現行のまま(記名で下げる) | 上の形骸化。帰結が ADR-0065 の影響の節にだけあり、決定として議論されていない |
| 代償措置の下限を別の欄で持ち、通常の下限を 80 のまま保つ(内部 7 の (c)) | 方向は同じだが、CI が読む下限が2つになり、アダプタごとの実装が増える。由来の欄1つで同じことができる。採らない |
| 初期化の直後の未達では代償措置を付けない | 未達の間の代償措置そのものは ADR-0028 決定6 の記録の対象で、外す理由が無い |
| 90 をやめて、1〜2名にも 80 を課す | 値そのものの議論は #296・EV-0143 の差し替えで扱う。本件では値を変えない |

### 文の案

第8章「再実行の時点と向き」の表に1行を足す:

| 項目 | 要求事項 |
| --- | --- |
| 未達の解消 | 未達に付けた代償措置(CI 基準の厳格化など)は、その未達が解けた時点で外す。緩める向きの決定として扱わない。外すのは、代償措置として標準の規則が導いた値に限る。採用者が較正して定めた値は変えない。未達の解消そのものが緩める向きの変更に当たる場合(S0 で G-6 が未達から省略へ変わる場合)は、その決定に代償措置の解除を含める |

本文の注記: 「代償措置を緩める向きの決定として扱うと、統制が成立した後も、根拠の無い値が残ります。未達の発生を記名なしで反映することの裏側です」

### 既存の ADR・条項との矛盾

- **ADR-0065 の影響の節(「初期化の直後の下限 90% は…残る。下げるには、記名と理由を伴う変更を要する」)と矛盾する**。どちらが誤りか: 影響の節の帰結は、ADR-0055 決定5 の非対称を代償措置の解除にまで機械的に延ばしたもので、決定として議論されていない。本意見は影響の節のほうを誤りとする。採用済み ADR は書き換えず、新 ADR で「ADR-0065 の影響のうち下限の項を置き換える」と書く
- ADR-0055 決定5 とは矛盾しない。決定5 の「緩める向き」の列挙(人の確認を減らす、委任の範囲を広げる、ゲートを省略へ変える)に、代償措置の解除は無い。新 ADR でその位置を明記する
- ADR-0028 決定6 とは矛盾しない(代償措置を解消に数えない、の向きを変えない)
- アダプタ `none` では下限を測らない(#330)ので、本件の直しの効果はアダプタのある構成に限られる。#330 で扱う

根拠: 内部 4(実行結果)、`generate-profile.mjs` 690-725・2950-2966 と ADR-0055・0065 の本文は自分で開いて確かめた。「全員が記名する」「テストを水増しする」は現場の推論で、測定は無い(新 ADR の影響に E0 として書く)。

## R-5 既存の CL2 の構成への案内(ルールセット `safety`)

### 結論: 3つを行う

1. `safety` ルールセットを足したことを新 ADR の決定として記録する(落とすとコードオーナー・署名・`d0-check` まで外れるため、という理由と、採らなかった `team` への変更を書く)
2. `standard-editions.md` の保守者の手続を、**既存の採用者の構成を再導出すると緩める向きの差分が出る更新**にも広げる。告知の中身は「どの構成で、どの値が、どちらの向きに変わるか」「採用者が何もしない場合の状態」「変える場合の記名の経路」
3. テンプレートの README に #302〜#310 の更新の節を遡って置き、旧い CL2 の構成への案内を書く。旧い構成を**黙って書き換えない**。`regulated` のままでよいことと、そのとき2件目の承認は G-6 の承認に数えないこと(ADR-0067 決定5)を書く

### 理由

- 旧い CL2 の構成は、そのままなら何も落ちない(内部 5.3)。害は小さい。しかし現場では、まったく別の設定の変更のために `/process-change` を実行した日に、突然「ブランチ保護 regulated → safety、記名が要る」と出る(読みでは、差分は1つの変更にまとめて出る。内部 5.3・`generate-profile.mjs:1230-1237`。実行は確かめていない)。何の告知も無いまま緩める向きの記名を求められると、採用者は (a) 内容が分からないまま記名する、か (b) 無関係な変更が止まる。どちらも手戻りであり、(a) は記名の形骸化である
- 保守者の義務が「落とす」更新だけを覆うのは、採用者に不利な側だけを見た線引きで、統制が緩む側の告知が抜けている。緩める向きこそ、採用者が自分で判断する(記名する)必要がある。判断の材料を渡さないまま記名を求める形は、本標準の「緩める向きは記名と理由」の趣旨に合わない
- 外部の型(内部 5.4 の注の Renovate)は、旧い名前を読み続け、書き換えは提案として出す。黙って書き換えず、黙って通しもしない。本件の案内も同じ形にする
- 旧い構成には、構成の承認数(1)とルールセット(2)の食い違いが元からある。案内にこれを書かないと、監査で「構成は1、実環境は2、どちらが正か」と問われたとき採用者が答えられない

### 他の案を落とす理由

| 案 | 落とす理由 |
| --- | --- |
| `migrate` で `regulated → safety` を自動で書き換える | ADR-0085 決定5 が「値を変えない」と定め、緩める向きの黙った読み替えを採らないと明記している。衝突する |
| 何もしない(旧い構成は標準より強いだけで不適合ではない) | 上の「無関係な変更の日に記名を求められる」手戻りと、記名の形骸化が残る |
| 旧い構成を不適合として契約検査で落とす | 強い側への逸脱を落とす理由が無い。落とす向きの更新を新たに作り、保守者の手続の負担を採用者に移すだけである |

### 文の案

`community/standard-editions.md` の節の題を「準拠テンプレートの更新で、既存の採用者を落とす変更・緩める向きの差分を出す変更を出すとき」とし、表に行を足す:

| --- | --- | --- |
| 5 | 既存の採用者の構成を再導出すると緩める向きの差分が出る更新では、差分が出る構成の条件、変わる値と向き、採用者が何もしない場合の状態、変える場合の記名の経路を列挙する。旧い値を読み込みで書き換えない | 更新の告知 |

箇条を足す: 「緩める向きの差分を、無関係な構成の変更と同じ記名へ混ぜない。採用者が旧い値を保つことを選べる形にする」

テンプレート側の確認事項(本件で確かめていない): 採用者が `regulated` を保ったまま別の `settings` の変更を通せるか。通せないなら、差分を分けて提示する直しを #357 または本件のテンプレートの Issue で行う。
