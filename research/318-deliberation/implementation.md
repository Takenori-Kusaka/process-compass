## 2. 裁定からの逸脱・裁定に書かれていない判断と、その理由

1. **エンジンへ動詞 `restore` を足した**。裁定は「規則 `r-e-cl1` に G-7 の省略・簡略の取り消しを足す」と書くが、既存の6つの動詞では、優先度の高い規則が低い規則の省略・簡略を「適用」へ戻す手段が無かった。強化(strengthen)で戻すと、CL1 の G-7 が S1 以降も「強化」となり、軸B・軸E の表と食い違う。`restore` は強化を下げず、対象が既に適用なら何もしない。エンジンの意味を変える変更なので、ADR-0088 決定4 に書いた
2. **省略が無効化した設定の復帰を足した**。規則のファイルはアルファベット順に読まれ、business-phase(S0 の省略)が team-size より先に読まれる。このため、S0 で G-6・G-7 の判定者の方式・レビューの方式の設定が、同じ優先度の省略によって黙って落ちていた。restore で対象を戻しても、設定が欠けたままになる。省略を取り消したときに、その省略が無効化した設定を戻すようにした。既存の構成のうち S0 × CL1 以上は、再導出で `review.mode` と G-7 の `approverMode` が変わる(厳しくする向き)
3. **ADR-0067 のステータスの節にも指し先を書いた**。裁定は ADR-0065 のステータスの節からの指し先だけを明記している。ADR-0067 の先送りを ADR-0088 で決着すると裁定(R-1 の8)が書くため、読み手が ADR-0067 から辿れるようにした。本文は書き換えていない
4. **G-6 には restore を使っていない**。CL1 以上の S0 で G-6 を適用する既存の設定(`appliesInAllStages`。ADR-0065 決定3)をそのまま残し、範囲の限定の取り消しだけを `set scope: all` で足した。結果は全升の試験で固定した
5. **導出の基準値は、導出値が下がっても自動では下げない**。裁定の対象は代償措置の下限の終了である。導出値そのものが下がる場合(規則の変更)は、従来どおり記名の決定(種別 settings で `"derived"`)とした。黙って下げないという ADR-0055 決定5 の扱いと同じ向きである
6. **承認の数の検査を、失敗から注記へ改めた範囲**。下回る場合の失敗は維持した。上回る場合だけを注記にした(R-5 の5)。統制を緩める向きの変更ではなく、本文の「下回らせない」への整合である

確認の結果:

- **確認1(段の定義と 1.4 の整合)**: 段1 は 1.4「独立」、段3 は「組織上独立した検証」、段4 は「第三者レビュー」と同じ条件で書いた。矛盾は無い
- **確認2(`RULE_APPROVER_SEAT` と第8章)**: 第8章「再実行の時点と向き」は、緩める向きの変更の決定者を「対象の席の責任者、または D-0 表1 の決定者」とする。強制層の閾値は AI維持管理者が承認する(3.11.2)。準拠テンプレートの `allowedDeciders(config, seat)` は、対象の席(`ai-maintainer`)の責任者と D-0 表1 の決定者を受け付ける。`RULE_APPROVER_SEAT = 'ai-maintainer'` は第8章と一致しており、変えていない。通しの確かめでも、差分の行に「決定できる者: AI維持管理者の席の責任者、または事業決裁者の席の責任者(D-0 表1 の決定者)」と出た

### 5.1 CL の判定と安全リスクアセスメントを、誰がどの段で確かめるか

- 背景: #318 は、独立した安全性の評価と段階「最強」の担当者に組織上の距離の段を求めた(ADR-0088)。一方、安全重要度(CL)の判定そのものと、安全リスクアセスメント(テンプレ9)を誰が確かめるかと、その段は決めていない。ISO 26262-2:2018 表1(GB/T 34590.2 の公開の草案で読んだ)は、HARA と影響分析の確認レビューを ASIL に依らず I3 とする。判定を誤ると後段の保証がすべて崩れる成果物である
