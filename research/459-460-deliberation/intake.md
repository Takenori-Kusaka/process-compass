# #459・#460 受付と内部の調査(2026-11-27)

担当: 受付・調査・裁定の案。標準の本文は変えていない。template は読むだけ(初期化済みの `../d1/template`、参照のコミット cfd4ff47 と同じ版で読んだ。d2 の template は未初期化)。

## 1. 受付

### 1.1 Issue の要旨(第三者の意見として扱う)

- #459: 「記名」が 1.4 に定義されていない。帳票への署名・押印と読まれる。実体は本人の操作に結び付いた記録である、という主張
- #460: 会社の既存の決裁の仕組み(ワークフロー・電子決裁・メール・PR の承認)の証跡を判定の記録として受け入れる条件が無い。名指しの媒体は様式と承認レビューだけで、条件を満たさなければ「様式へ戻る」
- 発端: publishing-hub のレビューレポート §5(R-093〜R-095)と §7.6 の所有者の指摘

### 1.2 所有者の決定として扱うもの

- (2026-11-27)資料や様式に、承認者の氏名・記名・押印・日付の欄を求めない。決裁の証跡は会社の既存の仕組みに残ればよい
- #460「所有者の期待」節: 求めるのは決裁が行われ、その証跡が残ること。仕組みが無い場合に限り様式を使う
- (2026-11-16)準拠テンプレートは標準を体現し連動させる。細かい定義を増やして柔軟性を失わない

### 1.3 審議の重さの案: **重**(#459 は単独なら軽だが、#460 と合わせて重で審議する)

理由:

1. **ADR の原則の変更に当たる**。#460 の所有者の期待を満たすには、次の決定を改める
   - ADR-0070 決定3「人が書く欄の受け皿は2つに限る」・決定8「条件を満たさないホスティングでは様式へ戻る」
   - ADR-0106 / gate-criteria.md「判定記録を基底ブランチへ入れる操作」の「帰属の裏づけは、記名者本人のアカウントの操作として、機械がホスティングの記録で確かめられるものに限る」(L135・L143)。外部のワークフローの記録は機械で照らせないため、受け入れるなら裏づけの経路を足す原則の変更になる
   - ADR-0036 決定1(記録の作成で成立)は変えない。外部の決裁の記録も記録であり、原則と両立する
2. **採用者への新しい義務**が生じる。外部の仕組みを受け入れる条件(性質の申告・事前の登録・写しの所在)は、採用者が満たす新しい要求になる
3. **規格の引用を要する**。受け入れる記録の性質を書くには、電子記録の真正性の先例(21 CFR Part 11 §11.50・§11.70、電子帳簿保存法の真実性)を踏まえる必要がある
4. #459 の定義の欠けだけなら軽(定義の欠け)。しかし定義の中身(媒体を問わない・帳票の署名に限らない)が #460 の結論に依存するため、分けて審議すると定義が後の結論と食い違う

→ 会議体は 5 委員(起案・現場・品質監査・規格・弁護)。外部の調査は実施した(sources.md)。

### 1.4 受付で問う3点への一次の答え

| 問い | 一次の答え |
| --- | --- |
| (1) 条文には結果と証跡まで、手順は手引きへ | 可能。条文は「受け入れる記録の性質」と「残る証跡(所在の参照・帰属の確認の記録・開示)」まで。SAP・電子決裁・メールとの接続の手順は附属書(導入の手引き)へ |
| (2) 新しい条項を足さずに第7章の例外承認で受けられないか | 受けられない。7.3 の対象はゲートの判定基準と条項が名指した事項に限り、構成の条件(記録の媒体・帰属の経路)を対象にしない(exception-escalation.md L59 付近)。仮に使えば、外部で決裁するたびに回収の期限付きの例外になり、恒常の運用を例外で回す「素通しの正規経路」(ADR-0036 決定3 の却下理由)になる |
| (3) 破られたとき誰が何を失うか | **今の標準で失っているもの**: ホスティングのアカウントを持たないトップマネジメントが社内の電子決裁で層1 を決裁した組織は、層1 の帰属を確かめられず、保証の主張の成立条件1 が不成立になる(IMPL-0415 の note)。D-0 の決定も同様に欠落に出る。つまり既存の決裁を使う組織は「組織として品質を保証する」と主張できない。**受け入れた後に破られた場合**(写しが外部の記録と食い違う・外部の記録が存在しない): 写しを確かめて承認した帰属の確認者の責任が、ホスティングの記録に残る。内部監査の抜き取りで見つかった記録は欠落へ戻し、その出荷の保証の主張を開示で取り消す |

### 2.2 「記名」の意味の類型

| 類型 | 例 | 件数の目安(docs 全体) | 帳票の署名と読まれるか |
| --- | --- | --- | --- |
| A 特定された人 | 「記名の自然人」(責任者・決定者) | 39 | 読まれにくい。意味は「名指しで特定された自然人」 |
| B 承認・決定の行為 | 「記名で確定する」「記名する」「記名を要する」 | 記名で 248・記名する 147・記名を要 56 | **読まれる**。#459 の指摘の中心 |
| C 記録の主体 | 「記名者」「記名者本人のアカウント」 | 431 | 中。帰属の規定と組で読めば操作の主体と分かる |
| D 様式の欄 | テンプレ11「記名: <氏名(役職)> / 記名日」(deliverable-templates.md L1722)、テンプレ12 L1860、「記名欄」(L1482) | 欄は数か所 | **欄そのもの**。所有者の決定と向きが食い違う |
| E 本文の記名(数えないもの) | 「本文の記名は、承認に数えない」(gate-criteria.md L896)、「記名が自己申告」 | 本文の記名 22・自己申告 15 | 標準自身が「名前を書いただけ」と「本人の操作」を区別している |

結論: 標準の規範上の「記名」は類型 B・C であり、**帰属は別の規定(本人のアカウントの操作)で裏づけるもの**として一貫している。欠けているのは 1.4 の定義だけ。ただし類型 D の欄は帳票の記名欄として実在する。

### 2.3 規定の所在と現状

- **overview.md 1.4**: 「判定の証跡」(L110)は「媒体は様式に限らない」。「帰属の確認」(L113)・「責任者=記名の自然人」(L118)・「トップマネジメント…記名し」(L135-136)。「記名」の項は無い
- **overview.md L34(1.1)**: 既存の QMS・決裁権限規程を置き換えずに、その上に接続する
- **gate-criteria.md「判定の成立」(L61-96)**: 成立要件は欄(判定者・判定日時・結果・確認した項目・差し戻し理由)。媒体は「欄を運ぶレビュー」だけを名指し、「欄を運ばない承認の操作は事務」。条件を満たさないホスティングは「様式へ戻ります」。保全の条件(対応表・宣言行の事前の定義・写しの取り出し・文書管理の規程・電子署名との関係)。EV-0109 は媒体を2つとして欠落を数える
- **gate-criteria.md「機械が出す欄と人が書く欄」(L105-121)**: 人が書く欄の受け皿は「記名者本人のレビューの本文」か「判定記録(様式)」の2つ。G-1・G-7・G-8・SG は様式。PR 本文と Issue のコメントは受け皿にしない(固定されない・削除できる)
- **gate-criteria.md「判定記録を基底ブランチへ入れる操作」(L124-)**: 帰属の裏づけは、機械がホスティングの記録で確かめられる本人のアカウントの操作に限る。裏づけの無い判定記録は欠落に数えず「記名が自己申告」と開示(L141)。効力を持つ記録(例外承認・停止の解除・層1・D-0 の決定の記名ほか)は効力を持つ前に裏づける
- **gate-criteria.md L896(統制の設定の変更の承認)**: 本文の記名は承認に数えない
- **gate-criteria.md G-1(L393-437)**: 見出しは「既存規程または D-0 の記名による」、期限は既存の稟議の運用どおり。しかし判定記録は様式(L118)。**既存の稟議で決裁し、さらに様式の判定記録を作る二重の構成**になっている(所有者の指摘どおり)
- **exception-escalation.md L58**: 承認した者の記名は名前の一致で裏づけず、本人のアカウントの操作で裏づける。PR の上のレビューでよい
- **IMPL-0415(gate-criteria.md L205)**: 層1・D-0 の記名の帰属を、記録を入れた PR の作成者・承認者で照合。確かめられない層1 は成立条件1 を不成立にする
- **phase5 ci-gates.md L493・L921**: 層1 の有効の検査は、版・記名(自然人の名義)・記名日の形を機械で読む

### 2.6 外部の調査(要約。抜き書きは sources.md)

- 21 CFR Part 11 §11.50 は署名に「氏名・日時・意味」、§11.70 は記録への結び付き、§11.10(e) は監査証跡を求める。**媒体・帳票の欄は指定しない**
- 電子帳簿保存法の真実性は、タイムスタンプ・履歴の残るシステム・訂正削除できないシステム・事務処理規程のいずれかで満たす。**技術で満たせない組織に規程の経路を残す**
- J-SOX(SRC-0537)は職務分掌を「別の者」で書き、承認の媒体を指定しない。IT 統制ガイダンスは未読
- ISO 9001 7.5 は未読(台帳も未読)。引用しない
