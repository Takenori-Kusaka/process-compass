# #459・#460 裁定の案(議長の裁定の前の案。2026-11-27)

前提は intake.md(重さ=重、内部調査)と sources.md(外部の抜き書き)。会議体(5 委員)へ渡す案であり、決定ではない。

## 0. 推奨の要点

1. 「記名」の語は改めず、1.4 に定義を足す(論点A)
2. 判定の記録として受け入れる記録を、媒体の名でなく**性質**で書く。組織の既存の決裁の仕組みの記録を、3つ目の受け皿として受け入れる。様式は「性質を満たす仕組みが無い場合」の受け皿にする(論点B)
3. 確認した項目は、**承認の意味の事前の定義**で満たせる。添付資料(起案者の書いたもの)の側には置けない(論点C)
4. 外部の記録の帰属は、記名者以外の名簿の人による**帰属の確認**で裏づける新しい経路を足す。機械は決定可能な条件だけを見る。照合の真偽は manual。区別して開示し、EV マークを付ける(論点D)
5. template の変更が要る。この束では変えず、実装マーク state=undelivered で表示して束 D1 へ回す(論点E)
6. ADR-0264 を起こす。ADR-0070 決定3・8 を一部置き換え、ADR-0106 の裏づけの経路を足す(論点F)

## 論点A 「記名」の定義か、語の置き換えか(#459)

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A1 定義を足す(推奨) | 1.4 に「記名」を置く。案: **「承認・決定・確定を行った者が誰であるかを、後から確かめられる形で記録に残すこと。媒体を問わない。帳票への署名・押印・手書きの氏名を求めない。記録の本文に氏名を書いたことだけでは、本人のものと裏づけない(裏づけは第4章「判定記録を基底ブランチへ入れる操作」による)。『記名の自然人』は、名指しで特定された1人の自然人をいう」** | 2,107 か所を変えずに読みが定まる。類型 A〜E(intake 2.2)をすべて覆う。ADR の本文(613 か所)を書き換えずに済む |
| A2 語を「本人の承認の記録」へ置き換える | 本文・template の全量を置換 | **採らない**。(a) 採用済み ADR は書き換えられず、旧語と新語が並び、定義の正本が2つになる (b) template の 1,863 か所はスクリプトの出力と試験の照合を含み、置換は回帰の源になる (c) 類型 A「記名の自然人」・類型 C「記名者」は「承認の記録」に置き換えると意味が壊れる (d) 判断軸は信頼性であり、語の置換は信頼性を上げない。読み手向けの平易な言い換え(「本人の承認の記録」)は、提案資料・附属書D の説明の文で使えばよい |
| A3 定義せず、手引きで説明する | 附属書に注記 | **採らない**。1.4 は用語の正本であり、規範の語の定義を手引きに置くと、規範の読みが手引きに依存する(ADR-0010 の向きの逆転) |

付随: 類型 D の様式の欄(テンプレ11 L1722「記名 / 記名日」、テンプレ12 L1860、L1482「記名欄」)の欄名は、論点B の結論に合わせて「決裁の記録(決裁した者・効力の日・記録の所在)」へ改める案を会議体へ出す。欄の中身(誰が・いつ)は記録の性質として残る(Part 11 §11.50 も氏名と日時を求める)。「欄を求めない」は「帳票に書き込む手続を求めない」の意であり、記録から誰が・いつ決めたかが分かることまで外すのではない、と裁定で明記する。

## 論点B 受け入れる記録の性質(#460 論点1)

| 案 | 内容 | 評価 |
| --- | --- | --- |
| B1 性質で書く(推奨) | 判定の記録の受け皿を3つにする。(1) 承認レビュー (2) **組織の決裁の仕組みの記録(性質を満たすもの)** (3) 様式(性質を満たす仕組みが無い場合)。性質は次の6つ | 所有者の期待と 1.1 の接続の原則に沿う。ツールを名指ししないので、ADR-0036 却下表の「ツールに成立要件を依存させない」を保つ |
| B2 媒体を列挙する | 「SAP・電子決裁・メール・PR」を名指す | **採らない**。ツールが変わるたびに条項が変わる。メールのように性質を満たさないことがある媒体を、名指しで受け入れてしまう |
| B3 現状維持(様式へ戻る) | 外部の決裁の後に様式を作る | **採らない**。二重の記録になり、所有者の決定と 1.1 に反する。intake 1.4(3) のとおり、外部で決裁した組織が成立条件1 を失う |

受け入れる性質(案。すべてを満たすものに限る):

| # | 性質 | 由来 |
| --- | --- | --- |
| P1 | 判定者本人に結び付く(本人の認証を経た操作として記録される) | 既存「書き手が判定者本人」、Part 11 §11.10(d)・§11.50(a)(1) |

- 条文には P1〜P6 と「残る証跡」までを書く。SAP 等との接続の手順は導入の手引き(adoption-guide.md)へ置く(受付の問い(1))

## 論点C 確認した項目・差し戻し理由の所在(#460 論点2)

| 案 | 内容 | 評価 |
| --- | --- | --- |
| C1 承認の意味の事前の定義で満たす(推奨) | P3 の定義で「この種別の承認 = 当該ゲートの判定基準の全項目を確認した」と決めておけば、確認した項目は定義から引ける。全項目でない承認・確認していない事項がある承認は、判定者本人がその仕組みのコメント欄に書く。差し戻しは、満たさない基準の項目番号を判定者本人がその仕組みに書く。書けない仕組みは、差し戻しに限り様式を使う | 「差し戻しは理由付き」(共通ルール3)と「判定者本人の言葉」(附属書C)を保つ。G-6 の挙動要約は対象外(PR として存在する判定であり、承認レビューのまま) |
| C2 添付資料の側に載っていれば足りる(Issue の論点2 の案) | 決裁の対象の資料に確認項目があればよい | **採らない**。添付資料は起案者(判定される側)が書く。判定者の確認した項目を、判定される側の文書で代える形は、PR 本文を受け皿にしない理由(作成側の欄。G-6 条件4)と同じ欠陥を持つ。添付資料は P4 の「対象」であって、判定の内容ではない |
| C3 欄を求めない | G-1・G-8 では確認した項目を要さない | **採らない**。ADR-0036 の成立要件を緩め、「承認の操作は事務」の区別が消える |

## 論点D 統制の閉じ方と帰属(#460 論点3・#459 論点3)

| 案 | 内容 | 評価 |
| --- | --- | --- |
| D1 外部の記録 + 帰属の確認で裏づける(推奨) | ホスティングのアカウントを持たない記名者(トップマネジメント等)の決裁は、外部の記録の所在(識別子)を写しの側に書き、写しを基底ブランチへ入れる変更を、記名者以外の名簿の人(AI の名義でなく、名義を共有していない人)が承認する。承認者は、外部の記録と写しの一致(決裁した者・日時・結果・対象の版)を確かめる。これを「外部の決裁の記録による帰属の確認」とし、効力を持つ記録(層1・D-0 の決定・例外承認)にも使える | 既存の「帰属の確認」の概念(1.4 L113)を延ばすだけで、新しい席を作らない。破られたときの責任が、帰属の確認者のアカウントの操作としてホスティングに残る |
| D2 外部の記録を機械の裏づけと同列に数える | 所在の記載だけで裏づけたことにする | **採らない**。所在の文字列は誰でも書ける(本文の記名と同じ欠陥。gate-criteria.md L896) |
| D3 数えず、自己申告として開示する(今の扱いに近い) | | **採らない**。強い決裁(電子決裁)を、名前を書いただけの記録と同じ「自己申告」に分類し、開示が実態と食い違う。成立条件1 が不成立のまま残る |
| D4 外部の仕組みの API を機械で照らすことを求める | | **採らない**。仕組みごとに実装が要り、標準が媒体を名指すのと同じになる。API を持たない仕組みを締め出す。照らせる採用者が上乗せで行うことは妨げない |

閉じ方の割り当て(コアポリシー「統制の閉じ方を裁定で決める」):

| 条件 | 閉じ方 |
| --- | --- |
| D-0 に外部の仕組みの申告(P1〜P6 の満たし方・種別とゲートの対応)がある | machine(存在・形) |
| 写しに外部の記録の所在(識別子)・決裁した者(名簿の人)・日時・結果・対象の版が埋まっている | machine(存在・形) |
| 写しを入れた変更の承認者が、記名者以外の名簿の人で、AI の名義でなく、名義を共有していない | machine(既存の照合と同じ) |
| 外部の記録が実在し、写しと一致する | **manual**(帰属の確認者)+ 内部監査の抜き取り。EV マーク(E0) |
| 外部の仕組みが P1〜P6 を実際に満たす | **adopter**(採用者の申告)+ 内部監査。EV マーク(E0) |

- 開示: 保証の開示の項目1 に「外部の決裁の記録で裏づけた記録(照合は人)」を件数で出す。自己申告とは区別する
- 成立条件1・4: D1 の裏づけを数える。数えることを EV マークで開示し、差し替え条件を「内部監査の抜き取りで見つかった不一致の件数」とする
- 内部監査で不一致が見つかった記録は、欠落へ戻し、その出荷の成立判定を開示で改める(intake 1.4(3))

## 論点F ADR の要否

**要る。ADR-0264** 「判定の記録は性質で受け入れ、組織の決裁の仕組みの記録を受け皿とする。帰属は記名者以外の人の確認で裏づける」(仮題)。

- 一部を置き換える: ADR-0070 決定3(受け皿は2つ)・決定8 の末尾(様式へ戻る)
- 経路を足す: ADR-0106(帰属の裏づけ)。原則「名前の一致だけを裏づけに数えない」は保つ
- 保つ: ADR-0036 決定1・決定3、gate-criteria.md「電子署名との関係」
- 採用済みの ADR の本文は書き換えない。0070・0106 には置き換えの注記だけを足すかを議長が決める(adr/index.md の運用)
