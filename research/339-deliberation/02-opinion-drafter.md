# Issue #339 起案の委員の意見

立場: 本標準(他組織が従う規格)として、信頼性を最も高める案を1つ起案する。安さ・変更量の少なさは理由にしない。調査(01)の A+F には縛られず、検討し直した結果を書く。

## 1. 採る案と理由

**案 A+F(維持して開示を強める)を採る。ただし F を「表示の追加」だけで終わらせず、3点に分けて書く。**

1. **検査は記入の有無のまま変えない**(ADR-0059 決定5 の線を維持)
2. **機械が確かめないことを、利用者の見る場所で言い切る**(F)。今は台帳(IMPL-0035 の note)にしか出ない。次の一手・保証の開示・D-0 の節12 に、種別ごとに「登録の根拠の内容は未確認(記入の有無のみ)」を出す。判定不能を「異常なし」と書かないのと同じ作法に揃える
3. **確認の責任の置き場を、規定の側で固定する**。登録の判定(リリース判定会 B-4 または D-0 の決定者)が、算出の所在を**開いて**計測できることを確かめた結果を、判定記録の本文に自由文で残す、という既存の求め(human-ai-boundary.md L509)を変えない。新しい欄(案G)は足さない

理由(信頼性の軸で)

- **機械で閉じる検査は、偽装を防がない**。実行で確かめた通り、`a` も `http://x` も通る。構文(B)を足すと `a/b` で通り、実在(C)を足すと実在する無関係の path で通る。K-7(ADR-0078)の論理「所在の実在は確かめたことを示さない」のとおり、どちらも**確認の代わりに通る型**の別の面である。検査を足すほど、合格が「確かめた」と読まれる危険が増す。信頼性は、検査の数ではなく、**合格が何を意味しないかの開示**で守る
- **統制の閉じ方の裁定の原則に一致する**。決定可能な条件(値の一致・存在・構文)だけ機械にする。ここで決定可能なのは「欄が埋まっている」までで、これは既にある。残りは自由な文の意味(算出が実在し、計測できるか)で、機械で閉じない。ゆえに manual(登録者の判定)にして開示する
- **計測の実態は実行時に別経路で出る**。autonomy.mjs は判定記録・取り込み履歴・計画表から差し戻し率・手戻り率を自ら集計し、判定不能を「異常なし」と書かない。`basis.detection` は他のどの計算にも読まれず、案内の文言(REWORK_UNCOUNTED)にだけ現れる。登録時の入力を機械で固めても、実行時の信頼は増えない
- **新規種別は登録時に母数が 0** である。登録時に算出を実行する案(D)は、拒否し続けるか判定不能を通すかの二択になる。登録時にできるのは、人が算出の手段と置き場を開いて確かめることだけである
- **現行の欠けは開示済みで、表示と実態は食い違わない**(IMPL-0035 は delivered, check=presence、note に「内容は確かめない」)。食い違うのは、**開示が利用者の画面にない**ことだけである。直すべき実際の欠けはここにある

## 2. 条項・ADR の文案の骨子

### 2.1 本文だけの分(src/・research/。この束で扱える)

- **新 ADR は起こさない**。ADR-0059 決定5 と ADR-0081 の線を維持するため。採用済み ADR の本文は書き換えない
- `human-ai-boundary.md` L519 IMPL-0035 の note に一文を足す(編集の指摘。意味は変えない)。案
  - 「検知条件ごとの記入が文字列として埋まっていれば受け付ける。所在の形や、計測している旨だけの記入かどうかは区別しない(区別は登録する者の判定)」
  - 足した後に `npm run impl:write` で台帳を再生成する
  - Why: 規定本文(L508)は「計測している旨だけの記入を算出の所在として扱わない」と書く。機械が区別しないことを note に書かないと、読み手が機械の検査に含まれると読む
- 同 L508 の末尾は変えない。「機械で確かめるのは、検知条件ごとの記入の有無まで」で既に言い切っている
- `template-repository.md` L610 は既に一貫しているため変えない。必要なら F の表示を採ったことを、template 側の実装が済んだ後に一行で足す(今は書かない。降りていない規定を降りたと書かないため)
- F の表示を標準側の規定にするか: **しない**。表示の文言は template の実装に任せ、標準側は IMPL マークで「登録の根拠の内容は未確認である旨を、利用者の見る表示に出す」を `state=undelivered`(plan と issue つき)の新規マークとして立てる案を、議長の判断に付す。立てるなら target は既存の降ろし先(`src/data/impl-targets.yaml` に実在するもの)から選ぶ。実在しない降ろし先を使わない
  - 立てない場合の代替: Issue #339 への申し送りだけにする。この場合は降りていない規定として台帳に出ないため、表示の追加が忘れられる危険が残る。**立てる方を推す**
- 根拠水準のマーク: 「登録の根拠の内容を機械が確かめなくても、登録者の判定と実行時の集計で足りる」という前提は実証を欠く。ADR-0059 の EV-0098(暫定、見直し 2027-04)が既に覆っているため、新しい EV は起こさず、research の裁定に EV-0098 を引く

### 2.2 template に及ぶ分(この束は触れない。#339 へコメントで残す)

1. `template/scripts/gate/autonomy.mjs` の `autonomyNoteLines()` と保証の開示・D-0 の節12 の出力に、登録した種別ごとの「登録の根拠の内容は未確認(記入の有無のみ)」を足す。「異常なし」と読まれない文言にする
2. 試験: 表示が出ること、検査の拒否が増えないこと(`a` 等が引き続き通ること。通ることを固定するのではなく、拒否を増やさない確認に留める)

5. 順序: 標準側の IMPL マークを先に立て、template の実装を後にする。`template:kb` の複製は規則データを変えないため不要

## 3. 採らない案とその理由

- **B 構文検査**: 偽装が容易(`a/b`)。合格が「所在を示した」と読まれ、K-7 の型に落ちる。決定可能ではあるが、決定可能な条件が意味を代理しない
- **C 実在検査**: 散文から path を取り出す規則が先に要り、決定可能でない部分を含む。実在は算出可能性を示さない(K-7)。fixture と試験が壊れ、採用者に先に置き場を作らせる新しい義務になる。重へ上げる条件に当たる
- **D 登録時の算出実行**: 母数 0 で判定不能が常態。決定不能
- **E 欄の廃止**: 5.5.4・5.4.6 の改廃。採用者が補う手段の置き場を失う。重
- **G 確認の記名欄**: 「確認した」の申告が確認の代わりに通る。型が同じ
- **B の弱い版(同一文字列を両欄に入れたら拒否 等)**: 意図の推定で決定可能でない。偽装は文字を変えるだけで回避できる
- **何も足さない A 単独**: 直さない理由は記録できるが、利用者の画面に出ない欠けが残る。「開示済み」の主張が台帳を読む者にしか届かないため、信頼性の軸で足りない

「採らない」と決めたことは、research/339-deliberation/decision.md に案ごとに理由つきで残す。「書かれていない」と「課さないと決めた」を区別するため。

## 5. 自案の弱点

- **開示は人が読まなければ効かない**。表示を足しても、「未確認」を読み飛ばして登録する者の行動は変わらない。manual の統制の本質的な限界で、機械では閉じない。根拠水準マークで開示するしかない
- **登録者が算出の所在を実際に開いたかは、誰も確かめられない**。判定記録に自由文で残すだけでは、申告になる(G と同じ型)。ここを閉じる策は、内部監査で登録済み種別の算出の所在を抜き取りで開くこと(adopter 側の統制)だが、附属書の内部監査にその項目が既にあるかを本調査で確かめていない。無ければ新しい義務に近づくため、この案には含めず、議長の判断(重へ上げるか)に付す
- **`a` のような明白に無意味な記入が通り続ける**。決定可能な最低線(例: 空白除去後の長さの下限)を引くこともできるが、閾値は実証を欠き、通る文字列を数文字増やすだけで、合格の意味を変えない。採らないが、利用者に「機械は明白な誤記も止めない」と見える不満は残る
- **template の表示の追加(小)は、この束で実装できない**。標準側の undelivered マークを立てる間、画面の開示は欠けたままになる。この間は台帳の IMPL-0035 note が唯一の開示である
- **F の IMPL マークの降ろし先**は、既存の `impl-targets.yaml` の登録に合う target があるか未確認。無ければマークを立てられず、申し送りだけに退く(2.1 の代替)
- 外部規格の調査をしていない(軽の範囲。新しい義務を課さないため)。ISO 9001 の記録の管理などを引く必要が出る案は、重へ上げる側で扱う
