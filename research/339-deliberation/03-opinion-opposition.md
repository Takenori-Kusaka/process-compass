# Issue #339 反対の委員の意見書

立場: 調査の推奨(A+F)に反対する側。安さ・変更量の少なさは理由にしない。読んだ原文は、ADR-0059 決定5、ADR-0081 の冒頭、ADR-0078 K-7、`human-ai-boundary.md` L508・L519、`config.mjs` の `missingBasis`・`isFilledValue`、`gate-criteria.md` L257、01-investigation.md。ADR-0054 決定4 の原文は読んでいない(調査の引用に依る)。

## 1. 推奨案(A+F)の欠陥

1. **「表示と実態は食い違わない」は誤り。IMPL-0035 の note は実態より狭い**。note は「記入の内容(算出が実在するか)は確かめない」と書く。読み手はここから、少なくとも所在らしい形は求めている、と読む。実際は `a`・`はい`・`計測している` が通る。標準 L508 は「計測している旨だけの記入を、算出の所在として扱わない」と書くが、機械は区別しない。note には、この条項を機械が守らせていないことが出ていない。コアポリシーの「表示と実態が食い違う『高』だけは直す」に当たりうる。A を採るなら「現状維持」でなく、note の直しを伴う。
2. **F は信頼性を上げない。誤読を減らすだけ**。全種別に常時出る「内容は未確認」は、`a` と実在の所在を区別しない。毎回出る警告は背景になる。F は有益だが、採用者が頼ったときに決めるべきことが漏れる状態を、F 単独では塞がない。塞いでいるのは「登録する者が判定する」という manual の統制と、その記名である。
3. **A の理由(3)「実行時の計測は autonomy が自ら出す」は #348 に依存する**。登録時に中身の無い根拠で通った種別は、判定不能になる。判定不能のとき種別を止めるかは IMPL-0291・#348 が重い審議で扱っている(調査 L41)。ADR-0081 の説明文は「止める」と書いており、調査の「open」との関係を、私は原文で確かめていない。確かめるべき点として残す。#348 の結論が「止めない」なら、A は理由(3)を失う。A の記録は、この依存を明記する。
4. **A の理由(2)「値が他の計算に読まれない」は、むしろ E の根拠になる側面がある**(下の 3 で扱う)。

## 2. 残る案と理由

**A′+F: 現状の検査を維持し、IMPL-0035 の note の食い違いを直し、F を足す。**

- A′ = 食い違いの直し。note を「機械が確かめるのは、各欄が空・記号のみ・『未定』等・様式の置き場の文言でないことまで。所在の形も実在も確かめない。『計測している旨だけ』の記入(標準 5.5.4)も機械は区別しない」へ改める。本文(src/)だけで済み、意味を変えない編集の指摘に当たる。`npm run impl:write` を要する
- 試験で現状を固定する案を添える。`a` が通ることを「既知の開示された欠け」として pin する試験。template に及ぶため Issue へのコメントに残す
- F は template の表示。採る価値はあるが、A′ より優先度は低い。F が無くても、A′ で開示と実態は一致する

理由: ADR-0081 L16 は「登録の根拠の欄の内容は登録する者が判定する」を、集計の実装を知った上で明示して維持している。この件はその維持にそのまま当たる。ADR-0059 決定5 も同じ線を引く。機械で閉じる条件(決定可能)に自由な文の意味は入らない、という裁定の原則とも合う。

## 3. 採らない案とその理由

- **B(所在の構文を要する)**: 調査は K-7 の論理に逆行するとして落とす。**私はこの落とし方に反対する**。K-7 が退けたのは、human-verify への添付と所在の記載を「課すこと」である。機械の存在検査を足すことではない。K-7 の理由句(所在の実在は確かめたことを示さない)は C には当たるが、B には当てはめにくい。B を落とす理由は別にある。
  - (a) 算出の所在は path とは限らない(ダッシュボード名、外部ツールの画面、手順書の見出し)。path 形を要すると、正当な記入が通らず、偽の path を書かせる。かえって内容が悪くなる
  - (b) `a/b` で通る。区別できるのは不注意な記入だけ
  - (c) 線を ADR-0059 決定5(記入の有無まで)から動かす。新 ADR が要り、重に当たる
  - B 自体は偽の安心を作るとは限らない。note が「構文のみ」と開示するなら、現行と同程度である。落とす決め手は (a) と (c) である
- **C(実在の検査)**: K-7 の論理がそのまま当たる(実在は算出できることを示さない)。散文から path を取り出す規則が決定可能でない。新規種別は登録時に記録が無く、実在する所在を先に作らせる義務になる。重。採らない
- **D(登録時に算出を実行)**: 登録時の母数が0で判定不能になる。決定可能でない。採らない
- **E(欄を外す)**: 正直さの点では A より優れて見える面がある。値はどの計算にも読まれず、検査は形式にすぎないからだ。それでも採らない。欄は統制ではなく**監査のための記録の所在**で、REWORK_UNCOUNTED が「basis.detection.reworkRate に書いた手段で補い、内部監査で確かめる」と案内する。外すと、採用者が自前の計測を持つ場合の置き場と、監査の入口が失われる。標準 5.5.4 の条項改廃にもなり、重。正直さの問題は、欄を外すことではなく、欄が統制のように読まれることだ。それは A′ の note の直しで解く
- **G(確認の記名欄)**: 登録は記名の事前承認で、登録の判定が「計測できること」を確かめる位置づけをすでに持つ。欄を足すと申告が確認の代わりに通る
- **付記して採らない**: 2欄の文が同一の記入を拒否する案は決定可能だが、同じダッシュボードを正当に指す場合がある。長さの下限は値に根拠が無く、ADR-0026 のマークを要する

## 4. 重へ上げる要否

- **A′+F は軽のまま**。新しい義務なし、ADR の原則の変更なし、安全に直接当たらない
- **B・C・D・E を採るなら重**。ADR-0059 決定5 の線を動かす、または 5.5.4 を改廃するため。上の理由で採らないので、上げる必要は生じない
- **注意点(重への契機にはしない)**: 1 の 3 のとおり、A の理由(3)は #348 の結論に依存する。#348 が「判定不能でも止めない」と決めた場合、中身の無い根拠で登録された L3 の種別に有効な引き下げが働かない状態が残りうる。その場合は #339 を再度開き、安全に当たるものとして扱う。A の記録に、この再審議の条件を書く
- 議長への裁定の依頼: A′ の note 直しを「編集の指摘」として議長が直し、独立の突合を1回行う。F は採否を議長が決める。私の意見は「採る。ただし信頼性の向上とは称さない」
