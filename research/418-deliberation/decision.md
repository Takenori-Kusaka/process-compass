# 議長の裁定(#418 7.6 のエスカレーションの段階の報告先と、確約範囲の変動の扱い)

入力: `council-00-agenda.md`、`survey-418-1-internal.md`、`survey-418-2-external.md`、`council-01-drafter.md`〜`council-05-defender.md`。新しい ADR は ADR-0095(2026-11-04 の main の次の空き番号)。

## 0. 前提として確かめた事実(議題に無かったもの)

- **SC-M の 0〜5% の変動に経路が無い**(現場・品質監査・規格・起案)。2.10.5・2.10.7 は SC-M の増減を量を問わず「SG または 7.6」とするが、7.6 のスコープの発火は 5% からである。5% 未満は、次の SG まで待つか黙って動かすかの 2 択になる。5% を価値責任者の許容値と読むと ADR-0019 決定7 と食い違う
- **「SC-M の 5% 変動」は循環している**(起案)。SC-M はエスカレーションを経ないと動かないのに、動いたらエスカレーションすると読める。発火の対象は「動かす必要の見込み」でなければならない
- **変動率の基準点と累計の扱いが無い**(品質監査)。1 回ごとに測ると読めば、4% ずつ刻めば一度も発火しない。確定時に SC-M だった項目を SC-P・SC-B へ移す操作も、変動として数えられていない
- **日程の起点が食い違う**(品質監査)。7.6 は実績の「1週間の遅延」で発火し、D-0 表3 は「見込み」で発火する
- **7.6 の閾値に根拠水準のマークが無い**(弁護・規格)。出典は #104 の原調査が引いた解説記事の設定例で、E0 に当たる
- **2.10.6 の手順2「期日を動かす」の決定者が書かれていない**(弁護)。手順1(SC-B → SC-P を削る)で足りないときに残る選択肢(期日・SC-M・基準を動かす)は、どれも SG で確定した値を動かす(起案)
- **1〜2 名の体制には B-2 が無く**(軸A。設置しない、記録のみ残す)、**事業決裁者と価値責任者の兼務はどの規模でも禁止されていない**(1〜2 名で許容、3 名以上で非推奨)。報告先を事業決裁者に分けても、兼務の体制では同じ人に戻る(現場・規格)
- 期限超過の自動承認は禁じられている(3.9.3)。みなし承認の形は採れない(規格)
- テンプレートの D-0 の節6 にある行「判定者どうしの見解が割れた」は、3.10.10 に根拠があり、標準の表3 の欠落である(起案・弁護・品質監査・現場)
- 品質側の表の報告先「判定者の上位者」「品質保証部門」と、3.9.3 の「決定者の上位」も、定義の無い語である(弁護・規格・起案)

## R-1 報告先を、本標準の語で書く

**裁定**: 「プロジェクト責任者」「部門責任者・PMO」を規範の語から外し、起票する者と判定する者を、本標準の席・会議体で書きます(5 委員一致)。実際の宛先と応答期限は D-0 表3 の記名によります。組織の部門長・PMO などは、D-0 表3 の「写しの宛先」として書いてよいものとし、判定する者にはしません(5 委員一致)。

## R-2 段階ごとに決めることと、報告する者と決める者の分離

**裁定**: 起票する者は価値責任者とします(材料の集計は ADR-0094 の D-0 表1「フローの観測と見込みの報告」の実行の担い手に任せてよい)。段階ごとの判定する者と決めることを、次のとおり定めます(規格・弁護・現場・品質監査の多数。起案の「段階1 も事業決裁者が判定」は、予算・日程の段階1 が頻繁に発火し、事業決裁者の受信箱が日常の報告で埋まるため、スコープの行に限って採る)。

| 区分 | 段階1 | 段階2 | 段階3 |
| --- | --- | --- | --- |
| 予算・日程 | 価値責任者が、D-0 表2 のチーム層の境界の内側で SC-B・SC-P を削って吸収する。結果を事業決裁者へ写しで報告する。期日・予算・SC-M は動かさない | 事業決裁者の記名の決定 | B-2 の判定 |
| スコープ(SC-M) | 事業決裁者の記名の決定(量を問わない) | 事業決裁者の記名の決定 | B-2 の判定 |

- **起票した者は、自分の起票を判定しない**(5 委員一致)。応答期限を過ぎたら、次の段階へ上げる。みなし承認にしない(3.9.3)
- 2.10.6 の手順2(期日を動かす)と、SC-M・基準を動かすことは、価値責任者が決めない。上の表の判定する者が決める
- 段階2 の事業決裁者の決定は、非同期の持ち回りでよい。リスク区分 R1 の変更に係る決定には使わない(規格・起案)

## R-3 SC-M の変動が価値責任者の単独の判定にならないための歯止め

**裁定**: (a)・(c) を採り、(b) は単独では採りません(5 委員一致)。

- (a) SC-M の変動は、量を問わず事業決裁者が判定する(価値責任者の許容値はゼロ)。閾値(15%・25%)は、事業決裁者から B-2 へ上げる境界に使う
- (c) 閾値は、G-1 の判定者(事業決裁者)が確定して記名する
- SC-M の変動率は、直近の確定(SG。S0 の初回は G-1)からの追加と削除の累計で測る。確定時に SC-M だった項目を SC-P・SC-B へ移すこと、分割して一部を外すことは、SC-M の減少として数える(品質監査)
- (b)(受理の記録を次の段階が点検する)は事後の追認になるため単独では採らない。ただし SC-M の判定記録は、次の SG の判定の入力にする(弁護・規格)
- SC-P・SC-B の調整は、従来どおり価値責任者が決め、7.6 の対象外とする
- **価値責任者と事業決裁者が同じ人の体制**: 自己の判定を禁止せず、代償措置も足さない(3.5 の兼務の表、ADR-0082 と揃える)。D-0 表3 に同一人物である旨を書き、判定記録に「自己の判定」と書いて開示する(品質監査・規格・弁護・現場)。受託では相手方との合意が外の歯止めになる(軸D)

**採らない案**: 段階1 の報告先を価値責任者にする(#406 の裁定。M-3 の食い違いを生む)。報告者と決定者をあらゆる規模で人の単位で分ける(1〜2 名で常に不適合か形だけの記名になる)。同一人物なら一つ上の段階へ報告する規則の単独採用(1〜2 名には上が無い)。全段階1 を事業決裁者へ送る。中間の会議体の新設(作業層に会議体を置かない)。みなし承認。

## R-4 閾値の数値

**裁定**: 規範値にせず、初期値にとどめます(5 委員一致)。「組織が確定」を「G-1 の判定者(事業決裁者)が確定して記名する」に改め、記録の無い G-1 では閾値が確定していないことを明記します。日程の発火を「遅延の見込み」に揃えます(品質監査)。7.6 の閾値に EV マーク(E0)を付けます。第1章 1.7 の「初期値」の強さの定義は、本件では行わず後継へ送ります(規格の提案)。

## R-5 D-0 と準拠テンプレート

**裁定**:

- D-0 表2 の 3 層(チーム層・案件層・経営層)を、7.6 の段階1〜3 の境界に 1 対 1 で写すと注記する。スコープ(SC-M)のチーム層の境界はゼロ(5 委員の多数。E0)
- D-0 表3 に行「確約範囲(SC-M)を動かす必要の見込み(量を問わない)」と「判定者どうしの見解が割れた」(3.10.10)を足す。列を「判定する者(席・会議体)」「写しの宛先」に改める。通知先に起票した席だけを書かないこと、兼務の体制では同一人物である旨を書くことを注記する
- 7.6 のラベルを、段階ではなく判定する席で引く。SC-M の段階1 は `state:needs-owner`
- 準拠テンプレートの ESCALATION(`next.mjs --role` の出力)と D-0 の様式の節4・節6 を、同じ形に改める。IMPL-0005 の注記を改める

## R-6 記録

- ADR-0095 を起こし、ADR-0019・ADR-0037・ADR-0094 を補う(本文を書き換えない)。SC-M の段階1 を `state:needs-owner` へ付けるのは、ADR-0037 の定義(ラベルは次に動く席を指す)の内側であり、置き換えに当たらない
- 採らない案は上記のとおり ADR に表で残す

## 残す論点(後継へ)

- 品質側の表の報告先「判定者の上位者」「品質保証部門」と、3.9.3 の「決定者の上位」の定義
- 7.6 の予算の段階3 と 7.7.4 の自動の上程が同時に成り立ったときの関係
- 第1章 1.7 での「初期値」の強さの定義(3.8.2 の「値と例示を置かない」作法との 2 系統の整理)

## 突合の後の訂正(2026-11-04、`crosscheck.md`)

独立の突合(高 1・中 8・低 9)を受けて、裁定と実装を次のとおり訂正しました。

- **第8章 軸D の内製の列を改める(H-1)**。「SC-M の変更は価値責任者と B-2 の判定で完結」が残り、本裁定と正反対に読めた。「事業決裁者が判定し、段階3 は B-2 が判定する。価値責任者は起票し、判定しない」へ
- **3.5.5 の `state:needs-owner` の範囲に、SC-M の段階1 を足す(M-1)**。**3.7.4 の B-2 の決定する事項に、段階3 の予算の超過と SC-M の変動を足す(M-8)**。B-2 を置かない 1〜2 名の体制では、段階3 も事業決裁者が判定する
- **着手決裁前の累計消費の閾値も、G-1 の判定者が確定して記名する(M-2)**
- **予算・日程の段階1 の「判定する者」を「判定を要しない」と書く(M-3)**。価値責任者の吸収は自分の権限(SC-B・SC-P の調整)の内側であり、判定ではない。起票した者が判定する者の行に入って、禁止と矛盾して読めた。吸収で足りないときは段階2 として事業決裁者が判定する(M-4)
- **D-0 表2 の写し方を定義する(M-5)**。チーム層・案件層・経営層の境界を超える見込みを、段階1・2・3 とする。スコープの行のチーム層に 0 を予め書く(L-9)
- **基準を下げることの決定者を 7.3 に戻す(M-6)**。2.10.6 と 7.3 で決定者が 2 通りになっていた
- **応答期限の超過の扱いを 3.9.3 に合わせる(M-7)**。「次の段階へ上げる」は、SC-M の段階1→2 で同じ事業決裁者へ戻り、段階3 には次が無い
- 低: 補助ファイルの語(L-1)、ESCALATION の見出し(L-2)、ADR の引用先(L-3)・影響(L-4)・兼務の箇条の限定の書き方(L-5)、閾値の記録が無い場合の帰結を G-1 の基準4 へ結ぶ(L-6)、受託の外の歯止め(L-7)
- **L-8(「プロジェクト責任者」を廃した言い回しに登録する)は採らない**。ADR-0094・ADR-0095 と記録が、廃した経緯を説明するためにこの語を正当に使っており、検査の対象を ADR から外す手当てが要る。ESCALATION の出力は `test-roster-rules.mjs` が検査している
