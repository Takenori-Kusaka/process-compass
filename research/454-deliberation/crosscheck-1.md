## 所見

### X-1(高・裁定と逆、表示と実態の食い違い)未完了の語の一覧が 20 行で切れ、省略を示さない

- 所在: `template/scripts/gate/check-pr.mjs` の `renderG6Material`。`for (const m of im.slice(0, 20))`(3057 行付近)
- 再現: `incompleteMarks` に 25 件を入れた `weakening` を `renderG6Material` に渡す。件数は「25 件」と出るが、行は 20 行しか出ない。「ほか N 件」も出ない(実行で確かめた)
- 裁定との関係: decision.md §2 は「未完了の語の件数の上限」を課さないと決めた。理由は「上限を超えた行が読まれない」で、「表示を丸めることも採らない(件数は必ず出す)」とある。ADR-0262 の採らない案の表にも、同じ文がある。G-6 の判定者は 21 行目以降を読めない。それでも、一覧の各行を確かめた(IMPL-1044)ことになる
- 直し方の案: 未完了の語の節では `slice` を外して全件を出す。要約の大きさに制約があるなら、省いた行を出す別の経路(ジョブの成果物など)を作る。そのうえで「ほか N 件(所在)」を出す。試験に 21 件以上の場面を足す
- 参考(範囲外): 既存の「検証を弱める変更」の節(skip・xfail・削除行のアサーション・期待値の改め)も `slice(0, 20)` で、省略を示していない。#454 の裁定の対象ではないので、後継は既存の Issue へコメントで足すかどうかを議長が決める

### X-2(中)注釈の中の検証の語を、空のテストの判定で「検証あり」と数える

- 所在: `check-pr.mjs` の `weakeningFindings` の `noAssertionTests`。`isAssertionLine` は、注釈の行で `ASSERTION_IN_COMMENT` を照合する
- 再現: 新しいファイル `test/a.test.js` に `it('a', () => {` / `  // expect(f()).toBe(1);` / `});` を足すと、一覧に出ない。pytest の `# assert f() == 1` だけのテストも同様に出ない
- 影響: 検証を注釈にしただけの空のテストが、0 件に紛れる。限界の文 `NO_ASSERTION_LIMIT` は「列挙した語の照合」と書くが、注釈の中の語を数えることは書いていない。「0件は中身があることを示さない」で全体の開示はあるので、高にはしない
- 直し方の案: 空のテストの判定では、注釈の行を検証に数えない(`#[` の行は除く)。削除行の判定(IMPL-0204)の `ASSERTION_IN_COMMENT` はそのまま残す。直さない場合は、限界の文に「注釈の中の検証の語も数える」と書く

### X-3(中)`--`・`<!--` の注釈を持つ拡張子では、行注釈の未完了の語を拾わない

- 所在: `check-pr.mjs` の `commentTail`。照合するのは `//`・`/*`・`#`・行頭の `*` だけ
- 再現: `db/a.sql` の `-- TODO: index`、`src/a.lua` の `-- TODO: x`、`src/A.vue` の `<!-- TODO: layout -->` は、どれも 0 件になる(実行で確かめた)。`CODE_EXTENSIONS` は sql・lua・vue・svelte を含む
- 影響: 限界の文 `INCOMPLETE_LIMIT` と 5.8.5 の本文は、「製品のコードの拡張子の追加行」の「行注釈の中の」語を拾うと書いている。sql・lua・vue・svelte では、この表示と実態が合わない。7 種のアダプタ(node・python 系・go)の主な言語では働くので、中とした
- 直し方の案: `commentTail` に `--` と `<!--` を足す。`--` は sql・lua・hs に限り、拡張子で分ける(JS の減算と混ぜない)。足さない場合は、限界の文に「`--`・`<!--` の注釈は読まない」と書く

### X-4(低)`#` を注釈と読む偽陽性

- 再現: `src/a.c` の `#define XXX 1`、`src/a.js` の `this.#XXX = 1;` が、未完了の語として出る
- 偽陽性の開示の型(確かめた結果として扱う)の範囲にある。直すなら、`#` を注釈に数える拡張子を py・rb・sh・ps1 などに限る

### X-5(低)注釈の中のアポストロフィが、未完了の語を隠す

- 直すなら、`commentTail` の中で、注釈の開始を先に探してから、それより前だけを `maskLiterals` に通す

### X-6(低・編集)「アダプタ7種の主な書式」に Rust と JUnit が入っている

- 所在: ADR-0262 決定3、`check-pr.mjs` の `ASSERTION` の上の注釈、decision.md R-6
- template のアダプタは go・node・none・python・python-poetry・python-uv・undetermined の7種で、Rust と JVM は無い。書式の列挙は「アダプタ7種と Rust・JUnit の主な書式」とすれば事実に合う。ADR-0262 は採用済みだが、push の前なら直せる

- 所在: `assurance-case.md` の H.2 の行「生成物の保守性(理解しやすさ・変更しやすさ)」

- 同じ行の第1列に理由(「本標準が保守性の証跡と合格水準を持たないため」)が入っていて、他の行の書き方と揃わない。編集の範囲
