## 所見

### Y-1(中・表示と実態の食い違い)行頭が `*` の行の検証の語を、空のテストの判定で数える

- 所在: `template/scripts/gate/check-pr.mjs` の `splitComment` の末尾 `return { code: t, comment: (slash || !known) && /^\s*\*/.test(t) ? t : null };`。行頭が `*` の行は、注釈として扱うのに `code` にも行全体を返す
- 再現: `a.test.js` に `it('a', () => {` / `  /**` / `   * expect(f()).toBe(1)` / `   */` / `});` を足すと、空のテストの一覧に出ない(0件)。`splitComment('   * expect(f()).toBe(1)', 'a.test.js')` は `code` と `comment` の両方に行全体を返す
- 表示との関係: `NO_ASSERTION_LIMIT` は「行注釈の中の語は数えない(…複数行のブロック注釈の * の無い中間行は読めず、検証に数える)」と書く。これは「`*` のある中間行は注釈として読み、数えない」と読める。実際は数える。5.8.5 の本文と G-6.md も「行注釈の中の語は検証の語に数えない」と書く。直す前(dac7dda^)も同じ挙動で、直しで足した文が実態と合わなくなった
- 高にしない理由: 検証を JSDoc 形式の注釈へ移しただけの空のテストという狭い場合で、限界の文の「0件は中身があることを示さない」が全体を開示している。偽陰性の向き(空のテストを隠す)なので、軽くはない
- 直し方の案: `*` の行の判定に当たったときは `code: ''` を返す(1行の変更)。試験に上の場面を足す。あわせて未完了の語の側でも、`*` の行の `throw new Error("not implemented")` を拾わなくなる(Y-2 の (c) が閉じる)。直さない場合は、限界の文を「複数行のブロック注釈の中間行は、行頭の `*` の有無に依らず読めず、検証に数える」へ改める

### Y-2(低・直しで入った後退)`/*` を行注釈と同じに扱い、`*/` より後ろのコードを捨てる

`splitComment` は `/*` を見つけると、それより後ろを全部注釈とみなします。直す前の判定と比べた差は次のとおりです(どちらも実行で確かめた)。

| 場面 | 直す前 | 直した後 | 向き |
| --- | --- | --- | --- |
| (a) `x(); /* c */ throw new Error("not implemented")`(未完了の語) | 1 | 0 | 取りこぼし |
| (b) `/* setup */ expect(f()).toBe(1);` だけのテスト(空のテスト) | 出ない | 出る | 偽陽性 |
| (c) 行頭が `*` の行の `throw new Error("not implemented")`(未完了の語) | 0 | 1 | 偽陽性 |
| (d) 正規表現 `/\//` の後ろの `throw …not implemented`・`expect` | 1・出ない | 0・出る | 取りこぼし・偽陽性 |

- (a)・(d) は本物の未実装の例外を取りこぼす向き。ただし、同じ行に注釈か正規表現の `//` を置き、その後ろに例外を書く稀な形に限る
- 直し方の案: `/*` は対応する `*/` までを注釈とし、その後ろを `code` に戻す。正規表現の中の `//` は読み分けない(限界の文で開示)
- 開示で閉じる場合の限界の文の案(INCOMPLETE_LIMIT と NO_ASSERTION_LIMIT の両方): 「1行の中で注釈の開始(// /* # -- <!--)より後ろは、`*/` の後ろのコードも含めて注釈として読む。正規表現の中の `//` も注釈の開始と読む」

### Y-3(低・既存。直しで変わらない)引用符の対の取り違えが注釈を隠す、言語の書式の偽陽性

- Rust の寿命の注記が3つあり、注釈にアポストロフィがある行 `impl<'a> Foo<'a> for X<'a> {} // isn't TODO` は 0件になる。直す前も 0件
- sh の `len=${#XXX}` は未完了の語として出る(偽陽性。直す前も同じ)。lua の長い文字列 `s = [[ -- TODO ]]` は出る(偽陽性。直しで `--` を読むようになって入った)
- 限界の文の「文字列の中は読まない」は、引用符の文字列に限った近似である。開示で閉じる場合の文の案: 「文字列は引用符(' " `)の対だけで読む。Rust の寿命の注記・lua の長い文字列・sh の `${#…}` は読み分けない」

### Y-4(低)大量の未完了の語でジョブの要約が上限を超えうる

- X-1 の直しで一覧は件数で切らなくなった。正本のジョブの要約(GITHUB_STEP_SUMMARY)は1ステップあたり 1 MiB が上限で、超えると要約全体が載らない。PR のコメントは 65,536 文字で切れるが、`upsertComment` の失敗は警告を出し要約へ案内する(既存)
- 数千行の未完了の語を足す PR で初めて当たる。`--report` のファイル(`evidence/pr-checks-base.md`)には全件が残る
- 開示で閉じる場合の文の案(EV か限界の文): 「一覧が大きすぎてジョブの要約に載らない場合は、`--report` のファイルを読む」。根拠水準マークまでは要らない

### Y-5(低・編集)

- `check-pr.mjs` の `splitComment` の直前に、旧関数の注釈「行注釈の部分を返す(無ければ null)。文字列の中身は先に除く」が残り、JSDoc が2つ重なっている
- `INCOMPLETE_LIMIT` の `#` の拡張子の列挙に `exs` が無い(コードは exs を含む)。lua に `/*` を数えているが、lua の注釈ではない(実害は無い。lua の構文では文字列の外に現れない)
- 本文 5.8.5 の「行注釈の書式は拡張子で決める(`//`・`/*`・`#`・`--`・`<!--`)」は、ブロック注釈の開始(`/*`・`<!--`)も「行注釈」と呼んでいる。限界の文の書き方と合わせて「注釈の書式」とする案
- IMPL-1043 の注記の「試験で確かめる; 行注釈の中の語は数えない」は、半角セミコロンで文をつないでいる。「。」にそろえる

## 確かめて問題が無かったこと

- 文字列の中の `#`・`--`・`//` を注釈と誤らない: py の `s = "# TODO"`、sql の `SELECT '-- TODO'`、kt の `"// TODO"`、go の生の文字列 `` `//x` ``、ts のテンプレートリテラルの中の `"//"`、rb の `"#{x}"`、cs の `@"C:\"` の後ろの `// TODO`、エスケープした引用符 `'it\'s'` の後ろの `// TODO`
- 本物の検証を取りこぼさない: pytest の `assert f() == '#'`、Jest の `toBe('//')`、Go の `"//"` を含む行の `t.Errorf`、注釈にアポストロフィがある行の `assert`、Rust の寿命の注記の後の `assert!`、Kotlin の `@Test` と `assertEquals`
- 注釈にしただけの検証を数えない(X-2 の意図どおり): Java の `@Test void x() { // assertEquals(...)`、pytest の `pass  # assert later` は空のテストとして出る(直す前は出なかった)
- 注釈にした定義を数えない: `// it('a', () => {})` だけのファイルは出ない
- 裁定との突合: 未完了の語の検出は合否に使わず、リスク区分に依らない(変えていない)。条文と G-6.md の直しは「確かめる」までにとどまり、差し戻しの文は無い。記名・氏名・日付の欄は足していない
