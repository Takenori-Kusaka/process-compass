# #454 会議体 意見書: 弁護(採用者の側)

- 立場: 新しい義務を負う採用者の弁護。同時に、課さない判断が採用者の利用者を危険に晒す点も見る
- 読んだもの: `decision-draft.md` 全文、`internal.md` の該当箇所、`G-6.md` 手順2、ADR-0244 の「課さないと決めたこと」。規格の本文は読んでいない
- 総評: 案の骨格(A2・B1・C2・D2・E2)には賛成する。ただし次の4点は直さないと、採用者に過剰な義務か、信頼できない合否もどきを課す。(1) 差し戻しの文(Q1)、(2) 未完了の印の対象ファイルの範囲、(3) H.2 の行の理由と「代わりに示すもの」、(4) IMPL-C の確認が記録に残らないのに、残るかのように書いていること

## 争点ごと

### Q1 差し戻しの文を条文に書くか: 書かない。「確かめる」までに揃える

- 案(`decision-draft.md:47`・`:145`)は「確かめられない行がある変更は差し戻す」を条文に置く。既存の 5.8.5 後段は「確かめる」までで、差し戻しの文を持たない(案自身が `:212` で認めている)
- 強い側へ寄せると、次の害が採用者に出る
  - 取り込み・移行・生成コードの PR で、未完了の印が数十行出る。1行でも確かめられなければ差し戻しなので、判定者は一括して差し戻すか、確かめずに通すかの二択になる。後者は「読み飛ばし」を制度が誘発する(Q2 に続く)
  - 「確かめられない」の意味が定まっていない。台帳の行が無い印と、判定者が分からない印は別である
- 差し戻しの根拠は、新しい文でなく既存の規定から引ける
  - 未完了の印に台帳の行が無い: 負債台帳の「妥協・TODO・仮実装はすべて記録する」(`deliverable-templates.md:770`。IMPL-0788)に反する。既存の義務の違反として差し戻せる
  - 検証の呼び出しの無いテストが、どの受入基準を確かめるか言えない: G-6 基準1 と基準2(自分の言葉で挙動を説明)で差し戻せる
- 提案: 条文は「一覧を G-6 の必須の確認事項として示す。G-5 の合否に使わない」までにする。差し戻しの理由づけは `gates/G-6.md` 手順2 に「台帳の行が無い印は IMPL-0788 違反、テストの対応が言えなければ基準1」と書く。これで新しい差し戻しの条項を作らず、5.8.5 後段と同じ強さに揃う
- 判定者への新しい義務かの問い: 課す。ただし G-6 手順2 は既に弱める変更の一覧を1件ずつ読ませている。同じ型の材料が2節増えるだけで、新しい手順・様式・記名は無い。許容できる

### Q2 偽陽性による読み飛ばし(現場の問いだが、採用者の負担として答える)

- 危険はある。案は0件でも定型の限界の文を3節分(弱める変更・未完了の印・検証の無いテスト)出す。常に出る長文は、読まれなくなる典型である
- 提案
  - 既存の節に混ぜない。節は分ける(弱める変更の読みが薄まらないため)
  - 0件のときの限界の文は、各節1行にして、詳細は G-6.md に寄せる。件数が1以上のときだけ詳細を出す(ADR-0124 決定2 の「拾わない形を出す」を保つなら、1行の定型で足りる)
  - 1節あたりの表示は、全件の件数を先に出し、行は上限(例: 50 行)で切って「残りは差分で確かめる」と出す。これは合否の上限ではなく表示の上限であり、1.8 や案の「件数の上限を課さない」と矛盾しない(上限は採用者に義務を課さない)
- 1.8(識別子の注釈)を採らないことには賛成する。理由は案の「AI が注釈を埋めれば消える」でなく、**注釈の定義が増えること**に置くべきである。案の理由は、未完了の印の語を言い換える回避(A3 の理由で自ら認めている)にも同じように当たり、A2 の価値も下げる。理由が一貫しない点を ADR-0262 で直す

### 案に無い欠陥 1: 未完了の印の対象ファイルが広すぎる

- 案(`:44`)の読む差分は「テストのパスの外のファイルの追加行」。これは Markdown・YAML・ロックファイル・生成物・取り込んだ外部のコード(vendor)・設定・画像説明まで含む。README の「TODO リスト」や、この標準自身のような文書主体のリポジトリでは偽陽性が大半になる
- 提案: 対象を、アダプタ7種が扱う言語の製品コードの拡張子に限る。vendor・生成物・文書・設定は対象外とし、限界の文に書く。限らないと、偽陽性の山が確認の時間という採用者の費用になり、Q2 の読み飛ばしを悪化させる
- TODO 系の語は行注釈の中に限る(案は書いている)。文字列リテラルの中の語を拾わない手段は決定可能でない。限界の文に出す

### 案に無い欠陥 2: 「検証の呼び出しの無いテスト」のファイル単位の近似が、安心を作る

- 近似は、アサーション0件のファイルだけを拾う。1つでもアサーションがあれば、10個の空のテストが同じファイルに在っても出ない。件数0 の表示が「テストは中身がある」と読まれる危険がある。案は限界の文に出すとするが、**0件の定型の文の第1文に「個々のテストの中身は見ていない」と置く**ことを求める(後の行に埋めない)
- 枠組みの外の検証(property-based、契約テスト、E2E の暗黙の失敗、`expect` 無しの例外期待など)が偽陽性になる。採用者が設定で除けない(5.2 の鍵を置かない判断)ので、除けない偽陽性が恒常的に出る採用者が生じる。5.2 の判断自体(鍵を置かない)には賛成するが、代償として**恒常的な偽陽性の採用者の逃げ道が無い**ことを ADR-0262 の影響に明記する。逃げ道を作るなら、採用者の構成の `guard.json` でなく、G-6 の判定者が「この枠組みは検証を内側に持つ」と確かめた結果を記録する形(新しい様式は作らない)に限る

### 案に無い欠陥 3: IMPL-C の確認が記録に残らないのに、残るかのように書かれている

- `:148` は「一覧を読まずに承認した記録が残る(C1 の記名の責任)」と書くが、案は新しい欄・様式・記名を置かない(`:155`)。G-6 の承認レビューが一覧を読んだかは、どこにも記録されない。矛盾である
- 結論: IMPL-C の `check=manual` は、確かめたかを機械も記録も検証できない統制である。これはコアポリシーの「機械で閉じない統制は manual か adopter にして根拠水準マークで開示する」に従えば許される。ただし**開示が要る**。IMPL-C の note と H.11 に「一覧を読んだかは記録に残らない。判定者の承認の自己申告に依る」と書く。弱める変更の一覧(IMPL-0204)の同じ弱点が既に開示済みなら、それに揃える。記名欄は求めない(#459)ので、記録に残す案は採らない
- 3 の「破られたとき誰が何を失うか」の記述は、この点を直した上で ADR-0262 に入れる

### Q3 言語ごとの語の一覧を template が持つこと

- 「細かい定義を増やさない」には反しないと考える。条文でなく定数に置くことと、既存の `SKIP_MARKS` が同じ構造であることによる
- ただし語の一覧の保守が、標準側の複製(`template:kb`)の乖離検査の対象になる。7言語分を最初から広げず、`SKIP_MARKS` と同じ範囲に限る。Go・Rust・Java を一度に入れて取りこぼしと偽陽性の実測が無いまま出すより、範囲を限り、範囲の外を限界の文に出す方が信頼できる。実測が無い間は EV-A の E0 を明記する(案は書いている)

### Q4 保留テスト: 求めない(案に賛成)。ただし H.11 の書き方に異論

- 求めると、全 R1 の採用者に新しいテスト運用(実装の担い手から隠したテストの管理)を課す。実証は研究のベンチマーク(E2)だけで、規程の先例が無い。採用者の費用は大きく、実証は乏しい。課さない
- 利用者への危険は残る。案の H.11 の文「機械では防げない。G-6 基準1 が唯一の層」は正直だが、**唯一の層である G-6 自体が全行を読まない承認**(H.5)である。H.11 には「G-6 基準1 は差分の全体を逐行で読むことを意味しない」を併記する
- 「課さない」でなく「妨げない」も書く: 採用者が自発的に保留テストを運用してよい。これは採用者の選択を狭めない(柔軟性)

### Q5 H.2 に保守性の行を足すこと: 足す。ただし理由と「代わりに示すもの」を直す。所有者への報告は要る

- 理由の直し: 案は「標準が製品の品質特性を判定すると標準が製品の良し悪しを判定し始める(ADR-0051 の線)」と書く。しかし本標準は既に G-5 でテスト・カバレッジ・lint・脆弱性を、製品の良し悪しに近い形で合否にしている。この理由は**既存の統制と矛盾して読まれ、反論される**。正しい理由は「保守性を支える証跡と合格水準を持たず、主張を立てると崩れが観測できない」(H.3 の主張の要件)である。ADR-0262 と H.2 はこの理由で書く
- 「代わりに示すもの」の直し: 負債台帳は妥協の記録で、保守性の代わりでも証跡でもない。載せると、台帳を付ければ保守性を示したと読まれる。「代わりに示すもの」は**なし**とし、台帳と4指標は「関連する既存の記録(保守性の証跡ではない)」と別の欄語で書く
- 所有者の確認: ADR-0051 は使いやすさ1件の決定である。「品質特性一般を主張しない」へ広げるのは、範囲の原則の一般化に近い。案の「ADR-0051 の適用であり、報告のみ」の読みは、上の理由の直しをした上でなら許せる。保守性だけの記述にとどめ、品質特性一般へ広げる文を書かない。広がる文が入るなら所有者の確認に上げる

## 論点(b)・(d)への賛否

- B1(合否にも一覧にもしない): 賛成。閾値を置くと、採用者に根拠の無い合否を課す。F-5 の理由の補記を ADR-0262 に書くことも賛成。ただし H.11 の行へ「重複・複雑度は標準が見ない。採用者は G-5 基準2 の lint で測ってよい」と**採用者が測ることを妨げない**旨を足す
- D2(変異試験の適用を変えない): 賛成。ADR-0244 の理由を覆す新しい実測が無い。リスク区分に依らず一覧を出すことも、実行時間を要さないので ADR-0244 の理由に当たらず、整合する
- E2(基準を増やさない): 賛成。附属書C のパス3 の追記は手引きなので新しい義務でない

## 採らない案の表への異論

- 「未完了の印の件数の上限」の採らない理由に ADR-0089 を引くが、ADR-0089 は「落ちることを期待する印」の件数の話である。同じ構造とは言えるが、**引用が根拠になるか実物を確かめてから書く**(私は ADR-0089 の本文を読んでいない)
- 「保留テストを R1 に求める」の行: 理由が「規程の先例が無い」だけだと、将来先例が出れば覆る。**採用者の費用**(隠したテストの管理)も理由に書く
- 表に足すべき行
  - 対象を全ファイルとする案(`:44`)。採らない理由: 文書・生成物・vendor の偽陽性
  - 一覧を読んだ記録を求める案(新しい欄)。採らない理由: 記名欄を求めない(#459)。代償として確認の自己申告を開示する
  - H.2 の「代わりに示すもの」に台帳を置く案。採らない理由: 台帳は妥協の記録で保守性の証跡でない

## 判断軸(信頼性)から見た残る懸念

- A2 は「AI が語を言い換えれば消える」検査である。実効の大半は、誠実だが不注意な書き手と、台帳に載せ忘れる運用の穴にある。悪意のある迂回には効かない。ADR-0262 は、この範囲を明記する(EV-A の限界。効くのは「うっかり」の拾い上げであって「ごまかし」の防止ではない)
- 合否にしないので、採用者の最悪の損失は確認の時間にとどまる。この点で A2 は採用者に安全な案である。逆に課さない場合の最悪(利用者が未完了の機能を受け取る)は、出荷判定が台帳だけを突合する構造に由来し、案が示す(`:148`)とおり実在する。A1 を採らないことに賛成する
