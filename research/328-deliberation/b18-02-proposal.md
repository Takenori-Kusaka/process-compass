# #328 残り「外殻・内殻」: 起案(束 B18、起案委員)

## 採る案: A'(「外殻」だけを 1.4 に定義し、内殻は定義しない)に、(b) の直しを最小にして足したもの

調査(b18-01)の案 A' を軸にする。実物を確かめて分かった次の点が、調査の見立てより変更行を減らす。

- lifecycle.md の 2.2 の表は、マクロライフサイクルの「判定の性質」を「投資継続・移管・出荷可否の判断」、「既存制度との関係」を「既存の稟議・決裁権限規程と、出荷判定の席・判定者・時点は変えない」と書く。すなわち **マクロ階層(外殻)は、出荷可否の判断(既存制度の下)を既に含んでいる**。したがって用法 (c)(「外殻ゲート(企画承認・出荷判定)」、proposal-template:57、tool/requirements、規則データ)は、外殻 = マクロライフサイクルの別名と定義しても**食い違わない**。調査が案 C で危惧した「(c) の意味が狭まる」は、定義を「SG に限る」でなく「2.2 の表のマクロ階層」とすれば起きない
- 食い違うのは (b)「外殻の合意 = G-2」(工程ゲートを外殻に数える用法)と、phase1 summary:56 の「内殻 = 工程ゲート G」の2系統だけ
- 744・751 の「外殻の変更管理」は、「既存の稟議・決裁(= 外殻)の側の変更管理」と読め、定義と合う。直さない
- 実物の確認: `provision-forms.yaml` の `variantForms` は4項目(統合プロセス、ピットイン、PIT-IN、正式名称)で、外殻・内殻は無い。「外郭」など異表記も公開ドキュメントに0件

## 波及の確認

- **provision-forms 登録: 不要**。ADR-0118 決定4は「登録するのは正表記を決めた決定のある語だけ」。新 ADR は決定の根拠になるが、探すべき異表記が実在しない(0件)ので項目を足さない。足すと自己試験の hit 文を作る必要があり、実用のない検査が増える
- **ADR-0118 との整合**: 決定4・見直しの契機(#328 で語を決める)に沿う。1.4 の語の決め方を「行を置く」とする導入文とも一致
- **規則データ・tailoring-kb.json・`npm run template:kb`: 変更なし**。tpl2 suite の fixture も、`scripts/test-tailoring-engine.mjs:265` の「外殻」はコメント1行で、文言を固定する検査ではない。template の md・様式(template-fields.yaml)に外殻・内殻は無く、template の push は不要
- **新しい義務: なし**(語の定義と用法の整合のみ)。採用者の対応づけ(既存決裁ゲートへの外殻ゲート)の意味は変わらない
- 実行する検査: `npm run check`(lint:refs, lint:provisions, textlint, evidence/impl/scope の台帳は変化なしのはず)。新 ADR を足すなら adr/index の更新と番号の検査

## 採らない案

- **案 A(内殻も定義)**: 内殻は本文にほぼ使われず(phase1 の1件のみ)、標準は対の語に「内側」を使う。使われない語を定義すると語が増え、方針(細かい定義を増やさない)に反する。phase1 の1件を「内側」へ直す方が小さい
- **案 B(外殻を消して置換)**: 変更行が最多(規則データ7箇所、複製 JSON、図 SVG 2枚、2.2 の図と代替文)で、tailoring の文言と複製の乖離リスクを負う。「外殻」が 2.2 の図で既に定義に近い使われ方をしており、消す利益が無い。また #438 が公式用語とした語を消すことにもなる
- **案 C(外殻を SG に限る)**: 出荷判定(G-7)が外殻ゲートから外れ、規則データ・proposal-template の意味が変わる。採用者の対応づけに影響しうるので重へ上がる。2.2 の表(マクロ = 出荷可否を含む)とも合わない
- **G-2 を外殻に含める定義(b を正とする)**: 1.4 の工程ゲートの定義(1つの開発サイクル内)と矛盾し、「外殻 = マクロ」の図とも割れる。G-2 の変更が既存の稟議・決裁を起動する経路は 2.10.8 が既に規定しており、外殻の定義に G-2 を入れる必要が無い

## 反対委員へ攻めどころ

- 744・751 の「外殻の変更管理」を直さない判断(定義の「既存の稟議・決裁」で読める)は妥当か
- 定義の「出荷可否の判断(既存制度の下)」が、G-7 を外殻に数えるように読めてしまわないか。工程ゲート G-7 は内側の制御点でもある。文言を「出荷可否について既存の決裁権限規程が定める判断」と詰める余地あり
