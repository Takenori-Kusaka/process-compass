## 1. 論点6 の問い

安全重要度(CL)の判定基準、および 7.4 が後回しを禁じる対象を、7.3 の例外承認の対象外とするか。規格で見るべき点は2つに分ける。

- Q1: 安全度水準・安全クラスを**決める行為そのもの**を、逸脱・免除・テーラリングの対象にできるか
- Q2: その水準に**応じて課される活動**を逸脱する場合に、誰の承認と何の記録が要るか(水準が高いほど承認が重くなるか)

## 2. 規格ごとの要点

### 2.1 ISO 26262-2(自動車)
- 4.2: 要求を満たさなくてよいのは (a) 規格に従ったテーラリングで該当しないと示した場合、(b) 不適合を受け入れる根拠があり、**その根拠が規格に従って評価済み**の場合の2つだけ【原: SRC-0790#c1】。対象の要求を ASIL の判定に限る記述はない。つまり判定(HARA)の要求も、評価済みの根拠があれば(b)に入りうる読みになる【二: 条文が HARA を名指しで除外していないことの読み】。
- 表の方法を別の方法へ置き換えるときは、根拠を示す【原: SRC-0790#c2】。
- テーラリング(6.4.5)は、対応する要求の ASIL を考慮して行い、根拠を安全計画に載せ、安全計画の確認レビューか機能安全アセスメントで評価される【二: LHP の解説、https://www.lhpes.com/blog/what-is-tailoring-in-functional-safety 。6.4.5 の本文はプレビューに無く【未】】。
- 確認措置(確認レビュー・監査・アセスメント)の独立性の段は ASIL で上がる(最上位は別部門・別組織)【二: Spyrosoft ほか。表の原文【未】】。
- 含意: **承認の重さを ASIL に連動させ、評価者を作り手から独立させる**型。「ASIL の判定を免除する」規定は確認できなかった(【未】: 全文を読んでいない)。

### 2.2 IEC 61508(機能安全の基本規格)
- 機能安全アセスメントの担当者の独立性は3段(独立した人・部門・組織)で、結果の重大さと SIL で最低の段が決まる【抜: SRC-0677。表の原文は 1998 年版 IEC 61508-1 表4・表5 を検索結果で見たのみ【二】】。
- 下の段を採るなら根拠の明記を要し、第三者認証は要求しない【抜: SRC-0677#c1・#c2】。
- SIL の割り当て自体は、ハザード・リスク分析(第5部は参考附属書)で行う。割り当てを免除する規定は確認できなかった【未】。
- 含意: 61508 は「根拠を記録して低い段を選ぶ」経路を、**最低限の段の表を下回らない範囲**で認める。表そのものを下回る許可は確認できなかった。#318 はこの経路を採らない判断をしている(SRC-0677 の summary)。突合の対象。

### 2.3 IEC 62304(医療機器ソフトウェア)
- 安全クラスの割り当て(4.3)は必須で、任意にする手順では適合を主張できない【原: SRC-0791#c1。認証機関の FAQ】。クラスはリスクマネジメントファイルに記録する【原: SRC-0791#c2】。
- 親の項目のクラスは分解先へ引き継がれる。別のクラスにするには、分離の根拠を文書にする。ソフトウェア外のリスク管理策でクラスを下げる場合は、独立性を示し、外部の管理策を検証する。不確かなときは上位のクラスに寄せる【二: governancedocs.com・conclusive.tech・Johner Institute の解説。2015 修正票 1 の本文は SRC-0525 のプレビューで、該当の節は読んでいない【未】】。
- 含意: 「安全クラスを下げる」ことは認めるが、**下げる側に根拠と検証を課し、上げる側には課さない**非対称がある。クラスの割り当てを任意にする(=免除する)ことは明確に認めない。

### 2.4 DO-178C / ARP4754A(航空)
- ソフトウェアレベル(A〜E)は DO-178C の中で決めるのではなく、**システム安全性評価(別の工程)の結果として与えられる**【二: Wikipedia、Aerospace Innovations ほか。FAA AC 20-115D は「割り当てられたレベルに対応する目標をすべて満たす」とする【抜: SRC-0529#c1】】。
- PSAC は認証当局との「契約」にあたる計画で、開発の解釈と目標の満たし方を当局へ示す【二: Aerospace Testing International】。計画からの変更・逸脱に当局の同意を要する旨は一般的な実務だが、本文では確認していない【未】。
- AC 20-115C: 指定の版(DO-178B 等)の代わりに DO-178C を使うには、14 CFR Part 21 subpart O に従う逸脱を申請する【二: 検索結果の抜粋。本文【未】】。
- 含意: レベルの決定権が**開発者の外**(システム安全・当局)にある。開発側の承認者がレベルの基準を緩める経路は、確認した範囲に無い。

### 2.5 ISO 14971(医療機器のリスクマネジメント)
- リスク受容の判定基準(criteria for risk acceptability)は、**トップマネジメントが定めた方針**に基づき、リスクマネジメント計画へ文書化する【二: 規格の抜粋を載せる解説と、PDF の検索結果。節番号 4.2(方針)・4.4(計画)は Johner Institute による】。
- トップマネジメントは、リスクマネジメントのプロセスの適切性を計画した間隔でレビューし、決定と処置を文書にする【二: 同上の PDF の抜粋】。
- 含意: 受容基準の**設定権者を製品チームより上に置き**、案件ごとの判断は基準に従わせる。基準の変更は上位の権限者の方針・レビューの対象。個別案件が基準を免除してもらう経路は、確認した範囲に無い。

## 3. 論点6 についての要点(裁定ではない)

| 問い | 確認できた範囲 |
| --- | --- |
| Q1 判定そのものを免除の対象にできるか | 免除を明文で認める規格は確認できなかった。62304 は割り当てを必須とする【原】。14971 は基準の設定権を上位に置く【二】。DO-178C はレベルの決定権を開発の外に置く【二】。26262 の 4.2(b) は、評価済みの根拠があれば不適合を許す一般規定で、判定を名指しで除外してはいない【原】(読みは【二】) |
| Q2 水準に応じた活動の逸脱 | 認める。ただし**根拠を文書にし、作り手から独立した者が評価する**。独立の度合いは水準が高いほど上がる(26262 の確認措置、61508 のアセスメント)【二/抜】 |
| 誰の承認か | 26262: 確認レビュー・アセスメントの評価者(独立)。61508: 独立した人/部門/組織。14971: トップマネジメント(基準の設定)。DO-178C: 認証当局 |
| 何の記録か | 根拠(26262・61508)、クラスの記録と分離・外部管理策の検証(62304)、方針とレビューの決定(14971)。いずれも作り手の自己申告だけでは閉じない |
| 下げる側と上げる側 | 62304 は下げる側にだけ根拠を課す。61508 は表を下回る許可を確認できなかった |

### 3.1 現行の選択肢との対応(intake 論点6 の A・B・C)
- A 現状維持: 規格の先例は、「評価済みの根拠つきの逸脱」(26262 4.2(b))に近い。ただし評価者の独立の段を要する点で、本標準の 7.3(承認者の記名)とは強さが違うかもしれない。
- B 安全重要度が掛かる基準だけ対象外: **判定そのもの**を免除しない点で 62304・14971・DO-178C と整合する。**判定に応じた活動**まで一律に対象外とする先例は確認できなかった。26262 や 61508 は活動の逸脱を根拠つきで認めている(上の Q2)ため、B を「活動の逸脱も不可」へ広げると規格より厳しくなる。
- C 対象外にせず、承認者を上位に限る: 26262・61508 の「水準が高いほど独立の度合いを上げる」型と整合。「上位」を何とするか(独立した人・部門・組織)の先例は 61508 の3段。
- 判定の基準そのものと、基準に従った活動を分けて考えるのが規格の構造に近い(Q1 と Q2 の区別)。ただし、この分け方を本標準の条項にするかは、会議体の議題。

## 4. 論点1・論点4 に添える外部の参照

### 論点1(S0 の「統合(G-4 へ)」の中身)
- ISO 9001:2015 8.3.2(設計開発の計画)は、段階と管理を、活動の性質・期間・複雑さに応じて定める【二: 解説 https://blog.auditortrainingonline.com/blog/understanding-iso-90012015-clause-8.3-design-and-development 。原文【未】】。8.3.4(管理)はレビュー・検証・妥当性確認を計画して行い、結果と処置を文書化した情報として保持する【二: 同上、iso9001expert.com】。
- 含意: レビューを**1つの判定にまとめること**自体は、計画に載せ、まとめた判定の中で確かめた事項と結果を記録するなら、規格の枠内。確かめる事項が「統合」で消えないこと(何を確かめたかの記録)が要点。本標準の「統合」は語義の定義を要する、という intake の見立てと矛盾しない。
- 12207・15288 の判定・レビューの節(15288 のプロジェクト評価・制御、決定管理)は、SRC-0491・SRC-0731 が公開プレビューで本文は読んでいない【未】。ここでは参照しない。

### 論点4(「判定の総数」の原則)
- 確かめた範囲で、ISO 9001 8.3・12207・15288 に**判定(レビュー・ゲート)の数の上限や総数の原則**を置く規定は見つからなかった【二: 8.3 の解説群を見た範囲。12207・15288 の本文は【未】】。規格は「どの段階でレビューするか」を複雑さに応じて計画させ、数は定めない。
- 含意: 総数の原則を立てることを外部規格が要請してはいない。原則を立てるか、引用を訂正するかは、内部(ADR-0074 との突合)で決まる。外部は B(原則を立てず引用を訂正)を妨げない。
