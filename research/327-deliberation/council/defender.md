## 論点1 S0 の G-2→G-4 の統合の中身

### 現行を弁護する点
- 軸B は S0 の G-2 を「統合(G-4 へ)」とし、規則 `r-b-poc` は `merge-into` を持つ。**統合先と統合の向きは既に決まっている**。足りないのは、統合で何が残るかの文である
- S0 は「捨てる前提で速く学ぶ」段階で、取り消せない操作は持たない。CL1 以上では G-6・G-7 が S0 でも適用される(tailoring-guide 525〜526 行)。破られたときの損失は S0 の手戻りに限られ、方針の問い(3)の「細かく書く」対象に当たらない
- 方針の問い(1)に従い、並べる材料と順は手引き(gates/G-4.md)に置く。条文は結果と証跡だけにする

### 反対する案
- (a) S0 専用の G-4 基準を新設する。採用者への新しい義務であり、G-4 の表が S0 とそれ以外で別物になる。基準番号が段階で分かれると、宣言行・KB・テンプレートの全てが段階ごとの分岐を持つ。損失の小さい S0 のために、全段階の読み手が分岐を読む負担を負う
- (b) S0 で G-2 を「省略」に改める。層の割り当てが誰にも無くなり、範囲内外の判定が成立しない(gate-criteria 457 行の循環が解けずに固定される)。「省略」は記録に何も残らない
- (c) 規則データの注記だけを直す。標準本文との食い違いが逆向きに残る。正本は標準側である

### 直す点(弁護しない)
1. **語の食い違い**: 規則データの注記は「要件合意は省略し、仕様承認に統合する」と書く。「省略」と「統合」は別の語で、読み手は G-2 の確認が消えたと読む。標準の用語は「統合」である。注記から「省略」を除く(`npm run template:kb` で複製する)
2. **循環**: G-4 基準5 は G-2 で割り当てた層を前提にする。統合の定義に「S0 では G-4 の判定記録が G-2 基準5 の層の割り当てを兼ねる」と書く。**割り当てる者と判定する者が同じになる**ことは、S0 の統合の帰結として明記し、隠さない
3. **証跡**: 定義の文は結果(G-2 の前提条件1と判定基準1〜5 が、G-4 の判定記録のどこかで確かめられていること)と、残る証跡(判定記録の欄)だけにする

### 弱点
定義だけでは、S0 で曖昧語・前提・やらないことの確認が行われたかを機械では検査できない。これは「自由な文の意味」であり、コアポリシーの統制の閉じ方どおり、manual と根拠水準マークで開示して閉じる。機械の検査を足す案は、S0 のために採用者の負担を増やすので採らない。

## 論点2 G-2 基準1 の数え上げの置き場

### 現行を弁護する点
- ADR-0051 決定2 は「確認方法への追加」とし、内容は判定せず対応の有無だけを見る。**新しい判定基準ではない**ことを、表の外の段落が表している。表の行へ移すと、判定基準が1行増えたと読まれうる(論点4 を呼ぶ)

### 弁護しきれない点
- 表の外の段落は、KB(integrated.yaml の criteria)に降りない。AI が KB を読む場面で、数え上げは読まれない。条文があり、実行層に届かない。実装マークか根拠水準マークでの開示が要る状態である(マークの有無は次の段で確かめる)
- 前例がある。G-4 基準6 は「機械が一覧を出す」行である。決定可能な条件(対応の有無)は表の行にできる

### 結論
移すなら「価値と受入基準の対応の一覧が判定記録にある」だけを行にする。「対応が妥当か」は行にしない(ADR-0051 決定2。自由な文の意味は機械で閉じない)。移さないなら、段落に実装マーク(undelivered)を付けて表示し続ける。どちらでも判定の意味は変わらず、判定の総数は増えない。位置の移動は軽で足りる。

反対する案: 妥当性まで行にする案。人の判断を表に入れ、合否が他の基準と相殺される(第4章冒頭の理由)。

## 論点3 G-4 基準5 の置き場

### 弁護しない点
第4章冒頭は「前提条件を判定基準に含めてはならない。前提条件は機械的に検査し、人の判断を介在させない」と書く。基準5 の「空欄の場合、判定を開始しない」は、判定基準の表の中の前提条件であり、**この定義と矛盾する**。条文の欠陥で、現行を弁護できない。

### 直し方(案A)
- 空欄の条件(判定欄が空でない)は、G-4 の前提条件の表へ移す。空欄は決定可能な条件(存在)であり、機械で検査できる
- 基準5 は、記入された範囲内外の判断が妥当かに絞る。人の判断なので判定基準に残す
- ADR-0075 決定4 と #291 X-8 の先例(未確定事項を前提条件の表へ移した)に沿う

### 反対する案
- (C) 基準5 を前提条件へ全部移す。範囲内外の妥当性は人の判断で、第4章冒頭が前提条件に人の判断を禁じる。範囲外の見落としは適合の主張の信頼に響く(方針の問い(3))。人の判断を判定から外せば、見落としを誰も判定しない
- (B) 基準5 を維持して第4章冒頭に例外を書く。定義に穴を開ける。論点7 の食い違いは、この定義が堅いから検出できた。弱めると同種の食い違いを次から検出できない

### 基準番号の扱い
番号を詰めると、宣言行の「基準 N」・KB・テンプレート・IMPL 注記が静かにずれて誤読になる。変更量の少なさは理由にしない。理由は、ずれが静かに起きることである。基準5 の番号は保ち、内容だけを絞り、`lint:refs` で参照の実在を確かめる。

## 論点4 「判定の総数」原則

### 現行を弁護する点(原則を立てない)
- ADR-0074 決定11 #2、ADR-0075、ADR-0094 は「ADR-0013 に無い」と3度記録した。**採用された原則は存在しない**。立てるなら新しい決定である
- ADR-0074 は検査の機構に上限を設けないと定めた。総数の原則は機構の増加を抑える向きで衝突する。衝突を解くために両方に但し書きを入れると、どちらの条項も読めなくなる
- 外部規格は、レビューの段階を複雑さに応じて計画させ、数の上限を置かない(survey-external 4節)。要請も先例もない
- 破られても、安全にも適合の主張にも響かない(intake 論点4)。方針の問い(3)に当たらない。**課さないと決めて理由を書く**のが最良である
- ADR-0013 決定2 の「導入を差し引きで提案する」は別の規定で、有効である。第4章 724 行と enablement.md 148 行の文は、この差し引きの検査として読める。原則と取り違えない

### 反対する案
- (A) 原則として立てる。ADR の原則の変更であり、重である。かつ過去6件の ADR が引いた「原則」を後から正当化することになる。**誤引用を遡って規則にする**のは、誤りを制度に変える
- (C) 「差し引きで示す」へ言い換える。決定2 と同じ内容で、新しい文を足すだけになる。決定2 を参照すれば足りる

### 直し方
採用済み ADR の本文は書き換えない(プロジェクトの規則)。新 ADR に「判定の総数を増やさない原則は採用していない。ADR-0016・0019・0021・0024・0041・0051 の引用は、ADR-0013 決定2 の差し引きと読む。採らない理由は ADR-0074 との衝突と外部の先例の不在」と書く。標準の本文(724 行・enablement.md 148 行)の「判定の総数」の語は、決定2 の差し引きの言い方へ揃える(編集)。

## 論点6 安全重要度の判定基準・7.4 の禁止を 7.3 の対象外とするか

最も強く論じる論点である。損失は安全に響く(方針の問い(3)の対象)。

### 先に、現行が既に何を決めているかを確かめる
1. 7.3 の対象は「ゲートの判定基準」と、条項が 7.3 を名指した事項に限る。**安全重要度を決める行為**(D-0 表10 の判定と判定者の記名)は G-1 の前提条件2 である。前提条件は判定基準でないので、7.3 の対象外と読める。つまり**判定そのものを免除する経路は、現行で既に無いと読める**(62304 の割り当て必須、14971 の基準設定権の上位、DO-178C の決定権の外部と一致する)
2. 7.3 は「条項が例外を認めないと定めた基準には、本節を用いない」と書く。7.4 は G-4・G-5・認証・認可・データ保全の検証の後回しを「禁止」と書く。この禁止は、条項が例外を認めない基準に当たると読める
3. 7.4 は 7.3 の「特殊形」で、5要求事項に制約が加わる。「一般の 7.3 は特殊形より緩い」という読みを許すと、**7.4 が禁じたものを 7.3 の一般形が通す**。これが欠けの本体である

### 弁護しない点(読み手が誤りうる箇所)
上の1〜3 は、一貫して読めば結論が出るが、条文は一箇所に書いていない。EV-0271 が「定めていない」と自ら書くのは、この意味で正しい。読み手は「7.4 は期日制約下の手続で、期日が無ければ G-5 を 7.3 で外せる」と誤読しうる。IMPL-0567 は「G-4・G-5・認証・認可・データ保全を対象にする行を例外として受け付けない」を意図として持つが、本文に明記が無く、undelivered である。**意図と本文が食い違う**。直す。

### 案ごとの評価
| 案 | 評価 |
| --- | --- |
| A 現状維持(EV-0271 の観測待ち) | 安全で観測を待つだけでは弱い。**ただし、既存の読みの明文化を添える形を弁護する** |
| B 安全重要度が掛かる基準だけ対象外 | 反対。下の1〜3 |
| C 対象外にせず承認者を上位に限る | 反対。下の4 |

### B・C への反対
1. **「掛かる基準」の範囲が決まらない**。安全重要度は案件ごと(CL)、リスク区分は変更ごと(R)である(ADR-0039)。どの判定基準が安全重要度に「掛かる」かは、CL ごとの適用表を引かなければ決まらない。定義を誤ると、適用外の基準を混ぜるか、掛かる基準を落とす。後者は安全に響く
2. **規格より厳しくなる**。外部の調査は、26262 と 61508 が活動の逸脱を根拠つきで認めることを示した(Q2)。判定そのものを外せないことは規格と一致するが、活動の逸脱まで一律不可にする先例は確認されていない。先例の無い義務を安全の名で課すのは、実証を欠く義務である
3. 規格が認める逸脱の道を塞ぐと、逸脱が必要な採用者は記録に残さない離脱に向かう。ADR-0036 と G-7 が「正規の経路を置かないと記録を偽る動機が生じる」と書いた理由が、そのまま当たる。安全の検証を外す者が記録を持たない状態は、記録を持つ例外承認よりも悪い
4. (C について)「上位」の定義が無い。61508 の3段(人・部門・組織)に倣うと、小さな採用者は上位を持てず、安全重要度が掛かる案件を進められない。承認者の独立は G-7 で既に立つ。例外承認だけに追加の独立を課すと、例外承認が通常の経路より重くなり、誘因が逆に働く。この論は変更量でなく誘因による

### 推す形(A に既存の読みの明文化を添える)
新しい義務を課さず、既存の読みを一箇所に書く。7.3 の対象の限定の項目へ次の3点。

1. 安全重要度の判定の記録(G-1 前提条件2)は、判定基準でないので 7.3 の対象外である(現行の読みの明文)
2. 7.4 が「禁止」とした対象(G-4・G-5・認証・認可・データ保全の検証)は、「条項が例外を認めないと定めた基準」に当たり、7.3 の一般形でも外せない
3. 安全重要度 CL1 以上の安全適合性の検証に例外承認を用いる場合の扱いは、EV-0271 のとおり観測後に審議する。観測前に義務を新設しないと決めた旨を書く

3 を「課さないと決めた」として理由とともに書き、「書かれていない」と「課さないと決めた」を読み手が区別できる状態にする(コアポリシー)。なお、2 は 7.3 の既存の文言(条項が例外を認めないと定めた基準)の適用を明示するだけで、新しい義務ではない、と議長が裁定できる。裁定できなければ、2 も観測後に回す。

### 方針の問い(2)への答え
新しい条項を足さずに、第7章の例外承認で受けられるか。**受けられる**。CL1 以上の安全適合性の検証は、例外承認の記録の理由欄に書かせ、G-8 のリスク受容の対象(未回収の例外を含む)で開示される。新しい欄は要らない。ただし理由欄に書くことを要求するかは、新しい義務に当たりうるので、手引き(gate スキル)の促しに留め、条文の義務にしない。

### 方針の問い(3)への答え
破られたとき失うのは、エンドユーザーと、適合を信頼した取得者である。取り消せない損害が出うる。だから「細かく書く」対象であり、推す形の1・2 は明文にする。B・C が追加で防ぐのは「7.4 の禁止の外にある CL1 以上の検証」だけで、その範囲と頻度は未観測(EV-0271)である。

### 弱点
- 26262 の確認措置の独立性が ASIL で上がる(二次情報)のに対し、7.3 の承認者の記名は CL の高さに応じて重くならない。規格の型との差で、弁護できない。EV-0271 の見直し(2027-05)に載せる。観測前の対象外の新設には反対するが、「CL に応じて承認を重くする」型(C の変形)は、観測後の審議の主題として残す
- 26262 の 6.4.5、61508 のテーラリング、62304 の 4.3 の原文は未確認(survey-external 5節)。**規格の引用を要する案(B・C)は、原文の確認が済むまで採れない**。この点だけで B・C は現時点で採決に耐えない

### 採らない案の記録
- B(安全重要度が掛かる基準だけ対象外): 範囲が決まらず、規格より厳しく、記録に残さない離脱を生む
- C(承認者を上位に限る): 上位の定義が無く、例外承認が通常の経路より重くなる誘因の逆転を生む

## 論点7 前提条件の混在(2.8 と G-1 の表)

- 直し方: G-1 の前提条件の表に行3を足す。新しい前提条件の新設ではなく、2.8 に既に書かれた条件を表へ揃える編集である。確認方法は記録の存在(安全リスクアセスメントの SR4 の残存の欄)に限り、決定可能な条件にする
- 反対する案: 2.8 の文を消して SR4 を審議の判定基準へ移す。第4章冒頭が禁じる混在を作り、SR4 の残存が他の基準と相殺されて通過しうる。安全を相殺に晒す
- IMPL-0849 は undelivered のまま表示し続ける。表に行が出れば、降ろし先(check-g1)が見るべき対象が明確になる
