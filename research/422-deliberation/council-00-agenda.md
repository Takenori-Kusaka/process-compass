# 会議体の議題(#422 人の承認とマージを、PR の本質的なレビューの論点と長期的な決定に絞り、残りを AI レビューで補う運用)

入力: Issue #422(所有者の提起)、`survey-422-1-internal.md`(内部)、`survey-422-2-external.md`(外部)。

## 前提として確かめた事実(要旨)

- **所有者の前提「Anthropic で行われている」は、一次資料で半分だけ確かめられた**。確かめられたこと: (a) 社内のほぼ全 PR に Code Review(AI)を掛けている、(b) Code Review は承認も阻止もしない(承認は人の判断)、(c) コードベースをリスクで層別し、規制対象・重要なコードだけに人の厳格な承認を残し、低リスク層は自動承認として人はリスク加重の標本を検査する(Deputy CISO の記事、2026-07-21)。確かめられなかったこと: 「人のレビューを本質的な論点と長期的な決定へ絞る」。逆に「アーキテクチャの詳細レビューは以前ほど重要なゲートではない」と書いている。絞る軸は「論点」ではなく「リスクの層」である可能性が高い
- **人の確認の範囲を絞ること自体は、本標準の既定と衝突しない**。G-6 の承認は全行を読んだことを意味しない(附属書H H.5、附属書C)。L1 の観点の絞り込みと規模の確認の「保証の所在」(第4章)、レビューパッケージ(ADR-0023)、/human-verify の「疑義が生じた箇所に限定して読む」が既にある。いずれも絞る根拠を機械的な導出か実行可能な保証に置いている
- **「残りを AI レビューで補う」と正面から衝突する規定**: H.4 条件4「通過を理由に人の確認を減らさない」、第4章の緩和根拠の表で AI の差分要約と自動レビューコメントが「認めない」、3.10.12「要約だけで判定しない」、第4章「判定の時点を移す別の経路を新設しない」
- **作成側や AI が論点を書くと、入力の分離(3.5.3)と ADR-0023 決定2・3・8 に掛かる**(注意を狭める情報で、作成側の主張)。「ここ以外は見なくてよい」と読めれば結論に当たる
- 長期的な決定には判断記録と G-3 がある(2.6)。PR に埋もれた設計上の選択を検出する手段は、PR テンプレートの自己チェックしか無い。外部の実例: Kubernetes の API レビューは、パス・型から機械的に検出し、専任の承認者の別経路で承認する
- 過去の Issue #162・#172 で、AI の事前審査を合否条件にする案、3 行要約の自動提示、G-6 の濃淡・抜き取り・パススルー基準を却下済み。#271 で承認ごとの署名様式を却下。#422 の動機は帯域ではなく形骸化である
- 穴: PR テンプレートの「レビュー観点の指定(任意)」に書き手・読む時点・結論を含めない旨が無い。check-pr はこの欄を読まない。G-6 に「確認していない事項」の記録が無い。論点の外で見つかった欠陥を測る量が無い。IMPL-0220・0253・0155・0168 が未達。`/review` 系のスキルは無い
- 外部の実証: Tufano ほか(2024、29 名の対照実験)。AI のレビューを起点にすると人は AI が示した場所に注意を寄せ、高重大度の指摘は増えなかった。人のレビューの価値の多くは保守性と理解の共有(Mäntylä & Lassenius 75%、Bacchelli & Bird 2013)で、AI レビューの既定の観点(正しさ)と重なりが小さい。AI レビューの検出性能は F1 約 50%(ベンダ関与の測定のみ)。Meta RADAR は低リスクの差分の自動承認で revert 率・障害率が下がったと報告(選択バイアス・単一組織・観察研究)

## R-1 人の確認の範囲を絞るか、何で絞るか

- 問い: 人の承認(G-6)の範囲を、PR ごとの論点に絞る運用を本標準に入れるか。入れるなら、論点の生成元(機械の導出 / 作成者 / AI)、入力の分離との関係。リスクの層で絞る(Anthropic の確かめられた運用)案との比較。附属書C のパス1 を論点の外にも必ず掛けるか

## R-2 長期的な決定の切り出し

- 問い: アーキテクチャ・公開インタフェース・データ形式・依存の追加などの長期的な決定を、PR から機械的に検出し、判断記録と人の承認の別経路に乗せるか(G-3 との関係)

## R-3 AI レビューの位置づけ

- 問い: 論点の外を AI レビューで「補う」ことを、検出の層(H.4)の外に数える余地があるか。AI レビューを承認とみなさないことの再確認。AI レビューの指示を PR 自身の変更から読まない(IMPL-0333 の系)

## R-4 記録・計測・テンプレート

- 問い: G-6 の判定記録に「確認した範囲 / 確認していない範囲」を書かせるか。論点の外で見つかった欠陥を計測するか。PR テンプレートの「レビュー観点の指定」を必須にするか、書き手と結論を含めない旨。準拠テンプレートへの降ろし方

## R-5 記録

- 問い: 新しい ADR を起こすか。#162・#172・#271 の却下・ADR-0023・ADR-0059・H.4 との関係。採らない案(リスク層別の自動承認、AI の検出率を前提にした配分など)の明記
