# IMPL-0506 の確認の条件についての議長の裁定

日付: 2026-11-18

## 事実

隔離のもとの自身の手順で、`aggregate-evidence.mjs` は終了コード 1 を返した。手順の条件の文言は「3 つとも 0」であり、**文言のままでは満たしていない**。隔離なしの対照の実行も同じ終了コードで、出力の差分は 0 行だった。失敗の原因は、確認に使った使い捨てのリポジトリの記録の欠落 17 件である。

## 裁定

条件の目的は「隔離が手順を妨げないこと」である。終了コード 0 は、記録のそろった案件を前提にした代理の指標だった。そこで、この項目の条件を「隔離のもとの終了コードと出力が、隔離なしの対照と一致する」へ改め、IMPL-0506 を delivered へ移す。

## 開示

- 条件は結果を見た後に改めた。元の文言と、改めた理由を、この記録と IMPL-0506 の note に残す
- 記録のそろった案件で集約が終了コード 0 になることは、隔離のもとでは確かめていない
- 独立の突合で、この裁定を確かめる対象に含める

## 採らない案

- undelivered のまま残す案: 隔離による拒否が無いことを対照で確かめており、未達の理由が隔離の性質と無関係である
- 元の文言を満たしたと書く案: 事実に反する

# T2 の再確認の不一致についての議長の裁定

日付: 2026-11-18

## 事実

直しの後の再確認(F2V)で、隔離のもとのコミットのトレーラが `assets=dirty` になり、隔離の外の `assets <id>` の `clean` と一致しなかった。隔離のもとの Claude Code が実行の間だけ `.claude/` 配下に空の足場を作り、`assetsUncommitted` がこれを数えるためである。

## 裁定

欠陥として直す。隔離を既定で置く基盤で `clean` が出ないと、トレーラの `assets=` は常に `dirty` になり、指示資産の変更を見分ける役に立たない。

- 実物の足場を `raw/v2/` と実行で確かめ、**追跡されていない、内容の無い足場だけ**を数えない。追跡中のファイルの変更と、内容のある未追跡のファイルは、これまでどおり `dirty` に数える
- 足場の判定は決定可能な条件(未追跡かつ大きさ 0、または空のディレクトリ)に限る
- 直した後に WSL2 で T2 をやり直す。一致するまで IMPL-0207・1019 の確認は済んだと扱わない

## 採らない案

- `dirty` のまま開示する案: 隔離を使う基盤で記録が区別の役に立たず、delivered の表示と実態が食い違う
- `.claude/` 全体を数えない案: 指示資産の変更を見逃す

## 追記(2026-11-18。束 B20 の独立の突合 2巡目 R2 の裁定)

- 上の「未追跡かつ大きさ 0、または空のディレクトリ」は、実装の形「未追跡で、大きさ 0 の通常ファイルか文字特殊ファイル」と読む
- git は空のディレクトリを数えない(`git status` に現れない)。ディレクトリを足場の条件に入れる必要はなく、実装の形を正とする
- 文字特殊ファイルの分岐は Windows では再現できない。確かめたのは WSL2 の実行の記録(`444-verification/raw/`)までである
