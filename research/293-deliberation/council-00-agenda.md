# 会議体の議題(Issue #293 リポジトリ運営 — CI・配布)

2026-10-23。議長は主担当。委員は 5 つの立場(起草・現場・品質保証と監査・規格・擁護)で、1 つの組として全論点を扱う。

入力: `issues-context.md`、調査 2 本(`survey-293-1-internal.md` 本リポジトリと標準の現状、`survey-293-2-external.md` 外部の実務)。

作業ツリーは #289〜#292(ADR-0071〜0076)の反映を含む。#292 で `ci.yml` は `npm run check` を走らせる形になった。その決定と矛盾する案を採るなら、その旨と材料を示す。

本 Issue は、本リポジトリの運営(実行層)と、標準の条項(#277・#280・#281 が提案する文)が混ざっている。**本リポジトリの運営の変更と、標準の条項の変更を分けて判定する**。後者はコアポリシーの対象。

## 判定の語

- **採る** — 調査の選択肢の 1 つ、または委員の案を採る。置き場所と文の案を示す
- **課さないと明記する** — 規定を置かないと決め、その旨を本文へ書く
- **先送り** — 材料が足りない。何が足りないかを書く(変更量を理由にしない)

どの論点でも、選ばなかった案を落とす理由を 1 案ずつ書く。安さ・変更量の少なさを採否の理由にしない。判断軸は信頼性。実証を欠く判断は根拠水準(E0〜E3)と見直しの条件を書く。

## 既に決まっていること(蒸し返さない。覆すなら材料を示す)

- 配布物そのものを検査する(ADR-0052 決定1)。生成元の版を記録する(決定2)
- G-5 の「対象なし」は記録して通す。実装が存在すれば使えない(ADR-0033)
- 検査装置を足すときは G-5 の 3 条件の型で判断する。総量に上限は置かない(ADR-0074)
- `ci.yml` は `npm run check` を走らせる(#292、ADR-0076 の前提)
- G-8 は GitHub Environments の承認で実装する(`ci-gates.md` デプロイゲート)
