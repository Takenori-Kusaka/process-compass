## 2. 論点

- a. 「どの種別を止めるか」への答え: **コア機能に関わる登録した変更種別**。本文 F5・ADR-0158 決定7 に既にある。K-4 の「第8章か 3.4.3 に帰結を書き足すか」は F5 で済んでいる(コメントを書いた時点で既に入っていた)
- b. 欠けているもの1(定義): 「関わる」の意味と、対応の記録が無いときの扱いが本文に無い。template は「コードに触れうる種別。空欄はすべて」と決めている(T2)。本文と template のどちらが正かを本文が言わない状態で、template を使わない採用者は F1(機能の単位)を種別へ落とす手掛かりを持たない
- c. 欠けているもの2(実行の試験): T8 が降りていない。1.3 で成り立つことは確かめたが、回帰で固定していない。登録外の ID を書いた行は何も止めない(場面 F)。これを止めるかは決定可能な条件(ID が登録の一覧に有るか)である
- d. 1名の体制の帰結: 保持者は常に1名以下(F7)なので、切替で使えるのは、すべてのコア機能の行で「なし」とされた種別だけ。7条件の5(F8)で個々の変更はもともとコア機能に触れないため、関わらない種別の定義(規則の範囲にコア機能のコードが入らない)は条件5 と同じ向きで、矛盾しない

## 3. 案と競わせ

### 案1(推す): 本文に「関わる」の定義と扱いを足し、template に2種別の試験を足す

本文の直す文の案(`human-ai-boundary.md`、`:302` の段落「停止は、委任を判定するたびに…」の後、`:304`「検知の入力となる記録の変更を…」の前に1段落):

> コア機能の理解保持者数による停止が止めるのは、そのコア機能に関わる登録した変更種別です。関わる種別は、該当を判定する機械の規則(5.5.7)の範囲に、その機能のコードが入りうる種別です。関わらないことを記録で示していない種別は、関わるものとして扱います。表の「該当機能を L1 へ引き下げる」は、登録した変更種別ではこの停止として現れます。関わらない種別の個々の変更も、5.5.4 の条件5 によりコア指定の機能に触れません。

第8章 `tailoring-guide.md:343` の末尾の文は直さない。括弧の参照だけを「(第5章 5.4.6 の停止の表の、コア機能の理解保持者数が1名以下の行と、関わる種別の定め)」へ改める(編集)。

template(実装の段):
- test-check-delegation.mjs に T8 の対を足す: 種別2つ、保持者1名、関わる種別=種別1 → 種別1 が保持者で止まり、種別2 は保持者で止まらない。空欄 → 両方止まる。「なし」 → 両方止まらない(第2区分の窓は両方に与える)
- 関わる種別の列に登録外の ID がある行を、委任の判定の出力で表示する(場面 F)。止めるか表示に留めるかは実装の段で決めず、裁定で「表示する。止めない」を推す(止めると書き誤り1つで全種別が止まり、誤りの所在が見えにくくなる。表示なら決定可能な条件のまま、誤りが人に見える)。※この点は議長の判断に委ねる
- 実装マーク: 足した段落に新しい IMPL(番号は指揮役が割り当てる)。target=autonomy-derivation、state=delivered、check=machine、test=template/scripts/gate/test-check-delegation.mjs。note に「関わる種別は運用引き継ぎ文書の節2 の列。空欄と列の無い旧い様式はすべてに関わる。なしは関わらない。登録外の ID は表示する」。IMPL-0284 は書き換えない

所有者の3問:
1. 結果と証跡: 結果は「保持者1名以下の機能に関わる種別が止まる」、証跡は「関わらないことの記録」(置き場は採用者。template では節2 の列)。手段は書かない
2. 第7章の例外承認で受けられないか: 受けない。停止は 5.4.6 の自動の措置で「実行を見送る裁量を持たない」(`human-ai-boundary.md:190`)。例外承認で停止を外す経路を作ると ADR-0081 決定3 に反する。本案は経路を作らず、既に止まるものの範囲を定義するだけ
3. 誰が何を失うか: 定義が無いと、関わる種別を狭く読んだ採用者が、保持者1名の機能に触れうる種別を L3 で回し続ける。失うのは、コア機能の理解が1名に依存する状態での事後監査の信頼(安全ではない。CL0・R3 に限るため。取り消しは条件4 で担保)。1名の体制はもともと適合を主張しない(`roles-responsibilities.md:296`)ため、適合の主張の信頼には2名以上の体制で効く

### 案2: 本文は直さず、試験だけを足して閉じる

- 根拠: F5・ADR-0158 決定7 で問いへの答えはある。template の定義(T2)で実行も揃う
- 採らない理由: 「関わる」の定義と空欄の扱いが template にしか無く、正本(本文)が template に従う形になる(CLAUDE.md「正本はこちら側」、ADR-0040 の部分集合の関係と逆)。template を使わない採用者が F1 の「該当機能」を種別へ落とせない。信頼性の観点で、定義の欠けを残したまま閉じる理由が無い

### 案3: 1名の体制では登録した種別をすべて止める(第8章の切替を1名の体制で使えなくする)

- 根拠: 1名の体制は保持者が常に1名以下で、適合も主張しない。区別を持つ意味が薄い
- 採らない理由: ADR-0158 決定7・ADR-0081 決定6 が「関わる種別が止まる」と決めており、原則の変更になる(重)。止める理由がコア機能の理解の欠けであるのに、関わらない種別まで止める根拠が無い。関わらない種別の変更はコア機能に触れない(条件5)。新しい制約を課すことにもなる

### 案4: 関わる種別の対応表を、採用者が必ず作る記録(必須欄)として本文に課す

- 根拠: 対応が明示されれば、F の書き誤りも減る
- 採らない理由: 新しい義務に当たる。案1 の「示していない種別は関わるものとして扱う」で、記録を作らない採用者は全種別が止まる側へ倒れ、結果は同じになる。義務を課さずに同じ結果が得られる

## 4. 推す案の性質

- 推す案: **案1**
- 採用者への新しい義務: **当たらないと読む**。理由: (i) 止まる範囲は既に F2・F3・F5 で決まっており、案1 は「関わる」を定義するだけ (ii) 記録を作らない採用者は全種別が止まる側へ倒れ、何かを書く義務は生じない (iii) 「計測できない種別は登録しない」(5.4.5 後段、ADR-0081 決定5)と同じ向きの扱い。ただし「関わらないことを記録で示していない種別は関わるものとして扱う」は、現行の本文の読みの幅(F1 を狭く読む採用者)を狭める。これを新しい義務とみる立場はありうるため、反対の委員と独立の突合で確かめる点として残す
- ADR の原則の変更: 当たらない(ADR-0081 決定4・6、ADR-0158 決定7 の範囲内)。新しい ADR は要らないと読む。採用済みの ADR の本文は書き換えない
- 安全: 当たらない(止める向きの定義。CL0・R3 に限る)
- 規格の引用: 要らない。外部の調査は行っていない
- 機械の検査にするもの: 「保持者数 ≤1 かつ 種別の ID が列に含まれる、または列が空欄」(決定可能)。「コードに触れうるか」の意味の正しさは機械で閉じない。manual とし、関わる種別の列の記入は採用者が確かめる(note に開示)
