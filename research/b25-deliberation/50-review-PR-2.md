## 新しい所見

### 高-N1 PR の記録ファイルを読めないとき、「記録を含まない PR」と表示し、注記も出さずに通す(直しが要る)

- 所在: template `scripts/gate/pre-review.mjs` の `fetchPrRecordFiles`(読めないファイルを `out` から落とす。891 行の注記は「確かめていないに回る」)と、差分で足した `respondedCheck` の `!records.length` の文言「確かめていない(記録を含まない PR)」、`respondedMain` の `records.length` の条件(記録を含まない PR は注記と要約を出さない)
- 事実(写しで実行。gh を差し替え、PR の files は docs/gates の記録を返し、contents の取得だけを 500 で失敗させた):
  - 記録1件だけで、それを読めない → `fetchPrRecordFiles` は `[]` → `respondedCheck` は `unverified`、行は「確かめていない(記録を含まない PR): 判定の記録(docs/gates/*.md)を含まない PR のため、この検査の対象ではない」。`records.length === 0` なので `::warning::` も要約も出ず、チェックは緑。PR は記録を含んでいる
  - 記録2件のうち1件を読めない → 読めた1件だけで照らし `pass`。読めなかった記録はどこにも出ない
- 表示と実態の食い違い: 本体の IMPL-0214 の note(本巡で改めた文)は「確かめていないが混ざる PR は総合を合格にせず…注記とジョブの要約に出す」と書くが、読めない記録は混ざっても合格になる。README の「確かめていないものが混ざる PR は、総合を合格にせず」、workflow の注釈も同じ。`fetchPrRecordFiles` の振る舞い自体は直しの前からあるが、直しが足した「記録を含まない PR」の文言と注記の抑止が、読めない記録を「対象ではない」と表示する。検査が黙って通す、に当たる
- 直す案: `fetchPrRecordFiles` は読めないファイルを `{ path, text: null }` で返す。`respondedCheck` は `text === null` を `unverified`(「記録 <path> を読めない。確かめていない」)として `seen` に足す。`!records.length` の分岐は「files の一覧に記録が無い」場合だけにする(`respondedMain` の注記の条件も、一覧上の記録の有無で決める)。試験に ng を2件足す(読めない記録だけ → 「記録を含まない」と出さず注記の対象。読めない記録+揃った記録 → `pass` にしない)

### 低-N1 `::warning::` の行の選び方が、合格の行も拾う(開示で閉じてよい)

- 所在: `respondedMain` の `/確かめていない|結べない|導出できない/` の絞り込み
- 事実(写しで実行): 混在の PR で、合格の行「宣言行が揃った(…)。応答の中身は確かめていない」も注記に入る。合格の行の文は事実で、注記の見出しが「確かめていない:」のため、合格した記録まで確かめていないように読める
- 閉じ方: 合格の行の「応答の中身は確かめていない」を絞り込みから外す(`seen` の種別で選ぶ)か、そのままにして要約の全行で読む。直さないなら記録だけでよい

### 低-N2 総合の判定の文が、増えた「確かめていない」の理由を含まない(開示で閉じてよい)

- 所在: `VERDICTS.unverified`「確かめていない(上程と結べない、または読めない。失敗にはしない)」
- 事実: R1 の必須応答の者を導出できない場合と、記録を含まない PR も同じ文になる。個別の行に理由が出るため、誤りではない
- 閉じ方: 「(個別の行を見よ)」程度の文へ改めるか、受け入れる

### 低-N3 R1 で CODEOWNERS が無いリポジトリは、判定資料が PR の R1 の上程が常に「確かめていない」になることを README が名指さない(開示で閉じてよい)

- 閉じ方: README の当該の文に「判定資料が PR のとき。CODEOWNERS を置いていないリポジトリでは常にこの扱いになる」を足す

### 低-N4 外した理由の「判定の記録に結べない」に、様式の欄に不備のある上程が入る(開示で閉じてよい)

- 閉じ方: `noRecord` を「欄に不備(リスク区分を含む)」と分けるのが本筋。直さないなら note か出力の注記へ「欄に不備のある上程を含む」と書く

### 低-N5 paths を外したことで、無関係の PR でも上程の読み取りの失敗が失敗のチェックになる(開示で閉じてよい)
