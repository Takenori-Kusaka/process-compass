## 1. 書く型と置き場所(M-1・M-2)

- 全委員が C(本文で関係を主張しないと明記する)を採った。理由: 併用を観測した記録が本標準に無い(E0)。外部の規格の多数派は方法中立(規格の確認: ISO/IEC/IEEE 12207:2026 は 2017 年版の附属書H「Application of Agile」を廃し、適用範囲の 1 文「アジャイルに適用できる。特定のモデル・方法論を求めない」へ寄せた。15288:2023・26515 も本文で手法名を出さない)。併用の有効性を実証した規格は無い
- 書く型の争点は、C に何を添えるか
  - 対応表(A の原形): 採らない。本標準の H.10 の先例「対応表は確かめていない範囲まで覆って見せる」が当たる。本プロジェクト自身の対応づけ(#267 の回答)が誤った。手法名では agile と traditional を分けられない(TSE 2021、二次)
  - 本文の併用の条件(B): 採らない。条件を書くと「満たせば併用が成り立つ」と読まれ、ADR-0068 の区別(適用の表明と適合の主張)に当たる。条件の中身(判定の成立・判定会議を開かない・3.7.5)は既存の規定にあり、2 か所で定めることになる(起草・擁護)
  - 何も添えない C だけ(擁護): 採らない。#298 の契機は「派生物は正本に無いことを書けない」。読者の既知(スクラム)に接続する説明が正本に無ければ、派生物は書けないままになる(現場)。説明は規範ではないので、ADR-0068 に当たらない
  - D(派生物へ委ねる)だけ: #298 の契機と矛盾する
- **裁定**: C(本文)+ 附属書A A.7 の説明。A.7 は規定の対象ごとに「本標準が定めるもの / 定めないもの」の 2 列で書き(規格)、手法の固有名の列を持たない
- 置き場所: 第1章 1.2 の表の後の段落(規格・現場・品質保証・擁護)。方法中立は適用範囲の事項で、12207:2026 も Scope に置く。新節 1.11(起草)は採らない: 関係の記述は適用範囲の帰結で、独立の節にすると主張の節に読まれる。1.9(主語が組織)・1.3(前提文書に数えることになる)には置かない
- 文の案(1.2 の表の後): 「本標準は、開発の方式・手法の名によって適用の対象を限定しません。本標準は、既存の開発手法との併用の可否・有効性・要素の対応・置き換えを主張しません。本標準が定めない事項(反復の周期、チームの会合、作業の一覧の運用、ステージより短い計画の方法)は、採用組織が定めます。他の手法を用いていること、またはその名と組み合わせて名乗ることを、適用の開始・適用の表明・適合の主張に数えません(1.10)」
- 1.5 の内容欄と附属書A の description の「既存プロセスとの対応」は、附属書A の中身(出自の表)と食い違い、#267 の誤りを生んだ(擁護)。「既存プロセスからの由来と既存の開発手法との関係」へ改める
- 2.2: 内側のループが手法を置き換えるのか上に載るのかを書いていない。「AI協調ループは、反復の周期・チームの会合・作業の一覧の運用を規定しません」の 1 文を足す(擁護は不要とした。列の見出しで読めるとする。だが附属書A A.1 の Water-Scrum-Fall の類比を通すと置き換えとも読めるので、1 文で閉じる)

## 2. A.7 に書くこと(M-3・M-4)

- 規範は置かない。説明の文で書く
- 既存の規定から導ける読み(所在を引く):
  1. 工程ゲートの判定は、チームの会合で代わらない(第4章 共通ルール1・「判定の成立」、3.7.5)
  2. チームが自ら開く会合は会議体(B-1〜B-4)に当たらない(1.4。M-6 で明記する)
  3. 停止の申し立ては、反復の中止とは対象が違う(停止の申し立ては変更・出荷を止める)
  4. 完成の定義の自己確認は、G-6・G-7 を兼ねない
  5. 本標準は周期・会合・作業の一覧・ステージより短い計画の方法を定めない
- スクラムガイド 2020 年 11 月版(取得 2026-10-23)の逐語で確かめた接点(規格・品質保証):
  - ガイドは組織標準の完成の定義を最低限として受け入れる。本標準のゲートの判定基準を組織の完成の定義へ入れる読みは、ガイドの文言と矛盾しない
  - ガイドはスプリントレビューをリリースの関門としない。G-7・G-8 をスプリントレビューに重ねる読みは採れない
  - 本標準は、併用した開発がスクラムであるかを判定しない
- これらに EV(E1、見直し 2027-10、差し替え条件: ガイドの改訂、併用した採用者の記録)を付ける
- H.10 の型で「対応の正しさと優劣を示さない。相手の改訂に追随する義務を負わない(見直しは EV の見直し日で行う)」と書く
- SAFe・Shape Up・カンバン・Disciplined Agile・XP の名を出さないと明記する。理由: 商標の手法・改訂の速い手法を名指しすると、追随の義務を負い、相手の公式見解と誤認される。逐語で確かめた接点を持たない
- ADR-0017(参照モデルを既存手法と同じ表に載せない)とは矛盾しない。手法を行に並べないため。置き換えの ADR は要らない

- A.3「実証済みの部品」: 「実証済みの」を削り、EV(E0)
- 2.10.1 の DSDM MoSCoW の `:::note` を EV マークの書式へ移す(E1)
- 2.6 の想定する反復周期に EV(E0)(擁護は別 Issue とした。実証を欠く値の開示は ADR-0026 の義務で、先送りの材料が無い)
- `integrated.yaml` の `origin` の「スクラムの反復」: 変えない(起草・品質保証・擁護)。由来の事実で、関係の主張ではない。規格・現場の「反復・漸進型の開発」への改めは、由来の正確さを下げる

## 4. 2.10 の文と会議体の定義(M-6)

- 1.4 は「会議体」を B-1〜B-4 と定義している(起草・規格・擁護)。閉じた列挙か例示かが文面から決まらない(現場・品質保証)。閉じると、テーラリングで会議体を設ける場合に誤りになる(現場の問い)
- **裁定**: 1.4 の定義に「本標準が定める会議体(B-1〜B-4)と、第8章の調整で設けたもの」と書き、「チームが自ら開く会合は会議体に当たらず、工程ゲートの判定の場でもない」を足す。これで 3.7.1・3.7.5・2.10 冒頭・2.10.5 の「会議体」はスクラムのイベントを禁じる読みにならない
- 2.10.3「スコープを定めるための場を別に設けません」: 「場」は定義語でない。「本標準は、事業ステージのスコープを定めるための場を、SG の判定と別に設けません」へ
- 2.10.4: 規範(通知を非同期で行う)は保ち、「通知を、定例の開催まで待たせてはなりません」へ。定例そのものを禁じる読みを外す
- 2.10.2 の禁止(精度を装った見積り手法)は適用範囲を見出しへ併記する(起草。ステージ単位の規模の合意に掛かる)。「精度を装った」の曖昧さは別 Issue
- ADR-0019 決定5・6 は、本標準が場を新設しないという設計で、採用組織の定例を禁じていない。誤りは本文の文の形。置き換えの ADR は要らない
- `phase6-operation/improvement-cycle.md` L45・L47 の「スプリントごとに回します」は、本標準が定義しない単位を要求に使っている(品質保証)。M-1 の方法中立と食い違う。「採用組織が定めた周期で回します」へ改める。L58 のスクラムガイドの引用は由来の引用として書き分ける

## 5. 名乗りと範囲の外(M-7・M-8)

### M-7

- 併用の表明は適用の表明でも適合の主張でもない(ADR-0068)。名称は内容を保証しない(ADR-0027)。手法名と組み合わせた名乗りは権威の借用に当たる(ADR-0027 が「AI共創共通フレーム」を退けたのと同じ型)
- 附属書H H.8 に行を足す(品質保証・規格・起草。現場・擁護は 1.10.2 で足りるとした)。足す理由: 派生物の書き手が最初に引くのは H.8 の表で、1.10.2 から導く読みは書き手に委ねると割れる
  - 使ってはならない表現: 「[手法名]と併用できる」「[手法名]互換」「[手法名]準拠のピットイン方式」「[手法名]にゲートを加えているので適合」
  - 使ってよい表現: 「本標準を適用している。チームの進め方には[手法名]を用いている」(2 つを別の文で書く条件つき)
- 本文と規定の附属書には手法の固有名を出さない。附属書A(参考)だけがスクラムガイドを版と年を添えて引く
- ADR-0080 に、C の決定、却下した案(対応表・本文の併用の条件・派生物への委任だけ・スクラム以外の手法名)、#267 の対応づけを本文へ降ろさないこと、会議体の定義を明確にしたことを記録する
