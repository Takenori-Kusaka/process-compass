### 1.5 結論(言及の全数から)

- 本標準が既存の反復手法について主張しているのは**由来**(附属書A A.1・A.3、参照モデルの `origin`)だけ。いずれも参考の位置で、EV マークが無い
- **関係**(併用できる・置き換える・包含する・競合する)の主張は、本文・附属書・参照モデルのどこにも無い。「主張しない」との表明も無い。**「書かれていない」状態**であり、「課さないと決めた」状態ではない
- 対応づけ(Scrum Master・DoD・Product Backlog と本標準の機構)は #267 の Issue コメントにだけある(`research/phase4-standard/issue-triage-2026-10-08.md` L514)。そのコメントは「附属書A で Scrum の構成要素として対応づける語」と書くが、附属書A A.3 が対応づけているのは「機能単位の反復・検査と適応」の1行だけで、SM・DoD・Backlog の語は附属書A に無い。**コメントの記述は附属書A の現状と一致しない**。同じ文面が Issue #267 のコメント(2026-10-08 投稿、issuecomment-6057033928)として公開済みであることを確かめた

## 3. 交差検査の対象(Issue 指定)の現状

### 3.1 第1章 1.2 適用範囲(`overview.md` L39-52)

- 表の4区分: 適用対象(生成AIエージェントを実装・設計・検証のいずれかに用いるソフトウェア開発と保守)、適用組織(1名体制・QMS も決裁規程も持たない体制を含む)、適用フェーズ(企画〜運用の全ライフサイクル)、適用外(AI を一切用いない開発、既存規程が上位で禁止する領域)
- 開発の方式・手法の区分は無い。「スクラムで開発している組織」は適用組織に含まれ、除外の根拠は無い
- 適用外の領域は第8章のテーラリングの記録に除外理由を残す(L48)
- 1.2 に手法との関係を書くと、適用範囲(適用する/しない)の記述と、関係(併用・対応)の記述が混ざる。1.2 の表は「範囲」の語彙(ADR-0049 の閉じた語彙と別物だが、適用範囲の書式 #226 の対象)

### 3.2 第2章 2.2 二層構造(`lifecycle.md` L19-47)

- 外殻(マクロライフサイクル): 既存の稟議・決裁権限規程、出荷判定の席・判定者・時点を変えない。署名の意味と残存リスクの受容の記名は改める
- 内側(AI協調ループ): 仕様承認(人)→ AI実装 → 自動検証(CI)→ 独立レビュー(人)。「新たに規定する」(L42)
- 二層の理由: 事業判断の頻度を上げると決裁が滞留し、開発反復の頻度を下げると AI の生成速度を活かせない
- 含意: 外殻は「既存制度を変えない」と明言するが、内側は「新たに規定する」。**既存の反復手法(スクラム等)が内側の層に既にある組織で、それを置き換えるのか、その上に重ねるのかを 2.2 は書いていない**。附属書A A.1 は同型を Water-Scrum-Fall に求めるが、Water-Scrum-Fall の「スクラム」に当たるのが内側の AI協調ループである。この読みでは、内側は**スクラムの位置を占める**ことになり、「併用」より「置き換え」に近い読みも成り立つ
- 2.6 の AI協調ループは機能単位(数時間〜数日)。スクラムのスプリント(1か月以内の固定長、複数機能)とは反復の単位が違う。両者を同じ層に置くのか、スプリントの中で AI協調ループが複数回回るのかは、本文に無い

### 3.3 附属書A の構造(`integrated-process.md` L1-78)

- 表題: 附属書A(参考) 設計の背景と由来。第1章 1.5 の表(L174)の内容欄は「本標準の構造を採用した理由と**既存プロセスとの対応**」
- 節: A.1 二層構造を採用した理由 / A.2 4つの設計原則と5つのギャップへの対応 / A.3 各要素の由来 / A.4 人間の検証帯域を守る設計 / A.5 変えるもの・変えないもの / A.6 前提と限界
- EV マークは0件(附属書C 3件・E 2件・G 1件・I 2件と比べて唯一0件)
- 1.5 の内容欄が「既存プロセスとの対応」を謳うのに、現状は由来の表(A.3)だけ。**1.5 の約束と附属書A の中身の間に既に隙間がある**。#298 の節は、この隙間を埋める位置として自然

### 3.4 ADR-0027

- 本文の自己参照は「本標準」。新節でも「ピットイン方式はスクラムと…」ではなく「本標準は…」と書く
- 名称は内容を保証しない(L73)。「ピットイン方式準拠のスクラム」のような複合の名乗りを認めるかは未決。附属書H H.8 の使ってはならない表現に「ピットイン方式に準拠しているので品質保証済み」が既にある(assurance-case.md L755 付近)

### 4.1 各案の注意点

- 案A
  - ADR-0017 決定5(参照モデルを既存手法と同じ表に並べない。比較の公平性・優劣)と緊張する。対応表は比較表と別物と言えるかの判断が要る
  - 附属書H H.10 の型(「適合は主張しない」「示さないものは示さないと決めた」「確かめたのは〜まで」)を流用できる
  - スクラムガイドは「一部だけを実装したものはスクラムではない」旨を述べる(と知られている。本調査では未確認)。対応表が「スクラムのこの部分を本標準のこれで置き換える」と読まれると、スクラムガイドの側からは「スクラムではない」になる
  - SAFe は Scaled Agile, Inc. の登録商標。第1章 1.7「特定の製品名に依存する表現は用いない」(L209)との整合の判断が要る(スクラムは商標の扱いが異なる。未確認)
  - 手法の版の改訂(スクラムガイド 2020 の次版、SAFe 6.0 等)への追随の負担。1.7「AI の能力に関する記述には時点を併記」と同様に、時点の併記が要る
- 案B
  - 本文に置くと規範が増え、実装マーク・適用範囲の書式・テンプレートの必須欄の検査に乗る。附属書A に置くと「条件」は説明に落ち、効かない
  - 「併用できる」と書かずに「併用する場合の条件」を書くと、併用できることを黙示に主張したと読まれる余地がある
  - 2.10 の「設けません」の読みを整理しないと、条件と既存の文が衝突しうる(§2.3)
- 案C
  - 受入条件を最小で満たす。ただし、起票者の問題(派生物が読者の既知と接続できない)は解かない。コアポリシー上、変更量の少なさは採否の理由にならない
  - 1.9 の箇条は「組織が主張しないこと」(組織の主張の範囲)で、本標準自身の主張の範囲と主語が違う。置き場は 1.9 の後段か 1.3 の caution(既存規格への適合を主張しない)の延長が候補
  - 附属書A A.1・A.3 の由来の主張(EV なし)と「関係を主張しない」の整合。由来は認めつつ関係は主張しない、を書き分ける必要
- 案D
  - 受入条件を満たさない(標準本文に節も「主張しない」の明記も無い)。単独では不成立。案C と組み合わせて「派生物が書けるのは何か」を決める形なら成立する
  - 起票の経緯(AGENTS.md 2.3 手順2: 正本に無い比較は派生物に書けない)から、D は概要記事の節を恒久に書けない状態を確定させる

### 4.2 組み合わせの候補

- C + A: 1.9 付近で関係(併用の可否)は主張しないと明記し、附属書A に対応表を「適合を主張しない・優劣を示さない・確かめた範囲」付きで置く
- C + B(附属書A): 主張しないと明記し、附属書A に「併用する組織が確かめること」を説明として置く(規範にしない)
- C + 附属書A A.1・A.3 の既存主張への EV 付与: 本件の範囲で附属書A の EV 0件を解消する
