## 1. 立場と、全体の見立て

1. **起票者の前提「読者の既知(スクラム)につなぐ説明は要る」は、現場の側からは正しい。ただし要るのは対応表ではない**。スクラムのチームが採用を検討するときに最初に出る問いは「スクラムをやめなければならないか」「会合を増やさなければならないか」「完成の定義と何が違うか」の 3 つである。これは手法の要素の対応(PO = 価値責任者、等)では答えられず、**本標準が何を規定し、何を規定しないか**で答えられる。HELENA で 76.8% がハイブリッドである以上、「併用できる」と書いても情報量は小さい(調査 2 §4.2)。情報量があるのは「どこで当たるか」である
2. **現状の本文は、スクラムのイベントを禁じる読みを許している**(発見 1・2・3・6)。これは「書かれていない」より悪い。説明の節を足す前に、この読みを消さなければならない。C(主張しない)だけを書いて 2.10・3.7・1.4 を据え置くと、「関係は主張しないが、スプリントプランニングは作業層の会議体として禁止」と読める本文が残る。**M-6 が本 Issue の中で最も信頼性に効く論点である**
3. **併用の条件を本文の新しい規範として書くことに、現場は反対する**。「完成の定義に G-5 の基準を含めなければならない」のような規範は、ゲートの判定基準が完成の定義と無関係に既に掛かっている以上、同じ中身を 2 か所で確かめる二重の作業(チェックリストと判定記録)を課すだけで、手戻りを減らさない。条件として必要なことはすべて既存の要求事項(判定の成立は判定記録、席は D-0 の記名、独立レビュアは作成指示者以外)から出る。**新しい規範を置かず、既存の要求事項の所在を引く説明として書く**
4. **手法名ごとの対応表は、現場では「名前の置き換え表」として使われ、適合の錯覚を生む**。「うちのスクラムマスターが文脈オーナーだから」で席の任命(D-0 の記名)を済ませた気になる。#267 の突合がまさに、スクラムマスター → Label Mailbox・文脈オーナーという、人の席と仕組みを混ぜた対応を書いていた(M-8)。軸は手法名ではなく規定の対象(席・判定・記録・停止・AI の自律・本標準が定めないもの)に置く
5. **承認待ちで遅くなるかは、#298 の書き方で増えも減りもしない**。期限(G-2・G-3 は 48 時間、G-4 は 24 時間、G-6 は応答 1 営業日 / 判定 2 営業日)は既存の規定である。#298 で効くのは、**ゲートの判定をスプリントの区切り(スプリントレビュー)へ寄せて溜める誤読を断つこと**だけである。溜めると、Water-Scrum-Fall の "Fall" を本標準が自ら作る。スクラムガイド自身が「スプリントレビューはリリースの関門ではない」と書いており、この 1 文で断てる

## 3. 論点ごとの詳細

### M-1 書く型

**判定: 採る(C + B を説明として)。** 本文に C を置き、附属書A に「どこで当たるか」の説明を置く。B の中身(併用の条件)は、新しい規範ではなく、既存の要求事項の所在を引く説明として書く。

文の案(第1章 1.2、表の後の段落。主語「本標準」の文で、1.7.2 により説明):

> 本標準は、適用対象を開発の方式(反復型・計画駆動・フロー型など)と、組織が用いる手法の名で限定しません。本標準は、既存の開発手法(スクラムなど)と併用できること、併用して成果が上がること、その手法の要素と本標準の規定が対応することを主張しません。手法の規定と本標準の要求事項を同時に満たした案件の記録を、本標準は観測していないためです。手法の要素と本標準の規定が同じ場面に現れる箇所の読み方は、附属書A A.7 参照。

あわせて `:::caution[暫定 EV-0149 / 見直し 2027-10]`(番号は議長が採番)。対象: 併用の可否・有効性・対応を主張しないこと。根拠の水準: E1(間接。併用の有効性を実証した規格・研究は調査の範囲に無い。HELENA は自己評価で効果量小、Agile-Stage-Gate は知覚ベース)。差し替え条件: 手法を併用した適用案件で、未達と記録の欠落の件数(1.10.2)を併記した適用の表明が得られた件数と、そのうち手法の側の規定を変えずに済んだかの記録。

選ばなかった案を落とす理由。

### M-6 2.10 等の文がスクラムのイベントを禁じる要求と読めるか

**判定: 採る。読める。本 Issue で直す。射程は 2.10 だけでなく 1.4・3.7 へ広げる。**

読みの検討。

- 2.10 冒頭「新しい会議体・ゲート・様式を設けません」: 主語は「本節」(直前の文「本節は…規定します」)で、1.7.2 の「主語が本標準である文」に準じる表明と読める。直さなくてよいが、「本節は」を明示すると迷わない

- 2.10.3: 「スコープを定めるための会議体を別に設けません」へ揃え、3.7.3 の同じ文とどちらか一方を正本にして他方は所在を引く(正本は 2.10.3。スコープの手続は 2.10 が正本と 3.7.3 自身が書いているため)

- **「会合」の定義を新設する**: 定義語を 1 つ増やすと、会合に何かを課す規定を将来書ける足場を作る。会議体の定義を閉じ、会議体に当たらないと書くだけで足りる
- **2.10.2 の禁止を「ストーリーポイントを含む」と明示する**: ステージの単位の規定を、反復内の計画へ広げることになる。広げる根拠(反復内でポイントを使ったことの害の測定)は調査に無い

ADR: 1.4 の定義の変更は語彙の決定であり、#298 の新 ADR(ADR-0080)の決定の 1 つとして記録する。採用済み ADR の本文は書き換えない。3.7.1 の基本方針(ADR が定めたもの)の中身は変えず、射程を書き分けるだけなので、置き換えではない。

### M-7 ADR-0068・ADR-0027・商標との整合

**判定: 採る(C の段落に 1 文)。**

- 文の案(1.2 の C の段落の末尾。主語「本標準」の説明): 「他の手法を用いていること、またはその名と本標準の名を組み合わせて名乗ることを、本標準は適用の開始(1.10.1)にも、適用の表明と適合の主張(1.10.2)にも数えません」
- 現場の側からの理由: 「スクラムにピットイン方式を足して回している」という言い方は、テーラリングの宣言なしに広がる。1.10.2 の箇条 2(件数を併記しない表明を適用の表明として扱わない)が既に同じ結果を課しているが、手法の名との組み合わせの名乗りは ADR-0027 L73(名称は内容を保証しない)が名称単独について書いただけで、組み合わせには触れていない。1 文で閉じる
- 商標: 本文で名を出すのは「スクラム」と文書名「スクラムガイド(2020 年版)」に限る。既に第8章 EV-0148 と改善サイクルが同じ文書名を出しており、新しい扱いではない。SAFe は出さない(M-3)。1.7 の「特定の製品名」は製品を指し、公開された枠組みの文書名は当たらないと読むが、この読みは確かめていない(他の委員へ問う)

選ばなかった案を落とす理由。

- **附属書H H.8 の使ってはならない表現に「スクラムと併用しているので適合」を足す**: 規定の附属書の規範が 1 つ増え、実装マークと検査の対象になる。1.10.2 の箇条 2 が同じ結果を課しており、H.8 は既に「ピットイン方式に準拠しているので品質保証済み」を持つ。手法名の組み合わせを列挙し始めると列挙の十分性を問われる(1.7.5 が列挙を求めない理由と同じ)
- **何も書かない**: ADR-0068 は「スクラムと併用している」を適用の表明でも適合の主張でもないと整理しているが(issues-context §2)、その整理は ADR の中にだけあり、採用者が読む本文に無い

## 4. 他の委員に問いたいこと

1. **起草へ**: 1.4 の「会議体」の定義の「B-1〜B-4」は、起草時に列挙の閉包として書いたのか、例示か。第3章 3.14(L1746)が「会議体の削減・統合はテーラリング(第8章)の対象とする」と書き、第8章「会議体と体制図の調整」(L822)が調整を規定している。テーラリングで会議体を設け直せる読みなら、組織が B-5 を置くことがありうる。そのとき「B-1〜B-4 に限る」と閉じる案は誤りになる。閉じ方を「第3章 3.7 に定めた会議体と、テーラリングで設けた会議体に限る」とすべきか
2. **品質保証と監査へ**: A.7 の「判定」の行(完成の定義の自己確認は G-6・G-7 を兼ねない)は、既存の要求事項から導ける説明として書いた。監査の場で、組織が完成の定義のチェックリストを判定記録の代わりに提出してきたとき、この説明が参考の附属書にあるだけで差し戻しの根拠として足りるか。足りないなら、根拠は第4章「判定の成立」の側で既に足りているか
3. **規格へ**: 第1章 1.7「特定の製品名に依存する表現は用いない」に、公開された枠組みの文書名(スクラムガイド)は当たるか。第8章 EV-0148 と改善サイクルが既に名を出しているが、それは 1.7 の例外として認めたのか、当たらないと読んだのか
4. **規格へ**: 2.10.4 の改文(「通知を、定例の場での報告で代えてはならない」)は、元の文(定例を設けない)より禁止の対象が狭い。元の文の起草の意図(`research/phase4-standard/140-131-scope-and-progress.md`)が定例そのものの抑止だったなら、改文は緩める向きの変更になる。起草の記録を読んだ委員はいるか
