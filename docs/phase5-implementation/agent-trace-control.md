本ページは参考(手引き)です。要求事項の正本は[第5章 5.8.6](/process-compass/phase4-process-design/human-ai-boundary/)「実行時の拒否と、エージェントの操作の確認」と 5.8.2・5.8.5 です。本ページは、その実装の形を示します。適合の条件には数えません([第1章 1.8](/process-compass/phase4-process-design/overview/))。

1回のタスクで数十から数百の操作が実行される環境では、痕跡を遡って探す目視の作業は、確認済みの印を付ける操作へ縮退します。本ページは、[附属書E E.6](/process-compass/phase4-process-design/developer-guide/)の5つの事象を、目視の対象から外し、実行時の拒否と機械の検出へ振り分ける形を示します。

## 事象ごとの担い手

| E.6 の事象 | 扱い | 担い手 | 本文の所在 |
| --- | --- | --- | --- |
| 仕様の範囲外のファイルを変更した | 実行時に拒否する | 書き込み範囲の制限 | 5.8.6 要求事項1 |
| 認証情報・秘密情報へ接触した | 実行時に拒否する | 読み取り範囲の制限、秘匿情報の隔離 | 5.8.6 要求事項1・4 |
| 想定していない外部への通信を行った | 実行時に拒否する | ネットワークの既定の拒否 | 5.8.6 要求事項1 |
| 失敗したテストを、テスト側の変更で通過させた | 差分から機械で検出する | CI の検査 | 5.8.5 の禁止事項3 と、その後の段落 |
| 検証を無効化する設定変更を含めた | 差分から機械で検出する | CI の検査 | 第4章 G-5「基準値と除外設定の変更」 |

人が確かめるのは、拒否が働いた事例と、機械の検出が指摘した事例です(5.8.6)。何も指摘が無いときに痕跡を読む作業は要りません。

## 実行時に拒否する

### 既定を拒否に置く

3つの事象は、起きてから見つけるより、起こさないほうが確実です。許可した範囲の外を拒否する構成の例を示します(5.8.6 要求事項3)。

| 対象 | 既定 | 許可する範囲の決め方 |
| --- | --- | --- |
| 書き込み | 拒否 | 実装計画のタスクが対象とするパス |
| 読み取り | リポジトリ内は許可 | 秘匿情報を含む経路を除外する |
| ネットワーク | 拒否 | 依存関係の取得先など、必要な宛先だけを許可する |
| コマンド実行 | 許可リスト | 実行を許すコマンドを列挙する |

- 拒否の発生そのものが、タスクの範囲の設定が実態と合っていない兆候になる。記録の要求は 5.8.6 要求事項5
- 準拠テンプレートでは、書き込みの遮断のフック(`.claude/hooks/guard-write.mjs`)が拒否を `.claude/denied.log` へ記録し、強制層への書き込みを遮断する
- 準拠テンプレートの権限設定(`.claude/settings.json`)は、秘匿情報の経路の読み取りを確認つきに置き、コマンドを許可リストに置く。書き込みの範囲とネットワークの既定の拒否は、まだ降りていない([実装の台帳](/process-compass/community/implementation-ledger/))

### 拒否を指示ではなく設定で行う

指示ファイルの遵守は保証されないため、許可範囲は実行環境の設定(強制層)に置きます(5.8.6 要求事項2、[第3章 3.11.3](/process-compass/phase4-process-design/roles-responsibilities/))。同じ区別を[スタック型 PR の運用](/process-compass/phase5-implementation/stacked-pr/)でも用いています。

| 層 | 置くもの |
| --- | --- |
| 誘導層(指示ファイル) | 範囲外へ出ようとした場合に人へ確認を求める旨 |
| **強制層**(実行環境の設定) | 書き込み範囲、ネットワーク、コマンドの許可リスト |

### 実行基盤を選ぶときの確かめ方

拒否の実装は、利用するエージェントの実行基盤が提供する機構に基づきます。本標準は特定の製品・拡張機能を指定しません。実行基盤を選ぶときは、次の4点を確かめると、5.8.6 の要求事項を満たせるかを判断できます。

| # | 確かめる点 | 対応する要求事項 |
| --- | --- | --- |
| 1 | 書き込み・ネットワーク・コマンド実行のそれぞれについて、許可範囲を設定できる | 5.8.6 要求事項2・3 |
| 2 | 設定を版管理下に置き、案件ごとに指定できる | 5.8.6 要求事項2 |
| 3 | 拒否された操作を、後から参照できる形で記録できる | 5.8.6 要求事項5 |
| 4 | 設定の変更が、エージェント自身の操作では行えない | 5.8.6 要求事項6 |

4を満たさない基盤では、範囲を広げる操作が実行の一部として行えるため、拒否は成立しません。

## 差分から機械で検出する

残る2つの事象は、実行の痕跡ではなく差分の性質から検出できます。

| 検査 | 検出の条件 | 扱いの所在 |
| --- | --- | --- |
| 検証の弱体化 | テストの削除、アサーションの削除、`skip` 相当の付与 | ラベルにとどめ、G-6 の必須の確認事項として示す(5.8.5 の後の段落) |
| 基準値の引き下げ | カバレッジ閾値、静的解析の重大度設定の変更 | 製品のコードと同じ変更では G-5 を通さない(第4章 G-5) |
| 検査の除外設定 | 除外リスト・無視設定への追加 | 同上 |
| テストだけの変更で失敗が解消した | 実装の差分が空で、直前の実行が失敗していた | ラベルにとどめる(5.8.5 の後の段落) |

準拠テンプレートでは、G-5(`pr-rules`)が基準値・除外設定と製品のコードの同時の変更を失敗にし、既存のテストの変更を PR へ一覧で出します。アサーションの削除と `skip` 相当の付与の検出とラベルは、まだ降りていません。

## 人が見るもの

開発者が確かめるのは、次の3つです(5.8.6)。

| # | 見るもの | 範囲 |
| --- | --- | --- |
| 1 | 拒否が働いた記録 | 件数は有界。0件であれば見るものが無い |
| 2 | 機械の検出が付けたラベル | 同上 |
| 3 | 実装計画の対象のパスと、実際に変更されたパスの差 | 機械の突合の出力 |

3つとも数え上げられます。範囲の定まらない確認は、時間の制約のもとで省かれます。ただし、拒否が0件であることは、想定外の操作が無かったことの根拠になりません(5.8.6 要求事項9)。拒否は、設定した範囲についてだけ働きます。

## 操作の要約

エージェントの操作の要約を AI に生成させない理由は次のとおりです(5.8.6 要求事項8)。

- 要約は評価を含む。「想定内の操作でした」という記述は、確認の結論を先に与える
- 監査の対象が、監査の記録を書く構造になる
- [第5章 5.8.5 の禁止事項5](/process-compass/phase4-process-design/human-ai-boundary/)と[レビューパッケージ](/process-compass/phase5-implementation/review-package/)の原則(生成を機械的な導出に限る)と同じ理由

実行したコマンドの分類、変更したパスの一覧、通信先の一覧は、いずれも集計であり評価を含みません。

## 生成の条件の記録

記録する項目(モデルの識別子と版、指示資産の版、実行の識別子)は、[第5章 5.8.2](/process-compass/phase4-process-design/human-ai-boundary/)によります。[PR ワークフロー](/process-compass/phase5-implementation/pr-workflow/)の「AI 関与範囲」欄と同じく、導出元から自動で埋める形が、5.8.2 の「人の転記に頼らない」を満たします。準拠テンプレートでは、モデルの識別はコミットのトレーラ `Co-Authored-By` に基づきます。実行の識別子と指示資産の版の自動の記録は、まだ降りていません。

エージェントへ渡した指示の全文は、記録の対象に含めないことを勧めます。理由は3つです。

- 分量が変更単位ごとに増え続ける。保管する量に対して、参照される場面が釣り合わない
- 指示には作業中の試行錯誤が混ざる。秘匿情報の混入を検査する対象が新たに増える
- 全文があっても生成は再現しない

上の項目が揃っても、同じ出力は得られません。提供者側の更新によって、同じ版の指定が同じ挙動を返さなくなる場合もあります。外部へ説明できるのは条件の特定までです(5.8.2)。

## この設計の限界

- 拒否が働くのは、設定した範囲についてだけである。想定していない経路は拒否されない。記録の目的は、この限界を埋めることではなく、後から経路を特定できるようにすること
- 差分からの機械の検出は、正当な変更と区別できない範囲ではラベルにとどまる。ラベルの確認を省く運用では、この層は働かない
