## ステータス

採用(2026-08-14)

## コンテキスト

規格調査4本と5者による会議体([#242](https://github.com/Takenori-Kusaka/process-compass/issues/242))で、**採否そのものは決まったが、いま置いても機能しない**規定が4件出ました。

例外承認の回収を担保する装置がその代表です。会議体は次の事実を確認しました。

- **PPAP・日本政府の標準ガイドライン・JAXA が、いずれも「基準を満たさないまま正規の通過を出せない」機構を持つ**
- **JAXA は、過去の判定事例の参照義務と、再発時の自動昇格を課している**
- **一方、案件 P-001 の 7.3 の適用件数は 0 件である**

**適用が0件である以上、参照すべき過去の判定も、止める対象の未回収項目も存在しません**。いま条文へ置いても空振りします。

### 保留と書くと、条件が消える

これを「保留」と記録すると、**次に読む者には「決まらなかった」としか見えません**。会議体が確認した先例も、空振りの理由も、いつ採るべきかも残りません。**次の会議体は、4本の調査と5者の意見書を読み直すところから始めます**。

[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)は未達と省略を区別しました。[ADR-0033](/process-compass/adr/0033-no-target-as-recorded-state/)は「対象なし」を記録して通過する状態を定義しました。**同じ精度が、決定の側にも要ります**。

### 先例は本標準の中にある

[ADR-0034](/process-compass/adr/0034-stack-is-output-of-exploration/)は「未確定は未達ではない。時期が来ていない状態である」と定めました。**同じ作法を、規定の採否へ適用します**。

## 決定

### 1. 「条件付きで後置」を、採否の第3の状態として置く

規定の採否は次の3つで記録します。

| 状態 | 意味 |
| --- | --- |
| **採る** | 本文または ADR へ反映する |
| **採らない** | 採らないと決めた。理由を記録する。本文へ明記するかは別に判断する |
| **条件付きで後置** | **採ると決めた。ただし条件が満たされるまで置かない** |

**「保留」を用いません**。保留は判断が済んでいない状態であり、後置は判断が済んでいる状態です。

### 2. 後置には、観測できる条件を書く

条件には**数えられる量**と、**どの観測が得られたら採るか**を書きます。書けない場合は後置と記録できません。[ADR-0045](/process-compass/adr/0045-replacement-conditions-must-discriminate/)の差し替え条件と同じ要件です。

### 3. 会議体が後置と判定した4件を、本 ADR に記録する

| # | 規定 | 採る条件 |
| --- | --- | --- |
| 1 | **昇格の禁止**(未回収の例外承認がある間、次のゲートで通過を出せない) | 7.3 の適用が、いずれかの案件で3件を超えたとき。**または 7.3 を経ずに基準未達のまま進んだ事案が1件でも見つかったとき** |
| 2 | **一貫性の強制**(過去の判定事例の参照義務、再発時の自動昇格) | 7.3 の例外承認が3件を超えたとき |
| 3 | **リスクの集約評価**(SR3 が多数残る状態を、1件の状態と区別する) | SR3 以上が5件を超えた案件が生じたとき |
| 4 | **安全リスクの見積りへの第三者の関与** | 案件が3人以上の体制になったとき |

**1 の第2条件が要です**。第1条件は「7.3 が使われている」ことの確認であり、第2条件は「7.3 が回避されている」ことの確認です。適用0件という観測は両方の仮説と整合するため、**回避を直接検出する条件を併せて置きます**。

### 4. 後置した規定を、根拠水準マークの対象としない

後置は本文へ反映していない状態です。**存在しない記述へマークを付けません**。条件の記録は本 ADR が担います。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 保留として記録する | 条件が消える。次の会議体が調査からやり直す |
| 4件とも採り、本文へ置く | 空振りする。**装置を増やすほど回避と未記録の確率が上がる**という会議体の確認と矛盾する |
| 4件とも採らないと決める | 先例が支持する装置を、実績が出る前に否定することになる |
| Issue の本文にのみ残す | Issue を閉じると追えない。決定の記録は ADR が正本である |

## 帰結

- 採否の記録に「条件付きで後置」の状態が加わる
- **後置した規定は本文に現れない**。実行層にも降りない
- 条件が満たされたとき、**新しい ADR で採否を決める**。本 ADR の本文は書き換えない
- **条件が満たされたことを検知する仕組みは無い**。次に該当の主題を扱うとき、本 ADR を読むことに依存する

:::caution[暫定 EV-0032 / 見直し 2027-08]
**対象**: 決定1(後置という状態を設ければ、条件が失われずに次回へ渡るという判断)。

**根拠の水準**: E0(なし)。

**根拠とした事例**: 2026-08-14 の会議体1回分。

**差し替え条件**: 本 ADR の4件について、条件が満たされた時点で採否が再検討された件数。**条件が満たされたにもかかわらず再検討されなかった件数が1件でも生じた場合、後置は記録として機能していないことになります**。
:::
