## コンテキスト

準拠テンプレートの `/process-change` は、AI を示す語を含む氏名の人を名簿へ足して確認の旨(`nameConfirmed`)を書き、同じ変化点でその人を席の責任者に任命する入力を拒否していました。記名者は確認される本人以外の、前から名簿にいる人(山田)でも同じでした。p302(テンプレート `ec8ecd6`)ではこの入力を受け付けていました。#319 の会議体は、回帰か決定かを人が決めるまで、元の期待(反映)のまま印を付けて本件へ送りました。

内部調査と実行による確認で、次のことが分かりました(`research/375-deliberation/`)。

- 原因は評価の時点の食い違いである。確認の記名の正しさ(本人以外か、名簿の人か、AI の名義でないか)は、この変化点の入力で照らす。確認が効くかは、この変化点の記録を足す前の構成で照らす。#296 の付記(テンプレート `4af67c5`)が、確認の効力を記録の有無で判定するよう改めたため、記録を足す前の評価の位置が初めて結果を左右した
- 標準(第4章 G-6、第6章 D-0 表5)・ADR-0079 決定7・#296 の会議体のどれも、確認と使用の前後を定めていない。前の変化点での確認を求める意図の記述も無い
- 確認だけの変化点でも、その変化点の記録の `nameOverrides` と出力の上書きの表示が、その確認を数えていなかった
- 委任の席の責任者の名義の検査(`clampSeats`)は、記録を持たない構成で照らしていた。前の変化点で本人以外が正しく確認した人でも、委任の席の責任者にできなかった。p302 では受け付けた
- 同じ変化点で数える試作では、本人の記名・AI の名義の記名・名簿に無い人の記名・記名なし・AI を示す語を含む名義どうしの相互の確認は、今と同じ理由と件数で拒否されたままだった
- 帰属の検査は、同じ PR に入れた2件の記録を同じ PR で照合する。変化点を分けても、確認が効力を持った後に使ったことの保証にはならない

外部の規格と実務が求めるのは、確認と付与の**論理の前後**であり、別の取引に分けることではありません(21 CFR 11.100(b)、NIST SP 800-63A-4、NIST SP 800-53 Rev.5 の IA-12(1)・AC-2 c、Microsoft Entra・Okta の申請の段)。CODEOWNERS と Kubernetes の RBAC は変更前の状態で判定しますが、対象は記名者の権限であり、付与される者の前提条件には当たりません。

会議体(起案・現場・品質監査・規格・弁護の5委員)の審議の記録は `research/375-deliberation/` にあります。5委員とも、同じ変化点の確認を数える案を推しました。

## 決定

### 1. 同じ変化点の確認を、その変化点の任命と記名の判定に数える。今の拒否を回帰として直す

- 名簿へ足すのと同じ変化点で、本人以外が記名した氏名の確認を、その変化点の任命・記名の判定に数える
- 確認と使用の前後は、論理の順序で足りる。確認の記名の要件を先に照らし、満たした確認だけを、その変化点の判定に数える。満たさない確認は拒否する
- 変化点を分けることは求めない。第4章 G-6 の氏名の確認の規定へ、その旨を書く
- 分類は回帰とする。#296 の付記が、評価の時点を定めずに検査の結果を変えた。標準が前後を定めていなかったため、本 ADR で解釈を確定させる
- 回帰の試験の根の場面の印(#375)と、連鎖の2場面の従属の印を外す。期待値は p302 と同じ(反映)であり、改めない(`changed` を置かない)

### 2. 評価の時点を、付与される者の前提条件(類A)と、記名・承認する者の資格(類B)に分ける

- 類A **付与される者の前提条件**は、この変化点の記録を足した後の構成で照らす。氏名の確認の効力と、席の責任者・委任の席の責任者・適合性確認の実施者と承認者に置かれる人の名義が当たる
- 類B **記名・承認する者の資格**は、変化点の前の構成で照らす。変化点の記名者、確認の記名者、任免の決定者、委任の規則の決定者と承認者が当たる
- したがって、この変化点で名簿へ足した人が、同じ変化点で他の人の氏名を確認しても数えない。例外は、第3章 3.13.3 の初回の記入(どの席にも責任者が記入されたことのない状態からの記入を、D-0 表1「体制と運用形態」の決定者の席に記入する人が記名する変化点)に限る。初回の記入では、確認の記名者をその変化点の名簿で照らす。任免の決定者の初回の例外と同じ判定である
- 外部の人だけが前の名簿にいる変化点は、初回の記入でなければ例外に当たらない。例外を「前の名簿の体制の内が0名」とした最初の実装は、こうした変化点で足した人の確認を数えていた(突合)
- 評価と書き出しは、同じ記録の1回の生成から作る。変化点の記録の `nameConfirmations`・`nameOverrides` と、出力の上書きの表示は、判定に使った記録と同じ記録から出る
- 一般原則「すべてを記録を足した後の構成で照らす」は採らない。類B を後の構成で照らすと、同じ変化点で足した者が自分たちの資格を作れる

準拠テンプレートでの検査ごとの類は、次の表のとおりです。

| 検査(準拠テンプレート) | 類 | 照らす構成 |
| --- | --- | --- |
| 記名の欄の検査 `namingProblems`(名簿、席の責任者、適合性確認の承認者の名義) | A | この変化点の記録を足した後 |
| この変化点で出された適合性確認の実施者と承認者 `qualificationAuthorityProblems`(担い手の識別の変更と同時の再確認を含む) | A | この変化点の記録を足した後 |
| 出力の上書きの表示と、変化点の記録の `nameOverrides` | A | この変化点の記録を足した後 |
| 委任の席(`clampSeats`)の責任者、適合性確認の実施者と承認者の名義 | A | この変化点の記録を足した後 |
| 決定した者の記名(AI の名義の判定) | B | 変化点の前の記録(決定5 の確認待ちを効かせる) |
| 決定した者の記名(名簿の人かの照合) | B の例外 | この変化点の名簿。初回の記入の決定者は、この変化点で名簿へ記入される。任免の決定者の要件は、前の構成で別に照らす |
| 氏名の確認の記名者の資格(本人以外か、名簿の人か、AI の名義でないか、この変化点より前から名簿にいるか) | B | 変化点の前 |
| 任免の決定者 | B | 変化点の前 |
| 委任の規則の決定者と承認者の資格(`clampSeats` の規則の成立) | B | 変化点の前 |

記名の欄の検査の中身は、すべて類A でした。類A と類B が同じ呼び出しに混じっていたのは委任の席の検査であり、呼び出しを分けました。

アカウント名の確認(`accountsConfirmed`)の記名者は、本 ADR の類B の「この変化点より前から名簿にいる」の照合の対象外です。#375 の論点は氏名の確認に限り、アカウント名の確認の記名者の資格は審議していません。本 ADR はアカウント名の確認にこの照合を課しません。

拒否の文は、原因(名簿に無い / 確認の旨が無い / 確認の旨に有効な記録が無い)ごとに分けます。確認の記名者の要件と、確認はその人を席に置くのと同じ変化点で出せることを案内します。

### 3. 委任の席の責任者の名義の検査に、変化点の記録を渡す

- 委任の席の検査(`clampSeats`)へ、変化点の記録を渡す。席の責任者の名義の確認は類A として、この変化点の記録を足した後の構成で照らす。同じ検査の中の規則の決定者・承認者の資格は類B として、変化点の前の構成で照らす
- これも回帰として本件で直す。根の場面と同じ構図であり、#296 の付記が判定を記録へ寄せたため、記録を持たない評価の位置が結果を左右した
- 委任の席が記名なしに自動で緩まないことを、試験で確かめる

### 4. 同じ変化点で確認して使ったことを区別する欄は足さない。帰属は時間の前後を保証しないと開示する

- 同じ変化点で確認して使ったことを区別する欄を、記録にも保証の開示にも足さない。確認(`nameConfirmations`)・記名者・任命の差分は1件の記録に並び、記録から読める。**本標準は、この区別の欄を課さないと決めた**
- 効力を持つ記録の帰属(ADR-0106)は、確認と使用の時間の前後を保証しない。同じ変化点の確認と使用は、同じ PR の操作で同時に裏づけられる。変化点を分けて同じ PR に入れても同じである
- 類B を前の構成で照らすことで、同じ変化点での自己作成の資格が塞がるという判断は、試作と試験の場面にしか支えられない。根拠水準を EV-0229 で開示する

### 5. 1名から2名以上へ移る変化点では、本人の自己申告の確認を確認待ちとして受け付ける(追加の裁定 AR-2)

- AI を示す語を含む氏名の本人1名の体制に2人目を足す変化点は、決定1・2 のままでは本人の記名でも2人目の記名でも拒否され、外部の人を先に名簿へ置く迂回しか無かった。1つの変化点の記名者は1人であり、確認の記名者はその変化点の記名者であるため、同じ変化点で2人目が本人の氏名を確認する形は構造上成り立たない
- 名簿の体制の内の人が1名から2名以上へ移る変化点では、前の名簿で効いていた本人の自己申告の確認(本人の記名・記録の無い確認)を、その変化点では**確認待ち**として受け付ける。名簿へ足すこと自体を拒否しない。確認待ちは、その変化点の評価に限って効かせる(前の名簿で効いていた確認であるため、類A と類B の両方で効かせる)
- 確認待ちの氏名は、書き出した構成では効かない。契約検査と出荷の証跡の集約は、記録の無い確認と同じく欠落として扱う。本人以外の人(2人目以降)が記名する後の変化点で確認するまで、変更の取り込みと出荷はできない。2つの変化点を同じ PR に入れてよい
- `/process-change` と拒否・注意の文は、確認待ちの氏名と、次の変化点で本人以外が確認する手順を案内する
- 確認待ちの印は、構成と記録のどちらへも書かない。2名以上の名簿で本人以外の記名の記録が無い確認は、記録から確認待ちと読める
- 根拠水準は EV-0229 に含めて開示する

### 6. 既存の記録の記名者を、氏名の確認の状態の移り変わりを理由に照らし直さない。確認待ちの本人が記名した確認は拒否する(追加の裁定 2 の AR-4・AR-5)

- 記名者の資格(類B)は、その記録が作られた変化点の前の構成で照らす。後の変化点で、既存の記録(委任の規則の決定者と承認者、変更種別の登録者など)の記名者を、氏名の確認の状態の移り変わり(自己申告 → 確認待ち → 確認済み)を理由に照らし直さない。1名の体制で有効に作られた記録は、確認待ちのあいだも作られた時点の効力を保つ
- 照らし直しを止めるのは、氏名の確認の状態の移り変わりだけに限る。人の離脱・席の交代・規則の失効など、ほかの理由による既存の記録の扱いは変えない
- 確認待ちのあいだは、契約検査が落ちるため、変更の取り込みと出荷はできない(決定5)。この扱いは変えない
- 準拠テンプレートは、本人の記名の記録だけがあり、2名以上の名簿で効かない確認を、既存の記録の記名者の照合に限って効かせる。本人の記名の記録は1名の名簿でだけ受け付けるため、その人が記名した既存の記録は記名した時点では効いていた。この変化点で追加・変更した記録の記名者には使わない
- 確認待ちの本人が記名者で、他の人の氏名の確認を含む変化点は、理由を示して拒否する。その確認は、記名者の名義が AI を示す語を含み、本人の氏名も確認待ちのため、後の変化点で数えられない。効かない確認の記録を受け付けない
- 再確認で、決定1〜5 のままでは、1名の体制で本人が委任の規則を決めて変更種別を登録していると、確認待ちを解く変化点が既存の登録者を前の構成で照らし直して拒否されることが分かった。統制を緩める穴ではないが、決定5 の「次の変化点で本人以外が確認すれば通る」が委任を使う体制で成り立たなかった

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| (b) 前の変化点での確認を要求する | 独立も、効力の前後の保証も増えない。帰属の検査は同じ PR の2件を同じ PR で照合する。委任の席では手順そのものが成り立たない。1〜2名の体制が2人目を迎える変化点で手数が倍になる |
| (d) 同じ変化点なら、確認と任命に別の記名者を求める | 標準に1つの変化点で2つの記名を求める定めが無い。小さい体制で手続が止まる |
| (e) 名簿の追加と確認の旗を同じ変化点で拒否する | 確認の手順そのものが成り立たない |
| (f) すべての検査を記録を足した後の構成で照らす | 同じ変化点で足した者が、自分たちの資格を作れる |
| 記名の欄の検査だけを直す | 変化点の記録の `nameOverrides` と出力の上書きの表示が、判定と食い違ったまま残る |
| 同じ変化点で確認して使ったことを区別する欄 | 1件の記録から読める。同じ事実を2か所に持つ |
| 類B の例外を「前の名簿の体制の内が0名」とする | 初回の記入より広い。外部の人だけが前の名簿にいる初回でない変化点で、同じ変化点で足した人の確認が数えられる。1名の体制が2人目を迎える変化点も救わない |
| 1名から2名へ移る変化点に限り、同じ変化点で足した人の確認を数える | 1つの変化点の記名者は1人であり、構造上成り立たない |
| 確認待ちを欠落に数えない | 2名以上の名簿で、本人の自己申告だけの氏名が効いたまま残る |
| 前の構成でも、確認待ちを確認済みとして効かせる | 確認待ちの本人が、新しい記録の記名者としても資格を持つことになり、決定5 の確認待ちの意味が崩れる |

## 影響

- 第4章 G-6: 氏名の確認の規定の後に、同じ変化点で記録してよいこと、変化点を分けることを求めないこと、評価の順序、確認の記名者の資格を前の構成で照らすこと(例外は初回の記入)、1名から2名以上へ移る変化点の確認待ちを書いた。IMPL-0266 の注記を改め、IMPL-0446 と EV-0229 を付けた
- 第6章 テンプレ0 の表5: 欄「氏名の確認」の説明に、確認した者の要件、確認と任命を同じ変化点でよいこと、確認待ちを書いた
- 準拠テンプレートの `generate-profile.mjs`: この変化点の記録の1回の生成、類A と類B の評価の時点、確認の記名者の資格と初回の記入の例外、確認待ち、`clampSeats` へ渡す記録
- 準拠テンプレートの `config.mjs`: 拒否の文を原因ごとに分けた。確認待ちの状態、契約検査の文、出荷の証跡の集約(`configIntegrityProblems`)での欠落。既存の記録の記名者を記録した時点の効力で照らす構成(`recordSignerContext`)
