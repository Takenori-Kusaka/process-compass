## ステータス

採用(2026-10-23)。置き換える決定はありません。

## コンテキスト

[#289](https://github.com/Takenori-Kusaka/process-compass/issues/289) は、実証案件の原則の照合(#275)のうち、原則4 と原則9 の未対応の部分を引き継ぎました。原則4 は「同じ種類の不具合が 2 件出たら class として扱い、3 件目を機械で止める」、原則9 は「値が正しいことと、値が効いていることは別物。両方をテストする」です。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/289-deliberation/`(`survey-289-4`、意見書、`decision.md` の D-13・D-14)にあります。

### 昇格の件数が 15 か所でばらついていた

昇格に関わる記述は、本標準とテンプレートの 15 か所にあり、件数・単位・強さがそろっていませんでした。件数は「3回」「2回以上」「2回」「件数なし」に分かれ、数える単位は誤り・指摘・質問・類型に分かれていました。第3章 3.11.4 要求事項2 の「2回以上」は、指示資産へ追記してよい条件(量の歯止め)であり、昇格の起動ではありません。それが同じ語で並んでいました。正本がどこにもありませんでした。

外部の規範は、件数でなく影響と再発性で是正を起動します。ISO 9001:2015 の 10.2.1 は、不適合の影響に応じた是正、類似の有無の確認、有効性のレビューを求め、件数を定めません(二次資料で確認)。Google SRE は、利用者に見えた事象への対策を必須とし、件数を定めません。件数の「3」に根拠は示されていません(E0)。

### 設定の値が正しいことと、設定が効いていることは別だった

内部統制の監査は、統制が設計どおりに在ること(設計の有効性)と、意図どおりに働くこと(運用の有効性)を分けて確かめます。設定したつもりで効いていなかった事例が、調査で 4 件見つかりました。検査が黙って失敗した事例、監査の道具の不具合で止められなかった事例、検証器の前提がずれていた事例、検査の装置が PR の CI で一度も走らなかった事例です。後ろの 2 件は、検査の装置そのものの不具合です。

本標準は、閾値・除外設定を製品のコードと同じ変更で変えることを禁じていました。変更後の設定が止まるべきものを止めるかは、求めていませんでした。保証の開示の項目4(附属書H)は、参考の附属書I の要件を証跡に引いていました。[ADR-0063](/process-compass/adr/0063-normative-informative-and-verbal-forms/)決定1 の直し残しです。

## 決定

### 1. 件数を起動条件にした義務を課さない

**同種の不具合や指摘の件数を、是正や機械の検査への移行を義務づける起動条件にしません**。何を同種とするかの分類は記録する者の申告で決まり、件数の閾値は分類によって外せます。影響を起点にすれば、初回から掛かります。[ADR-0025](/process-compass/adr/0025-context-forgetting-over-detection/)は、件数で差し戻す案を、閾値の根拠が無いとして退けています。

### 2. 第4章 G-5 に「是正の起動」を置き、正本とする

次を起点に、是正の記録を残させます。

- 出荷後に発覚した欠陥のうち、重大度が Sev1 または Sev2 のもの
- 欠陥注入(第5章 5.6.2)で見逃された類型
- 統制の弱化の検知

記録には、次の4つを書きます。

1. 同じ条件で再び起こりうるか
2. 類似がほかにあるか
3. 再発防止を仕組み(検査・監視・手順)で置くか。置かないなら、その理由
4. 効いたことの確認

機械の検査で失敗させる形にするのは、実効的な偽陽性が無い・修正できる・既存の違反を解消済み、の3つを満たす場合に限ります。この条件は ADR-0025 と、静的解析をコンパイルエラーへ上げる条件の公表例と同じです。

出荷後の Sev1・Sev2 の是正の記録は、[インシデント対応](/process-compass/phase6-operation/incident-response/)のポストモーテム(Sev1・Sev2 は必須)とし、ポストモーテムに4項目を含めることを求めます。同じ事象に2つの記録を作らないためです([#252](https://github.com/Takenori-Kusaka/process-compass/issues/252) の「1判定2ファイル」と同じ型を避けます)。準拠テンプレートは、ポストモーテムの手順に4項目を置きました(IMPL-0141、降りている)。欠陥注入の見逃しと統制の弱化の検知を起点とする記録の様式は、準拠テンプレートにありません(IMPL-0135、降りていない)。

### 3. 検査の装置の不具合も起点に含め、対策は足す・直す・外すから選ぶ

検査の装置そのものの不具合も、是正の起点に含めます。止めるべきものを止めなかった場合と、止めてはならないものを止めた場合の両方です。装置への対策は、検査を足す・直す・外すの3つから選びます。

#275 の原則4 の後半「適用範囲を装置へ広げない限定」は置きません。装置の不具合を対象から外すと、装置そのものの欠陥が是正に掛かりません。装置が増えすぎる懸念には「外す」を対策に含めて答えます。装置の総量の上限は #290 で決めます。

### 4. ほかの箇所の件数は目安とし、正本を引く

フェーズ5 の CI ゲートの「同種の指摘が3回」、運用カタログ、準拠テンプレートの観点表の件数は、ルール化を検討する候補に挙げる目安とし、正本(G-5 の是正の起動)を引く形にそろえます。件数に達したことは、機械の検査へ移す義務を生みません。件数の目安には暫定マーク EV-0124(E0)を付けます。第3章 3.11.4 要求事項2 の「2回以上」は、追記してよい条件(量の歯止め)であり昇格の起動ではないと注記します。

### 5. 設計の有効性と運用の有効性を第1章で定義する

第1章 1.4 に「設計の有効性」(設定の値が規定どおりである)と「運用の有効性」(その設定で、止まるべきものが実際に止まる)を定義します。

### 6. 統制の設定を変える変更に、陰性の確認の記録を求める

統制の設定(閾値・除外設定・必須の検査・ルールセット・フック・権限)を変える変更では、変更後も止まるべきものが止まることを確かめた結果(陰性の確認)を記録させます。記録には、通した違反の場面、検査の結果、確かめた者を書きます。強める向きの変更も対象です。規定は第4章 G-5「統制の設定の陰性の確認」に置き、PR 単位の検査に載せます。根拠水準は EV-0125(E1)で開示します。

`decision.md` の D-14 は置き場を「第5章 PR 単位の検査」と書いています。PR 単位の検査の規定は第4章 G-5 にあり、フェーズ5 の CI ゲート構成はそれを参照する側です。規定は第4章 G-5 に置き、フェーズ5 の表に行を足しました。

### 7. 製品の設定には課さず、周期の作動確認は先送りする

製品の設定(機能の切り替えの設定など)には、別の要求を課しません。製品の挙動は、受入基準とテストで確かめます。統制の設定が変更なしに外れていないかを周期的に確かめる要求は、先送りします。材料は、統制の設定が変更なしに外れる頻度の観測です。

### 8. 保証の開示の項目4 の参照先を本文の規定へ改める

附属書H の保証の開示 項目4 の参照先を、第4章 G-5「統制の設定の陰性の確認」へ改めます。附属書I の I.11 要件⑦は、手順の例として引きます。

## 検討した選択肢

| 論点 | 採らなかった案 | 採らなかった理由 |
| --- | --- | --- |
| 昇格 | 3 件目を機械で止める義務(原則4 のまま) | 件数の根拠が E0 である。分類は自己申告で、閾値は外せる |
| 昇格 | 書き分けだけ行い、正本を置かない | 15 か所の食い違いの原因(正本の不在)が残る。会議体は影響起点の記録を採る案が多数だった |
| 昇格 | 装置の不具合を対象から外す | 装置そのものの欠陥(調査の事例 2 件)が是正に掛からない |
| 統制の設定 | 一般要求を課さず、既存の所在を示すだけにする | 既存の所在は、変更のたびに設定が効いているかを確かめていない。会議体は採る案が多数だった |
| 統制の設定 | 製品の設定にも同じ要求を課す | 製品の挙動は受入基準とテストが既に見る |
| 統制の設定 | 周期の作動確認を課す | 外れる頻度の観測が無い |

## 影響

- 第1章 1.4 に、設計の有効性と運用の有効性の語が加わる
- 第4章 G-5 に「是正の起動」と「統制の設定の陰性の確認」が加わる。準拠テンプレートの PR 単位の検査は、統制の設定を変える PR に本文の記録を求める(IMPL-0134、記録の有無だけを確かめる)。場面が実際に止まったかは、機械で確かめない
- フェーズ5 の CI ゲート構成と運用カタログの「3回」が目安になり、正本を引く
- インシデント対応のポストモーテムの様式に「是正の起動」の節が加わる。QMS の是正処置の対応表は G-5「是正の起動」を正本として引く
- 欠陥注入の見逃しと統制の弱化の検知を起点とする是正の記録の様式は、準拠テンプレートに無い(IMPL-0135)。品質保証の担当が記録の有無を確かめる
- `rule-candidate` のラベルと、運用メトリクスの「ルール化の進み」が準拠テンプレートに実装されていない件は、#290 へ送る
