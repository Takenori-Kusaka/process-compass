## ステータス

採用(2026-08-14)

## コンテキスト

本標準の安全リスク区分(SR1〜SR4)は、危険源ごとに Hs / Ex / Oc / Av の4パラメータを見積もり、その結果を4段階の区分へ写します。**この方式そのものに、査読済みの批判があります**([#242](https://github.com/Takenori-Kusaka/process-compass/issues/242))。

**Cox, L.A. (2008) "What's Wrong with Risk Matrices?" Risk Analysis 28(2), 497-512**(本文未取得。書誌と要旨・解説による二次情報):

- 典型的なリスクマトリクスは、無作為に選んだ危険源の対の**1割未満しか正しく一義的に比較できない**
- 範囲の圧縮が起こる。**定量的に小さいリスクへ、より高い定性的評価を与えることがある**
- 頻度と深刻度が負に相関する場合は "worse than useless" であり、無作為な判断より劣りうる
- **規格が採用を促してきた一方、性能を厳密に検証した研究はほとんどない**

本標準の SR はマトリクスではありません。しかし**順序尺度のパラメータを categorical な区分へ写す構造は同じ**です。とくに最後の点は、そのまま当たります。

### 同時に、区分へ写すこと自体は先例を持つ

**NIST SP 800-30 Rev.1** は表I-2 で5段階のリスク水準を出しますが、**水準ごとの必須技法を定めません**。管理策の選択・運用認可の可否・監視頻度・優先順位づけの入口として使います。**本標準の SR と同じ使い方です**。

**ISO/TR 14121-2 6.4.3** は数値化について次のように書きます。

> can give **a false impression of numerical accuracy**

**同 6.4.2 の Table 2 は4区分**(high / medium / low / negligible)、**6.5.2 の Cl も4区分**です。区分へ写すこと自体は、機械安全の側にも情報セキュリティの側にも先例があります。

### したがって、争点は「区分へ写すか」ではない

争点は、**その区分が何を主張しているか**です。「SR3 は SR2 より危険である」を主張するなら Cox の批判に答える必要があります。答えられないなら、**主張しないと書くべきです**。

## 決定

### 1. SR は、危険源の大小を正しく順序づけるとは主張しない

**SR の値は、危険源どうしを比較するための量ではありません**。SR3 の危険源が SR2 の危険源より危険であるという主張を、本標準は行いません。

### 2. SR が決めるのは、低減の順序と受容の手続である

SR は次の3つの入口として使います。

- **低減を続けるかどうか**(SR4 が残る間は運用を開始しない)
- **受容の決裁の重さ**(SR2 以上の残留リスクの受容はリスク区分 R1 の決定として扱う)
- **見直しの契機**(自律レベル・実行形態を引き上げた場合の再評価)

いずれも**手続の入口**であり、危険源どうしの比較ではありません。

### 3. 判定の根拠の記述を、区分の値より優先する

計算式を規定しない方針([第6章](/process-compass/phase4-process-design/deliverable-templates/))を維持します。**根拠の記述が無く値だけがある記録は、判定として無効です**。

この方針は3系統の一次情報が支持します。

- **ISO/TR 14121-2 6.4.3** — 数値化は誤った精度の印象を与えうる
- **NIST SP 800-30 2.1** — 見積りの根拠(rationale)を評価の過程で要求することが、再現性と反復可能性を高める
- **ISO 12100** — 尺度と重みを規定しない

### 4. 区分の値を、案件どうしの比較に用いない

**SR の分布を案件間で比較しません**。見積りは自己申告であり、第三者認証を持ちません。比較は、見積りを甘くする誘因を直接与えます。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| SR は順序づけを主張する、と書く | Cox (2008) に答えられない。とくに「性能を検証した研究がほとんどない」に対して、本標準は何も持たない |
| 区分をやめ、パラメータの記録だけにする | 受容の決裁の重さを決める入口が無くなる。SR2 以上を R1 の決定として扱う規定が成立しない |
| 計算式を規定し、値の一貫性を担保する | 3系統の一次情報が反対する。ISO/TR 14121-2 6.4.3 が明示的に警告する |
| 何も書かない(現状) | 読み手は SR が順序づけを与えると読む。書かないことは、暗黙に主張することと同じ |

## 帰結

- 第6章に、SR が主張しないことを明記する
- **SR の値だけを根拠に低減の優先順位を決める運用は、本標準の想定ではない**
- 案件間の SR の分布を集計する指標を置かない
- **Cox の批判のうち「性能の検証がない」は、本 ADR では解消しない**。順序づけを主張しないことで批判の射程から外れるが、検証を与えたわけではない

:::caution[暫定 EV-0027 / 見直し 2027-08]
**対象**: 決定2(SR を手続の入口としてのみ使えば、順序づけを主張せずに運用が成立するという判断)。

**根拠の水準**: E1(間接)。

**根拠とした事例**: NIST SP 800-30 Rev.1 表I-2。

同表は5段階のリスク水準を出しますが、水準ごとの必須技法を定めず、管理策の選択と優先順位づけの入口として使います。**本標準の文脈でこの使い方が機能したという測定を持ちません**。

**差し替え条件**: SR を根拠に低減の優先順位を決めた記録の件数。件数が積み上がる場合、決定2 は守られておらず、実質的に順序づけとして使われていることになります。
:::
