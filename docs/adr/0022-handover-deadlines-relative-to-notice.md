## ステータス

採用(2026-08-06)

## コンテキスト

第2章 2.9.3 は、コンテキスト移管ゲートの期限を絶対日数で定めていた。

| ゲート | 旧規定の期限 |
| --- | --- |
| H-1 移管準備 | 交代の決定から5営業日以内 |
| H-2 書き戻し完了 | 交代日の10営業日前まで |

この2つを両立させるには、通知から交代日まで**最低でおよそ3週間**を要する。

一次調査(`research/phase1/20260806-workforce-mobility.md`)により、この前提の成り立たないことが判明した。JILPT 調査シリーズ No.174「企業の転勤の実態に関する調査」(2017年10月、常用労働者300人以上の企業 1,852社)の転勤前の打診時期(国内転勤、n=1,399)を次に示す。

| 打診の時期 | 割合 |
| --- | --- |
| 1日〜1週間前 | 8.2% |
| 1週間超〜2週間前 | 13.3% |
| 2週間超〜1ヵ月前 | 34.9% |
| 1ヵ月超 | 43.7% |

**少なくとも 21.5% の企業では、旧規定の H-2 を満たせない**。「2週間超〜1ヵ月前」の企業を含めると、成立しない場合はさらに増える。

**満たせない期限を置く制度は、運用されずに迂回される**。第7章 7.2 が例外手続について述べているのと同じ構造にあたる。

あわせて、同統計は**転居を伴う異動のみ**を対象としており、転居を伴わない異動の予告期間は確認できていない。引越しの準備を要しないため、より短い可能性がある。**規定はこの不確実性を吸収できなければならない**。

## 決定

1. **期限を絶対日数で固定せず、予告期間に応じて段階化する**。予告期間は「交代が**本人へ通知された時点**から交代日までの営業日数」とする
2. **起点を通知の時点とする**。組織の内部で決定した日ではない。前任者と後任者が動けるのは通知の後だからである
3. **本標準は予告期間の長さを要求しない**。予告期間は人事制度が定めるものであり、開発プロセスの標準が介入する対象ではない。規定するのは、与えられた予告期間の中で何を行うかである
4. **予告期間を4区分し、H-2 の期限と範囲を区分ごとに定める**。予告期間 5営業日未満では、**交代日の前に H-2 を置かない**
5. **短い予告では、書き戻す範囲を優先順位で絞る**。順位は 組織的文脈 → 運用上の勘所 → 設計の背景と制約 → 却下した選択肢 とし、**入れ替えを認めない**
6. **不足分は交代後へ繰り越す**。繰り越しが生じる場合(予告期間 10営業日未満)、**前任者の関与の延長を H-1 の判定と同時に確定させる**。期間・稼働の目安・連絡手段・繰り越した項目の4点を定める
7. **「必要に応じて協力する」を関与の延長として認めない**。期間と稼働を定めない約束は履行されない
8. **予告期間の区分を申告させない**。通知日と交代日から機械的に導出する。申告させると、期限の緩い区分を選ぶ動機が生まれる
9. **新しいゲートを設けない**。H-1〜H-3 の3つのまま、H-2 の期限の定義だけを変える
10. **2.9.8 は H-3 のみを扱う**ことを明記し、H-2 の不足分の措置(2.9.5)と役割を分ける

## 検討した選択肢

- **旧規定を維持し、予告期間が足りない場合を例外承認で処理する** — 手続は変わらないが、**企業の2割強で常時例外が発生する**。運用の開始と同時に全件が例外になる設計は、ADR-0018 が前提の劣化について退けたものと同じ構造である
- **H-2 の期限を「交代日の前営業日まで」へ一律に緩める** — 満たせない件数は消えるが、予告が十分にある場合でも書き戻しが交代の直前まで先送りされる。**期限は行動の時期を決める装置であり、緩めれば遅くなる**
- **予告期間の下限を本標準が要求する(例: 10営業日以上の予告を求める)** — 手続は成立するが、**人事制度への介入になる**。開発プロセスの標準が異動の予告期間を規定する構成は、受け入れられる見込みがない
- **予告期間の比率(例: 予告期間の25%)で期限を定める** — 連続的に対応できるが、営業日の端数処理が必要になり、短い予告では1日未満の期限が生じる。**4区分の階段のほうが運用と検査の双方で扱いやすい**
- **短い予告では H-2 を省略し、すべてを H-3 で回収する** — 単純だが、**組織的文脈と運用上の勘所は前任者の不在と同時に必要になる**。交代後に回収する設計では、その間の判断が止まる
- **区分を担当者に申告させる** — 実装は簡単だが、期限の緩い区分を選ぶ動機を与える。通知日と交代日は記録できるため、導出できる

## 影響

- 第2章 2.9.3 の期限の表を改め、「予告期間」の定義と一次統計への参照を追加した
- 第2章 2.9.5 に「期限と範囲を予告期間で決める」「短い予告のときに何から書き戻すか」「機械検査」の3節を新設した
- 第2章 2.9.8 の見出しを「H-3 が期限内に合格しない場合」へ改め、2.9.5 との役割分担を明記した
- H-1 の期限を「交代の決定から5営業日以内」から「交代の通知から3営業日以内(予告期間が5営業日未満の場合は翌営業日まで)」へ改めた。**予告期間が短い場合に H-1 が交代日を越える事態をなくすため**である
- H-1 の記録に、交代の通知日・交代日・予告期間・前任者の関与の延長の4欄を必須とした。**機械検査は維持される**
- **新しい記号を導入していない**。予告期間は営業日数で表し、区分に識別子を与えていない。識別子は他文書から参照する必要が生じてから足す(ADR-0018 決定11 と同じ方針)
- 予告期間 5営業日未満の場合、**書き戻しは交代日までに一切行われない**。この状態を制度として認めることになる。認めない設計は、2割強の企業で手続そのものを機能させないため、こちらを選んだ
- 転居を伴わない異動の予告期間は**依然として未確認**である。区分を予告期間から導出する構成にしたため、予告が想定より短くても規定は機能する。ただし**その場合の繰り越し量は本標準の想定を超えうる**
