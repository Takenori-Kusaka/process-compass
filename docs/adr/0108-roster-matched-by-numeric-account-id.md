## ステータス

採用(2026-11-05)。[ADR-0070](/process-compass/adr/0070-gate-record-medium-and-field-sources/) 決定8 の保全の条件のうち「アカウントと人の対応表」(第4章「判定の成立」)を補います。置き換えません。

## コンテキスト

第4章「判定の成立」の保全の条件は、アカウントと人の対応表に、ログイン名に加えてアカウントの数値の識別子を持つことを求め、ログイン名だけの対応表では承認者を同定できたものとして扱わないとしていました。準拠テンプレートの照合(`findPersonByAccount`)はログイン名の文字列一致だけで、契約検査は名簿に数値を書くと失敗させました。数値の識別子は、写し・PR の検査の入力・ホスティングの照会のどこでも取れていましたが、照合に使われていませんでした。この規定には実装マークが無く、降りていない規定として台帳に出ていませんでした(#429 の内部調査)。

品質監査の委員は、テンプレートがレビューの書き手のリポジトリとの関係(`author_association`)を見ないため、名簿の人が改名し旧名を第三者が取ると、その第三者の承認や宣言行のレビューが名簿の人の操作として数えられることを示しました。PR の時点の検査が、名簿に対応づかない作成を指示した者を黙って落とし、出荷の集約と判定が割れることも示しました。

GitHub のログイン名は、改名すると直ちに、削除の後は 90 日で他人が取得できます。数値の識別子は REST と GraphQL で引け、ルールセットの迂回者も数値で照合されます(外部調査、2026-11-05 時点)。

## 決定

### 1. 数値の識別子の要求を維持し、すべての照合へ広げる

ホスティングの記録を名簿の人へ対応づけるすべての照合(承認者・判定者・効力を持つ記録の帰属・作成を指示した者)を、数値の識別子で行います。ログイン名だけで対応づけた者を、同定できたものとして扱いません。ログイン名が一致し数値の識別子が異なるアカウントを、名簿の人へ対応づけません。作成を指示した者をアカウントで書いた場合は、検査の時点に数値の識別子へ解決し、解決した値と時点を残します。

### 2. 移行期間を置かない。写しの数値の識別子から移す

移行は、名簿の要素に数値の識別子を許すこと、記録用ブランチの写しが承認の時点に記録した数値の識別子から提案すること(名簿へ入れるのは人)、名簿とホスティングの食い違いを所見で示すことの 3 つを組み合わせます。移行期間のあいだログイン名だけの照合を数えて開示する案は、採りませんでした。本文の要求と食い違ううえ、写しから移せば移行を一度に済ませられ、期間を置く理由が無いためです。現在のホスティングから数値を引く方法の対象は、写しで見つからない人だけです。改名の後に他人が取ったログイン名を解決すると、別人の数値を固定するためです。

### 3. 「リポジトリの外側で保守する」を性質の要求に改める

以前の文は置き場の理由を本文に書いておらず、時点の名簿の対応(IMPL-0094。構成の履歴から承認の時点の名簿を引く)と食い違っていました。名簿の変更を効力を持つ記録(D-0 の決定の記名)として扱い、効力の前に帰属を裏づける要求に改めます。帰属の照合は IMPL-0415([#428](https://github.com/Takenori-Kusaka/process-compass/issues/428))で降ろします。

### 4. リポジトリとの関係を持たないアカウントの承認を数えない

レビューの書き手のリポジトリとの関係が、所有者・組織の構成員・招待した協力者(OWNER・MEMBER・COLLABORATOR)のいずれでもない承認と宣言行のレビューを数えません。この値は権限の強さではなく関係を示し、読み取りの権限の協力者も含みます。協力者に招いていない外部の確認者の承認は数えられなくなるため、外部の確認者は読み取りの権限でよいので協力者に招きます。数値の識別子への切り替えの前でも、旧名の取得による誤同定を防ぐためです。関係の値を持たない古い写しでは判定しません。PR の時点の検査は、名簿に対応づかない作成を指示した者がいる PR の承認を数えません(出荷の集約と揃える)。

### 5. 降ろす順序

数値の識別子による照合への切り替えは、名簿へ数値を入れる経路(決定2)と同じ単位で [#430](https://github.com/Takenori-Kusaka/process-compass/issues/430) に降ろします。経路より先に切り替えると、既存の採用者の承認がすべて同定できない側へ一度に落ち、名簿を直す手段が無いまま記録の欠落が出続けるためです。変更量を理由にしたのではありません。決定4 は本 ADR の時点で降ろします。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| ログイン名だけの照合を、期限つきで数えて開示する(M5) | 本文の要求と食い違う。写しから移行でき、期間を置く理由が無い |
| 数値の識別子を別の欄に並べる(M2) | 名簿の要素と数値の対応が離れ、食い違いを生む |
| 対応表をリポジトリの外へ出すだけ(M3) | 時点の名簿の対応が失われ、外の対応表の変更の帰属を確かめる手段が無い |
| 現在のホスティングから一律に数値を引く(M4 の単独) | 改名の後に他人が取ったログイン名を解決すると、別人の数値を固定する |
| 「リポジトリの外側」の文を維持する | 理由が無く、時点の名簿の対応と食い違う |
