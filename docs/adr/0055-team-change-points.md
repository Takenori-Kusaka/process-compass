## ステータス

採用(2026-09-30)

次の1点は、既存の決定への補足です。採用済みの ADR の本文は書き換えません。

- [ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)「影響」の「安全重要度 CL1 以上および規制業では、1〜2名の構成そのものを拒否する」は、初期化での拒否を指すと読む。運用中に人が離脱した場合は、拒否しない。拒否すると、旧い構成が残るためである。離脱を構成へ反映したうえで、出荷できない状態として表示する(決定5)

## コンテキスト

オーナーは、外部の変化への対応力が弱いと指摘しました(2026-09-02)。人が増える・減る、目的や納期が変わる、といった変化点を反映する手段が無いためです。品質保証部門の立場からは、体制や AI の構成が変わっても品質保証部門へ知らされない、という指摘が出ています(`research/phase4-standard/284-council-03-qa-audit.md`)。

### 手続は散在しており、束ねる規定が無かった

弁護役の意見書(`284-council-05-defender.md`)が示したとおり、個々の変化点には既に規定があります。

| 変化点 | 既存の規定 |
| --- | --- |
| 現任者の異動 | 3.13、D-0 の更新の契機 |
| 結果責任者・文脈オーナーの交代 | 2.9(移管ゲート H-1〜H-3) |
| 3名以上になる | 3.5.2 の例外の失効 |
| モデルの差し替え・廃止・障害時の切替 | 3.12.3、3.12.5、3.12.6 |
| 目的・納期・範囲の変更 | 2.10(スコープ3層)、7.6、7.10 |
| ステージ移行 | SG、軸B |
| 自律レベルの変更 | 5.4.5、5.4.6 |

欠けていたのは次の3つです。

- これらを1つの記録へ束ねる手続。変化点の後に、どの確認が無効になったかを特定する規定が無い
- 再テーラリングの契機。準拠テンプレートには「体制やステージが変わったときに再実行する」とあるが、標準の第8章には無い。**テンプレートが標準に無い規範を持っており、正本の向きが逆になっていた**([ADR-0040](/process-compass/adr/0040-template-forms-as-subset-of-standard/))
- 担い手の運用形態([ADR-0054](/process-compass/adr/0054-seat-accountable-performer/))と、AI の担い手の識別の変更を扱う規定

### 外部の調査で分かったこと

- 製造の 4M 変化点管理の解説は、担当者の変更・増員・欠勤・交替を変化点に数える。労働安全の変更管理は、手順へ波及する人員削減と再編を対象にし、波及しない組織変更を対象外に置く(FND-0019、E1)
- モデル・指示・ツール・権限の変更を、リスクの再評価と統制の再試験の契機に挙げる指針がある(FND-0191、E1)
- 機能安全の規格は、確認措置の完了後に対象が変わったとき、関係する確認措置をやり直すか補うよう求める(`SRC-0526`)
- 変化点管理を開発体制や AI の編成へ転用した例と、その効果の測定は見つからなかった(FND-0020、E1)

## 決定

### 1. 変化点に数えるもの

D-0 体制図、テーラリングの入力(軸A〜E)、担い手の適合性確認の前提、のいずれかを変える変化を、体制の変化点とします。

| # | 変化点 |
| --- | --- |
| 1 | 責任者の増減・交代・長期の不在、兼務の変更。責任者でない担い手(人)の増減・交代は、兼務禁止と独立の再判定に影響する場合、または人数の境界を通過する場合に限り数える |
| 2 | 人数の境界の通過(3名未満と3名以上、10名) |
| 3 | 担い手の運用形態の変更と、委任の範囲の変更 |
| 4 | AI の担い手の識別の変更(モデルの版・提供者、指示資産の恒久層、ツールと権限、実行基盤) |
| 5 | 軸B〜E の入力の変化(ステージ移行、規制への該当、委託への切替、安全重要度) |

席の責任者は席ごとに1名です。席の作業を複数の人で担う体制(開発者5名、独立レビュア2名など)では、成果物ごとの結果責任者を担当表(D-0)で1名に定めます([ADR-0054](/process-compass/adr/0054-seat-accountable-performer/) 決定1)。責任者でない担い手の出入りのすべてに手続を課すと、人数の多い体制では手続が常時走り、読まれなくなります。数えるのは、統制の成立を左右する出入りです。

### 2. 変化点に数えないもの

次は数えません。数えないと決めたことを条文に書きます。

- 目的・範囲・納期・予算の変更のうち、決定1 の1〜5 へ波及しないもの。これらは 2.10、7.6、SG が扱う
- 納期だけの変更。起票された場合は「構成の変更なし」と記録する
- 短期の不在。3.9.3 の代理指名による
- 版を固定したままのセッションの再起動と、並列数の変更
- 提供者の障害・利用上限で AI が使えない期間。3.12.5 が扱う。ただし、期間と、その間の扱い(人へ戻した / 止めた)を D-0 の改訂履歴に記録し、保証の開示の項目7 に出す
- 個々の変更のリスク区分の判定。変更ごとの判定であり、体制の変化ではない

納期を理由に統制を外す要求は、納期の変更としてではなく、**統制を緩める向きの変更**として決定5 の判定に掛けます。

3.12.5 の一時的な切り替えの間は、担い手の識別が変わります。変化点の手続は課しませんが、切り替えの間は委任を協働へ下げます。

### 3. 変化点の後、最初のゲート判定より前に D-0 と構成を改める

期限を日数で定めません。値の根拠が無いためです。事象で定めます。

| 段階 | 誰が | 何をするか |
| --- | --- | --- |
| 起票 | 気づいた者。1・2・5 は文脈オーナー、3 は対象の席の責任者、4 は AI維持管理者と AI運用担当者が責任を持つ | 変化点を D-0 の改訂として起こす |
| 決定 | D-0 体制図の決定の権限を持つ者。D-0 表1「体制と運用形態」の決定者を指す。緩める向きの変更は、対象の席の責任者が決定してもよい(決定5)。席の責任者の任免は、この決定者の記名を要する(下記) | 新しい体制と運用形態を確定する |
| 再導出 | 文脈オーナー | テーラリングを再実行し、構成と、実行主体が起動時に参照する内容(3.5.3)を再生成する。兼務禁止を機械で検査する |
| 失効 | 自動 | 3名未満の例外(3名以上になった時)、適合性確認(担い手の識別が変わった時)、適合性確認の承認(承認した席の責任者が交代した時)、暫定任命の期間 |
| 無効になった確認の特定 | 文脈オーナー | 仕掛かり中の成果物のうち、作成を指示した者と確認する者の関係が変わったものを挙げ、確認のやり直しの要否を決める |
| 移行 | 席の責任者 | 新任の責任者は暫定任命(3.4.1)、新しい担い手は適合性確認まで協働を上限とする |

成立済みの判定記録は書き換えません([ADR-0036](/process-compass/adr/0036-gate-closure-by-record/))。変化点をまたぐ未完了の判定は、新しい体制の判定者が引き継ぎます。

席の責任者の任免は、決定の段階で次のとおり扱います。

| 変化 | 扱い |
| --- | --- |
| 席の責任者を任命する。別の人へ交代させる。空いた席へ後任を置く | 決定である。D-0 表1「体制と運用形態」の決定者の記名と理由を要する。統制の向きにかかわらず要する |
| 人が体制から外れる。席が空く | 発生である。記名を待たず、即時に構成へ反映する(決定5) |
| 決定者その人を替える。決定者の席の責任者の交代と、表1 の決定者の変更が当たる | 前任の決定者の記名と理由を要する。前任者が体制から外れている場合は、組織上の任命権者の記名と理由を要する |
| 初回の記入。どの席にも責任者が記入されたことのない状態から、全席を記入する(人数に依らない) | 初期の設定として、D-0 表1「体制と運用形態」の決定者の席に記入する人の記名と理由で受け付ける。1人体制では本人が記名する。全員が離脱して全席が空いた状態は初回に当たらず、組織上の任命権者の記名による |

- 任免に決定者の記名を求めるのは、記名なしで席の責任者を替えられると、替わった者の名義で緩める向きの決定が通るためである
- 離脱と後任の任命を分ける。離脱は事実であり、決定を待つ対象ではない。後任を置くこと、別の人へ替えることは決定である
- 組織上の任命権者は、体制の外の人として D-0 体制図へ記載する。任命権者の記名で決定者を任命した場合は、その旨を変化点の記録と保証の開示へ表示する
- いずれの記名も、AI の名義を受け付けない

個別の変化点には、次を定めます。

- 暫定任命の期間中は、確認済みの者による併記を求める(3.4.1)。併記する者を置けない場合は、その判定を未達として表示する
- 適合性確認を承認した席の責任者が交代する変化点(離脱を含む)を、承認者であることを理由に止めない。承認は新しい責任者へ引き継がず、失効させる。新しい責任者が承認し直すまで協働を上限とする。厳しくする向きであり、即時に適用する。担い手の識別が変わっていなければ、確認の記録は有効なまま残る
- 担い手の識別を変える前に、新しい識別の適合性確認を済ませてよい。席の責任者が委任を続ける決定として記名した場合は、協働へ下げずに切り替えられる(第3章 3.4.2 の4条件)
- 安全重要度が上がり、委任を適用できなくなったときは、抜き取り待ちの委任の変更を、協働の手続で全件確認し直す
- ステージを前へ戻す変更(軸B を PoC へ戻すなど)は、記名と理由だけでは足りない。ステージ移行ゲート(SG)の判定を要する

### 4. 記録は D-0 の改訂履歴と構成の変更記録に置く

新しいゲート・会議体・台帳を作りません。記録する内容は次の6点です。

- 変化点の種別・日付・変更前後の D-0 の版
- 兼務禁止と独立性の再判定の結果
- 無効になった確認と、やり直しの要否
- 失効した適合性確認と例外、再確認の期日
- 決定した自然人
- 即時に知らせる事象(決定7)では、通知先と通知日。通知する者と通知先が同一人物である場合は、その旨

「構成の変更なし」という結果も記録します。納期だけの変更が起票された場合も、この結果を記録します。

変化点に数えない事象のうち、提供者の障害・利用上限で AI が使えなかった期間は、D-0 の改訂履歴へ記録します。記録するのは、期間と、その間の扱い(人へ戻した / 止めた)です。

構成と D-0 の書き換えには、次を定めます。

- **構成を書き換えるのは、変化点の手続だけとする**。手で構成を編集する運用を置かず、案内もしない。手で書き換えた構成は、記名と理由を残さないまま統制を緩められる
- 構成の変更記録は、追記だけで保つ。過去の記録の削除と差し替えを、検出できる形で持つ(決定6)
- D-0 のうち、構成から導ける欄(席・責任者・担い手・運用形態の表、委任の範囲、改訂履歴)は、構成から生成してよい。その場合は構成を正とする。生成した欄が構成に一致することを、機械で検査する。人が書くのは、決定の理由と記名に限る。同じ内容を二重に記入させると、片方だけが改められる

### 5. 緩める向きは判定、厳しくする向きは即時

統制を緩める向きの変更(人の確認を減らす、委任の範囲を広げる、ゲートを省略へ変える)は、記名と理由を要します。厳しくする向きの変更は、即時に適用します(5.4.5・5.4.6 と同じ非対称)。

- 緩める向きの決定をするのは、対象の席の責任者、または D-0 体制図の決定の権限を持つ者(D-0 表1「体制と運用形態」の決定者)である。**AI の名義の記名を受け付けない**
- 委任の範囲を狭める変更は、厳しくする向きである。即時に適用する
- ステージを前へ戻す変更は、記名と理由に加えて、ステージ移行ゲート(SG)の判定を要する(決定3)

**人の離脱で成立しなくなった統制は、緩める向きの決定ではなく、未達の発生です**。決定を待つ対象ではありません。

- 記名を待たず、即時に未達として構成へ反映し、表示する。旧い構成のまま止めない
- 未達の発生として扱うのは、体制内の人が実際に減った場合と、席の責任者が体制から外れた場合に限る
- 人が減っていないのに人の確認を減らす変更(独立レビューの確認者を外す、承認の数を下げる)は、緩める向きの決定である。記名と理由を要する
- 未達のまま出荷するかどうかは、既存の規定による。R1 の変更は 7.3 の例外承認を要する。CL1 以上と規制業では出荷できない

体制の縮小を緩める向きの決定として扱うと、記名が済むまでの間、成立していない統制が成立として表示され続けます。

### 6. 申告だけに頼らない

宣言と実態のずれを機械で検出します。対象は、宣言した人数と直近の承認者の数、宣言した担い手の識別と実際に動いたモデル、判定記録が参照する D-0 の版と構成の D-0 の版です。

あわせて、変化点の手続を経ない構成の書き換えを機械で検出します。検出するのは次の2つです。検出した書き換えは取り込まず、変化点の手続を経て出し直します。

- 構成が変わっているのに、変更記録の追記が無い状態
- 変更記録の切り詰めと差し替え。変更を取り込む先の版の変更記録と比べる

構成と変更記録を同時に書き換える改ざんは、手元の検査だけでは検出できません。止めるのは、変更を取り込む先の版との比較と、構成の変更に AI維持管理者の承認を要することです。

### 7. 品質保証部門へは、出荷記録の中で知らせる

期間中の変化点は、出荷ごとの「保証の開示」([ADR-0056](/process-compass/adr/0056-assurance-argument/))へ集約します。即時に知らせるのは、次の6つに限ります。通知先は、出荷判定者の席の責任者です。

- 人数の境界の通過
- 運用形態の変更
- 権限の一時制限(7.9)の発動
- 検出の層に数えている AI の担い手の識別の変更。検出率の測定値が失効するためである
- 独立レビュー(G-6)が、成立から未達へ変わる変化。責任者が同一人物になり、成立しなくなる場合を含む。人数の境界を通過しない変化でも知らせる
- 出荷判定者の席の責任者の交代

通知するのは、変化点を起票する責任を持つ者です(決定3)。人数の境界の通過は文脈オーナー、運用形態の変更は対象の席の責任者、AI の担い手の識別の変更は AI維持管理者と AI運用担当者が通知します。独立レビューが未達へ変わる変化と、出荷判定者の席の責任者の交代は、文脈オーナーが通知します。権限の一時制限の発動は、発動を記録した者が通知します。発動を記録するのは、見逃しの区分を判別する品質保証の機能です(第5章 5.6.3、第7章 7.9.6)。通知した者は、通知先と通知日を変化点の記録へ書きます(決定4)。通知のための台帳を別に作りません。通知先と通知日の無い即時の通知は、記録の欠落として扱います。

通知先には、次を定めます。

- 出荷判定者の席の責任者が交代する変化点では、新任者に加えて前任者へも通知する。前任者が体制から外れている場合は、D-0 表1「体制と運用形態」の決定者へ通知する。新任者だけへ通知すると、交代の事実が、交代した本人にしか届かない
- 品質保証部門を置く組織は、D-0 体制図に部門の通知先を定めてよい。定めた場合は、すべての即時の通知をそこへも送る。本標準は、部門の設置を要求しない
- 通知する者と通知先が同一人物である場合は、通知の記入を求めない。「通知する者と通知先が同一」と記録し、表示する。1人体制が当たる。部門の通知先を定めている場合は、そこへの通知を記録する

### 8. 再テーラリングの契機を第8章に置く

第8章へ、決定1 の変化点を再テーラリングの契機として規定します。準拠テンプレートは、変化点の種別を入力とし、構成の差分・失効と発生の一覧・残作業を出力する手段を持ちます。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 変化点のための新しいゲート・台帳・会議体を置く | 個々の手続は既にある。体制への転用の効果測定は無く、独立した手続を新設する根拠が弱い。7章の「新しい経路を足さない」に反する |
| 目的・納期の変更を一律に変化点へ数える | 既存の 2.10・7.6・SG と二重になる。体制・軸・委任の範囲へ波及する場合に限る |
| 変化点から D-0 の改訂までの日数を定める | 値の根拠が無い。「最初のゲート判定より前」という事象で定める |
| 申告制だけで運用する | 申告しないほうが楽な側へ崩れる。宣言と実態のずれを機械で検出する |
| モデルの変更のたびに、出荷済みの成果物を再検証する | 成果物の正しさの根拠は検証の記録であり、生成の条件ではない。再確認するのは工程の検出能力である |
| 体制の縮小を、緩める向きの決定として記名を待つ | 記名を待つ間、成立していない統制が成立として表示され続ける。人の離脱は決定ではなく事実であり、未達の発生として即時に反映する |
| 責任者でない担い手(人)の出入りを、すべて変化点に数える | 人数の多い体制で手続が常時走る。統制の成立を左右する出入り(兼務禁止と独立の再判定、人数の境界)に限る |
| AI が使えない期間を変化点に数える | 体制・軸・担い手の識別は変わらない。ただし期間と扱いは記録し、保証の開示へ出す |
| 構成を手で編集し、テーラリングの入力から再生成する経路を残す | 記名・理由・変更記録を残さずに、委任の一式の書き込みもステージの前戻しも通る。構成を書き換えるのは変化点の手続だけとする |
| 人が減っていない場合も、入力の変更で確認が成立しなくなれば未達の発生として扱う | 記名と理由なしに人の確認を減らす経路になる。人が実際に減った場合に限る |
| D-0 と構成の両方を、人が記入する | 変化点のたびに二重の記入が要り、片方だけが改められる。構成から導ける欄は生成してよいものとし、その場合は構成を正とする |
| 席の責任者の交代を、向きを持たない変更として記名なしで通す | 交代した者の名義で、緩める向きの決定が通る。任免は、D-0 表1「体制と運用形態」の決定者の決定である |
| 決定者の交代を、新任者本人の記名で通す | 決定の権限を、権限を持たない者が自分へ与える形になる。前任の決定者、または組織上の任命権者の記名を要する |
| 即時の通知を、品質保証部門へ直接送ることを必須にする | 本標準は部門の設置を要求しない。通知先は出荷判定者の席の責任者とし、部門を置く組織が通知先を足せる形にする |
| 1人体制でも、自分への即時の通知の記入を求める | 通知する者と通知先が同一であり、記入は何も伝えない。同一である事実を記録して表示する |

## 帰結

- 3.13 を「体制の変化点」へ拡充し、第8章へ再テーラリングの契機を置く
- D-0 体制図へ改訂履歴の欄を足す
- 準拠テンプレートへ、変化点を反映する手段を置く
- **起票されない変化点は検出できない場合がある**。機械で検出できるのは、人数・担い手の識別・版の不一致と、構成の書き換えに限る
- 定期異動の時期には、変化点の処理が集中する

:::caution[暫定 EV-0043 / 見直し 2027-03]
**対象**: 決定1〜3(体制の変化点の列挙と、最初のゲート判定より前に改めるという手続)。
**根拠の水準**: E1(間接)。
**差し替え条件**: 変化点の後に D-0 の改訂を経ずに成立した判定の件数と、変化点の前後での差し戻し率・検出率の記録。列挙に無い変化で統制が崩れた事例の件数。改訂を経ずに成立した判定が1件でも生じた場合、「最初のゲート判定より前」という定めは申告では守られないことになり、手続を機械の強制へ改める。列挙に無い変化による統制の崩れが1件でも生じた場合、その変化を列挙へ加える。変化点の後に検出率が下がった場合、移行の定め(暫定任命、協働の上限)では足りないことになり、移行の条件を強める。

製造と労働安全の変更管理からの類推です。開発体制や AI の編成へ転用した例と、その効果の測定は見つかっていません。
:::
