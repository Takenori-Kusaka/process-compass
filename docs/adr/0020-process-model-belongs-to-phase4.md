## ステータス

採用(2026-08-06)

## コンテキスト

統合プロセス参照モデルの置き場については、**既存プロセスの体系に新設が混じっていること**と、**フェーズ4からそこへ参照が張られていること**の2点が問題として挙がっていた。

[ADR-0017](/process-compass/adr/0017-separate-proposal-from-catalog/)は前半だけを解決した。一覧・横断比較表・サイドバーから提案を分離したが、**URL は `/processes/integrated/` のまま据え置いた**(同 ADR 決定2)。その結果、次が残っていた。

- **場所**: `/processes/` は既存プロセスの調査結果を置く名前空間である。本プロジェクトの提案が今もその配下にあった
- **参照の向き**: 第4章が「参照モデルの8ゲートを詳細化します」、第6章が「参照モデルの成果物を…」と書いており、**規範文書が別ページに従属して読める**構成になっていた
- **位置づけ**: サイドバーは参照モデルを「フェーズ3の出力・フェーズ4の入力」としていた

第1章から第8章と附属書A〜F が揃った現在、参照モデルは標準の**入力**ではない。[ADR-0010](/process-compass/adr/0010-data-doc-interface/)が定めるとおり、構造(要素の存在・識別子・関係)の正本はデータ側、判定基準の正本は本文側であり、両者は**同じ標準の2つの表現**にあたる。入力と出力の関係ではない。

## 決定

1. **統合プロセス参照モデルを本標準(フェーズ4)の一部として位置づける**。フェーズ3の出力でも、フェーズ4の入力でもない。**本標準が規定する構造の機械可読表現**とする
2. **URL を `/phase4-process-design/process-model/` へ移す**。ADR-0017 決定2(URL の据え置き)を本決定で置き換える
3. **旧 URL からリダイレクトする**。第1階層から第3階層までの全経路にスタブページを生成し、`meta refresh` と `canonical` で転送する。外部リンクを壊さない
4. **サイドバーの独立セクションを廃し、フェーズ4セクションの先頭へ置く**。ADR-0017 決定1 の「フェーズ3の後、フェーズ4の前」を本決定で置き換える
5. **本文の参照の向きを反転する**。「参照モデルを詳細化する」ではなく「本標準が規定する。構造の機械可読表現は参照モデルにある」と書く
6. **[ADR-0010](/process-compass/adr/0010-data-doc-interface/)の正本分担は変更しない**。要素ごとの正本(構造=データ / 判定基準=本文 / 用語=第1章 1.4)はそのまま維持する
7. **手書きのプロセスページを作らない**。移設後もスキーマ駆動の生成を維持する([ADR-0007](/process-compass/adr/0007-schema-driven-process-data/))。描画は共通コンポーネントへ切り出し、カタログと参照モデルの両方から使う
8. **URL の組み立てを1か所へ集約する**。`processPathSegment()` を唯一の分岐点とし、リンクの手書きを禁止する

## 検討した選択肢

- **URL を据え置き、本文の言い回しだけ直す** — 変更量は最小で、リンクも壊れない。しかし指摘の一方である「カタログに混じっている」状態が URL に残る。サイトの構造を URL から読む利用者には解決していない
- **参照モデルのページを廃し、本文へ統合する** — 位置づけの曖昧さは完全に消えるが、ADR-0007(スキーマ駆動)とプロセス提案ツール(M7)の前提を壊す。データは提案ツールの知識ベースそのものである
- **`/processes/` 全体をフェーズ1配下へ移し、参照モデルだけ残す** — 対称性は上がるが、カタログ側の URL が全件変わる。壊す範囲が本件の目的に対して大きすぎる
- **リダイレクトを置かず URL を切り替える** — 実装は単純だが、公開済みのページであり外部からの参照を壊す
- **ページを複製し、両方の URL で提供する** — リンク切れは起きないが、同一内容が2つの URL に存在する。検索の重複と、どちらが正かの判断を利用者へ委ねることになる

## 影響

- `src/pages/phase4-process-design/process-model/` に3階層のルートを新設した。`/processes/[process]/` 側は `integrated` を除外する
- 描画を `src/components/process/`(Overview / Phase / Activity)へ切り出した。**カタログと参照モデルは同一のコンポーネントを共有する**ため、表示の差分は生じない
- `src/pages/processes/integrated/[...path].astro` を追加し、旧 URL の全経路(第1〜第3階層)にリダイレクトのスタブを生成する
- `src/lib/process-diagrams.ts` に `processPathSegment()` と `PROCESS_MODEL_ID` を追加した。Mermaid 図の `click` 先もこの関数を通る
- `astro.config.mjs` のサイドバーから独立セクションを削除し、フェーズ4セクションの先頭へ移した。リンク検証の除外に新 URL を追加した
- ドキュメント9ファイルと `src/pages/tool/simulator.astro` の参照先を更新した
- 第4章・第6章・第8章・附属書A の導入文を、本標準を主語とする表現へ書き換えた
- **[ADR-0017](/process-compass/adr/0017-separate-proposal-from-catalog/)の本文は書き換えていない**。同 ADR の決定1(配置)と決定2(URL)を本 ADR が置き換える。決定3〜6(カタログの名称、一覧・比較表からの分離、階層レベルの表示名)は引き続き有効である
- リダイレクトのスタブは `meta refresh` である。HTTP 301 ではないため、検索エンジンの評価の引き継ぎは保証されない。GitHub Pages では HTTP リダイレクトを設定できないため、この方式を採った
- ページ数が 202 から 225 へ増えた。増分は参照モデルの新 URL(6ページ)とリダイレクトのスタブ(17ページ)である
