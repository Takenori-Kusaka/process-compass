## コンテキスト

- [#457](https://github.com/Takenori-Kusaka/process-compass/issues/457): 所有者の意見(2026-11-27。決定ではなく審議の入力)。チケットのように、目的・ゴール・調査・ステップ・インプット・結果を追えること。すべての記録を取るのではないこと
- 内部の調査で、既存の記録の切れ目を見つけた。理由を途中のコミットのメッセージへ書く勧めは、スカッシュで既定ブランチに残らない(K7)。途中のコミットのトレーラ `Agent-Run`・`Agent-Assets` を、スカッシュの後へ運ぶ仕組みが準拠テンプレートに無い(K8)。`Spec` が Issue の番号か `setup` の変更は、目的へ辿れない(K1)
- #361 の試行(2026-11-26)が、スカッシュの2つの設定を観測している。設定「PR の題名と本文」のメッセージは、題名・本文・GitHub が足す段落だけで、途中のコミットのメッセージを含まない(K7 の形。単一事例)。途中のコミットのトレーラが残るかは観測していない(K8)
- 外部の調査で、追跡を規範にした規格は、成果物の鎖(要求・試験・結果)を扱っていた。調査と入力を1本に含めることを求める規格は、読めた範囲に見つからなかった。変更の単位で調査の記録を求める規格も、読めた範囲に見つからなかった(調査の限界つき。「無い」ではない)
- 所有者の「チケット」の欄(目的・検証・インプット・理由)は、PR の様式と既存の記録が既に持つ。足りなかったのは新しい様式ではなく、どの記録を起点に読むかの記述と、起点の記録が既定の運用で残ることだった

## 決定

1. 条項・様式・欄を足さない。後から1つの変更を辿る起点を、既定ブランチのコミットから引ける PR の本文とする。PR を経ないコミットは、コミットのメッセージを起点とする。順序と辿れない箇所を、フェーズ5 PR 運用リファレンスの「後から1つの変更を辿る」に置く。附属書 H H.3 のブラックボックス化の2行(何をしたか、なぜそう作ったか)は2行のまま保ち、列を書き換える。機械の記録と人の記録で、止め方の区分が違うためである
2. 作業上の選択の理由の記録先の勧めを、マージの方式に依らず、既定ブランチか PR から辿れる所とし、PR の本文を既定にする。Draft の段階から選択のたびに書き足す。途中のコミットのメッセージだけに書くと、準拠テンプレートが勧めるスカッシュの設定(PR の題名と本文)では既定ブランチに残らない(置き場を限る規定ではなく、勧めの理由である)。PR を経ないコミットは、コミットのメッセージへ書く。5.5.1 の条文は変えない
3. 5.8.2 の「変更単位ごと」の生成の条件の記録は、その目的(同じ条件で生成された他の成果物の一覧)から、既定ブランチへ取り込んだ後も変更から引けることを含むと読む。条文は変えない。取り込みの後に引けない部分を、実装マーク IMPL-1061 として `未達` で表示する。IMPL-0207・IMPL-1019・IMPL-1033 は、主張する範囲が降りているため、`delivered` のまま保つ。運ぶ手段は準拠テンプレートの束 D1 で決める
4. 調査の記録の範囲を、ADR-0267 の決定1・6 のまま広げない。調査の結果は、既存の器へ寄せる。設計上の選択を決めた調査は判断記録(2.6)、確かめないまま置いた言明を残した調査は機能仕様の「前提」の表(トレーラ `Spec` から辿れる)、作業上の選択を決めた調査は 5.5.1 の理由の記録の所在(PR の本文から辿れる)である。前提の台帳(第6章 テンプレ10)は、本標準が置いた前提の観測の様式であり、寄せ先にしない([ADR-0075](/process-compass/adr/0075-acceptance-criteria-coverage-premises-and-ai-findings/))。人が調査そのものを依頼した作業の結果は、作業の成果物であり、追跡の記録ではない。成果物として扱うとは、その種類の既存の規定に従うことで、新しい確認の手続を足さない
5. 辿れることは機械で確かめない(manual)。受入基準の識別子で検証の記録を引く形は、様式の例で勧め、機械で検査しない。識別子の存在は、整合を意味しない

## 採らないと決めたこと

| 案 | 採らなかった理由 |
| --- | --- |
| 現状を保つ | 理由の記録先(K7)と生成の条件(K8)の欠けが残る。辿れることを主張しないので、辿れない箇所を欠陥と判定できない |
| 追跡を要求事項にする(G-6 基準6 に識別子を足す) | 採用者への新しい義務。識別子の存在は整合を意味しない。形式だけの記入へ寄る。ADR-0267 が G-6 の範囲を守った線に触れる。受入基準の識別子の欠けが実行で多いと分かったときに再検討する |
| チケットの様式を新設する | 既存の記録と内容が重なり、片方だけ直って食い違う。ステップの欄は 5.8.6 要求事項8(AI に操作の要約を生成させない)と衝突する。AI が書く欄は捏造しうる |
| H.3 の2行を1行に寄せる | 機械の記録と人の記録の区分が1つの升に混ざり、最も弱い止め方の導出(ADR-0266 決定5)が粗くなる |
| **「何を調査したか」の全件の記録(読んだ資料・調べた事項・効かなかった調査)** | **所有者の意見のうち、採らないと決めた部分。** 書くのが作成側で、作成側の主張にとどまり、判定に数えられない。AI が書く「何を調べたか」は捏造しうる。変更の単位で調査の記録を求める規格は、読めた範囲に見つからなかった。後から書くと事後の作文になり、AI の自己説明は実際に使った手掛かりを反映しない |
| 実行の記録の保持を標準の義務にする | 会話に秘密・個人情報を含みうる(ADR-0267 決定6)。採用者への新しい義務を支える実測が無い。所有者の「すべての記録を取るのではない」とも衝突する。申告でなく事実で「どのインプットに基づいたか」に答えうる唯一の案であることは記録する。インシデントや監査で、実行の記録が無いために影響範囲か原因を特定できなかった事例が出たときに再検討する |
| 5.8.2 へ「既定ブランチに残るコミットが生成の条件を持つこと」の一文を足す | 目的から読める。条文へ足すと細かい定義が増える。読みは本 ADR に置く |
| K8 の表示を `開示` にする | `開示` は「本標準が統制を置かず、主張しない」の意味。5.8.2 は統制を置いている。降りていないだけなので、ADR-0028 により `未達` |
| IMPL-1033 を `undelivered` にする | 降りている警告まで降りていないと表示する。欠けは運ぶ処理の側にある |
| スカッシュの設定をコミットのメッセージを含む形に変えて K8 を直す | 途中のトレーラが本文の中の段落に入り、末尾の段落だけを読む規範(ADR-0172)と衝突する。`Spec`・`Risk`・`Delegated` の読み方へ波及する |
| 第7章の例外承認で受ける | 7.3 は、満たさない判定基準を進める逸脱の手続である。本件は義務の有無の問題で、書かれていない義務を例外で埋められない |

## 影響

- 読む者(保守・インシデント対応・内部監査)は、PR の本文から、仕様・検証の記録・判断記録・生成の条件へ、1本の順序で辿れる。辿れない箇所は、手引きの表に開示されている
- 理由の記録先が、準拠テンプレートが勧めるスカッシュの設定でも既定ブランチから辿れる所になる。設定A(コミットの箇条)とマージコミットでは、PR の本文はホスティングの画面にしか無い。ホスティングの保持は保管ではない。理由は判定の根拠に数えない(ADR-0267 決定3)ので、判定の記録の保管と同じ重さは課さない
- 辿れることを機械は保証しない。PR の本文は作成側の主張で、起点にすることは判定の根拠に数えることではない
- 準拠テンプレートへの降ろしは束 D1 で行う(IMPL-1050〜1052・IMPL-1061)。降りるまで、実装台帳に「降りていない」と表示し続ける。#457 は束 D1 で降りるまで閉じない
- 本決定は採用者への新しい義務を足さない
- 再検討の契機: 抜き取りの監査で、本文に無い箇所へ到達できなかった件数が出たとき。#361 の GitHub 上の観測で、途中のトレーラが残ると分かったとき

## 根拠水準

- EV-0365: PR の本文を起点に辿れることが、後からの説明を支えること(E0)
- EV-0366: 設定「PR の題名と本文」のスカッシュのマージで、途中のコミットのメッセージが既定ブランチに残らないこと(E2)
- EV-0367: 複数コミットの PR のスカッシュの後に、途中のコミットの `Agent-Run`・`Agent-Assets` が残らないこと(E0。観測していない。AI の `Co-Authored-By` が残るかは対象外)
