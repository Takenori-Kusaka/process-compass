## ステータス

採用(2026-08-05)

## コンテキスト

当初は「心理的抵抗を和らげ、自発的な賛同を得るためのストーリー」を組み立てる方針を置いていた。着手時の調査で、この方針が依拠する4つの前提のうち3件に修正が必要であると判明した。

| 前提 | 検証結果 |
| --- | --- |
| まず納得させてから導入する | 支持されない。組織変革の一次文献は「役割と責任を先に変えることで態度が後から追随する」と主張し、全社的な変革プログラム自体が定着の障害になると指摘する |
| 変革の取り組みの7割が失敗する | 根拠がない。主要な出典5件を検証した研究が、いずれも根拠を示していないか無根拠の文献の孫引きであると結論している |
| 著名な変革フレームワークは実証済みである | モデル全体を検証した研究はない。個々の要素に支持はあるが、段階の順序が必要であるという主張は確立していない |
| パイロットから水平展開する | 妥当。ただし根拠は ISO 9001 ではない。同規格は導入手順を規定しない |

加えて、AI 導入に固有の事情を確認した。利用者の自己評価と実測値の間に大きな乖離を示した測定例があること、採用率が上がっても生成物への信頼は上がらないこと、および AI が組織の既存の弱さも拡大させることの3点になる。

日本の大企業に固有の事情として、承認までに3日以上を要する稟議が半数近くに達するという調査があり、**判定を追加する形の提案は既存の滞留に上乗せされる**。

## 決定

1. **賛同を移行の前提条件にしない**。「課題を持つ組織が小さく試す → 結果を示す → 隣接する組織へ広げる」の順序とし、賛同は結果として観測する対象に位置づける
2. **導入を差し引きで提案する**。廃止または置換する既存の承認・様式と、新設する判定を並べ、差し引きが負であることを提案する要件とする
3. **移行段階を T-0〜T-4、判定ゲートを TG-1〜TG-3、支援体制を EN-1〜EN-3 とする**。工程ゲート(G-1〜G-8)およびステージ移行ゲート(SG-0〜SG-2)とは対象が異なるため、記号を分ける
4. **支援と適合性判定の組織を分離する**。EN-1(移行支援)は適合性を判定せず、EN-3(標準所管)は監査およびゲート運営と報告線を共有しない
5. **現場推進者の任命に3点の付帯を義務づける**。稼働時間の公式な確保、専門的知識への到達経路、上位者による可視的な支援。3点を欠いたまま任命しない
6. **試行の対象は代表性で選び、範囲で絞る**。成功しやすい案件を選ばない
7. **速度と安定性を対で測る**。自己申告による生産性の変化を成果指標にしない
8. **根拠として用いない数値を明示する**。変革の7割失敗、研修転移の1割、学習の7対2対1、生成 AI の試行の95%失敗、データ品質による85%失敗
9. **抵抗を4因子に分解し、設計で対処する**。時間の未確保、効果の証拠の不在、押し付け、手順の煩雑さ。説得によって解消する対象としない
10. **職務内容の変更に伴う法的手続を本標準で規定しない**。所管部門への確認を要求する

## 検討した選択肢

- **当初の方針どおり賛同の獲得を先に置く** — 一次文献と実測データの双方に反する。とくに自己評価と実測の乖離は、主観的な納得を判定材料にできないことを示す
- **著名な変革フレームワークの段階をそのまま採用する** — 実務での知名度は高いが、モデル全体の実証的検証を欠く。権威として引用すると、根拠のない順序を標準として固定することになる
- **全社一斉に展開する** — 支援できる能力を超えた展開は、形式的な適合だけを生む。段階を分けて支援の能力に速度を合わせる
- **支援組織が適合性の判定も担う** — 組織の数は減るが、支援を求めることが評価上の不利益になり、不備が隠される
- **移行段階に既存の記号(G または SG)を流用する** — 記号数は減るが、工程の制御点と組織の移行段階が同じ記号になり、判定の対象を取り違える
