## ステータス

採用(2026-08-08)

## コンテキスト

本標準はこれまで固有の名前を持ちませんでした。本文では「本標準」という自己参照を用いています。参照モデルの呼称は「統合プロセス参照モデル」です。いずれも一般名詞の組み合わせであり、検索したときに他の文書と区別できません。「統合プロセスで開発している」と説明しても、内容は相手へ届きません。

外部へ発信する段階では、この状態が障害になります。テンプレートは「(名前)準拠テンプレート」という形で名乗るため、名前が決まらなければリポジトリ名も決まりません。

名前に求める条件は5つです。

- 聞いた瞬間に同じ絵が浮かぶこと。スクラムがラグビーの絵を呼ぶのと同じ働き
- 組織が一体で動く場面であること。個人の日常動作では、開発プロセスへ移したときの飛躍がない
- 検索したときに新語として立つこと
- 一般の人に口頭で通じ、規格文書のような堅さを持たないこと
- 官公庁および大企業の文書へ載せて品位を損なわないこと

## 決定

通称を**ピットイン方式**、正式名称を**AI協調型ソフトウェア開発プロセス標準**とし、二層で運用します。

| 層 | 用途 | 名称 |
| --- | --- | --- |
| 通称 | 口頭・検索・リポジトリ名・バッジ | ピットイン方式(PIT-IN) |
| 正式名称 | 稟議・QMS 文書・規格の引用 | AI協調型ソフトウェア開発プロセス標準 |

一文の説明を次のとおり定めます。

> マシンは人間より速い。それでも、決められた場所では必ず人間が触る。

### 命名の根拠

F1 のピット作業は、18〜20名が2秒以下で完了します。タイヤ一本に3名が付きます。最小単位まで分解した作業へ専任の担当者を配置し、この速さが生まれています。

この場面は、本標準の3つの規定と重なります。

- 作業の分解と持ち場の分離。タスクの分割基準([第4章](/process-compass/phase4-process-design/gate-criteria/))と兼務の禁止([第3章](/process-compass/phase4-process-design/roles-responsibilities/))に対応する
- レースそのものは止めないこと。AI の生成速度を落とさずに判定を通す構成に対応する
- 競技規則が安全のために意図的な遅延を定めていること。ゲート(G-1〜G-8)に対応する

### 使い分けの規則

- 本文中の自己参照は「本標準」を維持する。名称を定義したうえでの参照語として成立する
- 参照モデルの呼称は「ピットイン方式参照モデル」とする
- 英語表記は PIT-IN とする。ピットインは和製英語であるものの、日本語の語をそのまま出す方針を採る
- テンプレートリポジトリは `pit-in-template` とする

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 要(かなめ)・心柱・棟梁 | 静止した構造物であり、動作の絵がない |
| 関所・改札・節目・勘所 | 個人が通る場面であり、組織が一体で動く絵にならない |
| 双輪型AIガバナンス標準・二層ゲートモデル | 構造の説明であって名前ではない。略称の読み方も定まらない |
| AI共創共通フレーム | 共通フレームは他機関が策定した既存の名称。権威の借用にあたる |
| ゴーアラウンド方式 | 差し戻しの文化を的確に表すものの、名前が工程の一部を指す |
| クリアランス方式 | 国内ではクリアランスセールの印象が強く、検索で混ざる |

## 影響

- docs 配下の「統合プロセス」をすべて改める。参照モデルの呼称も変わる
- 通称が定着するまでは、初出で正式名称を併記する
- 「ピットイン方式」「ピットイン開発」はいずれも既存の用法がなく、新語として立つ

**名称は内容を保証しません**。ピットイン方式と名乗ることは、本標準の要求事項を満たしたことの根拠になりません。適合の主張は、ゲート判定の記録とテーラリングの宣言によります([第8章](/process-compass/phase4-process-design/tailoring-guide/))。
