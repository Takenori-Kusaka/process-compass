## ステータス

採用(2026-11-19)。審議は重です。記録は `research/b22-deliberation/` にあります。一部置き換え(→ 本 ADR の決定6): [ADR-0200](/process-compass/adr/0200-b18-first-group-adopter-record-conventions/)の決定4 のうち「必須にするかは、IMPL-0214 と同じ重の審議に残す」の部分を置き換えます。観測と通知の workflow を必須ステータスチェックにしない部分は保ちます。

## コンテキスト

- 第3章 3.10.2 は「期間を短縮できるのは第7章 7.4 のファストトラックを適用した場合に限る」と書き、短縮の下限は「未決」としていた(EV-0281)。一方、7.4 の後回しにできる対象は限定列挙で、事前レビュー期間を含まない。7.4 は「ここにないものを短縮してはなりません」と書く。3.10.2 の経路は、条文どうしで働かない可能性があった
- 3.10.9 の「R1 と同じ扱い」は、期間にも及ぶと読めるという指摘があった。直後の「つまり」の文は、判定へ進めないことに限っている
- 3.10.5 の R1 は、指名レビュア全員の記名の応答が揃うまで判定へ進めない。準拠テンプレートの機械は無応答を締切後に通知するだけで、止めない。止める検査を必須にするかは、ADR-0200 の決定4 が重の審議に残していた
- 外部に、会議体の事前配布の最短日数を定める規格の条文は見つかっていない。根拠にできる下限の数値が無い

## 決定

1. 事前レビュー期間を短縮できるのは、第7章 7.4 の行がそのゲートを名指す工程ゲートに限る。7.4 の限定列挙は変えない。3.10.2 が経路を定め、7.4 には参照の一文を置く
2. 7.4 が後回しを禁止したゲート(G-4・G-5)と第7章 B-1〜B-4 の会議体の上程は、短縮しない
3. 短縮の下限の営業日数を置かない。短縮した場合は、指名レビュア(必須応答ロールを含む)全員の記名の応答(賛否いずれか)が揃うまで判定へ進めない。揃わなければ通常の期間に戻り、判定日 T を公開の時点から通常の期間を満たす日へ移す。T−1 営業日の起案者の応答の記載と未解決論点の確定は、短縮しても省けない。公開の時点と各応答の時点を残す
4. 3.10.9 の「R1 と同じ扱い」は、判定へ進める条件(3.10.5)を指し、期間に及ばない。期間の長さは 3.10.2 のリスク区分による。この明記は意味を変えない編集の指摘である
5. IMPL-0214 から R2 の必須チェック(`pre-review-closed`)を外す。3.10.5 の R2 は、異議なしとみなして判定へ進むためである
6. R1 の上程では指名レビュアの全員、機械が必須応答の者を記載した上程(3.10.9)では必須応答の者の全員について、応答の宣言行が揃ったかを確かめる検査を、準拠テンプレートが用意する。3.10.2 で短縮した上程のうち、R1 の上程にも 3.10.9 の上程にも当たらないもの(R2・R3 の短縮)は、この検査の範囲に入れない(通知は IMPL-0830 の (c) が担う)。範囲を広げると、R2・R3 の短縮にも判定へ進めない検査が掛かり、付議していない範囲になるためである。観測と通知の3つの workflow(review-queue-control・flow-observation・pre-review)は必須にしない(ADR-0200 決定4 の残りを閉じる)。合格は「宣言行が揃った」であり、応答の中身は確かめない。上程と結べない PR は失敗にせず「確かめていない」と出す。標準はこの検査を既定の必須ステータスチェックにしない。必須にするかは採用者がブランチ保護で決める
7. 記名の応答が揃わないときの経路は、3.10.5 が定める 3.9.3 の措置(D-0 表3 に記名した者への通知と代理の指名)だけとする。第7章 7.3 は用いない。7.3 の対象は判定基準と 7.3 が名指した事項に限り、3.10.5 の「判定へ進めない」はそのどちらでもないためである
8. 課さないと決めたこと。(a) 短縮の下限の営業日数。(b) 小さいチームの省略の条項。(c) 管理者によるブランチ保護の回避を機械で止めること。(d) 応答の中身の実質を機械で確かめること

## 検討した選択肢(採らない)

| 案 | 採らなかった理由 |
| --- | --- |
| 下限の固定値 | 根拠にできる数値が外部に無い。小さいチームほど重く、数値を満たす形だけの運用(公開日の前倒しの記載)を招く |
| 下限を応答の割合で定める | 端数と営業日の数え方で争いが出る |
| 全員の応答と下限の日数の併存 | 全員が記名で応答した後に、さらに日数を待たせる理由が無い |
| 7.4 の表に事前レビュー期間の行を足す | 禁止の列(G-4・G-5)と同じ表で論じ直すことになる。B-1〜B-4 は PR を経ない運用があり、全員の応答を機械で確かめられない |
| 3.10.9 が期間にも及ぶ読み | 必須応答ロールを含む R2・R3 の案件に T−10 営業日の公開を課す、新しい義務になる。実装(期間はリスク区分 R1 だけで決まる)とも食い違う |
| 応答の宣言行の検査を既定で必須にする | 判定の記録が PR を経ない場合(B-1〜B-4 の会議体など)は止められず、止まるのは一部だけである。上程と判定の PR を結ぶ識別は、実物の GitHub で確かめていない。確かめていない識別で採用者の工程ゲートを既定で止めると、信頼性を下げる |
| 検査を作らない | 決定可能な条件(存在と数の一致)の検査を、照らせない場面があることを理由に全部捨てると、照らせる場面の信頼まで捨てる。部分であることは表示で開示できる |
| R1 の上程だけを検査する | 3.10.9 は区分によらず R1 と同じ扱いにする。R1 だけでは、必須応答ロールを含む R2・R3 の上程を素通しし、表示と実態が食い違う |
| R2 にも検査を課す | 条文に無い義務である |
| 揃わないときを 7.3 で受ける | 7.3 の対象の限定を広げる新しい条項になり、3.9.3 の経路と二重になる |
| 回避なしで止める | 外部の実務(GitHub の管理者回避、Gerrit の overrideIf)は止める型に回避を持つ。回避が無いと黙った回避を招く。3.9.3 の代理の指名で、代理の応答により宣言行が揃う |
| R1 を短縮から外す | 会議体に付議していない新しい制限である。R1 は元から全員の記名の応答を要するので、決定3 の条件は R1 の安全側を弱めない。残る「急かされた同意」の危険は EV-0337 で開示する |

## 影響

- 採用者は、7.4 の行にゲートを名指して書かない限り、事前レビュー期間を短縮できない。短縮した上程では、指名レビュア全員の応答が揃うまで判定に進めない
- 準拠テンプレートは、次の束で、7.4 の行がゲートを名指すかの照合・G-4 と B-1〜B-4 の短縮の通知・短縮した上程の応答の通知・応答の宣言行の検査を足す。それまでは IMPL-0830・IMPL-0214 が降りていない表示を続ける
- 検査を必須にしない構成では、機械は判定を止めない。条文は有効であり、止めるのは人である
- 管理者によるブランチ保護の回避は、機械で閉じない。代理の指名の記録(誰が・いつ・誰に)が証跡になる

:::caution[暫定 EV-0338 / 見直し 2027-05]
**対象**: 判定へ進めない場合の応答の宣言行の検査を、既定の必須ステータスチェックにしないこと。
**根拠の水準**: E0(なし)。
**差し替え条件**: 実物の GitHub で、上程と判定の記録の PR を結ぶ識別が誤検出・見逃しなく働いた実行の記録。
:::
