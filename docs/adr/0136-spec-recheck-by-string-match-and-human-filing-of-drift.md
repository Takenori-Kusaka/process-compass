## コンテキスト

[#355](https://github.com/Takenori-Kusaka/process-compass/issues/355) 束3 は、実装マーク IMPL-0241・IMPL-0023・IMPL-0498 の降りていない部分を扱いました。審議は軽(起案と反対の2委員)で行い、2委員の結論は割れました。議長が裁定し、記録は `research/355-deliberation/` にあります。

- 標準は、確定した版から受入基準・前提・スコープ外が変わった機能仕様について、出荷判定の証跡の集約で「合否にする」と公開済みだった。準拠テンプレートには実装が無かった
- 実行で確かめると、現行の比較関数は両側とも節を取り出せないとき「変更なし」に数え、変更が見えなかった。標準の第6章の様式の見出し「スコープ外(やらないこと)」も、完全一致の定義では読めなかった
- 3.13.5 の宣言と実態のずれの検出は、検出と起票の2文からなる。検出の試験は無く、起票を機械が行うかが曖昧だった
- 手動のスタックの層の合わさりを、集約は見ない

## 決定

### 1. 確定した版の変更は、G-4 の通過の記録との文字列の一致で合否にする(IMPL-0241)

出荷の範囲で `spec.md` が変わった機能ごとに(経路は問わず、`spec.md` の変更に限ります)、G-4 の通過の記録が対象とする版の3節と、範囲の先端の3節を、節ごとに比べます。結果は3値です。

- **一致**: 効いている通過のうち、版を読めたものの1件でも先端と等しい。両側とも節を取り出せなくても、全文(同じ正規化)が等しければ一致
- **不一致**: 一致する効いている通過が無く、その機能に版を読めた G-4 の通過の記録が1件でも在り(効いているか、後の差し戻しで打ち消されたかを問わない)、全件が先端と一致しない。片側だけ節が無い場合を含む。確定した版は在り、先端はそこから変わっていて、変更後の版を対象とする通過は無い。この3点は値で決まる。版を読めない効いている通過が在っても、不一致にする(版を書かない通過の記録で欠落を消させないため)。その通過が先端の版を対象とするなら、判定者が判定記録の対象へ版を書くと一致になる。**記載の欠落にする**
- **未確認**: 次のいずれか。**欠落にしない**。件数・機能・記録の所在・理由を `evidence.json` と品質レポートに出し(外部向けの開示は件数だけ)、出荷判定者が突合する
  - 打ち消された通過の版が先端と一致し、効いている通過に一致が無い。理由は「先端の版の通過が、後の差し戻しで打ち消されている(または判定日時が空で前後が決まらない)」
  - その機能に G-4 の通過の記録が1件も無い。コミットまたは PR のトレーラ Spec がこの機能を指す場合に限り、G-7 基準5 が欠落に数える。指さない場合、機械は欠落にしない
  - 対象に版が無い、写しが無い、判定の版のオブジェクトが取れない
  - 3節のうち両側で取り出せない節が在り、全文も一致しない

判定する席の責任者でない者の通過と、head が合わない写しは、通過の記録に数えません。

「効いている」は、効いている通過の一覧を返す1つの関数で決め、既存の `g4Approved` と再確認がその一覧を使います。定義を二重にしません。「基準5 の欠落がそのまま当たる」とは書きません。基準5 はトレーラ Spec が指す機能にしか当たらないためです。

限界として、次を開示します。写しの通過の後に様式で同じ版を差し戻しても、一致のままです(様式と写しの前後は比べません)。2つの変更が同じ仕様の別の節を変え、それぞれの head で通過しても、合流後の版は誰も判定していないため不一致になります。`spec.md` の削除と `specs/F-NNN/` の改名は、比べる対象に出ません。

見出しの定義は、「前提」「スコープ外」も「受入基準」と同じ前方一致に改めます。受入基準の定義は spec-lint と同じです。「前提知識」のように語が続く見出しも前提の節として読み、合否に効きます。表示(IMPL-0520)と集約は同じ関数を使います。

### 2. 正規化を強めない

正規化は、改行・行末の空白・端の空行を揃えるだけです。行内の空白や表の整形だけの変更も不一致になります。第4章「確定した版を変える場合」は、戻り幅を G-4 の判定者が判定し、提出者と担い手は選ばないと定めます。機械の正規化が先に「意味は同じ」と決めると、この規定と逆になります。閉じ方は、判定者が変更後の版を対象に判定記録を1件書くことです。

### 3. 宣言と実態のずれの起票は人が行う(IMPL-0023・IMPL-0524)

検出は機械で行い(IMPL-0023)、起票は人が行います(IMPL-0524)。機械は起票せず、構成も書き換えません。構成の書き換えの経路を変化点の手続に限る規定(3.13.4 要求事項1)と、決定者の記名に反するためです。集約は、人数と担い手の識別のずれごとに変化点の種別と補助ファイルの所在を保証の開示に出します。D-0 の版の不一致は記録の欠落として出し、変化点の種別は併記しません。起票されたか、前回のずれが残っているかを、機械は確かめません。

### 4. 層の合わさりの承認の数え方は変えない(IMPL-0498)

数え方を変えません。規定は課したままで、降ろす形が決まっていないだけです。`undelivered` `plan=scheduled` を保ちます。集約が層の合わさりを見ない事実を、標準の本文で開示します。

## 課さないと決めたこと

- 整形だけの変更を機械が「意味は同じ」と判定して通すこと
- 未確認・見出しの欠けを欠落にすること。合否が取得の深さという環境で変わる。さらに、見出しの存在が出荷の条件となる新しい義務になる(採るなら重)
- 範囲の外の機能を毎回比べること。導入より前の変更は見ないことを開示する
- 機械による Issue の自動起票
- 前回のずれが残る出荷を止めること。前回の開示にずれの種別の値が無い(採るなら重)
- 層の合わさりの数え方の変更、「機械が数えから外すことは課さない」と書くこと

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 所見だけにして `undelivered` にする(反対の委員) | 標準は既に集約で「合否にする」と公開している。所見に留めると標準の文を弱める |
| 現行の関数のまま合否に使う(両側 null を一致に数える) | 実行で、変更が見えないことを確かめた。偽の合格 |
| 正規化を強める(行内の空白・表の整形を除く) | 意味が同じかは G-4 の判定者が決める。コードスパンの中の空白など、意味を変えない保証が無い |
| 「最新の」G-4 の記録で比べる(#334) | 様式と写しの前後が決まらない |
| マージのコミットで版を代用する、`gh` で版を解決する | 基底が同じ仕様の別の節を先に変えていると、判定していない変更を含む偽の合格になる。集約の合否を網の呼び出しに依らせない |
| 未確認・見出しの欠けを欠落にする | 新しい義務(重)。未確認の実数を数えてから審議する |
| 範囲の外の機能も毎回比べる | 過去の G-7 が通過させた範囲を遡って止める |
| G-4 の記録が無い機能を、再確認の不一致(欠落)にする | 判定を受ける前の下書きの機能仕様で出荷が止まる。未確認の行で出し、トレーラ Spec が指す場合だけ基準5 が欠落に数える |
| 効いている通過に版を読めないものが在るときは未確認にする | 版を書かない通過を1件足すと欠落が未確認へ変わる(実行で確かめた) |
| (a) 範囲で `spec.md` が変わった機能を、変更したファイルだけを根拠に G-7 基準5 の欠落へ足す | 判定を受ける前の下書きの機能仕様(新しい機能の `spec.md` を既定ブランチへ入れ、G-2・G-4 を待つ状態)が出荷の範囲に在るだけで、出荷が止まる。基準5 の対象を広げる新しい義務で、採るなら重。代わりに、版を読めた通過の記録が在って先端と一致しない場合を不一致にする |
| 判定者・判定日時・D-0 の版の空欄を一般に欠落にする | 式が判定日時を要さなくなった。D-0 の版の空欄は既に数えている。様式への新しい必須は重 |
| G-3 の2点を全文一致で機械にする | 状態欄の正当な更新が偽の FAIL になる。式が未試作 |
| ADR-0078 の本文を直す | 採用済みの ADR は書き換えない |
| 検出と案内を1つの `delivered check=machine` にまとめる | 起票は機械が確かめない |
| `undelivered plan=scheduled` のまま表示だけ直す | 降ろす手段を決めていない規定を `scheduled` と表示し続けることになり、ADR-0084 決定4 に反する |
| 担い手の識別の部分一致を片方向に締める | 警告の量の実証が無い。版の無い共著者名をずれに数えると警告が常に出る |
| 数え方を変える、`plan=adopter` にする | GitHub 標準のスタックと区別できず偽の FAIL になる。親の到達による検出は ADR-0126 決定2 と同じ理由で採らない |

## 影響

- 出荷の範囲で、G-4 の通過を得た機能仕様の3節を変え、変更後の版を対象とする通過が無い場合は、出荷の証跡の集約が欠落とする。通過の記録が1件も無い機能は未確認で、トレーラ Spec が指す場合に限り、基準5 の欠落の対象になる。整形だけの変更でも同じで、判定者が判定記録を1件書いて閉じる
- 未確認の機能は欠落に数えない。出荷判定者が、品質レポートの機能・記録の所在・理由を突合する。squash で判定の版のオブジェクトが取れない環境では、未確認が多くなりうる
- 判定済みの古い版へ戻した変更は一致になる。範囲の外の機能と、導入より前の変更は見ない
- IMPL-0523(判断記録の書き換えの検出)は `undelivered` のまま台帳に出続ける
- IMPL-0498 は `undelivered` のまま台帳に出続ける
- 実装(準拠テンプレートの試験を含む)の実行での確認は、EV-0267・EV-0268 で開示する
