## ステータス

採用(2026-11-18)。束 B20 の重の件のうち、IMPL-0919(安全関連部の自律レベル)と IMPL-0766(CL3 の安全関連部の外だけ L2 以上)の決定です。

## コンテキスト

- 附属書F F.3 は、安全関連部に AI の支援を用いる場合の AI自律レベルを L1 に固定する。標準の表は CL2 の上限を「L2」と書き、安全関連部だけが L1 であることを読み取れなかった
- 準拠テンプレートの構成は、AI自律レベルの上限を案件の全体へ掛ける。安全関連部と外を分ける単位を持たない。L2 を支えない点は [ADR-0081](/process-compass/adr/0081-autonomy-downgrade-delivered-as-registration-stop/) の決定6 のとおり
- 受付は、Q1 の答えと CL の組を「定義の上ほぼ矛盾」と見た。[ADR-0171](/process-compass/adr/0171-s0-omission-premise-f2-q1-restores-g7/) は、CL0 と Q1「はい」の組は正当に生じうると書く。矛盾とは扱わない

## 決定

1. **F.3 を正とする**。安全関連部の AI自律レベルは CL に依らず L1 へ固定する。標準の表(軸E の「AI自律レベルの上限」、組み合わせ表、CL2 の説明)を、これに合わせて改める。標準が求めるのは安全関連部の L1 固定までである
2. **準拠テンプレートは Q1「はい」の案件の委任を案件の全体で止める**。範囲を持たないための振る舞いであり、採用者への義務ではない
3. **Q1 は委任を判定するたびに D-0 表10 から読む**。止めないのは「いいえ」と読めたときだけである。「はい」・未記入・様式のまま・「未定」・読めない・D-0 が無い、はすべて止める。登録の後に「はい」へ改めた場合も、判定のたびに読むので止まる
4. **判定は1関数(`safetyPartStop`)に一本化する**。種別の停止(`autonomyState`)・登録の拒否(`capRefusal`)・D-0 の表の生成と L3 の範囲(`renderAutonomyTable`・`l3ScopeIds`)が同じ関数を通る。構成の導出(`buildDelegation`)は変えず、構成へ Q1 を写さない。写すと D-0 と食い違い、ADR-0171 の決定4(写しが変えるのはゲートの状態だけ)にも反する
5. **CL3 の安全関連部の外だけ L2 以上を認める扱い(IMPL-0766)は、採用者の実装とする**(`plan=adopter`)。開く先の L2 がテンプレートに無い。許す側を実装しないことで失うのは採用者の効率で、安全は下がらない。禁止の側(IMPL-0765)は降りている。`lint:impl` が通ることを実行で確かめた。`decision=` の ADR の実在は lint が確かめないため、本 ADR を同じ変更で足す。B13 の分類を本 ADR で改める
6. **Q1 の答えの正しさは機械で閉じない**。確かめる者は判定者と確認者である

## 課さないと決めたこと

- 安全関連部の範囲を構成に持たせること(L2 を支えない現状では、持たせても開く先が無い)
- 止めたときの案内に「案件を分ける」を出すこと(分けて成立するかを確かめていない)

## 検討した選択肢(採らない)

| 案 | 採らなかった理由 |
| --- | --- |
| 既存の D-0 の欠落に任せる(起案) | 欠落は G-1 と出荷で効くが、委任の判定には効かない。D-0 を書かないだけで委任が動く |
| 範囲の宣言の欄を足す | 狭く書く抜け道になる |
| 初期化の回答の写しから Q1 を読む | ADR-0171 の決定4 に反する |
| 例外承認で委任を許す | 緩める向きの逸脱を記録すると、適合の主張の読み手を誤らせる |
| F.3 を CL2 だけ L2 へ緩める | 安全の側を下げる根拠が無い |
| 分岐を作って外だけ L2 を許す | 開く先の L2 が無い |
| IMPL-0766 のマークを外して ADR に書くだけにする | lint が通るので切り替える理由が無い。「課さない」ではなく「書かれていない」に見える |
| 題を「安全関連部を全体 L1 に固定する」とする(受付の題) | 全体 L1 を採用者の義務と読まれうる。標準の要求は安全関連部の L1 固定まで |

## 根拠水準

- 「安全関連か否かで線を引く固定」と「全体を止める形」は EV-0333(E0)。機能安全の規格の主流は段づけで、固定の先例は確かめられていない。本標準が足す判断である。見直し 2027-05

## 影響

- Q1 が「はい」(または読めない)の案件では、登録済みの変更種別の委任が止まる。D-0 の表は L1 と書く。D-0 の生成区間は Q1 を読んで描くため、Q1 を改めたら区間を再生成する(`node scripts/init/generate-profile.mjs --answers process.config.json`)
- 既存の試験の見本に、D-0 表10 の F.2 の記入を足した
- 申し送り: Q1 が「はい」(写し)で D-0 が「いいえ」の向き(IMPL-1016)は、本件は D-0 だけを読むので委任が動く。軽の裁定へ渡す
