## ステータス

採用(2026-10-13)。[ADR-0035](/process-compass/adr/0035-separation-by-execution-context/)の決定1 の適用範囲を置き換えます。ADR-0035 の決定2(人と実行主体の文脈の2つの単位)と決定3 は維持します。[ADR-0054](/process-compass/adr/0054-seat-accountable-performer/)の決定7(独立の定義)と決定8(G-6 の4条件、外部の確認者)を、書き換えずに補います。

## コンテキスト

[#308](https://github.com/Takenori-Kusaka/process-compass/issues/308) は、規則データの `sep-self-approval`(起案した主体は、その成果物の判定者にならない)が、どの検査にも現れないことを指摘しました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/302-310-deliberation/`(`survey-308.md`、`council-C-01`〜`05`、`decision.md` の C-4)にあります。

### 同じ原則に3つの書き方があった

| 所在 | 書き方 |
| --- | --- |
| 第3章 3.5 の図 | 「同一ゲートで:起案者 × 判定者」 |
| 規則データ `sep-self-approval` | 「起案した主体が判定すれば、判定は自己申告になる。役割の組み合わせによらず成立しない」。役割の組を持たず、例外なし |
| ADR-0035 決定1 | 「同一の成果物について、作成を指示した主体は、その成果物の判定者になりません。この原則は体制の規模、自律の水準、実行主体が人か AI かによって変わりません」 |

第3章 3.5 の表には、この原則に当たる行が最初からありません。表は「禁止する組み合わせを最小限に絞って明示します。それ以外の兼務は許可です」と書いています。

### 人の単位で読むと、標準の既定が抵触する

本標準の既定の割り当てでは、要件合意(G-2)、技術設計判断(G-3)、機能仕様承認(G-4)、出荷判定(G-7)の判定者は、判定の対象の成果物に結果責任(A)を負う席の責任者です。体制の人数によりません。第4章の共通ルール 1 は「単独判定: 判定者は1人」と定めます。ADR-0035 決定1 を人の単位で文字どおりに読むと、3名以上の体制でも、この4つのゲートが原則に抵触します。

[ADR-0054](/process-compass/adr/0054-seat-accountable-performer/)は「担い手が起案し、責任者が確定する」と定め、ADR-0035 を維持すると書きました。決定1 との関係は述べていません。

### 機械は検査していなかった

準拠テンプレートの兼務の検査は、役割の組を持たない規則を読み飛ばします。9席すべてが同一人物の構成でも、この規則はどの区分にも現れません(調査が実行して確認)。一方で、PROCESS-PROFILE.md は全案件に「起案した主体は、その成果物の判定者になりません」と出していました。

### 独立の主語が2通りあった

[#307](https://github.com/Takenori-Kusaka/process-compass/issues/307) は、外部の確認者の位置づけと、独立の定義の主語を問いました。記録は同じ場所の `survey-307.md`、`council-A-01`〜`05`、`decision.md` の A-11〜A-13 にあります。

ADR-0054 は、同じ日に2つの主語で独立を書いていました。決定7 は「確認する席の責任者が、作成を指示した者と別の自然人である」と書き、主語は席の責任者です。決定8 の4条件は「承認した者が…作成を指示した者でない」と書き、主語は承認した人です。上書きの関係を示す記録はありません。

主語の違いは、判定を分けます。2名体制で席を1つずつ持つと、独立レビュアの席の責任者の指示した変更を、開発者の席の責任者が確認する場面を避けられません。第3章 3.5 の表はこの確認を成立とし、機械も数えます。決定7 の文を文字どおりに当てると、成立しません。逆に、主語を承認した人だけにすると、構成が成立しているかを出荷の前に判定できません。

### 外部の確認者に2つの置き方があった

準拠テンプレートは、外部の確認者について2つの置き方を別の効果で扱っていました(調査が実行して確認)。人の名簿にだけ載せると、構成上の G-6 は未達のままです。数えるのは、外部の確認者が承認した変更だけです。独立レビュアの席の責任者に置くと、G-6 は適用になり、承認の強制が入り、確認を経ていない変更は記録の欠落になります。標準の本文は、どちらの置き方かを書いていませんでした。テンプレートの README だけが「独立レビュアの席の責任者にします」と書いていました。

任命基準(第3章 3.4)の主語は、ロールへの任命と席の責任者です。席の責任者に置けば文面上すべて掛かり、名簿にだけ載せれば何も掛かりません。位置づけの決定が、力量の確認の要否を決める構造でした。

## 決定

### 1. 「起案者は自分の起案を判定しない」は、実行主体の文脈の単位で課す

同一の成果物について、成果物を起案した実行主体の文脈は、その成果物の判定の草案を作りません。判定の草案を担い手に作らせる場合は、成果物を起案した担い手と、作業領域・セッション・認証情報を分けます。体制の人数によって変わりません。1名の体制でも、文脈は分けられるためです。

人の単位では、この原則を課しません。人の単位で禁止する組み合わせは、第3章 3.5 の表の組に限ります。

**要件合意(G-2)、技術設計判断(G-3)、機能仕様承認(G-4)、出荷判定(G-7)を、成果物の結果責任者が判定することは、禁じません**。これらの判定は、結果責任者が内容を確定する行為です。別の人による確認ではありません。別の人による確認を課すのは、独立レビュー(G-6)と、第3章 3.5 の表の組です。

1名体制に、この決定による未達と逸脱の表示を足しません。課していない事項だからです。

ADR-0035 決定1 が「体制の規模、自律の水準、実行主体が人か AI かによって変わりません」と書いた普遍性は、実行主体の文脈の単位で保ちます。人の単位での適用範囲は、本決定で第3章 3.5 の表の組に置き換えます。

### 2. 外部の確認者の2つの置き方を両方認め、効果を規定する

| 置き方 | 引き受ける範囲 | 構成上の G-6 | 確認を経ていない変更 |
| --- | --- | --- | --- |
| (ア)人の名簿に載せる | 依頼された変更の確認 | 未達のまま。確認した変更だけを数える | R1 は例外承認、R2・R3 は件数の開示 |
| (イ)独立レビュアの席の責任者に置く | 全変更の確認 | 適用する | 記録の欠落 |

- 既定は(ア)とする。変更ごとに頼まれる人は、席の責任を負わない
- (イ)は、任免の決定者の記名、力量の確認、席の規定に従うことの書面による合意の3つを条件とする
- (イ)の外部の確認者に、統制を緩める向きの決定権を与えない。独立レビュアの席の委任の宣言と範囲の拡大は、D-0 表1「体制と運用形態」の決定者が決定する。ADR-0054 決定10 が挙げる2者のうち、後者に限る限定である
- 外部の確認者を担い手だけに限る案は、採らない。守秘・対価・利害の扱いは、定めない([#300](https://github.com/Takenori-Kusaka/process-compass/issues/300) で範囲外と決めた)

書面の合意は、席の規定に従うことの合意です。守秘・対価・利害の中身には立ち入りません。

### 3. 独立を、構成の条件と変更ごとの条件の2層で定める

| 層 | 主語 | 条件 | 確かめる時点と証跡 |
| --- | --- | --- | --- |
| 構成の条件 | 席の責任者 | 確認する席の責任者が、確認される側の席の責任者と別の自然人である | 構成を変える時点。人の名簿と席 |
| 変更ごとの条件 | 確認した人 | 変更を確認して承認した人が、その変更の作成を指示した者と別の自然人である | 出荷の時点。承認者と指示者の記録 |

ADR-0054 決定7 の独立の行と、その2つ目の箇条(3名以上で、独立レビュアの席と開発者の席の責任者を同一人物にしない)は、構成の条件として読みます。決定8 の4条件は、変更ごとの条件として読みます。どちらも書き換えません。

承認した人が独立レビュアの席の責任者であるかは、変更ごとの条件にしません。席の作業を複数の人が担う体制を妨げないためです。この扱いは準拠テンプレートに既にあり、決定の記録がありませんでした。本決定で記録します。

同じ2層で、次の2つも定めます。

- 出荷判定(G-7)の独立: 構成の条件は席の兼務禁止、出荷ごとの条件は「G-7 を記名した人が、範囲内の変更の指示者でも G-6 の承認者でもない」である([ADR-0066](/process-compass/adr/0066-shipping-approver-separation-and-development-line/))
- 起案と判定の分離(決定1): 構成の条件を持たない。実行主体の文脈の単位でだけ課す

### 4. 力量の基準は、位置づけによらず同じにする

承認を独立した人の確認に数える人には、席の責任者でなくても、独立レビュアの任命基準を当てます。席の作業を担う体制の内の人、(ア)の外部の確認者、(イ)の外部の確認者の、いずれにも同じ基準を当てます。

- 確かめ方は、第3章 3.4.1 の成果物(実際の差し戻し記録)による。新しい数値は置かない
- 確認の記録が無い人の承認は、数える。数えたうえで、件数を保証の開示へ表示する
- 確認を依頼した本人による確認は、受け付ける。ほかの者による確認と区別して表示する
- 確認の記録が無いことを理由に、出荷を止めない

第3章 3.4.1 の暫定任命の規定のうち「併記のない判定を、成立した判定として表示しない」は、G-6 の変更ごとの承認には当てず、本決定の扱いによります。暫定任命の規定そのものは変えません。

根拠水準マークは、本文に置きました。(イ)の3条件は第3章 3.5 の EV-0104、依頼した本人による確認は第3章 3.4.1 の EV-0105 です。

:::caution[暫定 EV-0097 / 見直し 2027-04]
**対象**: 成果物を起案した文脈と、判定の草案を作る文脈を分けることが、判定の草案の質を上げるという前提。
**根拠の水準**: E1(間接)。
**差し替え条件**: 同じ文脈で作った判定の草案と、別の文脈で作った判定の草案について、人が確定の時点で改めた件数の比較。

生成側の文脈を切り離すと検出が上がるという向きの測定はあります([ADR-0054](/process-compass/adr/0054-seat-accountable-performer/)の EV-0041)。対象は確認側の検出であり、判定の草案ではありません。この決定の根拠は、人の単位の読みが標準の既定と両立しないことにあります。分離の効果の測定には依っていません。
:::

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 人の単位で、全ゲートに課す | RACI、単独判定、「1つの成果物に責任者は1人」と衝突する。採るなら、価値責任者とは別に要件の判定者の席を作ることになる。要件の判定を別人に置いた体制で手戻りが減ったという材料は、調査に無い。1名体制では G-1〜G-4 が成立しない |
| 禁止にせず、起案者と判定者が同一であることを記録と開示に出す | G-2〜G-4 では既定で同一になる。全件に出る表示は、未達の表示(体制の制約で満たせていないこと)と見分けがつかなくなり、[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)の区別を薄める |
| 少人数の体制の扱いだけを足す | 読みを決めないので、3名以上の体制の抵触が残る。機械が何を逸脱に数えるかを決められない |
| 規則を外し、AI の担い手が判定者にならないという既定だけを残す | 文脈の単位の規定が消える。ADR-0035 が止めたかった事象(1つのセッションが実装し、自らの成果物の判定の直前まで進んだ)に当たる規定が、判定の草案について残らない |
| 決めない | 図は禁止を掲げ、規則データは例外なしと書き、PROCESS-PROFILE.md は全案件に禁止の文を出し、機械は検査しない。監査で適合も不適合も判定できない |
| (決定2)外部の確認者を、席の責任者に置く形だけにする | R1 の変更だけを頼む体制が、全変更の欠落を負う。第3章 3.5 の「外部の確認者は R1 の変更へ集中させてよい」「R2 は件数で表示する」が働かなくなる。取り決めも力量の確認も無い人に、席の結果責任を負わせることになる |
| (決定2)外部の確認者を、担い手だけに限る | 全変更を外部が確認する体制から、承認の強制と、確認漏れを欠落にする検査が消える。準拠テンプレートの README と回帰の fixture が席の責任者の形を固定しており、覆す材料が無い |
| (決定2)守秘・対価・利害を定める | #300 で範囲外と決めた。契約の事項である |
| (決定3)主語を、承認した人の1つに揃える | 構成が成立しているかを、出荷の前に判定できなくなる。3名以上で独立レビュアの席と開発者の席の責任者を同一人物にしないという規定の居場所が無くなる |
| (決定3)主語を、席の責任者の1つに揃える | 2名体制の逆向きの確認が成立しなくなる。承認者2名の体制(2人目は席の責任者ではありえない)と両立しない |
| (決定4)力量の確認を、席の責任者に置く場合に限る | 名簿にだけ載せる置き方が、力量の確認を避ける抜け道になる。内外で基準を変える規格は、確認できた範囲に無い |
| (決定4)確認の記録が無い人の承認を数えない | 採用の初日に、全変更が独立した人の確認を経ていない変更になる。1名体制は、依頼者しか確認する者がいない。止めずに開示する形で解ける |

## 影響

- 第3章 3.5 の図の X3 を、文脈の単位の規定として書き直した。3.5.3 に「成果物を起案した文脈と、判定の草案を作る文脈」の項を置いた
- 規則データ `sep-self-approval` に、判定の単位(`unit: context`)を足した。準拠テンプレートの兼務の検査は、この規則を席の責任者の兼務として検査しない
- 準拠テンプレートの PROCESS-PROFILE.md と CLAUDE.md の文を改めた。構成の `roles[].selfApproval`(読む処理の無い欄)を外した
- **この規定を、機械は検査しない**。担い手の識別を突き合わせる検査が無いためである。実装マーク IMPL-0105 に「人が確かめる」と表示する([ADR-0061](/process-compass/adr/0061-check-means-on-implementation-marks/))
- 受入基準と設計の誤りに、別の人の確認による歯止めは無いままである。附属書H H.11 が開示している
- (決定2)第3章 3.5 に、2つの置き方の表と条件を置いた。準拠テンプレートは、独立レビュアの席の責任者が外部の確認者である席で、緩める向きの決定を席の責任者の記名では受け付けない(IMPL-0115)。力量の確認と書面の合意の記録は、構成に欄が無く、降りていない(IMPL-0116)
- (決定3)第1章 1.4 と第3章 3.5.4 の独立の行を、2層へ書き分けた。機械の挙動は変えていない。準拠テンプレートは、構成の表示(G-6 の状態)と変更ごとの件数を、既に別々に出している
- (決定4)第3章 3.4.1 に項を置いた。**件数の開示と、依頼した本人による確認の区別の表示は、準拠テンプレートに降りていない**(IMPL-0117)。構成に、席の責任者でない人の力量の確認の記録の欄が無いためである
- 外部の確認者を席の責任者に置いた体制では、確認を経ていない R2 の変更が、件数の開示ではなく記録の欠落になる。置き方を選ぶ時点で、採用者がこの差を知る必要がある
