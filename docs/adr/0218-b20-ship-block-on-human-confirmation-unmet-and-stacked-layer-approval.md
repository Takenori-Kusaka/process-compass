## ステータス

採用(2026-11-18)。束 B20 の重の件のうち、IMPL-0738(未達のまま出荷が止まらない穴)と IMPL-0498(層の合わさりの承認の数え方)の決定です。止める未達の範囲は、独立の突合 F-08 を受けた所有者の決定(2026-11-18。案 B)で定めました。

[ADR-0136](/process-compass/adr/0136-spec-recheck-by-string-match-and-human-filing-of-drift/) の決定4(層の合わさりの承認の数え方は変えない)を置き換えます。ADR-0136 の本文は書き換えません。[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)(未達と省略の区別)・ADR-0055・ADR-0088・ADR-0113 とは矛盾しません。審議の記録は `research/448-deliberation/b20-decision-heavy.md`(2 節・3 節)と、独立の突合 1 巡目への裁定 `research/448-deliberation/b20-round1-ruling.md`(1 節)です。

本文は公開の前の版なので、突合の裁定に合わせて直しました。

## コンテキスト

- 第8章の表は、CL1 以上と規制業の案件は未達のまま出荷しないと定める。ところが集約は、人員不足の出荷できない状態(shipBlocked)と、判定の確認の未達でしか止めなかった。手で `unmet: []`・`g3: omitted` と書いた構成は、契約検査の照合(`unmet[]` と `gates` の相互参照だけ)をすり抜ける
- 実行で確かめた。未達を生む処理は2種(G-6 と G-3)で、G-3 は「スタックが未確定、かつ PoC でない」ときだけである。スタックが確定していれば未達は0件で、典型の初期状態で出荷が永久に止まることはない
- 表の置かれた文脈は体制の縮小であり、引用の先例(ADR-0055・ADR-0088)も人の確認に関わる未達である。G-3 のような体制に由来しない未達まで止めることは、既存の条文の読みを超える(独立の突合 F-08)
- 層の合わさりの承認は、条文(IMPL-0250)が「数えない」と定めるのに、集約は PR ごとに数え続けました。ブランチを消す運用では、`refs/pull/N/head` を取得しないと先頭を読めない(使い捨てのリポジトリで確認)

## 決定

1. CL1 以上の案件と規制業の案件は、人の確認の未達を集約の記載の欠落に数える。人の確認の未達は、G-2 の価値責任者を置かない委託(様式 08 の「置かない」。IMPL-0755)、G-6(作成を指示した本人以外の確認者を置けない)、暫定任命の期間中の判定の併記の欠け(IMPL-0638。出荷の範囲の中の判定に限る)、手書きの構成にだけ現れる表に無い未達である。評価者の段の未達は、監査対応書式の記録の検査が別の経路で欠落に数える。解く道は未達の解消だけとする。G-3 など体制に由来しない未達は止めず、開示と G-8 の受容で出荷できる。CL0 で規制業でない案件は、現行のとおり開示と G-8 の受容で出荷できる
2. 止める未達の範囲は `config.mjs` の `UNMET_SHIP_SCOPE` の 1 か所で列挙する。表に無い値は止める側に倒す。開示の未達は、構成の `unmet[]` と、回答とスタックから導き直した G-3 の和とする(`derivedUnmet`)。G-3 の条件と記載は `detectUnmet` と共有する1か所に置く。G-3 は導き直すので、構成の手書きで開示から消せない。G-6 の未達の手書きの消去は集約では防がず、契約検査(`verify-gate-contract.mjs`)が落とす
3. 止まるのは出荷判定(集約の exit 1)で、マージは止めない(IMPL-0769 と同じ強さ)。人の確認の未達を止めることは第8章の表の既存の定めの実装であり、新しい義務を足さない。例外承認は未達を解かない(第7章 7.3)
4. 層の合わさり: 基底が既定ブランチ以外の写しで、その層自身に有効な承認が無いもの(X)の `merge_commit_sha` が、既定ブランチへ入った PR(Y)の `head_sha` の祖先なら、Y を確認ありに数えない(理由 `stackedLayer`)。有効な承認は、X の写しへ独立した人の確認の判定(`independentConfirmation`)を当てて決める。bot・AI の名義・作成者本人・作成を指示した者の承認は有効な承認でない。判定できないときは承認なしに倒す
5. 履歴を読めないときは、数えない側へ倒す(理由 `stackedUnconfirmed`)。浅い取得、または Y の先頭を取得できないときである。Y の先頭があり、浅い取得でなく、祖先でないとき(X の版が無い場合を含む)は数える
6. 判定が要るのは承認の無い X があるときだけで、そのとき Y ごとに `git fetch --no-tags origin refs/pull/<Y>/head` を行う。数えなかった結果は、G-7 基準5 の表(`exceptionNeeded`)が既存のとおり扱い、新しい停止は足さない。開示に、承認の無い層の件数・数えなかった件数・未確認の件数・見逃す場面を出す
7. 根拠水準: 0738 は EV-0331、0498 は EV-0332(いずれも E0)。EV-0269(数え方を変えない判断)は対象が消えるので外し、識別子は再利用しない

## 課さないと決めたこと

- **CL1 以上と規制業でも、G-3 の未達では出荷を止めない。スタックが未確定のまま G-8 の受容で出荷できる状態が残る**。所有者の決定(2026-11-18)による。書かれていないのではなく、課さないと決めた
- 既存の案件への猶予。解消は構成の変更1回で足り、新しい条項になる
- 欠陥ごとのリスク評価を止める条件にすること。評価の定義が標準に無く、機械で閉じない
- 取り込みの後に rebase した変更の検出。patch-id などの近似は決定可能でなく、偽陽性が出る。見逃す場面として開示する
- 拒否の設定(ADR-0124 決定4)。本決定は事後の数え方である

## 影響

- CL1 以上と規制業の採用者は、人の確認の未達が残ると出荷の証跡の集約が止まる。スタック未確定(G-3)では止まらず、開示に出る
- 手動のスタックを使う採用者は、承認の無い下の層を含む差分への承認が、確認ありに数えられない。例外承認の行が対応づけば、欠落にならない
- 取り込みの後の rebase は見つからず、GitHub の実機での `refs/pull/N/head` の公開と verify ジョブでの再実行は確かめていない。使い捨ての git リポジトリでだけ確かめた
- 確かめていない点: 契約検査(`verify-gate-contract.mjs`)は、G-3 の未達を手書きで消した構成を通す(開示は導き直した G-3 を出す)。G-6 の未達の手書きの消去(unmet の空化・g6.state の書き換え・gate の付け替え)は、契約検査が落とす(2巡目の突合で実行して確かめた)。止めるのは集約である(実行で確かめた)
