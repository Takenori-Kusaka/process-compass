## コンテキスト

[#422](https://github.com/Takenori-Kusaka/process-compass/issues/422) は、所有者の提起です。approve とマージを形だけ行っても意味がない。PR の様式などで本質的なレビューの論点と長期的な決定を切り出し、人の承認をそこへ絞り、残りを AI のレビューで補う運用が Anthropic で行われていると聞いた。これを調べて取り込みたい、というものです。調査(`research/422-deliberation/survey-422-*.md`)と、起案・現場・品質監査・規格・弁護の 5 委員の会議体(`research/422-deliberation/`)を経ました。

### 見つかったこと

- 所有者の前提は、一次資料で半分だけ確かめられた。確かめられたのは、社内のほぼ全 PR に AI のレビューを掛けること、AI のレビューが承認と阻止のどちらも行わないこと、コードベースをリスクで層別し、規制対象・重要なコードだけに人の厳格な承認を残し、低リスク層は自動承認として人がリスク加重の標本を見ること。確かめられなかったのは、人のレビューを PR ごとの本質的な論点と長期的な決定へ絞ることだった。絞る軸は論点ではなくリスクの層だった。この事実は採否の理由にしていない
- 本標準は、読む深さの配分を既に認めていた(附属書H H.5「承認は全行を読んだことを意味しない」、担保水準 L1、規模の確認の保証の所在、/human-verify の順5)。どれも絞る根拠を機械の導出か実行可能な保証に置く。範囲の上限を作成側や AI が決める形は、ADR-0023 決定2・3・7・8、第3章 3.5.3・3.10.12、附属書H H.4 条件4 と衝突する
- 準拠テンプレートの PR の様式の注記「省略した場合は差分全体が対象です」は、裏返すと「指定した場合は指定箇所だけが対象」と読めた
- 長期的な決定を PR から G-3 へ引き上げる手段は、PR の様式の折りたたみの自己チェック(作成側の申告)しか無かった
- 外部: AI のレビューを起点にすると、人は AI の示した箇所に注意を寄せ、高重大度の指摘は増えなかった(対照実験 1 件)。人のレビューの価値の多くは保守性と理解の共有で、AI のレビューの既定の観点(正しさ)と重なりが小さい。AI のレビューの検出性能は、ベンダの関与した測定しかない。パス・型から公開 API の変更を検出し、専任の承認者へ回すオープンソースの長期の運用がある(1 件。規格化された作法は無い)

## 決定

### 1. 確認の範囲と深さ(第4章 G-6)

- G-6 の承認の範囲を、PR ごとの論点に絞る運用を採らない
- 差分が受入基準の範囲内かの確認(附属書C のパス1)は、差分の全体に掛ける。作成側の指定・AI の指摘・注意喚起部で対象から外さない
- 逐行に読む箇所を限ってよいのは、根拠が機械の導出か実行可能な保証(L1 の根拠)の場合に限る
- 作成側の「レビュー観点の指定」と AI の指摘は、注意を狭める情報として扱い、範囲の上限にしない。パス1 を終えてから読むことを勧める。読んだ時点を記録で確かめる手段が無いため、要求事項にしない
- AI の申告した確かめた範囲を、人の読む範囲を狭める根拠にしない(EV-0205、E1)
- 第3章 3.5.3 の「注意を狭める情報を、仕様との突合を終える前に開いてはならない」が人の確認者に掛かるのは、レビューパッケージの注意喚起部だけとする。PR の「レビュー観点の指定」と AI のレビューの指摘は、PR の画面で差分と同時に示されて隠せず、読んだ時点を記録で確かめる手段も無いため、禁止の対象に含めない(突合 X-1 を受けて 3.5.3 に明記した)
- 内部監査の観点25 で、レビュー観点の指定に範囲を除外する記述が無いかを抜き取る(附属書H)

### 2. リスクの層で人の承認を外す運用の受け皿

- 低リスクの変更を人の承認なしで取り込み、人が標本を見る運用(Anthropic・Meta の確かめられた運用)は、第5章 5.5.4 の条件と G-6「委任の変更は判定の時点を事後へ移す」が受ける。リスクの採点で審査の深さを変える運用は、担保水準 L2 が受ける。2つ目の経路を新設しない(#172 の棄却と同じ理由)。この対応づけを本文に書く

### 3. 判断記録の要否の規則(第2章 2.6)

- 変更の対象のパス・変更種別から「判断記録を要する変更」を導く規則を、プロセス構成に置く。置き場と手続は区分の下限の規則(3.8.1)に揃え、別の値として書く。規則は基底ブランチから読む。規則の変更の下限を R2 とし、規則の変更に製品のコードを含めない
- 規則に当たった変更は、判断記録の識別(トレーラ `ADR`)を要する。取り込む前に、その判断記録の G-3 の判定記録を要する。新しい承認の席を置かない
- 規則に当たった変更を、申告で外す経路を置かない。偽陽性は、規則を狭める変更(統制を緩める変更)か、判断記録に「選択の余地が無かった」と書いて G-3 に掛けることで扱う
- S0 では失敗させず注意に留める。2.6 のステージ表の S0 の行が、判断記録を G-3 の判定の対象とした選択に限るためである。S1 以降は、規則の宣言をステージ表の判断記録の行(S1 はコア機能)に優先させる。規則は、組織がそのパスの選択を判断記録の対象と定めた範囲だからである。G-6 基準3 の規則に当たる変更も S1 以降に限る
- 規則の網羅は主張しない。規則が無い構成と、規則のパスが追跡中のファイルに当たらない構成は、未宣言として「判断記録を要する設計上の選択を検出できない」と示す。AI・作成者・レビュアは「判断記録が要る」と足してよく、AI の「当たらない」で外さない
- 依存の追加・更新は G-5 基準8 と G-6 基準5 の経路に残し、規則に自動で含めない
- G-6 基準3 を、規則に当たる変更へ広げる。設計上の選択の妥当性は G-3 が判定し、G-6 では判定しない(EV-0206、E2)
- 準拠テンプレートでは、G-5(`pr-rules`)が規則を照合する(IMPL-0384)。PR を経ないコミットへの照合は降りていない(IMPL-0389、#423)。規則を緩める構成の変更は、変化点の入口が決定者の記名なしに受け付けない(IMPL-0390)

### 4. AI のレビューの位置づけ

- 論点の外を AI のレビューで「補う」ことを、検出の層(附属書H H.4)の外に数えない。H.4 の条件4 を維持する。「補う」を規定の語にしない
- AI のレビューを承認とみなさないことは、H.4 と第3章 3.5.4 の既存の規定のとおりで、書き直さない
- AI のレビューの指示を PR 自身の変更から読まないことは、H.4 の条件3 で既に要求事項である。実行層(IMPL-0333)は降りていない(#369)。この欠落を運用の前提の欠落として記録する。準拠テンプレートの `ai-review.yml` に、head 側の指示を読む道具をそのまま使う構成は条件3 を満たさない旨を書く

### 5. 記録と計測

- G-6 の判定記録に「確認した範囲・確認していない範囲」の欄を課さない
- 絞り込みの失敗は結果の側で測る。第5章 5.6.2 に「示した箇所の内と外」を置き、注入の一部を注意を狭める情報の外に置いて、内と外の検出率を工程単位で記録する(運用中の継続の注入は準拠テンプレートに無く、IMPL-0387 は降りていない)。欠陥の台帳に欄「レビューで示した箇所(内 / 外 / 提示なし)」を置く(IMPL-0388)
- 「レビュー観点の指定」は任意のまま残す。書き手は作成側の人、指定の有無にかかわらず対象は差分の全体、結論を含めない、パス1 の後に読む、の4点を本文と準拠テンプレートの注記に書く
- `/review` のスキルは新設しない。`/gate G-6` と `/human-verify` に、パス1 を差分の全体に掛けることと、「限定」の根拠に作成側の指定と AI の指摘を数えないことを書く(IMPL-0385・0386)

### 課さないと決めたこと

次は、検討したうえで課さないと決めたことです。書かれていないのではありません。

- PR ごとに「人が確かめるべき論点」を作成側に書かせること、AI に抽出させること
- G-6 の判定記録に、確認した範囲・確認していない範囲を書かせること
- レビュアが AI の指摘を読む時点(推奨に留める)
- 「レビュー観点の指定」の必須化
- 長期的な決定の専任の承認者の席
- 規則に当たった変更を、人の記名による「設計上の選択を含まない」の記載で外すこと
- 「論点」を本標準の用語にすること

既存の未達(IMPL-0220・0253・0155・0168・0333)は、本 ADR で解消したことにしません。

## 影響

- 第4章 G-6(基準3、節「確認の範囲と深さ」、IMPL-0385・0386、EV-0205)、第3章 3.5.3(人に掛かる禁止の範囲)、附属書H(観点25)、附属書C(入力の分離の表の注)
- 第2章 2.6(節「判断記録の要否の規則」、IMPL-0384・0389・0390、EV-0206)
- 第5章 5.6.2(節「示した箇所の内と外」、IMPL-0387・0388)
- 附属書C(パス1、入力の分離の表)、フェーズ5 PR ワークフロー(レビュー観点の指定)
- 準拠テンプレート: `scripts/gate/check-pr.mjs`(構成の `decisionRules`)と試験、PR の様式、`gates/G-6.md`、`/human-verify`、欠陥の台帳、`ai-review.yml`
- 残るリスク: 規則に載らない長期的な決定(暗黙の契約、依存の意味の変化)は漏れる。自己チェック・パス1・差し戻しに残り、漏れは欠陥の台帳と内部監査の抜き取りで見つけて規則へ足す。パス1 の所要時間を測った資料は無い。小規模な組織では注入の件数が足りず、内と外の差を読めない
