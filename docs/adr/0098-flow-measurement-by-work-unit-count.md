## コンテキスト

[#417](https://github.com/Takenori-Kusaka/process-compass/issues/417) は、#406 / ADR-0094 の会議体が範囲の外とした流れの測定の 3 点です。調査(`research/417-deliberation/survey-417-*.md`)と、起案・現場・品質監査・規格・弁護の 5 委員の会議体(`research/417-deliberation/`)を経ました。

### 見つかったこと

- 2.10.1 は「件数ではなく容量」で配分すると書くが、容量の単位を定めていなかった。原調査では DSDM の 60% は工数の比で、清書のときに「工数」が「容量」に換わり、単位が落ちた(推測)。DSDM の原文は "in terms of effort to deliver" である。工数で数えると ADR-0019 決定3・ADR-0094 決定3 に当たり、件数で数えると 2.10.1 自身と矛盾した
- 数えるものの名が、要求・項目・作業単位・受入基準・Issue・タスクに分かれていた。作業単位は 1.4 に定義が無かった
- 完了スループットは「クローズした Issue の件数」で、閉じた理由を区別する記述が無かった。運用メトリクスは「未完了のまま閉じると滞留期間に現れる」と書いたが、滞留期間は未完了の項目だけを数えるため、閉じた項目と細かく分けた項目のどちらも現れない。水増しを捉える対の指標が働いていなかった
- EV-0087 の差し替え条件は「見積と実績の対応(実績 / 見積り)の実測 4 四半期分」を求めたが、実績の欄は様式に無く、ADR-0094 決定3 は実績を課さないとした。判定の文が実際に使うものは、見積の区分とやり直しの有無だけだった
- 準拠テンプレートの実装計画は見積の列を持たないのに、能力依存の定数の再評価は RC-03 を再評価待ちに数えていた
- 外部: Kanban Guide と Vacanti は件数で数え、story point とは同義でないとする。finished の定義は各チームの Definition of Workflow に委ねられ、主流は取り下げと重複を除く。計画外の完了を除く根拠は無い。GitHub の閉じた理由の既定は completed である。見積は平均で約 30% 超過する。自分の予実を振り返るだけでは、見積の精度が上がらない(Jørgensen & Gruschke 2009)。実績時間の記録・監視が業績を良くする証拠は無い(Ravid 2023 のメタ分析)

## 決定

### 1. 量は作業単位の個数とし、第1章 1.4 で 1 回だけ定義する

- 作業単位、作業単位の完了、完了スループット、計画容量を 1.4 に定義する。作業単位は、課題・タスクなど組織が 1 件の定義を記録する単位とする(第7章 7.7.9・ADR-0094 の「作業単位(タスク)」の用法を含む)。状態のラベルの対象としての用法(第3章 3.5.5)は課題と変更を指すと書き分ける
- 単位期間の長さと、平均をとる観測の窓(第4章「閾値の設定と較正」)を分ける。計画容量は、直近の観測の窓で測った単位期間あたりの完了スループットの平均 × 単位期間の数とする
- 計画容量は「直近の実測スループット × 当該ステージの単位期間の数」とし、作業単位の個数で表す
- 1 件の作業単位の定義、単位期間の長さ、完了の条件は組織が定め、規模の合意とともに記録する。置き場は S0 の初回は企画書(テンプレ6)、SG ではその判定記録とする。合意・計画容量・実測に同じ定義を用いる(2.10.2 要求事項4)。S0 の初回は計画容量を「実測なし」と記録し、SC-P の追加の上限を置かない
- SC-M に入れる要求は作業単位へ分けてから数える。分けていない要求は SC-M として確定せず SC-P に置く。分けた後に SC-M へ移すことは SC-M の増加であり、SG または 7.6 による。SC-P・SC-B の分けていない要求は、分けた見込みの個数で数える(EV-0199、E0)
- 2.10.5 の「容量の上限」を、SC-M・SC-P・SC-B の作業単位の個数の合計が計画容量を超える場合と書く
- 60%・20% は既定値のまま残す。DSDM の工数の比を個数の比へ移したことに実証が無いことを開示し、EV-0150 を E1 から E0 へ下げ、差し替え条件を記録のある量へ改める

### 2. 完了は、閉じた者の申告以外の記録で示されたものに限る

- 作業単位の完了を、組織が事前に定めた完了の条件を満たしたことが、取り込んだ変更との結び付きまたは完了の判定の記録で示された状態と定義する。閉じた操作そのものではない
- 取り下げ・重複・統合・分割・範囲からの削除で閉じたものは、定義に当たらないため数えない。除外の列挙は規範に置かず、手引きに例として挙げる
- 計画外の完了は数える
- 実測を測った同じ期間に、閉じたが完了に当たらない作業単位の個数を記録する(2.10.2 要求事項5)。これと 1 件の定義の記録を、完了スループットと併せて価値責任者が読む(2.10.4)。滞留期間は対にならないと手引きを直す。細かく分けたことによる増加を値で捉える指標は置けていない
- 閉じた理由の値だけを完了の証拠にしない
- 準拠テンプレートに集計は無い。降りていない規定として表示する(IMPL-0374)。様式の欄は IMPL-0373

### 3. EV-0087 は既存の記録で判定し、実績の欄を足さない

- 差し替え条件を、見積が 8 時間を超えたタスクと超えないタスクの、やり直しに至った割合と各群の件数に改める。最小標本数に満たない比較を判断に用いない
- 見積の区分ごとのやり直しの割合を、担い手ごと・人ごとに集計しない。テンプレ7 の運用ルールに置く(根拠水準のマークの中では説明として読まれ、禁止として効かないため)
- テンプレ7 に実績の欄を足さない(必須・任意とも)
- 8 時間の目安は残す。見直しの期日は 2027-04 のまま動かさない
- 見積の列を持たない様式では、能力依存の定数の再評価で RC-03 を再評価待ちに数えず、適用なしと示す(3.12.12。準拠テンプレートは IMPL-0372)

## 検討した選択肢

| 選択肢 | 出した者 | 採否と理由 |
| --- | --- | --- |
| 工数を容量の単位にする | 原調査の DSDM の読み | 採らない。作業単位 × 人の実績が要り、ADR-0094 決定3 と当たる |
| 見積の点数を単位にする | 検討 | 採らない。精度を装った見積り手法を用いない 2.10.2 と当たる |
| 単位の種類を組織に選ばせる | 検討 | 採らない(規格・弁護・品質監査)。既定値 60% の意味が組織ごとに変わり、既定値として働かない |
| 1 件の大きさを本標準が固定する | 検討 | 採らない(規格・弁護)。作業の性質に依る。定義を組織が記録し、合意と実測で揃える |
| 60%・20% を外す | 検討 | 採らない。S1 以降の初日に確約の上限が無くなる。見直しは EV-0150 による |
| 分けていない要求を確約範囲に入れる余地を残す | 検討 | 採らない。個数で数えられない量を確約することになる |
| 閉じた Issue の件数を数える | 現行の手引き | 採らない。取り下げ・重複が混ざる |
| 除外の列挙を規範に置く | 品質監査 | 採らない(規格)。列挙に無い閉じ方が完了に数えられる。肯定の定義なら漏れは値を下げる側へ倒れる |
| 計画外の完了を除く | 検討 | 採らない(5 委員一致)。根拠が無く、計画外の需要が見えなくなる |
| 閉じた理由の記録を規範で必須にする、またはその値を完了の証拠にする | 品質監査 | 採らない。既定が completed で、閉じた者の申告と同じである。閉じた理由は、数えなかった個数を出す材料にとどまる |
| 数える単位を本文で定めない | 弁護 | 採らない。分子と分母が違う量になり、比率が成り立たない |
| 閉じ方に警戒水準を置く | 検討 | 採らない。値の根拠が無い |
| テンプレ7 に実績の欄を足す(必須・任意) | 検討 | 採らない(5 委員一致)。ADR-0094 決定3 を維持する。判定に要らない |
| 経過時間(Draft PR の作成から取り込みまで)を差し替え条件にする | #406 の起案・現場 | 採らない(5 委員一致。出した委員も撤回)。待ちとレビューを含み、見積の作業量と別の量 |
| 任意に記録した実績を人の評価に使うことを禁じる | 規格 | 本件では採らない。実績の記録を課さない以上、禁止の対象が本標準の記録に無い |
| 8 時間の目安を即時に外す | 検討 | 採らない(弁護)。改めた差し替え条件の結果で 2027-04 に決める |
| EV-0087 の見直しの期日を 2027-11 へ延ばす | 起案 | 採らない。条件を改めたことを理由に後ろへずらすと、見直しが名目になる |
| ISO/IEC/IEEE 15939 を第1章 1.3 の参照文書に加える | 規格 | 本件では採らない。原典を読んでおらず、引く節を示せない〔未〕 |
| 体制の変化点(3.13)の後に計画容量を出し直す規定を置く | 品質監査の問い | 採らない。計画容量は直近の観測の窓で測り直されるため、別の規定を要しない |
| 作業単位を実装計画のタスクと別のものとして定義する | 当初の実装 | 採らない(独立の突合)。7.7.9・ADR-0094 が「作業単位(タスク)」と書いており、同じ語が 2 つの量を指す |

### 本件で決めないこと

- 8 時間の目安の存廃。改めた差し替え条件の結果で 2027-04 に決める。準拠テンプレートの実装計画は見積の列を持たないため、材料が無い場合の扱いも、そのときに決める
- 計画外の完了の比率を観測の対象にするか
