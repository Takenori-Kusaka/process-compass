## ステータス

採用(2026-08-07)

## コンテキスト

本サイトの規程には、実証に基づかない値が多数含まれます。停止条件の閾値、抜き取り監査の件数、エスカレーションの往復回数、測定の母数下限などです。運用を開始しなければ実測が得られず、実測がなければ値を確定できないため、これらを置くこと自体は避けられません。

問題は追跡です。本文には「実証に基づく値ではない」と書いてありますが、書式が揃っていないため、**どこに何件あるかを機械的に数えられません**。見直しの時期が来ても、対象を人手で探すことになります。

ソースコードには未完成箇所を示す慣習的な注釈がありますが、そのまま持ち込めません。本プロジェクトのトーン検査(`scripts/check-tone.mjs`)は、そうした注釈を「未完成の痕跡」として公開ドキュメントから排除します。<!-- tone-ok: 検査規則そのものへの言及 -->

そもそも両者は別物です。未完成は書き手に向けた印であり、公開してはなりません。根拠が弱いことは**読者が知るべき情報**であり、公開しなければなりません。

## 決定

根拠の水準が E3(独立した複数の測定)に達していない記述を、次の構文でマークします。

```markdown
:::caution[暫定 EV-0001 / 見直し 2027-02]
**対象**: 何が暫定なのか。
**根拠の水準**: E0(なし)。
**差し替え条件**: 何が得られたら確定させるか。
:::
```

4つの決定を含みます。

1. **マークは読者に見える**。HTML コメントや frontmatter ではなく、本文の注意書きとして表示する
2. **見直し期限を必須とする**。期限のないマークを認めない
3. **差し替え条件を必須とする**。「継続して検討する」のような文で埋められない項目にする
4. **根拠の水準を4段階の語彙で表す**。E0(なし)・E1(間接)・E2(単一事例)・E3(複数)とし、E3 のみマークを要しない

検査は `scripts/check-evidence.mjs` が行い、`npm run check` から実行します。全マークは[根拠水準の台帳](/process-compass/community/evidence-ledger/)へ自動集約します。書式の規約は[根拠水準のマーク規約](/process-compass/community/evidence-marking/)によります。

**期限の超過では `npm run check` を失敗させません**。月次の定期実行が検出し、棚卸しの Issue を起票します。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| frontmatter に一覧として集約する | 本文と離れるため、記述を書き換えてもマークが残る。乖離を検出できない |
| HTML コメントで埋め込む | 読者に見えない。根拠の水準の開示という目的を果たさない |
| ソースコードと同じ未完成の注釈を解禁する | 未完成と低根拠を混同する。トーン検査の規則とも衝突する |
| Issue だけで管理する | 本文のどこが該当するかを Issue 側からしか辿れない。読者には何も伝わらない |
| 期限の超過で `npm run check` を失敗させる | 日付の経過だけでデプロイが止まる。期限を延ばす操作が常態化し、期限が名目化する |

## 影響

- 全ページに構文の制約が加わる。書式の誤りは `npm run check` で失敗する
- 台帳ページは自動生成であり、手で編集すると検査が失敗する
- 規程の利用者は、どの値が実証に基づかないかをページ上と台帳の双方で確認できる

**マークの付け忘れを機械的に検出できません**。検査できるのは、書かれたマークの書式だけです。したがって「マークのない記述はすべて E3 である」とは読めません。この限界は規約ページにも明記します。

見直し期限の到来は、内容の変更を意味しません。差し替え条件の充足を確認する時期です。満たされていなければ期限を延ばし、記録を続けます。**期限の延長を記録なしで行わないこと**が、この仕組みが形骸化しない条件です。
