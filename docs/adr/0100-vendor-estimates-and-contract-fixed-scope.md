## コンテキスト

[#414](https://github.com/Takenori-Kusaka/process-compass/issues/414) は、#407 / ADR-0093 の会議体の現場の委員が残した 2 点です。この論点は ADR-0091 決定5 → #407 → #414 と 2 回送られていました。調査(`research/414-deliberation/survey-414-*.md`)と、起案・現場・品質監査・規格・弁護の 5 委員の会議体(`research/414-deliberation/`)を経ました。

### 見つかったこと

- 第8章 軸D の表に、見積り・提案・価格の行が無かった。7.7.9 の記録の置き場は発注側の企画書に固定され、受注側には要求事項11(上側を下回る差の受容)を記名する場が無かった
- 実測が存在しない間は SC-M を置かず全体が SC-P になる(2.10.2 の要求事項2)。軸D は SC-P の調整を「契約変更を伴わないことを契約に明記」とした。範囲を固定する請負の契約では、この 2 つが両立しない。後者の行には決定の記録が無かった
- 2.10.8 は「契約に影響」する変更を B-2 へ送る枝を既に持っていた
- 実測の主体(どの組織の実測か)が定義されておらず、委託先の交代で前の体制の実測を流用できた
- 外部: IPA の情報システム・モデル取引・契約書〈第二版〉は見積りを 4 段に分け、構想〜要件定義の見積りを参考値とする。提案書・見積書を個別契約の基礎とし(第4条)、変更の費用を従来の見積と比べて判断する(第38条の解説)。アジャイル開発版は準委任を前提とし、請負を確定している部分だけに限るよう勧める。Agile Contracts Primer は固定価格・固定範囲を避け、多段階・可変の型を示す。確約の比率の上限(DSDM 60%、Primer の約20%)は実証されていない。見積書の保存は税法で既に義務である

## 決定

### 1. 受注側の見積り

- 受注側の価格・見積書の様式・見積りの段の名前・保存期間・受注の決裁は、本標準で規律しない
- 受注側は、顧客へ示した見積りを版ごとに残し、書き換えない。変更の見積りは、示した版との差として示す(軸D。準拠テンプレートに置き場が無く、IMPL-0383 は降りていない)
- 発注側は、見積り値の出所を企画書に書く(7.7.9 の要求事項1、テンプレ6 の行「見積り値の出所」)。受注側の提案を根拠にした場合は、提案の識別と版、確定の見積りか参考値かを書く。幅が無ければ「提案に幅なし」、前提が無ければ「提案に前提なし」と書く。受注側の契約額・固定価格を、見積りの幅の上側として扱わない
- 7.7.9 の要求事項11 は発注側の提示に掛け、受注側の価格に掛けない

### 2. 契約で固定した範囲

- 契約で固定した範囲を、スコープの層とは別の属性として定義し、締結時に受入基準の識別子で記録する(テンプレ8 第14項。IMPL-0382)
- 軸D の行「計画範囲・調整枠の調整」を改める。契約で固定した範囲に触れる調整は、層によらず契約変更の起点とし、2.10.8 の「契約に影響」の経路で B-2 へ送る。価値責任者が単独で調整できるのは、契約で固定しない SC-P・SC-B に限る。7.6 は変えない
- 2.10.2 の要求事項2 は緩めない。実測が存在しない間(S0 の初回を含む)に範囲を固定する場合は、企画書に「実測の裏づけなし」と書き、発注側の事業決裁者が事業リスクとして記名で受容する(EV-0204、E0)
- 第2章 2.10.5 の調整の権限に同じ限定を書き、2.10.6 の手順1・2.10.7・2.10.8 の SC-P の組み替えにも掛ける。G-4 の外で固定した範囲に触れる調整が要ると分かった場合も、2.10.8 の「契約に影響」の枝へ入れる。B-2 を置かない体制では事業決裁者が裁定する
- 範囲を固定しない契約を推奨する。多段階の契約は手段の例として示し、課さない。契約の類型は選ばない

### 3. 実測の主体

- 実測は、当該案件で、同じ作業単位の定義で作業単位を完了させる組織(委託では受注側の実行の体制)の観測に限る。組織が変わった場合(委託先の交代を含む)は、実測が存在しない状態に戻る(2.10.2 の要求事項6。EV-0203、E0)。ステージの途中で組織が変わった場合は、確定済みの SC-M を消さず、観測の窓をその時点から新しくし、単位期間が 3 つそろうまで必達基準2 を「算定できない」と記録する(ADR-0099)。組織の交代は第3章 3.13.1 の変化点(委託先の交代)として記録する。テンプレ8 第10項に、受注側が作業単位の完了の記録を単位期間ごとに提出する行を置く(発注側が実測を得るため)

### 4. 様式と規則データ

- テンプレ8 に第14項「範囲と契約変更」を置き、「合意」を第15項へ繰り下げる
- テンプレ6 に行「見積り値の出所」と、欄「契約で固定した範囲(受託)」「実測の主体」を置く。「次ステージのスコープ3層」の表題は改めず、実測が存在しない間は SC-M を置かない旨の注記を置く(表題を改めると必須欄の照合と既存の企画書の読み替えが要り、注記で足りるため)
- 規則データ `r-d-outsourcer`・`r-d-vendor` に注記を足す。受託のプロファイルは作らない

## 影響

- 第8章 軸D(計画範囲・調整枠の行、顧客へ示した見積りの行、契約で固定した範囲の段落、定めないことの列挙、IMPL-0382・0383、EV-0204)
- 第2章 2.10.2(要求事項2 の書き方、要求事項6、EV-0203)
- 第7章 7.7.3(SC-M を置かない間の書き方)、7.7.9 の要求事項1・11
- 第6章 テンプレ6(見積り値の出所、契約で固定した範囲、実測の主体)、テンプレ8(第14項、合意を第15項へ)
- 規則データ `rules-dev-form.yaml`、準拠テンプレートの企画書(本体と 3 つのプロファイル)と AI-SLA 合意確認書
- 残るリスク: 実測が存在しない間は SC-P の追加に上限が無く(2.10.5)、範囲を固定する契約では固定した範囲の外の追加に上限が無い。価値責任者と事業決裁者の兼務の免除(7.6)が前提にする「相手方との合意が外の歯止め」は、範囲を固定しない契約では働かない。兼務の開示で受ける
