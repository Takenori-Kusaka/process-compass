## ステータス

採用(2026-08-14)

## コンテキスト

初回適用案件の受入基準86件のうち、**利用者が用途に気づくことを扱ったものは0件**でした([#246](https://github.com/Takenori-Kusaka/process-compass/issues/246))。

案件が中核の差だと主張していた利用者向けの操作面についても、受入基準は0件でした。企画書はその部分を「UI 装飾」と位置づけていました。

需要側の一次調査は、導入しない理由の首位として同じ結論へ収束していました。

| 出典 | 首位近辺の理由 |
| --- | --- |
| 総務省 令和7年版 情報通信白書 | **使い方がわからない 38.6%**(日本)。米 26.0% / 独 18.7% |
| IPA『DX動向2025』 | 効果やリスクの理解が不足 48.6%、**誤った回答を信じて利用してしまう 40.5%** |

**律速は機能の不足ではなく、利用者が用途を思いつかないこと、および出力を信じてよいか判断できないことでした**。

### 標準が扱うべきかは自明でない

EARS 記法の受入基準は「条件 + 期待動作」の形を求めます。**これは機械が検証できる形であって、人が用途に気づける形ではありません**。この2つは独立です。

一方で、**開発プロセスの標準が使いやすさを判定基準にすると、標準が製品の良し悪しを判定し始めます**。本標準は[5.7.4](/process-compass/phase4-process-design/human-ai-boundary/)で記述の質の機械判定を禁じ、ADR-0014 決定9 で成熟度ラベルを出さないと決めています。**製品の評価は、この標準の役割ではありません**。

### 案件側の帰属が大きい

会議体で帰属を確かめた結果です。

| 事象 | 帰属 |
| --- | --- |
| 受入基準86件に該当が0件 | **案件側の仕様設計**。標準は受入基準の内容を規定しない |
| 中核の差だと主張した部分の受入基準が0件 | **案件側**。価値仮説に根拠を付けずに進んだ結果 |
| 「見て気づけるか」を問う工程が標準に無い | **標準の落ち度ではない** |

## 決定

### 1. 使いやすさ・学びやすさを判定基準としない

**成果物が使いやすいか、利用者が用途に気づけるかを、いずれのゲートでも判定しません**。

**「書かれていない」のではなく、扱わないと決めました**。

理由は2つです。**第一に、判定できません**。使いやすさの判定は評価者の主観に依存し、5.7.4 が禁じた記述の質の判定と同じ構造になります。**第二に、扱うと標準が製品の良し悪しを判定することになります**。本標準が扱うのは、判断が実質的に行われたことの確認です。

### 2. 価値と受入基準の対応だけを G-2 で見る

**企画書 観点3(受益者と価値)に書いた価値のうち、受入基準へ対応するものが1件も無い項目が残っていないかを確認します**。

**受入基準の内容そのものは判定しません**。対応の有無だけを見ます。**判定できるのは、対応が存在するかどうかだけです**。

この確認は新しい判定基準ではなく、**G-2 基準1 の確認方法への追加**です。判定の総数を増やしません。

### 3. 案件が使いやすさを扱う場合、受入基準の側へ書く

案件が使いやすさを重要と判断する場合、**それを企画書の観点3 へ価値として書き、対応する受入基準を置きます**。決定2 の確認は、その対応の有無を見ます。

**標準は、何を価値とするかを指定しません**。指定するのは、価値として書いたものに受入基準が対応しているかだけです。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 使用性の判定基準をゲートへ追加する | 判定が評価者の主観に依存する。5.7.4 が禁じた構造と同じになる |
| 受入基準の類型に「発見可能性」を必須で加える | 受入基準の内容を標準が規定することになる。案件ごとに価値は異なる |
| SG-1 の「受入部門が要求を自らの言葉で再構成できている」を機能単位へ降ろす | 対象が受入部門であって受益者ではない。粒度もステージ全体であり、降ろすと別の要求になる |
| 何も書かない(現状) | 「書かれていない」のか「扱わないと決めた」のかが読み取れない |

## 帰結

- 使いやすさは、いずれのゲートでも判定されない
- **価値として書いたものに受入基準が対応しているかは、G-2 で見る**
- **利用者が用途に気づけるかは、本標準では担保されない**。この限界は解消しない
- 案件が使用性を扱う場合の経路は、企画書の観点3 と受入基準である

:::caution[暫定 EV-0037 / 見直し 2027-08]
**対象**: 決定2(価値と受入基準の対応を見れば、価値の取りこぼしを検出できるという判断)。

**根拠とした事例**: 案件 P-001。企画書に価値として書いた項目のうち、受入基準へ対応しないものが存在した1件の観測に基づきます。

**差し替え条件**: G-2 の確認で「対応する受入基準が無い価値」が指摘された件数と、そのうち後工程で価値の位置づけを見直した件数。**指摘が0件のまま、後工程で価値の位置づけの見直しが生じた場合、この確認は取りこぼしを検出していないことになります**。
:::
