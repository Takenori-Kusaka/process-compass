## コンテキスト

[#355](https://github.com/Takenori-Kusaka/process-compass/issues/355) 束4 は、実装マーク IMPL-0048・IMPL-0136・IMPL-0159・IMPL-0230 の降りていない部分を扱いました。審議は軽(起案と反対の2委員)で行い、2委員の結論は割れました。議長が裁定し、記録は `research/355-deliberation/` にあります。

- IMPL-0048(委任の期間の開示)は、期間の経路を通して流す試験が0本だった。実行で確かめると、一時のリポジトリでは1回1秒未満で流せた
- IMPL-0159(承認に要した時間と規模の比)の式は、運用メトリクスが既に定めている。集約は承認に要した時間と規模の比を出していなかった(超過 PR の判定完了時間は出していた)
- IMPL-0136(文書だけの変更の SLA の判定)の措置(催促・通知・代理判定者の指名)は、変更が開いている間に働く。出荷の時点の分布は、判定ではなく、措置でもない。レビュー SLA の節は未棚卸し
- 3.11.7 は「継続して計測します」と「個人の指標と保守性の指標は必ず対で確認します」の2文からなる。「個人の指標」は定義も、その収集を求める条項も本標準に無い

## 決定

### 1. 委任の期間の開示は1つのマークで降ろし、実機は根拠水準マークで開示する(IMPL-0048)

`delivered check=machine` と表示する条件は、試験が通ることです。規定の文は「区切って出す」「記録が無ければ欠落」を定め、定期の起動の仕組みを別の文で課していません。定期の起動が実機で動くかは、規定の文ではなく実装の根拠の水準です。そのためマークを分けず、EV-0275 で開示します。機械は、期間が過ぎたのに開示が出ていないことを検出しません。確かめるのは、期間の開示を突合して記名する出荷判定者の席で、5.5.4 に1文を足して書きます。

### 2. 承認に要した時間と規模の比は、人の承認だけで区間ごとに出す(IMPL-0159)

`delivered check=manual` で降ろします。規定の文は「計測する」で、判定を求めていません。

- 比は規模の区間ごとに出す。値は100行あたりの分の最小・下位四分位・中央値と件数である。閾値と比べず、前回との比較は出さない
- 承認者別の内訳を出さない。PR ごとの組にも login を持たせない(運用メトリクス原則4)
- 人の承認だけを数える。AI 名義の承認は判定でない。既存の IMPL-0100 の判定完了時間も、人の承認だけに直す
- 時計時間は承認者が掛けた時間の上限で、短い値だけが確かである。警戒サインは短い側なので、近似は見逃す向きにだけ誤る。起点が運用メトリクスの定義(Ready 化)と違う点とともに、EV-0276 で開示する
- 文書だけの変更は算定行数が0で、比を持たない(ADR-0072 決定3)。件数だけ出す
- ADR-0092 決定7 のうち IMPL-0159 は、製品のコードの変更について降りる

### 3. 文書だけの変更の SLA の判定は降ろさず、観測を判定と呼ばない(IMPL-0136)

`undelivered plan=scheduled issue=355 review=2027-02` を保ちます。観測(文書だけの変更の、作成から最後の人の承認までの時計時間の分布)は足します。見出しに「観測。SLA の判定ではない」と書き、「超過」の語と件数は出しません。降ろしていないのは、依頼の時刻を起点にした経過、営業日の暦(採用者の入力)、開いている変更への催促・通知です。規定の文は直さず、参照だけを足します。判定の主語と、文書だけに固有の判定を置くかは、重の審議で決めます。

### 4. 3.11.7 を2つのマークに分け、計測だけを採用者に委ねる(IMPL-0230・IMPL-0981)

- **「継続して計測します」(IMPL-0230)**: `plan=adopter` にする。
  - 委ねる理由: 4指標の定義・観測の窓・最小標本数は組織が G-1 で定める(第4章「閾値の設定と較正」)。履歴の解析の手段が採用者の基盤に依る。値は傾向の確認にだけ使い、合否にも 5.4.6 にも使わない
  - 求めること: G-1 で定めた定義と窓で自動の集計の手段を置き、値を 5.4.6 の入力にしない
- **「個人の指標と保守性の指標は必ず対で確認します」(IMPL-0981)**: 決めない。`undelivered plan=scheduled issue=355 review=2027-02` として新設し、直し方は重の審議へ残す。事実だけを EV-0277 で開示する

## 課さないと決めたこと

- 実機の通しを準拠テンプレートの検査に数えること。採用者の環境でしか行えない
- 比に警戒の水準・前回との比較・承認者別の内訳を付けること
- 文書だけの変更に、散文の行数を分母にした比を出すこと
- 文書だけの変更について、時計時間で超過の件数を出すこと。週末をまたぐ偽の超過が出る
- 準拠テンプレートが、リポジトリ単位の2指標の参考値や、個人の単位の指標を算出すること

| 0230: リポジトリ単位の2指標の参考値、個人の指標を準拠テンプレートが算出する | 定義で値が動き「計測した」という表示を生む / 運用メトリクス原則4 に反する |

## 見直しの契機

- EV-0275・EV-0277 の見直し時期(2027-02)、EV-0276 の見直し時期(2027-05)の到来
- #355 の重の審議で、IMPL-0136 の SLA の判定と IMPL-0981 の直し方が決まったとき
- 採用者または所有者の実機で、定期のワークフローの起動の記録が得られたとき

## 影響

- IMPL-0048 と IMPL-0159 は `delivered` になる。IMPL-0136 と IMPL-0981 は `undelivered` のまま台帳に出続ける
- IMPL-0230 は台帳の「採用者が実装する」に移る
- 出荷の証跡の集約は、承認に要した時間と規模の比、文書だけの変更の承認までの時間の分布を、保証の開示の観測に出す。合否にも警戒の条件にも使わない
- 実装(準拠テンプレートの試験を含む)の実行での確認は、EV-0275・EV-0276 で開示する
