## コンテキスト

[#362](https://github.com/Takenori-Kusaka/process-compass/issues/362) は、準拠テンプレートを、既定ブランチが `main` でないリポジトリへ持ち込めないことを問いました。`gate-g5.yml` の push の契機が `branches: [main]` に固定され、事前点検(#315)はそれを理由に既定ブランチが `main` でないリポジトリを止めていました。外部の連携が既定ブランチの名に依存するリポジトリは、改名できず、持ち込めませんでした。

審議の重さは軽です。採用者へ新しい義務を課さず、強制層のワークフローを案件ごとに変える経路を作らないためです。記録は `research/362-deliberation/`(`survey.md`、`council-01-drafter.md`、`council-02-opponent.md`、`decision.md`、`implementation.md`)にあります。

### 確かめた事実

| 事実 | 出所 |
| --- | --- |
| `on.push.branches` は式を評価しない。コンテキストを使える場所の表に無く(SRC-0730)、式を書くと「Invalid workflow file … Unrecognized named-value: 'github'」になり、どのブランチへの push でも失敗の実行が出る | 実機(2026-11-11) |
| push の絞りを外してジョブの `if:` で既定ブランチに絞ると、既定ブランチでないブランチへの push で、名が `gate-g5` の skipped の check run が先頭のコミットに付く。条件で skipped のジョブは必須チェックの成功に数えられる(SRC-0573)。PR の `gate-g5` が作られる前にマージを試みると、PR の検査が落ちる変更がマージされた | 実機(2026-11-11) |
| push を契機とするワークフローから `gate-g5.yml` を `workflow_call` で呼ぶと、既定ブランチでない push では呼び出し側のジョブの名(`default-push`)の skipped の check run だけが付き、既定ブランチへの push では `default-push / <ジョブ名>` の check run になる。PR の直後のマージは拒否された | 実機(2026-11-11。テンプレートの実物の `gate-g5.yml`) |
| 呼ばれた側の `github.event_name` は `push`、`github.event.before` は呼び出し側の push の直前のコミットであり、契約検査は `--base` で比べた | 実機の実行の記録(2026-11-11) |
| ルールセットの対象 `~DEFAULT_BRANCH` は既定ブランチの名に依らない。テンプレートのルールセット(`records` を除く)はすでに使っている | テンプレートの `.github/rulesets/` |

## 決定

### 1. push の契機を別のワークフローに分ける

- `gate-g5.yml` から `on.push` を外し、`on.workflow_call` を足す。`pull_request` と `workflow_dispatch` は残す
- `gate-g5-push.yml` を置く。契機は `on.push.branches: ['**']`(タグの push では起動しない)。ジョブは1つで、ID と名はどちらも `default-push`。条件は `github.ref == format('refs/heads/{0}', github.event.repository.default_branch)`。`github.ref_name` はタグと区別しないので使わない。`uses: ./.github/workflows/gate-g5.yml` で呼ぶ
- push のワークフローには、ID か名が `gate-g5` のジョブを置かない。どのワークフローにも、集約(`gate-g5.yml` の `gate-g5`)のほかに ID か名が `gate-g5` のジョブを置かない。別の契機で名が `gate-g5` の check run が PR の先頭のコミットに付くと、必須チェックを満たしてしまうためである
- 既定ブランチの名は実行時に読む。持ち込みの後に既定ブランチを改名しても、強制層を書き換えずに追随する
- 出荷の証跡の取り込み(`ship-evidence.yml`)と env-check の項目3 は、`gate-g5-push.yml` の成功した実行を先に探し、無ければ `gate-g5.yml` の実行(手動の起動)を探す

### 2. 事前点検は、名ではなく契機の形で止める

- 止める項目「既定ブランチが `main` でない」を外す
- 止める項目 `push-trigger` を置く。止めるのは次のいずれかの場合である。`gate-g5-push.yml` の欠けと決定1 と違う形、`gate-g5.yml` が push を契機に持つ(旧版の複製)、`gate-g5.yml` に `workflow_call` または `pull_request` が無い、集約のほかに ID か名が `gate-g5` のジョブがある。`pull_request` を欠くと、PR の必須チェック `gate-g5` の発行元が無くなる。旧版の `gate-g5.yml` を持ち込むと、名が `main` でないリポジトリで push の契約検査が黙って走らないためである
- 同じ確かめを契約検査が PR と push のたびに行う。初期化の後に push の契機を戻す変更を検出する
- 既定ブランチの名と読み方は、事実として点検の結果に残す。読み方が「現在のブランチ」(`origin` の HEAD も手元の `main` も無い)のときは、GitHub の既定ブランチと一致するかを人が確かめるよう添える(止めない)

### 3. 付随の修正

- `/pit`(`next.mjs`)の既定ブランチの読み方を、`origin` の HEAD を先に読む形へ直す。`main`・`master` しか見ない読み方では、既定ブランチが `trunk` のリポジトリで済んだタスクを数えなかった
- 準拠テンプレートの常駐の規則の核の文言「トランクベース。main は常にリリース可能に保つ」は改めない。核の文言の変更は標準の規定の書き換えに当たる([ADR-0084](/process-compass/adr/0084-check-strength-plans-and-resident-rules/)決定2)。既定ブランチが `main` でない案件では字義どおりに読めない、既知の食い違いとして記録する

## 影響

- 既定ブランチが `main` でないリポジトリへ、改名せずに持ち込める
- 初期化の後に既定ブランチを改名しても、push の契約検査が止まらない。従来の書き方では、改名で黙って止まっていた
- すべてのブランチへの push で、ジョブが skipped の実行が1つ増える。skipped のジョブは実行の時間を使わない
- 準拠テンプレートの強制層のファイルが1つ増える(`gate-g5-push.yml`)。`.github/workflows/**` は統制の設定であり、変更は AI維持管理者の承認を要する
- 既存の採用者は、テンプレートの更新の取り込みで `gate-g5.yml` と `gate-g5-push.yml` を揃える。片方だけを取り込むと、契約検査が `push-trigger` の不備で落ちる

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 止めたまま(現状) | 改名できないリポジトリを持ち込めない。初期化の後の改名で push の契約検査が黙って止まる穴も塞がない |
| `branches` に式を書く | 不正なワークフローになり、どのブランチへの push でも失敗の実行が出る |
| 初期化が既定ブランチの名を `branches:` へ書く | 強制層の定義を案件ごとに変える経路を作る(ADR-0085 で採らなかった理由と同じ)。改名のたびに強制層の変更が要り、改め忘れると push の検査が黙って止まる |
| 名を列挙する(`main`・`master`・`trunk`・`develop` など) | 列挙の外の名を持ち込めない。列挙した既定ブランチでないブランチの push で、契約検査が既定ブランチの履歴でない比較をする |
| `gate-g5.yml` の push の絞りを外し、ジョブの `if:` で絞る | 既定ブランチでない push の skipped の `gate-g5` が必須チェックを満たし、PR の検査が落ちる変更をマージできた。委任の条件3 はすべての `gate-g5` に success を求めるため、委任のマージが常に止まる |
| 上に加えて、集約の名を式で替える | 迂回は実機で塞げた。ただし、skipped のジョブの名を式の文字列のまま表示する振る舞いは文書に無く、ジョブ ID へ戻す振る舞いに変われば迂回が黙って戻る |
| 上に加えて、集約のジョブ ID も替える | どの振る舞いでも止まる側へ倒れる点は決定1 と同じ。ただし9つのジョブへ同じ条件を書き写し、ジョブの `if:` を確かめる検査が無い。集約のジョブ ID は契約検査と保証の開示が読む契約で、変えると既存の採用者に移行を求める |
| 改名の手引きだけを書く | 止めたままと同じ |
| 事前点検の名の項目を単に外す | 旧版の `gate-g5.yml` を持ち込んだリポジトリが素通りする |
| 「既定ブランチが `main` でない」を告げる項目にして一覧へ載せさせる | 名は、既定ブランチが出荷の系列かどうかの手がかりにならない。止める理由の無い事実を一覧の照合に掛けると、対処の要る事項と誤読される。既定ブランチの主系列を適用の開始と出荷の範囲の基準にすることは、第1章 1.10.1 と第5章がすでに定めている |
| 常駐の規則の核の文言を本件で改める | 標準の規定の書き換えに当たり、本件の審議の範囲を超える |
| 既定ブランチでないブランチでの `workflow_dispatch` を本件で塞ぐ | 手動の起動で名が `gate-g5` の check run が付くことは実機で確かめた。現状にもある経路で、決定1 は広げも狭めもしない。塞ぐ形の審議を経ていないため、範囲の外として申し送る |
