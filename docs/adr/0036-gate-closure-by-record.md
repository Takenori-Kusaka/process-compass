## ステータス

採用(2026-08-13)

## コンテキスト

案件 P-001 で、G-2(要件合意)の判定基準5点がすべて充足しているにもかかわらず、**「どうすればゲートが閉じるのか」が誰にも分からず工程が止まりました**([#223](https://github.com/Takenori-Kusaka/process-compass/issues/223))。

判定材料は揃い、レビューも済み、Issue も閉じられていました。存在しなかったのは判定記録だけです。**この状態が「通過」なのか「未判定」なのかを、標準から判定できません**。

### 規定と実行層の向きが逆転していた

第4章のゲート運用の共通ルールは「記録が残る」とだけ定めています。これは判定の成立要件とも、判定後の事務とも読めます。

一方で、準拠テンプレートには `gate-record` スキルと[テンプレ4 ゲート判定記録](/process-compass/phase4-process-design/deliverable-templates/)があり、記録の様式も「結果: 通過 / 差し戻し」という語彙も、そちらに書かれています。

| 項目 | 標準本文 | 準拠テンプレート |
| --- | --- | --- |
| ゲートを閉じる手順 | 無い | `gate-record` スキルにある |
| 判定の語彙 | 会議体の4値(3.7.3)のみ | テンプレ4 が2値を規定している |

[ADR-0010](/process-compass/adr/0010-data-doc-interface/)は「本章が判定基準の正本」という向きを定めています。**判定手続については、この向きが成立していません**。実行層のテンプレートが事実上の正本になっていました。

これは[#216](https://github.com/Takenori-Kusaka/process-compass/issues/216)で確定した「規定はあるが実行層へ降りていない」の**逆向き**の破れです。[実装マークの仕組み](/process-compass/community/implementation-marking/)は規定から降ろし先への一方向しか見ておらず、この逆流を検出できませんでした。

### 判定の語彙が工程ゲートに無い

第3章 3.7.3 は判定の4値(継続 / 中止 / 保留 / 差し戻し)を定めますが、主語は「すべての**会議体**は」です。工程ゲートは会議体ではありません。判定者は1人であり、判定会議を開かないためです。

3.7.4 の B-2 ステアリングコミッティは、決定しない事項として「**工程ゲート(G-1〜G-8)の判定**」を明記しています。中止と保留は投資の継続可否であり、ステージ移行ゲート(SG)の領分です。**4値を工程ゲートへ持ち込む設計にはなっていません**。

しかし工程ゲートの語彙が本文にないため、案件からは「どちらを使うのか不明」と見えます。

### 「条件付き」を求める要求が上がっている

P-001 の事業決裁者から、次の意見が寄せられました。

> 3.7.3 の4値には「差し戻し」と「保留」はあるが、**「条件を付して先へ進める」がない**。実務では最も使う判定である

具体例として、ADR-0004(JWT クレーム契約)が未執筆のまま F-003 の受入基準がそれに依存している状態が挙げられ、「ADR-0004 の執筆を条件として G-2 を通す」が最も妥当だが語彙がない、とされました。

**この事例を精査すると、条件付きの語彙は必要ありません**。G-2 の判定基準5点はすべて充足しています。ADR-0004 は G-3(技術設計判断)および G-4(機能仕様承認)の材料であり、G-2 の判定基準には含まれません。**当該ゲートの判定基準に含まれないものを、当該ゲートの判定へ持ち込んでいます**。

第3章 3.7.5 は「会議体に持ち込んではならない事項」を定めていますが、**工程ゲートについて同じ規定がありません**。欠けているのは条件付きの語彙ではなく、判定の範囲の規定です。

## 決定

### 決定1: 判定記録の作成をもって判定の成立とする

工程ゲートの判定は、判定記録([第6章 テンプレ4](/process-compass/phase4-process-design/deliverable-templates/))の作成をもって成立します。**記録の無い状態は未判定として扱います**。

Issue のクローズ、PR のマージ、ラベルの遷移は、いずれも判定の成立要件ではありません。判定の成立に伴う事務です。

理由は、記録がなければ判定の存在そのものが自己申告になるためです。[ADR-0035](/process-compass/adr/0035-separation-by-execution-context/)が自己申告による判定を排したのと同じ理由によります。

### 決定2: 工程ゲートの判定の語彙を2値とする

工程ゲートの判定は「**通過**」または「**差し戻し**」のいずれかとします。中止と保留を用いません。

中止と保留は投資の継続可否であり、ステージ移行ゲート(SG)が判断します。工程ゲートの問いは「この成果物を次工程へ進めてよいか」だけです。

第3章 3.7.3 の4値は会議体の語彙であり、工程ゲートへ適用しません。

### 決定3: 「条件付き通過」を設けない

条件を付して先へ進める手続は、**第7章 7.3 の例外承認**です。新しい判定値を設けません。

7.3 は次の5点を要求します。この5点が「条件」の実装にあたります。

- 例外承認の権限を持つ者による記名の承認
- 満たさない基準の項目番号と理由の記録
- 想定される影響と、顕在化した場合の対処の記録
- 回収の期限と回収責任者の設定、技術負債台帳への登録
- 回収が完了するまでの継続的な報告

新しい判定値を設けない理由は2つあります。

第一に、7.3・7.10(前提の受容)に続く3つ目の経路になります。同じ事象に3つの手続が並ぶと、最も緩い経路が選ばれます。

第二に、**「条件付き通過」は素通しの正規経路になります**。7.3 は回収の期限と責任者を要求しますが、判定値として与えると、その要求を伴わない通過が生まれます。本標準の一文「決められた場所では必ず人間が触る」が最も壊れやすい箇所です。

### 決定4: 工程ゲートの判定は当該ゲートの判定基準のみで行う

判定者は、当該ゲートの判定基準および全ゲート共通の通過条件だけを評価します。**次工程の材料が未完成であることを、当該ゲートの差し戻し理由にしてはなりません**。

当該ゲートの判定基準を満たさないまま進める場合に限り、7.3 の例外承認を用います。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 「条件付き通過」を第5の判定値として新設する | 決定3 のとおり。回収の要求を伴わない通過の経路が生まれる |
| 3.7.3 の4値を工程ゲートへ拡張する | 中止・保留は投資判断であり、B-2 が「工程ゲートの判定は決定しない」と定める構成と衝突する |
| Issue のクローズをもって判定の成立とする | 案件の課題管理ツールに依存する。ツールを変えると判定の成立要件が変わる |
| 標準を変更せず、テンプレ4 を判定手続の正本と認める | ADR-0010 の向きが逆転したままになる。テンプレートは案件が改変できるため、統制の根拠にならない |
| 判定記録の作成を事後の事務のままとする | 記録の無い判定を検出できない。P-001 の状態が再発する |

## 影響

- 第4章の共通ルール4 を、成立要件として書き直した。「判定の成立」「判定の語彙」「判定の範囲」の3節を新設した
- 第7章 7.3 に、条件を付して進める手続がここであることを明示し、第4章から相互参照した
- 第5章 [Label Mailbox](/process-compass/phase5-implementation/label-mailbox/) に、判定の成立とラベル遷移の関係を1節加えた。**ラベルは増やしていない**
- 準拠テンプレートのテンプレ4 と `gate-record` スキルを、実装マークの降ろし先として登録した
- **[実装マークの規約](/process-compass/community/implementation-marking/)に、逆流を検出できない限界を追記した**

:::caution[暫定 EV-0021 / 見直し 2027-02]
**対象**: 決定3(条件付き通過を設けない)。条件を付して進める要求を 7.3 の例外承認だけで受けきれるという判断。
**根拠の水準**: E2(単一事例)。
**差し替え条件**: 案件ごとに次の3つを数える。

- (a) 7.3 の例外承認の適用件数
- (b) G-7 基準5 の完備確認で検出された、判定記録の欠落件数
- (c) 期限を超過した未回収の例外承認の件数

**(b) が (a) を上回る案件が生じた場合、手続の重さが回避を招いていると判定する**。(a) と (b) がともに0であり、かつ判定基準の不充足が観測されなかった場合、7.3 だけで受けきれていると判定する。

案件 P-001 の G-2 で観測された1件の停止に基づきます。実務で条件付きの判定を必要とする頻度の実測を持ちません。

**本条件は 2026-08-14 に書き直しました**。旧条件は「3案件分のゲート判定記録と、7.3 の例外承認の適用件数。適用が過小であれば、手続の重さが回避を招いている」でしたが、**適用0件が「回避された」とも「逸脱が発生しなかった」とも読め、対立仮説を分離できませんでした**。件数を増やしても、過小の判定基準が無い以上は解消しません。経緯は[ADR-0045](/process-compass/adr/0045-replacement-conditions-must-discriminate/)によります。
:::
