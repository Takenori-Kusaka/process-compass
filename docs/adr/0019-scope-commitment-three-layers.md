## ステータス

採用(2026-08-06)

## コンテキスト

本標準には、タスクの棚卸し・進捗確認・スケジュール調整・規模の合意・次回マイルストーンまでのスコープ定義を、どこで行うかの規定がなかった。第7章 7.6 のエスカレーション基準と 7.7.4 の進捗率・消化進捗比はあるが、これらは**逸脱が起きた後の手続**にあたる。**通常運転時の進捗管理とスコープ調整の手続がなかった**。

あわせて、外殻(低頻度・既存決裁)と内側(高頻度・AI協調ループ)の速度差により、実装と合意した仕様の乖離が蓄積し、出荷判定(G-7)で全面的な差し戻しになるという問題があった。

両者は同じ設計面にある。「何をどこまで確約したか」が定まっていなければ、「そこから外れたか」も判定できない。したがって1つの決定として扱う。

調査により次を確認した。

- 工程の進行によって見積りの不確実性が収束するとは限らないという報告がある(2006年、実案件のデータ)。**見積りの精度を根拠に確約の量を決められない**
- 実測に基づく流れの指標には、完了後にしか得られない遅行指標(サイクルタイム)と、未完了の項目にのみ意味を持つ先行指標(滞留期間)がある
- 進捗の自己申告が長期にわたり高い完了率を示し続ける現象は、1988年に NASA の案件を対象とした分析で報告されている
- **柔軟なスコープを持たない案件は、顧客便益の実現において平均を下回った**という調査がある(2016年)。スコープの削減は逸脱ではなく通常の操作である
- 自動生成した要求トレーサビリティ行列を人手で検証させた実験(2010年)では、初期の精度が高い候補を与えられた分析者は**品質を下げた**。機械の出力を人が追認する構成は、人の判断を機械の出力へ引き寄せる
- AI の採用は変更のスループットと正の関係を持つ一方、**提供の安定性とは負の関係を持ち続けている**(2025年、約5,000名の調査)

## 決定

1. **スコープを3層で合意する**(SC-M 確約範囲 / SC-P 計画範囲 / SC-B 調整枠)。単一の一覧として扱わない。すべてが必須である計画は、期日と衝突した時点で削る対象を持たない
2. **確約範囲は計画容量の 60% を上限とする**。DSDM の MoSCoW が推奨する配分を初期値として採り、**実証研究に基づく値ではないことを明記する**
3. **規模は工数の絶対値ではなく、実測スループットに対する件数で合意する**。実測が存在しない段階では確約範囲を置かない
4. **進捗を担当者の完了率の申告で測らない**。到達(進捗率・遅行)と停滞(滞留期間・先行)の対で観測する
5. **棚卸しのための会議体を設けない**。滞留の一覧を非同期に確認し、既存の事前レビュー期間の仕組みへ載せる
6. **スコープを定める場を別に設けない**。ステージ移行ゲートの「継続」判定の確定事項へスコープを加える
7. **計画範囲と調整枠の増減は価値責任者の単独判定とし、逸脱として扱わない**。例外になるのは**確約範囲を動かすときだけ**とする。これが通常運転と例外の境界である
8. **期日に間に合わない場合の選択の順序を定める**。範囲を削る → 期日を動かす → 基準を下げる。順序を入れ替えない
9. **範囲の内か外かの判定は人が行う**。機械が検査してよいのは**記入の有無だけ**とする
10. **範囲外の変更を捕捉する場は G-4 とし、新しいゲートを設けない**。判定基準を1項追加する
11. **範囲外の変更が外殻の変更管理を起動しても、内側のループを止めない**。裁定を待つ項目は調整枠へ移し、着手しない
12. **差し引きを示す**。G-4 に記載事項を1つ加える代わりに、7.6 のスコープに関する発火条件を確約範囲の変動へ限定し、通常運転で発生する報告の件数を減らす
13. **新しい記号は `SC-M / SC-P / SC-B` の1系統のみとする**。既存の R1〜R3・Sev1〜3 を流用できる箇所では新設しない

## 検討した選択肢

- **既存の会議体(B-2)に棚卸しの議題を足す** — 場は増えないが、B-2 は月次であり、内側のループ(数時間〜数日)の停滞を捉えられない。加えて 3.7.5 が「判定を要しない報告のみの議題を定例へ置いてはならない」と定めている
- **週次の進捗定例を新設する** — 現場の実務には合うが、判定の総数を増やさないという原則(ADR-0013)に反する。滞留の検知は非同期の通知で足りる
- **MoSCoW をそのまま採用する(Must / Should / Could / Won't の4層)** — 広く知られている利点があるが、Should と Could の区別が実務で曖昧になりやすく、**本標準は既に「必達基準 / 評点基準」(7.7.3)という語を別の意味で用いている**。「Must」を訳した語と衝突する。3層へ縮め、独自の記号を与えた
- **既存の R1〜R3 でスコープの層を表す** — 記号は増えないが、R は決定の取り消し可能性を表す軸であり、範囲の確約度とは別の軸である。R1 の変更が調整枠に属することもある
- **スコープ内外を LLM に判定させる** — 判定の負担は減るが、契約的判断を意味的類似で代替することになる。2010年の実験が示すとおり、機械の出力を人が追認する構成は判断の質を下げうる。加えて 5.7.4 の原則に反する
- **乖離の検知を G-7(出荷判定)で行う** — 追加の判定は不要だが、これは現状そのものであり、指摘された問題(全面的な差し戻し)が起きる地点である
- **範囲外と判定した時点で内側のループを停止する** — 統制は確実になるが、停止が判定に直結すると判定を避ける動機が生まれる。ADR-0018 で前提の崩れについて同じ結論を採っている

## 影響

- 第2章に 2.10「スコープの確約と進捗の統制」を新設した。既存の 2.10 を 2.11 へ繰り下げた
- 第3章 3.7.3 の「継続」判定の確定事項に、次段階のスコープ3層を加えた
- 第4章 G-2 に判定基準5(スコープ3層への割り当て)、G-4 に判定基準5(範囲内外の判定の記入)を追加した。**判定の場は増えていない**
- 第7章 7.6 のスコープに関する発火条件を、確約範囲(SC-M)の変動のみへ限定した
- 第6章のテンプレ1にスコープ層の欄、テンプレ6に次ステージのスコープ3層の表を追加した。**新しいテンプレートを作っていない**
- 第8章 軸D に、確約範囲の変更を契約変更の起点とする行を追加した
- フェーズ6のメトリクスに「作業単位の滞留期間」「完了スループット」「確約範囲の変動」を追加し、ゲート滞留時間との違いを明記した
- 記号の索引に `SC-M / SC-P / SC-B` を追加した
- **記号の衝突を1件解消した**。テンプレ1・テンプレ7の受入基準の識別子 `AC-n` は、[ADR-0018](/process-compass/adr/0018-assumption-ledger/) が定めた前提の充足状態 `AC-0 / AC-1 / AC-2` と衝突していた。**受入基準の側を `CR-n` へ改称した**。ADR-0018 の決定は変更していない
- 調査根拠は `research/phase4-standard/140-131-scope-and-progress.md` に記録した
- 60% と 20% の配分はフレームワークの推奨値であり、実証がない。**自組織の実測へ置き換える前提で記載した**。置き換えの手続は定めておらず、次の課題として残る
- 確率的予測(モンテカルロ)の精度を示す査読研究、および「範囲内外」の意味的判定における LLM と人間の一致率を示す研究は、**いずれも特定できなかった**。本標準はどちらの数値も引用していない
