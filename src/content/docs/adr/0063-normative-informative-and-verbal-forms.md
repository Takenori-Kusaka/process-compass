## コンテキスト

[#310](https://github.com/Takenori-Kusaka/process-compass/issues/310) は、本標準が規格としての書き分けを欠いていると指摘しました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/302-310-deliberation/`(`survey-310.md`、`council-C-01`〜`05`、`decision.md` の C-7〜C-12)にあります。

調査が確かめた事実は、次のとおりです。

| 事実 | 内容 |
| --- | --- |
| 文末 | 第1章 1.7 が定める要求の形は3つだった。本文8章では、その形が約210件、平叙の「〜します」「〜しません」が約560件だった。規範の大半が、1.7 の挙げない形で書かれていた。推奨・許容の文末の定めは無かった |
| 附属書の種別 | 9編のうち、種別に当たる語を持つのは1編だった。語は4通りあった。本文は附属書B・D・F・H を「による」「準拠」で引いていた。手引きを自称する附属書に、禁止の文と実装マークがあった |
| 第8章 | 軸A の表に「この表は調整の手引きであり、要求事項の条項ではない」という括弧書きがあった。同じ表を、エンジンは規則として符号化していた |
| 表の升の語 | 「省略可」が、出荷判定(G-7)では省略、リリース決裁(G-8)では適用と、逆の結果になっていた |
| 2.5 と軸B | 第2章 2.5 と第8章 軸B が、S0 の技術設計判断(G-3)とリリース決裁(G-8)で食い違っていた。軸B の表に、この2つのゲートの行が無かった |
| 直し残し | 同じ事項を2か所に書き、片方だけを改めた箇所が残っていた(第7章 7.5、第2章 2.6) |
| 受入基準の確定 | 「AI が生成した受入基準をそのまま承認してはなりません」という禁止が、手引きを自称する附属書E にだけあった。記録で確かめる手段は無かった |

外部の規格の作法は、ISO/IEC 専門業務用指針 第2部(第9版、2021)を原典で読みました。同指針は、適合を主張するために満たす要求事項を利用者が識別できることを求め、規定の種類ごとに表現形式を定めます。附属書の種別は、本文からの引き方と附属書の見出しの両方で示すことを求めます。JIS Z 8301 は第三者の転載でしか読めていません。本 ADR は、同規格の文に依りません。

## 決定

### 1. 附属書の種別を、附属書の単位で宣言する

| 種別 | 附属書 | 本文からの引き方 |
| --- | --- | --- |
| 規定 | B・D・F・H | 「〜によります」 |
| 参考 | A・C・E・G・I | 「〜参照」 |

- 種別は、第1章 1.5 の表と、各附属書の表題に書く
- 本文が「による」で引く附属書を、規定とする
- 参考の附属書に、要求事項と禁止を置かない。置いてあったものは、本文か規定の附属書へ移す
- 節・段落の単位では宣言しない
- 第8章 軸A の括弧書き(この表は調整の手引き)を削る。第8章は規定である
- フェーズ5 とフェーズ6 は、本標準の構成の外にあり、本文に従属する。本文の要求事項を狭めない。食い違う場合は本文による

### 2. 規定の強さを、文末の形で示す

規定の表現形式の対応表を、第1章 1.7.1 に置きます。種類は7つです(要求・禁止・推奨・推奨しない・許容・可能性と能力・外部の制約)。本文(ですます調)と、箇条書き・表(である調)の2列で示します。

- 本文と規定の附属書の、平叙の動詞文は、要求として読む
- 説明は、理由の文と注記に書く
- 「〜できます」を許容に使わない
- 表の升の語は、閉じた語彙にする。「省略可」「任意」「どちらでもよい」を廃する
- 文末の検査を `npm run check` に足す

### 3. 受入基準の内容の良否は、課さない

受入基準の内容の良否に、判定基準を課しません。受入基準の確定を、第4章 G-2 に書きます。確定は、人が版を特定して判定記録へ記名する行為です。「そのまま承認してはなりません」は、推奨の形へ改めます。禁止は、記録で判定できる形(人の判定を経ずに確定としない)へ改めます。

### 4. 同じ事項は1か所に書き、廃した言い回しを検査する

同じ事項の規定は1か所に書き、ほかの箇所は所在を引くと、第1章 1.7 に定めます。条項を改めて廃した言い回しは、登録簿に載せ、残っていれば検査で落とします。直し残しは、次のとおり訂正します。

| 箇所 | 訂正 |
| --- | --- |
| 第7章 7.5 | 滞留への対処の手段と順は、第4章による。古い列挙を廃する |
| 第2章 2.6 | 書き戻しは、該当がある場合に限る。書く条件を 2.6 に置く |
| 附属書C | 1日に確認する件数の目安とする。上限と措置は第4章を引く |
| フェーズ5 のスタックの層数 | 第4章の目安(3層まで)に合わせ、段階3 を「3層」とする |

### 5. 事業ステージごとのゲートの状態は、第8章 軸B に一本化する

第2章 2.5 の表を廃し、第8章 軸B を引きます。軸B の表に全ゲートの行を置きます。**S0 でも、技術設計判断(G-3)とリリース決裁(G-8)を適用します**。エンジンの試験で固定します。S0 の独立レビュー(G-6)と出荷判定(G-7)の扱いは、別の決定によります(#302)。

:::caution[暫定 EV-0100 / 見直し 2027-04]
**対象**: 附属書の種別の割り当て(B・D・F・H を規定、A・C・E・G・I を参考とする)と、参考の附属書から本文へ移した規範の選び方。
**根拠の水準**: E0(なし)。
**差し替え条件**: 各附属書の全文と本文の条項の突合の結果。参考の附属書に残った平叙の文のうち、適合に効かせるべきだったものの件数。

種別は、本文からの引き方で決めました。移したのは、要求と禁止の文末を持つ文と、番号で引かれていた禁止事項です。参考の附属書の平叙の文は、棚卸ししていません。その中に、適合に効かせるべき手順が残っている場合があります。
:::

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 節の単位で、規定か参考かを宣言する | 札の付け忘れが、そのまま規範の漏れになる。現在の欠陥を、単位を小さくして増やす |
| 参考の附属書の中の要求形を残し、参考とみなすと書く | 効かせたい禁止を、効かない場所に置き続ける。フェーズ5 とスキルが番号で引いていた禁止事項の根拠が消える |
| 規定の附属書を認めず、すべて本文へ移す | 記法・様式・論証を、判定基準の表から遠い章が抱える。本文が引いている附属書を参考と呼ぶことになる |
| 要求は「〜しなければなりません」に限り、平叙文は説明とする | 書き換え漏れの1文が、そのまま義務の消失になる。平叙文を要求として読む形は、取りこぼしたときに、説明が要求として読まれる側へ倒れる |
| 文末ではなく、表に置いたものだけを要求とする | 条件と例外を伴う規範を表の行に入れると、限定が別の段落へ逃げる |
| 印を付けた語だけを規範の語とする | 本文は太字を強調に使っており、印に使える表記が残っていない |
| 受入基準について、人が改めた箇所の有無を記録させる | 書いた者しか真偽を知らない欄になる。形だけの修正を誘う |
| 受入基準の妥当性確認の活動を置く | ADR-0051 の決定2 と当たる。1名体制で成り立つ形が、材料に無い |
| 直し残しを訂正せず、新旧を注記で開示する | 古い文が要求の形のまま残る |
| S0 でリリース決裁(G-8)を省略する側へ合わせる | 出荷判定(G-7)を省略する S0 で、残存リスクの受容を記名する場所が無くなる |
| 「省略可」を許容として残し、組織に選ばせる | ADR-0028 の状態の語彙に、組織が選べる状態は無い。回答で状態が変わる経路を増やす |

## 影響

- 附属書9編の表題が変わる。附属書E・F の「実施の手引き」の自称、附属書G の「手引き」の自称を改めた
- 次の規範が、参考の附属書から本文へ移った。禁止事項の一覧(附属書E E.9 → 第5章 5.8.5)、基準値と除外設定の変更の分離(附属書E E.6 → 第4章 G-5)、並行実行の作業ツリーの分離(附属書E E.4 → 第3章 3.5.1)、提示の順序(附属書C → 第3章 3.5.3)、決裁制度への提示の規定(附属書G → 第6章)。番号で引いていた箇所は、移した先へ付け替えた
- 附属書I にあった実装マーク2件は、フェーズ5 の準拠テンプレートのページへ移した。番号は保った
- 本文8章と規定の附属書の、依頼の形(14件)と、廃した升の語(11件)を書き直した。許容の意味の「〜できます」は、人が読んで10件を書き直した
- **機械の確かめないことが残る**。「〜できます」の意味(許容・能力)と、平叙の動詞文の種類(要求・説明)は、機械で判定しない。「〜できません」の意味(禁止・不能)は、今回読んでいない
- フェーズ5 とフェーズ6 のページごとの種別は、定めていない。両フェーズにある禁止と実装マークの、本文との対応の突合は、今後の作業である
- 文末の書き分けが、適合の判定のばらつきを減らすという測定は、見つかっていない。第1章 1.7.1 に EV-0096 を置いた
