## コンテキスト

[#317](https://github.com/Takenori-Kusaka/process-compass/issues/317) は、ADR-0069 が決定の外に置いた委託(軸D)の残りを問いました。軸D の表で G-1・G-2・G-5 の置き先が無いこと、発注側がリポジトリを持つ形での指示資産と強制層の持ち主、判定の結果を受け取る者の所在、準拠テンプレートの様式 08 が持つ標準の外の節、決裁権限規程を前提にした文の5つです。指摘をそのまま条項にせず、調査(内部1本・外部1本)、会議体(起草・現場・品質保証と監査・規格・擁護の5つの立場)、突合の順で扱いました。記録は `research/317-deliberation/` にあります。議長の裁定は `decision.md` の R-1〜R-6 です。

判断の軸は、組織の境界を越えても、判定と統制の責任の所在が記録から一意に辿れることです。法令(偽装請負)の該当性は書きません(ADR-0069 決定3)。席に組織の属性を持たせません(ADR-0069 決定2)。席と組織は、テンプレ8 の記名で結びます。

### 表が8つのゲートのうち5つしか載せていなかった

軸D の表は、G-3・G-4・G-6・G-7・G-8 の置き先だけを書いていました。G-1 と G-2 は、席の規定から発注側に置くことが導けます。それでも表に無いため、受注側の社内の決裁を G-1 と読む余地が残っていました。G-5 は人の判定者を持たない機械のゲートであり、置き先を問うこと自体が合いません。

### 強制層を所有する組織と、変更を承認する席が別の組織にありえた

発注側がリポジトリと CI を持ち、受注側が作業する形では、AI維持管理者の席の責任者が強制層を所有する組織に属さない場合があります。この場合、所有しない側の承認だけで強制層を緩められます。所有する側は、変更を知る手段を持ちません。附属書H H.9 問15 は強制層の所有を問うのに、様式に書く欄がありませんでした。

### 様式 08 に、標準に無い節が5つあった

様式 08 の節 3・5・8・9・12 は、第8章が「契約に定める」と書く事項でした。不備は標準の側にありました。一方、様式 08 は標準の項目1(AI 利用の開示)と項目6(権利と責任)を落としており、omit の登録もありませんでした(ADR-0040 決定3 に反する)。第4節のチェックリストは、確認の基準を受入基準より広げる項目を含んでいました(ADR-0040 決定4 に反する)。様式が標準の外の節を持つことを、既存の検査は見ていませんでした。

### 決裁権限規程を持たない体制で読めない文が7か所あった

本文の7か所は、決裁権限規程や稟議の運用を前提にしていました。1.2 は1名の組織を適用の範囲に含めます。規程を持たない体制では、決定者と期限を読めませんでした。3.8.2 の「別の金額体系を新設してはならない」は、金額体系を持たない組織に適用すると、金額区分そのものを置けなくなります。

## 決定

### 1. 軸D の表へ G-1・G-2・G-5 を足し、8つのゲートを全部載せる

| ゲート | 置き先 | 理由 |
| --- | --- | --- |
| G-1 | 発注側に固定 | 事業決裁者は G-8 と同じ席で、G-8 は発注側に固定済みのため |
| G-2 | 発注側に固定 | 価値責任者が発注側に座るため。受注側の確認は、テンプレ8 第9項「契約上の確認行為との対応づけ」で扱う |
| G-5 | 置き先を持たない。強制層を所有する組織の CI で判定する | 人の判定者がいない機械のゲートのため |

- 受注側が受注の可否を決める社内の決裁は、本標準のゲートではない
- G-2 の決定者は1人である(3.8.3)
- 発注側に価値責任者がいない委託は、G-2 の未達として表示する。代わりの経路は作らない
- G-8 の理由を、決裁権限規程の有無に依らず成り立つ形へ改めた
- テンプレ8 第9項の注記と、様式 08 第9節の注記を、この表に合わせた

### 2. 強制層の範囲を列挙し、所有をテンプレ8 第9項に記録する

強制層は、ルールセットとブランチ保護、必須チェック、CI のワークフロー、ゲートの検査のスクリプト、検査の閾値と除外設定、エージェントの権限設定、実行前フックです。誘導層(`CLAUDE.md`、スキル)は、強制層と分けて扱います。

テンプレ8 第9項に、次の4欄を足します。附属書H H.9 問15 との不一致は、これで解けます。

- 強制層を所有する組織(リポジトリと CI の管理権限を持つ側)
- AI維持管理者の席の責任者と、その者の属する組織
- 誘導層と再利用層を保守する組織
- 強制層を緩める変更への、所有する組織の同意の形

強制層の変更は、AI維持管理者が承認します(ADR-0074 決定3 を維持)。AI維持管理者の席の責任者が強制層を所有する組織に属さない場合は、緩める向きの変更(遮断の解除・閾値の緩和・強制層の縮小)に、所有する組織が指名した者の同意の記録も要します。同意の形は「事前の同意」か「事後の提出」のどちらかを締結時に選びます。空欄は認めません。所有と承認が別の組織にあると、どちらの向きにも統制が成り立たないためです。

誘導層の持ち主は固定せず、記録だけを求めます。発注側の要求は、受入基準・出荷できない状態・強制層の検査として書きます。誘導層だけに書いた要求は、要求として扱いません(3.11.3)。理由は誘導層の性質(従わせる仕組みを持たない)であり、法令ではありません。

準拠テンプレートの側では、次を行います。

- CODEOWNERS の雛形の役割の行を、強制層と誘導層とも AI維持管理者(`@ai-maintainer`)へ割り当てる。欠けていた行(`.github/workflows/`、`scripts/gate/`、`.claude/hooks/`、CODEOWNERS 自身など)を足す。役割の行はコメントのまま置く。有効にする道具の側の扱いは [#358](https://github.com/Takenori-Kusaka/process-compass/issues/358) と重なるため、雛形に書き置く
- 強制層の要約値(ADR-0085 決定6)に、`.claude/settings.json` と `.claude/guard.json` を含める。初期化は、テーラリングした後の内容で記録する。書いた直後に乖離を出さないためである。取り込み(種別 `intake`)は、その時点のファイルで記録する。権限設定の緩みが、乖離として出るようになる。乖離は表示に使い、合否に使わない(ADR-0085 決定6 を維持)

所有する組織の同意の要件には実証がありません。根拠の水準は EV-0177(E0)で開示します。同意の記録を強制層の検査で確かめる手段は、準拠テンプレートに降りていません(IMPL-0340。未達)。

### 3. 判定の結果を受け取る者は、様式の1か所に置き、構成へ写さない

- 受け取る者の値は、構成(`process.config.json`)へ写さない。正本は AI-SLA 合意確認書(`docs/ai-sla.md` 第9節)の1か所とする。正本が二重になると、担当が替わるたびにずれるためである
- 委託の構成(開発形態が発注側・受注側)のときだけ、構成書(PROCESS-PROFILE)と `CLAUDE.md` の生成部分に、受け取る者の所在を示す1行と、相手の組織の担い手へ `@mention` だけで引き渡さない旨を出す(IMPL-0338)
- 受け取る者の欄が無いか、雛形のままのときは、`/pit` が注記を出す。合否と段階には使わない(IMPL-0337)
- 判定記録(テンプレ4)に「結果の受け渡し」の節を足し、渡した先と渡した日時を書く(IMPL-0336)。受け取った側の受領の確認は課さない

### 4. 様式 08 の節を標準へ上げ、様式から標準への逆向きの検査を足す

- 様式 08 の節 3(超過時の措置)・5(監査)・8(提出する記録)・9(受け入れの速度)・12(計算資源の費用)を、テンプレ8 へ上げた。超過時の措置と監査は、テンプレ8 の第3項・第5項に対応づけて必須欄に登録した。提出する記録・受け入れの速度・計算資源の費用と、第8章が契約に定めるとする読解の帯域を、第10項〜第13項として新設した。「合意」は第14項へ繰り下げた。節 10(AI 生成部分の追跡)は、項目1(AI 利用の開示)へ統合した
- 様式 08 の節の番号を、テンプレ8 の項の番号にそろえた。様式 08 に項目1 と項目6 を足し、必須欄に登録した
- 様式 08 の確認の基準のチェックリストから、受入基準より広げる3項目(判定記録・技術負債台帳・運用引き継ぎ文書の揃い)を外した。提出を求める記録は第10項に書く
- `deliverable-templates` の「第8項と第9項の欄は、準拠テンプレートの必須欄である」を、ADR-0069 決定8 と対応表に合わせて直した

ADR-0040 の検査に、3方向目を足します。

| 方向 | 確かめること | 欠いた場合に起きること |
| --- | --- | --- |
| 様式 → 対応表 | 様式の見出し(`## `)が、節を指す必須欄に対応するか、`extra:` へ理由つきで登録されているか | 標準に無い節を、登録も理由の記述もなく様式へ足せる |

`extra:` の登録は、見出しと理由を必須とします。標準の対応する記述(`standard`)を書いた場合は、その実在も確かめます。登録した見出しが様式から消えた場合も失敗にします。既存の13様式の見出し71件を登録しました。

### 5. 決裁権限規程を前提にした文を、1か所ずつ行の中で直す

- 7か所(`lifecycle` の G-1 の行、`roles-responsibilities` の3か所、`gate-criteria` の G-1 の期限、`tailoring-guide` の G-8 の理由と会議体の B-1 の行)を、行の中で直した。規程を持たない体制では、D-0 の記名と記録で読む
- 3.8.2 の「別の金額体系を新設してはならない」は、決裁権限規程を持つ組織に限る。規程を持たない組織は、金額区分の境界額を D-0 に記名で宣言する。決定者が区分で変わらない体制は、境界額の代わりにその旨を書けば足りる(IMPL-0341)
- 本標準は、境界額の値と例示を置かない。ISO 9001 の 5.3 は権限の割り当てを求めるが、金額の値を置かない。会社法と判例にも、固定の閾値は無い
- D-0 の表2(費用の層)と 3.8.2 の金額区分の全面の対応表は課さない。ただし、同じ変更で両者が別の決定者を指す場合にどちらが決めるかを、D-0 に書く。根拠の水準は EV-0178(E0)で開示する
- D-0 に「決裁の権限の出所」(規程・代表権・出資の決定など)の欄と、「組織上の任命権者」の欄を足した
- 1名の組織で、組織上の任命権者が本人である場合は、自己の任命を記録したうえで認める。新任の決定者が自分の任命を自分の記名で確定してはならない、とする規定の同じ行に、この限定の例外を書いた。1.2 が1名の組織を適用の範囲に含める以上、禁じると適用を始められないためである。例外は開示の対象とし、根拠の水準は EV-0179(E0)で開示する。準拠テンプレートの変化点の記録は、この例外を区別して記録しない(IMPL-0342。未達)

### 6. 偽装請負の外部の制約の注記を、疑義応答集の改訂に合わせる

本文の偽装請負の注記は、アジャイルに限っていません。範囲の改訂は要りません。注記に、次の3点を「〜とされています」の形の情報として足しました。法的助言ではありません。

- 疑義応答集 第3集の 2026-05-25 の改訂(Q8。アジャイル以外の請負にも当てはまる)
- 第1集 問7(作業の内容・順序・方法を文書で詳細に示すこと)
- 第3集 A2(役割・権限・進め方を予め合意しておくこと)

ゲートの判定・差し戻しと指揮命令の境界は、規範として書きません。第4章「ゲート運用の共通ルール」3 が「差し戻しは判定基準の項目と理由で示す」と既に定めているため、注記からその条項を引きます。

出典台帳は、SRC-0636(第3集)の版を 2026-05-25 の更新へ改め、Q8 と A2 を足しました。SRC-0635(第1集)に問7・問10・問14 を足しました。第2集(SRC-0671)、事務連絡(SRC-0672)、2026-05 のガイド(SRC-0673)、モデル契約 JISA 2020 年版(SRC-0674)のカードを起こしました。新しいカードと追加の主張は、取得の経路の都合で照合を部分(partial)としています。

## 検討した選択肢

採らないと決めた選択肢と、その理由です。

| 選択肢 | 採らない理由 |
| --- | --- |
| G-2 を発注側と受注側の双方の記名で成立させる(JISA モデル契約 17条型) | 3.8.3 の「決定者は1人」と当たる。受注側の確認は、契約上の確認行為との対応づけで扱える |
| 発注側が価値責任者を置かない委託に、代わりの経路を作る | その委託は G-2 の未達として表示される。代わりの経路は、未達を見えなくする |
| 席に組織の属性を持たせる | ADR-0069 決定2 と当たる。席と組織は、テンプレ8 の記名で結べば足りる |
| 作業の方法の資産(誘導層)を受注側の所有に固定する | 偽装請負の該当性の判断を規範へ持ち込むことになり、ADR-0069 決定3 と当たる。疑義応答集の記述は、外部の制約の注記に情報として置いた |
| AI維持管理者の席の責任者と、強制層を所有する組織の一致を必須にする | 発注側がリポジトリを持ち受注側が作業する形で、受注側から席を出すことを禁じる理由が、法令の区分にしか無い。所属が異なる場合の同意の記録で、統制の向きを保てる |
| 判定の結果を受け取る者を構成へ写す | 正本が二重になり、担当が替わるたびにずれる |
| 受け取った側の受領の確認を課す | 渡した側の記録(渡した先と日時)で所在は辿れる。受領の記名を課すと、相手の組織の手続を標準が定めることになり、ADR-0069 決定2 の「経路の中身を定めない」と当たる |
| 規程を持たない体制の読み替えを、1か所の一般規定に置く | 限定を規範と別の段落に置かない規則(#226)と当たる。読み手が一般規定を見落とすと、7か所が読めないまま残る |
| 境界額の値や例示を置く | 外部の規格と法令に固定の閾値が無い。例示は既定値として写される |
| D-0 の表2 と金額区分の全面の対応表を課す | 両者が同じ決定者を指す変更では、対応表は情報を足さない。食い違う場合の優先だけを書かせれば足りる |
| ゲートの判定・差し戻しと指揮命令の境界を、規範として書く | 法令の該当性の判断を規範へ持ち込むことになる(ADR-0069 決定3)。差し戻しの示し方は第4章「ゲート運用の共通ルール」3 が既に定めている |
| 強制層の要約値から、権限設定と遮断の定義を除いたままにする(ADR-0085 決定6 の現状) | 権限設定は強制層の中で最も緩めやすいファイルであり、取り込みの時点で緩みが見えない。初期化がテーラリングした後の内容で記録すれば、案件ごとの書き換えを乖離と取り違えない |
