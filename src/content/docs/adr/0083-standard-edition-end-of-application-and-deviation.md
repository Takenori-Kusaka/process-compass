## 決定

### 1. 本標準の版は、発行した版に限る

版は「第N版」と発行日で示します。要求を変えない改訂は「第N版 修正M」と示します。要求事項・禁止・適用範囲・判定基準・テーラリングの規則データ・テンプレートの必須欄を変える改訂は N を上げます。迷う改訂は N を上げます(EV-0158)。

発行は人(保守者)が行います。発行していない main の状態は作業中の版です。作業中の版は、適合の主張と逸脱を伴う適合の主張に名指せません。適用の表明には、配布物のコミットの識別とともに名指せます。適用の表明は件数を併記する事実の記述であり、版の意味の改訂に左右されないためです。表明まで止めると、第1版の発行まで採用の事実そのものを書けなくなります。帰結として、第1版の発行までは誰も2つの適合の主張をできません。第1版の発行は、取り消せない外部への発行であり、所有者が判断します。本 ADR は版を発行しません。

版の名は、発行の時点のコミットの配布物に限って付きます。発行のコミットは `src/data/edition.yaml` の履歴に記録します。発行の記録だけを足したコミット(差分が `edition.yaml` と準拠テンプレートの参照に限られるもの)も、発行の時点として扱います。それ以外のコミットの配布物は「作業中の版(第N版の後)」とコミットで示します。知識ベースは、最後に発行した版を `source.basedOn` に持ち、`source.edition` は発行の時点のときだけ持ちます。準拠テンプレートは、`source.edition` を持つ知識ベースからだけ、構成の版を発行した版へ切り替えます。

新しい版は旧い版を置き換えます。旧い版に従う案件は、旧い版への主張を期限なく続けてよいものとします。追従していない版への適合は主張できません。新しい版への主張は、その版で宣言をやり直した後の範囲に限ります。移行期間と失効は置きません(EV-0159)。

適用した版は、第8章の宣言(要求事項4)と準拠テンプレートの構成(`standard.edition`)に記録します。構成の版の切り替えは `/process-change` の種別 `edition` を経ます。配布の `VERSION.md` と知識ベース(`source.edition`)に、版とコミットを併記します。乖離の検査は版を比べます。

適用者への要求(表明と主張に版を書く、追従していない版を主張しない)は第1章 1.10.3 に置きます。版の発行・付番・引用の棚卸しの手続は、標準の保守の手続として [`community/standard-editions`](/process-compass/community/standard-editions/) に置きます。正本の値は `src/data/edition.yaml` です。

### 2. 適用の終了を1つの事象で定める

適用の終了は、適用を終えた記録を残した時点です。理由の区分(案件の完了・中止、運用の終了、採用の取り下げ)と、決定した者の記名を記録します。終了の記録が無ければ、適用は続いているものとして扱います。

一時停止、期日による失効、範囲の縮小を置きません。ADR-0068 決定3(途中の状態を置かない)と同じ型です。終了の後は、現在形の適用の表明をしません。公開の表示は、期間を示す形へ改めるか外します。過去の範囲の主張は、記録の保管の間だけ有効です。同じ案件で再開したら、件数は最初の開始から数え、空白の期間は記録の欠落とします(EV-0161)。

準拠テンプレートは、`changeLog` の種別 `end` で終了を記録します。再開の経路は持たず、undelivered として表示します(IMPL-0309)。

### 3. 「逸脱」を1義にし、主張を2つの名に分ける

「逸脱」は、本標準が条項で条件と代償措置を定めて認めた離脱に限ります(閉じた列挙)。いまの列挙は D-1(開発ライン × 出荷判定者の兼務。第3章 3.5.2、ADR-0029)の1件だけです。列挙への追加と削除は、版の番号 N を上げる改訂に限ります。

条項が記録と表示を定めながら条件と代償措置を定めていない離脱を、本 ADR は「列挙に無い離脱」と呼びます(決定7 と「影響」を参照)。列挙に無い離脱は、逸脱と未達のどちらにも当たりません。条項が定める記録と表示は、そのまま適用します。適合の主張と逸脱を伴う適合の主張を妨げます。

逸脱の無い範囲の主張は「適合の主張」、閉じた列挙の逸脱がある範囲の主張は「逸脱を伴う適合の主張」とし、各逸脱を列挙します。省略して「適合」と書きません(EV-0160)。正本は第1章 1.10.2 であり、附属書H H.8 は文の型だけを持ちます。第1章 1.7.1 の「逸脱を認めない」の語を改めました。事象の意味の「逸脱」(委任の範囲の逸脱、意図的な逸脱など)の改名は [#316](https://github.com/Takenori-Kusaka/process-compass/issues/316) へ送ります。

件数の範囲は表明の種類ごとに定めます。適用の表明は開始から表明の時点まで、2つの主張は主張の範囲の中を数えます。主張の範囲は開始と終了の間で、1つの版の中に置きます(EV-0162)。主張の名は範囲ごとに求めます。版の切り替えをまたぐ範囲は、版ごとに分けます。終了の前に終わる範囲についての主張は、終了の記録で無効になりません。

満たしていない要求事項の表示は、未達(ゲートの状態。ADR-0028)・記録の欠落・逸脱・列挙に無い離脱の4つです。ADR-0068 決定2 の「未達または記録の欠落」の二分を、この4つへ補います。列挙に無い離脱は、記録があり、ゲートが判定されうるのに、本標準が代償措置を定めていない離脱です。未達と記録の欠落のどちらにも当たらない第3の状態として、突合の段で議長が認めました(`decision.md` の 8 節 X-3)。

### 4. 引用は版つきにし、本標準には引用規格が無いと書く

全ての引用に発行年を付けます。部分(箇条・表・図)を引くときは、必ず版を付けます。版の無い引用をしません。現に版の無かった3行は、本標準が読んだ版(ISO 9001:2015、ISO/IEC/IEEE 90003:2018、ISO 12100:2010)で書きます。

第1章 1.3 の各行を読み、表の文書のどれも本標準の要求の一部になっていないことを確かめました。1.3 に「本標準には、引用規格はありません」と書き、表を参考文献として扱います。各行に出典台帳の SRC を引き、読んだ範囲を書きます。引用の版に台帳のカードがあることは、`npm run lint:citations` が検査します。版の発行ごとに、引用した規格の改訂の有無を棚卸しし、日付つきで記録します。採用者が第8章で規格を足すときも、版を付けて宣言します。

### 5. 適用の開始の境は、構成が設定済みになった最初のコミットとする

準拠テンプレートの実装が正しいと判断しました。ADR-0068 決定1 は、境を履歴の1コミットに固定し、後から動かせないとしています。`changeLog[0]` は切り詰め・書き換えができます。分かれるすべての場合で、実装の境のほうが早く、安全な向きです。

そのコミットに初期化の記録(`changeLog` の `init`)が無ければ、記録の欠落として示し、境は動かしません。そのコミットが検査の範囲にある間(初期化の PR、または手元で初期化のコミットを検査するとき)は、契約の検査を失敗にします。範囲の外の過去の欠けは注記に留めます(`decision.md` の 8 節 X-13)。宣言が不完全でも開始は動きません。再テーラリング、版の切り替え、再初期化は開始を動かしません。フェーズ5 の `ci-gates.md` と `template-repository.md` の記述を直しました。旧い構成の移行は [#315](https://github.com/Takenori-Kusaka/process-compass/issues/315) で扱います。

### 6. 附随の修正

- 第1章 1.2 の「適用の開始・適用の表明・適合の主張に数えません」を、適用の開始が時点であることと合う形(適用の開始に当たる事象として扱わない。表明と主張の根拠としても扱わない)に直した
- `improvement-cycle.md` の「プロセス定義の版管理」に、採用者のプロセス定義の版と本標準の版の区別を注記した
- 新しい規定には新しい EV(EV-0158〜EV-0162)を起こした。EV-0106 は広げない

### 7. 列挙に無い離脱の一覧を、本文に開示する

逸脱の語を閉じた列挙にした結果、従来「逸脱として記録する」としていた次の離脱は、逸脱でなくなりました。本標準は、これらに条件と代償措置を新しく発明しません。第1章 1.10.2 に一覧を置き、主張を妨げることを明示します。

| 離脱 | 条項 |
| --- | --- |
| 出荷判定者 × 事業決裁者の兼務(3名未満) | 第3章 3.5、第4章 G-8 |
| AI維持管理者 × AI運用担当者の兼務、欠陥注入の秘匿の不成立(1〜2名) | 第3章 3.5、第5章 5.6.2 |
| 認証情報を席ごとに分けられない構成 | 第3章 3.5.3 |
| コア機能の理解の保持者が1名以下 | 第3章 3.4.3 要求事項6 |
| 層1 の記名者が事業決裁者を兼ねる体制 | 第6章 テンプレ11 要求事項5 |

帰結として、1名の体制は、外部の確認者を置いて G-6 を満たしても、2つの適合の主張をどちらもできません。次の4つの規定が常に当たるためです。第3章 3.4.3 要求事項6(コア機能の理解の保持者が常に1名以下)、第3章 3.5 の出荷判定者 × 事業決裁者、第3章 3.5 と第5章 5.6.2 の AI維持管理者 × AI運用担当者と欠陥注入の時期と箇所の秘匿、第6章 テンプレ11 要求事項5(層1 の記名者が事業決裁者を兼ねる)。1名では独立の確認が成り立たない以上、主張できないことが正確な開示です。1名の体制が述べられるのは、適用の表明までです。この帰結は、所有者の確認を経ているところです(`decision.md` の 8 節 X-9。推奨は帰結として受け入れること)。1名・2名の体制のための代償措置を閉じた列挙へ加えるかは、調査と会議体を経る別の Issue で扱います。

コア機能の理解の保持者(第3章 3.4.3 要求事項6・7)と認証情報の分離(第3章 3.5.3、ADR-0035)が、条件と代償措置を定めた許可に当たるかも、同じ別の Issue で審議します。それまでは列挙に無い離脱として扱います(`decision.md` の 8 節 X-10)。

### 8. 採用済みの ADR の「逸脱」を読み替える

採用済みの ADR の本文は書き換えません。次の「逸脱」は、次のとおり読みます。各 ADR のステータスの節から、本決定を指します。

| ADR と決定 | 本文の語 | 読み方 |

| ADR-0035 決定2 | 権限の分離を満たせない体制の「代償措置つきの逸脱」(ADR-0029 と同じ扱い) | 列挙に無い離脱。記録と表示は ADR-0035 のとおり続ける。「ADR-0029 と同じ扱い」を、代償措置の定めと読まない。ADR-0029 の代償措置は、出荷判定の兼務に向けた措置であり、席ごとの認証情報が分かれていない状態を補う措置を ADR-0035 は定めていないためである。許可に当たるかは決定7 の別の Issue で審議する |

## 検討した選択肢

### 版(Q-1)

- **コミットを正本とし、人が読む識別を生成して併記する**(擁護): 採らない。機械の識別は改訂の意味を持たず、監査の場で版の識別子として通用しない。配布物が版を運ぶという指摘(ADR-0052 決定2)は採り、`VERSION.md` と知識ベースに版とコミットを併記した
- **「第N.M版」**(起草・品質保証): 採らない。小数の形は、M の改訂が要求を変えうると読まれる
- **semver**: 採らない。プロセス標準に「互換」の定義が無い
- **移行期間と旧い版の失効を置く**(認証の制度の型): 採らない。強制する認証の機関が無く、失効を確かめる者がいない
- **構成に版の欄を置かず、宣言だけに書く**(擁護): 採らない。宣言だけでは機械が版を照合できず、H.8 が求める「適用した版」を誰も書けない状態が残る
- **作業中の版のまま主張を認める**: 採らない。主張の対象が日々変わり、主張の意味を失う
- **作業中の版では適用の表明もできないとする**(会議体の段の裁定 Q-1): 突合の段で改めた(X-4)。表明は件数を併記する事実の記述であり、版の意味の改訂に左右されない。表明まで止めると、第1版の発行まで採用の事実そのものを書けない
- **main のどのコミットにも、最後に発行した版の名を付ける**: 採らない。発行の後の変更が、発行した版として配られる(X-1)

### 適用の終了(Q-2)

- **終了を定めない**: 採らない。終えた案件の現在形の表明が残る
- **一時停止・期日の失効・範囲の縮小を別の事象として置く**(認証の制度の型): 採らない。途中の状態を置かない ADR-0068 決定3 と当たり、未達を隠す経路になる
- **同じ案件で再開できないとする**(擁護): 採らない。再開を禁じても、別の案件として始め直す経路で同じことが起きる
- **再開で前の期間を明示するだけにする**(規格): 採らない。終了と再開で未達を隠す経路を閉じるのは、件数を最初の開始から数え、空白を記録の欠落とする案だけである

### 逸脱と主張(Q-3)

- **逸脱を 1.7.1 の意味(要求を満たさない状態の全体)に限り、3.5.2 を「許可」と呼ぶ**(規格): 採らない。ADR-0029 とテンプレートの `deviations[]` が既に構成の区分の意味で使っており、置き換えると記録の語と本文の語が逆になる
- **名を分けず、開示で足りるとする**(規格・擁護): 採らない。開示は短い引用(バッジ、提案書の1行)で落ちる。名に開示を運ばせる
- **12207 の「修整適合」の語を借りる**: 採らない。箇条4 の本文を読めていない
- **従来「逸脱として記録する」とした離脱を、閉じた列挙へまとめて入れる**: 採らない。条項が条件と代償措置を定めておらず、入れるには条件を発明することになる
- **列挙に無い離脱を「未達」または「記録の欠落」と呼ぶ**(会議体の段の裁定 Q-3 の字義): 採らない。この選択肢は会議体で検討したものではない。実装の段で第3の状態を足し、突合の段で議長が裁定した(X-3)。未達はゲートの状態の語(ADR-0028)であり、兼務や保持者の数はゲートではない。未達へ入れると、テンプレートの `unmet[]` の意味を壊す。記録はあるため、記録の欠落でもない

### 引用(Q-4)

- **本文に SRC の義務は要らない**(擁護): 採らない。引用の版を検査する手段になる
- **1.3 を引用規格の表として残す**: 採らない。各行を読んだ結果、要求事項を取り込んでいる行が無かった

### 適用の開始の境(Q-5)

- **`configured: true` と `changeLog[0].kind === 'init'` の両方を境の条件にする**(起草): 採らない。手で `configured` を先に入れた履歴で境が遅れ、その間の変更が数えられない。手で入れたことは記録の欠落として示す
- **`changeLog[0]` を境にする**(従来のフェーズ5 の記述): 採らない。後から切り詰め・書き換えができる

## 影響

- 第1版を発行するまで、どの採用者も適合の主張と逸脱を伴う適合の主張をできない。適用の表明は、作業中の版をコミットの識別とともに名指してできる。第1版の発行は所有者の判断であり、本 ADR の範囲の外にある
- 1名の体制は、決定7 の4つの規定のため常に列挙に無い離脱を持ち、適用の表明しかできない。出荷判定者と事業決裁者を兼ねる2名の体制、AI維持管理者と AI運用担当者を兼ねる2名の体制、コア機能の保持者が1名以下の案件、席ごとに認証情報を分けない構成も同じである。2名の体制が主張に至る条件は、第1章 1.10.2 の注記に置いた。従来の本文では、これらの構成が「逸脱を伴う」修飾の無い適合を主張できる余地があった
- 「列挙に無い離脱」は、裁定(`decision.md` Q-3)の「未達または記録の欠落」に当てはまらない離脱を表すために、実装で足した語である。突合の段で議長が第3の状態として認めた(X-3)。同じ離脱が繰り返し主張を妨げる場合は、条件と代償措置を定めて閉じた列挙へ加えるかを、本標準の改訂で検討する(EV-0160)
- 準拠テンプレートの構成は、`deviations[]` の欄の名と保存の形を変えない。読むときに、閉じた列挙の逸脱と列挙に無い離脱を分ける。構成の要約値が変わらないよう、保存する文字列も変えていない
- 事象の意味の「逸脱」は本文に残る。第1章 1.4 の注記で、定義の外にあることを示した。改名は #316 で行う
- 1.3 の外の本文の引用(JIS Z 8301、ISO 9000、安全規格の一部など)の版の棚卸しは終えていない。最初の版の発行の前に、棚卸しの手続で行う
