## コンテキスト

第4章「判定記録を基底ブランチへ入れる操作」は、写しと様式を「記名者と判定される側が書き換えられない場所」へ置くと定めていました。準拠テンプレートの記録用ブランチ `records` のルールセットは、履歴の書き換え(force push)と削除だけを止めます。書き込みの権限を持つ者とジョブのトークン(`GITHUB_TOKEN` の `contents: write`)は、新しいコミットで写しと様式を追記し、既存の記録の中身を変えられます。暫定マーク EV-0185 は、結論が出るまで記録用ブランチを書き換えられない記録として扱わないと書き、実装マーク IMPL-0353 は降りていない規定として表示されていました。ADR-0070 決定7 の「実機で確かめてから降ろします」は、確かめられないまま残っていました。

内部調査は、実装が EV-0185 の開示と逆を向いていた点を示しました。

- G-6 の承認を、ホスティングの記録より写しを優先して数え、差を所見に止めていた。写しの `commit_id`・`user.id` の書き換えは所見にもならなかった
- 基底ブランチの複製と記録用ブランチが食い違うと、記録用ブランチを正としていた。強い置き場を、弱い置き場に照らして「書き換えた」と判定していた
- 様式の帰属に、署名の無いコミットの author の一致を「弱い裏づけ」として数え、自己申告の件数から外していた。同じ標準の中で、効力を持つ記録はホスティングが検証した署名と committer・author の両方を求めていた
- 写しの取り出し(record-copy.yml)は、既にある写しを警告だけで残していた。マージより前に置いた写しが、そのまま G-6 に数えられた

内部調査は、差し戻しの記録を消すと停止を避けられると書きましたが、向きが逆でした。G-6 の差し戻しの記録を消すと差し戻し率が下がり、0% の継続で引き下げの側へ倒れます。脅威は偽の差し戻しを足して 0% の継続を切り、引き下げを避けることです。委任の判定はこの記録を PR の時点に読みますが、効力を持つ記録の列挙に入っていませんでした。

外部調査では、GitHub の上で書き込みを防ぐ手段は管理者に対して成立しないことを確かめました。ルールセットは管理者(個人所有では所有者)が外せます。ジョブのトークンはどのワークフローにも同じ名義で出るため、特定のワークフローに限れません([ADR-0090](/process-compass/adr/0090-job-token-and-deploy-credential-binding/))。Git の author と committer は書き手が任意に設定でき、認証に影響しません(2026-11-05 時点)。21 CFR Part 11 の 11.10(e) は、変更が以前の記録を覆わないことを求めます。変更そのものの禁止は求めません。

会議体(起案・現場・品質監査・規格・弁護の5委員)は、5委員とも防止ではなく検出を選びました。審議の記録は `research/379-deliberation/` です。

## 決定

### 1. 置き場の要求を「成立した記録を、記録を残さずには書き換えられない場所」へ改める

置き場は次の4つを満たします。

- 置き場の履歴の書き換えと削除を、ホスティングの規則で止める
- 成立した記録の変更・削除・名前の変更と、マージより前に置かれた写しを、出荷判定(G-7)の集約が履歴の走査で検出して欠落に数える
- 出荷ごとに置き場の先頭の識別子を基底ブランチの出荷の証跡に記録し、次の集約が今の先頭の祖先であることを確かめる
- 規制業と CL2 以上は、書き込みごとにホスティングが検証した署名を要し、署名の無い書き込みを欠落に数える

履歴の走査はマージのコミットの差分(第1の親との差分)を含めて読みます。写しの取り出しの衝突の記録も置き場の検出に含めます。検出を数える範囲は、前回の出荷で記録した先頭より後です(初回と連続しないときは全体)。署名を要するかは構成の区分(規制業・安全重要度)だけから導き、検出・開示・書き込みの経路で同じ判定を使います。

訂正は、元の記録を指す訂正の記録を足す形に限ります。起きた書き換え・衝突・署名の無い書き込みは、例外承認でだけ受け入れます。受け皿は技術負債台帳の区分「例外」の行で、「対象」に検出の識別子(コミットの識別子とファイル、衝突の記録の所在など)を書きます。帰属の照合は、変更を対象とする例外承認の照合によります。受け入れた検出は欠落に数えず、件数を開示します。受け皿が無いと、一度の検出で以後の出荷が恒久的に止まるためです。

ホスティングの規則で履歴の書き換えと削除を止められない構成(ルールセットを使えないプランなど)は、4つの1つ目を満たしません。第1章 1.10.2 の列挙に無い離脱として記録し、開示の定型の文で規則が止めていないことを示します。未達はゲートについての区分であり、置き場の性質には当たらないため、列挙に無い離脱を採りました。防止の一般要求と、外部の追記専用の保管(WORM・透明性ログ)は課しません。規制業では外部の保管を推奨とし、置かない場合の残余を開示します。誤検出を避けるため、準拠テンプレートは置き場を整形・自動修正・改行の変換の対象から外し、AI の担い手による置き場の既にある記録の編集を拒否します。

### 2. 写しの正を欄で決める

不変の欄(レビューの識別子・`user.id`・`commit_id`・`submitted_at`)はホスティングの一次記録を正とし、不一致を欠落にします。写しにだけあるレビューは欠落です。本文と状態は写しを取った時点の値を記録とし、ホスティングの側の変化(マージ後の編集・取り下げ)を所見にします。ただし G-6 の承認は、ホスティングの記録の状態で数えます。写しの状態を差し替えても数えさせないためです。マージより前に提出され、ホスティングの記録にあるのに写しが持たないレビューは、写しから落としたレビューとして欠落にします(マージの後のものは所見)。書き手のアカウントの削除とホスティングを読めない場合は、欠落にせず「照合できなかった」として件数を開示します。照合できなかった写しでは G-6 を数えません。存在しない PR 番号の写しも、ホスティングで照合できなければ数えません。出荷の後は基底ブランチの複製を正とし、G-7 基準5 と集約の突合の向きを改めます。

### 3. 署名の無い author の一致を判定記録の帰属に数えない

帰属の裏づけは、ホスティングの記録で確かめた記名者本人のアカウントの操作に限ります。署名はホスティングの検証で確かめ、committer と author の両方を数値の識別子で照らします。照らすのは、置き場で様式を足したコミットです(裁定 R-3)。様式の今の中身を基底ブランチへ入れた変更は、記名者本人の承認と、記名者が作成者で記名者以外のコミットを含まない場合に限って数えます。置き場の記録を複製して運ぶ機械のコミット(出荷の PR)は記名者以外のコミットに数え、出荷の PR を開いたことを裏づけに数えません。開いたことは、置き場へ誰が様式を足したかを示さないためです。効力を持つ記録の照合と同じ強さ・同じ関数で照らし、名義の共有([ADR-0107](/process-compass/adr/0107-performer-account-declared-and-shared-account-controls/))の扱いも揃えます。「記名者本人の push」は、push の主体を機械が読める場合に限ります。裏づかない判定記録は今までどおり欠落にせず、自己申告として開示します。保証の主張の成立条件4 は、帰属を裏づけた記名だけで判定します。

### 4. 先取りを三重に塞ぎ、委任の判定が数える差し戻しを効力を持つ記録に加える

写しの取り出しの処理は、既にある写しと不変の欄・状態・本文(マージの時刻までのレビュー)が食い違えば失敗し、衝突を記録します(一致すれば再実行として成功で終える)。マージより前に置かれた写しを、履歴の走査が欠落にします。写しにだけあるレビューを、ホスティングとの突合が欠落にします。

委任の判定が数える G-6 の差し戻しの記録を、効力を持つ記録の列挙と用語の定義に加えます。帰属を確かめられない差し戻し(偽の差し戻しを含む)は数えません。レビューの差し戻しの書き手は、G-6 の承認の数え方と対称に、名簿の人で AI の名義でなく書き込みの権限を持つ関係を持つ人とし、席の責任者に限りません。限ると、正当な差し戻しを落として引き下げを誤って発火させるためです。名義の共有(ADR-0107)は、効力を持つ記録と同じく帰属の確認を要します。この向きは停止の側へ倒れ、偽の差し戻しで 0% の継続を切る経路を塞ぎます。名簿の数値の識別子の提案は、写しを源とし、ホスティングの今の値と一致するものに限ります(ADR-0108 決定2 を補う)。提案は効力を持つ記録に加えません。

### 5. 書き込める主体を限れないことを開示する

書き込みの主体を限れないこと(ジョブのトークンはワークフローを限れない、管理者はルールセットを外せる)を、構成ごとの固定の文と走査の件数で保証の開示の項目1 に出し、外部へ渡す開示にも載せます。固定の文は、規則の適用の状態(確かめた / 適用されていない / 確かめていない)と署名の要否で出し分けます。開示は決定1〜4 と組で採ります。開示だけでは数え方が変わらないためです。

## 反論されうる点

### 規定を改めて IMPL-0353 を delivered にしたのは、言い換えで未達を消したのではないか

消えたのは「防止」の未達の表示です。代わりに、(1) 防止を課さないことと理由を本文の「採らない形」に書き、(2) 防げていないことを出荷ごとの保証の開示に定型の文で出し(IMPL-0439)、(3) 検出の規定を新しい実装マーク(IMPL-0432〜0435)で追います。読み手が「防いでいない」を知る経路は、以前より増えます。

### 検出は事後であり、出荷の前に書き換えた写しで G-6 が成立する時間がある

判定記録は ADR-0106 で「G-7 の集約。事後でよい」と区分した記録です。書き換えは G-7 の集約で欠落になります。事前に効く読み手(委任の判定と名簿の提案)は、決定4 で別に扱います。

### 網の外に残る経路

検出できない経路は2つです。1つ目は、管理者(個人所有のリポジトリでは所有者。1〜2名の体制では判定される側であることが多い)の操作です。管理者はルールセットを外し、前回の出荷の先頭より後の未出荷のコミットだけを作り直して force push できます。前回の先頭は新しい先頭の祖先のままで、作り直した記録は追加として走査を通ります。既定ブランチの出荷の証跡には触れません。写しは、不変の欄・状態・写しに無いレビューのホスティングとの突合が残る防御です。様式は記録用ブランチの上の記録だけが根拠のため、作り直しを検出できません。

2つ目は、前回の先頭まで含めて履歴を書き換え、既定ブランチの出荷の証跡も書き換える操作です。これは既定ブランチの強制層(PR と G-6)を破る操作です。最初の出荷より前の force push による書き換えも、記録した先頭が無いため検出できません。新しいコミットによる書き換えは、最初のコミットからの走査で検出します。

### 署名の鍵を持たない体制では、G-7 の様式が自己申告になりやすい

出荷の PR を開いたことは裏づけに数えません。記録用ブランチは書き込みの権限を持つ者とジョブのトークンが新しい様式を足せるため、出荷判定者が開いた出荷の PR で、第三者が足した「出荷判定者の記名」の様式まで裏づいたことになるためです。出荷の PR の機械の複製のコミット(github-actions[bot])は、記名者以外のコミットに数えます。署名の鍵を持たない体制では、G-7・G-8 の記名者がそれぞれ出荷の PR を本人のアカウントで承認する(作成者は自分の PR を承認できないため、記名者以外の人が PR を開く)か、記録用ブランチへ署名コミットで様式を足します。どちらも無ければ自己申告として開示し、保証の主張の成立条件4 は成立しません(EV-0226)。

### 開示の値が大きく変わる

署名の無い author の一致を外すと、多くの採用者で様式の大半が自己申告になります。変わるのは開示の値であり、出荷は止まりません。変わる前の値は、名前の一致で良く見えていました。前回の値を併記するため、変化の理由を本 ADR で示します(EV-0119 の観測値は前後で連続しない)。

## 帰結

- 第4章「判定記録を基底ブランチへ入れる操作」: 効力を持つ記録の表に委任の判定が数える G-6 の差し戻しの記録を足した。判定記録の帰属の裏づけを改め、「弱い裏づけ」の文を削った。置き場の要求・訂正の形・採らない形を書いた。EV-0185 を削除し(識別子は再利用しない)、EV-0224・EV-0226・EV-0227 を足した。IMPL-0353 と IMPL-0128 を改め、IMPL-0432・0433・0434・0440・0442・0443 を足した
- 第4章「判定の成立」: 名簿の数値の識別子の提案をホスティングで照合した値に限る文を足し、IMPL-0441 を付けた
- 第4章 G-6「承認レビューを判定記録とする条件」: 写しとホスティングの記録の突合の欄の区分、G-6 の数え方、写しの取り出しの衝突を書いた。EV-0225 と IMPL-0435・0437 を足した
- 第4章 G-7: 基準5 の突合の向き(IMPL-0436)、保証の開示の項目1 の定型の文と件数(IMPL-0439)、保証の主張の成立条件4 の記名者(IMPL-0438)
- 第1章 1.10.2 の列挙に無い離脱の表に、置き場の履歴の書き換えと削除を規則で止めていない構成を足した
- 第1章 1.4 の用語「効力を持つ記録」、第5章 5.4.6 の差し戻し率の分子、フェーズ5 の CI/CD ゲート構成を改めた
- 準拠テンプレートの集約: `records.mjs`(履歴の走査・祖先関係・ルールセットの検査・様式を足したコミット)と `aggregate-evidence.mjs`(突合・数え方・帰属・成立条件4・開示)
- 準拠テンプレートのそのほか: `autonomy.mjs`(差し戻しの帰属)、`roster-ids.mjs`、`record-copy.yml`(衝突)、`ship-evidence.yml`(先頭の記録)
- 準拠テンプレートの誤検出の対策: `.gitattributes`・`.prettierignore` と、強制層の保護のパターン。`generate-profile.mjs` のコメントを ADR-0106 決定6 に揃えた
- 範囲外の申し送り: gate-g5 と ship-evidence の verify が `pull_request` で PR の側の定義を読む論点は、[#371](https://github.com/Takenori-Kusaka/process-compass/issues/371) で扱う
