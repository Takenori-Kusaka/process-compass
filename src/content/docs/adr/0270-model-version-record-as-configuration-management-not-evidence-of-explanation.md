## コンテキスト

- [#457](https://github.com/Takenori-Kusaka/process-compass/issues/457): 所有者の意見(2026-11-27。決定ではなく審議の入力)。モデルの版そのものを証跡にする価値は無い
- ADR-0012 決定3 の理由「版を記録しない生成は再現できず、検証の対象を特定できない」は、5.8.2 の「記録の目的は、生成の再現ではありません」と食い違う。5.8.2 は、成果物が正しいことの根拠を、生成の条件でなく検証の記録とも書いている
- 本文で、版が説明の証跡として表示されているのは、H.3 の「何をしたか」の行、提案書の型の「監査対応」、H.5 問11 の置き方である。版の記録の役の大半(棚卸しした 30 か所のうち 25 か所。安全検証の手引きの「要求2の再現性の確保」は棚卸しから漏れており、本 ADR で改めた)は、影響範囲の特定・変化点の管理・供給者の管理・検出率の測定の有効性・宣言と実態のずれの検出である

## 決定

1. (ADR-0012 決定3 を置き換える)記録として、モデルの版・生成に用いた指示資産の版・検証の記録を求める。要求は変えない。版の記録の目的は構成管理である。影響範囲の特定、変化点、供給者の管理、検出率の測定の有効性、宣言と実態のずれの検出に使う。版を記録しない生成は、ある条件の問題が判明したとき、影響範囲へ含まれるかを判定できない(5.8.2)。ADR-0012 決定3 の「生成に用いた指示」は、5.8.2 の「指示の保存」と同じく、生成時に参照した指示資産の版の特定と読む(言い換えであり、要求は変わらない)
2. 版の記録を、何をしたかの説明・生成の再現・成果物の正しさの証跡に数えない。ブラックボックス化への答えは、ADR-0269 の追跡と検証の記録である。正しさの根拠は検証の記録である
3. 変更ごとの版の記録をやめない
4. 表示を揃える。H.3 の「何をしたか」の行、提案書の型の「監査対応」、H.5 問11 を、決定1・2 に合わせた。5.8.2 の本文は変えない。5.8.2 が既に、記録の目的は生成の再現ではないこと、正しさの根拠は検証の記録であることを書いている

## 採らないと決めたこと

| 案 | 採らなかった理由 |
| --- | --- |
| 変更ごとの版の記録をやめる(所有者の意見を、記録の廃止まで読む) | 安全関連部のモデルの版と指示を構成管理の下に置く要求(安全検証の要求2)が根拠を失う。ほかに、宣言と実態のずれの機械の検出、インシデント対応の影響範囲、内部監査の観点、保証の開示の項目7 が穴になる。記録の費用は自動でほぼ無く、やめて減る負担は小さい。所有者がこの読みを意図するなら、安全の議題として別に問う |
| 変更ごとの記録の代わりに、期間の記録(体制の改訂履歴の日付)で代える | 宣言と実態がずれたとき、期間の記録は実態を表さない。並行の実行・下位の担当で複数のモデルが動く構成では、期間で一意に決まらない |
| 表示だけを直し、理由を直さない | ADR-0012 決定3 の理由文が、5.8.2 と食い違ったまま残る |
| 5.8.2 へ「証跡ではない」を足す | 5.8.2 が既に書いている。二重に書くと、将来の食い違いの源になる |
| 台帳に抜き書きの無い外部の規格を根拠に引く | 読めていない条項を根拠にしない |

## 影響

- 安全関連部の要求2 の文は変えない。手引きの「再現性の確保」の語だけを、構成管理の語へ改めた
- 限界: モデルの識別は、記録を導出元から自動で取る IMPL-1034 が降りるまで、担い手が書く `Co-Authored-By`(IMPL-0176)による自己申告である。影響範囲の特定と、宣言と実態のずれの検出が使えるのは、申告が実際に動いたモデルを表す範囲に限る。版の別名と生成の非決定性のため、同じ版でも同じ挙動とは限らない。影響範囲は同じ条件の変更の一覧であり、問題の再現の保証ではない
- 提案書の型の「監査対応」と、H.5 問11 は、版を構成管理の記録として読ませる
- 再検討の契機: 版の記録が、監査・インシデントで読まれた実績が出ないとき。インシデントで、版によって影響範囲を絞れた、または絞れなかった記録が出たとき

## 根拠水準

- 新しい根拠水準のマークは足さない。版の記録で影響範囲を絞れた実績が無いことは、附属書 H の H.5 問11・問22 が既に開示している
