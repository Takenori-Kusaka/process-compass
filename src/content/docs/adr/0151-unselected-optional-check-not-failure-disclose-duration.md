## ステータス

採用(2026-11-17)。採用済みの ADR の決定を置き換えません。[ADR-0033](/process-compass/adr/0033-no-target-as-recorded-state/) 決定6(対象なし)を未実施へ広げず、[ADR-0056](/process-compass/adr/0056-assurance-argument/) の項目4 の行を、項目6 と同じ型で補います。[#330](https://github.com/Takenori-Kusaka/process-compass/issues/330) に答えます。

## コンテキスト

- アダプタのコマンドが空の任意の検査(静的解析・依存監査・ライセンス検査・依存の導入)は、通知を出して通過する。2026-11-17 に準拠テンプレートの複製で実行して確かめた。G-5 のジョブ `static-analysis` は、静的解析と依存監査のどちらか一方を実施しなくても成功する
- 保証の開示の項目4 は、静的解析と依存監査では、検査ごとに「未実施(コマンドが未設定)」と出す。通過との区別は、この2つでは実行で確かめた。ライセンス検査では成り立たない。空のコマンドで通った段を、準拠テンプレートの記録の段が実施(`scanRun: true`)として書き、項目4 が「実施(success)」と出す(IMPL-0992。降りていない)。依存の導入は集約に検査の項目が無く、項目4 に出ない
- 項目4 には、未実施が続いている期間を出す仕組みが無い。項目6 の未測定には、続いている期間を併記する型がある(第4章 G-5「保証の開示」、附属書H H.6)
- 実装が始まった後も空のまま運用されると、未実施が続いていても出荷ごとの開示から読み取れない
- 実行環境が入力を欠いて実施できなかった検査は、失敗に数える([ADR-0077](/process-compass/adr/0077-repository-ci-wiring-and-distribution/))。空のコマンドは、構成に書かれた選択であり、これとは異なる

## 決定

### 1. 構成で選んだ未実施は、実装の開始後も G-5 を失敗にしない

アダプタのコマンドが空の任意の検査(静的解析・依存監査・ライセンス検査・依存の導入)は、構成で選んだ未実施として扱い、G-5 を失敗にしない。項目4 には、静的解析・依存監査・ライセンス検査を検査ごとに未実施として出す。依存の導入は集約の検査の項目を持たず、項目4 の対象外とする。入力の欠落による未実施(ADR-0077 の範囲)とは区別する。テストの実行と秘匿情報の混入検査は、この扱いを受けない。カバレッジは任意の検査から外す([ADR-0124](/process-compass/adr/0124-unmeasured-coverage-merge-control-and-detection-scope/) 決定1。第5章の表を第4章に合わせる編集)。

### 2. 項目4 に、検査ごとの理由と継続期間を併記する

項目4 が「未実施」の検査には、理由と、未実施が続いている期間(未実施のまま出荷した最初の出荷からの経過と、連続した出荷の回数)を併記する。起点は項目6 と同じです。前回の成果物から起点と回数を引き継ぎます。理由が「検査対象が存在しない」の未実施にも当てる。継続は検査ごとに数え、理由が変わっても未実施が続く限り途切れない。

### 3. 課さないと決めたこと

- 継続の長さで差し戻さない。閾値(N 出荷)を課さない
- 第7章 7.3 の例外承認の対象にしない(7.3 は基準の不充足を承認する手続で、未実施の通過には入口が無い)
- G-8 の異議の対象(保証の開示に載った未達・未測定)と観点14 を広げない。内部監査の観点16 の確かめ方と附属書H H.6 の C3 の行で読めるようにする
- 基準2 の文に「未実施を0件に数えない」を足さない

### 4. 統制の水準

統制は「見える化」までとする。機械で検査するのは、項目4 の未実施と継続期間の出力(値の存在と日付で決定可能)だけで、合否には使わない。理由の妥当性は自由な文であり、機械で閉じない。継続期間の出力は、準拠テンプレート側が降ろしていない(IMPL-0990。undelivered)。

## 検討した選択肢

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 実装の開始後は空のコマンドを G-5 の失敗にする | 採らない | 採用者への新しい義務(重)。道具の無い言語・社内の閉じた道具の採用者を、空のままの抜け道か例外承認の連続へ追い込む。「実装の開始」の判定は目印を持たないコードで機械に閉じない |
| 依存監査だけを必須にする | 採らない | 新しい義務。同梱の node・python・go のアダプタは依存監査を既に持ち、言語ごとの既定のコマンドは手引きで足りる |
| 未実施が N 出荷続いたら失敗にする | 採らない | N の根拠が無い。値で落とすと形式的な記入を招く |
| 例外承認(7.3)で未実施の継続を受ける | 採らない | 7.3 の入口が無い。作れば新しい義務になる |
| 省略(第8章)で基準2・5 を外して受ける | 採らない | 本件の結論は省略を要しない。外せるかは第8章の範囲で、本件では決めない |
| 基準2 の文に「未実施を0件に数えない」を足す | 採らない | 基準の読みの変更(重)。項目4 が検査ごとに区別して出すことを実行で確かめたので、重複でもある |
| G-8 の異議の対象・観点14 に未実施を足す | 採らない | 出荷判定者への新しい義務(重)。死文にしない目的は観点16 で受ける |
| 継続期間の起点を G-4 の時刻・SG-0 にする | 採らない | G-4 は機能仕様ごとに何度も起き、単一の時刻にならない。SG-0 の記録は機械の入力として定まっていない |
| 継続期間を出さず、未実施の検査名の列挙だけにする | 採らない | 続いていることが読めず、項目6 との釣り合いを欠く |
| ADR-0033 決定6 を遡って未実施へ広げる | 採らない | 採用済みの ADR を書き換えない。本 ADR で扱う |
| 内部監査に新しい観点を立てる | 採らない | 観点16 の文言が既に未実施を含む。重複 |
| 空の理由の妥当性を機械で判定する | 採らない | 自由な文の意味で、機械で閉じない |

根拠の水準のマークは、本文の側に置きました。決定1 の判断(失敗にしなくても、項目4 の開示で通過との取り違えを防げる)は EV-0290 に、決定2 の前提(続いている期間を見せれば気づく)は EV-0289 にあります。どちらも E0(なし)で、設計の推論だけに依ります。差し替え条件は、取り違えまたは見落としの事例が1件記録されたときです。EV-0290 では、失敗にする案を重の審議で検討し直します。

## 影響

- 第4章 G-5: 「検査対象が存在しない場合の扱い」に構成で選んだ未実施の段落を足した。保証の開示の項目4 の行と箇条に継続期間を足した。IMPL-0989(delivered。静的解析・依存監査に限る)と IMPL-0990・IMPL-0992(undelivered)を付けた
- 附属書H: H.6 の併記の表に項目4 の行を足した。C3 の行と観点16 の確かめ方に継続期間を足した
- 第5章: template-repository.md の空コマンドの表を、カバレッジを分けて ADR-0124 に合わせた。ci-gates.md の併記と引き継ぎの規定を項目4 に広げた
- 準拠テンプレート: 変更なし。現在の準拠テンプレートは、空のライセンス検査を項目4 で実施(success)と出す(IMPL-0992。降りていない)。ライセンス検査の記録の誤り(申し送り T-8。IMPL-0992)・継続期間の出力・試験・注釈の誤り(adapter.mjs 冒頭の「コマンドが空の場合は失敗させます」)は #330 に残す

## 見直しの契機

- 未実施が通過と取り違えられた事例の報告
- 内部監査の観点16 で、継続した未実施が見つかった報告
- EV-0289・EV-0290 の見直し期限(2027-05)
