## コンテキスト

ADR-0088 は、組織上の距離の段1〜4 を定め、段を課す活動を独立した安全性の評価と段階「最強」の検証の担当者の2つに限りました。その上で、「CL の判定と安全リスクアセスメント(テンプレ9)を、誰がどの段で確かめるか」を、課さないと決めたものではなく決めていない事項として残しました。

内部調査で、次のことが分かりました(`research/373-deliberation/survey-373-1-internal.md`)。

- CL の判定には、段どころか判定者・確認者を定めた条項が無い。準拠テンプレートの初期化の回答(安全重要度の質問)は、記名と根拠なしで構成に入る
- CL0 の判定は、委任・1〜2名の構成・事業ステージによる G-6・G-7 の緩和・独立した安全性の評価とテンプレ9 の不要をまとめて開く。判定の誤りの影響が最も大きい判定に、確認の規定が最も薄い
- 区分を下げる操作には4つの要求事項(ADR-0030)があるのに、最初から低く判定した場合は根拠と記名が残らない。区分を下げる操作の根拠の記録の有無を、機械で確かめていない
- テンプレ9 は AI エージェントの危害の評価であり、製品のハザード分析とリスク評価ではない。要否は第6章(CL に依らない4条件)と第8章 軸E・規則データ(CL2 以上)で食い違う。様式に承認の欄が無い
- 区分の引き下げの記録先は、CL2 以上でテンプレ9 だが、テンプレ9 は製品の危害を書く欄を持たない
- #318 の弁護の委員が提案した「R の判定に段を課さない」の明記は、#318 の裁定と ADR-0088 のどちらにも載っていない

外部の調査では、調べた規格のどれも最も低い判定を確認の外に置いていませんでした(`survey-373-2-external.md`)。ISO 26262-2:2018 表1 は、QM の列でもハザード分析とリスク評価の確認レビューを最も遠い独立(I3)とします(翻訳採用の意見募集草案で読んだ)。FDA のガイダンス(2023-06)は、最も低い区分(Basic)にも区分の記述と理由を求め、判定をリスクコントロールの対策を入れる前のリスクで行います。EASA AMC 20-115D は、ソフトウェアのレベルを開発の外のシステム安全評価で割り当てます。一方で、安全の範囲に入るかどうかの判定にまで I3 相当を課す規格は、読めた範囲にありませんでした。

会議体(起案・現場・品質監査・規格・弁護の5委員)の審議と議長の裁定は `research/373-deliberation/` にあります。5委員とも欠陥を認めました。初回の CL の判定には記名と根拠が残らず、区分を下げる操作より軽いという点です。

## 決定

### 1. 判定の記録を全区分で必須にし、判定者と別の自然人が確かめる

- 安全重要度の判定の記録を、CL0 を含むすべての区分で必須にする。置き場は D-0 の表10「安全重要度の判定の記録」(第6章 テンプレ0)
- 記録に書くもの: 判定者の記名(D-0 表1「体制と運用形態」の決定者)、対策を入れる前の最悪の帰結(構成要素ごと)、1つ上の区分に当たらない理由、附属書F F.2 の回答(Q1 と、「はい」なら切り分けの結果と根拠)。確認者・段・段の根拠・確認日も同じ記録に書く
- 確認者は、判定者と別の自然人とする。段の下限は、判定で外れる1つ上の区分が評価者に求める段とする。CL0 の判定は段1、CL1 の判定は段2、CL2 の判定は段3。CL3 の判定は外れる区分が無いため段1。低く判定しても、確認が下限より軽くならない
- 判定の結果に依らない入力で段を引き上げる。附属書F F.2 の Q1 が「はい」の案件は段3。規制業の候補に当たる案件は少なくとも段2。ISO 26262-2 表1 のハザード分析の行と同じ形(結果に依らない確認)を、安全の範囲に入る案件だけで用いる
- 段の割り当ては類推にもとづき、本標準での実証が無い。EV-0231(見直し 2027-05)で開示する

### 2. 1〜2名の体制と、届かない確認の扱い

- 確認を体制の人数で免除しない。チームの外の自然人を確認者にできる。2名の体制で、相手の1名を確認者に数えてよいのは、求める段が段1 の場合に限る
- 判定の記録と判定者の記名の欠落は、G-1 の審議を止める。判定者本人が書けるためである。G-1 の後に欠けた場合は、出荷判定(G-7)の記載の欠落に当たる。G-1 の前の検査だけでは、G-1 の後に記録を消す・書き換える経路が残るためである
- 判定者の記名は、記録が作られた時点の D-0 表1 の決定者と照らす([ADR-0111](/process-compass/adr/0111-name-confirmation-in-same-change-point/) 決定6 と同じ原則)。決定者の交代の後も、交代の前に正しく作られた記録は効力を保つ。記録の時点で決定者でなかった人の記名は受け付けない
- 確認の欠落は、未達として表示し続ける。他の人の手が要るためである。未達のまま出荷するかは、第8章「再実行の時点と向き」の表による。CL0 で規制業に該当しない案件は、保証の開示への表示と G-8 の受容で出荷できる。CL1 以上と規制業の案件は、確認の未達のまま出荷しない
- **帰結**: 3〜9名の CL1 の案件で、段2 の確認者を内部に置けず外部からも調達できなければ、出荷できない。CL1 の判定は CL2 の守り(独立した安全性の評価の段2)を外す判定であり、その段の確認を一度も得られない構成は、CL2 でないことを誰にも確かめられていないためである。CL1 の案件に安全の確認を求める帰結として受け入れる
- 附属書F F.2 の Q1 が「はい」の案件で段3 の確認が欠けるときは、G-8 で受容しても出荷しない。G-7 の記載の欠落に当たる
- 理由の記述と AI の確認を、確認者の代わりにしない

### 3. テンプレ9 の要否と承認、引き下げの記録先

- テンプレ9 の要否は、第6章の CL に依らない4条件を正とする。第8章 軸E の表の CL0・CL1 の升を「第6章の適用条件による」に直す。規則データに、CL0・CL1 で `safetyRiskAssessment: conditional` を立てる規則 `r-e-sra-conditions` を足す。CL2 以上は従来どおり、条件に依らず必須とする
- 様式に承認の欄を置く。承認者は作成者と別の自然人(段1)。テンプレ9 の承認に段2・段3 を課さない。CL2 以上では、独立した安全性の評価者がテンプレ9 を読む
- 製品の危害を下げた記録(区分の引き下げの根拠)は、テンプレ9 ではなく安全重要度の判定の記録へ移す。区分に依らず同じ置き場とする

### 4. 仮の判定と機械の検査

- 準拠テンプレートの初期化の回答(安全重要度の質問)は仮の判定とする。判定の記録と判定者の記名がそろうまで、G-1 の審議を開始しない
- 区分を下げる操作では、引き下げの根拠の記録が実在することを機械で確かめる
- 機械が確かめる範囲: 判定の記録の欄、判定者の記名、確認者の記名(判定者と別の人であること、AI の名義でないこと)、引き下げの根拠の記録の実在。段2 以上の確認者の距離の照合は、#357(組織上の距離を構成の欄で表す)へ渡す
- 附属書H H.3 に観点29(安全重要度の判定の記録と確認)を足す。保証の開示の項目1 に、判定の確認の状態(判定者・確認者・求める段・記録した段・未達)を載せる

### 5. リスク区分(R)の判定に段を課さない

- R の判定に、組織上の距離の段を課さない。**課さないと決めた事項である**
- R は変更ごとに判定し(ADR-0039)、その確認は G-5 の区分の下限の検査と G-6 の承認が担う。案件ごとに一度の CL の判定と単位が違い、判定の確認の段の論法は R の判定に及ばない。変更ごとに段2 以上を課すと、1〜9名の体制は全変更で未達になる

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 全区分の判定に最も遠い段を課す | 安全の範囲に入るかどうかの判定にまで I3 相当を課す規格は、読めた範囲に無い。規格の裏づけの範囲を超える。1〜9名の体制のほぼ全件で外部の確認者を要する |
| 確認を求めない | 低い判定で確認を逃れる循環が残る。外部の規格のどれとも合わない |
| CL0 の判定にだけ確認を求める | CL1・CL2 と判定して、外れる区分の要求を逃れる経路が残る |
| 判定しなければ最上位とする既定値(IEC 62304 型) | 判定の記録を必須にすることで目的を果たす。既定値は、1〜2名の初期化を CL3 の拒否で詰ませる |
| 全区分を段1 から始め、入力でだけ段を上げる | CL1・CL2 の判定の確認が、外れる区分の評価者の段より軽くなる |
| テンプレ9 の確認に段2・段3 を課す | テンプレ9 は製品のハザード分析ではない。製品の危害の根拠は、安全重要度の判定の記録へ移す |
| R の判定に段を課す | R は変更ごとであり、確認は G-5・G-6 が担う |

どれも、決めていない事項ではなく、課さないと決めた事項です。
