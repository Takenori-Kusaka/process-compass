## ステータス

採用(2026-10-13)。一部置き換え(→ ADR-0084 の決定1): 決定2(`check` を欠くマークを検査で落とさない)と、決定1 の表の「(書いていない) 未分類」の行、`presence` の定義(記録・欄・ファイル・キーの有無まで)を、[ADR-0084](/process-compass/adr/0084-check-strength-plans-and-resident-rules/)の決定1 が置き換えました(2026-10-24)。以後 `check` を欠くマークを検査で落とし、`presence` は規則を運ぶ単位(欄・キー・行・ファイル)の有無までに限ります。決定3(既存のマークの棚卸しを今回行わない)は時点の決定であり、ADR-0084 が棚卸しを終えたことで補われます。決定1 のうち、`state` を2値に保つこと、`check` を独立に書くこと、`machine` と `manual` の意味は維持します。降りていない規定には計画の属性 `plan` が加わります。

## コンテキスト

[#308](https://github.com/Takenori-Kusaka/process-compass/issues/308) の調査で、実装マークが「降りている」と表示する規定の中に、機械が規定の中身を確かめていないものがあると分かりました。記録は `research/302-310-deliberation/`(`survey-308.md`、`council-C-01`〜`05`、`decision.md` の C-5)にあります。

- [実装マークの規約](/process-compass/community/implementation-marking/)が確かめるのは、降ろし先の実在である。構成のキーなら、キーがあることまでを確かめる
- IMPL-0001(兼務を禁止する組み合わせ)は `state=delivered` だった。同じ節の図が掲げていた1つの禁止は、どの検査にも現れていなかった([ADR-0060](/process-compass/adr/0060-drafting-context-and-two-layer-independence/))
- 曖昧語の禁止(第4章 G-2 基準2、G-5 基準4)は、機械が合否にしているのに、実装マークが1つも無かった
- 台帳の読み手は、「降りている」を「守られていることが確かめられている」と読む

「降ろし先がある」ことと、「規定の中身を検査している」ことは、別の事実です。1つの値で表すと、強いほうに読まれます。

## 決定

### 1. 検査の手段を、別の属性で示す

実装マークに属性 `check` を足します。

| 値 | 台帳の表示 | 意味 |
| --- | --- | --- |
| `machine` | 機械が確かめる | 機械が規定の中身を検査し、違反を止めるか件数で出す |
| `presence` | 実在だけ確かめる | 機械が確かめるのは、記録・欄・ファイル・キーの有無までである |
| `manual` | 人が確かめる | 機械は確かめない。確かめる者と時点を注記に書く |
| (書いていない) | 未分類 | 検査の手段を棚卸ししていない |

`state` は2値(降りている・降りていない)のまま保ちます。`state` と `check` は独立に書きます。

### 2. 未分類を隠さない

`check` を欠くマークを、検査は落としません。台帳の冒頭に、検査の手段ごとの件数と、未分類の件数を出します。未分類の規定を、検査されている規定として読まないよう、台帳に書きます。

新しく付けるマークには、`check` を必ず書きます。`check=machine` と書くのは、機械が違反を検出することを実行して確かめた規定に限ります。

### 3. 既存のマークの棚卸しは、今回行わない

既存のマーク(2026-10-13 時点で103件)は、未分類のまま残します。それぞれについて、機械が確かめているのが降ろし先の実在か、規定の中身かを確かめた材料がありません。棚卸しは別の作業とします。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| `state` に3つ目の値を足す | 届いたかどうかと、何が確かめるかは、直交する事実である。文は降りていて検査が無い規定、文も検査も無い規定、検査の一部だけがある規定を、1本の軸に並べられない |
| 検査していない規定に、新しい番号で `state=undelivered` を付ける | 文が実行層に出ている規定を「実行層に対応する記述がありません」と表示することになる。事実と違う表示を足す |
| 規則データの側に、検査の有無を持たせる | 兼務の規則にしか及ばない。実装マークと別の系統が1つ増える |
| 規約の文に書くだけにする | 規定ごとの表示にならない。台帳の読み方は変わらない |
| 棚卸しを終えてから属性を足す | 棚卸しの材料が揃うまで、「降りている」の読みが強いまま残る。未分類と表示するほうが、頼る側にとって正確である |

## 影響

- 台帳に、未分類の件数が出続ける。棚卸しが進むまで、この件数は大きいままである
- `check=machine` の真偽を、機械は確かめない。書いた者の確認に依る。この限界は、実装マークの規約の限界(マークの付け忘れを検出できない)と同じ種類である
- 台帳の「降りていない規定」の節の定型の文(「実行層に対応する記述がありません」)は、変えていない。一部だけが降りている規定を `state=undelivered` で書いた既存のマークとは、合っていないままである。棚卸しの中で扱う
