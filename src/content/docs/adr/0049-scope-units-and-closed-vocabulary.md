## ステータス

採用(2026-08-14)

## コンテキスト

[ADR-0039](/process-compass/adr/0039-scope-in-heading-and-unit-of-judgement/)で作った適用範囲の仕組みが、初回適用案件へ届いていませんでした([#239](https://github.com/Takenori-Kusaka/process-compass/issues/239))。

案件は第5章 5.7.3(選択肢の比較)を適用範囲を確かめずに全体へ適用し、**判定者に不要な記入を課したうえで、成立していた判定を「成立していない」と申告しました**。

**当該条項には既に注記が付いていました**。`### 5.7.3 選択肢の比較(適用: R1 の決定・例外承認)`。仕組みは正しく動いていました。

### 検出が2件しか拾えていなかった

`check-scope.mjs` の限定表現の検出は `R1` / `CL0` 形式に閉じていました。次の限定は対象外です。

| 条項 | 限定表現 |
| --- | --- |
| G-5 基準4 | 仕様変更を含む PR の場合 |
| G-6 基準3 | (コア機能のみ) |
| 附属書F | 安全関連ソフトウェアのみ |
| **B-3 設計審査会** | **S2 スケール、または安全・法規制の対象となる機能** |

**最後の1件は案件でも効いていました**。設計審査会が S1 で適用外となる事実を、案件は標準本文を直接読んで初めて知りました。

### 判定の単位が2つでは足りない

ADR-0039 決定4 は、リスク区分(変更ごと)と安全重要度(案件ごと)の2つを定めました。**事業ステージとコア指定が、どちらにも当てはまりません**。

**事業ステージを案件ごとの単位として扱うと、テーラリングの宣言が案件の全期間へ凍結されます**。「本案件は S1 なので独立レビューをコア機能に限る」という宣言が成立するのは S1 の間だけです。S2 への移行で自動的に失効しなければなりません。

## 決定

### 1. 判定の単位を4つとする

| 単位 | 条件の例 | 案件単位で適用外にできるか | 判定の時期 |
| --- | --- | --- | --- |
| 案件ごと | 安全重要度、チーム規模、開発形態 | できる | 案件の開始時 |
| **ステージごと** | **事業ステージ** | **できない** | **ステージ移行ごと(SG-n)** |
| **機能ごと** | **コア指定、安全・法規制の対象** | **できない** | **機能仕様の承認時(G-4)** |
| 変更ごと | リスク区分 | できない | 変更ごと |

**ADR-0039 の本文は書き換えません**。同 ADR 決定4 が R について定めた「案件の属性から変更ごとの適用外を導いてはならない」という論理を、**時間軸(ステージ)と対象軸(機能)へ拡張します**。

### 2. 検出の語彙を、閉じた集合に保つ

限定表現の検出へ加えるのは、決定1 の単位に対応する語彙だけです。

```
R1〜R3 / CL0〜CL3 / S0〜S2 / コア機能 / 安全関連ソフトウェア
```

**「〜のみ」「〜を含む場合」といった一般表現による拡張は採りません**。

理由は誤検出の質にあります。「〜のみ」は技術文書で頻出し、その大半は適用範囲の限定ではありません。40ページ超について1件ずつ「これは適用範囲か、単なる説明か」を判断させると、**除外の登録が検査を通すためだけの作業になります**。

ADR-0039 決定2 は「登録そのものを判断の記録とする」と定めました。**判断の記録が数百件に達したとき、それは記録ではなく雑音です**。

**語彙を閉じた集合に保つことで、誤検出の総量が予測可能になります**。

### 3. 会議体の適用条件を、見出しへ併記する

B-3 設計審査会の見出しへ `(適用: S2 スケール、または安全・法規制の対象となる機能)` を併記しました。**適用条件を表の1行へ置いたままにしません**。

### 4. テーラリングの表そのものは、注記の対象としない

第8章の軸の表は、それ自体が適用範囲を定義する表です。**その行へ注記を付けると入れ子になります**。表の存在が適用範囲の宣言である節は、除外へ理由付きで登録します。

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 一般表現(「〜のみ」等)まで検出を広げる | 誤検出が支配的になり、除外の登録が雑音化する。ADR-0039 決定2 の意図が壊れる |
| 判定の単位を2つのまま、ステージを案件ごとへ含める | テーラリングの宣言が案件の全期間へ凍結される。ステージ移行で失効しない |
| 検出を広げず、注記の追加だけを行う | どの節に注記が要るかを、人が40ページから探すことになる |
| 何もしない | 案件が標準本文を全部読まないかぎり適用範囲を知れない。#226 の再発 |

## 帰結

- 判定の単位が4つになり、台帳の表示も4値になる
- 語彙の拡張により**12件の新規検出**が生じ、うち12件を除外へ登録した。**適用範囲の限定として注記へ移したものは無い**
- **除外が12件に対し、注記が2件である**。この比は、検出の条件が広すぎることを示唆しうる
- **一般表現による限定は、引き続き検出されない**。この限界は解消しない

:::caution[暫定 EV-0035 / 見直し 2027-02]
**対象**: 決定2(語彙を閉じた集合に保てば、誤検出の総量が予測可能に保たれるという判断)。

**根拠の水準**: E0(なし)。

**根拠とした事例**: 2026-08-14 の語彙拡張1回分。

**差し替え条件**: 語彙を拡張した回ごとの、注記へ移した件数と除外へ登録した件数の比。**除外が注記の5倍を超える拡張が2回続いた場合、語彙の選び方が限定の検出に向いていないことになります**。初回は 12対0 であり、既にこの水準を超えています。
:::
