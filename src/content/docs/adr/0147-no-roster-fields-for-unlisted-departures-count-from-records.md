## ステータス

採用(2026-11-17)。審議は軽です。記録は `research/354-deliberation/` にあります。採用済みの ADR の決定を置き換えません。[ADR-0133](/process-compass/adr/0133-no-conditions-or-compensating-measures-for-unlisted-deviations/) の決定(列挙に無い離脱の条件と代償措置は定めない)と、[ADR-0083](/process-compass/adr/0083-standard-edition-end-of-application-and-deviation/) の述べられる名の導き方を、実装の側から補います。

## コンテキスト

[#354](https://github.com/Takenori-Kusaka/process-compass/issues/354) の項目2 は、第1章 1.10.2 の表が挙げる列挙に無い離脱のうち、準拠テンプレートの述べられる名(`claimStatus`)が数えない5つの扱いを問いました。

実行で確かめた事実は次のとおりです。

- コア機能の理解の保持者が1名以下であることと、層1 の記名者が事業決裁者を兼ねることは、出荷の証跡の集約が記録から既に読んでいる。しかし、集約が述べる名は、これらを数えなかった。同じ出力の中で、保証の開示の表は離脱を示し、名は「適合の主張」と出うる状態である
- 開発者と独立レビュアの席の担い手が同じ専用のアカウントを申告し、env-check の照合が両席とも確認済みの構成で、`claimStatus` は「適合の主張」、離脱0件を返した
- 保持者の数と層1 の記名者は、標準が記録の正本を既に定めている(運用引き継ぎ文書の節2、層1)

## 決定

### 1. 構成に欄を足さない

保持者の数と層1 の記名者のために、構成(`process.config.json`、`/process-change`)に欄を足さない。

### 2. 記録から決まるものだけを機械で数える

決定可能な条件(値の一致と数の比較)に限る。

- 出荷の証跡の集約は、運用引き継ぎ文書の節2 の保持者(本人以外の確認つきで数える既存の数え方)が1名以下のコア機能がある、または層1 の記名者が事業決裁者の席の責任者と同一のとき、列挙に無い離脱として数え、述べられる名を適用の表明へ下げる
- 記録が無い・解けないとき(引き継ぎ文書なし、節2 にコア機能の記載なし、層1 なし)でも、名を下げない。確かめられない旨を出力に残し、出荷判定者に確かめさせる
- 準拠テンプレートの述べられる名(`claimStatus`)は、兼務を禁止した組(構成の兼務禁止表。実行主体の文脈の単位の規則を除く)の2席の担い手が、同じ数値の識別子の専用のアカウントを申告した構成を、列挙に無い離脱として数える。構成だけで決まる。構成の契約検査は、この申告を拒否せず、注記を出す(拒否すると構成を記録できず、離脱を表示できない)
- 記録は作業ツリーから読む。範囲の終点のコミットの記録は読まない

### 3. 機械にしないものは、降りていない規定として表示し続ける

- 欠陥注入の時期と箇所の秘匿の不成立は、構造の判断である(降ろす先の議論は #356)
- 層1 の記名者と事業決裁者の氏名の表記が違う場合、禁止でない組の席どうしの認証情報の共有、ホスティングのアカウントの外の認証情報は、人が確かめる(降ろす先の議論は #446)

実装マークは、寄せ先の違う2つに分ける。準拠テンプレートの構成書の注記は、集約が数える項目と数えない項目を分けて書く。

### 4. 第1章 1.10.2 と第3章 3.5.3 の食い違いを、本件では揃えない

1.10.2 の「席ごとに認証情報を分けていない構成」と、3.5.3 のレーンの条件1(禁止でない組は同じレーン、すなわち同じ認証情報に置ける)は、禁止でない組の扱いが食い違う。どちらへ揃えるかは、離脱の範囲(適合の主張の信頼)とレーンの設計の両方に及ぶ。本件では揃えず、両方の読みで離脱に当たる部分(禁止の組)だけを機械にする。揃える向きの決定は #446 の審議で行う。

## 検討した選択肢

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 構成に保持者の数と層1 の記名者の欄を足し、記録との食い違いを契約検査で落とす | 採らない | 食い違いを検査で落とすには、契約検査が引き継ぎ文書と層1 を読む必要がある。それなら欄を介さず記録を直接読めばよい。欄は採用者に二重の記入を課す新しい義務であり、記入の時点で古びる。食い違ったとき、甘い側(構成の「2名」)が記録の示す離脱を隠す |
| 集約を機械にしない(開示の表にだけ出し、名は構成だけから決める) | 採らない | 同じ出力の中で、開示の表と名が食い違う状態が残る。離脱があるのに適合と出す向きの誤りは、受け取る者が気づけない |
| 記録が無い・解けないときも名を下げる | 採らない | 書き崩れ(列の名・確認日の書式)で、離脱でないものを離脱に数えて主張を妨げる。読めないときは下げず、確かめられない旨を残す向きに倒す。誤って下げる向きは採用者が気づいて直せるが、逆向きは気づけない |
| 秘匿の不成立を機械にする | 採らない | 「注入する者と見つける者を分けられない」は構造の判断である。測定の記録の `blind: false` は1回の測定であり、理由は自由な文である。機械の検査にするのは決定可能な条件だけにする |
| 禁止でない組を含め、席どうしの認証情報の共有を機械にする | 採らない | 1.10.2 と 3.5.3 の食い違いを、本件で一方へ揃えることになる(決定4) |
| 1.10.2 を「兼務を禁止した組の席どうし」へ揃える、または 3.5.3 を「席ごと」へ揃える | 本件では採らない | 前者は離脱の範囲を縮め、後者はレーンの設計(IMPL-0299)を変える。どちらも軽の範囲を超える。#446 で扱う |

## 影響

- 条文は変えない。述べられる名の導き方(IMPL-0308)の入力が増える
- 実装マーク IMPL-0521 の降りた部分は `delivered` へ改め、降りていない部分を、寄せ先の違う2つの印(秘匿は #356、認証情報の残りは #446)に分ける
- 準拠テンプレート: 採用者には新しい記入欄が増えない。記録の書き崩れで名が下がる場合は、集約の出力に理由が残る
- 見落とす向きの誤り: 記録を作業ツリーから読むため、範囲の終点のコミットの記録と異なる場合がある。実行で確かめていない(下の「確かめていないこと」)

## 確かめていないこと

- 範囲の終点のコミットの記録を読む経路。現在の実装は作業ツリーを読む
- 集約の実行で、名が「適合の主張」と出る状態の再現。一時のリポジトリでは、別の記録の欠落が先に名を適用の表明へ下げた

## 見直しの契機

- 記録の書き崩れで、離脱でないものを離脱に数えた事例が記録されたとき
- #446 で 1.10.2 と 3.5.3 のどちらかへ揃えると決まったとき
- 記録から決まる離脱が、述べられる名に効かない新しい経路が見つかったとき
