## ステータス

採用(2026-10-13)。[ADR-0021](/process-compass/adr/0021-ip-clearance-evidence-not-guarantee/)の決定2 のうち「検収」の語に関わる部分を置き換えます。同 ADR のほかの決定は変えません。[ADR-0040](/process-compass/adr/0040-template-forms-as-subset-of-standard/)を適用し、様式の対応を直します。

「影響」の最後の箇条で決定の外に置いた3点(軸D の表の G-1・G-2・G-5、指示資産の持ち主、標準の外の節を様式が持つこと)は、[ADR-0087](/process-compass/adr/0087-outsourcing-gate-placement-enforcement-ownership-and-authority-sources/)で扱いました。本 ADR の決定1〜8 は維持します。疑義応答集 第3集の版は、ADR-0087 の決定6 が 2026-05-25 の改訂へ改めました(2026-10-24)。

## コンテキスト

[#309](https://github.com/Takenori-Kusaka/process-compass/issues/309) は、受託で発注側の判定者が受注側の担い手へ伝える経路と、検収の無い契約での読み替えを問いました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/302-310-deliberation/`(`survey-309.md`、`council-B-01`〜`05`、`decision.md` の B-5〜B-7)にあります。

### 判定を別の組織へ置けるのに、結果の渡し先が空白だった

第8章 軸D は、技術設計(G-3)と独立レビュー(G-6)の判定を、発注側と受注側のどちらに置いてもよいと定めます。置き先、強制層の所有、受領する記録を、締結時に決めさせます。置いた判定の結果を相手の組織の誰へ渡すかは、定めていませんでした。差し戻しの示し方(満たさない基準の項目番号で示す)は第4章にありますが、組織をまたぐときの渡し先は空白でした。これは、法令と無関係に、本標準の内側の欠落です。

### 法令は、規格の条項にしない

発注者と受注者の労働者との関係には、法令の区分があります。調査は、区分の基準の告示と、厚生労働省の疑義応答集を原典で読みました。プルリクエスト上の指摘と差し戻し、発注側が所有する強制層による遮断が、この区分でどう扱われるかを示す公的な整理は、見つかりませんでした。

規格の作法は、法令上の要求事項を条項に含めないと定め、外部の制約を利用者への情報として示す形を持ちます(ISO/IEC 専門業務用指針 第2部 第9版の箇条4 と 7.6。原典で確かめました)。第1章 1.7.1 は、外部の制約の文末の形を既に持ちます。

### 「検収」に定義が無く、4通りに揺れていた

軸D の表は、G-2 と G-8 を「検収に対応づけ」と書いていました。「検収」は第1章 1.4 に定義がありませんでした。同じ対応づけが、表、規則データの2つの規則、組み合わせ例で、4通りの語で書かれていました。

調査は、民法の全文に「検収」の語が無いことを確かめました。公的なモデル契約は、この語を請負の工程にだけ使います。準委任の工程の終わりは、業務終了の確認と呼びます。準委任で外部へ委託するアジャイル開発のモデル契約は、月ごとの実施業務の確認を定め、成果物についての契約不適合責任は追及できないと解説します。ADR-0021 が「取得できなかった」と記録したモデル契約の条項は、今回の調査が原典で読みました(出典台帳 SRC-0634〜SRC-0639)。

### 様式が、双方向にずれていた

準拠テンプレートの AI-SLA 合意確認書の第2節は、冒頭に、判定の置き先で結果責任が決まるとする文を持っていました。[#300](https://github.com/Takenori-Kusaka/process-compass/issues/300) の検討で、採らないと決めた文です。標準の様式には、判定の置き先を記録する項がありませんでした。標準の様式の第8項(保証の開示と委任の適用)は、準拠テンプレートの様式にありませんでした。必須欄の検査は、通っていました。検査は、登録した欄の存在だけを見るためです。

必須欄の対応表は、「結果責任を負う者」の欄を省略として登録していました。省略の理由は、準拠テンプレートの第2節に依っていました。標準の当該の欄は、知財潔白性の結果責任を負う当事者の欄であり、判定の置き先とは別の事項です。

## 決定

### 1. 判定を別の組織へ置く場合は、判定の結果を受け取る者を、締結時に決めて記録する

対象は、判定を置いた組織と、判定の対象を作成した組織が異なる場合です。この場合は、判定の結果を受け取る者を、締結時に決めて記録します。受け取る者は、組織ごとに決めます。記録は、第6章 テンプレ8 によります。受け取る者が、当該の成果物の作成を担う本人と同じ場合は、その旨を記録します。

### 2. 経路の中身、宛先の固定、判定の置き先の限定を課さない

次のことを、本標準は課しません。

- 判定の結果を渡す経路の中身。受け取る者から作成の担い手へどう伝えるかは、当事者が決める
- 判定の結果の宛先を、特定の席または役職に固定すること
- 判定の置き先を、いまの許容より狭めること
- 席と受信箱に、組織の所属を表す属性を持たせること

### 3. 法令は、外部の制約の注記として書く

区分の基準の告示の名は、注記の中に書きます。文末は「〜とされています」の形にし、時点(2026-10-12)を書きます。判定の置き先の定めと、判定の結果を受け取る者の定めは、この区分についての評価を含みません。本標準に従って運用していることは、区分の判断の根拠になりません。

### 4. 「検収」を「契約上の確認行為」へ改め、第1章 1.4 に定義する

契約上の確認行為は、委託の契約が定める、発注側が納入物または実施された業務を確認する行為です。検収、業務終了の確認、実施業務の確認が例に当たります。何が当たり、どの効果を持つかは、契約によります。

G-2 と G-8 を契約上の確認行為に対応づけるかどうかと、対応づける先を、締結時に決めて記録します。対応づけない場合は、対応づけないと記録します。対応づける先を、本標準は固定しません。

### 5. 契約上の確認行為が無い契約でも、G-6 と G-7 は成立する

本標準のゲートの判定は、契約上の確認行為の有無と種類に依りません。受入基準への適合は、独立レビュー(G-6)と出荷判定(G-7)で確かめます。この2つの判定は、契約上の確認行為ではありません。

確認の基準を受入基準への適合に限定する構成は、契約が成果物の適否を確認する行為を定める場合に限って当たります。

### 6. 契約の類型ごとの読み替えの表を置かない

契約の類型は、契約の表題ではなく実態で決まります。類型ごとの表を置くと、契約の法的な性質の認定を、本標準が抱えることになります。

### 7. ADR-0021 の決定2 のうち、「検収」の語に関わる部分を置き換える

ADR-0021 の決定2 は「検収は仕様適合の判定であり、知財潔白性は成果物の属性である」と定め、両者を別の軸として併存させます。このうち「検収」を、「成果物の適否の確認」と読み替えます。仕様適合の判定と知財潔白性を別の軸として併存させる、という決定の中身は変えません。

### 8. 標準の様式に項を足し、準拠テンプレートの様式をその部分集合へ直す

第6章 テンプレ8 の様式に、「判定の置き先と結果の受け渡し」の項(第9項)を足します。準拠テンプレートの様式の第2節は、その部分集合へ直します。判定の置き先で結果責任が決まるとする文は、削ります。

必須欄の対応表は、「結果責任を負う者」の省略の登録を取り消し、標準の第8項と第9項の欄を必須欄に足します。規則データに残っていた「瑕疵担保責任」は、「契約不適合責任」へ直します。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 指示の経路に触れない | 判定を別の組織へ置きながら結果の渡し先を定めないのは、本標準の内側の欠落である。許容を与えた箇所で、外部の制約に触れうることを知らせない形にもなる |
| 判定の結果の宛先を、受注側の席の責任者に固定する | 宛先を固定する理由が、法令の区分にしか無い。法令上の要求事項を、名前を伏せて条項にすることになる。受注側が1名の体制では、席の責任者と担い手が同じ人になり、規範が空回りする。席に組織の所属の属性を足す必要がある |
| 判定の記録を、適否と理由に限る | レビューの指摘が作成の指示に当たるかを、本標準は決めていない。公的な整理も無い |
| 判定の置き先の許容を狭め、G-6 を受注側へ固定する | 発注側が兼務禁止を確認できない形が既定になる。本標準の内側の統制を弱める |
| 法務への確認を要求事項にする | 確かめた記録の中身を、本標準が定められない。欄を埋めたことが、確認の代わりになる |
| 受信箱の優先度を、受託の構成で変える | 区分の基準での評価を、原典から判定できない |
| 「検収」の語を残し、適用範囲の限定だけを書く | 定義の無い語で適用範囲を限ることになる。検収を置かない契約で受託する組織には、行が丸ごと当たらなくなる |
| 契約の類型ごとの読み替えの表を置く | 決定6 のとおり |
| 契約上の確認行為との対応づけを、本標準から外す | ゲートの判定と契約上の確認の時点がずれることへの手当てが無くなる。軸D のほかの「契約に明記する」を残したまま、対応づけだけを外す理由が書けない |
| 準拠テンプレートの第2節だけを直す | 標準の様式に対応する項が無いままになり、次に同じ食い違いが起きても検査で拾えない |
| 準拠テンプレートの第2節を削る | 判定の置き先と、結果を受け取る者の記録の場所が無くなる |

## 影響

- 第8章 軸D に「判定の結果を受け取る者を決める」の節を足し、外部の制約の注記を置いた。表の2行と、その後の段落を改めた。課さないことを、箇条で明記した
- 第1章 1.4 に「契約上の確認行為」を足した。第6章 テンプレ8 に第9項を足し、「合意」を第10項へ繰り下げた。第7項・第8項の番号は変わらない
- 規則データの軸D の注記を、「契約上の確認行為に対応づけるかどうかと、対応づける先を、締結時に決めて記録する」へそろえた。設問は足していない。`contractual` のパラメータは残した
- 準拠テンプレートの AI-SLA 合意確認書は、第2節を改め、知財の表へ「結果責任を負う者」を戻し、「保証の開示と委任の適用」の節を足した。**以前の様式で作った合意確認書は、書き換えない**。次の締結または見直しから、新しい様式を使う
- 必須欄の検査は、12様式・158欄(省略の登録 0欄)になった
- 軸D の「読解を第三者へ委託する」は、「発注側と受注側のどちらでもない組織へ委託する」へ言い換えた。第1章 1.4 の「第三者レビュー」の定義([ADR-0066](/process-compass/adr/0066-shipping-approver-separation-and-development-line/))と食い違わせないためである
- 廃した言い回しを7句、登録した。フェーズ1・2 の調査データが、他のプロセスの実務として記す「検収」と、当時の記述として引く「瑕疵担保責任」は、対象にしていない
- 根拠水準マーク(EV-0108。E1。見直し 2027-04)を、第8章 軸D に付けた。受け取る者と対応づけを記録することが、差し戻しの滞留や手戻りを減らすことを測った資料は、見つかっていない
- 判定の結果を受け取る者と、対応づけの欄は、様式に置いた(IMPL-0121・IMPL-0122)。機械が確かめるのは、欄の存在までである。記入の有無と中身は確かめない
- 外部の制約の注記は、法令の改正と疑義応答集の改訂で古くなる。疑義応答集の第3集は、掲載の URL が変わっており、掲載版に日付が無い。初版は読めていない
- 今回の決定の外に置いたものは、次のとおりである。軸D の表が G-1・G-2・G-5 の置き先を定めていないこと。発注側がリポジトリを持つ形での、指示資産の持ち主。標準に無い節が準拠テンプレートの様式にあることを、検査が見ないこと。会議体が見つけた論点として、後継の Issue へ送る
