## ステータス

採用(2026-10-23)。採用済みの ADR の決定を置き換えません。[ADR-0019](/process-compass/adr/0019-scope-commitment-three-layers/) 決定6 に当たる本文の文の形(2.10.3 の「設けません」)を、決定の趣旨に合わせて直しました。決定5 に当たる 2.10.5 の文は、第1章 1.4 の会議体の定義で読みが閉じるため変えていません。ADR-0019 の本文は変えていません。

## コンテキスト

[#298](https://github.com/Takenori-Kusaka/process-compass/issues/298) は、本標準とスクラムなど既存の反復手法との関係を問う Issue です。派生物(概要記事)が「スクラムとの関係」の節を持っていましたが、正本に無いことは派生物に書けないため、節を削った経緯があります。指摘をそのまま条項にせず、調査2本(内部の言及の全数、外部の規格と手法の書き方)と会議体5名の意見書で扱いました。記録は `research/298-deliberation/`(`decision.md` の M-1〜M-8)にあります。

### 見つかったこと

- 本標準は、既存の反復手法について**由来**(附属書A A.1・A.3、参照モデルの `origin`)だけを書いていた。**関係**(併用・置き換え・対応)の主張も、「主張しない」の表明も無かった。「書かれていない」状態であり、「課さないと決めた」状態ではなかった
- 第1章 1.5 の附属書A の内容欄と、附属書A の説明文は「既存プロセスとの対応」を約束していたが、附属書A にあったのは由来の表だけだった
- #267 への回答(2026-10-08)は、スクラムマスター・完成の定義・プロダクトバックログを「附属書A で対応づける語」と書いた。附属書A にその語は無い。誤りは回答の側である
- 附属書A A.1 は、単一の分析者(West、2011年)の留保(境界を設計しないことが問題)を、「境界を意図的に設計すれば有効な形になります」という十分条件の断定へ書き換えていた。A.3 の「実証済みの部品」も根拠を開示していなかった。附属書A の根拠水準のマークは0件だった
- 第1章 1.4 の「会議体」の定義の「B-1〜B-4」が、閉じた列挙か例示かが文面から決まらなかった。第2章 2.10.3「スコープを定めるための場を別に設けません」と 2.10.4「通知のための定例を設けない」は、主語が無く、第1章 1.7.2(迷う文は要求として読む)によって採用組織の定例を禁じる文として読めた。ADR-0019 が退けたのは本標準が場を新設することで、採用組織の定例ではない
- フェーズ6 の改善サイクルは、本標準が定義しない単位(スプリント)を、振り返りの周期の要求に使っていた
- 外部の規格の多数派は方法中立である。ISO/IEC/IEEE 12207 の 2026 年版は、2017 年版の附属書H(アジャイルへの適用)を廃し、適用範囲の1文(特定のモデル・方法論を求めない)へ寄せた。15288:2023 と 26515 も、本文で手法の名を出さない。併用の有効性を実証した規格は見つかっていない

## 決定

### 1. 本標準は、既存の開発手法との関係を主張しない(M-1・M-2)

第1章 1.2 の表の後に、「本標準は」を主語とする段落を置きました。開発の方式と開発手法の名で適用の対象を限定しないこと、既存の開発手法との併用の可否・有効性・要素の対応・置き換えを主張しないことを書いています。反復の周期・チームの会合の持ち方・事業ステージより短い期間の計画の方法は規定せず、採用組織に委ねます。作業の一覧については、第2章 2.10 が定める事項に限って規定します。作業の一覧の全体を規定しないと書くと、2.10 の要求事項(ADR-0019 決定1・4・5・7)と、フェーズ6 の改善サイクルの「Try を作業バックログへ登録する」が消えて読まれるため、範囲を 2.10 に限って書きました(突合 X-1)。方法中立は適用範囲の事項であるため、新しい節を立てず、適用範囲の節に置きました。第2章 2.2 には、AI協調ループについて同じ範囲を規定しない旨と、この層にも 2.10・第3章 3.12.10・第5章・第6章の規定が掛かることを、所在として書きました。附属書A A.1 の類比を通すと、内側の層が反復手法を置き換えるとも読めたためです。この層の規定を閉じた列挙で書かないのは、列挙から漏れた規定が掛からないと読まれるためです(突合 X-2)。

### 2. 附属書A A.7 に、定めるもの・定めないものの読み分けを置く(M-3・M-4)

附属書A A.7 は、規定の対象(席・判定・記録・停止・会合・周期と計画・AI の自律)ごとに「本標準が定めるもの」と「本標準が定めないもの」の2列で書きます。手法の名の列を持ちません。既存の規定から導ける読みは、所在を引いて説明として書きました。工程ゲートの判定はチームの会合で代わらないこと、チームの会合は会議体ではないこと、停止の申し立てと反復の中止は対象が違うこと、完成の基準の自己確認は G-6・G-7 を兼ねないことです。規範は置きません。

スクラムガイドは、逐語で確かめた接点の3つだけを、版(2020年11月版)と取得日(2026-10-23)を固定して引きます。組織の標準としての完成の定義、スプリントレビューがリリースの関門ではないこと、スクラムの不変性です。これらに EV-0153(E1)を付けました。附属書A の表題と第1章 1.5 の内容欄は、「既存プロセスからの由来と既存の開発手法との関係」へ改めました。

### 3. 由来の記述に根拠水準を開示する(M-5)

附属書A A.1 を、出典の帰属つきの文へ改めました(EV-0151、E0)。A.3 の「実証済みの」を削りました(EV-0152、E0)。第2章 2.10.1 の DSDM の値の注記を、根拠水準のマークの書式へ移しました(EV-0150、E1)。第2章 2.6 の想定する反復周期に、EV-0149(E0)を付けました。参照モデルの `origin`(「スクラムの反復」)は変えていません。由来の事実であり、関係の主張ではないためです。

### 4. 会議体の範囲を定義で閉じ、2.10 の文の形を直す(M-6)

第1章 1.4 の「会議体」を、本標準が定める B-1〜B-4 と、第8章「会議体と体制図の調整」で B-1〜B-4 を既存の場へ対応づけたもの、または設置したものと定義しました。既存の会合へ対応づけた場合、会議体の規定(第3章 3.7.3・3.7.5 ほか)は、対応づけた議題に限って掛かります。チームが自ら開く会合は、対応づけた議題を除き会議体に当たらず、工程ゲートの判定の場でもありません。これで、第3章 3.7.1・3.7.3・3.7.5 と第2章 2.10 の冒頭・2.10.5 の「会議体」は、対応づけた議題の外ではチームの会合を禁じる読みになりません(突合 X-3)。

第2章 2.10.3 を「本標準は、事業ステージのスコープを定めるための場を、ステージ移行ゲート(SG)の判定と別に設けません」へ改めました。2.10.4 は、非同期で通知する規範を保ち、「通知を、定例の開催まで待たせてはならない」へ改めました。ADR-0019 が守りたいのは通知の即時性であり、定例の禁止ではないためです。2.10.2 の禁止(精度を装った見積り手法)は、適用範囲(事業ステージのスコープ3層の規模の合意)を見出しへ併記しました。フェーズ6 の改善サイクルの「スプリントごと」は、「採用組織が定めた周期」へ改め、スクラムガイドの引用は由来の引用として書き分けました。

### 5. 手法の名との名乗りを、適用の表明と適合の主張に数えない(M-7)

他の手法を用いていること、またはその名と組み合わせて名乗ることを、本標準は適用の開始・適用の表明・適合の主張に数えません(第1章 1.2)。附属書H H.8 の「使ってはならない表現」に、「[手法名]と併用できる」「[手法名]互換」「[手法名]準拠のピットイン方式」「[手法名]にゲートを加えているので適合」の行を足しました。「使ってよい表現」には、本標準の適用と手法の使用を別の文で書く行を足しました。派生物の書き手が最初に引くのは H.8 の表で、第1章 1.10.2 から導く読みを書き手に委ねると割れるためです。手法を用いていることの表明は、ADR-0068 の適用の表明でも適合の主張でもありません。名称は内容を保証しません(ADR-0027)。手法の名と組み合わせた名乗りは、ADR-0027 が「AI共創共通フレーム」を退けたのと同じく、権威の借用に当たります。

本文と規定の附属書のうち、手法の固有名を名指して引くのは、根拠水準のマークの補足(第8章 EV-0148)だけです。スクラムガイドの文言の引用は、附属書A(参考)A.7 の接点と、フェーズ6 の改善サイクルの由来の引用に置き、版と取得日を添えます。

附属書H H.8 の「使ってはならない表現」の行は、規定の附属書に足した表現の禁止です。採用組織の対外の表明を縛り、実行主体の挙動を制約しないため、実装マークを付けていません(突合 X-4)。

## 課さないと決めたこと

| 論点 | 課さないこと・採らないこと | 理由 |
| --- | --- | --- |
| M-1 | 手法の名ごとの対応表(スクラム・SAFe・Shape Up などの役割・イベント・作成物と、本標準の席・ゲート・成果物の対応) | 附属書H H.10 の先例(対応表は確かめていない範囲まで覆って見せる)が当たる。本プロジェクト自身の対応づけ(#267 への回答)が誤った。手法の名では agile と traditional を分けられないという調査(IEEE TSE 2021)がある |
| M-1 | 本文の併用の条件(「併用する組織は〜しなければならない」) | 条件を書くと、満たせば併用が成り立つと読まれ、適用の表明と適合の主張の区別(ADR-0068)に当たる。条件の中身(判定の成立・判定会議を開かない・第3章 3.7.5)は既存の規定にあり、2か所で定めることになる |
| M-1 | 「主張しない」の1文だけを置き、説明を添えないこと | #298 の契機は、派生物が正本に無いことを書けないことである。読者の既知に接続する説明が正本に無ければ、派生物は書けないままになる。説明は規範ではないので ADR-0068 に当たらない |
| M-1 | 派生物(概要記事)へ委ねるだけにすること | #298 の契機と矛盾する |
| M-3 | 「併用できる」と書くこと | 併用した案件の記録が本標準に無い(E0) |
| M-4 | スクラム以外の手法(SAFe、Shape Up、カンバン、Disciplined Agile、XP など)を名指しすること | 商標の手法と改訂の速い手法を名指しすると、相手の改訂への追随を負い、相手の公式見解と取り違えられる。逐語で確かめた接点を持たない。名指ししないことは、それらの手法を用いる開発を適用の対象から外すことではない |
| M-5 | 参照モデルの `origin` の「スクラムの反復」を「反復・漸進型の開発」へ改めること | 由来の事実であり、関係の主張ではない。改めると由来の正確さが下がる |
| M-7 | #267 の対応づけ(スクラムマスター・完成の定義・プロダクトバックログ)を本文へ降ろすこと | 対応表を置かないと決めたため。訂正は #267 への訂正のコメントで行い、元のコメントは消さない |

## 影響

- 採用組織は、スクラムなどの反復手法を用いていても、本標準の要求事項の掛かり方を附属書A A.7 で読める。本標準は、その読みが正しいことも、併用が有効であることも主張しない
- 派生物は、第1章 1.2 の方法中立と、A.7 の定める事項・定めない事項を引ける。手法との対応表は、正本に無いため派生物にも書けない
- 第1章 1.4 の会議体の定義により、チームの会合は、第8章で B-1〜B-4 へ対応づけた議題に限って、第3章 3.7.3 の4値の判定と 3.9 の健全性指標の対象になる。対応づけた議題の外では対象にならない
- 準拠テンプレートへ降ろすものは無い。テンプレートにスクラムの語は無く、本件は実行主体の挙動を制約する規定を足していない
- 別 Issue で扱うものは3件ある。1件目は、第1章 1.3・附属書H H.10・EV-0106・ADR-0068 が引く ISO/IEC/IEEE 12207:2017 が、2026 年版の発行で廃止されたことへの追随である。2件目は第2章 2.3「既存の設計審査体系との対応」の注記の中の禁止、3件目は 2.10.2「精度を装った」の曖昧さである
