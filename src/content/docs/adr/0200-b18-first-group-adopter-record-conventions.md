## ステータス

採用(2026-11-18)。[ADR-0175](/process-compass/adr/0175-assign-445-450-undelivered-to-adopter-or-template/)の降ろし方の4区分を前提とし、降ろしたものが採用者に書かせる記録の形を決める。ADR-0175 は置き換えない。

## コンテキスト

- ADR-0175 は降ろし方を 4 区分(機械の検査・様式の欄・手引き・採用者の実装)までしか決めていない。降ろした検査が読む記録の形は決めていない
- 第1群の降ろしは、採用者のリポジトリに書かれる約束を伴う。安全関連部の範囲の宣言、台帳の行の見分け方、営業日の数え方、観測の workflow の位置づけである
- どれもあとから変えると、採用者の記録の読み方が変わる。そのため、実装の前に ADR として固定する

## 決定

1. 安全関連部の範囲は、構成の `riskFloor.rules[]` に `floor: "R1"` と `safetyRelated: true` を持つ規則として宣言する。新しい構成のキーは作らない。D-0 節16 の F.2 の Q1 が「はい」で、宣言が無い構成は、登録した変更種別を止める(IMPL-0594)
2. ファストトラック(7.4)の行と、コア機能の理解の保持者が 1 名以下の是正(3.4.3)の行は、技術負債台帳の既存の欄の先頭の語で見分ける。ファストトラックの行は区分「例外」で、内容の先頭を `ファストトラック(短縮: <ゲート>)` とする。是正の行は区分「負債」で、対象を `コア理解: <コア機能の名前>` とする。区分は足さず、欄も足さない
3. 営業日は土日を除いて数える。祝日は任意のファイル `.github/business-holidays.txt`(1行に YYYY-MM-DD)から読む。ファイルが無いときは土日だけを除き、出力に「祝日を数えていない」と必ず書く。関数は時計を読まず、日付を引数で受ける
4. 新しく足す観測と通知の workflow(`review-queue-control.yml`・`flow-observation.yml`・`pre-review.yml`)は、必須ステータスチェックにしない。必須にするかは、IMPL-0214 と同じ重の審議に残す
5. 課さないと決めたこと。(a) 印の付け忘れを機械で検出すること。印の無い行は、機械が当該の種類の行として見分けられない。(b) 安全関連部の宣言と F.7 の記録の「安全関連部の切り分け」の文が一致するかの機械の照合。一致は G-7 の出荷判定者が確かめる
6. CODEOWNERS の所有者は、名簿(`people[].accounts`)の人の個人のログイン名で書く。チームを書くときは個人と併記する。全行がチームだけの行、名簿に対応づかない個人、どの行の型にも当たらない変更は、G-5 が失敗させる。読むのは基底ブランチの CODEOWNERS で、GitHub と同じ順(`.github/CODEOWNERS`・`CODEOWNERS`・`docs/CODEOWNERS`)に探し、最初に見つけた1つを検査する。3か所のどれにも無い構成だけを「所有者を定義していない」として失敗にする。チームの構成員が誰かは確かめない(IMPL-0211)

## 課さないと決めたこと

決定5 の 2 点を課さない。印の無い行を内容の自由な文から探す検査は、意味を読む検査になり、機械で閉じない。宣言と記録の文の照合も同じです。どちらも検査の出力と IMPL マークの note で開示する。

## 検討した選択肢(採らない)

| 案 | 採らなかった理由 |
| --- | --- |
| 構成に `autonomy.safetyPaths` を新設する | 区分の下限の規則と正本が 2 つになり、`config.mjs` の検査を要する |
| F.7 の記録の範囲の欄を glob の書式に改める | 様式に細かい定義が増え、記録の文と機械の値が 1 つの欄に混ざる |
| F.2 の Q1 が「はい」の案件を全体で L1 にする | 切り分けを定めずに全体を安全関連として扱うと、AI の活用が全面的に停止すると本文が戒めている |
| 区分「ファストトラック」を新設する | 集約の区分の読み(`r.kind === '例外'` の箇所)が変わる |
| 台帳に是正の行の欄を足す | 構成の `LEDGER_COLUMNS` が変わり、採用者の既存の台帳が読めなくなる |
| 観測の workflow を必須チェックにする | 採用者の既定の必須チェックを増やす新しい義務であり、重の審議に属する |

## 影響

- 採用者は、F.2 の Q1 が「はい」の案件で、安全関連部の規則を構成に宣言する。宣言しないと、登録した変更種別が止まる
- 採用者は、ファストトラックの行とコア理解の是正の行を、決まった語で書く。書かないと機械が見分けられず、抜け道になる。この点を検査の出力で開示する
- 祝日を採用者が書かない間、営業日の数えは祝日を除かない。出力の開示で読み手に伝える
- 採用者は、CODEOWNERS の各行に個人のログイン名を併記する。チームだけの行は G-5 で落ちる。置き字 `@OWNER` が落ちるのは従来どおり(契約検査)で、新しく落ちるのは、チームだけの行、名簿へ対応づかない個人、型が覆わない変更の3つである。準拠テンプレートに CHANGELOG は無い。既存の採用者が読むのは、README の「失敗したとき」の表と取り込みの差分である
- 新しい workflow が失敗や遅延をしても、マージは止まらない。観測と通知が必須でないことの代償である

:::caution[暫定 EV-0326 / 見直し 2027-11]
**対象**: 決定1〜3 の記録の約束(宣言の置き場・印の語・営業日の数え方)。採用者が実際にこの書式で書けること、書き漏らしが抜け道にならないことは測られていない。
**根拠の水準**: E0(なし)。
**差し替え条件**: 採用者の台帳で、印の無いファストトラックの行が見つかった件数と、宣言を欠いて変更種別が止まった件数。
:::
