## ステータス

採用(2026-08-05)

## コンテキスト

フェーズ4は、設計思想・日々の作業テンプレート・実施ガイドが同一階層に並んでおり、粒度が揃っていなかった。JTC の品質保証部門やプロセス監査部門へそのまま提出できる標準としては、次の点が不足していた。

- 適用範囲・引用規格・用語の定義という、規程の導入部が存在しない
- 思想や検討経緯が要求事項と同じ本文に混在しており、監査時に「何が守るべき規定か」を特定できない
- 独立レビュー実施ガイドや記法ガイドが、章と同じ階層に並んでおり粒度が不整合
- AI 統制の根拠規格(ISO/IEC 42001 等)への参照がない

加えて、今後フェーズ4へ多数の内容が追加される見込みであった。追加先の器が定まっていないと、章の重複と用語の分裂が発生する。

## 決定

1. **本文8章＋附属書4編の構成とする**。本文は要求事項のみを規定し、附属書は背景・記法・様式を提供する
   - 第1章 総則 / 第2章 ライフサイクルとマイルストーン / 第3章 実施体制・ロール・会議体 / 第4章 ゲートと判定基準 / 第5章 人間とAIの役割境界 / 第6章 成果物・記録・トレーサビリティ / 第7章 例外・エスカレーション / 第8章 テーラリング
   - 附属書A 設計の背景と由来 / 附属書B EARS 記法 / 附属書C 独立レビュー実施ガイド / 附属書D 導入提案書の様式
2. **導入3点セット(適用範囲・引用規格・用語の定義)を第1章に置く**。ISO 9001 / JIS Q 9001 の箇条構成に合わせ、監査担当者が認識できる形式とする
3. **各章は「達成すべき成果(Outcomes)」から書く**。ISO/IEC/IEEE 12207:2017 が採用した成果ベースのプロセス定義に倣い、手順は成果の下位に置く
4. **AI の統制を独立章(第5章)とする**。既存 QMS に存在しない概念であり、既存章へ混ぜると監査時の追跡が困難になる
5. **テーラリングは本文の章(第8章)に置き、附属書へ落とさない**。附属書化すると「適用しなくてよい参考情報」と誤読され、標準が形骸化する
6. **既存スラッグを変更しない**。サイトは公開済みであり、外部リンクを維持する。章番号は表題と `sidebar.order` で表現する
7. **記述のトーンを規定文に統一する**。要求事項は「〜を規定する」「〜しなければならない」「〜してはならない」で記述し、組織内の口頭文脈に依存する表現を用いない
8. **AI 能力に関する記述には妥当な時点(YYYY-MM-DD)を併記する**

## 検討した選択肢

- **既存構成のまま加筆する** — 追加30件の内容が既存9ページへ分散し、章の重複と用語の分裂が確実に発生する。監査提出可能な体裁にもならない
- **スラッグも章番号へ変更する(`ch1-general` 等)** — 章立ての意図は明確になるが、公開済み URL がすべて壊れる。章の増減のたびにスラッグを振り直す必要も生じる
- **思想を削除する** — 設計の根拠が失われ、後任者が判断の経緯を追えなくなる。削除ではなく附属書への分離を選択した
- **ISO/IEC 12207 の4プロセス群をそのまま章立てにする** — 規格との対応は明確になるが、日本企業の QMS 監査担当者にとっては ISO 9001 箇条構成のほうが認識しやすい。両者を折衷し、導入部は ISO 9001、各章内部は 12207 の成果ベース記述とした

## 影響

- 以後の成果物は、上記8章のいずれかへ追加する。新規ページの追加は原則として行わず、章内の節として追加する
- 章をまたぐ用語は第1章「用語の定義」へ集約する。用語の最終確定は、全章の整備を終えた時点で行う
- `sidebar.order` は本文を 1〜8、附属書を 20〜23 とする。附属書の追加余地を確保するため 9〜19 を空ける
- 附属書A は要求事項を含まないため、監査提出時に除外できる
- 調査根拠は `research/phase4-standard/097-qms-chapter-structure.md` に記録した
