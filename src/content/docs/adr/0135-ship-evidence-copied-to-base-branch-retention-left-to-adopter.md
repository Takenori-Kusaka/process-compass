## コンテキスト

[#333](https://github.com/Takenori-Kusaka/process-compass/issues/333) は、出荷の証跡の保管の設計を扱いました。審議は軽(起案と反対の2委員)で行い、記録は `research/333-deliberation/` にあります。

- 準拠テンプレートの `ship-evidence.yml` は、証跡の一式を CI の成果物にだけ置き、保持の日数を指定していなかった。成果物の既定の保持は 90 日で、過ぎれば消える(出典は[ci-gates](/process-compass/phase5-implementation/ci-gates/)「証跡の保管と CI 基盤の保持期間」)
- 前回の出荷の証跡の取り込みも成果物だけを見ていたため、90 日を過ぎると「前回なし」になった
- 集約は、保持を過ぎて結果を読めない PR の G-5 を、「必須チェックを経ずにマージされた可能性」としてだけ出していた
- カバレッジの結果が、出荷の証跡へ取り込まれていなかった。取り込んでも、既定ブランチへの push の gate-g5 は起点を push の直前のコミットにするため、値が出荷の範囲の被覆に読めてしまう
- 検証方法と結果の節は、マージの後の編集も「あり」と数えていた

## 決定

### 1. 一式は基底ブランチへ写し、表示は「写した」までにする

証跡の一式(`evidence.json`・外へ渡す開示・取り込んだ入力の JSON)と digest の一覧(`manifest.json`)を、出荷のブランチ経由で基底ブランチの `docs/evidence/<日付>-<範囲>/` へ写します。既に品質レポートと記録用ブランチの先頭が同じ経路で基底ブランチへ入るため、新しい書き込みの主体を足しません。署名を課す構成の経路(`createCommitOnBranch`)も同じです。出荷の PR の verify ジョブが、追加以外の変更を失敗にし、digest の一覧との一致を検査します。

成果物 `ship-evidence` には `retention-days: 90` を明示し、一時置きと注記します。前回の証跡は、成果物を取れないとき、基底ブランチの写しのうち記録の時刻が最も新しいものから読みます。

**表示は「写した」までです。「保管した」とは書きません**。コミットに保持期限の規定が無いことは、公式の記述が無いことからの読みです。バイパス権限者には削除と書き換えの禁止が効きません。写しの存在・digest の一致・追加だけであることは機械で閉じ(IMPL-0521)、書き込みの権限を持つ者の変更は防がず、履歴に残るだけです。

### 2. 保管期間の充足は採用者に委ねる(IMPL-0243 を `plan=adopter` にする)

標準の規定「判定が指す記録は、組織が定める保管期間のあいだ到達できなければならない」は、課したままにします。準拠テンプレートは期間の値を知らず、リポジトリの寿命(削除・移管)も決められません。そのため、期間の充足を実装しないと決めました。IMPL-0243 は `undelivered` のまま `plan=adopter` に改めます。「予定」の表示が「採用者が実装する」へ恒久に変わります。新しい義務ではありません(第4章が既に課している)。

採用者に求めることは次の3点です。いずれも既存の規定の内側です。

- 保管期間の値を、自組織の文書管理規程で定める
- 保管の対象に証跡の一式(digest の一覧に載るもの)を含める
- リポジトリの外の保管の要否を決め、要るときは digest の一覧を使って引き渡す

第4章「判定の成立」は `impl-no-adopter.yaml` の節に当たりません。

### 3. 読めない G-5 は、マージの時点の写しで書き分け、欠落のまま数える(IMPL-0244)

record-copy は、マージの時点の head の gate-g5 の check run の結論を、写しの欄 `checks.gate_g5` に足します。読めなくても写しの手順を失敗させません。集約は、ホスティングから G-5 を読めないとき、次の3通りに文を書き分けます。

- 写しに結論がある: 保持切れの可能性
- 写しにも check run が無い: 必須チェックを経ていない可能性
- 写しの欄が無い、または取り出しで読めなかった: 区別できない旨

どの場合も欠落のまま数えます。**写しの値で G-5 の充足に数えません**。写しはホスティングと照合できないためで、ADR-0109 決定2 と同じ向きです。日付と保持日数の比較では分けません。保持日数はリポジトリ・組織・企業の3層の設定の結果で、集約のトークンで読めることを確かめていないためです。写しを出荷の時点でなくマージの時点で取るのは、マージから出荷までが保持期間より長い PR を救うためです。

### 4. カバレッジは同じ実行から取り込み、開示に起点と限定を足す

`license-scan` と同じ gate-g5 の実行から `coverage-result` と `dependency-diff` を取ります。実行の headSha が対象のコミットと一致するときだけ取り込み、一致しなければ何も取り込まず警告を出します。取り込み元は digest の一覧の `inputs` に残します。

範囲が変更のときの開示には、起点と「取り込んだ1回の実行が測った差分の値で、出荷の範囲の全体の被覆ではない」を同じ行に出します。出荷の範囲で測り直す実装は本件に含めません。

### 5. 検証の文の不一致は所見にする

集約は、写しがあり、ホスティングの本文も読めた PR について、「検証方法と結果」の節をマージの時点の写しと今の本文で比べます。不一致は所見で、欠落にも判定の条件にもしません。誤字の訂正でも不一致になるためです。ハッシュは足しません。写しが本文の全文を持つためです。マージより前の編集、規則のバイパスによる写しの書き換え、内容の妥当性は見ません。限定は所見の文に同じ行で書きます。標準の条項にせず、実装マークも付けません。

## 採用者に委ねる規定

| マーク | 規定 | 採用者に委ねる理由 | 採用者に求めること |
| --- | --- | --- | --- |
| IMPL-0243 | 判定が指す記録を、組織が定める保管期間のあいだ到達できる置き場に残すこと(期間の値、期間の充足、リポジトリの削除・移管の後の到達、リポジトリの外の保管) | 期間の値は組織の文書管理規程が定め、リポジトリの寿命も組織が決める。準拠テンプレートが実装できる余地が無い | 上の決定2 の3点。確かめる者は内部監査の担当(判定記録と証跡の指す先に到達できるかの抜き取り) |

## 課さないと決めたこと

「書かれていない」と「課さないと決めた」を区別するために、次を記録します。

- 構成へ保持日数の入力を足すこと。採用者の入力が増え、宣言が実態と食い違えば文言が誤る
- 外部の保管への引き渡しを必須にすること、引き渡さない旨の記録を課すこと。新しい義務で、重の審議に当たる
- 保持の設定を API で読むこと。権限と提供範囲を確かめていない
- 「保管した」「保管の置き場」と表示すること
- 事象3 の取り込みで、出荷の範囲の全体の被覆を測り直すこと

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| IMPL-0243 を範囲を絞って `delivered` にする | 規約は、規定の一部が降りていないとき `undelivered` とし、無い部分を note に書くと定める。期間の充足まで降りたと読める |
| IMPL-0243 を `plan=scheduled` のまま残す | 降ろす予定が無い規定を「予定」と出し続ける。表示が実態と食い違う |
| 期間の充足を、新しい manual のマークへ分ける | 1つの規定を2つのマークへ割る形になる。1文目は IMPL-0243 がそのまま負う |
| 記録用ブランチ `records/ship/` へ ship-evidence が直接追記する | 記録用ブランチへ書く主体が増え、署名の経路を二重に持つ。記録用ブランチの規則は基底ブランチより弱い |
| 日付と保持日数の比較で「保持切れ」と出す | 期間の外は必要条件にすぎない。実際の設定を知らなければ言えない |
| 写しの G-5 の結論で欠落を消す | 照合できない写しで充足を数えない。強制層の縮小に当たる |
| `retention-days` を「上限まで」と書き、成果物だけで `delivered` にする | 個別指定の上限は未確認。本文の2文目に反する |
| リリースの資産、attestation を既定の置き場・保管の根拠にする | 出荷の単位以外を覆えない。到達性を解かない。保持期間を確かめられなかった |
| 「検証方法と結果」の有無を、写しの本文で数える | マージの後の書き足しが欠落に変わる。判定の条件の変更で、重の審議に当たる。所見の件数を見てから別に審議する |
| 検証の文の不一致を欠落・失敗にする | 誤字の訂正でも不一致になる。標準は判定の条件にしていない |
| 検証の文のハッシュを写しへ足す | 写しは本文の全文を既に持つ |
| 事象4 を保留・却下する | 前提(写しの書き換えを検出できない)が、履歴の走査により当たらない |
| 何もしない | 証跡の指す先が現に消える |

## 見直しの契機

- EV-0261 の見直し時期(2027-04)の到来
- 通しの実行用の一時リポジトリでの1回の出荷で、一式が基底ブランチへ入り、verify が通ったとき
- 保持を 1 日に設定したリポジトリで、保持切れの PR の集約の出力が得られたとき
- 「検証方法と結果」の不一致の所見の件数が出たとき(有無を写しの本文で数えるかの重の審議)

## 影響

- 準拠テンプレートの出荷で、`docs/evidence/` に証跡の一式の置き場が増える。出荷の PR の差分が増え、verify が置き場ごとに digest の一覧を検査する
- IMPL-0243 は台帳に「採用者が実装する」と出続ける。IMPL-0521・IMPL-0244 は `delivered` で、機械が確かめる範囲は存在・digest の一致・追加だけ、写しの書き分けまでである
- record-copy の権限に読み取りだけの `checks` が増える
- 欄を足す前にマージした PR は、保持切れと未経由を区別できない
- 実機の通しは未確認で、EV-0261 で開示する
