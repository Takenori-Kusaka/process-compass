## コンテキスト

- [#466](https://github.com/Takenori-Kusaka/process-compass/issues/466): 人がボトルネックになる既定の構成への所有者の懸念。標準と準拠テンプレートは、E0(実証なし)の値を既定として置いていた(最小標本数 30・観測の窓 2 か月・同時保有 3 件・抜き取り 5 件など)。既定は、置いた時点で採用者の既定になる
- 所有者の決定 1(2026-11-27。問C。原文):

> 各社の過去トラやプロダクト特性に合わせて定義することを推奨としつつ、その定義がなければそのまま進め警告を出すだけにするのが現実的では？事業フェーズやプロダクト特性、そのシステムアーキテクチャや利用のされかた、扱うデータの種類に検知するべき値はかなり変わりそうです

- 同じ向きの決定(O-5。根拠 E0 の既定値): (b) 既定値を置かない。採用者が決める。議長の推奨 (a) とは違う
- 所有者の決定 2(2026-11-27。問3。事故の後の扱い): (Y) 警告だけにする。自動では戻さず、資料と開示に出し、戻すかは各社が決める。議長の推奨と 5 委員の一致((X) 規則として残す)とは違う。理由の原文:

> 再発防止策はその時のaiや周辺ツールに依存します。プロセスからは警告に留めアクションを促すまでのやくわりであるべきです

- 考え方: 標準の役割は、事故の起きた所を見えるようにして警告し、行動を促すまでである。決まった対処を固定しない。同じ向きの考えが当たりうる他の箇所は、本件では変えない(下の「課さないと決めたこと」)
- 所有者の確認(2026-11-27): 警告だけにするのは (a) 原因がまだ分からない事故での停止と、事故の台帳が無いときの停止も含める。(b) 安全や規制に関わる案件だけは、今のまま自動で戻す。線は標準の既存の区分で決まる条件とし、新しい区分を作らない
- 議長の受け止め: 議長の推奨は、問C・O-5・問3 のいずれも採られなかった。どれも「緩めて安全だという実測が無い」ことを理由に現行を残す側へ倒した点である。以後の案は「残す」を既定の答えにせず、信頼性が落ちる具体の場面を特定し、そこだけを条件によって塞ぐ軸を採った

## 決定

### 1. 検知・知らせ・抜き取りの値は、採用者が自社の事情に合わせて定める。標準は一律の既定値も参考の値も置かない

- 対象の値は 5 つ。最小標本数、観測の窓、同時保有の上限、事後の抜き取りの件数、手戻り率の基準値
- 採用者は、自社の過去のトラブルとプロダクトの特性に合わせて値を定め、記録することが推奨される。値は事業ステージ・プロダクトの特性・アーキテクチャ・使われ方・扱うデータの種類で変わる
- 準拠テンプレートは例の値も置かない。例が既定として効き、本文と実行層が食い違う
- 構成に書く値は、値・記録した日・決定した者・理由を残す(履歴つき)。緩い値は、効く所の表示と保証の開示にそのまま出す
- 観測の窓の下限 2 か月(検証)は残す。窓を短くしすぎると検知が鳴らない向きの制約で、採用者が決める値そのものではない。下限 1 への緩和は緩める向きで、別の決定とする

| 値 | 構成の欄 | 定めが無いとき |
| --- | --- | --- |
| 最小標本数 | `detection.minSample` | 差し戻し率 0% の継続と手戻り率の検知は働かない。止めない |
| 観測の窓 | `observationWindow` | 同上。表示は名目の 2 か月 |
| 同時保有の上限 | `reviewQueue.loadLimit` | 上限の知らせを出さない。期限超過の催促は出る |
| 事後の抜き取りの件数 | `delegation.sampling.perMonth` | 月の定めは当月の全件 |
| 手戻り率の基準値 | `reworkBaseline` | 手戻り率の検知は働かない。止めずに当月の全件を事後に確かめる |

- 連続運用 3 か月(自律レベルの引き上げ)は、組織が定める値のまま。参考の値を置かない。定めが無ければ引き上げの条件を満たさず、L1 のまま作業は続く
- 評価の周期は値ではなく手続の定めで、対象の外である
- 観測の窓の二重(第4章の四半期と 5.4.6 の 2 か月)は、第4章の側を 5.4.6 の窓を引く形に直して一本にする

### 2. 定めが無いときは、止めずに進め、働いていない検知の名を出す

- 値の定めが無いことを理由に、委任・出荷・引き上げを止めない。ADR-0158 決定2(基準値の未設定で止める)を置き換える
- 次の 3 か所に同じ文で、定めていない値の件数と、働いていない検知の名を出す
  - `/pit` の注記
  - 保証の開示の項目3 と期間の開示(組織の外へ渡す形は件数と値の名だけ)
  - 出荷の証跡の集約の宣言の表(欠落に数えない)
- 期間で消さない(ADR-0028)。値を定めた時点で消える
- 委任した種類は、定めが無い間、当月の全件を事後に確かめる。確認が足りない月の止める規則は 0272 決定2 が持つ

### 3. 全件の事後の確認は、形骸化の検知の代わりにならない。この限界を開示する

- 全件を事後に確かめる人は、形骸化の当事者でありうる。0% の継続の検知(確認の形骸化)も、手戻り率の検知も、値が無い間は働かない
- 同時保有の上限(V8)と、事故でない第2区分の 2 期連続の停止の値(V10)は、定めが無い側に代わりの行為が無い。書かないほうが得なままで、「働いていない検知」の開示だけが閉じ手になる。ADR-0158 の却下理由(基準値を書かないことが最も得になる)は、V4・V7・V9・手戻り率の基準値では当月の全件の確認が付くので逆転するが、V8・V10 には当たり続ける

### 4. 第1章 1.7.7 は、型を足さずに書き換える

- 第2箇条から、検知・知らせ・抜き取りを起動する値を外す。これらを「組織が定める値」とし、参考の値を置かない
- 該当の条項の満たし方は選択の形にする。値を定めて記録する、**または**、定めていない値の一覧と働いていない検知の名を、出荷の証跡の集約と保証の開示に出す。どちらも無ければ満たさない。集約が自動で出すので、人の記入は増えない
- 第3箇条(記録の無い値はテーラリングの宣言の欠落)に「検知の値を除く。その値は一覧に出す」を足す
- 対象の値を `src/data/` に列挙し、例外がそれ以外の値(権限の境界・受容の基準)へ及ばないことを検査する(決定可能)。誤読で権限の値が緩むことを、この検査で閉じる
- 型を足さない理由: 細かい定義を増やさない方針。ADR-0097 が採らなかった「4 型」の議論を再び開かない

### 5. 「準拠」の主張との関係

- 値を決めていない採用者も、準拠と言える。満たしたことになるのは、代わりの行為の実施と、定めていない値・働いていない検知の開示までである
- 適合の主張の併記(1.10.2)に「定めていない検知の値の件数と、働いていない検知の名」を足す。1.9 の主張しないことに「値を定めていない範囲で、確認の形骸化・手戻りの検知が働いていると述べない」を足す。附属書H H.8 の文の型にも同じ条件を足す

### 6. `/process-init` は、値を対話で聞く。例は既定ではない

- 委任を有効にする対話(0272 決定1)の中で、5 つの値を聞く。決め方の手引きは例であって既定値ではない。採るかは利用者に聞く
- 入口は `/process-change` の種別 `settings`。AI の名義は値の記録を拒む

### 7. 一般の案件では、AI が原因の重大な事故の後に、自動で引き下げず、警告に留める

置き換える定めは次の 3 つである(5.4.6 とその周り)。

1. AI が原因と確かめた重大な事故(Sev1・Sev2)で、該当範囲を 1 段階引き下げる定め(5.4.6 の表 1 行目と停止の表 1 行目)
2. 原因がまだ分からない重大な事故で、原因が分かるまで登録した種別を止める定め
3. 事故の台帳が無いときに、AI に任せる扱いを止める定め

- 措置は「該当範囲を示して警告する。自動では引き下げない」へ改める
- 事故: 欠陥の台帳の行のうち、重大度が Sev1・Sev2、検出の時点が「運用」か空欄、AI 起因が「あり」か「特定できない」か空欄、状態が「未解決」のもの。件数の基準を持たない。1 行あれば出る
- 数えるもの(機械。人の記入なし): 発生日より後に既定ブランチへ入った変更のうち、その所に触れ、取り込む前に独立の人の承認を経ていない変更の件数
- 警告の文の骨子: 「AI が原因の重大な事故(ID・重大度・発生日・AI 起因)の後も、取り込む前に人が読んでいない変更が N 件入っている。取り込む前に読む形へ戻すかは組織が決める。戻し方: 委任の範囲を狭める・協働へ下げる・保護するパスに足す」。原因を特定できないときは「特定できていない」、台帳が無いときは「事故の警告が働いていない」と出す
- 出す所: `/pit`、出荷の証跡の集約の宣言の表(欠落に数えず、G-7 を落とさない)、保証の開示の項目3 と期間の開示(組織の外へは件数と事故の ID だけ)、委任の判定の注記(該当の判定は変えない)。失敗にしない
- 消える時: 行の状態が「解決済み」になったとき。AI 起因が「なし」と確かめられたときも消える
- 戻すと決めたときの経路は既存のまま。委任の範囲を狭める・協働へ下げる向きは、厳しくする向きなので検知した時点で適用し、判定を待たない(5.5.7、ADR-0054 決定10)。新しい記入・欄・様式は足さない
- 事故の件数は、委任の種類の範囲の全体で数える。台帳の「原因の変更」のパスは読まない。警告なので、広く出る側に倒れても止まらない。範囲が広く出ることを、警告の文と本文に書く
- 5.4.6 の冒頭の段落に、この行を警告とし、自動の引き下げから外したことと理由を明記する。「書かれていない」と読まれないためである

### 8. 安全や規制に関わる案件は、現行のまま自動で戻す・止める

- 線: 案件の安全重要度が CL1 以上である、または規制業に該当する。第5章 5.5.4 の委任の適用の表の行と同じ条件である。新しい区分は作らない。案件ごとに決まり、構成(`process.config.json`)から機械が読める。安全重要度が未記入のときは、線の内側として扱う
- 線の内側では、決定7 の 3 つとも現行のまま(自動で戻す・止める)
- 3 つに同じ線を当てる理由: 1 だけを現行のままにして 2・3 を警告にすると、安全の案件の中で、確かめた事故より原因の分からない事故のほうが軽い扱いになる。既存の定めは、この線の内側で緩める決定を当てない(5.5.4 は委任を適用しない)。同じ線で揃える
- 5.4.6 の表は、行を増やさず、該当の行の中に適用の範囲を書く(適用範囲を規範と別の段落へ置かない)

### 9. 値の定めの有無は、安全や規制の線の外でも内でも、止める理由にしない

- 手戻り率の基準値の未設定で止める定めは、全案件(CL1 以上・規制業を含む)で外す。線(決定8)は、事故の後の扱いについて所有者が引いたもので、値の扱いには引いていない
- 値が未定義の間は、働いていない検知の名が出荷判定の資料と開示に出る。線の内側で値を必須にする形は、所有者の回答に無いので足さない

## 課さないと決めたこと

「書かれていない」と区別します。

| 論点 | 課さないこと | 理由 |
| --- | --- | --- |
| 値 | 最小標本数・窓・上限・件数・基準値の標準の既定値と参考の値 | 値は採用者の事情で変わる。既定値が全採用者の既定になる |
| 値 | 最小標本数などの下限(下限が既定値と同じ働きをする) | 下限の値を支える実証が無い |
| 事故の後 | 事故の件数・期間の値で人の確認へ戻す規則 | 所有者の決定。対処の固定そのものを標準の役割の外とした |
| 事故の後 | 警告に閾値・期限を置いて止める形 | 同上 |
| 事故の後 | 警告を見た採用者に「戻さない」の記名を求める形 | 人の新しい記入。所有者の軸に反する |
| 事故の後 | 事故の原因の変更が触れたパスを、取り込む前に読む範囲へ入れる規則 | 同上(下の (X)) |
| 他の自動の措置 | 差し戻し率 0% の継続・手戻り率・理解保持者数・事後の抜き取りの違反・担い手の識別の変更・提供者の障害・承認権限の一時制限・自己修正ループの停止条件を、警告に改めること | 範囲は事故の後の定めだけ。理由が違う(5.4.6 冒頭の「監督の劣化は静かに進み、申告されない」)ので、理由ごとに審議する。別の Issue(#467 のコメント)に一覧を残した |
| 引き上げ | 5.4.5 条件4(事象 0 件)・L1 の範囲の数え直し・検知の入力の台帳に触れる変更を委任に含めない定め | 現行のまま。警告の入力を、委任された変更が書き換えられないようにする |

### 採らなかった案 (X): 事故の後の規則として残す

- 内容: 事故の原因の変更が触れた所は、事故が解決するまで、取り込む前に人が読む形へ自動で戻る。件数の基準を持たない。1 件記録されれば戻る
- 出所と賛否: 3 版 §8 問3。**議長の推奨。5 委員一致で賛成**
- 採らない理由: 所有者の決定(上の原文)。失うもの(誤発火の間の待ち)は小さいと議長は見たが、所有者は対処の固定そのものを標準の役割の外とした
- 5 委員の反対意見の要旨(3 版の段階。所有者の理由の原文を見ていない。互いを読まずに書かれた):
  - 起案(`council3-01-drafter.md` 86): ADR の原則(5.4.6 の非対称)の変更で重の審議が要る。事故の後に同じ種類が確認されないまま続く
  - 現場(`council3-02-practitioner.md` 39・99): 警告は 2〜3 週間で壁紙になり、誰も止めない
  - 品質監査(`council3-03-qa-audit.md` 37・87): 事故の後の説明(なぜ止めなかったか)が立たない
  - 規格(`council3-04-standards.md` 33・97): ADR-0081 N-2(検知して人へ渡す区分を作らない)を覆し、非対称を壊す
  - 弁護(`council3-05-advocate.md` 33・70): 非対称を壊し、同じ原因の事故が再発する。失うのは利用者
- 議長の受け止め: 「壁紙」は、件数の変化の強調と出荷のたびの判定者の資料への掲載で一部だけ受ける。閉じない。議長は、AI 起因の Sev1・Sev2 は事後検証で台帳に記録される事実で、静かに進む劣化ではないと整理したが、5 委員は「非対称を壊す」と評した。この行について原則を置き換えたことは、5.4.6 の冒頭に明記する

## 影響

- 実装は準拠テンプレートの次の所にある
  - `scripts/gate/detection-values.mjs`: 値の読み取り・一覧・検査
  - `scripts/gate/autonomy.mjs`: 事故の後の分岐(一般は警告・線の内側は現行どおり停止)
  - `/process-init` の手順 6b と `/process-change` の `settings`
- 準拠テンプレートの文には、条項(章・節)だけを引き、ADR 番号を足していない
- 採用者への影響: 値を定めなくても止まらない。定めない間は、検知が働いていないことが出荷判定の資料と開示に毎回出る。事故が起きても、一般の案件では自動で人の確認へ戻らない。戻すかは各社が決める
- 失うもの:
  - 事故の後も、同じ原因の変更が人に読まれないまま取り込まれ続けうる。失うのは利用者(同じ原因の再発)と、採用者の品質責任者(事故の後に「なぜ止めなかったか」を説明する者)である
  - 本標準に従ったことを、事故の後に同じ所の確認を強めた根拠として示せない。戻すかの判断と記録は採用者の責任である。本標準が警告に留めるのは、再発を防ぐ手立てが、そのときの AI と周辺の道具によって変わるためである
- 残る手当て(既存): 出荷の前の全件の確認、G-7 基準2(未解決の欠陥)、形骸化の検知、5.4.5 条件4(事故の後は引き上げない)。委任(R3 の登録した種類)では、事後の抜き取りだけが人の目になる
- 警告の保証の開示の骨子: 「AI が原因の重大な事故の後に、自動で人の確認へ戻す仕組みを持たない。事故 N 件の後、その所に人の事前の確認を経ずに入った変更 M 件」
- 実装していない所(実装マークは undelivered で表示する)
  - `/pit` の件数が変わったときだけの強調
  - 期間の開示に、解決済みの事故の発生日から解決の日までの件数を残す処理
  - 台帳の「原因の変更」のパスで数えること
  - 委任の PR の検査(G-5)の出力へ「その所に触れる PR」の 1 行を出すこと
- 未確認: `/process-change` の `settings` の書き込みを通しで動かしていない。`delegation.yml` 側の警告の出力と、集約の宣言の表の行の見え方を、実機で見ていない
- 本文の側の食い違い: 本文の 5.4.6 と停止の表、1.7.7、1.10.2、1.9、H.8 は、本 ADR の決定へ書き換える。EV-0154 は対象を「5.4.5 条件4 の 0 件と、警告を出す 1 件」へ書き直す(識別子は再利用しない)
- 根拠水準: 以下のマークで開示する

:::caution[暫定 EV-0376 / 見直し 2027-05]
**対象**: 検知・知らせ・抜き取りの値の既定を置かず、定めが無ければ止めずに進めて、働いていない検知の名を開示する形が、既定値を置く形より信頼性を落とさないという判断。
**根拠の水準**: E0(なし)。
**差し替え条件**: 採用組織で、値を定めた組織と定めない組織の、検知の働きと欠陥の件数の比較。

所有者の決定です。緩めて安全だという実測は無く、公開の実務でも同型の例は見つかっていません。同時保有の上限と第2区分の 2 期連続の停止の値は、定めが無い側に代わりの行為が無く、書かないほうが得なままです。
:::

:::caution[暫定 EV-0377 / 見直し 2027-05]
**対象**: 値の定めが無い間、当月の全件を事後に確かめれば、検知の働かない期間の統制として足りるという判断。
**根拠の水準**: E0(なし)。
**差し替え条件**: 全件の事後の確認の実施の記録と、その間に起きた欠陥の件数の観測。

確かめる人が形骸化の当事者でありうるので、全件の事後の確認は形骸化の検知の代わりにはなりません。この限界は 1.9 の主張しないことに書きます。
:::

:::caution[暫定 EV-0378 / 見直し 2027-05]
**対象**: AI が原因の重大な事故(Sev1・Sev2)の後を、警告に留め、自動では取り込む前の確認へ戻さない判断(一般の案件)。
**根拠の水準**: E0(なし)。
**差し替え条件**: 採用組織で、警告の後に同じ所で同じ原因の Sev1・Sev2 が再び起きた件数と、警告を受けて戻した件数・戻さなかった件数の観測。

所有者の決定です。議長の推奨と 5 委員の一致は、自動で戻す案でした。事故の後に自動で人の確認へ戻す型の公開の実務も、調べた範囲で一次の資料を得ていません。警告が行動を生むかは測っていません。
:::
