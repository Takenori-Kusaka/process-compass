## ステータス

採用(2026-10-23)。[ADR-0059](/process-compass/adr/0059-no-approval-ratio-trigger/)の次の部分を置き換えます。

- 決定3 の「残る3つの比率(差し戻し率、重複率、手戻り率)」を、2つ(差し戻し率、手戻り率)へ置き換える(本 ADR の決定1)
- 決定4(準拠テンプレートは3つの比率を算出せず、IMPL-0104 を降りていないと表示する)を、本 ADR の決定6 で置き換える
- 決定5 のうち「`basis.detection` は3つの検知条件ごとの欄を持つ」を、2つの欄へ置き換える(本 ADR の決定1)

ADR-0059 の決定5 のうち、「機械が確かめるのは検知条件ごとの記入の有無まで」は維持します。準拠テンプレートが差し戻し率を自ら集計するようになっても、登録の根拠の欄の内容は、登録する者が判定します。

## コンテキスト

[#311](https://github.com/Takenori-Kusaka/process-compass/issues/311) は、第5章 5.4.6 の AI自律レベルの引き下げが準拠テンプレートに降りていないことを指摘しました(IMPL-0104 は降りていない)。あわせて、表の1行が「引き下げを検討する」と書いて節の「自動的に発火」と逆を向いていること、「1件」に根拠水準の開示が無いこと、附属書H の C6 が 5.4.6 の外の行を根拠としていることを挙げました。[#340](https://github.com/Takenori-Kusaka/process-compass/issues/340) の事象1(小さいチームで最小標本に届かず、第2区分が発火しない)も、本 Issue で扱いました。

指摘をそのまま条項にせず、調査2本(内部の突合と外部の実務)と会議体5名(起草・現場・品質保証・規格・擁護)の意見書で扱いました。記録は `research/311-deliberation/` にあります。裁定は `decision.md` の N-1〜N-6 です。

### 見つかったこと

- 準拠テンプレートの委任の登録は、5.4.4 により L3 の登録そのものである。引き下げの手段を持たないまま登録を受け付けることは、5.4.6「発火しない引き下げを、備えているものとして扱ってはなりません」と、テンプレート自身の規則に反していた
- テンプレートの運用引き継ぎ文書の様式は「理解保持者が1名になったら、その機能の AI 自律レベルを引き下げます」と書いていた。働かない引き下げを、働くものとして書いていた
- 変更の重複率は、本標準のどこにも定義が無かった。ADR-0059 が「量の定義を組織に定めさせる」案を退けた理由(定義の無い量を発火条件に残す)が、そのまま当たっていた
- 「検討する」は、担い手・期限・記録が無く、どの結果でも満たせるため検証できなかった。5.4.6 自身が退けた「人の点検を挟む」型と同じであった
- 「1名になった」は、2名から0名へ一度で減った場合は発火しなかった
- ADR-0059 の「4行目」は、#303 で表の行が1行減る前の番号であり、現在の3行目を指していた

## 決定

### 1. 変更の重複率を、引き下げの検知条件から外す(N-2)

5.4.6 の表から変更の重複率を外し、検知条件に置かないことを本文に明記します。5.5.4、第8章、附属書H、準拠テンプレートの `basis.detection.duplicationRate` も合わせて外します。運用メトリクスには検知条件としての重複率がもともと無く(「記録の重複率」は別の量)、手戻り率の定義を 5.4.6 に合わせただけです。廃した言い回しの登録簿に「重複率および手戻り率」「重複率と手戻り率」「重複率、手戻り率」「引き下げを検討する」と欄の名を載せ、再び現れたら検査で落とします。

外す理由は、定義の無い量を発火条件に残すと、発火したかどうかを誰も確かめられないためです。

**検知条件へ戻す条件**は、次の2つがそろうことです。

- 変更の重複率の定義(分子・分母・単位、比較する範囲)が示されること
- その定義で、記録から人の点検を経ずに算出する手段が示されること

戻す場合は、新しい ADR で決めます。

### 2. 手戻り率の行の措置を、自動の1段階の引き下げにする(N-2)

措置を「該当範囲を1段階引き下げる」に改めます。期限つきの判定(期限内に「引き下げない」の記名が無ければ引き下げる)は採りません。拒否権の形で裁量を戻すためです。誤った引き下げの費用は有界(L1 へ落ち、L1 は常に運用できる)ですが、見逃しの費用は有界ではありません。誤発火への手当ては、誤発火の記録で行います。

手戻り率の分子は、実装計画(テンプレ7)の状態を「やり直し」としたタスクとします。「やり直し」は、タスクを指す変更(トレーラ `Spec: F-NNN / Task-N`)が取り込まれた後、または不採用となった後に、同じタスクを指す変更が再び作られた状態です。計画表の記録とトレーラから数えた値は、同じ量を指すと定めます。

### 3. 「自動」を定義する(N-2)

5.4.6 の「自動」は、検知の記録が存在した時点で効力を生じ、判定を要しないことを指します。実行の担い手が機械か人かを問いません。実行する者は、事前に定めた規則を検知の記録に従って執行し、実行を見送る裁量を持ちません。SRE のエラーバジェットの規則(事前に合意した規則を人が執行する)と同じ型です。

### 4. 閾値の根拠を開示し、「1名以下」へ揃える(N-3・N-6)

- AI が起因となった Sev1・Sev2 の「1件」と、5.4.5 の条件4 の「0件」に EV-0154(E0)を付けた。重大度による規則であって統計の閾値でないことと、第7章 7.9.1 と扱いが違う理由を書いた
- 「1名」を「1名以下」へ改めた。根拠水準は第3章 3.4.3 の EV-0071 を引き、新しい EV を付けない
- 「2か月継続」の値は変えない(EV-0146)。数え方(毎月、直近2か月の窓で評価する。最小標本数に満たない評価は継続を切る)を書いた
- 組織が定めた値は、第4章「閾値の設定と較正」の要求事項1 で、値・観測の窓・最小標本数・決め方・次の見直しの時期の5つを G-1 の記録に求める
- 措置の下限は L1 とした。L1 の範囲で検知したときはレベルを変えず、5.4.5 の条件1・条件4 の期間を数え直す。第3章 3.12.5 の「1段階引き下げる」も同じ下限で読む
- 第3章 3.11.7 の短期書き換え率は、5.4.6 の入力でないと改めた

### 5. 最小標本数に満たない窓を判定不能とする(N-5)

窓の中の件数が最小標本数に満たない評価は、判定不能と記録します。判定不能は「異常なし」ではありません。発火しない状態です。判定不能が続く範囲は、第2区分を計測できない範囲として扱い、L2 以上を適用しません。

登録した変更種別で判定不能となったときは、判定可能な窓が得られるまで委任を止めます。これは引き下げではなく、適用の条件の欠落による停止です。判定可能な窓が得られた時点で、判定を待たずに戻ります。5.4.5 の後段は計測できない種別を登録しないと定めており、計測できなくなった種別に L3 を置き続けることを認める理由が無いためです。

- 件数の少ない範囲では、観測の窓を長くしてよい。最小標本数を下げてはならない
- 差し戻し率の分子は、判定基準の番号を引いた差し戻しに限る。番号の無い差し戻しは、0%の継続を切らない
- 保証の開示と次の一手には「判定不能(発火しない)」と表示する。窓ごとに受信箱へ渡すことは求めない(警報の疲労を招く)
- 引き下げた後の点検で引き下げが不要だったと分かった件数を、誤発火として記録する。EV の差し替え条件の材料とする

### 6. 準拠テンプレートは、登録した変更種別を L3、それ以外を L1 とする(N-1)

準拠テンプレートが支える AI自律レベルは、登録した変更種別の L3 と、それ以外の L1 の2つです。**L2 を支えません**。レベルを書く欄を構成に持たず、委任の登録から導きます(5.4.4 は、委任・標準変更・L3 を同じ登録と定める)。欄を持つと、登録とレベルの2つの正本ができ、食い違うためです。

- テーラリングの上限(`maxAutonomyLevel`)を、構成の `autonomy.maxLevel` へ落とす。上限が L3 未満の構成では、変更種別の登録を拒否する。上限の欄の無い旧い構成は、回答からテーラリングの規則で導く
- 第1区分(AI が起因となった Sev1・Sev2、原因を特定できない Sev1・Sev2、コア機能の理解保持者数1名以下)は、委任を判定するたびに記録から導き、該当する種別の委任を止める。停止を記録する手順を別に持たない
- 第2区分の差し戻し率は、テンプレートが毎月、直近2か月の窓で集計し、発火させる。最小標本数は30件
- 手戻り率は集計しない。降りていないことを表示し続ける
- 現在のレベルと停止は、次の一手の注記と保証の開示の項目3 に出す。D-0 の節12 の生成区間には、構成から導ける範囲(範囲ごとのレベルと計測の所在)を出す
- AI 起因の欄は、Sev1・Sev2 を記録する様式に置く。準拠テンプレートには運用の障害の台帳が無いため、欠陥の台帳に置き、ポストモーテムの書き方から写す。台帳には検出の時点(出荷前 / 運用)の欄を置き、出荷前に検出した欠陥を停止に数えない
- 停止の入力となる記録(欠陥の台帳と運用引き継ぎ文書)に触れる変更は、委任に該当させない。委任された変更が自らの停止の入力を書き換えられると、引き下げは発火しない
- 原因を特定できない Sev1・Sev2 による停止は、原因を特定する(AI 起因を「あり」か「なし」にする)まで解かない。登録し直しでは解かない
- 理解保持者数による停止は、運用引き継ぎ文書の履歴から1名以下だった時点を導き、2名以上へ回復した日より後の登録の判定まで解かない。履歴を読めない場合は、判定できないものとして止める
- 登録日の無い種別は、登録が完了していないものとして止める
- L1 の範囲での数え直しの記録と誤発火の記録は、欠陥の台帳の「引き下げの点検の記録」の表に置く(IMPL-0294・0295)

IMPL-0104 は、IMPL-0284〜0289・0291 に分けました。番号は再利用しません。IMPL-0290・0292・0293(AI 起因の欄、障害時の書き方、D-0 の表)は、新しい規定に付けた実装マークであり、IMPL-0104 から分けたものではありません。

### 7. 附属書H の C6 の根拠を付け替え、内部監査の観点を新設する(N-4)

C6 の「支える条項」から 5.4.6 を外し、「測定していない範囲では発動せず、未測定として開示される」を足します。5.4.6 は C9 の根拠に残し、観測に「計測していない範囲での L2 以上の適用」と「検知したのに発火の記録が無いこと」を足します。プロセス内部監査に観点23(AI自律レベルの適用と引き下げ)を新設します。

### 8. ADR-0059 の「4行目」を読み替える(N-6)

ADR-0059 の影響の節の「4行目の措置の語」は、#303 で行を削る前の番号です。現在の3行目(手戻り率の行)を指すものと読み替えます。ADR-0059 の本文は書き換えません。

## 課さないと決めたこと

| 論点 | 課さないこと | 理由 |
| --- | --- | --- |
| N-1 | 構成に AI自律レベルを書く欄を持つこと | 登録とレベルの正本が2つになり、食い違う。書いてあれば通る欄になる(#339 と同じ型) |
| N-1 | 準拠テンプレートでの L2 の支持 | 5.4.4 の登録は L3 の適用であり、テンプレートには L2 に当たる経路が無い。支えないことを宣言し、上限が L3 未満の構成では登録を拒む |
| N-2 | 「検知して人へ渡す」区分の新設 | 節の非対称(引き上げは判定、引き下げは自動)を一部の行で解くことになり、5.5.7 と ADR-0030 にも例外ができる |
| N-2 | 手戻り率の行の削除 | 分子を定義すれば計測できる |
| N-3 | 「直近の差し戻しからの経過」による 0%の継続の数え方 | 窓と最小標本数の既存の規定(第4章 要求事項3)と別の数え方を持ち込み、2か所で定めることになる |
| N-3 | 組織が定めた値への本標準の EV の適用 | 第1章 1.7.6 による。組織の値は、G-1 の記録に決め方と次の見直しを書かせる |
| N-5 | 判定不能の窓を「新しい登録・引き上げの根拠に使わない、自動では下げない」とする扱い | 計測できない範囲に L3 を置くことを 5.4.6 が禁じている。計測できなくなった後に置き続けることを許す理由が無い |
| N-5 | 最小標本数を下げること | 偶然の変動で発火・不発火が決まる |
| N-5 | 0%の継続を避ける意図での差し戻しの禁止(演出の禁止) | 記録から意図を判定できない。形だけの差し戻しは、判定基準の番号を引かない限り分子に数えない |
| N-5 | 判定不能の窓ごとの受信箱への引き渡し | 表示を見る席が既にある。窓ごとの引き渡しは警報の疲労を招く |

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 降ろさず、降りていないことの表示を続ける | 全委員が落とした。テンプレートの委任の登録は L3 の登録そのものであり、引き下げの手段を持たないまま登録を受け付けることは 5.4.6 に反する |
| 手戻り率の行に、期限つきの判定(期限内に「引き下げない」の記名が無ければ引き下げる)を置く | 決定2 のとおり。拒否権の形で裁量を戻す |
| 重複率の定義を組織に定めさせる | ADR-0059 が同じ案を退けた理由(定義の無い量を発火条件に残す)が当たる |
| 重複率の定義を本標準で新たに定める | 定義と計測の手段を示す材料が、調査で見つからなかった。決定1 の戻す条件として残す |
| 引き下げの状態を構成へ記録し、人が解除する | 状態を持つと、記録(台帳・判定記録)と食い違う。停止は判定のたびに記録から導く |
| 判定不能の窓で、何もしない(表示だけ) | 決定5 のとおり。計測できない範囲に L3 を置き続けることになる |

## 影響

- 準拠テンプレートの委任の判定は、登録した変更種別が止まっている間、委任に該当しないと判定する。止まった種別の変更は協働で扱い、人が変更ごとに確定する
- 欠陥の台帳(`docs/defect-ledger.md`)と運用引き継ぎ文書(`docs/handover.md`)が無い構成では、登録した変更種別の委任はすべて止まる。既存の採用者は、台帳に発生日・AI 起因・原因の変更・登録した変更種別の列を足し、引き継ぎ文書に関わる登録した変更種別の列を足す。列の無い旧い台帳の Sev1・Sev2 の行は、AI 起因を「特定できない」と同じく扱う
- 委任の判定のワークフローは、既定ブランチの履歴の全体を取得する。浅い取得では差し戻し率を判定できないものとして止める
- 小さいチームでは、差し戻し率の窓の件数が最小標本数(30件)に届かないため、委任は止まり続けうる。準拠テンプレートの窓と最小標本数は定数であり、組織が G-1 で長くした窓を構成に持たない。この制約は [#349](https://github.com/Takenori-Kusaka/process-compass/issues/349) で扱う
- 理解保持者数による停止は、運用引き継ぎ文書の git の履歴から1名以下だった時点を導き、回復した日より後の登録の判定まで解けない。浅い取得では履歴を読めないため止まる
- 差し戻し率の分子は、G-6 の判定記録のうち判定基準の番号を引いた差し戻しに限る。判定記録には、様式と、レビューを媒体とした判定(写しの宣言行 `G-6: 差し戻し / 基準 N`。[ADR-0070](/process-compass/adr/0070-gate-record-medium-and-field-sources/))の両方を含む。宣言行と基準の番号の無いレビューの差し戻しは数えない。対象を既定ブランチの履歴へ対応づけられない差し戻しは数えず、件数を注記に出す。宣言行と基準の番号の無いレビューの差し戻しの扱いは [#350](https://github.com/Takenori-Kusaka/process-compass/issues/350) で扱う
- 手戻り率は準拠テンプレートに降りていない(IMPL-0291)。採用者が集計の手段を備え、発火の有無は内部監査の観点23 で確かめる。手戻り率の算出は [#348](https://github.com/Takenori-Kusaka/process-compass/issues/348) で扱う
- CL2 の上限 L2 は、テーラリングの規則では安全関連部の上限である。準拠テンプレートの構成は安全関連部の範囲を持たないため、案件の全体へ掛け、理由を表示する(厳しくする側)。回答に安全重要度の無い旧い構成は L1 とする
- 旧い構成の `basis.detection.duplicationRate` は読まれず、`/pit` の注記に出る。登録の要件にも数えない
- 審査の保証水準(L0〜L2)と AI自律レベル(L1〜L3)の記号の衝突は、本 ADR の範囲外とし、[#347](https://github.com/Takenori-Kusaka/process-compass/issues/347) で扱う
