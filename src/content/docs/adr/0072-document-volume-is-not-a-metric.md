## ステータス

採用(2026-10-23)。[ADR-0047](/process-compass/adr/0047-limit-is-default-not-cutoff/)の決定5 のうち、行数の算定から除く散文を「判断記録・機能仕様・設計文書」の列挙で定める部分を、本 ADR の決定3 で置き換えます。散文の成果物を行数の算定から除外するという ADR-0047 決定5 の趣旨と、ほかの決定は維持します。[ADR-0058](/process-compass/adr/0058-size-over-is-confirmed-not-blocked/)は変えません。

## コンテキスト

[#289](https://github.com/Takenori-Kusaka/process-compass/issues/289) は、文書の量について 2 つの Issue を引き継ぎました。#252 は、実装 10 行に対して文書 21,116 行の実案件から、量の上限か比率の観測を求めました。#272 は、判断記録の本数・行数・参照の回数の観測と、規定を減らす手続を求めました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/289-deliberation/`(`survey-289-3`、意見書、`decision.md` の D-7〜D-12)にあります。成果物の構造は [ADR-0071](/process-compass/adr/0071-structure-of-principles-decisions-and-gate-records/)に分けました。

### 量と害の関係は測られていない

調査は、文書化の密度と信頼性の間に有意な関係を示さなかった報告と、生成した行数を虚栄の指標とする報告を見つけました(E1)。文書と実装の比率を管理の指標として運用する先例は、見つかりませんでした。比率は、実装が小さい段階(S0)で分母が小さく発散します。

### 集約の件数が、参考として測る形になっていた

準拠テンプレートの出荷の証跡の集約は「判断記録 N 件」を出していました。空の構成で、置き場の説明の文書(`README.md`)を数えて 1 件と出ていました(会議体の品質保証の委員が実行して確かめました)。件数の表示は、何を判断するかを書けないまま参考として測る形です。

### 行数の算定の除外が、本文と実行層でずれていた

第4章のタスクの分割基準は、行数の算定から「判断記録・機能仕様・設計文書」を除いていました。準拠テンプレートの PR 単位の検査は、全ての `*.md` を除いていました。製品のディレクトリへ置いた `*.md` は、算定とリスク区分の下限 R2 の両方から外れていました。

## 決定

### 1. 判断記録の総量と参照の実績を指標にしない(D-7)

判断記録の本数・行数・参照の回数を、運用メトリクスの指標にしません。運用メトリクスに「採用しない指標」の節を置き、理由とともに書きます。何を判断するために測るか(運用メトリクスの手続1)を書けず、対になる指標を指定できないためです。判断記録は、読まれなくても経緯として保持する性質を持ちます。#289 の受入条件の「第7章メトリクス」は、運用メトリクス(フェーズ6)と読みます。

出荷の証跡の集約は、判断記録を状態ごとの件数(採用・一部置き換え・置き換え・廃止)と、置き換えの両側の参照の不一致の件数で出します。`README.md` を数えません。

### 2. 文書の量を指標にせず、上限も警戒水準も置かない(D-8・D-9)

文書の総量、文書と実装の比率、文書の増加の速度を、指標にしません。上限・警戒水準・警戒サインも置きません。判定する側の負荷は、既存の「ゲート滞留時間」と「レビュー所要時間の分布」で見ます。害の正体は量ではなく読まずに通ることであり、それを測る指標は既にあります。根拠水準は EV-0123 で開示します。

上限を遮断として運用する形は、[ADR-0047](/process-compass/adr/0047-limit-is-default-not-cutoff/)および [ADR-0058](/process-compass/adr/0058-size-over-is-confirmed-not-blocked/)の決定と当たります。

### 3. 行数の算定から除く文書を、置き場の散文に限る(D-10)

第4章の除外を、「判断記録・機能仕様・設計文書」の3種の列挙から、「準拠の構成が文書の置き場と定める場所(`docs/`・`context/`・`specs/` ほか)にある散文のファイル」へ改めます。決定の記録の語は「構成が宣言する文書の置き場」です。「構成」は本標準で構成ファイルを指す語でもあるため、置き場を構成ファイルで宣言するとは限らないことを、語で明らかにしました。**置き場の外に置いた散文は、算定に含めます**。散文の量には基準を置きません。準拠テンプレートの PR 単位の検査を、これに合わせます。

除外の理由(400 行の根拠は散文に当たらない)は散文全体に当たるので、3種の列挙は狭すぎました。全ての `*.md` を除くと、製品のディレクトリへ置いた `*.md` が R2 の下限から外れる経路が開きます。置き場で限れば、理由の範囲を保ったまま、この経路だけを塞げます。数え過ぎたときの費用は、規模の確認 1 件です。

算定から除いた文書だけの変更は「判定完了時間の SLA で判定する」と書いています。出荷の集約は、文書だけの変更の判定完了時間を出していません。この句には、降りていない実装マーク(IMPL-0136)を付けます。

### 4. 探索の記録の量は課さない(D-11)

S0 の探索の記録の量を課しません。置き場と、ステージ移行ゲート(SG-0)へ渡す出力は、#294(S1 以降の技術検証。#250 の後継)で決めます。量を掛ける対象が、成果物として定義されていないためです。

### 5. 期限つきの実験の結果を判断記録の状態へ反映し、期限超過を四半期の入力にする(D-12)

改善サイクルの外側ループで期限つきの実験として導入した変更は、期限の後に、結果(継続・置き換え・廃止)を元の判断記録の状態へ反映します。拾えるように、判断記録の様式(テンプレ2)に「期限(期限つきの実験として導入した場合)」の欄を置き、継続は「採用(日付)。継続(日付)」と状態の行へ書きます。期限を過ぎても状態が変わらない判断記録を、四半期の振り返りの入力に出します。機械で拾えます(準拠テンプレートの `check-decisions --overdue`)。扱いは技術判断者が決めます。

### 6. 件数の削除義務は課さない(D-12)

「振り返りのたびに規定を 1 つ以上削る」のような件数の義務を課しません。件数の義務は、削るものが無い回に形式的な削除を生みます。件数の根拠もありません。装置と規定の総量と、減らす判断を誰が行うかは、#290 で扱います。

## 検討した選択肢

| 論点 | 採らなかった案 | 採らなかった理由 |
| --- | --- | --- |
| 総量 | 判断記録の本数・行数を観測指標にする | 減らす打ち手は「書かない」であり、判断記録の充足と逆へ動く |
| 総量 | 参照の回数を観測する | 人の読みは記録できない。AI の読み込みのログは 3.11.4 要求事項6 の範囲であり、#292 で扱う |
| 文書の量 | 文書と実装の比率を観測指標にする(上限なし) | 分母が小さい S0 で発散する。打ち手の無い、眺めるだけの指標になる |
| 文書の量 | 文書の量に上限を置く | 量を下げる圧力は、書くべき記録を消す。上限を遮断にする形は ADR-0047・0058 と当たる |
| 算定 | 散文を全て除く(現行の実行層) | 製品のディレクトリへ置いた `*.md` が、R2 の下限から外れる経路が残る(会議体は散文全体へ広げる案が多数だったが、この経路を理由に従わなかった) |
| 算定 | 3種の列挙を維持する(現行の本文) | 除外の理由は散文全体に当たり、列挙が狭すぎる |
| 減らす手続 | 毎回 1 つ以上削る義務 | 形式的な削除を生む。件数の根拠が無い |

## 影響

- 運用メトリクスに「採用しない指標」の節が加わる
- 第4章のタスクの分割基準の除外の文が改まる。準拠テンプレートの PR 単位の検査は、置き場の外の `*.md` を数える(IMPL-0049 の注記を改める)
- 改善サイクルの外側ループの手順に、結果の反映と期限超過の入力が加わる
- 判断記録と文書の量について、本標準は量の観測を持たない。量が害になる事例が出ても、量からは検出しない。検出はゲート滞留時間とレビュー所要時間による
