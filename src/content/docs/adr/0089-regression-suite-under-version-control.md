## コンテキスト

#284〜#288 の会議体は、決定を固定する回帰の試験(場面のスクリプトと入力)を作りました。#302〜#310 の組A・組C は、その試験を直して流しました。試験は利用者の端末の作業ディレクトリ(`tmp/`)にだけあり、リポジトリの版管理の外にありました。クラウドの作業環境には無く、失われる寸前でした。

#319 で退避物を写して流すと、次のことが分かりました。

- 前から落ちていた 16 件は、どちらも時計が原因でした。試験は実行した日の日付を1回だけ求めており、UTC の 0 時をまたぐ実行で落ちていました
- #311 より前から誰も流さずに落ちていた場面が 28 件ありました。「決定を固定している」という主張を、どの構成品目も支えていませんでした
- 移した試験をいまのテンプレートで流すと、初期化が事前点検(#315)で止まり、900 件が落ちました。原因を分けると、残りは 47 件でした
- 元のスイートは、拒否を期待する場面を出力のどこかに語があれば通していました。構成の差分の節に同じ語があるだけで、別の理由の拒否でも通りました
- 元のスイートの実行役は、失敗を終了コードへ渡していませんでした

議題の前提の誤りを1つ訂正します。廃した言い回しの登録簿の各句は、由来の欄 `by` を既に持っていました。足りなかったのは、`by` の指す決定が実在するかの検査です。

経緯の全体は `research/319-deliberation/`(調査・会議体・裁定・分類・移植の記録・実装の記録)にあります。

## 決定

### 1. 決定を固定する回帰の試験を、元の仕組みのまま版管理の下へ移す

- 置き場は親のリポジトリの `scripts/regress/` とする。試験の対象は `template/` の作業ツリーで、知識ベースは標準から作り直したものである。採用者へは配らない。テンプレートの `gate-g5.yml` の試験は、いまのまま残す
- 移す範囲は、決定(ADR の決定・K 番号・Issue)を名指せて、期待値を持つ場面のすべてとする。手で選び抜かない。移さない場面は、処置の表(`scripts/regress/DISPOSITION.md`)に、理由と、固定していた決定がほかの試験で覆われているかを書く。覆われていないものは表示し続ける
- 退避物は `research/319-deliberation/legacy-suite/` へ、手を加えずにハッシュの一覧とともに置く
- まず元の仕組みを保って移し、凍結した時計のもとで p302(#311 の前の基準の実行)との一致を場面ごとに確かめる。一致を確かめる前に、既存の試験の形へ書き直さない。書き直すと、決定が黙って変わったかを比べる基準を失うためである
- 移植の問題は移すときに直す。シェル・GNU・Windows への依存は Node へ置き換える。`gh` は PATH 上の Node の代役に替える。作業の場所は作業ツリーの外(`mkdtemp`)に作り、`git init` の後に最上位を確かめる。失敗は終了コードへ渡す
- 期待値を持たなかった matrix を matrix-sweep へ統合し、出力の期待値をコミットして持たせる。#318 で3行が変わっても合格のままだった原因が、期待値の欠如にあったためである

### 2. 各場面に、固定する決定を持たせる

- 各場面は欄 `fixes` に、固定する決定(ADR の決定・K 番号・Issue)を持つ。対応表は欄から生成し、手で持たない。正本は試験の中の欄の1か所である
- 決定の実在は機械で確かめる(`npm run lint:refs`)。ADR は頁と「決定N」、K 番号は #284・#285 の決定の見出し、Issue は調査・公開ドキュメントの記載で確かめる
- 実装マーク(IMPL)は条項と試験を結ぶものであり、ADR の決定を結ぶ欄にしない

### 3. 期待値を改めるときは、先に存在する決定を引く

- 決定を固定する場面の期待値を改めるには、改める根拠の決定(ADR の決定・Issue)を引く。場面の記録 `changed` に、引いた決定の識別子・日付・旧い期待値を残す
- 自由記述の理由の欄は求めない。AI が埋められる欄は確認にならないためである
- 規則と期待値は、同じ変更の中で改めてよい。そのとき、変わった場面の一覧(旧・新・引いた決定)を PR の本文へ出し、人が確かめる。実行役は一覧を `changed.md` に書く
- 機械が合否に使うのは、形の検査(`fixes`・`changed` の欄と、決定の実在)だけである。期待値の差分そのものでは失敗にしない。出力をそのまま期待値へ写すモードは作らない
- 決定を引かずに期待値を改めることは、5.8.5 の禁止事項3 に当たる
- fixture・入力が決定に反する場合は、期待値ではなく入力を直す

### 4. 拒否は理由で照合し、落ちることを期待する印は厳格にする

- 拒否を期待する場面は、拒否の理由の1件(`[エラー]`・`::error::` の行と、続く字下げ・箇条の行)の中で語を照合する。拒否の対象(差分のどの節に何が出たか)は、見出しで区切った節の中だけで照合する。2つを1回の照合にまとめない
- 「落ちることを期待する」印は自前で実装する。CI の Node 22 では `expectFailure` が黙って無視されるためである。印は Issue・照合する拒否の理由・見直しの時期を持つ。予期せず通った場合、別の理由で落ちた場合、見直しの時期を過ぎた場合、欄が欠けた場合は失敗にする
- 根の場面の失敗の結果として落ちる連鎖の場面は、根の印に従属させる。根が印のとおりに落ちている間だけ、連鎖の失敗を通す。根が落ちているのに連鎖が通れば失敗にする

### 5. 試験を流す経路と時計

- 回帰の試験は、sweep を含めて、親の `npm run check` に入れる。通らなければ公開と配布が止まる。量の上限は置かない。止まった実行を打ち切る `timeout-minutes` は、量の上限ではないため置く
- テンプレートの試験は、`gate-g5.yml` のジョブ `contract` の手順を一覧として共有し、親の `npm run check` から流す。テンプレートの `scripts/gate/test-*.mjs` のうち `gate-g5.yml` から実行されないものがあれば失敗にする
- `check-ci-wiring.mjs` が、`check` への結線・失敗を握りつぶす形の不在・`timeout-minutes`・作業の場所が作業ツリーの外であること・終了コードの伝搬を確かめる。実行役の振る舞いは `scripts/regress/test-run.mjs` が確かめる
- 時計は試験の側で止める。`NODE_OPTIONS=--import` の先読みで `Date` を差し替え、子プロセスまで届かせる。git の時刻も同じ時刻にそろえる。スクリプトごとに書かれた時点の時刻を宣言する。子プロセスを起動するたびに 1 秒進める論理の時計とし、コミットの前後を時刻で比べるスクリプトの順序を保つ
- 日付の境・時刻帯・`next_review` の経過・`confirmedAt` は、時刻を明示した場面で確かめる
- テンプレートのスクリプトが `Intl.DateTimeFormat` の `format()` を引数なしで呼ばないことを、走らせる前に確かめる。引数なしの呼び出しは差し替えた `Date` を読まず、時計が止まらない
- テンプレートに時刻を差し替える入口は足さない
- 作業用の複製には、初期化の事前点検(ADR-0085 決定2)への調整を2つ入れる(`@OWNER` の置き換えと、回答の JSON の除外)。調整を外した複製で初期化が止まることを、移した試験の側で確かめる

### 6. 落ちていた 47 場面を分類して直す

分類の草案は移植と別の文脈が作り、裁定(`decision.md` の 7.5 節)を経ました。人による確定は PR の差分の確認で行います。

| 分類 | 場面 | 直し方 |
| --- | --- | --- |
| 決定が変わった | matrix-sweep 3(ADR-0088 決定5)、new 1(同)、verify-n 1(ADR-0086 決定5) | 決定を引き、`changed` に記録して期待値を改めた。new は、期待値だけを改めると下限を「上げる」場面になり K40 の固定を失うため、入力を 75 へ改めた |
| 入力が決定に反する | replay 5(ADR-0066)、s5-init-pr 1(ADR-0079 決定2)、stages 20(ADR-0075 決定4・ADR-0079 決定3)、t288 9(ADR-0079 決定2・ADR-0082・ADR-0081)、t288b 1(ADR-0081) | 期待値を変えず、入力を直した。t288 の兼務は、ADR-0082 の記録を fixture に足して直した。席は分けない。場面が固定しているのは席の配置ではないためである |
| 回帰 | v3 K65(ADR-0053 決定1・ADR-0078 決定2) | 期待値を改めず、テンプレートの側を直した(決定6 の後段) |

| 移植の照合の範囲 | scenarios 1、v3 1 | 照合を拒否の理由と差分の節の2つに分けた。語は元のまま使い、期待値は変えない |

ADR-0078 決定2 は、ADR-0053 決定1 の基準(取り消せない時間帯が存在すること)を維持すると定めています。その基準は、準拠テンプレートの `CLAUDE.md` と `.claude/skills/pit/reference/handoff.md` から #294 で消えていました。v3 の K65 の場面は、この喪失を捉えていました。期待値を新しい文言へ改めると、喪失を固定します。テンプレートの2か所へ基準を戻し、常駐の規則の一覧(`claude-md-resident.json` の CR-010)の核の文言にも基準を足しました。誘導層と強制層の変更であり、AI維持管理者の承認を要します(`state:needs-platform`)。

### 7. #302〜#310 の手続の欠陥と、ADR-0066 の過大な主張

#302〜#310 の組A・組C が試験に当てた直しの内容は、正当でした。手続に3つの欠陥がありました。

1. 構成管理の外で直した
2. 元のスイートを更新しなかった(直しは作業用の写しにだけあった)
3. replay の入力を漏らした(`s4-acc3.json` の兼務が直っていなかった)

ADR-0066 の「影響」の「規則データ・本文・回帰の fixture を同時に直します」は、実際より多くを主張していました。直した fixture は作業用の写しであり、replay の入力には及んでいませんでした。ADR-0066 の本文は書き換えず、本 ADR に記録します。

### 8. fixture は決定の記録ではない

- 回帰の試験の fixture・入力・期待値は、決定の記録ではない。決定を固定する試験は、決定を引くこと(`fixes`)で意味を持つ
- ADR-0060 は、(決定2)「外部の確認者を、担い手だけに限る」の却下の理由に、回帰の fixture が席の責任者の形を固定していることを挙げていた。ADR-0066 は、fixture は決定の記録ではないとする。両者は食い違っていた
- ADR-0060 の却下が fixture を挙げなくても成り立つかを確かめた。却下は理由1(全変更を外部が確認する体制から、承認の強制と、確認漏れを欠落にする検査が消える)だけで成り立つ。支えは第3章 3.5 の(ア)(イ)の効果と、ADR-0054 決定1(担い手の定義)・決定8(G-6 の条件1・3)である。外部の確認者を席の責任者に置く場面と、外れた後に席を本人が引き取る場面は、p302・#311 の直前・いまのテンプレートのいずれでも通る。却下は維持する

### 9. 標準の側の規定

- 第4章「判定が指す記録の保管」の隣に「判定の根拠に数える試験の置き場」を置く。G-5 の判定の根拠に数える試験(スクリプト、入力のデータ、期待値、補助のファイル)は、判定の対象と同じ版管理の下に置く。個人の端末と、版管理から除外した場所の試験を根拠に数えない。第3章 3.12.3 の要求事項5 が覆わない範囲を覆う。根拠の水準は E1 とし、EV-0181 を付ける。実装マークは IMPL-0350 とする
- 第5章 5.8.5 の後の段落に2つを足す。期待値を改めるときは、改める根拠となる決定・要求を引く。「落ちることを期待する」印は `skip` 相当の付与と同じく検証を弱める変更として扱い、G-6 の確認事項に載せる。降ろし先は既存の IMPL-0204 に乗せ、注記を改めた
- 課さないと明記するもの: 「決定を固定する試験」という種別、試験の枠組み、時計の方式、印の件数の上限、期待値の差分による機械の阻止

### 10. 廃した言い回しの登録簿と、却下した案の残し方

- 登録簿の各句の `by` が、実在する ADR・Issue を1つ以上指すことを機械で確かめる(`lint:provisions` の検査13)。`by` の ADR に句が字句どおり現れることは求めない
- 会議体の決定を反映する作業では、却下した案ごとに、登録簿の句・否定の場面・どちらも置かない理由のいずれかを記録する。手順は `community/provision-forms.md`「却下した案ごとに、残す形を決める」に置いた
- `research/` は登録簿の検査の範囲に入れない。経緯の記録だからである。`zenn/` を入れるかは #320 で決める

本 ADR の却下した案の残し方は、次のとおりです。

| 却下した案 | 残す形 |
| --- | --- |
| 手で選んだ場面だけを移す | 置かない理由: 運用の選択であり、句にも挙動にもならない。処置の表が移さない場面を表示し続ける |
| 一致を確かめる前に既存の形へ書き直す | 置かない理由: 移植の手順の選択である |
| テンプレートへ置き、採用者へ配る | 否定の場面: 置き場が `scripts/regress/` であることは、`check-ci-wiring.mjs` の条件12 が `test:regress` の指す所在で確かめる |
| 対応表を手で持つ / IMPL に載せる | 置かない理由: 対応表は実行役の生成物(`fixes.md`)であり、手で持つ表が現れても検出の手段が無い。`check-fixes.mjs` が欄から決定を読む |
| 落ちる場面をそのまま入れる / 一括で直す | 否定の場面: 実行役の試験(`test-run.mjs`)が、落ちる場面があれば終了コード 1 を返すことを確かめる |
| scenarios の3件の期待を「拒否」へ反転 | 否定の場面: 根の場面は元の期待(反映)のまま印を持ち、予期せず通れば失敗する |
| Node の `expectFailure` に頼る | 置かない理由: 実行環境の版の事実であり、句にならない |
| テンプレートに時刻を差し替える入口 | 置かない理由: 入口が足されれば、テンプレートの強制層の変更として `state:needs-platform` を経る。入口の名を予測して句を登録できない |
| 自由記述の理由の欄 | 置かない理由: 実行役は `changed` に by・on・from だけを求める。理由の欄が足されても合否に使わないため、句にも挙動にもならない |
| 期待値の差分で機械が失敗させる / 自動更新 | 置かない理由: 第5章 5.8.5 の後の段落に課さないことを書いた。自動更新のモードは実行役に無い |
| 却下文の全文検索を検査にする | 置かない理由: 誤検出(`community/provision-forms.md` に記載) |
| `by` の ADR に句の字句一致を求める | 置かない理由: 由来の検査として過剰(`community/provision-forms.md` に記載) |
| sweep を週次・条件つきに限る | 否定の場面: `check-ci-wiring.mjs` の条件12 が、`test:regress` が `--only`・`--shard` を持たないことを確かめる |
| 標準に種別・枠組み・時計の方式・印の上限を課す | 置かない理由: 第4章と 5.8.5 の後の段落に、課さないことを書いた |

| 期待値をコミットし、人が差分で確かめ、自動で書き換えない(決定3) | Jest のスナップショットの手引き [SRC-0696]。更新はコミットの約 8.2% で起き、他の変更と同時に起きることが多い [SRC-0697] |
| 時計を試験の側で止める(決定5) | システムの時計を包んで差し替える [SRC-0694] |
| 落ちることを期待する印を厳格にし、Issue を結ぶ(決定4) | pytest の strict の xfail [SRC-0695]。試験の無効化の前にバグを起票する(Mozilla [SRC-0698])。Node.js の `todo` は終了コードに影響せず、`expectFailure` は v24.14.0 からである [SRC-0699] |

印に期限を持たせて機械が期限切れを落とす公式の仕組みは、調査の範囲で見つかりませんでした。見直しの時期を過ぎた印を失敗にするのは、本プロジェクトの選択です。

## 検討した選択肢

採らないと決めた選択肢と、その理由です。

| 選択肢 | 採らない理由 |
| --- | --- |
| 手で選んだ場面だけを移す | 選ばれなかった決定が、黙って固定を失う |
| 一致を確かめる前に既存の試験の形へ書き直す | 決定が変わったかを比べる基準を失う |
| テンプレートへ置き、採用者へ配る | 標準から作り直した知識ベースを要する。採用者の負担になる |
| 対応表を手で持つ / IMPL に載せる | 正本が増える / IMPL は条項を結ぶものである |
| 落ちる場面をそのまま入れる / 一括で直す | ADR-0073 / 分類を経ず、決定が黙って変わる |
| scenarios の3件の期待を「拒否」へ反転する | 5.8.5 の禁止事項3 と同じ形になる |
| Node の `expectFailure` に頼る | CI の Node 22 で黙って無視される |
| テンプレートに時刻を差し替える入口を足す | 署名した記録の日付を実行者が選べる経路になり、K65 の回避経路になる。統制の弱化である |
| 期待値を改める理由を自由記述の欄で求める | AI が埋められ、確認にならない |
| 期待値の差分で機械が失敗させる / 出力から期待値を自動で更新する | 5.8.5 の後の段落と食い違う / 盲目的な上書きになる |
| 却下文の全文検索を検査にする | 誤検出が多い |
| `by` の ADR に句の字句一致を求める | 66 句のうち 40 句が落ちる。由来の検査として過剰である |
| sweep を週次・条件つきに限る | 規則を変えた変更でこそ差が出る(#318 の3行)。その変更を流さない設計は、検出の機会を失う |
| 標準に「決定を固定する試験」の種別・試験の枠組み・時計の方式・印の件数の上限を課す | 一次資料の根拠が無い。採用者の選択である |
| t288 の兼務を、席を分けて直す | 場面が固定しているのは席の配置ではない。ADR-0082 は兼務を許したうえで記録を求めている |
| 事前点検への調整を、回答の JSON を複製の外へ置く形で行う | 15 本のスクリプトの入力の書き方を変え、p302 と比べる基準を変える。除外の形は、場面の入力を元のまま保つ |

## 影響

- 決定を固定すると主張する試験は、版管理の下にあり、凍結した時計のもとで誰がいつ流しても同じ結果を出す。期待値の改めは、決定へ辿れる
- `npm run check` の実行時間が延びる。4 CPU で、回帰の試験(sweep を含む)はおよそ 6〜10 分、テンプレートの試験はおよそ 1 分である。量の上限は置かない(ADR-0074)
- 落ちることを期待する印は、scenarios の3場面(根1・連鎖2)にある。見直しの時期は 2026-12 である。後継の Issue を起票したら、印の Issue 番号を付け替える
- 移さなかった fix288-r3 の 50 場面は、覆われていない可能性がある場面として処置の表に表示し続ける
- 後継の Issue の候補: (1) 同じ変化点で名簿へ足して確認し任命すると拒否される件 (2) `gate-g5.yml` の Node の版の固定(`setup-node` が無い) (3) 検証を弱める変更の検出(IMPL-0204。既存の #360)へ、落ちることを期待する印と期待値の改めを含める
