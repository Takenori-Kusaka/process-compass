## ステータス

採用(2026-11-15)。採用済みの ADR の決定を置き換えません。[ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/) が定めた棚卸しの手続を、残りの節へ当てて終えたときの決定です。採用済みの ADR の本文は書き換えていません。

## コンテキスト

[ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/) は、実装マークの対象を節の単位で棚卸しすると決め、一部の節だけを区分しました。[#324](https://github.com/Takenori-Kusaka/process-compass/issues/324) の着手の時点で、対象の 565 節のうち 398 節が未棚卸しでした。

#324 は、残りの節の区分と、区分の信頼性の確かめ方を求めました。審議の重さは軽です。記録は `research/324-deliberation/` にあります(裁定は `decision.md`、突合を受けた裁定は `ruling-A1.md`〜`ruling-C2-D.md`)。

- ADR-0076 は、全節を一度に棚卸しする案を「分類の一致率が測られないまま確定する」として採らなかった。本件は、一致率を測らないまま全節を区分する。この事実を、読み手が「書かれていない」と区別できる所に残す必要があった
- 着手の前に、反対の委員が区分済みの節に誤りの実例を見つけた。第7章 7.4・7.7.1 と第3章 3.12.2 である。規定を制度設計へ倒す誤りで、降りていない規定の表示を減らす向きだった
- 棚卸しの途中で、合う降ろし先が登録に無い規定が多数見つかった

## 決定

### 1. 2名の独立の分類と、一致の記録を課さない

区分は、登録者1名の判断です。登録の後に、登録者の記録を読まない別の文脈が、差分と本文と降ろし先の実物を突き合わせます。本件では4つの束ごとに行い、束ごとに2巡までで閉じました(1巡目は全体、2巡目は直した差分だけ)。

**2名の独立の分類と、その一致の記録は課しません**(所有者の決定 2026-11-12)。開示は、[実装マークの規約](/process-compass/community/implementation-marking/)の「区分の確かめ方」の根拠水準マーク EV-0270(E0)で行います。書くのは、確かめた手段、突合が読まなかった範囲の数、較正の結果、見つかった誤りの数と型です。棚卸しの手続の根拠水準マーク EV-0135(E1)とは対象が別なので、枠を分けます。

### 2. 制度設計へ倒す条件を、主題の列挙ではなく問いにする

区分の判定の順 6(規定を「対象にしない / 制度設計」とする条件)は、主題(任命、会議体の運営、予算の制度、契約、対外の表明)の列挙で判断しません。**その文を破ったことを、実行主体の外から検知するか拒む仕組みが成り立つか**で問います。成り立つなら、題が制度に見えても規定として扱います。「AI の担い手を縛らない」だけでは、対象から外す理由になりません。

本件の前から制度設計と区分していた節は、この問いで全件を読み直しました。制度設計の節は 20 から 6 になりました。

### 3. 合う降ろし先が無い規定は、予定の降ろし先を足して表示する

合う降ろし先が登録に無い規定には、近い降ろし先を当てません。予定の降ろし先(`kind: planned`。ADR-0076 決定8)を足し、`state=undelivered`・`plan=scheduled` のマークで表示します。運ぶ実物が準拠テンプレートに既に在るときは、そのファイルを既存のファイルの降ろし先として登録します。

- 予定の降ろし先は 11 件から 24 件になった
- `issue=` は、領域の合う open の Issue を名指す。合うものが無いときは、#324 を仮に名指す
- **採用者に委ねるか(`plan=adopter`)は、本件で決めない**。名指した Issue で決める

### 4. スキルの補助ファイルと、そのレビューの観点を、降ろし先に数える

準拠テンプレートのスキルが読ませる補助ファイルは、降ろし先に数えます。ゲートごとの補助ファイル(`gates/`)と、成果物ごとの手引き(`artifacts/`)です。手引きの「レビューの観点」も、規定を運ぶものに数えます。スキルはその1枚を読ませる入口で、観点は作る者とレビューする者に届くためです。

観点が規定の一部しか言わないときは、言う部分だけを `delivered` にし、残りを `undelivered` のマークに分けます。

### 5. 第2章 2.10.5 の計画容量の上限は、降りていない規定として表示する

第2章 2.10.5 の「作業単位の個数の合計が計画容量を超える追加をしてはならない」は、`undelivered` のマーク(IMPL-0851)で表示します。企画書の様式を降ろし先にしません。様式は合意の時点の値を運び、合意の後の追加を運ばないためです。

**機械の検査にするかは、本件で決めません**。作業単位ごとの層の帰属と、調整の後の個数を読む置き場が、本標準に定まっていません。置き場を定めることは採用者の記録の義務を増やすので、名指した Issue で扱います。

### 6. 棚卸しでは、`check=machine` と `plan=adopter` を新しく付けない

棚卸しで足すマークに、`check=machine` と `plan=adopter` を付けません。`check=machine` は違反と適合の対の試験を要し、`plan=adopter` は採用者に委ねる理由を ADR に書くことを要します。どちらも棚卸しの担当の判断にしません。本件の前後で、`check=machine` は 197 件、`plan=adopter` は 29 件のまま変わっていません。

### 7. `delivered` の基準は、実物を読んで確かめたこととする

`state=delivered` は、降ろし先の実物(ファイルの文・欄・関数)を開き、規定を運んでいることを読んで確かめたものに付けます。実行では確かめていません。

- `note` に、降ろし先の中の所在(ファイルと、見出し・識別子・関数名)を書く。行番号は書かない
- 実環境で確かめていない点は、`note` で開示する
- 1件のマークが、降りた規定と降りていない規定を束ねているときは、マークを分ける。分けたマークには新しい番号を振る
- 実環境の未確認を理由に `undelivered` としている既存のマーク(IMPL-0026・IMPL-0235)は、変えない

## 検討した選択肢

### 区分の確かめ方

| 案 | 採らなかった理由 |
| --- | --- |
| 2名の独立の分類と一致の記録を課す | 所有者の決定(2026-11-12)。課さないことを規約に明記し、根拠水準マークで開示する |
| EV-0135 の対象を書き直して、区分の確かめ方も含める | 対象と水準が別である(手続は E1、確かめ方は E0)。1つの枠にすると、弱いほうが隠れる |
| 読まなかった節の数を、ADR にだけ書く | 開示は、規約の読み手に届く場所に置く |
| 採用済みの ADR-0076 の本文へ、棚卸しを終えたことを書き足す | 採用済みの ADR は書き換えない |
| 独立の突合の母集団を、強い文末のある節に絞る | 規範が強い文末に載らない節(第3章 3.12.2)が網から落ちる。`none` の節は全件を読む |
| 突合の所見を、1巡目から開示だけで閉じる | 1巡目の所見は直す。開示して閉じるのは、2巡目の後に残る所見に限る |
| 規定を運ぶ手引きのうち、未登録の 9 枚を全部照合する | 2巡を超える見直しになる。未照合の向きは、降りているものを降りていないと表示しうる向きで、表示を減らさない(EV-0269) |
| 節の本文の指紋で、区分を無効にする | ADR-0076 決定3 で採らないと決めてある |
| 判定表だけを担当へ渡して始める | 担当ごとに読みがぶれる。裁定例を先に作り、担当ごとに較正を行った |

### 区分の判定

| 案 | 採らなかった理由 |
| --- | --- |
| 制度設計へ倒す条件を、主題の列挙のままにする | 区分済みの節に誤りの実例があった。誤りは、降りていない規定の表示を減らす向きである |
| 区分済みの節の誤りを、別の Issue へ送る | 同じ判定の誤りを残したまま、棚卸しを終えたと表示できない |
| 強い文末が 0 の節を、読まずに説明とする | 文末で作る母集団は閉じない(ADR-0076 決定1) |
| 既にマークを持つ節を、読まずにマーク済みとする | マーク済みは、節のすべての規定にマークがあると登録者が判断した記録である |
| 他節で追う(`elsewhere`)と登録したが追うマークが無い節を、理由だけ直す | 「他節で追う」の表示が、実態と食い違う |
| 対象にしない(`none`)の表示が実態と食い違う節を、理由だけ直す(第3章 3.12.2、附属書D の 4 節ほか) | 「対象にしない」の表示が、実態と食い違う。表示を減らす向きの誤りである |
| 第7章 7.9.5 要求事項5 と 7.4 制約5 を、ともに制度設計へ揃える | 表示を減らす向きになる。件数を数える部分は集約に乗る |
| 第7章 7.7.1 に、ADR-0096 の適用として `plan=adopter` を付ける | 採用済みの ADR の範囲を、棚卸しの担当の読みで広げない。`plan=scheduled` で登録し、名指した Issue で決める |
| 内部監査の観点と記録の定めを、ADR-0116 決定6 の範囲として制度設計に残す | ADR-0116 決定6 が制度設計としたのは、抽出の対象の選定だけである。採用済みの ADR の範囲を、棚卸しの読みで広げない |
| 「恒久層に登録します」(第6章)に `undelivered` のマークを足す | スキルが働きを運んでいる。降りているものを、降りていないと表示することになる |

### 降ろし先

| 案 | 採らなかった理由 |
| --- | --- |
| 合う降ろし先が無い規定に、近い降ろし先を当てる | 規定と関係の無い置き場が、台帳に載る(ADR-0076 が `planned` を置いた理由) |
| 近い降ろし先を仮に当てたまま残す(IMPL-0708・0718、IMPL-0960〜0962) | 同上。予定の降ろし先を足して付け替える |
| 既存の採用済みの降ろし先の説明を広げて当てる(会議体の議題の限定) | 近い降ろし先を当てることになる |
| 登録簿に新しい状態(区分済み・降ろし先未定)を足す | 登録簿の書式(ADR-0076)と検査の変更を要する。降ろし先の裁定で解ける |
| 予定の降ろし先を足すことを、重の審議とする | 重に当たるのは、採用者に委ねる選択である。未達の表示を足すことは、新しい義務を課さない |
| 合う降ろし先が無い節を、未棚卸しのまま閉じる | 未棚卸しの表示が残り、棚卸しを終えたと表示できない |
| 実物が在るのに登録が欠けている置き場の規定を、後継の Issue へ送る | 置き場は実在し、登録が欠けているだけである |
| 成果物ごとの手引きを降ろし先に登録せず、`undelivered` のままにする | 降りている規定を、降りていないと表示することになる |
| 手引きの「レビューの観点」を、運ぶものに数えない | 同じ形の補助ファイル(ゲートごとの補助ファイル)と、基準が割れる |
| 観測の出力の降ろし先(`flow-observation`)を分ける | 同じ観測の仕組みの出力で、置き場が同じである |

### マークの属性

| 案 | 採らなかった理由 |
| --- | --- |
| 棚卸しの中で、新しいマークを `plan=adopter` にする | 採用者に委ねる理由を、ADR に書く必要がある。棚卸しの担当の判断にしない |
| 棚卸しの中で、新しいマークを `check=machine` にする | 違反と適合の対の試験が要る。試験を足すことは棚卸しの外である |
| 降りた規定と降りていない規定を、未達のまま1件に束ねて残す | 降りている規定を降りていないと表示するのも、表示と実態の食い違いである |
| 降りている規定を、未達のまま残して開示する | 同上 |
| `issue=` の仮の名指し(#324)を禁じる | `plan=scheduled` は `issue=` を要する。棚卸しの途中で、後継を起票し続けることになる |
| 適用範囲の検査に掛かったマークの `note` を、一律に除外へ登録する | 除外は誤検出に限る。`note` の言い回しを改めて通した |

### 第2章 2.10.5 の計画容量の上限

| 案 | 採らなかった理由 |
| --- | --- |
| 企画書の様式(IMPL-0373)へ降りたものとして扱う | 様式は合意の時点の値を運び、合意の後の追加を運ばない |
| 制度設計のまま、降ろさない理由を登録簿に書く | 降りていない事実が、台帳に出ない |
| 本件で機械の検査にする | 入力の置き場が定まっていない。違反と適合の対の試験と、準拠テンプレートの変更を要する |

### 進め方と条文

| 案 | 採らなかった理由 |
| --- | --- |
| 398 節を1人の担当で仕分ける | 文脈が積もる。ADR-0076 も、一度に全節を確定させないことを選んだ |

## 影響

- 採用組織への新しい義務は無い。条項と準拠テンプレートは変えていない
- 規約の「対象の棚卸し」に、小節「区分の確かめ方」と EV-0270 が加わる。「棚卸しの残りは、章ごとの Issue で進めます」は、終えた事実と集計へ改まる
- 登録簿は、マーク済み 387 節・判定基準の表 7 節・対象にしない 171 節(説明 94・所在は他節 67・制度設計 6・課さない 4)・未棚卸し 0 節になった(2026-11-15)
- **降りていない規定の件数が増えた**。実装マークは 519 件から 966 件に、降りていない規定は 104 件から 333 件になった。うち降ろし先が予定のものは 37 件から 103 件である。増えたのは、棚卸しで規定が見つかったためである。件数は、合否にも警戒の条件にも使わない
- #324 を仮に名指すマークが 205 件ある。#324 を閉じる前に、領域の合う open の Issue へ付け替える(`npm run impl:issues -- --issue 324` が 0 件になること)
- 棚卸しで見つけた条文の食い違いの候補は、本件で直していない。事実だけを記録し、既存の open の Issue で扱う
  - CL2 の自律レベルの上限: 第8章 軸E の表と、附属書F F.3
  - 第2章 2.8 の文と、G-1 の前提条件の表
  - 第6章「レビュープロセスの流れ」と、第3章 3.10.7・3.10.8
  - 附属書B が名指す `formalize-criteria`(準拠テンプレートに無い名)
- 区分の誤りは残りうる。登録者と突合の担い手が同じ読み落としをした節は、どちらの確かめにも現れない
