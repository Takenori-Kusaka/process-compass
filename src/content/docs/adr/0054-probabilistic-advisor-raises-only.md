## ステータス

採用(2026-09-23)

## コンテキスト

オーナーから、TypeSafe AI の **Jev** を「ユーザの実行フェーズなどの判定AI」として準拠テンプレートへ組み込めないか、という検討依頼がありました。

本標準で「判定」は、人が行うゲート判定を指します。以下では、この部品を**助言AI**と呼びます。

### Jev の性質

Jev は 2026-09-15 に early access で公開されたモデルです。提供者はこれを System One モデルと呼んでいます。

- **出力**: 文章を生成しない。状態(テキスト)と型つきの問い(Choice / Score / Noul)を受け取り、選択肢ごとの確率と確信度を返す
- **応答時間と価格**: 応答は数百ミリ秒。価格は入力 $0.042/100万トークンで、出力は無料
- **提供形態**: 米国でホストされる API だけで、SLA はない
- **決定性**: **決定的ではない**。提供者は決定性ではなく一貫性を設計目標にしている
- **言語**: 英語が主な学習言語で、CJK の精度は同等でないと明記されている

### 標準は、確率的な判定を置ける場所を既に限っていた

**新しい規定は要りません**。次の既存の条項で、置き場所は決まっています。

| 条項 | 内容 |
| --- | --- |
| 5.5 | 価値判断・技術判断・理解の確認・記録の確認は、人が担う |
| 5.7.4 | 記述の実質性を機械的に判定して承認の可否を決めてはならない。自動的な判定は、人への提示(注意の喚起)に限る |
| 5.8.3 | 挙動の非決定性を隠す目的の実装は、AI に担わせない |
| [G-5 の設計方針](/process-compass/phase4-process-design/gate-criteria/) | AI による事前審査を合否条件にしない。**注意を向ける材料として提示し、合否には用いない** |
| [Label Mailbox](/process-compass/phase5-implementation/label-mailbox/) 原則3 | 付与した側がラベルの意味に責任を持つ |
| [ADR-0053](/process-compass/adr/0053-irreversible-by-criterion-not-enumeration/) | 第三者への送信は、取り消せない時間帯が生じる操作である |
| 3.12.3 | 新しいモデルは、基準集合での回帰評価と AI運用担当者の記名承認を経てから導入する |
| [エージェントの追跡と統制](/process-compass/phase5-implementation/agent-trace-control/) | 本標準は特定の製品を指定しない |

### テンプレートで工程を判定している箇所

工程を機械で判定している箇所は、テンプレートにありません。

- 会話の中のエージェントが、CLAUDE.md を読んで解釈している
- 記録から決定論的に読める状態もある(機能仕様の `status`、`docs/gates/` の判定記録)
- 一方で、**発話が何を求めているかは記録から読めない**

### 実測

合成した日本語の発話240件で評価しました。対象は工程10種と注意6種です。注意は、取り消せない操作・統制の弱化・技術判断・禁止事項1・2〜5 にあたります。

| 方式 | 工程の正解率 | ECE |
| --- | --- | --- |
| Jev(jev-1.13.0、質問文は英語) | 87.9% | 0.051 |
| Jev(質問文は日本語) | 83.3% | 0.054 |
| Claude Haiku(一括分類) | 84.2% | 0.080 |
| キーワード規則 | 55.8% | — |

閾値は奇数番の120件で決めました。偶数番のうち、フックが送る117件で確かめた値は次のとおりです。

- **工程**: 正解率は84.6%。確信度0.8以上だけを出すと、対象は全体の76.1%。その中の正解率は95.5%
- **注意**: 注意ごとの再現率は67〜100%。注意の要らない発話の6.9%で、注意が出た
- **揺れ**: 同じ発話を3回送ると、工程を出すかどうかが6.8%の発話で変わった
- **遅延**: p95 は344ms(日本から計測)

質問文の言語と方式は240件全体の結果で選んだため、偶数番の値もこの選択からは独立していません。

**正解ラベルは Claude 3者の合議で作ったもので、人は確認していません**。詳細は research の評価メモにあります。

## 決定

### 1. 判定AIの出力は、引き上げ方向の助言にだけ使う

次のことには使いません。

- ゲートの判定・承認
- 遮断
- 完了方向のラベル遷移(`state:dev-done` / `state:ready-to-merge` ほか)と、ラベルの自動付与
- 「該当しない」という結論

注意が出たとき、エージェントは発話が該当するかを自分で確かめます。該当すれば、既存の引き上げの経路(`state:needs-*`)に従います。

**注意が出ないことを、問題が無いことの根拠にしません**。

これは 5.5 / 5.7.4 / 5.8.3 の適用です。新しい規定ではありません。

### 2. 準拠テンプレートへ同梱し、既定は無効にする

`UserPromptSubmit` フック(`phase-advisor`)として同梱します。

案件で有効にするには、次の3つの記録が要ります。3つがそろうまで、フックは送信しません。**実装で担保します**。

あわせて、送信先を次の条件で絞ります。

- 送信先は、フックのコード内の許可リストに載ったものだけとする
- 決裁記録に書かれた送信先と一致しなければ送らない
- 秘匿情報らしき文字列を含む発話は送らない

| 記録 | 決める人 | 根拠 |
| --- | --- | --- |
| 外部送信の決裁 | オーナー | ADR-0053。第三者への送信 |
| ツールの採用 | AI維持管理者 | 外部ツールの採用可否 |
| モデルの採用 | AI運用担当者 | 3.12.3。評価セットでの回帰評価と記名承認 |

### 3. 版を固定し、閾値の較正は人が行う

- 版は `jev-1.13.0` に固定する。**応答の版が要求と異なる場合は、助言を出さない**
- 閾値は評価で決めた初期値である。**実績から自動で更新しない**
- 版を切り替えるときは評価セットで測り直し、現行との差分を記録する

### 4. 記録から導けることは、コードで判定する

実装の依頼に機能 ID があるときは、`docs/gates/` に G-4 判定記録があるかをコードで照合します。分類器には尋ねません。

分類器に尋ねるのは、**記録から読めない発話の意図**だけです。

### 5. 送信先を特定製品に固定しない

送信先は、System One 互換の API として差し替えられるようにします。Jev は参照実装として既定値に置きますが、**無効のまま配布します**。

送信先を変えるときは、次の2つが要ります。

- オーナーの決裁のやり直し。送信先ごとに所在国・保持・学習の扱いが違うため
- 許可リスト(強制層)の変更

### 6. G-5 と `/process-init` には入れない

- G-5 の検査(spec-lint)には組み込まない。非決定的な判定を必須の検査に入れると、同じ差分の合否が揺れる
- `/process-init` の5軸の推定にも使わない。5軸は利用者の状況であり、推測で埋めることを禁じている

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 採らない。記録から決定論的に導く仕組みだけを置く | 発話の意図は記録から読めない。キーワード規則は、工程の正解率が55.8%、注意の再現率が0〜43%で、代わりにならなかった |
| Claude(Haiku)を command フックから呼ぶ | 委託先は増えない。しかし次の3点で採らなかった。(1) 本体のエージェントも Claude であり、確認する側と共通の原因を持つ(テンプレートの README が G-6 で述べる理由と同じ)。(2) prompt 型のフックは許可か遮断しか返せず、助言を差し込めない。(3) command 型にすると、Anthropic の API キーが別に要る |
| Jev で遮断・自動ラベル付与・G-5 の必須チェックを行う | 5.7.4 と G-5 の設計方針に反する。決定的でないため、同じ発話や差分で結果が揺れる |
| 既定で有効にして配布する | 案件ごとに決めるべき外部送信の可否を、テンプレートが先に決めてしまう(ADR-0053 決定4)。「AI 利用の制約」で認可済みツールだけを選んだ案件とも衝突する |

## 帰結

- 準拠テンプレートに次のものが入る
  - `.claude/hooks/phase-advisor.mjs`
  - 適合性評価のスクリプトと評価セット240件(`scripts/advisor/`)
  - 設定の `phaseAdvisor`(既定は無効)
- `/process-init` で構成を作り直しても、`phaseAdvisor` の値は引き継がれる
- 誤警報と取りこぼしが起きる。評価では、注意の要らない発話の約7%で注意が出た。注意ごとの再現率は67〜100%だった
- 評価の正解ラベルは AI が付けたものである。案件で使い始める前に、人の確認を含めて測り直す必要がある

:::caution[暫定 EV-0040 / 見直し 2027-03]
**対象**: 決定2・3(助言が注意を向ける材料として機能し、初期値の閾値で誤警報を許容できる水準に収まるという判断)。

**根拠の水準**: E1(間接)。

**根拠とした事例**: 合成した日本語の発話240件での実測。正解ラベルは Claude 3者の合議で、人の確認はない。**案件での利用実績は、まだ無い**。

**差し替え条件**: 有効にした案件で、次の2つを数える。(a) 注意が出た件数と、そのうち人が妥当と判断した件数。(b) 人が事後に「注意すべきだった」と判断したのに、注意が出なかった件数。(a)・(b) を合わせて30件たまった時点で閾値を見直す。
:::
