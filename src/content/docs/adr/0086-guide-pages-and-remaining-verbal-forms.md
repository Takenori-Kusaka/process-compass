## コンテキスト

[#316](https://github.com/Takenori-Kusaka/process-compass/issues/316) は、#302〜#310 の規定の表現形式の整理で残った事項を問いました。フェーズ5・6 の頁の種別、文末の「できません」、平叙の「〜します」、参考の附属書の要求に見える文、様式と記入例、禁止事項の番号、「逸脱」の用例です。指摘をそのまま条項にせず、調査(内部1本・外部1本)、会議体(起草・現場・品質保証と監査・規格・擁護の5つの立場)、突合の順で扱いました。記録は `research/316-deliberation/` にあります。議長の裁定は `decision.md` の R-1〜R-7 と 1.5 節です。

判断の軸は、監査人と採用者が文面と所在だけで要求事項かどうかを一意に決められることです。意味の判定を読み手に委ねる形より、形で決まる形を採りました。形で決まる規則は、機械で検査できます。

### 頁の種別が3つあった

ADR-0063 は、フェーズ5・6 を「本文に従属する」としました。規定とも参考とも読めない第3の区分です。フェーズ5・6 の頁には、要求の文末、実装マーク(65件)、本文が「によります」で内容を委ねる引き、条項番号に似た独自の番号(「第5章 4.5.2」の衝突)が残っていました。頁にしか無い定めの中には、本文に根拠の無い緩める向きの定め(緊急の修正で事業ゲートの事前決裁を事後報告へ切り替える)もありました。

### 文末の「できません」が、禁止と能力の否定を兼ねていた

本文と規定の附属書の文末の「できません」は、禁止と能力の否定の2つの意味で使われていました。#302〜#310 で 29 件の禁止がこの形に紛れていました。

### 大量の書き換えで、意味を取り違えるおそれがあった

平叙の「〜します」(420 件と「とします」51 件)、「できません」(64 件)、参考の附属書の平叙の文、「逸脱」の用例(336 件)を書き換えるにあたり、擁護の委員は、大量の書き換えで意味を取り違える懸念を示しました。文脈を分けた2つの AI の読み手が、互いの結果を見ずに振り分けました。読み手の一致率は、平叙の文で 93.8%(471 文のうち 442 文)、「できません」で 93.8%(64 文のうち 60 文)、参考の附属書で 82.3%(524 文のうち 431 文)、「逸脱」で 76.8%(336 件のうち 258 件)でした。割れた文は、実装の担当が本文を読んで決め、結果と理由を `research/316-deliberation/implementation.md` に残しました。2つの読み手は検出の層であり、確定に数えません。確定は、変更を取り込む人の差分のレビューで行います。

## 決定

### 1. フェーズ5・6 の頁を、全体として参考(手引き)とする

第1章 1.8 に次を書きます。

- フェーズ5・6 の記述は、適合の条件に数えない。種別を頁と節の単位で分けない
- 本文の要求事項を緩めず、要求事項を加えない。食い違う場合は本文による
- 本文と規定の附属書は、フェーズ5・6 を「〜参照」で引く。要求事項の内容を頁へ委ねない
- 頁に要求と禁止の文末を置かない。置かない文末は、1.7.1 の表の要求・禁止の形のうち、平叙の動詞文(「〜します」「〜しません」)を除くすべてである。頁の平叙の動詞文は、説明として読む。本文の要求を述べるときは、同じ文の中で本文の所在を引く
- 頁では、条項番号に似た独自の番号を振らない
- 実装マークは、番号を保ったまま本文の条項の側へ移す。頁には実装の所在だけを残す

頁にしか無い規範は、次の4つに振り分けました。

| 種類 | 扱い |
| --- | --- |
| 委任型の引き | 内容を本文へ上げた。製品の名前と道具の語は上げない |
| 頁が独自に置いた定め | 1件ずつ、本文へ採るか課さないと明記するかを決めた。本文に根拠の無い緩める向きの定めは削った |
| 本文の写し | 本文の所在を引く形にした |
| 実装の所在を示すだけの引き | 「参照」の形にした |

テンプレートの持ち込みの3つの定め(ADR-0085 が手引きの中に残したもの)は、第1章 1.10.3 の要求事項へ上げました。3つの行には、適用範囲「(適用: 準拠テンプレートを用いる案件)」を行の中に書きます。取り込んだテンプレートの識別は、道具の語(コミット)を外し「版管理の識別」と書きます。

附属書H(規定)が観測の担当として番号で引いていた内部監査の観点は、附属書H H.3「内部監査で確かめる観点」へ上げました(観点1〜6・10〜20・22・23)。番号は過去の監査記録との対応のために引き継ぎ、振り直しません。附属書H が引かない観点7・8・9・21 は、プロセス内部監査の頁に手引きの例として残し、本標準は課さないと書きました。関係する暫定マーク(EV-0060・EV-0076・EV-0080)は附属書H へ移しました。

`lint:provisions` に3つの検査を足します。番号は[規定の表現形式の検査](/process-compass/community/provision-forms/)の「検査の一覧」の表と、スクリプトの見出しの番号にそろえます。検査8 はフェーズ5・6 の頁の、上の列挙の文末のうち同じ文の中に本文の所在が無いもの、検査9 は本文と規定の附属書がフェーズ5・6 を「による」「に規定」「に定め」「が正本」で引く文、検査10 は「第N章 X.Y」の X が N でない引用です。同じ文の中の引用が、その文の根拠となる条項かどうかを、機械は確かめません。このことを第1章 1.7.4 に開示します。

### 2. 文末の「できません」を、本文と規定の附属書で使わない

- 禁止の意味の文は、禁止の文末へ改める
- 能力・不可能の文は、1.7.1 の表に新設した「可能性・能力の否定」の形(「〜は不可能です」「〜する手段がありません」)へ改める
- 文中の「できない」(連体修飾など)は対象の外とする
- 肯定の「できます」は、ADR-0063 の全件の読みの記録があるため維持する
- `lint:provisions` に文末の検査(検査7)を足す

### 3. 平叙文を要求として読む規則を保ち、説明の類にメタの文だけを足す

ADR-0063 決定2(平叙の動詞文を要求として読む)を維持します。第1章 1.7.2 の説明の類に「メタの文」を1つだけ足します。主語が本標準またはその部分(本章・本節・次の表・図)で、述語が記述の動詞(規定します・示します・定義します・扱います・述べます)である文です。要求の動詞(求めます・課します・要求します)の文は、この類に入りません。既存の類「主語が本標準の文」も、述語が記述の動詞の場合に限ると改めます。

1.7.1 の表の要求の行に「〜を要します」「〜を求めます」を、不必要の行を、こと止めを規定の文末に使わないことを足します。因果の文は「〜ためです」「〜ことがあります」の形へ書き直します。注記の中の要求は、注記の外へ出します。規定の文書の注記の中の要求・禁止の文末は、検査12 が検出します。

### 4. 参考の附属書の要求に見える文を、4つの基準で本文へ戻す

本文へ戻す基準は次の4つです。

- (a) 本文が根拠として引いている
- (b) 適合・ゲートの判定・記録の有効性を左右する基準か記録の事項を定めている
- (c) 実行主体の挙動を止める、または範囲を限る
- (d) 本文と値が食い違う

どれにも当たらない文は、推奨の形か本文の所在を引く形へ改め、課さないことを明記しました。

- 第5章に 5.8.6(実行時の拒否と、エージェントの操作の確認)を新設し、附属書E E.6 とフェーズ5 の頁にあった実行時の拒否と、AI レビューの指示の置き場を本文へ移した
- 附属書I I.11 の要件⑥⑦を本文へ移した。要件①〜⑤ は採用の判断だけに掛かるため附属書I に残し、推奨の形へ改めた
- 附属書E E.7 は本文 3.12.10 を引く形にした
- 附属書C の「1〜3行」を G-6 の「1〜2文」へ合わせた
- 5.8.5 の禁止事項の番号の正本を本文とし、附属書E E.9 が引く形にした
- 附属書G を同じ4つの基準で振り分け、推奨の形か本文の所在を引く形へ改めた。附属書H が依っていた G.1 の条件は、第6章「決裁制度への提示」の規定1・2 を引く形にした
- 第4章 G-6 に基準6(変更の検証の方法と結果の記録)を新設した。既存の基準に同じ内容は無かった。基準 (b) に当たる。判定者に新しい差し戻しの理由を与える、締める向きの変更である。実装マークは IMPL-0335(G-6 のスキル。確かめる者は G-6 の判定者)
- 5.8.6 の要求事項は、拒否が働かずに起きた秘密情報への接触と想定外の通信について、影響の確認を課さない。附属書E E.6 の旧版の「影響を確認する」は、基準 (a)〜(d) のどれにも当たらないためである。この場合の扱いは組織のインシデント対応に委ねる。拒否を実装していない状態は、要求事項1 を満たさない

### 5. 記入例を見本と宣言し、受入基準と前提の記号を分ける

- 第1章 1.7.2 に、記入例とひな形は採用者の文書の見本であって本標準の規定ではないと書く
- 附属書B に、受入基準の文末の形は組織が定めると書く。見本は「〜しなければならない」「〜してはならない」で示し、こと止めを使わない。テンプレートの機能仕様の記入例と型の名を附属書B にそろえる
- 受入基準の識別子を `AC-N` とし、機能をまたいで引くときは機能の ID を前に置く(`F-NNN/AC-N`)。標準の例の `CR-N` も改める
- 前提の充足状態の記号を `AS-0 / AS-1 / AS-2` へ改める。旧版の記号で書いた台帳は読み替える
- テンプレ4 とテンプレートの判定記録に「再提出の期限」の欄を足す(IMPL-0328)

受入基準の側を `AC-N` に戻したのは、テンプレートのスクリプトと様式が既に `AC-` を読み書きしているためです。前提の側の記号を改める方が、影響が小さくなります。記法そのものは、ADR-0075 のとおり組織が定めます。

### 6. 禁止事項の番号を、一覧の所在で修飾する

番号の正本は本文の2つの一覧(第5章 5.8.5、第8章のテーラリングの禁止事項)です。引くときは常に一覧の所在で修飾します(「5.8.5 の禁止事項3」「テーラリングの禁止事項7」)。廃した番号は再利用しません。テンプレートは独自の通し番号を持ちません。

- テンプレートの CLAUDE.md の旧6 は第4章 G-5 の「基準値と除外設定の変更」を、旧9 は 5.5.1 (c) を引く
- 旧7・旧8 は、第3章 3.5.5 の要求事項(旧7 は要求事項3、旧8 は要求事項2)を引く「ラベルによる引き渡し」の表へ移す。本文 3.5.5 へ上がったため、本文の要求である。番号は持たない
- 「テンプレートの運用の規則」の表には、本文に根拠の無い「書けるところまで分解する」だけを残す。本文の要求ではないと明記する
- 修飾の無い「禁止事項N」を検出する検査(検査11)を足す

| 「逸脱」 | 1.4 の定義は変えない。事象・一般の意味の用例を、文脈を読んで改める(一括の置換はしない)。改めた句を廃した言い回しの登録簿へ載せる |

「逸脱」の改名は次のとおりです。

| 旧 | 新 |
| --- | --- |
| 委任の範囲の逸脱、抜き取りで見つかる逸脱 | 委任の条件に反する変更 |
| 意図的な逸脱 | 承知の上の承認(Just Culture の区分の文脈では「意図的な違反」) |
| 基準・期日・閾値・予算の逸脱 | 基準の不充足、期日・予算の超過 |
| R2 以上の規範の逸脱 | R2 以上の規範を満たさないこと |
| 定義と衝突する本文の用例(記録が無いことを指す) | 記録の欠落 |
| 1〜2名の体制の席の兼務など、テンプレートの用例 | 列挙に無い離脱 |
| 外部の概念の訳(逸脱の規範化) | 逸脱の常態化(normalization of deviance) |

`[逸脱]` の札は、閉じた列挙の逸脱に限ります。列挙に無い離脱には `[列挙に無い離脱]` の札を設けます。札の名に「離脱」の1語を使わないのは、第1章 1.4 が「離脱」を逸脱と列挙に無い離脱の両方を含む上位の語として使うためです。構成の `deviations[]` が両方を持つ場合は、項目ごとに区分(`category`)を記録します。データ形式を変えるため、強制層の変更として開示します。合算の語は「未達のゲート・逸脱・列挙に無い離脱の数」のように3つを並べて書き、「逸脱」の1語で列挙に無い離脱を含めません。

札の意味の変更は、移行で統制を緩めません。層1 の条件に `[列挙に無い離脱]` の札が1つも無い場合は、`[逸脱]` を旧版の意味(逸脱と列挙に無い離脱の両方)で読み、その旨を注記に出します。出荷は止めません。`[列挙に無い離脱]` を足して記名し直した層1 だけを、新しい意味で読みます。記名済みの層1 の「受容しない条件」の範囲を、記名した人の決定なしに狭めないためです。実装マークは IMPL-0334(出荷の証跡の集約。違反と適合の対の試験つき)です。

## 検討した選択肢

採らないと決めた選択肢と、その理由です。

| 選択肢 | 採らない理由 |
| --- | --- |
| フェーズ5・6 を規定とする | 製品の名前に依存する設定が要求事項になり、1.7 の前文と当たる |
| 頁ごと・節ごとに種別を分ける | 札の付け忘れがそのまま規範の漏れになる(ADR-0063 の理由)。IEEE は箇条単位の参考の札を禁じている |
| 能力の否定に「できません」を残す | 能力の否定と禁止を読み手が文脈で分ける形が残る。#302〜#310 で 29 件の禁止が紛れたのと同じことが再び起きる |
| 平叙文を ISO の向き(現在形は陳述)で読む | 全件を書き直さない限り、要求が説明へ落ちる向きの誤りを生む |
| 因果の文を説明の類に加える | 形で要求と区別できず、要求を言い逃れる根拠になる |
| 参考の附属書の平叙の文を一括で書き換える | 本文へ戻すべき文(判定の基準、実行主体の挙動を止める文)が推奨へ落ちる。4つの基準で1件ずつ振り分けた |
| 禁止事項に新しい文字の接頭辞を付ける | 所在で修飾する方が、規格の引用の作法と合う。接頭辞は第3の番号体系を増やす |
| 初期化の PR を本文の要求にする | PR を作れない環境がある。PR を経ないコミットの規則(G-7)で足りる(ADR-0068) |
| 「逸脱」を一括で置換する。「不適合」「離脱」へ改名する | 一括の置換は定義どおりの用例まで変える。「不適合」は適合の区分と紛れる。「離脱」は「列挙に無い離脱」と紛れる |
| `[逸脱]` を新しい意味へ即時に切り替える | 記名済みの層1 の受容しない条件が、記名者の決定なしに狭まる。緩める向きの変更を記名なしに行うことになる |
| 札の名を `[離脱]` にする | 「離脱」は逸脱を含む上位の語であり、札が列挙に無い離脱だけを指すと読めない |
| 常駐の規則の照合から、所在の列を外す | 案件が禁止事項の所在を書き換えても照合が落ちない。ADR-0084 が核から外すのは「止める仕組み」と「例」の列だけである |
| 受入基準の側の識別子を `CR-N` のまま保ち、前提の記号を残す | テンプレートのスクリプトと様式が `AC-` を読み書きしており、標準の例とテンプレートが食い違ったままになる |
