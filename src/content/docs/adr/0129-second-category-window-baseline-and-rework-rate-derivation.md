## コンテキスト

[#350](https://github.com/Takenori-Kusaka/process-compass/issues/350)・[#349](https://github.com/Takenori-Kusaka/process-compass/issues/349)・[#348](https://github.com/Takenori-Kusaka/process-compass/issues/348)・[#340](https://github.com/Takenori-Kusaka/process-compass/issues/340) は、第2区分(差し戻し率・手戻り率)の検知と、自己修正のループの強制の範囲を扱いました。審議は軽(起案と反対の2委員)で行い、記録は `research/340-350-deliberation/` にあります。

- 差し戻し率の分子は、宣言行(`G-6: 差し戻し / 基準 N`)を持つ承認レビューに限っていた。宣言行の無い CHANGES_REQUESTED を数えない理由が、「番号を引かない」という別の軸に置かれていた
- 観測の窓は2か月に固定されていた。5.4.6 は窓を長くすることを許すが、構成に値を持つ場所が無かった
- 手戻り率は準拠テンプレートが集計せず、第2区分の2本のうち1本が機械で発火しなかった
- 自己修正のループの強制は `start` を呼んだ単位に限るが、その範囲が IMPL-0272 に書かれていなかった

## 決定

### 1. 宣言行の無い承認レビューを数えない理由を「判定記録ではない」に置く

宣言行の無い承認レビュー(ホスティングの CHANGES_REQUESTED だけのものを含む)は、差し戻し率の分子に数えません。理由は、宣言行を持たないレビューが判定記録ではないことです(第4章「判定の成立」の記録の媒体)。番号の有無と、宣言行の有無は別の軸です。

数えていない差し戻しの要求の件数を、`/pit`・保証の開示の差し戻し率の文・0%の継続による停止の理由に出します。記録用ブランチを読めないときは「読めない」と出し、0 件と出しません。

### 2. 観測の窓を構成の欄にする

- 構成の `observationWindow` に整数の月数を持つ。下限は2、未設定は2。準拠テンプレートの構成の欄の設計として、差し戻し率と手戻り率の両方に使う共通の窓とする。標準の手戻り率の集計の既定(第4章 要求事項3。四半期・30件)は変えない
- 最小標本数は欄を持たない(30件に固定)。構成の形で「下げる」を表現できないようにする
- 窓を長くするのは緩める向きとする。準拠テンプレートでは、判定不能の窓を長くすると停止が解け、評価可能な窓を長くすると0%の継続が薄まって発火が遅れるため、どちらも委任を広げる。向きを問わず、決定した者の記名と理由を要し、値・記録した日・決定した者・理由を構成に残す
- 値は記録した日より後の評価の日から当てる。前の評価の日へ遡って当てない。窓を長くしても、既に発火した引き下げは戻らない。記録した日は、入口を実行した日である(変化点の発効日を過去に置いても、実行した日が刻まれる)
- 現在の状態の窓も、直近の評価の日に効く値で数える。窓を長くした日から次の評価の日までは前の値で数え、判定不能の停止は新しい窓が当たる最初の評価の日から解ける。表示は、いま数えている値を出し、まだ効いていない新しい値を「次の評価の日から」で併記する
- 窓の長さを `/pit` と保証の開示に常に出す。既定より長いときは、決定した者と日付を併記する
- 窓に上限を置かない。理由は2つある。上限の値を支える実証が無いこと(EV-0259)と、窓の長さを常時開示することである

### 3. 手戻り率を算出する

- 母数は、窓の中の、登録した変更種別に入る取り込みの変更を持つタスク(トレーラ `Spec: F-NNN / Task-N`)。単位はタスク
- 分子は、次のどちらかに当たるタスク。(ア)既定ブランチの第1親の履歴に、同じタスクを指すトレーラの取り込みが2つ以上ある。(イ)実装計画の履歴のいずれかの版で、状態が「やり直し」だった。(イ)を履歴の和にするのは、状態が「やり直し」の後に「着手」「完了」へ進むため、現在の版だけを読むとやり直しを終えたタスクが分子から消えるためである。委任された変更が計画表の行を書き換えても、履歴に残った「やり直し」は消せない
- 基準値は構成の欄(`reworkBaseline`。百分率。既定値なし)。観測の窓と同じ形で記録し、同じ効力日を持つ。上げるのは緩める向きである
- 母数が最小標本数(30件)に達し、比が基準値を超えた評価で、評価の日より後の登録の判定まで種別を止める。評価の日より後に作られた記録は、その評価の日へ遡って数えない
- 基準値が未設定、または母数が最小標本数に満たないときは、止めずに「発火しない」と表示する。履歴を読めないときは「読めない」と表示する
- 表示には、算出した値・母数・分子の内訳・基準値・判定の状態と、数えていない残りを必ず出す
- 5.4.6 の分子の定義は変えない。準拠テンプレートの算出は、その定義の部分集合である

### 4. 自己修正のループの強制の範囲を明記し、ロックの外の反復を採用者に委ねる

準拠テンプレートの強制は、`start` を呼んだ単位だけです。この範囲は IMPL-0272 へ明記します。`start` を呼ばない反復は、テストを先に書く作業と区別できません。そのため検知と遮断のどちらも行いません。要求事項5 は、自律実行を解禁する採用者への規範です。強制できない環境では、自律実行を解禁しません。AI のレビューの往復(IMPL-0279。ADR-0084)は同じ構造のため、同じ扱いとします。附属書H の3.12.10 へ、降りていないことを1行足します。

## 課さないと決めたこと

「書かれていない」と「課さないと決めた」を区別するために、次を記録します。

- 観測の窓の上限を置くこと。上限の値を支える実証が無い
- 最小標本数の欄を持つこと。上げる向きは検知を遅らせ、下げる向きは標準が許していない
- 宣言行の無いレビューを差し戻しの分子に数えること。分子の定義の変更で、重の審議に当たる
- PR 本文・コメントから基準の番号を抜き出して数えること。自由な文の意味の判定であり、機械で閉じない
- 手戻り率の基準値に既定値を置くこと。根拠が無い
- 手戻り率を計画表の現在の行だけで数えること。やり直しを終えたタスクが数え漏れる
- 計画表を委任の範囲から外すこと。計画表を更新する変更がすべて委任から外れる
- `start` を呼ばない反復をフックで検知すること。テスト駆動の通常の作業と区別できず、警告が読まれなくなる
- テストの実行を `self-heal.mjs` 経由に限る義務を採用者に課すこと。新しい義務で、重の審議に当たる

## 重の審議へ送ったこと

次の2点は、採用者への新しい義務、または停止の表の改訂に当たるため、本 ADR では決めていません。

- 手戻り率が判定不能・基準値未設定のとき、登録した変更種別を止めるか(IMPL-0291。#348 を閉じずに残す)
- 自律実行を構成するとき、強制の手段の所在の記録を求めるか([#340](https://github.com/Takenori-Kusaka/process-compass/issues/340) を受け皿として開いたまま残す)

一発承認率・AI 生成行の短期書き換え率に観測の窓と最小標本数を掛けることは、後継の [#441](https://github.com/Takenori-Kusaka/process-compass/issues/441)(IMPL-0268)で扱います。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 手戻り率を算出しない | 第2区分の2本のうち1本が常に発火しない。採用者の手段の確かめは年次の内部監査だけで、毎月の評価に代わらない |
| 手戻り率をトレーラだけで数える | 不採用の後の再作成を、計画表に書かれた分まで捨てる理由が無い |
| 件数が0でない月は0%の発火を保留し、人が確かめる | 引き下げの手前に人の判定を挟む。ADR-0081 決定3 と #311 の裁定に反する |
| 解禁の記録に、強制の範囲の理解の確認を足す | 採用者への新しい義務に当たる。自由な文の記名は機械で閉じない |
| 窓の変更を過去の評価へ遡って当てる | 過去の0%の停止が消える |
| 窓・基準値を含む変化点で、発効日が今日より前なら拒否する | 1件の変化点にほかの欄(発効日を過去に置く正当な理由のある欄)が同居しうるため、正規の記録を妨げる。実行した日を刻めば遡りは閉じる |
| 判定の日の窓で判定可能になった時点で、判定不能の停止を即時に解く(その窓の0%も評価として扱う) | 評価の日が毎月であるという 5.4.6 の構えを崩し、判定の日ごとに評価が増える。遡らない原則の例外が1つ増える |
| 標準の手戻り率の窓の既定を2か月へ変える | 根拠(EV-0146)は差し戻し率の継続の期間の値で、手戻り率の窓を短くする実証が無い。審議もしていない |

## 見直しの契機

- EV-0259 の見直し時期(2027-10)の到来
- 手戻り率の判定不能・基準値未設定で止めるかの重の審議の結論
- 窓を既定より長くした採用組織で、0%の継続の発火までの期間の観測が得られたとき

## 影響

- 準拠テンプレートの構成に `observationWindow`・`reworkBaseline` が加わる。どちらも省略でき、旧い構成の意味を変えない
- 手戻り率の基準値を置かない採用組織では、手戻り率は「発火しない」と表示され続ける。降りていないことは、IMPL-0291・IMPL-0518 の台帳で表示される
- 機械が確かめるのは算出と比較までで、計画表に書かれない再作成と、ロックの外の反復は、採用者の手段に委ねる
