## ステータス

採用(2026-11-19)。審議は重です。記録は `research/b22-deliberation/` にあります。一部置き換え: [ADR-0151](/process-compass/adr/0151-unselected-optional-check-not-failure-disclose-duration/) の決定1 のうち「テストの実行と秘匿情報の混入検査は、この扱いを受けない」(必須の段は test・secretScan)の集合を、条件つきで広げます。条件に当たる構成では、ミューテーション試験の段と規制要件の段も、空のコマンドを失敗にします。ADR-0151 の決定3 と決定4 は置き換えません。

## コンテキスト

- 所有者の方針(#445)は、安全・規制業の構成で G-5 の段のコマンドが空なら G-5 を失敗にする、である。現状は、規則 r-e-cl3 と r-c-regulated が注記として持つだけで、G-5 の入口に段が無い(IMPL-0763・0836・0930・0931)
- 附属書F F.4 の HR(強く推奨)は「しない理由を記録して省ける」。理由つきの省略を残すと、空の段が一文の理由で通り、方針が成り立たない
- 附属書F の適用の判定は F.2 の Q1 である。Q1 の回答は D-0 節16 の記名の記録として、準拠テンプレートが既に読んでいる(`cl-judgment.mjs` の `f2Q1Of`)。答えの書式は check-d0 が強制している。決定可能な条件である
- ADR-0200 決定1 の安全関連部の範囲の宣言(`safetyRelated`)は、準拠テンプレートに降りていない(IMPL-0594 は undelivered)。範囲(パス)の宣言であり、附属書F が案件に掛かるかの判定でもない
- 7.3 の対象は、ゲートの判定基準と、本標準の条項が 7.3 を名指して定めた事項に限る。G-4・G-5 の判定を実施しないまま進めるために 7.3 を用いない。実施した判定で個々の基準を満たさない場合は、条項が例外を認めないと定めた基準を除き、妨げない
- 集約 `gate-g5` は `failure`・`cancelled` だけを落とし、`skipped` を通す。既存のジョブの一部は、未設定の構成や push の経路で正当に skipped になる。skipped を一律に失敗とすると、その一部も落ちる
- 附属書H の表は、R1 の変更で変異試験を「必須。当該範囲を変更するたびに実行する」とする。この規定に実装マークが無かった

## 決定

1. ミューテーション試験の段は、D-0 節16 の「附属書F F.2 の回答」が「はい」で始まる案件と、安全重要度 CL3 の案件で必須とする。CL3 の判定は、記録の区分と構成の回答の高いほうによる。段のコマンドが空なら G-5 の失敗とする。Q1 を読めない場合(記録の欠落・書式の崩れ)は、G-5 では段を必須にしない。「判定できない」と注意に出す。記録の欠落は、既に止まる(G-1 の前は check-d0、G-1 の後は出荷の集約)。G-5 で重ねて止めると、構成の直後の全 PR が落ちる
2. 規制要件の段は、軸C が規制業の構成で必須とする。段のコマンドが空なら G-5 の失敗とする。照らす規則集は採用者が G-1 で定める
3. 安全重要度 CL2 で Q1 が「いいえ」の案件には課さない。G-7 基準7 は検証の記録を人が読む層として CL2 を含めたままとする。G-5 の段は実行を機械が止める層として、附属書F の適用(Q1)と CL3 に限る
4. 安全関連部の範囲の宣言(ADR-0200 決定1 の `safetyRelated`)を条件に使わない。降りていない宣言に依ると、条件そのものが降りていないことになる
5. 附属書F F.4 の HR のうち、決定1 の案件のミューテーション試験は、しない理由の記録で省けない。F.4 の表の本文は変えず、表の直後に注を置く。これは本標準の判断であり、規格の要求ではない。故障挿入試験を含むほかの HR の項目は変えない
6. ミューテーションスコアの閾値は、G-1 で案件が定めて記名する。本標準は値を置かない。決定1 の案件で閾値が未設定、または数値でなければ G-5 の失敗とする。ADR-0166 決定4(分量の上限の未設定を欠落に数えない)と分ける理由は次のとおりである。決定4 は、既定の値を持たないまま数えると全採用者の G-7 が落ちるためだった。本決定は、条件に当たる案件だけに掛かり、人身に響く
7. 段が空、または閾値が未設定のままの通過に、7.3 の例外承認を用いない。ミューテーションの段を実施し、スコアが閾値に届かない場合は、7.3 の例外承認の対象とする。そのために、附属書F F.6 が 7.3 を名指す。閾値を下げるときは、G-1 の記名をし直す。規制要件の段の不合格は、7.3 の対象にしない。法令・規制の要求を組織の例外承認で外す経路を作らないためである。規則集の見直しは G-1 の記名で行う。規則集の変更(規則の削除・除外)は、G-5 の「基準値と除外設定の変更」に当たるものとして扱う(適用: 軸C の規制業)。新しい義務だが、規制業に限り、適合の主張の信頼に響く
8. 新しい段は、G-5 の判定基準の8つに足さない。集約の合否に含める。条件に当たる構成では、段のジョブの結果が `success` であることを集約が確かめ、skipped を通過にしない。既存のジョブの skipped の扱いは変えない
9. 機械が確かめるのは、段のコマンドが空でないこと、閾値が数値であること、生き残ったミューテーションの一覧の所在が出力にあること、段のジョブの結果までとする。コマンドが実際に変異を作るか、規則集が実際に規制要件を照らすか、閾値の較正が実測に依るかは、機械で確かめない。人が確かめる(G-1 の判定者、G-6 の確認者)。EV-0329 で開示する
10. 規格を根拠に引かない。本標準の判断である。機能安全の規格が故障挿入とミューテーションを推奨度を段階づけた手法として挙げることは、二次資料による背景であり、条項番号を書かない
11. 故障挿入の独立の段(`faultInjection`)は置かない。CI で回る故障挿入(実行前の挿入。附属書F F.5 の分類)はミューテーション試験の段に含める。実行時の挿入とハードウェアによる挿入の結果は、F.7 の記録(様式09)へ試験項目ごとに書く。出荷判定者は G-7 基準7 で読む。**G-5 は、故障挿入の記録の有無を機械で見ない**。所有者の回答(2026-11-19)による。この開示は、附属書F F.6 と EV-0329 にも置く
12. ADR-0151 決定3 の「閾値を課さない」の閾値は、未実施の継続期間の閾値である。ミューテーションスコアの閾値とは別のものであり、本 ADR の決定6 と矛盾しない
13. 附属書H の表の、R1 の変更で変異試験を当該範囲の変更のたびに実行する規定(IMPL-1026)は、案件ごとの段(決定1)とは別の、変更ごとの規定である。本 ADR は、この規定と附属書F F.4 の R1 の列(R=推奨)の食い違いを裁定しない。実装マークで表示し、#445 に残す。所有者の答えが届いたら、それに従って直す

## 課さないと決めたこと

- CL2 の案件への一律の適用(附属書F の適用外へ義務を広げない)
- 決定1 の案件のミューテーション試験について、しない理由の記録による省略
- 標準が閾値の数値を置くこと(F.6 の「本標準は値を定めません」と自己矛盾する)
- 規制業へのミューテーション試験(規制業にミューテーションを課す根拠が無い)
- CL3 への規制要件の段(CL3 の根拠は安全であり、規制要件ではない)
- G-5 で故障挿入の記録の有無を機械が見ること
- 規制要件の段の不合格を 7.3 の例外承認で外すこと

### 採らなかった案 乙(故障挿入の記録を照らす段)

乙は、`faultInjection` を、外部で実行した故障挿入の記録(所在・日付・版)を照らす段として G-5 に置き、記録が無ければ G-5 を失敗にする案でした。実行時・ハードウェアの故障挿入の記録の欠けを、G-7 より前の G-5 で止められる点が利点でした(起案委員の案)。

所有者は甲(置かない)を選びました。採らなかった理由は次のとおりです。

- 照らすコマンドの実質(記録が実在するか、版が一致するか、中身が故障挿入か)は機械で閉じない。存在と書式を見る段は、常に成功する別名として置かれうる。影響の節と F.6 が道具の無い言語に許す、記録を照らすコマンドとの差は次のとおりである。本案の段は記録の存在と書式だけを見る。ミューテーションの段は閾値との比較と生き残りの一覧の所在を機械が見る
- 標準は、記録の在りかの書式を新しく決める必要が生じる。F.7 の記録(様式09)と二重になる
- G-5 の段が増える。実行時・ハードウェアの故障挿入の記録を出荷判定者が読む経路は、G-7 基準7 に既にある
- CI で回る実行前の挿入は、F.5 の分類どおりミューテーション試験に含まれ、決定1 の段が受ける

失うものは、G-5 で故障挿入の記録の有無を機械が見ないことです。実行時の挿入の記録の欠けは、G-7 まで見えません。この開示は EV-0329 にあります。見直しの条件は、実行時・ハードウェアの故障挿入の記録の欠けが G-7 まで見つからず、手戻りを生んだ件数です。

## 影響

- 附属書F: F.4 の表の直後に注を置いた。F.6 に必須の条件・7.3 の名指し・機械が確かめる範囲・故障挿入の記録を G-5 が見ない旨を足した。EV-0329 を置いた
- 第4章 G-5: 「判定基準を実装する検査と集約」の後に、新しい段を集約の合否に含める旨と、skipped を通過にしない旨を足した。判定基準の表は変えていない
- 第8章: 軸C の規制業に規制要件の段を足した。CL3 の欄の文言を、ミューテーション試験(実行前の故障挿入を含む)へ改めた
- 実装マーク: IMPL-0763・0836・0930・0931 の note を書き換えた(状態・plan・issue・review は保つ)。IMPL-1026 を新しく付けた(附属書H の R1 の変更ごとの変異試験。降りていない規定の表示であり、F.4 の R1 の列との食い違いは未裁定)
- 閾値割れの 7.3 の経路は、降りている IMPL-0996(G-5 を対象とする例外の行を常に記録の欠落にする)と食い違う。段のジョブが台帳を読むか IMPL-0996 を改めるまで成立しない(IMPL-0931 の note に開示した)
- 準拠テンプレート: 変更なし。規則データ(`src/data/tailoring/`)も変えていない。段の追加、構成の閾値、集約の skipped の確認、契約検査、規則 r-e-cl3 の注記の改め、例外承認の対応づけは、次の template の束で行う
- 採用者は、条件に当たる構成で、段のコマンドと閾値を G-1 で定める。道具の無い言語では、外部で実行したミューテーションの記録を照らすコマンドを段に置いてもよい。実施して閾値に届かない場合は 7.3 を用いてよい
