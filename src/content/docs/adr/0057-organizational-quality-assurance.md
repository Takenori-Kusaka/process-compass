## ステータス

採用(2026-10-03)。[ADR-0056](/process-compass/adr/0056-assurance-argument/)の決定2、決定3 のうち「本標準は品質を保証すると主張しない」に当たる部分、決定8、帰結の「本標準は『品質を保証する』と主張しない」を置き換えます。ADR-0056 のそれ以外の決定(決定1・4・5・6・7・9・10)は維持します。

## コンテキスト

### ADR-0056 は主語を取り違えていた

ADR-0056 は、「本標準を回せば品質が保証される」という文言を退け、帰結に「本標準は『品質を保証する』と主張しない」と書きました。前半は正しい判断です。規格そのものは保証の主体になりません。誤りは、その一般論を**本標準を採用した組織**にまで広げたことです。

規格が保証しないことと、規格を採用した組織が保証を主張することは、両立します。調べた枠組みは、いずれも同じ構図をとっていました(2026-10 時点。出典の所在は `research/phase4-standard/288/`)。

| 枠組み | 規格の側 | 主張し責任を負う側 |
| --- | --- | --- |
| ISO 9001 | 要求事項を定める | 能力を実証する組織。品質マネジメントシステムの有効性の説明責任はトップマネジメントにある(箇条 5.1.1) |
| ISO/IEC 42001、NIST AI RMF | 枠組みを示す。保証しない | AI を開発・提供・利用する組織。説明責任の枠組みを組織が持つ |
| 保証ケース(GSN、ISO/IEC/IEEE 15026) | 論証の構造だけを定める | 主張を立てる者。主張の十分性は読み手が判断する |
| JSQC-Std 00-001:2023、JIS Q 9027:2018 | 品質保証を「組織が行う体系的活動」と定義する | 組織 |

ADR-0056 は品質保証の意味を ISO 9000 の一文(確信を与えることに焦点を合わせた品質マネジメントの一部)だけで定めていました。日本には、より広い現行の定義があります。JSQC-Std 00-001:2023 の 1.3 の定義は次のとおりです。

> 顧客・社会のニーズを満たすことを確実にし,確認し,実証するために,組織が行う体系的活動

同規格は、ISO 9000 の「確信を与える」を3つの動詞へ意図して広げたと明記しています。あわせて、引用していた ISO 9000:2015 は 2026-05-27 に廃止され、ISO 9001:2026 が 2026-09-16 に発行されました。

### 採用の判断者は「保証すると言えるか」を問う

本プロジェクトのオーナーは、「保証すると言えないプロセスは採用されない」と指摘し、採用判断シートのたたき台を示しました。シートは、採用候補者が開発側へ18の問いを投げ、5つの要素(主張・範囲・根拠・証拠・限界と責任)を伴う回答で採否を組み立てる形をとります。問いは2つの命題に分かれます。

- 品質保証の命題(Q1〜Q9): AI の成果物を全面的に信頼せず、全件を精読しなくても、当該リリースを出してよい理由を説明できるか
- 組織継続の命題(Q10〜Q18): AI の利用を広げても、費用・依存・知識・人材・責任を組織の統制下に置き、AI やベンダーが変わり、止まっても事業を続けられるか

オーナーのゴールは、このシートで両方の判定が「採用可能」になることです。シートは、即時に保留・不採用とする8つの条件を持ちます。1つでも当たれば「採用可能」になりません。

### 品質保証の側の欠落

会議体(起案、品質保証、規格・法務、懐疑の4つの立場)が、ADR-0056 の構成をシートへ当てました。欠けていたのは次の3つです。

- 保証を主張する主体と、主張が成立する条件
- G-8 の受容が何に照らして行われるか。受容の基準を、誰も事前に定めていない
- 社内の受容と、外部への責任(製造物責任・契約責任)との関係

### 組織継続の側の欠落

同じシートの Q10〜Q18 には、現行の条項でほぼ部分的にしか答えられず、Q16(AI に依存しない技術判断力)には答えがありませんでした。2巡目の会議体(起案、採用を判断する部門長、懐疑の3つの立場)は、次の欠落を挙げました。

- 依存先のうち「代替が無い」「退出を試していない」「縮退の能力を確かめていない」ものを、誰が、いつまで受容したかの記録が無い
- 縮退は経路(人へ戻す)だけが定まり、処理できる量が定まっていない
- 止める者は定まっているが、ゲートの間で誰でも止められる経路と、止めたことを評価で不利に扱わない約束が無い
- AI の利用の効果を、自己申告(体感の速さ)と利用量で測る経路を塞いでいない

## 決定

### 1. 保証の主体は、本標準を適用する組織とする

本標準は保証の主体になりません。保証を主張し、その責任を負うのは、本標準を適用した組織です。最終責任はトップマネジメントにあります。本標準は、組織が保証を主張するための要求事項であり、その主張の拠り所です。

### 2. 最上位の主張は3つの動詞で組み、相手は顧客と社会とする

組織の保証の主張は、JSQC-Std 00-001 の3つの動詞で組みます。相手は顧客と社会です。受託では発注者を含めます。

| 動詞 | 中身 |
| --- | --- |
| 確実にする | 約束する品質(受入基準、出荷基準、壊してはならない品質条件)を、生成より前に人が定める。AI の出力を未検証の入力として扱い、作成の指示者から切り離された検証で確かめる仕組みを確立している |
| 確認する | 出荷ごとに、開発ラインの外の記名の自然人が、基準の充足と記録の完備を突合する。検証が働いているかを測る。出荷後の欠陥を原因の工程へ戻し、是正する |
| 実証する | 約束を明文化し、守られていることを証拠(保証の開示)で示す。確かめていない範囲を開示し、残存リスクを受容の基準に照らして記名の自然人が受け入れたことを記録で示す |

ADR-0056 決定2 の主張(工程の主張)は捨てません。保証の根拠の層(検証の主張)へ移します。保証は欠陥が無いことの約束ではない、という点は維持します。

### 3. 合意は3層と外枠で定める

| 層 | 何を | 誰が | いつ |
| --- | --- | --- | --- |
| 層1 | 品質保証の方針と受容の基準(1ページ) | トップマネジメントが記名する | 導入時と、体制・事業・外枠の変化点だけ |
| 層2 | 品質の約束と保証範囲 | 事業決裁者が G-1 で承認する | 案件の開始時 |
| 層3 | 出荷判定(G-7)と残存リスクの受容(G-8) | 出荷判定者と事業決裁者が記名する | 出荷ごと |
| 外枠 | 法令・契約・整合規格・技術水準・社会の許容 | — | — |

**外枠は受容の対象ではなく、前提条件です**。法令の不充足は誰も受容できません。外枠の不充足が分かった場合の扱いは、出荷を止めるか、外枠の内側へ入れる設計の変更です。

### 4. 「全員の合意」は条項にしない

組織の全員の合意を保証の条件にしません。権限者の決定と記名、責任の割り当て、組織への周知、誰でも懸念を記録できる経路、品質保証の機能の独立、に置き換えます。基準は「リスクの最小化」ではなく、「受容の基準を満たす残存リスク」です。

### 5. 社内の受容は、外部への責任を限定しない

本文に明記します。製造物責任は欠陥で問われ、社内の受容は抗弁になりません。記録が効くのは、過失責任の場面での注意義務の立証と、開示の請求への応答です。その効き目は検証していません(EV-0068)。

### 6. AI を信頼することを、保証の根拠にしない

保証の根拠は、AI から独立した検証、測った検出能力、確かめていない範囲の開示、受容の基準に照らした記名の受容に置きます。「AI が生成した」は抗弁になりません。担当者・モデル・提供者が交代することを前提にします。

QA4AI コンソーシアムのガイドラインは、機械学習の製品について「開発プロセスの管理による品質保証が寄与する割合も小さい」と書きます。これは、振る舞いがデータから帰納的に決まる製品についての指摘です。**機械学習の振る舞いを持つ製品について、その振る舞いの保証は本標準の範囲外とします**。本標準が管理するのは生成の過程ではなく、成果物を AI と独立に確かめる検証の過程です。

### 7. 「保証」の3つの意味を分け、対外表現を改める

| 意味 | 中身 | 本標準での扱い |
| --- | --- | --- |
| 品質保証(assurance) | 要求事項が満たされるという確信の根拠を、範囲を定めて証拠と論証で示す | 本標準が定める |
| 契約上の担保(warranty) | 契約で約す適合や無償修補 | 定めない。契約と法務の領分 |
| 結果の約束(guarantee) | 欠陥が無いこと、必ず動くことを約す | 使ってはならない表現とする |

範囲・根拠・証拠を伴う「品質を保証する」は、使ってよい表現へ移します(附属書H H.8)。範囲を書かない「品質を保証する」、「欠陥が無いことを保証する」、「本標準が品質を保証する」は、使ってはならない表現として残します。

### 8. 保証の主張の成立条件を6つとする

出荷ごとに、保証範囲に入る変更について、次をすべて満たす場合に、組織は「品質を保証する」と主張できます。

| # | 成立条件 | 何で確かめるか |
| --- | --- | --- |
| 1 | 層1 の方針と受容の基準が、トップマネジメントの記名で有効である | 方針の文書と記名 |
| 2 | 層2 の保証範囲が、G-1 で宣言されている | 企画書、G-1 の判定記録 |
| 3 | 範囲内の変更が、作成の指示者と別の自然人の確認(G-6。委任の変更は事後の抜き取り)を経ている | 保証の開示 項目1・3 |
| 4 | 出荷判定(G-7)と残存リスクの受容(G-8)を、別の自然人が記名している | 判定記録 |
| 5 | 検出能力を測定している。未測定が、層1 の定める期間を超えて続いていない | 保証の開示 項目6 |
| 6 | 保証の開示に記載の欠落が無く、層1 の「受容しない条件」に当たる事実が無い | 保証の開示、G-7 |

- 成立・不成立は、保証の開示から機械で判定して出力する
- 成立しない範囲は、**「品質保証の対象外として出荷した」と記録し、顧客へ伝える**。出荷はできる。対象外として出荷することの受容は、層1 の定める権限者が記名する
- 保証範囲に入る・入らないの2値は、ADR-0056 が退けた等級ではない。「条件付き保証」「保証レベル」のような中間の語を作らない
- 1名体制は、外部の確認者を置かない限り、条件3・4 を満たせない。組織として品質を保証するとは主張できない。外部へ依頼して条件へ届く道筋を附属書H に示す。検証の記録と開示の価値は残る

### 9. 層1 の様式は1ページ・5項目とする

第6章にテンプレ11「品質保証の方針と受容の基準」を置きます。案件ごと・出荷ごとに書かせません。

| # | 項目 |
| --- | --- |
| 1 | 保証の相手と範囲の方針。何を保証し、何を保証しないか。機械学習の振る舞いの保証は範囲外。停止の申し立てと差し戻しの件数を評価の減点に使わないこと、AI の利用量と PR の本数とリードタイムを人の目標値にしないこと |
| 2 | 受容しない条件(否定リスト) |
| 3 | 外枠の列挙 |
| 4 | 受容の権限の段階。品質の残存リスク、組織継続の状態(期限つき)、有事の決定者、AI の利用の拡大と停止を決める者を行に含める |
| 5 | 上申先。異議を退けた受容、段階を超える受容、停止の申し立てを退けた解除の届け先 |

### 10. G-7 の署名の意味は変えず、G-8 を層1 へ照らす

- G-7: 署名の意味は変えない。突合の対象へ2点を足す。(a) 保証の主張の成立判定の出力が開示にあること (b) 層1 の「受容しない条件」に当たる事実が開示に無いこと。(b) は値の良否の判断ではなく、トップマネジメントが事前に定めた客観的な条件との突合であり、ADR-0056 決定5 と整合する
- G-8: 受容を、層1 の受容の基準と権限の段階に照らして行う。出荷判定者の異議を退けて受容した場合と、段階を超える受容は、層1 の上申先へ必ず届ける

### 11. 採用判断シートは、要求事項ではない附属書I「採用判断の手引き」として取り込む

- Q1〜Q18 の**すべて**に、本標準としての回答を5要素で書く。範囲外と決めて答えない問いを置かない
- 回答の根拠は条項へのリンクで示す。本標準の回答は作成者の自己評価であり、根拠水準 E0 で開示する
- 即時保留・不採用の8条件のそれぞれに、本標準のどの規定が「当たらない」ことを示すかを書く
- 採否の判定は採用者が行う。手引きは判定しない。本標準が自らの採否を判定する形を避けるためである
- 附属書D と附属書H H.9 から、この附属書へ参照する

### 12. 組織継続の要求事項を、既存の記録の上に足す

新しい台帳・会議体・ゲート・周期的に見直す文書を作りません。既存の記録から生成し、実測で示し、変化点でだけ書きます。

| 問い | 決定 | 置き場所 |
| --- | --- | --- |
| Q10・Q11 投資の目的と総費用 | 企画書に3行を足す(下流の指標で書く期待成果、AI を使わない場合との比較の基準値、拡大と停止の基準)。案件または開発ラインの単位で、下流の指標により AI の利用を評価する。自己申告と AI の利用量を評価の入力にしない。総費用に検証・修正・教育・管理を含める | テンプレ6、新 7.7.8 |
| Q12 依存先 | 承認済みモデルの一覧を依存先の一覧へ広げ、単一障害点の一覧を機械で作る | 新 3.12.11 |
| Q13 縮退 | D-0 表7 に3列(人へ戻したときに処理できる量、縮退で止める業務、復旧の目安)。処理できる量は、AI が使えなかった期間の記録と変更の履歴から実測で示す。実測が無い間は「未確認」と表示する | テンプレ0、3.12.5 |
| Q14 退出 | 3.12.3 の回帰評価を別の提供者で行う(退出の予行)。指示資産の提供者依存を評価項目に入れる。試していない場合は開示し、層1 の権限者が期限つきで受容する | 3.12.3 |
| Q13・Q14・Q16 の演習 | 「人へ戻す」と「別の提供者へ替える」の2種だけを、既存の訓練の類型として足す | 開発避難訓練 |
| Q15・Q16 理解と判断力 | 判断を担う席の責任者は、AI を使わずに判断できる力量の確認を任命時と層1 の周期で受ける。自己申告を認めない。代理者が有効な確認を持たない席は「後継不在」と表示する。コア機能の理解の保持者が1名以下の状態を逸脱とする | 新 3.4.3、D-0 表5 |
| Q17 止める権限 | 誰でも停止を申し立てられ、申し立てた時点で対象を保留する。解除は層1 の受容の権限者の記名。退けた解除は上申先へ届ける。拒否権ではない | 新 7.11 |
| Q18 有事の決定者 | 重大事故・情報漏えい・契約変更・規制変更のそれぞれについて、停止・切替・顧客説明を決める者を、層1 の項目4 と D-0 表4 に置く | テンプレ11、テンプレ0 |

継続の側の状態は、保証の開示の項目5 と項目7 へ出します。項目の数は変えません。期限つきの受容は、期限を過ぎたら記録の欠落として扱います。継続の要求事項は、決定8 の成立条件へ入れません。品質の検証が成立している出荷まで「品質保証の対象外」になるためです。

### 13. ADR-0056 との関係

| ADR-0056 の決定 | 扱い |
| --- | --- |
| 1 論証を附属書H に置く。既存の条項からの投影 | 維持 |

ADR-0056 の EV-0044 の差し替え条件は「最上位の主張に修正を求められた場合、決定2・3 を改める」でした。本 ADR はその発動に当たります。ただし契機は実在の監査ではなく、オーナーの指摘と会議体の調査です。EV-0044 の水準は E0 のままです。

## 検討した選択肢

### 品質保証の側

| 案 | 却下の理由 |
| --- | --- |
| 「本標準に従えば品質が保証される」(本標準を主語にする) | 規格は保証の主体にならない。採用した組織が責任を標準へ転嫁する書き方になる |
| ADR-0056 の文言を維持し、「組織は保証を主張してよい」と注記だけ足す | 何を条件に何を主張できるかが定まらない。各組織が「保証する」を自由に書けば、対外表現の歯止めが働かない |
| 石川型の結果の保証(顧客が安心して長く使える品質を保証する) | 範囲と基準を伴わない主張になる。測定の無い結果を約束させる |
| 「品質説明力を持つ」を最上位に置き、「保証」の語を避ける | 採用の場(稟議・QMS)で通じない。オーナーの指摘に応えない |
| ISO 9000 の定義だけを典拠に残す | 日本の利用者に向けた標準が、廃止済みの 2015 年版の一文で止まる理由が無い |
| 組織の全員の合意を保証の条件にする | 規格はどこも求めていない。品質不正の調査では、合意と同調が逸脱を固定化した。全員の合意は、誰も止めない状態と区別できない |
| 受容の基準の値(件数・比率)を本標準が定める | ISO 14971・NIST AI RMF とも水準を定めない。本標準も根拠となる測定を持たない |
| 層1 を案件ごとに D-0 で定める | 案件ごとに基準が変わると、組織として保証すると言えない |
| 層1 の決定者を品質保証部門にする | 説明責任はトップマネジメントから委譲できない。決める者と牽制する者が同じになる |
| 層1 に第三者認証を求める | 本標準に認証の制度は無い。独立は品質保証の機能の独立と内部監査で置き換える |
| 成立条件を4つにする(検出能力の測定を外す) | 言葉だけが先に立つ失敗を防げない。未測定の継続を、層1 の定める期間で上限づける形で条件に入れた |
| 条件を欠く出荷を禁じる | 1名体制と初期段階の採用を閉ざす。[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)の方針(未達を隠さず表示する)に反する |
| 「完全保証 / 条件付き保証 / 保証なし」の3段階 | 等級であり、ADR-0056 決定6 に反する。「条件付き」は満たしたという主張として読まれる |
| G-7 で受容の基準への適合を判定させる | 出荷判定者に十分性の判定を戻す。照合は受容する者(G-8)が行う |
| G-7 を一切変えない | 層1 の「受容しない条件」は値の良否ではなく、事前に定めた客観的な条件である。突合しないと、受容しない条件に当たる出荷が G-8 へ届く前に止まらない |
| 採用判断シートを取り込まない(附属書D の問答だけで答える) | 問いが採用の判断者のものであり、品質保証部門の問い(H.9)には組織継続の命題が無い |
| 本標準が採否ロジックと判定まで持つ | 本標準が自らの採否を判定する形になる。採否は採用者が行う |
| 答えを持たない問いを「範囲外」と明記して残す | オーナーのゴール(両方の判定で「採用可能」)に届かない。組織継続の側の会議体を開き、全問に答える形を採った |
| 契約書の「品質保証」条項へ保証の主張をそのまま引用させる | 品質保証(assurance)が契約上の担保(warranty)として読まれる。担保の範囲は契約で別に定める |

### 組織継続の側

| 案 | 却下の理由 |
| --- | --- |
| 依存先の台帳を手で書く文書として新設する | D-0 表5・表7・理解記録との二重記入になる。生成で同じ一覧が得られる |
| 複数の AI 提供者の常時並行運用を課す | 問いが求めるのは替えられることの説明であり、並行運用ではない。退出の予行(別の提供者での回帰評価)を入れることを条件に課さない |
| 退出の予行を、同じ提供者の別世代でも可とする | 提供者からの退出を試したことにならない |
| 全社の AI 投資のポートフォリオ判断を定める | 開発プロセス標準の範囲を超える。案件と開発ラインの単位で答え、組織としての拡大と停止の権限者を層1 に書かせる |
| AI を使わない作業日の数値を定める | 頻度と技能の維持の関係を測った研究が無い。確認の中身で担保し、周期は層1 が定める |
| 全構成員への一律の教育 | Q15・Q16 は判断の席とコア理解の保持者の問題である。第3章 3.4.1 の教育の対象範囲を維持する |
| AI を使わない力量の確認を自己申告で認める | 証拠にならない。接続のログで不使用を確かめられる期間の成果物か、判定者の面前での演習に限る |
| 後継の計画書を書かせる | 書いただけで実行されない。D-0 表5 の代理者が有効な確認を持つかで判定する |
| 縮退時の処理量に下限の値を置く | 値の根拠が無い。実測を求め、受容は層1 の権限の段階で決める |
| 見積りが未確認の席・後継不在の席を出荷不可にする | 1名体制と小規模の組織が宣言できなくなる。表示と期限つきの受容で扱う |
| 停止の申し立てに拒否権を与える | 止める権限が席の数だけ生まれ、受容の権限の段階が崩れる |
| 停止の申し立てを匿名で受け付ける | 誰の見解を退けたかを追えなくなる。匿名の経路は組織の内部通報制度に委ねる |
| 層1 を8項目へ広げる | 層1 の肥大は、案件ごと・出荷ごとに書かせない原則を崩す。項目4 の行として入れる |
| 組織継続のための第2の方針文書を置く | 記名の対象が2つになり、片方だけが改められる |
| 継続の要求事項を、保証の主張の成立条件へ足す | 品質の検証が成立している出荷まで対象外になる |
| 保証の開示に項目8「継続」を足す | ADR-0056 決定6 の7項目を維持すると決めた。既存の項目5・7 の出所を足す |
| 演習の類型を多数足す | 1回の演習で縮退・退出・AI を使わない判断力の証拠を取れる2種に限る |

## 帰結

- 第1章 1.9 を「本標準を適用する組織が主張できること、主張しないこと」へ改める。1.4 に用語を足す
- 附属書H の H.1・H.2・H.3・H.5・H.6・H.8・H.9・H.10・H.11・H.12 を改め、品質保証の意味の節を書き直す
- 第3章に 3.4.3・3.12.11 を新設し、3.12.3・3.12.5 を広げる
- 第4章の G-1 の確認方法、G-7 の突合、G-8 の照合と上申を改める。判定基準の表の行は増やさない
- 第6章にテンプレ11 を新設し、テンプレ0・テンプレ6 へ欄を足す
- 第7章に 7.7.8・7.11 を新設する。旧 7.11(関連する章)は 7.12 へ送る
- 附属書I「採用判断の手引き」を新設する。附属書D から参照する
- プロセス内部監査の観点へ、層1 の有効性、期限つきの受容の期限切れ、停止の申し立ての扱い、上申の届き方を加える
- 開発避難訓練に、人へ戻す訓練と、別の提供者へ替える訓練の2類型を足す
- 実行層(準拠テンプレート)へ降ろす規定には実装マークを付ける。成立判定の出力、層1 の様式、企画書と D-0 の欄、停止の申し立ての保留が当たる
- **本標準は保証の主体にならない**。保証を主張するのは、方針・範囲・開示を伴う適用組織である
- 主張を強めても、本標準の運用が欠陥の流出を減らした測定が無いという開示は弱めない(附属書H H.9 問17)

## 補足(2026-10-03): 採用判断シートでの1回目の判定を受けた修正

### 採らなかった案

| 案 | 却下の理由 |
| --- | --- |
| 導入前の検証を要求事項にする | 附属書I は要求事項ではない手引きである。採用前の手続を標準の要求にすると、本標準が自らの採否の条件を課す形になる。手順と様式は手引きとして示し、行うかは採用者が決める |
| 導入前の検証の合否の基準を本標準が定める | 検出率の下限などの値を支える測定が無い。基準は採用者が実行の前に決める |
| リスク区分を規則だけで決め、人の確定を無くす | 規則は網羅できない。規則が押さえるのは下限だけとし、確定は人が記名で行う |
| 自律実行の保留を、ラベルから実行基盤へ機械で連動させることを求める | 実行基盤の種類が多く、手段を1つに定められない。人の操作で止め、停止までの時間を開示する |
| 記名者を一律に経営者(社長)とする | 大企業の一部門の採用を閉ざす。3つの権限と連署で、記名の有効性を判定できる形にした |
| 周期・間隔・最低数の初期値を本標準が置く | 値を支える測定が無い。空欄を不利な側へ倒す扱いで、記入を促す |
| 後継の計画書を書かせる | 決定12 の却下の理由と同じ。確認済みの候補の数で判定する |
| 効果と人の挙動を、導入前の検証の合否に含める | 導入前の検証の期間と規模では測れない。範囲と期限を付けた残余リスクとして受容し、運用の記録で確かめる |

### 根拠水準
