## コンテキスト

[#355](https://github.com/Takenori-Kusaka/process-compass/issues/355) 束1 は、実装マーク IMPL-0043(G-7 基準4)・IMPL-0132(G-3 の記載の検査)・IMPL-0042(G-7 基準3)の降りていない部分を扱いました。審議の重さは軽です(起案・反対の2委員)。

- 白紙の `05-handover.md` は、節3 と節5 の表が非空のため、「非空」だけの検査では通る。様式の初期の文と比べないと白紙を拾えない
- 白紙の `02-adr.md` の写しは、初期の文を見ない検査では5欄とも「空でない」で通る
- 標準のテンプレ5 の「エスカレーション順序」が、準拠テンプレートの様式にも対応表の `fields`・`omit` にも無かった。G-7 基準4 が名指す3項目の1つを書く場所が無い状態だった
- 前の判断記録との記述の一致は、定義が標準に無い。全部を置き換える判断記録は、正当に同じ影響を書く

## 決定

### 1. 基準4 は出荷判定者の判定として降ろし、機械は未記入の検出までを別のマークで持つ(IMPL-0043・IMPL-0985)

- 標準に「基準4 の記録」の段落を足す。完備を判定するのは出荷判定者のままで、機械の検出は「未記入」と呼ぶ。記入が在ることは完備を意味しないと本文に書く
- IMPL-0043 は基準4 そのものを指し続け、`delivered check=manual`(確かめる者: 出荷判定者)にする。機械の未記入の検出は IMPL-0985 `delivered check=machine` にする
- 採用者の義務は増えない。3項目は基準4 の文と第6章の様式が既に求める。機械が未記入を欠落に数えても、判定者の判定は残る
- **ADR-0084 の採らなかった案との関係**: 採らなかったのは、有無の部分だけを `delivered` にして基準の残りを `undelivered` に置く分け方である。基準が降りている側にも数えられるためである。今回は基準の全体を `manual` で降ろし、台帳は基準4 を「人が確かめる」と出す。機械の部分は標準に別の文が在るので別のマークにした。IMPL-0042 は分けない。独立の突合で確かめる
- 機械が未記入と数えるのは、置き場が無い項目と、空欄または同梱の様式(`templates/05-handover.md`)の初期の文のままの項目である。様式の文を1字書き換えた記載と「TBD」は記入として通る。同梱の様式が無いリポジトリでは、空欄だけを見て、比べていない旨を出す
- 置き場は見出しの語(「監視」「障害時の連絡先」「復旧手順」または先頭のセルが「切り戻し」の表の行)で読む。標準の様式の見出しと箇条書きで書いた文書も記入ありと読む
- 準拠テンプレートの様式の節5 へ「障害時の連絡先」(表と「エスカレーション順序」の行)を足す。対応表の `fields` へ登録する。節の番号は変えない

### 2. G-3 の記載の検査のうち3つを機械で降ろす(IMPL-0132)

- 対象は状態が採用・一部置き換えの判断記録である。保管領域は見ない。事業影響の節が無い記録と、行が無い記録は失敗にする
- 空は、空白・「—」・プレースホルダ・同梱の様式の初期の文と一致・取り消しの可否の選択肢が2つ以上残る、のいずれか。初期の文との比較を採る理由は、見ないと白紙の写しが通るからである(実行で確認した)
- 単一の値は、区切りの前後に異なる値を持たないもの。幅の中身の妥当性は見ない
- 「なし」は、なし・無し・特になし・該当なし・n/a との一致。「不明」「TBD」と、理由を添えた「なし(…)」は通る。標準の文は「なし」を名指す
- 採用した記録で落ちたものは、置き換える判断記録を起こして直す(採用後に書き換えてよいのは状態の行だけ)

### 3. 前の記録との一致は降ろさない(IMPL-0986)

`undelivered check=manual plan=scheduled issue=355 review=2027-02` で新設します。所見の出力も実装しません。標準の表は「検査する」と書いています。所見へ読み替えると、標準の文の意味が変わります。人の列を改めると、G-3 の判定者に所見を読む務めが足されます。これは採用者への新しい務めです。2委員はこの形を審議していません。直し方の候補は3つです。一致を失敗とする案、所見として判定者が読む案、課さないと決める案です。束2 と同じ重の審議へ残します。ADR-0071 の「降りていない」は、この項目だけ有効なまま残ります。

### 4. 受容した負債の記録漏れ(IMPL-0042)は重の審議へ移す

この束では note と `review=2027-02` だけを直す。`state` は動かさない。標準が既に求める欄だけでは、台帳に無い妥協を結合できない。部分降ろしは採らない。`gates/G-7.md` の手順へ、出荷判定者が PR のチェック項目と台帳を突合する旨を足す。

### 5. 「完備」を求める規定のマークの書き方(この束の裁定)

規定の文が完備・欠落 0 件・内容の充足を求めるとします。機械が確かめるのは、単位の有無・非空・様式の初期の文との不一致までです。この場合、規定の全体は `manual`(判定者)で表示し、`presence` と `machine` のどちらも付けません。機械の部分は、標準に別の文が在るときだけ別のマークにします。規約(`implementation-marking.md`)の直しと、`delivered check=presence` の既存の件(103 件)の棚卸しは、この ADR では行いません。note に完備・欠落・空欄の語を持つものが9件以上あり、#355 へコメントで残します。

## 課さないと決めたこと

- 「完備」の読みを定義する1文を標準へ足すこと
- 引き継ぎ文書の全セルが非空であることを求めること。正当な空のセルを欠落にする
- 前の判断記録との一致を、この束で失敗または所見にすること
- 様式の文の1字の書き換えや「TBD」を、類似度や語の一覧で落とすこと。閾値と一覧に根拠が無い
- 回復に要する時間を自然文で読むこと

## 影響

- IMPL-0043 は `delivered check=manual`、IMPL-0132 は `delivered check=machine` になる。IMPL-0985(機械の未記入の検出)を新設する
- IMPL-0042 と IMPL-0986 は `undelivered` のまま台帳に出続ける
- 出荷の証跡の集約の基準4 の行は、3項目の記入の有無を出す。完備は出さない
- 採用者の既存の引き継ぎ文書は、障害時の連絡先の欄を追記しないと、未記入または置き場なしの欠落になる。採用済みの判断記録で事業影響の欄が空のものは、置き換える判断記録を起こして直す
- 実行での確認(準拠テンプレートの試験を含む)は、EV-0282・EV-0283 で開示する。回帰の全量は push の前に1回流す
