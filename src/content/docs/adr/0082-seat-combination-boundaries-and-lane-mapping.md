## ステータス

採用(2026-10-23)。採用済みの ADR の決定を置き換えません。[ADR-0037](/process-compass/adr/0037-label-points-to-lane-not-role/)を補います。同 ADR の決定1〜4 は維持し、第3章 3.5.1 の既定の写像の行を改めます。同 ADR のコンテキストの「圧縮それ自体は設計」が [ADR-0066](/process-compass/adr/0066-shipping-approver-separation-and-development-line/) 以後は成り立たないこと、同 ADR の「△(避けたい)」を「非推奨」と読むことを、本 ADR の決定7 に記録します。ADR-0066 の決定は維持し、同 ADR の影響の節が後継へ送った2つの論点(価値責任者と技術判断者の兼務の境界、既定の写像)を本 ADR が決めます。

## コンテキスト

[#312](https://github.com/Takenori-Kusaka/process-compass/issues/312) は、席の兼務の境界と既定の写像が章の間で食い違うことを指摘しました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/312-deliberation/`(`survey-312-1-internal.md`・`survey-312-2-external.md`、意見書5本、`decision.md` の P-1〜P-6、`implementation.md`)にあります。

### 価値責任者×技術判断者の境界が3通りに割れていた

| 所在 | 3〜4名 | 5〜9名 | 10名以上 |
| --- | --- | --- | --- |
| 第3章 3.5 の表 | 許容 | 許容しない(「5名未満の体制のみ許容」) | 許容しない |
| 第8章 軸A、テーラリングのエンジン、準拠テンプレートのスキル | 非推奨 | 非推奨 | 禁止(拒否) |
| 準拠テンプレートの D-0 の様式 | 可 | 不可(「5名未満のみ可」) | 不可 |

5名の境界は、体制の変化点(第3章 3.13.1)にも、テーラリングの設問の選択肢にも、機械の判定にもありませんでした。越えたことを誰も捉えられず、根拠水準のマークもありませんでした。10名の境界は EV-0148 で開示されていましたが、その対象はコア機能の別チームのレビューと QA 専任の出荷判定であり、この組の禁止を含んでいませんでした。

### 既定の写像が、自らの条件1 に2か所で反していた

3.5.1 の既定の写像は、独立レビュアと出荷判定者を1つの QM レーンに置き、事業決裁者を価値責任者と同じ PO レーンに置いていました。条件1 は「禁止または△とされた組み合わせを、同一レーンへ写像しない」と定めています。独立レビュア×出荷判定者は ADR-0066 で禁止、事業決裁者×価値責任者は△でした。

レーンは作業領域・セッション・認証情報の組です(ADR-0037 決定1)。第3章 3.5.3 の実行主体の文脈と同じ組です。同じレーンに置くと、同じ文脈が両方の席の作業を担い、G-6 の承認と G-7 の記名が同じ認証情報から出られます。G-7 の保証の主張の成立条件4 は、承認したアカウントを人へ対応づけて確かめるため、レーンを共有すると条件4 が成り立ちません。

### `state:dev-done` の受け手が決まっていなかった

Label Mailbox の 4.3 のラベルの表、PR の運用、準拠テンプレートの `handoff.md` は「出荷判定者(QM)」、準拠テンプレートの受信箱の表(`MAILBOX`)は独立レビュアと出荷判定者の両方、`next.mjs` は独立レビュアを指していました。4.3.1 の状態遷移表は、`dev-done` を受けて独立レビューを行い `ready-to-merge` へ進める遷移を定めています。

### 標準の様式に人の名簿が無かった

第1章・第4章 G-6・第8章・ADR-0065 決定5 は「表5(人の名簿と席)」を確認者の有無と人数の根拠とします。テンプレ0 の表5 は席ごとの行だけを持ち、席を持たない担い手・外部の確認者・アカウント・所属の欄がありませんでした。準拠テンプレートは名簿(`people[]`)を持っており、標準の様式がテンプレートの部分集合でない状態でした(ADR-0040)。

### 表の記号が 1.7.3 の語彙に無かった

3.5 の表の「○」「△(避けたい)」は、第1章 1.7.3 の升の語彙(許容・非推奨・禁止)にありません。△ は禁止とも非推奨とも読め、上の割れの原因になりました。

## 決定

### 1. 価値責任者×技術判断者は、許容(1〜2名)・非推奨(3〜9名)・禁止(10名以上)とする

- 5名の境界を廃する。監査できない境界は統制にならない
- 10名以上の禁止を残す。根拠を欠くことを EV-0156(E0、見直し 2027-10)で開示する
- 3〜9名で兼務する場合は、兼務の事実と理由を D-0 体制図の「非推奨の兼務の記録」へ書く。記録の無い兼務は記載の欠落とする
- 代替の統制を課さない。意図的な決定である
- 人数ではなくチームの数で境界を引く案は、[#338](https://github.com/Takenori-Kusaka/process-compass/issues/338) に残す。#338 の審議で、この組の扱いを改めて問う

10名以上の禁止を残す理由は次のとおりです。この組は 3.5 の禁止の原則(X1〜X4)のどれにも当たらず、G-3 と G-2・G-4 は互いを確認する手続を持ちません。人数で独立の意味が変わる根拠も、外部の人数の閾値も見つかっていません。この指摘は正しいものです。ただし根拠を欠くことは、残す側と外す側の両方に当たります。禁止の撤廃は統制を緩める向きであり、撤廃を支える観測もありません。不確かなときに、既存の統制を外す方へは倒しません。

### 2. 事業決裁者×価値責任者は、3名以上で非推奨とし、どの規模でも禁止しない

- 3名以上で兼務する場合は、決定1 と同じ記録を書く
- 禁止しないことは意図的な決定である。G-8 の受容の自己完結は、出荷判定者×事業決裁者の禁止が止めている
- 根拠を欠くことを EV-0157(E0、見直し 2027-10)で開示する
- 人数の無い限定(「小規模のみ」)を廃する

### 3. 既定の写像で、禁止の組を同じレーンに置かない

| ロール | 既定のレーン | 受信箱のラベル |
| --- | --- | --- |
| 独立レビュア | Review | `state:dev-done` |
| QA(出荷判定者) | Ship | `state:ready-to-merge` |
| 事業決裁者 | Owner(決裁のみ) | `state:needs-owner` |
| 文脈オーナー | PO | なし |
| AI運用担当者 | Ops(案件のレーンと共有しない) | なし |

- ほかの行(価値責任者、技術判断者、開発者、監査担当、AI維持管理者)は変えない
- 文脈オーナーと AI運用担当者にラベルを置かないのは、ADR-0037 決定2 による
- 条件1 を「禁止の組を同じレーンに置かない。非推奨の組を同じレーンに置くときは記録する」へ改める。条件1 は体制の人数に依らず、3.5.2 の例外で人の単位の兼務を認める場合にも当てる
- 推奨構成の図の「出荷判定者: 独立レビュー」を改める。レーンは7つになる
- 写像を構成の `roles[]` へ出力する規定は、準拠テンプレートがレーンの概念を持たないため、降りていない規定として表示する(IMPL-0299)
- レーンの名(Review・Ship・Owner・Ops)は、ラベルの名(`state:qm-blocked` など)を変えずに足した。語の統一は [#328](https://github.com/Takenori-Kusaka/process-compass/issues/328) で扱う

### 4. `state:dev-done` の受け手は独立レビュアだけとする

- 遷移の正本は Label Mailbox 4.3.1 の状態遷移表とする。4.3 のラベルの表、PR の運用、準拠テンプレートの `handoff.md` と `MAILBOX` の側を直す
- `state:ready-to-merge` は、独立レビュアが G-6 の判定記録を作成した後に付ける。出荷判定者は付けない。次に動くのは出荷判定者のレーン(マージの実行)とする
- G-7 は出荷の範囲ごとの判定であり、PR ごとのラベルでは起動しない
- 既定ブランチへの取り込みが出荷を起動する構成では、出荷判定者は G-7 の判定記録を作成した後にマージする。取り込みが出荷を起動しない構成では、マージは G-7 を待たない
- ラベルを足さない。`state:ready-to-merge` が「G-6 を通過し、マージを待つ」状態を表せるため、第5章 4.2 原則5 の後段(伝達の欠落)に当たらない

### 5. テンプレ0 の表5 を「人の名簿と席」とする

- 表5-1(席と責任者)と表5-2(人の名簿)に分ける。番号を変えないので、本文と ADR-0065 の「表5(人の名簿と席)」の参照が、書き換えずに正しくなる
- 表5-1 に「兼務する席」の列と、「非推奨の兼務の記録」の表を置く
- 表5-2 の欄は、識別子・氏名・区分(体制の内 / 外部の確認者 / 組織上の任命権者)・リポジトリ上のアカウント・所属(10名以上で必須)・氏名の確認(確認した者と日付。1名の名簿は自己申告と明記)・最終更新日とする
- 必須欄を `src/data/template-fields.yaml` に登録し、両方向で検査する
- 名簿の記載の正しさは機械で確かめない。プロセス内部監査の観点6 で確かめる

### 6. 表の升は 1.7.3 の語彙で書く

- △・○ を廃し、許容・非推奨・禁止と括弧の限定で書く。1.7.3 に語を足さない
- 旧い記号と語(○・△・可・不可)を、升の語の検査(`retiredCellWords`)に登録する。旧い言い回し(「△(避けたい)」「5名未満」「小規模のみ許容」「小規模のみ可」「兼務は避けたい」)を、廃した言い回しの検査に登録する
- 準拠テンプレートの D-0 節2 も同じ語で書く

### 7. ADR-0037 の読み方

- ADR-0037 のコンテキストが QM レーンへの圧縮を「設計であり、誤りではない」とした評価は、ADR-0066 以後は成り立たない。レーンを圧縮すること一般を誤りとはしない。禁止の組を1つのレーンへ圧縮することが、条件1 と第3章 3.5.3 に反する
- ADR-0037 の「価値責任者 × 技術判断者を△(避けたい)」は、本 ADR 以後「非推奨(3〜9名)、禁止(10名以上)」と読む。同 ADR の決定3(技術判断者を価値責任者のレーンへ既定で割り当てない)は、この読みでも維持される
- ADR-0037 の決定3 の「技術判断者 × 開発者 = ○」は「許容」と読む

## 検討した選択肢

| 案 | 却下の理由 |
| --- | --- |
| 価値責任者×技術判断者の境界を5名に揃える(変化点・設問・機械・EV を足す) | 5名と10名を区別する根拠が、内部にも外部にも無い。根拠の無い境界を1つ増やすと、規則の状態の組が増え、どれも検証されないまま固定される |
| 5名と10名の2段を明文化し、両方に EV を付ける | 同上。EV を付けても、5名を区別する根拠が無いことは変わらない |
| 10名以上の禁止も廃し、全規模で非推奨にとどめる | 禁止の撤廃は統制を緩める向きであり、撤廃を支える観測が無い。根拠の弱さは EV で開示し、差し替え条件の観測を待つ |
| 規模に依らず許容し、G-3 の記録を兼務者以外が読んで異議の有無を記名する条件を課す | 兼務で失われる牽制が特定されておらず、記名が何を確かめるかを定義できない。定義できない確認は記入の有無の検査に落ちる([#339](https://github.com/Takenori-Kusaka/process-compass/issues/339) と同じ型) |
| 3〜9名の兼務に代替の統制(判定記録の追記と他者の確認)を課す | 同上。効果を測った措置が無く、措置を行ったことが安心の根拠として独り歩きする。代替の統制を課さないと明記し、兼務の事実と理由の記録で代える |
| 境界を採用組織が自ら定める | 自己申告で規則を外せる形になる([ADR-0044](/process-compass/adr/0044-no-search-obligation-for-existing-parts/) 決定4、第8章 軸A が退けた型) |
| 事業決裁者×価値責任者を10名以上で禁止する | 禁止へ広げる根拠になる記録と測定が無い。G-8 の受容の自己完結は、別の禁止が止めている |
| ADR-0066 を置き換え、独立レビュアと出荷判定者の兼務を許す | G-7 の基準5 は G-6 の記録を突合する。兼ねると自分の記録を自分で突合する。誤りと判断する材料が無い |
| 独立レビュアと出荷判定者の分離を R1 の変更に限る | 席は案件ごと、リスク区分は変更ごとに決まる([ADR-0039](/process-compass/adr/0039-scope-in-heading-and-unit-of-judgement/))。変更ごとに席の責任者を入れ替える形は成り立たない |
| レーンの共有を許し、条件1 を人の単位の禁止だけに改める | レーンは文脈の単位であり、3.5.3 の文脈の単位の禁止と食い違う。承認と記名を人へ対応づけられない |
| 既定の写像を定めず、案件に委ねる | ADR-0037 が是正した欠落(割り当て先のないロール)が戻る |
| `state:dev-done` を出荷判定者へ渡す | G-6 の判定者が受け取らない。出荷判定者が独立レビューを行う構成を示し続ける |
| `state:dev-done` を両方の受信箱に入れる | どちらが拾ったかを記録から決められない。「自分の受信箱だけを見る」規則の下で責任の所在が決まらない |
| G-7 用のラベルを足す | G-7 は PR 単位ではない。伝達の欠落が無く、語彙を増やす理由に当たらない |
| 名簿を標準に置かず、本文の「表5(人の名簿と席)」の呼び方を改める | 確認者・人数・所属の判定の根拠が標準の様式から消える |
| 表5 の席の表に列を足して名簿を兼ねる | 席を持たない担い手と外部の確認者を、席の行で表せない |
| 名簿を新しい表番号で置く | 本文と ADR-0065 の「表5(人の名簿と席)」の参照が誤ったまま残る。採用済みの ADR の本文は書き換えられない |
| 1.7.3 に △ を足す | 「非推奨」と区別できる意味が無い。同じ強さに2つの表し方が生じる |

## 影響

- 第3章 3.5 の表を 1.7.3 の語で書き、非推奨の兼務の記録・代替の統制を課さないこと・5名の境界を置かないこと・事業決裁者×価値責任者を禁止しないことを明記した。EV-0156・EV-0157 を置いた
- 第3章 3.5.1 の写像の表・条件1・推奨構成の図を改め、3.5.1 と 3.5.2 の節の位置を番号の順に入れ替えた(番号は変えていない)。3.4 に監査担当の任命基準の所在を足した
- 第5章 5.5.1 の「1名に集中させません」の主語を席の責任者にし、人の単位の兼務の可否は第3章 3.5・3.5.2 によると引いた。禁止の強さは変えていない
- 第8章 軸A に事業決裁者×価値責任者の行を足し、出荷判定の 1〜2名の列の条件(開発ライン×出荷判定者の例外に当たる構成)を明示した。IMPL-0278 の注記を実装に合わせ、降りている検出を IMPL-0300 に分けた
- 第6章 テンプレ0 の表5 を「人の名簿と席」とした
- Label Mailbox 4.3・4.3.1・4.5、PR の運用を、受け手と付与者の定めに合わせた
- 第7章 7.4 の「後回しにできる対象」の表の升(可・不可)を、升の語の検査への登録に合わせて許容・禁止へ改めた。規定の強さは変えていない
- 規則データ(`rules-team-size.yaml`)の旧語を改め、事業決裁者×価値責任者の注記を足した。エンジンの10名以上の禁止(`mustSplitFrom`)は変えていない
- 準拠テンプレートは、`MAILBOX` から出荷判定者の `state:dev-done` の受信と `state:ready-to-merge` の付与を外した。非推奨の兼務を `/pit` の注記に出し、D-0 節2 に記録の無い非推奨の兼務を出荷の証跡の集約が記載の欠落とする。D-0 節1 の名簿に、記入があるときだけ氏名の確認の列を出す(列の無い旧い生成区間も一致として受け付ける)
- **既存の採用者への影響**: 3〜9名で価値責任者と技術判断者を兼ねている、または3名以上で事業決裁者と価値責任者を兼ねている採用者は、D-0 節2 に記録を書くまで、出荷判定の証跡の集約が欠落を出す。構成(`process.config.json`)は変えずに読める
- レーンの名と、ラベルの名(`state:qm-blocked`)の食い違いは残る。#328 で扱う
