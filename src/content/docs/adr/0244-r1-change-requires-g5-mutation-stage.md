## ステータス

採用(2026-11-20)。審議は重です。記録は `research/b28-deliberation/` にあります。一部置き換え: [ADR-0151](/process-compass/adr/0151-unselected-optional-check-not-failure-disclose-duration/) 決定1 の必須の段の集合(ADR-0224 が広げた後のもの)に、R1 の変更の段 mutation を足します。[ADR-0224](/process-compass/adr/0224-g5-mutation-and-regulatory-stages-required-for-safety-and-regulated/) 決定13 の「本 ADR が足すのは、案件ごとの段だけ」を、案件ごとの段に加えて R1 の変更ごとの段を足す形に置き換えます。ADR-0224 の決定1・6・7・9 は保ちます。番号は仮で、取り込みの直前に照らします。

## コンテキスト

- 附属書H H.1 の表は、R1 の変更で変異試験を「必須。当該範囲を変更するたびに実行する」とする。実装は無く、G-5 の入口に段が無かった(IMPL-1029)
- 所有者の回答(#445。2026-11-20)は、R1 の変更で段 mutation を必須にし、空なら G-5 を失敗にする(全採用者)。道具の無い言語は外部の記録を照らすコマンドで受ける。閾値は設定した場合だけ合否に使う
- ADR-0224 決定6 は、案件の条件(Q1 が「はい」・CL3)に当たる構成で閾値を必須にした。R1 だけに当たる構成に閾値を課すかは未決だった
- R は変更ごと、CL は案件ごとに判定する(ADR-0039)。CL0 の案件の認証の変更も R1 である

## 決定

1. 段 mutation は、「案件の条件(ADR-0224 決定1)」または「この変更が R1」のとき必須とする。必須で段のコマンドが空か、キーが無ければ、G-5 の失敗とする。必須でなければ、段のコマンドを走らせず、注意を出して通し(コマンドを書いたことで R2・R3 の PR の合否条件にしない)、R1 の PR では空だと失敗する旨を添える
2. R1 の判定は決定可能な入力だけで行う。PR の経路は、PR の本文の区分と、基底ブランチの構成の区分の下限(riskFloor)の高いほうとする。push の経路は、コミットのトレーラ Risk: と下限の高いほうとする。判定の入力が読めないとき(起動の経路・本文・変更ファイル・コミットのいずれかを取れない)は、必須の側に倒す。手動の実行(workflow_dispatch)は PR でも push でもなく、リスク区分を判定しないので、この倒し方に当たる。区分の下限の規則は、check-pr と同じ変更の一覧(名前の変更を検出する)に当てる
3. 段のコマンドは、`mutation-result: score=<0〜100 の数値または none> survivors=<生き残りの一覧の所在>` の1行を出す。行が無い、スコアが数値でも none でもない、所在が空のとき、段は失敗とする。none(対象の変異体なし)は、閾値があっても比較せず通す。外部の記録を照らすコマンドも同じ約束を満たす
4. 閾値(ci.mutationThreshold)は基底ブランチの構成から読む。案件の条件に当たる構成では必須(ADR-0224 決定6 のまま)。R1 だけに当たる構成では求めず、設定した場合だけ数値の型を確かめて合否に使い、スコアが届かなければ失敗とする。無ければ「閾値なしで通過。走った事実と所在だけを証跡とし、検出力が足りるとは主張しない」と段の出力に1行出す
5. 段が空のままの通過に 7.3 の例外承認を用いない。閾値を定めている場合の閾値割れは 7.3 の対象とする(附属書F F.6。台帳の行の約束と段が読む機械は ADR-0243)
6. 附属書H H.4 の「検証に数えない」の文は変えない。G-5 を経ない変更、閾値なしの通過、検査対象が存在しない構成の受け皿として残る。G-5 の段の通過は、検出力を測ったことの十分条件ではない(IMPL-1029 の note で開示する)
7. 準拠テンプレートの7つのアダプタには、空の mutation・regulatory を置く。既定のコマンドは置かない。依存の追加は採用者の G-3 の技術選定である
8. R2 の週次の実行は、別のマーク(IMPL-1035。undelivered)に分ける。R1 の PR ごとの段とは別の規定である

## 課さないと決めたこと

- R1 だけに当たる構成への閾値の必須(全採用者に G-1 での閾値の記名を新しく課すことになるため、所有者が採らなかった)。ADR-0224 決定6 の範囲は変えない
- スタックごとの既定のコマンド(Stryker・mutmut など)をアダプタへ置くこと
- 取り込みから一定期間は注意にとどめる猶予期間
- 外部の記録に対象のコミットの SHA を書かせて照合すること(必須でも任意でも採らない。`echo` で満たせ、改ざんを防がない。報告の標準の形式に欄が無い)。記録の日付・mtime の検査、署名・attestation も採らない
- `true`・`echo` の類のコマンドを型で見分けて注意に出すこと(列挙が閉じない。既存の段に同種の検査の先例も無い)
- 所在の実在を機械で確かめること(所在は URL や CI の成果物でもありうる。決定可能でない)
- 閾値なしで通った R1 の PR の件数を集約で数えること、PR ごとに注意の注釈を積むこと
- R2 と書いて段を省いた PR の件数を集約に出すこと(区分の確定は 3.8.1 の確定者と G-6 の既存の統制)
- CHANGELOG.md の新設(移行の注意は README の「テンプレート更新時の既存案件への影響と運用ルール」に1項を足す)
- 必須でない変更(R2・R3)でも段のコマンドを走らせ、結果を注意に出して通すこと。全ての PR に実行の時間が掛かる。附属書H H.1 は R2 を週次の定期実行で合否条件にせず、R3 を任意とする。PR ごとの費用の公開の実測が無く、EV-0345 の開示は R1 の PR が対象なので、開示の外へ費用を広げない
- 手動の実行(workflow_dispatch)で段を必須にせず、注記にとどめること(同じ名前のチェックが同じコミットに付きうる。必須でない扱いにすると、R1 の変更で空の段を通す経路になりうる)
- 安全の案件だけに限ること、R1 で段が空なら注意にとどめて集約に件数を出すこと(所有者が採らなかった)

## 検討した選択肢(採らない)

| 案 | 採らない理由 |
| --- | --- |
| R1 の判定を区分の下限だけで行う | 人が規則より高く確定した R1 を落とす |
| R1 の判定を本文の区分だけで行う | 本文の誤記と、同じ実行の他のジョブの判定が食い違う |
| push の経路を確かめない | PR を経ないコミットは出荷の集約が事後に欠落として扱うが、段の必須とは別の統制である。トレーラは書く者が省けるため下限を併せる |
| 判定の入力が読めないとき下限だけで判定して注意に出す | 適合の主張の信頼に響く。必須の側に倒す |
| R1 の変更ごとの段を別の段(mutationR1)にする | 同じコマンドの段が2つになり、片方を `true` で埋める抜け道が増える |
| 段が空の R1 の通過を 7.3 で受ける | 判定を実施しないまま進める 7.3 の使い方になる(ADR-0153 決定2・ADR-0224 決定7) |
| 規格を根拠に引く | ADR-0224 決定10 のまま。本標準の判断である |

## 影響

- 附属書H H.1: 表の直後に、R1 の変更の段の文と EV-0345 を足した。附属書F F.6: 7.3 の名指しに R1 の変更ごとの段を足し、道具の無い言語の許しを R1 にも掛けた。F.6 の表の「優先」に、R1 の変更は H.1 により必須である旨を添えた(意味は変えていない)
- 準拠テンプレート: scripts/gate/adapter.mjs と mutation-stage.mjs、gate-g5.yml の段のジョブ、契約検査の閾値の型、様式09の注、README の移行の注意
- 移行: R1 の PR で段が空だと、取り込みの後の最初の R1 の PR で G-5 が落ちる。R2・R3 の PR は、段のコマンドを書いても走らず落ちない。手動の実行は必須の側に倒れて落ちうる
- 集約は段のジョブ(mutation・regulatory)の success を求める(gate-g5.yml の集約の式と needs)。構成に閾値が無いことの注意の1行も集約が出す(案件の条件に当たる構成では、段と契約検査が失敗にする旨の文)。段のジョブが段を呼ぶ結線は、試験が値の一致で固定する。固定するのは、経路・比較の起点・PR の本文・基底の構成の受け渡しと、全履歴の取得である。閾値割れを 7.3 で受ける機械(ADR-0243)と R2 の週次の実行は、降ろしていない

## 根拠水準

- PR ごとの増分実行の所要時間と費用に、公開の実測が見つかっていない。EV-0345(附属書H H.1)で開示する
- 機械が確かめるのは、段の必須の判定・出力の行の構文・閾値の型とスコアの大小までである。コマンドの実質、外部の記録の真正と新しさ、所在の実在は manual(確かめる者: G-6 の判定者)で、EV-0339 で開示する
