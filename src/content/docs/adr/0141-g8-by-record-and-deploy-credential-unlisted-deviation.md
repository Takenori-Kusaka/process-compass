## 決定

### 1. G-8 は判定記録で成立する。配備の環境の承認は成立に数えない

G-8 は、判定記録(第6章 テンプレ4)の作成で成立します(ADR-0036 決定1)。配備の環境の必須レビュアは、採用者が足してよい統制です。G-8 の成立には数えません。必須レビュアの承認の記録は、判定記録の代わりになりません。両者が食い違えば、成立を決めるのは判定記録です。第5章 QMS 文書管理の G-8 の行を、G-7 の行にならって改めます。兼務の扱いと発注側への固定(ADR-0035・ADR-0087)は落としません。

### 2. 配備は G-8 の判定記録の後に行う。機械による停止は課さない

判定記録の無いまま行った配備は、G-8 を経ない出荷であり、記録の欠落として扱います。この順序は、本標準が ADR-0036 から導いた読みです。決定1は、判定記録の作成で判定が成立し、記録の無い状態を未判定とします。決定2は、ゲートの問いを次工程へ進めてよいかとします。新しい原則ではありません。読みであることを、本文で根拠水準マークにより開示します。

緊急の修正にも、G-8 を経ない配備の経路を置きません。第4章の振り分けで、緊急の修正での事業ゲートの事前決裁を事後報告へ切り替える定めを削った決定と同じ向きです。G-8 の判定基準を満たせない場合は、第7章 7.3 の例外承認を経て判定記録を書きます。

本標準は、配備の機構が G-8 の判定記録を確かめてから動くことを課しません。課さないと決めた事項です。判定記録の真正性を閉じないまま読ませると、検出を門と読ませるためです。配備先は案件ごとに違います(ADR-0090 決定6)。

### 3. 「未達」の二義を書き分ける

第1章 1.10.2 の「未達のゲート」は、構成に記録したゲートの状態をいいます(ADR-0028)。条項が「保証の開示に未達として記録する」と書く要求事項の不充足は、保証の開示の表示です。未達のゲートの件数に数えません。適合の主張を妨げるかは、その条項が定めます。表示の語は増やしません。ゲートの外の未達をすべて列挙に無い離脱とする判別の規則は、採りません(ADR-0113 の確認の欠落まで移るため)。

### 4. 配備の資格情報の規定を満たさない構成を、列挙に無い離脱とする

第4章 G-8「配備の統制と資格情報の置き場」を満たさない構成は、列挙に無い離脱です。本標準は条件と代償措置を定めません。記録の3項目(開いている経路、経路を持つ主体と直接の書き込みの可否、狭める措置と止めないもの)は、ADR-0090 決定2 のとおり書きます。2つの場合(手段が無い、使わないと決めた)の分け方も維持します。

理由は、型が判定記録の置き場の履歴と同じだからです。統制がホスティングの機構で閉じず、書き込みの権限を持つ者が、人の判定の場所(G-8)を経ずに配備先へ届きます。同じ型の一方だけが適合の主張を妨げる理由はありません。

### 5. 第7章 7.3 の例外承認を経た構成は、列挙に無い離脱に数えない

第4章 G-8「配備の統制と資格情報の置き場」の条項は、第7章 7.3 を名指します(ADR-0134 決定6)。7.3 の要求事項のすべてを満たし、効力を失っていない例外承認を経た構成は、列挙に無い離脱として数えず、例外承認の件数に数えます(ADR-0134 決定2・3)。規定を満たしたことにはしません。例外承認の記録では、決定4 の記録の3項目を技術負債台帳の「内容」の欄に書きます(7.3 の要求事項3 の想定される影響と対処に当たります)。所有者の回答の「代償措置」は、この要求事項3 を指すと読みます。回収の期限を過ぎた例外承認は効力を失い、記録の欠落になります(ADR-0134 決定5)。

これは、本標準が列挙に無い離脱の条件と代償措置を定めることではありません(ADR-0133)。7.3 は、不充足を期限つきで認め、回収まで追跡する手続です。同程度の防御ではありません(ADR-0134 決定1)。受け手には、例外承認の件数の併記で届きます。

構成の条件のうち 7.3 を名指すのは、本条項だけです。席の兼務の禁止・文脈の分離・人の名簿・認証情報の分離などは、従来どおり 7.3 の対象にしません。本条項だけを名指す理由は次のとおりです。

- 不充足を、日付のある行為で解ける(配備の環境を設ける、配備先の書き込みを限る、配備先をリポジトリの外へ移す)。回収の期限が意味を持つ
- 例外承認が無いまま主張を一律に妨げると、配備先が同じリポジトリの中の採用者は、主張を捨てるか、満たしたと書くかを迫られる。ADR-0134 が「範囲に例外承認があれば主張を妨げる」案を、正規の経路を使えなくし記録を偽る動機を作るとして退けたのと同じ理由である

### 6. 契約の条件は区分を変えない

統制の手段を使えない理由が契約の条件でも、区分は変えません。費用がかかること、他の手段がより安いことは、満たしたものとして扱う理由になりません。本標準は、契約の条件に固有の条件・代償措置を定めません。リポジトリの外の秘密情報の置き場を、満たす形に新たに加えません。規範は製品と契約のプランを名指ししません。プランごとの提供は、手引きに日付つきで置きます。

### 7. D-3 を再検討し、採らない

ADR-0133 が #329 へ送った D-3(判定記録の置き場の要約値を、別の置き場へ追記して突き合わせる措置)を再検討しました。ADR-0133 の理由(検出型の統制と二重になる。2つの置き場の権限者が異なるかを機械で閉じられない。1名の体制では成り立たない)は、契約の条件に依らず、本件でも変わりません。採りません。ADR-0133 決定1 の表の「#329 の裁定を待つ」には、決定4・6 の型で答えます。判定記録の置き場の履歴の区分は変わりません。同条項は 7.3 を名指しません。

### 8. PR を経ない起動の結果を、G-5 の通過に数えない

PR を経る変更の G-5 の通過に数えるのは、当該の PR を評価した起動の結果に限ります。手動の起動など PR を経ない起動で、同じ名の結果が PR の先頭のコミットに付いても、数えません。PR を経ない起動は、PR の差分・本文・基底との比較を前提とする判定を飛ばしうるためです。第4章 G-5「判定のコードの読み元」の箇条(変更の側から同じ名前・同じ送り手で結果を出せる構成は外せない形に当たらない)と、G-5 が PR ごとの判定であることの帰結であり、新しい原則ではありません。

PR を経ないコミットの G-5(既定ブランチへの push を契機とする実行。第4章「変更の要求を経ないコミット」)と、出荷の証跡の取り込みが出荷の対象のコミットの成功した実行を読むこと(ADR-0123 決定)は、この決定の対象の外です。前者は G-5 の実行そのもの、後者は G-5 の通過の判定でなく証跡の取り込みで、PR の先頭のコミットに付く結果を数える問題とは別です。

起動の事象は値であり、機械で確かめられます。準拠テンプレートへの降ろしは別に行い、それまでは降りていない規定として表示します。成功した手動の起動が必須チェックを満たすかは、実機で確かめていません。

### 9. リスクの一覧の受け止めを、実在する統制に合わせる

運用のリスクの一覧の「配備の自動化の不備」の受け止めに、PR を経ない起動を足し、第4章 G-8 の規定と記録へ辿れるようにします。一覧に書くのは、実在する統制だけです。統制は増えません。誤った安心を与える表示を正すための変更です。

## 影響

- 列挙に無い離脱は9つになる。閉じた列挙は D-1 のまま変わらない
- 配備先が同じリポジトリの中にあり、ジョブのトークンで書く構成は、7.3 の例外承認を経ない限り、適合の主張を述べられなくなる。**採用者への新しい義務である**。例外承認を経た構成は、例外承認の件数を併記して主張できる。Free の私的リポジトリは、判定記録の置き場の履歴の離脱で既に主張できない
- 配備は G-8 の判定記録の後に行う。既存の決定の読みであり、本 ADR で新しい原則は足さない
- 準拠テンプレートの述べられる名は、配備の資格情報の離脱も、その例外承認も数えない。出荷の証跡の集約は、`gate-g5` の結果の起動の事象を確かめていない。降りていない規定として表示し、#329 のコメントに降ろしの項目を残す
- 本リポジトリの配布の開示は、区分の語を改める。主張への効果は無い
- 実証を欠く判断がある(根拠水準マーク EV-0282〜EV-0285)

## 見直しの契機

- 採用者で、判定記録の無い配備が見つかったとき(決定2 を審議し直す)
- 配備の資格情報の例外承認が、回収でなく承認のし直しで繰り返し延びる行が観測されたとき(ADR-0134 の EV-0271 と同じ源)
- 成功した手動の起動が PR の必須チェックを満たすかを、実機で確かめたとき
