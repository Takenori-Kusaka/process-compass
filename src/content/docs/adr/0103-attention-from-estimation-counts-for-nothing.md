## コンテキスト

[#401](https://github.com/Takenori-Kusaka/process-compass/issues/401) は、2026-09-23 のオーナーの依頼に対して作られた 3 本の Draft PR(process-compass #283、pit-in-template #50・#51)を取り込めないため、審議し直すものです。旧案は、TypeSafe の分類器 Jev で利用者の発話から実行の段階などを推定し、人へ戻す側にだけ働く助言として、既定無効でテンプレートへ同梱する案でした。オーナーは同日に「条件付きで採用」を選びましたが、条件の記録は無く、PR はマージされていません。調査(`research/401-deliberation/survey-401-*.md`)と、起案・現場・品質監査・規格・弁護の 5 委員の会議体(`research/401-deliberation/`)を経ました。弁護の委員は旧案の側に立ちました。

### 見つかったこと

- 旧案の設計の核(人へ戻す側にだけ働く、出ないことを根拠にしない、既定無効、版の固定と人による較正、G-5 に入れない)は、その後の ADR と同じ向きだった
- 旧案には当時からの欠陥があった。端末から個人の API キーで外部のサービスへ直接つなぎ(3.12.2 の接続経路に当たらない)、部品の中の許可の一覧と正規表現を外部送信の統制とした(3.12.8・5.8.6 に適合しない)。判定記録の照合は、その後の判定記録の置き場(ADR-0070)では常に「見つかりません」になる
- 外部通信の既定拒否(5.8.6)は準拠テンプレートに降りていない(IMPL-0200)。旧案は、その前に外部送信の部品を入れる順序だった
- 旧案の評価は、正解ラベルを AI 3 者の合議で付け、提供元の違いを別案の却下の理由にした
- 外部: 自動化バイアスには、助言に従う作為の誤りと、助言が出ないため行動しない不作為の誤りがある。警告疲れで助言は無視・無効化される。拡張の設定ファイルを PR で差し替えて送信先を変える攻撃の実例がある(2025〜2026)。規格は特定の製品の名指しを原則として避ける。開発の工程で分類器の助言を評価した資料は見つからない
- 旧案の「オーナー」は、本プロジェクトのオーナーと採用者の組織の席を一語で重ねていた

## 決定

### 1. 位置づけ(第5章 5.8.7・5.5.1、附属書H H.4)

- 推定による注意の喚起を、判定にも検出の層にも数えない材料とする。第5章に 5.8.7 を置き、製品を名指さない一般の規定とする
- 出力を、判定・承認・遮断・完了・ラベルの付与と遷移・区分の確定・「該当しない」の結論に用いない。厳しくする向きにだけ働く出力に限り、作業を先へ進める誘導を持たせない。出ないことを、確認の省略・区分の引き下げ・統制を緩めることの根拠にしない(EV-0210、E1)
- 5.5.1 に、注意の喚起は人へ戻す場合を増やさず減らさないこと、人へ戻すかを注意の有無で決めないこと、出ないことを当たらないことの根拠にしないことを置く。準拠テンプレートの CLAUDE.md と常駐の規則へ降ろす(IMPL-0398)。部品を同梱しなくても、採用者が独自に足す場合に誤りは起こるため
- 「引き上げ」の語を使わない。5.4.5・5.5.7 では緩める向きの語であるため

### 2. 外部送信

- 組織の管理外へ送る構成では、次を取り消せない操作の上流の操作として扱い、担い手に行わせない。送信を始める設定の有効化と、送信先・送る項目の変更である
- 個々の送信は送信ごとに人へ戻さない。有効化は、事業決裁者が送信先・送る項目と送らない項目・期限を定めて記名で決める。送信先・項目・モデルの版・部品の要約値・期限のどれかが変われば決め直す(EV-0211、E1)。新しい承認の型は作らない
- 推定のモデル・サービスは AI 実行基盤(3.12.2)として AI運用担当者の経路で接続し、3.12.3 で導入し、依存先の一覧(3.12.11)に載せる。どの統制も依らないため、単一障害点の一覧の対象にはしない。部品の中の送信先の一覧と秘匿情報の検出を、5.8.6・3.12.8 を満たしたものとして扱わない
- 層1 項目4「AI の利用の拡大」へは、本標準の側で読み込まず、除外もしない(組織が層1 で定める)

### 3. 同梱と名指し

- 準拠テンプレートへは、既定無効の形でも同梱しない。外に置く任意の部品としても配らない。本文・テンプレート・既定値で製品を名指さない
- 再審の条件。次のすべてがそろうまで、同梱を審議し直さない
  - (a) 5.8.6 の準拠テンプレートへの降ろし(IMPL-0200)
  - (b) 3.11.6 の外部ツールの採用の手続の降ろし(IMPL-0228・0229)
  - (c) 人が正解を確定した基準集合による評価
  - (d) 提供者による経路・保持・学習利用の条件の公開
  - (e) 採用者からの要望か試行の記録
- フェーズ5 の手引きに、採用者が足す場合の置き方の例を置く
- 旧案のブランチ(`docs/adr-0054-phase-advisor`、pit-in-template の `feat/phase-advisor-jev`・`feat/phase-advisor-eval`)は、再審の材料として残す
- 5.8.7 の要求事項は、採用者が部品を置くときに掛かる(IMPL-0399〜0402。採用者に委ねる未達として表示する。準拠テンプレートが部品を持たないため)

### 4. 評価と観測

- 旧案の評価を、採否と根拠水準の根拠に使わない。提供元の違いを使った却下理由を撤回する
- 推定のモデルには 3.12.3 を掛ける。基準集合の正解を確定するのは人である。3.4.2 の適合性確認と退出の予行を掛けない(モデルが席の担い手でないため)
- 閾値は案件がモデルの版ごとに定め、技術判断者が記名で決める。本標準は閾値の値と警戒水準を課さない
- 働きを件数(注意・人へ戻した・戻しを要した・戻さなかった・事後に分かった見逃しのうち注意が出なかったもの)で観測する。件数を検出率として開示しない。見逃しは事後に見つかった分だけで、0 件を見逃さない根拠にしない(EV-0212、E1)

### 5. 決める者

- 本標準と準拠テンプレートの改訂の採否は、本プロジェクトのオーナーが決める
- 採用者の組織で推定による注意の喚起を置くか、外部送信を有効にするかは、採用者の席(事業決裁者・AI維持管理者・AI運用担当者・技術判断者)が決める
- オーナーの 2026-09-23「条件付きで採用」は、条件の記録が無く、マージされず内容の確認も成立しなかった。本 ADR は、改訂の側で同梱を採らないと決める。2026-09-23 の選択を維持・変更・取り下げのどれとするかは、オーナー本人が記録する(#401 で待つ)

### 課さないと決めたこと

次は、検討したうえで課さないと決めたことです。書かれていないのではありません。

- 推定による注意の喚起を置くこと(使わない選択は適合を妨げない)
- 閾値の値と、観測した件数の警戒水準
- 送信ごとの人の承認
- 注意の喚起を検出の層に数え、H.4 の 5 条件を掛けること
- 層1 項目4 への当てはめを本標準が決めること
- 送信に関わる法令の整理(組織の規程による)
