## ステータス

採用(2026-11-26)。審議は軽です。新しい義務は無く、附属書F F.6・附属書H H.1 に在る規定と、束 B22・B26・B28 で裁定した実装を降ろします。記録は `research/b31-deliberation/` にあります。番号は仮で、取り込みの直前に照らします。

置き換え: [ADR-0222](/process-compass/adr/0222-b20-run-record-isolation-and-provisional-license/) 決定1 の理由の一文「対象が G-5 の判定の行は、常に例外承認として対応づけず欠落になる」を、段 mutation の閾値割れの行について置き換えます(決定6)。[ADR-0217](/process-compass/adr/0217-b20-exception-use-display-and-record-checks/) の影響の節の「止めるのは、7.9.4 の行の欠落(決定2)だけである」を、枠の超過の拒否(IMPL-0630。G-5)について置き換えます(決定7)。ADR-0222 決定1(暫定のライセンスの許可を構成で受け、台帳で受けない)と ADR-0217 の決定は保ちます。

## コンテキスト

- 附属書F F.6 は、段 mutation が閾値を定めたうえでスコアが閾値に届かないとき、7.3 の例外承認の対象とすると名指す。[ADR-0224](/process-compass/adr/0224-g5-mutation-and-regulatory-stages-required-for-safety-and-regulated/) 決定7 の原文は「段が空、または閾値が未設定のままの通過に、7.3 の例外承認を用いない。ミューテーションの段を実施し、スコアが閾値に届かない場合は、7.3 の例外承認の対象とする。」である。[ADR-0244](/process-compass/adr/0244-r1-change-requires-g5-mutation-stage/) 決定5 は、台帳の行の約束と段が読む機械を本 ADR に予告した
- 実装は降りていなかった(IMPL-0931)。準拠テンプレートの G-5 は PR ごとの gate-g5 で動き、台帳の行を読む入口が無い。IMPL-0996 は、対象が G-5 の判定の行を、常に例外承認として対応づけず欠落にする。両者が食い違っていた
- 附属書H H.1 の表は、R2 の変更の変異試験を「週次の定期実行。合否条件にしない」とする(IMPL-1036)。テンプレートに定期の起動のワークフローは無かった

## 決定

1. 段 mutation の閾値割れだけを、技術負債台帳の区分「例外」の行で受ける。閾値割れとは、段のコマンドが終了コード 0 で終わり、出力の行(`mutation-result:`)の構文が正しく、スコアが基底の構成の閾値より小さいことをいう。案件の条件の段と R1 の段の両方に掛ける(附属書F F.6 の名指しの実装。ADR-0224 決定7・ADR-0244 決定5)
2. 行の約束は次の8条件で、すべて決定可能である。段が、`scripts/gate/exception-expiry.mjs` の関数で読む。集約は束 U6c で同じ関数へ寄せる(決定5)(適用: 段 mutation が閾値割れを出した PR)
   1. 区分が「例外」
   2. 対象が `G-5 PR-<当該の PR の番号>` と完全一致する。`PR #12` の形・別の PR・別のゲートは候補にしない
   3. 内容の先頭が固定の印 `変異試験の閾値割れ`(強調の記号と全角を正規化して読む)。印に下限の数値は書かせない(決定の注1)
   4. 状態が有効を指す値(未返却・未回収・有効)のどれかと完全一致する
   5. 返却の目安が日付として読め、段の実行の日に期限が過ぎていない(期限の日は効力がある)。日付は呼び出し側が渡し、関数は時計を読まない。遠い日付を書けることは既存の例外の行と同じで、機械は見ない
   6. 承認した者の記入があり、名簿の人へ対応づく。AI の名義・PR の作成者・作成を指示した者のいずれでもない。作成を指示した者を `@` で書いた PR は受けない側に倒す(段が識別子で確かめられない)
   7. 受容した理由の記入がある
   8. 帰属: 承認した者本人が、対象の PR の上で宣言行 `例外承認: D-NNN` のレビューを出し、レビューの対象のコミットが PR の先頭と一致する(ADR-0106 の (A))
3. 基底(既定ブランチの先端)にある ID は基底の内容で読む。PR の中で期限・状態・印を書き換えても効かない。PR の中で足した行は、決定2 の8 を満たしたときだけ数える。閾値は基底の構成から読む(閾値を下げる PR が自分の閾値割れを受けることはできない)
4. push の経路は、先頭のコミットが PR のマージのコミットであることを、ホスティングの記録で確かめたときだけ、その PR の行で照らす。記録は、`merged` で `merge_commit_sha` が先頭と一致し、`base.ref` が既定ブランチの PR がちょうど1件であることを指す。確かめられないときと手動の実行は受けない(PR を経ない push・0件・2件以上・取得の失敗)。確かめる対象は squash(テンプレートの既定)である。ほかのマージの方式は照合が取れたときだけ受け、取れなければ失敗のままとする
5. 出荷の集約(G-7)は、対象 `G-5 PR-<番号>` で印のある行を、IMPL-0996 の「G-5 の行は常に欠落」から外し、既存の 7.3 の照合と回収の追跡に載せる。ほかの G-5 の行(`G-5 P-001` など)は欠落のままとする。この改めは、出荷の集約の定義の変更を伴う別の単位(束 U6c)で降ろす。それまで IMPL-0931・IMPL-1029 は降りていない規定として残す。次の2点を、IMPL-0931 の note と README に開示する。段で受けた行が、G-7 で帰属を確かめられない欠落になりうる(安全の側)。印の無い `G-5 PR-<番号>` の行は、段が受けず gate-g5 が失敗のままである
6. [ADR-0222](/process-compass/adr/0222-b20-run-record-isolation-and-provisional-license/) 決定1 の理由の一文「対象が G-5 の判定の行は、常に例外承認として対応づけず欠落になる」を、**置き換える**。段 mutation の閾値割れの行(対象 `G-5 PR-<番号>`・印あり)は、決定5 のとおり欠落にしない。ほかの G-5 の判定の行は、いまのまま欠落になる。決定1(暫定のライセンスの許可を構成で受け、台帳で受けない)は変えない。ライセンスの暫定の許可は印を持たず、決定2 の行の約束に当たらない
7. [ADR-0217](/process-compass/adr/0217-b20-exception-use-display-and-record-checks/) の影響の節の「止めるのは、7.9.4 の行の欠落(決定2)だけである」を、枠の超過の拒否(IMPL-0630。G-5 が PR の時点で止める)について置き換える。採用済みの ADR の本文は書き換えない
8. R2 の週次の定期実行(IMPL-1036)は、gate-g5 の外の週次のワークフロー(`mutation-weekly.yml`。schedule と workflow_dispatch)で降ろす。週次の型(`PIT_IN_MUTATION_MODE=weekly`)は、イベントが schedule か workflow_dispatch のときだけ有効で、pull_request・push では無視して通常の判定に戻る。週次の型は必須の判定をせず、コマンドが空なら何も測っていない旨を注意に出して終了コード 0、閾値割れも終了コード 0 で段の出力の1行とジョブの要約(`GITHUB_STEP_SUMMARY`)へ出す(附属書H H.1「合否条件にしない」)。コマンドの終了コードが 0 でない・出力の行が壊れているときだけ失敗とする(実行できなかった事実)。比較の起点は置かず、範囲は段のコマンドが決める。gate-g5 の集約とブランチ保護に入れず、ジョブの名も gate-g5 にしない。IMPL-1036 は delivered・manual とする(機械が見るのはワークフローの存在と形・週次の型の段の挙動まで。既定のコマンドは空で何も測らず、定期実行が止まったことの検知は無い。確かめる者: G-6 の判定者)
9. 段が行で閾値割れを受けた事実と、G-7 の照合の結びは機械で閉じない。G-7 が見るのは行の形(対象・印)と帰属・期限だけである。段がその行で受けた事実は、段の出力の1行(ジョブのログ。保持の期限がある)と承認した者の宣言行に頼る(manual)。受けたスコアの妥当性・理由の当否・回収の中身は、承認した者と G-6 の判定者が確かめる。手引き(exception-paths.md)は、承認した者に、宣言行のレビューを出す前に段の出力のスコアを読み、受容した理由の欄へ書くよう求める

決定の注1: 印に下限(`下限: N`)を書かせ、スコア ≥ 下限を機械で比べる案は採らない(下の表)。

決定の注2: 作成者の排除は、行の側(決定2 の6)と帰属の部品(`exceptionReviewBacking`)の両方が持つ。行の側の判定は、受けない理由の文言を早く正しく出すために残す。同じ部品の呼び出しで、別の定義ではない。単独では陰性の確認で観測できない(外した複製でも、帰属の部品が同じ者のレビューを退けるため落ちない)。

## 課さないと決めたこと

- 規制要件の段(regulatory)の不合格を台帳の行で受けること(ADR-0224 決定7 のまま)
- CL1 以上の行への承認者の追加の独立(上位の者など)。ADR-0153 決定3 のまま。EV-0295 の差し替え条件で再審議する
- 期限の書き換え(延長)を段で見ること。範囲の始点と終点で見る G-7 の機械(IMPL-0787)に任せ、段では二重に持たない
- 返却の目安への上限の機械検査。既存の例外の行と同じで、遠い日付は書ける
- 段が行で受けた事実を、出荷の集約が段の出力と突き合わせること。段の出力はジョブのログで、保持の期限がある
- **受否の判定を、変更のコードを実行しない判定へ移すこと**。ADR-0115 決定1(変更のコードを実行しない判定は、判定のコードと構成を基底から読み、変更の側の出力を信頼しないデータとする)との突合: 帰属の照合は段のジョブ(変更の側)の中で行う。段の出力の行と、受否の材料(PR の記録の一時ファイル)は、PR の側のコードから偽れる。これは EV-0339 の manual と同じ水準で、新しい抜け道ではない。G-6・承認した者が、段の出力と宣言行を読んで確かめる(manual)。基底の構成・基底の台帳は基底から読み、取れないときは作業ツリーへ倒さず受けない
- 台帳の行の判定を、check-pr(`exceptionFor`)と同じ関数にすること。check-pr は対象の形(`PR #N`)と入力の形が違う。両関数の「受けない理由」の集合の一致の試験は足さない(二重の定義であることを、本 ADR で開示する)
- 週次の閾値割れを失敗にすること、週次の比較の起点を定めること

## 検討した選択肢(採らない)

| 案 | 採らない理由 |
| --- | --- |
| 対象を `PR #N`(変更の行)で書かせる | 集約の変更の照合が、その行を当該の PR の例外承認として対応づけ、G-6 を経ない変更の例外にも数えうる。G-5 の閾値割れの承認が、別の基準の例外として効く |
| 帰属に、行を入れた PR の作成者・承認者(ADR-0106 の (B))を段で受ける | 段のジョブにホスティングの照会を広く足す。行は1つの PR に限る記録で、対象の PR の上のレビューはいつも出せる |
| 印に下限を書かせ、スコア ≥ 下限を機械で比べる | 下限を書くのは行の書き手で、0 を書けば空になる。承認の後にコミットが変われば、先頭一致の (A) で承認が効かなくなる。残るのは同じ先頭での再実行の揺れだけで、失うのは承認した者の目の前の PR の中に限られる。新しい書式に釣り合わない |
| 終了コードが 0 でなくても行が読めれば受ける | 閾値割れと道具の失敗を見分けられない(決定可能でない) |
| 受否を pr-rules(check-pr)で決める | 段の結果は段のジョブにあり、ジョブ間で結果を渡す結合が増える。check-pr は別の束が変更中 |
| 集約が PR ごとの段のスコアと行を突き合わせる | 段の出力はジョブのログで、保持の期限がある。段の時点で受否を決め、行を台帳に残す |
| push の経路を一切受けない | 受けた PR のマージの後に、既定ブランチの G-5 が必ず失敗する。失敗の表示を見過ごす習慣を作る |
| 既定ブランチに既に入った行だけを受ける | 閾値割れの PR 自身を通せず、経路が成立しない |
| U6a で `unjudgedGateExceptions` を先に緩める・段だけを先に push する | 段は受けるが G-7 が取り下げを指示する途中の状態を採用者へ出す。IMPL-0996 が delivered のまま実態だけ弱まる窓を作る。template の push は1回にまとめる |
| 帰属を (A) のレビューだけにし、期限・AI の名義・指示者の排除を外す | 既存の例外の照合と食い違う別の定義になる |
| コミットのメッセージの `(#N)` から PR を推す | マージの方式に依り、決定可能でない |
| `PR #N` の形の行への診断の文 | 候補なしの案内(行の書き方の所在)で足りる |
| 週次の実行で閾値割れを失敗にする | 附属書H H.1「合否条件にしない」。閾値を下回ったままの構成で毎週の失敗が続くと、失敗の表示を見過ごす習慣を作る |
| 週次の比較の起点を7日前に定める | H.1 は「週次の定期実行」までで、範囲を定めていない。範囲は段のコマンドが決める |
| IMPL-1036 を machine と表示する | 既定は空で何も測らず終了 0。表示が実態より強い |
| R2 の週次を別の Issue へ付け替える・採用者に委ねる | 合う open の Issue が無い。先例(context-drift.yml)の cron で決定可能な形に降ろせる |

- 準拠テンプレートの文書: 手引き `exception-paths.md`、様式 `03-debt-ledger.md`、README の移行の注意(項21 の文の改めと項23)
- 道具の側で閾値を終了コードへ結ぶ(Stryker の `thresholds.break` を `PIT_IN_MUTATION_THRESHOLD` に合わせる等)と、閾値割れが終了コード 1 になり、台帳の行で受けられない。README に書く
- 出荷の集約の改め(決定5)は束 U6c で降ろす。それまで IMPL-0931・1029 は降りていない規定として表示し続ける
- 本体: IMPL-0996・0931・0763・0930・1029 の note の改め、IMPL-1036 の delivered 化、`src/data/impl-targets.yaml` への workflow の登録、根拠水準マーク2件

## 根拠水準

- squash 以外のマージの方式での push の照合、実際の GitHub の応答・権限は確かめていない。EV-0347 で開示する
- 週次の実行の所要時間・費用の公開の実測が無く、実際の cron の起動も確かめていない。EV-0348 で開示する
- 機械が確かめるのは行の約束の8条件・終了コード・行の構文・基底の閾値との比較・push の照合・週次の型が効くイベントまでである。受けたスコアの妥当性・理由の当否・回収の中身・承認した者の権限・週次の結果を読むことは manual である
