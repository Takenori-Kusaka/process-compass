## ステータス

採用(2026-10-23)。採用済みの ADR の決定を置き換えません。[ADR-0078](/process-compass/adr/0078-rejudge-on-change-and-irreversible-operation/) 決定6(G-5 基準3 の測る範囲を企画時に決める)を、既定の範囲と開示で**補います**。決定6 の「範囲を選べる」は保ちます。ADR-0078 のステータスの節は変えていません。

## コンテキスト

[#296](https://github.com/Takenori-Kusaka/process-compass/issues/296) は、固定定数の棚卸し(#295)の後継として、本文の固定値と、その値を支える規範・実装の食い違いをまとめた Issue です。指摘をそのまま条項にせず、調査2本と会議体5名の意見書で扱いました。記録は `research/296-deliberation/`(`decision.md` の L-1〜L-11)にあります。本 Issue は値を動かす材料を持ちません。値を動かさず、根拠水準を開示し、方法と記録を求める形を基本にしました。

### 見つかったこと

- G-5 基準3 は範囲を選べる(ADR-0078 決定6)が、第4章「AI 品質指標の扱い」の別の節は新規の範囲に限っていた(#294 の突き合わせ漏れ)。全体の割合は、変更で加えたコードの未被覆を既存の被覆で薄める。準拠テンプレートは全体の割合だけを測っていた
- 承認が承認した差分に束ねられることは、G-6 の構造の前提なのに、ルールセットの設定の値にしか無かった。`team` のルールセットの実環境の確認と契約検査は、承認の失効の設定を見ていなかった。集約も、承認の版と取り込んだ版を比べていなかった
- 自己修正の停止条件は、第3章 3.12.10 が既に定めていた(連続失敗・無進捗・累積消費。回数だけの遮断を採らない)。準拠テンプレートの `self-heal.mjs` は担い手の申告する回数だけで止め、記録は `.gitignore` の下にあった。規定の附属書H が、参考の附属書E E.7 を根拠に使っていた。E.7 の「7.7.2 の指標へ算入」には行き先が無かった
- 「手戻り率」の名で、本文に4通りの定義があった。第4章の行の書き換えの比率は、閾値を確定すれば合否条件になりえた。母数の規則は「最小標本数または観測の窓」で、窓だけでも満たせた
- 監査の抽出数の単位(案件・変更のいずれで数えるか)と、全件にする境界が書かれていなかった
- 10名の境界、カバレッジの 80%・90%、14日・30件・四半期、差し戻し率0%の2か月、引き上げの観測窓3か月に、根拠水準の開示が無かった
- 運用メトリクスは「現在の指標体系は上限20件に収まる」「手集計の指標は無い」と書いていたが、いずれも事実と異なっていた
- 確約範囲・コア指定のパスは、実在しないパスを1本書くだけで宣言済みとして扱われ、規模の基準なし(null)が全変更に効いた

## 決定

### 1. G-5 基準3 の既定の範囲を、変更で加えた・変えたコードとする(L-1)

範囲を選べることは保ちます(ADR-0078 決定6)。既定を変更で加えた・変えたコードにします。全体で判定する場合は、変更の未被覆が全体の被覆で薄まることを保証の開示に記録しなければなりません。結果には、測った範囲・分母・測っていない製品のファイルの数を出します。記録した範囲と構成の範囲の一致を、契約検査で確かめます。第4章「AI 品質指標の扱い」は、基準3 を記録した範囲で判定すると改め、適用範囲を見出しへ移しました。80%・90% に EV-0143 を付けました。準拠テンプレートの node のアダプタは、変更で加えた行と行単位の被覆から変更の範囲を測ります(IMPL-0245)。他のアダプタは `undelivered` です(IMPL-0259)。

### 2. 承認を、承認した差分に束ねる(L-2)

G-6 の条件の表の後の箇条に、「承認は、承認した差分に対して数える。差分を変える更新の後は、その承認を数えてはならない。差分が同一であることを機械で確かめられない更新は、差分を変える更新として扱う」を置きました。第3章と ADR-0067 が「4条件」を数で引くため、表の5行目にはしていません。出荷の証跡の集約は、承認したコミットと取り込んだ PR の先頭を比べ、異なる承認を数えません(IMPL-0263)。契約検査と実環境の確認は、`team` を含むすべてのルールセットで承認の失効の設定を確かめます(IMPL-0264・0265)。

### 3. 自己修正の停止は第3章 3.12.10 を正本とする(L-3)

3.12.10 に実装マークを付け、降ろし先 `self-heal` を登録しました。準拠テンプレートの `iterate` は、自らテストを実行し、失敗したテストの識別を記録します。連続失敗(反復の上限)と無進捗(同じ失敗の集合の連続)で保留にし、解除は名簿の人の名義に限ります。記録は追跡する置き場に置きます。単一タスクの累積消費は測らず、`undelivered` です(IMPL-0277)。E.7 は 3.12.10 を引く手引きへ改め、根拠の無い経験則の文と、行き先の無い参照を外しました。附属書H は 3.12.10 を引きます。登録簿の RC-05 は、3.12.10 の初期値の名へ改めました。

### 4. AI 生成行の短期書き換え率を、合否条件から外す(L-4)

第4章の量を「AI 生成行の短期書き換え率」と呼び、合否条件にしてはならないとしました。行の帰属は推定にすぎず、合否にすると AI の関与を記録しない動機が生まれ、AI関与率と生成の条件の追跡を壊すためです。運用メトリクスの「手戻り率」はタスクの単位の量とし、差し戻し率(G-6 の変更を求められた PR の比率)を含めないよう整理しました。5.4.6 と三識は、それぞれの量を名指しで引きます。母数の規則は「観測の窓を定め、窓の中の件数が最小標本数に満たない値を判断に用いない」へ締めました。14日に EV-0144、30件・四半期に EV-0145 を付けました。

### 5. 規模の観測と算定を、差し替え条件を観測できる形にする(L-8・L-9)

出荷の集約は、規模の超過の理由の内訳と、別集計の倍率の分布(1倍・2倍・5倍を超えた件数)を出します。EV-0084 の差し替え条件を観測できないと、マークは見直されないためです。5倍は据え置きます。文書の置き場の判定は、文書・データの拡張子を列挙して外し、それ以外を製品として数える形へ反転しました。拡張子の無いファイルは先頭の `#!` で判定します。確約範囲・コア指定のパスが追跡中のファイルに1件も当たらなければ、未宣言として扱います。

### 6. 監査・境界・登録簿の値の根拠を開示し、単位を書き分ける(L-5・L-6・L-7)

監査の抽出を2段(案件 → 案件の中の変更)にし、段ごとに母集団・方法・件数・結果・再現の手段を記録します。母集団が5件未満の段は全件とします。委任の事後監査の5件は変更の件数と書き分けました。登録簿の RC-11 を「監査の周期と抽出数」へ広げました。10名の境界に EV-0148 を付け、人数は表5 の人で数え、AI の担い手と外部の確認者を数えないとしました。5.4.6 の「差し戻し率0%が2か月」を RC-12(能力に依らない)として登録し、EV-0146 を付けました。RC-09(3か月)に EV-0147 を付けました。G-5 基準6 の分量の上限は、降りていないことを本文に表示しました(IMPL-0222・0269)。

### 7. アカウント名の確認と、登録簿の整合の検査を確かめられる形にする(L-9・L-10)

AI を示す語を含むアカウント名の人は、本人以外が記名した名簿の変更がある場合だけ、人のアカウントとして数えます。確認によって数えた承認の件数を開示します(IMPL-0266)。登録簿の整合の検査に、要求事項4 の区分と JSON の `capabilityDependent`・`noRelaxByCapability` の一致、`configKey` の実在の照合を足し、変異試験で固定しました。運用メトリクスの表は候補の一覧とし、正式指標は採用組織が手続1〜4 を経て採った指標と定めました。上限20件は正式指標に掛かります。完了スループットの対の指標を滞留期間と明記し、第4章「ゲートの健全性」の表は運用メトリクスを参照する形にしました。

## 課さないと決めたこと

| 論点 | 課さないこと | 理由 |
| --- | --- | --- |
| L-1 | カバレッジの基準値を実績へ機械的に追従させる方式(ratchet) | 運用メトリクス「実績を基準へ機械的に変換しない」の規定1・2 に反する。使われていないコードの削除が失敗として現れる。機械が基準値を書き換える経路が、基準値を改変できる証跡になる |
| L-1 | 基準3 の範囲を変更のコードに固定すること(ADR-0078 決定6 の一部置き換え) | 変更の範囲を測る手段を持たない言語・構成の案件が、基準3 を満たせなくなる。全体で判定する場合の薄まりは開示で扱う |
| L-2 | 承認の後の更新を「些末な変更」と申告して承認を持ち越すこと | 申告で外せる条件は、分類で閾値を外せる(ADR-0073 決定1 と同じ理由)。差分の同一を機械で確かめる持ち越しの手段は今は無い |
| L-3 | 連続失敗回数(停止の総数)の上限の廃止 | 失敗の内容が毎回変わる振動は、無進捗の判定では止まらず、累積消費の上限まで続く。3.12.10 の「単独では不十分」の表と、費用の歯止めを失う |
| L-5 | 抽出数を母集団の大きさに比例させること | 監査の標本の理論で、母集団の大きさは必要な抽出数にほとんど効かない。大きな組織では過大、小さな組織では過少になる |
| L-6 | 人数の境界を採用組織が定める形 | 自己申告で厳しい列の規則を外せる。ADR-0044 決定4 が退けた「自己申告の閾値で適用範囲を切る」と同じ型である |
| L-6 | 10名の境界を能力依存の定数の登録簿に載せること | 組織の構造に由来し、担い手の能力に依らない |
| L-7 | 本標準の起草者が登録簿の定数を自ら再評価して記録すること | 登録簿の再評価は、変化点を持つ採用組織の人が記名する手続である。契機と記名の無い記録が、登録簿の運用に見えてしまう。本標準の値は EV の見直し日で見直す |
| L-8 | ファイル数だけの超過の軽減 | ADR-0058 決定1 が正である。作成側の「機械的な変更」の申告で検査を外す経路を作らない |
| L-8 | `/pit` の注記に規模の数値を出すこと | ADR-0058 決定7(AI への指示から規模の数値を外した)による |
| L-9 | AI の担い手の名の語彙を、AI に特有の形に限って人のアカウントとの衝突を減らすこと | 検出を危険側へ緩める |
| L-9 | 規模の観測に前回の集約との比較を出すこと | 何を判断するための比較かを書けない。決定性の試験だけを足した |
| L-10 | バックログの純増を指標に置くこと | 作業単位の分割や早い完了でスループットが歪んでも逆向きに動かず、対の指標の要件(手続2)を満たさない。ADR-0074 決定8 のまま |

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 基準3 を変更の範囲に固定する(起草の原案) | 決定1 のとおり。測る手段の無いアダプタの案件が基準3 を満たせない |
| G-6 の条件の表に5行目を足す | 第3章と ADR-0067 が「4条件」を数で引く。箇条に置けば条件の数は変わらない |
| 自己修正の規範を 5.8 か 7.7 へ新設する | 規範は 3.12.10 に既にある。2か所目を書くと、同じ停止に2つの初期値が並ぶ |
| 停止の総数を外し、同じ失敗の連続だけで止める | 交互の失敗で止まらず、累積消費の歯止めを失う |
| 「手戻り率」の名を1つに統一し、定義を1つに揃える | 第4章の量(行の書き換え)と運用メトリクスの量(タスクのやり直し)は別の量である。同じ名で呼ぶと、5.4.6 の検知条件がどちらを指すかが決まらない |
| 監査の抽出数を母集団に比例させる(起票の案) | 課さないと決めた。母集団の大きさは抽出数にほとんど効かない |
| 10名の境界をチームの数へ替える | 境界の軸の変更は材料が無い。別 Issue で扱う |

## 影響

- 準拠テンプレートの node の構成は、既定で変更の範囲のカバレッジを測る。変更した製品のファイルが計測されていなければ G-5 が失敗する。全体で判定する構成は、結果と保証の開示に薄まりが出る
- 承認の後の push は、`team` の構成でも承認を失効させる。集約は、承認の版を確かめられない承認を数えない。gh が返すレビューの版の項目は、実機で確かめていない
- 自己修正の `iterate` はテストを実行する。テストのコマンドがアダプタに無い構成では反復を記録できない
- 文書の置き場に置いた、列挙に無い拡張子のファイルは製品のコードとして数えられる。このため、規模の算定の値は増えうる
- 停止の累積消費、node 以外のアダプタの変更の範囲、比率の期間の集計、G-5 基準6 の分量の上限は、準拠テンプレートに無く `undelivered` で表示する
