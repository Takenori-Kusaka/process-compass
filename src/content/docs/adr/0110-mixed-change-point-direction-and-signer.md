## コンテキスト

準拠テンプレートの変化点の記録は、向き(`direction`)を1つの値で持ちます。値は、緩める・任免の決定・厳しくする・未達の発生・なしの5つです。1つの変化点が席の責任者の任免と緩める向きの行を両方含むとき、どちらへ寄せるかは、標準と ADR のどちらにも定めがありませんでした。導出は 2026-10-01 の初期実装から「緩める > 任免の決定」でした。

回帰の試験の 2名 mvp・growth cl0 の行は、p302 の観測で向き「任免の決定」を期待していました。ADR-0088 決定5 の実装の後は、確認者を任命して未達が解けると、代償措置の終了(カバレッジの下限 90 → 80)が緩める向きの行として同じ差分へ出ます。観測は「緩める」へ変わりました。#319 の突合 X-6 は、この変化を決定なしで期待値へ固定しないとしました。ADR-0089 は印を付けて本件へ送りました。

内部調査と実行による確認で、次のことが分かりました(`research/376-deliberation/`)。

- 標準は変化点の向きを1つの値として定めていない。第3章 3.13.3 は向きを変更ごとに扱い、任免を「統制の向きにかかわらず決定として扱う」直交の軸に置く。3.13.4 の記録の項目に向きの欄は無い
- 記名の照合は向きの値に依らない。任免の行と緩める向きの行を行ごとに照らし、1人の記名者に両方の要件を同時に課している。向きの値が変えるのは表示だけである
- X-6 が根拠とした matrix-sweep の元の注記「任免を同じ入力に含む場合、向きは任免の決定」は、任免と発生の優先を述べたもので、緩める向きとの優先の根拠にならない。同じ期待値の 2名 poc cl0 の行は、p302 から緩めるを期待していた。p302 の poc では `G-6 独立レビュー: 未達 → 適用しない` が緩める向きの行だった
- 1人では全行の要件を満たせない組がある。(a) 前任の決定者が離脱済みで、組織上の任命権者が決定者を任命する変化点に代償措置の終了が混ざると、任命権者は緩める向きの行を、新任の決定者は自分の任命を決められない。(b) 決定者の交代と緩める向きの行を1つの変化点に含むと、前任の決定者が緩める行の席の責任者として残らない限り、どちらの記名でも拒否される。どちらも、変化点を分けると通った
- 緩める向きの行の拒否の文言には、変化点を分ける案内が無かった
- 変化点の記録は、差分のどの行が任免でどの行が緩める向きかを残していなかった

Issue 本文の「ADR-0087 の決定5」は、ADR-0088 決定5 の誤記です。代償措置の終了を緩める向きの行として出すと定めたのは ADR-0088 決定5 であり、ADR-0087 決定5 は決裁権限規程の文の直しです。

会議体(起案・現場・品質監査・規格・弁護の5委員)の審議の記録は `research/376-deliberation/` にあります。

## 決定

### 1. 単一値の向きは要約とし、緩めるを優先する。両方を含むときは「緩める(任免を含む)」と表示する

- 1つの変化点が緩める向きの行を1件でも含めば、要約の向きを「緩める」とする。優先の順は、緩める > 任免の決定 > 未達の発生 > 厳しくする > なし である(今の導出を決定として記録する)
- 緩める向きの行と任免の行を両方含む変化点は、表示を「緩める(任免を含む)」とする。値(`loosen`)は変えない。表示は、行ごとの種類(決定3)を持つ記録に限る
- 単一値の向きを、記名の要件の根拠に使わない。要件は行ごとに照らす(決定2)。これを第5章 準拠テンプレートの「向きの扱い」へ書く

### 2. 記名者はすべての行の要件を満たす1人に限る。満たす者がいなければ受け付けず、変化点を分ける

- 1つの変化点の記名者は、その変化点のすべての行(任免・緩める向き・名簿の表記の変更)の要件を満たす1人に限る。満たす者がいなければ、その変化点を受け付けない。今の挙動であり、第3章 3.13.3 へ要求事項として書く
- 満たす者がいない場合は、変化点を分ける。決定者その人を替える変化点と、組織上の任命権者が記名する変化点には、緩める向きの行を入れない。緩める向きの行は、新しい決定者が記名する後の変化点で決める
- 拒否の文言に、分け方の案内を足す。案内は、名簿のだれの記名でも全行の要件を満たせない場合に限って出す
- ADR-0088 決定5 は維持する。代償措置の終了は、未達を解く差分に出る。分けた後も、終了の行は未達を解く変化点の差分に出る。決めるのは、その変化点の記名である(実行で確かめた)
- p302 で受け付けていた (b) の場面が拒否されることは、回帰ではなく正しい強化と判定する。p302 では緩める向きの行が出ず、その要件を照らしていなかった

### 3. 変化点の記録に、差分の行ごとの種類を残す

- 第3章 3.13.4 の記録に「変更の行ごとの種類」を加える。種類は、任免・緩める・名簿の表記の変更・厳しくする・未達の発生のいずれかとする。いずれにも当たらない行(名簿への追加など)は、その旨を残す
- 準拠テンプレートの変化点の記録(`changeLog[]`)は、差分(`diff`)と同じ順・同じ数の種類の配列(`rowKinds`)を持つ
- 旧い記録には無くてよい。移行しない。欄の無い記録は、種類の区分の無い記録として扱う。欄がある記録で差分の行と数が合わないものを、検査が問題にする
- 記名者が満たした要件の根拠(資格)は、行ごとに残さない。資格は記録の時点の構成から導ける

### 4. 兼務の行の分類を維持し、見つかった2点は後継の Issue で審議する

- 新しく生じる兼務の行を緩める向きの行とし、決定できる者を D-0 表1 の決定者に限る今の扱いを維持する
- 実行で次の2点が見つかった。どちらも本件の論点(向きの優先)の外にあり、兼務の禁止の規定(第3章 3.5)と小さい体制の扱いに及ぶ。調査と会議体を経ずに条項を置かない。後継の Issue [#432](https://github.com/Takenori-Kusaka/process-compass/issues/432) で審議する
  - 兼務を照合する鍵が席の組だけで、人を含まない。離脱(発生)で入った兼務は、後で別の人を置けるようになっても行が出ず、誰の決定にも掛からずに続く
  - 決定者は、自分が当事者になる新しい兼務を自分の記名で決められる

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 任免を優先する(案A) | 緩める向きの変更が要約から消える。任免の記名で全体が決まったと誤読させる |
| 向きを集合で持つ(案D) | 行ごとの種類(決定3)と同じ事実を2か所に持つ。`SIGNED_DIRECTIONS` を引く帰属の照合の移行で取りこぼす危険がある |
| 決定者を替える変化点で、緩める向きの行を変更前の決定者が決める | 緩める向きの行は変更後の構成で効く。決定の権限を離れる者に、その後の構成の緩和を決めさせることになる。外部の裏づけも無い |
| 任免と緩める向きの行の混在を一律に拒否する | 事業ステージ S1 では、任免と代償措置の終了の行を入力として分けられない場面がある |
| 2名の記名(連名)を要する | 第3章 3.13.4 の記録5 は決定した自然人を単数で定める。2名を要する根拠が無い |
| 組織上の任命権者に緩める権限を渡す | 任命権者は体制の外の人である。任免のために置いた名義で、統制の緩和を決められるようになる |
| 要件の和(どちらか一方の要件で足りる)とする | 統制の抜け道になる。任免を決められる者が、決められない緩和を同じ記名で通せる |
| 記名者の資格を行ごとに記録する | 記録の時点の構成から導ける。同じ事実を2か所に持つ |

## 外部の実務との対応(情報)

NIST SP 800-53 Rev.5 の CM-3・CM-4・CM-5(4)・AC-5 は、束ねた変更の承認の要件の合わせ方(最も厳しい要件・分割・和)を明文で定めず、組織に委ねます(転載で確認。原典は未読。2026-11-05 時点)。Prow の approve は、変更が触れたすべてのファイルについて承認者の承認を求めます。GitHub のルールセットは、食い違う定義に最も厳しい版を当てます。どちらも、要件を緩める合わせ方を採っていません。分割による迂回の禁止(FAR 13.003(c)(2))はあります。本 ADR の「分ける」は、要件を満たす者がいない場合に、各段をその段の要件を満たす者が記名する形であり、要件を下げる分割ではありません。緩める向きの行は、分けた後も決定者の記名を要します。ISO/IEC 27001 附属書A・ISO/IEC 20000-1・ISO 9001・ITIL 4 は原典を読めていません。EV-0228 の見直しで確かめます。

## 影響

- 第3章 3.13.3: 任免の表の後の箇条に、行ごとの要件と変化点の分け方を足した。IMPL-0444 と EV-0228 を付けた
- 第3章 3.13.4: 記録7(変更の行ごとの種類)を足した。IMPL-0445 を付けた
- 第5章 準拠テンプレートの「向きの扱い」: 単一値の向きが要約であること、優先の順、「緩める(任免を含む)」の表示、要件を行ごとに照らすこと、行ごとの種類の欄を書いた
- 準拠テンプレート: `generate-profile.mjs`(行ごとの種類の記録、分け方の案内)、`config.mjs`(表示の関数と欄の検査)、PR の検査6b の見出し・出荷の証跡の集約・プロセス構成の要約の表示、契約検査。導出の優先と `SIGNED_DIRECTIONS`、帰属の照合は変えていない
- 回帰の試験: matrix-sweep の 2名 mvp・growth cl0 の印を外し、期待の向きを緩めるへ改めた。(a)(b) を分けずに出すと拒否される場面と、分けると通る場面を固定した
- 分ければ通ることは、確かめた組にしか支えられない(EV-0228)。3名以上の体制と、外部の確認者が独立レビュアの席に就く組は確かめていない
- 1つの変化点で済んでいた (b) の場面は、2回の変化点に分ける必要がある。利用者の手数は増える
