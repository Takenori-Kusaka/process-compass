## コンテキスト

[#358](https://github.com/Takenori-Kusaka/process-compass/issues/358) は、エージェントの指示資産・権限・実行の記録の規定のうち、準拠テンプレートに降りていない 14 件と、試験の無い書き込みの遮断のフック 2 件を扱いました。本文の実装マークの番号は付け直しの後の番号とずれており、現在の番号で扱いました(`research/358-deliberation/intake.md`)。

内部の調査と実行での確認(`research/358-deliberation/survey.md`)と、外部の調査(`survey-external.md`)で、次のことが分かりました。

- 3.11.5 は「変更時に機械検査する」とし、検査項目に「既存の記述と矛盾しないか」「コードベースから導出できる内容でないか」を挙げる。自然言語の規則どうしの矛盾と、導出できる内容を決定的に判定する手続は無い。業界の道具が決定的に検査できているのも、分量・参照の実在・型の照合だけである
- 5.8.6 要求事項3 の「タスクの対象のパスに限る」は、エージェントがどのタスクかを選べる構成では境界にならず、タスクの外の作業(仕様・計画・記録の起案)の範囲も無い。タスクの対象のパスに限る実装は、読んだ提供者のどれにも無い
- Claude Code の権限設定では、許可の無い Edit は確認つき(ask)で、拒否ではない。実行基盤の隔離(sandbox)はシェルだけに掛かり、ファイルの道具・MCP・フックは隔離の外で、ネイティブの Windows では隔離しない。確認を自動で判定する権限の形では、確認つきは人の確認でもない
- 3.11.3「遵守が必須の規則を誘導層に書いてはならない」は、強制の手段が無い禁止を指示文の行で置くテンプレートの CLAUDE.md と、字面で食い違う
- guard-write のフックは、大文字と小文字を変えたパスを保護の型に照合しなかった。Windows と macOS の既定のファイルシステムでは、同じファイルを指す
- 公開のリポジトリの成果物は 90 日を超えて保てない。四半期の抜き取りの時点で、AI の確認の入力の記録が消えうる

軽の審議の2委員がそろって 3.11.5 の改廃を求め、5.8.6 要求事項3 の改廃で割れたため、重の審議(5 委員)で決めました(`research/358-deliberation/decision.md`)。

## 決定

### 1. 3.11.5 の機械検査を、判定できる2点に限る。矛盾と導出の判断は AI維持管理者のレビューで記録する

- 機械で検査するのは、1ファイルあたりの分量が上限内か(上限が無ければ「上限未設定」と示し、上限内と記録しない)と、導出できる内容のうち形で特定できるもの(ディレクトリの木の図など)の検出の2点とする。検出が 0 件であることを、導出できる内容が無いことの根拠にしない
- 既存の記述との矛盾と、形で特定できない導出できる内容は、AI維持管理者がレビューで確かめて記録する。AI の確認の指摘は材料に使ってよいが、機械の検査とこの確認のどちらにも数えない
- 「所有者定義により AI維持管理者のレビューを必須とする」を「AI維持管理者の本人の承認を必須とする。手段は所有者定義に限らない」へ改める。team の体制のルールセットは CODEOWNERS のレビューを必須にしないためである
- 3.11.3 の文言を「違反を許容できない規則を、誘導層だけに置いてはならない。降ろす手段が無い規則は、機械で止まらないことを示して誘導層に書いてよく、書いたことを守られた根拠にしない。降りていない規定として表示し続ける」へ改める
- 準拠テンプレートでは、G-5(`gate-g5-base`)が指示資産の変更を統制の設定の変更の承認と同じ数え方の範囲に入れる。陰性の確認は課さない。G-5(`pr-rules`)が行数・上限・木の図を一覧に出し、上限を超えたら失敗させ、個人用のファイルの追跡を失敗させる。PR の様式に「指示資産の変更の確認」の欄を置く(IMPL-0227・0501〜0504)

### 2. IMPL-0491 の主題を、拒否から指示文の行へ改める

本文は拒否の設定を課さず(ADR-0124 決定4)、PR を経ない取り込みは検出に掛からないと書いています。課していない拒否を `scheduled` と表示するのは、ADR-0084 決定4 の表示の誤りです。CLAUDE.md の行に禁止を置き、`[機械]` を付けません。

### 3. 5.8.6 要求事項3 の書き込みの範囲と「拒否」の語を定める

- 書き込みの許可は、既定ブランチへ入った実装計画の対象のパスの和と、強制層に列挙した計画外の置き場に限る。範囲を決める入力は既定ブランチの版から読み、エージェントは範囲を狭められるが広げられない。タスクごとの超過は要求事項10 の差で示す
- 本節の「拒否」は、求められた操作をせずに終えることとする。確認つきは拒否に数えない
- 準拠テンプレートへは、本件では降ろさない。計画の読み方と計画外の置き場の既定の一覧を決める実測が無く、誤った遮断で採用者がフックを外す危険があるためである(IMPL-0200。scheduled)。隔離が効く基盤のシェルとネットワークは IMPL-0506(scheduled)、隔離の効かない経路(ネイティブの Windows のシェル・MCP・WebFetch)は IMPL-0507(adopter)、秘匿情報の配置(要求事項4)は IMPL-0508(adopter)とする
- 秘匿情報の経路の読み取りは、初期化の前の権限設定でも拒否に置く(IMPL-0509)。読み取りの拒否は要求事項4 を満たさない

### 4. 書き込みの遮断のフックの表示を分け、照合の欠陥を直す

- IMPL-0198 は、ファイルの道具による強制層への書き込みの遮断と拒否の記録に限り、試験(`test-guard-write.mjs`)で `machine` にする。IMPL-0187 も `machine` にする
- 要求事項6 のうちシェルの経路は開いている。IMPL-0510(scheduled)として分ける。IMPL-0198 を根拠に要求事項6 の全体の適合を述べない
- フックの照合を、大文字と小文字を区別しない形に直す

### 5. 生成の条件の自動の記録は、観測と git のフックの形で、実機の確認まで降ろさない

道具の入力を書き換える形(`updatedInput` でコミットのコマンドにトレーラを足す)は採りません。確認の画面と実際に動くコマンドが食い違い、複合のコマンドで壊れるためです。履歴からの導出も採りません。コミットに無い変更と利用者の範囲の指示を落とした近似の値を、記録として出すためです。

採る形は、SessionStart で観測した値の記録と、git のフックによるトレーラの付与です。実機で確かめるまで `scheduled`(IMPL-0207)とします。Claude Code 以外の基盤(IMPL-0511)と、実行の記録の保持(IMPL-0512)は採用者に委ねます。5.8.2 の「指示資産の版」に、コミットに無い変更の有無と、利用者の範囲の指示は版を記録できない旨を足します。

### 6. AI の確認の入力の記録の保持を本文へ上げ、実機の確認まで降ろさない

附属書H H.4 に「条件2〜5 の確認の時点まで取り出せる状態で残す。実行の基盤の保持の既定に頼らない。期間は組織が定める」を足します。マークの注記にしか無かった要求です。準拠テンプレートでは記録用ブランチへ写す形を採り、確認の項目を IMPL-0492 の注記に置いて、GitHub Actions の実機で確かめるまで `scheduled` に残します。

### 7. 指示文で運べる行動の規則を CLAUDE.md へ降ろす

次の規則を、CLAUDE.md の行と常駐の規則の一覧へ置きます。

- 操作の要約を AI に生成させない(IMPL-0206。PR の「変更の概要」は操作の要約に当たらない)
- 「再現できる」と外部へ説明しない(IMPL-0208)
- 待つ費用を承認を急がせる理由にしない(IMPL-0257)
- 進捗を完了率の申告で書かない(IMPL-0282)
- 指示資産の保守(IMPL-0221・0223・0224)と外部ツールの採用(IMPL-0228・0229)

外部ツールの一覧は `.mcp.json` に置き、統制の設定として AI維持管理者の承認を要します。利用者の範囲のサーバーは案件の設定で止められません(IMPL-0505。adopter)。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 3.11.5 の3点を残し、矛盾の形(核の文言の否定、名指す仕組みの無い `[機械]` の行)を「形の検査」として降ろす | 形を検出しても「矛盾しないか」を判定したことにならず、採用者に文言どおりの主張をさせる。確かめる行為そのものは AI維持管理者のレビューとして残すため、統制は消えない |
| 矛盾と導出の判断を LLM の判定で「機械検査」とする | 決定的でない判定を検査と称させる。ADR-0012 と附属書H H.4 は、AI の判定を検出の層に限る |
| 分量の上限の未設定を G-5 の失敗にする | 値を組織に定めさせることを強いる。値を支える実証が無い(ADR-0084) |
| CLAUDE.md へ足す行を、既存の行を削って相殺する | 参考の値(200 行)を事実上の上限にし、ADR-0084 と食い違う。行数は一覧で出し続ける(テンプレートの CLAUDE.md は 210 行になった) |
| 指示資産の変更に陰性の確認を課す | 誘導層は止める仕組みでなく、陰性の確認の対象にならない |
| 5.8.6 要求事項3 を現行の文言のまま「計画の対象パスの和」と読む | タスクの外の作業の範囲が条文に無く、読み方が採用者ごとに割れる |
| guard-write で計画の対象パスの外への書き込みを本件で遮断する | 計画外の置き場の既定と計画の読み方を実測で決めていない。誤った遮断はフックを外させる |
| 実行基盤の隔離を置いて IMPL-0200 を delivered にする | ネイティブの Windows で効かず、ファイルの道具・MCP は隔離の外である |
| IMPL-0491 を、マージのコミットの第2親が既定ブランチから到達できるかで検出する | 手動のスタックの正当な同期と、禁じた取り込みが同じ形のマージのコミットになる |
| `updatedInput` でコミットのコマンドにトレーラを足す | 確認の画面と実際のコマンドが食い違う。複合のコマンドとヒアドキュメントで壊れる |
| 指示資産の版を履歴から導出する | コミットに無い変更と利用者の範囲の指示を落とす近似を、記録として出す |
| 入力の記録を成果物の保持の延長(retention-days)で残す | 公開のリポジトリは 90 日を超えられず、設定の上限で黙って切り詰められる |
| IMPL-0187・0198 を `check=machine` に1つで改める(Issue 本文の案) | 0198 の要求事項6 のうちシェルの経路が開いており、試験の範囲を超えた主張になる |

## 落ちうる検査と直し方

| 検査 | 落ちる場面 | 直し方 |
| --- | --- | --- |
| G-5(`gate-g5-base`)の承認 | CLAUDE.md・AGENTS.md・`.claude/skills/` ほか、または `.mcp.json` を変えた PR に、AI維持管理者の本人の承認のレビューが無い | AI維持管理者が承認のレビューを出す。`/process-change` が CLAUDE.md の生成区間を書き換える PR も当たる |
| G-5(`pr-rules`) | `CLAUDE.local.md`・`.claude/settings.local.json` を追跡へ入れた | 追跡から外す(`git rm --cached`) |
| G-5(`pr-rules`) | 指示資産が `.claude/guard.json` の `instructionAssetLimit.maxLinesPerFile` を超える | 分ける・削る。上限を変えるのは強制層の変更 |
| 統制の設定の陰性の確認 | `.mcp.json` を変えた PR に陰性の確認の節が無い | PR の様式の節を書く |

## 見直しの契機

- 計画の対象パスの和で書き込みを拒否する実装の実測(IMPL-0200・EV-0251)
- 隔離・SessionStart・git のフック・記録用ブランチへの写しの実機の確認(IMPL-0506・0207・0510・0492)
- 指示資産の変更の記録で、木の図の検出の誤検出と拾い漏れの観測(EV-0250)

## 影響

- 採用者: 指示資産の変更に、AI維持管理者の本人の承認が要る。規則の前に入った変更は遡って数えない。IMPL-0198 を根拠に 5.8.6 要求事項6 の全体の適合を述べていた場合は、主張を改める(シェルの経路は IMPL-0510)
- 適合の主張: 第1版は未発行であり、経過措置を置かない
- 番号: IMPL-0501〜0512、EV-0250・EV-0251 を使った
