## ステータス

採用(2026-11-17)。[ADR-0094](/process-compass/adr/0094-flow-observation-without-new-seats/) 決定4・[ADR-0099](/process-compass/adr/0099-reachability-forecast-three-bands/) 決定3・[ADR-0125](/process-compass/adr/0125-implementation-gaps-in-gate-forms-and-pickup/) を維持する。#359 の再確認の裁定のうち IMPL-0174 の表示を改める(決定1)。軽の審議の結論です(Issue [#443](https://github.com/Takenori-Kusaka/process-compass/issues/443)、`research/441-443-444-deliberation/decision.md` §2)。準拠テンプレートの変更は AI維持管理者の承認待ちです。

## コンテキスト

- #359 の残り(`issue=443` の 11 件)のうち、表示が実態と合わない項目、置き場が標準に無い項目、準拠テンプレートが読めない入力(会計・層の帰属)に依る項目が混ざっていた
- IMPL-0174 は機械の部分(`content-sampling.mjs`)も人の部分(/gate の節「四半期の抽出」)も template に降りているが、`scheduled` のまま残り、降ろす予定の無い規定を scheduled と表示し続けていた(ADR-0084 決定4)
- 完了スループットの述語が定まらず、7.7.3 の区分の入力が「候補」のままでは、2.10.2 要求事項4 の同じ定義が守られない

## 決定

1. IMPL-0174 は `state=delivered check=manual` とする。要求事項2 の機械の部分と、要求事項4 の確かめる者(判定者以外の人)の運び手が揃っているためである。`check=manual` が「機械は確かめない」と開示する。機械の統制とは読ませない(#359 の動機を保つ)
2. 準拠テンプレートは、既定の完了の条件を1つの決まった文で持つ(既定ブランチへ取り込んだ PR が `closes` で結び付き、完了の理由で閉じた作業単位)。完了の条件(2.10.2 要求事項4 の置き場。S0 の初回は企画書の欄、ステージ移行ゲートの後はその判定記録)がその文と完全に一致する案件でだけ、完了スループットを算定する。完了の条件を読む集計の処理は準拠テンプレートにまだ無い(undelivered)。降ろすときは、企画書の欄に加えて SG の判定記録の完了の条件を読む。これは IMPL-0374 の note で開示する。一致しない案件は「算定できない(完了の条件が既定と異なる)」と出し、IMPL-0377 では算定できない組とする。一致の判定は値の比較で、決定可能である。既定の述語が実際の完了を表すかは確かめていない(EV-0317)
3. 価値責任者の調整の記録は、第6章 テンプレ4 のゲート欄「価値責任者の調整」で残し、種別と理由は人が書く欄に残す。欄は名指しせず、5.7.2 の決断の記録の構造(確認していない事項の必須など)は課さない(2.10.5)。2.10.6 の見込みの評価と、選んだ手順と順序を記録する義務は、本 ADR では課さない(重の候補として #443 に残す)。「価値責任者の判断」の名は流用しない。IMPL-0954・IMPL-0899 は、束 C の裁定どおり flow-observation へ降ろす
4. adopter にするもの。いずれも、準拠テンプレートに読む源が無い
   - IMPL-1018(7.6 の予算の超過の見込みの入力): 会計の基盤に依る。IMPL-0499 と同じ置き場に記録する
   - IMPL-0615(累計消費): 会計の基盤に依る。採用者が割合で測り、7.6 を起票する。7.6 は `impl-no-adopter.yaml` に無く、人の起票の経路が残るため、統制は消えない
   - IMPL-0851(層ごとの個数の上限): 層の帰属を機械が読めるラベルの運用は課さないと決めた。採用者が数える手段を置く
5. IMPL-0500(`--pickup` が止めた件数)の置き場は、作業単位の Issue へ1行残す宣言行とする。書けなかった件数を別に出す。#359 の裁定5 が退けたのはコメントを読んで判定する経路であり、本案は結果を書くだけで判定に使わない
6. 5.7.5 の承認様式の周期的な変更は、提示(レビュー本文の雛形と判定記録の草案で確認を求める項目の示し方)に限る。判定記録の見出しと機械が読む欄、/human-verify の検証の順序は回さない。提示した版を記録する新しい欄は足さない
7. 2.10.4 の「着手した時点」は、本文に定義を足さず、準拠テンプレートの定義として開示する(IMPL-0283)
8. IMPL-0614 は、材料の集計(残る作業単位の個数・実測スループット・残る期間・SC-M の変動率)を template が降ろす。日程の見込みの評価と発火の判断は価値責任者が行い、機械はしない
9. 採らなかった案は下の表のとおり

## 結果

- 調整の記録は新しい様式のファイルを足さず、採用者に新しい義務を課さない
- 完全一致の規則は、既定の文を使わない採用者に、自分で数えて記録させる。2.10.2 要求事項4 のとおりで、今と変わらない
- 準拠テンプレートの実装(IMPL-0283・0374・0377・0614・0954・0899・0500・0175)は #443 で降ろす。それまで `state=undelivered` で表示し続ける
- 重の候補として残す点: IMPL-0899 の順序の違反を誰が確かめるか(他の席に置くと新しい義務になる)。2.10.5 と 3.10.1 の適用範囲の食い違いは #325 へ寄せる

## 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| IMPL-0174 を分け、要求事項2 を adopter にする | 条項と実装の境界が合わない。adopter の意味にも当たらない |
| IMPL-0174 を `scheduled` のままにする | 降ろす予定が無く、ADR-0084 決定4 に反する |
| IMPL-0174 を `check=machine` にする | 要求事項2 の残りが機械で閉じない |
| 完了スループットを「完了の候補」として数える | 7.7.3 の入力の定義と食い違う |
| 完了の述語を2段にし、作業単位ごとに完了の判定記録を求める | 新しい記録の義務になる |
| 完了の述語を G-6 の通過の記録にする | G-6 を省略する構成で数えられない |
| IMPL-0954・IMPL-0899 を adopter にする | 束 C の裁定の前提を取り違えている。欠けていたのは記録の定義だけである |
| 調整の記録に「価値責任者の判断」の名を流用する | `--pickup` の着手の前提と取り違える |
| IMPL-0851 のために層のラベルの運用を課す | 採用者への新しい義務になる |
| 日程の見込みを機械が判定する | 評価する者(価値責任者)が入れ替わる |
| 累計消費を template が推計する | 推計の源が無い |
| 提示した版を記録する欄を足す | 新しい義務になる。提示は PR の本文に残る |
| /human-verify の検証の順序や記録の見出しを回す | 検証の論理と機械の読み取りを壊す |
| IMPL-0283・IMPL-0377 を adopter にする | ADR-0094 決定4 と #359 の重の裁定4 に反する |
