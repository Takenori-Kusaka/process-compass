## コンテキスト

[#356](https://github.com/Takenori-Kusaka/process-compass/issues/356) の部分 A(降ろし方)は、第5章 5.6.2 と第7章 7.9 の `undelivered` 19件を扱います。2委員(起案と反対)の結論は割れました。起案は `adopter` 0件、反対は 9件でした。議長が規定ごとに裁定しました。

- 注入した欠陥が出荷物へ流出すると、取り消せません。標識の残存を止める第3層・第4層(IMPL-0047・IMPL-0192)は、降ろす価値が最も高い
- 第4層には、演習をしない採用者のタグが全部落ちるという懸念がある。走査を出荷の経路の中で毎回無条件に走らせ、記録を準拠テンプレート自身が作れば解ける
- 標識の可視性と秘匿(#356 B の K-1)で形が変わりうる規定は、いま固めません
- 運用中の継続の注入は、人が準拠テンプレートの外で行う。止める対象の仕組みが準拠テンプレートに無い

## 決定

### 1. 第3層・第4層を、準拠テンプレートの出荷の経路で毎回無条件に走らせる(IMPL-0047・IMPL-0192)

- 走査(`scripts/gate/seeded-error-scan.mjs`)は、範囲(直前のタグから当該タグまで。最初のリリースは根から)の全コミットの本文に、行頭の空白を許した標識の行(`Seeded-Error:`)が1件でもあれば失敗する。トレーラの解析だけには頼らない(squash で0件になる)
- 標識の文字列は走査の中の定数1か所に置く。標識の形が B-4 の審議で変わっても、1か所で直せる
- 台帳の照合は、採用者が `--ledger` でリポジトリの外の台帳(キー `id`・`expiresAt`・`reclaimedAt`)を渡したときだけ行う。渡さなければ、記録に「台帳と照合していない」と出す。失敗にはしない。ship-evidence には台帳を渡す入力を足していない(台帳の所在は B-1・B-4 の結論に依る)。照合は、採用者が走査の手順へ入力を足したときだけ働く。台帳を渡したのに読めない・解けないときは、走査を成立させず(scanRun false・failures)、集約が失敗にする
- 走査の記録 `evidence/seeded-error-scan.json` は、`ship-evidence` のタグの実行が集約の前に同じジョブの中で作る(`evidence/` は `.gitignore` の下にあり、別のジョブへ届かないため)。verify ジョブも、集約の再実行の前に同じ範囲で走査し直す
- 集約は、記録の欠落・`scanRun` が true でない・`residual` が 0 でない・範囲(起点と終点の SHA)が対象と合わない、のいずれかで失敗する。表示は項目6(検出率)とは別の行にする
- 記録と表示は「標識の残存なし(手で写した変更は走査の対象外)」と書き、流出がないとは書かない。条文は「4層あっても流出しないと記録してはならない」と定める
- 標識の文字列を説明に含むコミット(文書の変更など)も失敗になる(偽の失敗)。失敗の文に「本文から語を外すか、第7章の例外承認で受ける」と書く。除外の規則は足さない。標識の形が B-4 で変わりうるため。EV-0291 の対象に含める
- 採用者に新しい義務は生じない。条文は既に、記録の無い出荷を失敗と定めている

### 2. 手引きで降ろす規定(IMPL-0160・0161・0163・0196・0168)

- IMPL-0160(用途の限定): 基準の様式の注意書きとスキルに限定の文を置く。`delivered check=manual`(確かめる者: 品質保証の担当)
- IMPL-0161(周知): 導入前の検証の分だけを降ろす。基準の様式に行「注入の事前周知の記録の所在」を足し、未記入なら `run` を実行しない。`delivered check=presence`(単位: 欄)。周知の中身は確かめない。行を持たない旧い様式は、`env` の行と同じく実行を止めず、記録に「様式に行なし」と出す
- IMPL-0163・0196(性質と箇所の制約): スキルの手順に要件3〜9 を案内し、レビューの観点に確かめを置く。`delivered check=manual`。基準の様式に欄は足さない。欄の存在の確認は、性質を確かめた根拠に読まれるため。依存のファイルへの警告も置かない。一覧は網羅できず、警告の不在は要件の充足の根拠に読まれるため
- IMPL-0168(結果の反映): 経路は既にある(欠陥の台帳の様式の節「是正の記録」と、スキル `adoption-trial` の手順)。マークの注記の「経路が無い」は誤りだったので直す。`delivered check=manual`。起点の記録と行の対応は IMPL-0497 の領分

### 3. 運用中の継続の注入の7規定は採用者に委ねる(`plan=adopter`)

運用中の継続の注入は、人が準拠テンプレートの外で行います。台帳・停止・申請・頻度の仕組みの定義は、#356 B の結論(注入する者の扱い(B-1)、標識の形(B-4)、数える単位(B-5))で変わります。先に作ると、結論が出た後で作り直しです。

IMPL-0161 の運用中の分は、番号と意味(周知)を保つため IMPL-0991 に分けます。降ろし先が準拠テンプレートの内(導入前の検証)と外(運用中)で混ざるのは、この規定だけです。

| マーク | 規定 | 採用者に委ねる理由 | 採用者に求めること |
| --- | --- | --- | --- |
| IMPL-0991 | 運用中の継続の注入の事前周知 | 継続の注入は準拠テンプレートの外で人が行う | 周知の記録を残し、周知なしに注入しない。品質保証の担当が記録を読む |
| IMPL-0197 | 識別子を含めない(台帳と検査の出力) | 運用中の台帳が準拠テンプレートに無い。導入前の検証の記録の扱いは ADR-0067 決定6 による | 台帳と出力に検出者・見逃した者・受注者の識別子を含めず、集計をチーム・工程の単位に限る |
| IMPL-0164 | 頻度・難度 | 条文が件数を定めず、組織が決める(附属書H H.7)。破られて失うのは測定の妥当性だけ | 測定として意味のある件数を蓄積できる頻度を置く。難度を前期の検出率から機械的に決めない。件数が足りないときは条文どおり開示する |
| IMPL-0193 | 停止の4条件 | 止める対象の注入の仕組みが準拠テンプレートに無い。期限を超えた未回収は IMPL-0047 が出荷で止める | 4条件で注入を自動で止め、停止の解除を人の操作に限る |
| IMPL-0194 | 申請による停止 | 運用中の注入の手続である | 申請者を対象チームの責任者、承認者を品質保証の機能とし、期限と記録を要する。承認者を置けない小さい体制は、第7章の例外承認で受ける |
| IMPL-0387 | 示した箇所の内と外 | 運用中の注入が前提 | 内と外の検出率を分けて工程単位で記録する。件数が足りなければ条文が開示を求める |
| IMPL-0821 | 説明の提示との併用 | 併用を示す記録の定義が無い。定義を足すと、空の欄になる | 説明の提示を入れた判断に、欠陥注入の測定との併用を確かめる記録を残す |

これらは規定を課したままです。採用者の義務は条文のまま変わりません。

## 課さないと決めたこと

- 運用中の継続の注入の台帳(13キー)と台帳の検査を、準拠テンプレートに置くこと
- 第1層・第2層を、いま `machine` で降ろすこと
- 第4層を「演習を宣言した採用者だけ」に限ること。走査を無条件に走らせれば、限る必要が無い
- 標識の文字列を説明に含むコミットを除外する規則を足すこと
- 台帳を渡さない採用者の出荷を、失敗にすること

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 運用中の継続の注入の台帳と検査を準拠テンプレートに置く(起案) | B-1・B-4・B-5 の結論で中身が変わる定義を先に固める。損失は測定の妥当性で、項目6 の「未測定」の開示で受けている |
| 第1層・第2層を今 `machine` で降ろす(起案) | K-1 の衝突を実装で固める |
| 第4層を演習を宣言した採用者に限る(反対の示唆) | 適用範囲を限ると、条文より弱くなる |
| IMPL-0161・0163 に記入の欄を足し、欄の存在を確かめる(起案) | 欄の存在を確かめたことが、周知した・性質を確かめたの根拠に読まれる。IMPL-0161 は、実行を止める1行だけにした |
| IMPL-0196 で依存のファイルへの注入を警告する(反対) | 一覧は網羅できず、警告が出ないことが要件を満たした根拠に読まれる |
| IMPL-0193 を `scheduled` のまま残す(起案) | 止める対象の注入の仕組みが準拠テンプレートに無い。記録ができても止める先が無い |
| IMPL-0627・0666 の発動を、範囲ごとの見逃しを数えて一覧に出す(起案) | 数える単位が K-2 で決まっていない |
| 19件をすべて `manual` で降ろし、`undelivered` を0にする(反対が却下を提案) | 台帳の見かけのための案 |
| 走査をトレーラの解析だけで行う | squash で0件になる |
| マークを細かく割る | 番号の安定を保つ。IMPL-0991 だけは、降ろし先が内と外で混ざるため分ける |

## 実行で確かめたこと

- `adoption-trial.mjs run` は、基準の表に足した行を未記入の検査に乗せる。基準の読み取りは、行ごとの一覧に登録した行を `isFilledValue` で検査する。実行して、様式の説明のままなら問題を返し、記入済みなら返さず、行を持たない旧い様式は止めないことを確かめた(`test-seeded-error-scan.mjs`)
- `ship-evidence.yml` のタグの実行(`evidence` ジョブ)の中で、集約の前に走査の手順を挟めた。手順の本文を bash で動かし、記録ができ `residual` が 0 になることを確かめた。条件(`if:`)を付けないことも試験が確かめる
- verify ジョブは別のジョブで `evidence/` を持たないため、走査の記録が無いと集約の再実行が欠落で落ちる。verify ジョブにも、本文の印の範囲で走査し直す手順を足した。実機の GitHub では確かめていない
- 標識の照合を外した版では、取り込み4通りの失敗の場面が通ってしまうこと、集約の欠落・`scanRun`・`residual`・範囲の判定を外した版では、それぞれの失敗の場面が通ってしまうことを確かめた。試験が照合と判定を確かめている証拠になる

## 見直しの契機

- EV-0291 の見直し時期(2027-02)の到来
- #356 B の会議体で、標識の形(B-4)・数える単位(B-5)・注入する者の扱い(B-1)が決まったとき
- 採用者の走査の記録で、偽の失敗または見逃しが観測されたとき

## 影響

- IMPL-0047・IMPL-0192 は `delivered check=machine` になる。IMPL-0160・0163・0196・0168 は `delivered check=manual`、IMPL-0161 は `delivered check=presence` になる。IMPL-0991 を新設する
- 降ろし先 `seeded-error-scan` は予定の置き場から、準拠テンプレートのファイルの種別に改まる
- `ship-evidence` のタグの実行と verify ジョブに走査の手順が加わる。採用者は、演習をしなくても走査の記録を作る。標識の文字列を本文に含むコミットがある範囲は、出荷が失敗する
- 実行での確認は EV-0291 で開示する。GitHub 上の squash は確かめていない
