## コンテキスト

[#318](https://github.com/Takenori-Kusaka/process-compass/issues/318) は、#302〜#310 の申し送りとして、次の5点を問いました。

- 独立の強さを、承認者の人数ではなく組織上の距離で上げるべきか(ADR-0067 で先送りした論点)
- CL1 以上かつ S0 の G-7 の扱い
- ツールの要件の文書のシナリオ1 が、エンジンの出力と食い違っていること
- 未達が解けた後もカバレッジの下限 90% が残ること
- CL2 のブランチ保護を承認 1 の `safety` へ移したことを、既存の採用者へどう伝えるか

指摘をそのまま条項にせず、次の順で扱いました。記録は `research/318-deliberation/` にあります。議長の裁定は `decision.md` の R-1〜R-6 です。

- 調査: 内部1本(`survey-318-1-internal.md`)と外部1本(`survey-318-2-external.md`)
- 会議体: 起草・現場・品質保証と監査・規格・擁護の5つの立場(`council-01`〜`05`)
- 突合

判断の軸は、独立の強さを、記録から確かめられる属性で表すことです。

### 「組織的に独立」に定義が無かった

G-6 の独立した安全性の評価、軸E の表、附属書F 要求5 は「組織的に独立した者」と書いていました。5.8.4 の段階「最強」は「組織的な独立」と書いていました。どれも定義がありませんでした。小さな体制では、隣の同僚がこの語に読み替えられます。監査では、この語の充足を記録から確かめられません。

外部の調査が読めた範囲の安全規格は、どれも独立の強さを作成者からの組織上の距離で段階づけていました。人数で段階づける規格は見つかりませんでした。距離の判定の基準は、指揮系統・資源・リリースの権限の3つに収れんしていました(ISO 26262-2:2018 表1 の I3、IEEE 1012 の管理と財務の独立)。

### 2名の目的は、強さの段とは別だった

ADR-0067 決定1 は、承認者を2名とする目的を「1名の承認者の確認だけでは変更を取り込めない状態を作り、その記録を残すこと」と定めています。検出率の向上は主張していません。外部の調査が示す「人数で強さを上げる規格は無い」という知見は、本標準がもう主張していない主張への反論です。

### 5.8.4 と軸E が食い違っていた

附属書F 要求4 と 5.8.4 は、安全関連ソフトウェアのテスト生成の分離を段階「最強」としていました。軸E の表は、CL2 を「強」としていました。

### CL1 以上では、ステージが進むと統制が緩む逆転があった

ADR-0065 決定3 は、CL1 以上では S0 でも G-6 を適用すると決めました。G-7 は S0 で省略、S1 で簡略のままでした。G-6 のコア機能への限定(S1)も残っていました。結果として、CL1 以上の構成では、S0 が S1 より厳しくなる升がありました。

G-7 を省略しても、出荷の証跡の集約は独立の欠落を数え続けます。それでも、数えた欠落を読んで差し戻す席がありません。G-7 は G-6 の欠落を差し戻す唯一の場所です。

### 未達の代償措置で上がった下限が、未達の後も残っていた

未達の代償措置で、カバレッジの下限は 90% へ上がります。準拠テンプレートは、この値を基準値と区別せずに持っていました。席を記入して未達が解けても、下限は 90% のまま残りました。下げるには、理由の分からない記名が要りました。表示は、この値を「較正により変更」と出していました。

## 決定

### 1. 第1章 1.4 に組織上の距離の段1〜4 を定義し、人数とは別の軸に置く

| 段 | 名称 | 成立の条件(確認者と、実装の責任者・作成者との関係) |
| --- | --- | --- |
| 段1 | 別の者 | 別の自然人である(1.4「独立」) |
| 段2 | 別の指揮系統 | 段1 に加え、直属の上長が異なり、確認者が対象のリリースの権限を持たない |
| 段3 | 組織上の独立 | 作成の部門から、指揮系統・資源(予算と人事評価)・リリースの権限の3つで独立している(1.4「組織上独立した検証」) |
| 段4 | 第三者 | 別の法人で、案件に利害を持たない(1.4「第三者レビュー」) |

- 段は確認者ごとに、確認の時点で判定する
- 承認者の人数は段を上げない。段も承認者の人数を満たさない
- 段は評価・確認の活動に掛ける。G-6 の変更ごとの承認は段1 のままとする
- 1.4 の「組織上独立した検証」の定義に、指揮系統・資源・リリースの権限の3つの軸を足し、段3 と同じ条件にした。同じ組織の別部門でも、3つのいずれかで作成の部門と結び付く部門の検証は当たらない。既存の語を厳しくする向きの変更である(突合 X-2)
- 1.4 の「第三者レビュー」の「別の組織」を、段4 と同じ「別の法人」に揃えた。同じ企業グループの別の法人でも、資本・人事の関係で案件に利害を持つ者は当たらない。既存の語を厳しくする向きの変更である(突合 X-14)
- 段は数字で呼ぶ。外部の規格の記号は本文に並べない。対応は本 ADR の「参考: 外部の規格との対応」に情報として置く
- 体制の人数ごとに、内部で届く段と外部から調達する段を第8章 軸A に表で示す

### 2. 求める段と、届かないときの扱い

- 独立した安全性の評価: CL2 は段2 以上、CL3 は段3 以上
- 5.8.4 の段階「最強」の検証の担当者: CL2 は段2 以上、CL3 は段3 以上
- G-6 の承認: 段1(変えない)
- 届かない段は未達とする。外部の評価者を名簿へ登録して満たせる。登録が無い間は未達として表示し、CL1 以上は第8章により未達のまま出荷しない
- 理由を書いて低い段を選ぶ経路は置かない。基準を満たさないまま進める経路は、例外承認・前提の受容・未解決事項の3つで閉じている。例外承認は従来どおり使える
- AI の確認者は、どの段にも数えない。道具の適格性による算入の経路も作らない
- 段と、段の根拠(指揮系統・資源・リリースの権限。段4 は所属の法人と利害の有無)を記録する欄を、第6章 テンプレ4 と附属書F F.7 に置き、準拠テンプレートの様式と必須欄へ降ろす。段を記録から確かめられる属性として残すためである(突合 X-11)
- 値は暫定であり、EV-0180(E1)で開示する
- 構成への降ろし方は #357 へ渡す。対象は名簿の欄(直属の上長・所属の法人・部門・外部の評価者)、段の検査、IMPL-0080 の強化、IMPL-0184 である。それまで機械が確かめるのは段1 だけである(IMPL-0344 は `state=undelivered plan=scheduled issue=357`)

### 3. 5.8.4 と軸E の食い違いを、表の側を直して解く

軸E の表の CL2 を「最強(段2 以上)」、CL3 を「最強(段3 以上)」へ改めます。附属書F は CL2 から掛かる個別の要求であり、表の側を誤りとしました。CL2 にとっては厳しくする向きの変更です。

本文の「組織的に独立」「組織的な独立」は、すべて段を名指す語へ改めました。改めた箇所は、G-6・軸E・附属書F 要求4 と要求5・5.8.4・保証の主張の表・テンプレ4 の欄・準拠テンプレートの生成物です。5.8.4 の「段階的に上がります」から 1.4 を引きます。

### 4. CL1 以上では、軸B による G-6・G-7 の緩和をどのステージでも適用しない

規則 `r-e-cl1` に、次の2つを足しました。

- G-6 の範囲を全変更とする設定(S1 のコア機能への限定を取り消す)
- G-7 の省略・簡略を取り消す操作

CL2・CL3 の S0 で G-7 が適用に戻ることは、副作用ではなく、この規則による決定です。

取り消しを規則で書くため、テーラリングエンジンへ7つ目の動詞 `restore`(適用へ戻す)を足しました。性質は次のとおりです。

- 優先度の低い規則の省略・簡略・併合を取り消す。同じ優先度では、set と同じく、先に効いている省略を優先する(突合 X-9)
- 強化は下げない
- 対象が既に適用なら、何もしない
- 省略が無効化した設定(判定者の方式・レビューの方式など)を、省略の取り消しに合わせて戻す。復活したゲートが、省略の前に決まっていた設定を失わないためである。規則のファイルの読み込みの順で同じ優先度の設定が黙って落ちていた件も、この仕組みで戻す。省略を別の省略が上書きした場合も、先の省略が無効化した設定を引き継いで戻す(突合 X-8)

エンジンの試験で、体制2区分 × ステージ4区分 × CL0〜CL3 の全升の G-6 の状態と範囲、G-7 の状態を固定しました(IMPL-0345)。

CL1 の S0・S1 と CL2 の S1 にとっては厳しくする向きの変更です。構成を変える経路は構成の変更の手続だけであり、準拠テンプレートの取り込みは構成の値を変えません。このため、「即時に適用」を次のように降ろします(突合 X-4)。

- 現行の規則で再導出すると厳しくなる差(未適用の厳格化)を、取り込みの出力・次の一手の注記・保証の開示に、適用されるまで表示し続ける(IMPL-0349)
- 安全重要度 CL1 以上で G-6・G-7 が規則より緩いまま残る構成は、出荷の証跡の集約が欠落として数える。CL1 以上は、適用されるまで出荷しない
- 適用は、記名を待たない再導出で行う。AI の担い手は、表示を理由に構成を書き換えない

1〜2名の体制で CL1 以上または規制業の組み合わせは、構成そのものを認めません(ADR-0028)。エンジンは構成を拒否しないため、規則 `r-e-small-team-not-allowed` と `r-c-regulated-small-team-not-allowed` で、認めない組み合わせであることを提案の注記に出します。全升の試験は、1〜2名(確認者あり・なし)の升を含めます(突合 X-12)。

CL0 の S1 の G-7「簡略」の中身は、本 ADR の範囲外です。

### 5. カバレッジの下限は由来と基準値を持ち、代償措置の終了を同じ差分の中で決める

- 構成は、下限の由来(`ci.coverageOrigin`: 導出・代償措置・較正)と基準値(`ci.coverageBaseline`)を持つ。基準値は、導出値の 80(代償措置を除き、規則が G-5 を強める構成は 90)、または組織が較正した値である
- 代償措置は2つの層にある。規則の層(確認者を置けない体制の G-5 の強化。規則 `r-s-no-external-reviewer`)と、準拠テンプレートの未達の記録(`unmet[].compensation` の `ci-strict`)である。規則が代償措置と明言する調整には印(`compensation: true`)を付け、どちらも基準値の導出に数えない。回答や名簿を改めて未達が解けたら、その変更の差分に終了の行を出す(突合 X-1)
- 代償措置で上がった下限(90)は、未達の記録(`unmet[].coverageFloor`)に属し、基準値と分ける
- 未達を解く変更では、代償措置の終了(90 → 基準値)を、同じ差分の中に緩める向きの行として出す。その変更の記名で決める。別の記名の儀式は要さない。黙って戻すこともしない([ADR-0055](/process-compass/adr/0055-team-change-points/) 決定5)
- 「較正により変更」の表示は、由来が較正の場合だけに出す
- 由来の記録の無い旧い構成の下限は、黙って下げない。取り込みの際に、由来が不明である旨と戻す候補を表示し、採用者が記名で決める
- 試験は5つ置く。未達で 90、解けると差分に終了の行、較正の値は動かない、表示、旧い構成である。未達が名簿から生じる経路と、確認者なしの回答から生じる経路の両方を試す(IMPL-0346・IMPL-0348)
- 80・90 の値の根拠は EV-0143 のまま #296 へ渡す。安全規格に帰さない

緩める向きの行の決定者は、AI維持管理者の席(`RULE_APPROVER_SEAT`)の責任者か、D-0 表1 の決定者です。この決定者が第8章の決定者と食い違うかを確かめました。第8章「再実行の時点と向き」は、緩める向きの変更を「対象の席の責任者、または D-0 表1 の決定者」の記名で決めると定めます。強制層の閾値の変更は AI維持管理者が承認します(3.11.2)。準拠テンプレートの照合(`allowedDeciders`)は、対象の席の責任者と D-0 表1 の決定者を受け付けます。食い違いはありませんでした。

### 6. ルールセット `safety` を記録し、強制する承認は「下回らせない」とする

- #305 の実装で、準拠テンプレートは CL2(承認者1名)へ承認 1 のルールセット `safety` を導くようになった。これは ADR-0067 決定5 の帰結であり、本 ADR で決定として記録する(IMPL-0110 の注記に書き足した)
- 軸E の読み方の「ブランチ保護が強制する承認の数は、この表の人数と一致させる」を、「下回らせない。上回る承認は保証の主張に数えない」へ改める。本文が「一致」、実環境の統制の確認が「以上」で食い違っていた。「一致」のままでは旧い構成が不適合となり、採用者を緩める変更へ追い込む。本文の側を誤りとした
- 強制される承認の数が構成の数を上回るとき、契約検査は注記を出し、保証の開示の項目1 に並べて出す(IMPL-0347)。外から見える承認2 と、記録の保証1名分の食い違いを隠さないためである。改める前の契約検査は、上回る構成を黙って通していた。開示を足す向きの変更であり、緩める向きの変更ではない(突合 X-6)
- 下回るかは、承認の要求と承認者の数の大きいほうと比べる。承認の要求が承認者の数より小さい手書きの構成の穴を塞ぐ(厳しくする向き)
- 旧い CL2 の構成(`regulated`、承認2)は、そのままで不適合ではない。2件目の承認は保証の主張に数えない。`safety` へ移るには記名が要る。準拠テンプレートの README に、#302〜#310 と本件の告知を遡って置いた

### 7. 再導出すると緩める向きの差分になる更新を出すときの、保守者の手続

`community/standard-editions.md` に、保守者の手続を足しました。

- 準拠テンプレートの更新のうち、既存の採用者の構成を再導出すると緩める向きの差分になるものは、差分の行・理由・採用者の記名の経路を告知する
- 取り込みでは値を変えずに表示する
- 緩める向きの適用は、採用者の記名でだけ行う

### 8. ツールの要件の文書を、エンジンの出力に合わせて直す

`tool/requirements.md` のシナリオ1・2 を直しました。エンジンは変えません(ADR-0028 決定6)。

- シナリオ1: 確認者がいれば G-6 を省略し、CI の厳格化を伴わない。いなければ G-6 は未達で、CI の厳格化は代償措置であり代わりにならない。G-1(簡略)・G-3・G-8 も残る
- シナリオ2: 品質「高」の入力の欠落を補った。「推奨として付く」は、1.7.3 と当たるため改めた
- 冒頭に、この文書は規則の帰結を示す例で、標準の一部ではないと書いた。正本は標準と規則データである
- シナリオが主張する出力は、ペルソナの試験が持つ。確認者のいない変形を足し、各シナリオに試験の所在を書いた
- 文とエンジンの出力を機械で照合する検査は作らない

## 参考: 外部の規格との対応(情報)

本標準の段は、外部の規格の段と1対1に対応しません。規格ごとに、段の数も、段を掛ける活動も異なるためです。次の対応は、読み手が自組織の規格へ写すときの目安です。要求事項ではありません。

| 本標準 | ISO 26262-2:2018 表1(GB/T 34590.2 の公開の草案で読んだ) | IEC 61508(二次の解説で読んだ) | ISO/IEC 17020 附属書A |
| --- | --- | --- | --- |
| 段1 別の者 | I1 | 独立した人 | C型(同一の人が設計と検査を兼ねない)に近い |
| 段2 別の指揮系統 | I2(同じ直属の上長に報告しない) | — | — |
| 段3 組織上の独立 | I3(管理・資源・リリースの権限で独立) | 独立した部門 | B型(親組織の一部だが、責任を組織上分離する)に近い |
| 段4 第三者 | 規定の段ではない(外部の評価者で満たす) | 独立した組織 | A型 |

ISO 26262 と IEC 61508 の原文(有償)は読めていません。版と読んだ写しは出典台帳(SRC-0675〜SRC-0689)にあります。根拠の水準は EV-0180 で開示します。

## 検討した選択肢

採らないと決めた選択肢と、その理由です。

| 選択肢 | 採らない理由 |
| --- | --- |
| 承認者2名を、距離の要件へ置き換える | 2名の目的(ADR-0067 決定1)は、1名の承認者の確認だけで取り込めない状態を作ることで、強さの段とは別である |
| 2名の承認者の一方に距離を足す | 規格は距離を確認の活動に掛け、変更ごとの承認には掛けない |
| G-6 の変更ごとの承認に距離を掛ける | 同上。検証の独立は、規格でも「別の者」で足りる(DO-178C も同じ) |
| 理由を記録して低い段を選ぶ(IEC 61508 型) | 基準を満たさないまま進める4つ目の経路になる。小さな体制では常に使われる逃げ道になる。例外承認の経路は従来どおり使える |
| AI の確認を、道具の適格性によって段に数える(DO-330 型) | 道具の適格性の手続が本標準に無い |
| 段階「最強」を CL3 に限る | 附属書F 要求4 を CL2 で緩める |
| CL1/S0 の G-7 を省略のまま残す、または簡略にする | 省略では、出荷の証跡の集約が数えた独立の欠落を読んで差し戻す席が無くなる。「簡略」は本文に中身が無く、定義の無い語で出荷判定を緩めることになる |
| CL2・CL3 の S0 の G-7 を省略へ戻す | 安全適合性の検証の記録(附属書F)の判定者が消える |
| エンジンをツールの要件の文書のシナリオに合わせる | エンジンは ADR-0028 決定6(代償措置は未達の代わりにならない)に従う |
| 文書の文とエンジンの出力を機械で照合する | 文書は例であり、主張は試験が持つ |
| 未達が解けたら下限を黙って戻す、または戻すのに別の記名を要する | 黙って戻すと、緩める向きの変更が記名を経ない(ADR-0055 決定5)。別の記名は要らない。未達を解く変更の記名で足りる |
| 旧い構成を自動で移行する(`migrate`)、または不適合として落とす | 自動の移行は、記名なしの緩める再解釈になる(ADR-0085)。旧い構成は標準より厳しいだけであり、不適合ではない |
