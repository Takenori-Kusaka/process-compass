## ステータス

採用(2026-10-13)。[ADR-0027](/process-compass/adr/0027-process-name-pit-in/)の「影響」の文(適合の主張は、ゲート判定の記録とテーラリングの宣言による)を、条項として具体化します。[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)・[ADR-0050](/process-compass/adr/0050-enforcement-layer-is-not-staged/)・[ADR-0057](/process-compass/adr/0057-organizational-quality-assurance/)を置き換えません。決定1 と決定4 を、[ADR-0083](/process-compass/adr/0083-standard-edition-end-of-application-and-deviation/)が補います(2026-10-24)。決定1 の境は構成が設定済みになった最初のコミットと読み、決定4 の表には、従う本標準の版・逸脱・列挙に無い離脱と、逸脱を伴う適合の主張が加わります。適用の終了は同 ADR の決定2 によります。

## コンテキスト

[#306](https://github.com/Takenori-Kusaka/process-compass/issues/306) は、既にコードと履歴があるリポジトリへ本標準を後から入れる場合の扱いを問いました。指摘をそのまま条項にせず、調査・会議体・突合の順で扱いました。記録は `research/302-310-deliberation/`(`survey-306.md`、`council-B-01`〜`05`、`decision.md` の B-1〜B-4)にあります。

### 適合を主張する条件を定めた条項が無かった

本標準は「適合の主張」の語を使っていましたが、条件を定めた条項を持ちませんでした。拠り所は、ADR-0027 の「影響」の1文、第8章「調整は宣言を伴う」の1段落、附属書H H.8 の自己宣言の1行に散っていました。案件がいつから本標準を適用していると言えるかを定めた文は、ありませんでした。

フェーズ5 の `enablement.md` は「サンドボックスの承認を得た案件だけが本標準を適用する」と書いていました。既存の規程を持つ組織の文であり、規程を持たない体制には当たりません。

### 実行層は、既に境を持っていた

準拠テンプレートは、構成の初期化のコミットを境にしていました。初期化より前の履歴は、変更の件数に数えず、欠落にもしません。初期化の後は、導いたゲートの記録が無ければ、記録の欠落として出します。一部のゲートだけを働かせる途中の段階を表す値は、ありません。調査が、既存のリポジトリを模した複製で実行して確かめました。本文は、この境を「適用の開始」と呼んでいませんでした。

### 第1章 1.2 だけが、古かった

第1章 1.2 は、適用組織を「社内の品質マネジメントシステムまたは決裁権限規程を有する組織」としていました。1名体制を対象に数える決定は、ADR-0028(1〜2名の利用を想定から外す案を退けた)、[ADR-0056](/process-compass/adr/0056-assurance-argument/)、ADR-0057 にあります。第1章 1.9 も、1名体制が適用の内側にいることを前提に、保証を主張できない条件を書いています。1.2 は、これらの決定より前の文面のままでした。

### 外部の型

調査が読めた範囲では、導入の途中を適合の型として持つ規格はありませんでした。途中を名指しする枠組みは、水準の尺度の低い値として名指しします。その値は評価者が付けるもので、組織が自分で名乗る状態ではありません。適合を2値で扱う規格は、途中に名前を与えず、宣言した範囲で扱います。ISO/IEC/IEEE 12207:2017 の適合の箇条の本文は、読めていません。調査の記録は `survey-306.md` の2章にあります。

## 決定

### 1. 適用の単位は案件とし、適用の開始を、テーラリングの宣言を案件の記録に残した時点とする

適用の開始は、当該案件のテーラリングの宣言(第8章「調整は宣言を伴う」)を、案件の記録に残した時点です。準拠テンプレートでは、構成の初期化がこれに当たります。

適用の開始より前の変更は、本標準の要求事項の対象としません。適用の開始より前の案件について、本標準を適用していると表明しません。

境を開始に置きます。完了(導いたゲートがすべて働いた時点)に置くと、未達を残す1名体制が永久に適用の外へ落ち、開始から完了までの出荷が規定の外に落ちます。準拠テンプレートでは、境は履歴の1コミットで決まり、後から動かせません。

### 2. 適用の開始の後は、導いた要求事項のすべてを同時に適用する

満たしていない要求事項は、未達または記録の欠落として表示します。ゲートを順に有効にしていく経過措置は、設けません。

強制の前に、違反に当たる操作を観測するだけの期間を置く場合は、適用の開始より前に置きます。適用の開始の後に、強制層を観測だけの設定にしません。ADR-0050(強制層を段階にしない)と同じ向きです。

### 3. 導入の途中を表す状態を設けない

「導入中」「準備中」「一部適用」に当たる状態と、その呼び名を定めません。途中であることは、未達のゲートと記録の欠落の件数で表示します。ADR-0028 の5値(ゲートの状態)は変えません。

### 4. 適用の表明と、適合の主張を分ける

| 述べること | 条件 |
| --- | --- |
| 適用の表明(本標準を適用している) | 適用の開始の後である。未達のゲートの件数と、記録の欠落の件数を併記する |
| 適合の主張(本標準に適合している) | 適用の開始の後で、未達のゲートと記録の欠落が無い範囲に限る |

適用の表明と適合の主張は、品質保証の主張(ADR-0057)とは別の主張です。本標準は、表明と主張を誰が確かめるかを定めません。認証の制度は設けません。

### 5. 順序によらず動かせない要求事項の一覧を置かない

適用の開始の後は、導いた要求事項のすべてが同時に掛かります。「後でよいもの」が無いので、一覧は各条項の主語を言い換えるだけになります。一覧は、2つ目の規範になります。

### 6. 規程を持たない体制(1名を含む)を、適用組織に含める

第1章 1.2 の適用組織と、1.1 の目的2 を改めます。品質マネジメントシステムまたは決裁権限規程を有する組織は、本標準をその上に接続します。どちらも持たない体制は、決定の権限を D-0 体制図に記名で定めます。

`enablement.md` の「既存規程との併存」の節(サンドボックスを含む)は、既存の規程を持つ組織に適用範囲を限ります。サンドボックスの承認は、既存規程の免除の条件であり、適用の開始ではありません。適用の開始は、決定1 の時点に一本化します。試行前チェックリストでは、体制に該当しない項目へ、該当しない理由を書かせます。

1名の体制を適用組織に含めることは、その体制が品質保証の主張の成立条件を満たすことを意味しません。

### 7. 既存のリポジトリへの持ち込みは、確かめた事実と定めだけを書く

準拠テンプレートを既存のリポジトリへ持ち込むときに確かめた事実と、そこから置いた3つの定めを、フェーズ5 の「準拠テンプレートリポジトリ」へ書きます。根拠水準マークを付けます。定めは次の3つです。

- テンプレートの履歴を併合しない
- 名前が重なる 5 ファイルへ、テンプレートの内容を含める
- 既存の `package.json` へ、カバレッジの要約を出すスクリプトを用意する

常駐の規則を欠いたまま検査が通る経路は、準拠テンプレートの検査を直して塞ぎます。

**持ち込みの手順の全体は、先送りにします**。実際の GitHub 上での通しの検証と、python・go の既存のリポジトリでの試行が無いためです。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 導いたゲートがすべて働くまで、適用に数えない | 「働いた」を判定する記録が無い。未達を残す1名体制が、永久に適用の外へ落ちる。開始から完了までの出荷が、表示の義務の外へ出る。ADR-0028 決定3(隠す経路を設けない)と逆を向く |
| 構成の初期化を適用の開始とするとだけ書く | 境は決まるが、表明の条件が無い。初期化しただけで「適合」と読まれる余地が残る。決定4 と組にして採った |
| 「準備中」などの案件の状態を新設する | 読めた範囲の規格に、導入の途中を適合の型として持つものが無い。状態に留まる期間の上限の値に根拠が無い。ADR-0028 は、期間で消える表示を退けている。ADR-0057 は、段階の呼び名が、満たしたという主張として読まれることを理由に、3段階の保証を退けている |
| 決めず、定めていないと書いたままにする | 「定めていません」は、書き忘れと区別できない。実行層は既に境を持っており、本文だけが黙っている状態になる |
| 動かせない要求事項の所在の一覧を置く | 一覧の見出しの語が、各条項の主語(事業ステージ、案件、変更)を言い換える。名指しされなかったゲートは遅らせてよいと読まれ、決定2 と逆になる |
| ゲートを順に有効にする経過措置を認める | 免除した期間に置かれたものが、そのまま残る(ADR-0050 が、事業ステージによる段階について退けた理由と同じ) |
| 適用組織を文面どおりに保ち、規程を持たない個人は対象外と明記する | ADR-0028・ADR-0056・ADR-0057 が退けた形である。第8章 軸A の1〜2名の列と、準拠テンプレートの1名の構成が根拠を失う |
| 規程を持たない体制の適用の開始を、別に定める | 適用の開始の定義が2か所になる。決定1 の定義は、承認する組織が無くても使える |
| 準拠テンプレートは新規専用と明記する | 附属書I I.11 の導入前の検証は、採用者のコードと採用者のリポジトリで行う。採用の時点の証拠を弱める向きになる |
| 持ち込みの手順の全体を、いま書く | 確かめたのは手元の git と node だけである。確かめていない手順を示すと、読み手は従った結果を本標準に帰す |
| 持ち込みを手引きだけで扱い、検査を直さない | 既存の `CLAUDE.md` に区間の目印の2行を足すだけで、検査が通る経路が残る |

## 影響

- 第1章に 1.10「適用の開始と適合の主張」を新設した。1.1・1.2・1.4・1.5 を改めた。附属書H H.8 の自己宣言の行を、適用の表明と適合の主張の2行に分けた
- **1〜2名の体制は、適用の開始の時点で独立レビュー(G-6)が未達である**(準拠テンプレートでは、構成の初期化の直後。[ADR-0065](/process-compass/adr/0065-s0-omission-premises-and-roster-derived-confirmer/) 決定5 の帰結)。この間に述べられるのは、適用の表明までである。適用の表明に併記する未達の件数は、少なくとも 1 件になる
- 適用の表明と適合の主張は、保証の主張の成立条件を満たしたことを意味しない。1〜2名の体制が成立条件4 を満たす道筋は、附属書H H.1 による([ADR-0066](/process-compass/adr/0066-shipping-approver-separation-and-development-line/))
- 準拠テンプレートの `check-process-rules` が、`CLAUDE.md` の常駐の規則の節(見出しと本文)を確かめるようにした。区間の目印だけを足した既存の `CLAUDE.md` は、検査が落とす。節の中の個々の行の有無は確かめない
- 根拠水準マークを2件付けた。EV-0106(第1章 1.10。E1。見直し 2027-04)と、EV-0107(準拠テンプレートリポジトリ「既存のリポジトリへ持ち込む」。E2。見直し 2027-04)
- 適用の表明に併記する件数を、表明の様式として出力する仕組みは無い(IMPL-0120。降りていない)。件数は、構成と出荷の証跡の集約の出力から読める
- 今回の決定の外に置いたものは、次のとおりである。適用の終了の定義。本標準の版の付番と、改訂時の適合の主張の扱い。`pre-init` の境の定義が、フェーズ5 の `ci-gates.md` と実装で1語違うこと。降ろし先 `claude-md` の実装マークが、区間の外を検査していないこと。会議体が見つけた論点として、後継の Issue へ送る
