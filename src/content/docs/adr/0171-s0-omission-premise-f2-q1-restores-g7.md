## ステータス

採用(2026-11-17)。[ADR-0065](/process-compass/adr/0065-s0-omission-premises-and-roster-derived-confirmer/) 決定1 を一部置き換える(前提を4つにする)。[ADR-0159](/process-compass/adr/0159-g7-criteria-3-6-7-8-records-prose-sla-and-degradation-pairing/)「影響」の未決(S0 で G-7 を戻すか)を決める。ADR-0065・ADR-0159 の本文は書き換えない。重の審議の結論です(Issue [#355](https://github.com/Takenori-Kusaka/process-compass/issues/355) 束 B13、`research/355-deliberation/b13-decision.md`)。

## コンテキスト

- S0・標準品質・CL0 は G-7 を省略する。軸E の升は、附属書F F.2 の Q1 が「はい」なら F.7 の記録を要すると書くが、その記録を判定する席が無い
- 出荷の証跡の集約の基準7 は not-checked で、G-8 は技術品質を判定しない。F.7 が無いまま、人身への危害を生じうる制御を持つ成果物が実験参加者へ出る
- 導出は F.2 を入力に持たない。構成の G-7 を導出より厳しくする正規の経路も無い(実行で確かめた)。ゲートの状態は回答からの導出だけで決まり、手での書き換えは契約検査が拒否する
- 導出に入れず集約だけが止める案では、採用者が欠落を解く方法が、CL・品質の回答を偽って上げることと、事実と異なりうる S1 への移行だけになる。統制が偽りの記録を誘う

## 決定

1. S0 の省略の前提に、前提4「D-0 表10 の附属書F F.2 の Q1 が『いいえ』」を足す。Q1 が「はい」の案件は、S0・標準品質・CL0 でも G-7 を適用し、基準7 で F.7 の記録を判定する
2. 導出の入力に Q1 の写し(初期化の回答。仮の答え)を足す。正本は D-0 表10 とする。写しが「いいえ」で正本が「はい」なら記載の欠落にして出荷を止める。逆向きは注意にとどめる。q-criticality と D-0 節16 の関係と同じ型である
3. G-6 は戻さない([ADR-0065](/process-compass/adr/0065-s0-omission-premises-and-roster-derived-confirmer/) 決定4 を維持する)。G-6 を省略して G-7 を適用する構成の独立確認の欠落は、「G-6 が未達の体制」と同じに扱う(第4章 G-7 基準5 の表)
4. CL は F.2 から導かない(別の軸の判定で置き換えない。ADR-0039 と [ADR-0159](/process-compass/adr/0159-g7-criteria-3-6-7-8-records-prose-sla-and-degradation-pairing/) 決定4 の逆の向き)。F.2 の写しが変えるのはゲートの状態だけである
5. 課さないと決めたこと: (a) G-7 の判定者の作成者からの独立 (b) Q1 の答えの正しさの機械での検証 (c) CL の F.2 による引き上げ (d) 部分の G-7 (e) G-6 の復帰 (f) 案件より細かい出荷単位での絞り込み (g) 第7章 7.3 への新しい条項

## 結果

- Q1 が「はい」の S0 案件は、G-7 の記録(運用引き継ぎ文書・技術負債台帳・ゲート判定記録・欠陥の台帳)と判定を負う。速度の損失は取り消せる
- Q1 を「いいえ」と書く抜け道は残る。manual の統制として開示する(根拠水準マーク EV-0315)
- 前提1・2 を機械で確かめない決定(ADR-0065 決定1)は変えない。機械が確かめる前提は 3 と 4(値の一致)だけである
- 準拠テンプレートの実装(質問・規則・試験・集約の突合)は #448 で降ろす。それまで実装マーク IMPL-1015・IMPL-1016 を `state=undelivered` で表示し続ける

## 採らなかった案

| 案 | 採らない理由 |
| --- | --- |
| 導出に入れず、集約だけが「Q1 はい × G-7 省略」を欠落に数える | 欠落を正規の経路で解けない。解く手段が偽りの回答と手での書き換えだけになる |
| 段3 の確認者が出荷ごとに F.7 を確かめる | 段3 の務めは案件の初めに1回の区分の確認である。出荷ごとの判定は G-7 の席・期限・差し戻しを別名で作り直す |
| Q1「はい」を CL2 以上へ強いる | F.2 で CL を決めることになり、ADR-0159 決定4・ADR-0039 に反する。CL0 と Q1「はい」の組は正当に生じうる |
| 課さないと決めて開示する | 免除を支える外部の根拠は実験室の一時使用に限られ狭い。探索・実証でも開発側と別の者が見る事例が多い。入口(Q1)を誤る経路が残ることは、出口の席を外す理由にならない |
| G-6 も戻す | ADR-0065 決定4 を覆す。目的は F.7 の判定の席で、G-6 は要らない |
| 部分の G-7(基準7 だけ) | ゲートの状態の種類が増え、判定記録・期限・差し戻しの対応が別に要る |
| G-8 に F.7 の判定を負わせる | G-8 は技術品質を蒸し返さない席である |
| 第7章 7.3 の例外承認で「基準7 を承認する行を要する」と読む | 存在しない判定の例外を作る。S0 では外す判定基準が存在しない |
| 導出が D-0 表10 を直接読む | 導出が文書の自由記述に依存し、同じ回答から同じ構成を導く原則が崩れる |
| settings に「ゲートを導出より厳しくする」汎用の欄を足す | Q1 との結び付きが機械に見えない。理由の無い厳格化を生む |
| 軸B の G-7 の升の括弧に F.2 を今書く | `stage-table.mjs` の CONDITIONS に無い語で `check-stage-table` が落ちる。エンジンが回答を持つ template の束で行う |
| 出荷ごとの絞り込み(安全関連部の変更だけ G-7) | 機械が決定できない |
