### 失敗を出さずに統制が外れる経路が、5つあった

会議体と調査は、持ち込みの場面で、検査が失敗を出さないまま統制が外れる経路を5つ見つけました。手順の文書だけでは塞がりません。

| 経路 | 起きること |
| --- | --- |
| 区間の目印の無い既存の `CLAUDE.md`、独自の `AGENTS.md`、入れ子の指示ファイル | 矛盾する指示は、どちらかが任意に選ばれる。近いファイルが優先される基盤がある |
| 既存の `.claude/settings.json` に、テンプレートのフックの登録が無い | 禁止事項3(テストの失敗をテスト側で解消する)の機械の遮断が働かない。初期化は既存の設定へ登録を足していなかった(現場 F-1・F-2) |
| `CODEOWNERS` の置き場の重なりと、雛形の所有者 `@OWNER` | GitHub は最初の1か所だけを使い、不正な行を飛ばす(SRC-0666)。コードオーナーが誰もいない状態が、失敗にならない |
| `gate-g5.yml` の push の契機が `main` に固定 | 既定ブランチが `main` でないリポジトリで、既定ブランチへの push に検査が走らない |
| 実環境の確認(`env-check`)の `checks-only` の穴 | G-6 が無効の構成では、必須チェック gate-g5 の適用を確かめず、ルールセットの項目を「確認済み」と記録していた(品質保証 V-1) |

### 境が、併合した別の履歴へ移りえた

ADR-0083 の決定5 は、境を「構成が設定済みになった最初のコミット」とし、分かれるすべての場合で早い側に倒れると判断しました。この判断は1本の履歴の上での議論でした。準拠テンプレートの探し方は全履歴を歩いていました。開始の後に、古い日付で `configured: true` の構成を持つ別の履歴を併合すると、境がその履歴のコミットへ移ります(品質保証 V-4)。会議体の時点では読解による推論でした。実装の前に、準拠テンプレートの試験(`test-adoption.mjs`)で再現して確かめました。

### 開始より前の履歴を、出所で分けていた

出荷の証跡の集約は、開始より前の履歴のうち、テンプレート由来の初期コミット(親を持たず、テンプレートのファイルだけを持つもの)を一覧から除き、ほかの製品の変更を一覧に出していました。識別の基準は検証できず、誤ると製品の変更が開示から消えます。

### 構成が、自身の形式の版と生成元を持たなかった

構成の `schemaVersion` は要約値の連鎖の有無を表すだけで、既知より大きい値を黙って通していました(V-5)。構成は、生成に使ったテンプレートのコミットを記録していませんでした(V-6)。旧い版で生成した構成が、テンプレートの更新で契約検査に落ちるとき、移す経路がありませんでした。テンプレートの README は、取り込みの判断を「例外承認等」に委ね、記録の無い判定を「未達」と呼んでいました(ADR-0083 決定3 と食い違う)。

## 決定

### 1. 既存のリポジトリで適用を始める要求事項を、第1章 1.10.1 に置く

要求事項は、適用の開始の記録の内容として掛けます。開始より前の準備の活動には掛けません。

- 適用の開始の記録に、既存の統制の資産の一覧と、資産ごとの扱い(取り込む・置き換える・残して並存する・対象外とする)を含める
- 扱いは、技術判断の席の責任者(人)が記名で確定する。AI は起案までとする
- 機械が検出した資産は、一覧に載せる(一覧の網羅を人の申告だけで示さない)
- 統制に効くファイルが、テンプレートの規則を欠いたまま適用を始めない

判定の対象は、記録の有無と記名、機械が検出した資産との照合、統制に効くファイルの規則の有無です。擁護者の「棚卸しは判定できない」に対する答えです。一覧が既存の資産を網羅したことそのものは判定しません。手順はテンプレートの手引き(フェーズ5 の準拠テンプレートの頁と、テンプレートの README)に置きます。根拠水準は EV-0166 で開示します。

### 2. 初期化の前に、書き込まない事前点検を置く

準拠テンプレートに `scripts/gate/preflight.mjs` を置きます。初期化も同じ点検をし、止める項目が1つでもあれば構成を書きません。

- 止める(指示ファイル): 目印の無い `CLAUDE.md`、常駐の規則を欠く `CLAUDE.md`、扱いの記録の無い独自の `AGENTS.md` と入れ子の指示ファイル
- 止める(強制層): 2か所以上の `CODEOWNERS`、`@OWNER` の残り、フックの登録の欠け、テンプレートのワークフロー `gate-g5.yml` の欠け、既定ブランチが `main` でないこと
- 止める(記録): 資産の一覧の欠け(検出した資産が載っていない、扱いが4つの値に無い、記名が無いか AI の名義)
- 告げる(一覧へ載せる): 既存の製品のコードと履歴、既存のワークフロー、既存の `CODEOWNERS`、言語の目印、カバレッジの測定の穴、`.gitignore` の行、共通の祖先の無い履歴の併合(主系列の根でない根のコミットごと)
- 共通の祖先の無い履歴の併合は止めない(突合 X-4 による R-2 の改め)。古い併合(モノレポへの統合、部分木の併合)は履歴を書き換えないと戻せず、止めると持ち込みそのものができなくなる。開始より前の履歴は出所を問わず主張の外であり、止める理由(定め1)はテンプレートの履歴の併合にしか当たらない。テンプレートの履歴の併合を識別して、止めたり免除したりはしない(決定3 の却下と同じ理由)。点検は定め1 を告げ、併合した側の根のコミットを一覧の行にする
- 入れ子の指示ファイルの検出から除くのは、準拠テンプレート自身が持つ指示ファイルに限る(突合 X-14)
- フックの登録の欠けは欠陥として直す。初期化と `generate-profile.mjs --merge-hooks` が、既存の設定へ登録を併合する(既存の登録は残す)。契約検査は、設定済みの構成でもフックの登録の欠けを失敗にする
- `@OWNER` の残りは、契約検査でも失敗にする。開始の後に戻した場合も止めるためである
- カバレッジの測定の穴は止めない。node では G-5 の test ジョブが失敗し、go では G-5 基準3 を「実施しない」と記録するため、黙っては外れない。これは ADR-0028 の「未達」ではない(突合 X-12)。品質保証の委員の「受容の記録が無ければ止める」は、G-5 の失敗と「実施しない」の記録と二重になるため採らない
- 点検は事実を読むだけで、設問の回答を検出の結果で埋めない
- 初期化は、点検の結果を適用の開始の記録(`changeLog[0]` の `preflight`)へ書く。`--dry-run` も、止める項目があれば構成を出さない。設定済みの構成の複製など初期化を経ない経路で記録が欠ければ、契約検査は記録の欠落として注記し(失敗にしない)、出荷の証跡の集約は適用の開始のコミットを範囲に含む出荷で記録の欠落にする(突合 X-2。ADR-0083 決定3 と同じ扱い)

止める側と告げる側の分け方の根拠水準は、EV-0167 で開示します。

### 3. 適用の開始の境を既定ブランチの主系列の上に置き、開始より前に出所を問わず主張しない

- 第1章 1.10.1 へ置くのは、道具に依らない語の2文に限る(突合 X-3)。境を既定ブランチの主系列の上に置く文と、開始より前の履歴に出所を問わず主張せず、開始の後に併合した履歴も出所を問わず対象とする文である。git の第1親という実装の規則は、標準の要求事項にしない
- 準拠テンプレートでは、境を既定ブランチの第1親の連鎖(`git log --first-parent`)の上で `configured: true` になった最初のコミットとする。併合した別の履歴の中のコミットを境にしない(ADR-0083 決定5 を補う)。この実装の規則は、フェーズ5 の準拠テンプレートの頁と本 ADR に置く
- 境がマージのときは、第2親の側を含む境の全祖先を開始より前とする
- 開始より前の履歴は、出所(採用者の過去の変更、併合した他のリポジトリの履歴、テンプレートの開発履歴)を問わず要求事項の対象外とし、件数だけを開示する。テンプレート由来かどうかの識別による免除をやめる
- 開始の後に共通の祖先の無い履歴を併合した場合、その履歴のコミットを要求事項の対象とし、免除しない

V-4 は試験で再現してから直しました。

### 4. 実環境の確認を4値にし、確かめる項目を足す

- 結果は、確認済み・不一致・未確認(理由)・対象外の4値とする。対象外を確認済みに数えない。読めた空の一覧(不一致)と読めなかった場合(未確認)を区別する。規格の委員の「2値に理由を添える」は採らない。対象外と確認済みの重なり(V-1)が、まさに2値の欠陥だったためである
- 必須チェック gate-g5 の適用は、G-6 が無効の構成でも確かめる(`checks-only` の穴。附属書H 項目4 と第4章 G-5 に対するテンプレートの欠陥)
- 確かめる項目に、旧来のブランチ保護との重なり、効いている `CODEOWNERS` の所在と `codeowners/errors`、ルールセットのバイパスの主体を足す。バイパスの主体の鍵が応答に無ければ、権限不足で読めないとする
- 対象外は、書く側と読む側の両方で2つの場合に限る(コードオーナーの承認を要しない構成で `CODEOWNERS` が無い、効いているルールセットが無いときのバイパスの主体)。記録は手で書けるため、読む側がほかの対象外を未確認に倒し、対象外を重ねて全体を確認済みに至る経路を塞ぐ。記録の時点の G-6 の状態が現在と違えば確認し直す(突合 X-1。附属書H 項目4 と附属書I I.11 要件⑦ の「確認済み」の定義を、読む側の実装に届かせる)
- 旧来のブランチ保護だけで必須チェック gate-g5 と承認の規則を効かせている構成は、旧来の保護が管理者にも適用されている場合に限り、ルールセットの項目を確認済みと読む。管理者に適用されない旧来の保護は、バイパスの主体と同じ理由で数えない(突合 X-17)
- 必須チェックの発行元(`integration_id`)の固定は、実際の GitHub 上で確かめてから規定にする。確かめていないことを記録に書く
- 人の記名の確認は、持ち込みの時点と強制層の変化点に行う。G-8 ごとに機械が読み取り、乖離を検出の層として出す(確認済みには数えない)。G-8 ごとの読み取りは、まだ準拠テンプレートに降りていない(IMPL-0324)。定期の再確認の周期は課さない(EV-0168 で開示)
- ルールセットの Evaluate の状態を前提にしない
- EV-0107 を、node の既存のリポジトリ(EV-0169)と、python・go の既存のリポジトリ(EV-0170)に分けて開示する。差し替え条件に「`env-check` が実環境で確認済みに至った記録を少なくとも1件」を加える。EV-0107 の本文は規約どおり書き換えず、2026-10-12 の試行の開示として残す。EV-0107 に加える条件が EV-0169・EV-0170 にあることを、両方の側から辿れるように書く(突合 X-10)。EV-0169 の水準は E1(間接)とする。本節の手順と事前点検を既存のリポジトリへ通して当てた試行が無いためである

### 5. 構成に形式の版を持たせ、移行を種別 `migrate` で行う

- 移行(種別 `migrate`)は、取り込んだテンプレートの記録(強制層の要約値)を書き換えない(突合 X-6。決定6)

- 構成に形式の版(`formatVersion`)を持たせる。`schemaVersion` の意味は変えない。契約検査は、知らない版(既知より大きい `formatVersion`・`schemaVersion`)の構成を拒否する
- 移行は `/process-change` の種別 `migrate` とする。版ごとに現行の版への直接の変換を持ち、PR で出す。移行はゲートの状態・席・閾値の値を変えない。値を変える必要がある構成は、記名を伴う構成の変更へ渡す
- 読み込みで既定値を補うのは、結果が同じか厳しくなる場合に限る。欄の無い構成は版 0 として読み、移行を注記する(失敗にしない)
- 猶予の期間を置かない。1.10.1 と ADR-0083 決定1 に矛盾し、成立しないと分かっている状態を通すためである
- 版の欄の無い宣言と D-0 を、遡って書き換えない。次に改めるときに版を書く
- テンプレートは、自身の検査が実装する標準の版を宣言する(知識ベースの `source.edition`)。要求事項の検査を変えるテンプレートの更新を取り込むことは、版の切り替え(1.10.3)と同時に行う。規格の委員の指摘(1.10.3 で旧い版の主張を続けられる一方、テンプレートは最新の検査で落とす)を採った。第1版の発行の前は、どの構成も作業中の版に従う。取り込み(種別 `intake`)は知識ベースの生成元の前後を変化点の記録に書き、従う作業中の版の切り替えを記録に残す(突合 X-18)

根拠水準は EV-0171 で開示します。

### 6. 取り込んだテンプレートを記録し、取り込みを強制層の変更として扱う

- 構成に、取り込んだテンプレートのコミット(`template.commit`)と、強制層のファイルの要約値と、知識ベースの生成元を道具だけが書く。不一致は表示し、合否に使わない。記録は来歴の主張であって証明ではないと明記する。擁護者の「部分的な複製は証明にならない」を、この開示で受ける。値を持たない場合より、乖離を見える形にする方を、信頼性の高い側と判断した
- 要約値の範囲は、フック・スキル(`.claude/skills/**`)・ワークフロー・ルールセット・ゲートと初期化のスクリプト・アダプタとする。案件ごとに書き換える `.claude/settings.json`・`guard.json` は含めない(突合 X-16)
- 要約値を記録し直すのは、初期化と `/process-change` の種別 `intake`(テンプレートの取り込み)に限る。`intake` は記名の自然人の決定(AI の名義は不可)と理由を要し、取り直す直前の乖離(変わった・無くなった・増えたパス)を変化点の記録に書く。契約検査は PR で基底の記録と比べ、取り直したパスを注記に列挙する。強制層を弱める変更と記録の取り直しを、記名なしで同じ PR に入れると、乖離の注記が「一致」になるためである(突合 X-6)
- 取り込みは、ファイルを複製する PR で行い、強制層の変更として扱う(`state:needs-platform`。陰性の確認)。取り込まないことは許す。取り込まないことは例外承認ではない
- 既存の採用者を落とす変更を出す保守者の義務(落ちうる検査と直し方の列挙、書き込まずに試す手段の同梱、猶予なし)を `community/standard-editions.md` に置く。採用者への要求事項ではなく、保守の手続である
- テンプレートの git のタグは要求しない
- 配布物の真正性と受け取る側の検査は [#332](https://github.com/Takenori-Kusaka/process-compass/issues/332) へ渡す。本件は記録と告知までとする
- テンプレートの README の2つの誤用を直す。記録の無い判定は「未達」でなく「記録の欠落」である(ADR-0083 決定3)。更新の取り込みの判断は「例外承認等」でなく、強制層の変更である

### 7. 採らないと決めたことを、本文に明記する

次の8つを、採らない理由とともに本文に書きます。標準の水準の3つ(手順の全体を標準に置くこと、段階の展開、既存の違反の基準線)を第1章 1.10.1 に、8つすべてをフェーズ5 の準拠テンプレートの頁に書きます(突合 X-11)。

- 持ち込みの手順の全体を標準に置くこと
- 段階の展開(資産ごとの順次の適用)
- 既存の違反の基準線(基準を満たさないまま進める4つ目の経路)
- テンプレート由来の履歴の識別による免除(トレーラ・作者・一覧の照合)
- 猶予の期間、緩める向きの黙った読み替え
- 定期の再確認の周期を課すこと
- Evaluate モードを前提にすること
- テンプレートの git のタグを要求すること

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 持ち込みの手順の全体を標準に置く | 実際の GitHub 上の通しの検証と、python・go の試行が無い。確かめていない手順に従ったことを適合の根拠にさせない |
| 手順だけをテンプレートに置き、標準には何も置かない | 監査が照らす要求事項が無く、採用者ごとに検証が漏れる。テンプレートの README に、根拠条項の無い規範が残る |
| 第8章のテーラリングの宣言に要求事項5 を足す | 宣言は体制と構成の申告で、開始の記録とは時点が違う。開始の記録の一部とする方が ADR-0083 決定5 と一致する |
| 資産ごとに順に適用する段階の展開 | 1.10.1(導いた要求事項のすべてを同時に適用する)と矛盾し、部分的な適用を適合と読ませる |
| 既存の違反の基準線を記録し、新しい違反だけを止める | 閾値の緩和と機械で区別できない。基準を満たさないまま進める4つ目の経路になる(擁護・品質保証・規格の3委員) |
| カバレッジの穴を、受容の記録が無ければ止める | 未達の表示と二重になり、止める理由にならない |
| 既定ブランチの名を初期化が書き換え、push の契機を変える | 強制層のワークフローを案件ごとに変える経路を作る。後継の Issue で検討する |
| 共通の祖先の無い履歴の併合を止める(当初の R-2) | 古い併合を持つリポジトリが、履歴を書き換えないと持ち込めない。止める理由はテンプレートの履歴の併合にしか当たらない(突合 X-4) |
| テンプレートの履歴の併合を識別して止める・免除する | 識別は出所の申告に依り、証明にならない(決定3 の却下と同じ理由) |
| 種別 `migrate` で要約値も取り直す | 記名なしで、強制層の変更と記録の取り直しを同じ PR に入れられる(突合 X-6) |
| 1.10.1 に git の第1親の語で境を書く | 道具の語を規格の要求事項にする。準拠テンプレートの頁に置けば足りる(突合 X-3) |
| 既知のテンプレートのコミットの一覧と照合して、テンプレート由来を識別する | 一覧は版ごとに要り、照合しても同じハッシュを持つことしか言えない。開始より前は主張しないので、識別して得るものが無い |
| トレーラ(`Imported-From:` など)でテンプレート由来を識別する | 誰でも書ける。出所を証明しない |
| env-check を2値に理由を添える形にする | 対象外と確認済みの重なり(V-1)が2値から生じていた |
| env-check に定期の再確認の周期を課す | 周期の値に根拠が無い。変化点と G-8 の機械の読み取りで受け、外れの観測で見直す(EV-0168) |
| ルールセットの Evaluate で試してから有効にする手順 | Evaluate は Enterprise Cloud の文書にしか状態として現れない |
| 移行に猶予の期間を置く | 成立しないと分かっている状態を、期間を区切って通すことになる |
| 旧い構成を読み込みで黙って読み替える | 緩める向きの補いを、人の確定なしに行うことになる |
| `template.commit` を記録しない(証明にならないため) | 乖離を見えない形に残すより、来歴の主張として開示する方が信頼性が高い |
| テンプレートの git のタグを要求する | コミットで識別できる。タグを採用者の側の要求にする理由が無い |

## 影響

- 準拠テンプレートの強制層を変えた。契約検査(`verify-gate-contract.mjs`)、初期化(`generate-profile.mjs`)、事前点検(`preflight.mjs`。新規)である。実環境の確認(`adoption-trial.mjs` の `env-check`、`org-assurance.mjs`)、出荷の証跡の集約(`aggregate-evidence.mjs`)、集約のワークフロー(`gate-g5.yml` に試験2本)も変えた。テンプレートの側では、AI維持管理者の承認(`state:needs-platform`)を要する変更として出した
- 既存の採用者の構成は、`formatVersion` の欄が無くても契約検査で落ちない(注記に移行を出す)。`@OWNER` が残る構成と、フックの登録を欠く構成は、契約検査で落ちる。これは既存の採用者を落とす変更である。テンプレートの README に告知の節(「process-compass #315 の更新を取り込むとき」)を置いた。落ちうる検査・直し方・書き込まずに試すコマンド・`evidence.json` の欄の変化を列挙した(突合 X-5。`community/standard-editions.md` の保守者の義務を初回から満たす)
- #315 より前の初期化の構成は、適用の開始の記録に事前点検の結果を持たない。契約検査は注記する。出荷の証跡の集約は、適用の開始のコミットを範囲が含む出荷だけで、記録の欠落として扱う
- env-check の4値より前の記録は、「未確認(旧い形の記録)」と読まれる。採用者は env-check を実行し直す
