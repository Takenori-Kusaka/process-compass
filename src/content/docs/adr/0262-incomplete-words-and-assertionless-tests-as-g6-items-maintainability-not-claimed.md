## ステータス

採用(2026-11-27)。審議は重です。記録は `research/454-deliberation/` にあります。ADR-0244 と IMPL-1029 は覆しません。番号(IMPL-1042〜1044・EV-0355・EV-0356)は push の直前に付け直します。

## コンテキスト

- 5.8.5 の後段は、検証を弱める変更を差分から機械で検出し、G-6 の必須の確認事項として一覧に示し、G-5 の合否に使わない型を持つ(IMPL-0204)。対象は既存の検証を減らす操作だけで、新しく足したテストの中身と製品のコードの未完了の語は見ていなかった
- 技術負債台帳へ妥協・TODO・仮実装を記録する義務は既にある(IMPL-0788)。義務を破った変更を見つける検出が欠けていた
- 準拠テンプレートの既存の `ASSERTION` は、テストの題の文字列(`it('should x')` の `should`)を検証と数えていた。実行で確かめた(2026-11-27): 検証の行を題の行へ置き換えた差分が、削除行のアサーションではなく期待値の改めの対に数えられた
- 保守性を主張しないことは、どこにも書かれていなかった。「書かれていない」と「主張しないと決めた」を読み手が区別できなかった
- 外部: ISO/IEC 25010・5055・29119 は定義と弱点の数え上げまでで、合格水準を採用者・契約に残す。本文は読んでいない(二次・要旨)。閾値・決め打ちの検出の研究は、ベンチマークの段階(E2)である

## 決定

1. **5.8.5 後段の型へ2種を足す**。(i) 検証の語が1つも無い追加のテストのファイル、(ii) 製品のコードの追加行の未完了の語。一覧に出し、G-6 の必須の確認事項とし、G-5 の合否に使わない。**リスク区分に依らず出す**。検証を弱める変更とは節を分ける。「印」は skip・xfail の意味で使われているので、新しい検出は「未完了の語」と呼ぶ
2. **検出の対象と粒度**: (i) はファイル単位の近似で、同じファイルに検証の語が1つでもあれば他の空のテストは出ない。テストのパスの定義(`testPatterns`)の外は対象外。(ii) は製品のコードの拡張子の追加行に限り、行注釈の `TODO`・`FIXME`・`XXX` と未実装を示す例外・マクロだけを読む。同じ PR で削除した行と同じ本文の追加行は出さない。限界の文は節ごとに0件でも出す
3. **検証の語の数え方を直す**(R-2)。題の文字列と宣言の名前を数えない。アダプタ(go・node・python 系)と Rust・JUnit の主な書式(`verify(`・`raises`・`assertRaises`・`should_panic`・`shouldBe`・Go の `t.Error*`・Rust の `assert!`・JUnit の `assert*`)を試験で確かめる。既存の IMPL-0204 の削除行のアサーションの検出にも効く
4. **G-6 の義務の強さは、既存の 5.8.5 後段と同じ「確かめる」まで**にそろえる。確かめられない行の差し戻しの文を条文に置かない(差し戻しは既存の G-6 基準1・2 と IMPL-0788 で足りる)。手引きに「確かめて偽陽性と分かった行は、確かめた結果として扱う」と書く。確認が行われたことは機械で確かめない(manual。自己申告)
5. **G-6 が当たらない変更**(事業ステージによる範囲の限定、G-6 の省略・未達の構成、委任で判定を事後へ移した変更)では、一覧は出るが事前に読む判定者がいない。検出できるとは主張しない
6. **重複の比率・複雑度・決め打ち・弱いアサーションは、G-5 の合否に使わず、一覧にも出さない**(B1)。閾値の実証が E0〜E1 であること、正当な重複(試験の表・生成コード)の偽陽性、規格が合格水準を定めないこと、パターンで閉じないことによる。重複の比率を合否に使わない理由の補記であり、ADR-0137・0159 の決定は変えない。残るリスクとして H.11 に書く
7. **空の本体・固定値を返す本体の検出を課さない**。構文の分析が言語ごとに要り、降りない規定になる。採用者の静的解析(G-5 基準2)に委ねる
8. **H.2 に保守性の行を足す**(ADR-0051 の線の適用)。理由は、本標準が保守性の証跡と合格水準を持たないこと。「代わりに示すもの」に技術負債台帳を挙げない(保守性の証跡と読まれるため)。H.3 に主張を足さない。品質特性一般へ広げる文は書かない(広げるなら所有者の確認が要る)。ISO/IEC 25010 の副特性を並べない(H.10)
9. **G-6 の判定基準は増やさない**。附属書C の手引きに、複雑さ・重複が挙動要約の書けない原因のときは質問か分割・整理を求める旨を足す(既存の「理解できないまま承認しない」の具体化)
10. **変異試験の適用は変えない**(ADR-0244・IMPL-1029・IMPL-1036)。R2 の PR と R3 では、弱いアサーションを機械が見ないことを H.11 に書く
11. **統制の閉じ方**: 一覧の出力・限界の文・節の分離・題の語を数えないことは機械(template の試験)。一覧の各行を確かめることは manual(自己申告。EV-0356)。検出の方式の範囲は E0(EV-0355)

## 課さないと決めたこと・採らなかった案

| 案 | 区分 | 理由 |
| --- | --- | --- |
| 何もしない | 採らない | 台帳へ記録する既存の義務が、検出されないまま残る |
| 2種を G-5 の合否にする | 採らない | 正当な語(台帳に記録した将来の課題、抽象の基底の例外、期待される例外の検証)まで止まる。語を書き換えて回避される。G-5 の原則の条件1(実効的な偽陽性が無い)を満たさない |
| 保留テスト(実装の担い手からテストを隠す構造)を R1 に求める | **課さないと決めた**。覆す条件: 保留テストの実務の実証が出たとき | 採用者への新しい義務で、外部の根拠が研究のベンチマーク(E2)にとどまり、プロセスの規程の実証が無い。従: 採用者の費用(テストの二重の管理) |
| 偽陽性を除く採用者の設定の鍵 | **課さないと決めた**。見直しの条件: 誤検出の実測が G-6 の読み飛ばしを示したとき | 鍵ごとに 0 件の意味が採用者間で揃わなくなり、作成側が鍵で一覧を消す経路もできる |
| G-6 の判定者に、確かめられない行の差し戻しを条文で課す | **課さないと決めた** | 同じ型の中で強さが2通りあると G-6 の読み方が割れる。強い側に寄せれば既存の一覧にも義務が増え、本件の範囲を超える |
| 未完了の語の検出の対象を全ファイルにする | 採らない | 文書・生成物の偽陽性で一覧が読まれなくなる |
| テストを変異させて確かめる手順を R2・R3 に足す | **課さないと決めた**(既存の決定の維持) | ADR-0244 が退けた理由を覆す新しい根拠が無い。R2 の週次の実行(IMPL-1036)は在る |
| 未完了の語の件数の上限 | **課さないと決めた** | 上限を超えた行が読まれない。表示を丸めることも採らない |
| 個々のテストの単位の検出(構文の分析) | 本改訂では課さないと決めた | 言語ごとの解析器が要り、降りない規定になる。ファイル単位の近似の限界は開示する |
| 重複の比率・複雑度の閾値で合否にする・一覧を G-6 へ出す | 採らない | 閾値の実証が無い。判定者が結果を書く基準が無く、どの主張も支えない検査になる(H.3 末尾) |
| H.3 に主張「保守性」を足す | 採らない | 証跡が無く、足すには新しい検査か様式が要る |
| G-6 基準7「保守性が許容できる」 | 採らない | 許容の基準が定義できず、記録から判定できない。H.2 の「主張しない」と矛盾する |
| 未完了の語と台帳の行を識別子の注釈で結ぶ | **課さないと決めた** | 定義が増え、作成側の AI が注釈を埋めれば一覧から消える |
| checked coverage を R2 に求める | 採らない | 道具と言語が限られ、相関の定量が未確認。降りない規定になる |

## 影響

- 守るのは、受入基準を満たしたとされる機能の未完了を受け取る採用者の利用者と、カバレッジを根拠に残存リスクを受容する出荷判定者である。失うのは、一覧の偽陽性を確かめる G-6 の判定者の時間である
- 検証の語の数え方の直しは、既存の IMPL-0204 の一覧(削除行のアサーション・期待値の改めの対)の数を変えうる。題の文字列の `should` に隠れていた削除行のアサーションが、削除行として出る
- 実際の案件での誤検出の率は測っていない(EV-0355)。確認が行われたことは機械で確かめない(EV-0356)
- 見直しの契機: EV-0355・EV-0356 の見直し(2027-05)、誤検出が G-6 の読み飛ばしを示したとき、保留テストの実務の実証が出たとき
