## コンテキスト

[#419](https://github.com/Takenori-Kusaka/process-compass/issues/419) の論点の 1 つです。#418 の会議体の規格の委員が、第1章 1.7 に「初期値」の定義が無いことを指摘しました。調査(`research/419-deliberation/survey-419-*.md`)と 5 委員の会議体(`research/419-deliberation/`)を経ました。

### 見つかったこと

- 「初期値」の用法は 8 通りに分かれていた。7.6 では記録が無ければ G-1 の基準4 を満たさない(ADR-0095)。7.7.4 には無記録の扱いが無い。G-5・G-7 の判定基準、レビューの規模の上限、5.4.6 の自動の引き下げは、記録が無くても黙って効く。7.10.3 では例の意味だった
- それでも、多くの箇所は本文が既に強さを書いていた。3.12.10 は「本標準は停止条件の値を規定しません。組織が定め、記録することを要求します」、第4章「閾値の設定と較正」は「値の決め方(初期値のまま / 実測からの置き換え)」の記録を求め、7.7.2 は「G-1 の時点で確定し記録しなければなりません」と書く。欠けていたのは強さではなく、強さを区別する語だった
- ISO/IEC 専門業務用指針 第2部に「初期値」「既定値」という規定の種類は無く、参考の値は要求事項と区別しなければならない(9.4.1)。利用者に値を定めさせるなら、どう定めどこへ明示するかを規定しなければならない(5.9)
- 外部の作法は、組織が必ず定めて記録する値(NIST SP 800-53 の組織が定めるパラメタ、OWASP ASVS)、記録が無いときに効く保守的な既定(ISO 13849-1)、例示の 3 型に分かれる。FedRAMP は 2026-06 に「最低線の値は実質的に上限としても働く」として、割り当てていた値の大多数を外した
- 準拠テンプレートの G-1 の検査は、企画書の「エスカレーション閾値」の行の空欄を検出していなかった。7.7.2 の閾値を書く行も企画書に無かった

## 決定

### 1. 値の扱いを 3 型で書く(第1章 1.7.7)

| 型 | 所在で使う語 | 記録が無いとき |
| --- | --- | --- |
| 組織が定める値 | 「組織が定める値」。示す値は「参考の値」 | 当該の基準を満たさない。参考の値は効かない |
| 既定値 | 「既定値」 | 既定値が効く。条項が求める場合は、既定値のまま用いることも記録する |
| 例 | 「例」 | 何も効かない |

- 値の扱いは 1.7.1 の規定の種類にしない。強さは文末の形、値の扱いは所在の語で示す
- 権限の境界と受容の基準を数で配る値は、組織が定める値とする。組織の規模に依る値には参考の値と例のどちらも置かない(ADR-0087 の作法を一般則にする)。検知・発火・停止を起動する値のうち、置き換えずに用いても統制を弱めない値は、既定値としてよい
- 置き換えを認めない値(5.5.3・5.5.5 の上限など)は型の外とし、要求事項の中に書く
- 定める者・時点・記録先の書かれていない組織が定める値は、第8章のテーラリングの宣言で定めて記録する。置き換えの手続の書かれていない既定値は、テーラリングの宣言で置き換えて記録する(共通の受け皿)
- 表の列に型の違う値を並べるときは、列の見出しを「値」などの中立の語にし、行ごとの型を表の前後の文で示す
- 本則は本標準の記述にだけ掛かる。採用組織の文書に型の宣言を課さない(1.7.6 と同じ)
- 既定値と参考の値の根拠が実証に依らない場合は、根拠水準のマークを付ける。型の判断そのものは EV-0198(E1)で開示する

### 2. 振り分けは本文が既に書いている強さに従う

本件で強さを変えるのは、本文が強さを書いていない箇所だけとします。本件は語の区別の欠陥を直すものであり、個々の値の強さを改める議論を経ていないためです。

| 箇所 | 型 |
| --- | --- |
| 7.6 の段階と着手決裁前の累計消費 | 組織が定める値(参考の値)。ADR-0095 決定5 |
| 7.7.2 の閾値と 7.7.4 の検知の値 | 組織が定める値(参考の値)。7.7.2 |
| 3.12.10 の停止条件、3.11.4 の要求事項1、G-5 基準3 | 組織が定める値(参考の値) |
| 第4章「閾値の設定と較正」と 5.4.6 の検知の値 | 既定値。既定値のまま用いることも記録する |
| G-5・G-7 の判定基準の件数・比率、レビューの規模の上限・SLA・同時保有数、5.4.5 の条件1・4、2.10.1 の 60%・20%、附属書F の R1〜R3 の列 | 既定値。G-5 基準7 と G-7 の「欠落 0 件」などの完備の要求は値ではない |
| 3.8.2 の決裁者の割当 | 既定値。変えた交点を、その交点で表の割当により決裁する者が記名して D-0 表2-2 に記録する(決裁を失う側の記名なしに決裁を移さない。決裁権限規程を持つ組織は規程による) |
| 7.10.3 の劣化の事象、テンプレ5 のリスクの区分、附属書F F.4 の安全関連部の列 | 例(7.10.3 の閾値の数値は組織が定める値) |

### 3. 7.6 と 7.7.4 は組織が定める値とする

- 7.6 は ADR-0095 決定5 のとおり組織が定める値とする。記録の無いまま閾値を効かせると、事業決裁者の確定していない権限の境界で段階が分かれ、ADR-0095 決定5・6 を覆すためである
- 7.6 の参考の値は残す。比率は自らの予算・範囲に対する比であり、金額の境界額と違って組織の規模に依らない。参考の値をそのまま用いても、確定した者は G-1 の判定者の記名で分かる
- 7.7.4 も組織が定める値とする。記録の無い案件は G-1 の基準4 を満たさず、G-1 の前は配賦した予算が無く 7.7.4 が働かない。既定値が受け皿になる場面が残らない
- 受け皿の穴は検査の欠落として塞ぐ。準拠テンプレートの企画書に 7.7.4 の閾値の行を足し、G-1 の検査が 7.6 と 7.7.4 の閾値の行の空欄を検出する(IMPL-0371)

### 4. 「初期値」を規定の文書で使えなくする

規定の文書(本文 8 章と規定の附属書。注記とコメントを含む)で「初期値」を検出し、`npm run check` を失敗させます(`src/data/provision-forms.yaml` の `retiredValueWords`)。手引きの頁は検査の外です。手引きのうち本標準の値を引く箇所は、本 ADR と同じ語へ改めました。手引き独自の値の説明の語は残します。

## 検討した選択肢

| 選択肢 | 出した者 | 採否と理由 |
| --- | --- | --- |
| 「初期値」を 1.7.1 の規定の種類に加える | 検討 | 採らない(5 委員一致)。指針 第2部に無い種類であり、表に無い形を規定に使わないという 1.7.1 の決まりと当たる |
| 「初期値」を定義して残す | 検討 | 採らない。8 通りの用法のうち定義に合わない箇所が残り、読み手が一つずつ確かめる負担が残る |
| 「初期値」を既定値の型の名として残す | 品質監査 | 採らない。7.6 の読み(記録が無ければ効かない)が定着した語であり、既定値の意味へ移すと逆の読みが残る |
| 4 型(規範値を型に含める) | 起案 | 採らない。置き換えを認めない値は、要求事項として書けば足りる |
| 7.6 を既定値にする | 起案 | 採らない。ADR-0095 決定5・6 を覆す(決定3) |
| 7.6 の参考の値を消す | 規格が会議体に委ねた側 | 採らない(決定3)。参考の値を残す理由と、ADR-0087 との違いを記録した |
| 7.7.4 を既定値にする | 規格・現場 | 採らない(決定3)。受け皿の必要は G-1 の検査の欠落であり、検査で塞ぐ |
| すべての値を組織が定める値にする | 検討 | 採らない。小さな体制が初日に動けず、検知の歯止めが記録の欠けで外れる |
| すべての閾値を規範値にする | 検討 | 採らない。ADR-0095 の却下を維持する |
| 既定値で運用していることの記録を一律に課す | 品質監査 | 採らない。置き換えの記録が無いことが、既定値で運用している証拠になる。記録を求める条項だけが求める |
| 採用組織に型の宣言を課す | 検討 | 採らない(弁護)。1.7.6 と同じく、本標準が自らに課す作業を採用者へ広げない |
| 型の体系を置かず、記録が無いときの扱いを各条項に書き足すだけにする | 弁護 | 型を置いて採る。書き足しを漏れなく行わせ、検査で止める手段として型を使う |
| 本件で個々の値の強さを改める | 検討 | 採らない。値ごとの議論を経ていない。後継の論点として残す |
