## ステータス

採用(2026-11-27)。審議は重です。記録は `research/455-deliberation/` にあります。ADR-0044 の決定5 を、範囲を明示して一部置き換えます。

## コンテキスト

- ADR-0044 決定5 は、存在しないパッケージの参照は依存関係の解決で失敗し、G-5 の既存の検査で捕まると決め、新しい条文を置かないとした。決定5 が述べるのは**未登録の名前**だけである。幻覚された名前を攻撃者が先に登録する型(slopsquatting)では、解決は成功する。決定5 は誤りではなく、範囲が欠けていた。
- 決定5 の前提(未登録の名前は解決で落ち、G-5 が落ちる)を、準拠テンプレートで実行して確かめた記録が無かった
- 基準8 の一覧は「PR の記述」へ出すと条文に書いていたが、実装はジョブの要約と `evidence/` へ出す。表示と実態が食い違っていた。さらに、差分の行を切って、切ったことを表示しなかった
- 外部の根拠は、脅威の測定が 2024 年初のモデルのものに限られ、2026-11 のエージェントでの率と実害の規模の一次記録が無い(EV-0351)

## 決定

1. **決定5 の範囲を明示する**。依存の解決が走る構成(アダプタ node の `npm ci` など、依存の取得のコマンドが空でない構成)では、未登録の名前は依存の取得の失敗で G-5 が落ちる。これを実行で確かめた(2026-11-27。node 26.13.0・npm 11.20.0。乱数の名前 `zz-nonexistent-pkg-<乱数>`、レジストリは読み取りの照会だけ)。
   - マニフェストだけに足した構成の `npm ci`: 404、終了コード 1
   - ロックファイルに、存在しない名前の解決元 URL を書いた構成の `npm ci`: 404、終了コード 1
   - 名前を足して `npm install`: 404、終了コード 1
   - 段の失敗が集約の失敗になる結線は、アダプタの `run install` が終了コードを伝えること、setup-stack の依存の取得に `continue-on-error` が無いこと、集約が failure と success でない結果を落とすことを、試験で固定した(IMPL-1041)
   - 限定: 依存の取得が空の構成、アダプタ none・undetermined では解決が走らず、捕まらない。この状態は一覧の頭に「依存の解決: 未実施(理由)」と出す。ADR-0151 が依存の導入を保証の開示 項目4 の対象外とした理由を覆す材料は無く、項目4 の扱いは変えない。解決の成功は、名前が登録済みであることしか示さず、悪性でないことを示さない
   - 実行で落ちない構成が見つかれば、そのスタックで実在を独立の基準にすることを、議長の裁定で足りる改訂として行う。python・go では確かめていない
   - 決定5 の「新しい条文を置かない」は、登録済みの悪性の名前について置き換える。次の決定2〜4 が受ける
2. **基準8 の一覧に来歴の欄と状態行を足す**(合否は判定しない)。欄は解決元・版の公開日時・名前の初回公開日時・公開者・署名と来歴の証明の有無・検証の結果。頭に依存の解決・照会・検証の状態と、表示から省いた件数を出す。取得できない値は空欄にせず、「照会せず」「取得できず」「対象外」と出す。印は、初出の名前・公開者の変更・証明の退行・検証の失敗・照会せず・取得できず・対象外・表示の省略とする。解析と照会の入力は、表示で切った後の行にしない
3. **検証の失敗を G-5 の合否にしない**(基準9 を本改訂で置かない)。検証の結果は一覧の欄とし、失敗の行を印として G-6 の必須の確認事項にする。署名・来歴の証明・完全性を種類で分け、完全性を来歴と数えない。偽陽性が私設レジストリ・ミラー・鍵の更新の時期で実行では未確認であるため(EV-0353)。採用者の実行の記録を見て再審議する
4. **G-6 基準5 の観点を2つに限って拡張する**。(i) 追加・更新した依存が意図した部品であること、(ii) 一覧の印の付いた行を読んだこと。直接の依存は全件、推移的な依存は印の行だけが対象である。照会せず・対象外・表示の省略の行は、読む対象に含める。印の件数に上限を設けない。確認は悪意の不在を確かめない。確認の記載は、5.8.5 の検出の一覧の型へそろえる。この型は、一覧を G-6 の必須の確認事項へ載せ、記載は機械が確かめない。本件も manual とする(EV-0354)
5. **一覧の出力先の条文を実装に合わせる**。「PR から辿れる G-5 の記録(ジョブの要約)」とする。記録の保持は、第4章の「判定が指す記録の保管」の既存の規定による。新しい保持の条文は置かない
6. **準拠テンプレートの降ろし方**: 解析と照会を降ろすのは node だけ。python・go は未降下(IMPL-1039。`plan=adopter`)で、差分の行だけを出し「解析せず」と表示する。ロックファイルの無い構成は「推移的な依存は見えない」を、私設・ミラー経由は「対象外」を出す。解析・一覧の組み立て(ネットワークを使わない)と照会(ネットワークを使う)はファイルで分け、試験は応答を差し替える
7. **統制の閉じ方**: 機械で閉じるのは、未登録の名前の失敗の結線・一覧の存在・欄・状態行・省略の件数。欄の値は合否を判定しない。意図した部品かは manual で、根拠水準を開示する(EV-0354)。手元と CI の install の露出は本件で閉じない(5.8.6。IMPL-0200)

## 課さないと決めたこと・採らなかった案

| 案 | 区分 | 理由 |
| --- | --- | --- |
| 検証の失敗 0 件を G-5 基準9 として合否にする | 本改訂では課さないと決めた(EV-0353 の見直しで再審議) | 偽陽性が未確認で、「出たら一覧へ下げる」昇降の条件は採用者から見て安定した規定にならない。例外の経路は #459 と順序が衝突する |
| 実在を独立の基準にする | 現時点で採らない(条件つき) | 未登録の名前は install で既に落ちる。足すのはレジストリ照会の不達という故障点で、登録済みの悪性の名前を通す。落ちない構成が実行で見つかればそのスタックで採る |
| ADR-0151 を変えて、依存の導入の未実施を保証の開示 項目4 に出す | 採らない | ADR-0151 の理由を覆す材料が無い。一覧の状態行で開示する |
| CI で install スクリプトの抑止(`--ignore-scripts` 等)を必須にする | 課さないと決めた | ネイティブの構築を要する依存の正規の構成を壊す。手引きとして README に置く |
| 公開から日数の閾値(cooldown)を標準の基準にする | 課さないと決めた(EV-0352) | 値の根拠が規格でも観測でも定まらない。道具の設定で掛けることは妨げない |
| 採用者に cooldown の設定の有無を開示させる | 課さないと決めた | 開示を求めると欄の欠落が新しい差し戻しを生み、守るのは開示の有無であって依存ではない |
| ダウンロード数を扱う | 採らない | 水増しでき、定義が揃わず、閾値の先例が無い |
| 署名者の期待値(誰が署名すべきか)の一致を確かめる | 本改訂では課さないと決めた | 期待値の正本がレジストリに無く、採用者ごとの宣言を要する。公開者の変更の印で兆候を見る |
| 印の件数に上限を設ける | 採らない | 上限を超えた行が読まれない行になる |
| 既知の悪意の一覧(OSV の MAL-)を基準2 の範囲と主張する | 主張しない | 重大度の無い記録はすり抜けうる(未確認)。道具によって拾うことを手引きに書き、保証しない |

## 影響

- 基準8 の一覧が、登録済みの悪性の名前の兆候(初出の名前・公開者の変更・証明の退行)を読み手へ出す。G-6 の確認が、読む対象を印の付いた行へ絞れる
- 守るのは、出荷される製品の利用者である。失うのは、照会の不達や対象外の行を読む手間を負う判定者である。手元と CI の install の露出は閉じない
- 実レジストリでの値の正しさ(公開日時・公開者・証明の有無の読み取り)は、応答を差し替えた試験でしか確かめていない。python・go は降りていない
- 見直しの契機: EV-0351〜EV-0354 の見直し、レジストリの来歴の普及率の変化、5.8.6 要求事項2 が降りたとき、採用者の実行の記録
