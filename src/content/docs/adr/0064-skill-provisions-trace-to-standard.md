## ステータス

採用(2026-10-13)。[ADR-0040](/process-compass/adr/0040-template-forms-as-subset-of-standard/)の決定4(標準と逆の指示を書かない)を、様式から、スキルの手順の文へ及ぼします。ADR-0040 のほかの決定は維持します。

## コンテキスト

[#310](https://github.com/Takenori-Kusaka/process-compass/issues/310) の調査は、準拠テンプレートのスキル(56ファイル)を全文読み、190 の事項を標準と突き合わせました。記録は `research/302-310-deliberation/`(`survey-310.md` 1.8、`decision.md` の C-10)と、全件の一覧 `tmp/302-310/s310-skills-inventory.md` にあります。

| 種別 | 件数 | 内容 |
| --- | --- | --- |
| テンプレートにだけある | 17 | 標準に対応する記述が見つからない |
| 弱い言い直し | 13 | 標準の要求を、弱い形・狭い範囲で言い直している。または落としている |
| 強い言い直し | 7 | 標準が限定つきで書く事項を、無限定の禁止・必須にしている |
| 食い違い | 14 | 数値・順序・対象・主語・番号が違う |
| 不明 | 4 | 標準の側が割れている。または定義を確かめられない |

- #300 が標準の側で改めた文が2件、スキルに改訂前のまま残っていた
- 変更ごとのリスク区分 R1 に課す要求を、スキルが案件の安全重要度で書いていた。安全重要度の低い案件の R1 の変更で、標準の要求がスキルの上で消えていた
- スキルの手順の文を読む検査は、1つも無かった。[実装マークの規約](/process-compass/community/implementation-marking/)は、実行層にしか無い規定を検出する手段が無いと、自分で開示していた

## 決定

### 1. 要求と禁止の文末を持つ文に、所在か印を必須にする

準拠テンプレートのスキルの文のうち、要求または禁止の文末を持つものには、次のどちらかを付けます。

- 本標準の所在(本文の節、規定の附属書の節、実装マークの番号)
- 「テンプレート独自」の印と、足した理由

テンプレート独自の文は、本標準の要求事項を弱めません。本標準と逆の指示を書きません。本標準が限定つきで定める事項を、限定を外して書きません。本標準と食い違う場合は、本標準によります。

### 2. 検査する

`npm run check` が、印の有無と、所在の実在を確かめます。対象は、文末が要求・禁止の形の行と、禁止を列挙する節の項目です。参考の附属書は、根拠として受け付けません。

### 3. 55件を個別に処理する

食い違いと言い直しの55件は、1件ずつ処理しました。処理の記録は `research/302-310-deliberation/implementation-C.md` にあります。標準の側が割れている件は、スキルを改めず、標準で決める事項として残します。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 独自の文を認めず、すべてに標準の所在を求める | スキルにある実装の知恵(転記の印、日数の目安)を、標準へ上げるか消すかの2択にする。標準は、形式と配置を準拠テンプレートに委ねている |
| 独自の文を認め、印と台帳で開示するだけにする | 印の付け忘れを拾えない。標準より強い・弱い・逆の文を、止められない |
| 55件を個別に処理するだけにする | 経路が無いままなので、次の改訂で同じ差が生まれる |
| 準拠テンプレートを、規格の外と明記する | 現場が従うのはスキルの文である。規格の外と書いても、標準の要求を落とす差は利用者に見えない |

## 影響

- スキルの文に、HTML コメントの印が付く。読み手には表示されない
- **検査が確かめるのは、印の有無と所在の実在までである**。引いた節の内容とスキルの文が合っているかは、確かめない。標準の要求をスキルが落としていることも、検出しない
- 平叙の文と依頼の形で書いた規則は、検査の対象の外である。スキルの規則の多くは、この形で書かれている。対象を広げるかどうかは、検査を運用した後に決める
- スキルの突合は190 の事項であり、全文の1文ごとの突合ではない。食い違いが残っている場合がある
