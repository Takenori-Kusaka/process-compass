## ステータス

採用(2026-11-17)。軽の審議の結論です(Issue #330、`research/330-deliberation/b12-03-ruling-proposal.md` の T-5・T-7)。[ADR-0084](/process-compass/adr/0084-check-strength-plans-and-resident-rules/) 決定4(adopter の型)を補い、置き換えません。

## コンテキスト

- IMPL-0239(第4章 G-5 の対象なしによる通過)と IMPL-0234(アダプタを使うジョブの失敗の伝播)は、`plan=scheduled`、`issue=330` の降りていない規定だった
- IMPL-1001(G-5 基準6 の分量の上限が未設定の状態を宣言の欠落として数えること)は、`plan=scheduled`、`issue=337` だった。準拠テンプレートは既定の上限を持たず(値は組織が定める値。第1章 1.7.7)、数えると上限を置いていない全採用者の G-7 が落ちる
- #330 の準拠テンプレートの項目で、降ろせる部分は降りた。基準と理由は項目4 が検査ごとに出す。続いていることは継続期間(IMPL-0993)が出荷ごとに見せる。依存の導入の段に `continue-on-error` を置かないことは、構文で確かめる
- 残った部分は、準拠テンプレートが保証できない。`scheduled` のまま残すと、降ろす見込みの無い計画を「予定」と表示し続ける
- 登録簿 `src/data/impl-no-adopter.yaml` に、この2件の節(G-5 の検査対象が存在しない場合の扱い)は載っていない。adopter にできる

## 決定

次の4点を、準拠テンプレートに降ろさず、採用者に委ねる。マークは `plan=adopter`、`check=manual`、`decision=ADR-0166` とし、`issue=` と `review=` は付けない。規定は課したままです。

1. **判定の時刻の記録(IMPL-0239)**。対象なしで通した判定の時刻は、準拠テンプレートの集約が記録しない。集約の生成の時刻は G-5 の判定の時刻ではない。ジョブごとに記録を書かせて取り込む経路は、G-5 の全ジョブと出荷の証跡の結線に及ぶ。継続期間で読める以上の信頼を足さない
2. **実装の開始の後に対象なしを用いないことの機械的な停止(IMPL-0239)**。実装の開始の時点を機械は決められない。目印のないコードは機械で見つけられない。目印が下の階層にあり所在を書いていない場合の一部は、IMPL-0475 の検査が落とす。それ以外は人が確かめる
3. **各スタックの検査器が依存の取得の失敗で失敗に終わること(IMPL-0234)**。`npm audit`、`license-checker`、`pip-audit`、`govulncheck` 等の入力の欠落時の挙動は道具の実装で、準拠テンプレートは保証できない。空の install と lock ファイルだけの構成で、`license-checker` が空の一覧で通りうる筋が残る

4. **分量の上限が未設定の状態を宣言の欠落として数えること(IMPL-1001)**。上限の値は組織が定める値(第1章 1.7.7)で、準拠テンプレートは既定の上限を持たない。そのため準拠テンプレートの集約は、未設定を宣言の欠落として G-7 で数えず、保証の開示 項目2 の宣言の表に未設定の行として出すまでにとどめる。上限を定めて宣言することと、未設定のまま出荷しないことの確認は、採用者に委ねる。標準の 1.7.7 の扱い(宣言の欠落)は課したままである。マークは `plan=adopter`、`check=manual`、`decision=ADR-0166` とし、`issue=` は付けない

### 採用者に求めること

- 実装の開始の後に対象なしの通過が続いていないかを、項目4 の継続期間を見て確かめる。続くときは、アダプタの所在(`projectDir`)か目印を直す。判定の時刻を残したい採用者は、自らの CI の記録を出荷の証跡に添える
- 採用するスタックの検査器が、依存の取得に失敗したとき失敗で終わることを、導入のときに一度確かめる。通ってしまう検査器は、自らの CI に取得の成否の検査を足す
- 分量の上限を組織が定めて宣言する。宣言の表に未設定の行が残っていないかを、出荷判定の前に確かめる(IMPL-1001)
- 確かめる者は、計画の担当ではなく、技術判断者の席の責任者とする(導入のとき・スタックを変えるとき・出荷判定の前)

### 委ねる理由

4は、既定の上限の値を持たないまま数えると、上限を置いていない全採用者の G-7 が落ち、採用者に新しい差し戻しを課すことになる。数えない代わりに、宣言の表へ出して見える状態を保つ。1と2は、記録を足しても継続期間より強い信頼にならない。3は、道具の実装であって、準拠テンプレートの単位(単一の案件のリポジトリ)の中で保証できない。

## 検討した選択肢

| 案 | 採否 | 理由 |
| --- | --- | --- |
| `plan=scheduled` のまま残す | 採らない | 降ろす見込みが無いのに予定と表示する。降りていない規定の台帳を、実態と食い違わせる |
| 集約の生成の時刻を判定の時刻と読み替えて delivered にする | 採らない | 表示と実態が食い違う |
| 各ジョブに記録を書かせて取り込む経路を新設する | 採らない | G-5 の全ジョブと出荷の証跡の結線に及び、継続期間以上の信頼を足さない |
| 各スタックの検査器をテンプレートが包んで失敗を保証する | 採らない | スタックごとの道具の実装に依存し、未検証のコマンドを書くことになる |
| 準拠テンプレートが、上限の未設定を宣言の欠落として数える(IMPL-1001) | 採らない | 既定の上限を持たないまま、上限を置いていない全採用者の G-7 を落とす。値は組織が定める値(1.7.7)で、値を定めさせる強制は採用者への新しい義務になる |

## 影響

- IMPL-0239・IMPL-0234・IMPL-1001 は `plan=adopter`、`decision=ADR-0166` の降りていない規定として台帳に出し続ける。`#330`・`#337` の計画からは外れる
- 採用者に新しい記入欄は増えない

:::caution[暫定 EV-0320 / 見直し 2027-05]
**対象**: 判定の時刻の記録と依存の取得の失敗の確認を、採用者の確認に置いても、対象なしの通過と検査器の空の通過が見過ごされないこと(決定1〜3)。
**根拠の水準**: E0(なし)。
**備考**: 判断であり、採用者の観測は無い。
**差し替え条件**: 実装の開始の後も項目4 の継続期間が延びた事例の件数。検査器が取得の失敗で通った事例の件数。事例が1件でもあれば、決定を審議し直す。
:::

## 確かめていないこと

- 採用者が出荷判定の前に、宣言の表の未設定の行を確かめるか
