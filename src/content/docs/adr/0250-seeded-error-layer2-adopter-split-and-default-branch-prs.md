## ステータス

採用(2026-11-20)。審議は軽です。記録は `research/b27-deliberation/` にあります。仮番号です(番号の付け直しは指揮役が行う)。

## コンテキスト

- 第5章 5.6.2 の第2層は、注入したコミットに標識を付けること、標識を含むコミットの本番のブランチへの取り込みを取り込みの前に拒否すること、演習用のブランチで標識の失われる履歴の書き換えをしないことを含む。IMPL-0191 は3つを1つのマークで持っていた
- 機械で閉じるのは取り込みの前の拒否だけである。標識を付け忘れた注入は、どの層の走査にも当たらない。PR のブランチの書き換えで標識を落とした履歴は、取り込みの前の検査も出荷の走査も見つけない
- 取り込み前の拒否の対象とする「保護ブランチ」を、ルールセットの include から読むと、判定記録の置き場(`records`)宛の PR で誤って走る。既定ブランチの先端から切ったばかりの演習用ブランチは、既定ブランチと同じ SHA を指すため、SHA の一致では取り違える
- 直接の push の欠けの表示は、B26 の裁定が preflight に置かないと決めた。その前提(env-check が既に pull_request の欠けを出す)は、G-6 が有効なときだけ成り立ち、checks-only では成り立たなかった

## 決定

1. 第2層のうち、標識を欠いた注入をしないこと、演習用のブランチで標識の失われる履歴の書き換えをしないことは、IMPL-1033(`plan=adopter`)に分ける。IMPL-0191 は取り込みの前の拒否だけを持つ。確かめる者は採用者の品質保証の担当である。採用者に求めること・委ねる理由は次の表のとおり

   | 規定 | 委ねる理由 | 採用者に求めること |
   | --- | --- | --- |
   | 標識を欠いた注入をしない | 注入の操作は採用者が行い、準拠テンプレートに運ぶ仕組みが無い。注入の記録はリポジトリの外にあり、出荷の経路に入力が無い | 注入のたびに識別子と期限をコミットとともに履歴に残る形で付ける |
   | 演習用のブランチで標識の失われる履歴の書き換えをしない | 書き換えは PR の検査も出荷の走査も見つけない。機械の検査は決定可能な条件に限る(自由な操作の防止は機械で閉じない) | 演習用のブランチで squash・rebase・履歴の書き換えを禁じる設定と、その記録を持つ |

2. 取り込み前の拒否(IMPL-0191)の対象は、PR の基底が既定ブランチ(`--policy-base`)と同じ名の参照である PR とする。判定は参照の名で行い、SHA では比べない。ルールセットの include は読まない。リリースブランチは本番のブランチに数えない。リリースブランチを持つ採用者は、強制層の変更(check-pr の判定の拡張)として扱う
3. 既定ブランチへの直接の push の欠けは、止めずに表示する。表示の置き場は env-check のルールセットの項目(`pull_request` の規則が無いとき、状態を変えずに詳細へ足す)とし、preflight には置かない。経路の実在は実機で確かめておらず、EV-0345 で開示する。#361 で確かめる
4. PR の失敗の文は、出荷の走査の文と分け、第7章の例外承認を案内しない(PR のブランチで文を直せるため)

## 検討した選択肢(採らない)

| 案 | 採らなかった理由 |
| --- | --- |
| ルールセットの include を読んで保護ブランチを決める | `records` 宛の PR で誤って走る。glob の解釈を増やす |
| SHA の一致で既定ブランチ宛とみなす | 切ったばかりの演習用ブランチを取り違え、見つける者の面に標識の失敗を出す(秘匿を崩す) |
| 演習用ブランチ宛の PR も止める | 見つける者の面に標識を出し、秘匿を崩す |
| リリースブランチを本番のブランチに数える | 条文は本番のブランチの定義を置かない。細かい定義を増やす |
| preflight に表示を足す | 宣言の JSON だけを読み、実機を見ない。B26 の裁定が採らないと決めた |
| 直接の push の欠けを失敗または不一致にする | 構成の選択肢(checks-only)を実質的に奪う |
| checks-only の ruleset に承認0名の `pull_request` の規則を足す | 採用者への新しい義務になる。#361 の実機の確認で経路が実在したとき、重の審議の題とする |
| (i)(iii)を IMPL-0191 の note の開示だけで済ませる | 台帳の state・check の欄が、閉じていない部分を閉じたように読ませる |
| (i)(iii)を IMPL-0190 の note へ足す | 第1層のマークに範囲が混ざる |
| (i)を注入の記録と標識の突合で機械に閉じる | 注入の記録(台帳)がリポジトリの外にあり、出荷の経路に入力が無い(ADR-0161 の採らない案と同じ理由) |
| PR の文に例外承認の経路を置く | 直す手段がある段階で例外を置く理由が無い |

## 影響

- 台帳に、降りていない規定として IMPL-1033 が出続ける。IMPL-0191 は準拠テンプレートの検査が降りたとき `delivered check=machine` になる
- ルールセットの JSON とワークフローは変えない。check-pr の新しい失敗は G-5 を厳しくする変更である(準拠テンプレートの README に明記する)
- ADR-0161 の表と ADR-0139 の表は書き換えない。本 ADR が(i)(iii)の帰属を決める
