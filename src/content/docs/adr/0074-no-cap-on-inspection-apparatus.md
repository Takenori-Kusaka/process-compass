## ステータス

採用(2026-10-23)。[ADR-0073](/process-compass/adr/0073-corrective-action-by-impact-and-control-effectiveness/)の決定3 のうち、検査の装置の不具合を是正の起点に含める範囲(重大度の限定を持たない部分)と、決定2 の起点「統制の弱化の検知」の範囲(記名の済んだ縮小を含めない)を、本 ADR の決定5 で置き換えます。ADR-0073 のその他の決定は維持し、決定6 は本 ADR の決定4 が補います。[ADR-0050](/process-compass/adr/0050-enforcement-layer-is-not-staged/)の参照の誤りの正誤を、決定11 に記録します。

## コンテキスト

[#290](https://github.com/Takenori-Kusaka/process-compass/issues/290) は、実証案件の報告(#267・#270)と原則の照合(#275 原則5、#269)から、検査装置の総量を扱いました。観測は5つです。装置が増え続けて開発の容量を食うこと、足す費用の安さと外す費用の高さ、「80 点で止める」凍結、装置修理の PR の割合、1 つの PR から後続の Issue が 1 つずつ生じることです。あわせて、附属書B の escape clause の採否が問われていました。指摘をそのまま条項にせず、調査3本と会議体5名の意見書で扱いました。記録は `research/290-deliberation/`(`decision.md` の E-1〜E-13)にあります。

### 量は数える単位で動く

検査装置の量を数える単位(ジョブ、スクリプト、規則の1行)は定義で動き、束ねれば値を満たせます。規制の総量を管理した制度の公的な評価(英国 2016、カナダ 2022)は、廃止に数えた規則の多くが負担に影響しなかったと示しました。変更に占める装置修理の割合は、2つの実証案件で同じ名の量が 55〜65% と 15.6〜45.3% に揺れました。

### 効いている検査の集合が見えていなかった

会議体の品質保証の委員が、準拠テンプレートで次を実行して確かめました。

- G-5 の集約ジョブの `needs` から 8 基準のうち 5 つのジョブ(秘匿情報の検査を含む)を外しても、契約検査は「整合しています」と答え、保証の開示 項目4 は「実施」と出した
- 検査を意図して外す PR は、陰性の確認に正直に「止まらなかった」と書けば落ちた。偽って「止まった」と書けば通った
- 検査のスクリプトを `process.exit(0)` に替えた PR は、誤りと注意を1件も出さずに通った
- 初期化は、事業ステージが PoC のとき、フックの保護と権限設定の遮断を外していた。ADR-0050 が退けた「S0 に限り強制層の適用を免除する」そのものである

量を数えない以上、前提が2つ要ります。効いている検査の集合が正しく見えること、外すときに記名の責任者がいることです。品質保証の委員は、量を課さない判定の条件にこの2つを挙げました。本 ADR は両方を採ります。

## 決定

### 1. 検査装置の総量に上限を置かない

検査装置の量(本数・行数・実行時間・変更に占める割合)について、上限・警戒水準・警戒サインを置きません。運用メトリクスの「採用しない指標」に書きます。害は量ではありません。止めるべきものを止めないこと、止めてはならないものを止めること、保守に手間を食うことの3つです。前の2つは是正の起動(ADR-0073)が、3つ目は決定3 の棚卸しが拾います。根拠水準は EV-0126(E1)で開示します。

第1章 1.4 に「検査装置」を定義します。強制層の検査と、それを動かす構成とスクリプトの総称です。

### 2. 判定基準を実装する検査が集約に入っていることを、機械で確かめる

第4章 G-5 に「判定基準を実装する検査と集約」を置きます。判定基準を実装する検査は、必須の検査の集約の合否に含めなければならず、集約から外すことで基準を外してはなりません。外せるのは第8章の調整だけです。準拠テンプレートの契約検査が、集約の `needs` と結果の使い方を確かめます(IMPL-0142)。

附属書H の保証の開示 項目4 の「実施」は、集約が合否に使った検査から導きます。項目は増やさず、出所を直します。これは ADR-0073 決定5(設計の有効性で運用の有効性に代えない)の直し残しです(IMPL-0147)。

### 3. 強制層の検査の追加・削除・統合は AI維持管理者が承認する

強制層への組み込みの承認は、追加・削除・統合のいずれも AI維持管理者とします。[ADR-0038](/process-compass/adr/0038-detection-handoff-of-control-weakening/)の決定3(強制層の変更の承認者は AI維持管理者)で既に決まっている席です。どの規則を機械化するか(検査の追加の要否)は、技術判断者が決めます(第4章 G-5)。要否の判断と強制層の一貫性の承認を分けることで、G-5 と 3.11.2 の両方の文が成り立ちます。第3章 3.11.2 の承認権限、3.11.4 の要求事項3・4 の範囲、3.11.8 の RACI に明記します。RACI には「CI の検査の追加の要否」(A = 技術判断者)と「強制層の検査の追加・削除・統合」(A = AI維持管理者)の行を足します。Label Mailbox の `state:needs-platform` の範囲も、追加を含む形に揃えます。AI の名義の承認は受け付けません。

会議体の決定(E-2)は追加の A を技術判断者としていましたが、ADR-0038 決定3 の字面と当たるため、突合の後の議長の裁定で上記へ改めました(`research/290-deliberation/decision.md`「突合の後の裁定」X-2)。

[ADR-0056](/process-compass/adr/0056-assurance-argument/)の決定10 の廃止の候補は、3.11.4 要求事項4 の四半期の棚卸しの入力にします。候補を挙げる材料は、検査の装置を起点とする是正の記録と、検査ごとの失敗の履歴です。運用カタログの四半期に棚卸しの行を足し、四半期の振り返りの参加者に AI維持管理者を加えます。新しい判定の場は作りません。根拠水準は EV-0127(E1)で開示します。棚卸しの入力を一覧に出す手段は準拠テンプレートに無く、IMPL-0145(降りていない)で表示します。

足す側を軽く、外す側を重くする非対称は、意図した設計として保ちます。外す変更は統制を緩める向き([ADR-0055](/process-compass/adr/0055-team-change-points/) 決定5 と同じ非対称)であり、記名と理由を要します。Label Mailbox 4.2 原則4 の上申も保ちます。

### 4. 検査を外す変更の記録を置く

陰性の確認(ADR-0073 決定6)の結果に「外した」を加えます。記録は、外した検査、その検査が止めていた場面、外した後にその場面を止めるもの(または止めないと決めた理由)、受け入れた者(AI維持管理者。AI の名義は不可)の4つです。準拠テンプレートの PR 単位の検査がこの記録を確かめます(IMPL-0143)。

統制の設定に、検査装置(テンプレートの `scripts/gate/**`・`scripts/vendor/**`・`adapters/**`)を加えます(IMPL-0134 の範囲を広げた)。プロセス内部監査の観点4 に、必須の検査の削除を加えます。

### 5. ADR-0073 決定3 の起点の範囲を、影響で限る(一部置き換え)

記名の済んだ縮小は、是正の起動の起点「統制の弱化の検知」に当たりません。記名の無い縮小は当たります。

ADR-0073 決定3 の「検査の装置そのものの不具合も、起点に含めます」の範囲を、装置の不具合が起点(Sev1・Sev2 の欠陥の流出、欠陥注入の見逃し、統制の弱化)に当たる影響を生んだ場合に限ります。それ以外の誤検知は、月次の CI ゲートの見直しで扱います。ADR-0073 決定3 は重大度の限定を持たず、字義どおりに読むと誤検知1件ごとに是正の記録が義務になり、運用カタログの月次の作業と食い違っていました。

これは読み方ではなく決定の範囲の変更です。誤検知の大半は起点の影響を生まないため、ADR-0073 決定3 の「止めてはならないものを止めた場合」は、多くが起点から外れます。そのため ADR-0073 の決定3 の一部置き換えとして扱い、両側の状態の行を揃えます([ADR-0071](/process-compass/adr/0071-structure-of-principles-decisions-and-gate-records/)の状態の語彙)。誤検知が起点に当たるのは、たとえば誤検知を理由に検査が外され、統制が弱まった場合です。記名の済んだ縮小を起点の「統制の弱化の検知」に当てないことも、ADR-0073 決定2 の起点の範囲を狭めます。これは本決定の前半として、同じ一部置き換えに含めます(突合の後の議長の裁定 X-3)。

### 6. 追加の凍結を課さない

本標準は、検査の追加を一律に止める手続を定めません。検査の追加は義務ではないので、組織は宣言なしに控えてよいものとします。凍結中であることだけを、是正の記録の項目3(再発防止を仕組みで置かない理由)にしてはなりません。出荷後の Sev1・Sev2 の是正の記録は、凍結中も省けません。

### 7. 足す向きの本文を「足す・直す・外す」へ改め、「ルール化の進み」を外す

運用メトリクスの「ルール化の進み」を指標の表から外し、「採用しない指標」へ移します。対になる指標を指定できず(手続2)、自動集計が実装されていませんでした(手続3)。値は常に 0 で、警戒サインは点き続けていました。「ゲートの成長 = 健全」という前提は、ADR-0056 決定10・ADR-0073 決定3 の向きと逆です。

G-5 の「合意済みルールはすべて機械化」を、ADR-0073 決定2 の3つの条件を満たすものに限る文へ改めます。誤りは限定を落とした文の側で、機械化できるものは機械化するという原則は守ります。CI/CD ゲート構成の「成長させます」と図を「足す・直す・外す」へ改め、改善サイクルの内側ループに、CI の検査を外す・統合する変更は AI維持管理者が承認すると書きます。統制を緩める向きのその他の変更(基準値の引き下げ・除外設定の追加など)の承認者は動かさず、既存の規定(第4章 G-5「基準値と除外設定の変更」、[ADR-0055](/process-compass/adr/0055-team-change-points/) 決定5、第3章 3.8.1)を引きます(突合の後の議長の裁定 X-1)。`rule-candidate` のラベルで収集する、の文は規定から外します。指標を外したので、ラベルの役目が無くなります。

### 8. 装置修理の割合と後続の起票の件数を課さない

変更に占める装置修理の割合と、変更あたりの後続の Issue の件数・バックログの純増を、「採用しない指標」に置きます。修理はパスで分けられず、ラベルで分ければ ADR-0073 決定1 の理由(分類は申告で、閾値は分類で外せる)が当たります。後続の起票は見つけたことの記録でもあり、件数を下げる圧力は起票の抑制へ向きます(ADR-0072 と同じ型)。バックログの純増を完了の流れの対の指標とする案は、#296 の候補として申し送ります。

### 9. escape clause を3つの意味に分けて記録する

| 意味 | 扱い | 所在 |
| --- | --- | --- |
| (a) 要求文の中の逃げ道の句 | **採用済み**([ADR-0062](/process-compass/adr/0062-ambiguous-terms-source-of-truth/))。第4章 G-2 基準2 の類と検出語。附属書B は G-2 を引く。残っていた直し残し(第6章 テンプレ1 の注記の旧い6語、第8章 軸A の升)を本 ADR で直した | 第4章 G-2、附属書B |
| (b) 当てはまらない項目を外す規定 | **課さない**。附属書B のチェックリストに「該当なし」の欄を置かない。外すのは第8章の規則と事実の記録に限る | 附属書B |
| (c) 基準が言い訳に転用されるパターン | **採用者には課さない**。本標準の起草手順に置く | 第1章 1.7.5、附属書B、`community/provision-forms.md` |

#269 の突合(2026-10-08)の「附属書B に escape clause の記述が無い」は、ADR-0062(2026-10-13)より前の状態の記述であり、(a) の意味では解消済みです。#290 本文の「当てはまらない項目を外す規定」は (b)、#269 の起票の文言は (c) の読みです。1つの語で3つの別物を指したままでは、「書かれていない」と「課さないと決めた」を意味ごとに区別できません。

(c) の起草手順として、条項を新設し改める会議体の突合で、その条項が何を理由に緩めることへ読み替えられうるかを問い、見つけた読み替えは条項の中に禁止として書きます。附属書H H.11「残るリスク」の表を、本標準の主張に掛かる読み替えの台帳として扱います。本標準は既に会議体で条項ごとに読み替えの禁止を書いてきました。その作業を手順にします。採用者に読み替えの列挙を課した規格は見つからず、列挙の網羅は記録で判定できません。根拠水準は EV-0128(E1)で開示します。#269 の「Pre-PMF だから」の転用は、第8章 軸B と ADR-0050 で既に塞がれていると附属書B に記します。

### 10. 逃げ道の句を本標準の規定文に使わないことを、起草規則にする

`community/provision-forms.md` に「本標準の規定文に逃げ道の句を使わない。委ねるなら『組織が定める』と書く」を起草規則として置きます。本標準の規定文に対する逃げ道の句の機械検査は課しません。辞書による検出の適合率は 0.70〜0.81 と報告されており、ADR-0073 決定2 の3つの条件(実効的な偽陽性が無い)を満たさないためです。`lifecycle.md` 2.10 の冒頭の説明の文は、規定の文ではないので直しません。

## 検討した選択肢

| 論点 | 採らなかった案 | 採らなかった理由 |
| --- | --- | --- |
| 総量 | 本数・行数の上限 | 数える単位が動き、統合で満たせる。判定者が差し戻す根拠を持たない |
| 総量 | 警戒水準だけを置く | 点いたときの打ち手を書けない([ADR-0072](/process-compass/adr/0072-document-volume-is-not-a-metric/)と同じ論法) |
| 総量・席 | 総数を増やさない(ratchet) | 初期の案件(検査 0 本)を縛り、統合で満たせる。業界の ratchet は違反の件数を固定する仕組みで、対象が逆 |
| 席 | 足す席と外す席を同じ(技術判断者)にする | 外す判断を、足した者が抱え込む。外す側の独立が弱まる。会議体は AI維持管理者が多数だった |
| 席 | 外す手続を軽くする | 統制の弱化の経路(ADR-0038・ADR-0055)を開く。軽くする材料は無い |
| 凍結 | 凍結を標準の手続・テーラリングの選択にする | 「80 点」は測れず、凍結の効果は測られていない。宣言で是正の判断を先取りする |
| 装置修理の割合 | パスで機械判定する、ラベルで数える | パスでは修理を分けられない。ラベルは ADR-0073 決定1 の理由が当たる |
| ルール化の進み | 両側の警戒にする、データ源を実装して残す | データ源が無いまま2つ点く。ラベルは申告で、付ければ消える警戒になる |
| (a) | 本標準の規定文の逃げ道の句を機械で検査する | 適合率が 0.70〜0.81 で、3つの条件を満たさない |
| (c) | 採用者の基準に転用の列挙や反例の欄を課す | 列挙の網羅は記録で判定できず、定型文で埋まる。書かれた禁止は守られにくい |
| (c) | 一般的な濫用防止規定(目的に反する結果を文言の充足で得てはならない) | 当該ゲートの判定基準だけで判定する [ADR-0036](/process-compass/adr/0036-gate-closure-by-record/) 決定4 と当たる |
| (b) | チェックリストに理由つきの「該当なし」を置く | 記入者の裁量で外す欄は、[ADR-0028](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)・ADR-0036・ADR-0071 が退けた形である |

指標の総数の上限(正式指標 20 件と表の行数)は、#289 の決定どおり #296 へ送ります。本 ADR は指標を足さず、「ルール化の進み」を1つ外しました。この変化を #296 へ申し送ります。

## 影響

- 第1章 1.4 に「検査装置」が加わる。1.7.5 に、組織が書く基準へ読み替えの列挙を求めないことが加わる
- 第3章 3.11.2・3.11.4・3.11.5・3.11.8 に、強制層の検査の削除・統合の席と、非対称を保つことが加わる
- 第4章 G-5 に「判定基準を実装する検査と集約」と「検査を外す変更の記録」が加わり、原則の文と「是正の起動」が改まる
- 第8章 軸A の升が 1.7.3 の語彙になり、軸B の参照が 3.11.3 になる。規則データ(`rules-team-size.yaml`)の同じ升も改めた
- 附属書B にチェックリストの「該当なし」を置かないことと、読み替えの列挙を求めないことが加わる。附属書H の項目4 の出所が改まる
- 運用メトリクスの「採用しない指標」に4行が加わり、「ルール化の進み」が指標の表から外れる。改善サイクル・運用カタログ・CI/CD ゲート構成・プロセス内部監査が改まる
- 準拠テンプレート: 契約検査が集約の `needs` を確かめる。保証の開示 項目4 が集約から「実施」を導く。PR 単位の検査が「外した」の記録を受け付け、検査装置の変更にも陰性の確認を求める。初期化が PoC でも強制層を外さない。いずれも試験を足した
- 検査装置を変えるすべての PR(テンプレートの更新の取り込みを含む)に、陰性の確認の記録が要るようになる。記録の負担は増える。検査のスクリプトの骨抜きが黙って通る経路を塞ぐ代償として受け入れる
- PoC の立ち上げで、エージェントは強制層を編集できなくなる。過剰に感じる遮断は、ADR-0050 決定3 のとおり遮断の範囲の設計として扱う
