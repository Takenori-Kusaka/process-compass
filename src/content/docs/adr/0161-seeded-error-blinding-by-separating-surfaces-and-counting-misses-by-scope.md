## コンテキスト

5.6.2 は、運用中の継続の注入で、個々の時期・箇所を見つける者に知らせないことを求めます(要求事項2)。同じ節の実装上の要求の例(フェーズ5)は、標識(トレーラ)と演習用のブランチの名を、PR の画面に出す設計でした。標識が見つける者の面に出ると、時期と箇所が知られます。標準の例が、標準の要求事項2 を破っていました。

5.6.2 の「注入に気づいたときの手続」1 は、演習の識別子を添えた報告を求めていました。見つける者が識別子を見られるのは、標識が面に出ている場合だけです。同じ節は、演習かどうかの判別を担当者へ求めないと定めます。

7.9.1 の1 は、見逃しの連続を発動の条件にします。5.6.2 は個人単位の検出率の算出を禁じます。7.9.2 の目的の文(ADR-0067 決定2)と 7.9.6 の記録する事項は、「検知された者」「対象の人」を主語にしており、この禁止と食い違いました。一方、ADR-0127 決定5 と IMPL-0118 の集約は、範囲で数えています。

## 決定

### 1. 運用中の継続の注入で、秘匿が成り立たなかった層は未測定として開示する

- 秘匿が成り立たない場合とは、次の3つである。注入する者が見つける者を兼ねる場合。見つける者がレビューに用いる面へ、標識か演習の印が出る場合。時期か箇所を見つける者へ知らせた場合。5.6.2 の事前の周知の後へ、この1段落を置く(IMPL-1011)
- 根拠は、附属書H が保証の開示の人の層の検出率を目隠しの欠陥注入による値と定めていること。破れた層の値は、定義の上で人の層の検出率に当たらない。載せないことは、新しい義務ではなく定義の帰結である
- 運用中の継続の注入に限る。導入前の検証は、ADR-0133 決定5 のまま(附属書I I.11 要件③を本文の要求にしない)
- **課さないと決めたもの**: 注入する者を見つける者と分ける体制、秘匿の不成立への代償措置と是正。これらは ADR-0133 決定1 のままである

### 2. 1.10.2 の表から、秘匿の行を外さない

外すと適合の主張の条件を緩める向きになる。ADR-0133 決定8 の再び検討する契機(EV-0160・EV-0265 の観測、#329 の裁定、外部の確認者の席の見直し)は来ていない。離脱は適合の主張の水準、未測定は値の表示の水準で働き、二重にならない。関係を決定1 の段落に1文で書いた。

### 3. 注入する者を体制の外に置けることを、条文に書かない

条文は注入する者の所属を定めていない。1.10.2 の行の当たる条件(分けられない場合)は、外の者が注入すれば当たらない。外の注入者の条件(同意・守秘・公平性)を条文に書くと、誰が課すかが空いたまま定義が増える。手引き(フェーズ5)に「体制の外の者が注入する構成」を置き、形の説明と、ソフトウェア開発の先例が見つかっていないことの開示にとどめる。勧める書き方にはしない。

### 4. 標識はコミットとともに履歴に残し、取り込みの前の拒否を緩めない。秘匿は面の分離で取る

- 第2層の標識は、コミットとともに履歴に残る形で付ける(git notes のように取り込みで失われる置き場を閉じる)。置き場の名(トレーラ)は条文に書かない
- 標識は機械が読むためのものである。見つける者の面に出れば要求事項2 は成り立たない。その場合も、標識を外したり、取り込みの前の拒否を出荷の前の確かめに代えたりしてはならない。流出は取り消せないため、流出の防止を秘匿より先に取る。秘匿の側は決定1 で受ける
- 秘匿は、見つける者がレビューに用いる面から標識を外すことで取りにいく。方法の例(メタデータを出さずに差分だけを示すレビューパッケージ)は手引きに置く。面の分離であり、閲覧の権限の分離ではない。実証が無い(EV-0310)
- 緩める案(第2層を「取り込みの前または出荷の前」にする)を採らない理由。条文は各層の独立を定める。緩めると、第3層(タグの時点の走査)が機械の唯一の止めになる。main から継続的に配備する構成では、タグの前に main の内容が環境へ届く(推論。実行では確かめていない)。代わりの統制として挙がった外の台帳の照合は、出荷の経路に入力が無い(ADR-0139 決定1)。標識をコミットに残すなら、緩める必要が無い

### 5. 7.9 の見逃しは、範囲ごとに数える。見逃した者ごとには数えない

- 7.9.1 の1 は、見逃した欠陥の類型と対応する範囲ごとに数える。未測定とした層の結果は数えない(附属書H C6 と同じ)。7.9.1 の2 の判別は、5.6.3 の人の手続で行う。発動と通知を、機械は行わない(7.9.6 のまま)
- どちらが誤りか。5.6.2 の個人単位の集計の禁止が既に、人で数える読みを排除している。誤りは、7.9.2 の目的の文と 7.9.6 の「対象の人」の側である。ADR-0127 決定5 は既に 7.9.2 の字義(範囲)を正としている
- 7.9.2 の目的の文を「検出能力の低下が測定された範囲で、承認を単独では数えない」へ、7.9.6 の記録する事項から 7.9.1 の1 による発動の対象の人を除く。**意味が変わる**(編集の指摘ではない)。制限の対象は範囲の承認権限を持つ者の全員になる。個人の不利益は減る向きで、2名を要する者は増える向きである
- **1名の範囲では、実質が個人になる**。範囲の承認権限を持つ者が1名なら、範囲の制限はその者の承認への制限と同じである。附属書H の項目6 は測定した見つける者を名簿と併記するため、少人数では範囲から人を推し量れる。本標準はこの場合に別の扱いを定めない(課さないと決めたこと)。7.9.2 に開示した。保護として効くのは、範囲の承認者が複数いる体制だけである。注入する者が見つける者を兼ねる1名の体制では、決定1 により値が未測定になり、発動しない
- 小さい体制で発動した後に2名を確保できなければ、7.9.4(7.4 の手続、7.9.5 の枠)による。条項は足さない
- 閾値は EV-0064 のまま。範囲で数えることの効果は EV-0311

### 6. 5.6.2 の手続1 の矛盾を直す

要求事項2(時期・箇所を知らせない)が、測定の成立条件です。手続1 の識別子の報告は、突合の便宜にすぎません。突合は所在で行えます(附属書H H.4)。手続1 が誤り側です。手続1 を「通常の指摘と同じ操作で報告する。識別子を求めない。通常の指摘より多くの操作を求めない」へ改め、手続2 に「突合は注入した側が所在で行う」を足しました。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 第2層を「取り込みの前または出荷の前」へ緩める | 層の独立を破り、タグの前に main から配備する構成で機械の止めが無くなる。代わりの統制(外の台帳)は出荷の経路に入力が無い |
| 標識の置き場をリポジトリの外へ移す | 第3層が読む標識が無くなる |
| 外の台帳と指紋を主の方式にする(先送りも) | 第3層が台帳に依存し、台帳は出荷の経路に無い。フォークの PR に秘密が渡らない。偽の一致の率が未検証。足りないものがそろえば、併用として再び検討できる。秘匿には効かない |
| git notes | squash・cherry-pick で失われ、既定で push されない |
| 要求事項2 を「箇所」に限る | 秘匿を弱める |
| 決定1 を課さず、template の挙動の開示にとどめる | 附属書H の定義の帰結を書かないと、template の外の実装が破れた値を測定値として載せうる |
| 決定1 を導入前の検証にも掛ける | ADR-0133 決定5 が本文の要求にしないと決めた。本件の議題の外 |
| 1.10.2 の秘匿の行を外す | 契機が来ておらず、緩める向き |
| 外の注入者の条件を条文に書く | 誰が課すかが空いたまま定義が増える |
| 注入役を別の AI 役にする型を手引きの例に置く | 先例が無く、同じ系統のモデルが見つける側に回る偏りを測っていない。例に置くと秘匿が成り立つ構成と読まれる |
| 7.9 を二層にする(機械が範囲で数えて知らせ、誰を制限するかは人が決める) | 入力が template に無い。範囲で制限するなら名指す段が要らない。知らせる仕組みは機械による発動の禁止の趣旨に近づく |
| 7.9 を人で数える | 5.6.2 の個人単位の集計の禁止で既に排除されている |
| 7.9.6 の「対象の人」を「範囲の承認権限を持つ者」と読み替えて欄を残す | 7.9.1 の1 で人を記録する欄が残り、見逃しと人が結び付く |
| 手引きに「枠の残りを発動の記録に添える」例を置く | 7.9.5 要求事項5 の報告と重なる。細かい定義を増やす |
| 第1層の文を「閉じた記録・削除の記録を残す」へ改める | 新しい記録の義務を足し、開いたまま残る期間の限定を消す。現行の文は既に状態で書かれ、監査が状態で確かめられる |
| 「1つの操作」を条文に残す | 識別子を外すと報告は通常の指摘になる。「通常の指摘より多くの操作を求めない」で数えられる形は保てる |
| IMPL-0190・0191・0169 を scheduled のまま残す | 0190・0169 は template に決定可能な条件が無く、理由を書ける(adopter)。0191 は降ろす作業が後継に残る |
| IMPL-0191 を adopter にする | 理由の「台帳が要る」は外の台帳の前提で、消えた。取り込みの前の唯一の機械の止めを、template が届けられるのに届けないことになる |
| IMPL-0169 を delivered・manual にする | template に運ぶ文が無いまま delivered と書くと、表示と実態が食い違う |
| scheduled を0件にする | 台帳の見かけのための形になる。IMPL-0191・1010 は template の作業が残る |
| 5.6.2 の免除に第7章の例外承認を使う | 7.9.4 は制限された状態での決裁で、5.6.2 の免除ではない |

## 影響

- 破られたときの損失。注入した欠陥が main・製品へ届くと、製品の利用者と採用者が失う(取り消せない)。細かく書く。秘匿の破れた値が測定値として載ると、保証の開示の読み手が適合の主張の信頼を失う。見逃しを人で数えると、レビューする個人が不利益と報告の抑制を負う
- 運用中の継続の注入をしない採用者には、何も増えない
- 降りていない規定: IMPL-0191(標識の取り込み前の拒否)と IMPL-1010(制限の記録)は、準拠テンプレートの作業が残る。#356 は開いたまま残す
- 機械で閉じる条件: 保護ブランチ宛の PR のコミットの標識の行の有無(降りた後)、制限の記録の欄の有無と根拠の値。機械で閉じない条件: 面に標識が出たか、秘匿の宣言の真偽(manual)、面の分離が秘匿に効くか(EV-0310)
- 根拠水準: EV-0310(面の分離。E0)、EV-0311(範囲で数える判断。E1)
- 確かめていないこと: 配備の経路(決定4 の推論)、GitHub 上の squash・rebase の挙動(EV-0291)、IEEE 1028・ISO/IEC/IEEE 29119・ISO/IEC 17043 の本文

## 見直しの契機

- EV-0310・EV-0311 の見直し時期(2027-05)の到来
- IEEE 1028・ISO/IEC/IEEE 29119 の本文を読んで、注入する者の独立が要件だった場合(決定1・3 を再審議する)
- ルールセットを使えない採用者の件数の観測
