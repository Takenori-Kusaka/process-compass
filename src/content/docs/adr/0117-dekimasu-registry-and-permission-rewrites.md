## コンテキスト

第1章 1.7.1 は、文末の「〜できます」を許容の意味で使わず、可能性と能力の記述に限ると定めています。1.7.4 は、許容か能力かを機械は判定せず、人が読んで確かめると定めていました。ADR-0063 で許容の意味の 10 件を書き直しましたが、全件の一覧は残っていません。その後の改訂で文が増えました。

#366 は、本文8章と規定の附属書の文末の肯定の「できます/できる」を機械で抽出し、75 件を得ました。文脈を分けた2つの AI の読み手が、前後1文で振り分けました。一致は 75 件のうち 75 件でした。許容と、両方に読めるとした 22 件は、AI の裁定役が頁の文脈で確かめ、1件の区分を変えました。結果は、許容 15 件(行為・選択の許容 11、主張の成立 3、外部の規格の適用の条件 1)、能力・可能性 26 件、判定基準と条件の項目 31 件、「生じる」の意味 2 件、命題 1 件です。

許容の 15 件は、1.7.1 にすでに反していました。人が読むという定めだけでは、回帰を止められていませんでした。

審議は軽で開きました(起案・反対の2委員)。本 ADR は、2委員の結論が重なる範囲を決めます。記録は `research/366-deliberation/` にあります。

## 決定

### 1. 許容の 15 件と「生じる」の2件を、1件ずつ改める

型どおりに機械で置き換えません。型を当てると、意味か強さの変わる件があるためです。各件の段落を読み、意味と強さを保つ文にしました。

| 件 | 所在 | 改めた形 |
| --- | --- | --- |
| K-014 | 第3章 3.6 | 「委譲してよい」。隣の箇条の許容の形とそろえた |
| K-018 | 第4章 G-1 | 「層1 の記名の有無を、G-1 の前提条件と判定基準に含めない」。許容の形「判定してよい」は、層1 の欠けを理由にした差し戻しを妨げず、元の文意より弱いため |
| K-019・K-020・K-022・K-023 | 第4章 G-2・G-3・G-4 | 「判定記録の媒体にしてよいものとします」。同じ文の3度の出現と、同じ段落の K-020 を同じ形にそろえた |
| K-021 | 第4章 G-2 基準3 | 許容を「引き受けない行を示す」ことに限った。差し戻しは、後の文の要求(「基準3 で差し戻します」)が担う。同じ行為に許容と要求が並ぶ形を解いた |
| K-049 | 第7章 7.3 | 「裏づけにしてよい」 |
| K-054 | 第8章 | 許容ではなく、登録の前提を満たすかの命題であった。「登録の前提を満たす体制です」の形にした。後の文「逆は成り立ちません」とつながる形である |
| K-058 | 第8章 軸E | 正本の表(本章「再実行の時点と向き」の、未達のまま出荷する対象の表)を引く形にした。元の文は R1 の変更の例外承認(第7章 7.3)に触れず、正本の表より広い2つ目の許容になっていた。正本の表を正とした |
| K-060 | 附属書F | 外部の制約の形「ISO 13849-1 では、…適用するとされています」。本標準の許可ではなく、規格の内容である |
| K-073 と第7章 7.11 要求事項1 | 附属書H・第7章 | 「申し立ててよい」。7.11 の「申し立てられる」は表に無い形で、第1章 1.7.1 に反していた。附属書H の再掲は、保留の扱いを「7.11 の要求事項2 によります」と引き、再掲の側に要求を足さない |
| K-012・K-015 | 第3章 | 「経路が生じる/生じます」。能力でも可能性でもない「出来る」の意味であった。規則データ(`src/data/processes/integrated.yaml`)の同じ文も改めた |

### 2. 主張の成立の3件を、1.9 と同じ限定の形にする

G-7「保証の主張の成立判定」(正本)と附属書H の再掲2か所を、「組織が…『品質を保証する』と主張するのは、…場合に限ります」の形にしました。第1章 1.9 が既に使う形であり、要求事項として読まれ、新しい要求を足しません。附属書H H.1 の文は条件ではなく主張の中身を述べる文であり、「次の意味の主張に限ります」の形にしました。

### 3. 全件を区分つきで登録簿に置き、新しい出現を検査で止める

残る 58 件を `src/data/dekimasu-registry.yaml` に、区分(能力・可能性、判定基準と条件の項目、その他)と区分の根拠つきで置きます。`npm run check` は、本文と規定の附属書の文末の「できます/できる」の文が登録簿に無いとき、および登録した文が本文から消えたときに失敗します(`scripts/check-dekimasu.mjs`)。区分に許容は置けません。

機械は、許容か能力かを判定しません。確かめるのは、区分を付けて登録された文かどうかです。区分の当否は、登録の差分を人が読んで確かめます。第1章 1.7.4 を、この検査の所在に合わせて改めました。

### 4. 一致率と、文脈で変わった件を対にして開示する

2つの読み手の一致 75/75 と、文脈の確認で 22 件のうち1件が変わったことを、EV-0172 の観測に対で記録しました。一致率だけを足すと、AI の読み手の一致率を書き換えの起点にする手順の判断を誤らせるためです。登録の区分の根拠の水準は EV-0234(第1章 1.7.4)で開示します。75 件のどれも人が読んでおらず、53 件は文脈でも確かめていません。読み手の作業の記録は空で、2つの読み手が互いの出力を読んでいないことは、指示と出力の違いからしか裏づけていません。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 調査の書き換えの型を、機械で一律に当てる | K-018・K-021・K-054・K-073 で意味か強さが変わる |
| 主張の成立を許容の形(「主張してよいものとします」)で書く | 主張の成立を「してよい」と読ませ、本標準が主張を認可すると読まれる。保証の主張は組織の主張である(ADR-0057) |
| 主張の成立を「主張が成り立ちます」の形で書く | 平叙の動詞文であり、1.7.2 では要求として読まれるが、何を求めるかが文から決まらない |
| G-7 の文に「満たさない変更について主張してはなりません」を足す(K-026 の文案) | 新しい禁止であり、裁定の範囲の外である。満たさない場合の扱いは 1.9 が既に定めている |
| 能力・可能性と条件の項目の 59 件を、JIS Z 8301 の形(文末に「できる」を使わない)へ寄せる | 1.7.1 の表を変え、ADR-0086 決定2 を置き換えることになり、重へ上げる要がある。JIS の向きは転載でしか確かめておらず(EV-0096)、原典で確かめた ISO/IEC 専門業務用指針 第2部 箇条7 は能力・可能性に can を使う |
| 主語(人・組織)と述語(行為の動詞)で許容らしい「できます」を警告する検査 | 許容の 11 件の多くは主語を書かず、取りこぼす。能力の記述も拾い、誤検出が多い |
| 「〜られる」の可能形を機械の抽出へ広げる | 受け身・尊敬・自発と同じ形で、誤検出が多い。7.11 要求事項1 と K-073 だけを本件で改めた |
| 7.11 要求事項1 を要求の形(「組織は申し立てを受け付ける」)へ改める | 採用者への新しい義務で、重へ上げる要がある |
| 命題の K-027(G-7 の表「署名が意味しないこと」の列)を改める | 表の列の見出しが命題であることを示し、誤読のおそれが小さい。登録簿に区分「その他」で置いた |

どれも、決めていない事項ではなく、本件で課さない・行わないと決めた事項です。JIS の形へ寄せる案と 7.11 を要求の形へ改める案は、重の審議(外部の調査と5委員の会議体。JIS の原本の照合を含む)を経れば採りうる案です。
