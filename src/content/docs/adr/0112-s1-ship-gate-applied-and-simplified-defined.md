## コンテキスト

第8章 軸B の表は、CL0 の S1 の出荷判定(G-7)を「簡略(CL1 以上は適用)」としていました。この「簡略」は、2026-07-15 の初版の表からあり、中身を定義されたことがありません。升の括弧は CL1 以上の取り消しを書くだけで、減らすものを書いていません。本文に中身の段落も無く、規則データも `simplify` の札だけを持っていました。ADR-0088 は、同じ理由(「簡略」は本文に中身が無く、定義の無い語で出荷判定を緩めることになる)で CL1 以上から簡略を外し、CL0 を決めていない事項として残しました。

内部調査と実行による確認で、次のことが分かりました(`research/374-deliberation/`)。

- G-7 の判定基準を CL0・S1 で見ると、基準7 は CL0 で既に適用外、基準6 はもともと合否に使わない。基準2(トリアージの S1 の行)と基準3(負債台帳の S1 の運用)は、ステージによる緩和を基準の中に既に持つ。基準5・9 は、S0 の省略の前提3、G-8、保証の主張の成立条件4 の前提である。実質の省略の候補は、基準4 の一部だけだった
- 準拠テンプレートは、集約・成立条件4・スキル・様式のどこでも `simplified` を `required` と同じに判定する。違いは、保証の開示の項目2 に「簡略化」と出る表示と、変化点の順位だけだった。外へは簡略と宣言し、中身は適用として判定していた。実行で比べると、`g7` の状態だけを変えた2つの構成で、集約の欠落と成立判定は同じだった
- エンジンを実行すると、簡略が残るのは CL0 × S1 × 品質「標準」だけだった。品質「高」・規制業の S1 は、軸C の強化が軸B の簡略に勝つ。第8章の升は、この上書きを書いていなかった。S0 の G-6・G-7 の升も、品質「高」以上で適用へ戻ることを書いていなかった
- S0 の品質「高」以上では、G-7 が軸C の `strengthen` の上書きで適用に戻る一方、省略が無効化した判定者の方式(`approverMode`)が戻っていなかった。エンジンの全升の試験(IMPL-0345)は品質「標準」だけを走査しており、記載(「全升」)と実態が食い違っていた
- 外部にも、定義の無い「簡略」でゲートを緩める例は見当たらなかった。ISO 9001 8.6 は、どの規模でも、受入基準への適合の証拠とリリースを許可した人の追跡可能性を記録に求める。G-7 そのものである(英露対訳版で確かめた。正本ではない)

会議体(起案・現場・品質監査・規格・弁護の5委員)の審議の記録は `research/374-deliberation/` にあります。5委員とも、中身の無い「簡略」は守れないと認めました。弁護の委員を含みます。

## 決定

### 1. CL0 × S1 の G-7 を「適用」とし、S1 の軽さの所在を本文に書く

- 第8章 軸B の表の S1 の G-7 を「適用」とする。規則 `r-b-mvp` から `g-ship` の `simplify` を外す
- S1 の軽さは、ゲートの状態ではなく判定基準と範囲の中にある。所在を第8章と第4章 G-7 に書く: 基準2 が照らすトリアージマトリクスの S1 の行、基準3 が問う負債台帳の S1 の運用(記録+返却目安)、独立レビュー(G-6)の範囲(コア機能)。どのステージでも G-7 が記録と基準の突合に限ることも軽さの一部である
- S1 であることを理由に G-7 の判定基準を外さない。S1 の G-7 を簡略にしないことは、決めた事項である
- 保証の開示の項目2 に、S1 で実際に緩めている G-6 の範囲の限定を載せる。項目2 は状態を変えたゲートだけを載せており、実際に緩めた G-6 の範囲を宣言していなかった
- 「S1 の緩和は基準の中で足り、G-7 を適用しても S1 の小さいチームの負担が過大にならない」は実証が無い。暫定マーク EV-0230(見直し 2027-05)で開示する

### 2. 軸の間の優先を1か所に置き、升に上書きの条件を書き、升とエンジンの出力を突き合わせる

- 第8章 軸B の表の直下に「軸の間の優先」を置く。軸C(品質要求)・軸E(安全重要度)の強化は、軸B の緩和(省略・簡略・統合・範囲の限定)に優先する。最終の状態は、導出(テーラリングエンジン)の出力を正とする
- 緩める升には、他の軸が緩和を取り消す条件を括弧で書く。S0 の G-6・G-7 に「CL1 以上・品質『高』以上は適用」を書く
- 升の表記とエンジンの出力を突き合わせる検査(`scripts/check-stage-table.mjs`、`npm run check` に含む)を足す。実装マーク IMPL-0447
- エンジンの全升の試験(IMPL-0345)を、品質の3種(標準・高・規制業)へ広げる
- 規則 `r-c-high`・`r-c-regulated` に、`g-ship` の `restore` を明示する。S0 の品質「高」以上の G-7 の適用を、`strengthen` の上書きの副作用ではなく、この規則の決定にする。省略が無効化した判定者の方式は戻る。試験で固定する

### 3. 「簡略」の語を残し、第1章 1.7.3 に定義を置く

- 工程ゲートの状態の「簡略」は、適用の一種である。判定基準を外さず、判定の対象となる成果物の形・分量を、升の括弧と本文で示した限定の範囲で減らすことをいう
- 中身(括弧の限定と本文)の無い「簡略」を置かない。括弧が無い「簡略」と、括弧の中が他の軸の取り消しの条件だけの「簡略」を、規定の表現形式の検査(`npm run lint:provisions`)と決定2 の検査で止める。機械が確かめるのは限定の有無までであり、限定が減らすものを正しく書いているかは、条項の起草と査読で確かめる
- G-1 の S0 の「簡略(1枚企画書)」は、この定義に合う。括弧に減らすもの(1枚企画書)があり、第8章の段落が「記述の分量を減らす調整であり、前節の宣言を外すものではない」と境界を書く

### 4. 記録・開示・試験

- エンジンの試験の CL0・S1 の G-7 の期待を `standard` に直す。CL1・S1 の簡略を検出していた否定の対は消さない。S1 の簡略を規則へ戻した知識ベースで、全升の試験が CL0・S1 の簡略を検出し、`r-e-cl1` の `restore` と軸C の強化が CL1 以上・品質「高」以上の S1 の簡略を取り消すことを確かめる対に置き換える
- 旧い構成(簡略で記録された S1 の G-7)は、厳しくする向きの変更として扱う。準拠テンプレートは、未適用の厳格化として保証の開示に表示する。CL0 では欠落として数えない(blocking でない)。判定の中身が同じため、出荷を止めて得る信頼性が無い
- IMPL-0345 の注記を直す(S1 の G-7 の簡略を外し、品質の走査と軸C の restore を足す)
- 集約が G-6 の範囲 `core-only` を読まないらしいという副次の所見と、S0 の前提3 と S1 の G-6 の範囲の食い違いの疑いを、実装で実行して確かめた。どちらも食い違いがあった(下記「影響」)。本 ADR では直さず、後継の Issue へ送る

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| (a) 基準ごとに簡略の中身を定義する | 省けるのは基準4 の一部だけで、実質が無い。基準6・7 を中身に数えると、何も緩めない調整を緩めたと宣言することになる |
| (c) 省略へ寄せる | ISO 9001 8.6 の最小の記録、S0 の省略の前提2・3(ADR-0065)、ADR-0088 の理由、保証の主張の成立条件4 を崩す |
| (d) 簡略の条件を変更ごとのリスク区分(R)へ寄せる | G-7 は出荷(複数の変更の束)の判定で、R は変更ごとに決まる(ADR-0039)。出荷の判定の最小の記録は、束に含まれる変更の R に依らず要る。R ごとの軽さは G-5・G-6 の側に既にある |
| 暫定で「簡略」を残す | 宣言と判定の食い違いが続く |
| 「簡略」の語の廃止 | G-1 の S0 の簡略は中身を持つ |
| 「簡略」を禁止事項へ足す | 定義と検査で足りる |

どれも、決めていない事項ではなく、課さないと決めた事項です。

## 影響

- 第8章 軸B: S1 の G-7 の升、S0 の G-6・G-7 の括弧、軸の間の優先、S1 の軽さの所在の段落、EV-0230、IMPL-0447、IMPL-0345 の注記
- 第1章 1.7.3・1.7.4: 「簡略」の定義、中身の無い「簡略」を置かないこと、検査の列挙
- 第4章 G-7: 判定基準を事業ステージで外さないことと S1 の軽さの所在。保証の開示の項目2 に範囲を限ったゲートと未適用の厳格化を載せること
- 道具の頁(知識ベースのスキーマ・提案ロジック): restore の例から「MVP の簡略化」を外した
- 規則データ: `r-b-mvp` の `g-ship` の `simplify` を外した。`r-c-high`・`r-c-regulated` に `g-ship` の `restore` を足した。`r-e-cl1` の注記から S1 の簡略を外した
- 検査: `scripts/check-stage-table.mjs`(新設)、`scripts/check-provisions.mjs` の検査3、エンジンの試験
- 準拠テンプレート: 知識ベースの複製、保証の開示の項目2 の表示(G-6 の範囲の限定、旧い構成の G-7 の未適用の厳格化)、試験 `test-tailoring-declaration.mjs`・`test-roster-rules.mjs`。集約の出力は、項目2 の表示と、旧い構成に限り項目1 の未適用の厳格化の1行(blocking でない)のほかは変わらないことを、実行して確かめた
- 実行で確かめた食い違い(後継の Issue へ送る。本 ADR では直さない)
  - 準拠テンプレートの集約は G-6 の適用を状態だけで決め、範囲 `core-only` を読まない。S1 でコア機能でない変更の独立した確認の欠如も、記録の欠落に数える。実装は本文(S1 の G-6 はコア機能)より厳しく、決定1 が挙げる S1 の軽さのうち G-6 の範囲は、集約に降りていない
  - S0 の省略の前提3 は、S0 の期間に独立した確認を経なかった変更を、S1 以降の出荷で欠落として扱い、コア機能に限らない。S1 の G-6 はコア機能に限る。S0 の期間と S1 の期間のコア機能でない変更で、本文の扱いが分かれる
