## ステータス

採用(2026-10-23)。採用済みの ADR の決定を置き換えません。[ADR-0041](/process-compass/adr/0041-scope-is-not-exhaustive/)・[ADR-0048](/process-compass/adr/0048-gate-criteria-source-of-truth/)・[ADR-0057](/process-compass/adr/0057-organizational-quality-assurance/)・[ADR-0061](/process-compass/adr/0061-check-means-on-implementation-marks/)・[ADR-0064](/process-compass/adr/0064-skill-provisions-trace-to-standard/)の決定と突き合わせ、いずれも延長であって矛盾しないことを確かめました(後掲「既存の決定との関係」)。[ADR-0075](/process-compass/adr/0075-acceptance-criteria-coverage-premises-and-ai-findings/) 決定9 の事実の誤りを、同 ADR の本文で直しました(未公開の新 ADR のため)。

## コンテキスト

[#292](https://github.com/Takenori-Kusaka/process-compass/issues/292) は、実装マークを足すべき条項を特定する手続を求めました。[実装マークの規約](/process-compass/community/implementation-marking/)は、マークを付けた規定についてだけ降ろし先を追跡します。付け忘れた規定は台帳に現れず、規約の「限界」は「網羅性を機械的に確かめる手段は現時点でありません」と書くだけでした。

指摘をそのまま条項にせず、調査3本と会議体5名の意見書で扱いました。記録は `research/292-deliberation/`(`decision.md` の I-1〜I-14)にあります。

### 付け忘れが実際に見つかった

調査の範囲(第5章 5.6〜5.8、第3章 3.10・3.11、フェーズ5 の3頁)だけで、マークの無い規範が多数見つかりました。

- 第5章 5.6.2 の欠陥注入の規定は、1つのマーク(IMPL-0047)が別の頁から残存の確認だけを指していた。周知・隔離・除去型の禁止・継続の測定に、マークが無かった
- 第3章 3.11.4 要求事項6(読み込みの記録)は、節に別のマーク(IMPL-0130)があったため、節の単位では漏れが見えなかった
- IMPL-0095 は第6章のコードブロックの中にあり、検査が読まず、台帳から漏れていた。読者には文字列のまま表示されていた
- 準拠テンプレートの `implement` スキルは、テスト生成と実装を同じ文脈で行っていた。第5章 5.8.4 の見出しの禁止に文面どおり当たるのに、スキルは「テンプレート独自。厳しい側」と書いていた
- 事前レビュー期間の自動化の頁は、準拠テンプレートに検査と集計がある前提で書かれていた。実際にはどれも無かった

### 台帳の件数が、網羅の主張として読まれ得た

台帳は降りていない規定の件数を冒頭に出します。0件になると、`check-impl.mjs` は節ごと消していました。件数の少なさを、規定が降りたことの根拠として読める形でした。

## 決定

### 1. 母集団は、対象の頁の節と、番号つきの要求事項の表の行とする

対象は、本文8章・規定の附属書・フェーズ5・6 の各頁です。節は見出しと次の見出しまでの本文で、本文の無い見出しは数えません。番号つきの要求事項・禁止事項の表の行も単位にします。参考の附属書・ADR・community の頁は対象外です。

文末の表現で規範の文を機械で列挙することは、棚卸しの補助に限り、合否に使いません。第1章 1.7.1 は文末の強さに差を置かず、1.7.2 は迷う文を要求として読みます。文末で作る母集団は閉じません(標本の適合率 約 0.73)。外部の網羅の検査(適用宣言書・適合性の試験)は、識別子を先に振った閉じた集合を対象にします。本標準でそれに当たるのは節の見出しです。

フェーズ5・6 を含めます。名指しの頁(事前レビュー期間の自動化・欠陥注入の隔離設計)がフェーズ5 にあり、外すと手続の外に出るためです。第1章 1.8 の「フェーズ5・6 は本文に従属する」は、マークの要否とは別の問いです。

### 2. 区分を4つにし、判定者・人の席の規定も対象にする

区分は、マーク済み(節が持つ識別子を列挙)・判定基準の表(知識ベースへ降りる)・対象にしない(閉じた区分と理由)・未棚卸しです。対象にしない理由の区分は、説明・制度設計・所在は他節・課さないの4つで、所在は他節には所在の節を必須とします。

マーク済みの登録は、登録者が「この節の、実行主体の挙動を制約する規定のすべてに、列挙したマークがある」と判断したことの記録です。マークは従来どおり規定ごとに付け、1つのマークで節が済んだと扱いません。

第1章 1.4 は担い手を、人または AI の実行主体と定めます。ゲートの判定者・ロールの席が守るべき手続のうち、様式・スキル・通知へ降ろすものを、規約の「対象にする」に足します。既に判定者の規定にマークが付いており、規約の表が実務と食い違っていました。

### 3. 登録簿を本文の外に置き、消えた鍵と使われない除外を落とす

登録簿は `src/data/impl-inventory.yaml` です。鍵は頁と見出しの経路で、見出しの適用範囲の注記は外します。第6章の重複した見出しは、経路で区別します。

失敗にするのは、登録の無い節、消えた鍵、台帳に無い識別子、登録から漏れた節の中のマーク、対象にしない節の中のマーク、閉じた語彙の外の区分、空の理由です。いずれも決定論で判定でき、偽陽性が出ません。

**本文の指紋(ハッシュ)による登録の無効化は課しません**。文言の調整のたびに発火し、確認が機械的な更新に変わるためです。節の中身が変わって新しい規定が入ったことは、機械が見ない事項として規約の「限界」に書きます。

### 4. 未棚卸しは基準線から減る向きにだけ動かす

2026-10-23 時点の全節(943 節)を未棚卸しとして一度だけ登録し、基準線にします。登録の無い節は失敗にします。基準線に無い節を未棚卸しで登録することも失敗にします。見出しを改めた節を未棚卸しで登録し直す経路を塞ぐためです。台帳の冒頭に、未棚卸しの件数を章ごとに出します。

本 Issue で棚卸しした範囲は、第5章 5.6〜5.8、第3章 3.10・3.11、フェーズ5 の事前レビュー期間の自動化・欠陥注入の隔離設計・エージェントの操作の統制です。残りは章ごとの Issue で進めます。根拠水準は EV-0135(E1)で開示します。

### 5. 降りていない規定の件数を、合否にも警戒の条件にも使わない

**降りていない規定の件数を、合否にも警戒の条件にも使いません**。0件を異常の兆候とする規格は見つかりません。正当な0件と区別できず、件数を目標にすると、規定をマークしないまま残す誘因になります。網羅の側は、未棚卸しの件数で示します。

0件でも、台帳に「降りていない規定」の節と件数の行を出します。検査そのものには陽性対照(既知の違反を入れて落ちることの試験。`scripts/test-check-impl.mjs`)を置きます。根拠水準は EV-0136(E0)で開示します。

### 6. 限界を、機械が確かめることと確かめないことに分けて書く

規約の「限界」を書き直します。機械が確かめること(節の登録の有無、鍵の実在、識別子の実在、除外とマークの併存、降ろし先の実在)と、確かめないこと(節の中の網羅、区分の判断の正しさ、登録の後の節の中身の変更、対象の頁の外の規範)を並べます。

「台帳の件数は網羅の証明ではない。降りていない規定0件・未棚卸し0件のどちらも、規定がすべて降りたことを示さない」を、規約と台帳の定型文に置きます。[ADR-0041](/process-compass/adr/0041-scope-is-not-exhaustive/) 決定1(列挙は網羅でないことを明記する)を、本標準自身の台帳に当てたものです。

### 7. 参考の附属書にマークを置かない

参考の附属書にはマークを置かないことを、規約の「対象にしない」に書きます。対応する規範には、本文の所在で付けます。検査(`check-provisions`)は既に参考の附属書のマークを落としていましたが、規約に書かれていませんでした。附属書E E.5 の受入基準の数え上げは、G-7 基準1・G-4 基準6 のマークで追跡されます。

### 8. 降ろし先に「予定」の種別を置き、コードブロックの中のマークを落とす

降ろし先の登録簿に `planned` の種別を足します。存在を確かめず、`state=undelivered` のマークだけが使えます。これが無いと、降りていない規定のマークも実在するファイルを指すしかありませんでした(IMPL-0047 の食い違いの原因)。

コードブロックの中のマークは、検査で失敗にします。規約の書式の見本だけを除きます。

### 9. 名指しの条項を直してから付ける

- 第5章 5.6.2 は規定ごとに分けて付ける。IMPL-0047 は番号と意味(残存の確認)を保ち、欠陥注入の隔離設計の第3層の位置へ移す。附属書I の様式が番号で引いているためである。第4層は新しい番号にする
- 第5章 5.8.1 は対象にしない(所在は他節)。5.8.2 は3項目それぞれに付ける。準拠テンプレートの `commit.md` がモデルの版を「テンプレート独自」としていたのは、本標準の要求を弱める([ADR-0064](/process-compass/adr/0064-skill-provisions-trace-to-standard/) 決定1)。誤りはテンプレートで、直した
- 第5章 5.8.4 は、準拠テンプレートの `implement` スキルを、受入基準だけを渡した別の文脈でテストを生成する形へ直してから付ける。本文に「中以上の段階は、弱の文脈の分離を含む」を足す(要求は変えない)。構成の兼務禁止表(`separations`)に段階を持たせることは課さない
- 第3章 3.11.4 要求事項6 は、降りていない・人が確かめるで付ける。記録の単位を「ファイル」に揃え、常駐の指示ファイルの読み込みの実績を、外す候補の根拠にしないと書く
- 事前レビュー期間の自動化の頁は、準拠テンプレートに検査と集計がある前提を直す。機械は意見の様式の欄の空欄を示すだけにし、意見として扱わないかは起案者が応答に記録して、判定者が確かめる。規範には降りていない(降ろし先は予定)で付ける

### 10. ADR-0075 の事実の誤りを直す

[ADR-0075](/process-compass/adr/0075-acceptance-criteria-coverage-premises-and-ai-findings/) 決定9 は、準拠テンプレートの集計が AI の出力を除いていないと読める書き方でした。テンプレートには `pre-review-closed`・`lint-comments.mjs`・応答率の集計のいずれもありません。ADR-0075 は未公開の新 ADR のため、本文を直しました。採用済み ADR の書き換えには当たりません。

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 強い文末の文だけを母集団にする | 第1章 1.7.1 は文末の強さに差を置かない。迷う文を要求として読む 1.7.2 と当たる |
| 文の単位で、除外の無い網羅を求める | 除外が千件規模になり、理由が書き埋められる印に堕ちる。G-5 の3条件の「実効的な偽陽性が無い」を満たさない |

| 本文の指紋で登録を無効にする(少数意見: 起草) | 文言の調整のたびに発火し、確認が機械的な更新に変わる。限界として開示する |
| 本 Issue で全節を棚卸しする(少数意見: 起草・規格) | 900 節超を一度に分類すると、分類の一致率が測られないまま確定する。範囲を限り、残りに章ごとの Issue を起票する |
| フェーズ5・6 を母集団から外す(少数意見: 規格) | 名指しの頁がフェーズ5 にあり、手続の外に出る |
| 降りていない規定0件を警戒の条件にする | 0件を赤旗とする規格が見つからない。正当な0件と区別できず、降ろさずに残す誘因になる |
| IMPL-0047 を廃番にする | 番号を引く採用者の記録が残る。意味を保って位置を移すほうが、記録が別物を指さない |
| 降りていない規定のマークに、実在する別のファイルを指させる | 規定と関係の無いファイルが降ろし先として台帳に載る。`planned` で、まだ無いことを示す |

## 影響

- 規約に「対象の棚卸し」が加わり、「限界」が改まる。「対象にする」に判定者・席の手続、「対象にしない」に参考の附属書が加わる。降ろし先の種別に `planned` が加わる
- 台帳の冒頭に、棚卸しの状況(章ごとの未棚卸しの件数)と、件数を網羅の証明として読まない定型文が加わる。降りていない規定の節は0件でも出る
- `npm run check` に `npm run test:impl`(検査の陽性対照)が加わる。`check-impl.mjs` は、登録の無い節・消えた鍵・コードブロックの中のマークで失敗する
- 見出しを改める・節を足す執筆者は、登録簿に区分を書く作業が1つ増える。未棚卸しで逃がす経路は無い
- 第5章 5.6.2・5.8.2〜5.8.5、第3章 3.10・3.11、フェーズ5 の3頁にマークが加わる(IMPL-0159〜IMPL-0230)。多くは降りていない規定として台帳に出る
- 準拠テンプレート: `implement` スキルがテストを別の文脈で生成する。`commit.md` がモデルの版を本標準の要求として書く
- 棚卸しの残り(未棚卸しの節)は、章ごとの Issue で進める。それまで台帳の未棚卸しの件数は大きいままである
