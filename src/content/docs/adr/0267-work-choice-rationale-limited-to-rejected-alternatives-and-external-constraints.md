## コンテキスト

- [#457](https://github.com/Takenori-Kusaka/process-compass/issues/457): 第三者の意見。5.5.1 は作業上の選択を記録させるが、理由を求めない。準拠テンプレートの PR 様式だけが「何を・なぜ」を求めていた。決裁者の問い「後から誰が説明できるか」に、通常の変更で答えられない
- 破られ方: 全選択に理由を求めると定型文で埋まり、確定の場の人の確認が読まない承認へ縮退する。失うのは確定の場の人である
- 外部の調査(2026-11-27): 変更の単位で設計の理由を求める規格・法令は、調べた範囲に見つからなかった。EU AI Act 附属書IV 2(b) の理由と ISO/IEC/IEEE 42010 の rationale は、システムの単位・アーキテクチャ上重要な判断の単位で、本標準では 2.6 が担う。PR の説明文の書き方は LLM のレビューの判定を左右する(FND-0147)。AI が書く理由は、実際の生成の原因と一致しないことがある(SRC-0769。要旨のみ)
- **本決定は採用者への新しい義務であり、規格の上乗せである**。「既存の義務の明確化」ではない。規格が求めることを根拠にしない。42001 の A.6.2.7・A.6.2.8、12207 の記録要求、IEEE 1016 は本文を読んでいない

## 決定

1. 5.5.1 の作業上の選択のうち、退けた案がある選択と外部の制約に従った選択で、理由を記録する。外部の制約は、受入基準・既存の規約・依存の制約・実行環境・既存の公開インタフェースなど、変更の外で決まっている条件とする。どちらにも当たらない選択は、選んだ内容だけを記録する(理由の無い選択は、書き手が、比べた案と従った制約のどちらも無いと記録した選択と読む)
2. 理由は、依った受入基準の項目・規約・制約の所在か、退けた案とそれを退けた理由で示す。所在を示せない理由には、推測である旨を添える
3. 理由は作成側の主張であり、検証と G-6 の判定の根拠に数えない。読む順序は、第3章 3.5.4 の入力の分離による。5.5.1 へ入力の分離の規則を写さず、参照に止める
4. 確定の後に理由を改めるときは、確定の時点の記録を書き換えず、改めた内容と改めた理由を追記する。改ざんの防止は機械で閉じず、manual で受ける
5. 設計上の選択は、2.6 の判断記録による。ステージ表 S2「全件必須」は 2.6 の範囲で、本決定はこれに代わらない。判断記録が作業上の選択の理由の記録を兼ねてもよい
6. 本標準は、開発の道具として使う AI との会話・推論の経緯の保存を課さない。実行の記録の保持は採用者に委ねる(IMPL-0512)。採用者が自らの製品に組み込む AI の記録の義務(EU AI Act 第12条など)は免除しない
7. 機械の検査は、常駐の行の語の存在だけに限る(束 D1 で降ろす。IMPL-1050)。理由の有無と質は manual で閉じ、暫定 E0(EV-0358)で開示する。本標準の側のマークは、準拠テンプレートへ降りるまで `state=undelivered`(IMPL-1050〜1052)で表示する

## 採らないと決めたこと

| 案 | 採らなかった理由 |
| --- | --- |
| 現状維持と投影だけ(案A) | 決裁者の問いに通常の変更で答えられない欠けが残る |
| G-6 基準2 に理由を足す(案C)、G-6 基準3 を全変更へ広げる(案D) | 基準2(レビュアの言葉)・基準3(コアまたは規則に当たる変更)の範囲を守る。判定側の負担を全変更へ広げる |
| 会話の全文の保存を義務にする(案E) | 会話は理由の記録ではない。秘密・個人情報を含みうる。5.8.2 が指示の全文を求めない判断と矛盾する |
| 全ての作業上の選択に理由を求める | 読む側の量が増え、重要な選択が埋もれる(ADR-0072)。定型文で埋まる |
| 「差分から読み取れない選択」を範囲の基準にする(条文・手引きとも) | 「読み取れる」は書き手の主観で、AI は自分の選択を自明とみなしやすい。確認する側も決定できない |
| 「判定の入力にしない」と書く | PR の本文は同じ画面に出るので、読むこと自体は止められない。止められない統制を書くと、表示と実態が食い違う |
| 7.3 の例外承認で受ける、理由を書けなかったときは 7.3 と書く | 全変更に常態で掛かる記録を受けると台帳が例外で埋まり、G-7 の突合が働かなくなる |
| 理由の文字数・項目数の下限、理由の質の機械判定・AI 採点 | 量は質の代わりにならない(ADR-0072)。自由な文の意味は機械で閉じない |
| PR の節の存在の機械検査 | 記録先をコミットのメッセージでもよいとする条文より狭くなる |
| 確定時点の PR 本文の写しの必須化、抜き取りで理由を確認した記録の新設 | 理由は判定の根拠に数えず、判定の記録の保管と同じ重さを課す理由が弱い。新しい機構・様式を足すほどの欠けは確かめていない |
| 記録先をコミットのメッセージに限る、書く時点の義務化 | 置き場は問わない(G-6 基準6 と同じ書き方)。条文は結果と証跡までで、時点は手順として手引きで勧める |
| 5.5.1 の見出しへ適用を併記する | 見出しは席・責任者・担い手の全体で、併記すると節全体を限る。限定は理由の文と行の中に書く |
| EV の測定を AI 維持管理者の棚卸し(3.11.4)へ割り当てる | 3.11.4 は指示資産の保守で、変更の記録の測定ではない。採用者へ新しい測定の義務を課す |
| 準拠テンプレートの注記を推奨へ戻し、標準を変えない | 決裁者の問いに答えられないまま残る。テンプレートは標準を体現する方針で、乖離は標準の側の欠けとして閉じる |

## 影響

- 担い手(AI を含む)は、退けた案と従った制約を、所在つきで変更の記録へ書く。確定の場の人は、選択と理由をまとめて確認する。この確認は独立の統制ではない。独立は G-6 が担う
- 準拠テンプレートへの降ろしは束 D1 で行う(IMPL-1050〜1052)。降りるまで、実装台帳に「降りていない」と表示し続ける。#457 は束 D1 で降りるまで閉じない
- 附属書H H.3 の投影表「ブラックボックス化(なぜそう作ったか)」の行を、本決定に合わせて改めた
- 限界: AI が退けた案を申告しない過少申告は防げない。理由が実際の原因と違っていても、機械では見つからない
- 範囲の外の発見: review-guide の「(コア機能のみ)」が G-6 基準3 より狭かったため、本束で改めた。ステージ表 S2 と G-6 基準3 の関係の読み方(#457 へコメント)と、段階1 の非コア機能かつ R2 の扱い(#454 へコメント)は、別の Issue で扱う
- 再検討の契機: EV-0358 の差し替え条件(定型文の割合、過少申告の件数)が出たとき
