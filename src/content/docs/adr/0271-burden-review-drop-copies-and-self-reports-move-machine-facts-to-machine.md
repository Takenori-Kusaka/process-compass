## 決定

### 1. 点検の軸

- 書く行為が、判断の帰属の記録そのもの(誰が何を決めたか)なら残す。写しに当たる記録、機械が既に止めている事象の自己申告なら、やめるか機械へ移す
- 「ふだん読まれない」だけでは、やめる理由にしない。事故の後にだけ読まれる記録がある
- 機械の既定値で人の欄を埋めない。確かめた人の不在を、確かめた記録に見せかけるため。機械へ移すのは、機械の事実の写しと起案までで、確定は人に残す
- 「機械が止める」を理由にやめるものは、実行で確かめる。確かめられないものは移さない

### 2. やめる

- 機能仕様の承認表と、frontmatter の `approved_by`・`approved_at`(`status:` は残す)。正本は判定記録と承認レビューで、様式の欄はその写しだった
- 企画書の「承認(G-1)」の写しの欄
- 実装計画の承認(G-4)の表。節の見出しは残し、「承認の記録の所在」の 1 行にする
- PR の自己チェックの項目 1〜3(テスト・外部インタフェース・再発明)と項目 5(閾値・除外設定)。項目 1〜3 の観点は、作成側の手引き(`/implement` の手順)へ移す。項目 5 が防ぐ事象は、`pr-rules` がマージの前に止める(実行で確かめた)
- 第6章「実装作業における順序」の段階3 の記録の義務。段階3 は「方針と生成結果を比べる」とし、記録は求めない。比べた結果、生成結果を採った場合は、作業上の選択の理由(退けた案)として残す(第5章 5.5.1)。IMPL-0819 の note を改める

### 3. 機械へ移す

- PR の「AI 関与範囲」: 人の 2 欄をやめ、正本はコミットのトレーラ(`Co-Authored-By`・`Agent-Run`)とする。標準の PR 運用は、この欄を既に「自動」と定めていた。導出は準拠テンプレートに未実装で、[#464](https://github.com/Takenori-Kusaka/process-compass/issues/464) で降ろす予定とし、実装マーク(IMPL-1061、`plan=scheduled`)で表示する。それまで欄にはトレーラが正本である旨だけを置く
- G-1 の検査(check-d0・check-g1)の出力: 草案を起こす文脈が、実行したコマンドと実行日時を添えて、出力の本文を記録へ貼る。判定は人が行う
- 前提の台帳の立ち上げ時の「観測した事象」「最終観測日」: 出所つきの初期値(起案)を様式に置く。充足状態の確定は人に残す。「未観測」という新しい値は作らない
- 実装計画のタスク状態の「着手」「完了」: `/pit` がブランチとトレーラから導く。導出は、着手前・着手・完了の 3 つで人の記入と一致した(実行で確かめた)。人が書くのは「やり直し」だけにする。流れの観測の「着手」(最初の PR)は別の指標で、変えない
- AI の担い手の数値 ID: スキルがログイン名から引いて示し、人が確かめる(改名・乗っ取りの確認を添える)
- D-0 の「従う本標準の版」: 構成の `standard.edition` から、生成区間へ移す。「層1 の版」は `/process-change` を経ずに変わるので、人が書く行のまま残す

### 4. まとめる

- 席の責任者の入力を、人ごとの席の列挙でも書けるようにする(`/process-change` の `accountable`)。構成・D-0 の席の表・兼務の開示は、展開後の入力から生成する

### 5. 残す

- 段階1(実装の方針を先に書く)と、「段階1 を経ずに段階2 へ進んではならない」は残す(所有者の決定 2026-11-27)。段階1 は、判断を先に確定してから AI の出力を参照する構成で、引きずられる効果を抑える。記録の義務は段階3 だけをやめる。段階1 を手引きへ下ろす案は、根拠の最も厚い統制を勧めへ下げるので採らない

## 影響

- 変更 1 件で人の書く欄は、計画済みの 2 件目以降の変更で約 4 割、新機能の最初の変更で約 2.5 割減る(採らなかった件と縮めた件を引き直す前の近似。EV-0368)。出荷と立ち上げの減りは小さい。当初の案の削減の多くは、二重の数えと、標準が AI の記入を禁じる欄だった
- 人が判断する行為(ゲートの判定、リスク区分の確定、G-6 の挙動要約、出荷の決断)は、1 つも減らしていない
- 採用者への影響: 既存の PR 様式・様式 01/06/07 の承認欄を持つ採用者は、そのまま使える(読む機構が無い)。旧い D-0 は、生成区間の目印が無くても失敗にしない(注意を出す)
- G-6 が省略・未達の構成の PROCESS-PROFILE(「G-6 を経ない変更」の節)と、`/pit` の出荷判定者の役割カードの注記へ、「G-6 を経ない変更には、独立した人の確認が無いことになる。PR の自己チェックは、確かめた証拠に数えない」を足した。新しい義務ではなく、既にある注記の補い
- 限界: 所要時間と採用者の実績は測っていない。「読まれない」「形骸化する」は、読む機構の有無と様式の形から導いた。M-5 の「不明」(トレーラ無しの取り込みの検出)は、実装できた範囲が一部(状態の列が「完了」で、トレーラ付きのコミットが無いタスクだけ)。様式は人に「完了」を書かせないので、トレーラ無しで取り込んだタスクは、表に「完了」と書かない限り `/pit` に未取り込みと見える。`/pit` は機能ごとに、実装中のタスクと未取り込みのタスクの数を出し、タスクごとの状態は出さない
- 残るリスク: `/pit` の「実装中」はブランチの有無で決まり、標準の「着手」(Draft PR の作成)とずれることがある。標準の本文は「導いてよい。ただし着手の定義は前項による」の形にとどめ、着手の定義の整理は本件で行わない
- 標準の本文の食い違いを 2 か所直した(実装計画の状態の導出、D-0 の版の欄の生成区間)
