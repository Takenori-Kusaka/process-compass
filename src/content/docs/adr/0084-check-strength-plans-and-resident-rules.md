## ステータス

採用(2026-10-24)。採用済みの ADR の決定を置き換えません。[ADR-0061](/process-compass/adr/0061-check-means-on-implementation-marks/)の決定2(未分類を落とさない)と決定3(既存のマークを棚卸ししない)を補います。棚卸しを終えたので、以後 `check` を欠くマークを検査で落とします。ADR-0061 の決定1(`state` を2値に保ち、`check` を独立に書く)は維持します。[ADR-0064](/process-compass/adr/0064-skill-provisions-trace-to-standard/)の検査の範囲を、依頼の形の文末と準拠テンプレートの `CLAUDE.md` へ広げます。[ADR-0068](/process-compass/adr/0068-start-of-application-and-conformance-claim/)の「影響」にある常駐の規則の節の確認を、規則の単位へ改めます。

## コンテキスト

[#314](https://github.com/Takenori-Kusaka/process-compass/issues/314) は、#302〜#310 の審議の積み残しとして、実装マークの検査の手段と、降りていない規定の扱いを問いました。指摘をそのまま条項にせず、調査(内部1本・外部1本)、会議体(起草・現場・品質保証と監査・規格・擁護の5つの立場)、突合の順で扱いました。記録は `research/314-deliberation/`(`survey-314-1-internal.md`、`survey-314-2-external.md`、`council-01`〜`05`、`decision.md` の R-1〜R-6、`implementation.md`)にあります。

### 未分類が 100 件残り、`machine` の根拠が書かれていなかった

ADR-0061 は `check` を足し、既存のマークを未分類のまま残しました。#314 の時点で、305 件のうち 100 件が未分類でした。`check=machine` の 54 件のうち 19 件は、注記に試験の名がありませんでした。確かめ直すと、8 件は違反の入力で落ちる試験と適合の入力で通る試験の対を持たず、2 件は欄やキーの有無までしか確かめていませんでした。`check=presence` の中には、規則の行がある節の見出しだけ、手順のファイルの実在だけを確かめるものがありました。

### 常駐の規則は、節の見出ししか確かめていなかった

準拠テンプレートの `check-process-rules` は、`CLAUDE.md` の常駐の規則の節の見出しと本文の有無を確かめていました。節の中の禁止の行を消しても、否定を除いても、検査は通りました。

### G-5 基準6 は、どこにも降りていなかった

第4章 G-5 の基準6(文脈ファイルの形式検査)は、参照切れ 0 件と分量の上限の超過 0 件を求めます。準拠テンプレートに基準6 のジョブはありませんでした。本文の開示は分量の上限だけを未達と書き、参照切れも未達であることを書いていませんでした。

### 降りていない規定に、降ろすかどうかの区別が無かった

`state=undelivered` の 100 件余りは、降ろす予定のものと、採用者が自ら実装する前提のものを区別していませんでした。後者は永久に予定に見え、前者は放置されても分かりませんでした。台帳の定型文は、降ろし先が実在する規定にも「実行層に対応する記述がありません」と書いていました。

### スキルの文の検査は、依頼の形と `CLAUDE.md` を見ていなかった

ADR-0064 の検査は、要求・禁止の文末だけを対象にしていました。スキルには「〜ないでください」の依頼の形の禁止が 20 行ありました。`CLAUDE.md` の生成区間の外は、検査の対象の外でした。

### 外部の型

| 型 | 出典の所在 | 本 ADR での使い方 |
| --- | --- | --- |
| 検証の方法の区分と合否の基準(検査・分析・実演・試験) | `survey-314-2-external.md` F1〜F4 | `check` の3値と、`machine` に試験を名指させること |

## 決定

### 1. 検査の強さを分類し、`machine` に試験を名指させる

- 未分類 100 件をこの Issue で分類した。以後、`check` を欠くマークを検査で落とす。迷ったら弱い値を書く
- `check=machine` は属性 `test` で試験のファイルを名指す。試験は違反の入力で落ちる場面と適合の入力で通る場面の対を持ち、目印 `IMPL-NNNN:ng` と `IMPL-NNNN:ok` を含む。試験は必須の集約から実行される(準拠テンプレートは集約 `gate-g5` が合否に使うジョブの `run:`、本リポジトリは `package.json` の `check`)。`check-impl.mjs` が3つを確かめる。**この確かめは、試験の中身が規定を正しく確かめていることを示さない**
- 規定が入口(コマンド・スキル)についてのものなら、関数を直接呼ぶ試験では足りない。A-11(外部の確認者の記名による緩める向きの決定の拒否)は、変化点の入口を通す試験を足した
- `check=presence` は、規則を運ぶ単位(欄・キー・行・ファイル)の実在の確認に限る。単位を注記に書く。より粗い単位の確認は `manual` とする
- 降ろし先の登録簿の欄 `check`(検査のスクリプトの名)を `checker` へ改める。同じ語が別の意味で使われていた
- 検査の強さの区分に根拠水準のマークを付ける(EV-0163。E1)

### 2. 常駐の規則を、規則ごとに照合する

- 準拠テンプレートの常駐の規則の一覧(`scripts/gate/claude-md-resident.json`)に、規則ごとの識別子・節・核の文言を持たせる。照合は、太字・逆引用符・リンクの記法・HTML コメント・空白の違いを除いて行う。核の文言が同じ節のいずれかの行に含まれれば満たす
- 案件が行の前後へ書き足すこと、節の中で並べ替えること、節と行を足すことは妨げない。表の行では、「止める仕組み」と「例」の列を核に含めない(案件の CI に合わせて書き換えてよい)
- 核の文言を変えることは、標準の規定の書き換えである。照合が落ちるのは真の検出である
- 一覧の作り直し(`--write-resident`)は追加だけ。一覧から規則を除くことは強制層の縮小であり、`state:needs-platform` を経て、一覧の `omit` へ理由つきで移す
- 変異の試験(行の削除、節を1行に置き換える、否定を除く)で照合が落ちることを確かめる
- 常駐の規則の行を降ろし先とするマークの値は `presence`(単位: 行)とする

### 3. G-5 基準6 の開示を直し、参照切れを降ろす

- 第4章 G-5 の基準6 の開示を、参照切れと分量の上限の両方について書き直す
- 準拠テンプレートに、文脈ファイル(`CLAUDE.md`・`AGENTS.md`・`context/`・`.claude/` の Markdown)の相対リンクと取り込み(`@` で始まるパス)の先の実在を確かめる検査を置く。ジョブ `context-format` として、集約 `gate-g5` の `needs` に入れる
- 見出しのアンカーと、逆引用符の中のパスは対象の外とする。降りていない残りとして開示する。基準の縮小ではなく、降ろした範囲の開示である
- 分量の上限は降ろさない。値を支える実証が無い
- IMPL-0269 を参照切れ(IMPL-0269)と分量の上限(IMPL-0312)の2つに分ける

### 4. `state` は2値のまま、降りていない規定に計画を付ける

- 属性 `plan` を足す。`scheduled`(降ろす予定。`issue` と `review` を要する)と `adopter`(準拠テンプレートは実装せず、採用者が自ら実装する。`decision` を要する。規定は課したまま)
- すべての `state=undelivered` に `plan` を付ける
- 「課さない」は `plan` の値にしない。課さないと決めた規定は、条項を改めて棚卸しの `not-imposed` へ移す([ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/))
- `adopter` にできない規定の登録簿(`src/data/impl-no-adopter.yaml`)を置く。第5章 5.8.3・5.4.3 の一律で委譲できない領域、5.5.5 の人が確定する判断、第7章 7.11 の停止の申し立て、Label Mailbox 4.7 の統制の弱化の検出が当たる
- 降ろす順序は、表示の誤り → `adopter` にできない規定 → G-7・G-8・R1 の決定に関わる規定 → その他とする。根拠が無いので EV-0164(E0)を付ける
- 見直しの年月を過ぎた件数を台帳の冒頭に出す。合否には使わない。期日の日数は課さない
- 台帳の降りていない規定の定型文を、降ろし先の種別(予定の置き場か、実在する降ろし先か)で書き分ける。列の見出しの「(予定)」を除く

### 5. スキルの文の検査の範囲を広げ、限界を書く

- 「〜ないでください」の行を要求・禁止の文末へ書き直す。検査の文末にも依頼の形を加える
- 準拠テンプレートの `CLAUDE.md` の生成区間の外を、検査の対象に加える
- 平叙の否定と太字の否定は対象の外とし、件数を検査の出力に出す。語の整理は [#316](https://github.com/Takenori-Kusaka/process-compass/issues/316) で扱う
- この検査は文の所在の追跡であり、AI の担い手がその文に従うことを示さない。EV-0165(E0)を付ける
- 振る舞いの評価(複数回の試行)は CI に課さない

### 6. 附随の修正

- A-11 の入口を通す試験を足す(決定1)
- IMPL-0209 の降ろし先に `/human-verify` のスキルを登録し、マークを降りている状態へ改める。スキルの印を `根拠: IMPL-0209` へ改める
- IMPL-0206・IMPL-0120 の注記を事実に合わせる
- 逆向きの追跡をファイルの単位で採る。準拠テンプレートのゲートのスクリプト・フック・ワークフローの各ファイルは、降ろし先の登録簿にあるか、除外の一覧(`src/data/impl-untraced.yaml`。理由の区分は `library` / `infra`)にある。どちらにも無いファイルを検査で落とす
- 準拠テンプレートのコード・スキル・様式に書かれた IMPL の番号が、標準本文に実在することを確かめる

## 検討した選択肢

### 検査の強さ(R-1)

| 案 | 採らなかった理由 |
| --- | --- |
| 深さの属性(NIST SP 800-53A の depth)を足す | 単位を `presence` の定義で縛り、注記で示せば足りる。属性を増やすと、同じ事実を2か所で書く |
| 降ろし先の登録簿に単位の欄 `unit` を足す | 同上。1つの降ろし先が、欄と行の両方の規則を運ぶことがある |
| 別のセッションで全件を分類し直す | 危険な誤り(根拠なく `machine` と書く)は、機械が試験の目印と結線で止める。`presence` は単位の注記が確かめの手がかりを持つ。分類し直しの手間に見合う誤りの種類が残らない |
| 未分類のまま残し、件数の開示を続ける | 未分類は「降りている」を強く読ませる状態を続ける。棚卸しの材料(試験の対と単位)は揃った |

### 常駐の規則(R-2)

| 案 | 採らなかった理由 |
| --- | --- |
| 節の見出しの照合のままにする(採用者の編集の自由を優先する) | 禁止の行を消しても、否定を除いても通る。規則ごとの照合でも、前後への書き足しと並べ替えは妨げない |
| 行の全文で照合する | 採用者が「止める仕組み」の列や注記を自分の基盤に合わせて書き換えるたびに落ちる。正当な書き換えで一覧の更新が要り、更新が形骸になる |
| 常駐の規則を生成区間へ移す | 案件が書き足せなくなる。生成区間は構成からの導出物である |

### G-5 基準6(R-3)

| 案 | 採らなかった理由 |
| --- | --- |
| 分量の上限の既定値(200 行)を置いて降ろす | 値を支える実証が無い。再評価の登録簿の目安があるだけである |
| 見出しのアンカーも確かめる | 日本語の見出しの slug は描画系ごとに作り方が違い、誤検出が多い。G-5 の原則(実効的な偽陽性が無いこと)に反する |
| 逆引用符の中のパスも確かめる | テンプレートの例は、案件が後で作るファイルを指す。既存の違反を解消できない |
| 基準6 を緩める | 基準を外せるのは第8章の調整だけである。降ろした範囲を開示する |

### 降りていない規定(R-4)

| 案 | 採らなかった理由 |
| --- | --- |
| `state` に3つ目の値を足す | 届いたかどうかと、どう扱うかは直交する。ADR-0061 が3つ目の値を落とした理由と同じ |
| 区別を足さない(運用で扱う) | 採用者が実装する規定は永久に予定に見え、予定の規定は放置されても分からない。運用は忘れられ、データは検査できる([ADR-0052](/process-compass/adr/0052-delivery-is-verified-at-the-destination/)) |
| `plan` に「課さない」の値を置く | 課さないことは条項の決定であり、マークの値で済ませると条項が残ったまま課さないことになる。棚卸しの `not-imposed` へ移す |
| 見直しの期日の日数を課す | 外部の先例(脆弱性の是正、認証の是正計画)は統制の種別ではなくリスクの評価で期日を決める。日数を写す根拠が無い |
| 期日を過ぎた件数で検査を落とす | 暦で CI が落ちる。件数を目標にすると、マークしない誘因が生まれる([ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/)の決定5) |

### スキルの文(R-5)

| 案 | 採らなかった理由 |
| --- | --- |
| 運用の実績を待って範囲を広げる | 範囲の外の禁止が印なしで増える経路は、運用を待っても塞がらない |
| 平叙の否定と太字の否定も対象にする | 説明の文と規則の文を文末で分けられず、誤検出が多い。件数を出し、語の整理(#316)で扱う |
| 振る舞いの評価(複数回の試行)を CI に入れる | 非決定的な結果を合否に使うと、偽陽性で落ちる検査になる |

### 附随(R-6)

| 案 | 採らなかった理由 |
| --- | --- |
| 逆向きの追跡を採らない(規約が手段の不在を開示済み) | 開示だけでは、新しいスクリプトが標準に無い規則を持ち込んでも分からない。ファイルの単位なら閉じた集合を作れる |
| 逆向きの追跡を関数・規則の単位で行う | 機械で閉じた集合を作れず、登録を保守できない |
| IMPL-0042・0043 を、降りた部分(記録の有無)と降りていない部分に分ける | どちらも1つの判定基準(G-7 基準3・4)である。有無の部分だけを `delivered` の別のマークにすると、台帳がその基準を「降りている」側にも数え、強いほうへ読まれる(ADR-0061 のコンテキストと同じ失敗)。定型文の書き分けと注記で、欠けている部分を示す |

## 影響

- `check` を欠くマーク、試験の目印と結線の無い `machine`、単位の無い `presence`、計画の無い `undelivered` を、`npm run check` が落とす
- 準拠テンプレートの集約 `gate-g5` の `needs` に `context-format` が加わる。ブランチ保護の必須の検査は集約を指すため、採用者の設定は変わらない
- 準拠テンプレートの `CLAUDE.md` の常駐の規則の文言を変えると、案件の `check-process-rules` が落ちる。テンプレートの側で規則を足したら、一覧へ追加する
- `scheduled` の Issue のうち、起票できなかった領域は #314 を仮の Issue として名指す。起票の下書きは `research/314-deliberation/followup-issues.md` にある。起票したら番号を改める
- 試験の目印は、試験の中身が規定を正しく確かめていることを示さない。目印の場面が規定の違反と適合に当たるかは、条項を改めるときの突合で確かめる
