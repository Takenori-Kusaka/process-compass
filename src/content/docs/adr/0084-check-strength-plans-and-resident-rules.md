## ステータス

採用(2026-10-24)。[ADR-0061](/process-compass/adr/0061-check-means-on-implementation-marks/)の決定2(`check` を欠くマークを検査で落とさない)と、決定1 の表の「(書いていない) 未分類」の行、`presence` の定義(記録・欄・ファイル・キーの有無まで)を、本 ADR の決定1 で置き換えます。読み方の補足ではなく決定の範囲の変更なので、一部置き換えとして扱います([ADR-0074](/process-compass/adr/0074-no-cap-on-inspection-apparatus/)の決定5 と同じ扱い)。ADR-0061 の決定3(既存のマークを棚卸ししない)は時点の決定であり、棚卸しを終えたことで補います。ADR-0061 の決定1 のうち、`state` を2値に保つことと `check` を独立に書くことは維持します。[ADR-0064](/process-compass/adr/0064-skill-provisions-trace-to-standard/)の検査の範囲を、依頼の形の文末と準拠テンプレートの `CLAUDE.md` へ広げます。[ADR-0068](/process-compass/adr/0068-start-of-application-and-conformance-claim/)の「影響」にある常駐の規則の節の確認を、規則の単位へ改めます。

## コンテキスト

[#314](https://github.com/Takenori-Kusaka/process-compass/issues/314) は、#302〜#310 の審議の積み残しとして、実装マークの検査の手段と、降りていない規定の扱いを問いました。指摘をそのまま条項にせず、調査(内部1本・外部1本)、会議体(起草・現場・品質保証と監査・規格・擁護の5つの立場)、突合の順で扱いました。記録は `research/314-deliberation/`(`survey-314-1-internal.md`、`survey-314-2-external.md`、`council-01`〜`05`、`decision.md` の R-1〜R-6、`implementation.md`)にあります。

### 未分類が 100 件残り、`machine` の根拠が書かれていなかった

ADR-0061 は `check` を足し、既存のマークを未分類のまま残しました。#314 の時点で、305 件のうち 100 件が未分類でした。`check=machine` の 54 件のうち 19 件は、注記に試験の名がありませんでした。確かめ直すと、8 件は違反の入力で落ちる試験と適合の入力で通る試験の対を持たず、2 件は欄やキーの有無までしか確かめていませんでした。`check=presence` の中には、規則の行がある節の見出しだけ、手順のファイルの実在だけを確かめるものがありました。

### 常駐の規則は、節の見出ししか確かめていなかった

準拠テンプレートの `check-process-rules` は、`CLAUDE.md` の常駐の規則の節の見出しと本文の有無を確かめていました。節の中の禁止の行を消しても、否定を除いても、検査は通りました。

### G-5 基準6 は、どこにも降りていなかった

第4章 G-5 の基準6(文脈ファイルの形式検査)は、参照切れ 0 件と分量の上限の超過 0 件を求めます。準拠テンプレートに基準6 のジョブはありませんでした。本文の開示は分量の上限だけを未達と書き、参照切れも未達であることを書いていませんでした。

### 降りていない規定に、降ろすかどうかの区別が無かった

`state=undelivered` の 100 件余りは、降ろす予定のものと、採用者が自ら実装する前提のものを区別していませんでした。後者は永久に予定に見え、前者は放置されても分かりませんでした。台帳の定型文は、降ろし先が実在する規定にも「実行層に対応する記述がありません」と書いていました。

### スキルの文の検査は、依頼の形と `CLAUDE.md` を見ていなかった

ADR-0064 の検査は、要求・禁止の文末だけを対象にしていました。スキルには「〜ないでください」の依頼の形の禁止が 20 行ありました。`CLAUDE.md` の生成区間の外は、検査の対象の外でした。

## 決定

### 1. 検査の強さを分類し、`machine` に試験を名指させる

- 未分類 100 件をこの Issue で分類した。以後、`check` を欠くマークを検査で落とす。迷ったら弱い値を書く
- `check=machine` は属性 `test` で試験のファイルを名指す。試験は違反の入力で検出する場面と適合の入力で通る場面の対を持ち、目印 `IMPL-NNNN:ng` と `IMPL-NNNN:ok` を含む。試験は必須の集約から実行される(準拠テンプレートは集約 `gate-g5` が合否に使うジョブの `run:`、本リポジトリは `package.json` の `check`)。`check-impl.mjs` が3つを確かめる。**この確かめは、試験の中身が規定を正しく確かめていることを示さない**
- 規定が入口(コマンド・スキル)についてのものなら、関数を直接呼ぶ試験では足りない。A-11(外部の確認者の記名による緩める向きの決定の拒否)は、変化点の入口を通す試験を足した
- 試験の目印の `:ng` は「違反の入力で検出する(落ちる、または件数・一覧・警告に出る)」場面、`:ok` は「適合の入力で通る」場面とする。同じ IMPL の `:ng` と `:ok` は別の行に置く(1つの検査に両方の目印を付けない)
- 試験を実行する手順が、`run:` の行の `|| true`、手順の `if:`、手順の `continue-on-error` を持つ場合は、結線の不備として落とす
- `check=presence` は、規則を運ぶ単位(欄・キー・行・ファイル)の有無までの確認に限る。単位を注記に書く。より粗い単位の確認と、規則がファイルの中の振る舞い(遮断する・順に行う)にある場合のファイルの実在の確認は `manual` とする
- `check=manual` の注記に、確かめる者(「確かめる者: 」または「人が確かめるのは」)を書く。機械が求める
- 降ろし先の登録簿の欄 `check`(検査のスクリプトの名)を `checker` へ改める。同じ語が別の意味で使われていた
- 検査の強さの区分に根拠水準のマークを付ける(EV-0163。E1)

### 2. 常駐の規則を、規則ごとに照合する

- 準拠テンプレートの常駐の規則の一覧(`scripts/gate/claude-md-resident.json`)に、規則ごとの識別子・節・核の文言を持たせる。照合は、太字・逆引用符・リンクの記法・HTML コメント・空白の違いを除いて行う。核の文言が同じ節のいずれかの行に含まれれば満たす
- 核の文言は、箇条書きの行と太字で始まる段落の行では、行の文のうち `[機械]` の注記と行の中の所在(「詳細:」「理由:」)より前とする。表の行では、核に含める列の升をつないだものとする。行の一部(最初の文など)を核にすると、行の残りから否定を除く変異が通るため、行の全文を核とする
- HTML コメントは、複数行のものも含めて、行へ分ける前に、行番号を保ったまま空行へ置き換える。描画されないコメントの中の規則は、規則として数えない
- 案件が行の前後へ書き足すこと、節の中で並べ替えること、節と行を足すことは妨げない。表の行では、「止める仕組み」と「例」の列を核に含めない(案件の CI に合わせて書き換えてよい)
- 核の文言を変えることは、標準の規定の書き換えである。照合が落ちるのは真の検出である
- 一覧の作り直し(`--write-resident`)は追加だけ。一覧から規則を除くことは強制層の縮小であり、`state:needs-platform` を経て、一覧の `omit` へ移す。`omit` の各項目に、除く理由(`reason`)と承認した AI維持管理者の氏名(`approvedBy`)を書く。`check-process-rules` が、欠けた項目と AI の名義の `approvedBy` を落とす
- 変異の試験により、照合が落ちることを確かめる。変異は、行の削除、節を1行に置き換えること、否定を除くこと、節の本文を複数行のコメントで囲むことである。変異は試験の中に持つ固定の写しに対して行い、案件の `CLAUDE.md` を読まない。陰性の対照として、太字を外しただけの文書でも、照合と変異の試験の両方が通ることを確かめる。案件の `CLAUDE.md` の照合は `check-process-rules` が行う
- 機械で止まらないこと(限界)を開示する。(a) 案件が `CLAUDE.md` の行と一覧の規則を同じ変更で消すこと。どの検査も落ちず、差分のレビューだけが拾う。(b) 行末へ打ち消し(「(当社では適用しない)」など)を書き足すこと。前後への書き足しを許した帰結であり、照合は通る。どちらも `state:needs-platform` の対象である強制層の縮小に当たり、レビューで止める
- 常駐の規則の行を降ろし先とするマークの値は `presence`(単位: 行)とする

### 3. G-5 基準6 の開示を直し、参照切れを降ろす

- 第4章 G-5 の基準6 の開示を、参照切れと分量の上限の両方について書き直す
- 準拠テンプレートに、文脈ファイル(`CLAUDE.md`・`AGENTS.md`・`context/`・`.claude/` の Markdown)の相対リンクと取り込み(`@` で始まるパス)の先の実在を確かめる検査を置く。ジョブ `context-format` として、集約 `gate-g5` の `needs` に入れる
- 逆引用符の中の、`.claude/` と `scripts/` で始まるパスも対象に入れる。テンプレートが持つ置き場への所在であり、`CLAUDE.md` が規則の索引として行末に置く所在(「詳細: `.claude/skills/...`」)もここに当たる。雛形の記号(`N`・`NNN`・`G-N`・`F-NNN`・`<…>`・`*` など)を含むものと、`.gitignore` に当たるもの(実行時に作られる端末ごとの状態。`.claude/.self-heal` など)は除く
- 見出しのアンカーと、逆引用符の中のそれ以外で始まるパス(`docs/`・`context/` など)は対象の外とする。テンプレートの例は案件が後で作るファイル(`docs/D-0-governance.md` など)を指し、テンプレートの時点では実在しないためである。降りていない残りとして開示する。基準の縮小ではなく、降ろした範囲の開示である
- 分量の上限は降ろさない。値を支える実証が無い
- IMPL-0269 を参照切れ(IMPL-0269)と分量の上限(IMPL-0312)の2つに分ける

### 4. `state` は2値のまま、降りていない規定に計画を付ける

- 属性 `plan` を足す。`scheduled`(降ろす予定。`issue` と `review` を要する)と `adopter`(準拠テンプレートは実装せず、採用者が自ら実装する。`decision` を要する。規定は課したまま)
- すべての `state=undelivered` に `plan` を付ける
- 「課さない」は `plan` の値にしない。課さないと決めた規定は、条項を改めて棚卸しの `not-imposed` へ移す([ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/))
- `adopter` にできない規定の登録簿(`src/data/impl-no-adopter.yaml`)を置く。第5章 5.8.3・5.4.3 の一律で委譲できない領域、5.5.1 の人へ戻す3つの場合と 5.5.5 の人が確定する判断、第7章 7.11 の停止の申し立て、Label Mailbox 4.7 の統制の弱化の検出が当たる
- 降ろす順序は、表示の誤り → `adopter` にできない規定 → G-7・G-8・R1 の決定に関わる規定 → その他とする。根拠が無いので EV-0164(E0)を付ける。第2段と第3段は、マークが置かれた節の鍵を登録簿(`impl-no-adopter.yaml`・`src/data/impl-decision-sections.yaml`)と照らして決める。注記の語(G-7・G-8・R1)では判別しない。付随の言及(「R1 は10営業日前」など)を拾い、決定に関わらない規定を前へ出すためである
- `adopter` とした規定ごとに、採用者に委ねる理由と、採用者に求めることを次の表に記録する。理由を書けない規定は `adopter` にせず `scheduled` とする

| マーク | 規定 | 採用者に委ねる理由 | 採用者に求めること |
| --- | --- | --- | --- |
| IMPL-0086 | 軸A の機能責任者への委譲 | 組織に固有の推奨であり、委譲の先と範囲は組織の体制で決まる | 委譲するなら、委譲の先と範囲を D-0 体制図へ書く |
| IMPL-0222 | 指示資産の保守要求の値 | 値を支える実証が無い。採用者が自らの値を定める | 値と、その値を選んだ理由を層1 か判断記録へ書く |
| IMPL-0269 | G-5 基準6 の参照切れのうち降りていない残り | 見出しのアンカーの slug は採用者の描画系に依存する。`docs/`・`context/` のパスは案件が後で作るファイルである | 採用者の描画系でアンカーを確かめる検査と、案件のファイルを作った後の参照の検査を足し、集約の `needs` へ入れる |
| IMPL-0277 | 停止条件のうち消費の計測 | 消費の計測は、モデルへの接続経路(API・契約の形態)に依存する | 接続経路に応じた計測の手段を置き、停止条件の値と照らす |
| IMPL-0279 | AI レビューの往復の停止 | 往復を止める手段は、実行の基盤(エージェントの実行環境)に依存する | 実行の基盤で往復の上限を設定し、設定の所在を D-0 へ書く |
| IMPL-0299 | ロールとレーンの写像 | レーン(作業領域・セッション・認証情報の組)は、採用者の実行環境の設定で決まる | 写像を D-0 体制図へ書き、実行環境の設定と合わせる |
| IMPL-0312 | 1ファイルの分量の上限 | 上限の値を支える実証が無い | 値を定め、検査を足して集約の `needs` へ入れる |

- 見直しの年月を過ぎた件数を台帳の冒頭に出す。合否には使わない。期日の日数は課さない
- `issue=` が閉じた Issue を名指すことは、機械で検出しない。検査はオフラインで実行し、Issue の状態を知り得ないためである。閉じた Issue を名指さないことは、Issue を閉じる者が確かめる。#314 は、`issue=314` のマークが 0 件になったことを閉じる条件とする(決定の時点で、後継の Issue を起票できなかった領域の 60 件が #314 を仮に名指す)
- 台帳の降りていない規定の定型文を、降ろし先の種別(予定の置き場か、実在する降ろし先か)で書き分ける。列の見出しの「(予定)」を除く

### 5. スキルの文の検査の範囲を広げ、限界を書く

- 「〜ないでください」の行を要求・禁止の文末へ書き直す。検査の文末にも依頼の形を加える
- 準拠テンプレートの `CLAUDE.md` の生成区間の外を、検査の対象に加える
- 平叙の否定と太字の否定は対象の外とし、件数を検査の出力と実装の台帳(自動生成)に出す。規約の限界の表は台帳の件数を引き、手で数値を書かない。語の整理は [#316](https://github.com/Takenori-Kusaka/process-compass/issues/316) で扱う
- この検査は文の所在の追跡であり、AI の担い手がその文に従うことを示さない。EV-0165(E0)を付ける
- 振る舞いの評価(複数回の試行)は CI に課さない

### 6. 附随の修正

- A-11 の入口を通す試験を足す(決定1)
- IMPL-0209 の降ろし先に `/human-verify` のスキルを登録し、マークを降りている状態へ改める。スキルの印を `根拠: IMPL-0209` へ改める
- IMPL-0206・IMPL-0120 の注記を事実に合わせる
- 逆向きの追跡をファイルの単位で採る。準拠テンプレートのゲートのスクリプト・フック・ワークフロー・エージェントの設定(`.claude` 直下の `json`)・ルールセット(`.github/rulesets` の `json`)の各ファイルは、降ろし先の登録簿にあるか、除外の一覧にある。除外の一覧は `src/data/impl-untraced.yaml` であり、理由の区分は `library` / `infra` / `variant` である。`variant` は登録簿の降ろし先の変種・設定であり、同じ規定を運ぶ降ろし先を `of` で名指す。どちらにも無いファイルを検査で落とす。なお対象の外に残るもの(`.github/CODEOWNERS`、`.github/actions/` など)は規約に列挙する
- 準拠テンプレートのコード・スキル・様式に書かれた IMPL の番号が、標準本文に実在することを確かめる

## 検討した選択肢

### 検査の強さ(R-1)

| 案 | 採らなかった理由 |
| --- | --- |
| 深さの属性(NIST SP 800-53A の depth)を足す | 単位を `presence` の定義で縛り、注記で示せば足りる。属性を増やすと、同じ事実を2か所で書く |
| 降ろし先の登録簿に単位の欄 `unit` を足す | 同上。1つの降ろし先が、欄と行の両方の規則を運ぶことがある |
| 別のセッションで全件を分類し直す | 危険な誤り(根拠なく `machine` と書く)は、機械が試験の目印と結線で止める。`presence` は単位の注記が確かめの手がかりを持つ。分類し直しの手間に見合う誤りの種類が残らない |
| 未分類のまま残し、件数の開示を続ける | 未分類は「降りている」を強く読ませる状態を続ける。棚卸しの材料(試験の対と単位)は揃った |

### 常駐の規則(R-2)

| 案 | 採らなかった理由 |
| --- | --- |
| 節の見出しの照合のままにする(採用者の編集の自由を優先する) | 禁止の行を消しても、否定を除いても通る。規則ごとの照合でも、前後への書き足しと並べ替えは妨げない |
| 行の全文で照合する | 採用者が「止める仕組み」の列や注記を自分の基盤に合わせて書き換えるたびに落ちる。正当な書き換えで一覧の更新が要り、更新が形骸になる |
| 常駐の規則を生成区間へ移す | 案件が書き足せなくなる。生成区間は構成からの導出物である |
| 変異の試験を案件の `CLAUDE.md` に対して行う(当初の実装) | 太字を外すなどの許される編集で置き換えが空振りし、必須の contract ジョブが落ちる(突合 X-4)。照合は `check-process-rules` が案件の文書に対して行えば足りる |

### G-5 基準6(R-3)

| 案 | 採らなかった理由 |
| --- | --- |
| 分量の上限の既定値(200 行)を置いて降ろす | 値を支える実証が無い。再評価の登録簿の目安があるだけである |
| 見出しのアンカーも確かめる | 日本語の見出しの slug は描画系ごとに作り方が違い、誤検出が多い。G-5 の原則(実効的な偽陽性が無いこと)に反する |
| 逆引用符の中のすべてのパスを確かめる | `docs/`・`context/` の下を指すテンプレートの例は、案件が後で作るファイルを指す。既存の違反を解消できない。`.claude/`・`scripts/` で始まるパスはテンプレートが持つ置き場を指すので、こちらだけを対象に入れた |
| 逆引用符の中のパスをすべて対象の外とする(当初の実装) | `CLAUDE.md` が規則の索引として行末に置く所在がすべて対象の外になり、テンプレートで参照切れの起こる経路がほとんど降りない(突合 X-8) |
| 基準6 を緩める | 基準を外せるのは第8章の調整だけである。降ろした範囲を開示する |

### 降りていない規定(R-4)

| 案 | 採らなかった理由 |
| --- | --- |
| `state` に3つ目の値を足す | 届いたかどうかと、どう扱うかは直交する。ADR-0061 が3つ目の値を落とした理由と同じ |
| 区別を足さない(運用で扱う) | 採用者が実装する規定は永久に予定に見え、予定の規定は放置されても分からない。運用は忘れられ、データは検査できる([ADR-0052](/process-compass/adr/0052-delivery-is-verified-at-the-destination/)) |
| `plan` に「課さない」の値を置く | 課さないことは条項の決定であり、マークの値で済ませると条項が残ったまま課さないことになる。棚卸しの `not-imposed` へ移す |
| 見直しの期日の日数を課す | 外部の先例(脆弱性の是正、認証の是正計画)は統制の種別ではなくリスクの評価で期日を決める。日数を写す根拠が無い |
| 期日を過ぎた件数で検査を落とす | 暦で CI が落ちる。件数を目標にすると、マークしない誘因が生まれる([ADR-0076](/process-compass/adr/0076-inventory-of-implementation-marking-targets/)の決定5) |
| 閉じた Issue を名指すマークを機械で検出する | 検査はオフラインで実行し、Issue の状態を知り得ない。状態を問い合わせると、ネットワークと権限に依存する検査になる |
| 第3段を注記の語(G-7・G-8・R1)で判別する(当初の実装) | 付随の言及を拾う。判別の誤りを残す手段を、信頼性の軸で採らない(突合 X-13) |

### スキルの文(R-5)

| 案 | 採らなかった理由 |
| --- | --- |
| 運用の実績を待って範囲を広げる | 範囲の外の禁止が印なしで増える経路は、運用を待っても塞がらない |
| 平叙の否定と太字の否定も対象にする | 説明の文と規則の文を文末で分けられず、誤検出が多い。件数を出し、語の整理(#316)で扱う |
| 振る舞いの評価(複数回の試行)を CI に入れる | 非決定的な結果を合否に使うと、偽陽性で落ちる検査になる |

### 附随(R-6)

| 案 | 採らなかった理由 |
| --- | --- |
| 逆向きの追跡を採らない(規約が手段の不在を開示済み) | 開示だけでは、新しいスクリプトが標準に無い規則を持ち込んでも分からない。ファイルの単位なら閉じた集合を作れる |
| 逆向きの追跡を関数・規則の単位で行う | 機械で閉じた集合を作れず、登録を保守できない |
| IMPL-0042・0043 を、降りた部分(記録の有無)と降りていない部分に分ける | どちらも1つの判定基準(G-7 基準3・4)である。有無の部分だけを `delivered` の別のマークにすると、台帳がその基準を「降りている」側にも数え、強いほうへ読まれる(ADR-0061 のコンテキストと同じ失敗)。定型文の書き分けと注記で、欠けている部分を示す |

## 影響

- `check` を欠くマーク、試験の目印と結線の無い `machine`、単位の無い `presence`、計画の無い `undelivered` を、`npm run check` が落とす
- 準拠テンプレートの集約 `gate-g5` の `needs` に `context-format` が加わる。ブランチ保護の必須の検査は集約を指すため、採用者のブランチ保護の設定は変わらない
- 強制層の変更である([ADR-0074](/process-compass/adr/0074-no-cap-on-inspection-apparatus/)の決定3)。次の4点を含む。**強制層の検査の追加と強化は AI維持管理者(人)が承認する。AI の名義の承認は受け付けない**。準拠テンプレートの PR には `state:needs-platform` を付ける
  1. contract ジョブに試験を足す(`test-context-refs`・`test-claude-md-resident`・`test-loosening-decider`・`test-spec-lint`)
  2. `check-process-rules` の合否の条件を、節の照合から規則ごとの照合へ強め、`omit` の項目の理由と承認者を求める
  3. `.claude/skills/` の10ファイルと `CLAUDE.md` の文言を、依頼の形から禁止の形へ改める(エージェント指示資産の変更)
  4. 既存の採用者は、テンプレートの更新を取り込むと、参照切れの検査(逆引用符の中の `.claude/`・`scripts/` のパスを含む)、常駐の規則の照合、`omit` の検査で `gate-g5` が落ち始めうる。採用者は、参照の先を直すか、AI維持管理者の承認を経て `omit` へ移す
- 準拠テンプレートの `CLAUDE.md` の常駐の規則の文言を変えると、案件の `check-process-rules` が落ちる。テンプレートの側で規則を足したら、一覧へ追加する
- `scheduled` の Issue のうち、起票できなかった領域は #314 を仮の Issue として名指す。起票の下書きは `research/314-deliberation/followup-issues.md` にある。起票したら番号を改める。#314 は、`issue=314` のマークが 0 件になるまで閉じない(決定4)
- 試験の目印は、試験の中身が規定を正しく確かめていることを示さない。目印の場面が規定の違反と適合に当たるかは、条項を改めるときの突合で確かめる
