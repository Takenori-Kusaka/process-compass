## ステータス

採用(2026-10-23)。採用済みの ADR の決定を置き換えません。[ADR-0072](/process-compass/adr/0072-document-volume-is-not-a-metric/) 決定4 が本 Issue へ送った「探索の記録の置き場と、SG-0 へ渡す出力」を、本 ADR の決定1 で回収します(後掲「既存の決定との関係」)。ADR-0072 のステータスの節は変えていません。

## コンテキスト

[#294](https://github.com/Takenori-Kusaka/process-compass/issues/294) は、次の改訂の入力として 8 論点をまとめた Issue です。#250(S1 以降の技術検証)、#278(後段に人の門がある場合の停止)、#279(文脈を持たない読み手の役)、#273(スタック型 PR)、#274(定額の上限とキャッシュ)、#268(AI の反対理由の構造化)、#271(添付の証跡の置き場)、#254(検査の規模の下限)の残りを含みます。

指摘をそのまま条項にせず、調査2本と会議体5名の意見書で扱いました。記録は `research/294-deliberation/`(`decision.md` の K-1〜K-9)にあります。

### 見つかったこと

- ゲートで確定した成果物(受入基準・前提・判断記録)を後から変えたとき、どのゲートをやり直すかが本文に無かった。#250 の「技術検証の置き場」は、この一般の欠落の1例だった。附属書H の ISO 9001 対応表は、箇条 8.3.6(設計・開発の変更)をコードの変更の機構だけで満たすと示しており、対応を実態より強く示していた
- G-2 の判定者は前提の引き受け手と定められていたが、引き受けない場合の差し戻しの根拠が無かった
- 停止の単位となる「取り消せない操作」が定義されていなかった。字面どおりに読むと、既定ブランチへの push で公開する構成では、既定ブランチへ入る編集のすべてが停止の対象になった
- `label-mailbox.md` に、ADR-0053 が用いないと決めた語「不可逆4操作」が残り、取り消せない操作の戻す先を価値責任者と誤って書いていた
- スタック型 PR の頁は、中間層の先行マージを CI の必須チェックで拒否すると書いていた。必須チェックはルールセットの対象のブランチへのマージにしか効かず、準拠テンプレートの対象は既定ブランチだけである。PR 単位の検査は基準値を PR の基底から読んでおり、スタックの上の層では未マージの下の層の基準値で判定された
- AI 実行予算の定義は従量を前提にし、提供者が課す利用上限を扱っていなかった
- 判定記録・出荷の証跡が指す記録の保管について、CI 基盤の保持期間(成果物の既定 90 日、2026-10-01 以降はチェックの履歴も設定の保持期間に従う)との関係が書かれていなかった
- G-5 基準3 の基準値は、何の割合とするか(全体、または変更で加えたコード)を決める者と時期を書いていなかった。準拠テンプレートは全体の割合を測り、標準の目安(新規コード)と食い違っていた

## 決定

### 1. 確定した版を変えたら、確定したゲートの判定を受け直す(K-1)

第4章に「確定した版を変える場合」を置きます。受入基準・前提・スコープ外を変える場合は G-2(S0 で G-2 を G-4 へ統合する場合は G-4)、判断記録を変える場合は G-3 の判定を、変更後の成果物で受け直します。戻り幅は変わった成果物で決まり、**変更の契機(技術検証の結果、顧客の要望、障害など)によって受け直すゲートを変えません**。新しいゲートは設けません。

G-2(S0 は G-4)の判定者が前提を引き受けない場合は、閉じていない未確定事項として扱い、前提条件1 を満たさないものとして差し戻します。引き受けないのは崩れたときの影響を負えないという判断であり、前提の内容の判定ではありません(G-2 基準3 は前提の内容を判定しないまま)。

S0 の探索の記録の置き場と様式は課しません。SG-0 へ渡すのは SG-0 の決断の記録(第5章 5.7.2)の「確認した事項・確認していない事項」で、確認した事項には依った探索の記録を挙げ、到達できることを求めます。

**「技術検証」の種別・様式・置き場・ステージは設けません**。技術検証は実装計画の通常のタスクとします。本標準の経路は成果物の変化で起動し、契機で起動しないためです。種別を設けると、検証と名付けなかった変更が経路の外に出ます。

附属書H の ISO 9001 対応表の箇条 8.3.6 の行に、この節を対応として足し、確定の後の変更を機械が検出しないことを弱い点に書きます。機械の検出は準拠テンプレートに無く、`undelivered` で表示します(IMPL-0241)。

本決定には根拠水準マークを付けません。既に定めた「確定」の定義から出る戻りを書き出したもので、新しい値や前提を置いていないためです。

### 2. 取り消せない操作を、効果を他の者の操作を介さずに生じさせる操作と定める(K-2)

第5章 5.5.1 に定義を置きます。取り消せない操作とは、取り消せない効果を、他の者の操作を介さずに生じさせる操作です。効果の判定の基準は ADR-0053 決定1 のまま(取り消せない時間帯が存在すること)です。

- 反映・発行を後段で人が行う(5.5.5 項目4)上流の編集は、取り消せない操作に数えない
- 後段が人でない経路(委任のマージ・自動マージ・予約の公開・push を契機の配備)では、上流の操作が当たる
- 既定ブランチへの取り込みや push が発行・本番への反映を直接起動する構成では、その取り込み・push が当たり、委任によるマージの対象にしない
- **後段に人だけが通せる門が残ることを理由に、停止を省く免除は置きません**

原則4(`label-mailbox.md`)は 5.5.1 の定義を引く形にし、戻す先を事業決裁者に直します。統制の弱化は、取り消せない操作とは別の停止の事由として残します。根拠水準は EV-0141(E2)です。

### 3. スタック型 PR は既定ブランチへの取り込みで G-5・G-6 を成立させる(K-4)

第4章「タスクの分割基準」に「積み重ねた変更とゲート」を置きます。G-5 の起動を PR の基底ブランチで絞りません。G-5・G-6 は既定ブランチへ取り込む PR で成立し、既定ブランチ以外を基底とする PR をマージしません。下の層から順に取り込み、上の層の基底を付け替えます。合わさった差分への承認を層ごとの確認に数えません。PR 単位の検査が読む基準値・台帳の例外承認・区分の下限の規則・停止の申し立ての解除の記録は、既定ブランチから読みます。

準拠テンプレートの `check-pr.mjs` は、差分を PR の基底から取り、基準値などを `--policy-base`(既定ブランチ)から読むように改めました(IMPL-0249)。中間層の先行マージを拒否する設定はテンプレートに無く、`undelivered` で表示します(IMPL-0248・0254・0255)。スタック型 PR の頁の前提表に、GitHub 標準のスタック(2026-07-30 公開プレビュー、2026-10-06 一般提供)を足しました(EV-0139)。

ルールセットの対象を機能ブランチへ広げる案は採りません。直接の push の扱いを実機で確かめておらず、着地の保護で足りるためです。エージェントが作るスタックの負担の増減は、両論を併記するにとどめます。

### 4. 判定が指す記録は保管期間のあいだ到達できなければならない(K-7)

第4章「判定の成立」に「判定が指す記録の保管」を置きます。判定記録と出荷の証跡が指す記録は、組織が定める保管期間のあいだ到達できなければなりません。CI 基盤の既定の保持を、保管とみなしません。保管期間の値は定めません。

準拠テンプレートの出荷の証跡は CI の成果物にだけ置かれ、集約は保持切れを「必須チェックを経ずにマージされた可能性」と誤って示しうることを、`undelivered` で表示します(IMPL-0243・0244)。保管の設計は別 Issue で扱います。

### 5. 費用の統制は課金形態を前提にしない(K-5)

3.12.7 の上限は提供者が課す利用上限を含むものとし、到達時の扱い(待つ・従量へ移る・止める)を G-1 で決めます。提供者の上限を組織が設定した上限に数えません。待つことで費用が増えることを、承認を急がせる理由にしません。7.7.1 で、AI 実行予算は課金形態を前提にしない統制の単位とし、消費の実績が無ければ未測定と報告します。3.12.2 で、個人で契約した経路は定額であっても正規の経路に当たらないとします。キャッシュの費用構造は、数値を書かない形で `compute-strategy.md` へ置きます(EV-0140)。トークン効率は診断用で、7.7.8 の評価の入力にしません。

### 6. G-5 基準3 の測る範囲を企画時に決める(K-8)

基準値は、測る範囲(全体か、変更で加えたコードか)を併せて企画時に決め、記録します。記録と保証の開示に、割合・範囲・分母を出します。準拠テンプレートの `coverage-check.mjs` は全体の割合だけを測り、`undelivered` で表示します(IMPL-0245・0246)。

### 7. 確認の範囲は、確認側へ渡した入力の記録で示す(K-3・K-6)

附属書H H.4 に「確認側へ渡した入力の記録」を置きます。確認側へ渡した入力(自動で読み込まれる指示ファイル・道具の定義・起動の指示を含む)を列挙できない確認を、文脈を渡していない確認として記録してはなりません。AI が出力した確かめた範囲の申告を、確認の範囲の根拠にしてはなりません。入力の記録を機械が実行の記録から書く手段は、準拠テンプレートに無く `undelivered` です(IMPL-0253)。

## 課さないと決めたこと

| 論点 | 課さないこと | 理由 |
| --- | --- | --- |
| K-1 | 「技術検証」を作業の種別にすること。その様式・置き場・ステージ | 経路は成果物の変化で起動する。種別を設けると、検証と名付けなかった変更が経路の外に出る |
| K-1(1-C) | 前提の行に検証のタスクを書かせ、着手の前提条件にすること | 責任者と期限を付けた持ち越し(ADR-0036 決定3)に当たる |
| K-1 | S0 の探索の記録の置き場と様式 | 量を課さないのと同じく、置き場を課すには対象の定義が要り、定義する材料が無い。求めるのは到達性だけ |
| K-2(2-C・2-D) | 後段に人の門があることによる停止の免除。門の位置を構成に登録させる免除 | 門が実在するか・効くかを、実行主体か登録の手続が判定することになる。1〜2 名の体制や委任のマージでは後段が人でなくなる。GitHub の門は既定で管理者が迂回できる(ADR-0077)。後段の監視は前段を置き換えないとする提供者の指針、承認の疲れの指摘(二次) |
| K-3 | 文脈を持たない読み手の役を要求事項にすること | 根拠は単一事例と自己実施 1 回(E2 以下)。H.4 条件1 の欠陥注入で文脈の欠落を測る方法が無い。読み手に伝わるかは ADR-0051 決定1 が扱わないと決めた領域に重なる。組織外への発行の前の工程は ADR-0053 決定5 が退けた形。手引きは附属書C(参考)に置く |
| K-5 | 手元の実行の記録の日次の複製 | 提供者の保持の仕様に依り、本標準の判定が読む記録ではない |
| K-6 | AI の出力に、反対の理由の列挙・観点ごとの所見・確かめていない範囲を含める値として課すこと | ADR-0075 決定7・10 と同じ向き。覆す材料は E0 の資料と前後比較の無い事例だけ。範囲の自己申告は構造を満たしたまま食い違いうる。組織が置くことは妨げない |
| K-7 | human-verify への添付と、添付の所在の記載 | 所在の実在は確かめたことを示さない(G-2 基準3 の理由)。署名の様式は ADR-0056 が却下済み |
| K-8 | カバレッジの判定の規模の下限 | 下限未満の「判定しない」は ADR-0033 決定7 の 3 区分に無い 4 つ目の状態になり、未実施を通過として残す。分割で判定を避けられる。外部の規格は規模でなくリスク・安全度で厳しさを変える(二次)。EV-0142 |

## 影響

- 確定した版を変えた機能仕様・判断記録は、変更後の版で G-2(S0 は G-4)・G-3 の判定を受け直す。機械の検出は無く、出荷判定者の突合と内部監査に依る(IMPL-0241)
- 取り消せない操作の停止は、上流の編集から、効果を生む操作(マージ・起動・配備が動く push)の前へ移る。担い手が効果を生む操作を自ら行う構成では、その前で止まる
- 準拠テンプレートの `pr-rules` は、基準値などを既定ブランチから読む。手元で `--policy-base` を省くと、従来どおり基底から読む
- 準拠テンプレートの `CLAUDE.md`(人へ戻す3つの場合)と `/pit` の handoff、`/gate` の G-2・G-3・G-4 の補助ファイルに、本 ADR の規定を置いた
- 中間層の先行マージの拒否、判定記録の版の機械の照合、入力の記録、証跡の保管、カバレッジの範囲と分母は、準拠テンプレートに無く `undelivered` で表示する
