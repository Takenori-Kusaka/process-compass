プロセスの健全性は印象でなく指標で判断します。このページは、統合プロセスの運用で継続計測する指標体系と、その**警戒サイン(いつ手を打つか)**を定義します。

## 指標体系の全体像

```mermaid
graph TD
  M["運用メトリクス"]
  M --> F["流れ<br>(速度と滞留)"]
  M --> Q["品質<br>(欠陥と負債)"]
  M --> AI["AI協調<br>(委譲の効き)"]
  M --> G["統制<br>(ゲートの実効性)"]
  M --> B["事業継続性<br>(理解の維持)"]
```

原則は3つです。

- **自動集計できる指標だけを正式指標にする**(手集計は続かない。集計はAIとCIの仕事)
- **単独の指標で判断しない**(速度だけ見ると品質を犠牲にする最適化が起きる。対になる指標とセットで見る)
- **個人の評価に使わない**(プロセスの健全性を測る道具であり、人を測る道具にすると数字が歪む)

## 分類別の指標と警戒サイン

### 流れ(速度と滞留)

| 指標 | 内容 | 算出方法(データソース) | 警戒サイン |
| --- | --- | --- | --- |
| 機能リードタイム | 仕様承認(G-4)→ 本番反映までの日数 | G-4 承認コメントの日時 → 機能IDを含む最初のリリースタグの日時(GitHub API) | トレンドの継続悪化 |
| ゲート滞留時間 | 各ゲートの提出→判定 | G-5/G-6 は PR の Ready 化 → 承認の時間差(GitHub API)。その他はゲート判定記録(テンプレ4)の提出・判定日時 | 期限超過率 10% 超 |
| 差し戻し率 | ゲートごとの差し戻し割合 | G-6 は Changes requested の付いた PR 比率(GitHub API)。その他は判定記録の判定結果を集計 | 0% 継続(素通し)または 50% 超(手前の品質問題) |
| エスカレーション数 | 期限超過による代理判定の発生 | 判定記録の期限超過・代理判定欄を集計 | 特定判定者への集中(帯域不足) |

### 品質(欠陥と負債)

| 指標 | 内容 | 算出方法(データソース) | 警戒サイン |
| --- | --- | --- | --- |
| 重大欠陥の流出 | 本番で発覚した重大欠陥数 | `bug` かつ Sev1/Sev2 ラベルの Issue 起票数(GitHub API) | 1件でも発生したら原因ゲートの特定と改修 |
| 欠陥の検出工程 | どのゲートで捕まえたか | 欠陥 Issue の「検出ゲート」欄(起票テンプレートで必須化)を集計 | 下流(G-7以降)での検出比率の上昇 |
| 負債残高トレンド | 台帳の未返却残高 | 負債台帳(テンプレ3の表)を CI がパースし、状態=未返却の行数を記録 | 3か月連続増加 |
| テスト実効性 | 変異テスト通過率等(形骸化検知) | 変異テストツール(Stryker 等)のスコアを CI 成果物として保存 | 実装を写しただけのテストの増殖 |

### AI協調(委譲の効き)

| 指標 | 内容 | 算出方法(データソース) | 警戒サイン |
| --- | --- | --- | --- |
| AI関与率 | コミットのAIトレーラ比率(規制業は必須集計) | `git log --grep "Co-Authored-By"` の件数 ÷ 全コミット数(期間指定) | — (現状把握用) |
| 手戻り率 | AI生成→人差し戻しの割合(タスク単位) | Changes requested を1回以上受けた PR 比率+実装計画表の「やり直し」件数 | 高止まり(仕様・文脈の品質問題)または不自然な0%(検証の放棄) |
| トークン効率 | 機能あたりのトークン消費 | AI 利用の課金・使用量レポートを機能ID(Spec トレーラ)単位で集計 | 特定機能への異常な再試行集中 |
| 文脈の鮮度 | 恒久層ファイルの最終更新・参照切れ数 | `git log -1 --format=%cs <ファイル>` の経過日数+リンク検査(lychee 等)の失敗数 | 停滞ファイルの増加(陳腐化) |

### 統制(ゲートの実効性)

| 指標 | 内容 | 算出方法(データソース) | 警戒サイン |
| --- | --- | --- | --- |
| レビュー所要時間の分布 | 変更規模に対する独立レビューの時間 | PR の Ready 化 → 承認の時間差と差分行数の散布(GitHub API) | 規模に対して極端に短い承認の続発(rubber stamp) |
| 挙動要約の品質 | 要約の欠落・定型文化 | 承認コメントの挙動要約欄の有無を CI で検査し、欠落数を記録(文面の質は四半期に人がサンプル確認) | コピペ的要約の増加 |
| ルール化の進み | 人の指摘→CI移管の件数 | `ci:` 種別のコミットのうち「レビュー指摘由来」ラベル付き PR の件数 | ゼロが続く(ゲートが成長していない) |
| 判定記録の完備率 | ゲート判定記録の欠落 | リリースタグ時点で[エビデンス集約](/process-compass/phase5-implementation/ci-gates/)が判定記録の欠落を検査 | 欠落の発生(監査可能性の毀損) |

### 事業継続性(理解の維持)

| 指標 | 内容 | 算出方法(データソース) | 警戒サイン |
| --- | --- | --- | --- |
| コア理解カバレッジ | コア機能ごとの理解保持者数 | コア機能一覧 × 理解記録(deep-read の ADR・判断記録)の記録者数を突合 | 保持者1名以下のコア機能の存在(単一障害点) |
| 判断記録の充足 | コア機能のADR完備率 | コア機能を触った PR のうち `ADR:` トレーラ付きコミットを含む比率(git log) | 未記録のコア変更 |
| 復旧演習 | コア機能の障害対応演習の実施 | 演習記録(運用カタログの四半期作業)の最終実施日 | 半期を超えて未実施 |

## 収集の実装(3つのデータソース)

すべての指標は次の3系統から自動収集できます。手集計が必要な指標は上の表に存在しません。

| 系統 | 取得手段 | 対象指標 |
| --- | --- | --- |
| Git履歴・GitHub API | `git log`(トレーラ集計)、`gh api`(PR・レビュー・Issue・タグの日時) | 流れ全般、AI関与率、レビュー所要時間、判断記録の充足 |
| CI 成果物 | ワークフローが保存する JSON(テスト・変異スコア・検査結果) | テスト実効性、挙動要約の欠落検査、判定記録の完備率 |
| 記録のパース | 負債台帳・ゲート判定記録・演習記録(様式が固定なので機械可読) | 負債残高、滞留時間、エスカレーション、復旧演習 |

```bash
# 例: AI関与率(直近30日)
total=$(git log --since="30 days ago" --oneline | wc -l)
ai=$(git log --since="30 days ago" --grep "Co-Authored-By" --oneline | wc -l)
echo "AI関与率: $ai / $total"

# 例: G-6 レビュー所要時間(Ready化→承認)の一覧
gh pr list --state merged --limit 50 --json number,createdAt,reviews \
  --jq '.[] | {number, approvedAt: (.reviews[] | select(.state=="APPROVED") | .submittedAt)}'
```

- 週次の集計ジョブ(cron)で3系統を取得し、1つの JSON にまとめてリポジトリへコミットする。ダッシュボードはその JSON を描画するだけにする(集計と表示の分離)

## ダッシュボード化

- 収集は CI・リポジトリ API・台帳から自動化する([エビデンス自動集約](/process-compass/phase5-implementation/ci-gates/)と同じ仕組みに載せる)
- 週次で見るのは警戒サインの点灯だけ。全指標の眺め回しは四半期の[振り返り](/process-compass/phase6-operation/improvement-cycle/)で行う
- 将来的には、プロセス提案ツール(M7)がこの指標体系を「導入後の健全性診断」として内蔵することを構想している

## 指標が示す「次の一手」の早見表

| 症状 | 疑うべき原因 | 打ち手 |
| --- | --- | --- |
| 滞留が増えた | 判定者の帯域不足 | 委譲・機械化・タスク分割([プレイブック](/process-compass/phase4-process-design/gate-criteria/)) |
| 差し戻し率0%が続く | ゲートの素通し | 挙動要約の点検、レビュー時間の確認 |
| 負債残高が増え続ける | 返却枠の不足・記録だけ運用 | 返却枠の拡大、トリアージの実施 |
| 手戻り率が高い | 仕様・文脈の品質不足 | 受入基準の形式チェック強化、文脈の書き戻し |
| コア理解1名以下 | 理解維持の形骸化 | 理解共有の作業化(ペア読解・演習) |
