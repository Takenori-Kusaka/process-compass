本標準の規定は、案件の実行層へ降りて初めて実行主体へ届きます。降りていない規定は、**案件からは「規定がない」ものとして扱われます**。

実際に、次の事象が続きました。

| 案件からの申し立て | 実際 |
| --- | --- |
| ロールとセッションの対応づけの規定がない | 第3章 3.5.1 にあった |
| 段階的なエスカレーションの規定がない | 第7章 7.6 と D-0 第4節にあった |
| 強制層の変更が事業決裁者へ直行してしまう | `state:needs-platform` という経路があった |

いずれも公開されており、リンクも通っていました。**読まれる場所に無かっただけです**。

本規約は、規定と降ろし先の対応をマークして追跡可能にする書式を定めます。

## 何を追跡するか

対象は「実行主体の挙動を制約する規定」です。全条項を対象にしません。維持できない台帳は、それ自体が降りていない規定になります。

| 対象にする | 対象にしない |
| --- | --- |
| 実行主体が守るべき禁止・権限・経路 | 背景・根拠・比較の記述 |
| 案件の構成へ反映すべき判断 | 組織の制度設計に関する規定 |
| 案件のエージェントが起動時に知る必要のある内容 | 読者の理解のための解説 |

## 書式

規定の直後へ、HTML コメントとして置きます。読者には表示されません。**開示ではなく追跡のためのマーク**であり、[根拠水準のマーク](/process-compass/community/evidence-marking/)とは目的が異なります。

```markdown
<!-- impl IMPL-0001 target=config-roles state=delivered note="兼務の禁止を構成へ出力する" -->
```

| 要素 | 規則 |
| --- | --- |
| 識別子 | `IMPL-` + 4桁の連番。**再利用しない**。マークを削除しても番号を空けたままにする |
| `target` | 降ろし先の識別子。`src/data/impl-targets.yaml` に登録されたものだけを使う |
| `state` | `delivered`(降りている)または `undelivered`(降りていない) |
| `note` | 何の規定かを1行で。台帳の見出しになる。空白を含む場合は引用符で囲む |

## 降ろし先の登録簿

`src/data/impl-targets.yaml` が降ろし先の正本です。登録されていない `target` を書くと検査が失敗します。

| 種別 | 意味 | 検査の内容 |
| --- | --- | --- |
| `config-key` | 準拠テンプレートが生成する `process.config.json` のキー | サンプル回答から構成を生成し、キーの存在を確かめる |
| `template-file` | 準拠テンプレートに置くファイル | 存在を確かめる |

**降ろし先の実在を機械的に確かめます**。台帳が「降ろしたつもり」の一覧になると、降りていない規定を隠すためです。

## 降りていない規定の扱い

`state=undelivered` は削除の対象ではありません。**降りていない事実を表示し続けます**。[未達のゲート](/process-compass/adr/0028-unmet-gate-distinct-from-omitted/)と同じ扱いです。

台帳は降りていない規定を冒頭に置きます。下位の節へ送りません。

## 運用

- マークを追加・変更したら `npm run impl:write` で台帳(`community/implementation-ledger.md`)を再生成する
- 台帳は自動生成である。**手で編集しない**
- `npm run check` が台帳の鮮度と降ろし先の実在を検査する

## 限界

**マークの付いていない規定は検出できません**。本規約が保証するのは、マークを付けた規定について降ろし先が実在することだけです。網羅性は保証しません。

網羅性を機械的に確かめる手段は現時点でありません。**この限界を隠さずに運用します**。
