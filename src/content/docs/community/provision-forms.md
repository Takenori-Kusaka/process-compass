本標準は、何が要求事項で、何がそうでないかを、文面から識別できるように書きます。決まりの正本は[第1章 1.5・1.7](/process-compass/phase4-process-design/overview/)です。本ページは、その決まりを機械で確かめる検査の書式と運用を定めます。判断の根拠は [ADR-0063](/process-compass/adr/0063-normative-informative-and-verbal-forms/)によります。

## 何を検査するか

`npm run check` が `scripts/check-provisions.mjs` を実行します。単独では `npm run lint:provisions` で実行します。

| # | 検査 | 対象 | 検出するもの |
| --- | --- | --- | --- |
| 1 | 附属書の種別の宣言 | 附属書9編と第1章 1.5 の表 | 表題の「(規定)」「(参考)」と、1.5 の表の「種別」が、登録簿と一致しない |
| 2 | 規定の文末 | 本文8章と規定の附属書 | 依頼の形(「〜ください」)と「〜すべき」の文末 |
| 3 | 表の升の語 | 本文8章と規定の附属書 | 升が「省略可」「任意」「どちらでもよい」「○」「△」「可」「不可」である(語だけ、または語と括弧書き)。「省略可」は地の文でも検出する。工程ゲートの状態の「簡略」の升が、括弧に減らすものの限定を持たない(括弧が無い、または括弧の中が「CL1 以上は適用」のような他の軸が取り消す条件だけ。第1章 1.7.3)。「簡略」で始まるが「簡略(限定)」の形で読めない升(「簡略化」、升の末尾の句点など)も止める。限定が減らすものを正しく書いているかは確かめない |

| 11 | 禁止事項の番号 | 公開ドキュメント(ADR と台帳を除く)と準拠テンプレート | 「禁止事項N」を、一覧の所在(「5.8.5 の」「テーラリングの」)で修飾せずに引いている(第1章 1.7。#316) |

## 機械が確かめないこと

次の3つは、機械で判定できません。人が読んで確かめます。

| 確かめないこと | 理由 |
| --- | --- |
| 「〜できます」が許容か、能力・可能性か | 同じ文末が2つの意味を持つ。文脈を読まないと分からない。機械は、文が区分つきで登録されているかだけを確かめる(後掲「文末の『できます』の登録簿」) |
| 平叙の動詞文(「〜します」)が要求か説明か | 文末の形が同じである。第1章 1.7.2 は、迷う文を要求として読むと定める |
| 言い回しを変えた写し | 廃した言い回しの検査は、登録した句をそのままの文字列で探す |

**検査が通ることは、書き分けが正しいことを意味しません**。検査が確かめるのは、使わないと決めた形が残っていないことだけです。

## 登録簿

登録簿は `src/data/provision-forms.yaml` です。

| キー | 内容 |
| --- | --- |
| `documents` | 検査の対象のページと種別。`normative`(本文と規定の附属書)または `informative`(参考の附属書)。附属書は記号を `annex` に書く |
| `retiredCellWords` | 表の升に使わない語 |
| `retiredWordsAnywhere` | 地の文でも検出する語 |
| `retiredValueWords` | 規定の文書で使わない値の語。語、廃した決定、代わりに書くこと |
| `retiredPhrases` | 廃した言い回し。句、廃した日、廃した決定、代わりに書くこと |
| `retiredScan` | 廃した言い回しを探す置き場と、探さない置き場 |
| `guides` | 手引きの頁の置き場(フェーズ5・6 のディレクトリ)。検査8 の対象 |
| `prohibitionLists` | 禁止事項の番号の修飾の語と、検査11 の対象の置き場 |

フェーズ5 とフェーズ6 のページは、`documents` に登録していません。頁の全体を参考(手引き)とし、頁ごと・節ごとの種別を定めないためです(第1章 1.8。[ADR-0086](/process-compass/adr/0086-guide-pages-and-remaining-verbal-forms/))。

## 文末の『できます』の登録簿

`npm run check` が `scripts/check-dekimasu.mjs` を実行します。単独では `npm run lint:dekimasu` で実行します。試験は `npm run test:dekimasu` です。判断の根拠は [ADR-0117](/process-compass/adr/0117-dekimasu-registry-and-permission-rewrites/)によります。

本文と規定の附属書(`documents` の `normative`)で、文末が「〜できます」「〜できる」の文を拾い、登録簿 `src/data/dekimasu-registry.yaml` と照合します。次のときに失敗します。

- 登録簿に無い文がある
- 登録した文が本文に無い(文を改めた、または消した)
- 区分が `capability`(能力・可能性)・`criterion`(判定基準・条件・力量要件の項目)・`other`(命題など)のどれでもない。許容(`permission`)は置けない
- 区分の根拠(`basis`)が `ai-blind`・`ai-context`・`human` のどれでもない

文の区切りと末尾の判定は、#366 の抽出(`research/366-deliberation/extract.mjs`)と同じです。文は「。」・表の升・`<br>`・箇条の末尾で区切ります。リンクを文字列に直し、末尾の括弧・強調・読点を外してから判定します。`mermaid` などのコードブロック、HTML の注記、フロントマターは見ません。様式の `markdown`・`text` のコードブロックの中の文は見ます。文の途中の「できる」と、「できるようにする」のように補助の語が続く文は、拾いません。

検査に落ちたときは、次のどちらかで処理します。

- 許容の意味の文は、第1章 1.7.1 の許容の形(「〜してよいものとします」「〜してよい」)へ改める
- 能力・可能性、または判定基準と条件の項目の文は、区分と根拠を付けて登録する。登録の差分を、取り込む人が読んで区分を確かめる

文を改めたら、登録の `text` も改めます。行番号では引きません。行は動くためです。

**検査が通ることは、区分が正しいことを意味しません**。`ai-blind` と `ai-context` の登録は、AI の振り分けで、人が読んでいません(第1章 1.7.4 の EV-0234)。

## 廃した言い回しの登録

条項を改めて古い言い回しを廃したときは、その言い回しの特徴的な句を `retiredPhrases` へ登録します。同じ事項を書くほかの箇所に古い文が残ると、読み手が古い側で済ませるためです。

- 登録する句は、古い言い回しにだけ現れる短い句にする。一般の語を登録しない
- 登録したら `npm run lint:provisions` を実行し、検出された箇所を、改める・所在を引く形へ替える・対象外として除外する、のいずれかで処理する
- `by` には廃した決定を `ADR-NNNN` か `#NNN` で書く。検査13 が実在を確かめる。`by` の ADR の本文に句が字句どおり現れることは求めない。登録した句の多くは、ADR が要約して書いた古い言い回しであり、字句の一致を求めると由来の検査として過剰になるためである(ADR-0089)
- 決定の記録(`adr/`)は探さない。廃した言い回しを経緯として引くためである
- 自動生成の台帳は探さない
- `zenn/` は探さない。派生物の置き場であり、別の査読の経路で改めるためである。**廃した言い回しが派生物に残ることを、この検査は検出しない**

## 除外の印

正当な使用は、行に印を書いて除外します。理由を必ず書きます。理由の無い印は無効です。

| 印 | 効く検査 | 書く場所 |
| --- | --- | --- |
| `<!-- provision-ok: 理由 -->` | 2〜5、7〜11 | 対象の行 |
| `retired-ok: 理由` | 6 | 対象の行。Markdown では HTML コメントの中、YAML とスクリプトではコメントの中に書く |

検査3 の「可」「不可」「○」「△」は、規定の強さでない升(例: 並列に実行できるかの可否、判定基準への丸付け)とも一致します。そうした升を持つ表の行には、`provision-ok` の印に「規定の強さではない」旨の理由を書いて除外します。規定の強さを表す升は、印で除外せず、第1章 1.7.3 の語で書き直します。

```markdown
旧版が「〇〇」と呼んだ条件は、この決定によって廃しました。<!-- retired-ok: 廃した旧称を示す -->
```

## 起草の規則(機械で検査しないもの)

本標準の条項を新設し、改めるときは、次の2つに従います。どちらも機械では検査しません。人が読んで確かめます([ADR-0074](/process-compass/adr/0074-no-cap-on-inspection-apparatus/))。

### 逃げ道になる句を使わない

本標準の規定の文と、規定の章の表の升に、逃げ道になる句(満たさなくてよい余地を残す句。例: 「必要に応じて」「可能な限り」「原則として」)を使いません。<!-- retired-ok: 使わない句の例を示す --> 組織に委ねる事項は「組織が定める」と書きます。組織が選べることを示すときは、[第1章 1.7.3](/process-compass/phase4-process-design/overview/)の「許容」で書きます。

機械で検査しない理由は、語の検出が説明の文と規定の文を分けられないためです。辞書による検出の適合率は 0.70〜0.81 と報告されており、失敗させる検査の3つの条件([第4章 G-5](/process-compass/phase4-process-design/gate-criteria/)「是正の起動」。実効的な偽陽性が無い)を満たしません。採用者の受入基準の曖昧語の検出(第4章 G-2 基準2)は、検査の範囲を受入基準の節に絞っており、この規則と別のものです。

### 緩める理由への読み替えを問う

条項を新設し、改める会議体の突合では、その条項が何を理由に緩めることへ読み替えられうるかを問います。見つけた読み替えは、条項の中に禁止として書きます(「〜を理由に、…してはなりません」)。本標準の主張そのものに掛かる読み替えは、[附属書H](/process-compass/phase4-process-design/assurance-case/) H.11「残るリスク」の表へ行を足します。H.11 の表を、本標準の主張に掛かる読み替えの台帳として扱います。

この手順は本標準の起草者に掛かり、採用者には掛かりません。採用者が書く基準に読み替えの列挙を求めないことは、[第1章 1.7.5](/process-compass/phase4-process-design/overview/)によります。

### 値を書くときは型を選ぶ

本文と規定の附属書に値(数値・閾値・席の割当)を書くときは、[第1章 1.7.7](/process-compass/phase4-process-design/overview/)の3つの型から1つを選び、値の所在の語で示します。手順は次のとおりです。

1. 値が権限の境界か受容の基準を配るかを問う。配るなら組織が定める値とし、定める者・時点・記録先を書く。組織の規模に依る値には、参考の値と例のどちらも置かない
2. 配らない値で、検知・発火・停止を起動し、置き換えずに用いても統制を弱めないなら、既定値としてよい。置き換えの手続と記録を書く
3. どちらでもない説明のための値は、例の中にだけ置く
4. 置き換えを認めない値は型の外とし、要求事項の中に書いて、置き換えを認めない旨を書く
5. 表の列に値を並べるときは、列の見出しを「値」などの中立の語にし、行ごとの型を表の前後の文で示す。型の違う行を、1つの型の見出しの下に並べない
6. 既定値と参考の値の根拠が実証に依らない場合は、根拠水準のマークを付ける

型の宣言は本標準の記述にだけ掛かり、採用者には掛かりません。

### 却下した案ごとに、残す形を決める

会議体の決定を条項・テンプレート・検査へ反映する作業では、却下した案ごとに、次の3つのいずれかを記録します。記録の場所は、その決定の ADR の「検討した選択肢」か却下の一覧です([ADR-0089](/process-compass/adr/0089-regression-suite-under-version-control/))。

| 形 | 使う場面 | 書くこと |
| --- | --- | --- |
| 登録簿の句 | 却下した案が、古い言い回しとして本文・テンプレートに残りうる | `retiredPhrases` へ句を登録し、ADR に句を書く |
| 否定の場面 | 却下した案が、挙動としてテンプレートへ入りうる | 却下した挙動を拒否・不在として確かめる場面を、回帰の試験(`scripts/regress/`)かテンプレートの試験へ置き、ADR に場面の名を書く |
| どちらも置かない理由 | 句にも挙動にもならない(例: 標準に課さないと決めた事項、運用の頻度の選択) | 置かない理由を ADR に1行で書く |

却下した案が黙って戻る経路は、言い回しの写しと挙動の実装の2つです。3つの形は、その2つの経路を塞ぐか、塞がない理由を残すかを、案ごとに決めさせます。「書かれていない」と「課さないと決めた」を、後から読む者が区別できる状態を保つためです。

却下文の全文を検索する検査は置きません。却下の文は経緯として ADR・調査メモに残り、同じ語が説明として本文にも現れるため、誤検出が多くなります。

## 附属書の種別を変えるとき

附属書の種別(規定・参考)は、あとから変えにくい決定です。変えるときは、次の順で行います。

1. 変更を [ADR](/process-compass/adr/) として起票する
2. 第1章 1.5 の表、附属書の表題と冒頭の宣言、登録簿の `documents` を改める
3. 参考へ変える場合は、要求・禁止の文と実装マークを、本文か規定の附属書へ移す。規定へ変える場合は、本文からの引き方を「〜による」へ改める

## 準拠テンプレートのスキルの文

準拠テンプレートのスキルの文のうち、要求と禁止の文末を持つものには、本標準の所在か、テンプレート独自の印を付けます。この検査は別のスクリプト(`npm run lint:skills`)が行います。書式は[実装マークの規約](/process-compass/community/implementation-marking/)「準拠テンプレートのスキルの文」によります。
